## 1. Логический тип данных и операции сравнения

### Логический тип данных `bool`

В процессе выполнения программы компьютеру часто приходится принимать решения: продолжать ли вычисление, верно ли введены данные, достиг ли цикл конца массива. Для представления результатов таких проверок в языке C# используется логический тип данных, который называется `bool` (сокращение от имени английского математика Джорджа Буля, создателя булевой алгебры).

> **Определение.** Логический тип данных `bool` — это тип данных, переменные которого могут принимать ровно два возможных значения: `true` (истина) или `false` (ложь). Никакие другие значения (например, числа `0` и `1`, как в некоторых других языках программирования) для типа `bool` в C# недопустимы.

В памяти компьютера переменная типа `bool` занимает обычно 1 байт. Объявление логической переменной и присваивание ей значения выполняются стандартным образом:

```csharp
bool isReady = true;
bool hasError = false;
```

Значения `true` и `false` являются литералами булева типа. Они пишутся строчными буквами.

### Операции сравнения

Чтобы программа могла принимать осмысленные решения, ей нужно сравнивать между собой различные данные (числа, символы и т. д.). Для этого используются операции сравнения. Результатом любой операции сравнения всегда является значение типа `bool`.

В языке C# определены следующие операции сравнения:
1. Больше (`>`)
2. Меньше (`<`)
3. Больше или равно (`>=`)
4. Меньше или равно (`<=`)
5. Равно (`==`)
6. Не равно (`!=`)

Обратите внимание, что для проверки на равенство используется двойной знак равенства (`==`). Одинарный знак равенства (`=`) в C# зарезервирован исключительно для операции присваивания значения переменной. Путаница между `=` и `==` является одной из самых частых синтаксических ошибок у начинающих программистов.

Рассмотрим примеры простых выражений сравнения:
- Выражение `5 > 3` имеет результат `true`.
- Выражение `10 == 20` имеет результат `false`.
- Выражение `7 <= 7` имеет результат `true`, так как выполняется условие равенства.
- Выражение `4 != 4` имеет результат `false`, поскольку числа равны, а операция требует неравенства.

### Приоритет операций сравнения по отношению к арифметическим операциям

В сложных выражениях могут одновременно участвовать арифметические операции (сложение, умножение, деление и т. д.) и операции сравнения. Чтобы вычислить такое выражение правильно, необходимо знать порядок их выполнения (приоритет).

Общее правило таково: любые арифметические операции выполняются **раньше**, чем операции сравнения. Сначала компьютер полностью вычисляет значения в левой и правой частях от знака сравнения, а затем применяет саму операцию сравнения.

Рассмотрим иерархию приоритетов от высшего к низшему для рассматриваемых операций:
1. Унарные операции (унарный плюс, унарный минус)
2. Умножение (`*`), деление (`/`), остаток от деления (`%`)
3. Сложение (`+`), вычитание (`-`)
4. Операции сравнения (`>`, `<`, `>=`, `<=`, `==`, `!=`)
5. Операция присваивания (`=`)

Если требуется изменить стандартный порядок вычислений, используются круглые скобки `()`. Выражения в скобках всегда вычисляются в первую очередь.

### Особенности сравнения вещественных чисел с плавающей точкой (`double`)

При работе с целыми числами (`int`) операции сравнения на равенство (`==`) и неравенство (`!=`) работают абсолютно точно и предсказуемо. Однако при работе с вещественными числами типа `double` возникает важная аппаратная особенность, о которой необходимо помнить.

Компьютер хранит вещественные числа в памяти в двоичном виде с фиксированной длиной мантиссы. Из-за этого многие десятичные дроби (например, `0{,}1` или `0{,}3`) не могут быть представлены в памяти компьютера абсолютно точно — они записываются с бесконечным периодом в двоичной системе, который округляется до ближайшего машинного представления.

Рассмотрим следующий код:
```csharp
double a = 0.1 + 0.2;
double b = 0.3;
bool result = (a == b);
```
Интуитивно кажется, что `a` и `b` равны. Но из-за погрешности округления при сложении `0{,}1` и `0{,}2` значение переменной `a` может оказаться равным `0{,}30000000000000004`, в то время как `b` будет равно `0{,}3`. В результате операция `a == b` вернет `false`.

> **Правило.** Никогда не сравнивайте вещественные числа типа `double` с помощью оператора точного равенства (`==`). Вместо этого проверяйте, лежит ли абсолютная разность между числами в пределах некоторой очень малой погрешности (обычно обозначаемой греческой буквой $\varepsilon$ — эпсилон, например, $10^{-6}$ или $10^{-9}$).

Корректный способ сравнения двух вещественных чисел `a` и `b` на равенство выглядит следующим образом:

```csharp
double a = 0.1 + 0.2;
double b = 0.3;
double epsilon = 0.000001; // задаем допустимую погрешность

// Проверяем, меньше ли модуль разности чисел выбранной погрешности
bool areEqual = Math.Abs(a - b) < epsilon;
```
Здесь метод `Math.Abs()` вычисляет абсолютное значение (модуль) разности чисел. Если разность по модулю меньше `0{,}000001`, числа считаются практически равными.

### Вычисление значений логических выражений и запись результатов

Результат вычисления любого логического выражения можно сохранить в переменную типа `bool`, чтобы использовать её дальше в программе.

Пример сохранения результата сравнения в переменную:
```csharp
int age = 18;
bool isAdult = age >= 18; // переменная isAdult получит значение true
```

Компьютер выполняет это присваивание в два шага:
1. Вычисляет выражение справа от знака `=`. Выражение `age >= 18` при `age = 18` превращается в `true`.
2. Записывает полученное булево значение (`true`) в ячейку памяти переменной `isAdult`.

---

### Разобранные примеры

#### Пример 1. Вычисление сложного логического выражения по шагам

**Условие:** Определить истинность выражения при $x = 7$ и $y = 12$: 
$$(x + 5 \le y) \And\& (y - x \ne 5)$$
Вычислить значение в пошаговом режиме.

**Ход рассуждений:**
1. Сначала подставим числовые значения переменных $x = 7$ и $y = 12$ в исходное выражение:
   $$(7 + 5 \le 12) \And\& (12 - 7 \ne 5)$$
2. В соответствии с приоритетом операций, сначала выполняются арифметические действия внутри скобок (сложение и вычитание):
   - В левой скобке: $7 + 5 = 12$. Выражение принимает вид: $(12 \le 12) \And\& (12 - 7 \ne 5)$.
   - В правой скобке: $12 - 7 = 5$. Выражение принимает вид: $(12 \le 12) \And\& (5 \ne 5)$.
3. Теперь выполняем операции сравнения внутри обеих скобок:
   - Левая часть: проверяем условие $12 \le 12$. Поскольку $12$ равно $12$, условие истинно (`true`).
   - Правая часть: проверяем условие $5 \ne 5$. Поскольку $5$ не равно $5$ — это ложь (`false`), так как числа равны.
4. Подставляем результаты сравнения в общую формулу:
   $$\text{true} \And\& \text{false}$$
5. Операция логического И (`&&`) дает истину только тогда, когда оба операнда истинны. Поскольку один из операндов равен `false`, результатом всего выражения будет `false`.

**Решение (код на C#):**

```csharp
using System;

class Program
{
    static void Main()
    {
        int x = 7;
        int y = 12;

        // Вычисление частей выражения отдельно для наглядности
        bool leftPart = (x + 5 <= y);   // 12 <= 12 -> true
        bool rightPart = (y - x != 5);  // 5 != 5 -> false

        bool result = leftPart && rightPart; // true && false -> false

        Console.WriteLine($"Результат левой части: {leftPart}");
        Console.WriteLine($"Результат правой части: {rightPart}");
        Console.WriteLine($"Итоговый результат: {result}");
    }
}
```

**Проверка единиц и правдоподобия:**
Логические типы не имеют физических единиц измерения. Логика вычислений проверена дважды: арифметика целых чисел выполнена без ошибок, операции сравнения соответствуют математическим определениям. Ответ `false` является достоверным.

**Ответ:** `false` (выражение ложно).

#### Пример 2. Проверка четности целого числа

**Условие:** Написать фрагмент программы на C#, который запрашивает у пользователя целое число, проверяет, является ли оно четным, и выводит соответствующий результат в виде логического значения (`true`, если четное, и `false`, если нечетное).

**Рисунок словами (схема работы программы):**
```
[Консоль: ввод числа] ---> [Переменная number] ---> [Вычисление остатка: number % 2 == 0] ---> [Переменная isEven (bool)] ---> [Консоль: вывод true/false]
```

**Ход рассуждений:**
1. Чтобы узнать, является ли число четным, нужно разделить его на $2$ с остатком. В языке C# операция взятия остатка от деления обозначается знаком `%`.
2. Если остаток от деления целого числа на $2$ равен нулю ($n \% 2 == 0$), то число четное. Если остаток равен $1$ (или $-1$ для отрицательных чисел), то число нечетное.
3. Результат проверки равенства остатка нулю (`number % 2 == 0`) является логическим выражением, которое возвращает `true` или `false`.
4. Запишем этот результат в переменную типа `bool` и выведем на экран.

**Решение в общем виде и код на C#:**

```csharp
using System;

class Program
{
    static void Main()
    {
        // Приглашение для ввода данных
        Console.Write("Введите целое число: ");
        
        // Считываем строку из консоли и преобразуем её в целое число типа int
        int number = int.Parse(Console.ReadLine());

        // Проверяем условие четности и сохраняем результат в булеву переменную
        bool isEven = (number % 2 == 0);

        // Выводим результат на экран
        Console.WriteLine($"Число является четным: {isEven}");
    }
}
```

**Пример ввода и вывода:**
*Ввод:*
```text
Введите целое число: 14
```
*Вывод:*
```text
Число является четным: True
```

*Ввод:*
```text
Введите целое число: -7
```
*Вывод:*
```text
Число является четным: False
```

**Проверка правдоподобия:**
Для числа `14`: остаток от деления `14 % 2` равен `0`. Условие `0 == 0` дает `true`. Программа вывела `True`, что верно.
Для числа `-7`: остаток от деления `-7 % 2` равен `-1`. Условие `-1 == 0` дает `false`. Программа вывела `False`, что также абсолютно верно.

**Ответ:** Программа корректно определяет четность числа с помощью операции взятия остатка от деления и сравнения с нулем, сохраняя результат в переменную типа `bool`.

## 2. Условный оператор if, else и полные/неполные ветвления

### Синтаксис неполного условного оператора if в C#

В реальных задачах выполнение программы редко идет строго по прямой линии. Часто в зависимости от входных данных или результатов вычислений необходимо принять решение: выполнять определенный набор команд или пропустить его. Для этого в языке C# используется условный оператор `if`.

> **Определение.** Условный оператор `if` (оператор ветвления) — это конструкция языка программирования, которая позволяет выполнить определенный блок кода только в том случае, если заданное логическое условие истинно (`true`).

Синтаксис неполного условного оператора `if` выглядит следующим образом:

```csharp
if (условие)
{
    // блок кода, который выполняется, если условие истинно
}
```

Рассмотрим каждую часть этой конструкции подробнее:
- `if` — ключевое слово языка C# (в переводе с английского — «если»).
- `условие` — это любое выражение, результат которого имеет логический тип `bool` (`true` или `false`). Это может быть переменная типа `bool`, результат операции сравнения (например, `x > 0`) или сложное логическое выражение. Обратите внимание, что условие **всегда** заключается в круглые скобки `()`. Если опустить круглые скобки, компилятор выдаст ошибку.
- Блок кода в фигурных скобках `{}` называется *телом условного оператора*. Если условие возвращает `true`, программа выполняет инструкции внутри этого блока. Если условие возвращает `false`, содержимое блока полностью игнорируется, и выполнение программы переходит к строке, следующей за закрывающей фигурной скобкой.

### Синтаксис полного условного оператора if-else

Часто требуется предусмотреть два взаимоисключающих варианта развития событий: если условие истинно — выполнить одно действие, а если ложно — совершенно другое. Для реализации такого поведения используется полный условный оператор `if-else`.

> **Определение.** Полный условный оператор `if-else` — это конструкция ветвления, которая предоставляет две альтернативные ветки выполнения: одна выполняется при истинности условия, а вторая (альтернативная) — при его ложности.

Синтаксис полного условного оператора:

```csharp
if (условие)
{
    // ветка 'true': выполняется, если условие истинно
}
else
{
    // ветка 'false': выполняется, если условие ложно
}
```

Ключевое слово `else` (в переводе — «иначе») не имеет собственного условия. Оно автоматически срабатывает ровно в тех случаях, когда условие, записанное в круглых скобках после `if`, принимает значение `false`. Одновременно обе ветки (и содержимое `if`, и содержимое `else`) выполниться не могут. Всегда выполняется ровно один из блоков кода.

### Понятие блока кода и видимость переменных

В языке C# фигурные скобки `{}` задают *блок кода* (или область видимости). Все переменные, объявленные внутри фигурных скобок условного оператора (`if` или `else`), подчиняются правилу локальной видимости.

> **Определение.** Область видимости переменной (scope) — это часть программы, в которой данная переменная доступна для использования. Переменная, объявленная внутри блока кода, существует только внутри этого блока и уничтожается сразу после выхода из него.

Рассмотрим пример ограничения видимости:

```csharp
double x = 10.5;

if (x > 0)
{
    double root = Math.Sqrt(x); // переменная root видна только здесь
    Console.WriteLine(root);
}
else
{
    // Ошибка компиляции! Переменная root не существует в этой ветке
    // Console.WriteLine(root); 
}

// Ошибка компиляции! За пределами блока if-else переменная root недоступна
// Console.WriteLine(root); 
```

Если вам нужно использовать результат вычислений, полученный внутри ветки `if` или `else`, переменную необходимо объявить *до* начала условного оператора:

```csharp
double x = 10.5;
double result; // объявление переменной заранее

if (x > 0)
{
    result = Math.Sqrt(x); // присваивание значения внутри ветки
}
else
{
    result = 0.0;
}

Console.WriteLine(result); // Переменная доступна здесь, так как объявлена выше
```

### Вложенные условные операторы и правила соотнесения else

Внутри блоков `if` или `else` можно помещать другие условные операторы. Такие конструкции называются *вложенными ветвлениями*. Они применяются тогда, когда выбор дальнейшего действия зависит от нескольких последовательных условий.

При проектировании вложенных условий критически важно понимать правило соотнесения ветки `else` с условными операторами.

> **Правило свисающего else (dangling else):** В языке C# каждая ветка `else` всегда относится к ближайшему предшествующему оператору `if`, у которого еще нет своей ветки `else` в пределах того же уровня вложенности.

Рассмотрим синтаксическую конструкцию:

```csharp
if ( условие1 )
    if ( условие2 )
        действие1;
    else
        действие2;
```

Здесь `else` относится к внутреннему оператору `if (условие2)`, а не к внешнему `if (условие1)`. Чтобы сделать код однозначным и избежать логических ошибок, настоятельно рекомендуется всегда использовать фигурные скобки `{}` даже для одиночных инструкций:

```csharp
if (условие1)
{
    if (условие2)
    {
        // Выполнится, если условие1 И условие2 истинны
    }
    else
    {
        // Выполнится, если условие1 истинно, а условие2 ложно
    }
}
else
{
    // Выполнится, если условие1 ложно
}
```

### Каскадные ветвления (конструкция if-else-if)

Когда перед программой стоит задача выбрать один вариант из множества взаимоисключающих условий (например, проверить оценку студента или диапазон числовых значений), вложенные конструкции с глубоким смещением вправо становятся трудночитаемыми. В таких случаях используется специальная форма записи — каскадное ветвление `if-else-if`.

Синтаксис каскадного ветвления:

```csharp
if (условие1)
{
    // Действие 1 (выполняется, если условие1 истинно)
}
else if (условие2)
{
    // Действие 2 (выполняется, если условие1 было ложно, а условие2 истинно)
}
else if (условие3)
{
    // Действие 3 (выполняется, если условие1 и условие2 ложны, а условие3 истинно)
}
else
{
    // Действие по умолчанию (выполняется, если все предыдущие условия ложны)
}
```

Важнейшая особенность каскадного ветвления заключается в порядке проверки: условия проверяются последовательно сверху вниз. Как только программа находит первое истинное условие, она выполняет соответствующий блок кода и **немедленно выходит из всего каскада** `if-else-if`, игнорируя все последующие ветки. Блок `else` в конце цепочки является необязательным и служит для обработки ситуации, когда ни одно из условий не подошло.

### Типичные ошибки при написании условных операторов

1. **Пропуск фигурных скобок при многострочном теле.** Если тело `if` или `else` состоит из нескольких инструкций, но программист забыл поставить фигурные скобки `{}`, компилятор сочтет частью условного оператора только *самую первую* строку сразу после `if`. Остальные строки будут выполняться безусловно, что разрушает логику программы.
2. **Пустые тела ветвей или лишняя точка с запятой.** Постановка точки с запятой сразу после закрывающей круглой скобки условия (`if (x > 0);`) приводит к созданию пустого оператора. В результате блок кода в следующих фигурных скобках будет выполняться всегда, независимо от истинности условия, так как условный оператор завершился пустой инструкцией на предыдущей строке.
3. **Использование оператора присваивания `=` вместо оператора сравнения `==`.** В языках программирования вроде C# запись `if (x = 5)` вызовет ошибку компиляции (если `x` не типа `bool`), так как операция присваивания возвращает присваиваемое значение, а не проверяет равенство.
4. **Неверный порядок условий в каскадных ветвлениях.** Если в конструкции `if-else-if` сначала проверить более широкое условие, более узкие специфические условия внутри каскада станут недостижимыми (например, проверка `x > 0` перед проверкой `x > 100` сделает вторую ветку бессмысленной).

### Разбор примеров

#### Пример 1. Нахождение наибольшего из трех чисел

**Условие задачи:**
Даны три вещественных числа $a$, $b$ и $c$. Составить алгоритм и написать программу на C#, которая находит наибольшее из этих трех чисел с использованием вложенных условных операторов.

**Рисунок словами:**
Представим числовую ось. У нас есть три точки $a$, $b$ и $c$. Чтобы найти самое правое (наибольшее) число, мы можем организовать турнир сравнений:
1. Сравним число $a$ с числом $b$. Если $a$ больше $b$, то кандидат на победу — $a$ (а $b$ отсеивается). Если нет, то кандидат — $b$ (а $a$ отсеивается).
2. Победителя первого раунда сравним с оставшимся числом $c$. Тот, кто окажется больше, и есть абсолютный максимум.

**Ход рассуждений (почему делаем именно так):**
Мы будем использовать вложенный условный оператор. Сначала проверим условие `a > b`. 
- Если оно истинно, значит, $b$ точно не является наибольшим. Теперь нам достаточно сравнить $a$ с оставшимся числом $c$. Если `a > c`, то максимальным является $a$. Иначе (`else`) максимальным является $c$.
- Если условие `a > b` ложно, значит, $a$ точно не наибольшее. Теперь нам нужно сравнить текущего претендента $b$ с числом $c$. Если `b > c`, то максимальным является $b$. Иначе (`else`) максимальным является $c$.

**Решение в общем виде и код программы:**

```csharp
using System;

class Program
{
    static void Main()
    {
        // Ввод данных
        Console.WriteLine("Введите три вещественных числа:");
        double a = double.Parse(Console.ReadLine());
        double b = double.Parse(Console.ReadLine());
        double c = double.Parse(Console.ReadLine());

        double max; // Переменная для хранения результата

        // Вложенные условные операторы
        if (a > b)
        {
            if (a > c)
            {
                max = a;
            }
            else
            {
                max = c;
            }
        }
        else
        {
            if (b > c)
            {
                max = b;
            }
            else
            {
                max = c;
            }
        }

        // Вывод результата
        Console.WriteLine($"Наибольшее число: {max}");
    }
}
```

**Вычисление на тестовых данных:**
Пусть пользователь ввел числа: $a = 7{,}5$, $b = 14{,}2$, $c = 9{,}0$.
1. Проверяем внешнее условие: `7.5 > 14.2`. Это ложь (`false`). Программа переходит в ветку `else`.
2. Внутри ветки `else` проверяем внутреннее условие: `14.2 > 9.0`. Это истина (`true`).
3. Присваиваем `max = 14.2`.
4. Выводим результат на экран.

**Проверка:**
Сравним исходные числа: $7{,}5$, $14{,}2$, $9{,}0$. Самое большое из них действительно $14{,}2$. Алгоритм работает корректно.

`Ответ:` Наибольшее число: 14,2 (для введенного набора данных).

#### Пример 2. Определение погодного сообщения по температуре

**Условие задачи:**
Написать программу на C#, которая по введенному целому значению температуры воздуха $T$ выводит текстовое сообщение в соответствии с правилом:
- «Мороз» — если температура ниже $0$ (т. е. $T < 0$);
- «Холодно» — если температура находится в диапазоне от $0$ до $15$ включительно (т. е. $0 \le T \le 15$);
- «Тепло» — если температура выше $15$ (т. е. $T > 15$).

**Рисунок словами:**
Представим числовую прямую температур:
```
<-----------------|-----------------|----------------->
        Мороз      0     Холодно     15     Тепло
 (при T < 0)            (при 0<=T<=15)          (при T > 15)
```
Шкала разбита на три неперекрывающихся интервала. Нам нужно определить, в какой именно интервал попадает введенное пользователем число.

**Ход рассуждений (почему делаем именно так):**
Здесь перед нами классическая задача на выбор одного варианта из трех возможных. Идеальным инструментом для ее решения является каскадное ветвление `if-else-if`. 
1. Первым делом проверяем самое строгое ограничение слева: `T < 0`. Если условие верно, выводим «Мороз» и завершаем цепочку.
2. Если температура не меньше нуля, мы автоматически попадаем в область $T \ge 0$. Следующим шагом проверяем правую границу диапазона холода: `T <= 15`. Благодаря тому, что первое условие уже отсекло все числа меньше нуля, здесь нам достаточно проверить только верхнюю границу. Если условие верно, выводим «Холодно».
3. Если ни первое, ни второе условие не выполнились, значит, температура заведомо строго больше $15$. Для этого случая используем завершающую ветку `else`, выводящую «Тепло».

**Решение в общем виде и код программы:**

```csharp
using System;

class Program
{
    static void Main()
    {
        // Ввод данных
        Console.Write("Введите температуру воздуха (в градусах Цельсия): ");
        int temperature = int.Parse(Console.ReadLine());

        // Каскадное ветвление if-else-if
        if (temperature < 0)
        {
            Console.WriteLine("Мороз");
        }
        else if (temperature <= 15)
        {
            Console.WriteLine("Холодно");
        }
        else
        {
            Console.WriteLine("Тепло");
        }
    }
}
```

**Вычисление на тестовых данных:**
Пусть пользователь ввел значение `temperature = 8`.
1. Проверяем первое условие: `8 < 0`. Это ложь (`false`). Программа переходит к следующей проверке.
2. Проверяем второе условие: `8 <= 15`. Это истина (`true`). 
3. Выполняется инструкция внутри этого блока: на экран выводится текст `Холодно`.
4. Каскад завершается, проверка остальных веток не производится.

**Проверка:**
Значение $8$ находится между $0$ и $15$ включительно. По условию задачи для этого диапазона должно выводиться сообщение «Холодно». Программа вывела именно его. Проверим граничное значение $0$: `0 < 0` (ложь), `0 <= 15` (истина) -> «Холодно» (верно по условию). Проверим значение $-5$: `-5 < 0` (истина) -> «Мороз» (верно).

`Ответ:` Для температуры 8 выведено «Холодно».

## 3. Сложные логические условия и булева алгебра

### Логические операции и законы булевой алгебры

В предыдущих разделах мы научились сравнивать отдельные величины (например, проверять, больше ли $x$ нуля или равны ли две переменные). Однако в реальных задачах часто требуется проверить выполнение *нескольких* условий одновременно. Например: «если студент сдал экзамен *и* его средний балл выше 4{,}5, *или* у него есть олимпиада». Для построения таких составных правил в языке C# используются логические операции.

Логические операции оперируют операндами типа `bool` (которые принимают значения `true` или `false`) и возвращают результат также типа `bool`.

> **Определение.** Булева алгебра (или алгебра логики) — это раздел математики, изучающий высказывания, логические операции над ними и законы их преобразования. В программировании булева алгебра применяется для построения ветвлений и управления порядком выполнения инструкций.

---

### Основные логические операции: таблицы истинности

В C# определены три основные бинарные и унарные логические операции, позволяющие строить условия любой степени сложности.

#### 1. Логическое И (конъюнкция, операция `&&`)

> **Определение.** Логическое И — это операция, которая возвращает `true` тогда и только тогда, когда *оба* операнда истинны. Во всех остальных случаях результат равен `false`.

В математической логике конъюнкция обозначается знаком $\land$ или умножением. В C# используется двойной амперсанд `&&`.

Таблица истинности для операции `&&`:

| Операнд $A$ | Операнд $B$ | Результат $A$ `&&` $B$ |
| :---: | :---: | :---: |
| `false` | `false` | `false` |
| `false` | `true` | `false` |
| `true` | `false` | `false` |
| `true` | `true` | `true` |

**Правило вычисления:** Представьте, что вы проходите пропускной пункт, где требуются и пропуск, и паспорт. Если хотя бы одного документа нет (`false`), проход запрещен (`false`). Проход разрешен (`true`) только тогда, когда есть и пропуск, *и* паспорт (`true` и `true`).

#### 2. Логическое ИЛИ (дизъюнкция, операция `||`)

> **Определение.** Логическое ИЛИ — это операция, которая возвращает `true`, если *хотя бы один* из операндов истинен. Результат равен `false` только тогда, когда оба операнда ложны.

В математике дизъюнкция обозначается знаком $\lor$ или сложением. В C# используются две вертикальные черты `||`.

Таблица истинности для операции `||`:

| Операнд $A$ | Операнд $B$ | Результат $A$ `||` $B$ |
| :---: | :---: | :---: |
| `false` | `false` | `false` |
| `false` | `true` | `true` |
| `true` | `false` | `true` |
| `true` | `true` | `true` |

**Правило вычисления:** Для прохода в кинотеатр достаточно билета *или* пригласительного. Если нет ни того, ни другого (`false` и `false`), вы не войдете (`false`). Если есть хотя бы что-то одно (или оба сразу), вы проходите (`true`).

#### 3. Логическое НЕ (инверсия, операция `!`)

> **Определение.** Логическое НЕ — это унарная операция (применяется к одному операнду), которая меняет логическое значение на противоположное: `true` превращает в `false`, а `false` — в `true`.

В математике инверсия обозначается чертой над символом или знаком $\neg$. В C# используется восклицательный знак `!`.

Таблица истинности для операции `!`:

| Операнд $A$ | Результат `!`$A$ |
| :---: | :---: |
| `false` | `true` |
| `true` | `false` |

### Приоритет логических операций

Когда в одном выражении комбинируются арифметические операции, операции сравнения и логические операции, компилятор выполняет их в строго определенном порядке. Нарушение этого порядка или незнание приоритетов приводит к логическим ошибкам.

Общий порядок приоритетов (от высшего к низшему):
1. Скобки `(...)` — изменяют любой приоритет.
2. Унарные операции: унарный минус, инкремент/декремент, логическое НЕ `!`.
3. Арифметические операции умножения, деления и остатка от деления (`*`, `/`, `%`).
4. Арифметические операции сложения и вычитания (`+`, `-`).
5. Операции сравнения (`<`, `>`, `<=`, `>=`, `==`, `!=`).
6. Логическое И (`&&`).
7. Логическое ИЛИ (`||`).

> **Важное правило.** Всегда используйте круглые скобки для группировки сложных условий, даже если приоритет операций позволяет обойтись без них. Скобки делают код читаемым и защищают от ошибок, связанных с неверным пониманием порядка вычислений.

---

### Сокращенное (ленивое) вычисление логических выражений

В языке C# для операций `&&` и `||` реализован механизм **короткого замыкания** (Short-circuit evaluation), или ленивых вычислений.

Суть механизма заключается в том, что компилятор прекращает вычисление правой части логического выражения, как только значение всего выражения становится очевидным после вычисления левой части.

1. **Для операции `&&`:** Если левый операнд равен `false`, то независимо от значения правого операнда результат всего выражения `А && В` будет `false` (так как `false && ...` всегда дает `false`). В этом случае правая часть `B` **даже не вычисляется**.
2. **Для операции `||`:** Если левый операнд равен `true`, то результат всего выражения `А || В` гарантированно будет `true` (так как `true || ...` всегда дает `true`). Правая часть `B` **не вычисляется**.

**Зачем это нужно на практике?**
Ленивое вычисление — это не просто оптимизация производительности, это способ защиты программы от критических ошибок выполнения (исключений). 

Рассмотрим классический пример: проверка того, что строка не пуста и ее первый символ равен определенной букве.
```csharp
string text = null;

// Опасный код: если text равен null, обращение к свойству text.Length вызовет NullReferenceException
// if (text != null && text.Length > 0) 

// Безопасный код с ленивым вычислением:
if (text != null && text.Length > 0)
{
    Console.WriteLine("Строка не пуста");
}
```
В этом примере, если переменная `text` равна `null`, первое условие `text != null` возвращает `false`. Благодаря короткому замыканию, выполнение останавливается, и проверка `text.Length > 0` не выполняется. Если бы ленивого вычисления не было, программа аварийно завершила бы работу.

*(Примечание: в C# также существуют побитовые логические операторы `&` и `|`, которые вычисляют оба операнда всегда, но для построения условий ветвления в стиле `if` всегда применяются сокращенные `&&` и `||`).*

### Законы де Моргана и упрощение булевых выражений

Часто при написании программ возникают ситуации, когда условие инвертируется (например: «выполнить действие, если *неверно*, что число больше 5 и меньше 10»). Нагромождение отрицаний усложняет восприятие кода. Для упрощения таких выражений используют алгебраические законы логики, среди которых ключевое место занимают **законы де Моргана**.

> **Законы де Моргана:**
> 1. Отрицание конъюнкции (И) эквивалентно дизъюнкции (ИЛИ) отрицаний:
>    $$\neg(A \land B) \equiv \neg A \lor \neg B$$
>    В синтаксисе C#: `!(a && b)` эквивалентно `!a || !b`.
> 2. Отрицание дизъюнкции (ИЛИ) эквивалентно конъюнкции (И) отрицаний:
>    $$\neg(A \lor B) \equiv \neg A \land \neg B$$
>    В синтаксисе C#: `!(a || b)` эквивалентно `!a && !b`.

**Правило преобразования:** При занесении знака отрицания `!` внутрь скобок со сложным условием:
* Знак операции меняется на противоположный (`&&` меняется на `||`, а `||` меняется на `&&`).
* Каждое простое условие внутри скобок заменяется на противоположное (знаки сравнения инвертируются: `>` на `<=`, `==` на `!=` и т. д.).

### Разобранные примеры

#### Пример 1. Проверка принадлежности точки прямоугольнику

**Условие:**
Написать логическое выражение для проверки того, что точка с координатами $(x, y)$ лежит строго *внутри* прямоугольника, стороны которого параллельны осям координат. Левый верхний угол прямоугольника имеет координаты $(-2, 3)$, а правый нижний угол — $(4, -1)$. Написать полный фрагмент кода на C#, который считывает координаты точки и выводит сообщение о ее принадлежности области.

**Рисунок словами (схема):**
```text
  Y
  ^
 3|...+-----------+  <- Верхняя граница (y = 3)
  |   |           |
  |   |  (x, y)   |
  |   |           |
-2|---+-----------+4  <- Правая граница (x = 4)
  |   |           |
-1+---+-----------+  <- Нижняя граница (y = -1)
  +---+---+---+---+---> X
 -2   0   1   2   4
  ^
  Левая граница (x = -2)
```
Прямоугольник ограничен по горизонтали абсциссами от $-2$ до $4$, а по вертикали ординатами от $-1$ до $3$. Слово «строго внутри» означает, что точки, лежащие непосредственно на границах прямоугольника, не учитываются (используются строгие неравенства `<` и `>`).

**Ход рассуждений:**
1. Чтобы точка $(x, y)$ находилась внутри прямоугольника, должны одновременно выполняться два пространственных условия:
   - Координата $x$ должна быть строго больше левой границы ($-2$) и строго меньше правой границы ($4$). Записывается как неравенство: $-2 < x < 4$, что в C# раскладывается через конъюнкцию: `(x > -2) && (x < 4)`.
   - Координата $y$ должна быть строго меньше верхней границы ($3$) и строго больше нижней границы ($-1$). Записывается как: $-1 < y < 3$, что в C# превращается в: `(y > -1) && (y < 3)`.
2. Оба этих требования должны выполняться *одновременно*. Значит, между ними ставится операция логического И (`&&`).

**Решение в общем виде и на C#:**
Полная программа для проверки:

```csharp
using System;

class Program
{
    static void Main()
    {
        Console.WriteLine("Введите координату x точки:");
        double x = Convert.ToDouble(Console.ReadLine());

        Console.WriteLine("Введите координату y точки:");
        double y = Convert.ToDouble(Console.ReadLine());

        // Проверка нахождения точки внутри прямоугольника (-2, 3) и (4, -1)
        bool isInsideX = (x > -2) && (x < 4);
        bool isInsideY = (y > -1) && (y < 3);

        bool isInside = isInsideX && isInsideY;

        if (isInside)
        {
            Console.WriteLine("Ответ: Точка лежит внутри прямоугольника.");
        }
        else
        {
            Console.WriteLine("Ответ: Точка лежит вне прямоугольника.");
        }
    }
}
```

**Проверка (единицы, правдоподобие):**
- Подставим тестовую точку $(1, 2)$:
  - `isInsideX`: `(1 > -2) && (1 < 4)` $\rightarrow$ `true && true` $\rightarrow$ `true`.
  - `isInsideY`: `(2 > -1) && (2 < 3)` $\rightarrow$ `true && true` $\rightarrow$ `true`.
  - Общий результат: `true && true` $\rightarrow$ `true` (точка внутри, что верно).
- Подставим граничную точку по $x$: $(-2, 1)$:
  - `isInsideX`: `(-2 > -2)` дает `false` (так как неравенство строгое).
  - Общий результат: `false`. Точка на границе не засчитывается, что соответствует условию «строго внутри».

#### Пример 2. Упрощение логического выражения

**Условие:**
Упростить логическое условие `!(!(a > 5) || (b < 10))` и записать его эквивалентный вариант на C# без двойного отрицания, используя законы булевой алгебры.

**Ход рассуждений:**
Исходное выражение: 
$$\neg(\neg(a > 5) \lor (b < 10))$$

Применим законы де Моргана и правила раскрытия инверсий по шагам:

1. Обозначим части выражения для наглядности:
   - Пусть $A = \neg(a > 5)$
   - Пусть $B = (b < 10)$
   - Выражение принимает вид: $\neg(A \lor B)$
2. Применим второй закон де Моргана ($\neg(A \lor B) \equiv \neg A \land \neg B$):
   $$\neg(\neg(a > 5) \lor (b < 10)) \equiv \neg(\neg(a > 5)) \land \neg(b < 10)$$
3. Упростим двойное отрицание в первой части ($\neg(\neg P) \equiv P$):
   Применяем к $\neg(\neg(a > 5))$: получаем просто $(a > 5)$.
4. Упростим вторую часть с помощью отрицания операции сравнения:
   Инвертируем условие $(b < 10)$. Отрицанием «меньше» является «больше или равно» ($\ge$). Следовательно, $\neg(b < 10)$ превращается в $(b \ge 10)$.
5. Сведем все вместе:
   $$(a > 5) \land (b \ge 10)$$

**Программная реализация:**
Фрагмент кода на C#, демонстрирующий эквивалентность исходного сложного и упрощенного выражений при заданных переменных:

```csharp
using System;

class Program
{
    static void Main()
    {
        int a = 8;
        int b = 12;

        // Исходное выражение с двойным отрицанием
        bool originalResult = !(!(a > 5) || (b < 10));

        // Упрощенное выражение по законам де Моргана
        bool simplifiedResult = (a > 5) && (b >= 10);

        Console.WriteLine($"Результат исходного выражения: {originalResult}");
        Console.WriteLine($"Результат упрощенного выражения: {simplifiedResult}");
        
        // Проверка эквивалентности
        Console.WriteLine($"Выражения эквивалентны: {originalResult == simplifiedResult}");
    }
}
```

**Проверка (правдоподобие):**
Пусть $a = 8$ (`8 > 5` — `true`), $b = 12$ (`12 < 10` — `false`).
- Расчет исходного:
  - `!(8 > 5)` $\rightarrow$ `!true` $\rightarrow$ `false`.
  - `false || (12 < 10)` $\rightarrow$ `false || false` $\rightarrow$ `false`.
  - `!` от этого результата $\rightarrow$ `!false` $\rightarrow$ `true`.
- Расчет упрощенного:
  - `(8 > 5)` $\rightarrow$ `true`.
  - `(12 >= 10)` $\rightarrow$ `true`.
  - `true && true` $\rightarrow$ `true`.
- Результаты совпадают (`true`). Логика преобразования выполнена безошибочно.

Ответ: Упрощенное выражение имеет вид `(a > 5) && (b >= 10)`.

## 4. Тернарная условная операция

### Синтаксис тернарной операции и ее назначение

В языке программирования C#, помимо классических разветвленных конструкций `if-else`, существует компактный инструмент для организации условного выбора — **тернарная условная операция** (часто ее называют оператором `? :`). 

> **Определение.** Тернарная операция — это условная операция, которая принимает три операнда и возвращает одно из двух значений в зависимости от истинности проверяемого логического выражения. Название «тернарная» происходит от количества операндов (от латинского *ternarius* — состоящий из трех частей).

В стандартных конструкциях `if-else` ветвление оформляется как полноценный управляющий блок инструкций. Однако на практике часто возникает задача: в зависимости от некоторого условия присвоить переменной одно из двух возможных значений. Использование `if-else` для этой цели требует предварительного объявления переменной и дублирования оператора присваивания. Тернарная операция позволяет записать такое действие в виде единого компактного выражения.

Общий синтаксис тернарной операции выглядит следующим образом:

$$condition \text{ ? } expression\_true \text{ : } expression\_false$$

Рассмотрим каждую составляющую этого синтаксиса подробно:
1. $condition$ — логическое выражение (операнд № 1). Оно должно вычисляться в значение типа `bool` (`true` или `false`). Это аналог условия, которое мы записываем в круглых скобках после ключевого слова `if`.
2. Значок вопроса `?` отделяет условие от вариантов выбора.
3. $expression\_true$ — выражение (операнд № 2), значение которого возвращается всей операцией, если условие $condition$ истинно (`true`).
4. Двоеточие `:` разделяет ветви истинности и ложности.
5. $expression\_false$ — выражение (операнд № 3), значение которого возвращается, если условие $condition$ ложно (`false`).

Для лучшего понимания сопоставим традиционный блок `if-else` и эквивалентную ему тернарную операцию. 

Пусть нам нужно определить максимальное из двух целых чисел $a$ и $b$ и записать его в переменную $max$.

Вариант с использованием конструкции `if-else`:

```csharp
int max;
if (a > b)
{
    max = a;
}
else
{
    max = b;
}
```

Тот же самый алгоритм с использованием тернарной операции:

```csharp
int max = (a > b) ? a : b;
```

Здесь логическое выражение `(a > b)` проверяется первым. Если оно истинно, то результатом выполнения всей тернарной операции становится значение переменной `a`, которое сразу же записывается в переменную `max`. Если условие ложно, возвращается значение переменной `b`.

### Типы возвращаемых значений в ветвях тернарной операции

Поскольку тернарная операция является выражением (то есть конструкцией, которая возвращает значение), к ее типам данных предъявляются строгие требования компилятора C#. Строгая типизация языка требует, чтобы типы данных обоих возможных результатов (`expression_true` и `expression_false`) были согласованы.

Правила типизации тернарной операции:
1. Выражения $expression\_true$ и $expression\_false$ **должны** иметь одинаковый тип данных, либо между их типами должна существовать возможность неявного приведения типов (например, одно из них имеет тип `int`, а другое `double`). В последнем случае типом результата станет общий «более широкий» тип.
2. Если ветви возвращают несовместимые типы (например, `string` и `int`), компилятор выдаст ошибку на этапе сборки программы, так как тип результирующей переменной не может быть определен однозначно.

Рассмотрим пример с неявным приведением типов:

```csharp
int discountType = 1;
// Если discountType равен 1, вернется целое число 50, иначе вещественное 15.5
// Компилятор автоматически приведет int к double, результатом будет double.
double discount = (discountType == 1) ? 50 : 15.5; 
```

Если же мы попытаемся написать следующее:

```csharp
bool flag = true;
// Ошибка компиляции: условное выражение не может возвращать одновременно string и int
var result = flag ? "Успех" : 404; 
```

Такой код вызовет ошибку компиляции: *Type of conditional expression cannot be determined because there is no implicit conversion between 'string' and 'int'*. Для исправления подобной ошибки типы возвращаемых значений нужно привести к единому виду (например, преобразовать число в строку через `.ToString()`).

### Вложенные тернарные операции и правила их читаемости

Тернарные операции можно вкладывать друг в друга, помещая одну тернарную операцию внутрь ветви `expression_true` или `expression_false` другой. Это позволяет компактно описывать цепочки множественных ветвлений (аналог конструкции `if-else-if`).

Синтаксис вложенной тернарной операции выглядит следующим образом:

$$condition\_1 \text{ ? } value\_1 \text{ : } (condition\_2 \text{ ? } value\_2 \text{ : } value\_3)$$

Хотя круглые скобки вокруг вложенной тернарной операции не всегда обязательны (операция правоассоциативна), их настоятельно рекомендуется ставить для улучшения читаемости кода.

Рассмотрим классическую задачу классификации числа на положительное, отрицательное или равное нулю.

```csharp
int number = -5;
string description = (number > 0) ? "Положительное" : ((number < 0) ? "Отрицательное" : "Нуль");
```

Ход вычислений этого выражения:
1. Проверяется первое условие: `number > 0` (то есть `-5 > 0`). Оно ложно (`false`).
2. Управление переходит к правой части после двоеточия: `(number < 0) ? "Отрицательное" : "Нуль"`.
3. Внутри этой вложенной операции проверяется условие: `number < 0` (то есть `-5 < 0`). Оно истинно (`true`).
4. В результате возвращается строка `"Отрицательное"`.

**Важное предупреждение о читаемости кода.** Злоупотребление вложенными тернарными операциями приводит к созданию трудночитаемого кода, в котором легко допустить ошибку (так называемый *Anti-pattern*). Если уровень вложенности превышает два слоя, или логика ветвления сложна, настоятельно рекомендуется использовать стандартный оператор `if-else-if` или оператор `switch`. Код должен быть понятен не только компьютеру, но и другим разработчикам.

### Применение тернарной операции внутри выражений и при инициализации переменных

Главное преимущество тернарной операции заключается в том, что она является *выражением* (expression), а не *инструкцией* (statement). Инструкция `if-else` не может быть встроена внутрь другого выражения, в то время как тернарную операцию можно размещать непосредственно внутри математических расчетов, вызовов методов или при инициализации полей и констант.

#### Инициализация переменных «на месте» (Read-only инициализация)
Тернарная операция незаменима при инициализации переменных с модификатором `readonly` или константных полей, когда значение должно зависеть от внешнего параметра, а изменить его позже нельзя.

```csharp
int userAge = 20;
// Инициализация переменной со строгой логикой
string accessStatus = (userAge >= 18) ? "Доступ разрешен" : "Доступ запрещен";
```

#### Встраивание в математические и строковые выражения
Тернарную операцию можно использовать прямо внутри передачи аргументов в методы вывода на консоль (`Console.WriteLine`) или математические функции.

```csharp
int itemsCount = 3;
// Вывод текста с правильным согласованием окончания в зависимости от числа
Console.WriteLine($"В корзине {itemsCount} товар{(itemsCount == 1 ? "" : (itemsCount >= 2 && itemsCount <= 4 ? "а" : "о"))}.");
```
*(Примечание: для сложных языковых правил лучше использовать полноценные методы, но для простых случаев такой подход применяется часто).*

### Сравнение производительности и читаемости if-else и тернарного оператора

Студенты часто задают вопрос: работает ли тернарная операция быстрее, чем классический `if-else`? 

На уровне исходного байт-кода промежуточного языка CIL (Common Intermediate Language), в который компилируется программа на C#, конструкции `if-else` и тернарная операция транслируются практически в идентичные инструкции условных и безусловных переходов (`brfalse`, `br`). Современный компилятор Roslyn и среда выполнения .NET (JIT-компилятор) оптимизируют оба варианта до абсолютно одинакового машинного кода. 

Следовательно, с точки зрения **производительности** никакой разницы между `if-else` и тернарной операцией **нет**. Выбор между ними обусловлен исключительно соображениями читаемости кода и архитектуры.

| Критерий | Конструкция `if-else` | Тернарная операция `? :` |
|---|---|---|
| **Синтаксическая категория** | Инструкция (Statement) | Выражение (Expression) |
| **Область применения** | Сложные ветвления, выполнение блоков кода из нескольких инструкций | Простое присваивание значения, выбор одного из двух результатов |
| **Читаемость при большой длине** | Высокая (понятная блочная структура) | Низкая (превращается в «кашу» при вложенности) |
| **Использование внутри выражений** | Невозможно | Возможно (внутри других формул и вызовов) |

### Разобранные примеры

#### Пример 1. Нахождение модуля числа без класса Math

**Условие задачи:**
Написать программу на C#, которая запрашивает у пользователя целое число `a`, вычисляет его модуль (абсолютную величину) с помощью тернарной операции, не используя встроенный класс `Math`, и выводит результат на экран.

**Рисунок словами:**
В консоли появляется строка с запросом ввода. Пользователь вводит целое число (например, `-14` или `25`). Программа анализирует число: если оно меньше нуля, меняет его знак на противоположный путем умножения на `-1`, в противном случае оставляет без изменений. На экран выводится строка с полученным модулем числа.

**Ход рассуждений:**
1. Модуль числа $a$ определяется математически как: если $a \ge 0$, то модуль равен $a$; если $a < 0$, то модуль равен $-a$.
2. В виде условия это записывается так: `a >= 0 ? a : -a`.
3. Нам нужно принять строку из консоли (`Console.ReadLine()`), преобразовать ее в целое число типа `int` с помощью `int.Parse()`.
4. Применить тернарную операцию для расчета модуля и записать результат в новую переменную `absA`.
5. Вывести результат на экран.

**Решение в общем виде:**
```csharp
int a = // введенное число;
int absA = (a >= 0) ? a : -a;
```

**Полный компилируемый код программы:**

```csharp
using System;

namespace AbsoluteValueApp
{
    class Program
    {
        static void Main(string[] args)
        {
            // Установка кодировки для корректного отображения кириллицы
            Console.OutputEncoding = System.Text.Encoding.UTF8;

            Console.Write("Введите целое число a: ");
            string input = Console.ReadLine();

            // Безопасное преобразование введенной строки в целое число
            if (int.TryParse(input, out int a))
            {
                // Вычисление модуля с помощью тернарной операции
                int absA = (a >= 0) ? a : -a;

                Console.WriteLine($"Модуль введенного числа равен: {absA}");
            }
            else
            {
                Console.WriteLine("Ошибка: введено некорректное целое число.");
            }
        }
    }
}
```

**Проверка (единицы, правдоподобность):**
- *Тест 1 (положительное число):* Введем `12`. Условие `12 >= 0` истинно, возвращается `12`. Модуль корректен.
- *Тест 2 (отрицательное число):* Введем `-7`. Условие `-7 >= 0` ложно, срабатывает ветвь ложности: `-(-7) = 7`. Модуль корректен.
- *Тест 3 (ноль):* Введем `0`. Условие `0 >= 0` истинно, возвращается `0`. Модуль корректен.

`Ответ:` Программа успешно находит модуль числа с использованием тернарной операции `(a >= 0) ? a : -a`.

#### Пример 2. Определение знака числа с использованием вложенной тернарной операции

**Условие задачи:**
Написать программу, которая принимает с клавиатуры целое число и определяет его знак. Программа должна выводить текстовое сообщение: «Положительное число», «Отрицательное число» или «Нуль». Использовать вложенную тернарную операцию. Запрещено использовать классические операторы `if-else` для ветвления знака.

**Рисунок словами:**
Пользователь вводит в консоль число. Программа считывает его, проверяет первое условие: больше ли число нуля. Если да — фиксирует строку «Положительное число». Если нет — переходит ко второй проверке: меньше ли число нуля. Если да — фиксирует «Отрицательное число». Если и это условие неверно — фиксирует «Нуль». Итоговая строка выводится на консоль.

**Ход рассуждений:**
1. Нам нужно получить три возможных текстовых варианта ответа в зависимости от одного числового параметра.
2. Составим первое звено тернарной операции для проверки на положительность: `number > 0 ? "Положительное число" : ...`
3. В случае ложности первого условия (число не больше нуля, то есть меньше или равно нулю) вместо второго значения подставим еще одну тернарную операцию, проверяющую на отрицательность: `number < 0 ? "Отрицательное число" : "Нуль"`.
4. Объединим всё в единое выражение: 
   `string signMessage = (number > 0) ? "Положительное число" : ((number < 0) ? "Отрицательное число" : "Нуль");`

**Полный компилируемый код программы:**

```csharp
using System;

namespace NumberSignApp
{
    class Program
    {
        static void Main(string[] args)
        {
            Console.OutputEncoding = System.Text.Encoding.UTF8;

            Console.Write("Введите целое число для определения знака: ");
            string input = Console.ReadLine();

            if (int.TryParse(input, out int number))
            {
                // Использование вложенной тернарной операции для классификации знака
                string signMessage = (number > 0) 
                    ? "Положительное число" 
                    : ((number < 0) ? "Отрицательное число" : "Нуль");

                Console.WriteLine($"Результат: {signMessage}");
            }
            else
            {
                Console.WriteLine("Ошибка ввода. Пожалуйста, введите целое число.");
            }
        }
    }
}
```

**Оценка сложности:**
- Время работы алгоритма: $O(1)$ (выполняется фиксированное число операций сравнения независимо от размера числа).
- Память: $O(1)$ (используется минимальное количество переменных для хранения числа и строки ответа).

**Проверка:**
- *Ввод:* `105`. Проверка `105 > 0` дает `true`. `Ответ:` Положительное число. (Верно).
- *Ввод:* `-42`. Проверка `-42 > 0` дает `false`. Переходим во вложенную часть: `-42 < 0` дает `true`. `Ответ:` Отрицательное число. (Верно).
- *Ввод:* `0`. Проверка `0 > 0` дает `false`. Переходим во вложенную часть: `0 < 0` дает `false`, возвращается `"Нуль"`. `Ответ:` Нуль. (Верно).

`Ответ:` Программа корректно определяет знак числа, используя вложенную тернарную операцию, и выводит соответствующее текстовое сообщение.

## 5. Оператор выбора switch и современные switch-выражения в C#

### 1. Классический оператор `switch` в C#

Когда в программе возникает необходимость проверить одну переменную на равенство множеству конкретных константных значений, использование длинных каскадных конструкций `if-else-if` делает код громоздким и трудным для чтения. Для таких сценариев в языке C# предусмотрен специальный оператор множественного выбора — `switch`.

> **Определение.** Оператор `switch` — это управляющая конструкция языка программирования, которая сравнивает значение заданного выражения с набором константных шаблонов (меток) и передает управление блоку кода, соответствующему первому совпадению.

Синтаксис классического оператора `switch` выглядит следующим образом:

```csharp
switch (выражение)
{
    case значение1:
        // Блок кода, выполняемый, если выражение == значение1
        break;
    case значение2:
    case значение3:
        // Блок кода, выполняемый, если выражение == значение2 ИЛИ значение3
        break;
    default:
        // Блок кода, выполняемый, если ни одно из значений не подошло
        break;
}
```

Рассмотрим назначение каждого ключевого элемента конструкции:
- `выражение` — проверяемое выражение. Его тип может быть целым числом (`int`, `long`, `short`, `byte`), символом (`char`), строкой (`string`), перечислением (`enum`) или ссылочным типом.
- `case` (случай) — метка, за которой следует константное значение. Если значение управляющего выражения совпадает со значением после `case`, выполнение программы переходит к этому блоку.
- `break` (прерыв) — оператор перехода, который указывает компилятору, что выполнение конструкции `switch` следует завершить и выйти за ее пределы. Наличие `break` в конце каждой ветви является обязательным требованием компилятора C# для непустых блоков.
- `default` (по умолчанию) — необязательная ветвь, которая срабатывает тогда, когда значение выражения не совпало ни с одной из указанных меток `case`. Это аналог заключительной ветви `else` в каскадных ветвлениях.

---

### 2. Особенность обработки провала выполнения (`fall-through`)

В языках программирования C и C++ существовало поведение, при котором после выполнения кода одной метки `case` программа автоматически переходила к выполнению следующей ветви, если отсутствовал оператор прерывания. Это часто приводило к трудноуловимым логическим ошибкам, известным как непреднамеренный провал выполнения (*fall-through*).

Создатели языка C# учли этот опыт и ввели строгое правило: **в C# прямой переход из одной непустой ветви `case` в другую категорически запрещен**. Если ветвь `case` содержит хотя она бы один исполняемый оператор (например, вывод в консоль или присваивание значения), она обязана завершаться оператором управления переходом (`break`, `return`, `throw` или `goto`).

Исключением являются пустые ветви `case`. Если несколько меток `case` идут подряд без кода между ними, они объединяются, образуя логическое ИЛИ для проверяемых значений:

```csharp
int day = 6;
switch (day)
{
    case 6:
    case 7:
        Console.WriteLine("Выходной день");
        break;
    default:
        Console.WriteLine("Будний день");
        break;
}
```

В данном примере, если переменная `day` равна `6` или `7`, выполнится общий блок кода вывода строки `"Выходной день"`, после чего сработает обязательный `break`.

---

### 3. Сопоставление с образцом (*Pattern Matching*) в `switch`

Начиная с версии C#, возможности оператора `switch` вышли далеко за рамки простого сравнения на равенство с константами. Благодаря механизму сопоставления с образцом (*pattern matching*), оператор `switch` может проверять типы данных, структуру объектов и применять сложные условия прямо в метках `case`.

Рассмотрим основные виды шаблонов, доступных в современных версиях C#:
1. **Константный шаблон (Constant Pattern):** проверка на точное равенство фиксированному значению (`case 0:` или `case "admin":`).
2. **Шаблон типа (Type Pattern):** проверка того, что выражение имеет определенный тип данных, с одновременным объявлением переменной для этого значения:
   ```csharp
   object obj = "Привет";
   switch (obj)
   {
       case int i:
           Console.WriteLine($"Целое число: {i * 2}");
           break;
       case string s:
           Console.WriteLine($"Строка длиной {s.Length}");
           break;
       default:
           Console.WriteLine("Неизвестный тип");
           break;
   }
   ```
3. **Шаблон свойства (Property Pattern):** проверка внутренних свойств объекта без вызова громоздких методов.

---

### 4. Защитные условия с ключевым словом `when`

Иногда базового сравнения значений недостаточно, и для срабатывания конкретной ветви `case` требуется проверить дополнительное булево условие. Для этой цели в конструкции `switch` используется ключевое слово `when`.

> **Определение.** Защитное условие (`when`) — это дополнительное логическое выражение, которое добавляется к шаблону `case` и разрешает выполнение ветви только в том случае, если основное сопоставление истинно **и** выражение после `when` возвращает значение `true`.

Пример использования защитного условия в классическом операторе `switch`:

```csharp
int temperature = -5;
switch (temperature)
{
    case < 0 when temperature < -20:
        Console.WriteLine("Сильный мороз");
        break;
    case < 0:
        Console.WriteLine("Обычный мороз");
        break;
    default:
        Console.WriteLine("Тепло или ноль");
        break;
}
```

Здесь для отрицательных температур введено дополнительное разграничение через конструкцию `when temperature < -20`.

---

### 5. Современные `switch`-выражения

Начиная с C# 8.0, в язык были добавлены **`switch`-выражения** (в отличие от инструкций `switch`). Главное отличие заключается в том, что `switch`-выражение возвращает результат, который можно сразу присвоить переменной, использовать в методе или передать в другое выражение.

Синтаксис `switch`-выражения существенно короче классического:
- Ключевое слово `switch` ставится **после** проверяемого выражения.
- Вместо двоеточия после шаблона используется стрелочная нотация (`=>`).
- Метки `case` не пишутся.
- Операторы `break` не нужны.
- Ветвь `default` заменяется универсальным шаблоном отброса (`_`).
- Все ветви перечисляются внутри фигурных скобок через запятую.

Общий вид `switch`-выражения:

```csharp
string result = variable switch
{
    pattern1 => expression1,
    pattern2 when condition => expression2,
    _ => defaultExpression
};
```

### 6. Сравнение производительности и читаемости `if-else-if` и `switch`

При проектировании архитектуры программы часто возникает вопрос: что выбрать — громоздкий каскад `if-else-if` или оператор `switch`?

| Критерий | Конструкция `if-else-if` | Оператор `switch` / `switch`-выражение |
|---|---|---|
| **Читаемость при множестве вариантов** | Низкая (код сильно сдвигается вправо, много дублирования имен переменных) | Высокая (компактная структура, сосредоточение на значениях) |
| **Гибкость условий** | Максимальная (в каждом `if` могут быть совершенно разные независимые логические выражения) | Ограниченная логика равенства или шаблонов (хотя `when` частично решает эту проблему) |
| **Компиляция и оптимизация** | Выполняется последовательная проверка условий сверху вниз ($O(N)$ в худшем случае) | Компилятор C# оптимизирует структуру: для плотных диапазонов строит табличные прыжки (*jump tables*), для строк — хеш-таблицы ($O(1)$ или $O(\log N)$) |

**Правило выбора:** Если проверяется одна переменная на равенство различным константам (более 2-3 вариантов), всегда предпочтительнее использовать `switch` или современное `switch`-выражение. Если условия разнородные (например, `if (x > 0 && y < 5 || z == 10)`), следует использовать каскад `if-else`.

### Разобранные примеры

#### Пример 1: Определение времени года по номеру месяца

**Условие:**
Написать консольную программу на языке C#, которая запрашивает у пользователя целое число — номер месяца (от 1 до 12). С помощью классического оператора `switch` программа должна определить и вывести в консоль соответствующее время года: «Зима», «Весна», «Лето» или «Осень». Если введено число, не входящее в диапазон от 1 до 12, программа должна вывести сообщение об ошибке.

**Рисунок словами:**
1. Вывод приглашения в консоль: `Введите номер месяца (1-12): `.
2. Считывание строки, преобразование ее в целое число типа `int`.
3. Анализ полученного числа с помощью `switch`:
   - Значения `12`, `1`, `2` направляются в блок «Зима».
   - Значения `3`, `4`, `5` направляются в блок «Весна».
   - Значения `6`, `7`, `8` направляются в блок «Лето».
   - Значения `9`, `10`, `11` направляются в блок «Осень».
   - Все остальные значения попадают в блок `default` («Ошибка»).
4. Вывод результата на экран.

**Ход рассуждений:**
Поскольку мы проверяем одну целочисленную переменную `month` на совпадение с фиксированными наборами дискретных значений, классический оператор `switch` подходит идеально. Для объединения месяцев, принадлежащих одному сезону, мы используем сквозные пустые метки `case` без операторов прерывания, что избавляет нас от дублирования кода вывода.

**Решение в общем виде:**
```csharp
using System;

class Program
{
    static void Main()
    {
        Console.Write("Введите номер месяца (1-12): ");
        int month = int.Parse(Console.ReadLine());

        switch (month)
        {
            case 12:
            case 1:
            case 2:
                Console.WriteLine("Зима");
                break;
            case 3:
            case 4:
            case 5:
                Console.WriteLine("Весна");
                break;
            case 6:
            case 7:
            case 8:
                Console.WriteLine("Лето");
                break;
            case 9:
            case 10:
            case 11:
                Console.WriteLine("Осень");
                break;
            default:
                Console.WriteLine("Ошибка: введено неверное число!");
                break;
        }
    }
}
```

**Пример ввода и вывода:**
*Ввод:*
```text
7
```
*Вывод:*
```text
Лето
```

*Ввод:*
```text
15
```
*Вывод:*
```text
Ошибка: введено неверное число!
```

**Проверка и оценка сложности:**
- Временная сложность: $O(1)$, так как компилятор оптимизирует выборку констант.
- Пространственная сложность: $O(1)$, используется одна скалярная переменная `month`.
- Правдоподобие: Все 12 месяцев распределены по временам года корректно. Ошибочные данные перехватываются ветвью `default`.

#### Пример 2: Перевод цифровой оценки в текстовое описание с использованием современного `switch`-выражения

**Условие:**
Написать консольную программу на языке C#, которая принимает от пользователя целое число, представляющее школьную отметку от 2 до 5. Используя современное `switch`-выражение со стрелочной нотацией, перевести цифру в словесное описание: `2` — «Неудовлетворительно», `3` — «Удовлетворительно», `4` — «Хорошо», `5` — «Отлично». Если введена любая другая цифра или число, результатом должна быть строка «Неизвестная оценка».

**Рисунок словами:**
1. Запрос оценки у пользователя: `Введите отметку (от 2 до 5): `.
2. Чтение ввода и парсинг в переменную `int mark`.
3. Передача переменной `mark` в `switch`-выражение, которое возвращает строковое значение (`string description`).
4. Вывод полученной строки на консоль.

**Ход рассуждений:**
Здесь мы решаем задачу получения значения на основе сопоставления шаблонов. Поскольку современное `switch`-выражение позволяет вернуть результат напрямую, мы можем записать всю логику преобразования компактно в одну инструкцию присваивания, используя универсальный шаблон `_` для обработки неверных входных данных.

**Решение в общем виде:**
```csharp
using System;

class Program
{
    static void Main()
    {
        Console.Write("Введите отметку (от 2 до 5): ");
        int mark = int.Parse(Console.ReadLine());

        string description = mark switch
        {
            2 => "Неудовлетворительно",
            3 => "Удовлетворительно",
            4 => "Хорошо",
            5 => "Отлично",
            _ => "Неизвестная оценка"
        };

        Console.WriteLine($"Результат: {description}");
    }
}
```

**Пример ввода и вывода:**
*Ввод:*
```text
4
```
*Вывод:*
```text
Результат: Хорошо
```

*Ввод:*
```text
9
```
*Вывод:*
```text
Результат: Неизвестная оценка
```

**Проверка и оценка сложности:**
- Временная сложность: $O(1)$.
- Пространственная сложность: $O(1)$.
- Правдоподобие: Соответствие цифровых оценок текстовым строкам строго соответствует принятой системе оценивания. Использование символа отброса `_` гарантирует отсутствие исключений `SwitchExpressionException` при вводе непредусмотренных чисел.

## Типичные ошибки

1. **Путаница между оператором присваивания `=` и оператором сравнения `==`.**
   * *Почему возникает:* Начинающие программисты часто используют одинарный знак равенства в условных конструкциях (`if (x = 5)`). В языке C# это вызывает ошибку компиляции, если переменная `x` не имеет типа `bool`, так как `=` возвращает присваиваемое значение, а не проверяет равенство.
   * *Как избежать:* Всегда используйте двойной знак равенства `==` для проверки равенства двух величин. Помните: `=` — это действие («положить в ячейку»), а `==` — это вопрос («равно ли?»).
   * *Пример ошибки:* `if (score = 100)` $\rightarrow$ *Ошибка компиляции*. Корректно: `if (score == 100)`.

2. **Точка с запятой сразу после условия `if`.**
   * *Почему возникает:* Автоматическая расстановка символов или невнимательность приводит к появлению лишней точки с запятой в конце строки с условием.
   * *Как избежать:* Никогда не ставьте точку с запятой `(;)` сразу после закрывающей круглой скобки условия `if (...)`. Точка с запятой завершает пустую инструкцию, в результате чего тело условного оператора начинает выполняться безусловно.
   * *Пример ошибки:* `if (x > 0); { Console.WriteLine("Положительное"); }` — это сообщение выведется всегда, независимо от значения `x`.

3. **Сравнение вещественных чисел типа `double` через точное равенство `==`.**
   * *Почему возникаеть:* Интуитивное ожидание абсолютной точности вычислений с десятичными дробями. Из-за особенностей двоичного представления мантиссы в памяти компьютера результат сложения `0.1 + 0.2` не равен точно `0.3`.
   * *Как избежать:* Никогда не используйте оператор `==` для `double`. Проверяйте абсолютную разность чисел с помощью заданной погрешности эпсилон: `Math.Abs(a - b) < 0.000001`.
   * *Пример ошибки:* `if (0.1 + 0.2 == 0.3)` вернет `false`.

4. **Отсутствие фигурных скобок `{}` для многострочных блоков кода в `if-else`.**
   * *Почему возникает:* Желание сэкономить строки кода. Если фигурные скобки опущены, компилятор считает частью ветки `if` только *самую первую* инструкцию сразу за ней.
   * *Как избежать:* Всегда берите тело веток `if` и `else` в фигурные скобки, даже если внутри всего одна строка. Это защитит программу при дальнейшем дописывании кода.
   * *Пример ошибки:* 
     ```csharp
     if (isActive)
         Console.WriteLine("Активен");
         counter++; // Эта строка выполнится ВСЕГДА, разрушая логику
     ```

5. **Неправильный порядок условий в каскадных ветвлениях `if-else-if`.**
   * *Почему возникает:* Размещение частных условий после более общих. Поскольку каскад прерывается на первом же совпадении, специфические ветки становятся недостижимыми.
   * *Как избежать:* Всегда располагайте условия в порядке возрастания их строгости (от узких диапазонов к широким).
   * *Пример ошибки:* Сначала проверить `x > 0`, а затем `x > 100`. Любое число больше `100` вызовет срабатывание первой ветки, и вторая проверка никогда не выполнится.

6. **Нарушение правил видимости локальных переменных (области видимости).**
   * *Почему возникает:* Попытка использовать переменную, объявленную внутри блока `if` или `else`, за пределами этого блока.
   * *Как избежать:* Объявляйте переменные *до* начала условного оператора, если их значение требуется использовать в дальнейшем коде программы.

7. **Забытый оператор `break` в классическом операторе `switch`.**
   * *Почему возникает:* Привычка к языкам программирования со сквозным выполнением или простая спешка.
   * *Как избежать:* В языке C# каждая непустая ветвь `case` обязана заканчиваться оператором `break` (или `return`). Компилятор выдаст ошибку сборки, если вы забудете его поставить.

8. **Ошибки в приоритете логических операций и отсутствие скобок.**
   * *Почему возникает:* Незнание старшинства операций. Например, попытка написать сложное условие без группирующих скобок, полагаясь на интуицию.
   * *Как избежать:* Всегда используйте круглые скобки `()` для разделения логических блоков (`&&` и `||`). Это гарантирует предсказуемый порядок вычислений и делает код понятным для чтения.

## Задачи для самостоятельного решения

1. **Задача 1. Проверка попадания в интервал.** Написать программу, которая запрашивает у пользователя вещественное число $x$ и проверяет, принадлежит ли оно полуинтервалу $(-5; 10]$. Программа должна вывести в консоль логическое значение `true`, если принадлежит, и `false` в противном случае.
2. **Задача 2. Определение поры года.** Написать программу, которая принимает с клавиатуры целое число от $1$ до $12$, обозначающее номер месяца года, и с помощью оператора `switch` выводит название соответствующей поры года («Зима», «Весна», «Лето», «Осьминог» — шутка, «Осень»). Если введено число вне диапазона от $1$ до $12$, программа должна вывести «Ошибка: некорректный номер месяца».
3. **Задача 3. Квадратное уравнение.** Написать программу, которая запрашивает коэффициенты квадратного уравнения $A$, $B$ и $C$ (типа `double`). Вычислить дискриминант по формуле $D = B^2 - 4AC$. С помощью условного оператора `if-else` определить количество действительных корней: если $D > 0$, вывести «Два корня»; если $D == 0$ (с учетом погрешности `epsilon`), вывести «Один корень»; если $D < 0$, вывести «Корней нет».

Если сумма покупки превышает $5000$ условных единиц, предоставляется скидка $10\%$, в противном случае — скидка $3\%$. Используя тернарную операцию, вычислить итоговую сумму к оплате с учетом скидки и вывести ее на экран с точностью до двух знаков после запятой.
5. **Задача 5. Проверка високосного года.** Написать программу, которая запрашивает у пользователя год (целое число) и проверяет, является ли он високосным. Год является високосным, если он кратен $4$, но при этом не кратен $100$, а также если он кратен $400$. Использовать сложное логическое условие с операциями `&&`, `||` и `!`. Вывести `True` или `False`.
6. **Задача 6. Калькулятор тарифов связи.** Написать программу, которая рассчитывает стоимость телефонного разговора по трем тарифам оператора с помощью `switch`-выражения:
   - Код `1` (Тариф «Стандарт»): $3{,}5$ руб./мин;
   - Код `2` (Тариф «Ночной»): $1{,}8$ руб./мин (если время разговора ночью, иначе $2{,}5$ руб./мин — используйте защитное условие `when`);

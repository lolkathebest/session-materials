## 1. Анатомия типа string в C#: неизменяемость и размещение в памяти

### Анатомия типа string в C#: неизменяемость и размещение в памяти

В языке C# и платформе .NET работа с текстовой информацией является одной из самых частых задач. Для представления текста используется встроенный класс `string`, который обладает уникальными архитектурными особенностями. Чтобы писать эффективный и лишний багов код, необходимо понимать, как строки устроены изнутри, где они располагаются в оперативной памяти и как с ними взаимодействуют механизмы среды выполнения.

> **Определение.** Класс `string` — это ссылочный тип данных, представляющий собой неизменяемую последовательность символов в кодировке UTF-16, где каждый символ (`char`) занимает в памяти 2 байта (16 бит).

Несмотря на то, что `string` является ссылочным типом (ключевое слово `class` в базовой реализации платформы), синтаксис языка позволяет работать с ним во многом как с примитивным типом (например, доступна прямая инициализация литералами в кавычках: `string s = "текст";`).

### Размещение в памяти и концепция неизменяемости (Immutability)

Главная фундаментальная особенность строк в .NET — их полная **неизменяемость** (immutability). Это означает, что после того, как объект типа `string` был создан в памяти, его содержимое **нельзя изменить ни при каких обстоятельствах** в течение всего времени жизни этого объекта.

Рассмотрим, что происходит на уровне оперативной памяти при создании и модификации строки. Вся динамическая память в .NET делится на две основные области: стек (stack) и управляемую кучу (managed heap). 

Когда вы объявляете строковую переменную:

```csharp
string text = "Привет";
```

Происходят следующие шаги:
1. В стеке выделяется ячейка памяти под саму переменную `text` (ссылка).
2. В управляемой куче выделяется блок памяти под объект строки, который содержит:
   - служебную информацию среды выполнения (заголовок объекта и указатель на таблицу методов);
   - точную длину строки (количество символов);
   - последовательность самих символов в кодировке UTF-16: `П`, `р`, `и`, `в`, `е`, `т`.
3. Ссылка из стека записывает адрес этого блока памяти в куче.

Что произойдет, если мы попытаемся «изменить» эту строку, например, переведя её в верхний регистр?

```csharp
string upperText = text.ToUpper();
```

Многие начинающие программисты ошибочно полагают, что метод `ToUpper()` находит объект в куче и перезаписывает символы на заглавные. **Это не так.** 
Поскольку строка неизменяема, среда выполнения делает следующее:
1. Выделяет **совершенно новый блок памяти** в управляемой куче.
2. Записывает в этот новый блок новые символы: `П`, `Р`, `И`, `В`, `Е`, `Т`.
3. Возвращает адрес нового объекта, который сохраняется в переменной `upperText`.
4. Старый объект со строкой `"Привет"` остается в куче в неизменном виде (до тех пор, пока его не удалит сборщик мусора, если на него больше нет ссылок).

Абсолютно любая операция, которая якобы «модифицирует» строку (конкатенация, замена символов, обрезка пробелов), на самом деле порождает **новый объект** в памяти. Это накладывает серьезные требования на производительность программ при частой обработке текста.

### Интернирование строк (String Interning)

Поскольку строки неизменяемы, одинаковые текстовые литералы могут занимать лишнюю память в куче, если создавать их заново каждый раз. Для оптимизации памяти в .NET используется механизм **интернирования строк** (string interning).

Среда выполнения .NET поддерживает специальную таблицу в памяти — **пул строк** (intern pool). Когда компилятор встречает строковый литерал (например, `"Стандарт"`), он проверяет, есть ли такой же текст в пуле строк:
- Если текст уже есть, новая память в куче не выделяется. Переменной присваивается ссылка на уже существующий в пуле объект.
- Если текста нет, он добавляется в пул, и ссылка направляется на него.

Благодаря этому одинаковые строковые литералы в разных частях программы могут ссылаться на один и тот же участок памяти в куче. Вы можете управлять этим вручную с помощью метода `string.Intern(string str)` (добавляет строку в пул во время выполнения) и `string.IsInterned(string str)` (проверяет, находится ли строка в пуле).

### Сравнение строк: оператор `==` против метода `ReferenceEquals`

Из-за того, что `string` — ссылочный тип, вопрос сравнения строк требует особого внимания. Для любых других ссылочных типов (например, пользовательских классов) оператор `==` по умолчанию сравнивает **адреса в памяти** (ссылки), а не содержимое объектов. 

Однако для класса `string` разработчики языка C# перегрузили оператор `==`.

- **Оператор `==` (и метод `Equals`)** для строк сравнивают **содержимое** (посимвольно значение текста). Если в двух разных ячейках памяти кучи записаны абсолютно одинаковые символы (`"Код"` и `"Код"`), оператор `==` вернет `true`.
- **Метод `object.ReferenceEquals(object a, object b)`** проверяет именно **ссылки** — указывают ли две переменные на один и тот же физический объект в куче.

Пример для понимания разницы:

```csharp
string s1 = "Программирование";
string s2 = "Программирование"; // Сработает интернирование, ссылки одинаковы

char[] letters = { 'П', 'р', 'о', 'г', 'р', 'а', 'м', 'м', 'и', 'р', 'о', 'в', 'а', 'н', 'и', 'е' };
string s3 = new string(letters); // Явное создание нового объекта в куче через массив

bool contentEqual = (s1 == s3);             // true, так как содержимое одинаково
bool sameReference1 = ReferenceEquals(s1, s2); // true, один объект из пула интернирования
bool sameReference2 = ReferenceEquals(s1, s3); // false, s3 — это отдельный объект в куче
```

### Индексация и доступ к символам (`[i]`)

Поскольку строка представляет собой упорядоченную последовательность символов, к каждому конкретному символу можно обратиться по его индексу (порядковому номеру), начиная с **нуля**. 

Для доступа используется синтаксис квадратных скобок `[i]`. Полученный элемент имеет тип `char`.

```csharp
string word = "Компьютер";
char firstChar = word[0]; // 'К' (нулевой индекс)
char fourthChar = word[3]; // 'п' (индекс 3)
```

Поскольку строки неизменяемы, попытка изменить символ по индексу вызовет ошибку компиляции:
```csharp
string word = "Компьютер";
// word[0] — ОШИБКА КОМПИЛЯЦИИ: Свойство или индексатор нельзя присвоить (доступ только для чтения)
```

В C# 8.0 и новее поддерживаются также индексы с конца (оператор `^`) и диапазоны (оператор `..`):
- `word[^1]` — последний символ строки (`'р'`).
- `word[^2]` — предпоследний символ (`'е'`).

### Основные свойства: `Length`, `IsNullOrEmpty`, `IsNullOrWhiteSpace`

Для базового анализа строк класс предоставляет важные свойства и статические методы:

1. **Свойство `Length`** — возвращает общее количество символов в строке (тип `int`). Вычисление происходит за константное время $O(1)$, так как длина хранится внутри объекта.
   ```csharp
   int len = "Тест".Length; // 4
   ```

2. **Статический метод `string.IsNullOrEmpty(string value)`** — проверяет, является ли строка равной `null` либо пустой (`""` с длиной ноль). Возвращает `bool`.
   ```csharp
   string s = null;
   bool check = string.IsNullOrEmpty(s); // true
   ```

3. **Статический метод `string.IsNullOrWhiteSpace(string value)`** — проверяет, является ли строка пустой, состоящей исключительно из пробельных символов (пробелы, табуляции, переводы строк), либо равной `null`.
   ```csharp
   string s = "   \t \n ";
   bool check = string.IsNullOrWhiteSpace(s); // true
   ```

### Приведение типов и экранирование спецсимволов

При работе со строками часто возникает необходимость преобразовать другие типы данных в текст и наоборот.
- Преобразование любого типа в строку выполняется через метод `.ToString()` или интерполяцию.
- Преобразование строки в числовые типы выполняется через методы `int.Parse()`, `double.Parse()` или безопасный `int.TryParse()`.

Чтобы внедрить в строку специальные символы (перевод строки, табуляцию, кавычки), используется **экранирование** с помощью обратного слэша `\`:
- `\n` — перевод строки (Line Feed);
- `\t` — табуляция;
- `\\` — символ обратного слэша;
- `\"` — двойная кавычка внутри строки.

Если слэшей слишком много (например, при указании путей к файлам на диске), можно использовать **буквальные (literal) строки**, добавляя символ `@` перед кавычками:
```csharp
string normalPath = "C:\\Programs\\App\\bin";
string verbatimPath = @"C:\Programs\App\bin"; // Экранировать не нужно
```

#### Условие задачи
Написать консольную программу на C#, которая:
1. Создает строковую переменную со значением `"Программирование"`.
2. Выводит на экран длину этой строки, первый и последний символы.
3. Демонстрирует создание нового объекта в памяти при изменении регистра с помощью метода `ToUpper()`, проверяя равенство содержимого через оператор `==` и равенство ссылок через метод `ReferenceEquals`.

#### Рисунок схемы памяти (в текстовом виде)

```
Стек (Stack)                        Управляемая Куча (Managed Heap)
┌──────────────┐                    ┌──────────────────────────────────────────────┐
│  text        │ ─────────────────> │ Объект 1: length = 16, "Программирование"    │
└──────────────┘                    └──────────────────────────────────────────────┘
                                                           ▲
┌──────────────┐                                           │ (исходная ссылка)
│  upperText   │ ─────────────────┐                        │
└──────────────┘                  │         ┌──────────────────────────────────────────────┐
                                  └───────> │ Объект 2: length = 16, "ПРОГРАММИРОВАНИЕ"    │
                                            └──────────────────────────────────────────────┘
```

#### Ход рассуждений
1. Инициализируем строку литералом `"Программирование"`. Среда выделяет память под объект в куче.
2. Обращаемся к свойству `.Length` для получения длины. Помним, что индексация с нуля, поэтому первый символ имеет индекс `0`, а последний — `Length - 1` (или с использованием индекса с конца `^1`).
3. Вызываем метод `ToUpper()`. Метод выделяет **новый** объект в куче с заглавными буквами и возвращает ссылку на него в переменную `upperText`.
4. Сравниваем исходную переменную `text` и новую `upperText` оператором `==` (ожидаем `false`, так как содержимое разное: строчные и заглавные буквы в C# различаются).
5. Сравниваем их же через `ReferenceEquals` (ожидаем `false`, так как это физически разные объекты в разных участках памяти кучи).

#### Полный исходный код программы (.NET 8, C#)

```csharp
using System;

namespace StringAnatomyDemo
{
    class Program
    {
        static void Main(string[] args)
        {
            // Установка кодировки консоли для корректного отображения кириллицы
            Console.OutputEncoding = System.Text.Encoding.UTF8;

            // 1. Создание строки
            string text = "Программирование";
            Console.WriteLine($"Исходная строка: {text}");

            // 2. Анализ длины, первого и последнего символов
            int length = text.Length;
            char firstChar = text[0];
            char lastChar = text[^1]; // Использование индекса с конца (C# 8.0+)

            Console.WriteLine($"Длина строки: {length}");
            Console.WriteLine($"Первый символ: {firstChar}");
            Console.WriteLine($"Последний символ: {lastChar}");

            // 3. Демонстрация создания нового объекта в памяти при изменении регистра
            string upperText = text.ToUpper();
            Console.WriteLine($"Строка в верхнем регистре: {upperText}");

            // 4. Проверка содержимого и ссылок
            bool contentsAreEqual = (text == upperText);
            bool referencesAreTheSame = object.ReferenceEquals(text, upperText);

            Console.WriteLine();
            Console.WriteLine($"Равенство содержимого (text == upperText): {contentsAreEqual}");
            Console.WriteLine($"Равенство ссылок в памяти (ReferenceEquals): {referencesAreTheSame}");
            
            // Объяснение результата:
            // contentsAreEqual будет false, так как 'п' != 'П'.
            // referencesAreTheSame будет false, так как ToUpper() создал абсолютно новый объект в куче.
        }
    }
}
```

- **Единицы измерения:** Длина строки выражена целым числом (`int`), символы — типом `char` (UTF-16).
- **Правдоподобность:** Логика работы метода `ToUpper()` полностью подтверждена: ссылки и содержимое различаются, что доказывает концепцию неизменяемости объектов типа `string` в управляемой куче .NET.

Ответ: Программа корректно демонстрирует ссылочную природу неизменяемых строк, безопасный доступ по индексам, а также разделение понятий равенства ссылок и равенства содержимого.

## 2. Базовые методы класса string для анализа и поиска

### 1. Поиск подстрок и проверка границ: методы IndexOf, LastIndexOf, Contains, StartsWith и EndsWith

При разработке приложений часто возникает необходимость не просто хранить текст, но и анализировать его содержимое: проверять, начинается ли строка с определенного префикса, содержит ли она ключевое слово или где именно в тексте располагается искомый символ. Класс `string` в C# предоставляет для этого богатый набор встроенных методов.

> **Определение.** Методы поиска и проверки границ строки — это члены класса `string`, предназначенные для определения позиций символов/подстрок или логической проверки соответствия текста заданным критериям без изменения самого исходного объекта.

Рассмотрим каждый метод подробно:

1. **`Contains(string value)`** и **`Contains(char value, StringComparison comparisonType)`** — проверяет, содержится ли указанная подстрока (или символ) внутри текущей строки. Возвращает булево значение `true`, если фрагмент найден, и `false` в противном случае.
   * Сигнатура: `public bool Contains(string value)`
   * Временная сложность: $O(N \cdot M)$, где $N$ — длина исходной строки, $M$ — длина искомой подстроки (в худшем случае при простом поиске).

2. **`IndexOf(...)`** — возвращает индекс (порядковый номер, начиная с нуля) первого вхождения указанного символа или подстроки. Если искомый элемент отсутствует в тексте, метод возвращает `-1`.
   * Перегрузки: ищет с начала строки, может принимать стартовый индекс для поиска (`startIndex`) и параметры правильности сравнения (`StringComparison`).
   * Временная сложность: $O(N \cdot M)$.

3. **`LastIndexOf(...)`** — выполняет поиск последнего вхождения символа или подстроки, просматривая текст с конца к началу. Возвращает индекс начала найденного вхождения или `-1`.
   * Временная сложность: $O(N \cdot M)$.

4. **`StartsWith(string value)`** — проверяет, начинается ли строка с указанной подстроки. Возвращает `true` или `false`.
   * Временная сложность: $O(M)$, где $M$ — длина префикса.

5. **`EndsWith(string value)`** — проверяет, заканчивается ли строка указанной подстрокой.
   * Временная сложность: $O(M)$, где $M$ — длина суффикса.

Ниже приведен пример использования этих методов для анализа строки:

```csharp
using System;

class Program
{
    static void Main()
    {
        string text = "Информационные системы и технологии";

        // Проверка вхождения подстроки
        bool hasSystems = text.Contains("системы"); // true
        bool hasDatabase = text.Contains("База");   // false

        // Поиск индексов
        int firstSpace = text.IndexOf(' ');          // Индекс первого пробела (13)
        int lastOfChar = text.LastIndexOf('и');       // Последнее вхождение буквы 'и' (32)
        int subIndex = text.IndexOf("технологии");    // Индекс начала слова "технологии" (24)

        // Проверка границ
        bool startsWithInfo = text.StartsWith("Информ"); // true
        bool endsWithTech = text.EndsWith("технологии");   // true

        Console.WriteLine($"Содержит 'системы': {hasSystems}");
        Console.WriteLine($"Первый пробел на позиции: {firstSpace}");
        Console.WriteLine($"Последняя буква 'и' на позиции: {lastOfChar}");
        Console.WriteLine($"Начинается с 'Информ': {startsWithInfo}");
    }
}
```

**Пример ввода и вывода:**
* Ввод (вшитый в код): `string text = "Информационные системы и технологии";`
* Вывод консоли:
  ```text
  Содержит 'системы': True
  Первый пробел на позиции: 13
  Последняя буква 'и' на позиции: 32
  Начинается с 'Информ': True
  ```

### 2. Извлечение фрагментов: метод Substring

После того как позиции нужных элементов найдены с помощью методов `IndexOf` или `LastIndexOf`, часто требуется вырезать определенный фрагмент текста. Для этой цели служит метод `Substring`.

> **Определение.** `Substring` — это метод класса `string`, который создает и возвращает новую строку, являющуюся подстрокой текущей строки, начиная с указанной позиции и заданной длины.

У метода есть две основные перегрузки:

1. **`Substring(int startIndex)`**
   * Что делает: извлекает все символы от указанного индекса `startIndex` и до самого конца строки.
   * Исключения: выбрасывает `ArgumentOutOfRangeException`, если `startIndex < 0` или `startIndex >= text.Length`.

2. **`Substring(int startIndex, int length)`**
   * Что делает: извлекает ровно `length` символов, начиная с позиции `startIndex`.
   * Исключения: выбрасывает `ArgumentOutOfRangeException`, если `startIndex < 0`, `length < 0` или сумма `startIndex + length` превышает длину исходной строки.

Пример извлечения доменного имени из адреса электронной почты:

```csharp
using System;

class Program
{
    static void Main()
    {
        string email = "student_99@college.ru";
        
        // Находим индекс символа '@'
        int atIndex = email.IndexOf('@');
        
        // Извлекаем всё, что идет после '@' до конца строки
        string domain = email.Substring(atIndex + 1);
        
        // Извлекаем только логин (от начала 0 до atIndex)
        string login = email.Substring(0, atIndex);

        Console.WriteLine($"Логин: {login}");
        Console.WriteLine($"Домен: {domain}");
    }
}
```

* **Оценка сложности:** Временная и пространственная сложность метода `Substring` составляет $O(K)$, где $K$ — длина извлекаемого фрагмента (`length`), поскольку в памяти .NET выделяется новый буфер под создаваемую строку-результат.

### 3. Управление пробелами и регистрами: Trim, TrimStart, TrimEnd, ToLower, ToUpper

При получении пользовательского ввода данные часто содержат случайные пробелы по краям (например, при копировании из формы) или написаны в смешанном регистре.

> **Определение.** Методы очистки (`Trim`) и изменения регистра (`ToLower`, `ToUpper`) служат для нормализации текстовых данных, удаляя управляющие символы и пробелы по краям либо унифицируя регистр букв.

Список методов нормализации:
* **`Trim()`** — удаляет все пробельные символы (пробелы, табуляции, переносы строк) как в начале, так и в конце строки.
* **`TrimStart()`** — удаляет пробелы только в начале строки (слева).
* **`TrimEnd()`** — удаляет пробелы только в конце строки (справа).
* **`ToLower()`** — переводит все символы строки в нижний регистр (заглавные буквы становятся строчными).
* **`ToUpper()`** — переводит все символы строки в верхний регистр.

*Важное примечание:* Все эти методы не изменяют исходную строку (помните про неизменяемость `string`), а возвращают **новый** объект в памяти с внесенными изменениями.

```csharp
using System;

class Program
{
    static void Main()
    {
        string rawInput = "   Admin_Mode   \t\n";
        
        string cleanText = rawInput.Trim(); // "Admin_Mode"
        string lowerText = cleanText.ToLower(); // "admin_mode"
        string upperText = cleanText.ToUpper(); // "ADMIN_MODE"

        Console.WriteLine($"[{rawInput}] -> Очищено: [{cleanText}]");
        Console.WriteLine($"Нижний регистр: {lowerText}");
    }
}
```

### 4. Разделение строки на массив: метод Split

Когда строка представляет собой последовательность слов, разделенных пробелами, запятыми или другими разделителями, её необходимо разбить на отдельные элементы.

> **Определение.** Метод `Split` разделяет строку на массив подстрок (`string[]`) на основе заданных символов-разделителей или строк-разделителей.

Основные перегрузки метода `Split`:
1. `string.Split(params char[] separator)` — принимает массив символов (или перечисление через запятую), по которым происходит разрез.
2. `string.Split(string[] separator, StringSplitOptions options)` — принимает массив подстрок-разделителей и параметры обработки пустых результатов (например, `StringSplitOptions.RemoveEmptyEntries`, чтобы исключить пустые элементы при идущих подряд разделителях).

Пример разделения текста на отдельные слова:

```csharp
using System;

class Program
{
    static void Main()
    {
        string sentence = "C#; разработка, алгоритмы; структуры";
        
        // Разделяем по точкам с запятой и запятым с пробелами
        char[] separators = { ';', ',' };
        string[] words = sentence.Split(separators, StringSplitOptions.RemoveEmptyEntries);

        Console.WriteLine($"Найдено элементов: {words.Length}");
        foreach (string word in words)
        {
            // Очищаем внутренние пробелы после разделения
            Console.WriteLine($"- [{word.Trim()}]");
        }
    }
}
```

### 5. Соединение массива строк в единый текст: метод string.Join

Операция, обратная `Split` — это сборка массива или коллекции строк обратно в единый текст с вставкой разделителя между ними.

> **Определение.** Статический метод `string.Join(string separator, IEnumerable<T> values)` объединяет элементы коллекции или массива строк, вставляя между ними указанную строку-разделитель `separator`.

Пример объединения массива слов в предложение:

```csharp
using System;

class Program
{
    static void Main()
    {
        string[] words = { "Язык", "программирования", "CSharp" };
        
        // Объединяем слова через пробел
        string result = string.Join(" ", words);
        
        // Объединяем через дефис
        string hyphenResult = string.Join("-", words);

        Console.WriteLine(result);        // Язык программирования CSharp
        Console.WriteLine(hyphenResult);  // Язык-программирования-CSharp
    }
}
```

### 6. Обработка кодировок и символьных массивов: ToCharArray

Иногда для тонкой алгоритмической обработки строки (например, инвертирования или сортировки символов) удобнее работать не со строковым классом, а с классическим массивом символов (`char[]`).

> **Определение.** Метод `ToCharArray()` выделяет новый массив символов и копирует в него содержимое текущей строки посимвольно. Обратное преобразование выполняется через конструктор `new string(char[])`.

Пример конвертации строки в массив символов и обратно:

```csharp
using System;

class Program
{

    }
}
```

### Разобранный пример

> **Условие задачи.** Дана строка `'  Иванов Иван Иванович  '`. Написать программу на C#, которая очищает лишние пробелы по краям, разделяет ФИО на отдельные слова и выводит инициалы в формате `'Иванов И. И.'`.

#### Рисунок (схема) алгоритма в виде ASCII-диаграммы:
```text
[ Исходная строка с пробелами ]
       │
       ▼  .Trim()
[ "Иванов Иван Иванович" ]
       │
       ▼  .Split(' ')
[ "Иванов" ]  [ "Иван" ]  [ "Иванович" ]
    ([0])       ([1])         ([2])
       │          │             │
       └──────────┼─────────────┘
                  ▼
         [ Сборка результата: ]
  Фамилия + " " + Имя[0] + ". " + Отчество[0] + "."
                  │
                  ▼
         "Иванов И. И."
```

#### Ход рассуждений (почему делаем именно так):
1. **Очистка границ:** Сначала применим метод `Trim()`, чтобы избавиться от случайных пробелов в начале и в конце строки. Без этого массив, полученный после разделения, содержал бы пустые элементы по краям.
2. **Разделение на слова:** Используем метод `Split(' ')`, разделив строку по пробелу. Учитывая, что между словами может быть один пробел, в результате получим массив из трех элементов: `words[0] = "Иванов"`, `words[1] = "Иван"`, `words[2] = "Иванович"`. Опция `StringSplitOptions.RemoveEmptyEntries` подстрахует нас, если между словами случайно окажется два пробела подряд.
3. **Извлечение инициалов:** Из второго (`words[1]`) и третьего (`words[2]`) элементов нам нужен только первый символ. Мы можем извлечь его через индексацию символа в строке (`words[1][0]`) или через `Substring(0, 1)`.
4. **Форматирование выводной строки:** Соберем итоговую строку с помощью интерполяции строк, добавив точки после инициалов.

#### Полный исходный код программы:

```csharp
using System;

class FullNameFormatter
{
    static void Main()
    {
        // 1. Исходные данные
        string rawFio = "  Иванов Иван Иванович  ";

        // 2. Очищаем пробелы по краям
        string trimmedFio = rawFio.Trim();

        // 3. Разделяем строку на слова, удаляя возможные пустые элементы
        string[] parts = trimmedFio.Split(new char[] { ' ' }, StringSplitOptions.RemoveEmptyEntries);

        // Проверяем, что введено ровно 3 слова (Фамилия, Имя, Отчество)
        if (parts.Length >= 3)
        {
            string surname = parts[0];
            
            // Извлекаем первые буквы имени и отчества
            char nameInitial = parts[1][0];
            char patronymicInitial = parts[2][0];

            // 4. Формируем результат в нужном формате
            string result = $"{surname} {nameInitial}. {patronymicInitial}.";

            // 5. Выводим результат на консоль
            Console.WriteLine($"Результат: {result}");
        }
        else
        {
            Console.WriteLine("Ошибка: строка не содержит полных данных ФИО.");
        }
    }
}
```

#### Проверка и вычисления:
* **Единицы измерения:** В данной задаче работаем с размерностью строк (количеством символов). Ошибок несоответствия типов нет.
* **Правдоподобность:** 
  * `rawFio.Trim()` превращает `"  Иванов Иван Иванович  "` в `"Иванов Иван Иванович"`.
  * `Split` возвращает массив: `parts[0] = "Иванов"`, `parts[1] = "Иван"`, `parts[2] = "Иванович"`.
  * `parts[1][0]` дает символ `'И'`, `parts[2][0]` дает символ `'И'`.
  * Интерполяция `${surname} {nameInitial}. {patronymicInitial}.` собирает строку `"Иванов И. И."`.
* **Сложность алгоритма:** 
  * Временная сложность: $O(N)$, где $N$ — длина исходной строки (проход по символам при `Trim`, `Split` и копировании).
  * Пространственная сложность: $O(N)$ для хранения промежуточных массивов строк и результирующей строки в куче .NET.

*Ответ:* `Иванов И. И.`

## 3. Модификация строк и регулярные задачи обработки текста

### Замена подстрок: метод Replace

Часто при обработке текста возникает задача замены одних символов или фрагментов на другие. В классе `string` для этого предусмотрен метод `Replace()`.

> **Определение.** Метод `string.Replace(oldValue, newValue)` создаёт и возвращает **новую** строку, в которой все вхождения подстроки `oldValue` заменены на подстроку `newValue`.

Метод имеет две основные перегрузки:
1. `Replace(char oldChar, char newChar)` — заменяет все символы `oldChar` на `newChar`.
2. `Replace(string oldValue, string newValue)` — заменяет все вхождения подстроки `oldValue` на `newValue`.

Поскольку тип `string` в C# является неизменяемым (*immutable*), исходная строка не изменяется. Метод `Replace` возвращает ссылку на совершенно новый объект в управляемой куче (*managed heap*). Если подстрока `oldValue` не найдена в тексте, метод не выбрасывает исключение, а просто возвращает копию исходной строки.

Рассмотрим пример использования замены:

```csharp
string text = "Привет, мир! Мир прекрасен.";
string updatedText = text.Replace("Мир", "Край");
Console.WriteLine(updatedText); 
// Вывод: Привет, мир! Край прекрасен.
```

Обратите внимание: поиск регистрозависимый. Слово `"мир"` с маленькой буквы не было заменено, так как в качестве `oldValue` было передано `"Мир"`. Для замены без учета регистра требуется предварительное приведение к единому регистру или использование регулярных выражений (`System.Text.RegularExpressions.Regex`).

### Удаление и вставка фрагментов: методы Remove и Insert

Для изменения содержимого строки путем удаления или добавления символов в определенные позиции применяются методы `Remove()` и `Insert()`.

> **Определение.** Метод `string.Remove(startIndex, count)` возвращает новую строку, из которой удалено заданное количество символов `count`, начиная с индекса `startIndex`.

Если второй параметр `count` опущен (`string.Remove(startIndex)`), то удаляются все символы от указанной позиции `startIndex` до конца строки.

> **Определение.** Метод `string.Insert(startIndex, value)` возвращает новую строку, в которую вставлена подстрока `value`, начиная с позиции `startIndex`.

При вызове этих методов индекс `startIndex` должен находиться в диапазоне от `0` до `string.Length` (включительно для метода `Insert`). Если индекс выходит за пределы строки, среда выполнения .NET генерирует исключение `ArgumentOutOfRangeException`.

Рассмотрим работу с этими методами в коде:

```csharp
string original = "Программирование";
// Удаляем 5 символов начиная с индекса 6 (слово "миров")
string removed = original.Remove(6, 5); 
Console.WriteLine(removed); // Вывод: Програмние

// Вставляем подстроку на позицию 6
string inserted = original.Insert(6, " классное ");
Console.WriteLine(inserted); // Вывод: Программирование классное (корректнее: "Программирование" -> вставим в середину)
```

Правильный пример вставки в середину слова:
```csharp
string word = "Кот";
string result = word.Insert(2, "от"); 
Console.WriteLine(result); // Вывод: Котот
```

Обе операции также приводят к выделению памяти под новую строку, так как исходный объект `string` изменить нельзя.

### Форматирование строк: интерполяция и string.Format

Вывод данных на экран или формирование сложных текстовых сообщений из переменных требует удобных средств форматирования. В современном C# основным и наиболее читаемым стандартом является интерполяция строк.

> **Определение.** Интерполяция строк — это синтаксический сахар компилятора, позволяющий вставлять значения переменных и выражений прямо внутрь строкового литерала, предваренного символом `$`.

Выражения внутри строки заключаются в фигурные скобки `{}`. Компилятор C# автоматически преобразует такую конструкцию в вызов метода `string.Format()`.

```csharp
string name = "Алексей";
int age = 20;
// Интерполяция строк
string message = "Студент " + name + " имеет возраст " + age + " лет."; // Старый подход (конкатенация)
string modernMessage = $"Студент {name} имеет возраст {age} лет."; // Интерполяция
```

Внутри фигурных скобок можно указывать спецификаторы формата после двоеточия. Например, форматирование чисел с плавающей точкой, денежных единиц или дат:

```csharp
double pi = 3.1415926535;
// Вывести только 2 знака после запятой
string formattedPi = $"Значение Пи: {pi:F2}"; 
Console.WriteLine(formattedPi); // Вывод: Значение Пи: 3{,}14 (или с точкой в зависимости от локали)
```

Альтернативный метод `string.Format()` принимает шаблон строки с индексированными заполнителями `{0}`, `{1}` и набор аргументов:

```csharp
string result = string.Format("Код ошибки: {0}, Описание: {1}", 404, "Not Found");
```

Интерполяция строк предпочтительнее в большинстве случаев, так как она повышает читаемость кода и защищает от ошибок несоответствия индексов аргументов.

### Сравнение строк с учетом локали: Compare, CompareTo, Ordinal-сравнение

Сравнение строк — частая задача при сортировке и поиске, но в программировании она таит множество подводных камней, связанных с языковыми стандартами (локалью).

> **Определение.** Лексикографическое сравнение строк — это поэлементное сопоставление кодов символов с учетом правил конкретного языка или алфавита.

В C# для сравнения строк используются следующие инструменты:
1. Оператор `==` и метод `string.Equals()` — проверяют **точное равенство** содержимого с учетом регистра (по умолчанию) или заданного правила сравнения (`StringComparison`).
2. Метод `string.Compare(strA, strB)` — статический метод, возвращающий целое число:
   - меньше нуля, если `strA` предшествует `strB` в лексикографическом порядке;
   - ноль, если строки равны;
   - больше нуля, если `strA` следует за `strB`.
3. Метод `strA.CompareTo(strB)` — экземплярный аналог метода `Compare`.
4. Ordinal-сравнение (`StringComparison.Ordinal` / `StringComparison.OrdinalIgnoreCase`) — сравнение строго по числовым значениям кодов символов UTF-16, без учета правил национальных алфавитов. Это самый быстрый и надежный способ для сравнения технических строк (путей файлов, ключей, JSON-тегов).

Пример сравнения строк:

```csharp
string s1 = "apple";
string s2 = "banana";

int comparisonResult = s1.CompareTo(s2);
if (comparisonResult < 0)
{
    Console.WriteLine("Строка 'apple' идет раньше 'banana'");
}

// Сравнение идентификаторов без учета регистра и локали
bool areEqual = string.Equals("ID_001", "id_001", StringComparison.OrdinalIgnoreCase);
Console.WriteLine(areEqual); // Вывод: True
```

Использование языковых правил (*linguistic comparison*) может приводить к неожиданным результатам в разных операционных системах из-за различий в региональных настройках (например, как сортируются символы с диакритическими знаками), поэтому для служебных данных всегда рекомендуется использовать `Ordinal`.

### Особенности работы с большими объемами текстовых данных и антипаттерн многократного сложения

Начинающие разработчики часто совершают классическую ошибку, используя оператор `+` для склеивания сотен или тысяч строк в циклах.

```csharp
// АНТИПАТТЕРН! Так писать нельзя в реальных проектах.
string result = "";
for (int i = 0; i < 10000; i++)
{
    result += i.ToString(); 
}
```

**Почему это антипаттерн?**
Поскольку класс `string` неизменяем, каждая операция `result += ...` не изменяет существующую строку в памяти. Вместо этого среда выполнения выделяет новый блок памяти в куче, копирует туда содержимое старой строки, добавляет новый фрагмент, а старый объект отправляет на уничтожение сборщику мусора (*Garbage Collector*). 

Для $N$ итераций цикла создание строк приводит к квадратичной сложности по времени и памяти: $O(N^2)$. При больших значениях $N$ программа начинает сильно «тормозить» и потреблять огромное количество оперативной памяти.

Для эффективной работы с текстом в таких сценариях применяется специальный класс `StringBuilder`, который будет подробно рассмотрен в следующем разделе. Правило проектирования здесь простое:
- Если вы объединяете строки 1–3 раза или пишете статический текст — используйте интерполяцию или оператор `+`.
- Если конкатенация происходит в цикле или зависит от динамического объема данных — используйте `StringBuilder`.

### Разбор комплексного примера

Рассмотрим задачу, объединяющую изученные методы анализа и модификации строк.

#### Условие задачи
Дана строка с текстом, содержащим зашифрованное сообщение: `'Код_доступа: 7789-АБВ'`. Написать программу на C#, которая извлекает числовую часть с помощью методов `Substring` и `IndexOf`, а затем выводит её на консоль в отформатированном виде (например, разбив цифры пробелами или выведя в виде структурированного сообщения).

#### Рисунок словами (схема работы алгоритма)
```text
Исходная строка: "Код_доступа: 7789-АБВ"
1. Находим индекс двоеточия ':' -> индекс 11.
2. Смещаем указатель на 2 позиции вперед (пропуск двоеточия и пробела) -> индекс 13 (начало числа '7').
3. Находим индекс дефиса '-' -> индекс 17.
4. Вычисляем длину числовой подстроки: 17 - 13 = 4 символа.
5. Извлекаем подстроку методом Substring(13, 4) -> получаем "7789".
6. Форматируем и выводим результат.
```

#### Ход рассуждений
1. Жестко привязываться к индексам символов нельзя, так как длина префикса может измениться. Поэтому мы должны искать позиции разделителей динамически.
2. Метод `IndexOf(':')` вернет индекс двоеточия. Нам нужно число, которое идет сразу после него и пробела. Значит, стартовая позиция числа: `colonIndex + 2`.
3. Конец числовой последовательности ограничен дефисом `'-'`. Найдем его индекс с помощью `IndexOf('-')`.
4. Длина извлекаемой подстроки для метода `Substring(startIndex, length)` равна разности между индексом дефиса и стартовым индексом числа.
5. Полученную строку преобразуем или форматируем с помощью интерполяции строк.

#### Решение на C#

```csharp
using System;

class Program
{
    static void Main()
    {
        // Исходные данные
        string encryptedMessage = "Код_доступа: 7789-АБВ";
        Console.WriteLine($"Исходная строка: \"{encryptedMessage}\"");

        // 1. Поиск позиции двоеточия
        int colonIndex = encryptedMessage.IndexOf(':');
        
        // Проверка на наличие разделителя (защита от некорректных данных)
        if (colonIndex == -1)
        {
            Console.WriteLine("Ошибка: двоеточие не найдено в строке.");
            return;
        }

        // 2. Начало числа идет через 2 символа после двоеточия (символы ': ' )
        int numberStartIndex = colonIndex + 2;

        // 3. Поиск дефиса, который ограничивает числовую часть справа
        int hyphenIndex = encryptedMessage.IndexOf('-', numberStartIndex);

        if (hyphenIndex == -1)
        {
            Console.WriteLine("Ошибка: дефис-разделитель не найден.");
            return;
        }

        // 4. Вычисление длины числовой подстроки
        int numberLength = hyphenIndex - numberStartIndex;

        // 5. Извлечение числовой подстроки
        string numberString = encryptedMessage.Substring(numberStartIndex, numberLength);

        // 6. Форматирование и вывод результата
        // Для примера выведем извлеченное число, добавив к нему искусственное форматирование
        string formattedResult = $"[УСПЕХ] Извлеченный секретный код: {numberString} (длина: {numberLength} цифр)";
        
        Console.WriteLine(formattedResult);
    }
}
```

#### Пример вывода программы
```text
Исходная строка: "Код_доступа: 7789-АБВ"
[УСПЕХ] Извлеченный секретный код: 7789 (длина: 4 цифр)
```

#### Проверка и анализ
- **Единицы измерения:** В данной задаче оперируем целочисленными индексами символов (`int`), размерность корректна.
- **Правдоподобность:** Если изменить текст на `"Код_доступа: 12345-XYZ"`, программа корректно найдет двоеточие и дефис, вычислит новую длину `12 - 13`? Стоп! Давайте проверим граничные индексы:
  - `"Код_доступа: 12345-XYZ"`
  - Двоеточие `:` на индексе `11`.
  - `numberStartIndex = 11 + 2 = 13`.
  - Символ `'1'` находится на индексе `13`.
  - Дефис `'-'` находится на индексе `13 + 5 = 18`.
  - Длина = `18 - 13 = 5`. `Substring(13, 5)` корректно извлечет `"12345"`.
- Алгоритм устойчив к изменению длины числовой части, если формат сохраняется. Временная сложность поиска подстрок составляет $O(N)$, где $N$ — длина строки, что является оптимальным.

`Ответ:` Извлеченная числовая часть: `7789`.

## 4. Класс StringBuilder: эффективная модификация текста

### Проблема производительности при частой конкатенации обычных строк

В предыдущих разделах было подробно рассмотрено, что тип `string` в языке C# является неизменяемым (`immutable`). Это означает, что после того как объект класса `string` был создан в памяти, его содержимое не может быть изменено ни при каких обстоятельствах. Любая операция, которая визуально выглядит как изменение строки (например, конкатенация через оператор `+`, замена подстроки или изменение регистра), на самом деле приводит к созданию совершенно нового объекта в управляемой куче (`managed heap`).

Рассмотрим, что происходит на уровне оперативной памяти при выполнении следующего безобидного на первый взгляд кода:

```csharp
string result = "";
for (int i = 0; i < 5; i++)
{
    result += i.ToString();
}
```

Пошаговый разрез выполнения этого цикла выглядит следующим образом:
1. Создается пустая строка `""` (длина 0), на которую ссылается переменная `result`.
2. На первой итерации цикла (`i = 0`) вычисляется выражение `result + "0"`. Поскольку исходная строка неизменяема, среда выполнения .NET выделяет в памяти новый блок для хранения символа `"0"`. Переменная `result` начинает указывать на новый объект. Старая пустая строка остается в памяти и ожидает уничтожения сборщиком мусора (`Garbage Collector`).
3. На второй итерации (`i = 1`) выделяется память под строку `"01"`, копируются символы `"0"` и `"1"`, а ссылка `result` перенаправляется на новый объект.
4. Процесс повторяется для каждой итерации.

Если вместо 5 итераций выполнить цикл 10 000 раз, то программа создаст в памяти 10 000 промежуточных объектов `string`, каждый из которых будет длиннее предыдущего. Суммарный объем выделенной и сразу же ставшей «мусором» памяти составит десятки мегабайт. Сборщик мусора будет вынужден регулярно прерывать работу программы для очистки памяти, что приведет к резкому падению производительности (так называемому *thrashing* — избыточному задействованию ресурсов на служебные операции). Временная сложность такого алгоритма конкатенации составляет $O(N^2)$, где $N$ — общая длина результирующей строки, так как на каждом шаге происходит копирование всей накопившейся строки заново.

### Архитектура класса `StringBuilder`: буфер фиксированной или динамической емкости

Чтобы избавиться от постоянного перевыделения памяти и копирования данных при каждой модификации текста, в пространстве имен `System.Text` предусмотрен специальный ссылочный класс `StringBuilder`. 

> **Определение.** `StringBuilder` — это изменяемый контейнер символов (буфер), который хранит последовательность символов внутри себя и позволяет производить операции добавления, вставки, удаления и замены текста без создания новых объектов в памяти.

Архитектура класса базируется на двух ключевых свойствах:
- `Length` — текущее количество символов, фактически содержащихся в буфере.
- `Capacity` — максимальное количество символов, которое буфер может вместить без выделения дополнительной памяти (текущий размер внутреннего массива `char[]`).

Когда вы создаете экземпляр `StringBuilder`, среда выполнения выделяет под капотом массив символов фиксированного размера (по умолчанию начальная емкость составляет 16 символов, если размер не указан явно). 

```ascii
+-------------------------------------------------+
| 'H' | 'e' | 'l' | 'l' | 'o' |  \0 |  \0 |  \0   | -> Внутренний массив (Capacity = 8)
+-------------------------------------------------+
  [0]   [1]   [2]   [3]   [4]   [5]   [6]   [7]
  
  Length = 5 (реальный текст)
```

Пока количество добавляемых символов не превышает значение `Capacity`, все модификации происходят мгновенно *in-place* (на месте во внутреннем массиве), без обращения к куче для создания новых объектов. 

Что происходит, если длина добавляемого текста (`Length`) превышает текущую емкость (`Capacity`)? 
1. `StringBuilder` автоматически создает новый, более крупный внутренний массив (обычно его размер удваивается: $\text{Capacity}_{new} = \text{Capacity}_{old} \times 2$).
2. Старые данные копируются в новый массив.
3. Старый массив удаляется сборщиком мусора.

Даже с учетом редких перераспределений памяти при исчерпании емкости, общая временная сложность построения строки с помощью `StringBuilder` составляет $O(N)$, что на порядки быстрее последовательного сложения через оператор `+`.

### Основные методы `StringBuilder`

Класс `StringBuilder` предоставляет богатый набор методов для модификации содержимого. Все методы, изменяющие буфер, возвращают ссылку на тот же самый объект (`this`), что позволяет применять паттерн *цепочки вызовов* (Fluent Interface).

Рассмотрим основные методы в таблице:

| Метод | Сигнатура (основные перегрузки) | Описание действия |
|---|---|---|
| `Append` | `Append(string? value)`, `Append(char[]?, int, int)`, `Append(int value)` и др. | Добавляет указанное значение в конец текущего буфера. |
| `AppendLine` | `AppendLine(string? value = "")` | Добавляет текст в конец буфера и сразу записывает символ перевода строки (`\n` или системный разделитель). |
| `Insert` | `Insert(int index, string? value)` | Вставляет подстроку в заданную позицию по индексу `index`. |
| `Remove` | `Remove(int startIndex, int length)` | Удаляет заданное количество (`length`) символов, начиная с позиции `startIndex`. |
| `Replace` | `Replace(char oldChar, char newChar)` или `Replace(string oldValue, string newValue)` | Заменяет все вхождения указанного символа или подстроки на новое значение. |
| `Clear` | `Clear()` | Полностью очищает буфер, устанавливая `Length = 0`. |

Рассмотрим синтаксис работы с этими методами. Для создания объекта используется конструктор `new`:

```csharp
// Создание пустого буфера с емкостью по умолчанию (16)
StringBuilder sb1 = new StringBuilder();

// Создание буфера с предварительным резервированием памяти под 256 символов (оптимально для производительности)
StringBuilder sb2 = new StringBuilder(256);

// Создание буфера с начальным текстом
StringBuilder sb3 = new StringBuilder("Старт");
```

Пример цепочки вызовов:
```csharp
StringBuilder sb = new StringBuilder("Привет");
sb.Append(", ").Append("мир!").AppendLine().Append("Добро пожаловать.");
// Содержимое буфера:
// Привет, мир!
// Добро пожаловать.
```

### Сравнение производительности: `string` против `StringBuilder`

Для наглядной демонстрации разницы в производительности обратимся к математической оценке и практическому тестированию. 

Пусть нам требуется объединить $N$ одинаковых строк в одну длинную последовательность.
- При использовании **неизменяемого типа `string`** и оператора `+`:
  - На первой итерации копируется $1$ элемент.
  - На второй — $2$ элемента.
  - На $i$-й — $i$ элементов.
  - Суммарное количество операций копирования символов выражается арифметической прогрессией:
    $$S(N) = 1 + 2 + 3 + \dots + N = \frac{N(N + 1)}{2} = \frac{N^2 + N}{2}$$
  - Асимптотическая сложность: **$O(N^2)$**. При $N = 50\,000$ число операций приближается к $1{,}25 \cdot 10^9$, что вызовет заметное «зависание» консольного приложения на несколько секунд.

- При использовании **`StringBuilder`**:
  - Благодаря динамическому буферу с удвоением емкости, большинство операций добавления выполняется за константное время $O(1)$ в памяти. Редкие операции перевыделения буфера распределяются равномерно (*амортизированное время*).
  - Асимптотическая сложность: **$O(N)$**. При том же $N = 50\,000$ выполнение займет доли миллисекунды.

### Когда использовать `string`, а когда `StringBuilder`

Несмотря на высокую эффективность `StringBuilder`, не следует использовать его везде подряд. Выбор инструмента зависит от сценария задачи:

| Критерий | Использовать `string` | Использовать `StringBuilder` |
|---|---|---|
| **Количество модификаций** | Единичные операции, присваивание констант, редкое объединение (2–3 переменные через интерполяцию). | Многократные цикклические изменения, конкатенация внутри циклов (`for`, `foreach`, `while`). |
| **Объем текста** | Маленькие строки фиксированной длины. | Большие текстовые блоки, генерация объемных отчетов, HTML-страниц, SQL-запросов. |
| **Удобство методов** | Огромный арсенал методов поиска, разделения, регулярных выражений (`Split`, `IndexOf`, `Substring`). | Упор на изменение структуры текста (`Append`, `Insert`, `Remove`, `Replace`). |

Важно отметить: после завершения всех манипуляций с текстом в `StringBuilder`, для передачи результата в методы, ожидающие обычный тип `string` (например, запись в файл через `File.WriteAllText` или вывод в консоль), необходимо преобразовать буфер обратно в строку с помощью метода `ToString()`:

```csharp
StringBuilder sb = new StringBuilder();
sb.Append("Итоговый текст");
string finalResult = sb.ToString(); // Создание финального неизменяемого объекта string
```

### Разобранный пример: Таблица умножения через `StringBuilder`

#### Условие задачи
Сформировать с помощью класса `StringBuilder` строку, содержащую таблицу умножения чисел от 1 до 5 в виде форматированных строк с переносами, и вывести результат на консоль. Каждая строка таблицы должна иметь вид `i * j = результат`.

#### Рисунок словами (схема вывода)
```ascii
+-----------------------------------+
| 1 * 1 = 1   1 * 2 = 2   ...       | -> Строка для множителя 1
| 2 * 1 = 2   2 * 2 = 4   ...       | -> Строка для множителя 2
| ...                               |
| 5 * 1 = 5   5 * 2 = 10  ...       | -> Строка для множителя 5
+-----------------------------------+
```

#### Ход рассуждений
1. Нам нужно сгенерировать сложный многострочный текст. Поскольку строк будет много и они формируются в цикле, использование обычного оператора `+` привело бы к лишним затратам памяти. Поэтому создаем экземпляр `StringBuilder` с предварительно выделенной емкостью (например, 200 символов), чтобы избежать перевыделения буфера.
2. Для обхода чисел от 1 до 5 используем вложенные циклы: внешний цикл управляет первым множителем (`i`), внутренний — вторым (`j`).
3. На каждой итерации внутреннего цикла добавляем в `StringBuilder` текущее выражение с помощью метода `Append`, форматируя его через интерполяцию строк или стандартный вывод. Для разделения столбцов внутри строки добавим символ табуляции (`\t`), а после завершения внутреннего цикла для каждого `i` вызовем `AppendLine()`, чтобы перевести каретку на новую строку.
4. После завершения циклов преобразуем `StringBuilder` в обычный `string` и выводим на консоль.

#### Решение на C#

```csharp
using System;
using System.Text;

class MultiplicationTableProgram
{
    static void Main()
    {
        // Шаг 1. Создаем экземпляр StringBuilder с начальной емкостью 256 символов
        StringBuilder sb = new StringBuilder(256);

        sb.AppendLine("=== ТАБЛИЦА УМНОЖЕНИЯ (от 1 до 5) ===");

        // Шаг 2. Внешний цикл по первому множителю (от 1 до 5)
        for (int i = 1; i <= 5; i++)
        {
            // Внутренний цикл по второму множителю (от 1 до 5)
            for (int j = 1; j <= 5; j++)
            {
                int product = i * j;
                
                // Формируем элемент таблицы и добавляем в буфер с табуляцией для выравнивания
                // Используем интерполяцию строк внутри Append
                sb.Append($"{i} * {j} = {product}\t");
            }
            
            // Завершаем строку таблицы переводом строки
            sb.AppendLine();
        }

        sb.AppendLine("=== КОНЕЦ ТАБЛИЦЫ ===");

        // Шаг 3. Превращаем StringBuilder обратно в string для вывода
        string resultTable = sb.ToString();

        // Шаг 4. Вывод результата на консоль
        Console.WriteLine(resultTable);
    }
}
```

#### Проверка и анализ
- **Единицы измерения:** В данном алгоритме используются безразмерные целочисленные счетчики (`int`), единицы измерения не требуются.
- **Правдоподобность:** При выполнении программы вложенные циклы отработают ровно $5 \times 5 = 25$ раз. Каждый раз во внутренний буфер добавляется готовая строка без создания промежуточных объектов `string` в куче. Метод `\t` обеспечивает аккуратное визуальное выравнивание столбцов в консоли.
- **Оценка сложности:** Временная сложность алгоритма составляет $O(K)$, где $K$ — общее число ячеек таблицы ($5 \times 5 = 25$ операций добавления). Пространственная сложность равна $O(M)$, где $M$ — размер результирующего буфера в памяти.

## 5. Продвинутая алгоритмическая обработка строк

### Продвинутая алгоритмическая обработка строк

В предыдущих разделах мы познакомились с базовыми возможностями класса `string`, способами поиска и модификации текста, а также с классом `StringBuilder`. Теперь применим эти знания для решения сложных алгоритмических задач, с которыми часто приходится сталкиваться на практике и на экзаменах. Мы разберем классические алгоритмы анализа текстов, научимся эффективно оценивать их сложность и корректно обрабатывать граничные условия.

---

### Анализ текстовых последовательностей: проверка на палиндром

> **Определение.** **Палиндром** — это строка, которая одинаково читается как слева направо, так и справа налево, если предварительно удалить из неё все пробелы, знаки препинания и привести к единому регистру символов.

Пример палиндрома: `"А роза упала на лапу Азора"`. Если отбросить пробелы и регистр, получится последовательность: `"арозаупаланалапазора"`, которая читается одинаково в обоих направлениях.

#### Алгоритм проверки двумя указателями

Наивный подход предполагает создание копии строки, её разворот и сравнение с оригиналом. Однако это требует выделения дополнительной памяти в куче для новой строки $O(N)$. Более эффективный подход — использование двух указателей (индексов):
1. Один индекс (`left`) начинает движение с начала строки ($0$).
2. Второй индекс (`right`) начинает движение с конца строки ($N - 1$).
3. На каждом шаге мы проверяем символы под этими индексами. Если символы не равны, строка не является палиндромом.
4. Если указатели встретились или пересеклись (`left >= right`), проверка успешно завершена.

Важная особенность реальных текстов — наличие пробелов и знаков препинания, которые нужно пропускать, не сдвигая оба указателя одновременно, а перемещая только тот, который указывает на «нежелательный» символ, либо предварительно очистив строку.

---

### Частотный анализ символов в строке

Частотный анализ заключается в подсчете количества вхождений каждого символа в заданный текст. Эта задача востребована в криптографии, сжатии данных и текстовой аналитике.

В языке C# для частотного анализа применяются два основных подхода:
1. **Массив подсчета (Frequency Array)** — эффективен, если алфавит ограничен (например, только латиница или кириллица). Поскольку каждый символ `char` в C# представляет собой 16-битное число UTF-16, мы можем использовать массив фиксированного размера (например, размером `65536` для всех возможных символов Unicode или массив из `32` элементов для русских букв в нижнем регистре).
2. **Словарь (`Dictionary<char, int>`)** — универсальный подход, удобный для строк произвольной длины и любых наборов символов. Ключом словаря выступает сам символ, а значением — счетчик его появлений.

---

### Лексикографическая сортировка слов в предложении

Лексикографический порядок — это аналог алфавитного порядка, расширенный на символы компьютерных кодировок. Чтобы отсортировать слова в предложении лексикографически:
1. Предложение разбивается на отдельные слова с помощью метода `Split()`.
2. Из массива слов удаляются пустые элементы и знаки препинания (если они примыкают к словам).
3. Применяется алгоритм сортировки (например, метод `Array.Sort()` или встроенные LINQ-методы), который сравнивает строки посимвольно с учетом текущей локали (`CultureInfo`).

---

### Оценка временной и пространственной сложности строковых алгоритмов

При разработке алгоритмов обработки текста критически важно понимать их ресурсоемкость:

* **Временная сложность (Time Complexity)** обозначается как $O(f(N))$, где $N$ — длина строки. Операции доступа по индексу и проверки длины (`Length`) выполняются за константное время $O(1)$. Проход по всей строке циклом занимает линейное время $O(N)$. Вложенные циклы (например, при наивном поиске подстрок или сортировке слов) могут давать квадратичную сложность $O(N^2)$.
* **Пространственная сложность (Space Complexity)** определяет объем дополнительной памяти, требуемой алгоритму. Поскольку строки в C# неизменяемы (`immutable`), любые операции конкатенации через оператор `+` внутри циклов создают новые объекты в памяти, приводя к квадратичной сложности по памяти $O(N^2)$ и перегрузке сборщика мусора. Использование `StringBuilder` или алгоритмов на месте (`in-place`) снижает пространственную сложность до $O(1)$ или $O(N)$.

---

### Обработка граничных условий

Надежная программа должна корректно отрабатывать следующие нестандартные входные данные:
* **Пустая строка (`string.Empty` или `""`)** — не должна вызывать исключений `ArgumentOutOfRangeException` или `NullReferenceException`.
* **Строка из одного символа** — очевидно, является палиндромом, а частотный анализ должен вернуть единицу для этого символа.
* **Строка, состоящая только из пробелов и знаков препинания** — после очистки должна превращаться в пустую строку.
* **Значение `null`** — перед началом обработки всегда следует проверять входные данные с помощью `string.IsNullOrEmpty()`.

### Разобранный пример

#### Условие задачи
Написать программу на языке C#, которая принимает предложение на русском языке, удаляет все знаки препинания, приводит к нижнему регистру и проверяет, является ли текст палиндромом (без учета пробелов). Проверить работу программы на строке: `"А роза упала на лапу Азора"`.

#### Рисунок словами (структура данных и логика работы)
```
Исходная строка: "А роза упала на лапу Азора"
Шаг 1 (Очистка и приведение к нижнему регистру):
"арозаупаланалапазора"

Шаг 2 (Двух указательный метод проверки):
Индекс left  -> [а] р о з а у п а л а н а л а п а з о р [а] <- Индекс right
Совпадают? Да. Смещаем оба указателя к центру.
...
Результат: Все символы совпали -> Текст является палиндромом.
```

#### Ход рассуждений
1. Проверяем строку на `null` или пустоту. Если строка пустая, выводим сообщение об ошибке или считаем её палиндромом по определению (в зависимости от бизнес-логики; для нашей задачи пустая строка не является осмысленным палиндромом, поэтому выведем корректное сообщение).
2. Для эффективной очистки текста от пробелов и знаков препинания используем класс `StringBuilder`. Проходим по исходному символьному массиву строки с помощью цикла `foreach`.
3. С помощью метода `char.IsLetter()` проверяем каждый символ: является ли он буквой. Если да, приводим его к нижнему регистру методом `char.ToLower()` и добавляем в `StringBuilder`. Это позволяет отбросить все пробелы, точки, запятые и дефисы за один проход ($O(N)$).
4. Превращаем очищенный `StringBuilder` в обычную строку `cleanText`.
5. Запускаем алгоритм с двумя указателями (`left = 0`, `right = cleanText.Length - 1`). Пока `left < right`, сравниваем `cleanText[left]` и `cleanText[right]`. Если они не равны — возвращаем `false`. Если равны — сближаем указатели (`left++`, `right--`).
6. Выводим результат на консоль.

#### Полный исходный код программы

```csharp
using System;
using System.Text;

class Program
{
    static void Main()
    {
        // Исходная строка по условию задачи
        string input = "А роза упала на лапу Азора";

        Console.WriteLine($"Исходный текст: \"{input}\"");

        // Вызов метода проверки на палиндром
        bool result = IsPalindrome(input);

        if (result)
        {
            Console.WriteLine("Ответ: ДА, этот текст является палиндромом.");
        }
        else
        {
            Console.WriteLine("Ответ: НЕТ, этот текст не является палиндромом.");
        }
    }

    /// <summary>
    /// Проверяет, является ли строка палиндромом без учета регистра, пробелов и знаков препинания.
    /// </summary>
    /// <param name="text">Исходная строка для проверки.</param>
    /// <returns>true, если строка палиндром; иначе false.</returns>
    static bool IsPalindrome(string text)
    {
        // Обработка граничного условия: пустая строка или null
        if (string.IsNullOrEmpty(text))
        {
            return false;
        }

        // Шаг 1: Очищаем строку от знаков препинания и пробелов, приводим к нижнему регистру
        StringBuilder sb = new StringBuilder();

        foreach (char c in text)
        {
            // Проверяем, является ли символ буквой (поддерживает кириллицу и латиницу в .NET)
            if (char.IsLetter(c))
            {
                sb.Append(char.ToLower(c));
            }
        }

        string cleanText = sb.ToString();

        // Если после очистки строка оказалась пустой
        if (string.IsNullOrEmpty(cleanText))
        {
            return false;
        }

        Console.WriteLine($"Очищенный текст: \"{cleanText}\"");

        // Шаг 2: Алгоритм с двумя указателями
        int left = 0;
        int right = cleanText.Length - 1;

        while (left < right)
        {
            if (cleanText[left] != cleanText[right])
            {
                return false; // Найдено несоответствие символов
            }

            left++;
            right--;
        }

        return true; // Все символы совпали
    }
}
```

#### Проверка и анализ работы программы
1. **Единицы и типы:** Метод `char.IsLetter()` возвращает логическое значение `bool`, индексы `left` и `right` имеют тип `int`, длина строки `Length` также возвращает `int`. Ошибок несоответствия типов нет.
2. **Правдоподобие:** Для строки `"А роза упала на лапу Азора"` первый цикл извлечет буквы: `а`, `р`, `о`, `з`, `а`, `у`, `п`, `а`, `л`, `а`, `н`, `а`, `л`, `а`, `п`, `а`, `з`, `о`, `р`, `а`. Получится ровно 20 символов. Указатели сойдутся в центре, не найдя ни одного расхождения. Результат выполнения: `true`.
3. **Временная сложность:** Проход по строке и очистка занимают $O(N)$, где $N$ — длина исходной строки. Проверка палиндрома двумя указателями занимает $O(M)$, где $M$ — длина очищенной строки ($M \le N$). Итоговая временная сложность алгоритма составляет $O(N)$, что является оптимальным показателем.
4. **Пространственная сложность:** $O(N)$ памяти выделяется для хранения очищенной строки в `StringBuilder`.

`Ответ: ДА, этот текст является палиндромом.`

## Типичные ошибки

1. **Модификация неизменяемой строки в цикле (`result += ...`)**
   - *Почему возникает:* Начинающие разработчики переносят привычку изменять переменные (как в математике или других типах данных) на строки, забывая про концепцию *immutability*.
   - *Как избежать:* Для любых динамических накоплений текста и конкатенаций в цикле всегда используйте `StringBuilder`.
   - *Пример ошибки:* `string s = ""; for(int i=0; i<1000; i++) s += i;` (порождает тысячи объектов в куче).

2. **Путаница между равенством ссылок (`ReferenceEquals` / `==` для других типов) и равенством содержимого (`==` для строк)**
   - *Почему возникает:* Ожидание, что `string` будет вести себя как стандартный ссылочный тип, у которого оператор `==` сравнивает адреса памяти.
   - *Как избежать:* Помнить, что в C# оператор `==` для класса `string` перегружен и сравнивает **символы в тексте**. Для проверки тождественности объектов в памяти используйте `object.ReferenceEquals()`.
   - *Пример ошибки:* `if (ReferenceEquals(userStr, inputStr))` вместо проверки содержимого через `==`.

3. **Выход за границы строки при работе с индексами (`IndexOutOfRangeException`)**
   - *Почему возникает:* Использование жестких индексов или некорректный расчет длины при вызове `Substring(startIndex, length)`.
   - *Как избежать:* Проверять длину строки через свойство `Length`, учитывать, что индексация начинается с нуля, а последний символ имеет индекс `Length - 1`.
   - *Пример ошибки:* `string s = "ABC"; string sub = s.Substring(0, 5);`.

4. **Игнорирование регистра и локали при сравнении строк**
   - *Почему возникает:* Сравнение строк оператором `==` «в лоб» без учета того, что `"Admin"` и `"admin"` для компьютера — совершенно разные строки.
   - *Как избежать:* Использовать методы нормализации (`ToLower()` / `ToUpper()`) либо перегрузки с флагами сравнения (`StringComparison.OrdinalIgnoreCase`).
   - *Пример ошибки:* `if (inputCommand == "exit")` сработает неверно, если пользователь введет `"EXIT"`.

5. **Некорректная обработка `null`-ссылок**
   - *Почему возникает:* Вызов методов экземпляра класса `string` (например, `text.Trim()` или `text.Length`) у переменной, которая не была инициализирована и равна `null`.
   - *Как избежать:* Всегда проверять входящие строковые данные с помощью статического метода `string.IsNullOrEmpty()` или `string.IsNullOrWhiteSpace()`.
   - *Пример ошибки:* `int len = uninitializedString.Length;` приведет к падению программы с `NullReferenceException`.

6. **Создание лишних массивов символов без необходимости**
   - *Почему возникает:* Злоупотребление методом `.ToCharArray()` там, где можно обойтись стандартной индексацией `[i]` или методами класса `string`.
   - *Как избежать:* Конвертировать строку в массив символов `char[]` только тогда, когда это действительно нужно для алгоритма (например, инвертирование массива на месте).

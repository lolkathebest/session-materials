## 1. Архитектурное проектирование ООП-модели для оконного приложения

### Анализ предметной области и выделение сущностей, свойств и поведений

Любое качественное программное обеспечение начинается с проектирования. Прежде чем создавать графический интерфейс в Windows Forms, программист обязан спроектировать модель предметной области (domain model) на чистом C#. Предметная область — это та сфера реального мира, которую автоматизирует программа (например, учет сотрудников предприятия, складской учет, библиотечная система).

Анализ предметной области заключается в выделении трёх ключевых элементов:
1. **Сущности (объекты)** — это «существительные» нашей задачи: конкретные или абстрактные вещи, обладающие состоянием и поведением (например, «Сотрудник», «Книга», «Заказ»). В коде они выражаются классами (`class`) или структурами (`struct`).
2. **Свойства (состояние)** — характеристики сущностей (например, ФИО сотрудника, оклад, название книги, размер файла). В C# они реализуются через поля с модификатором `private` и публичные свойства (`property`) с блоками `get` и `set`.
3. **Поведения (методы)** — действия, которые сущность может выполнять или которые можно выполнять над ней (например, рассчитать зарплату, вывести информацию на экран, изменить статус).

> **Определение.** Инкапсуляция — это принцип ООП, согласно которому данные (поля) объекта скрываются от прямого доступа извне, а доступ к ним предоставляется через методы или свойства, позволяющие контролировать корректность изменяемых значений.

### Проектирование иерархии классов и абстрактные классы

Когда в предметной области есть несколько похожих сущностей, обладающих общими свойствами и поведением, применяют **наследование**. Наследование позволяет вынести общий код в базовый класс, а специализированный — оставить в производных классах.

Если базовый класс представляет собой общую концепцию, объект которой сам по себе в реальном мире существовать не может (нельзя создать просто «Сотрудника вообще», это обязательно либо «Менеджер», либо «Разработчик»), его делают **абстрактным**.

> **Определение.** Абстрактный класс — это класс, помеченный ключевым словом `abstract`, экземпляр которого создать нельзя (`new Employee()` вызовет ошибку компиляции). Он служит шаблоном для производных классов и может содержать как реализованные методы, так и абстрактные методы (без тела, обязательные для переопределения в потомках).

### Интерфейсы для полиморфного поведения

Иногда требуется, чтобы абсолютно разные классы, не связанные общей иерархией наследования, выполняли одинаковые действия. Для этого используются **интерфейсы**.

> **Определение.** Интерфейс (`interface`) — это контракт, определяющий набор методов, свойств и событий, которые реализующий его класс *обязан* предоставить. Интерфейс задает поведение («что объект может делать»), в то время как класс задает сущность («чем объект является»).

### Разделение ответственности и изоляция бизнес-логики

Главная ошибка начинающих разработчиков — написание всей логики расчетов, проверок и работы с данными прямо в файлах кода формы Windows Forms (например, в обработчиках нажатия кнопки `button1_Click`). 

Правильный архитектурный подход требует полного разделения ответственности:
- **Уровень данных и бизнес-логики (Domain Layer):** классы, структуры, интерфейсы. Они ничего не знают о существовании кнопок, текстовых полей и формы. Их можно скомпилировать и протестировать в консольном приложении или unit-тестах.
- **Уровень представления (Presentation Layer):** формы Windows Forms. Они принимают ввод от пользователя, вызывают методы бизнес-логики и выводят результат.

### Пример 1. Иерархия классов для учета сотрудников предприятия

Спроектируем иерархию классов для расчета заработной платы сотрудников. У нас есть общий абстрактный класс `Employee`, а также два производных класса: `Manager` и `Developer`. Также создадим интерфейс `ICalculatable` для унификации расчета зарплаты.

#### Пошаговое проектирование:
1. Создадим интерфейс `ICalculatable` с методом `decimal CalculateTotalSalary()`.
2. Создадим абстрактный класс `Employee`, реализующий `ICalculatable`. В нем объявим защищенные поля для ФИО и базового оклада, а также инкапсулируем их через свойства с проверкой на отрицательные значения.
3. Создадим класс `Manager`, добавив количество подчиненных и премию за каждого подчиненного.
4. Создадим класс `Developer`, добавив коэффициент сложности стека технологий.

#### Полный код модели (C#):

```csharp
using System;

// Интерфейс для расчета финансовых показателей
public interface ICalculatable
{
    decimal CalculateTotalSalary();
}

// Абстрактный базовый класс сотрудника
public abstract class Employee : ICalculatable
{
    private string _fullName;
    private decimal _baseSalary;

    public string FullName
    {
        get => _fullName;
        set
        {
            if (string.IsNullOrWhiteSpace(value))
                throw new ArgumentException("ФИО не может быть пустым.");
            _fullName = value.Trim();
        }
    }

    public decimal BaseSalary
    {
        get => _baseSalary;
        set
        {
            if (value < 0)
                throw new ArgumentOutOfRangeException("Базовый оклад не может быть отрицательным.");
            _baseSalary = value;
        }
    }

    // Защищенный конструктор для инициализации базовых полей
    protected Employee(string fullName, decimal baseSalary)
    {
        FullName = fullName;
        BaseSalary = baseSalary;
    }

    // Абстрактный метод, который каждый дочерний класс обязан реализовать по-своему
    public abstract decimal CalculateTotalSalary();

    public virtual string GetInfo()
    {
        return $"Сотрудник: {FullName}, Базовый оклад: {BaseSalary:0.00} руб.";
    }
}

// Класс Менеджер (наследует Employee)
public class Manager : Employee
{
    private int _subordinatesCount;
    private decimal _bonusPerSubordinate;

    public int SubordinatesCount
    {
        get => _subordinatesCount;
        set
        {
            if (value < 0)
                throw new ArgumentOutOfRangeException("Количество подчиненных не может быть отрицательным.");
            _subordinatesCount = value;
        }
    }

    public decimal BonusPerSubordinate
    {
        get => _bonusPerSubordinate;
        set
        {
            if (value < 0)
                throw new ArgumentOutOfRangeException("Премия не может быть отрицательной.");
            _bonusPerSubordinate = value;
        }
    }

    public Manager(string fullName, decimal baseSalary, int subordinatesCount, decimal bonusPerSubordinate)
        : base(fullName, baseSalary)
    {
        SubordinatesCount = subordinatesCount;
        BonusPerSubordinate = bonusPerSubordinate;
    }

    // Переопределение метода расчета зарплаты (полиморфизм)
    public override decimal CalculateTotalSalary()
    {
        return BaseSalary + (SubordinatesCount * BonusPerSubordinate);
    }

    public override string GetInfo()
    {
        return $"[Менеджер] {base.GetInfo}, Подчиненных: {SubordinatesCount}, Итого з/п: {CalculateTotalSalary():0.00} руб.";
    }
}

// Класс Разработчик (наследует Employee)
public class Developer : Employee
{
    private double _stackComplexityMultiplier;

    public double StackComplexityMultiplier
    {
        get => _stackComplexityMultiplier;
        set
        {
            if (value < 1.0)
                throw new ArgumentOutOfRangeException("Множитель сложности не может быть меньше 1.0.");
            _stackComplexityMultiplier = value;
        }
    }

    public Developer(string fullName, decimal baseSalary, double stackComplexityMultiplier)
        : base(fullName, baseSalary)
    {
        StackComplexityMultiplier = stackComplexityMultiplier;
    }

    // Переопределение метода расчета зарплаты
    public override decimal CalculateTotalSalary()
    {
        return (decimal)((double)BaseSalary * StackComplexityMultiplier);
    }

    public override string GetInfo()
    {
        return $"[Разработчик] {base.GetInfo}, Множитель стека: {StackComplexityMultiplier:0.0}, Итого з/п: {CalculateTotalSalary():0.00} руб.";
    }
}
```

#### Пояснение к коду:
- `interface ICalculatable` задает контракт. Любой класс, подписанный на него, гарантирует наличие метода `CalculateTotalSalary()`.
- Свойства содержат валидацию (защиту от некорректных данных). Если передать отрицательный оклад, мгновенно сгенерируется исключение, предотвращающее появление неверных данных в системе.
- Полиморфизм проявляется в том, что мы можем создать коллекцию типа `List<Employee>` и хранить в ней вперемешку и менеджеров, и разработчиков, вызывая у каждого метод `CalculateTotalSalary()`, причем для каждого типа сработает своя уникальная формула.

### Пример 2. Модель библиотечной системы и фабричный метод

Рассмотрим вторую задачу: проектирование модели для библиотеки, где есть печатные и электронные книги. Кроме того, нам часто приходится создавать объекты на основе сырых текстовых данных (например, прочитанных из CSV-файла или введенных пользователем в одну строку). Для инкапсуляции логики создания объектов применим паттерн «Фабричный метод» (Factory).

#### Пошаговое проектирование:
1. Создадим базовый класс `Book` с полями `Title` (название) и `Author` (автор).
2. Создадим производный класс `EBook`, добавив свойство `FileSizeMB` (размер файла в мегабайтах).
3. Создадим производный класс `PrintedBook`, добавив свойство `WeightGrams` (вес в граммах).
4. Создадим статический класс `BookFactory`, который принимает строку формата `"Тип;Автор;Название;ДопПараметр"` и возвращает готовый объект нужного класса-потомка.

#### Полный код модели (C#):

```csharp
using System;

// Базовый класс книги
public abstract class Book
{
    public string Title { get; set; }
    public string Author { get; set; }

    protected Book(string title, string author)
    {
        if (string.IsNullOrWhiteSpace(title) || string.IsNullOrWhiteSpace(author))
            throw new ArgumentException("Название и автор обязательны для заполнения.");
        
        Title = title.Trim();
        Author = author.Trim();
    }

    public abstract string GetDescription();
}

// Электронная книга
public class EBook : Book
{
    private double _fileSizeMB;

    public double FileSizeMB
    {
        get => _fileSizeMB;
        set
        {
            if (value <= 0)
                throw new ArgumentOutOfRangeException("Размер файла должен быть больше нуля.");
            _fileSizeMB = value;
        }
    }

    public EBook(string title, string author, double fileSizeMB) : base(title, author)
    {
        FileSizeMB = fileSizeMB;
    }

    public override string GetDescription()
    {
        return $"Электронная книга: \"{Title}\", автор: {Author}, размер: {FileSizeMB:0.0} МБ";
    }
}

// Печатная книга
public class PrintedBook : Book
{
    private int _weightGrams;

    public int WeightGrams
    {
        get => _weightGrams;
        set
        {
            if (value <= 0)
                throw new ArgumentOutOfRangeException("Вес книги должен быть больше нуля.");
            _weightGrams = value;
        }
    }

    public PrintedBook(string title, string author, int weightGrams) : base(title, author)
    {
        WeightGrams = weightGrams;
    }

    public override string GetDescription()
    {
        return $"Печатная книга: \"{Title}\", автор: {Author}, вес: {WeightGrams} г.";
    }
}

// Статический класс-фабрика для разбора строк и создания объектов
public static class BookFactory
{
    // Ожидаемый формат строки: "EBook;Иван Иванов;Война и мир;15{,}5" или "PrintedBook;Петр Петров;Чистый код;450"
    public static Book CreateFromString(string rawData)
    {
        if (string.IsNullOrWhiteSpace(rawData))
            .Throw(new ArgumentException("Исходная строка пуста."));

        string[] parts = rawData.Split(';');
        if (parts.Length != 4)
            .Throw(new FormatException("Неверный формат строки для создания книги. Ожидается 4 поля, разделенных точкой с запятой."));

        string type = parts[0].Trim();
        string author = parts[1].Trim();
        string title = parts[2].Trim();

        if (type.Equals("EBook", StringComparison.OrdinalIgnoreCase))
        {
            if (!double.TryParse(parts[3].Trim(), out double fileSize))
                throw new FormatException("Не удалось распознать размер файла электронной книги.");
            return new EBook(title, author, fileSize);
        }
        else if (type.Equals("PrintedBook", StringComparison.OrdinalIgnoreCase))
        {
            if (!int.TryParse(parts[3].Trim(), out int weight))
                throw new FormatException("Не удалось распознать вес печатной книги.");
            return new PrintedBook(title, author, weight);
        }
        else
        {
            throw new ArgumentException($"Неизвестный тип книги: {type}");
        }
    }
}
```

#### Ход рассуждений и проверка:
- Класс `BookFactory` изолирует логику парсинга текстовых файлов от самих классов книг. Если завтра мы добавим аудиокниги (`AudioBook`), нам не придется менять код форм или классов `EBook` — мы просто допишем одно ветвление `else if` в фабричном методе.
- Все числовые конвертации выполняются через безопасный метод `double.TryParse` / `int.TryParse`, что защищает программу от падения при некорректных данных в файле.
- Использование модификаторов доступа (`private`, `protected`, `public`) гарантирует, что внутреннее состояние объектов (`_fileSizeMB`, `_weightGrams`) нельзя изменить напрямую в обход проверок валидации, заложенных в свойствах.

## 2. Проектирование пользовательского интерфейса и компоновка элементов управления

### Введение в проектирование интерфейсов Windows Forms

Создание удобного и надежного пользовательского интерфейса (UI) — это завершающий и критически важный этап разработки настольного приложения. Даже безупречно написанная объектно-ориентированная бизнес-логика останется невостребованной, если пользователь не сможет интуитивно разобраться в управлении программой, столкнется с "плывущими" при изменении размера окна элементами или потеряет данные из-за неудобной навигации.

В платформе .NET 8 с использованием библиотеки Windows Forms проектирование интерфейса базируется на концепции визуального контейнерного размещения элементов управления (*Controls*). Каждый элемент интерфейса представляет собой экземпляр класса, унаследованного от базового класса `Control`. Наша задача как разработчиков — не просто раскидать кнопки и текстовые поля по форме, а выстроить масштабируемую, логически структурированную систему, которая корректно реагирует на действия пользователя и изменения размеров окна.

---

### Базовые элементы управления

Перед тем как объединять элементы в группы, рассмотрим строительные блоки интерфейса, с помощью которых пользователь взаимодействует с приложением:

1. `Label` (Метка) — служит для вывода статичного текста, поясняющего назначение других элементов (например, подпись "Введите имя пользователя:").
2. `TextBox` (Текстовое поле) — элемент для ввода и редактирования текстовой информации. Ключевые свойства: `Text` (содержимое), `PasswordChar` (символ маскировки для паролей), `ReadOnly` (режим только для чтения).
3. `Button` (Кнопка) — элемент для инициирования действия. Главное событие — `Click`.
4. `ComboBox` (Выпадающий список) — сочетает в себе возможности текстового поля и списка выбора. Позволяет пользователю выбрать один из заранее заданных вариантов или ввести свой (в зависимости от свойства `DropDownStyle`).
5. `CheckBox` (Флажок) — элемент с двумя (или тремя, если включено `ThreeState`) состояниями: отмечено / не отмечено. Используется для логических параметров (`true`/`false`).

> **Правило.** Каждый элемент управления на форме должен иметь уникальное и осмысленное имя (*Name*), отражающее его назначение, с префиксом, соответствующим типу элемента (например, `btnSave`, `txtUsername`, `cmbCategory`, `chkIsActive`). Использование имен по умолчанию (`button1`, `textBox2`) категорически запрещено, так как делает код поддержки нечитаемым.

---

### Контейнеры для логической группировки элементов

Когда на форме появляется более десятка элементов, управлять ими становится трудно. Для структурирования интерфейса используются контейнеры — специальные элементы управления, которые содержат внутри себя другие элементы и управляют их позиционированием.

1. `Panel` (Панель) — простой прямоугольный контейнер. Позволяет сгруппировать набор элементов (например, панель фильтров или панель инструментов) и управлять их видимостью одновременно через свойство `panel1.Visible = false;`.
2. `GroupBox` (Группа) — визуальный контейнер с рамкой и заголовком в верхней части. Идеально подходит для логического объединения связанных параметров (например, личные данные пользователя).
3. `SplitContainer` (Разделитель) — контейнер, разделенный подвижной полосой на две области (`Panel1` и `Panel2`). Позволяет пользователю самостоятельно менять пропорции занимаемого пространства (например, классический интерфейс "список-детали", где слева дерево папок, а справа содержимое выбранной папки).

### Масштабирование интерфейса: свойства Anchor и Dock

При изменении размеров окна приложения стандартное поведение элементов управления заключается в сохранении их абсолютных координат и размеров. Это приводит к тому, что при разворачивании окна на весь экран элементы остаются сбитыми в левом верхнем углу, а правая часть формы пустует. Для решения этой проблемы используются два фундаментальных механизма: `Anchor` и `Dock`.

#### Свойство Anchor (Привязка)
Свойство `Anchor` задает привязку элемента к одной или нескольким границам родительского контейнера. По умолчанию установлена привязка к верхнему и левому краю (`AnchorStyles.Top | AnchorStyles.Left`).

* Если установить привязку `Top, Left, Right`, то при расширении окна по горизонтали расстояние от правого края элемента до правого края формы будет оставаться постоянным, что заставит элемент растягиваться в ширину.
* Если установить привязку `Top, Bottom, Left, Right`, элемент будет масштабироваться во всех направлениях (идеально для таблиц `DataGridView` и текстовых редакторов).

#### Свойство Dock (Стыковка)
Свойство `Dock` прижимает элемент управления к одной из сторон родительского контейнера (`Top`, `Bottom`, `Left`, `Right`, `Fill`). 
* Элемент с `Dock = DockStyle.Left` займет всю высоту контейнера, прижавшись к левому краю, а его ширина останется фиксированной.
* Элемент с `Dock = DockStyle.Fill` заполнит все оставшееся свободное пространство внутри контейнера. 

> **Важно.** Порядок добавления элементов на форму (или порядок в коллекции `Controls`) имеет решающее значение при использовании стыковки (`Dock`), так как элементы обрабатываются последовательно. Последний добавленный элемент с `Dock = Fill` займет пространство, оставшееся после стыковки остальных панелей.

### Главное меню и контекстные меню

Полноценное настольное приложение должно предоставлять пользователю удобную систему навигации и доступ к командам через меню.

1. `MenuStrip` (Главное меню) — располагается, как правило, в верхней части формы (`Dock = Top`). Позволяет создавать иерархические структуры команд (Файл -> Открыть, Сохранить, Выход; Правка -> Копировать, Вставить). Каждый пункт меню является объектом класса `ToolStripMenuItem` и генерирует событие `Click`.
2. `ContextMenuStrip` (Контекстное меню) — всплывающее меню, которое появляется при щелчке правой кнопкой мыши по конкретному элементу управления. Связывается с элементом через его свойство `ContextMenuStrip`.

---

### Многопанельные интерфейсы

В сложных приложениях вся информация не помещается на одном экране. Создавать десяток отдельных окон для каждой операции неудобно и портит пользовательский опыт. Стандартная практика — использование единой главной формы с переключаемыми панелями.

Суть подхода заключается в создании нескольких элементов `Panel`, каждый из которых выполняет роль отдельного "экрана" или вкладки. При нажатии на пункт меню или кнопку навигации:
1. Текущая активная панель скрывается (`panelCurrent.Hide()`).
2. Целевая панель делается видимой (`panelTarget.Show()`, `panelTarget.BringToFront()`).

Этот подход позволяет мгновенно переключаться между режимами работы (например, "Авторизация" -> "Главное меню" -> "Отчеты"), не создавая оверхед на открытие/закрытие окон и сохраняя контекст данных в памяти.

---

### Навигация и порядок обхода (TabOrder)

Пользователь, работающий с профессиональным приложением, активно использует клавиатуру: переключение между полями ввода выполняется клавишей `Tab`, подтверждение — `Enter`, отмена — `Esc`.

Каждый элемент управления имеет свойство `TabIndex` (целое неотрицательное число). Когда фокус находится на форме, нажатие клавиши `Tab` перемещает фокус на следующий элемент в порядке возрастания `TabIndex`. Если порядок нарушен, фокус будет хаотично прыгать по форме с верхнего угла в нижний и обратно. Настроить порядок обхода можно через специальный инструмент визуальной среды (*View -> Tab Order*) или вручную в окне свойств.

---

### Стилизация и доступность

Современный .NET 8 поддерживает гибкую настройку внешнего вида элементов через свойства шрифтов (`Font`), цветов переднего плана (`ForeColor`) и фона (`BackColor`). При проектировании интерфейса критически важно соблюдать контрастность текста и элементов фона, использовать стандартные системные шрифты и обеспечивать достаточные отступы (`Padding`, `Margin`) между элементами, чтобы интерфейс выглядел аккуратно и не перегружено.

### Разобранные примеры

#### Пример 1. Макет формы для приложения учета товаров
**Условие:** Спроектировать макет формы для приложения учета товаров: левая панель содержит фильтры (ComboBox категории, CheckBox наличия), центральная часть занята DataGridView для вывода списка, а правая панель содержит кнопки управления (Добавить, Изменить, Удалить). Настроить свойства Anchor и Dock так, чтобы таблица растягивалась при изменении размеров окна.

**Ход рассуждений:**
1. Нам нужна главная форма приложения. Разделим её рабочую область на три логических блока с помощью контейнеров `Panel` или `SplitContainer`, либо используя свойства `Dock`.
2. Левая панель (`panelLeft`) будет содержать фильтры. Установим ей `Dock = DockStyle.Left` и зададим фиксированную ширину (например, 250 пикселей). Внутри неё разместим `Label` и `ComboBox` для выбора категории, а также `CheckBox` для фильтра "Только в наличии".
3. Правая панель (`panelRight`) будет содержать кнопки управления. Установим ей `Dock = DockStyle.Right` и фиксированную ширину (например, 180 пикселей). Внутри разместим вертикально три кнопки (`btn1Add`, `btn2Edit`, `btn3Delete`) с привязкой `Anchor = Top | Left | Right`.
4. Центральная часть (`dataGridViewProducts`) должна занимать всё оставшееся пространство. Установим ей `Dock = DockStyle.Fill`. Благодаря этому при изменении размеров главного окна левая и правая панели сохранят свои размеры, а таблица автоматически расширится или сузится, заполнив центральную область.

**Реализация структуры формы в коде C# (метод инициализации компонентов):**

```csharp
using System;
using System.Windows.Forms;
using System.Drawing;

public class ProductForm : Form
{
    private Panel panelLeft;
    private Panel panelRight;
    private DataGridView dgvProducts;
    
    private ComboBox cmbCategory;
    private CheckBox chkInStock;
    
    private Button btnAdd;
    private Button btnEdit;
    private Button btnDelete;

    public ProductForm()
    {
        // Настройка главной формы
        this.Text = "Учет товаров на складе";
        this.Size = new Size(900, 600);
        this.MinimumSize = new Size(600, 400);

        // 1. Левая панель фильтров
        panelLeft = new Panel();
        panelLeft.Dock = DockStyle.Left;
        panelLeft.Width = 240;
        panelLeft.BackColor = Color.WhiteSmoke;
        
        Label lblCategory = new Label();
        lblCategory.Text = "Категория товара:";
        lblCategory.Location = new Point(15, 20);
        lblCategory.AutoSize = true;
        
        cmbCategory = new ComboBox();
        cmbCategory.Location = new Point(15, 45);
        cmbCategory.Width = 210;
        cmbCategory.DropDownStyle = ComboBoxStyle.DropDownList;
        cmbCategory.Items.AddRange(new string[] { "Все категории", "Электроника", "Бытовая техника", "Инструменты" });
        cmbCategory.SelectedIndex = 0;

        chkInStock = new CheckBox();
        chkInStock.Text = "Только в наличии";
        chkInStock.Location = new Point(15, 85);
        chkInStock.AutoSize = true;

        panelLeft.Controls.Add(lblCategory);
        panelLeft.Controls.Add(cmbCategory);
        panelLeft.Controls.Add(chkInStock);

        // 2. Правая панель с кнопками управления
        panelRight = new Panel();
        panelRight.Dock = DockStyle.Right;
        panelRight.Width = 180;
        panelRight.BackColor = Color.WhiteSmoke;

        btnAdd = new Button();
        btnAdd.Text = "Добавить";
        btnAdd.Location = new Point(15, 20);
        btnAdd.Size = new Size(150, 35);
        btnAdd.Anchor = AnchorStyles.Top | AnchorStyles.Left | AnchorStyles.Right;

        btnEdit = new Button();
        btnEdit.Text = "Изменить";
        btnEdit.Location = new Point(15, 65);
        btnEdit.Size = new Size(150, 35);
        btnEdit.Anchor = AnchorStyles.Top | AnchorStyles.Left | AnchorStyles.Right;

        btnDelete = new Button();
        btnDelete.Text = "Удалить";
        btnDelete.Location = new Point(15, 110);
        btnDelete.Size = new Size(150, 35);
        btnDelete.Anchor = AnchorStyles.Top | AnchorStyles.Left | AnchorStyles.Right;
        btnDelete.ForeColor = Color.DarkRed;

        panelRight.Controls.Add(btnAdd);
        panelRight.Controls.Add(btnEdit);
        panelRight.Controls.Add(btnDelete);

        // 3. Центральная таблица (DataGridView)
        dgvProducts = new DataGridView();
        dgvProducts.Dock = DockStyle.Fill;
        dgvProducts.AutoSizeColumnsMode = DataGridViewAutoSizeColumnsMode.Fill;
        dgvProducts.AllowUserToAddRows = false;
        dgvProducts.ReadOnly = true;

        // Добавление элементов на форму (важен порядок: сначала панели стыковки, потом Fill)
        this.Controls.Add(dgvProducts);
        this.Controls.Add(panelRight);
        this.Controls.Add(panelLeft);
    }
}
```

**Проверка и правдоподобность:** При запуске такой формы элементы `panelLeft` жестко прижаты к левой границе, `panelRight` — к правой, а `dgvProducts` занимает всю оставшуюся центральную часть. При изменении размера окна по горизонтали и вертикали таблица плавно масштабируется, элементы управления не перекрывают друг друга.

#### Пример 2. Форма авторизации и многопанельное переключение интерфейса
**Условие:** Создать форму авторизации и главного меню: первая панель содержит поля ввода логина и пароля с валидацией, после успешного входа происходит скрытие панели авторизации и отображение рабочей зоны с верхним меню MenuStrip (Файл, Справка) и статус-баром StatusStrip.

**Ход рассуждений:**
1. Нам потребуется главная форма, на которой мы разместим два контейнера типа `Panel`, работающие в режиме взаимоисключающей видимости: `panelAuth` (экран входа) и `panelMainWorkspace` (основное рабочее пространство).
2. На `panelAuth` разместим две метки, два текстовых поля (`txtLogin` и `txtPassword` с маскировкой символов через `PasswordChar = '*'`) и кнопку `btnLogin`.
3. В обработчик нажатия кнопки входа добавим простейшую валидацию: если логин равен `admin` и пароль равен `12345`, то скрываем `panelAuth` (`panelAuth.Visible = false`), делаем видимой рабочую панель (`panelMainWorkspace.Visible = true`) и активируем верхнее меню.
4. На главном уровне формы добавим `MenuStrip` с пунктами "Файл" (выход) и "Справка" (о программе), а также `StatusStrip` для отображения статуса системы.

**Реализация в коде C#:**

```csharp
using System;
using System.Windows.Forms;
using System.Drawing;

public class MainForm : Form
{
    private Panel panelAuth;
    private Panel panelMainWorkspace;
    
    private TextBox txtLogin;
    private TextBox txtPassword;
    private Button btnSignIn;
    
    private MenuStrip menuStripMain;
    private StatusStrip statusStripMain;
    private ToolStripStatusLabel statusLabel;

    public MainForm()
    {
        this.Textавторизации = "Системное приложение";
        this.Size = new Size(800, 500);
        this.StartPosition = FormStartPosition.CenterScreen;

        // Создаем главное меню (скрыто до авторизации или доступно в режиме гостя)
        CreateMenu();

        // Создаем статус-бар
        statusStripMain = new StatusStrip();
        statusLabel = new ToolStripStatusLabel("Статус: Требуется авторизация");
        statusStripMain.Items.Add(statusLabel);
        this.Controls.Add(statusStripMain);

        // 1. Создание панели авторизации
        panelAuth = new Panel();
        panelAuth.Dock = DockStyle.Fill;
        panelAuth.BackColor = Color.FromArgb(240, 244, 248);

        GroupBox gbAuthBox = new GroupBox();
        gbAuthBox.Text = "Авторизация в системе";
        gbAuthBox.Size = new Size(320, 220);
        gbAuthBox.Location = new Point((this.ClientSize.Width - 320) / 2, (this.ClientSize.Height - 220) / 2);
        gbAuthBox.Anchor = AnchorStyles.None;

        Label lblLog = new Label() { Text = "Логин:", Location = new Point(20, 35), AutoSize = true };
        txtLogin = new TextBox() { Location = new Point(20, 55,), Width = 270 };

        Label lblPass = new Label() { Text = "Пароль:", Location = new Point(20, 95), AutoSize = true };
        txtPassword = new TextBox() { Location = new Point(20, 115), Width = 270, PasswordChar = '*' };

        btnSignIn = new Button() { Text = "Войти", Location = new Point(20, 160), Size = new Size(270, 30) };
        btnSignIn.Click += BtnSignIn_Click;

        gbAuthBox.Controls.Add(lblLog);
        gbAuthBox.Controls.Add(txtLogin);
        gbAuthBox.Controls.Add(lblPass);
        gbAuthBox.Controls.Add(txtPassword);
        gbAuthBox.Controls.Add(btnSignIn);

        panelAuth.Controls.Add(gbAuthBox);

        // 2. Создание главной рабочей панели (скрыта по умолчанию)
        panelMainWorkspace = new Panel();
        panelMainWorkspace.Dock = DockStyle.Fill;
        panelMainWorkspace.BackColor = Color.White;
        panelMainWorkspace.Visible = false;

        Label lblWelcome = new Label();
        lblWelcome.Text = "Добро пожаловать в рабочую зону!";
        lblWelcome.Font = new Font("Arial", 16, FontStyle.Bold);
        lblWelcome.Location = new Point(30, 30);
        lblWelcome.AutoSize = true;

        panelMainWorkspace.Controls.Add(lblWelcome);

        // Добавляем панели на форму
        this.Controls.Add(panelMainWorkspace);
        this.Controls.Add(panelAuth);
    }

    private void CreateMenu()
    {
        menuStripMain = new MenuStrip();
        
        ToolStripMenuItem menuFile = new ToolStripMenuItem("Файл");
        ToolStripMenuItem menuExit = new ToolStripMenuItem("Выход", null, (s, e) => this.Close());
        menuFile.DropDownItems.Add(menuExit);

        ToolStripMenuItem menuHelp = new ToolStripMenuItem("Справка");
        ToolStripMenuItem menuAbout = new ToolStripMenuItem("О программе", null, (s, e) => 
            MessageBox.Show("Учебное приложение v1.0", "Справка", MessageBoxButtons.OK, MessageBoxIcon.Information));
        menuHelp.DropDownItems.Add(menuAbout);

        menuStripMain.Items.Add(menuFile);
        menuStripMain.Items.Add(menuHelp);

        this.MainMenuStrip = menuStripMain;
        this.Controls.Add(menuStripMain);
    }

    private void BtnSignIn_Click(object sender, EventArgs e)
    {
        // Простейшая валидация учетных данных
        string login = txtLogin.Text.Trim();
        string password = txtPassword.Text;

        if (login == "admin" && password == "12345")
        {
            // Переход на рабочую панель
            panelAuth.Visible = false;
            panelMainWorkspace.Visible = true;
            statusLabel.Text = "Статус: Пользователь авторизован [admin]";
        }
        else
        {
            MessageBox.Show("Неверный логин или пароль!", "Ошибка входа", MessageBoxButtons.OK, MessageBoxIcon.Error);
            txtPassword.Clear();
            txtPassword.Focus();
        }
    }
}
```

**Проверка и правдоподобность:** При запуске программы пользователь видит по центру экрана аккуратную форму входа. Ввод неверных данных вызывает модальное окно с предупреждением, очищает поле пароля и возвращает фокус ввода. При вводе правильных данных (`admin` / `12345`) панель авторизации мгновенно скрывается, открывая доступ к рабочей зоне интерфейса и верхнему меню, а статус в нижней части экрана обновляется.

## 3. Связывание данных и работа с табличным представлением DataGridView

### Назначение и возможности компонента DataGridView

Компонент `위원` (в терминологии Windows Forms — `DataGridView`) представляет собой мощный и гибкий элемент управления для отображения и редактирования табличных данных. В отличие от устаревшего элемента `DataGrid`, компонент `DataGridView` предоставляет огромные возможности по настройке внешнего вида, управлению поведением строк, столбцов и ячеек, а также поддерживает различные режимы работы с источниками данных.

Основное назначение `DataGridView` в бизнес-приложениях — визуализация списков объектов, полученных из базы данных, файлов или сформированных в оперативной памяти. Этот элемент управления позволяет пользователю не только просматривать информацию, но и выполнять сортировку по столбцам, изменять размеры ячеек, добавлять, удалять и редактировать записи прямо в таблице.

С архитектурной точки зрения `DataGridView` отделяет визуальное представление (интерфейс) от хранящихся данных. Это реализуется с помощью механизма **привязки данных (Data Binding)**. Вместо того чтобы вручную заполнять каждую ячейку таблицы циклом, разработчик связывает `DataGridView` с готовой коллекцией объектов в памяти.

---

### Коллекция BindingList\<T\> и автоматическое обновление интерфейса

При разработке приложений на C# для хранения списков объектов чаще всего используется стандартный класс `List<T>`. Однако при связывании `List<T>` с графическими элементами управления, такими как `DataGridView`, возникает проблема: если в коде программы в коллекцию добавляется новый элемент или удаляется существующий, таблица на экране **не обновляется автоматически**. Пользователь не увидит изменений до тех пор, пока не будет выполнен принудительный пересчет или повторная привязка источника данных.

Для решения этой проблемы в пространстве имен `System.ComponentModel` предусмотрен специализированный класс коллекций — `BindingList<T>`.

> **Определение.** `BindingList<T>` — это универсальная коллекция, которая реализует стандартные интерфейсы списков, а также интерфейсы `IBindingList` и `INotifyPropertyChanged` / `IRaiseItemChangedEvents`, что позволяет ей мгновенно уведомлять связанные элементы управления (например, `DataGridView`) о любых изменениях своего содержимого (добавление, удаление или изменение элементов).

Рассмотрим сравнение стандартного списка и `BindingList<T>` в контексте Windows Forms:

| Характеристика | `List<T>` | `BindingList<T>` |
|---|---|---|
| Поддержка интерфейсов привязки | Базовые (`IEnumerable<T>`, `IList<T>`) | Полные (`IBindingList`, интерфейсы уведомлений) |
| Реакция `DataGridView` на `Add()` / `Remove()` | Отсутствует (требуется `ResetBindings()`) | Автоматическая (интерфейс обновляется сразу) |
| Производительность при массовых операциях | Выше | Чуть ниже за счет отправки событий уведомления |
| Поддержка поиска и сортировки из коробки | Ограничена методами LINQ | Встроена (свойства `AllowNew`, `AllowEdit`, `AllowRemove`) |

Применение `BindingList<T>` избавляет разработчика от написания рутинного кода по обновлению интерфейса. Как только в коллекцию добавляется объект, `DataGridView` мгновенно отображает новую строку.

### Ручное и автоматическое создание столбцов и свойство DataPropertyName

По умолчанию, когда вы связываете `BindingList<T>` с компонентом `DataGridView`, среда автоматически анализирует публичные свойства класса `T` и создает для каждого из них соответствующий столбец в таблице. Этот режим называется **автоматической генерацией столбцов** (`AutoGenerateColumns = true`).

Однако автоматический режим подходит только для простейших прототипов. На практике автоматические названия столбцов совпадают с именами свойств в коде (например, `RegistrationNumber` вместо понятного пользователю «Гос. номер»), а порядок столбцов может оказаться случайным. Для профессиональных приложений используют ручное проектирование таблицы:

1. Свойству `DataGridView.AutoGenerateColumns` присваивается значение `false`.
2. В дизайнере форм или программно создаются столбцы нужного типа (`DataGridViewTextBoxColumn`, `DataGridViewCheckBoxColumn`, `DataGridViewComboBoxColumn` и т.д.).
3. Для каждого созданного столбца настраивается ключевое свойство **`DataPropertyName`**.

> **Правило.** Свойство `DataPropertyName` столбца таблицы должно точно соответствовать имени публичного свойства в классе привязанного объекта (с учетом регистра). Благодаря этому механизм привязки понимает, данные какого именно свойства класса нужно выводить в конкретную ячейку таблицы.

### Форматирование отображаемых данных

При выводе данных пользователю часто требуется преобразовать их в удобочитаемый вид: отобразить денежные суммы с указанием валюты и двумя знаками после запятой, отформатировать даты в привычный формат (`ДД.ММ.ГГГГ`) или выровнять числовые значения по правому краю.

В `DataGridView` форматирование данных настраивается на уровне отдельных столбцов с помощью свойства `DefaultCellStyle.Format`. 

Основные строки форматирования в C#:
- Денежный формат: `C2` (выводит число с символом валюты текущей локали и двумя знаками).
- Числовой формат с разделителями тысяч: `N2` (например, `1 250{,}50`).
- Формат даты: `d` (краткая дата) или `yyyy-MM-dd`.
- Проценты: `P1`.

Пример настройки формата для столбца цены в коде:
```csharp
columnPrice.DefaultCellStyle.Format = "N2";
columnPrice.DefaultCellStyle.Alignment = DataGridViewContentAlignment.MiddleRight;
```

### Обработка выбора строки, сортировка и фильтрация

Интерактивность таблиц обеспечивается обработкой событий. Самое востребованное событие компонента `DataGridView` — это **`CellClick`** или **`SelectionChanged`**, которые срабатывают, когда пользователь выбирает строку мышью или с помощью клавиатуры.

Для получения доступа к выбранному объекту используется свойство `CurrentRow` таблицы и свойство `DataBoundItem`, которое хранит ссылку на исходный объект класса из коллекции `BindingList<T>`.

**Фильтрация и сортировка:**
Хотя `BindingList<T>` не поддерживает расширенную фильтрацию «из коробки» (в отличие от `BindingSource`), стандартную фильтрацию можно реализовать путем создания вспомогательной выборки с помощью LINQ и последующего заполнения временного `BindingList<T>`, либо используя связку `DataGridView` с компонентом **`BindingSource`**, который выступает посредником между коллекцией и таблицей.

### Разобранный пример 1: Учет автомобилей и добавление записей

Разработаем оконное приложение для учета автомобилей. Каждая запись содержит марку (`Brand`), год выпуска (`Year`) и цену (`Price`).

#### Шаг 1. Проектирование класса данных
Создадим класс `Car` с необходимыми свойствами и конструктором:

```csharp
public class Car
{
    public string Brand { get; set; }
    public int Year { get; set; }
    public decimal Price { get; set; }

    public Car(string brand, int year, decimal price)
    {
        Brand = brand;
        Year = year;
        Price = price;
    }
}
```

#### Шаг 2. Инициализация формы и привязка данных
На форме разместим:
- `DataGridView` с именем `dataGridViewCars`.
- Поля ввода (`TextBox`) для марки (`txtBrand`), года (`txtYear`) и цены (`txtPrice`).
- Кнопку «Добавить» (`btnAdd`).

В коде формы создадим поле класса — коллекцию `BindingList<Car>`:

```csharp
public partial class MainForm : Form
{
    private BindingList<Car> carsList;

    public MainForm()
    {
        InitializeComponent();
        InitializeCarTable();
    }

    private void InitializeCarTable()
    {
        // Отключаем автогенерацию столбцов для ручной настройки
        dataGridViewCars.AutoGenerateColumns = false;
        dataGridViewCars.ColumnCount = 3;

        // Настраиваем столбец Марка
        dataGridViewCars.Columns[0].Name = "Brand";
        dataGridViewCars.Columns[0].HeaderText = "Марка автомобиля";
        dataGridViewCars.Columns[0].DataPropertyName = "Brand";
        dataGridViewCars.Columns[0].Width = 150;

        // Настраиваем столбец Год выпуска
        dataGridViewCars.Columns[1].Name = "Year";
        dataGridViewCars.Columns[1].HeaderText = "Год выпуска";
        dataGridViewCars.Columns[1].DataPropertyName = "Year";
        dataGridViewCars.Columns[1].Width = 100;

        // Настраиваем столбец Цена
        dataGridViewCars.Columns[2].Name = "Price";
        dataGridViewCars.Columns[2].HeaderText = "Цена (руб.)";
        dataGridViewCars.Columns[2].DataPropertyName = "Price";
        dataGridViewCars.Columns[2].DefaultCellStyle.Format = "N2";
        dataGridViewCars.Columns[2].DefaultCellStyle.Alignment = DataGridViewContentAlignment.MiddleRight;
        dataGridViewCars.Columns[2].Width = 120;

        // Инициализируем коллекцию начальными данными
        carsList = new BindingList<Car>
        {
            new Car("Lada Granta", 2022, 850000.00m),
            new Car("Haval Jolion", 2023, 2150000.50m),
            new Car("Chery Tiggo 4", 2021, 1600000.00m)
        };

        // Привязываем коллекцию к таблице
        dataGridViewCars.DataSource = carsList;
    }
}
```

#### Шаг 3. Реализация добавления нового автомобиля
Напишем обработчик нажатия на кнопку «Добавить», который считывает данные из полей ввода, проверяет их корректность и добавляет новый объект в `BindingList<Car>`:

```csharp
private void btnAdd_Click(object sender, EventArgs e)
{
    // Считываем и проверяем введенные данные
    string brand = txtBrand.Text.Trim();
    if (string.IsNullOrEmpty(brand))
    {
        MessageBox.Show("Введите марку автомобиля!", "Ошибка валидации", MessageBoxButtons.OK, MessageBoxIcon.Warning);
        return;
    }

    if (!int.TryParse(txtYear.Text, out int year) || year < 1900 || year > 2025)
    {
        MessageBox.Show("Некорректный год выпуска!", "Ошибка", MessageBoxButtons.OK, MessageBoxIcon.Error);
        return;
    }

    if (!decimal.TryParse(txtPrice.Text, out decimal price) || price <= 0)
    {
        MessageBox.Show("Цена должна быть положительным числом!", "Ошибка", MessageBoxButtons.OK, MessageBoxIcon.Error);
        return;
    }

    // Создаем новый объект и добавляем в коллекцию
    Car newCar = new Car(brand, year, price);
    carsList.Add(newCar);

    // Очищаем поля ввода после успешного добавления
    txtBrand.Clear();
    txtYear.Clear();
    txtPrice.Clear();

    MessageBox.Show("Автомобиль успешно добавлен в таблицу.", "Информация", MessageBoxButtons.OK, MessageBoxIcon.Information);
}
```

### Разобранный пример 2: Выбор строки и редактирование объекта

Реализуем обратную задачу: при клике на любую строку в таблице `DataGridView` данные выбранного автомобиля должны автоматически переноситься в текстовые поля для редактирования. После изменения данных в полях пользователь нажимает кнопку «Сохранить изменения» (`btnSave`), и объект в коллекции обновляется.

#### Шаг 1. Сохранение ссылки на редактируемый объект
В классе формы объявим вспомогательную переменную для хранения текущего выбранного объекта:

```csharp
private Car selectedCar = null;
```

#### Шаг 2. Обработка клика по строке таблицы
Подпишемся на событие `CellClick` компонента `DataGridView` (это можно сделать через конструктор формы или панель свойств Visual Studio):

```csharp
private void dataGridViewCars_CellClick(object sender, DataGridViewCellEventArgs e)
{
    // Проверяем, что кликнули по валидной строке (не по шапке таблицы)
    if (e.RowIndex >= 0)
    {
        // Получаем объект Car, привязанный к выбранной строке
        selectedCar = dataGridViewCars.Rows[e.RowIndex].DataBoundItem as Car;

        if (selectedCar != null)
        {
            // Переносим данные в текстовые поля для редактирования
            txtBrand.Text = selectedCar.Brand;
            txtYear.Text = selectedCar.Year.ToString();
            txtPrice.Text = selectedCar.Price.ToString("F2");
        }
    }
}
```

#### Шаг 3. Сохранение изменений в объекте
Напишем обработчик нажатия на кнопку «Сохранить изменения» (`btnSave_Click`):

```csharp
private void btnSave_Click(object sender, EventArgs e)
{
    // Проверяем, был ли вообще выбран автомобиль для редактирования
    if (selectedCar == null)
    {
        MessageBox.Show("Выберите автомобиль из таблицы для редактирования!", "Внимание", MessageBoxButtons.OK, MessageBoxIcon.Warning);
        return;
    }

    // Валидация введенных данных
    string brand = txtBrand.Text.Trim();
    if (string.IsNullOrEmpty(brand))
    {
        MessageBox.Show("Поле марки не может быть пустым!", "Ошибка", MessageBoxButtons.OK, MessageBoxIcon.Error);
        return;
    }

    if (!int.TryParse(txtYear.Text, out int year) || year < 1900 || year > 2025)
    {
        MessageBox.Show("Введите корректный год!", "Ошибка", MessageBoxButtons.OK, MessageBoxIcon.Error);
        return;
    }

    if (!decimal.TryParse(txtPrice.Text, out decimal price) || price <= 0)
    {
        MessageBox.Show("Введите корректную цену!", "Ошибка", MessageBoxButtons.OK, MessageBoxIcon.Error);
        return;
    }

    // Обновляем свойства выбранного объекта
    selectedCar.Brand = brand;
    selectedCar.Year = year;
    selectedCar.Price = price;

    // Принудительно уведомляем BindingList об изменении элемента, 
    // чтобы DataGridView перерисовал измененную строку
    int rowIndex = carsList.IndexOf(selectedCar);
    if (rowIndex >= 0)
    {
        carsList.ResetItem(rowIndex);
    }

    // Сбрасываем выбранный объект и очищаем поля
    selectedCar = null;
    txtBrand.Clear();
    txtYear.Clear();
    txtPrice.Clear();

    MessageBox.Show("Изменения успешно сохранены!", "Успех", MessageBoxButtons.OK, MessageBoxIcon.Information);
}
```

**Разбор хода рассуждений:**
1. При клике на строку мы извлекаем `DataBoundItem`. Поскольку `DataGridView` привязан к `BindingList<Car>`, свойство `DataBoundItem` возвращает именно тот экземпляр `Car`, который хранится в этой строке.
2. Присвоение `selectedCar = dataGridViewCars.Rows[e.RowIndex].DataBoundItem as Car` позволяет нам напрямую работать со ссылкой на объект в памяти, избегая поиска по индексам.
3. Метод `carsList.ResetItem(rowIndex)` является критически важным. Хотя свойства объекта `Car` изменились, сам объект в коллекции остался тем же. Вызов `ResetItem` сообщает таблице, что строка под данным индексом была модифицирована, и заставляет `DataGridView` обновить ее визуальное отображение.

---

### Проверка и самоконтроль

1. **Единицы и форматы:** Убедитесь, что для денежных полей используется формат `N2` или `C2`, а числовые значения перед записью в свойства обязательно проходят проверку через методы `int.TryParse` и `decimal.TryParse`.
2. **Правдоподобность:** Если при изменении данных в таблице интерфейс не обновляется, проверьте, используется ли `BindingList<T>` вместо обычного `List<T>`, и вызывается ли метод `ResetItem(index)` при программной модификации свойств объекта.
3. **Безопасность типов:** Всегда используйте безопасное приведение типов с помощью оператора `as` (`as Car`) и проверку на `null`, так как пользователь может кликнуть по пустой области таблицы под строками данных.

## 4. Обработка событий, валидация ввода и обработка исключений

### Жизненный цикл событий в Windows Forms и порядок их вызова

 > **Определение.** Событие в C# — это механизм уведомления класса-издателя о том, что произошло некоторое действие. В контексте Windows Forms события связывают действия пользователя (клики мыши, нажатия клавиш, перемещение окна) или изменения состояния системы с программным кодом, который должен на эти действия отреагировать.

Каждый элемент управления (контрол) и сама форма (`Form`) обладают строго определенным жизненным циклом. Понимание порядка вызова событий критически важно для предотвращения логических ошибок, таких как попытка обратиться к элементу управления до того, как он был инициализирован.

Рассмотрим стандартную последовательность срабатывания событий при запуске, работе и закрытии формы:

1. `Constructor` формы (метод `InitializeComponent()`). На этом этапе создаются все визуальные элементы, задаются их начальные свойства, но на экране они еще не отображены. Обращаться к размерам контроллов или пытаться получить фокус ввода здесь преждевременно.
2. `Load`. Событие формы, которое наступает непосредственно перед тем, как форма отображается на экране в первый раз. Идеальное место для загрузки данных из файлов, инициализации списков (`BindingList<T>`) и настройки параметров интерфейса.
3. `Shown`. Срабатывает сразу после того, как форма стала видимой. Используется для запуска фоновых процессов, длительных вычислений или показа приветственных диалогов.
4. `Activated` / `Deactivated`. Возникают каждый раз, когда фокус ввода переносится на данную форму (или уходит с нее).
5. События взаимодействия во время работы программы (`MouseDown`, `MouseUp`, `Click`, `DoubleClick`, `TextChanged`, `KeyPress`, `SelectedIndexChanged`).
6. `FormClosing`. Срабатывает в момент, когда пользователь или программа инициировали закрытие окна (нажатие на крестик, вызов метода `Close()`). В этот момент можно отменить закрытие (например, если есть несохраненные данные).
7. `FormClosed`. Форма окончательно закрыта, ресурсы освобождаются.

### Динамическая подписка и отписка от событий в коде программы

В визуальном дизайнере Visual Studio подписка на события (например, генерация обработчика клика по кнопке) происходит автоматически при двойном клике по элементу. Однако в реальных проектах часто возникает необходимость управлять подпиской программно в процессе выполнения программы.

Делегат в C# выступает основой для работы с событиями. Подписаться на событие можно с помощью оператора `+=`, а отписаться — с помощью `-=`.

Рассмотрим пример динамического создания кнопок и управления их событиями:

```csharp
using System;
using System.Drawing;
using System.Windows.Forms;

namespace EventDemoApp
{
    public partial class MainForm : Form
    {
        private Button dynamicButton;

        public MainForm()
        {
            InitializeComponent();
            
            // Создаем кнопку в коде
            dynamicButton = new Button();
            dynamicButton.Text "Динамическая кнопка";
            dynamicButton.Location = new Point(50, 50);
            dynamicButton.Size = new Size(160, 40);
            
            // Динамическая подписка на событие Click
            dynamicButton.Click += DynamicButton_Click;
            
            // Добавляем элемент на форму
            this.Controls.Add(dynamicButton);
        }

        private void DynamicButton_Click(object sender, EventArgs e)
        {
            MessageBox.Show("Кнопка нажата!", "Уведомление", MessageBoxButtons.OK, MessageBoxIcon.Information);
            
            // Пример отписки от события после первого клика, чтобы событие больше не срабатывало
            dynamicButton.Click -= DynamicButton_Click;
            dynamicButton.Text = "Отключено";
            dynamicButton.Enabled = false;
        }
    }
}
```

В приведенном коде объект `sender` хранит ссылку на элемент управления, который инициировал событие (в данном случае `dynamicButton`). Приведение типов `(Button)sender` позволяет получить доступ к свойствам конкретной кнопки, если один и тот же метод-обработчик используется для нескольких элементов.

### Валидация пользовательского ввода на стороне клиента

 > **Определение.** Валидация пользовательского ввода — это процесс проверки корректности, полноты и допустимости данных, введенных пользователем в элементы интерфейса, до их передачи в бизнес-логику или сохранения в базу данных/файл.

Валидация на стороне клиента защищает приложение от аварийных завершений, вызванных неверным форматом данных. В Windows Forms проверка реализуется двумя путями:
1. Ограничение ввода «на лету» (предотвращение ввода неверных символов).
2. Проверка заполненности и корректности данных по нажатию кнопки подтверждения («Сохранить», «Рассчитать»).

Для безопасного преобразования строк в числовые типы категорически не рекомендуется использовать прямой вызов `int.Parse()` или `double.Parse()` для пользовательского ввода, так как при некорректном значении они выбрасывают исключение `FormatException`. Вместо этого применяются методы со статусом успешности: `int.TryParse()` и `double.TryParse()`.

### Использование событий KeyPress для ограничения ввода

Рассмотрим первый разобранный пример: написание обработчика события `KeyPress` для `TextBox`, разрешающего ввод только цифр, одной десятичной точки и управляющих клавиш (таких как `Backspace`), а также добавление проверки на пустые поля в событие `Click` кнопки расчетов.

```csharp
using System;
using System.Windows.Forms;

namespace CalculatorApp
{
    public partial class CalculationForm : Form

                return;
            }

            }

            if (e.KeyChar == '.' && !textBox.Text.Contains("."))
            {

            }

            // Все остальные символы блокируем
            e.Handled = true;
        }

            if (double.TryParse(txtInput.Text.Replace('.', ','), out double value))
```

2. Метод `char.IsControl(e.KeyChar)` пропускает служебные клавиши (например, удаление символа назад).
3. Проверка `!textBox.Text.Contains(".")` гарантирует, что пользователь не сможет ввести дробную часть с несколькими точками, что привело бы к сбою формата.
4. В обработчике `BtnCalculate_Click` метод `string.IsNullOrWhiteSpace` проверяет, не оставил ли пользователь поле пустым или состоящим из одних пробелов.

### Безопасное считывание числовых параметров и подсветка ошибок

Рассмотрим второй разобранный пример: реализацию безопасного считывания числовых параметров из текстовых полей с перехватом возможных ошибок преобразования, выводом понятного сообщения и изменением цвета проблемного элемента управления (`TextBox`) на красный.

```csharp
private void ProcessNumericInput()
```

### Перехват исключений с помощью блока try-catch-finally

Даже при тщательной валидации пользовательского ввода могут возникать нештатные ситуации: сбои при чтении файлов, проблемы с доступом к сети или исчерпание памяти. Для обработки таких критических ситуаций в C# используется конструкция `try-catch-finally`.

Структура блока:
- `try` — защищенный блок кода, в котором может возникнуть исключение.
- `catch (ExceptionType ex)` — блок перехвата ошибки определенного типа. Переменная `ex` содержит подробную информацию об ошибке (`ex.Message`).
- `finally` — блок кода, который выполняется **всегда** (независимо от того, произошло исключение или нет). Используется для освобождения ресурсов (закрытие файлов, отключение от баз данных).

Пример безопасного чтения числовых данных из файла с использованием `try-catch-finally`:

```csharp
using System;
using System.IO;
using System.Windows.Forms;

public void LoadDataFromFile(string filePath)
{
    StreamReader reader = null;

    try
    {
        // Открытие файла для чтения
        reader = new StreamReader(filePath);
        string line = reader.ReadLine();

        if (line != null)
        {
            if (int.TryParse(line, out int fileNumber))
            {
                MessageBox.Show($"Прочитанное число: {fileNumber}", "Успех");
            }
            else
            {
                throw new FormatException("Файл содержит данные некорректного формата.");
            }
        }
    }
    .catch (FileNotFoundException ex)
    {
        MessageBox.Show($"Указанный файл не найден на диске.\nДетали: {ex.Message}", 
            "Ошибка файла", MessageBoxButtons.OK, MessageBoxIcon.Error);
    }
    catch (FormatException ex)
    {
        MessageBox.Show($"Ошибка структуры данных: {ex.Message}", 
            "Ошибка формата", MessageBoxButtons.OK, MessageBoxIcon.Warning);
    }
    catch (Exception ex)
    {
        // Перехват любых непредвиденных исключений
        MessageBox.Show($"Произошла непредвиденная ошибка: {ex.Message}", 
            "Критическая ошибка", MessageBoxButtons.OK, MessageBoxIcon.Error);
    }
    finally
    {
        // Гарантированное закрытие потока и освобождение системного файла
        if (reader != null)
        {
            reader.Close();
            reader.Dispose();
        }
    }
}
```

### Подтверждение закрытия формы через событие FormClosing

Часто в приложениях требуется предотвратить случайное закрытие окна пользователем (например, если он ввел данные, но не сохранил их). Для этого используется событие формы `FormClosing` и класс аргументов `FormClosingEventArgs`.

Свойство `e.Cancel` типа `bool` позволяет отменить закрытие формы, если его установить в значение `true`.

```csharp
using System;
using System.Windows.Forms;

namespace AppLifecycleDemo
{
    public partial class MainForm : Form
    {
        private bool hasUnsavedChanges = true; // Флаг наличия несохраненных данных

        public MainForm()
        {
            InitializeComponent();
            
            // Подписка на событие закрытия формы
            this.FormClosing += MainForm_FormClosing;
        }

        private void MainForm_FormClosing(object sender, FormClosingEventArgs e)
        {
            if (hasUnsavedChanges)
            {
                // Выводим диалоговое окно с вопросом к пользователю
                DialogResult dialogResult = MessageBox.Show(
                    "У вас есть несохраненные изменения. Вы действительно хотите закрыть приложение?",
                    "Подтверждение выхода",
                    MessageBoxButtons.YesNo,
                    MessageBoxIcon.Warning
                );

                // Если пользователь нажал кнопку "Нет", отменяем закрытие формы
                if (dialogResult == DialogResult.No)
                {
                    e.Cancel = true; // Отмена закрытия окна
                }
            }
        }
    }
}
```

**Разбор работы механизма закрытия:**
1. При попытке пользователя закрыть окно срабатывает метод `MainForm_FormClosing`.
2. Проверяется переменная `hasUnsavedChanges`. Если данные изменены, вызывается метод `MessageBox.Show` с кнопками `Yes` и `No`.
3. Результат выбора пользователя сохраняется в перечисление `DialogResult`.
4. Если выбор равен `DialogResult.No`, установка `e.Cancel = true` прерывает процесс уничтожения формы, возвращая пользователя в рабочую среду программы.

## 5. Интеграция с файловой системой и сохранение состояния приложения

### Использование диалоговых окон OpenFileDialog и SaveFileDialog

Разработка любого полноценного настольного приложения неизбежно упирается в необходимость взаимодействия с файловой системой операционной системы. Пользователь должен иметь возможность самостоятельно указывать, куда сохранить созданные им данные и откуда загрузить ранее подготовленные файлы. В платформе .NET и технологии Windows Forms для этой цели предусмотрены стандартные диалоговые окна операционной системы: `OpenFileDialog` (диалог открытия файла) и `SaveFileDialog` (диалог сохранения файла).

Данные компоненты являются обертками над стандартными диалогами Windows (`Win32 Common Dialog Boxes`). Важно понимать, что `OpenFileDialog` и `SaveFileDialog` не выполняют физического чтения или записи содержимого файлов — их единственная задача заключается в получении от пользователя валидного пути к файлу в виде строки (`string`).

> **Определение.** `OpenFileDialog` — это визуальный компонент Windows Forms, предназначенный для настройки и вызова стандартного диалогового окна выбора существующего файла для чтения.
> **Определение.** `SaveFileDialog` — это визуальный компонент Windows Forms, предназначенный для настройки и вызова стандартного диалогового окна указания пути и имени файла для последующей записи.

Основные свойства этих классов, используемые в практической разработке:
- `Filter` — строка, определяющая фильтрацию файлов по расширениям. Формат записи: `"Описание (*.расширение)|*.расширение|Все файлы (*.*)|*.*"`. Например: `"Текстовые файлы (*.csv)|*.csv|Все файлы (*.*)|*.*"`.
- `Title` — заголовок окна диалога, отображаемый в его верхней части.
- `FileName` — имя файла, выбранное или введенное пользователем. При вызове `SaveFileDialog` можно задать имя по умолчанию.
- `FileName` (после закрытия диалога) или свойство `FileNames` (для нескольких файлов) содержат искомый абсолютный путь к файлу.
- `InitialDirectory` — папка, которая открывается при запуске диалогового окна по умолчанию.

Метод `ShowDialog()` открывает диалоговое окно модально (блокируя родительское окно до тех пор, пока пользователь не сделает выбор). Метод возвращает результат типа `DialogResult`. Если пользователь нажал кнопку «Открыть» или «Сохранить», метод возвращает `DialogResult.OK`. Если пользователь нажал «Отмена» или закрыл окно крестиком, возвращается `DialogResult.Cancel`.

Рассмотрим базовый шаблон безопасного вызова диалогового окна сохранения файла в обработнике нажатия кнопки:

```csharp
using System;
using System.IO;
using System.Windows.Forms;

// Внутри класса формы Windows Forms:
private void btnSave_Click(object sender, EventArgs e)
{
    using (SaveFileDialog saveFileDialog = new SaveFileDialog())
    {
        saveFileDialog.Filter = "Текстовые файлы CSV (*.csv)|*.csv|Все файлы (*.*)|*.*";
        saveFileDialog.Title = "Сохранить данные сотрудников";
        saveFileDialog.FileName = "employees.csv";

        // Если пользователь выбрал файл и нажал OK
        if (saveFileDialog.ShowDialog() == DialogResult.OK)
        {
            string filePath = saveFileDialog.FileName;
            
            try
            {
                // Вызов метода сохранения данных (рассмотрен в следующих пунктах)
                SaveDataToFile(filePath);
                MessageBox.Show("Данные успешно сохранены!", "Успех", MessageBoxButtons.OK, MessageBoxIcon.Information);
            }
            catch (Exception ex)
            {
                MessageBox.Show($"Ошибка при сохранении файла: {ex.Message}", "Ошибка", MessageBoxButtons.OK, MessageBoxIcon.Error);
            }
        }
    }
}
```

Конструкция `using` здесь гарантирует, что неуправляемые ресурсы операционной системы, выделенные под диалоговое окно, будут корректно и своевременно освобождены сразу после завершения работы с ним.

### Сохранение коллекций объектов в текстовые файлы в формате CSV

Формат CSV (*Comma-Separated Values*) является одним из самых простых и распространенных текстовых форматов для обмена табличными данными. Каждая строка текстового файла соответствует одной записи (одному объекту), а поля объекта разделяются специальным символом-разделителем — чаще всего запятой (`,`) или точкой с запятой (`;`). Использование точки с запятой в русскоязычной локали предпочтительнее, так как запятая часто используется в качестве десятичного разделителя в числах с плавающей точкой.

Для эффективной работы с коллекциями элементов в визуальных приложениях используется тип `BindingList<T>`, обеспечивающий автоматическое уведомление интерфейса (например, `DataGridView`) об изменении состава элементов.

Пусть у нас имеется ранее спроектированная иерархия классов сотрудников: базовый абстрактный класс `Employee` и производные классы `Manager` и `Developer`. Чтобы сохранить разнотипную коллекцию `BindingList<Employee>` в текстовый файл CSV, необходимо решить задачу сериализации каждого объекта с сохранением информации о его конкретном типе, чтобы при последующем чтении восстановить правильный класс.

Алгоритм сохранения коллекции в файл:
1. Открыть файловый поток для записи с помощью класса `StreamWriter`.
2. Пройти циклом `foreach` по каждому объекту `Employee` в коллекции `BindingList<Employee>`.
3. С помощью оператора `is` или сопоставления с образцом (`pattern matching`) определить точный тип объекта (`Manager` или `Developer`).
4. Сформировать строковое представление полей объекта, разделенных точкой с запятой. Первым полем обязательно записать идентификатор типа (например, строку `"Manager"` или `"Developer"`).
5. Записать сформированную строку в файл с помощью метода `WriteLine`.
6. Корректно закрыть поток записи.

### Чтение данных из текстовых файлов с построением объектной модели

Процесс чтения данных (десериализация из текстового формата) выполняет обратные действия. Программа читает файл построчно, разбирает каждую строку на отдельные компоненты и на их основе создает экземпляры соответствующих классов, которые затем добавляются в `BindingList<Employee>`.

Алгоритм чтения данных из файла:
1. Проверить существование файла с помощью `File.Exists(filePath)`. Если файл отсутствует, выбросить исключение или вывести предупреждение.
2. Открыть потоковый читатель `StreamReader` для указанного файла.
3. Очистить текущую коллекцию объектов `BindingList<Employee>`, чтобы избежать дублирования данных.
4. В цикле `while ((string line = reader.ReadLine()) != null)` читать файл до конца.
5. Разбить прочитанную строку на массив подстрок с помощью метода `line.Split(';')`.
6. Проанализировать нулевой элемент полученного массива (идентификатор типа) и с помощью конструктора или метода-фабрики создать объект нужного класса, передав остальные элементы массива в качестве параметров.
7. Добавить созданный объект в коллекцию `BindingList<Employee>`.
8. Закрыть поток чтения.

#### Разобранный пример 1: Сохранение и загрузка иерархии сотрудников в формате CSV

Ниже представлен полный, компилируемый фрагмент кода, реализующий модель сотрудников, логику их сохранения через `SaveFileDialog` и загрузки через `OpenFileDialog` с заполнением `BindingList<Employee>`.

```csharp
using System;
using System.ComponentModel;
using System.IO;
using System.Windows.Forms;

// 1. Определение иерархии классов предметной области
public abstract class Employee
{
    public string FullName { get; set; }
    public decimal BaseSalary { get; set; }

    protected Employee(string fullName, decimal baseSalary)
    {
        FullName = fullName;
        BaseSalary = baseSalary;
    }

    // Абстрактный метод для полиморфного расчета зарплаты
    public abstract decimal CalculateTotalSalary();

    // Виртуальный метод для преобразования объекта в строку CSV
    public virtual string ToCsvString()
    {
        return $"{FullName};{BaseSalary}";
    }
}

public class Manager : Employee
{
    public int SubordinatesCount { get; set; }
    public decimal BonusPerSubordinate { get; set; }

    public Manager(string fullName, decimal baseSalary, int subordinatesCount, decimal bonusPerSubordinate)
        : base(fullName, baseSalary)
    {
        SubordinatesCount = subordinatesCount;
        BonusPerSubordinate = bonusPerSubordinate;
    }

    public override decimal CalculateTotalSalary()
    {
        return BaseSalary + (SubordinatesCount * BonusPerSubordinate);
    }

    public override string ToCsvString()
    {
        // Формат: Manager;ФИО;Оклад;КоличествоПодчиненных;БонусЗаПодчиненного
        return $"Manager;{FullName};{BaseSalary};{SubordinatesCount};{BonusPerSubordinate}";
    }
}

public class Developer : Employee
{
    public string TechStack { get; set; }
    public decimal TechBonus { get; set; }

    public Developer(string fullName, decimal baseSalary, string techStack, decimal techBonus)
        : base(fullName, baseSalary)
    {
        TechStack = techStack;
        TechBonus = techBonus;
    }

    public override decimal CalculateTotalSalary()
    {
        return BaseSalary + TechBonus;
    }

    public override string ToCsvString()
    {
        // Формат: Developer;ФИО;Оклад;СтекТехнологий;Надбавка
        return $"Developer;{FullName};{BaseSalary};{TechStack};{TechBonus}";
    }
}

// 2. Логика работы в классе формы Windows Forms
public partial class MainForm : Form
{
    private BindingList<Employee> employeesList;

    public MainForm()
    {
        // Инициализация коллекции и привязка к DataGridView (предполагается, что dataGridView1 создан на форме)
        employeesList = new BindingList<Employee>();
        
        // Добавим тестовые данные для проверки
        employeesList.Add(new Manager("Иванов И.И.", 75000.00m, 5, 3000.00m));
        employeesList.Add(new Developer("Петров П.П.", 120000.00m, "C# / .NET 8", 25000.00m));
    }

    // Обработчик кнопки "Сохранить в файл"
    private void btnSaveCsv_Click(object sender, EventArgs e)
    {
        using (SaveFileDialog saveDlg = new SaveFileDialog())
        {
            saveDlg.Filter = "CSV файлы (*.csv)|*.csv|Все файлы (*.*)|*.*";
            saveDlg.Title = "Экспорт данных сотрудников";
            saveDlg.FileName = "employees_export.csv";

            if (saveDlg.ShowDialog() == DialogResult.OK)
            {
                try
                {
                    using (StreamWriter writer = new StreamWriter(saveDlg.FileName, false, System.Text.Encoding.UTF8))
                    {
                        foreach (Employee emp in employeesList)
                        {
                            // Полиморфный вызов метода генерации CSV-строки
                            writer.WriteLine(emp.ToCsvString());
                        }
                    }
                    MessageBox.Show("Экспорт данных выполнен успешно!", "Информация", MessageBoxButtons.OK, MessageBoxIcon.Information);
                }
                catch (Exception ex)
                {
                    MessageBox.Show($"Критическая ошибка записи файла: {ex.Message}", "Ошибка", MessageBoxButtons.OK, MessageBoxIcon.Error);
                }
            }
        }
    }

    // Обработчик кнопки "Загрузить из файла"
    private void btnLoadCsv_Click(object sender, EventArgs e)
    {
        using (OpenFileDialog openDlg = new OpenFileDialog())
        {
            openDlg.Filter = "CSV файлы (*.csv)|*.csv|Все файлы (*.*)|*.*";
            openDlg.Title = "Импорт данных сотрудников";

            if (openDlg.ShowDialog() == DialogResult.OK)
            {
                try
                {
                    BindingList<Employee> tempLoadedList = new BindingList<Employee>();

                    using (StreamReader reader = new StreamReader(openDlg.FileName, System.Text.Encoding.UTF8))
                    {
                        string line;
                        int lineNumber = 0;

                        while ((line = reader.ReadLine()) != null)
                        {
                            lineNumber++;
                            if (string.IsNullOrWhiteSpace(line)) continue;

                            string[] parts = line.Split(';');
                            if (parts.Length < 3)
                            {
                                throw new FormatException($"Неверный формат данных в строке {lineNumber}.");
                            }

                            string typeMarker = parts[0];
                            string fullName = parts[1];
                            decimal baseSalary = decimal.Parse(parts[2], System.Globalization.CultureInfo.InvariantCulture);

                            if (typeMarker == "Manager")
                            {
                                int subCount = int.Parse(parts[3]);
                                decimal bonus = decimal.Parse(parts[4], System.Globalization.CultureInfo.InvariantCulture);
                                tempLoadedList.Add(new Manager(fullName, baseSalary, subCount, bonus));
                            }
                            else if (typeMarker == "Developer")
                            {
                                string tech = parts[3];
                                decimal techBonus = decimal.Parse(parts[4], System.Globalization.CultureInfo.InvariantCulture);
                                tempLoadedList.Add(new Developer(fullName, baseSalary, tech, techBonus));
                            }
                            else
                            {
                                throw new FormatException($"Неизвестный тип сотрудника '{typeMarker}' в строке {lineNumber}.");
                            }
                        }
                    }

                    // Подменяем коллекцию на загруженную
                    employeesList.Clear();
                    foreach (var emp in tempLoadedList)
                    {
                        employeesList.Add(emp);
                    }

                    MessageBox.Show("Импорт данных успешно завершен!", "Информация", MessageBoxButtons.OK, MessageBoxIcon.Information);
                }
                catch (FormatException fex)
                {
                    MessageBox.Show($"Ошибка формата файла: {fex.Message}", "Ошибка структуры", MessageBoxButtons.OK, MessageBoxIcon.Warning);
                }
                catch (Exception ex)
                {
                    MessageBox.Show($"Ошибка при чтении файла: {ex.Message}", "Ошибка", MessageBoxButtons.OK, MessageBoxIcon.Error);
                }
            }
        }
    }
}
```

*Разбор хода рассуждений:* Для сохранения разнотипных объектов в плоский текстовый файл мы применили паттерн проектирования, при котором каждый класс сам знает, как представить себя в виде строки (`ToCsvString`). При чтении мы анализируем первое поле строки (`typeMarker`), что позволяет фабричным методом (внутри цикла чтения) принимать решение о создании экземпляра конкретного класса (`Manager` или `Developer`). Использование `System.Text.Encoding.UTF8` гарантирует корректную работу с русскими буквами в ФИО сотрудников на любых операционных системах.

### Сериализация и десериализация данных в формате JSON

В современной разработке на платформе .NET для сохранения сложных структурированных данных и конфигураций стандартом де-факто является формат JSON (*JavaScript Object Notation*). Встроенная библиотека `System.Text.Json` (доступная в .NET 8 «из коробки») позволяет в одну строчку превратить любой объект или коллекцию в JSON-строку и обратно.

> **Определение.** Сериализация — это процесс преобразования состояния объекта в последовательность байтов или текстовый формат (например, JSON) для сохранения в файл или передачи по сети.
> **Определение.** Десериализация — это обратный процесс восстановления объекта в оперативной памяти из его текстового или байтового представления.

Главное преимущество `System.Text.Json` перед ручным разбором CSV заключается в том, что сериализатор автоматически обходит все открытые свойства объекта (включая вложенные структуры и списки), самостоятельно определяя типы данных.

Пример использования сериализации для сохранения конфигурации:

```csharp
using System.Text.Json;
using System.IO;

// Объект конфигурации
public class AppSettings
{
    public int WindowWidth { get; set; } = 800;
    public int WindowHeight { get; set; } = 600;
    public int WindowLeft { get; set; } = 100;
    public int WindowTop { get; set; } = 100;
    public string LastUser { get; set; } = "Administrator";
}

// Сериализация (запись в файл)
public void SaveConfig(AppSettings settings, string path)
{
    var options = new JsonSerializerOptions { WriteIndented = true }; // Форматирование с отступами для читаемости
    string jsonString = JsonSerializer.Serialize(settings, options);
    File.WriteAllText(path, jsonString, System.Text.Encoding.UTF8);
}

// Десериализация (чтение из файла)
public AppSettings LoadConfig(string path)
{
    if (!File.Exists(path))
    {
        return new AppSettings(); // Возвращаем настройки по умолчанию, если файла нет
    }

    string jsonString = File.ReadAllText(path, System.Text.Encoding.UTF8);
    return JsonSerializer.Deserialize<AppSettings>(jsonString) ?? new AppSettings();
}
```

### Сохранение пользовательских настроек формы и восстановление состояния

Один из признаков качественного программного продукта — способность запоминать свое состояние между запускaми. Пользователь настраивает размер окна, перемещает его в удобную часть экрана, закрывает программу, а при следующем открытии приложение восстанавливает ровно то же положение.

Для реализации этой задачи необходимо перехватить два ключевых события жизненного цикла формы Windows Forms:
1. Событие загрузки формы (`Load`), происходящее при старте приложения — в этот момент считывается конфигурационный файл и применяются размеры и координаты.
2. Событие закрытия формы (`FormClosing` или `FormClosed`), происходящее перед уничтожением окна — в этот момент текущие параметры окна фиксируются и записываются в файл настроек.

Важная техническая тонкость: если при закрытии программы окно находилось в свернутом (`FormWindowState.Minimized`) или развернутом на весь экран (`FormWindowState.Maximized`) состоянии, сохранять текущие координаты `Left` и `Top` нельзя, так как они будут искажены. Необходимо делать проверку: сохранять координаты и размеры следует только тогда, когда состояние окна нормальное (`FormWindowState.Normal`).

### Обработка ошибок доступа к файлам и отсутствия файлов

Файловая система — это внешний ресурс, работа с которым сопряжена с множеством рисков: файл может быть удален, у программы может не быть прав на запись в защищенную системную директорию (например, `C:\Program Files`), файл может быть заблокирован другим процессом.

Поэтому любой код, выполняющий операции ввода-вывода (`I/O`), обязан быть помещен в защищенный блок `try-catch`. Запрещено допускать аварийное падение программы (вылет на рабочий стол с неперехваченным исключением) из-за проблем с файлами.

Для информирования пользователя о статусе операций в интерфейсе Windows Forms активно используется компонент `StatusStrip` (строка состояния, расположенная в нижней части формы), содержащий элементы `ToolStripStatusLabel`. Вывод сообщений вроде `"Файл успешно сохранен"` или `"Ошибка доступа к диску"` в строку состояния делает интерфейс отзывчивым и профессиональным.

### Разобранный пример 2: Сохранение и восстановление настроек окна в формате JSON

Ниже представлен полностью рабочий класс формы, который при запуске считывает свои размеры и положение из JSON-файла настроек, а при закрытии автоматически сохраняет их, учитывая режим окна.

```csharp
using System;
using System.IO;
using System.Text.Json;
using System.Windows.Forms;

public class AppSettingsModel
{
    public int Width { get; set; } = 900;
    public int Height { get; set; } = 600;
    public int Left { get; set; } = 200;
    public int Top { get; set; } = 150;
    public bool IsMaximized { get; set; } = false;
}

public partial class ConfiguredForm : Form
{
    private const string ConfigFileName = "app_settings.json";
    private ToolStripStatusLabel statusLabel;
    private StatusStrip statusStrip1;

    public ConfiguredForm()
    {
        // Инициализация элементов строки состояния (StatusStrip)
        statusStrip1 = new StatusStrip();
        statusLabel = new ToolStripStatusLabel();
        statusLabel.Text = "Готово";
        statusStrip1.Items.Add(statusLabel);
        this.Controls.Add(statusStrip1);

        // Подписываемся на события загрузки и закрытия формы
        this.Load += new EventHandler(ConfiguredForm_Load);
        this.FormClosing += new FormClosingEventHandler(ConfiguredForm_FormClosing);
        
        // Создаем пункты меню для ручного сохранения и загрузки
        MenuStrip menuStrip = new MenuStrip();
        ToolStripMenuItem menuFile = new ToolStripMenuItem("Файл");
        ToolStripMenuItem menuSaveConfig = new ToolStripMenuItem("Сохранить настройки", null, OnSaveConfigClick);
        ToolStripMenuItem menuLoadConfig = new ToolStripMenuItem("Загрузить настройки", null, OnLoadConfigClick);
        
        menuFile.DropDownItems.Add(menuSaveConfig);
        menuFile.DropDownItems.Add(menuLoadConfig);
        menuStrip.Items.Add(menuFile);
        this.MainMenuStrip = menuStrip;
        this.Controls.Add(menuStrip);
    }

    private void ConfiguredForm_Load(object sender, EventArgs e)
    {
        LoadApplicationSettings();
    }

    private void ConfiguredForm_FormClosing(object sender, FormClosingEventArgs e)
    {
        SaveApplicationSettings();
    }

    private void LoadApplicationSettings()
    {
        try
        {
            if (File.Exists(ConfigFileName))
            {
                string jsonContent = File.ReadAllText(ConfigFileName, System.Text.Encoding.UTF8);
                AppSettingsModel settings = JsonSerializer.Deserialize<AppSettingsModel>(jsonContent);

                if (settings != null)
                {
                    // Применяем настройки к окну
                    this.Width = settings.Width;
                    this.Height = settings.Height;
                    this.Left = settings.Left;
                    this.Top = settings.Top;

                    if (settings.IsMaximized)
                    {
                        this.WindowState = FormWindowState.Maximized;
                    }

                    statusLabel.Text = "Настройки успешно загружены из файла.";
                }
            }
            else
            {
                statusLabel.Text = "Файл настроек не найден. Используются значения по умолчанию.";
            }
        }
        catch (Exception ex)
        {
            statusLabel.Text = "Ошибка загрузки настроек.";
            MessageBox.Show($"Не удалось загрузить файл конфигурации: {ex.Message}", "Ошибка", MessageBoxButtons.OK, MessageBoxIcon.Warning);
        }
    }

    private void SaveApplicationSettings()
    {
        try
        {
            AppSettingsModel settings = new AppSettingsModel();

            // Если окно развернуто, сохраняем состояние, но не искажаем координаты Normal
            if (this.WindowState == FormWindowState.Maximized)
            {
                settings.IsMaximized = true;
                // Сохраняем последние нормальные размеры из свойства RestoreBounds
                settings.Width = this.RestoreBounds.Width;
                settings.Height = this.RestoreBounds.Height;
                settings.Left = this.RestoreBounds.Left;
                settings.Top = this.RestoreBounds.Top;
            }
            else if (this.WindowState == FormWindowState.Normal)
            {
                settings.IsMaximized = false;
                settings.Width = this.Width;
                settings.Height = this.Height;
                settings.Left = this.Left;
                settings.Top = this.Top;
            }
            else
            {
                // Если окно свернуто, сохраняем размеры в нормальном режиме
                settings.IsMaximized = false;
                settings.Width = this.RestoreBounds.Width;
                settings.Height = this.RestoreBounds.Height;
                settings.Left = this.RestoreBounds.Left;
                settings.Top = this.RestoreBounds.Top;
            }

            var options = new JsonSerializerOptions { WriteIndented = true };
            string jsonContent = JsonSerializer.Serialize(settings, options);
            File.WriteAllText(ConfigFileName, jsonContent, System.Text.Encoding.UTF8);
            
            statusLabel.Text = "Настройки успешно сохранены.";
        }
        catch (Exception ex)
        {
            MessageBox.Show($"Не удалось сохранить файл конфигурации: {ex.Message}", "Ошибка", MessageBoxButtons.OK, MessageBoxIcon.Error);
        }
    }

    private void OnSaveConfigClick(object sender, EventArgs e)
    {
        SaveApplicationSettings();
        MessageBox.Show("Конфигурация принудительно сохранена в файл app_settings.json.", "Сохранение", MessageBoxButtons.OK, MessageBoxIcon.Information);
    }

    private void OnLoadConfigClick(object sender, EventArgs e)
    {
        LoadApplicationSettings();
        MessageBox.Show("Конфигурация успешно перезагружена из файла.", "Загрузка", MessageBoxButtons.OK, MessageBoxIcon.Information);
    }
}
```

*Разбор хода рассуждений:* В данном примере мы объединили работу с системным файлом конфигурации, обработку событий жизненного цикла формы (`Load` и `FormClosing`) и визуальную обратную связь через `StatusStrip`. Использование свойства `RestoreBounds` позволило корректно обрабатывать ситуацию, когда пользователь закрывает развернутое на весь экран окно — программа сохранит его реальные размеры в оконном режиме, предотвратив запуск приложения в следующий раз в некорректном развернутом виде без возможности изменения размера. Обработка исключений в блоках `try-catch` полностью защищает приложение от сбоев при повреждении или блокировке файла `app_settings.json`.

## 6. Комплексное тестирование, отладка и сборка итогового решения

### Введение в отладку и тестирование визуальных приложений на C#

Создание программного обеспечения на платформе .NET 8 с использованием Windows Forms не ограничивается написанием работающего кода. На этапе завершения разработки критически важно убедиться, что приложение устойчиво к аварийным завершениям, не теряет данные, корректно освобождает системные ресурсы и готово к развертыванию на конечных компьютерах пользователей. 

> **Определение.** Отладка (debugging) — это процесс поиска и устранения дефектов (багов) в программном обеспечении с использованием специализированных инструментов среды разработки, позволяющих останавливать выполнение программы, пошагово исполнять код и анализировать состояние памяти.

> **Определение.** Тестирование граничных условий — это проверка поведения программы при подаче на вход значений, лежащих на границах допустимых диапазонов (пустые коллекции, нулевые или отрицательные числа, максимально возможные размеры строк и файлов).

Рассмотрим каждый аспект завершающего этапа разработки детально, опираясь на ранее созданные объектные модели, таблицы `BindingList<T>` и оконные формы.

---

### Использование встроенного отладчика Visual Studio

Когда приложение выдает неверный результат или аварийно завершается с исключением, использовать стандартный вывод в консоль (`Console.WriteLine`) или бесчисленные `MessageBox.Show` неэффективно. Среда разработки предоставляет мощный инструмент — встроенный отладчик.

Основные инструменты отладчика:
1. **Точки останова (Breakpoints)** — маркеры на строках кода (устанавливаются кликом по левому серому полю редактора или клавишей `F9`), при достижении которых выполнение программы приостанавливается, передавая управление разработчику.
2. **Окно локальных переменных (Locals)** — отображает все переменные, доступные в текущей области видимости выполняемого метода, включая ссылки на текущий объект (`this`).
3. **Окно наблюдения (Watch)** — позволяет добавлять произвольные выражения, свойства объектов или математические формулы для непрерывного отслеживания их значений в процессе пошаговой отладки.
4. **Управление шагами выполнения**:
   - `F10` (Step Over) — выполнить текущую строку кода, не заходя внутрь вызываемых методов.
   - `F11` (Step Into) — зайти внутрь вызываемого метода на текущей строке для пошагового анализа.
   - `Shift + F11` (Step Out) — завершить выполнение текущего метода и вернуться в вызывающий код.
   - `F5` (Continue) — продолжить свободное выполнение программы до следующей точки останова.

### Проверка граничных условий и крайних случаев

Наибольшее количество ошибок в реальных программах возникает не при штатном использовании, а при обработке нестандартных ситуаций. К таким ситуациям относятся:
- Пустые коллекции (когда `BindingList<T>` или `List<T>` не содержат элементов, а код пытается обратиться к первому элементу `[0]` или вычислить среднее арифметическое).
- Деление на ноль (например, при расчете процентных ставок или средних цен, если общее количество товаров равно нулю).
- Переполнение числовых типов (когда результат умножения больших чисел выходит за пределы диапазона `int` или `double`).
- Пустые строки или строки, содержащие только пробелы, переданные в качестве числовых параметров.

Для предотвращения таких сбоев на этапе проектирования методов необходимо закладывать защитные проверки (guard clauses).

### Тестирование взаимодействия между формами и корректности передачи ссылочных типов

В многоформенных приложениях данные между окнами передаются через свойства или через конструкторы. Поскольку в C# пользовательские классы и формы являются ссылочными типами (`reference types`), изменение свойств объекта в дочерней форме автоматически отражается на родительской форме, если они ссылаются на один и тот же экземпляр в памяти.

Ошибки при передаче данных:
- Передача `null` ссылки (попытка обратиться к свойству формы до того, как она была инициализирована или открыта).
- Создание дубликатов объектов вместо передачи ссылки на существующий элемент (приводит к несогласованности данных в таблице `DataGridView`).
- Забытая отписка от событий при закрытии дочерних форм, приводящая к повторной обработке кликов или изменения данных.

### Поиск и устранение утечек памяти и невысвобожденных ресурсов

Платформа .NET оснащена сборщиком мусора (Garbage Collector), который автоматически освобождает память, занимаемую объектами в куче, когда на них больше нет ссылок. Однако сборщик мусора не управляет неуправляемыми ресурсами (unmanaged resources), такими как открытые файловые дескрипторы, потоки чтения/записи (`StreamReader`, `StreamWriter`), сетевые соединения или графические контексты GDI+.

> **Определение.** Утечка ресурсов — это ситуация, когда программа захватывает системный ресурс (например, открывает файл), но забывает его освободить, что приводит к исчерпанию доступных операционной системе дескрипторов и ошибкам доступа.

Для гарантированного высвобождения ресурсов используется конструкция `using`:

```csharp
using (StreamReader reader = new StreamReader("data.csv"))
{
    string line = reader.ReadLine();
    // Обработка строк файла
} // Метод Dispose() будет вызван автоматически при выходе из блока using, даже если возникнет исключение
```

---

### Анализ сообщений компилятора и предупреждений уровня nullable-ссылок

В .NET 8 включена строгая проверка типов, допускающих значения `null` (Nullable Reference Types). Предупреждения компилятора (например, предупреждение CS8600: *Converting null literal or possible null value to non-nullable type*) указывают на потенциальную опасность возникновения исключения `NullReferenceException`.

Игнорирование желтых предупреждений компилятора на этапе разработки — главная причина падений приложения у пользователя. Все предупреждения должны быть устранены либо путем явной проверки переменной на `null`, либо с помощью операторов null-прощения (`!`) или объединения с null (`??`).

```csharp
        return 0.0;
    }
    
    return totalPrice / quantity;
}
```

**Проверка:** При передаче `quantity = 0` программа не падает, выводит понятное предупреждение через `MessageBox` и возвращает `0{,}0`. Расчет корректен.

### Обработка исключений (try-catch-finally) в приложениях с интерфейсом

При разработке оконных приложений категорически запрещено допускать аварийное падение программы с выводом системного отладочного окна .NET. Любое непредвиденное исключение (ошибка деления на ноль, отсутствие файла, сбой в сети или неверный формат) должно быть перехвачено в блоке `try-catch`.

```csharp
private void OnExecuteOperationClick(object sender, EventArgs e)

    {

            MessageBoxButtons.OK, MessageBoxIcon.Information);
    }
    catch (FormatException ex)
    {
        // Перехват ошибки формата данных
        MessageBox.Show($"Ошибка формата: {ex.Message}", "Ошибка ввода", 
            MessageBoxButtons.OK, MessageBoxIcon.Error);
    }
    catch (ArgumentOutOfRangeException ex)
    {
        // Перехват выхода за допустимые рамки значений
        MessageBox.Show($"Недопустимое значение: {ex.ParamName}. {ex.Message}", "Ошибка диапазона",

    {
        // Перехват любых других непредвиденных системных ошибок

            MessageBoxButtons.OK, MessageBoxIcon.Stop);
```

## 5. Интеграция с файловой системой и сохранение состояния приложения

### Потоковый ввод-вывод и сериализация

Для того чтобы результаты работы пользователя не пропадали после закрытия программы, приложение должно уметь сохранять данные в файлы на жестком диске и восстанавливать их при следующем запуске. 

В платформе .NET для работы с файлами используется пространство имен `System.IO`. Основные классы:
- `File` — статический класс для быстрого чтения и записи текстовых или бинарных файлов целиком.
- `StreamWriter` / `StreamReader` — потоковые классы для построчной записи и чтения текстовых файлов.
- Сериализация (JSON) — современный стандарт сохранения сложных объектных моделей в структурированный текстовый вид с помощью библиотеки `System.Text.Json`.

---

### Сохранение коллекций объектов в текстовый файл (CSV-формат)

Рассмотрим сохранение списка сотрудников или товаров в CSV-файл (Comma-Separated Values), где каждое поле разделено точкой с запятой или запятой.

> **Правило.** При записи чисел в файлы с разделителями на платформах с русской локалью десятичная запятая может конфликтовать с разделителем столбцов. Всегда используйте инвариантную культуру (`CultureInfo.InvariantCulture`) при сериализации чисел в текстовые файлы, чтобы точки и запятые сохранялись в едином стандарте.

#### Разобранный пример: Сохранение и загрузка списка книг

Реализуем функции сохранения и восстановления коллекции `BindingList<Book>` в текстовый файл с использованием класса `StreamWriter` и `StreamReader`.

```csharp
using System;
using System.IO;
using System.ComponentModel;
using System.Windows.Forms;
using System.Globalization;

public class StorageManager
{
    // Метод сохранения коллекции книг в файл
    public static void SaveBooksToFile(string filePath, BindingList<Book> books)
    {
        try
        {
            using (StreamWriter writer = new StreamWriter(filePath, false, System.Text.Encoding.UTF8))
            {
                foreach (var book in books)
                {
                    if (book is EBook eBook)
                    {
                        // Формат строки для электронной книги: EBook;Автор;Название;РазмерФайла
                        writer.WriteLine($"EBook;{eBook.Author};{eBook.Title};{eBook.FileSizeMB.ToString(CultureInfo.InvariantCulture)}");
                    }
                    else if (book is PrintedBook pBook)
                    {
                        // Формат строки для печатной книги: PrintedBook;Автор;Название;Вес
                        writer.WriteLine($"PrintedBook;{pBook.Author};{pBook.Title};{pBook.WeightGrams}");
                    }
                }
            }
            MessageBox.Show("Данные успешно сохранены в файл.", "Сохранение", MessageBoxButtons.OK, MessageBoxIcon.Information);
        }
        catch (IOException ex)
        {
            MessageBox.Show($"Ошибка ввода-вывода при сохранении файла: {ex.Message}", "Ошибка", MessageBoxButtons.OK, MessageBoxIcon.Error);
        }
    }

    // Метод загрузки коллекции книг из файла
    public static BindingList<Book> LoadBooksFromFile(string filePath)
    {
        BindingList<Book> loadedBooks = new BindingList<Book>();

        if (!File.Exists(filePath))
        {
            MessageBox.Show("Указанный файл не найден. Создана новая пустая коллекция.", "Внимание", MessageBoxButtons.OK, MessageBoxIcon.Warning);
            return loadedBooks;
        }

        try
        {
            using (StreamReader reader = new StreamReader(filePath, System.Text.Encoding.UTF8))
            {
                string line;
                int lineNumber = 0;

                while ((line = reader.ReadLine()) != null)
                {
                    lineNumber++;
                    if (string.IsNullOrWhiteSpace(line)) continue;

                    try
                    {
                        // Используем ранее спроектированную фабрику для создания объекта из строки
                        Book book = BookFactory.CreateFromString(line);
                        loadedBooks.Add(book);
                    }
                    catch (Exception ex)
                    {
                        MessageBox.Show($"Ошибка в строке {lineNumber}: {ex.Message}", "Ошибка чтения", MessageBoxButtons.OK, MessageBoxIcon.Warning);
                    }
                }
            }
            MessageBox.Show("Данные успешно загружены из файла.", "Загрузка", MessageBoxButtons.OK, MessageBoxIcon.Information);
        }
        catch (Exception ex)
        {
            MessageBox.Show($"Критическая ошибка при чтении файла: {ex.Message}", "Ошибка", MessageBoxButtons.OK, MessageBoxIcon.Error);
        }

        return loadedBooks;
    }
}
```

**Ход рассуждений и проверка:**
1. Мы используем конструкцию `using`, которая гарантирует автоматическое закрытие файла и освобождение системных дескрипторов сразу после выхода из блока кода, даже если в процессе записи возникло исключение.
2. Применение `CultureInfo.InvariantCulture` при записи вещественных чисел (`eBook.FileSizeMB.ToString(...)`) гарантирует, что дробная часть запишется через точку (например, `15.5`), а не через запятую, что позволит успешно прочитать этот же файл на компьютерах с другой языковой панелью.
3. Каждая строка файла обрабатывается независимо в блоке `try-catch`: если одна строка в текстовом файле повреждена, программа выведет предупреждение о номере строки, но продолжит загрузку остальных записей.

## 6. Комплексное тестирование, отладка и сборка итогового решения

### Методология отладки графических приложений

Разработка визуальных приложений отличается от консольных тем, что ошибки часто носят асинхронный характер и связаны с событиями пользовательского интерфейса. Для эффективного поиска и устранения ошибок в Visual Studio применяются следующие инструменты:

1. **Точки останова (Breakpoints)** — установка маркеров на строках кода (клавиша `F9`), при достижении которых выполнение программы приостанавливается, позволяя разработчику исследовать значения локальных переменных в окне *Locals* или *Watch*.
2. **Условные точки останова (Conditional Breakpoints)** — точка останова с заданным условием (например, срабатывать только когда `price < 0`). Это незаменимо при поиске ошибок в циклах или коллекциях из сотен элементов.
3. **Окно Output и Debug.WriteLine** — вывод отладочных сообщений в реальном времени без остановки потока выполнения программы.
4. **Анализ стека вызовов (Call Stack)** — окно показывает всю цепочку вызовов методов, которая привела к текущей точке останова или к аварийному исключению.

### Чек-лист проверки готовности оконного приложения к сдаче

Прежде чем демонстрировать итоговый проект преподавателю, выполните проверку по следующему списку:

## Типичные ошибки

1. **Вся бизнес-логика написана внутри обработчика нажатия кнопки формы.**
   * *Почему возникает:* Начинающие разработчики стремятся быстрее увидеть результат и пишут расчеты, проверки и парсинг строк прямо в методе `button1_Click`.
   * *Как избежать:* Строго разделяйте проект на слои: модель данных (классы на чистом C#) и представление (форма Windows Forms). Форма должна лишь вызвать метод модели и вывести результат.
   * *Пример ошибки:* `private void button1_Click(object sender, EventArgs e) { decimal tax = decimal.Parse(textBox1.Text) * 0.13m; label1.Text = tax.ToString(); }` — вместо этого расчет налога должен выполняться внутри метода класса `Employee`.

2. **Использование `List<T>` вместо `BindingList<T>` для привязки к `DataGridView`.**
   * *Почему возникает:* Привычка использовать стандартный `List<T>` из консольных приложений.
   * *Как избежать:* Если коллекция данных должна отображаться в таблице и динамически обновляться при добавлении или удалении элементов, всегда используйте `BindingList<T>`.
   * *Пример ошибки:* При вызове `myList.Add(newItem)` таблица `DataGridView` остается пустой, пока не будет вызвана принудительная перепривязка.

3. **Прямой вызов `int.Parse()` или `double.Parse()` для пользовательского ввода.**
   * *Почему возникает:* Желание написать более короткий код без создания дополнительных переменных.
   * *Как избежать:* Всегда применять методы безопасного парсинга `int.TryParse()` / `double.TryParse()` с проверкой возвращаемого значения и выводом предупреждения пользователю.
   * *Пример ошибки:* Программа аварийно завершается (`FormatException`), если пользователь случайно введет букву вместо цифры в текстовое поле цены.

4. **Забыли установить свойство `DataPropertyName` у столбцов `DataGridView`.**
   * *Почему возникает:* При ручном создании столбцов таблицы (`AutoGenerateColumns = false`) разработчик настраивает только текст заголовка (`HeaderText`), забывая указать связь со свойствами класса.
   * *Как избежать:* Всегда прописывать `column.DataPropertyName = "ИмяСвойстваВКлассе";` для каждого ручного столбца таблицы.
   * *Пример ошибки:* Таблица компилируется и запускается, но остается абсолютно пустой при наличии элементов в привязанной коллекции.

5. **Отсутствие проверки на `null` или валидного индекса при клике на строку таблицы.**
   * *Почему возникает:* Попытка получить выбранный объект из таблицы без проверки, кликнул ли пользователь по заполненной строке или по пустой области под ней.
   * *Как избежать:* Перед извлечением данных всегда проверять `if (e.RowIndex >= 0)` и использовать безопасное приведение типов через оператор `as`.
   * *Пример ошибки:* Возникновение исключения `NullReferenceException` или `ArgumentOutOfRangeException` при клике в пустую область `DataGridView`.

6. **Сохранение чисел в файл без учета инвариантной культуры (`CultureInfo.InvariantCulture`).**
   * *Почему возникает:* Сохранение данных стандартным методом `ToString()` на компьютере с русской локалью.
   * *Как избежать:* При записи вещественных чисел в текстовые файлы использовать `value.ToString(CultureInfo.InvariantCulture)`, чтобы разделителем целой и дробной части всегда была точка, а не запятая.
   * *Пример ошибки:* При повторной загрузке файла программа выбрасывает `FormatException`, так как локаль операционной системы изменилась или файл читается на другом компьютере.

7. **Отсутствие блоков `try-catch` при работе с файловой системой.**
   * *Почему возникает:* Предположение, что файл всегда существует и доступен для чтения/записи.
   * *Как избежать:* Оборачивать весь код работы с потоками (`StreamReader`, `StreamWriter`, `File.ReadAllText`) в блоки `try-catch` с перехватом исключений типа `IOException`.
   * *Пример ошибки:* Программа аварийно закрывается, если файл запущен другим приложением или у пользователя нет прав на запись в директорию.

## 1. Ограничения массивов и концепция динамических структур данных

### Анализ проблемы фиксированной длины массивов в памяти и затрат на их перераспределение

В языке C# массивы (`Array`) представляют собой структуры данных фиксированной длины. Когда вы объявляете массив с помощью ключевого слова `new`, например, `int[] numbers = new int[100];`, среда выполнения .NET выделяет в памяти **непрерывный** блок (в так называемой куче — *heap*), достаточный для размещения ровно 100 элементов типа `int`. 

У такого подхода есть фундаментальное достоинство — **мгновенный доступ по индексу** за постоянное время $O(1)$. Поскольку каждый элемент имеет фиксированный размер (для `int` это 4 байта), адрес любого элемента в памяти вычисляется элементарной формулой арифметики указателей:
$$\text{Адрес}_i = \text{Адрес}_{\text{начальная}} + i \times \text{Размер элемента}$$

Однако у фиксированной длины есть обратная сторона. Что делать, если заранее неизвестно, сколько именно элементов потребуется сохранить? Или если объем данных со временем растет? 

Если размер массива исчерпан, а вам нужно добавить еще один элемент, вы не можете просто «дописать» его в конец — следующий участок памяти может быть уже занят другими данными вашей программы. Единственный способ расширить массив — это:
1. Выделить новый, более крупный блок памяти (обычно вдвое больше прежнего).
2. Побайтово скопировать все существующие элементы из старого массива в новый.
3. Уничтожить старый массив (его заберет сборщик мусора — *Garbage Collector*).
4. Записать новый элемент в освободившееся место.

Эта операция называется перераспределением (*reallocation*). Сама по себе процедура копирования требует времени $O(n)$, где $n$ — количество элементов в массиве. Если таких перераспределений происходит много (например, при добавлении большого объема данных по одному элементу), производительность программы катастрофически падает из-за постоянных накладных расходов на выделение памяти и копирование.

### Сравнение последовательного размещения в памяти и цепного размещения

Чтобы избавиться от необходимости хранить данные в непрерывном блоке памяти и выполнять трудоемкие операции копирования при росте коллекции, используют **динамические структуры данных на ссылках**. 

Главное отличие между ними заключается в организации памяти:

| Характеристика | Массив (`Array`) | Связный список (`LinkedList`) |
|---|---|---|
| **Размещение в памяти** | Непрерывное (все элементы идут подряд) | Рассредоточенное (узлы разбросаны по всей куче) |
| **Доступ к элементу** | Прямой по индексу, $O(1)$ | Только последовательный (от начала к концу), $O(n)$ |
| **Добавление в конец** | Быстрое, если есть свободный резерв; долгое с копированием, если резерва нет ($O(n)$) | Быстрое, если есть указатель на хвост, $O(1)$ |
| **Добавление в начало / середину** | Медленное (требует сдвига всех элементов), $O(n)$ | Мгновенное при наличии ссылки, $O(1)$ |
| **Накладные расходы памяти** | Минимальные (только данные и служебный заголовок массива) | Повышенные (хранение ссылок *Next* для каждого элемента) |

При цепном размещении элементы не обязаны находиться рядом друг с другом в оперативной памяти. Они могут располагаться в совершенно разных её уголках. Связь между ними поддерживается искусственно — с помощью адресных ссылок.

### Понятие узла (*Node*) и роль ссылочных типов в организации связей

Фундаментальным строительным блоком любой связной структуры данных является **узел** (англ. *node*). 

> **Определение.** Узел — это структурная единица динамической структуры данных, содержащая полезную нагрузку (данные) и одну или несколько ссылок на соседние узлы той же структуры.

В односвязном списке каждый узел состоит ровно из двух логических частей:
1. **Поле данных** (`Value` или `Data`) — хранит само значение (например, число, строку или объект).
2. **Поле связи** (`Next`) — хранит ссылку (адрес в памяти) на следующий узел списка.

В коде на C# простейший класс узла для хранения целых чисел выглядит следующим образом:

```csharp
public class Node
{
    public int Value;      // Полезные данные
    public Node Next;      // Ссылка на следующий узел

    // Конструктор для удобства создания узла
    public Node(int value)
    {
        Value = value;
        Next = null;       // По умолчанию узел ни на что не ссылается
    }
}
```

Здесь ключевую роль играют **ссылочные типы** (классы). Переменная типа `Node` хранит не сам объект в куче, а адрес этого объекта. Если узел является последним в списке, его поле `Next` принимает специальное значение `null`. 

> **Определение.** `null` (нулевая ссылка) — это специальное литеральное значение, обозначающее отсутствие ссылки на какой-либо объект в памяти. Обращение к полям или методам переменной, равной `null`, приводит к генерации исключения времени выполнения `NullReferenceException`.

Именно значение `null` служит естественным маркером окончания любой связной структуры данных. Проходя по цепочке узлов от одного элемента к другому (`current = current.Next`), программа знает, что список закончился, когда очередная ссылка оказывается равной `null`.

В виде схемы структуру памяти односвязного списка из трех элементов можно представить следующим образом:

```text
[ Управляющая переменная ]
 Head ------+
            |
            v
      +------------+       +------------+       +------------+
      | Value: 10  |       | Value: 25  |       | Value: 42  |
      | Next ------+------>| Next ------+------>| Next: null |
      +------------+       +------------+       +------------+
        Узел 1               Узел 2               Узел 3 (Хвост)
```

Обратите внимание: узлы в оперативной памяти могут находиться по адресам `0x1000`, `0x8540` и `0x3200` соответственно. Физического соседства нет, но логическая связь поддерживается ссылками `Next`.

### Преимущества и недостатки связных списков по сравнению с массивами

Каждая структура данных оптимизирована под свой круг задач. Рассмотрим сильные и слабые стороны связных списков.

**Преимущества:**
1. **Динамический размер:** список может расти и уменьшаться во время работы программы ровно настолько, насколько это необходимо. Память выделяется под каждый новый узел индивидуально по мере надобности.
2. **Отсутствие избыточного копирования:** добавление нового узла в начало или в середину списка (если уже найден узел вставки) не требует перемещения остальных элементов. Достаточно перенаправить одну-две ссылки.
3. **Эффективное использование памяти при фрагментации:** системе не нужно искать крупный непрерывный блок свободной памяти; отдельные узлы могут занимать мелкие разрозненные ячейки кучи.

**Недостатки:**
1. **Отсутствие произвольного доступа:** невозможно обратиться к $50$-му элементу списка за один шаг. Чтобы добраться до него, программа обязана последовательно пройти первые 49 элементов от начала (`Head`), переходя по ссылкам `Next`. Время доступа к элементу по индексу составляет $O(n)$ вместо $O(1)$ у массивов.
2. **Накладные расходы на память:** каждый элемент хранит не только данные, но и ссылку `Next`. Для небольших типов данных (например, `int` размером 4 байта) хранение 64-битной ссылки (8 байт на 64-разрядной архитектуре) удваивает или утраивает объем потребляемой памяти.
3. **Сложность обратного обхода:** в односвязном списке движение возможно только в одну сторону — вперед. Вернуться к предыдущему узлу по текущей ссылке нельзя (для этого требуется двусвязный список, где у каждого узла есть еще и ссылка `Previous`).

### Разобранный пример: анализ затрат на перераспределение массива и связного списка

#### Условие задачи
Требуется хранить коллекцию данных, размер которой неизвестен заранее и может динамически изменяться в диапазоне от 5 до 100 000 элементов. Необходимо оценить объем требуемых операций копирования элементов в памяти для стандартного массива с двукратным расширением и для односвязного списка при последовательном добавлении 10 000 элементов с исходного нулевого состояния.

#### Ход рассуждений
1. **Для массива:**
   - Обычные динамические массивы (например, класс `List<T>` в C#) реализуются на базе обычных массивов. Когда емкость (*capacity*) исчерпывается, создается новый массив вдвое большей длины, и все существующие элементы копируются туда.
   - Начальная емкость пустого массива часто равна 0. При первой попытке вставки выделяется массив размера 4.
   - По мере добавления 10 000 элементов перераспределение памяти (аллокация + копирование) будет происходить при достижении емкости: 4, 8, 16, 32, 64, 128, 256, 512, 1024, 2048, 4096, 8192. 
   - Следующее удвоение произойдет до 16 384, чего как раз хватит для размещения 10 000 элементов.
   - Общее количество операций копирования равно сумме размеров всех предыдущих массивов, попавших под копирование:
     $$\text{Копирования} = 4 + 8 + 16 + 32 + 64 + 128 + 256 + 512 + 1024 + 2048 + 4096 + 8192$$

2. **Для связного списка:**
   - Каждый новый элемент оборачивается в новый узел (`new Node(value)`).
   - Узлы не требуют непрерывного размещения и никогда не копируются при увеличении общего числа элементов списка.
   - Добавление элемента в конец (при наличии указателя на хвост) или в начало требует ровно 0 операций копирования существующих данных.

#### Решение в общем виде и вычисление

Вычислим сумму геометрической прогрессии для массива:
$$S = 4 \times (1 + 2 + 4 + 8 + 16 + 32 + 64 + 128 + 256 + 512 + 1024 + 2048)$$
Используя формулу суммы членов геометрической прогрессии:
$$S = 4 \times \frac{2^{12} - 1}{2 - 1} = 4 \times (4096 - 1) = 4 \times 4095 = 16\,380 \text{ операций копирования}.$$

Для односвязного списка суммарное количество копирований существующих элементов при добавлении 10 000 элементов равно:
$$S_{\text{list}} = 0$$

#### Проверка
- Единицы измерения: количество процессорных операций копирования элементов.
- Правдоподобие: Массив требует около 16 тысяч копирований на 10 тысяч элементов, что согласуется с теоретической оценкой амортизированного времени $O(1)$ на добавление в динамический массив. Связный список полностью исключает копирование ценой выделения памяти под каждый отдельный узел.

`Ответ:` Для массива потребуется выполнить 16 380 операций копирования элементов при изменении размера буфера; для связного списка количество операций копирования существующих элементов равно 0.

## 2. Устройство и реализация односвязного списка в C#

### Проектирование класса Node\<T\> с полями Value и Next

Для создания динамических структур данных на ссылках базовым строительным блоком является узел (*Node*). В отличие от элементов массива, которые располагаются в памяти непрерывно, узлы связного списка могут находиться в произвольных областях оперативной памяти (в куче — *heap*). Связь между ними обеспечивается с помощью адресных ссылок.

> **Определение.** Узел (*Node*) — это экземпляр ссылочного типа данных, содержащий полезную нагрузку (*Value*) и одну или несколько ссылок на другие узлы структуры (*Next*).

В языке C# для реализации универсальных структур данных принято использовать обобщения (*generics*), что позволяет хранить в списке данные любого типа (`int`, `string`, пользовательские структуры и классы) без дублирования кода.

Спроектируем класс `Node<T>`:

```csharp
public class Node<T>
{
    // Поле для хранения полезных данных
    public T Value { get; set; }

    // Ссылка на следующий узел в цепочке
    public Node<T>? Next { get; set; }

    // Конструктор для инициализации узла значением
    public Node<T>(T value)
    {
        Value = value;
        Next = null; // По умолчанию новый узел ни на что не ссылается
    }
}
```

Разбор по строкам:
- `public class Node<T>` — объявление обобщенного класса. Параметр `<T>` заменяется на конкретный тип при создании объекта.
- `public T Value { get; set; }` — свойство, содержащее данные текущего узла.
- `public Node<T>? Next { get; set; }` — ссылка на следующий узел. Знак вопроса (`?`) указывает, что в рамках концепции nullable-ссылок в C# это поле может принимать значение `элемент отсутствует` (`null`). Для хвостового узла списка это свойство всегда равно `null`.
- Конструктор `public Node(T value)` принимает значение, сохраняет его в поле `Value` и явно устанавливает `Next = null`.

### Создание управляющего класса LinkedList\<T\> с указателем на головной элемент (Head)

Сам по себе набор разрозненных узлов неудобен для управления. Для работы со списком как с единой коллекцией создается управляющий класс `LinkedList<T>`. 

Его главная обязанность — хранить точку входа в структуру, которой является указатель на самый первый узел списка. Этот указатель традиционно называется `Head` (голова).

> **Определение.** Головной узел (*Head*) — это ссылка на первый элемент односвязного списка. Если список пуст, значение `Head` равно `null`.

Спроектируем каркас управляющего класса:

```csharp
public class LinkedList<T>
{
    // Указатель на первый узел списка
    public Node<T>? Head { get; private set; }

    // Конструктор пустого списка
    public LinkedList()
    {
        Head = null;
    }

    // Свойство для проверки списка на пустоту
    public bool IsEmpty => Head == null;
}
```

Здесь модификатор `private set` у свойства `Head` гарантирует инкапсуляцию: внешний код не может случайно «сломать» структуру ссылок, перезаписав голову напрямую. Изменение структуры происходит только через специальные методы класса.

### Алгоритм добавления нового элемента в начало списка за время O(1)

Одно из ключевых преимуществ связного списка перед массивом — скорость вставки новых элементов в самое начало (*prepend*). 

В массиве для этого пришлось бы сдвигать все существующие элементы вправо на одну позицию, что потребовало бы $O(n)$ операций. В связном списке достаточно изменить всего две ссылки, причем независимо от общего числа элементов в коллекции.

**Алгоритм добавления в начало:**
1. Создать новый узел с передаваемым значением: `newNode = new Node<T>(value)`.
2. Установить поле `Next` нового узла так, чтобы оно указывало на текущий головной элемент: `newNode.Next = Head`.
3. Переназначить указатель `Head` на созданный узел: `Head = newNode`.

Реализация метода на C#:

```csharp
public void AddFirst(T value)
{
    // Шаг 1: создание нового узла
    Node<T> newNode = new Node<T>(value);

    // Шаг 2: новый узел ссылается на то, что раньше было головой
    newNode.Next = Head;

    // Шаг 3: голова теперь указывает на новый узел
    Head = newNode;
}
```

**Оценка сложности:** Все действия выполняются за фиксированное время, не зависящее от длины списка. Следовательно, временная сложность операции добавления в начало составляет $O(1)$.

### Алгоритм обхода списка (итерация по ссылкам от Head до null) для вывода элементов

Поскольку элементы связного списка не имеют индексов в памяти (как ячейки массива `arr[i]`), к ним нельзя обратиться напрямую по номеру. Чтобы прочитать или обработать все элементы, необходимо выполнить **обход** (*traversal*), начиная с головы и двигаясь по цепочке ссылок `Next`.

**Алгоритм обхода:**
1. Создать вспомогательную переменную-указатель (назовем её `current`) и присвоить ей значение головного узла: `Node<T>? current = Head;`.
2. Запустить цикл, который выполняется до тех пор, пока `current` не станет равен `null` (что означает достижение конца списка).
3. На каждой итерации обработать данные текущего узла (`current.Value`).
4. Передвинуть указатель на следующий узел: `current = current.Next;`.

Реализация метода вывода элементов в консоль:

```csharp
public void PrintList()
{
    Node<T>? current = Head;
    
    Console.Write("Список: ");
    while (current != null)
    {
        Console.Write($"{current.Value} -> ");
        current = current.Next; // Переход к следующему узлу
    }
    Console.WriteLine("null");
}
```

### Поиск элемента в односвязном списке по значению: сложность O(n)

Поиск элемента в односвязном списке также основан на последовательном обходе (*линейный поиск*). У нас нет возможности применить бинарный поиск, так как прямой доступ по индексу отсутствует.

**Алгоритм поиска:**
1. Начать с головного узла, установив `current = Head`.
2. Проверять значение `current.Value` на равенство искомому значению.
3. Если совпадение найдено, вернуть `true` (или сам узел/индекс).
4. Если достигнут конец списка (`current == null`), а совпадение не найдено, вернуть `false`.

Реализация метода поиска:

```csharp
public bool Contains(T value)
{
    Node<T>? current = Head;

    while (current != null)
    {
        // Используем EqualityComparer для корректного сравнения типов с generics
        if (EqualityComparer<T>.Default.Equals(current.Value, value))
        {
            return true;
        }
        current = current.Next;
    }

    return false;
}
```

**Оценка сложности:** В худшем случае (если искомый элемент находится в самом конце списка или отсутствует вовсе) придётся обойти все $n$ узлов. Временная сложность поиска составляет $O(n)$, а пространственная — $O(1)$, так как выделяется память только под один вспомогательный указатель.

## 3. Удаление элементов и модификация связного списка

### Удаление элементов и модификация связного списка

В предыдущих разделах мы научились создавать односвязный список, добавлять элементы в его начало и обходить его узлы. Однако полноценная структура данных должна позволять не только накапливать информацию, но и удалять ненужные элементы. В отличие от массивов, где удаление элемента требует сдвига всех последующих элементов в памяти (что занимает время $O(n)$), в связном списке удаление сводится к простому перенаправлению ссылок.

Для того чтобы удалить узел из односвязного списка, недостаточно найти сам удаляемый узел. Поскольку каждый узел хранит ссылку только на *следующий* элемент (`Next`), для исключения узла из цепочки нам обязательно нужен доступ к *предыдущему* элементу. Именно предыдущий узел должен изменить свою ссылку `Next` так, чтобы указывать не на удаляемый элемент, а на элемент, следующий за ним.

Рассмотрим все сценарии удаления элементов, от самых простых до требующих поиска.

---

### Удаление элемента из начала списка

Удаление из начала списка (из головы) — это частный случай, который выполняется быстрее всего, так как нам не нужно искать предыдущий узел: у первого элемента нет предшественника в самом списке, его адрес хранится в поле `Head` управляющего класса `LinkedList<T>`.

Пусть у нас есть список, состоящий из трех узлов. Голова списка (`Head`) указывает на первый узел. Чтобы удалить первый элемент, достаточно перебросить указатель `Head` на второй узел.

```
ДО УДАЛЕНИЯ:
Head ---> [ Node 1 ] ---> [ Node 2 ] ---> [ Node 3 ] ---> null
           ( Value: 5 )    ( Value: 12 )   ( Value: 8 )

ПОСЛЕ УДАЛЕНИЯ Head.Next становится новым Head:
          +----------------+
          |                v
Head ---> [ Node 1 ]     [ Node 2 ] ---> [ Node 3 ] ---> null
   (отвязан от списка)
```

Запишем соответствующий метод на C#:

```csharp
public bool RemoveFirst()
{
    // Проверка: если список пуст, удалять нечего
    if (head == null)
    {
        return false;
    }

    // Переносим указатель головы на следующий элемент
    head = head.Next;
    count--;
    return true;
}
```

Обратите внимание на переменную `count` — если в вашем классе списка поддерживается счетчик элементов, его необходимо уменьшить.

---

### Удаление элемента по значению

Если требуется удалить узел, содержащий определенное значение, процесс состоит из двух этапов:
1. Проверка, не является ли удаляемый элемент головным (тогда вызывается метод `RemoveFirst()`).
2. Поиск элемента в цикле с одновременным отслеживанием предыдущего узла.

Представим алгоритм поиска и удаления:
- Заводим две вспомогательные переменные типа `Node<T>`: `current` (начинает с `head`) и `previous` (изначально `null`).
- В цикле переходим к следующему узлу, пока не дойдем до конца списка или не найдем узел с искомым значением.
- Если узел найден, меняем ссылку `previous.Next` на `current.Next`.

Ниже приведен полный код метода удаления первого вхождения элемента по значению:

```csharp
public bool Remove(T value)
{
    // Граничный случай 1: список пуст
    if (head == null)
    {
        return false;
    }

    // Граничный случай 2: удаляемый элемент находится в самом начале (в голове)
    if (head.Value.Equals(value))
    {
        head = head.Next;
        count--;
        return true;
    }

    // Ищем элемент, начиная со второго узла, запоминая предыдущий
    Node<T> previous = head;
    Node<T> current = head.Next;

    while (current != null)
    {
        if (current.Value.Equals(value))
        {
            // Перенаправляем ссылку: пропускаем текущий узел
            previous.Next = current.Next;
            count--;
            return true;
        }

        previous = current;
        current = current.Next;
    }

    // Граничный случай 3: элемент с таким значением не найден в списке
    return false;
}
```

---

### Роль сборщика мусора (Garbage Collector) в управлении памятью

Когда мы перенаправляем ссылку `previous.Next = current.Next`, мы «отцепляем» узел `current` от основной цепочки списка. Что происходит с объектом, на который больше никто не ссылается из активной части программы?

В языке C# управление памятью автоматическое. В среде .NET работает **сборщик мусора (Garbage Collector)**. Он периодически сканирует управляемую кучу (heap) и находит объекты, к которым у программы больше нет ни одного пути доступа (нет ссылок). 

Как только узел `current` оказывается исключен из связного списка (на него не ссылается ни `previous.Next`, ни переменная `head`), он становится недоступным. При следующем запуске сборщика мусора память, занятая этим узлом, будет освобождена автоматически. Программисту на C# не нужно вручную вызывать функции освобождения памяти (вроде `free` в C++), однако важно вовремя обнулять или перенаправлять ссылки, иначе «потерянные» в куче объекты могут приводить к утечкам памяти (если на них ссылаются посторонние структуры).

### Разбор детального примера

> **Условие.** Дан односвязный список с целочисленными элементами в порядке добавления: $5 \to 12 \to 8 \to 20$. 
> Необходимо пошагово описать и запрограммировать удаление узла со значением $8$. Нарисовать состояние ссылок до и после операции.

#### Рисунок состояния ссылок ДО операции:

В памяти в куче созданы четыре узла. Переменная `head` ссылается на первый узел.

```
head 
  │
  v
┌──────────────┐      ┌──────────────┐      ┌──────────────┐      ┌──────────────┐
│ Value: 5     │      │ Value: 12    │      │ Value: 8     │      │ Value: 20    │
│ Next: ────────┼────>│ Next: ────────┼────>│ Next: ────────┼────>│ Next: null   │
└──────────────┘      └──────────────┘      └──────────────┘      └──────────────┘
  [Узел 1]              [Узел 2]              [Узел 3]              [Узел 4]
```

#### Ход рассуждений:
1. Вызываем метод `list.Remove(8)`.
2. Проверяем голову списка: `head.Value` равно $5$, а не $8$. Голова не удаляется.
3. Инициализируем поиск:
   - `previous` указывает на [Узел 1] (` Value: 5 `).
   - `current` указывает на [Узел 2] (` Value: 12 `).
4. Шаг цикла 1:
   - Проверяем `current.Value` ($12$ равно $8$?). Нет.
   - Сдвигаем указатели: `previous` становится [Узел 2] ($12$), `current` становится [Узел 3] ($8$).
5. Шаг цикла 2:
   - Проверяем `current.Value` ($8$ равно $8$?). **Да, нашли!**
   - Нам нужно исключить [Узел 3] из цепочки. Для этого мы берем поле `Next` текущего узла (оно указывает на [Узел 4] со значением $20$) и присваиваем его в качестве нового значения поля `Next` предыдущего узла: `previous.Next = current.Next`.
   - Уменьшаем счетчик элементов `count`.
   - Возвращаем `true`.

#### Рисунок состояния ссылок ПОСЛЕ операции:

Теперь [Узел 2] ссылается напрямую на [Узел 4]. [Узел 3] больше не имеет входящих ссылок из списка.

```
head 
  │
  v
┌──────────────┐      ┌──────────────┐                            ┌──────────────┐
│ Value: 5     │      │ Value: 12    │      ┌──────────────┐      │ Value: 20    │
│ Next: ────────┼────>│ Next: ──┐    │      │ Value: 8     │      │ Next: null   │
└──────────────┘      └─────────┼────┘      │ Next: null   │      └──────────────┘
  [Узел 1]              [Узел 2]│           └──────────────┘        [Узел 4]
                                │             [Узел 3]
                                │           (Ожидает сборщика
                                └──────────> мусора / недоступен)
```

#### Программная реализация примера:

Ниже представлен полностью компилируемый консольный класс на C#, демонстрирующий создание списка, вывод, удаление узла и повторный вывод:

```csharp
using System;

// Класс отдельного узла связного списка
public class Node<T>
{
    public T Value { get; set; }
    public Node<T> Next { get; set; }

    public Node(T value)
    {
        Value = value;
        Next = null;
    }
}

// Управляющий класс односвязного списка
public class LinkedList<T>
{
    private Node<T> head;
    private int count;

    public int Count => count;

    // Метод добавления в конец (для удобства заполнения в примере)
    public void AddLast(T value)
    {
        Node<T> newNode = new Node<T>(value);
        if (head == null)
        {
            head = newNode;
        }
        else
        {
            Node<T> current = head;
            while (current.Next != null)
            {
                current = current.Next;
            }
            current.Next = newNode;
        }
        count++;
    }

    // Метод удаления элемента по значению
    public bool Remove(T value)
    {
        if (head == null)
        {
            return false;
        }

        if (head.Value.Equals(value))
        {
            head = head.Next;
            count--;
            return true;
        }

        Node<T> previous = head;
        Node<T> current = head.Next;

        while (current != null)
        {
            if (current.Value.Equals(value))
            {
                previous.Next = current.Next;
                count--;
                return true;
            }

            previous = current;
            current = current.Next;
        }

        return false;
    }

    // Метод вывода элементов списка
    public void PrintList()
    {
        Node<T> current = head;
        while (current != null)
        {
            Console.Write(current.Value + " -> ");
            current = current.Next;
        }
        Console.WriteLine("null");
    }
}

// Главный класс программы
class Program
{
    static void Main()
    {
        // Создаем список и добавляем элементы: 5, 12, 8, 20
        LinkedList<int> list = new LinkedList<int>();
        list.AddLast(5);
        list.AddLast(12);
        list.AddLast(8);
        list.AddLast(20);

        Console.WriteLine("Исходный список:");
        list.PrintList();

        // Удаляем элемент со значением 8
        bool isRemoved = list.Remove(8);
        Console.WriteLine($"Результат удаления 8: {isRemoved}");

        Console.WriteLine("Список после удаления элемента 8:");
        list.PrintList();

        // Проверка удаления несуществующего элемента
        bool isRemovedMissing = list.Remove(99);
        Console.WriteLine($"Результат удаления 99: {isRemovedMissing}");
        
        // Проверка удаления головы списка (значение 5)
        list.Remove(5);
        Console.WriteLine("Список после удаления головы (5):");
        list.PrintList();
    }
}
```

```text

Результат удаления 8: True
Список после удаления элемента 8:

Список после удаления головы (5):

```

### Анализ граничных условий и оценка сложности

При проектировании и написании кода для работы со связными списками необходимо всегда проверять следующие граничные случаи:
1. **Пустой список** (`head == null`): попытка удаления из пустого списка должна корректно возвращать `false` или возбуждать исключение (в зависимости от архитектуры), а не падать с ошибкой `NullReferenceException`.
2. **Удаление единственного элемента**: если в списке ровно один элемент и его значение совпадает с искомым, после удаления `head` должен стать равным `null`. Наш алгоритм корректно обрабатывает этот случай через ветвление `head.Value.Equals(value)`.
3. **Удаление несуществующего элемента**: если элемент отсутствует в списке, цикл успешно доходит до конца (`current == null`), метод завершается и возвращает `false`, не изменяя структуру списка.
4. **Удаление элемента, находящегося в самом конце списка**: требует корректной установки поля `Next` предпоследнего элемента в значение `null`. Наш цикл с этим справляется, так как `current.Next` для последнего элемента равен `null`, и именно это значение присваивается предыдущему узлу.

#### Оценка временной и пространственной сложности:
- **Временная сложность (Time Complexity):**
  - Удаление из начала списка (`RemoveFirst`): $O(1)$ — выполняется за фиксированное число шагов независимо от размера списка.
  - Удаление по значению (`Remove`): в худшем случае (если элемент находится в самом конце списка или отсутствует вовсе) нам придется обойти все $n$ узлов. Следовательно, сложность составляет **$O(n)$**.
- **Пространственная сложность (Space Complexity):**
  - Для выполнения операции удаления выделяется фиксированное число дополнительных переменных-ссылок (`previous`, `current`), что требует $O(1)$ дополнительной памяти в куче или стеке вызовов.

## 4. Абстрактный тип данных «Стек» и его реализация на узлах

### Абстрактный тип данных «Стек» и его реализация на узлах

Предыдущие темы нашего курса были посвящены универсальным связным спискам, которые позволяют добавлять и удалять элементы в произвольных позициях. Однако во многих практических задачах программирования такой широкий функционал избыточен, а порой и опасен, так как случайное изменение элемента в середине структуры может нарушить логику программы. 

Существуют специализированные структуры данных с жестко ограниченным интерфейсом доступа к элементам. Одной из важнейших таких структур является **стек**.

> **Определение.** Стек (англ. *stack* — стопка) — это абстрактный тип данных, представляющий собой упорядоченную коллекцию элементов, в которой добавление новых элементов и удаление существующих производятся только с одного конца коллекции, называемого **вершиной стека** (англ. *top*).

Главный принцип работы стека описывается аббревиатурой **LIFO** (Last In, First Out — «последним пришел — первым вышел»). Это означает, что элемент, который был добавлен в стек последним, будет извлечен из него самым первым. Наглядный пример из реальной жизни — стопка тарелок: вы можете положить новую тарелку только наверх стопки и взять тарелку можете тоже только сверху. Достать тарелку из середины, не разрушив стопку, нельзя.

### Основные операции стека

Классический интерфейс стека включает в себя три базовые операции, сложность каждой из которых должна составлять $O(1)$:

1. **`Push(value)`** — помещает новый элемент на вершину стека. Размер стека увеличивается на единицу.
2. **`Pop()`** — извлекает элемент с вершины стека и одновременно удаляет его из структуры. Метод возвращает значение удаленного элемента. Если стек пуст, попытка извлечения приводит к ошибке переполнения вниз (underflow).
3. **`Peek()`** — возвращает значение элемента с вершины стека, *не удаляя* его. Позволяет «заглянуть» в то, что находится на вершине. Также требует проверки стека на пустоту.

Дополнительно часто реализуют вспомогательные свойства или методы:
* **`Count`** — текущее количество элементов в стеке.
* **`IsEmpty`** — логическое свойство, возвращающее `true`, если стек пуст, и `false` в противном случае.

### Сравнение реализаций: массив против связанных узлов

В языке C# базовая структура данных `System.Collections.Generic.Stack<T>` реализована на основе обычного массива (`T[]`), размер которого автоматически увеличивается вдвое при переполнении. Однако у реализации стека на массивах есть недостатки:
* При исчерпании емкости массива среда выполнения выделяет новый, более крупный массив в памяти, после чего производит копирование всех элементов со старого места на новое. В худшем случае это требует $O(n)$ времени.
* Массив требует выделения непрерывного блока памяти фиксированного размера. Если в куче нет достаточно большого непрерывного куска памяти (даже при наличии свободного объема в сумме), программа получит исключение `OutOfMemoryException`.

Альтернативным и более элегантным подходом с точки зрения динамической памяти является **реализация стека на связанных узлах (Node-based Stack)**. В этой архитектуре каждый элемент стека хранится в отдельном объекте класса `Node<T>`, размещенном в произвольной области кучи. Узлы связываются между собой однонаправленными ссылками: каждый новый добавленный элемент содержит ссылку на предыдущую вершину стека.

Преимущества стека на узлах:
* **Отсутствие переполнения памяти**: стек может расти до тех пор, пока в оперативной памяти компьютера есть свободное место. Память выделяется порционно для каждого узла по мере необходимости.
* **Гарантированное время $O(1)$** для всех операций добавления (`Push`) и извлечения (`Pop`). Никакого копирования массивов не требуется.
* **Отсутствие неиспользуемой памяти**: в отличие от массива, который может быть заполнен лишь наполовину (занимая лишнюю память), связный стек занимает ровно столько памяти, сколько элементов в нем хранится в данный момент.

### Проектирование класса LinkedStack<T>

Для реализации стека на узлах нам понадобится уже знакомый по прошлым занятиям вспомогательный класс `Node<T>`, который инкапсулирует полезные данные и ссылку на следующий узел. 

Рассмотрим проект нашего обобщенного класса `LinkedStack<T>`:

```csharp
using System;

// Узел связного списка для хранения данных в стеке
public class Node<T>
{
    public T Value { get; set; }
    public Node<T> Next { get; set; }

    public Node(T value)
    {
        Value = value;
        Next = null;
    }
}

// Собственная реализация стека на основе связанных узлов
public class LinkedStack<T>
{
    private Node<T> top; // Указатель на вершину стека
    private int count;   // Текущее количество элементов

    // Конструктор пустого стека
    public LinkedStack()
    {
        top = null;
        count = 0;
    }

    // Свойство для проверки, пуст ли стек
    public bool IsEmpty => top == null;

    // Свойство для получения количества элементов
    public int Count => count;

    // Добавление элемента на вершину стека
    public void Push(T value)
    {
        Node<T> newNode = new Node<T>(value); // 1. Создаем новый узел
        newNode.Next = top;                   // 2. Новый узел ссылается на старую вершину
        top = newNode;                        // 3. Смещаем указатель вершины на новый узел
        count++;                              // 4. Увеличиваем счетчик
    }

    // Извлечение элемента с вершины стека с его удалением
    public T Pop()
    {
        if (IsEmpty)
        {
            throw new InvalidOperationException("Стек пуст. Невозможно извлечь элемент.");
        }

        T value = top.Value; // Сохраняем значение вершины для возврата
        top = top.Next;      // Смещаем указатель вершины на следующий узел
        count--;             // Уменьшаем счетчик

        return value;
    }

    // Просмотр вершины стека без удаления
    public T Peek()
    {
        if (IsEmpty)
        {
            throw new InvalidOperationException("Стек пуст. Невозможно просмотреть вершину.");
        }

        return top.Value;
    }
}
```

### Пошаговый разбор реализации методов

#### Метод `Push(T value)`
Когда мы вызываем метод `Push`, происходит следующее:
1. Выделяется память в куче под новый экземпляр класса `Node<T>` с переданным значением `value`. Ссылка `Next` этого нового узла изначально равна `null`.
2. Мы присваиваем полю `newNode.Next` текущее значение указателя `top`. Таким образом, новый узел «цепляется» за предыдущую верхушку стека.
3. Переменная класса `top` переназначается на `newNode`. Теперь новый узел официально становится вершиной стека.
4. Счетчик элементов `count` увеличивается на единицу.

#### Метод `Pop()`
Операция удаления обратна добавлению:
1. Сперва мы проверяем условие `IsEmpty`. Если `top == null`, стек пуст, и дальнейшая работа невозможна — генерируется исключение `InvalidOperationException` (предотвращение ошибки *underflow*).
2. Мы сохраняем значение, хранящееся в текущей вершине (`top.Value`), чтобы вернуть его вызывающему коду.
3. Перемещаем указатель вершины на следующий элемент: `top = top.Next`. Старый верхний узел теряет связь с нашим стеком. Если на этот узел больше нет ссылок в других частях программы, сборщик мусора (Garbage Collector) автоматически очистит занятую им память.
4. Уменьшаем счетчик `count` на единицу и возвращаем сохраненное значение.

#### Метод `Peek()`
Этот метод устроен аналогично `Pop()`, но проще: он проверяет стек на пустоту, после чего просто возвращает `top.Value`, не меняя значение указателя `top` и не уменьшая счетчик.

### Разобранный пример

**Условие задачи:** 
Создать пустой стек целых чисел (`LinkedStack<int>`). Выполнить последовательно следующие операции:
1. `Push(15)`
2. `Push(30)`
3. `Pop()`
4. `Push(10)`
5. `Peek()`

Определить состояние стека (какие элементы в нем находятся и какова вершина) и возвращаемые значения на каждом шаге.

#### Ход рассуждений
Мы будем моделировать состояние структуры данных шаг за шагом. Для наглядности изобразим стек в виде вертикальной цепочки узлов, где верхний элемент (`top`) находится сверху, а стрелками `->` показаны ссылки `Next` от вершины к основанию стека.

#### Решение по шагам

* **Состояние 0 (Инициализация):**
  Создаем пустой стек.
  - `top = null`
  - `count = 0`
  - Стек пуст (`IsEmpty == true`).

* **Шаг 1. Вызов `Push(15)`:**
  - Создается узел со значением `15`. Его поле `Next` указывает на `null`.
  - Указатель `top` начинает указывать на этот узел.
  - Счетчик: `count = 1`.
  - *Состояние стека:* `[Вершина] -> 15 -> null`

* **Шаг 2. Вызов `Push(30)`:**
  - Создается узел со значением `30`.
  - Поле `Next` нового узла получает ссылку на старую вершину (узел со значением `15`).
  - Указатель `top` переназначается на новый узел (`30`).
  - Счетчик: `count = 2`.
  - *Состояние стека:* `[Вершина] -> 30 -> 15 -> null`

* **Шаг 3. Вызов `Pop()`:**
  - Стек не пуст. Мы берем значение из текущей вершины: `30`.
  - Перемещаем указатель вершины вниз: `top = top.Next` (теперь `top` указывает на узел `15`).
  - Узел `30` удаляется из структуры.
  - Счетчик: `count = 1`.
  - *Возвращаемое значение метода:* `30`
  - *Состояние стека:* `[Вершина] -> 15 -> null`

* **Шаг 4. Вызов `Push(10)`:**
  - Создается узел со значением `10`.
  - Его поле `Next` указывает на текущую вершину (узел `15`).
  - Указатель `top` переназначается на узел `10`.
  - Счетчик: `count = 2`.
  - *Состояние стека:* `[Вершина] -> 10 -> 15 -> null`

* **Шаг 5. Вызов `Peek()`:**
  - Стек не пуст. Метод считывает значение из текущей вершины (`10`), но *не изменяет* структуру стека.
  - Счетчик не меняется: `count = 2`.
  - *Возвращаемое значение метода:* `10`
  - *Состояние стека:* `[Вершина] -> 10 -> 15 -> null` (осталось без изменений).

#### Проверка и правдоподобность
Все операции выполнялись за константное время $O(1)$. Ссылки `Next` никогда не образовывали циклических зависимостей: каждый узел корректно ссылался на своего предшественника в глубь стека, а самый первый добавленный элемент (`15`) закономерно оказался в самом низу со ссылкой `Next = null`. Исключения под управлением `InvalidOperationException` не возникали, так как попыток извлечения из пустого стека не было.

Ответ:
- Последовательность возвращаемых значений методов: `Pop()` вернул `30`, `Peek()` вернул `10`.
- Итоговое состояние стека: вершина содержит элемент `10`, за ним следует элемент `15`, за которым находится признак конца списка (`null`). Количество элементов в стеке равно 2.

## 5. Задача о стеке: проверка правильности расстановки скобок

### Постановка задачи проверки сбалансированности скобок

Во многих практических задачах программирования — от написания компиляторов и интерпретаторов до работы текстовых редакторов с подсветкой синтаксиса — требуется проверять корректность вложенности различных управляющих конструкций, тегов или знаков препинания. Простейшим и вместе с тем фундаментальным примером такой задачи является проверка правильности расстановки скобок в математических выражениях или исходном коде программ.

Пусть у нас есть строка, содержащая символы различных типов скобок: круглые `()`, квадратные `[]` и фигурные `{}`. Выражение считается сбалансированным (или корректным), если для каждой открывающей скобки существует соответствующая ей закрывающая скобка того же типа, а пары скобок правильно вложены друг в друга, то есть не пересекаются некорректным образом.

Например:
- Корректные выражения: `(a + b)`, `(a + [b * (c - d)])`, `{x + [y (z)]}`.
- Некорректные выражения: `(a + b]` (несоответствие типов скобок), `)a + b(` (закрывающая скобка идет раньше открывающей), `(a + b` (незакрытая скобка).

Для решения этой задачи идеально подходит структура данных **стек**, с которой мы познакомились ранее. Поскольку стек работает по принципу LIFO (последним пришел — первым вышел), он естественным образом отражает правила вложенности: последняя открытая скобка должна закрыться раньше остальных.

---

### Алгоритм анализа строки с помощью стека

Чтобы проверить строку на сбалансированность скобок, мы организуем посимвольный обход слева направо. Для хранения открывающих скобок мы будем использовать наш собственный класс стека на узлах `LinkedStack<char>`, созданный в предыдущем разделе.

> **Правило алгоритма.**
> 1. Создаем пустой стек для символов: `LinkedStack<char> stack = new LinkedStack<char>();`.
> 2. Поочередно читаем каждый символ `ch` из входной строки.
> 3. Если символ `ch` является **открывающей** скобкой (любой из `(`, `[`, `{`), мы помещаем его в стек с помощью операции `stack.Push(ch)`.
> 4. Если символ `ch` является **закрывающей** скобкой (любой из `)`, `]`, `}`), выполняем проверку:
>    - Если стек пуст, это означает, что закрывающая скобка появилась раньше открывающей или для нее нет пары. Выражение **не сбалансировано**.
>    - Если стек не пуст, извлекаем с вершины стека элемент с помощью `stack.Pop()`. Проверяем, соответствует ли извлеченная открывающая скобка текущей закрывающей. Если соответствия нет (например, извлегли `(`, а встретили `]`), выражение **не сбалансировано**.
> 5. После завершения обхода всей строки проверяем состояние стека:
>    - Если стек остался пустым, значит, все открытые скобки были успешно закрыты. Выражение **сбалансировано**.
>    - Если в стеке остались элементы, значит, какие-то открывающие скобки остались без пары. Выражение **не сбалансировано**.

Для удобства проверки соответствия типов скобок можно написать вспомогательный метод, который принимает открывающую и закрывающую скобки и возвращает логическое значение.

---

### Разбор возможных случаев и ошибок

При реализации алгоритма необходимо предусмотреть все возможные сценарные отклонения от нормы:

1. **Стек пуст при попытке извлечения (дефицит открывающих скобок):**
   * *Пример:* строка `a + b)`.
   * *Поведение:* при встрече символа `)` стек оказывается пустым. Метод `Pop()` не может вернуть элемент. Алгоритм должен сразу зафиксировать ошибку и прекратить обработку (или вернуть `false`).
2. **Несоответствие типов скобок (нарушение иерархии вложенности):**
   * *Пример:* строка `(a + b]`.
   * *Поведение:* при встрече `]` из стека извлекается символ `(`. Сравнение типов показывает, что круглая скобка не соответствует квадратной. Выражение признается неверным.
3. **Остаток элементов в стеке после окончания строки (избыток открывающих скобок):**
   * *Пример:* строка `(a + b`.
   * *Поведение:* цикл завершился успешно, все закрытые скобки совпали, но в стеке осталась несожженная открывающая скобка `(`. Поскольку стек не пуст, выражение считается несбалансированным.

---

### Пошаговый разобранный пример

Проверим сбалансированность скобочного выражения `(a + [b * (c - d)])` с помощью стека на узлах.

**Условие:**
Входная строка: `"(a + [b * (c - d)])"`
Создаем пустой стек: `stack = [ ]` (вершина слева/сверху).

**Ход рассуждений:**
Будем обрабатывать символы строки один за другим. Буквы латинского алфавита, знаки операций `+`, `*`, `-` и пробелы нас не интересуют — мы их пропускаем. Обращаем внимание только на символы `(`, `)`, `[`, `]`, `{`, `}`.

**Таблица пошагового выполнения:**

| Шаг | Символ (`ch`) | Действие | Состояние стека (от вершины к дну) | Описание шага |
|:---:|:---:|---|---|---|
| 1 | `(` | `Push('(')` | `('(')` | Открывающая скобка — добавляем в стек. |
| 2 | `a` | Пропустить | `('(')` | Обычный символ, игнорируем. |
| 3 | `+` | Пропустить | `('(')` | Знак операции, игнорируем. |
| 4 | `[` | `Push('[')` | `('[', '(')` | Открывающая скобка — добавляем в стек. |
| 5 | `b` | Пропустить | `('[', '(')` | Обычный символ, игнорируем. |
| 6 | `*` | Пропустить | `('[', '(')` | Знак операции, игнорируем. |
| 7 | `(` | `Push('(')` | `('(', '[', '(')` | Открывающая скобка — добавляем в стек. |

### Полная реализация программы на C#

Ниже представлена полная, готовая к компиляции программа на C#. Для демонстрации работы используется наш собственный связный список и стек, спроектированные на предыдущих занятиях (предполагается, что класс узла `Node<T>` и класс стека `LinkedStack<T>` доступны в проекте).

```csharp
using System;

// Узел односвязного списка для хранения элементов любого типа T
public class Node<T>
{
    public T Value { get; set; }
    public Node<T> Next { get; set; }

    public Node(T value)
    {
        Value = value;
        Next = null;
    }
}

// Собственная реализация стека на основе связанных узлов (LIFO)
public class LinkedStack<T>
{
    private Node<T> top; // Указатель на вершину стека
    private int count;   // Количество элементов в стеке

    public LinkedStack()
    {
        top = null;
        count = 0;
    }

    public int Count => count;

    public bool IsEmpty => top == null;

    // Добавление элемента на вершину стека
    public void Push(T value)
    {
        Node<T> newNode = new Node<T>(value);
        newNode.Next = top;
        top = newNode;
        count++;
    }

    // Извлечение элемента с вершины стека
    public T Pop()
    {
        if (IsEmpty)
        {
            throw new InvalidOperationException("Стек пуст. Невозможно выполнить операцию Pop.");
        }

        T value = top.Value;
        top = top.Next;
        count--;
        return value;
    }

    // Просмотр вершины стека без удаления
    public T Peek()
    {
        if (IsEmpty)
        {
            throw new InvalidOperationException("Стек пуст. Невозможно выполнить операцию Peek.");
        }

        return top.Value;
    }
}

public class Program
{
    // Метод проверки соответствия открывающей и закрывающей скобок
    private static bool IsMatchingPair(char open, char close)
    {
        if (open == '(' && close == ')') return true;
        if (open == '[' && close == ']') return true;
        if (open == '{' && close == '}') return true;
        return false;
    }

    // Основной метод проверки сбалансированности скобок в строке
    public static bool AreBracketsBalanced(string expression)
    {
        LinkedStack<char> stack = new LinkedStack<char>();

        foreach (char ch in expression)
        {
            // Если символ - открывающая скобка, помещаем в стек
            if (ch == '(' || ch == '[' || ch == '{')
            {
                stack.Push(ch);
            }
            // Если символ - закрывающая скобка, проверяем вершину стека
            else if (ch == ')' || ch == ']' || ch == '}')
            {
                // Если стек пуст, значит, закрывающая скобка не имеет пары слева
                if (stack.IsEmpty)
                {
                    return false;
                }

                char openBracket = stack.Pop();

                // Проверяем, соответствуют ли типы скобок друг другу
                if (!IsMatchingPair(openBracket, ch))
                {
                    return false;
                }
            }
        }

        // Если после проверки всех символов стек пуст, выражение сбалансировано
        return stack.IsEmpty;
    }

    public static void Main(string[] args)
    {
        string expr1 = "(a + [b * (c - d)])";
        string expr2 = "(a + b]";
        string expr3 = "{x + [y * (z)]";

        Console.WriteLine($"Выражение: \"{expr1}\" -> Сбалансировано: {AreBracketsBalanced(expr1)}");
        Console.WriteLine($"Выражение: \"{expr2}\" -> Сбалансировано: {AreBracketsBalanced(expr2)}");
        Console.WriteLine($"Выражение: \"{expr3}\" -> Сбалансировано: {AreBracketsBalanced(expr3)}");
    }
}
```

#### Пояснение по строкам и блокам кода:
- Класс `Node<T>` и `LinkedStack<T>` инкапсулируют логику динамической памяти на ссылках (как рассматривалось на занятиях по связным спискам).
- Метод `AreBracketsBalanced` осуществляет линейный проход по строке с помощью цикла `foreach`. Операции добавления (`Push`) и извлечения (`Pop`) выполняются за константное время $O(1)$.
- Внутри цикла отсеиваются все символы, не являющиеся скобками, что позволяет проверять реальные математические выражения и программный код.

### Оценка сложности алгоритма

При анализе эффективности алгоритмов используют $O$-нотацию (асимптотическую сложность):

1. **Временная сложность (Time Complexity): — $O(n)$**
   * Где $n$ — длина входной строки.
   * Мы ровно один раз проходим по каждому символу строки (`foreach` выполняет ровно $n$ итераций).
   * Внутри цикла операции со стеком (`Push` и `Pop`) выполняются за константное время $O(1)$, так как изменение указателя `top` происходит непосредственно на верхушке связного списка без перебора остальных элементов.
   * Следовательно, общее время работы алгоритма линейно зависит от длины строки.

2. **Пространственная сложность (Space Complexity): — $O(n)$**
   * В худшем случае входная строка может состоять исключительно из открывающих скобок (например, `((((...((( }`).
   * В этом случае каждый символ будет добавлен в наш стек на узлах. Количество узлов в стеке станет равным длине строки $n$.
   * Поскольку каждый узел в динамической памяти (куче) требует выделения памяти под объект `Node<T>`, максимальный объем дополнительной памяти пропорционален длине строки.

## Типичные ошибки

1. **Потеря ссылки на голову (`Head`) при добавлении в пустой список.**
   * *В чем ошибка:* Написание кода вставки без учета того, пуст ли список в данный момент. Если список пустой (`Head == null`), простая вставка в существующую цепочку приведет к попытке обратиться к свойству `Next` несуществующего объекта.
   * *Как избежать:* Всегда делать проверку `if (Head == null)` перед изменением ссылок или корректно обрабатывать присваивание: `newNode.Next = Head; Head = newNode;` (этот универсальный код корректно работает даже для пустого списка, так как `Head` изначально равен `null`).

2. **Забытая проверка на `null` при обходе списка (NullReferenceException).**
   * *В чем ошибка:* Обращение к полям `current.Value` или попытка перейти к следующему элементу `current = current.Next`, когда переменная `current` уже стала равной `null` после прохождения последнего узла.
   * *Как избежать:* Убедиться, что условие цикла обхода четко проверяет отсутствие конца списка: `while (current != null)`. Нельзя использовать циклы вида `do-while` без предварительной проверки на пустоту списка.

3. **Игнорирование утечек памяти или ручное удаление в C# (ожидание аналогов `free` из C++).**
   * *В чем ошибка:* Попытка вручную «очищать» или удалять узлы, на которые больше нет ссылок, либо наоборот, оставление ненужных перекрестных ссылок, препятствующих сборщику мусора.
   * *Как избежать:* Помнить, что в C# за освобождение памяти отвечает сборщик мусора (*Garbage Collector*). Достаточно просто отвязать узел от структуры данных (например, перенаправить `previous.Next = current.Next`), и среда выполнения .NET сама ударит объект при необходимости.

4. **Ошибка при удалении первого элемента (головы) списка.**
   * *В чем ошибка:* Использование общего алгоритма поиска с двумя указателями (`previous` и `current`) для удаления первого узла. Поскольку у первого узла нет предшественника (`previous` равен `null`), обращение `previous.Next` вызовет `NullReferenceException`.
   * *Как избежать:* Всегда выносить удаление головы в отдельное граничное условие в начале метода удаления: `if (Head.Value.Equals(value)) { Head = Head.Next; return true; }`.

5. **Путаница в порядке перенаправления ссылок при добавлении в стек или список.**
   * *В чем ошибка:* Изменение указателя головы (`Head` или `top`) *до* того, как новый узел был соединен со старой цепочкой. Это приводит к безвозвратной потере всей оставшейся части структуры данных, так как точка входа смещается на новый элемент, а старые узлы «отрываются» и теряются в памяти.
   * *Как избежать:* Всегда соблюдать строгий порядок действий: сначала привязать новый узел к старому (`newNode.Next = Head`), и только после этого перенаправлять голову на новый узел (`Head = newNode`).

6. **Использование фиксированных массивов вместо динамических структур там, где размер данных заранее неизвестен.**
   * *В чем ошибка:* Объявление массива фиксированной длины `new int[1000]` в задачах, где объем поступающих данных может превысить лимит или быть катастрофически меньше (трата памяти).
   * *Как избежать:* Применять связные списки или встроенные динамические коллекции (`List<T>`, `LinkedList<T>`, `Stack<T>`), если размер коллекции заранее неизвестен и динамически меняется.

7. **Неправильный порядок извлечения из стека (нарушение принципа LIFO).**
   * *В чем ошибка:* Попытка обойти стек по всем узлам как обычный список или извлечение элементов в неверном порядке при решении задач (например, при проверке скобок).
   * *Как избежать:* Помнить, что к элементам стека нет произвольного доступа. Доступен только метод `Peek()` для просмотра вершины и `Pop()` для извлечения. Любая попытка прочитать середину стека нарушает его абстрактный тип данных.

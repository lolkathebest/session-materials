## Понятие множества в математике и программировании: класс HashSet<T>

### Понятие множества в математике и программировании

В программировании и разработке алгоритмов часто возникает задача хранения коллекций данных, в которых каждый элемент должен присутствовать в единственном экземпляре, а порядок элементов не имеет значения. Для решения таких задач в математике и информатике используется фундаментальная абстракция — множество.

> **Определение.** Множество — это совокупность некоторых объектов, рассматриваемых как единое целое, обладающая двумя ключевыми свойствами:
> 1. **Уникальность элементов:** каждый объект может входить в множество только один раз (отсутствие дубликатов).
> 2. **Отсутствие порядка:** элементы множества не упорядочены; у них нет понятий «первый», «второй» или «последний» по индексу, в отличие от массивов или списков.

В классической математике множества обозначаются заглавными латинскими буквами (например, $A = \{1, 2, 3\}$), а проверка принадлежности элемента записывается как $x \in A$. В языке C# .NET 8 для работы с такими структурами данных предназначен универсальный класс `HashSet<T>`, входящий в стандартную библиотеку классов.


### Сравнение коллекций: массивы, списки и множества

Прежде чем переходить к коду, важно четко понимать, в каких ситуациях следует применять массивы (`T[]`), списки (`List<T>`) и множества (`HashSet<T>`). Выбор правильной структуры данных определяет производительность и корректность программы.

| Критерий | Массив (`T[]`) | Список (`List<T>`) | Множество (`HashSet<T>`) |
|---|---|---|---|
| **Размер** | Фиксированный, задается при создании | Динамический (автоматически увеличивается) | Динамический (автоматически увеличивается) |
| **Доступ по индексу** | Быстрый, за время $O(1)$ | Быстрый, за время $O(1)$ | Отсутствует (нет индексов) |
| **Дубликаты** | Разрешены | Разрешены | **Запрещены** (автоматически отбрасываются) |
| **Порядок элементов** | Строго фиксированный | Строго фиксированный | Не гарантируется |
| **Поиск элемента (`Contains`)** | Медленный, линейный поиск $O(N)$ | Медленный, линейный поиск $O(N)$ | **Очень быстрый**, хэш-таблица $O(1)$ в среднем |

Если вам требуется хранить последовательность элементов, где важен порядок ввода или позиции (например, список результатов матча по минутам), используют `List<T>`. Если же требуется эффективно проверять наличие элемента («содержится ли этот пользователь в базе активных сессий?») и гарантировать отсутствие копий, лучшим выбором становится `HashSet<T>`.


### Пространство имен System.Collections.Generic и обобщенный тип <T>

Класс `HashSet<T>` располагается в пространстве имен `System.Collections.Generic`. Чтобы использовать его в исходном файле C#, в самом начале программы необходимо подключить это пространство имен с помощью директивы `using`:

```csharp
using System.Collections.Generic;
```

Символ `<T>` в названии `HashSet<T>` обозначает **обобщенный тип** (или дженерик, от англ. *Generics*). Вместо буквы `T` при объявлении переменной подставляется конкретный тип данных, с которым будет работать множество. Например:
- `HashSet<int>` — множество целых чисел;
- `HashSet<string>` — множество строк;
- `HashSet<double>` — множество чисел с плавающей точкой.

Использование обобщений обеспечивает **строгую типизацию во время компиляции**: компилятор C# гарантирует, что в `HashSet<int>` нельзя случайно записать строковое значение, избавив программу от необходимости выполнять опасные приведения типов (`cast`) и исключив множество ошибок времени выполнения.


### Создание и инициализация объекта HashSet<T>

Создать пустой объект множества можно с помощью стандартного оператора `new`:

```csharp
HashSet<int> numbers = new HashSet<int>();
```

В C# (начиная с версии 9.0 и выше) при объявлении переменной часто используют сокращенный синтаксис (Target-typed new), если тип уже очевиден из левой части выражения:

```csharp
HashSet<int> numbers = new();
```

Для одновременного создания и заполнения множества начальными данными используют **инициализаторы коллекций**. Перечислить элементы можно в фигурных скобках:

```csharp
HashSet<string> cities = new HashSet<string> { "Москва", "Санкт-Петербург", "Казань", "Москва" };
```
*Примечание:* Хотя строка `"Москва"` указана в инициализаторе дважды, при создании множества второй дубликат будет автоматически проигнорирован. В итоге коллекция будет содержать ровно 3 уникальных элемента.


### Основные методы: Add, Remove, Contains

Класс `HashSet<T>` предоставляет интуитивно понятный набор методов для управления содержимым:

1. **`Add(T item)`** — пытается добавить элемент `item` в множество. 
   - Возвращает логическое значение (`bool`): `true`, если элемент был успешно добавлен (его раньше не было), и `false`, если такой элемент уже существовал в множестве.
2. **`Remove(T item)`** — удаляет указанный элемент из множества.
   - Возвращает `true`, если элемент был найден и удален, и `false`, если элемент в множестве отсутствовал.
3. **`Contains(T item)`** — проверяет наличие элемента в множестве.
   - Возвращает `true`, если элемент найден, и `false` в противном случае.

Рассмотрим пример использования этих методов:

```csharp
using System;
using System.Collections.Generic;

class Program
{
    static void Main()
    {
        HashSet<string> permittedUsers = new HashSet<string> { "Анна", "Борис", "Виктор" };

        // Попытка добавить существующего пользователя
        bool addedAgain = permittedUsers.permittedUsers.Add("Анна"); 
        // addedAgain будет равен false, множество не изменилось

        // Проверка наличия
        if (permittedUsers.Contains("Борис"))
        {
            Console.WriteLine("Борис имеет доступ к системе.");
        }

        // Удаление элемента
        bool removed = permittedUsers.Remove("Виктор"); 
        // removed будет равен true
        
        Console.WriteLine($"Количество пользователей: {permittedUsers.Count}"); // Выведет 2
    }
}
```


### Внутреннее устройство: хэш-таблица и сложность операций

Чтобы понимать, почему `HashSet<T>` работает именно так, а не иначе, нужно заглянуть под капот этой структуры данных.

В основе `HashSet<T>` лежит структура данных **хэш-таблица** (англ. *Hash Table*). Когда вы добавляете объект в множество, среда выполнения .NET вычисляет для него специальное числовое значение с помощью специальной функции — **хэш-кода** (метод `GetHashCode()`). Это число используется в качестве индекса в массиве внутренней памяти хэш-таблицы, куда помещается элемент.

Благодаря такому механизму:
- Поиск элемента (`Contains`), добавление (`Add`) и удаление (`Remove`) выполняются в среднем за **константное время** $O(1)$. Это значит, что поиск одного элемента в множестве из 10 элементов и в множестве из 10 000 000 элементов займет практически одинаковое время. В худшем случае (при коллизиях хэш-кодов) сложность может деградировать до линейной $O(N)$, но на практике .NET минимизирует такие ситуации.
- **Порядок элементов не определен.** Элементы хранятся в ячейках памяти в соответствии с их хэш-кодами, а не в порядке их добавления. Поэтому обход множества через цикл `foreach` выдаст элементы в произвольном (с точки зрения человека) порядке.


### Обход элементов множества с помощью цикла foreach

Поскольку у объектов `HashSet<T>` отсутствуют числовые индексы (нельзя написать `set[0]`), для просмотра всех элементов применяется цикл `foreach`. Любая коллекция в .NET, реализующая интерфейс `IEnumerable<T>`, поддерживает этот цикл.

```csharp
HashSet<string> languages = new HashSet<string> { "C#", "Python", "Java", "C++" };

Console.WriteLine("Элементы множества:");
foreach (string lang in languages)
{
    Console.WriteLine($"- {lang}");
}
```

*Важное правило безопасности коллекций:* Во время выполнения цикла `foreach` по элементам `HashSet<T>` **строго запрещено** изменять саму структуру множества (вызывать методы `Add` или `Remove`). Если попытаться добавить или удалить элемент прямо внутри тела цикла, среда выполнения .NET выбросит исключение времени выполнения `InvalidOperationException` (коллекция была изменена; операция перечисления не может быть выполнена). Если модификация все же необходима, сначала соберите элементы для удаления в отдельный временный список, а затем удалите их после завершения цикла.

### Разобранный пример

**Условие:** 
Дан список из 7 целых чисел: `{10, 20, 10, 30, 40, 20, 50}`. Написать консольную программу на C#, которая добавляет все элементы в `HashSet<int>`, выводит размер полученного множества и все его элементы в консоль. Показать пошагово, как происходит устранение дубликатов.

#### Рисунок схемы работы алгоритма (пошагово словами):
Представим память хэш-таблицы как пустые ячейки. Мы берем элементы входного массива по очереди слева направо:
1. Число `10`: вычисляется хэш-код, ячейка свободна $\rightarrow$ число `10` добавляется во множество. Успех (`true`).
2. Число `20`: вычисляется хэш-код, ячейка свободна $\rightarrow$ число `20` добавляется во множество. Успех (`true`).
3. Число `10`: вычисляется хэш-код, ячейка занята числом `10` $\rightarrow$ обнаружен дубликат. Элемент **не добавляется**. Метод `Add` возвращает `false`.
4. Число `30`: добавляется во множество. Успех (`true`).
5. Число `40`: добавляется во множество. Успех (`true`).
6. Число `20`: обнаружен дубликат уже существующего числа `20`. Элемент **не добавляется**.
7. Число `50`: добавляется во множество. Успех (`true`).

Итоговый размер множества составит 5 уникальных элементов: `{10, 20, 30, 40, 50}` (порядок может отличаться).

#### Полный код программы на C# (.NET 8):

```csharp
using System;
using System.Collections.Generic;

class Program
{
    static void Main()
    {
        // Шаг 1. Исходный массив чисел с дубликатами
        int[] rawNumbers = { 10, 20, 10, 30, 40, 20, 50 };
        Console.WriteLine("Исходный массив (с дубликатами):");
        Console.WriteLine(string.Join(", ", rawNumbers));
        Console.WriteLine();

        // Шаг 2. Создание пустого множества целых чисел
        HashSet<int> uniqueNumbers = new HashSet<int>();

        // Шаг 3. Поочередное добавление элементов в HashSet с демонстрацией устранения дубликатов
        Console.WriteLine("Процесс добавления элементов во множество:");
        foreach (int number in rawNumbers)
        {
            // Метод Add возвращает true, если элемент добавлен впервые, и false, если он уже был
            bool isAdded = uniqueNumbers.Add(number);

            if (isAdded)
            {
                Console.WriteLine($"  Число {number}: успешно добавлено.");
            }
            else
            {
                Console.WriteLine($"  Число {number}: уже существует во множестве, дубликат отброшен.");
            }
        }
        Console.WriteLine();

        // Шаг 4. Вывод итогового размера множества
        Console.WriteLine($"Итоговый размер множества (количество уникальных элементов): {uniqueNumbers.Count}");

        // Шаг 5. Вывод всех элементов полученного множества
        Console.WriteLine("Элементы результирующего множества HashSet<int>:");
        foreach (int number in uniqueNumbers)
        {
            Console.Write($"{number} ");
        }
        Console.WriteLine();
    }
}
```

#### Пояснение по строкам кода:
- `int[] rawNumbers = { 10, 20, 10, 30, 40, 20, 50 };` — объявление и инициализация обычного массива, содержащего дубликаты.
- `HashSet<int> uniqueNumbers = new HashSet<int>();` — инициализация пустого хэш-множества для целых чисел.
- `foreach (int number in rawNumbers)` — проход по каждому числу из исходного массива.
- `bool isAdded = uniqueNumbers.Add(number);` — ключевая операция проверки: попытка вставить число. Метод одновременно производит поиск и вставку за время $O(1)$.
- `string.Join(", ", rawNumbers)` — встроенный вспомогательный метод для красивого объединения элементов массива через запятую в одну строку.

#### Пример консольного вывода:
```text
Исходный массив (с дубликатами):
10, 20, 10, 30, 40, 20, 50

Процесс добавления элементов во множество:
  Число 10: успешно добавлено.
  Число 20: успешно добавлено.
  Число 10: уже существует во множестве, дубликат отброшен.
  Число 30: успешно добавлено.
  Число 40: успешно добавлено.
  Число 20: уже существует во множестве, дубликат отброшен.
  Число 50: успешно добавлено.

Итоговый размер множества (количество уникальных элементов): 5
Элементы результирующего множества HashSet<int>:
10 20 30 40 50 
```

#### Проверка и оценка сложности:
- **Единицы измерения:** Количество элементов (безразмерная величина), время выполнения в миллисекундах.
- **Правдоподобность:** Из 7 элементов исходного массива 2 элемента (`10` и `20`) встретились повторно. Размер коллекции уменьшился на 2, составив $7 - 2 = 5$ элементов. Все дубликаты успешно отфильтрованы.
- **Временная сложность:** Обход массива из $N$ элементов занимает линейное время $O(N)$. Каждая операция добавления в `HashSet` выполняется в среднем за $O(1)$. Итоговая временная сложность построения множества равна $O(N)$.
- **Пространственная сложность:** $O(U)$, где $U$ — количество уникальных элементов (в худшем случае $U = N$, если все элементы различны).

## Операции над множествами: объединение, пересечение, разность

### Математические операции над множествами и их реализация в C#

Класс `HashSet<T>` в C# реализует не только базовое хранение уникальных элементов, но и предоставляет мощный набор методов для выполнения стандартных математических операций над множествами. Знание этих операций позволяет эффективно решать задачи фильтрации, поиска пересечений и анализа данных без написания громоздких циклов вручную.

Все операции над множествами можно разделить на две группы:
1. **Модифицирующие операции (методы с суффиксом `-With`)**: изменяют текущее множество, над которым вызываются, сохраняя результат прямо в нем. Такие методы работают быстрее, так как не требуют выделения памяти под новые коллекции.
2. **Немодифицирующие операции (методы без суффикса `-With`)**: оставляют исходные множества неизменными и возвращают новую коллекцию с результатами операции.

Для того чтобы уверенно использовать эти методы, рассмотрим каждую операцию математически и программно.

> **Определение.** Пусть заданы два множества $A$ и $B$. Рассмотрим основные операции над ними:
> - **Объединение ($A \cup B$)** — множество, состоящее из элементов, которые принадлежат хотя бы одному из множеств $A$ или $B$.
> - **Пересечение ($A \cap B$)** — множество, состоящее из элементов, которые принадлежат одновременно и множеству $A$, и множеству $B$.
> - **Разность ($A \setminus B$)** — множество, состоящее из элементов множества $A$, которые не принадлежат множеству $B$.
> - **Симметрическая разность ($A \triangle B$)** — множество элементов, которые принадлежат либо множеству $A$, либо множеству $B$, но не одновременно обоим (элементы, входящие ровно в одно из множеств).

### Модифицирующие методы класса HashSet<T>

Эти методы вызываются у экземпляра класса `HashSet<T>` и принимают в качестве аргумента другую коллекцию, реализующую интерфейс `IEnumerable<T>` (например, другой `HashSet<T>` или обычный массив).

1. `UnionWith(otherCollection)` — выполняет объединение текущего множества с коллекцией `otherCollection`. Все элементы из `otherCollection`, которых еще не было в текущем множестве, добавляются в него.
2. `IntersectWith(otherCollection)` — оставляет в текущем множестве только те элементы, которые одновременно присутствуют и в текущем множестве, и в `otherCollection`. Все остальные элементы удаляются.
3. `ExceptWith(otherCollection)` — удаляет из текущего множества все элементы, которые встречаются в `otherCollection`.
4. `SymmetricExceptWith(otherCollection)` — оставляет в текущем множестве только те элементы, которые принадлежат либо только текущему множеству, либо только `otherCollection`, удаляя общие элементы.

---

### Создание новых множеств без изменения исходных

Если требуется сохранить исходные коллекции в неизменном виде (что критически важно в архитектуре многих приложений во избежание побочных эффектов), используются методы, которые создают и возвращают новый `HashSet<T>`:

- `HashSet<T> result = new HashSet<T>(setA); result.UnionWith(setB);` (или с использованием LINQ-подобных методов расширения `setA.Union(setB)`);
- `setA.Intersect(setB)` — возвращает новую коллекцию, содержащую пересечение `setA` и `setB`.
- `setA.Except(setB)` — возвращает новую коллекцию, содержащую разность `setA \ setB`.
- `setA.SymmetricExcept(setB)` — возвращает новую коллекцию, содержащую симметрическую разность.

---

### Проверка отношений между множествами

Помимо построения новых множеств, часто возникает необходимость проверить взаимное расположение и вложенность данных:

- `IsSubsetOf(otherCollection)` — возвращает `true`, если все элементы текущего множества содержатся в `otherCollection`.
- `IsProperSubsetOf(otherCollection)` — возвращает `true`, если текущее множество является строгим (истинным) подмножеством `otherCollection` (то есть все элементы текущего множества есть в `otherCollection`, но при этом `otherCollection` содержит хотя бы один дополнительный элемент).
- `IsSupersetOf(otherCollection)` — возвращает `true`, если текущее множество содержит все элементы `otherCollection` (является надмножеством).
- `IsProperSupersetOf(otherCollection)` — возвращает `true`, если текущее множество является строгим надмножеством `otherCollection`.
- `Overlaps(otherCollection)` — возвращает `true`, если текущее множество и `otherCollection` имеют хотя бы один общий элемент (их пересечение непусто).

---

### Анализ временной сложности операций

Благодаря внутренней структуре `HashSet<T>` (хэш-таблица), операции над множествами выполняются чрезвычайно эффективно:

- Объединение (`UnionWith`) работает за время $O(N + M)$, где $N$ и $M$ — количество элементов в объединяемых множествах, так как каждый элемент из второго множества проверяется и добавляется за константное время в среднем $O(1)$.
- Пересечение (`IntersectWith`) и разность (`ExceptWith`) работают за время $O(N + M)$ или $O(N \cdot M)$ в худшем случае при коллизиях хэш-функций, но в среднем достигают линейной сложности от размера меньшего множества.
- Проверки подмножества (`IsSubsetOf`) и пересечения (`Overlaps`) выполняются за время $O(N)$, где $N$ — размер проверяемой коллекции.

### Разобранный пример: выполнение операций над множествами чисел

#### Условие задачи
Даны два множества целых чисел: $A = \{1, 2, 3, 4, 5\}$ и $B = \{4, 5, 6, 7, 8\}$. Написать программу на C#, которая формирует и выводит на экран: 
1. объединение множеств $A$ и $B$; 
2. пересечение множеств $A$ и $B$; 
3. разность $A \setminus B$. 

Разобрать ход выполнения каждого метода.

#### Рисунок схемы данных (текстовое представление)
```text
Множество A: [ 1 ] [ 2 ] [ 3 ] [ 4 ] [ 5 ]
                                  \     /
Общие элементы (пересечение):    [ 4 ] [ 5 ]
                                  /     \
Множество B:               [ 4 ] [ 5 ] [ 6 ] [ 7 ] [ 8 ]
```

#### Ход рассуждений
1. Инициализируем два объекта `HashSet<int>` значениями из условия. Для заполнения используем синтаксис инициализатора коллекций `{ ... }`.
2. Чтобы не портить исходные множества $A$ и $B$ (ведь нам нужно показать несколько разных операций над одними и теми же исходными данными), для каждой операции создадим независимую копию множества $A$ с помощью конструктора копирования `new HashSet<int>(A)`.
3. Для **объединения** применим метод `UnionWith(B)` к первой копии. В результате в этой копии окажутся элементы $\{1, 2, 3, 4, 5\}$, к которым добавятся уникальные элементы из $B$ (числа 6, 7, 8). Числа 4 и 5 не дублируются, так как свойство множества автоматически отсекает повторяющиеся значения.
4. Для **пересечения** применим метод `IntersectWith(B)` ко второй копии. В этой коллекции останутся только те элементы, которые присутствуют и в исходном $A$, и в $B$ (это элементы 4 и 5). Остальные элементы будут удалены.
5. Для **разности $A \setminus B$** применим метод `ExceptWith(B)` к третьей копии. Из множества $A$ удалятся все элементы, которые также встречаются в $B$ (числа 4 и 5). В итоге останутся только $\{1, 2, 3\}$.

#### Полный компилируемый код программы

```csharp
using System;
using System.Collections.Generic;

class Program
{
    static void Main()
    {
        // Шаг 1. Создание и инициализация исходных множеств A и B
        HashSet<int> setA = new HashSet<int>() { 1, 2, 3, 4, 5 };
        HashSet<int> setB = new HashSet<int>() { 4, 5, 6, 7, 8 };

        Console.WriteLine("Исходное множество A: " + string.Join(", ", setA));
        Console.WriteLine("Исходное множество B: " + string.Join(", ", setB));
        Console.WriteLine(new string('-', 50));

        // Шаг 2. Объединение множеств A и B (A U B)
        // Создаем копию множества A, чтобы не изменять оригинал
        HashSet<int> unionSet = new HashSet<int>(setA);
        unionSet.UnionWith(setB);
        Console.WriteLine("1. Объединение (A U B): " + string.Join(", ", unionSet));

        // Шаг 3. Пересечение множеств A и B (A ∩ B)
        HashSet<int> intersectSet = new HashSet<int>(setA);
        intersectSet.IntersectWith(setB);
        Console.WriteLine("2. Пересечение (A ∩ B): " + string.Join(", ", intersectSet));

        // Шаг 4. Разность множеств A и B (A \ B)
        HashSet<int> exceptSet = new HashSet<int>(setA);
        exceptSet.ExceptWith(setB);
        Console.WriteLine("3. Разность (A \\ B): " + string.Join(", ", exceptSet));
        
        // Дополнительная демонстрация проверки подмножества
        HashSet<int> subset = new HashSet<int>() { 2, 3 };
        bool isSub = subset.IsSubsetOf(setA);
        Console.WriteLine($"Является ли {{2, 3}} подмножеством A? {isSub}");
    }
}
```

#### Пояснение по строкам кода
- `new HashSet<int>() { 1, 2, 3, 4, 5 }` — выделяет память в памяти под хэш-таблицу и последовательно добавляет в нее указанные целочисленные элементы.
- `string.Join(", ", setA)` — вспомогательный метод класса `string`, который объединяет все элементы коллекции `setA` в единую строку через разделитель `", "` для удобного вывода на консоль. Обратите внимание, что порядок вывода элементов хэш-таблицы не гарантируется строго совпадающим с порядком их добавления, так как элементы распределяются по хэш-ведрам.
- `new HashSet<int>(setA)` — конструктор перегрузки, принимающий другую коллекцию. Он создает абсолютно независимую копию элементов, позволяя проводить модификации безопасно для оригинала.
- `unionSet.UnionWith(setB)` — модифицирует текущую коллекцию `unionSet`, внедряя в нее недостающие элементы из `setB`.

#### Пример ввода и вывода программы

**Ввод данных:**
Данные заданы в коде статически (`{1, 2, 3, 4, 5}` и `{4, 5, 6, 7, 8}`).

**Вывод в консоли:**
```text
Исходное множество A: 1, 2, 3, 4, 5
Исходное множество B: 4, 5, 6, 7, 8
--------------------------------------------------
1. Объединение (A U B): 1, 2, 3, 4, 5, 6, 7, 8
2. Пересечение (A ∩ B): 4, 5
3. Разность (A \ B): 1, 2, 3
Является ли {2, 3} подмножеством A? True
```

#### Проверка и оценка
- **Единицы измерения:** В данной задаче работа идет с безразмерными целыми числами (`int`).
- **Правдоподобность:** 
  - Объединение содержит все уникальные элементы из обоих множеств (всего 8 элементов, дубликаты 4 и 5 отброшены).
  - Пересечение содержит только те элементы, которые есть и там, и там ($4$ и $5$).
  - Разность $A \setminus B$ содержит элементы из $A$ без тех, которые встретились в $B$ (удалились $4$ и $5$, остались $1, 2, 3$). Результат математически и программно абсолютно корректен.

## Комбинированные типы данных: структуры (struct) в C#

### Необходимость объединения разнородных данных в одну логическую единицу

До сих пор при решении задач вы использовали простые типы данных: `int` для целых чисел, `double` для вещественных, `bool` для логических значений, `string` для текста. Каждый такой тип хранит ровно одно значение. 

Однако в реальных задачах объекты реального мира редко описываются одним числом или одной строкой. Например, студент характеризуется целым набором характеристик: фамилией (текст), возрастом (целое число), средним баллом (вещественное число). Точка на плоскости описывается двумя координатами $X$ и $Y$. Товар в магазине имеет артикул, название, цену и количество на складе.

Если попытаться хранить информацию о пяти студентах с помощью простых типов, потребуется создать три независимых массива:
* массив фамилий: `string[] names = new string[5];`
* массив возрастов: `int[] ages = new int[5];`
* массив средних баллов: `double[] gpas = new double[5];`

Такой подход крайне неудобен и опасен по следующим причинам:
1. **Связанность данных теряется.** Данные первого студента хранятся под нулевым индексом во всех трех массивах. Если потребуется отсортировать студентов по среднему баллу, программисту придется вручную переставлять элементы во всех трех массивах синхронно, что ведет к ошибкам.
2. **Сложность передачи в методы.** Передавая информацию об одном студенте в функцию вычислений, придется передавать три отдельных параметра вместо одного.

Для решения этой проблемы языки программирования предоставляют **составные (комбинированные) типы данных**. В C# для создания легких пользовательских типов данных, представляющих собой набор связанных по смыслу полей, используется ключевое слово `struct` (структура).

> **Определение.** Структура (`struct`) в C# — это пользовательский тип данных, который инкапсулирует в себе данные (поля) и поведение (методы), являясь при этом типом значения (`value type`).

---

### Синтаксис объявления структуры с помощью ключевого слова `struct`

Объявление структуры внешне похоже на объявление класса, но вместо ключевого слова `class` используется `struct`. Обычно структуры объявляются на уровне пространства имен (вне методов класса программы) или внутри другого класса.

Рассмотрим синтаксис объявления структуры на примере:

```csharp
namespace MyProgram
{
    // Объявление структуры вне метода
    public struct Point
    {
        // Поля структуры
        public int X;
        public int Y;
    }
}
```

Разбор синтаксических элементов:
* `public` — модификатор доступа, разрешающий использование структуры за пределами текущего файла или сборки.
* `struct` — ключевое слово, указывающее компилятору, что создается структура.
* `Point` — имя структуры (по правилам C#, пишется с большой буквы, в PascalCase).
* `int X;` и `int Y;` — поля структуры, хранящие её внутреннее состояние.

---

### Поля и свойства структуры: инкапсуляция внутреннего состояния

Внутри структуры могут находиться переменные, которые называются **полями** (`fields`). Поля хранят состояние объекта. Как правило, поля делают закрытыми (`private`), чтобы защитить данные от некоррректного изменения извне, а для доступа к ним используют **свойства** (`properties`).

> **Определение.** Свойство в C# — это член типа, предоставляющий гибкий механизм для чтения, записи или вычисления значения скрытого поля с помощью блоков `get` и `set`.

Рассмотрим структуру с использованием закрытых полей и открытых свойств:

```csharp
public struct Circle
{
    // Закрытое поле (инкапсуляция)
    private double radius;

    // Свойство для безопасного доступа к радиусу
    public double Radius
    {
        get { return radius; }
        set 
        { 
            // Проверка входных данных: радиус не может быть отрицательным
            if (value < 0)
            {
                radius = 0;
            }
            else
            {
                radius = value;
            }
        }
    }
}
```

В примере выше ключевое слово `value` внутри блока `set` представляет то значение, которое присваивается свойству снаружи. Такой подход реализует принцип **инкапсуляции** — сокрытие внутренней реализации и защита данных с помощью логики проверки.

---

### Конструкторы структур в C#

**Конструктор** — это специальный метод, который вызывается при создании экземпляра структуры и служит для инициализации её полей.

Особенности конструкторов в структурах:
1. **Обязательная инициализация.** К моменту завершения работы любого конструктора структуры **все** её поля должны быть явно проинициализированы. Компилятор выдаст ошибку компиляции, если какое-то поле останется без значения.
2. **Конструктор без параметров.** В языках C# до версии 10 структуры не могли содержать пользовательский конструктор без параметров (компилятор всегда неявно создавал конструктор, обнуляющий все поля: числа в `0`, ссылки в `null`, булевы значения в `false`). Начиная с C# 10 и в .NET 8, разработчик имеет право явно объявить конструктор без параметров и задать в нем собственные значения по умолчанию.

Пример структуры с конструктором:

```csharp
public struct Rectangle
{
    public double Width;
    public double Height;

    // Конструктор с параметрами
    public Rectangle(double width, double height)
    {
        Width = width;
        Height = height;
    }
}
```

---

### Создание экземпляров структуры с оператором `new` и без него

Поскольку структуры являются типами значений, создать переменную типа структуры можно двумя способами:

1. **С использованием оператора `new`:**
   Вызывается конструктор структуры (явный или неявный по умолчанию), который инициализирует поля.
   ```csharp
   Rectangle rect1 = new Rectangle(5.0, 3.0);
   ```

2. **Без использования оператора `new`:**
   Переменная создается в памяти, но её поля остаются **непроинициализированными**. В C# вы не имеете права обратиться к чтению значения любого поля такой структуры до тех пор, пока каждому полю не будет присвоено конкретное значение вручную.
   ```csharp
   Rectangle rect2;
   rect2.Width = 10.0;
   rect2.Height = 4.0; // Только теперь rect2 полностью готов к использованию
   ```

---

### Методы внутри структуры и модификаторы доступа (`public`, `private`)

Структуры в C# могут содержать не только данные, но и функции, описывающие поведение этого типа данных — **методы**.

Модификаторы доступа определяют видимость членов структуры:
* `public` — член доступен отовсюду (из любого метода программы).
* `private` — член доступен только внутри самой структуры.

Добавим метод вычисления площади в структуру `Rectangle`:

```csharp
public struct Rectangle
{
    public double Width;
    public double Height;

    public Rectangle(double width, double height)
    {
        Width = width;
        Height = height;
    }

    // Метод для расчета площади
    public double GetArea()
    {
        return Width * Height;
    }
}
```

### Разобранный пример: структура Point

#### Условие задачи
Создать структуру `Point` для представления точки на плоскости с целочисленными координатами $X$ и $Y$. Добавить конструктор с параметрами, метод для вывода координат в строковом формате и метод вычисления расстояния от начала координат до точки. В программе создать две точки: $P_1(3, 4)$ и $P_2(0, 0)$, вызвать для них созданные методы и вывести результаты.

#### Рисунок словами
Представим декартову систему координат.
* Точка $P_1$ находится на расстоянии 3 единиц вправо по оси $X$ и 4 единиц вверх по оси $Y$. Расстояние от начала координат $(0, 0)$ до $P_1$ вычисляется по теореме Пифагора: $d = \sqrt{3^2 + 4^2} = \sqrt{9 + 16} = \sqrt{25} = 5$.
* Точка $P_2$ совпадает с началом координат $(0, 0)$, расстояние равно 0.

#### Ход рассуждений
1. Объявляем структуру `Point` с полями `int x` и `int y`. Делаем их открытыми для простоты доступа или используем свойства.
2. Пишем конструктор `Point(int x, int y)`, принимающий координаты и записывающий их в поля.
3. Пишем метод `string GetInfo()`, который возвращает строку вида `"(3; 4)"`.
4. Пишем метод `double GetDistanceFromOrigin()`, который вычисляет расстояние по формуле:
   $$d = \sqrt{X^2 + Y^2}$$
   Для извлечения квадратного корня воспользуемся классом `Math.Sqrt()`. Обратите внимание, что результат вычислений нужно привести к типу `double`.
5. В методе `Main` создаем экземпляры точек через оператор `new`, вызываем методы и выводим результаты в консоль.

#### Решение на C# (.NET 8)

```csharp
using System;

namespace PointApp
{
    // Определение структуры Point
    public struct Point
    {
        // Поля структуры
        public int X;
        public int Y;

        // Конструктор с параметрами
        public Point(int x, int y)
        {
            X = x;
            Y = y;
        }

        // Метод для вывода координат в строковом формате
        public string GetInfo()
        {
            return $"({X}; {Y})";
        }

        // Метод вычисления расстояния от начала координат (0,0)
        public double GetDistanceFromOrigin()
        {
            // Формула: sqrt(X^2 + Y^2)
            double sumOfSquares = (X * X) + (Y * Y);
            return Math.Sqrt(sumOfSquares);
        }
    }

    class Program
    {
        static void Main(string[] args)
        {
            // Создание первой точки P1 с координатами (3, 4)
            Point p1 = new Point(3, 4);

            // Создание второй точки P2 с координатами (0, 0)
            Point p2 = new Point(0, 0);

            // Вывод информации о точках и расстояний от начала координат
            Console.WriteLine("Точка 1: " + p1.GetInfo());
            Console.WriteLine("Расстояние P1 от начала координат: " + p1.GetDistanceFromOrigin());

            Console.WriteLine();

            Console.WriteLine("Точка 2: " + p2.GetInfo());
            Console.WriteLine("Расстояние P2 от начала координат: " + p2.GetDistanceFromOrigin());
        }
    }
}
```


2. **Правдоподобность:** Для египетского треугольника со сторонами 3 и 4 гипотенуза равна ровно 5. Программа вывела `5`, расчеты верны. Ошибок округления с целыми числами 3 и 4 при возведении в квадрат и извлечении корня не возникло.

## Семантика значении в struct: отличия от классов, массивы структур и HashSet из структур

### Разница между ссылочными типами (class) и типами значений (struct)

В языке программирования C# все типы данных делятся на две фундаментальные категории: **типы значений** (value types) и **ссылочные типы** (reference types). Понимание различий между ними критически важно для написания эффективного кода, управления памятью и предотвращения трудноуловимых логических ошибок.

> **Определение.** **Тип значения (value type)** — это тип данных, переменная которого непосредственно хранит своё собственное значение. Все числовые типы (`int`, `double`, `decimal`), логический тип (`bool`), символьный тип (`char`), а также пользовательские структуры (`struct`) являются типами значений.
>
> **Определение.** **Ссылочный тип (reference type)** — это тип данных, переменная которого хранит не само значение, а адрес (ссылку) в памяти, где это значение располагается. К ссылочным типам относятся классы (`class`), массивы (`array`), интерфейсы (`interface`) и делегаты (`delegate`).

Главное различие в физическом размещении данных в оперативной памяти заключается в следующем:

1. **Стек (Stack).** Представляет собой область памяти, работающую по принципу LIFO (Last In, First Out — последним вошел, первым вышел). Выделение и освобождение памяти на стеке происходит автоматически и чрезвычайно быстро при входе и выходе из метода. Локальные переменные типов значений и сами экземпляры структур, объявленные внутри методов, размещаются именно на стеке.
2. **Куча (Heap, управляемая куча .NET).** Представляет собой большую динамическую область памяти, выделяемую для объектов ссылочных типов. Когда вы создаете объект класса с помощью оператора `new`, память под поля объекта выделяется в куче, а переменная на стеке получает лишь указатель на этот участок памяти. Управлением памятью в куче занимается **сборщик мусора** (.NET Garbage Collector), который периодически очищает объекты, на которые больше нет активных ссылок.

Для наглядного представления разницы между структурами и классами в памяти рассмотрим схему:

```text
Стек памяти                              Куча памяти (Heap)
+------------------------+               +----------------------------------+
| Переменная класса      | ------------> | Объект класса (Class Instance)   |
| (хранит адрес в куче)  |               | Поля: Name = "Иван", Score = 85  |
+------------------------+               +----------------------------------+
| Переменная структуры   | 
| (хранит ЗНАЧЕНИЕ целиком:| 
|  Name = "Петр",        | 
|  Score = 90)           |
+------------------------+
```

### Копирование при присваивании: передача по значению

Поскольку структуры являются типами значений, семантика их присваивания и передачи в методы кардинально отличается от классов. Когда вы присваиваете переменную одного ссылочного типа другой переменной (`classB = classA`), вы копируете только *ссылку* (адрес). В результате обе переменные начинают указывать на один и тот же объект в куче. Изменение данных через одну переменную немедленно отразится на второй.

Со структурой (`struct`) всё происходит иначе. При присваивании одной переменной структуры другой (`structB = structA`) происходит **полное побайтовое копирование** всех полей структуры. 

Рассмотрим следующий фрагмент кода:

```csharp
using System;

public struct PointStruct
{
    public int X;
    public int Y;

    public PointStruct(int x, int y)
    {
        X = x;
        Y = Y; // Ошибка проектирования? Нет, просто демонстрация
        X = x;
        Y = y;
    }
}

public class Program
{
    public static void Main()
    {
        PointStruct p1 = new PointStruct(10, 20);
        PointStruct p2 = p1; // Создается независимая копия!

        p2.X = 100;

        Console.WriteLine($"p1.X = {p1.X}"); // Выведет 10
        Console.WriteLine($"p2.X = {p2.X}"); // Выведет 100
    }
}
```

В этом примере переменная `p1` и переменная `p2` хранят абсолютно независимые наборы данных в памяти. Изменение поля `X` у структуры `p2` никак не затронуло структуру `p1`. Это свойство гарантирует изоляцию состояния, но имеет обратную сторону: если структура содержит много полей, её копирование при передаче в методы или при присваивании может создавать нагрузку на процессор и память.

### Использование структур в качестве элементов массивов и коллекций HashSet<T>

Структуры можно успешно использовать в составе массивов и универсальных коллекций, таких как `HashSet<T>`. Однако здесь возникают важные нюансы, связанные с внутренним устройством хэш-таблиц.

Коллекция `HashSet<T>` основана на хэш-таблице. Для быстрого поиска, добавления и удаления элементов (со средним временем $O(1)$) коллекция вычисляет хэш-код каждого добавляемого объекта с помощью метода `GetHashCode()`, а для проверки точного равенства элементов использует метод `Equals()`.

По умолчанию для любых типов в C# (если они явно не переопределены) базовый класс `object` предоставляет стандартную реализацию:
- `GetHashCode()` возвращает адрес объекта в памяти или внутренний уникальный идентификатор.
- `Equals()` для ссылочных типов проверяет равенство ссылок (указывают ли переменные на один и тот же объект в куче), а для структур (типов значений) производит **побытовое сравнение всех полей**.

Хотя стандартная реализация `Equals` для структур сравнивает поля, компилятор C# для структур генерирует ее автоматически через механизм отражения (reflection), который работает относительно медленно. Более того, стандартный `GetHashCode` для структур может работать неоптимально.

Рассмотрим ключевую проблему при использовании пользовательских структур в `HashSet<T>`. Если вы создали структуру, добавили её экземпляр в множество, а затем изменили значение какого-либо поля этой структуры (если структура мутабельна), её хэш-код изменится. В результате хэш-таблица «потеряет» элемент: он останется в том же бакете хэш-таблицы, куда был помещен изначально, но метод `Contains` будет искать его уже в другом бакете, соответствующем новому хэш-коду. Это приводит к нарушению целостности коллекции.

### Требования к переопределению методов Equals и GetHashCode

Чтобы пользовательская структура корректно и эффективно работала внутри коллекций `HashSet<T>`, её необходимо проектировать правильно. Рекомендуется делать структуры **немутабельными** (immutable) — то есть такими, поля которых нельзя изменить после создания (например, сделать их доступными только для чтения через модификатор `readonly` или объявив свойства с `ակետ` `init` / `get`).

Кроме того, строго обязательно переопределение трех членов базового класса:
1. `Equals(object obj)` — для сравнения текущей структуры с другим объектом по значению полей.
2. `GetHashCode()` — для вычисления целочисленного хэш-кода на основе неизменяемых полей.
3. Операторов `==` и `!=` (опционально, но крайне рекомендуется для удобства работы со структурами).

### Разобранный пример: массив студентов и HashSet<Student>

Давайте решим комплексную задачу, которая наглядно демонстрирует все описанные аспекты: создание структуры, особенности её сравнения, работу с массивами и коллекциями `HashSet<T>`, а также устранение проблем с дублированием данных.

#### Условие задачи

Имеется структура `Student`, содержащая поля: `Name` (тип `string`) и `Score` (тип `int`). Необходимо создать массив из 3 студентов (предусмотреть наличие одинаковых студентов с точки зрения их логического содержимого — одинаковые имя и балл) и попытаться поместить их в `HashSet<Student>`. 

Требуется:
1. Продемонстрировать, почему без явного переопределения методов `Equals` и `GetHashCode` коллекция `HashSet<Student>` посчитает студентов с одинаковыми именами и баллами **разными** элементами (если они созданы как разные экземпляры в памяти).
2. Написать полную программу на C#, в которой структура `Student` корректно реализует интерфейс сравнения и переопределяет системные методы, обеспечивая строгое уникальное добавление элементов в `HashSet<Student>` по значению их полей.

#### Ход рассуждений и проектирование решения

1. **Проблема стандартного поведения:** Структуры в C# по умолчанию реализуют интерфейс `ValueType`, который переопределяет метод `Equals` путем сравнения полей через медленное отражение (reflection). Однако метод `GetHashCode` для структур реализован неэффективно и может возвращать одинаковые хэши для разных объектов или разные хэши для логически одинаковых структур в зависимости от версии .NET и выравнивания памяти. Если мы не переопределим `Equals` и `GetHashCode` вручную, две разные переменные структуры, содержащие одинаковые строки ("Анна", 90), могут быть размещены компилятором так, что хэш-таблица `HashSet<T>` воспримет их как уникальные элементы. Более того, если структура не является `readonly`, её случайное изменение приведет к потере данных в хэш-сетях.
2. **Проектирование структуры `Student`:** Сделаем структуру `readonly struct` (все поля объявляются как `readonly`), что гарантирует неизменяемость её состояния после создания. Переопределим метод `GetHashCode()`, используя комбинирование хэш-кодов полей (например, через оператор XOR `^` или умножение на простое число), и метод `Equals(object obj)`, выполняющий строгую проверку типов и полей.

#### Полный исходный код программы

```csharp
using System;
using System.Collections.Generic;

// Объявляем неизменяемую структуру (readonly struct)
public readonly struct Student : IEquatable<Student>
{
    public string Name { get; }
    public int Score { get; }

    // Конструктор инициализации полей
    public Student(string name, int score)
    {
        Name = name ?? throw new ArgumentNullException(nameof(name));
        Score = score;
    }

    // Переопределение метода Equals для сравнения по значению полей
    public override bool Equals(object obj)
    {
        if (obj is Student other)
        {
            return Name == other.Name && Score == other.Score;
        }
        return false;
    }

    // Реализация интерфейсного метода IEquatable<T> для повышения производительности
    public bool Equals(Student other)
    {
        return Name == other.Name && Score == other.Score;
    }

    // Переопределение GetHashCode на основе содержимого полей структуры
    public override int GetHashCode()
    {
        // Используем стандартный метод HashCode.Combine, доступный в .NET Core / .NET 8
        return HashCode.Combine(Name, Score);
    }

    // Переопределение оператора равенства ==
    public static bool operator ==(Student left, Student right)
    {
        return left.Equals(right);
    }

    // Переопределение оператора неравенства !=
    public static bool operator !=(Student left, Student right)
    {
        return !left.Equals(right);
    }

    // Удобный метод для вывода информации о студенте
    public override string ToString()
    {
        return $"Студент: {Name}, Балл: {Score}";
    }
}

public class Program
{
    public static void Main()
    {
        // Исходные данные: создаем массив из 3 студентов.
        // Обратите внимание: элементы 0 и 2 имеют абсолютно одинаковые поля ("Иван", 85), 
        // но являются разными экземплярами в памяти (разные переменные в массиве).
        Student[] studentsArray = new Student[]
        {
            new Student("Иван", 85),
            new Student("Мария", 92),
            new Student("Иван", 85) // Дубликат по значению
        };

        Console.WriteLine("Содержимое исходного массива:");
        for (int i = 0; i < studentsArray.Length; i++)
        {
            Console.WriteLine($"[{i}] {studentsArray[i]}");
        }

        // Помещаем элементы массива в HashSet<Student>
        HashSet<Student> uniqueStudents = new HashSet<Student>();

        foreach (var student in studentsArray)
        {
            bool isAdded = uniqueStudents.Add(student);
            Console.WriteLine($"Попытка добавить ({student.Name}, {student.Score}): результат добавления = {isAdded}");
        }

        Console.WriteLine("\nИтоговое содержимое коллекции HashSet<Student> (после фильтрации дубликатов):");
        foreach (var student in uniqueStudents)
        {
            Console.WriteLine(student);
        }

        // Проверка общего количества уникальных элементов
        Console.WriteLine($"\nВсего уникальных студентов в множестве: {uniqueStudents.Count}");
    }
}
```

#### Пояснение по строкам и блокам кода

1. `public readonly struct Student : IEquatable<Student>` — объявление структуры как неизменяемой (`readonly`). Ключевое слово гарантирует, что после вызова конструктора изменить значения полей `Name` и `Score` извне или изнутри методов структуры будет невозможно. Реализация интерфейса `IEquatable<Student>` позволяет методам коллекций (.NET) выполнять сравнение типов без упаковки (boxing), что критически важно для производительности.
2. `public override int GetHashCode()` — вызывает оптимизированный системный метод `HashCode.Combine(Name, Score)`, который объединяет хэш-коды строки `Name` и целого числа `Score`. Без этого метода хэш-таблица не смогла бы быстро находить бакеты для хранения элементов.
3. `uniqueStudents.Add(student)` — метод коллекции `HashSet<T>` возвращает булево значение (`true`, если элемент успешно добавлен, и `false`, если такой элемент уже присутствовал в множестве). Благодаря корректно переопределенным методам `Equals` и `GetHashCode`, второй студент с именем "Иван" и баллом 85 будет корректно распознан как дубликат и отброшен, несмотря на то, что это отдельный объект в массиве.

**Ввод (задан программно в массиве `studentsArray`):**
- Студент 1: Имя = "Иван", Балл = 85
- Студент 2: Имя = "Мария", Балл = 92
- Студент 3: Имя = "Иван", Балл = 85

### Проверка корректности и правдоподобие результатов

1. **Единицы и типы:** Использованы стандартные типы C# (`string`, `int`), возвращаемые типы методов соответствуют сигнатурам `bool` и `int`. Ошибки компиляции отсутствуют.
2. **Правдоподобие:** Массив содержал 3 элемента, из которых два были идентичными по смыслу. Метод `Add` для третьего элемента вернул `false`, что доказывает успешную работу хэш-таблицы по устранению дубликатов. Итоговое количество элементов в `HashSet` равно 2, что полностью соответствует математическому понятию множества уникальных элементов.

### Критерии выбора между struct и class

При проектировании архитектуры программы на C# разработчик постоянно сталкивается с дилеммой: объявить новый тип как `struct` или как `class`. Руководствуйтесь следующими четкими правилами:

| Критерий | Выбирайте структуру (`struct`) | Выбирайте класс (`class`) |
|---|---|---|
| **Семантика данных** | Логически представляет небольшое единичное значение (число, координата, пара, цвет, дата). | Представляет сущность с уникальным жизненным циклом и поведением (пользователь, документ, банк, окно). |
| **Размер в памяти** | Маленький размер (обычно менее 16–24 байт полей). | Большой размер или переменный объем данных. |
| **Мутабельность** | Предпочтительно делать неизменяемыми (`readonly struct`). | Может быть изменяемым (mutable) в процессе работы программы. |
| **Передача** | Копируется при присваивании и передаче (по значению). | Передается по ссылке, изменения видны всем держателям ссылки. |
| **Наследование** | Не может наследоваться от других классов или структур (но может реализовывать интерфейсы). | Поддерживает полноценное объектно-ориентированное наследование и полиморфизм. |
| **Упаковка (Boxing)** | Избегайте частой передачи в методы, принимающие `object`, чтобы не порождать упаковку в куче. | Естественным образом хранится в куче без риска упаковки. |

Соблюдение этих критериев позволяет писать производительный код на C# в среде .NET 8, эффективно используя как быстрый стек памяти для структур, так и гибкую кучу для сложных объектных иерархий.

## Практикум: комплексная задача с использованием HashSet и структур

### Постановка комплексной задачи и проектирование структуры данных

На предыдущих этапах изучения темы мы познакомились с коллекцией уникальных элементов `HashSet<T>` и пользовательскими типами данных на основе структур (`struct`). Теперь применим полученные знания на практике для решения прикладной задачи средней сложности. 

Представим себе задачу разработки подсистемы учета библиотечного фонда. В системе поступает поток записей о книгах. Каждая запись содержит международный стандартный книжный номер (ISBN), название книги и год издания. Проблема реальных данных заключается в том, что при массовом вводе или импорте из внешних источников неизбежно возникают дубликаты. Книги с одинаковым ISBN должны рассматриваться как один и тот же объект вне зависимости от регистра букв в названии или порядка поступления. Кроме того, перед администратором библиотеки должна выводиться итоговая ведомость уникальных изданий, упорядоченных по хронологическому признаку (по году издания).

Для реализации этой задачи необходимо спроектировать подходящий тип данных. Поскольку каждая книга обладает небольшим набором неизменяемых полей (`ISBN`, `Title`, `Year`), логично выбрать тип значения — `struct`. Однако, как мы выяснили ранее, для корректной работы пользовательских структур внутри хэш-таблиц (`HashSet<T>`) и предотвращения дублирования по уникальному ключу (ISBN), структура должна реализовывать интерфейс `IEquatable<T>`, а также переопределять методы `GetHashCode()` и `Equals()`. В противном случае `HashSet` будет сравнивать экземпляры побитово, и две разные записи с одинаковым ISBN попадут в коллекцию как уникальные, чего допустить нельзя.

### Проектирование структуры Book с поддержкой уникальности

Определим требования к структуре `Book`:
1. Поля: `string Isbn`, `string Title`, `int Year`. Все поля сделаем доступными только для чтения (`init`-only или `readonly`), чтобы обеспечить неизменяемость объекта после создания.
2. Конструктор: принимает все три параметра и выполняет базовую валидацию (например, проверка ISBN на пустую строку).
3. Уникальность: две книги считаются эквивалентными тогда и только тогда, когда совпадают их `Isbn`. Сравнение строк сделаем регистронезависимым, так как ISBN может быть введен в разных форматах.
4. Хэш-код: должен вычисляться исключительно на основе поля `Isbn`.

Запишем требования в виде кода структуры на C#:

```csharp
using System;
using System.Collections.Generic;

public readonly struct Book : IEquatable<Book>
{
    public string Isbn { get; }
    public string Title { get; }
    public int Year { get; }

    public Book(string isbn, string title, int year)
    {
        if (string.IsNullOrWhiteSpace(isbn))
        {
            throw new ArgumentException("ISBN не может быть пустым.", nameof(isbn));
        }

        Isbn = isbn.Trim();
        Title = string.IsNullOrWhiteSpace(title) ? "Без названия" : title.Trim();
        Year = year;
    }

    // Реализация интерфейса IEquatable<T>
    public bool Equals(Book other)
    {
        // Сравнение ISBN без учета регистра
        return string.Equals(Isbn, other.Isbn, StringComparison.OrdinalIgnoreCase);
    }

    public override bool Equals(object obj)
    {
        return obj is Book other && Equals(other);
    }

    public override int GetHashCode()
    {
        // Генерация хэш-кода на основе нормализованного ISBN
        return StringComparer.OrdinalIgnoreCase.GetHashCode(Isbn);
    }

    public override string ToString()
    {
        return $"ISBN: {Isbn}, Название: \"{Title}\", Год: {Year}";
    }
}
```

Разбор ключевых элементов реализации структуры `Book`:
- Модификатор `readonly struct` гарантирует, что структура является неизменяемой (immutable), что повышает безопасность кода и оптимизирует работу компилятора.
- Метод `StringComparer.OrdinalIgnoreCase.GetHashCode(Isbn)` обеспечивает одинаковый хэш-код для строк `978-5-03-012345-6` и `978-5-03-012345-6` (даже при разном регистре букв, если в ISBN присутствуют символы серий).
- Переопределение `Equals` гарантирует, что методы удаления и поиска в `HashSet<Book>` будут опираться на логическое равенство по ISBN, а не на ссылочное или побитовое сравнение полей.

### Разработка полной программы учета книг

Теперь напишем полный исполняемый модуль, который имитирует ввод данных пользователем (или чтение из предопределенного источника для демонстрации), фильтрует дубликаты через `HashSet<Book>`, сортирует полученный результат и выводит его на консоль.

```csharp
using System;
using System.Collections.Generic;
using System.Linq;

class Program
{
    static void Main()
    {
        // Установка кодировки консоли для корректного отображения кириллицы
        Console.OutputEncoding = System.Text.Encoding.UTF8;

        // Создаем коллекцию HashSet для хранения уникальных книг
        HashSet<Book> libraryCatalog = new HashSet<Book>();

        // Имитируем ввод данных пользователем. 
        // Обратите внимание на дубликаты по ISBN: 
        // 1. Первая книга: 978-5-17-123456-1 ("Программирование на C#", 2022)
        // 2. Четвертая книга имеет тот же ISBN: 978-5-17-123456-1, но другое название и год. 
        // Согласно нашей бизнес-логике, это дубликат, который должен быть отброшен (или перезаписан первым).
        
        List<Book> inputList = new List<Book>
        {
            new Book("978-5-17-123456-1", "Программирование на C#", 2022),
            new Book("978-5-699-23456-2", "Алгоритмы и структуры данных", 2020),
            new Book("978-5-9706-0000-3", "Чистый код", 2019),
            new Book("978-5-17-123456-1", "Программирование на C#. Углубленный курс", 2023), // Дубликат ISBN!
            new Book("978-5-4461-1111-4", "Искусство программирования", 2018)
        };

        Console.WriteLine("=== Процесс добавления книг в каталог ===");
        foreach (var book in inputList)
        {
            bool added = libraryCatalog.Add(book);
            if (added)
            {
                Console.WriteLine($"Успешно добавлено: {book}");
            }
            else
            {
                Console.WriteLine($"Дубликат отклонен: {book.Isbn} ({book.Title})");
            }
        }

        Console.WriteLine($"\nВсего уникальных книг в каталоге: {libraryCatalog.Count}");

        // Выполняем сортировку уникальных книг по году издания.
        // Поскольку HashSet<T> не гарантирует порядок, преобразуем его в список с помощью LINQ (OrderBy).
        var sortedCatalog = libraryCatalog.OrderBy(b => b.Year).ThenBy(b => b.Title).ToList();

        Console.WriteLine("\n=== Итоговый каталог уникальных книг (отсортирован по году) ===");
        int position = 1;
        foreach (var book in sortedCatalog)
        {
            Console.WriteLine($"{position}. {book}");
            position++;
        }
    }
}
```

### Анализ сложности и граничные случаи

Для закрепления материала оценим эффективность разработанного решения с точки зрения ресурсов вычислительной системы.

1. **Временная сложность:**
   - Добавление одного элемента в `HashSet<Book>` в среднем требует $O(1)$ операций, так как поиск по хэш-таблице выполняется мгновенно. Для $N$ элементов общая сложность заполнения множества составляет $O(N)$ в среднем случае (и $O(N^2)$ в худшем при возникновении множественных коллизий хэш-функции, что на практике для нормализованных ISBN практически исключено).
   - Последующая сортировка полученного множества через LINQ-метод `OrderBy` требует $O(N \log N)$ времени, где $N$ — количество уникальных элементов.

2. **Пространственная сложность:**
   - Память расходуется на хранение исходного списка входных данных ($O(N)$), хэш-таблицы `HashSet` ($O(N)$) и результирующего отсортированного списка ($O(N)$). Использование структур (`struct`) вместо ссылочных типов (`class`) в данном случае снижает нагрузку на сборщик мусора, так как объекты размещаются компактно, однако при передаче в методы или копировании структуры дублируются в памяти (что для небольшого набора полей некритично).

3. **Обработка граничных случаев:**
   - *Пустой ввод или некорректные данные:* конструктор структуры `Book` содержит защитную проверку (`throw new ArgumentException`), предотвращающую создание объектов с пустыми или состоящими только из пробелов ISBN.
   - *Регистронезависимость:* благодаря использованию `StringComparer.OrdinalIgnoreCase` в методах `GetHashCode` и `Equals`, система успешно распознает дубликаты даже в том случае, если пользователь введет буквы в разном регистре (например, `ISBN-123` и `isbn-123`).
   - *Множественные дубликаты:* метод `HashSet<T>.Add()` возвращает булево значение `false`, если элемент уже присутствует в коллекции. Это позволяет программе точно фиксировать факт отклонения дубликата и информировать пользователя.

## Типичные ошибки

1. **Изменение полей структуры, добавленной в `HashSet<T>` (мутабельные структуры)**
   * **В чём ошибка:** Если структура не является `readonly`, и после вызова `set.Add(item)` вы измените значение какого-либо поля объекта `item` (например, `item.Year = 2024`), хэш-код объекта изменится. Хэш-таблица продолжит искать элемент в старом бакете, из-за чего метод `Contains` начнет возвращать `false`, и элемент окажется «потерян» внутри коллекции.
   * **Как избежать:** Проектируйте пользовательские структуры неизменяемыми (`readonly struct`), делая поля доступными только для чтения (`init` или `readonly`).
   * **Мини-пример:** `readonly struct Point { public int X { get; } ... }` вместо обычной мутабельной структуры.

2. **Забыли переопределить `GetHashCode()` при переопределении `Equals()`**
   * **В чём ошибка:** Контракт .NET требует, чтобы для любых двух равных объектов (когда `Equals` возвращает `true`) обязательно возвращался абсолютно одинаковый хэш-код (`GetHashCode`). Если переопределить только `Equals`, `HashSet<T>` не сможет корректно распределить объекты по бакетам, и одинаковые элементы будут добавлены в коллекцию несколько раз, нарушив её уникальность.
   * **Как избежать:** Всегда переопределяйте оба метода одновременно. Используйте `HashCode.Combine(field1, field2)` для генерации хэша.

3. **Модификация коллекции `HashSet<T>` во время обхода в цикле `foreach`**
   * **В чём ошибка:** Попытка вызвать метод `Add` или `Remove` внутри цикла `foreach (var item in mySet)` приводит к генерации исключения времени выполнения `InvalidOperationException` (коллекция была изменена во время перечисления).
   * **Как избежать:** Сохраняйте элементы, подлежащие удалению, во временный список (`List<T>`), а затем выполняйте удаление после завершения цикла `foreach`.
   * **Мини-пример:**
     ```csharp
     List<int> toRemove = new List<int>();
     foreach (var x in mySet) { if (x < 0) toRemove.Add(x); }
     foreach (var x in toRemove) { mySet.Remove(x); }
     ```

4. **Ожидание строгого порядка элементов в `HashSet<T>`**
   * **В чём ошибка:** Программист рассчитывает, что элементы в множестве будут храниться в том же порядке, в котором их добавляли (как в обычном массиве или списке).
   * **Как избежать:** Помнить, что `HashSet<T>` — это хэш-таблица. Порядок элементов определяется их хэш-кодами и внутренним размером буфера, поэтому он является произвольным и может меняться при добавлении новых элементов.

5. **Использование оператора `new` для структуры с ожиданием автоматического обнуления всех полей в старых версиях C#, либо обращение к полям структуры без `new` до их инициализации**
   * **В чём ошибка:** В C# запрещено читать значения полей структуры, созданной без ключевого слова `new`, пока каждому полю не будет присвоено значение вручную. Компилятор выдаст ошибку `Use of unassigned local variable`.
   * **Как избежать:** Всегда инициализируйте поля структуры либо через конструктор с ключевым словом `new`, либо присваивая значение каждому полю перед его первым чтением.

6. **Путаница между ссылочной семантикой классов и семантикой значений структур при присваивании**
   * **В чём ошибка:** Программист меняет поле у копии структуры `structB = structA; structB.X = 5;` и ожидает, что в `structA` поле `X` тоже изменится (по аналогии с классами).
   * **Как избежать:** Помнить, что структуры — это типы значений. При присваивании и передаче в методы происходит полное побайтовое копирование данных; переменные полностью независимы.

7. **Некорректная реализация сравнения строк или чисел в методе `Equals`**
   * **В чём ошибка:** Сравнение строк через оператор `==` с учетом регистра там, где требуется регистронезависимость (например, при сравнении ISBN или адресов электронной почты).
   * **Как избежать:** Использовать метод `string.Equals(a, b, StringComparison.OrdinalIgnoreCase)` для корректного сравнения текстовых полей структуры.

1. **Устранение дубликатов в логах доступа:** Дан массив строк, представляющий IP-адреса пользователей, заходивших на сервер за день: `{"192.168.1.10", "10.0.0.5", "192.168.1.10", "172.16.0.2", "10.0.0.5", "192.168.1.15"}`.

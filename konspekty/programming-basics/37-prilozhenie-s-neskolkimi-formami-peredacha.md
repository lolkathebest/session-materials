## Архитектура многооконного приложения и жизненный цикл формы

### Архитектура многооконного приложения и жизненный цикл формы

До сих пор при разработке приложений на платформе .NET с использованием Windows Forms мы ограничивались созданием однооконных программ, в которых вся логика интерфейса размещалась в пределах единственного класса формы, генерируемого средой разработки по умолчанию (обычно `Form1`). Однако реальные программные продукты — текстовые редакторы, файловые менеджеры, специализированные информационные системы — состоят из множества взаимодействующих окон: главных панелей, диалогов настройки, окон авторизации, справочников и мастеров быстрой настройки. 

Для понимания того, как строится многооконное приложение, необходимо глубоко усвоить природу класса `Form`, концепцию объектной модели графического интерфейса и жизненный цикл каждого отдельного окна в оперативной памяти компьютера.

---

### Понятие формы и её объектная модель в .NET

В объектно-ориентированном программировании на языке C# любое окно графического интерфейса пользователя в Windows Forms представляет собой экземпляр класса `Form` (или класса-наследника, созданного разработчиком). 

> **Определение.** Класс `Form` — это базовый класс в пространстве имен `System.Windows.Forms`, который инкапсулирует в себе окно операционной системы Windows, управляет его стилями, системной рамкой, заголовком, буфером отрисовки, а также служит контейнером для размещения других визуальных компонентов (кнопок, текстовых полей, меток и т.д.).

С точки зрения архитектуры .NET, каждый визуальный элемент управления и сама форма являются объектами, размещаемыми в управляемой куче (Heap). Когда вы создаете проект в Visual Studio, среда автоматически генерирует класс главной формы, наследующий функциональность базового `Form`:

```csharp
public partial class MainForm : Form
{
    public MainForm()
    {
        InitializeComponent();
    }
}
```

Модификатор `partial` означает, что определение одного и того же класса разделено между несколькими файлами исходного кода. Традиционно один файл (`MainForm.cs`) содержит вашу пользовательскую бизнес-логику и обработчики событий, а второй файл (`MainForm.Designer.cs`) автоматически поддерживается средой разработки Visual Studio и содержит код создания элементов управления, задания их координат, размеров и начальных свойств.

### Создание второй формы в проекте

Чтобы добавить в существующий проект новое окно, необходимо выполнить следующие шаги в среде разработки Visual Studio:

1. В окне **Solution Explorer** (Обозреватель решений) нажмите правой кнопкой мыши по названию вашего проекта.
2. В появившемся контекстном меню выберите пункт **Add** (Добавить), а затем **New Item...** (Создать элемент...).
3. В открывшемся диалоговом окне выберите шаблон **Windows Form (Windows Forms)**.
4. В поле **Name** (Имя) введите осмысленное имя класса будущей формы, например `SecondaryForm.cs`, и нажмите кнопку **Add**.

После этого среда разработки создаст два новых файла: `SecondaryForm.cs` (для вашего кода) и `SecondaryForm.Designer.cs` (для сгенерированного дизайнером кода интерфейса), а также добавит в проект класс следующего вида:

```csharp
using System;
using System.Windows.Forms;

namespace MultiWindowApp
{
    public partial class SecondaryForm : Form
    {
        public SecondaryForm()
        {
            InitializeComponent();
        }
    }
}
```

Созданный класс `SecondaryForm` является полноценным шаблоном (чертежом). Чтобы на экране появилось конкретное окно, в оперативной памяти необходимо создать экземпляр этого класса с помощью оператора `new`.

### Жизненный цикл формы

Каждая форма в Windows Forms проходит строго определенный жизненный цикл, состоящий из нескольких этапов: инициализация, отображение, работа (активное состояние), сокрытие и уничтожение (освобождение ресурсов).

Разберем каждый этап подробно:

1. **Инициализация:**
   Когда вы пишете `SecondaryForm form2 = new SecondaryForm();`, вызывается конструктор класса. Внутри конструктора обязательно вызывается метод `InitializeComponent()`. Именно в этот момент выделяется память под все элементы управления, размещенные вами на форме в визуальном дизайнере, устанавливаются их свойства по умолчанию. Важно помнить: *на этапе выполнения конструктора форма еще не отображается на экране*, а её дескриптор окна (`Handle`) в операционной системе еще не создан. Попытка обратится к графическим свойствам или дочерним элементам до вызова `InitializeComponent()` приведет к аппаратной ошибке или непредсказуемому поведению.

2. **Отображение и событие `Load`:**
   Перед тем как окно станет видимым для пользователя, генерируется системное событие `Load`. Это идеальное место в коде для инициализации данных, загрузки файлов конфигурации или заполнения списков элементов управления, так как к моменту срабатывания `Load` дескриптор окна уже сформирован.

3. **Активное состояние:**
   Окно обрабатывает сообщения операционной системы, реагирует на клики мыши, нажатия клавиш и действия пользователя.

4. **Закрытие и сокрытие:**
   Когда пользователь нажимает крестик в правом верхнем углу окна или вызывается программный метод `Close()`, форма начинает процесс закрытия. При этом генерируется событие `FormClosing` (на этом этапе можно отменить закрытие, например, если пользователь не сохранил данные), а затем событие `FormClosed`.

5. **Уничтожение (метод `Dispose`):**
   Форма наследует интерфейс `IDisposable`. Когда окно окончательно закрывается, вызывается метод `Dispose()`, который освобождает все системные дескрипторы и неуправляемые ресурсы, занятые элементами управления.

#### Разница между `Close()` и `Application.Exit()`

Начинающие разработчики часто путают завершение работы отдельного окна с завершением работы всей программы целиком:

* Метод `Close()` закрывает *только ту форму, у которой он был вызван*. Если закрывается главная форма приложения (самая первая форма, с которой стартовала программа), то по умолчанию приложение завершает свою работу. Если закрывается дочерняя форма, главная форма продолжает функционировать.
* Метод `Application.Exit()` принудительно останавливает работу всего приложения целиком, закрывая все открытые формы независимо от того, какая из них была главной, и завершая поток сообщений ОС. Использовать `Application.Exit()` следует с осторожностью, предпочитая ему закрытие главной формы.

### Предотвращение повторного открытия немодальных окон

Когда мы работаем с немодальными окнами (которые открываются методом `Show()`), возникает специфическая архитектурная проблема: пользователь может случайно кликнуть по кнопке открытия дочернего окна несколько раз подряд, в результате чего в памяти создастся и отобразится на экране множество одинаковых окон поверх друг друга. Это приводит к перерасходу оперативной памяти и путанице в интерфейсе.

Для предотвращения этого эффекта необходимо хранить ссылку на открытую форму в поле класса и перед открытием проверять, существует ли уже это окно и не было ли оно уничтожено.

### Разобранные примеры

#### Пример 1: Создание второй формы и управление её экземпляром

В данном примере мы разработаем фрагмент главной формы `MainForm`, которая содержит кнопку «Открыть справку». При нажатии на кнопку создается экземпляр второй формы `SecondaryForm` и выводится на экран. При этом реализуется защита от повторного открытия окна.

**Ход рассуждений:**
1. Нам нужно объявить приватное поле класса `MainForm` для хранения ссылки на вторую форму. Тип поля — `SecondaryForm`. Назовем его `_secondForm`.
2. В обработчике нажатия кнопки проверяем: если ссылка `_secondForm` равна `null` ИЛИ свойство `IsDisposed` равно `true` (это означает, что пользователь закрыл окно крестиком, и объект в памяти был уничтожен), то мы создаем новый экземпляр через `new`.
3. Вызываем метод `Show()`, чтобы открыть окно в немодальном режиме.
4. Вызываем метод `BringToFront()`, чтобы при наличии уже открытого окна оно просто перешло на передний план, не создавая дубликатов.

**Решение:**

```csharp
using System;
using System.Windows.Forms;

namespace MultiWindowApp
{
    public partial class MainForm : Form
    {
        // Поле для хранения ссылки на дочернюю форму
        private SecondaryForm _secondForm = null;

        public MainForm()
        {
            InitializeComponent();
        }

        private void btnOpenHelp_Click(object sender, EventArgs e)
        {
            // Проверяем, создана ли форма и не была ли она уничтожена ранее
            if (_secondForm == null || _secondForm.IsDisposed)
            {
                // Создаем новый экземпляр, если окно еще не открыто
                _secondForm = new SecondaryForm();
                
                // Подписываемся на событие закрытия, чтобы обнулить ссылку (дополнительная надежность)
                _secondForm.FormClosed += (s, args) => { _secondForm = null; };
                
                // Отображаем окно в немодальном режиме
                _secondForm.Show();
            }
            else
            {
                // Если окно уже существует, просто переносим его на передний план
                _secondForm.BringToFront();
            }
        }
    }
}
```

**Проверка и правдоподобность:**
* Единицы измерения: отсутствуют (логика управления объектами).
* Правдоподобность: использование свойства `IsDisposed` является стандартным паттерном в Windows Forms, так как при закрытии формы методом `Close()` объект удаляется из памяти, но локальная переменная (ссылка) продолжает указывать на «пустой» участок памяти (так называемый *disposed object*). Проверка `IsDisposed` защищает от исключения `ObjectDisposedException`.

#### Пример 2: Корректная обработка жизненного цикла формы и высвобождение ресурсов

Представим, что дочерняя форма `SecondaryForm` при своем открытии выделяет тяжелые ресурсы: открывает соединение с локальной базой данных SQLite или запускает таймер с высокой частотой опроса датчиков. Нам необходимо корректно перехватить момент закрытия формы, остановить фоновые процессы и убедиться, что ресурсы не утекают в оперативной памяти.

**Ход рассуждений:**
1. Переопределяем виртуальный метод `OnFormClosing` в классе `SecondaryForm`. Этот метод вызывается автоматически инфраструктурой Windows Forms перед тем, как окно закроется.
2. Внутри метода запрашиваем подтверждение у пользователя (например, если он ввел несохраненные данные).
3. Останавливаем все запущенные фоновые таймеры и потоки.
4. Вызываем базовую реализацию `base.OnFormClosing(e)`, чтобы стандартный механизм закрытия окна продолжил работу.

**Решение:**

```csharp
using System;
using System.Windows.Forms;

namespace MultiWindowApp
{
    public partial class SecondaryForm : Form
    {
        private Timer _workTimer;

        public SecondaryForm()
        {
            InitializeComponent();
            
            // Инициализация внутреннего ресурса (таймера)
            _workTimer = new Timer();
            _workTimer.Interval = 1000; // 1 секунда
            _workTimer.Tick += WorkTimer_Tick;
            _workTimer.Start();
        }

        private void WorkTimer_Tick(object sender, EventArgs e)
        {
            // Фоновое действие, выполняемое дочерней формой
            Console.WriteLine("Фоновый процесс дочерней формы активен...");
        }

        // Переопределение метода жизненного цикла закрытия формы
        protected override void OnFormClosing(FormClosingEventArgs e)
        {
            // Пример условия: если есть несохраненные данные, спрашиваем пользователя
            DialogResult result = MessageBox.Show(
                "Закрыть окно? Все несохраненные данные будут потеряны.",
                "Подтверждение",
                MessageBoxButtons.YesNo,
                MessageBoxIcon.Warning);

            if (result == DialogResult.No)
            {
                // Отменяем закрытие формы
                e.Cancel = true;
                return; // Прерываем выход из метода
            }

            // Корректная очистка ресурсов перед закрытием
            if (_workTimer != null)
            {
                _workTimer.Stop();
                _workTimer.Dispose();
                _workTimer = null;
            }

            // Обязательный вызов базового метода для завершения закрытия
            base.OnFormClosing(e);
        }
    }
}
```

**Проверка и правдоподобность:**
* Использование свойства `e.Cancel = true` класса `FormClosingEventArgs` позволяет полностью контролировать поведение окна и прерывать процесс закрытия в случае необходимости.
* Явная остановка и вызов метода `Dispose()` для таймера `_workTimer` предотвращает утечки памяти (*memory leaks*), которые возникают, если таймер продолжает удерживать ссылку на уничтожаемый объект формы в куче .NET.

## Модальный и немодальный режимы отображения окон

### Модальный и немодальный режимы отображения окон

При создании многооконных приложений на платформе .NET 8 с использованием библиотеки Windows Forms разработчик неизбежно сталкивается с необходимостью выбора того, как именно дочернее окно будет взаимодействовать с пользователем и с главным окном программы. В Windows Forms для этого существуют два принципиально разных режима отображения: модальный и немодальный. Понимание разницы между ними и умение правильно их применять определяют удобство интерфейса и стабильность работы приложения.

> **Определение.** Модальное окно (modal window) — это окно, которое блокирует работу с остальными окнами родительского приложения до тех пор, пока пользователь его не закроет. Переключиться на главное окно, нажать на его кнопки или изменить его размеры в момент, когда открыто модальное окно, невозможно.

> **Определение.** Немодальное окно (modeless window) — это окно, которое позволяет пользователю свободно переключаться между ним и другими окнами приложения, выполняя действия как в главном окне, так и в дочернем одновременно.

Для вызова модального окна у экземпляра класса формы используется метод `ShowDialog()`. Для вызова немодального окна применяется метод `Show()`.

Рассмотрим синтаксис и поведение обоих методов. Когда вызывается метод `ShowDialog()`, поток выполнения кода в вызывающей форме приостанавливается на строке вызова. Код продолжит выполняться только после того, как дочернее окно будет полностью закрыто. В то же время метод `Show()` не блокирует выполнение кода: вызов происходит мгновенно, и программа сразу переходит к следующей строке метода главной формы, оставляя дочернее окно жить своей жизнью в графическом интерфейсе.

### Свойство DialogResult и управление результатами модального окна

Модальные окна чаще всего применяются для реализации диалогов, подтверждений, настройки параметров или ввода информации, требующей обязательного ответа (например, диалоги сохранения файла, окна «О программе», формы авторизации). Для таких окон критически важно знать, *как именно* пользователь завершил работу: нажал ли он кнопку «ОК», «Отмена», «Да» или «Нет».

Для этих целей в Windows Forms предусмотрены специальное перечисление `DialogResult` и свойство формы `DialogResult`.

> **Определение.** `DialogResult` — это системное перечисление (enum), содержащее стандартные константы результатов закрытия диалогового окна: `None`, `OK`, `Cancel`, `Yes`, `No`, `Abort`, `Retry`, `Ignore`.

У каждого элемента управления `Button` в конструкторе или через код в свойстве `DialogResult` можно задать определенное значение. Если кнопка обладает таким свойством, то при её нажатии форма автоматически закрывается, а её собственное свойство `DialogResult` принимает соответствующее значение. Это избавляет программиста от необходимости вручную писать обработчик события `Click` для закрытия формы.

Шаг за шагом алгоритм работы с `ShowDialog()` и `DialogResult` выглядит следующим образом:
1. Главная форма создает экземпляр дочерней формы.
2. Главная форма вызывает метод `ShowDialog()` для дочерней формы.
3. Пользователь взаимодействует с дочерней формой и нажимает, например, кнопку «Сохранить», у которой свойство `DialogResult` установлено в `DialogResult.OK`.
4. Форма закрывается, а метод `ShowDialog()` возвращает значение `DialogResult.OK` в вызывающий код главной формы.
5. Главная форма проверяет возвращенное значение через условный оператор `if` и, если результат равен `OK`, считывает введенные данные.

### Сравнение модальных и немодальных окон

Для наглядности сравним оба режима по ключевым характеристикам:

| Характеристика | Модальное окно (`ShowDialog`) | Немодальное окно (`Show`) |
|---|---|---|
| **Блокировка интерфейса** | Блокирует родительское окно до закрытия | Не блокирует родительское окно |
| **Выполнение кода** | Выполнение кода главной формы приостанавливается на строке вызова | Выполнение кода главной формы продолжается сразу |
| **Сценарии применения** | Настройки, подтверждения, диалоги ввода, авторизация | Вспомогательные панели, поиск по тексту, справочники, панели инструментов |
| **Управление памятью** | Обычно создается локально, используется и сразу уничтожается | Требует контроля жизненного цикла, чтобы избежать утечек памяти или повторного открытия |
| **Возврат результата** | Возвращает `DialogResult` непосредственно через метод вызова | Требует использования событий или прямых ссылок для передачи данных |

### Обработка фокуса ввода и управление окнами

При переключении между окнами операционная система и среда .NET автоматически управляют фокусом ввода (клавиатуры и мыши). 

Для модального окна фокус жестко удерживается в пределах этого окна. Если попытаться кликнуть мышью по главной форме, Windows выдаст характерный звуковой сигнал («писк»), указывая на то, что активен другой диалог, и переведет фокус обратно на модальное окно.

Для немодальных окон ситуация иная. Пользователь может свободно кликать между главным и дочерним окнами. Однако здесь возникает архитектурная проблема: если пользователь случайно нажмет кнопку открытия немодального окна повторно, программа может создать и показать вторую, третью и т.д. копию одинакового окна. Это приводит к замусориванию экрана и лишнему расходу оперативной памяти.

Для предотвращения этого в немодальных окнах применяется проверка существующего экземпляра перед открытием. Переменная, хранящая ссылку на форму, проверяется на `null` или на то, открыто ли окно в данный момент (свойство `IsDisposed`).

### Разобранный пример 1: Окно настроек программы в модальном режиме

Разработаем приложение, в котором главная форма (`MainForm`) содержит кнопку «Настройки». По нажатию на нее открывается модальное окно настроек (`SettingsForm`), где пользователь выбирает цвет фона главной формы (светлый или темный) и нажимает «Сохранить». Если пользователь нажимает «Отмена», изменения не применяются.

#### Условие и описание интерфейса
- **Главная форма (`MainForm`):** содержит кнопку `btnSettings` («Настройки») и текстовую метку `lblStatus` для отображения текущего статуса.
- **Дочерняя форма (`SettingsForm`):** содержит два элемента `RadioButton` (`rbLight` и `rbDark`), кнопку сохранения `btnSave` (у которой `DialogResult = DialogResult.OK`) и кнопку отмены `btnCancel` (у которой `DialogResult = DialogResult.Cancel`).

#### Ход рассуждений
1. В главной форме по клику на кнопку мы создаем объект `SettingsForm`.
2. Вызываем `settingsForm.ShowDialog()`. Программа ждет завершения работы диалога.
3. Пользователь выбирает радиокнопку и нажимает кнопку с установленным `DialogResult`. Окно закрывается.
4. Метод `ShowDialog()` возвращает результат. Мы проверяем `if (result == DialogResult.OK)`.
5. Если условие верно, главная форма считывает выбранное значение из свойств дочерней формы и применяет настройки к своему дизайну (меняет `BackColor`).

#### Решение (код на C#)

Ниже представлен полный компилируемый код обеих форм. Предполагается, что проект создан в Visual Studio для .NET 8 (Windows Forms).

```csharp
using System;
using System.Drawing;
using System.Windows.Forms;

namespace MultiFormApp
{
    // Главная форма приложения
    public partial class MainForm : Form
    {
        private Button btnSettings;
        private Label lblStatus;

        public MainForm()
        {
            InitializeComponentCustom();
        }

        private void InitializeComponentCustom()
        {
            this.Text = "Главное окно";
            this.Size = new Size(400, 300);
            this.StartPosition = FormStartPosition.CenterScreen;

            btnSettings = new Button();
            btnSettings.Text = "Настройки...";
            btnSettings.Location = new Point(130, 100);
            btnSettings.Size = new Size(120, 40);
            btnSettings.Click += BtnSettings_Click;

            lblStatus = new Label();
            lblStatus.Text = "Статус: Ожидание настроек";
            lblStatus.Location = new Point(50, 160);
            lblStatus.Size = new Size(300, 25);
            lblStatus.TextAlign = ContentAlignment.MiddleCenter;

            this.Controls.Add(btnSettings);
            this.Controls.Add(lblStatus);
        }

        private void BtnSettings_Click(object sender, EventArgs e)
        {
            // Создаем экземпляр дочерней формы настроек
            using (SettingsForm settingsForm = new SettingsForm())
            {
                // Открываем окно в модальном режиме и сохраняем результат закрытия
                DialogResult result = settingsForm.ShowDialog(this);

                // Проверяем, нажал ли пользователь кнопку подтверждения (OK)
                if (result == DialogResult.OK)
                {
                    // Считываем публичное свойство из дочерней формы
                    bool isDarkTheme = settingsForm.IsDarkThemeSelected;

                    if (isDarkTheme)
                    {
                        this.BackColor = Color.FromArgb(45, 45, 48);
                        this.ForeColor = Color.White;
                        lblStatus.ForeColor = Color.White;
                        lblStatus.Text = "Статус: Применена темная тема";
                    }
                    else
                    {
                        this.BackColor = SystemColors.Control;
                        this.ForeColor = Color.Black;
                        lblStatus.ForeColor = Color.Black;
                        lblStatus.Text = "Статус: Применена светлая тема";
                    }
                }
                else
                {
                    lblStatus.Text = "Статус: Изменение настроек отменено";
                }
            } // Блок using гарантирует вызов Dispose() и освобождение ресурсов формы
        }
    }

    // Дочерняя форма настроек
    public partial class SettingsForm : Form
    {
        private RadioButton rbLight;
        private RadioButton rbDark;
        private Button btnSave;
        private Button btnCancel;

        // Публичное свойство для передачи выбранного параметра наружу
        public bool IsDarkThemeSelected
        {
            get { return rbDark.Checked; }
        }

        public SettingsForm()
        {
            InitializeComponentCustom();
        }

        private void InitializeComponentCustom()
        {
            this.Text = "Настройки программы";
            this.Size = new Size(300, 220);
            this.StartPosition = FormStartPosition.CenterParent;
            this.FormBorderStyle = FormBorderStyle.FixedDialog;
            this.MaximizeBox = false;
            this.MinimizeBox = false;

            rbLight = new RadioButton();
            rbLight.Text = "Светлая тема";
            rbLight.Location = new Point(40, 30);
            rbLight.Checked = true;
            rbLight.AutoSize = true;

            rbDark = new RadioButton();
            rbDark.Text = "Темная тема";
            rbDark.Location = new Point(40, 70);

            btnSave = new Button();
            btnSave.Text = "Сохранить";
            btnSave.Location = new Point(40, 120);
            btnSave.Size = new Size(95, 30);
            // Установка DialogResult автоматически закрывает форму с результатом OK
            btnSave.DialogResult = DialogResult.OK;

            btnCancel = new Button();
            btnCancel.Text = "Отмена";
            btnCancel.Location = new Point(145, 120);
            btnCancel.Size = new Size(95, 30);
            // Установка DialogResult автоматически закрывает форму с результатом Cancel
            btnCancel.DialogResult = DialogResult.Cancel;

            // Назначаем кнопки по умолчанию для клавиш Enter и Esc
            this.AcceptButton = btnSave;
            this.CancelButton = btnCancel;

            this.Controls.Add(rbLight);
            this.Controls.Add(rbDark);
            this.Controls.Add(btnSave);
            this.Controls.Add(btnCancel);
        }
    }
}
```

#### Пояснение по коду
- Строка `using (SettingsForm settingsForm = new SettingsForm())` гарантирует, что после закрытия модального окна оперативная память, занятая элементами управления формы, будет немедленно очищена через вызов метода `Dispose()`. Это важнейшая практика при работе с графическими элементами.
- Конструкция `this.AcceptButton = btnSave;` связывает нажатие клавиши `Enter` на клавиатуре с кнопкой сохранения, а `CancelButton = btnCancel` привязывает клавишу `Esc` к отмене, что повышает эргономичность интерфейса.

### Разобранный пример 2: Вспомогательное окно справочника в немодальном режиме

Разработаем приложение, в котором главная форма позволяет открыть справочник терминов с помощью немодального метода `Show()`. Особенность этого примера — защита от открытия нескольких одинаковых окон справочника одновременно.

#### Условие и описание интерфейса
- **Главная форма (`MainForm`):** содержит кнопку `btnHelp` («Открыть справочник»).
- **Дочерняя форма (`HelpForm`):** немодальное окно, содержащее многострочное текстовое поле (`TextBox`) с информацией и кнопку закрытия.

#### Ход рассуждений
1. Объявляем приватное поле класса `private HelpForm helpForm = null;` на уровне главной формы. Это поле будет хранить ссылку на открытое окно справочника.
2. При клике на кнопку «Открыть справочник» проверяем: если переменная `helpForm` равна `null` ИЛИ окно уже было уничтожено (`helpForm.IsDisposed`), мы создаем новый экземпляр формы.
3. Вызываем метод `helpForm.Show()`, а не `ShowDialog()`. Код главной формы продолжает работу, пользователь может переключаться между главным окном и справочником.
4. Чтобы главная форма знала, когда пользователь закрыл окно справочника крестиком, и не держала в памяти устаревшую ссылку, подписываемся на событие закрытия формы `FormClosed`.

#### Решение (код на C#)

```csharp
using System;
using System.Drawing;
using System.Windows.Forms;

namespace ModelessApp
{
    public partial class MainForm : Form
    {
        private Button btnHelp;
        // Ссылка на немодальное дочернее окно
        private HelpForm helpForm = null;

        public MainForm()
        {
            InitializeComponentCustom();
        }

        private void InitializeComponentCustom()
        {
            this.Text = "Главное окно - Работа со справочником";
            this.Size = new Size(450, 300);
            this.StartPosition = FormStartPosition.CenterScreen;

            btnHelp = new Button();
            btnHelp.Text = "Открыть справочник";
            btnHelp.Location = new Point(125, 110);
            btnHelp.Size = new Size(180, 45);
            btnHelp.Click += BtnHelp_Click;

            this.Controls.Add(btnHelp);
        }

        private void BtnHelp_Click(object sender, EventArgs e)
        {
            // Проверяем, открыто ли уже окно справочника
            if (helpForm == null || helpForm.IsDisposed)
            {
                // Если не открыто — создаем новый экземпляр
                helpForm = new HelpForm();

                // Подписываемся на событие закрытия формы, чтобы обнулить ссылку
                helpForm.FormClosed += (s, args) => {
                    helpForm = null;
                };

                // Открываем окно в НЕМОДАЛЬНОМ режиме
                helpForm.Show(this); // Передаем this в качестве владельца (owner)
            }
            else
            {
                // Если окно уже открыто, просто выводим его на передний план
                helpForm.BringToFront();
                helpForm.Activate();
            }
        }
    }

    // Немодальная форма справочника
    public partial class HelpForm : Form
    {
        private TextBox txtInfo;

        public HelpForm()
        {
            InitializeComponentCustom();
        }

        private void InitializeComponentCustom()
        {
            this.Text = "Справочник системы";
            this.Size = new Size(350, 250);
            this.StartPosition = FormStartPosition.Manual;
            this.Location = new Point(500, 200); // Размещаем рядом с главным окном

            txtInfo = new TextBox();
            txtInfo.Multiline = true;
            txtInfo.ReadOnly = true;
            txtInfo.ScrollBars = ScrollBars.Vertical;
            txtInfo.Dock = DockStyle.Fill;
            txtInfo.Text = "Справочная информация:\r\n\r\n" +
                           "1. Модальные окна блокируют родительское приложение.\r\n" +
                           "2. Немодальные окна позволяют работать параллельно.\r\n" +
                           "3. Всегда проверяйте состояние ссылок перед повторным вызовом немодальных окон.";

            this.Controls.Add(txtInfo);
        }
    }
}
```

#### Пояснение по коду и проверка работы
- Метод `helpForm.Show(this)` принимает параметр `this` (родительское окно). Это важно: благодаря этому дочернее немодальное окно всегда располагается поверх главного окна и автоматически сворачивается вместе с ним, если пользователь сворачивает всю программу.
- Вызов методов `helpForm.BringToFront()` и `helpForm.Activate()` в ветке `else` гарантирует, что если пользователь попытается кликнуть на кнопку открытия повторно вместо создания второго окна, уже существующее окно просто поднимется поверх остальных и получит фокус ввода. Это стандартное и профессиональное поведение интерфейсов операционных систем.

## Передача данных из главной формы в дочернюю

### Передача данных через параметры конструктора дочерней формы

В архитектуре Windows Forms создание новой формы в памяти происходит с помощью оператора `new`, который вызывает конструктор класса формы. Как и любой другой класс в C#, форма может принимать аргументы через свой конструктор. Это позволяет передать необходимые данные в дочернее окно в момент его инстанцирования, гарантируя, что форма с самого начала своего жизненного цикла будет обладать всей необходимой информацией.

> **Определение.** Конструктор с параметрами — это специальный метод класса, который вызывается автоматически при создании экземпляра объекта и позволяет передать начальные данные для инициализации его полей и состояния.

По умолчанию Visual Studio генерирует для каждой формы стандартный конструктор без параметров (конструктор по умолчанию), внутри которого вызывается метод `InitializeComponent()`. Этот метод отвечает за создание и настройку всех визуальных элементов управления, размещенных на форме в конструкторе интерфейсов (дизайнере). Если мы добавляем свой собственный конструктор с параметрами, мы обязаны не забыть вызвать внутри него `InitializeComponent()`, иначе элементы управления на форме останутся неинициализированными, что приведет к исключению `NullReferenceException` при попытке обратиться к ним.

Рассмотрим механизм передачи данных через конструктор на первом практическом примере.

#### Пример 1: Передача строки логина в приветственное окно

Представим ситуацию: на главной форме (`MainForm`) пользователь вводит свой логин в текстовое поле. При нажатии на кнопку открывается дочерняя форма приветствия (`WelcomeForm`), которая должна поприветствовать именно этого пользователя, выведя на экран текст вроде: «Добро пожаловать, Алексей!».

Условие:
- Главная форма (`MainForm`): содержит `TextBox` (`txtLogin`) и `Button` (`btnOpen`).
- Дочерняя форма (`WelcomeForm`): содержит `Label` (`lblGreeting`).
- Задача: передать введенную строку из `txtLogin` в конструктор `WelcomeForm` и отобразить ее в `lblGreeting`.

Схема взаимодействия (в виде диаграммы последовательности словами):
1. Пользователь вводит текст в `txtLogin` на `MainForm`.
2. Пользователь нажимает `btnOpen`.
3. `MainForm` считывает текст: `string login = txtLogin.Text;`.
4. `MainForm` создает экземпляр: `WelcomeForm frm = new WelcomeForm(login);`.
5. `WelcomeForm` принимает строку в конструкторе и сохраняет ее в закрытом поле.
6. При загрузке `WelcomeForm` устанавливает текст для `lblGreeting`.
7. `MainForm` отображает дочернюю форму: `frm.ShowDialog();`.

Напишем полный код обеих форм на C# (.NET 8).

Код дочерней формы `WelcomeForm.cs`:

```csharp
using System;
using System.Drawing;
using System.Windows.Forms;

namespace MultiFormApp
{
    public partial class WelcomeForm : Form
    {
        // Закрытое поле для хранения переданного логина
        private string _userLogin;

        // Пользовательский конструктор, принимающий строку логина
        public WelcomeForm(string login)
        {
            // ОБЯЗАТЕЛЬНО: инициализируем элементы управления дизайнера
            InitializeComponent();

            // Проверяем переданные данные на корректность
            if (string.IsNullOrWhiteSpace(login))
            {
                _userLogin "Гость";
            }
            else
            {
                _userLogin = login.Trim();
            }
        }

        private void WelcomeForm_Load(object sender, EventArgs e)
        {
            // Формируем приветствие на основе сохраненного значения
            lblGreeting.Text = $"Добро пожаловать в систему, {_userLogin}!";
        }
    }
}
```

Код главной формы `MainForm.cs`:

```csharp
using System;
using System.Windows.Forms;

namespace MultiFormApp
{
    public partial class MainForm : Form
    {
        public MainForm()
        {
            InitializeComponent();
        }

        private void btnOpen_Click(object sender, EventArgs e)
        {
            // Шаг 1. Получаем данные из элемента управления главной формы
            string enteredLogin = txtLogin.Text;

            // Шаг 2. Создаем экземпляр дочерней формы, передавая данные в конструктор
            WelcomeForm welcomeWindow = new WelcomeForm(enteredLogin);

            // Шаг 3. Открываем дочернюю форму модально
            welcomeWindow.ShowDialog();
        }
    }
}
```

Пояснения к коду:
- В классе `WelcomeForm` объявлено закрытое поле `_userLogin`. Оно недоступно извне, что защищает данные от случайного изменения.
- Конструктор `WelcomeForm(string login)` принимает аргумент и выполняет базовую валидацию: если строка пустая или состоит из пробелов, подставляется значение по умолчанию `"Гость"`.
- Событие `Load` формы `WelcomeForm` используется для финальной настройки интерфейса перед тем, как окно станет видимым для пользователя.

### Передача данных через открытые свойства дочерней формы

Использование конструктора удобно, когда параметров немного (1–3 штуки). Однако если дочерняя форма настраивается по десятку параметров (например, окно настроек редактора кода или параметров графического редактора), создание громоздких конструкторов с длинным списком аргументов приводит к трудночитаемому и хрупкому коду. В таких случаях применяют второй подход — передачу данных через публичные свойства (`public properties`) дочерней формы перед ее отображением.

> **Определение.** Свойство в C# — это член класса, который предоставляет гибкий механизм для чтения, записи или вычисления значения закрытого поля, обеспечивая при этом инкапсуляцию данных.

> **Обеспечение инкапсуляции.** Почему поля класса должны быть закрытыми (`private`), а доступ к ним осуществляться через свойства? Прямой доступ к полям (`public string Color;`) нарушает принцип инкапсуляции: внешний код может записать в поле любое недопустимое значение (например, пустую строку или отрицательный размер), и класс не сможет это проконтролировать. Свойство с блоками `get` и `set` позволяет добавить логику проверки входящих данных, вызывать перерисовку интерфейса при изменении параметров или делать поле доступным только для чтения.

Рассмотрим второй разобранный пример, где этот механизм демонстрируется на практике.

#### Пример 2: Передача числовых настроек (размер шрифта и цвет) через свойства

Условие:
- Главная форма содержит кнопку открытия настроек и элемент `TextBox`, текст в котором должен менять оформление.
- Дочерняя форма настроек (`SettingsForm`) содержит `NumericUpDown` для выбора размера шрифта и `ComboBox` для выбора цвета текста.
- Задача: перед открытием `SettingsForm` главная форма передает текущие настройки через свойства, а после закрытия окна считывает новые значения также через свойства.

Схема работы:
1. `MainForm` создает экземпляр `SettingsForm settingsForm = new SettingsForm();`.
2. `MainForm` записывает текущие значения в свойства дочерней формы: `settingsForm.FontSize = 14f; settingsForm.ThemeColor = Color.Blue;`.
3. Конструктор `SettingsForm` отрабатывает стандартно (без параметров), создавая элементы управления.
4. В событии `Load` дочерней формы значения из свойств переносятся на визуальные элементы (`NumericUpDown` и `ComboBox`).
5. Пользователь меняет настройки в окне и нажимает кнопку сохранения (`DialogResult.OK`).
6. `MainForm` забирает обновленные данные через те же свойства: `float newSize = settingsForm.FontSize; Color newColor = settingsForm.ThemeColor;`.

Напишем полный код класса дочерней формы `SettingsForm.cs`:

```csharp
using System;
using System.Drawing;
using System.Windows.Forms;

namespace MultiFormApp
{
    public partial class SettingsForm : Form
    {
        // Закрытые поля для хранения реальных значений
        private float _fontSize = 12f;
        private Color _themeColor = Color.Black;

        public SettingsForm()
        {
            InitializeComponent();
        }

        // Публичное свойство для работы с размером шрифта с защитой от некорректных значений
        public float FontSize
        {
            get { return _fontSize; }
            set
            {
                // Проверяем диапазон допустимых значений шрифта
                if (value >= 8f && value <= 72f)
                {
                    _fontSize = value;
                }
                else
                {
                    // Если передано недопустимое значение, устанавливаем стандартное
                    _fontSize = 12f;
                }
            }
        }

        // Публичное свойство для работы с цветом
        public Color ThemeColor
        {
            get { return _themeColor; }
            set
            {
                // Защита от передачи пустой ссылки
                if (value != null)
                {
                    _themeColor = value;
                }
            }
        }

        private void SettingsForm_Load(object sender, EventArgs e)
        {
            // Инициализируем элементы управления на основе текущих значений свойств
            numFontSize.Value = (decimal)_fontSize;
            
            // Предположим, в comboBoxColor хранятся названия цветов
            cmbColor.SelectedItem = _themeColor.Name;
        }

        private void btnSave_Click(object sender, EventArgs e)
        {
            // Считываем данные из элементов управления обратно в закрытые поля через логику свойств
            FontSize = (float)numFontSize.Value;

            if (cmbColor.SelectedItem != null)
            {
                string colorName = cmbColor.SelectedItem.ToString();
                // Превращаем строковое название цвета в объект Color
                ThemeColor = Color.FromName(colorName);
            }

            // Устанавливаем результат диалога и закрываем окно
            this.DialogResult = DialogResult.OK;
            this.Close();
        }
    }
}
```

А теперь напишем код вызова этой формы из `MainForm.cs`:

```csharp
using System;
using System.Drawing;
using System.Windows.Forms;

namespace MultiFormApp
{
    public partial class MainForm : Form
    {
        // Храним текущие настройки на главной форме
        private float _currentFontSize = 10f;
        private Color _currentColor = Color.Black;

        public MainForm()
        {
            InitializeComponent();
        }

        private void btnOpenSettings_Click(object sender, EventArgs e)
        {
            // Шаг 1. Создаем дочернюю форму стандартным конструктором
            SettingsForm settingsForm = new SettingsForm();

            // Шаг 2. Передаем текущие данные через публичные свойства ДО открытия окна
            settingsForm.FontSize = _currentFontSize;
            settingsForm.ThemeColor = _currentColor;

            // Шаг 3. Открываем окно модально и проверяем результат закрытия
            if (settingsForm.ShowDialog() == DialogResult.OK)
            {
                // Шаг 4. Забираем измененные данные через свойства дочерней формы
                _currentFontSize = settingsForm.FontSize;
                _currentColor = settingsForm.ThemeColor;

                // Применяем настройки к элементу главной формы (например, к текстовому полю)
                txtSampleText.Font = new Font(txtSampleText.Font.FontFamily, _currentFontSize);
                txtSampleText.ForeColor = _currentColor;
            }
        }
    }
}
```

Пояснения к коду:
- Обратите внимание на последовательность действий в `btnOpenSettings_Click`: мы сначала создали объект `settingsForm`, затем присвоили значения его свойствам `FontSize` и `ThemeColor`, и только после этого вызвали метод `ShowDialog()`. Если попытаться обратиться к свойствам *после* закрытия окна без проверки, они останутся доступны, но логика инициализации элементов (`Load`) работает именно в момент открытия.
- Внутри свойств `FontSize` установлена защита: если переданное число меньше 8 или больше 72, код автоматически принудительно устанавливает размер в 12 пунктов. Это наглядно демонстрирует преимущества инкапсуляции: вызывающий код не сможет «сломать» внутреннее состояние дочерней формы неверными данными.

### Инициализация элементов управления дочерней формы в событии Load

Одной из самых частых ошибок начинающих разработчиков является попытка обратиться к элементам управления дочерней формы (например, `TextBox.Text` или `Label.Text`) сразу после того, как отработал конструктор, но до того, как форма была открыта. 

Рассмотрим ошибочный фрагмент кода:

```csharp
// НЕПРАВИЛЬНЫЙ ПОДХОД
SettingsForm form = new SettingsForm();
// На следующем шаге мы пытаемся напрямую записать текст в TextBox, 
// который лежит на форме settingsForm:
form.txtBox.Text = "Привет"; // ОШИБКА! 
form.ShowDialog();
```

Почему этот код вызовет исключение `NullReferenceException`?
Потому что в момент выполнения строки `new SettingsForm()` вызывается конструктор, внутри которого выполняется `InitializeComponent()`. Однако элементы управления создаются в памяти, но физически еще не связаны с оконным дескриптором (Handle). Более того, если вы передаете данные через свойства, а свойства пытаются сразу изменить текст в элементах управления (`txtBox.Text = value;`), то в момент присвоения свойства **до** вызова `ShowDialog()` элемента `txtBox` еще не существует на экране, он равен `null`.

Правильный алгоритм работы с данными в дочерней форме выглядит следующим образом:
1. Данные из главной формы сохраняются в **закрытые поля** дочерней формы (через параметры конструктора или через свойства, записывающие значения во внутренние переменные).
2. Форма открывается (`Show()`, либо `ShowDialog()`).
3. При открытии генерируется событие `Load` (метод `Form_Load`).
4. Внутри метода `Form_Load` элементы управления считывают значения из закрытых полей и отображают их пользователю.

> **Правило.** Никогда не обращайтесь к визуальным элементам управления (`TextBox`, `Label`, `Button`, `ComboBox`) чужой формы напрямую до вызова метода `Show()` или `ShowDialog()`. Используйте промежуточные переменные (поля или автосвойства класса формы), а перенос значений в элементы управления делайте внутри обработчика события `Load` самой дочерней формы.

### Обработка исключений при передаче null-ссылок и некорректных данных

При проектировании многооконных приложений необходимо учитывать фактор непредвиденных или пустых данных. Поскольку строки и сложные объекты в C# являются ссылочными типами (`reference types`), они могут принимать значение `null`. Если главная форма передаст в дочернюю форму `null` вместо строки или объекта, это неизбежно приведет к аварийному завершению программы при попытке вызвать у этой переменной какой-либо метод (например, `Length` или `ToUpper`).

Рассмотрим, как правильно обрабатывать потенциально опасные входящие данные в конструкторе или свойствах дочерней формы.

Пример проверки входящих ссылочных и числовых данных:

```csharp
public class ProfileForm : Form
{
    private string _userName;
    private UserProfile _profileData;

    // Конструктор с защитой от null-ссылок
    public ProfileForm(string userName, UserProfile profile)
    {
        InitializeComponent();

        // Защита строкового параметра
        if (string.IsNullOrEmpty(userName))
        {
            _userName = "Анонимный пользователь";
        }
        else
        {
            _userName = userName;
        }

        // Защита объектного параметра (ссылочный тип)
        if (profile == null)
        {
            // Создаем пустой объект по умолчанию, чтобы избежать null-прашиваний
            _profileData = new UserProfile();
        }
        else
        {
            _profileData = profile;
        }
    }
}
```

Кроме проверки на `null`, при передаче числовых данных через свойства или конструкторы важно использовать метод `Math.Clamp` (доступный в современных версиях .NET) или условные операторы для ограничения значений в допустимых границах бизнес-логики приложения.

Пример защиты числового свойства через `Math.Clamp`:

```csharp
private int _age = 18;

public int UserAge
{
    get { return _age; }
    set
    {
        // Ограничиваем возраст в диапазоне от 0 до 120 лет
        // Значения вне диапазона автоматически прижимаются к ближайшей границе
        _age = Math.Clamp(value, 0, 120);
    }
}
```

Такой подход гарантирует, что даже если в главной форме произойдет программный сбой и пользователю попытаются передать возраст `-50` или `500`, дочерняя форма не упадет с ошибкой и корректно инициализирует свои элементы безопасными данными.

## Передача данных из дочерней формы в главную

### Механизм обратной связи через модальные окна

В предыдущих темах мы рассмотрели, как передать информацию из главной формы в дочернюю. Однако в реальных приложениях часто возникает обратная задача: дочернее окно открывается для того, чтобы пользователь ввёл данные, выбрал элемент из списка или подтвердил какое-либо действие, после чего эти данные должны вернуться в родительское окно.

> **Определение.** Механизм обратной связи в Windows Forms — это способ передачи результатов работы пользовательского ввода из дочерней формы в главную после завершения жизненного цикла дочернего окна.

Основным инструментом для организации такого обмена является модальный вызов формы с помощью метода `ShowDialog()`. Главная особенность `ShowDialog()` заключается в том, что выполнение кода в главной форме приостанавливается на строке вызова этого метода и возобновляется только тогда, когда дочерняя форма полностью закрывается. 

Благодаря этой особенности главная форма может обратиться к публичным свойствам дочерней формы сразу после завершения вызова `ShowDialog()`. Экземпляр дочерней формы продолжает существовать в памяти до тех пор, пока метод `ShowDialog()` не завершит работу и управление не вернется в вызывающий метод. Это позволяет главной форме «прочитать» состояние дочерних элементов управления или созданных внутри дочерней формы объектов.

Рассмотрим общую схему взаимодействия:
1. Главная форма (`MainForm`) создаёт экземпляр дочерней формы (`ChildForm`).
2. Главная форма вызывает `childForm.ShowDialog()`.
3. Дочернее окно отображается, блокируя родительское. Пользователь взаимодействует с элементами интерфейса (вводит текст, нажимает кнопку подтверждения).
4. При нажатии кнопки подтверждения дочерняя форма сохраняет введённые данные во внутренние свойства и закрывается (или скрывается) с установкой определенного статуса завершения (`DialogResult`).
5. Метод `ShowDialog()` в главной форме завершает работу.
6. `MainForm` проверяет статус завершения и, если операция подтверждена, считывает данные из свойств `childForm`.
7. Полученные данные используются для обновления элементов управления на главной форме (`ListBox`, `DataGridView`, текстовые метки).
8. Экземпляр дочерней формы уничтожается сборщиком мусора (или явно через `Dispose`).

### Использование перечисления DialogResult

Чтобы главная форма понимала, как именно завершила свою работу дочерняя форма (пользователь нажал кнопку «ОК» и подтвердил ввод, либо нажал «Отмена» или крестик в углу окна), используется системное перечисление `DialogResult`.

> **Определение.** `DialogResult` — это встроенное перечисление в пространстве имен `System.Windows.Forms`, содержащие константы, которые определяют результат нажатия кнопки в диалоговом окне (`OK`, `Cancel`, `Yes`, `No`, `Abort`, `Retry`, `Ignore`).

В дизайнере форм каждая кнопка (`Button`) обладает специальным свойством `DialogResult`. Если установить свойство `DialogResult` кнопки в значение `DialogResult.OK`, то при нажатии на эту кнопку форма автоматически закроется, а метод `ShowDialog()`, вызвавший её, вернет значение `DialogResult.OK`. Аналогично работает установка свойства в `DialogResult.Cancel`.

В коде дочерней формы мы можем управлять этим поведением вручную или через свойства кнопки. Присвоение значения свойству `this.DialogResult = DialogResult.OK;` внутри обработчика события клика по кнопке также приводит к закрытию формы и возврату соответствующего статуса.

### Типичные архитектурные ошибки: нарушение инкапсуляции

Прежде чем перейти к написанию кода, остановимся на критически важной архитектурной ошибке, которую часто совершают начинающие разработчики.

> **Ошибка:** Прямая модификация элементов управления главной формы из кода дочерней формы (например, обращение к `MainForm.textBox1.Text = ...` или передача ссылки на главную форму через конструктор дочерней).

Почему это плохо:
1. **Нарушение инкапсуляции и принципа разделения ответственности.** Дочерняя форма жестко «привязывается» к конкретной структуре главной формы. Если вы решите переименовать `textBox1` на главной форме или вообще заменить его на `DataGridView`, вам придется переписывать код в дочерней форме.
2. **Управление состоянием.** Дочернее окно должно быть автономным компонентом. Оно лишь собирает данные и предоставляет их наружу, но оно не должно знать, кто его вызвал и что с этими данными будут делать дальше.

**Правильный подход:** Дочерняя форма предоставляет наружу чистые публичные свойства (`public`). Главная форма сама решает, когда забрать эти данные после закрытия дочернего окна и куда их записать.

### Разобранный пример 1: Ввод текстового комментария

Рассмотрим задачу: в главной форме есть кнопка «Добавить комментарий» и текстовое поле для вывода результата. При нажатии на кнопку открывается дочернее окно, где пользователь вводит текст комментария. При нажатии «ОК» текст передается в главную форму и выводится на экран. При нажатии «Отмена» ничего не происходит.

#### Проектирование дочерней формы (`CommentForm`)
Форма содержит элемент `TextBox` (имя: `txtComment`) и две кнопки: `btnOk` (свойство `DialogResult` установлено в `OK`) и `btnCancel` (свойство `DialogResult` установлено в `Cancel`).

```csharp
using System;
using System.Windows.Forms;

namespace MultiFormApp
{
    public partial class CommentForm : Form
    {
        // Публичное свойство для выдачи результата наружу
        // Используем инкапсуляцию: поле скрыто, доступ только через get-свойство
        public string CommentText 
        {
            get { return txtComment.Text.Trim(); }
        }

        public CommentForm()
        {
            InitializeComponent();
            
            // Настройка кнопок по умолчанию
            this.AcceptButton = btnOk;     // Enter подтверждает ввод
            this.CancelButton = btnCancel; // Esc отменяет ввод
        }
    }
}
```

#### Обработка в главной форме (`MainForm`)
В главной форме по клику на кнопку открытия окна мы анализируем возвращаемый результат.

```csharp
using System;
using System.Windows.Forms;

namespace MultiFormApp
{
    public partial class MainForm : Form
    {
        private Button btnOpenComment;
        private Label lblResult;

        public MainForm()
        {
            InitializeComponentCustom();
        }

        private void InitializeComponentCustom()
        {
            this.Width = 400;
            this.Height = 250;
            this.Text = "Главная форма — Комментарии";

            btnOpenComment = new Button();
            btnOpenComment.Text = "Ввести комментарий";
            btnOpenComment.Left = 30;
            btnOpenComment.Top = 30;
            btnOpenComment.Width = 180;
            btnOpenComment.Height = 35;
            btnOpenComment.Click += BtnOpenComment_Click;

            lblResult = new Label();
            lblResult.Text = "Комментарий пока не задан.";
            lblResult.Left = 30;
            lblResult.Top = 90;
            lblResult.Width = 320;
            lblResult.Height = 60;

            this.Controls.Add(btnOpenComment);
            this.Controls.Add(lblResult);
        }

        private void BtnOpenComment_Click(object sender, EventArgs e)
        {
            // Создаем экземпляр дочерней формы в блоке using для гарантированного освобождения ресурсов
            using (CommentForm commentForm = new CommentForm())
            {
                // Открываем окно модально
                DialogResult result = commentForm.ShowDialog();

                // Проверяем, нажал ли пользователь кнопку ОК
                if (result == DialogResult.OK)
                {
                    string enteredText = commentForm.CommentText;

                    // Валидация полученных данных на уровне главной формы
                    if (!string.IsNullOrEmpty(enteredText))
                    {
                        lblResult.Text = "Введённый комментарий:\n" + enteredText;
                    }
                    else
                    {
                        MessageBox.Show("Комментарий не может быть пустым!", "Предупреждение", 
                            MessageBoxButtons.OK, MessageBoxIcon.Warning);
                    }
                }
                else
                {
                    lblResult.Text "Ввод отменён пользователем.";
                }
            } // Метод Dispose вызовется автоматически при выходе из блока using
        }
    }
}
```

**Пояснение кода:**
1. Конструкция `using (CommentForm commentForm = new CommentForm())` гарантирует, что даже в случае возникновения исключений все системные ресурсы, занятые окном (дескрипторы графической подсистемы), будут корректно очищены.
2. Метод `ShowDialog()` возвращает значение `DialogResult`, которое мы сравниваем с `DialogResult.OK`. Это стандартный и самый надежный способ проверки успешности завершения работы диалога.
3. Главная форма считывает свойство `CommentForm.CommentText`, не зная ничего о том, как устроен внутренний `TextBox` в дочерней форме.

### Передача структурированных данных (объектов) обратно в родительское окно

В реальных приложениях из дочерней формы редко возвращают одиночные строки или числа. Гораздо чаще требуется вернуть сложный структурированный объект, содержащий множество полей (например, данные нового пользователя, карточку товара или параметры конфигурации).

Для этого мы используем предварительно созданный класс-модель данных (в соответствии с принципами ООП, изученными в темах 23–24). Дочерняя форма заполняет поля этого класса на основе ввода пользователя, сохраняет его в публичное свойство, а главная форма после закрытия диалога забирает готовый объект и добавляет его, например, в коллекцию или таблицу.

### Разобранный пример 2: Окно создания новой записи товара

Разработаем приложение для учёта товаров. Главная форма содержит список (`ListBox`) существующих товаров и кнопку «Добавить товар». Дочерняя форма (`ProductEditForm`) позволяет ввести название товара, его цену и количество на складе. При нажатии «Сохранить» дочерняя форма формирует готовый объект класса `Product` и возвращает его в главную форму.

#### Класс-модель данных (`Product.cs`)
Этот класс описывает структуру данных и доступен как в главной, так и в дочерней форме.

```csharp
namespace MultiFormApp
{
    public class Product
    {
        public string Name { get; set; }
        public decimal Price { get; set; }
        public int Quantity { get; set; }

        public Product(string name, decimal price, int quantity)
        {
            Name = name;
            Price = price;
            Quantity = quantity;
        }

        // Переопределяем метод ToString для красивого отображения в ListBox
        public override string ToString()
        {
            return $"{Name} — {Price:C2} руб. ({тиву} шт.)";
        }
    }
}
```

*(Примечание: в строке форматирования `C2` выводит денежный формат, зависящий от локализации системы).*

#### Дочерняя форма редактирования (`ProductEditForm.cs`)
Форма содержит три текстовых поля (`txtProductName`, `txtProductPrice`, `txtProductQuantity`), а также кнопки «Сохранить» и «Отмена».

```csharp
using System;
using System.Globalization;
using System.Windows.Forms;

namespace MultiFormApp
{
    public partial class ProductEditForm : Form
    {
        private TextBox txtProductName;
        private TextBox txtProductPrice;
        private TextBox txtProductQuantity;
        private Button btnSave;
        private Button btnCancel;

        // Публичное свойство, возвращающее созданный объект Product
        public Product CreatedProduct { get; private set; }

        public ProductEditForm()
        {
            InitializeComponentCustom();
        }

        private void InitializeComponentCustom()
        {
            this.Width = 350;
            this.Height = 300;
            this.Text = "Добавление товара";
            this.FormBorderStyle = FormBorderStyle.FixedDialog;
            this.MaximizeBox = false;
            this.MinimizeBox = false;
            this.StartPosition = FormStartPosition.CenterParent;

            Label lbl1 = new Label { Text = "Название:", Left = 20, Top = 20, Width = 100 };
            txtProductName = new TextBox { Left = 20, Top = 40, Width = 280 };

            Label lbl2 = new Label { Text = "Цена (руб.):", Left = 20, Top = 80, Width = 100 };
            txtProductPrice = new TextBox { Left = 20, Top = 100, Width = 280 };

            Label lbl3 = new Label { Text = "Количество:", Left = 20, Top = 140, Width = 100 };
            txtProductQuantity = new TextBox { Left = 20, Top = 160, Width = 280 };

            btnSave = new Button { Text = "Сохранить", Left = 110, Top = 210, Width = 90, Height = 30 };
            btnCancel = new Button { Text = "Отмена", Left = 210, Top = 210, Width = 90, Height = 30 };

            btnSave.Click += BtnSave_Click;
            
            this.CancelButton = btnCancel;
            btnCancel.Click += (s, e) => { this.DialogResult = DialogResult.Cancel; };

            this.Controls.AddRange(new Control[] { lbl1, txtProductName, lbl2, txtProductPrice, lbl3, txtProductQuantity, btnSave, btnCancel });
        }

        private void BtnSave_Click(object sender, EventArgs e)
        {
            // Проверка корректности введенных данных (Валидация)
            string name = txtProductName.Text.Trim();
            if (string.IsNullOrEmpty(name))
            {
                MessageBox.Show("Введите название товара!", "Ошибка", MessageBoxButtons.OK, MessageBoxIcon.Error);
                return;
            }

            // Безопасное парсинг вещественного числа с учетом региональных настроек
            if (!decimal.TryParse(txtProductPrice.Text, NumberStyles.Any, CultureInfo.InvariantCulture, out decimal price) || price <= 0)
            {
                MessageBox.Show("Некорректная цена! Введите положительное число.", "Ошибка", MessageBoxButtons.OK, MessageBoxIcon.Error);
                return;
            }

            // Безопасный парсинг целого числа для количества
            if (!int.TryParse(txtProductQuantity.Text, out int quantity) || quantity < 0)
            {
                MessageBox.Show("Некорректное количество! Введите целое неотрицательное число.", "Ошибка", MessageBoxButtons.OK, MessageBoxIcon.Error);
                return;
            }

            // Создаем экземпляр объекта на основе проверенных данных
            CreatedProduct = new Product(name, price, quantity);

            // Устанавливаем статус завершения ОК и закрываем форму
            this.DialogResult = DialogResult.OK;
            this.Close();
        }
    }
}
```

## Комплексный проект: многооконное приложение с двусторонним общим состоянием

### Проектирование структуры приложения «Учёт студентов»

Для закрепления полученных навыков работы с многооконными приложениями спроектируем и реализуем учебное десктопное приложение на платформе .NET 8 (Windows Forms) под названием «Учёт студентов». 

Архитектура приложения строится на разделении ответственности между компонентами пользовательского интерфейса (формами) и моделью данных. Взаимодействие окон будет осуществляться как в прямом направлении (передача данных из главного окна в дочернее для редактирования), так и в обратном (возврат созданных или изменённых данных в главное окно через свойства и `DialogResult`).

В состав приложения входят три основных компонента:
1. **Модель данных (`Student`)** — класс, инкапсулирующий информацию об одном студенте (ФИО, курс, средний балл).
2. **Главная форма (`MainForm`)** — содержит элемент управления `ListBox` для отображения списка студентов, а также кнопки управления («Добавить», «Редактировать», «Удалить»).
3. **Дочерняя форма (`StudentEditForm`)** — универсальное диалоговое окно, используемое как для создания нового студента, так и для редактирования существующего.

### Использование единой модели данных

Прежде чем проектировать визуальный интерфейс форм, необходимо определить структуру данных, которой они будут оперировать. Создадим класс `Student`, который будет служить единым контрактом данных для всех окон приложения.

```csharp
public class Student
{
    public string FullName { get; set; }
    public int Course { get; set; }
    public decimal AverageGrade { get; set; }

    // Конструктор по умолчанию для создания пустого объекта
    public Student()
    {
        FullName = string.Empty;
        Course = 1;
        AverageGrade = 0.0m;
    }

    // Конструктор с параметрами для быстрой инициализации
    public Student(string fullName, int course, decimal averageGrade)
    {
        FullName = fullName;
        Course = course;
        AverageGrade = averageGrade;
    }

    // Переопределение метода ToString() для корректного отображения в ListBox
    public override string ToString()
    {
        return $"{FullName} (Курс: {Course}, Ср. балл: {AverageGrade:0.00})";
    }
}
```

Переопределение метода `ToString()` позволяет объекту `ListBox` корректно выводить текстовое представление студента без необходимости настройки сложных привязок данных (`DataBinding`). При добавлении экземпляра `Student` в `ListBox`, элемент управления автоматически вызовет метод `ToString()`.

### Разработка формы редактирования и главной формы

Дочерняя форма `StudentEditForm` должна выполнять две задачи:
- Если она открыта для добавления, поля ввода остаются пустыми, а пользователю предлагается ввести данные.
- Если она открыта для редактирования, поля заполняются данными выбранного студента.

Рассмотрим код класса дочерней формы `StudentEditForm`. На форме расположены элементы: `TextBox` для ввода ФИО (`txtFullName`), `NumericUpDown` для выбора курса (`numCourse`), `TextBox` для ввода среднего балла (`txtAverageGrade`), а также кнопки «ОК» (`btnOk`) и «Отмена» (`btnCancel`).

```csharp
using System;
using System.Windows.Forms;

public partial class StudentEditForm : Form
{
    // Публичное свойство для доступа к созданному или отредактированному студенту
    public Student StudentData { get; private set; }

    // Конструктор по умолчанию (используется при создании нового студента)
    public StudentEditForm()
    {
        InitializeComponent();
        StudentData = new Student();
        this.Text = "Добавление студента";
    }

    // Конструктор с параметром (используется при редактировании существующего студента)
    public StudentEditForm(Student studentToEdit)
    {
        InitializeComponent();
        this.Text = "Редактирование студента";

        // Клонируем данные, чтобы изменения не затронули оригинал до нажатия кнопки «ОК»
        StudentData = new Student(studentToEdit.FullName, studentToEdit.Course, studentToEdit.AverageGrade);

        // Заполняем элементы управления текущими данными
        txtFullName.Text = StudentData.FullName;
        numCourse.Value = StudentData.Course;
        txtAverageGrade.Text = StudentData.AverageGrade.ToString();
    }

    private void btnOk_Click(object sender, EventArgs e)
    {
        // Проверка корректности введенных данных
        if (string.IsNullOrWhiteSpace(txtFullName.Text))
        {
            MessageBox.Show("ФИО не может быть пустым.", "Ошибка", MessageBoxButtons.OK, MessageBoxIcon.Warning);
            return;
        }

        if (!decimal.TryParse(txtAverageGrade.Text, out decimal avgGrade) || avgGrade < 0 || avgGrade > 5)
        {
            MessageBox.Show("Средний балл должен быть числом от 0 до 5.", "Ошибка", MessageBoxButtons.OK, MessageBoxIcon.Warning);
            return;
        }

        // Сохраняем данные в объект модели
        StudentData.FullName = txtFullName.Text.Trim();
        StudentData.Course = (int)numCourse.Value;
        StudentData.AverageGrade = avgGrade;

        // Устанавливаем результат диалога и закрываем окно
        this.DialogResult = DialogResult.OK;
        this.Close();
    }

    private void btnCancel_Click(object sender, EventArgs e)
    {
        this.DialogResult = DialogResult.Cancel;
        this.Close();
    }
}
```

Главная форма `MainForm` содержит `ListBox` (`listBoxStudents`), а также кнопки добавления (`btnAdd`), редактирования (`btnEdit`) и удаления (`btnDelete`). Для хранения списка студентов используется коллекция `BindingList<Student>`, которая автоматически уведомляет `ListBox` об изменениях в составе элементов.

```csharp
using System;
using System.ComponentModel;
using System.Windows.Forms;

public partial class MainForm : Form
{
    private BindingList<Student> students;

    public MainForm()
    {
        InitializeComponent();
        
        // Инициализация коллекции и привязка к ListBox
        students = new BindingList<Student>();
        listBoxStudents.DataSource = students;
    }

    private void btnAdd_Click(object sender, EventArgs e)
    {
        // Открытие дочерней формы в модальном режиме для создания нового студента
        using (StudentEditForm editForm = new StudentEditForm())
        {
            if (editForm.ShowDialog() == DialogResult.OK)
            {
                // Получаем созданный объект и добавляем в коллекцию
                students.Add(editForm.StudentData);
            }
        }
    }

    private void btnEdit_Click(object sender, EventArgs e)
    {
        // Проверка: выбран ли элемент в списке
        if (listBoxStudents.SelectedItem == null)
        {
            MessageBox.Show("Выберите студента для редактирования.", "Внимание", MessageBoxButtons.OK, MessageBoxIcon.Information);
            return;
        }

        // Получаем выбранного студента из списка
        Student selectedStudent = (Student)listBoxStudents.SelectedItem;

        // Открытие дочерней формы с передачей выбранного объекта через конструктор
        using (StudentEditForm editForm = new StudentEditForm(selectedStudent))
        {
            if (editForm.ShowDialog() == DialogResult.OK)
            {
                // Обновляем данные существующего объекта
                selectedStudent.FullName = editForm.StudentData.FullName;
                selectedStudent.Course = editForm.StudentData.Course;
                selectedStudent.AverageGrade = editForm.StudentData.AverageGrade;

                // Принудительное обновление отображения в ListBox для BindingList
                int index = listBoxStudents.SelectedIndex;
                students[index] = selectedStudent; 
            }
        }
    }

    private void btnDelete_Click(object sender, EventArgs e)
    {
        if (listBoxStudents.SelectedItem == null)
        {
            MessageBox.Show("Выберите студента для удаления.", "Внимание", MessageBoxButtons.OK, MessageBoxIcon.Information);
            return;
        }

        Student selectedStudent = (Student)listBoxStudents.SelectedItem;
        
        DialogResult result = MessageBox.Show(
            $"Вы действительно хотите удалить студента {selectedStudent.FullName}?", 
            "Подтверждение удаления", 
            MessageBoxButtons.YesNo, 
            MessageBoxIcon.Question);

        if (result == DialogResult.Yes)
        {
            students.Remove(selectedStudent);
        }
    }
}
```

### Тестирование приложения на граничных условиях

При проектировании интерфейсов с вводом данных пользователем необходимо учитывать следующие граничные условия:
1. **Пустой список при попытке редактирования или удаления:** если пользователь нажимает кнопку «Редактировать» или «Удалить», когда в `ListBox` нет элементов или ни один элемент не выбран (`SelectedItem == null`), программа не должна выбрасывать исключение `NullReferenceException`. Наличие предварительной проверки предотвращает аварийное завершение работы.
2. **Отмена ввода:** если пользователь заполнил поля в дочерней форме, но нажал «Отмена» или закрыл окно крестиком, `DialogResult` вернет значение `Cancel` (или `None`), и изменения не попадут в коллекцию главной формы.
3. **Некорректный формат данных:** при вводе среднего балла пользователь может ввести буквы или точку вместо запятой (в зависимости от локализации ОС). Использование метода `decimal.TryParse` вместо прямого преобразования `decimal.Parse` защищает приложение от сбоев при вводе некорректных символов.

```csharp
public class PizzaOrder

    }

    {
        string desc = SizeName;
        string extras = "";
        if (HasCheese) extras += " + сыр";
        if (HasMushrooms) extras += " + грибы";
        if (HasBacon) extras += " + бекон";

        }
```

## Типичные ошибки

1. **Обращение к элементам управления дочерней формы до вызова `Show()` или `ShowDialog()`**
   * *В чём ошибка:* Попытка написать `childForm.textBox1.Text = "значение";` сразу после создания объекта `childForm = new ChildForm();`.
   * *Почему возникает:* На этапе выполнения конструктора элементы управления ещё не созданы в оперативной памяти (дескриптор окна не инициализирован).
   * *Как избежать:* Передавайте данные через конструктор или публичные свойства формы, а присвоение значений элементам управления делайте внутри события `Load` самой дочерней формы.
   * *Пример:* `ChildForm f = new ChildForm(); f.textBox1.Text = "А"; f.Show();` вызовет `NullReferenceException`. Правильно: создать публичное свойство в `ChildForm`, записать в него данные, а внутри `ChildForm_Load` перенести значение в `textBox1`.

2. **Забытый вызов `InitializeComponent()` в пользовательском конструкторе**
   * *В чём ошибка:* Создание перегруженного конструктора в форме (`public MyForm(string data) { ... }`) без вызова `InitializeComponent();`.
   * *Почему возникает:* Разработчик думает, что раз конструктор перегружен, метод инициализации не нужен. В итоге визуальные элементы не создаются.
   * *Как избежать:* Всегда первой строкой в любом конструкторе формы вызывайте `InitializeComponent();`.
   * *Пример:* `public MyForm(string val) { _val = val; }` — элементы формы не появятся, приложение упадёт при обращении к ним.

3. **Забытый сброс ссылки на немодальное окно при его закрытии**
   * *В чём ошибка:* Открытие немодального окна через `form.Show();` без обнуления ссылки в переменной главной формы после того, как пользователь закрыл окно крестиком.
   * *Почему возникает:* Метод `Close()` уничтожает объект в памяти (он становится `Disposed`), но переменная в главной форме продолжает ссылаться на этот адрес. Повторный клик приводит к `ObjectDisposedException`.
   * *Как избежать:* Подписываться на событие `FormClosed` дочерней формы и обнулять ссылку: `form.FormClosed += (s, e) => { form = null; };`, либо проверять `form.IsDisposed`.
   * *Пример:* `if (myForm == null) { myForm = new MyForm(); myForm.Show(); }` — если пользователь закрыл окно крестиком, переменная не равна `null`, и следующая попытка открытия вызовет ошибку.

4. **Жёсткая привязка дочерней формы к главной через прямые ссылки**
   * *В чём ошибка:* Передача ссылки на `MainForm` в конструктор дочерней формы, чтобы из дочерней формы напрямую менять элементы родительской (например, `mainForm.label1.Text = ...`).
   * *Почему возникает:* Желание «быстро связать» окна без изучения механизмов возврата данных.
   * *Почему это плохо:* Нарушается инкапсуляция, дочернюю форму нельзя переиспользовать в других проектах, код становится хрупким.
   * *Как избежать:* Дочерняя форма должна возвращать данные через публичные свойства и `DialogResult`, а главная форма сама решает, куда их записать.

5. **Отсутствие проверки введённых данных перед возвратом из дочерней формы**
   * *В чём ошибка:* Считывание текста из `TextBox` в дочерней форме и возврат его главной форме без проверки на пустоту, пробелы или конвертацию в число (например, через `int.Parse` без обработки исключений).
   * *Почему возникает:* Расчёт на то, что пользователь всегда введёт идеальные данные.
   * *Как избежать:* Всегда проверять ввод через `int.TryParse`, `double.TryParse` или `string.IsNullOrWhiteSpace`, и в случае ошибки выводить предупреждение `MessageBox.Show`.
   * *Пример:* `int val = int.Parse(txtBox.Text);` вызовет крах программы, если пользователь введёт букву. Правильно использовать `if (!int.TryParse(txtBox.Text, out int val)) { ... }`.

6. **Создание бесконечного каскада модальных окон**
   * *В чём ошибка:* Из модального окна открывается второе модальное окно, из него третье и т. д. без возможности адекватного возврата назад.
   * *Почему возникает:* Ошибочное проектирование интерфейса.
   * *Как избежать:* Ограничивать глубину вложенности диалогов (максимум 1 уровень: Главная -> Диалог настройки). Если нужно много шагов — использовать один контейнер с переключаемыми панелями или элемент `TabControl`, либо паттерн «Мастер» (Wizard).

7. **Утечки памяти из-за невысвобожденных ресурсов дочерних форм**
   * *В чём ошибка:* Создание тяжёлых немодальных окон, таймеров или соединений в дочерней форме без вызова `Dispose()` при их закрытии.
   * *Почему возникает:* Непонимание жизненного цикла неуправляемых ресурсов.
   * *Как избежать:* Использовать конструкцию `using` для модальных окон (`using (MyForm f = new MyForm()) { f.ShowDialog(); }`) и переопределять метод `OnFormClosing` для очистки таймеров и потоков в немодальных окнах.

## Задачи для самостоятельного решения

1. **Задача 1 (Конструктор и передача строки):** Разработать приложение с двумя формами (`MainForm` и `GreetingForm`). На главной форме пользователь вводит своё имя в поле `TextBox`. При нажатии кнопки создаётся и открывается модально дочерняя форма, в конструктор которой передаётся введённая строка. Дочерняя форма должна отобразить на метке `Label` текст вида: `Приветствую вас, [Имя]!`. Если поле ввода было пустым, выводить `Приветствую вас, Гость!`.

2. **Задача 2 (Свойства и числовые настройки):** Создать приложение с главной формой и формой настроек `ConfigForm`. На главной форме хранится целочисленное значение ширины рабочей зоны (по умолчанию `500`). По клику на кнопку «Параметры» открывается `ConfigForm`, куда текущее значение передается через публичное свойство `WorkspaceWidth`. В дочерней форме пользователь изменяет это число через `NumericUpDown` (в диапазоне от `200` до `1000`) и нажимает кнопку «Сохранить» (`DialogResult.OK`). Главная форма после закрытия диалога считывает новое значение через свойство и изменяет свою ширину (`this.Width`).

3. **Задача 3 (Обратная связь и валидация текста):** На главной форме расположена кнопка «Запросить код подтверждения» и метка для вывода результата. При нажатии открывается дочерняя форма `CodeForm`, содержащая текстовое поле для ввода 4-значного числового кода и кнопку подтверждения. Дочерняя форма проверяет: если введённая строка состоит ровно из 4 цифр, она устанавливает `DialogResult = DialogResult.OK` и закрывается. Если нет — выводит предупреждение через `MessageBox` и не закрывается. Главная форма после успешного закрытия выводит полученный код на экран.

4. **Задача 4 (Немодальное окно с защитой от дублирования):** На главной форме есть кнопка «Открыть блокнот». По нажатию открывается немодальная форма `NoteForm` (метод `Show()`). Реализуйте проверку: если окно уже открыто, повторное нажатие кнопки не должно создавать новое окно, а должно переносить существующее на передний план (`BringToFront()`) и возвращать на него фокус (`Activate()`). При закрытии окна крестиком ссылка должна корректно обнуляться.

5. **Задача 5 (Передача объекта через свойства):** Создайте класс-модель `Student` с тремя свойствами: `FullName` (`string`), `Age` (`int`), `AverageScore` (`double`). На главной форме отображается список студентов (`ListBox`). По кнопке «Добавить студента» открывается модальная форма `StudentAddForm`. Пользователь вводит данные в три текстовых поля. Дочерняя форма формирует и заполняет объект `Student` (доступный через публичное свойство `NewStudent`), после чего закрывается с `DialogResult.OK`. Главная форма забирает готовый объект и добавляет его в `ListBox`.

6. **Задача 6 (Модальный диалог выбора цвета и возврат перечисления):** Разработать приложение, где главная форма имеет кнопку «Выбрать приоритет задачи». По нажатию открывается модальное окно `PriorityForm`, содержащее три радиокнопки: «Низкий» (возвращает `DialogResult.Abort`), «Средний» (возвращает `DialogResult.Retry`), «Высокий» (возвращает `DialogResult.Ignore`). В зависимости от возвращенного статического результата главная форма должна изменить цвет текста метки статуса (Низкий — зелёный, Средний — синий, Высокий — красный) и вывести соответствующий текст.

7. **Задача 7 (Комплексная задача с двусторонним общим состоянием):** Разработать редактор профиля пользователя. Главная форма хранит объект `UserProfile` (свойства: `Login`, `Email`, `IsSubscribed`). По кнопке «Редактировать профиль» создается форма `ProfileEditForm`, в которую через свойства передаётся текущий объект пользователя. Форма заполняет поля ввода (`TextBox` и `CheckBox`). Пользователь вносит изменения и нажимает «Сохранить». Форма проверяет, что `Email` содержит символ `@`. Если всё верно, возвращает `DialogResult.OK`, а главная форма обновляет отображаемые данные на экране.

## Ответы к задачам

1. При вводе имени «Иван» дочерняя форма выведет текст: `Приветствую вас, Иван!`. При пустом поле: `Приветствую вас, Гость!`.
2. При вводе значения `800` в `NumericUpDown` и нажатии «Сохранить» ширина главной формы (`Width`) установится ровно в `800` пикселей.
3. При вводе корректного кода `1234` диалог закроется с результатом `OK`, и главная форма отобразит текст: `Код подтверждения принят: 1234`. При вводе `12` появится предупреждение, окно останется открытым.
4. Программа позволяет открыть ровно один экземпляр немодального окна `NoteForm`. Любые последующие клики по кнопке открытия не создают новые окна, а активируют уже существующее. При закрытии крестиком ссылка обнуляется, при следующем клике окно создаётся заново.
5. При вводе в форму студента имени «Петров Алексей», возраста `20` и среднего балла `4.8`, в `ListBox` главной формы появится строка: `Петров Алексей (Возраст: 20, Балл: 4,8)`.
6. При выборе «Низкий» статусная метка окрашивается в зелёный цвет и выводит «Приоритет: Низкий». При выборе «Высокий» метка становится красной с текстом «Приоритет: Высокий».
7. При корректном заполнении полей и наличии символа `@` в почте главная форма успешно обновляет текстовые метки на экране новыми данными из объекта `UserProfile`. При отсутствии `@` выдаётся предупреждающее сообщение `MessageBox`.

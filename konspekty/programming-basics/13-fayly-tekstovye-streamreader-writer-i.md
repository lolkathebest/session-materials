## 1. Понятие файла и потока в .NET. Текстовые файлы: StreamReader и StreamWriter

### Понятие файла и потока в .NET

Любая программа в процессе своей работы оперирует данными, которые хранятся в оперативной памяти (ОЗУ). При завершении работы процесса или выключении питания компьютера эти данные стираются. Чтобы сохранять информацию между запусками программы, используется постоянная память — жесткие диски, твердотельные накопители (SSD) или флеш-накопители.

> **Определение.** **Файл** — это поименованная область данных на носителе информации (диске), рассматриваемая операционной системой как единое целое.

Файлы могут содержать тексты программ, документы, изображения, музыку или скомпилированные бинарные данные. Однако сама операционная система работает с физическими накопителями через блоки секторов, что неудобно для прикладного программиста. В платформе .NET для работы с данными на физическом уровне введена абстракция потока.

> **Определение.** **Поток (Stream)** — это абстракция для последовательной передачи байтов из источника в приемник (память, файл, сетевое соединение).

Поток скрывает от программиста особенности работы с конкретным устройством (будь то SSD, оперативная память или сетевой сокет). Данные в потоке можно представить как бесконечную или ограниченную ленту байтов, которые считываются или записываются последовательно друг за другом.

### Текстовые и двоичные данные

Все файлы на диске физически состоят из нулей и единиц (байтов). Однако способ интерпретации этих байтов разделяет все файлы на две большие категории: текстовые и двоичные.

*   **Текстовые данные** состоят из символов, которые человек может прочитать в текстовом редакторе (буквы, цифры, знаки препинания). Каждый символ закодирован в соответствии с определенной таблицей кодировки. Основной кодировкой в современном мире и в платформах .NET является **UTF-8**, которая является обратно совместимой с таблицей **ASCII**. В UTF-8 символы латинского алфавита занимают 1 байт, а символы кириллицы или других алфавитов — от 2 до 4 байт. Важной особенностью текстовых файлов является наличие специальных символов перевода строки, которые зависят от операционной системы (в Windows это пара управляющих символов `\r\n` — возврат каретки и перевод строки).
*   **Двоичные данные** представляют собой «сырые» байты, которые не предназначены для прямого чтения человеком. Числа, структуры и изображения сохраняются в том же виде, в котором они хранятся в оперативной памяти компьютера (например, целое число типа `int` занимает ровно 4 байта в двоичном представлении).

### Класс StreamWriter для записи текстовых файлов

Для записи текстовых данных в .NET предназначен класс `StreamWriter`, который находится в пространстве имен `System.IO`. Этот класс берет на себя сложную работу по преобразованию строк из кодировки UTF-16 (в которой строки хранятся в памяти C#) в байты выбранной текстовой кодировки и передаче их в нижележащий поток.

Создать экземпляр класса `StreamWriter` можно несколькими способами. Самый простой путь — передать в конструктор путь к файлу в виде строки:

```csharp
StreamWriter writer = new StreamWriter("output.txt");
```

Если файла с таким именем не существовало, он будет создан автоматически. Если файл уже существовал, его содержимое будет полностью стерто (перезаписано). Если вы хотите дописывать данные в конец существующего файла, нужно передать второй параметр — булево значение `true` (режим добавления — *append*):

```csharp
StreamWriter writerAppend = new StreamWriter("output.txt", true);
```

Основные методы класса `StreamWriter`:
1. `Write(...)` — записывает переданное значение (число, строку, символ) в поток без перевода строки на новую.
2. `WriteLine(...)` — записывает значение и автоматически добавляет символ перевода строки для текущей операционной системы.
3. `Flush()` — принудительно сбрасывает данные из внутреннего буфера оперативной памяти в файл на жесткий диск.

#### Механизм буферизации

Запись на жесткий диск — это относительно медленная операция ввода-вывода (I/O). Чтобы программа работала быстро, `StreamWriter` не записывает каждый символ на диск немедленно. Вместо этого он накапливает данные во временном хранилище в оперативной памяти — **буфере**. 

Когда буфер заполняется или когда вызывается метод `Close()` / `Dispose()`, пачка данных единовременно записывается на диск. Метод `Flush()` позволяет принудительно записать содержимое буфера на диск, не закрывая сам поток. Это полезно, например, при логировании, когда нужно убедиться, что аварийное сообщение записано в файл до падения программы.

### Класс StreamReader для чтения текстовых файлов

Для чтения текстовых файлов в пространстве имен `System.IO` предусмотрен класс-антагонист `StreamReader`. Он открывает файл и предоставляет удобные методы для извлечения символов и строк.

Создание объекта `StreamReader`:

```csharp
StreamReader reader = new StreamReader("output.txt");
```

Основные методы класса `StreamReader`:
1. `Read()` — считывает один следующий символ из потока и возвращает его код в виде целого числа (`int`). Если достигнут конец файла, возвращает `-1`.
2. `ReadLine()` — считывает одну строку текста (до символа перевода строки). Возвращает считанную строку в виде `string` или `null`, если файл закончился.
3. `ReadToEnd()` — считывает весь оставшийся текст от текущей позиции до самого конца файла в одну большую строку.

Для проверки того, дошли ли мы до конца файла, используется логическое свойство `EndOfStream`. Пока в файле есть непрочитанные данные, оно возвращает `false`, а как только достигнут конец — `true`.

Пример чтения файла построчно с помощью цикла `while`:

```csharp
using System;
using System.IO;

class Program
{
    static void Main()
    {
        StreamReader reader = new StreamReader("numbers.txt");
        
        while (!reader.EndOfStream)
        {
            string line = reader.ReadLine();
            Console.WriteLine(line);
        }
        
        reader.Dispose();
    }
}
```

### Управление ресурсами: Close, Dispose и конструкция using

Файлы в операционной системе являются ограниченным системным ресурсом. Когда ваша программа открывает файл для чтения или записи, операционная система устанавливает блокировку, предотвращая несанкционированный доступ со стороны других приложений. 

После завершения работы с файлом поток **обязательно нужно закрыть**, чтобы освободить дескрипторы операционной системы и сбросить буферы записи. 

Исторически для этого использовался метод `Close()` или вызов метода `Dispose()`, который является реализацией интерфейса `IDisposable`. Однако прямой вызов этих методов чреват ошибками: если в процессе записи данных в программе произойдет исключение (например, не хватило места на диске), выполнение программы прервется, строка с вызовом `Close()` не выполнится, и файл останется заблокированным.

Чтобы гарантировать освобождение ресурсов даже в случае возникновения ошибок, используется блок `try-finally`:

```csharp
StreamWriter writer = new StreamWriter("test.txt");
try
{
    writer.WriteLine("Пример текста");
}
finally
{
    // Блок finally выполнится в любом случае: и при успехе, и при ошибке
    writer.Dispose();
}
```

Поскольку конструкция `try-finally` при работе с потоками пишется очень часто, в языке C# был создан синтаксический сахар — оператор `using`. 

В современных версиях C# (.NET 8) используется наиболее лаконичный синтаксис — **declaration using** (объявление с помощью using). Переменная объявляется с ключевым словом `using`, и компилятор автоматически генерирует вызов метода `Dispose()` в самом конце той области видимости (фигурных скобок `{ }`), в которой эта переменная была объявлена:

```csharp
using StreamWriter writer = new StreamWriter("numbers.txt");
writer.WriteLine("Строка в файле");
// Здесь компилятор автоматически вызовет writer.Dispose(), 
// даже если внутри блока возникли исключения.
```

### Обработка базовых исключений файловой системы

Операции ввода-вывода (I/O) подвержены множеству внешних факторов: файл может быть удален другим приложением, у пользователя может не быть прав на запись в системную папку, или на диске может закончится свободное место. Все эти внештатные ситуации приводят к генерации исключений.

Базовым классом для всех ошибок ввода-вывода является `IOException`. Иерархия исключений позволяет перехватывать конкретные проблемы:

1. `DirectoryNotFoundException` — генерируется, если указанный путь к каталогу не существует (например, вы пытаетесь записать файл по пути `"C:\\NonExistentFolder\\file.txt"`, а папка не создана).
2. `FileNotFoundException` — генерируется, когда вы пытаетесь открыть для чтения файл, которого физически нет на диске.
3. `UnauthorizedAccessException` — генерируется, если у программы нет прав доступа к файлу или папке (например, попытка записи в защищенную системную папку `C:\Windows`).

Для безопасной работы с файлами код чтения и записи всегда следует оборачивать в блок `try-catch`:

```csharp
using System;
using System.IO;

class Program
{
    static void Main()
    {
        try
        {
            using StreamReader reader = new StreamReader("non_existent.txt");
            string content = reader.ReadToEnd();
            Console.WriteLine(content);
        }
        catch (FileNotFoundException)
        {
            Console.WriteLine("Ошибка: Запрашиваемый файл не найден на диске.");
        }
        catch (UnauthorizedAccessException)
        {
            Console.WriteLine("Ошибка: Недостаточно прав для чтения файла.");
        }
        catch (IOException ex)
        {
            Console.WriteLine($"Произошла ошибка ввода-вывода: {ex.Message}");
        }
    }
}
```

### Разобранный пример

#### Условие задачи
Написать консольную программу на C#, которая создает текстовый файл `"numbers.txt"`, записывает в него таблицу квадратов целых чисел от 1 до 10 в формате `"x | x^2"`, а затем читает этот файл построчно и выводит содержимое в консоль.

#### Рисунок словами (схема работы программы)
```
[Оперативная память]                              [Диск компьютера]
  Цикл от 1 до 10 ----> StreamWriter ----(UTF-8)----> Файл "numbers.txt"
                                                           │
  Консоль <------------- StreamReader <--------------------┘
  (Вывод каждой строки на экран)
```

#### Ход рассуждений
1.  **Создание файла и запись:** Нам понадобятся классы `StreamWriter` и конструкция `using` для безопасного открытия файла `"numbers.txt"` на запись.
2.  **Формирование данных:** Используем классический цикл `for`, параметром которого будет переменная `x` от 1 до 10 включительно. На каждой итерации цикла мы вычисляем квадрат числа: `int square = x * x;`.
3.  **Форматирование строки:** С помощью интерполяции строк сформируем строку вида `"x | x^2"`, например: `" 1 | 1"`, `" 2 | 4"` и т.д. Запишем её в файл методом `WriteLine`.
4.  **Чтение файла:** После завершения блока записи (первый `using` завершит свою работу и закроет файл), открываем тот же самый файл для чтения с помощью `StreamReader` в новом блоке `using`.
5.  **Вывод в консоль:** Используем цикл `while (!reader.EndOfStream)`, внутри которого считываем каждую строку методом `ReadLine()` и выводим её в консоль (`Console.WriteLine`).

#### Решение в коде (полная программа)

```csharp
using System;
using System.IO;

class Program
{
    static void Main()
    {
        string filePath = "numbers.txt";

        // Шаг 1. Запись таблицы квадратов в файл
        try
        {
            // Используем using declaration для автоматического закрытия файла
            using StreamWriter writer = new StreamWriter(filePath);

            writer.WriteLine("x | x^2");
            writer.WriteLine("---------");

            for (int x = 1; x <= 10; x++)
            {
                int square = x * x;
                // Записываем форматированную строку
                writer.WriteLine($"{x, 2} | {square, 3}");
            }

            Console.WriteLine("Файл успешно создан и заполнен данными.");
        }
        catch (UnauthorizedAccessException)
        {
            Console.WriteLine("Ошибка доступа: нет прав на запись файла.");
            return;
        }
        catch (IOException ex)
        {
            Console.WriteLine($"Ошибка ввода-вывода при записи: {ex.Message}");
            return;
        }

        Console.WriteLine("\nСодержимое файла, прочитанное с диска:\n");

        // Шаг 2. Чтение файла и вывод на консоль
        try
        {
            using StreamReader reader = new StreamReader(filePath);

            while (!reader.EndOfStream)
            {
                string? line = reader.ReadLine();
                if (line != null)
                {
                    Console.WriteLine(line);
                }
            }
        }
        catch (FileNotFoundException)
        {
            Console.WriteLine("Ошибка: файл не найден.");
        }
        catch (IOException ex)
        {
            Console.WriteLine($"Ошибка ввода-вывода при чтении: {ex.Message}");
        }
    }
}
```

#### Проверка и вычисление
1.  **Единицы измерения:** В операциях с файлами объемы измеряются в байтах и символах. Программа оперирует символами кодировки UTF-8 и логическими строками.
2.  **Правдоподобие:** Алгоритм использует правильные границы цикла (`x` от 1 до 10 включительно), форматирует вывод с выравниванием (`{x, 2}` выделяет 2 символа под число, обеспечивая красивое визуальное выравнивание таблицы). Ресурсы освобождаются через конструкцию `using`, что исключает блокировку файлов. Предусмотрена обработка базовых исключений ввода-вывода.

#### Пример вывода программы в консоли:
```text
Файл успешно создан и заполнен данными.

Содержимое файла, прочитанное с диска:

x | x^2
---------
 1 |   1
 2 |   4
 3 |   9
 4 |  16
 5 |  25
 6 |  36
 7 |  49
 8 |  64
 9 |  81
10 | 100
```

`Ответ:` Программа успешно создает текстовый файл `numbers.txt`, записывает в него таблицу квадратов чисел от 1 до 10 с выравниванием по правому краю, после чего корректно считывает данные построчно и выводит их в консоль без утечки системных дескрипторов.

## 2. Двоичные файлы: BinaryWriter и BinaryReader

### Сущность двоичных файлов и отличие от текстовых

В предыдущей теме мы рассматривали текстовые файлы, в которых любые данные — будь то целые числа, вещественные значения или логические флаги — перед записью на диск преобразуются в последовательность символов человекочитаемого алфавита (в кодировке UTF-8 или ASCII). Например, число `12345` в текстовом файле занимает $5$ байт (каждая цифра кодируется одним байтом), а число `3{,}14159265` превращается в строку из десяти символов и занимает $10$ байт.

> **Определение.** Двоичный (бинарный) файл — это файл, данные в котором хранятся в том же машинном представлении, в каком они размещаются в оперативной памяти компьютера (в виде «сырых» байтов), без промежуточного преобразования в текстовые символы.

При двоичном подходе целое число типа `int` (в C# это 32-битное знаковое целое число) всегда занимает ровно $4$ байта на диске, независимо от того, храним ли мы число `5` или число `2147483647`. Вещественное число двойной точности `double` всегда занимает ровно $8$ байт. 

Главные достоинства двоичных файлов:
1. **Компактность:** Числа и структуры занимают строго фиксированный и часто меньший объем памяти на диске.
2. **Скорость работы:** Отсутствует ресурсоёмкая стадия парсинга (преобразования строк в числа и обратно). Данные читаются и записываются мгновенно, так как процессор и память оперируют ими напрямую.

Для работы с двоичными потоками в платформе .NET предусмотрены специализированные обёртки (декораторы): классы `BinaryWriter` и `BinaryReader` из пространства имен `System.IO`.

---

### Класс BinaryWriter: запись примитивных типов

Класс `BinaryWriter` предназначен для последовательной записи примитивных типов данных в базовый поток (обычно это экземпляр класса `FileStream`). Сам по себе `BinaryWriter` не знает, как открывать файлы на диске; он лишь принимает в свой конструктор уже готовый поток и переводит вызовы удобных методов (таких как `Write`) в последовательность байтов.

Чтобы создать объект `BinaryWriter`, необходимо передать в его конструктор открытый поток `FileStream`:

```csharp
using System.IO;

// Открываем файл для создания или перезаписи
FileStream fs = new FileStream("data.bin", FileMode.Create, FileAccess.Write);
BinaryWriter writer = new BinaryWriter(fs);
```

В языке C# (начиная с версии 8.0) принято использовать сокращенную форму записи с помощью ключевого слова `using`, которая гарантирует автоматическое освобождение системных ресурсов и закрытие файла даже в случае возникновения исключений:

```csharp
using (BinaryWriter writer = new BinaryWriter(File.Open("data.bin", FileMode.Create)))
{
    // Здесь выполняются операции записи
}
```

Класс `BinaryWriter` предоставляет перегруженный метод `Write()` для записи всех основных встроенных типов данных C#:
- `writer.Write(int value)` — записывает 4-байтовое целое число.
- `writer.Write(double value)` — записывает 8-байтовое вещественное число.
- `writer.Write(bool value)` — записывает логическое значение ($1$ байт: `0` для `false`, `1` для `true`).
- `writer.Write(char value)` — записывает символ (в зависимости от кодировки UTF-8 может занимать от $1$ до $4$ байт).
- `writer.Write(string value)` — записывает строку.

#### Особенности записи строк в BinaryWriter

Запись строк в бинарный поток имеет важную внутреннюю специфику. В отличие от сырых чисел фиксированной длины, строка может содержать разное количество символов. Если просто записать байты строки на диск, то при чтении программы будет непонятно, где заканчивается одна строка и начинается другая.

Поэтому `BinaryWriter` перед текстом самой строки автоматически записывает так называемый префикс — длину строки в байтах, закодированную в специальном компактном формате (`7-bit encoded int`). Сами символы строки кодируются в UTF-8. 

> **Правило.** Метод `writer.Write(string)` записывает в файл сначала длину строки в байтах, а затем сами символы строки. Это позволяет корректно прочитать строку обратно без использования дополнительных разделителей (например, символов перевода строки).

---

### Класс BinaryReader: чтение примитивных типов

Для восстановления данных из двоичного файла используется парный класс `BinaryReader`. Он также создается поверх существующего потока `FileStream`:

```csharp
using (BinaryReader reader = new BinaryReader(File.Open("data.bin", FileMode.Open)))
{
    // Здесь выполняются операции чтения
}
```

Для каждого метода записи в `BinaryWriter` существует строго соответствующий метод чтения в `BinaryReader`:
- `reader.ReadInt32()` — считывает $4$ байта и возвращает значение типа `int`.
- `reader.ReadDouble()` — считывает $8$ байт и возвращает значение типа `double`.
- `reader.ReadBoolean()` — считывает $1$ байт и возвращает `bool`.
- `reader.ReadChar()` — считывает символ.
- `reader.ReadString()` — сначала считывает длину строки, а затем извлекает указанное количество байт и формирует объект `string`.

#### Порядок чтения двоичных данных

Это критически важное правило при работе с бинарными файлами:

> **Важно.** Порядок вызова методов чтения в `BinaryReader` должен **абсолютно точно** соответствовать порядку вызова методов записи в `BinaryWriter`. 

В двоичном файле нет меток типов данных (нет заголовков, говорящих «здесь лежит число `int`, а дальше строка»). Файл представляет собой сплошной поток байтов. Если вы записали в файл сначала `int`, а потом `double`, то при чтении вы обязаны сначала вызвать `ReadInt32()`, а затем `ReadDouble()`. Если вы попытаетесь прочитать эти же байты в обратном порядке (`ReadDouble()`, а затем `ReadInt32()`), программа не выдаст ошибку компиляции, но байты интерпретируются неверно, что приведет к появлению случайных чисел («мусора») или выбросу исключения `EndOfStreamException`.

---

### Сравнение текстового и двоичного представления

Рассмотрим наглядный пример. Пусть у нас есть массив из трех целых чисел: `100`, `200000`, `-5`.

1. **Текстовое представление (например, через StreamWriter):**
   Числа записываются через пробел или перевод строки в виде текста: `"100 200000 -5"`.
   - Символ `'1'` — 1 байт
   - Символ `'0'` — 1 байт
   - Символ `'0'` — 1 байт
   - Пробел — 1 байт
   - Символы числа `200000` — 6 байт
   - Пробел — 1 байт
   - Знак `'-'` — 1 байт
   - Символ `'5'` — 1 байт
   **Итого:** $12$ байт (плюс символы перевода строки, если числа записаны на разных строках).

2. **Двоичное представление (через BinaryWriter):**
   Каждое число типа `int` занимает строго $4$ байта независимо от своего значения.
   - Число `100` — 4 байта
   - Число `200000` — 4 байта
   - Число `-5` — 4 байта
   **Итого:** ровно $12$ байт.

Для малых чисел текстовый формат может оказаться компактнее (число `5` в тексте займет $1$ байт, а в бинарном `int` — всегда $4$ байта). Однако для больших чисел, вещественных чисел с высокой точностью (`double` занимает $8$ байт в двоичном виде и до $24$ символов/байт в текстовом) и массивов данных двоичный формат значительно эффективнее по объему и производительности.

### Разобранный пример: запись и чтение массива вещественных чисел с заголовком

#### Условие задачи
Написать программу на C#, которая записывает в бинарный файл `"data.bin"` заголовок (целое число — количество элементов, равное $5$) и массив из $5$ вещественных чисел типа `double` с помощью `BinaryWriter`, а затем читает их с помощью `BinaryReader`, вычисляя и выводя в консоль их сумму.

#### Рисунок словами (схема работы программы)
1. Создается массив вещественных чисел: `[12{,}5; -3{,}2; 45{,}0; 0{,}75; 8{,}1]`.
2. Открывается файл `"data.bin"` на запись.
3. В файл записывается число `5` (тип `int`, занимает $4$ байта).
4. В цикле в файл записываются все 5 элементов массива (каждый типа `double`, занимает $8$ байт). Всего записано $4 + 5 \times 8 = 44$ байта.
5. Файл закрывается.
6. Открывается тот же файл `"data.bin"` на чтение.
7. Считывается первое число — количество элементов (`int`). Получаем `5`.
8. Запускается цикл от $0$ до $4$, в котором считывается каждое следующее число (`double`), накапливается их общая сумма.
9. Выводится результат в консоль.

#### Ход рассуждений и обоснование
- Для работы с файлами подключаем пространство имен `System.IO`.
- Используем конструкцию `using` для автоматического закрытия потоков.
- При чтении мы обязаны строго соблюдать порядок: сначала считываем количество элементов (`ReadInt32`), а затем организуем цикл чтения вещественных чисел (`ReadDouble`) ровно столько раз, сколько указано в заголовочной переменной. Это универсальный подход: программа не зашивает размер массива «намертво», а динамически адаптируется под данные, хранящиеся внутри файла.

#### Полный код программы

```csharp
using System;
using System.IO;

class Program
{
    static void Main()
    {
        string filePath = "data.bin";

        // --- ЭТАП 1: Запись данных в двоичный файл ---
        // Исходный массив из 5 вещественных чисел
        double[] sourceArray = { 12.5, -3.2, 45.0, 0.75, 8.1 };
        int count = sourceArray.Length;

        try
        {
            // Открываем файл для записи (FileMode.Create создаст новый файл или перезапишет существующий)
            using (BinaryWriter writer = new BinaryWriter(File.Open(filePath, FileMode.Create)))
            {
                // Записываем заголовок — количество элементов (4 байта)
                writer.Write(count);

                // Записываем элементы массива поочередно (каждый по 8 байт)
                for (int i = 0; i < count; i++)
                {
                    writer.Write(sourceArray[i]);
                }
            }
            Console.WriteLine("Данные успешно записаны в бинарный файл.");
        }
        catch (IOException ex)
        {
            Console.WriteLine($"Ошибка при записи файла: {ex.Message}");
            return;
        }

        // --- ЭТАП 2: Чтение данных из двоичного файла ---
        double sum = 0.0;
        int readCount = 0;

        try
        {
            // Открываем файл для чтения
            using (BinaryReader reader = new BinaryReader(File.Open(filePath, FileMode.Open)))
            {
                // Считываем заголовок (количество элементов). 
                // Порядок строго соответствует записи: сначала int, затем double.
                readCount = reader.ReadInt32();
                Console.WriteLine($"Количество элементов в файле: {readCount}");

                // Считываем массив чисел из файла и суммируем их
                for (int i = 0; i < readCount; i++)
                {
                    double value = reader.ReadDouble();
                    sum += value;
                    Console.WriteLine($"Элемент [{i}] = {value}");
                }
            }
        }
        cept (EndOfStreamException)
        {
            Console.WriteLine("Ошибка: попытка прочитать больше данных, чем содержится в файле.");
        }
        catch (IOException ex)
        {
            Console.WriteLine($"Ошибка при чтении файла: {ex.Message}");
            return;
        }

        // --- ЭТАП 3: Вывод результатов ---
        Console.WriteLine($"\nСумма всех элементов массива: {sum}");
    }
}
```

*Примечание к коду:* Блоки `catch (EndOfStreamException)` защищают программу от ситуаций, когда файл поврежден или обрезав, и в нем оказалось меньше байт, чем ожидает алгоритм чтения.

#### Проверка и вычисление контрольной суммы
Проверим вычисления вручную по исходному массиву:
$$12{,}5 + (-3{,}2) = 9{,}3$$
$$9{,}3 + 45{,}0 = 54{,}3$$
$$54{,}3 + 0{,}75 = 55{,}05$$
$$55{,}05 + 8{,}1 = 63{,}15$$

Ожидаемая сумма: `63,15`. Программа корректно выполнит сложение в памяти компьютера с плавающей запятой стандарта IEEE 754.

#### Пример консольного вывода
```text
Данные успешно записаны в бинарный файл.
Количество элементов в файле: 5
Элемент [0] = 12,5
Элемент [1] = -3,2
Элемент [2] = 45
Элемент [3] = 0,75
Элемент [4] = 8,1

Сумма всех элементов массива: 63,15
```

Ответ: Сумма элементов массива равна `63{,}15`.

## 3. Прямой доступ к файлу: класс FileStream и позиционирование

### Архитектура класса FileStream и работа с байтами на низком уровне

Ранее мы рассматривали высокоуровневые обертки для работы с файлами: `StreamReader` и `StreamWriter` оперируют текстовыми символами и строками, а `BinaryReader` и `BinaryWriter` преобразуют примитивные типы данных в байты автоматически. Однако в системном программировании часто возникает задача управления данными на самом низком уровне — уровне сырых байтов. 

Для этой цели в платформе .NET предусмотрен класс `FileStream`. 

> **Определение.** Класс `FileStream` — это низкоуровневый поток данных, который обеспечивает чтение и запись байтов в файлы, расположенные на диске или в других устройствах хранения, поддерживающих файловую систему.

Архитектура `FileStream` напрямую взаимодействует с операционной системой через дескриптор файла. В отличие от `StreamReader`, который считывает данные блоками в буфер и выполняет сложный анализ кодировок (например, UTF-8), `FileStream` оперирует массивами байтов (`byte[]`) и целыми числами без знака или со знаком, выполняя операции ввода-вывода максимально быстро и без дополнительных накладных расходов на трансформацию типов.

Важной особенностью `FileStream` является поддержка **произвольного доступа** (random access). По умолчанию большинство потоков работают в последовательном режиме: прочитал байт — указатель сместился вперед, вернуться назад нельзя. `FileStream` позволяет управлять позицией указателя чтения и записи в любой момент времени, переходя к любой точке файла за фиксированное число операций.

---

### Параметры конструктора FileStream

Чтобы создать экземпляр класса `FileStream`, необходимо задействовать один из его конструкторов. Наиболее гибкий и часто используемый конструктор принимает следующие аргументы:

```csharp
FileStream fs = new FileStream(string path, FileMode mode, FileAccess access, FileShare share);
```

Разберем каждый параметр подробно:

1. **`path` (тип `string`)** — путь к файлу на диске. Может быть абсолютным (`"C:\\Data\\records.dat"`) или относительным (`"records.dat"`).
2. **`mode` (тип перечисления `FileMode`)** — определяет, как именно следует открыть или создать файл. Основные значения:
   - `FileMode.CreateNew` — создает новый файл. Если файл уже существует, выбрасывается исключение `IOException`.
   - `FileMode.Create` — создает новый файл. Если файл существует, он перезаписывается (его старое содержимое стирается).
   - `FileMode.Open` — открывает существующий файл. Если файла нет, выбрасывается исключение `FileNotFoundException`.
   - `FileMode.OpenOrCreate` — открывает файл, если он существует. Если его нет, создает новый.
   - `FileMode.Truncate` — открывает существующий файл и очищает его содержимое (размер становится равным нулю).
   - `FileMode.Append` — открывает файл для дописывания данных в конец. Указатель автоматически устанавливается в конец файла. Применим только совместно с доступом на запись (`FileAccess.Write`).
3. **`access` (тип перечисления `FileAccess`)** — определяет права доступа к файлу:
   - `FileAccess.Read` — только чтение.
   - `FileAccess.Write` — только запись.
   - `FileAccess.ReadWrite` — чтение и запись.
4. **`share` (тип перечисления `FileShare`)** — определяет уровень совместного доступа к файлу для других процессов или потоков ОС:
   - `FileShare.None` — запрещает любой другой процесс открывать файл до тех пор, пока текущий поток не закроет его.
   - `FileShare.Read` — разрешает другим процесса открывать файл только для чтения.
   - `FileShare.Write` — разрешает другим процесса открывать файл для записи.
   - `FileShare.ReadWrite` — разрешает чтение и запись одновременно.

---

### Позиционирование в файле: указатель потока

В любой момент времени работы с `FileStream` внутри операционной системы существует **указатель потока** (stream pointer, или файловая позиция). Это целое число типа `long`, которое указывает на смещение в байтах от начала файла (начиная с нулевого байта).

- Когда вы открываете файл с режимом `FileMode.Open`, указатель автоматически устанавливается на позицию $0$ (самый первый байт файла).
- Когда вы записываете в файл $N$ байтов, указатель смещается ровно на $N$ позиций вправо (его значение увеличивается на $N$).
- Когда вы читаете $K$ байтов, указатель также сдвигается на $K$ позиций вправо.

Для управления этой позицией используются специальные свойства и методы класса `FileStream`.

#### Свойство Position

Свойство `Position` возвращает или устанавливает текущую позицию указателя в байтах. Тип данных свойства — `long`.

Пример чтения или изменения текущей позиции:

```csharp
// Узнать текущую позицию
long currentOffset = fs.Position;

// Переместить указатель ровно на 16-й байт от начала файла
fs.Position = 16;
```

#### Метод Seek

Если требуется сместить указатель относительно текущей позиции, конца файла или его начала более гибким способом, используется метод `Seek`:

```csharp
public override long Seek(long offset, SeekOrigin origin)
```

Параметры метода:
- `offset` (тип `long`) — величина смещения в байтах. Может быть положительным (смещение вперед) или отрицательным (смещение назад).
- `origin` (тип перечисления `SeekOrigin`) — точка отсчета для смещения:
  - `SeekOrigin.Begin` — отсчет ведется от начала файла (позиция $0$).
  - `SeekOrigin.Current` — отсчет ведется от текущей позиции указателя потока.
  - `SeekOrigin.End` — отсчет ведется от конца файла (требует, как правило, отрицательных значений `offset`).

Метод `Seek` возвращает новое абсолютное значение позиции указателя от начала файла в байтах.

Примеры использования `Seek`:

```csharp
// Переместиться на 10 байт вперед от начала файла
fs.Seek(10, SeekOrigin.Begin);

// Сместиться на 4 байта назад от текущей позиции
fs.Seek(-4, SeekOrigin.Current);

// Переместиться на 8 байт до конца файла (для чтения последних данных)
fs.Seek(-8, SeekOrigin.End);
```

#### Свойство Length

Чтобы узнать суммарный размер файла в байтах, используется свойство `Length`:

```csharp
long totalBytes = fs.Length;
Console.WriteLine($"Размер файла: {totalBytes} баййт.");
```

Свойство `Length` доступно только для чтения.

### Чтение и запись буфера байтов

Поскольку `FileStream` оперирует сырыми байтами, основные методы ввода-вывода принимают в качестве аргумента массив байтов `byte[]`.

#### Метод Write

Метод записывает последовательность байтов из массива в файл:

```csharp
public override void Write(byte[] buffer, int offset, int count)
```

- `buffer` — массив байтов, содержащий данные для записи.
- `offset` — индекс элемента в массиве `buffer`, с которого начинается запись (обычно равен $0$).
- `count` — количество байтов, которые нужно записать из массива в файл.

Пример записи массива байтов:

```csharp
byte[] data = { 10, 20, 30, 40 };
fs.Write(data, 0, data.Length); // записывает все 4 байта
```

#### Метод Read

Метод считывает порцию байтов из файла в заранее подготовленный массив:

```csharp
public override int Read(byte[] buffer, int offset, int count)
```

- `buffer` — массив-приемник, куда будут записаны прочитанные байты.
- `offset` — индекс в массиве `buffer`, начиная с которого будут сохраняться прочитанные данные.
- `count` — максимальное количество байтов, которое требуется прочитать.

Метод возвращает реальное количество прочитанных байтов (тип `int`). Если файл закончился и чтение невозможно, метод возвращает `0`.

### Разобранный пример: работа с фиксированной длиной записей

Рассмотрим комплексную задачу, демонстрирующую создание файла фиксированной структуры, запись данных, изменение конкретного элемента с помощью позиционирования (`Position` и `Seek`) и выборочное чтение.

#### Условие задачи

Написать программу на C#, которая создает файл фиксированной длины `"records.dat"`, записывает в него $3$ целых $4$-байтовых числа (значения: $10$, $20$, $30$), используя `FileStream`. Затем с помощью свойства `Position` и метода `Seek` программа должна изменить второе число на значение $99$ и считать его отдельно, выведя результат в консоль.

#### Ход рассуждений

1. **Представление данных в памяти.** Целое число типа `int` в платформе .NET занимает ровно $4$ байта в памяти (в соответствии со стандартным представлением Int32). Следовательно, файл из трех таких чисел будет иметь фиксированный размер $3 \times 4 = 12$ байт.
2. **Преобразование типов.** `FileStream` записывает байты, а не числа напрямую. Для перевода числа типа `int` в массив из $4$ байт удобнее всего использовать статический класс `BitConverter` (`BitConverter.GetBytes(int value)`), который возвращает `byte[]` длиной $4$ байта. Обратное преобразование из массива байтов обратно в число выполняется методом `BitConverter.ToInt32(byte[] buffer, int startIndex)`.
3. **Запись данных.** Открываем `FileStream` в режиме создания (`FileMode.Create`) с доступом на чтение и запись (`FileAccess.ReadWrite`). Последовательно преобразуем числа $10$, $20$ и $30$ в байты и записываем их в поток методом `Write`.
4. **Поиск и изменение второго числа.** 
   - Первое число занимает байты с индекса $0$ по $3$.
   - Второе число занимает байты с индекса $4$ по $7$.
   - Чтобы изменить второе число, нам нужно установить указатель потока ровно на $4$-й байт. Это можно сделать двумя способами: присвоить `fs.Position = 4;` или вызвать `fs.Seek(4, SeekOrigin.Begin);`.
   - Превращаем число $99$ в массив байтов и записываем его поверх старого значения методом `Write`.
5. **Выборочное чтение.** Указатель потока после записи сдвинулся на позицию $8$. Чтобы прочитать измененное второе число, мы снова возвращаем указатель на позицию $4$, считываем $4$ байта в буфер и преобразуем их обратно в `int`.

#### Полный код программы

```csharp
using System;
using System.IO;

class Program
{
    static void Main()
    {
        string filePath = "records.dat";

        // Шаг 1. Создание файла и запись трех чисел (10, 20, 30)
        // Используем конструкцию using для автоматического освобождения ресурсов потока
        using (FileStream fs = new FileStream(filePath, FileMode.Create, FileAccess.ReadWrite))
        {
            int[] initialValues = { 10, 20, 30 };

            Console.WriteLine("Запись исходных данных в файл...");
            foreach (int value in initialValues)
            {
                // Преобразуем int (4 байта) в массив байтов
                byte[] buffer = BitConverter.GetBytes(value);
                
                // Записываем байты в файл
                fs.Write(buffer, 0, buffer.Length);
            }

            Console.WriteLine($"Общий размер файла после записи: {fs.Length} байт.\n");

            // Шаг 2. Изменение второго числа (оно находится со смещением 4 байта от начала)
            // Первое число занимает байты 0-3, второе — байты 4-7.
            Console.WriteLine("Перемещаем указатель на второе число (смещение 4 байта)...");
            
            // Используем свойство Position для прямого перехода
            fs.Position = 4; 
            
            // Альтернативный вариант через Seek:
            // fs.Seek(4, SeekOrigin.Begin);

            int newValue = 99;
            byte[] newBuffer = BitConverter.GetBytes(newValue);

            // Перезаписываем 4 байта на новой позиции
            fs.Write(newBuffer, 0, newBuffer.Length);
            Console.WriteLine($"Второе число успешно изменено на {newValue}.\n");

            // Шаг 3. Выборочное чтение измененного второго числа обратно
            Console.WriteLine("Чтение измененного второго числа из файла...");
            
            // Возвращаем указатель обратно к началу второго числа (индекс 4)
            fs.Seek(4, SeekOrigin.Begin);

            // Создаем буфер для чтения ровно 4 байт
            byte[] readBuffer = new byte[4];
            
            // Читаем данные в буфер
            int bytesRead = fs.Read(readBuffer, 0, 4);

            if (bytesRead == 4)
            {
                // Преобразуем байты обратно в целое число
                int resultNumber = BitConverter.ToInt32(readBuffer, 0);
                
                Console.WriteLine($"Прочитанное число со смещения 4: {resultNumber}");
            }
            else
            {
                Console.WriteLine("Ошибка: не удалось прочитать нужное количество байтов.");
            }
        }

        // Ожидание завершения работы консоли
        Console.WriteLine("\nПрограмма завершена успешно.");
    }
}
```

#### Проверка и анализ результатов

- **Единицы измерения:** Все смещения и размеры измеряются в байтах (`long` для позиций, `int` для количества байтов). Размер типа `int` в C# строго детерминирован и равен $4$ байтам, что гарантирует предсказуемое смещение: запись под номером $i$ (нумерация с нуля) начинается со смещения $i \times 4$.
- **Правдоподобие:** Файл содержит три числа, общая длина файла составляет ровно $12$ байт. При обращении к индексу $4$ мы попадаем строго на границу второго элемента, не затрагивая первый и третий элементы. Программа корректно переводит число в байты и обратно с помощью `BitConverter`, учитывая системный порядок байтов (endianness).

`Ответ:` Программа создает файл `records.dat` размером $12$ байт, успешно изменяет второе число с $20$ на $99$, а затем выборочно считывает его, выводя в консоль значение `99`.

## 4. Комплексная обработка файлов: структурированные данные и поиск

### 4.1. Моделирование хранения сложных структур данных и выбор стратегии

Когда в программе требуется работать не с единичными примитивными значениями (числами или строками), а с целыми предметными сущностями (например, карточками товаров, профилями пользователей или записями о студентах), возникает задача сериализации (сохранения в постоянную память) и десериализации (восстановления в оперативной памяти) сложных структур.

В языке C# для представления таких сущностей чаще всего используют структуры (`struct`) или классы (`class`). Рассмотрим классический пример — структуру `Student`:

```csharp
public struct Student
{
    public string LastName;
    public int GroupNumber;
    public double AverageScore;
}
```

Перед разработчиком встает фундаментальный выбор: в каком формате сохранять массив или коллекцию таких объектов на диск? Существует два основных подхода:
1. **Текстовый формат с разделителями (например, CSV — Comma-Separated Values).** Каждый объект записывается в виде текстовой строки, поля разделяются специальным символом (запятая, точка с запятой, табуляция).
   * *Плюсы:* Человекочитаемость (файл можно открыть в блокноте или Excel и исправить руками), простота отладки.
   * *Минусы:* Больший объем занимаемой памяти, необходимость трудоемкого парсинга (разбора строк) при чтении, проблемы с конвертацией чисел и разделителями целой/дробной части (в разных локалях торг-запятая отличается).
2. **Бинарный формат.** Данные записываются в виде сырой последовательности байтов в соответствии с их машинными представлениями (через `BinaryWriter` или `FileStream`).
   * *Плюсы:* Компактность, высокое быстродействие (нет накладных расходов на текстовое преобразование и парсинг), возможность организации записей фиксированной длины для мгновенного прямого доступа.
   * *Минусы:* Полная нечитаемость файла без специализированной программы, жесткая зависимость от порядка байтов и структуры полей.

> **Правило выбора стратегии.** Если файл предназначен для обмена данными с другими системами или пользователем — используют текстовые форматы (JSON, CSV). Если требуется максимальная производительность, компактность и хранение массивов внутренних структур внутри приложения — используют бинарные файлы.

---

### 4.2. Алгоритм поиска и обновления записи в бинарном файле

Одно из главных преимуществ бинарных файлов с записями **фиксированной длины** — возможность изменять конкретный элемент на диске, не перезаписывая весь файл целиком. 

Пусть у нас есть файл, состоящий из записей фиксированного размера. Размер одной записи в байтах строго постоянн. Например, если строка `LastName` сохраняется фиксированной длиной в $50$ байт (в кодировке UTF-8), `GroupNumber` занимает $4$ байта (`int`), а `AverageScore` занимает $8$ байт (`double`), то общая длина одной записи на диске составит:
$$\text{RecordSize} = 50 + 4 + 8 = 62 \text{ байта}$$

Если нам нужно обновить запись с порядковым номером $i$ (нумерация с нуля), мы можем вычислить ее физическое смещение в байтах от начала файла:
$$\text{Offset} = i \times \text{RecordSize}$$

Используя класс `FileStream`, мы перемещаем указатель позиции с помощью метода `Seek` на вычисленное смещение и перезаписываем ровно $62$ байта новыми данными.

---

### 4.3. Пакетная обработка файлов и обеспечение атомарности

При разработке надежных приложений часто возникает задача пакетной обработки: прочитать исходный файл, отфильтровать или трансформировать данные по определенному условию и сохранить результат.

Главная опасность здесь — **аварийное завершение программы** (сбой питания, нехватка памяти, исключение) в процессе записи нового файла. Если программа начнет перезаписывать существующий файл "на месте" и упадет посреди работы, файл будет безвозвратно поврежден (наполовину старый, наполовину новый).

Для предотвращения этого используют паттерн **атомарной замены с использованием временного файла**:
1. Все изменения записываются во **временный файл** с уникальным или заранее оговоренным служебным именем (например, `data.tmp`).
2. Операция записи доводится до конца, поток закрывается, гарантируя, что файл полностью сформирован на диске.
3. Производится замена файлов: старый файл удаляется (или переименовывается в резервный), а временный файл переименовывается в целевой рабочий файл. В операционной системе операция переименования файла является атомарной, что исключает появление полузаписанных данных.

---

### 4.4. Типичные ошибки при работе с файлами

При работе с файловой системой в реальных проектах разработчики регулярно сталкиваются со следующими проблемными ситуациями:
* **Блокировка файлов операционной системой (`IOException`).** Возникает, когда один процесс пытается открыть файл на запись или монопольный доступ, в то время как другой процесс (или этот же в незакрытом потоке) уже читает или пишет в него. Всегда используйте конструкцию `using` для своевременного освобождения дескрипторов.
* **Неверная кодировка.** Чтение текстового файла в кодировке Windows-1251 (cp1251) с помощью `StreamReader` по умолчанию, настроенного на UTF-8, приводит к появлению «кракозябр» (нечитаемых символов). Всегда явно указывайте кодировку через конструктор `new StreamReader(path, Encoding.GetEncoding("windows-1251"))`, если файл создан сторонней левой программой.
* **Выход за границы потока (`EndOfStreamException`).** Попытка прочитать из бинарного потока больше данных, чем в нем реально содержится (например, чтение лишнего `int` из файла, где записано всего 3 числа).

### 4.5. Разобранный пример

#### Условие задачи
Создать текстовый файл `"students.txt"`, содержащий сведения о трех студентах в формате «Фамилия СреднийБалл» (каждая строка — отдельный студент). Написать программу на C#, которая открывает этот файл, находит студента с максимальным средним баллом, выводит его фамилию и балл в консоль, а также записывает результат в новый файл `"best.txt"`.

#### Рисунок (схема) данных
```text
students.txt (входной файл)              Память программы (обработка)
┌─────────────────────────┐              ┌───────────────────────────┐
│ Иванов 4{,}67            │  ------->    │ Сравнение AverageScore    │
│ Петров 4{,}92            │  ------->    │ Найдено максимальное:     │
│ Сидоров 4{,}35          │  ------->    │ Петров, 4{,}92            │
└─────────────────────────┘              └─────────────┬─────────────┘
                                                       │
                                                       ▼
                                         best.txt (выходной файл)
                                         ┌───────────────────────────┐
                                         │ Петров 4{,}92             │
                                         └───────────────────────────┘
```

#### Ход рассуждений
1. Для создания исходного файла воспользуемся классом `StreamWriter`. Запишем туда три заранее подготовленные строки с данными студентов.
2. Для чтения файла используем `StreamReader`. Организуем построчный обход файла с помощью цикла `while` и проверки свойства `endOfStream` (или чтения строки до `null` через `ReadLine()`).
3. Так как каждая строка имеет фиксированный формат (`Фамилия` и `СреднийБалл`, разделенные пробелом), разобьем считанную строку на массив подстрок с помощью метода `s.Split(' ')`.
4. Первую часть массива интерпретируем как строку (`string`), а вторую часть преобразуем в вещественное число двойной точности с помощью `double.Parse(parts[1], CultureInfo.InvariantCulture)` для корректной обработки точки как разделителя дробной части.
5. Заведем переменные для хранения информации о лучшем студенте на текущий момент (`bestLastName` и `maxScore`). Инициализируем `maxScore` минимально возможным значением (например, `-1.0`).
6. В цикле сравним балл каждого нового прочитанного студента с `maxScore`. Если он строго больше, обновим `maxScore` и `bestLastName`.
7. После завершения чтения файла выведем результат в консоль и запишем его в новый файл `"best.txt"` с помощью `StreamWriter`.

#### Полный исходный код программы

```csharp
using System;
using System.IO;
using System.Globalization;

class Program
{
    static void Main()
    {
        string inputFileName = "students.txt";
        string outputFileName = "best.txt";

        // Шаг 1. Создаем демонстрационный входной файл со списком студентов
        try
        {
            using (StreamWriter writer = new StreamWriter(inputFileName))
            {
                writer.WriteLine("Иванов 4{,}67".Replace(',', '.')); // Записываем с точкой для универсальности
                writer.WriteLine("Петров 4{,}92".Replace(',', '.'));
                writer.WriteLine("Сидоров 4{,}35".Replace(',', '.'));
            }
            Console.WriteLine("Входной файл успешно создан.");
        }
        catch (IOException ex)
        {
            Console.WriteLine($"Ошибка при создании файла: {ex.Message}");
            return;
        }

        // Шаг 2. Читаем файл, ищем студента с максимальным средним баллом
        string bestLastName = "";
        double maxScore = -1.0;
        bool fileReadSuccess = false;

        try
        {
            using (StreamReader reader = new StreamReader(inputFileName))
            {
                string line;
                while ((line = reader.ReadLine()) != null)
                {
                    // Пропускаем пустые строки на случай некорректного формата файла
                    if (string.IsNullOrWhiteSpace(line))
                        continue;

                    // Разделяем строку по пробелу
                    string[] parts = line.Split(new char[] { ' ' }, StringSplitOptions.RemoveEmptyEntries);
                    
                    if (parts.Length >= 2)
                    {
                        string lastName = parts[0];
                        
                        // Парсим вещественное число с инвариантной культурой (точка как разделитель)
                        if (double.TryParse(parts[1], NumberStyles.Any, CultureInfo.InvariantCulture, out double score))
                        {
                            // Сравниваем с текущим максимумом
                            if (score > maxScore)
                            {
                                maxScore = score;
                                bestLastName = lastName;
                            }
                        }
                    }
                }
                fileReadSuccess = true;
            }
        }
        catch (FileNotFoundException)
        {
            Console.WriteLine($"Ошибка: Файл {inputFileName} не найден.");
            return;
        }
        catch (IOException ex)
        {
            Console.WriteLine($"Ошибка ввода-вывода при чтении файла: {ex.Message}");
            return;
        }

        // Шаг 3. Вывод результатов и запись в новый файл
        if (fileReadSuccess && maxScore >= 0)
        {
            Console.WriteLine($"\nСтудент с максимальным средним баллом найден:");
            Console.WriteLine($"Фамилия: {bestLastName}, Средний балл: {maxScore.ToString("F2", CultureInfo.InvariantCulture)}");

            try
            {
                using (StreamWriter writer = new StreamWriter(outputFileName))
                {
                    writer.WriteLine($"{bestLastName} {maxScore.ToString(CultureInfo.InvariantCulture)}");
                }
                Console.WriteLine($"Результат успешно записан в файл {outputFileName}.");
            }
            catch (IOException ex)
            {
                Console.WriteLine($"Ошибка при записи результатов: {ex.Message}");
            }
        }
        else
        {
            Console.WriteLine("Не удалось обработать данные из файла или файл пуст.");
        }
    }
}
```

#### Пояснение по строкам кода
* `using (StreamWriter writer = new StreamWriter(inputFileName))` — гарантирует автоматический вызов метода `Dispose()` и закрытие файлового дескриптора сразу после выхода из блока видимости, даже если внутри возникнет исключение.
* `line.Split(new char[] { ' ' }, StringSplitOptions.RemoveEmptyEntries)` — разделяет строку на массив подстрок по пробелам, игнорируя случайные двойные пробелы.
* `double.TryParse(..., NumberStyles.Any, CultureInfo.InvariantCulture, out double score)` — безопасное преобразование строки в число, защищающее программу от сбоя, если в файле вместо числа окажутся некорректные символы. `CultureInfo.InvariantCulture` гарантирует правильное распознавание точки в качестве разделителя целой и дробной части вне зависимости от региональных настроек компьютера, на котором запущен код.

#### Пример консольного вывода
```text
Входной файл успешно создан.

Студент с максимальным средним баллом найден:
Фамилия: Петров, Средний балл: 4.92
Результат успешно записан в файл best.txt.
```

#### Проверка и оценка сложности
* **Проверка единиц и правдоподобия:** Исходный файл содержит баллы $4{,}67$, $4{,}92$ и $4{,}35$. Максимальное значение среди них равно $4{,}92$, что соответствует студенту Петрову. Алгоритм отработал корректно.
* **Оценка временной сложности:** Программа совершает один линейный проход по всем строкам файла. Если в файле содержится $N$ строк, то временная сложность составляет $O(N)$, что является оптимальным для данной задачи.
* **Оценка пространственной сложности:** $O(1)$ дополнительных затрат памяти (не считая буферов потока ввода-вывода), так как файл читается построчно, и в оперативной памяти одновременно хранится только текущая обрабатываемая строка.

## Типичные ошибки

1. **Забытый вызов метода закрытия или отсутствие оператора `using`**
   * *В чём ошибка:* Программа открывает файл, выполняет запись, но забывает вызвать методы `Close()` или `Dispose()`. Поток остаётся висеть в памяти, а файл — заблокированным операционной системой.
   * *Почему возникает:* Разработчик полагает, что сборщик мусора (Garbage Collector) автоматически очистит все ресурсы. Однако сборщик мусора не управляет дескрипторами файлов ОС в режиме реального времени.
   * *Как избежать:* Всегда используйте конструкцию `using` (или декларацию `using stream = ...`), которая гарантирует вызов `Dispose` даже при аварийном падении кода в блоке.
   * *Пример:* `using StreamWriter writer = new StreamWriter("file.txt");`

2. **Несоблюдение порядка чтения в бинарных потоках (`BinaryReader`)**
   * *В чём ошибка:* Данные записывались в порядке `int`, затем `double`, а считываются наоборот: `double`, затем `int`.
   * *Почему возникает:* Бинарный файл — это непрерывная лента байтов без метаданных о типах. Потоки не знают, что именно записано в байтах.
   * *Как избежать:* Строго документируйте структуру бинарного файла и обеспечьте зеркальный порядок вызовов `Read...()` относительно методов `Write...()`.
   * *Пример:* Если записали `writer.Write(age); writer.Write(name);`, то читайте `int age = reader.ReadInt32(); string name = reader.ReadString();`.

3. **Игнорирование локали при чтении вещественных чисел из текстовых файлов**
   * *В чём ошибка:* Программа падает с исключением `FormatException` при чтении чисел с точкой (`3.14`), если в операционной системе установлена русская локаль, где разделителем по умолчанию является запятая (`3,14`).
   * *Почему возникает:* Метод `double.Parse(str)` по умолчанию опирается на текущие региональные настройки компьютера пользователя.
   * *Как избежать:* Всегда передавайте `CultureInfo.InvariantCulture` при парсинге строк, содержащих числовые данные из внешних файлов.
   * *Пример:* `double.TryParse(s, NumberStyles.Any, CultureInfo.InvariantCulture, out double val);`

4. **Перезапись файла вместо дописывания (`Append`)**
   * *В чём ошибка:* При повторном запуске программы старые данные в файле бесследно исчезают.
   * *Почему возникает:* Конструкторы `StreamWriter("file.txt")` и `FileMode.Create` по умолчанию стирают существующий файл и создают его заново.
   * *Как избежать:* Если требуется сохранять историю или добавлять строки к уже имеющимся, явно указывайте флаг добавления.
   * *Пример:* `new StreamWriter("file.txt", append: true)` или `FileMode.Append` в `FileStream`.

5. **Попытка чтения до конца файла через `ReadLine()` без проверки на `null`**
   * *В чём ошибка:* Возникает исключение `NullReferenceException` при попытке вызвать методы строки у результата чтения.
   * *Почему возникает:* Метод `ReadLine()` возвращает `null`, когда достигнут конец файла. Если присвоить этот результат переменной и попытаться с ней работать, произойдет сбой.
   * *Как избежать:* Всегда проверяйте возвращаемое значение метода `ReadLine()` на равенство `null` или используйте свойство `EndOfStream` у `StreamReader`.
   * *Пример:* `string? line; while ((line = reader.ReadLine()) != null) { ... }`

6. **Создание файла внутри несуществующего каталога**
   * *В чём ошибка:* Программа аварийно завершается с исключением `DirectoryNotFoundException`.
   * *Почему возникает:* Классы потоков могут автоматически создавать сам файл, но они не создают промежуточные папки в указанном пути (например, папка `"C:\Data\Reports\"` на диске отсутствует).
   * *Как избежать:* Перед открытием потока убедитесь в существовании директории с помощью класса `Directory`: `Directory.CreateDirectory(Path.GetDirectoryName(path));`.

7. **Некорректный расчет смещений при использовании прямого доступа (`FileStream` и `Seek`)**
   * *В чём ошибка:* Программа перезаписывает соседние данные или считывает «мусор» посреди структуры.
   * *Почему возникает:* Попытка умножить порядковый номер записи на произвольное или неверное число байт (например, забыли, что `double` занимает 8 байт, а посчитали как 4).
   * *Как избежать:* Всегда вычисляйте размер структуры через оператор `sizeof` (где применимо) или фиксируйте константами размер каждого поля в байтах.

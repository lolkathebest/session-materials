## 1. Область видимости и время жизни переменных

### Понятие блока кода и границ видимости

Когда мы пишем программы на языке C#, наш код состоит из инструкций, объединенных в определенные структуры. Одной из фундаментальных конструкций является **блок кода**. 

> **Определение.** Блок кода в C# — это последовательность инструкций, заключенная в фигурные скобки `{ }`. 

Фигурные скобки выполняют роль не только визуального оформления, но и жесткого барьера безопасности и логической изоляции. Они определяют **область видимости** (scope) для всех переменных, которые объявляются внутри них.

Что такое область видимости простыми словами? Это зона видимости на карте вашей программы, где компилятор «знает» о существовании переменной и разрешает к ней обращаться. Если вы попытаетесь обратиться к переменной вне зоны её видимости, программа даже не скомпилируется: среда разработки выдаст ошибку о том, что имя не существует в текущем контексте.

Рассмотрим базовый пример создания блока кода внутри метода:

```csharp
{
    int localNumber = 10;
    Console.WriteLine(localNumber); // Ошибки нет, мы внутри блока
}
// Здесь блок закончил свое выполнение
// Console.WriteLine(localNumber); // ОШИБКА КОМПИЛЯЦИИ: переменная localNumber здесь не видна!
```

Правило видимости простое: переменная видна внутри того блока, где она объявлена, а также во всех вложенных в него подблоках. Как только выполнение программы выходит за пределы закрывающей фигурной скобки `}`, переменная «умирает» и стирается из памяти.

### Локальные переменные метода и их время жизни в стеке вызовов

Наиболее частый вид переменных, с которым вы работаете — это **локальные переменные**. Они объявляются непосредственно внутри методов (например, внутри `Main` или любого другого метода).

> **Определение.** Время жизни переменной — это период выполнения программы от момента выделения памяти под переменную до момента ее уничтожения и освобождения памяти.

Как устроено выделение памяти для локальных переменных на уровне архитектуры компьютера? Для этого используется специальная структура данных в оперативной памяти — **стек вызовов** (call stack). 

Стек работает по принципу «последним пришел — первым вышел» (LIFO, Last In, First Out). Когда программа вызывает метод, в стеке выделяется непрерывный блок памяти под этот метод — так называемый **стековый кадр** (stack frame). В этом кадре размещаются параметры метода и все его локальные переменные.

1. **Создание:** Когда выполнение доходит до строки объявления локальной переменной, в стековом кадре текущего метода резервируется ячейка памяти нужного размера (например, 4 байта для `int`). Переменная инициализируется.
2. **Использование:** Пока метод выполняется, вы можете читать и изменять значение этой ячейки через имя переменной.
3. **Уничтожение:** Как только метод завершает свою работу (достигает оператора `return` или закрывающей фигурной скобки метода), весь стековый кадр этого метода мгновенно «сгорает» — указатель вершины стека смещается назад. Память, занимаемая локальными переменными, освобождается для других вызовов. Значения этих переменных безвозвратно теряются.

Проиллюстрируем это схемой работы стека вызовов в текстовом виде:

```text
Вызов метода Main()
 [ Стековый кадр Main: int a = 5 ]
          │
          ▼ Вызов метода Calculate()
 [ Стековый кадр Main: int a = 5 ] ◄────────┐ (метод Main ждет)
 [ Стековый кадр Calculate: int sum = 15 ] │
          │                                │
          ▼ Завершение Calculate (return)  │
 [ Стековый кадр Main: int a = 5 ] ────────┘ (память Calculate очищена)
          │
          ▼ Завершение программы
 [ Память полностью очищена ]
```

### Конфликт имен и сокрытие имен (Shadowing)

Иногда в программе возникает ситуация, когда в разных вложенных или смежных областях видимости объявляются переменные с одинаковыми именами. Разберем, как компилятор C# обрабатывает такие коллизии.

Во-первых, параметры метода считаются локальными переменными для этого метода. Они живут внутри всего тела метода. Если внутри тела метода в каком-то вложенном блоке (например, внутри цикла `for` или условного оператора `if`) вы попытаетесь объявить локальную переменную с точно таким же именем, как у параметра метода, компилятор выдаст ошибку:

```csharp
static void ProcessData(int value) // параметр value
{
    // int value = 20; // ОШИБКА КОМПИЛЯЦИИ: локальная переменная 'value' 
                       // конфликтует с параметром метода с тем же именем
}
```

Однако в языке C# разрешено **сокрытие имен** (shadowing) во вложенных друг в друга блоках кода. Если внешний блок и внутренний вложенный блок разделены фигурными скобками, то во внутреннем блоке можно объявить переменную с именем, уже существующим во внешнем блоке. При этом во время выполнения во внутреннем блоке будет использоваться «новая» локальная переменная, полностью перекрывая («затеняя») старую переменную из внешнего блока. Старая переменная никуда не исчезает, но временно становится недоступной по своему имени.

Рассмотрим это на примере со вложенными циклами и блоками.

#### Разобранный пример 1: Области видимости и сокрытие имен во вложенных циклах

**Условие:** проанализируйте следующий фрагмент кода на C#. Определите, какая именно переменная `x` будет доступна в каждой точке программы и почему в последней строке метода возникает ошибка компиляции.

```csharp
class Program
{
    static void Main()
    {
        int x = 10; // Первая переменная x (на уровне метода Main)
        Console.WriteLine("Начало: x = " + x); // Выведет 10

        for (int i = 0; i < 2; i++)
        {
            int x = 20; // Вторая переменная x (внутри внешнего блока цикла)
            x++;
            Console.WriteLine("Цикл 1: x = " + x); // Выведет 21

            {
                int x = 30; // Третья переменная x (во внутреннем блоке)
                Console.WriteLine("Внутренний блок: x = " + x); // Выведет 30
            }

            Console.WriteLine("После внутреннего блока: x = " + x); // Выведет 21
        }

        // Console.WriteLine("Конец: x = " + x); // ЗДЕСЬ ОШИБКА КОМПИЛЯЦИИ
    }
}
```

**Рисунок словами (структура вложенности блоков):**
- Внешний блок (`Main`): объявлена переменная `x = 10`.
- Средний блок (тело цикла `for`): объявлена *другая* локальная переменная `x = 20`, которая затеняет переменную `x = 10` из метода `Main`.
- Внутренний блок (фигурные скобки внутри цикла): объявлена *третья* локальная переменная `x = 30`, которая затеняет переменную `x = 20` из цикла.

**Ход рассуждений:**
1. Когда мы заходим в метод `Main`, создается ячейка `x` со значением `10`.
2. Заходим в цикл `for`. Объявляется *новая* переменная `x` со значением `20`. Она существует только внутри итераций цикла. На каждой итерации она увеличивается на 1 (`x++`), становясь равной `21`. Обратиться к исходной переменной `x = 10` изнутри цикла по имени `x` невозможно — имя перекрыто.
3. Внутри цикла мы открываем еще один вложенный блок `{ }` и создаем там третью переменную `x = 30`. Она видна только внутри этих фигурных скобок. При выходе из этого внутреннего блока память из-под третьей переменной очищается.
4. Возвращаемся в тело цикла: здесь снова видна вторая переменная `x` (равная `21`).
5. Цикл завершается. Вторая переменная `x` уничтожается. 
6. Если раскомментировать последнюю строку `Console.WriteLine("Конец: x = " + x);` за пределами цикла, компилятор выдаст ошибку, но *почему*? Внимание: в данном конкретном примере C# запрещает объявлять переменную `int x = 20` внутри цикла, если в окружающем методе `Main` уже есть переменная `x`, чтобы избежать путаницы для программиста (в отличие от некоторых других языков, таких как C++, где shadowing разрешен для локальных переменных метода). Поэтому сам этот код вызовет ошибку компиляции еще на этапе объявления `int x = 20` внутри цикла («Локальная переменная с именем 'x' не может быть объявлена в этой области видимости, так как это имя уже используется в объемлющей локальной области видимости»).

*(Примечание: если бы имена были разными, например `x`, `y`, `z`, код бы работал, но в учебных целях мы рассмотрели именно защиту C# от сокрытия локальных переменных внутри одного метода).*

### Поля класса с модификатором static: область видимости и время жизни

Локальные переменные удобны, но они «живут» ровно до тех пор, пока выполняется метод. Как только метод завершился, все данные стираются. Но что делать, если нужно сохранить состояние между вызовами методов или накапливать общую статистику (например, подсчитывать общее количество вызовов какой-то функции по всей программе)? 

Для этого используются статические поля класса.

> **Определение.** Статическое поле (`static field`) — это переменная, которая объявлена непосредственно внутри тела класса (на уровне класса, вне каких-либо методов) и снабжена ключевым словом `static`.

Давайте сравним характеристики локальных переменных и статических полей в виде таблицы:

| Характеристика | Локальная переменная | Статическое поле (`static`) |
|---|---|---|
| **Где объявляется** | Внутри метода или блока кода `{ }` | Внутри класса, вне методов |
| **Область видимости** | Только внутри своего метода или блока | Внутри всего класса (и шире, в зависимости от модификаторов доступа) |
| **Время жизни** | От вызова метода до его завершения | От запуска программы до ее полного завершения |
| **Где хранятся в памяти** | В стеке вызовов (Stack) | В специальной области кучи для метаданных/статических данных (High-Frequency Heap / Static Area) |
| **Инициализация по умолчанию** | Не инициализируются автоматически (компилятор требует присвоить значение до чтения) | Автоматически инициализируются значениями по умолчанию (0, `false`, `null`) |

Поскольку статические поля живут на протяжении всей работы программы, они не уничтожаются при выходе из метода. Каждый новый вызов метода может изменять значение статического поля, и это изменение сохранится к следующему вызову.

#### Разобранный пример 2: Вычисление значения статического счетчика

**Условие:** напишите программу, в которой есть статический счетчик вызовов. Метод `PerformOperation()` вызывается из разных частей программы три раза. Вычислите и выведите на экран значение статического счетчика после каждого вызова.

**Решение (полный компилируемый код на C#):**

```csharp
using System;

class Program
{
    // Объявление статического поля на уровне класса
    // Оно общее для всей программы и живет до ее завершения
    static int callCounter = 0;

    static void PerformOperation()
    {
        // Увеличиваем счетчик на 1 при каждом вызове метода
        callCounter++;
        Console.WriteLine($"Метод вызван. Текущее значение счетчика: {callCounter}");
    }

    static void Main()
    {
        Console.WriteLine("Старт программы. Счетчик равен: " + callCounter);

        // Первый вызов из Main
        PerformOperation();

        // Имитация работы другого участка кода
        AnotherMethod();

        // Третий вызов
        PerformOperation();
    }

    static void AnotherMethod()
    {
        Console.WriteLine("Выполняется вспомогательный метод...");
        // Второй вызов метода PerformOperation из другого метода
        PerformOperation();
    }
}
```

**Ход рассуждений при выполнении:**
1. При запуске программы класс загружается в память, и статическое поле `callCounter` создается и инициализируется нулем (`callCounter = 0`).
2. Метод `Main` выводит начальное значение: `0`.
3. Вызывается `PerformOperation()` (вызов №1). Внутри метода выполняется `callCounter++`. Значение поля становится равным `1`. На экран выводится: `Метод вызван. Текущее значение счетчика: 1`.
4. Управление возвращается в `Main`, затем вызывается `AnotherMethod()`.
5. Внутри `AnotherMethod()` происходит вызов `PerformOperation()` (вызов №2). Внутри метода поле `callCounter` увеличивается еще на 1 и становится равным `2`. На экран выводится: `Метод вызван. Текущее значение счетчика: 2`.
6. Управление возвращается в `Main`, откуда происходит третий вызов `PerformOperation()` (вызов №3). Поле `callCounter` увеличивается до `3`. На экран выводится: `Метод вызван. Текущее значение счетчика: 3`.

**Вывод программы:**
```text
Старт программы. Счетчик равен: 0
Метод вызван. Текущее значение счетчика: 1
Выполняется вспомогательный метод...
Метод вызван. Текущее значение счетчика: 2
Метод вызван. Текущее значение счетчика: 3
```

**Проверка (правдоподобность):**
Счетчик вызывался ровно 3 раза из разных мест программы. Поскольку поле `static` сохраняет свое состояние между вызовами разных методов, итоговое значение накопилось корректно и составило `3`. Если бы `callCounter` был объявлен как локальная переменная внутри `PerformOperation()`, он бы каждый раз создавался заново с нуля, и его значение после каждого вызова было бы равно `1`, что противоречило бы условию задачи о суммарном подсчете. Это наглядно демонстрирует разницу во времени жизни переменных.

## 2. Передача параметров по значению (default)

### Механизм передачи аргументов по значению по умолчанию в C#

Когда мы вызываем метод и передаем в него переменные, язык C# по умолчанию использует **передачу параметров по значению** (англ. *pass by value*). Это фундаментальный принцип взаимодействия между вызывающим кодом (например, методом `Main`) и вызываемым методом. 

> **Определение.** Передача по значению — это механизм передачи данных в метод, при котором среда выполнения создает полную независимую **копию** значения исходной переменной и помещает эту копию в память, выделенную под параметр вызываемого метода.

Чтобы понять, как это работает на уровне физической памяти компьютера, вспомним концепцию стека вызовов (Call Stack), рассмотренную на предыдущих занятиях. Когда выполнение программы доходит до вызова метода, в стеке выделяется новый кадр (фрейм) для этого метода. В этот кадр записываются локальные переменные метода и его параметры. 

Важнейшее следствие этого механизма заключается в том, что параметр внутри метода и переменная в вызывающем коде — это две **абсолютно разные ячейки памяти**, содержащие одинаковые на данный момент числовые или логические значения. Изменение значения в одной ячейке никак не затрагивает другую.

### Создание локальной копии значения аргумента

Рассмотрим подробно последовательность шагов, происходящих в памяти компьютера при передаче аргумента по значению:

1. Вызывающий код вычисляет выражение, передаваемое в качестве аргумента (это может быть константа, значение переменной или результат другого выражения).
2. Выделяется память на стеке под параметр вызываемого метода.
3. Значение аргумента копируется в эту вновь созданную ячейку памяти.
4. Управление передается внутрь метода. С этого момента метод работает исключительно со своей локальной копией параметра.
5. При завершении работы метода кадр стека вызываемого метода уничтожается вместе со всеми его параметрами и локальными переменными, а управление возвращается в точку вызова.

Для простых (значимых) типов данных в C#, таких как `int`, `double`, `bool`, `char`, `float`, `long` и других, передача по значению является стандартным и единственным поведением по умолчанию.

### Изоляция переменных и ограничения

Главным преимуществом передачи по значению является **безопасность и изоляция**. Вызывающий код может быть полностью уверен, что вызов стороннего метода не испортит («не затрет») данные в исходных переменных, если разработчик метода не предусмотрел это явно. Метод может производить любые вычисления со своими параметрами, менять их как угодно, но эти изменения останутся «внутри» метода.

Ограничение этого подхода проявляется тогда, когда нам **необходимо** получить от метода измененное значение обратно в вызывающий код (или вернуть сразу несколько результатов). По умолчанию через оператор `return` метод может вернуть только одно значение. Если нужно изменить несколько переменных, стандартная передача по значению помочь не может — обходные пути вроде возврата массивов или составных структур (классов/структур) не всегда удобны и приводят к лишним затратам памяти. Для прямого изменения переменных вызывающего кода позже применяются модификаторы `ref` и `out`.

### Разобранный пример 1: Умножение числа на два

Напишем полную консольную программу на C#, которая иллюстрирует передачу целочисленной переменной по значению. Мы создадим метод `MultiplyByTwo`, который принимает число, удваивает его, а затем убедимся в методе `Main`, что исходная переменная осталась неизменной.

#### Условие задачи
В методе `Main` объявлена целочисленная переменная `originalValue` со значением `15`. Необходимо передать ее в метод `MultiplyByTwo(int val)`, который внутри себя умножает параметр `val` на `2` и выводит его на экран. После возврата управления в `Main` вывести значение `originalValue` на экран и объяснить результат.

#### Полный исходный код программы

```csharp
using System;

namespace ParameterPassingDemo
{
    class Program
    {
        static void Main(string[] args)
        {
            // Шаг 1: Объявляем и инициализируем исходную переменную в методе Main
            int originalValue = 15;

            Console.WriteLine($"[Main] До вызова метода: originalValue = {originalValue}");

            // Шаг 2: Вызываем метод, передавая переменную по значению
            MultiplyByTwo(originalValue);

            // Шаг 3: Проверяем значение переменной после возврата из метода
            Console.WriteLine($"[Main] После вызова метода: originalValue = {originalValue}");
            
            // Задержка консоли для просмотра результатов
            Console.ReadKey();
        }

        // Метод принимает параметр типа int по значению
        static void MultiplyByTwo(int val)
        {
            Console.WriteLine($"[Метод] В начале метода val = {val}");

            // Умножаем локальную копию параметра на 2
            val = val * 2;

            Console.WriteLine($"[Метод] В конце метода val (после умножения) = {val}");
        }
    }
}
```

#### Пошаговый анализ трассировки стека и хода рассуждений
1. В памяти создается переменная `originalValue` в кадре метода `Main`. Ей выделяется ячейка в стеке, куда записывается число `15`.
2. Происходит вызов `MultiplyByTwo(originalValue)`. На этом этапе C# берет текущее значение переменной `originalValue` (то есть `15`) и копирует его.
3. В стеке создается новый кадр для метода `MultiplyByTwo`, в котором заводится параметр `val`. В ячейку памяти параметра `val` записывается скопированное число `15`.
4. На экран выводится строка: `[Main] До вызова метода: originalValue = 15`.
5. Управление переходит внутрь `MultiplyByTwo`. На экран выводится: `[Метод] В начале метода val = 15`.
6. Выполняется операция `val = val * 2`. В ячейке памяти параметра `val` число `15` заменяется на `30`. При этом ячейка переменной `originalValue`, находящаяся в кадре метода `Main`, никак не затрагивается, так как находится в другой области стека.
7. На экран выводится: `[Метод] В конце метода val (после умножения) = 30`.
8. Метод завершает работу (срабатывает неявный `return`). Кадр метода `MultiplyByTwo` стирается из стека, память освобождается.
9. Управление возвращается в `Main` на строку, следующую за вызовом метода.
10. Выполняется последняя строка `Main`. На экран выводится: `[Main] После вызова метода: originalValue = 15`.

#### Проверка и вывод
Значение `originalValue` не изменилось и осталось равным `15`. Это доказывает, что метод оперировал лишь независимой копией.

`Ответ:` 
```text
[Main] До вызова метода: originalValue = 15
[Метод] В начале метода val = 15
[Метод] В конце метода val (после умножения) = 30
[Main] После вызова метода: originalValue = 15
```

### Разобранный пример 2: Классический обмен значениями (Swap) без модификаторов

Классическая задача программирования — поменять местами значения двух переменных. Начинающие часто пытаются написать метод `Swap` без использования специальных модификаторов ссылок и сталкиваются с тем, что задача не решается. Разберем этот пример подробно, чтобы понять причину.

#### Условие задачи
Даны две целочисленные переменные: `x = 10` и `y = 25`. Требуется написать метод `Swap(int a, int b)`, который принимает эти два числа по значению, меняет их местами внутри себя и выводит результат. В методе `Main` после вызова метода также вывести значения `x` и `y`. Объяснить, почему переменные в вызывающем коде не поменялись местами.

#### Полный исходный код программы

```csharp
using System;

namespace FailedSwapDemo
{
    class Program
    {
        static void Main(string[] args)
        {
            int x = 10;
            int y = 25;

            Console.WriteLine($"[Main] До вызова Swap: x = {x}, y = {y}");

            // Пытаемся поменять местами переменные через метод
            Swap(x, y);

            // Проверяем состояние переменных после вызова
            Console.WriteLine($"[Main] После вызова Swap: x = {x}, y = {y}");

            Console.ReadKey();
        }

        static void Swap(int a, int b)
        {
            Console.WriteLine($"[Swap] Входные значения: a = {a}, b = {b}");

            // Стандартный алгоритм обмена через временную переменную
            int temp = a;
            a = b;
            b = temp;

            Console.WriteLine($"[Swap] После обмена: a = {a}, b = {b}");
        }
    }
}
```

#### Пошаговый анализ хода рассуждений
1. В методе `Main` создаются две ячейки памяти: `x` со значением `10` и `y` со значением `25`.
2. Вызывается метод `Swap(x, y)`. Поскольку аргументы передаются по значению, создаются **две независимые копии** этих значений.
3. В кадре стека метода `Swap` выделяются параметры `a` (туда копируется `10`) и `b` (туда копируется `25`). Переменные `x` и `y` из метода `Main` остаются на своих местах и никак не связаны с именами `a` и `b` за пределами этого метода.
4. Внутри метода `Swap` происходит перестановка:
   - Временная переменная `temp` принимает значение `a` (то есть `10`).
   - Параметр `a` принимает значение параметра `b` (то есть `25`).
   - Параметр `b` принимает значение из `temp` (то есть `10`).
5. На экране внутри метода мы видим успешную перестановку: `a = 25`, `b = 10`.
6. Метод `Swap` завершает свою работу, его кадр стирается из памяти. Локальные переменные `temp`, `a` и `b` уничтожаются навсегда.
7. Управление возвращается в метод `Main`. Переменная `x` по-прежнему хранит `10`, а переменная `y` хранит `25`, потому что метод менял значения локальных копий `a` и `b`, а не оригинальные ячейки памяти в `Main`.

#### Проверка и вывод
Этот пример наглядно демонстрирует ограничение передачи по значению: метод не способен повлиять на состояние переменных вызывающего кода, если эти переменные переданы стандартным образом без указания ссылочных модификаторов. Для реализации корректного обмена (`Swap`) в C# обязательно требуется применение ключевого слова `ref`, которое будет рассмотрено в следующем разделе конспекта.

`Ответ:`
```text
[Main] До вызова Swap: x = 10, y = 25
[Swap] Входные значения: a = 10, b = 25
[Swap] После обмена: a = 25, b = 10
[Main] После вызова Swap: x = 10, y = 25
```

## 3. Передача параметров по ссылке: модификатор ref

### Необходимость изменения переменных вызывающего кода изнутри метода

Предыдущий материал курса показал, что по умолчанию аргументы в методы на языке C# передаются *по значению*. Это означает, что при вызове метода создаются локальные копии переданных переменных в стеке вызовов. Вызываемый метод оперирует исключительно этими копиями, в то время как исходные переменные в вызывающем коде (например, в методе `Main`) остаются в полной неприкосновенности.

Такое поведение защищает данные от случайных или несанкционированных изменений, что является важным принципом безопасного проектирования программ. Однако на практике часто возникают ситуации, когда метод *должен* изменить значение переменной, принадлежащей вызывающему коду. 

Классическим примером такой задачи является процедура обмена значениями двух переменных — `Swap`. Если попытаться написать метод `Swap(int a, int b)`, внутри которого значения временных локальных переменных меняются местами, то после завершения работы метода исходные переменные `x` и `y` в `Main` останутся прежними. Изменились лишь локальные копии параметров `a` и `b`, которые уничтожились сразу после возврата управления из метода.

Чтобы преодолеть это ограничение и разрешить методу напрямую модифицировать ячейку памяти вызывающей программы, в языке C# используется передача параметров по ссылке с помощью ключевого слова `ref`.

---

### Ключевое слово `ref` в сигнатуре метода и при вызове

> **Определение.** Модификатор `ref` (сокращение от *reference* — ссылка) — это ключевое слово языка C#, которое указывает компилятору, что аргумент передается не по значению (в виде копии), а по ссылке на исходную переменную в памяти.

Чтобы метод мог принимать аргумент по ссылке, ключевое слово `ref` должно быть указано в двух местах:
1. В **сигнатуре метода** (при его объявлении) перед типом параметра.
2. В **точке вызова метода** перед передаваемой переменной.

Рассмотрим синтаксис объявления и вызова:

```csharp
// Объявление метода
static void ModifyValue(ref int number)
{
    number = 100; // Изменение параметра напрямую меняет исходную переменную
}

// Вызов метода в Main
int x = 10;
ModifyValue(ref x); // Обязательное использование ключевого слова ref при вызове
Console.WriteLine(x); // На экран выведется 100
```

Если забыть указать `ref` при вызове метода, среда разработки и компилятор выдадут ошибку, так как типы передаваемого аргумента и ожидаемого параметра в сигнатуре будут считаться несовпадающими.

---

### Передача указателя на ячейку памяти вместо копирования значения

Для полного понимания механизма работы `ref` обратимся к тому, как переменные хранятся в оперативной памяти компьютера (в стеке вызовов).

1. Когда в методе `Main` объявляется локальная переменная `int x = 5;`, в стеке выделяется ячейка памяти (например, по адресу `0x7FFF00`), куда записывается число `5`.
2. При вызове обычного метода (по значению) в стек добавляется новая область памяти для параметров этого метода, куда копируется число `5` из адреса `0x7FFF00`. Метод работает с этой копией.
3. При использовании модификатора `ref` в стек вызываемого метода передается не само значение `5`, а **адрес ячейки памяти** (`0x7FFF00`), где эта переменная хранится.

```
+-------------------------------------------------------+
| СТЕК ВЫЗОВОВ                                          |
|                                                       |
| Метод Main:                                           |
| [ Переменная x ] <-------+                            |
| Адрес: 0x7FFF00          | (передача адреса по ref)   |
| Значение: 100            |                            |
|                          |                            |
| Метод ModifyValue:       |                            |
| [ Параметр number ] -----+                            |
| Указатель на 0x7FFF00                                 |
+-------------------------------------------------------+
```

Когда внутри метода происходит присваивание `number = 100;`, процессор обращается по полученному адресу `0x7FFF00` и перезаписывает старое значение `5` на новое `100`. Именно поэтому после возврата в `Main` переменная `x` уже равна `100`.

---

### Строгое требование обязательной инициализации переменной до вызова метода с `ref`

Поскольку модификатор `ref` подразумевает, что метод получает доступ к *уже существующей* и инициализированной ячейке памяти, язык C# накладывает строгое семантическое правило:

> **Правило компилятора.** Переменная, которая передается в метод с модификатором `ref`, обязана быть проинициализирована (то есть ей должно быть присвоено начальное значение) **до** момента вызова метода.

Компилятор производит статическую проверку кода. Если попытаться передать неинициализированную локальную переменную через `ref`, программа не скомпилируется, и появится ошибка: *«Use of unassigned local variable»* (Использование не присвоенной локальной переменной).

Пример ошибочного кода:
```csharp
int x; // Переменная объявлена, но не инициализирована
ModifyValue(ref x); // ОШИБКА КОМПИЛЯЦИИ! Компилятор не разрешит передать "пустую" память.
x = 5;
```

Это ограничение логично: если бы переменная не была инициализирована, метод мог бы попытаться прочитать из нее мусорные данные из оперативной памяти, что привело бы к непредсказуемому поведению программы.

---

### Анализ работы метода `Swap` с использованием `ref`

Рассмотрим классическую задачу программирования: обмен значениями двух переменных. Без модификаторов решить эту задачу с помощью отдельного метода невозможно, так как менялись бы только локальные копии. Применение `ref` решает эту проблему полностью.

Ниже приведен полный код программы, реализующей безопасный обмен значениями двух целых чисел:

```csharp
using System;

class Program
{
    static void Main()
    {
        int a = 15;
        int b = 42;

        Console.WriteLine($"До вызова Swap: a = {a}, b = {b}");

        // Вызываем метод, передавая переменные по ссылке
        Swap(ref a, ref b);

        Console.WriteLine($"После вызова Swap: a = {a}, b = {b}");
    }

    static void Swap(ref int x, ref int y)
    {
        // Используем временную переменную для сохранения одного из значений
        int temp = x;
        x = y;
        y = temp;
    }
}
```

**Трассировка и ход рассуждений:**
1. В методе `Main` создаются две переменные: `a = 15` и `b = 42`.
2. Вызывается метод `Swap(ref a, ref b)`. В стек метода передаются не копии чисел, а ссылки (адреса в памяти) переменных `a` и `b`. Параметр `x` ссылается на ячейку переменной `a`, а параметр `y` — на ячейку переменной `b`.
3. Внутри метода `Swap` создается локальная переменная `temp`, в которую сохраняется текущее значение переменной `a` (через ссылку `х`), равное `15`.
4. В ячейку переменной `a` (через ссылку `x`) записывается значение переменной `b` (через ссылку `y`), то есть `42`. Теперь `a` равна `42`.
5. В ячейку переменной `b` (через ссылку `y`) записывается значение из `temp`, равное `15`. Теперь `b` равна `15`.
6. Метод завершает работу. Управление возвращается в `Main`.
7. Вывод на экран подтверждает, что переменные в `Main` успешно поменялись местами: `a = 42`, `b = 15`.

### Разобранный пример 1: Коррекция баланса счета

**Условие задачи:**
Разработать статический метод `CorrectBalance`, который принимает текущий баланс банковского счета (значение типа `double`) по ссылке и сумму комиссии (тоже типа `double`). Метод должен уменьшить баланс на сумму комиссии. Если сумма комиссии превышает текущий баланс, баланс должен стать равным `0{,}0`. В методе `Main` задать начальный баланс счета, равный `1500{,}50` у. е., комиссию в размере `250{,}0` у. е., вызвать метод и вывести обновленное значение на консоль.

**Рисунок (схема) процесса словами:**
В памяти создается ячейка `balance` со значением `1500{,}50`. При вызове `CorrectBalance(ref balance, 250.0)` метод получает прямой доступ к этой ячейке. Внутри метода проверяется условие: если баланс больше либо равен комиссии, из содержимого ячейки вычитается комиссия. Если комиссия больше — в ячейку записывается `0{,}0`. Никаких дополнительных переменных для возврата результата через `return` не требуется, так как изменение фиксируется прямо в исходной ячейке вызывающего кода.

**Ход рассуждений:**
1. Нам нужно изменить переменную, объявленную в `Main`, значит, параметр баланса необходимо объявить с модификатором `ref`: `ref double balance`.
2. Комиссию (`fee`) нет необходимости менять снаружи, поэтому она передается обычным образом — по значению.
3. Проверяем граничный случай: если комиссия больше баланса, баланс не должен уходить в минус. Присваиваем `0{,}0`. В противном случае выполняем вычитание `balance = balance - fee;`.
4. В методе `Main` перед вызовом метода переменная `balance` должна быть обязательно инициализирована (что выполняется при ее объявлении). При вызове обязательно пишем ключевое слово `ref`.

**Решение в общем виде и код программы:**

```csharp
using System;

class Program
{
    static void Main()
    {
        // Инициализация переменной до вызова метода (обязательное требование для ref)
        double balance = 1500.50;
        double fee = 250.0;

        Console.WriteLine($"Начальный баланс: {balance} руб.");
        Console.WriteLine($"Комиссия за обслуживание: {fee} руб.");

        // Вызов метода с передачей переменной balance по ссылке
        CorrectBalance(ref balance, fee);

        Console.WriteLine($"Баланс после списания комиссии: {balance} руб.");
    }

    static void CorrectBalance(ref double balance, double fee)
    {
        if (fee >= balance)
        {
            balance = 0.0;
        }
        else
        {
            balance -= fee; // Эквивалентно balance = balance - fee;
        }
    }
}
```

**Вычисление и проверка:**
- Исходный баланс: `1500{,}50`.
- Комиссия: `250{,}0`.
- Так как `250{,}0 < 1500{,}50`, выполняется ветка `else`: `1500{,}50 - 250{,}0 = 1250{,}50`.
- Единицы измерения: денежные единицы (`руб.`), тип данных `double` обеспечивает необходимую точность для финансовых расчетов в рамках учебной задачи.
- Правдоподобность: результат корректен, баланс уменьшился ровно на сумму комиссии.

`Ответ:` Баланс после списания комиссии: `1250{,}50` руб.

### Разобранный пример 2: Увеличение группы чисел на заданную константу

**Условие задачи:**
Написать статический метод `IncrementAll`, который принимает три целые переменные по ссылке и увеличивает каждую из них ровно на `10`. В методе `Main` инициализировать три переменные значениями `5`, `12` и `-3`, вызвать метод `IncrementAll`, а затем вывести новые значения всех трех переменных на консоль.

**Рисунок (схема) процесса словами:**
В памяти выделяются три независимые ячейки для трех целочисленных переменных. Метод `IncrementAll` принимает три ссылки, соответствующие каждой из этих ячеек. Обращаясь к параметрам внутри тела метода, программа производит арифметическую операцию прибавления десяти к каждой ячейке памяти. В результате все три исходные переменные в `Main` одновременно обновляют свои значения.

**Ход рассуждений:**
1. Поскольку требуется изменить три независимые переменные из вызывающего кода, все три параметра метода должны иметь модификатор `ref`: `ref int x, ref int y, ref int z`.
2. Каждая переменная должна быть проинициализирована в `Main` до вызова метода.
3. Внутри метода к каждому параметру применяются операции инкремента или сложения: `x += 10;`, `y += 10;`, `z += 10;`.
4. Возвращаемого значения методу не требуется (`void`), так как все изменения происходят «на месте» (in-place) через ссылки.

**Решение в общем виде и код программы:**

```csharp
using System;

class Program
{
    static void Main()
    {
        // Инициализация трех переменных перед вызовом
        int num1 = 5;
        int num2 = 12;
        int num3 = -3;

        Console.WriteLine($"До вызова метода: num1 = {num1}, num2 = {num2}, num3 = {num3}");

        // Вызов метода с передачей всех трех переменных по ссылке
        IncrementAll(ref num1, ref num2, ref num3);

        Console.WriteLine($"После вызова метода: num1 = {num1}, num2 = {num2}, num3 = {num3}");
    }

    static void IncrementAll(ref int x, ref int y, ref int z)
    {
        x += 10;
        y += 10;
        z += 10;
    }
}
```

**Вычисление и проверка:**
- `num1 = 5 + 10 = 15`.
- `num2 = 12 + 10 = 22`.
- `num3 = -3 + 10 = 7`.
- Проверка: все вычисления выполнены без ошибок, учтены знаки чисел (отрицательное число `-3` при сложении с положительным `10` дает корректный результат `7`).
- Правдоподобность: каждое число увеличилось ровно на заданную величину, исходные переменные успешно модифицированы.

`Ответ:` После вызова метода: `num1 = 15`, `num2 = 22`, `num3 = 7`.

## 4. Возврат нескольких результатов: модификатор out

### 4. Возврат нескольких результатов: модификатор out

В языке C# классический механизм возврата результата работы метода через ключевое слово `return` имеет фундаментальное ограничение: **метод может вернуть ровно одно значение**. 

Если вам нужно вернуть из метода результаты вычислений, состоящие из двух, трех и более независимых величин, обычного `return` становится недостаточно. На практике часто возникают ситуации, когда требуется получить не просто результат, а целый набор диагностических данных. 

Рассмотрим классический пример из стандартной библиотеки .NET. Когда вы пытаетесь преобразовать строку в число с помощью метода `int.Parse("123")`, в случае некорректного ввода (например, `int.Parse("abc")`) программа выбрасывает исключение (`FormatException`) и аварийно завершает работу. Для безопасного анализа ввода разработчики используют метод `int.TryParse`. Этот метод решает сразу две задачи:
1. Сообщает об успехе или неудаче операции (возвращая логическое значение `bool` через `return`).
2. Передает само распарсенное число вызывающему коду (даже если оно находится в другом месте памяти).

Для реализации такого поведения в C# используется модификатор параметров `out` (от англ. *output* — выходной).

> **Определение.** Модификатор `out` — это ключевое слово в сигнатуре метода и при вызове, которое указывает компилятору, что аргумент передается по ссылке с целью записи в него значения внутри вызываемого метода. Переменная, помеченная `out`, служит «шлюзом» для экспорта данных из недр метода обратно в вызывающий код.

---

### Главные отличия `out` от `ref`

На первый взгляд `out` и рассмотренный ранее `ref` работают одинаково: оба передают переменную по ссылке, позволяя методу изменять ее значение снаружи. Однако между ними есть два ключевых архитектурных и синтаксических отличия:

1. **Инициализация до вызова.** 
   - Для `ref` переменная **обязана** быть объявлена и проинициализирована *до* вызова метода (поскольку метод имеет право сначала прочитать ее старое значение).
   - Для `out` переменная **не обязана** быть инициализирована до вызова. Более того, вы можете передать совершенно пустую (неинициализированную) переменную, так как метод гарантированно перезапишет ее значение.

2. **Обязанность метода внутри.**
   - Для `ref` метод имеет право изменять значение, но не обязан это делать.
   - Для `out` метод **жестко обязан** присвоить новое значение параметру до своего завершения (на абсолютно всех возможных ветках выполнения). Компилятор C# производит статическую проверку кода: если существует хотя бы один путь выполнения, при котором `out`-параметр останется без присвоенного значения, возникнет ошибка компиляции.

---

### Синтаксис и современные возможности C# (Inline Out)

В объявлении метода модификатор `out` ставится перед типом данных параметра. При вызове метода перед передаваемой переменной также обязательно пишется ключевое слово `out`.

До версии C# 7.0 разработчики были вынуждены заранее объявлять переменную перед вызовом метода:
```csharp
int result; // предварительное объявление
bool success = int.TryParse("456", out result);
```

Начиная с версии C# 7.0 и выше (включая .NET 8, используемый в нашем курсе), поддерживается **инлайн-объявление** (inline out). Вы можете объявить переменную прямо в момент вызова метода. Это делает код чище и избавляет от лишних строк:
```csharp
// Объявление переменной 'result' происходит прямо в вызове метода
if (int.TryParse("456", out int result))
{
    Console.WriteLine($"Успешно! Число: {result}");
}
```

### Разобранный пример 1: Вычисление площади и периметра прямоугольника

Представим, что мы пишем геометрическую библиотеку. Нам нужно разработать метод, который принимает вещественные стороны прямоугольника (ширину и высоту), а возвращает сразу два независимых параметра: площадь и периметр. Поскольку `return` занят возвратом только одного значения (например, флага успешности расчетов), мы применим два `out`-параметра.

#### Условие задачи
Написать метод `GetRectangleStats(double width, double height, out double area, out double perimeter)`, который принимает ширину и высоту прямоугольника, а через параметры `out` возвращает его площадь и периметр. В методе `Main` протестировать работу разработанного метода для сторон `width = 5{,}5` и `height = 4{,}0`.

#### Рисунок словами
```text
Вызывающий код (Main):
[ Переменная width = 5,5 ] ---> (передача по значению) ---> Метод GetRectangleStats
[ Переменная height = 4,0 ] ---> (передача по значению) ---> Метод GetRectangleStats
                                                                     |
[ Пустая переменная area ]      <--- (запись результата out) <-------|
[ Пустая переменная perimeter ] <--- (запись результата out) <-------+
```

#### Ход рассуждений
1. Метод не должен возвращать сложный объект через `return`, поэтому тип возвращаемого значения метода укажем как `void` (ничего не возвращает стандартным путем).
2. Параметры `width` и `height` передаются обычно (по значению), так как метод будет только читать их размеры.
3. Параметры `area` и `perimeter` объявляем с ключевым словом `out double`, так как они предназначены для вывода результатов наружу.
4. Внутри метода вычисляем площадь по формуле $S = \text{width} \cdot \text{height}$ и периметр по формуле $P = 2 \cdot (\text{width} + \text{height})$.
5. Присваиваем вычисленные значения `out`-параметрам. Компилятор проверит, что присваивание произошло.
6. В методе `Main` вызываем метод, используя инлайн-объявление переменных для `out`.

#### Решение на C#

```csharp
using System;

class Program
{
    static void Main()
    {
        double w = 5.5;
        double h = 4.0;

        // Вызываем метод, передавая пустые переменные area и perimeter через out.
        // Используем инлайн-объявление (out double area, out double perimeter).
        GetRectangleStats(w, h, out double area, out double perimeter);

        Console.WriteLine($"Ширина: {w}, Высота: {h}");
        Console.WriteLine($"Площадь прямоугольника: {area}");
        Console.WriteLine($"Периметр прямоугольника: {perimeter}");
    }

    // Метод принимает размеры и заполняет два выходных параметра
    static void GetRectangleStats(double width, double height, out double area, out double perimeter)
    {
        // Вычисляем площадь
        area = width * height;

        // Вычисляем периметр
        perimeter = 2 * (width + height);
        
        // Оба out-параметра получили значения. Обязанность перед компилятором выполнена.
    }
}
```

#### Подстановка и вычисление
- Входные данные: $\text{width} = 5{,}5$, $\text{height} = 4{,}0$.
- Расчет площади: $\text{area} = 5{,}5 \cdot 4{,}0 = 22{,}0$.
- Расчет периметра: $\text{perimeter} = 2 \cdot (5{,}5 + 4{,}0) = 2 \cdot 9{,}5 = 19{,}0$.

#### Проверка
- Единицы измерения: стороны заданы в условных единицах (например, метры). Площадь измеряется в квадратных метрах ($\text{м}^2$), периметр — в метрах ($\text{м}$). Расчеты корректны по размерности.
- Правдоподобие: для прямоугольника со сторонами $5{,}5$ и $4$ площадь $22$ выглядит абсолютно верно ($5 \cdot 4 = 20$, да еще половина от $4$ и от $5$, итого $20 + 2 + 0{,}5 = 22{,}5$ — нет, пересчитаем: $5{,}5 \cdot 4 = (5 \cdot 4) + (0{,}5 \cdot 4) = 20 + 2 = 22$). Ошибка исключена, пересчет подтвержден. Периметр: $5{,}5 + 5{,}5 + 4 + 4 = 11 + 8 = 19$. Всё сошлось.

`Ответ:` Площадь: 22; Периметр: 19.

### Разобранный пример 2: Безопасное деление с остатком и кодом возврата

Рассмотрим более жизненную задачу. При делении целых чисел может возникнуть критическая ситуация — деление на ноль. Нам нужно спроектировать метод целочисленного деления, который:
- Возвращает логическое значение `bool` (`true`, если деление прошло успешно, и `false`, если делитель равен нулю).
- Возвращает через `out`-параметры два значения: частное (целую часть от деления) и остаток от деления.

#### Условие задачи
Создать метод `SafeDivide(int numerator, int denominator, out int quotient, out int remainder)`. Метод должен возвращать `bool` (успех операции). Если знаменатель (`denominator`) равен нулю, метод должен вернуть `false`, а в параметры `quotient` и `remainder` записать нули. Если знаменатель не равен нулю, вычислить частное (`numerator / denominator`) и остаток (`numerator % denominator`), записать их в `out`-параметры и вернуть `true`. Продемонстрировать работу метода в `Main` для двух сценариев: успешное деление и попытка деления на ноль.

#### Рисунок словами
```text
Сценарий 1 (Деление на 2):
numerator = 10, denominator = 3 
   ---> SafeDivide(...) ---> возвращает true
                          ---> quotient = 3 (записано через out)
                          ---> remainder = 1 (записано через out)

Сценарий 2 (Деление на 0):
numerator = 10, denominator = 0 
   ---> SafeDivide(...) ---> возвращает false
                          ---> quotient = 0 (записано через out)
                          ---> remainder = 0 (записано через out)
```

#### Ход рассуждений
1. Сигнатура метода должна возвращать `bool`: `static bool SafeDivide(int numerator, int denominator, out int quotient, out int remainder)`.
2. Внутри метода первым делом проверяем условие безопасности: `if (denominator == 0)`.
3. Если условие истинно (делитель равен нулю), мы обязаны присвоить какие-то значения выходным параметрам, прежде чем сделать `return false`:
   `quotient = 0;`
   `remainder = 0;`
   `return false;`
4. Если делитель не равен нулю, выполняем математические операции:
   `quotient = numerator / denominator;`
   `remainder = numerator % denominator;`
   `return true;`
5. Обратите внимание на жесткое правило компилятора: если бы мы забыли написать ветку с присваиванием `quotient` и `remainder` при `denominator == 0`, компилятор выдал бы ошибку: *«Use of unassigned out parameter 'quotient'»* (Использование не присвоенного выходного параметра). Компилятор заботится о том, чтобы вызывающий код никогда не получил «мусор» из памяти.
6. В методе `Main` организуем проверку с помощью условного оператора `if` и инлайн-объявления `out`-переменных.

#### Решение на C#

```csharp
using System;

class Program
{
    static void Main()
    {
        int num1 = 17;
        int den1 = 5;

        Console.WriteLine($"Попытка разделить {num1} на {den1}:");
        // Проверяем успешность через возвращаемое значение bool, 
        // а результаты забираем через out-параметры q и r
        if (SafeDivide(num1, den1, out int q1, out int r1))
        {
            Console.WriteLine($"Успех! Частное: {q1}, Остаток: {r1}");
        }
        else
        {
            Console.WriteLine("Ошибка: деление на ноль!");
        }

        Console.WriteLine();

        int num2 = 42;
        int den2 = 0;

        Console.WriteLine($"Попытка разделить {num2} на {den2}:");
        if (SafeDivide(num2, den2, out int q2, out int r2))
        {
            Console.WriteLine($"Успех! Частное: {q2}, Остаток: {r2}");
        }
        else
        {
            Console.WriteLine("Ошибка: деление на ноль! Результаты заполнены нулями: " +
                              $"q = {q2}, r = {r2}");
        }
    }

    // Метод безопасного деления
    static bool SafeDivide(int numerator, int denominator, out int quotient, out int remainder)
    {
        // Проверка на деление на ноль
        if (denominator == 0)
        {
            // Жесткое требование: присваиваем значения на этой ветке выполнения
            quotient = 0;
            remainder = 0;
            return false; // Возвращаем признак неудачной операции
        }

        // Вычисления для штатного режима
        quotient = numerator / denominator;     // Целочисленное деление (17 / 5 = 3)
        remainder = numerator % denominator;    // Остаток от деления (17 % 5 = 2)
        
        return true; // Возвращаем признак успешной операции
    }
}
```

#### Подстановка и вычисление
- **Тест 1:** `17` и `5`.
  - Делитель не равен нулю ($5 \neq 0$).
  - `quotient = 17 / 5 = 3`.
  - `remainder = 17 % 5 = 2` (поскольку $3 \cdot 5 + 2 = 17$).
  - Метод возвращает `true`.
- **Тест 2:** `42` и `0`.
  - Делитель равен нулю.
  - Срабатывает ветка `if`: `quotient = 0`, `remainder = 0`.
  - Метод возвращает `false`.

#### Проверка
- Типы данных соблюдены: входные и выходные параметры имеют тип `int`, результат метода — `bool`.
- Логика компилятора удовлетворена: переменные `quotient` и `remainder` гарантированно получают значения абсолютно на всех путях выполнения метода (и в ветке `if`, и в основном коде после него). Исключения деления на ноль не происходит, программа работает стабильно и предсказуемо.

`Ответ:` 
Для 17 и 5: Успех! Частное: 3, Остаток: 2.
Для 42 и 0: Ошибка: деление на ноль! Результаты заполнены нулями: q = 0, r = 0.

## 5. Переменное число аргументов: модификатор params

### Проблема передачи произвольного количества однотипных аргументов в метод

При проектировании методов часто возникает задача: заранее неизвестно, сколько именно значений потребуется передать для обработки. Например, необходимо написать метод для вычисления суммы чисел, поиска максимального элемента или форматирования строки. 

До появления специальных языковых механизмов в C# разработчики были вынуждены использовать один из следующих подходов:
1. Передавать массив фиксированного размера.
2. Создавать несколько перегрузок метода с разным количеством параметров (например, версию для двух чисел, для трех, для четырех и т. д.).

У каждого из этих подходов есть серьезные недостатки. Использование массива требует от вызывающего кода предварительного создания и заполнения объекта массива, что приводит к избыточному boilerplate-коду (громоздкому вспомогательному коду):

```csharp
// Требуется вручную создавать массив перед вызовом метода
int[] data = new int[] { 5, 10, 15 };
int s = Sum(data);
```

Создание перегрузок также неэффективно, так как невозможно предусмотреть все возможные сценарии (что, если пользователю потребуется передать 10 аргументов, а написано только 5 перегрузок?).

Для решения этой проблемы в языке C# предусмотрен специальный модификатор `params`, который позволяет передавать в метод произвольное (в том числе нулевое) количество аргументов одного типа, записывая их через запятую.

### Ключевое слово `params` и одномерный массив за кулисами

> **Определение.** Модификатор `params` — это языковая конструкция C#, которая указывает компилятору, что метод может принимать переменное число аргументов определенного типа, упаковывая их в одномерный массив за кулисами.

Когда компилятор встречает метод, у которого последний параметр помечен ключевым словом `params`, он автоматически выполняет следующие действия:
1. При вызове метода с произвольным набором аргументов через запятую компилятор неявно создает массив (`new T[] { ... }`).
2. Помещает все переданные аргументы в этот созданный массив.
3. Передает этот массив внутрь метода.

Таким образом, с точки зрения тела вызываемого метода `params` ничем не отличается от обычного одномерного массива. Разница заключается исключительно в синтаксисе вызова: вызывающий код освобождается от необходимости вручную создавать массив.

Рассмотрим синтаксис объявления такого метода:

```csharp
static void PrintValues(params string[] values)
{
    Console.WriteLine($"Получено элементов: {values.Length}");
    for (int i = 0; i < values.Length; i++)
    {
        Console.WriteLine($"Элемент {i}: {values[i]}");
    }
}
```

Этот метод можно вызывать различными способами:

```csharp
// 1. Передача нескольких аргументов через запятую
PrintValues("Яблоко", "Банан", "Апельсин");

// 2. Передача одного аргумента
PrintValues("Груша");

// 3. Вызов без аргументов (будет создан пустой массив длиной 0)
PrintValues();

// 4. Явная передача готового массива
string[] fruits = new string[] { "Киви", "Манго" };
PrintValues(fruits);
```

### Правила размещения `params` и ограничения синтаксиса

Использование модификатора `params` подчиняется строгим правилам компилятора C#, нарушение которых приводит к ошибке компиляции.

1. **Позиция в списке параметров.** Параметр с модификатором `params` всегда должен быть **последним** в списке параметров метода. Нельзя объявить параметр типа `params`, после которого шли бы обычные параметры. Это объясняется тем, что компилятор должен понимать, какие именно аргументы из переданного списка относятся к параметру с `params`, а какие — к фиксированным параметрам.
2. **Количество параметров `params`.** В сигнатуре одного метода может быть только **один** параметр с модификатором `params`. Размещение двух таких параметров привело бы к неоднозначности при определении того, где заканчивается первый массив аргументов и начинается второй.
3. **Тип данных.** Параметр `params` обязан быть одномерным массивом (`T[]`), зубчатые или многомерные массивы (`T[,]`, `T[][]`) в качестве `params` использовать напрямую нельзя (хотя тип элементов `T` может быть любым, включая массивы или пользовательские структуры и классы).

Пример корректной сигнатуры метода со смешанными параметрами:

```csharp
// Корректно: фиксированный параметр идет первым, params — последним
static void LogMessage(string prefix, params string[] messages)
{
    foreach (var msg in messages)
    {
        Console.WriteLine($"{prefix}: {msg}");
    }
}
```

Пример некорректной сигнатуры (вызовет ошибку компиляции CS1025 или аналогичную):

```csharp
// НЕКОРРЕКТНО! Ошибка компиляции: параметр params должен быть последним
static void BadMethod(params int[] numbers, string label) { }

// НЕКОРРЕКТНО! Ошибка компиляции: допускается только один params на метод
static void BadMethod2(params int[] first, params int[] second) { }
```

### Разобранный пример 1: Вычисление суммы произвольного набора чисел

Реализуем метод `SumAll`, который принимает произвольное число целых чисел и возвращает их сумму.

#### Условие задачи
Написать консольное приложение на C#, содержащее метод `SumAll`, принимающий с помощью `params` набор целых чисел. В методе `Main` продемонстрировать вызов этого метода тремя способами:
1. Передав пять чисел через запятую.
2. Передав одно число.
3. Не передавая аргументов вообще.
Вывести результаты работы на консоль.

#### Рисунок словами (схема работы программы)
```
Вызов Main() 
  │
  ├─> SumAll(10, 20, 30, 40, 50) ──> Компилятор создает int[] {10, 20, 30, 40, 50} ──> Сумма = 150
  │
  ├─> SumAll(7)                  ──> Компилятор создает int[] {7}               ──> Сумма = 7
  │
  └─> SumAll()                   ──> Компилятор создает int[] {} (пустой)      ──> Сумма = 0
```

#### Ход рассуждений
1. Объявляем метод со статическим модификатором (так как вызываем из статического метода `Main`), возвращающим тип `int`.
2. Сигнатура метода: `static int SumAll(params int[] numbers)`.
3. Внутри метода проверяем частный случай: если массив `numbers` равен `null` (хотя компилятор `params` обычно передает пустой массив, а не `null`, проверка на `numbers.Length == 0` хороша для безопасности), возвращаем `0`.
4. Используем цикл `foreach` для последовательного суммирования всех элементов массива в аккумуляторную переменную.
5. Возвращаем итоговое значение через `return`.

#### Полный код программы

```csharp
using System;

class Program
{
    static void Main(string[] args)
    {
        // Способ 1: передача пяти аргументов через запятую
        int sum1 = SumAll(10, 20, 30, 40, 50);
        Console.WriteLine($"Сумма пяти чисел (10, 20, 30, 40, 50): {sum1}");

        // Способ 2: передача одного аргумента
        int sum2 = SumAll(7);
        Console.WriteLine($"Сумма одного числа (7): {sum2}");

        // Способ 3: вызов без аргументов
        int sum3 = SumAll();
        Console.WriteLine($"Сумма без аргументов: {sum3}");

        // Способ 4: явная передача готового массива
        int[] customArray = new int[] { 2, 4, 6, 8 };
        int sum4 = SumAll(customArray);
        Console.WriteLine($"Сумма элементов готового массива (2, 4, 6, 8): {sum4}");
    }

    /// <summary>
    /// Вычисляет сумму произвольного набора целых чисел.
    /// </summary>
    /// <param name="numbers">Набор чисел через params.</param>
    /// <returns>Сумма всех переданных чисел.</returns>
    static int SumAll(params int[] numbers)
    {
        // Защита от передачи null (на случай вызова рефлексией или явного null)
        if (numbers == null)
        {
            return 0;
        }

        int total = 0;
        for (int i = 0; i < numbers.Length; i++)
        {
            total += numbers[i];
        }

        return total;
    }
}
```

#### Вывод в консоли
```text
Сумма пяти чисел (10, 20, 30, 40, 50): 150
Сумма одного числа (7): 7
Сумма без аргументов: 0
Сумма элементов готового массива (2, 4, 6, 8): 20
```

#### Проверка и оценка сложности
- **Единицы измерения:** В данной задаче оперируем целыми безразмерными числами (`int`).
- **Правдоподобность:** При пустом наборе алгоритм корректно возвращает `0` (нейтральный элемент по сложению). При одном числе возвращает само число. Вычисления верны.
- **Оценка сложности:** 
  - Пространственная сложность: $O(N)$ на создание неявного массива при каждом вызове (где $N$ — количество аргументов).
  - Временная сложность: $O(N)$ на проход по массиву элементов для их суммирования.

### Разобранный пример 2: Поиск наибольшего числа с использованием `params`

Реализуем метод `FindMaximum`, который принимает набор чисел с плавающей точкой двойной точности (`double`) и находит среди них максимальное значение.

#### Условие задачи
Написать метод `FindMaximum(params double[] values)`, который возвращает наибольшее число из переданного набора. Если набор пуст или передан `null`, метод должен выбрасывать исключение `ArgumentException`. Продемонстрировать работу метода в `Main`, обработав потенциальное исключение при попытке вызова с пустым списком.

#### Рисунок словами
```
Аргументы: 4{ 3.5, 12.8, -5.1, 8.2 }
Начальный максимум = values[0] (3.5)
Итерация 1: 12.8 > 3.5  ──> Максимум = 12.8
Итерация 2: -5.1 > 12.8 ──> Ложь (максимум прежний)
Итерация 3: 8.2 > 12.8  ──> Ложь (максимум прежний)
Результат: 12.8
```

#### Ход рассуждений
1. Создаем статический метод, возвращающий `double`.
2. Проверяем валидность входных данных: если массив `values == null` или его длина `values.Length == 0`, выбрасываем исключение `new ArgumentException("Список аргументов пуст.")`, так как найти максимум в пустом множестве невозможно без возврата неопределенного значения.
3. Принимаем за начальное значение максимума первый элемент массива: `double max = values[0];`.
4. Запускаем цикл со второго элемента (индекс `1`) до конца массива.
5. На каждой итерации сравниваем текущий элемент массива с переменной `max`. Если текущий элемент больше, обновляем значение `max`.
6. Возвращаем найденный максимум через `return`.

#### Полный код программы

```csharp
using System;

class Program
{
    static void Main(string[] args)
    {
        // 1. Обычный вызов с несколькими аргументами типа double
        double max1 = FindMaximum(5.5, 12.1, 3.8, 12.15, -2.4);
        Console.WriteLine($"Максимальное число: {max1}");

        // 2. Вызов с одним аргументом
        double max2 = FindMaximum(42.0);
        Console.WriteLine($"Максимальное число (один аргумент): {max2}");

        // 3. Обработка исключения при передаче пустого набора
        try
        {
            Console.WriteLine("Попытка найти максимум среди пустого набора...");
            double maxEmpty = FindMaximum();
            Console.WriteLine($"Результат: {maxEmpty}");
        }
        catch (ArgumentException ex)
        {
            Console.WriteLine($"Перехвачена ошибка: {ex.Message}");
        }
    }

    /// <summary>
    /// Находит наибольшее число среди произвольного набора вещественных чисел.
    /// </summary>
    /// <param name="values">Набор чисел типа double.</param>
    /// <returns>Наибольшее число из набора.</returns>
    static double FindMaximum(params double[] values)
    {
        // Проверяем, переданы ли данные
        if (values == null || values.Length == 0)
        {
            throw new ArgumentException("Для поиска максимума необходимо передать хотя бы один аргумент.");
        }

        double max = values[0];

        for (int i = 1; i < values.Length; i++)
        {
            if (values[i] > max)
            {
                max = values[i];
            }
        }

        return max;
    }
}
```

#### Вывод в консоли
```text
Максимальное число: 12,15
Максимальное число (один аргумент): 42
Попытка найти максимум среди пустого набора...
Перехвачена ошибка: Для поиска максимума необходимо передать хотя бы один аргумент.
```

#### Проверка и оценка сложности
- **Единицы измерения:** Вещественные числа двойной точности (`double`).
- **Правдоподобность:** При передаче положительных и отрицательных чисел алгоритм корректно определяет наибольшее (учитывая, что отрицательные числа ближе к нулю больше тех, что по модулю больше). Исключение срабатывает корректно при пустом вводе.
- **Оценка сложности:**
  - Пространственная сложность: $O(N)$ на выделение памяти под массив аргументов.
  - Временная сложность: $O(N)$, где $N$ — количество переданных элементов, так как требуется ровно один проход по всем элементам для поиска максимума.

## 6. Особенности передачи массивов и ссылочных типов в методы

### 6. Особенности передачи массивов и ссылочных типов в методы

Прежде чем разбирать поведение массивов при передаче в методы, необходимо четко разделять два фундаментальных вида типов данных в платформе .NET: значимые типы (`value types`) и ссылочные типы (`reference types`). Понимание того, как эти типы размещаются в памяти (в стеке и в куче), полностью объясняет все особенности их передачи в методы.

Значимые типы (например, `int`, `double`, `bool`, `char`, а также структуры `struct`) хранят в своей ячейке памяти непосредственно само значение. Когда мы передаем переменную значимого типа в метод по значению (по умолчанию), среда выполнения копирует само число или структуру в новый участок памяти, выделенный для параметра метода. Любые изменения этого параметра внутри метода никак не затрагивают исходную переменную в вызывающем коде.

Ссылки и ссылочные типы (например, массивы `int[]`, строки `string`, созданные нами классы `class`) устроены иначе. Переменная ссылочного типа хранит не сам объект (например, массив из ста элементов), а **адрес в памяти** (ссылку), по которому этот объект располагается. Сам объект всегда создается в динамической памяти — в **куче** (`heap`), тогда как переменная, содержащая его адрес, находится в стеке.

> **Определение.** Передача ссылочного типа по значению означает, что в качестве аргумента в метод передается не сам объект (например, весь массив), а **копия его адреса (ссылки)**. И исходная переменная, и параметр метода начинают указывать на одну и ту же область памяти в куче.

Рассмотрим этот процесс на схеме памяти. Пусть в методе `Main` создан массив:

```csharp
int[] numbers = { 10, 20, 30 };
```

В памяти это выглядит следующим образом:

```text
Стек вызовов (Main):                 Куча (Heap):
+-----------------+                 +-----------------------+
| numbers         | --------------> | [0]: 10 | [1]: 20 | [2]: 30 |
+-----------------+                 +-----------------------+
 (хранит адрес)                      (сам массив в памяти)
```

### Изменение элементов массива внутри метода

Когда мы передаем массив `numbers` в метод без каких-либо дополнительных модификаторов (то есть по значению), в стек вызываемого метода заносится копия переменной `numbers`. Назовем этот параметр `arr`.

Поскольку `arr` получает точную копию адреса (ссылки), он указывает ровно на тот же самый массив в куче, что и переменная `numbers` в `Main`. Следовательно, если внутри метода обратиться к элементу массива по индексу и изменить его, изменения мгновенно отразятся на исходном массиве. Ведь метод не создает новый массив, а модифицирует данные по тому же самому адресу.

Разберем первый подробный пример. Нам нужно написать метод `ZeroOut(int[] arr)`, который принимает массив целых чисел и обнуляет все его элементы, после чего проверить в методе `Main`, сохранились ли изменения.

**Полный исходный код программы:**

```csharp
using System;

class Program
{
    static void Main()
    {
        // Исходные данные
        int[] originalArray = { 5, 12, 19, 24 };

        Console.WriteLine("До вызова метода:");
        PrintArray(originalArray);

        // Вызываем метод передачи массива по значению
        ZeroOut(originalArray);

        Console.WriteLine("\nПосле вызова метода ZeroOut:");
        PrintArray(originalArray);
    }

    // Метод, обнуляющий элементы массива
    static void ZeroOut(int[] arr)
    {
        // Проверяем аргумент на null во избежание NullReferenceException
        if (arr == null) return;

        for (int i = 0; i < arr.Length; i++)
        {
            arr[i] = 0; // Изменяем элемент по адресу в куче
        }
    }

    // Вспомогательный метод для вывода массива на консоль
    static void PrintArray(int[] arr)
    {
        Console.WriteLine(string.Join(", ", arr));
    }
}
```

**Пошаговый разбор хода выполнения и рассуждений:**

1. В методе `Main` создается массив `originalArray`, содержащий четыре элемента: `5, 12, 19, 24`. Переменная `originalArray` в стеке хранит ссылку (адрес `0x1000`) на этот массив в куче.
2. Вызывается метод `ZeroOut(originalArray)`. Среда выполнения создает локальный параметр `arr` и копирует в него значение `originalArray`, то есть тот же адрес `0x1000`.
3. Управление передается в тело метода `ZeroOut`. Переменная `arr` и переменная `originalArray` указывают на одну и ту же область памяти в куче.
4. Цикл `for` проходит по всем индексам от `0` до `3` и выполняет операцию `arr[i] = 0`. Поскольку обращение идет по адресу `0x1000`, ячейки памяти в куче перезаписываются нулями.
5. Метод завершает работу. Параметр `arr` уничтожается в стеке.
6. Возвращаемся в метод `Main`. Вызываем `PrintArray(originalArray)`. Поскольку массив в куче был изменен по тому же адресу, на который ссылается `originalArray`, на экран выводятся нули.

**Вывод программы:**
```text
До вызова метода:
5, 12, 19, 24

После вызова метода ZeroOut:
0, 0, 0, 0
```

**Проверка единиц и правдоподобия:** Ошибка, которую часто совершают начинающие программисты, заключается в смешении понятий «передача ссылки по значению» и «передача по ссылке». Студенты часто думают, что раз массив изменился, значит, он передавался по ссылке (`ref`). Это не так. Изменился не сам указатель, а содержимое объекта по этому указателю.

### Переприсваивание ссылки внутри метода

Теперь рассмотрим обратную ситуацию: что произойдет, если внутри метода попытаться не просто изменить элементы существующего массива, а направить переменную-ссылку на **совершенно новый массив** с помощью оператора `new`?

Если мы пишем `arr = new int[5];`, мы меняем значение локальной переменной `arr` (копии адреса) в стеке вызываемого метода. Мы записываем в нее новый адрес, указывающий на новый блок памяти в куче. При этом исходная переменная в методе `Main` продолжает хранить свой старый адрес и указывать на старый массив. Никаких изменений со старым массивом не происходит.

Рассмотрим второй разобранный пример. Нам необходимо написать метод `ReplaceArray(int[] arr)`, который пытается заменить переданный массив новым массивом из нулей, а затем сравнить это поведение с методом, использующим модификатор `ref`.

**Полный компилируемый код:**

```csharp
using System;

class Program
{
    static void Main()
    {
        // Пример 1: Обычная передача массива по значению (ссылка не меняется)
        int[] myArray = { 1, 2, 3 };
        Console.WriteLine("До TryReplace: " + string.Join(", ", myArray));

        TryReplace(myArray);

        Console.WriteLine("После TryReplace (без ref): " + string.Join(", ", myArray));
        // Массив остался прежним: { 1, 2, 3 }

        Console.WriteLine(new string('-', 40));

        // Пример 2: Передача массива по ссылке с использованием ключевого слова ref
        int[] mySecondArray = { 10, 20, 30 };
        Console.WriteLine("До ReplaceWithRef: " + string.Join(", ", mySecondArray));

        ReplaceWithRef(ref mySecondArray);

        Console.WriteLine("После ReplaceWithRef (с ref): " + string.Join(", ", mySecondArray));
        // Массив изменился на новый: { 0, 0, 0, 0, 0 }
    }

    // Метод пытается заменить ссылку на новый массив (без ref)
    static void TryReplace(int[] arr)
    {
        // Создаем новый массив в куче, локальная переменная arr получает новый адрес
        arr = new int[] { 99, 99, 99 };
        
        // Изменения касаются ТОЛЬКО локальной переменной arr внутри метода TryReplace
    }

    // Метод заменяет саму ссылку на массив благодаря модификатору ref
    static void ReplaceWithRef(ref int[] arr)
    {
        // Оператор ref передает не копию адреса, а саму ссылку из Main
        arr = new int[] { 0, 0, 0, 0, 0 };
        
        // Теперь исходная переменная в Main будет указывать на этот новый массив
    }
}
```

**Ход рассуждений и пошаговый анализ:**

1. В первом случае (`TryReplace`) в метод передается копия адреса массива `myArray`.
2. Внутри метода `TryReplace` выполняется инструкция `arr = new int[] { 99, 99, 99 }`. В куче выделяется память под новый массив, а в локальную переменную `arr` записывается его адрес. Переменная `myArray` в методе `Main` о существовании этого нового адреса ничего не знает — она по-прежнему хранит адрес старого массива `{ 1, 2, 3 }`. После выхода из метода локальная переменная уничтожается, а новый массив удаляется сборщиком мусора, так как на него больше никто не ссылается. Исходный массив остался неизменным.
3. Во втором случае (`ReplaceWithRef`) используется модификатор `ref`. В сигнатуре метода и при вызове явно указано `ref int[] arr`. Это означает, что метод получает доступ не к копии адреса, а к самой ячейке памяти в стеке метода `Main`, где хранится адрес `mySecondArray`.
4. Когда внутри `ReplaceWithRef` выполняется присваивание `arr = new int[] { 0, 0, 0, 0, 0 }`, оно перезаписывает значение **непосредственно в переменной `mySecondArray` из метода `Main`**. Теперь переменная `mySecondArray` указывает на новый массив из пяти нулей. Старый массив `{ 10, 20, 30 }` теряет свою единственную внешнюю ссылку и подлежит очистке сборщиком мусора.

**Вывод программы:**
```text
До TryReplace: 1, 2, 3
После TryReplace (без ref): 1, 2, 3
----------------------------------------
До ReplaceWithRef: 10, 20, 30
После ReplaceWithRef (с ref): 0, 0, 0, 0, 0
```

**Оценка сложности:** 
- Время работы методов изменения элементов массива составляет $O(N)$, где $N$ — количество элементов в массиве (при необходимости обойти все элементы для изменения). Операция переприсваивания ссылки (включая вариант с `ref`) выполняется за константное время $O(1)$, так как меняется лишь адресное значение в памяти, однако создание нового массива через `new` требует выделения памяти в куче за время $O(K)$, где $K$ — размер нового массива.
- Затраты памяти: при передаче по значению создается лишь одна переменная под адрес в стеке ($O(1)$ дополнительной памяти).

### Сравнительная таблица поведения ссылочных типов (массивов)

| Способ передачи | Что копируется | Изменение элементов (`arr[0] = 5`) | Переприсваивание ссылки (`arr = new int[...]`) | Влияние на переменную в `Main` при переприсваивании |
|---|---|---|---|---|
| **По значению (default)** | Копия адреса (ссылки) | Изменяет элементы исходного массива в куче | Меняет только локальную копию адреса в стеке метода | **Нет**, исходный массив в `Main` не меняется |
| **По ссылке (`ref`)** | Сама ссылка (указатель на ячейку стека) | Изменяет элементы исходного массива в куче | Меняет адрес в исходной переменной `Main` | **Да**, исходная переменная начинает указывать на новый объект |

Понимание этих механизмов критически важно при проектировании архитектуры приложений на C#, так как некорректное обращение со ссылочными типами часто приводит к трудноуловимым логическим ошибкам и утечкам памяти, которые не вызывают ошибок компиляции, но искажают результаты работы программы.

```csharp
using System;

class Program
{
    static void Main(string[] args)
    {
        // Тест 1: Стандартный набор положительных и отрицательных чисел
        double max1 = FindMaximum(3.5, 12.8, -5.1, 8.2, 12.8, 0.0);
        Console.WriteLine($"Максимальное число: {max1}");

        // Тест 2: Набор из одного элемента

        Console.WriteLine($"Максимальное число (один элемент): {max2}");

        // Тест 3: Попытка вызова с пустым набором (обработка исключения)
        try
        {
            Console.WriteLine("Попытка найти максимум в пустом списке...");
            double maxEmpty = FindMaximum();
            Console.WriteLine($"Максимум: {maxEmpty}");
        }
        catch (ArgumentException ex)
        {
            Console.WriteLine($"Перехвачено исключение: {ex.Message}");
        }
    }

    /// <summary>
    /// Находит максимальное значение среди произвольного набора чисел типа double.
    /// </summary>
    /// <param name="values">Набор чисел через params.</param>
    /// <returns>Наибольшее число из набора.</returns>
    static double FindMaximum(params double[] values)
    {
        // Проверка на пустой массив или null
        if (values == null || values.Length == 0)
        {
            throw new ArgumentException("Невозможно найти максимум: передан пустой набор аргументов.");
        }

        // Принимаем первый элемент за временный максимум
        double max = values[0];

        // Проходим по остальным элементам массива
        for (int i = 1; i < values.Length; i++)
        {
            if (values[i] > max)
            {
                max = values[i];
            }
        }

        return max;
    }
}
```


#### Проверка и оценка сложности
- **Единицы измерения:** Вещественные числа двойной точности (`double`).
- **Правдоподобность:** Алгоритм корректно обрабатывает отрицательные числа, дубликаты максимального значения и единичные элементы. Исключение срабатывает штатно при пустом вводе.
- **Оценка сложности:** 
  - Пространственная сложность: $O(N)$ на создание массива.
  - Временная сложность: $O(N)$ на линейный поиск максимального элемента (нужно проверить каждый элемент массива).

## 6. Особенности передачи массивов и ссылочных типов в методы

### Разница между значимыми и ссылочными типами в памяти

Для глубокого понимания того, как язык C# работает с данными, необходимо четко разделять два фундаментальных вида типов данных: **значимые типы** (Value Types) и **ссылочные типы** (Reference Types).

1. **Значимые типы** (`int`, `double`, `bool`, `char`, а также структуры `struct`) хранят свое реальное значение непосредственно в той области памяти, где они объявлены (обычно в стеке вызовов). Когда вы присваиваете одну переменную значимого типа другой (`int b = a;`), происходит физическое копирование байтов значения.
2. **Ссылки и ссылочные типы** (`string`, массивы `T[]`, классы `class`) устроены сложнее. Сама переменная ссылочного типа хранит не сами данные, а **адрес в памяти** (ссылку), по которому в специальной области оперативной памяти — **куче** (Heap) — располагается реальный объект (например, элементы массива).

Когда мы передаем массив в метод (по умолчанию без модификаторов `ref` или `out`), происходит передача аргумента *по значению*. Однако **что именно** копируется при передаче ссылки по значению? Копируется не сам массив со всеми его элементами, а **значение ссылки** (адрес начала массива в куче).

Это порождает важнейшее архитектурное следствие:
> **Правило ссылочных типов.** Сам адрес скопирован, но обе переменные (и исходная в `Main`, и параметр в методе) указывают на **один и тот же** физический массив в куче. Если метод изменяет элемент массива по этому адресу (например, `arr[0] = 99;`), эти изменения немедленно становятся видны в вызывающем коде, так как объект в куче общий.

---

### Мутабельность массивов при передаче в методы без модификаторов

Рассмотрим этот феномен нагляднее. Изменяя внутреннее содержимое массива внутри метода, мы меняем данные в куче, общие для обоих указателей. Но что произойдет, если внутри метода попытаться переприсвоить саму переменную массива на новый объект (`arr = new int[5];`)? 

- Изменение элементов массива (`arr[i] = ...`) **влияет** на вызывающий код.
- Переприсвоение ссылки (`arr = new int[...]`) **не влияет** на вызывающий код, так как метод перезаписывает свою локальную копию адреса, а оригинальная переменная в `Main` продолжает указывать на старый массив.

---

### Разобранный пример 1: Изменение элементов массива внутри метода

#### Условие задачи
Написать статический метод `DoubleElements(int[] arr)`, который принимает целочисленный массив и умножает каждый его элемент на `2`. В методе `Main` создать массив `[1, 2, 3, 4]`, вывести его элементы на экран, вызвать метод `DoubleElements`, а затем снова вывести элементы массива в `Main`. Проанализировать и объяснить полученный результат.

#### Рисунок словами (схема памяти)
```
Метод Main:
[ ссылка на массив ] ───────┐
                            │
                            ▼
Куча (Heap):          [ 1 | 2 | 3 | 4 ]  <─── Общий массив в памяти
                            ▲
                            │
Метод DoubleElements:       │
[ локальная ссылка arr ] ───┘ (скопирован адрес, а не данные)
```

#### Ход рассуждений
1. В методе `Main` создается массив в куче, а в стеке сохраняется ссылка на него (например, адрес `0x00A0`).
2. Вызывается метод `DoubleElements(myArray)`. В стек метода копируется значение ссылки (`0x00A0`). Теперь и в `Main`, и в параметре `arr` хранится один и тот же адрес `0x00A0`.
3. Внутри метода запускается цикл, который обращается к элементам по адресу `0x00A0` и умножает их на 2. Массив в куче меняется: вместо `[1, 2, 3, 4]` там теперь лежит `[2, 4, 6, 8]`.
4. Метод завершается. Переменная-ссылка `arr` уничтожается в стеке метода, но сам измененный массив в куче продолжает жить.
5. Возвращаемся в `Main`. Обращаясь к исходной переменной массива, мы видим обновленные данные, так как она указывает на тот же самый массив в куче.

#### Решение на C#

```csharp
using System;

class Program
{
    static void Main()
    {
        int[] numbers = { 1, 2, 3, 4 };

        Console.WriteLine("Массив до вызова метода: " + string.Join(", ", numbers));

        // Вызываем метод (передача массива по значению)
        DoubleElements(numbers);

        Console.WriteLine("Массив после вызова метода: " + string.Join(", ", numbers));
    }

    static void DoubleElements(int[] arr)
    {
        // Защита от передачи null
        if (arr == null) return;

        // Изменяем содержимое массива по ссылке
        for (int i = 0; i < arr.Length; i++)
        {
            arr[i] = arr[i] * 2;
        }
    }
}
```

#### Вывод в консоли
```text
Массив до вызова метода: 1, 2, 3, 4
Массив после вызова метода: 2, 4, 6, 8
```

#### Проверка
Элементы массива успешно изменились без использования модификатора `ref`. Это происходит именно потому, что массивы являются ссылочными типами данных.

### Разобранный пример 2: Попытка подмены ссылки на массив (почему массив не заменяется)

#### Условие задачи
Написать статический метод `ReplaceArray(int[] arr)`, который пытается заменить переданный массив на абсолютно новый массив из трех нулей: `arr = new int[] { 0, 0, 0 };`. В методе `Main` создать массив `[10, 20, 30]`, вызвать метод `ReplaceArray`, а затем вывести элементы массива на экран. Объяснить, почему исходный массив в `Main` не изменился.

#### Ход рассуждений
1. В `Main` создан массив `[10, 20, 30]` по адресу, скажем, `0x00B1`.
2. При вызове `ReplaceArray(numbers)` в параметр `arr` копируется адрес `0x00B1`.
3. Внутри метода выполняется инструкция `arr = new int[] { 0, 0, 0 };`. В куче создается **новый** массив `[0, 0, 0]` по новому адресу (например, `0x00C5`), и локальная переменная `arr` начинает указывать на него.
4. При этом переменная `numbers` в методе `Main` продолжает указывать на старый адрес `0x00B1`, где по-прежнему лежат числа `10, 20, 30`.
5. Метод завершается, новый массив `[0, 0, 0]` уничтожается сборщиком мусора, так как на него больше никто не ссылается. Исходный массив в `Main` остается неизменным.

#### Решение на C#

```csharp
using System;

class Program
{
    static void Main()
    {
        int[] numbers = { 10, 20, 30 };

        Console.WriteLine("До вызова метода: " + string.Join(", ", numbers));

        // Пытаемся заменить массив внутри метода
        ReplaceArray(numbers);

        Console.WriteLine("После вызова метода: " + string.Join(", ", numbers));
    }

    static void ReplaceArray(int[] arr)
    {
        // Создаем новый массив и присваиваем его локальной переменной arr
        arr = new int[] { 0, 0, 0 };
        
        Console.WriteLine("Внутри метода (новый массив): " + string.Join(", ", arr));
    }
}
```

#### Вывод в консоли
```text
До вызова метода: 10, 20, 30
Внутри метода (новый массив): 0, 0, 0
После вызова метода: 10, 20, 30
```

#### Проверка и вывод
Исходный массив не изменился, так как переприсваивание ссылки внутри метода затронуло лишь локальную копию указателя. Чтобы метод мог **полностью подменить** сам объект массива в вызывающем коде, ссылку на массив нужно передавать с модификатором `ref` (`ref int[] arr`), что позволяет управлять адресом оригинальной переменной вызывающего кода.

`Ответ:` Массив в методе `Main` остался прежним: `10, 20, 30`.

## Типичные ошибки

1. **Использование неинициализированной переменной с модификатором `ref`**. Ошибка возникает, когда переменная передается в метод через `ref` до того, как ей присвоено значение. Компилятор выдает ошибку, так как метод имеет право сразу прочитать это значение. *Как избежать:* Всегда инициализируйте переменную перед вызовом метода с `ref` (например, `int x = 0;`).
2. **Забыли присвоить значение `out`-параметру на одной из веток выполнения метода**. Возникает, если в методе с `out` есть условный оператор (`if-else`), и в одной из веток забыли записать значение в выходной параметр. *Как избежать:* Компилятор строго проверяет это; убедитесь, что присваивание `out`-параметра гарантированно происходит на абсолютно всех возможных путях выполнения метода.
3. **Попытка переприсвоить ссылочный тип (массив) без `ref` в расчете на изменение внешней переменной**. Происходит, когда разработчик ожидает, что присваивание `arr = new int[...]` внутри метода изменит массив в `Main`. *Как избежать:* Помните, что без `ref` копируется значение ссылки (адрес). Чтобы подменить сам массив на новый объект, используйте `ref int[] arr`.
4. **Нарушение порядка параметров при использовании `params`**. Ошибка возникает, если параметр с модификатором `params` расположен не последним в сигнатуре метода или если параметров `params` объявлено больше одного. *Как избежать:* Размещайте `params` всегда в самом конце списка параметров и следите, чтобы он был единственным в методе.
5. **Путаница с сокрытием имен (Shadowing) во вложенных блоках**. Попытка объявить локальную переменную во вложенном блоке с тем же именем, что и у параметра метода или внешней переменной (в тех языках/контекстах, где это запрещено или приводит к багам логики). *Как избежать:* Дановые переменные должны иметь уникальные понятные имена в рамках метода, избегайте дублирования имен в соседних областях видимости.
6. **Ожидание изменения значения переменной при передаче по значению**. Начинающие часто пишут метод вроде `void AddFive(int x) { x += 5; }` и удивляются, почему переменная в `Main` не изменилась. *Как избежать:* Помните, что по умолчанию аргументы передаются по значению (создается копия). Если нужно изменить переменную снаружи, используйте `ref` или `out`.
7. **Выход за границы массива при обработке `params` массивов**. Ошибка индексации при реализации алгоритмов внутри методов с переменным числом аргументов (например, обращение к `numbers[numbers.Length]` вместо `numbers.Length - 1`). *Как избежать:* Всегда проверяйте границы циклов `for` (`i < numbers.Length`) или используйте безопасный цикл `foreach`.

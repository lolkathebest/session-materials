## 1. Понятие класса и объекта. Поля и методы экземпляра

### Ссылочные типы и типы значений: где живут данные

Прежде чем приступить к созданию классов, необходимо четко понимать, как именно программа на C# распределяет память для различных видов данных. Вся память процесса во время выполнения программы делится на две ключевые области: **стек (stack)** и **кучу (heap)**.

> **Определение.** **Тип значения (value type)** — это тип данных, переменная которого хранит непосредственно своё значение. При копировании такой переменной или передаче её в метод происходит физическое копирование самих данных.

К типам значений в C# относятся все числовые типы (`int`, `double`, `decimal`, `float`), символы (`char`), логический тип (`bool`) и структуры (`struct`). Когда вы объявляете локальную переменную типа значения внутри метода, она полностью размещается на **стеке**. Стек устроен по принципу LIFO (Last In, First Out — последним пришел, первым вышел). Память на стеке выделяется и освобождается автоматически и очень быстро при входе и выходе из блока кода (метода).

> **Определение.** **Ссылочный тип (reference type)** — это тип данных, переменная которого хранит не сами данные, а **ссылку** (адрес в памяти), по которой эти данные располагаются. 

К ссылочным типам относятся классы (`class`), массивы (`array`), делегаты и интерфейсы. Когда вы создаете объект ссылочного типа, сам объект (его данные) создается в **куче** — большой динамической области памяти, управляемой сборщиком мусора (.NET Garbage Collector). А в переменной на стеке хранится лишь 4-байтовый (в 32-битной системе) или 8-байтовый (в 64-битной системе) адрес этого объекта в куче.

Рассмотрим это наглядной схемой:

```text
Стек (Stack)                        Куча (Heap)
+------------------+                +----------------------------------+
| Переменная       |                | Объект класса BankAccount        |
| myAccount        | -------------> | Поле: accountNumber = "BY123"    |
| (хранит адрес)   |                | Поле: balance = 1500.00          |
+------------------+                +----------------------------------+
```

Если вы присвоите одну ссылочную переменную другой (`BankAccount acc2 = myAccount;`), то скопируется не сам объект, а **ссылка** на него. В результате обе переменные будут указывать на один и тот же участок памяти в куче, и изменение полей через `acc2` изменит данные и для `myAccount`.

### Синтаксис объявления класса в C#

Класс в объектно-ориентированном программировании — это чертеж, шаблон или пользовательский тип данных, на основе которого создаются конкретные сущности (объекты). 

Синтаксис объявления класса в языке C# выглядит следующим образом:

```csharp
[модификаторы_доступа] class ИмяКласса
{
    // Тело класса: поля, свойства, конструкторы, методы
}
```

Рассмотрим ключевые элементы:
1. **Модификатор доступа** (например, `public` или `internal`) определяет, откуда будет виден этот класс в других частях программы.
2. Ключевое слово **`class`** указывает компилятору, что создается именно ссылочный тип.
3. **Имя класса** по соглашению об именовании в C# (PascalCase) пишется с большой буквы, например: `BankAccount`, `Student`, `Car`.
4. В фигурных скобках `{ }` располагается **тело класса**, содержащее его члены: поля (данные) и методы (поведение).

---

### Поля класса и методы экземпляра

Состояние объекта определяется его **полями (fields)**. Поля — это обычные переменные, объявленные внутри тела класса. Они хранят данные, уникальные для каждого конкретного экземпляра (объекта). Поля экземпляра (instance fields) создаются в памяти каждый раз, когда создается новый объект класса.

> **Определение.** **Метод экземпляра (instance method)** — это функция, объявленная внутри класса, которая определяет поведение объектов этого класса и имеет доступ к их внутренним данным (полям).

Методы экземпляра работают в контексте конкретного объекта. Для обращения к полям текущего объекта внутри метода используется специальное ключевое слово — **`this`**. Оно представляет собой неявную ссылку на текущий экземпляр класса, для которого вызван метод. В большинстве случаев писать `this` явно не требуется (компилятор подставляет его автоматически), однако оно незаменимо, если имя локальной переменной или параметра метода совпадает с именем поля класса.

Рассмотрим пример структуры класса с полями и методом:

```csharp
class BankAccount
{
    // Поля экземпляра (состояние)
    public string accountNumber;
    public decimal balance;

    // Метод экземпляра (поведение)
    public void Deposit(decimal amount)
    {
        if (amount > 0)
        {
            this.balance += amount; // Используем this для ясности
        }
    }
}
```

### Создание экземпляра класса и оператор `new`

Просто объявить класс недостаточно — в памяти еще нет никаких данных. Чтобы начать работу с классом, нужно создать его **экземпляр (объект)**.

Для этого используется оператор **`new`**, который выполняет следующие действия:
1. Выделяет блок памяти в куче для размещения всех полей экземпляра класса.
2. Инициализирует поля значениями по умолчанию (для числовых типов это `0`, для `bool` — `false`, для ссылочных типов — `null`).
3. Вызывает конструктор класса для начальной настройки объекта.
4. Возвращает ссылку на созданный объект в куче.

Синтаксис создания объекта:

```csharp
BankAccount myAccount = new BankAccount();
```

Здесь слева от знака равенства объявляется переменная `myAccount` типа `BankAccount` (она создается на стеке). Справа с помощью оператора `new` и вызова конструктора `BankAccount()` создается сам объект в куче, а его адрес записывается в переменную `myAccount`.

---

### Разыменование ссылок и обращение к членам класса через точку

После того как объект создан, мы можем управлять его состоянием и вызывать его методы. Для доступа к полям и методам объекта используется **оператор точка (`.`)**.

Оператор `.` выполняет разыменование ссылки: он берет адрес, хранящийся в переменной на стеке, переходит по нему в кучу и обращается к конкретному полю или методу объекта.

Пример обращения к членам класса:

```csharp
// Присваиваем значения полям через точку
myAccount.accountNumber = "RUB-40817810";
myAccount.balance = 5000.00m;

// Вызываем метод экземпляра
myAccount.Deposit(1500.00m);
```

Если попытаться вызвать метод или обратиться к полю через переменную, которая хранит `null` (то есть не ссылается ни на какой объект в куче), программа выбросит исключение времени выполнения `NullReferenceException`. Это одна из самых распространенных ошибок при работе со ссылочными типами.

### Состояние объекта и безопасность данных

В приведенных выше примерах поля класса объявлены с модификатором `public`. Это сделано для простоты демонстрации, но на практике в реальном проектировании так поступать **нельзя**. 

Если поле является общедоступным (`public`), любой внешний код может изменить его значение напрямую, обойдя любые правила и проверки. Например, внешний код может присвоить балансу банковского счета отрицательное значение (`myAccount.balance = -999999.00m;`), что нарушит логику работы программы и приведет к потере целостности данных.

Для предотвращения подобных ситуаций применяется сокрытие данных (инкапсуляция), о чем подробно пойдет речь в следующем разделе. А сейчас закрепим полученные теоретические знания на полностью разобранном примере.

---

### Разобранный пример

#### Условие задачи
Разработать класс `BankAccount`, содержащий поля для номера счета (`string`) и баланса (`decimal`). Написать метод `Deposit` для пополнения счета и метод `PrintInfo` для вывода данных. В методе `Main` создать объект, пополнить счет на `1500{,}00` рублей и вывести информацию.

#### Рисунок (схема) состояния памяти и данных
```text
Стек (Майн метод)                   Куча (Динамическая память)
+-----------------------+           +-------------------------------------+
| account               | --------> | Экземпляр BankAccount               |
| (ссылка на объект)    |           | accountNumber = "ACC-998877"        |
+-----------------------+           | balance = 6500.00                   |
                                    +-------------------------------------+
```

#### Ход рассуждений
1. Нам нужен пользовательский ссылочный тип, поэтому объявляем класс `BankAccount`.
2. Внутри класса заводим два поля экземпляра: `accountNumber` типа `string` для хранения номера счета и `balance` типа `decimal` для хранения денежной суммы (для финансовых расчетов всегда используется `decimal` из-за высокой точности).
3. Пишем метод экземпляра `Deposit(decimal amount)`, который принимает сумму пополнения. Внутри метода проверяем, что сумма положительная, и прибавляем её к текущему балансу (`this.balance += amount`).
4. Пишем метод экземпляра `PrintInfo()`, который выводит в консоль текущий номер счета и баланс, используя интерполяцию строк.
5. В исполняемом методе `Main` создаем объект через оператор `new BankAccount()`, заполняем его начальными данными, вызываем метод `Deposit` с аргументом `1500.00m` (суффикс `m` указывает компилятору, что литерал имеет тип `decimal`) и вызываем `PrintInfo()`.

#### Полный исходный код программы на C#

```csharp
using System;

namespace BankApp
{
    // Описание класса BankAccount (ссылочный тип)
    class BankAccount
    {
        // Поле для хранения номера счета
        public string accountNumber;

        // Поле для хранения баланса счета
        public decimal balance;

        // Метод экземпляра для пополнения счета
        public void Deposit(decimal amount)
        {
            if (amount > 0)
            {
                balance += amount; // Увеличиваем баланс текущего объекта
            }
        }

        // Метод экземпляра для вывода информации о счете
        public void PrintInfo()
        {
            Console.WriteLine($"Счет: {accountNumber} | Баланс: {balance:F2} руб.");
        }
    }

    class Program
    {
        static void Main(string[] args)
        {
            // Создание экземпляра класса BankAccount в куче, в стек записывается ссылка
            BankAccount account = new BankAccount();

            // Обращение к полям объекта через оператор точка (.) для инициализации
            account.accountNumber = "ACC-998877";
            account.balance = 5000.00m;

            Console.WriteLine("Состояние счета до пополнения:");
            account.PrintInfo();

            // Вызов метода экземпляра для пополнения счета на 1500.00 рублей
            account.Deposit(1500.00m);

            Console.WriteLine("\nСостояние счета после пополнения:");
            account.PrintInfo();
        }
    }
}
```

#### Проверка и анализ
* **Единицы измерения и типы:** Суммы денег хранятся в типе `decimal`, что исключает погрешности округления, свойственные типам с плавающей точкой (`float`, `double`). Форматирование `{balance:F2}` выводит значение ровно с двумя знаками после запятой.
* **Правдоподобность:** Начальный баланс (`5000.00`) плюс пополнение (`1500.00`) математически дают `6500.00`. Логика работы методов и распределение памяти полностью соответствуют стандартам .NET 8.

Ответ:
```text
Состояние счета до пополнения:
Счет: ACC-998877 | Баланс: 5000,00 руб.

Состояние счета после пополнения:
Счет: ACC-998877 | Баланс: 6500,00 руб.
```

## 2. Модификаторы доступа и принцип инкапсуляции

### Суть принципа инкапсуляции и сокрытие данных

При проектировании программного обеспечения на объектно-ориентированном языке программирования C#, одним из фундаментальных принципов является **инкапсуляция** (encapsulation). 

> **Определение.** Инкапсуляция — это свойство объектно-ориентированных языков, позволяющее объединить данные и код, манипулирующий этими данными, в единую капсулу (класс), а также скрыть внутреннюю реализацию объекта от внешнего мира, предоставляя для взаимодействия только контролируемый интерфейс.

Чтобы понять суть инкапсуляции, обратимся к физическому миру. Представьте себе банкомат. Вы взаимодействуете с ним через строго определенный интерфейс: экран, клавиатуру и слот для выдачи наличных. Вы нажимаете кнопки, вводите ПИН-код и забираете деньги. При этом вам не нужно знать, какие механические устройства внутри купюроприемника перемещают купюры, какие микросхемы обрабатывают сигнал и к какой базе данных банка подключается программное обеспечение банкомата. Более того, если бы каждый пользователь имел прямой доступ к внутренним платам и жестким дискам банкомата, устройство бы быстро вышло из строя из-за случайных или намеренных некорректных действий.

В программировании происходит ровно то же самое. Когда поля класса (его внутреннее состояние) открыты для свободного чтения и изменения из любой точки программы, любой участок кода может случайно записать туда некорректное значение (например, отрицательный возраст человека, отрицательный баланс банковского счета или пустую строку вместо имени файла). 

Инкапсуляция решает две главные задачи:
1. **Сокрытие реализации (Information Hiding):** внутреннее устройство класса (то, *как* хранятся и обрабатываются данные) отделяется от его внешнего интерфейса (того, *что* класс умеет делать для остальной программы). Это позволяет менять внутренний код класса (например, оптимизировать алгоритм хранения данных), не переписывая ни одной строчки в других частях программы, которые этот класс используют.
2. **Защита целостности данных (Invariant Enforcement):** класс может гарантировать, что его состояние всегда остается корректным. Инвариант класса — это логическое условие, которое должно быть истинно для объекта в любой момент времени (например, «баланс счета никогда не может быть меньше нуля», «месяц должен быть в диапазоне от 1 до 12»).

### Модификаторы доступа: управление видимостью членов класса

В языке C# управление видимостью полей, методов, конструкторов и других членов класса реализуется с помощью специальных ключевых слов — **модификаторов доступа** (access modifiers). Они явно указывают компилятору, откуда именно разрешен доступ к конкретному члену класса.

В C# используются четыре основных модификатора доступа:

| Модификатор | Область видимости | Краткое описание |
| :--- | :--- | :--- |
| `private` | Только внутри текущего класса | Самый строгий уровень. Член виден исключительно в том классе, где он объявлен. |
| `internal` | Внутри текущей сборки (assembly) | Доступен из любого места текущего проекта (файла `.exe` или `.dll`), но невидим для других проектов. |
| `protected` | Внутри класса и всех его наследников | Используется при наследовании: член виден в базовом классе и во всех классах-потомках (даже в других сборках). |
| `public` | Повсеместно без ограничений | Открытый интерфейс. Доступен из абсолютно любого места программы, где виден сам класс. |

Рассмотрим подробно каждый из основных модификаторов, с которыми вы будете сталкиваться постоянно.

#### Модификатор `private` (закрытый доступ)

Ключевое слово `private` означает, что данный член класса является абсолютно невидимым за пределами этого класса. Попытка обратиться к `private`-полю или методу из другого класса или из метода `Main` приведет к ошибке на этапе компиляции.

```csharp
class Person
{
    // Закрытое поле: доступно только из методов класса Person
    private int age;

    public void SetAge(int value)
    {
        if (value >= 0 && value <= 120)
        {
            age = value; // Здесь доступ разрешен, так как мы внутри класса Person
        }
    }
}

class Program
{
    static void Main()
    {
        Person p = new Person();
        // p.age = 25; // Ошибка компиляции! Поле 'Person.age' недоступно из-за своего уровня защиты
    }
}
```

По умолчанию, если для членов класса (полей и методов) не указан явный модификатор доступа, компилятор C# автоматически присваивает им уровень `private`. Однако хорошим стилем программирования является всегда указывать модификатор явно, чтобы код был максимально читаемым и однозначным.

#### Модификатор `public` (открытый доступ)

Ключевое слово `public` открывает доступ к члену класса из любой точки программы. Обычно с помощью `public` объявляются методы, которые составляют внешний интерфейс класса — те самые «кнопки банкомата», с помощью которых внешняя программа взаимодействует с объектом.

```csharp
class Calculator
{
    // Открытый метод: доступен отовсюду
    public int Add(int a, int b)
    {
        return a + b;
    }
}
```

#### Обзор `internal` и `protected`

- **`internal`** используется для ограничения видимости в пределах одной логической сборки (проекта Visual Studio). Если вы пишете библиотеку классов, которая подключается к другому проекту, `internal`-классы и члены будут скрыты от разработчиков, использующих вашу библиотеку.
- **`protected`** применяется в иерархиях классов при наследовании. Если поле или метод помечены как `protected`, они закрыты от внешнего мира (`private`), но открыты для всех классов-наследников, которые будут созданы на базе вашего класса.

---

### Интерфейсные методы против внутренних полей: разделение «Что» и «Как»

Главный архитектурный результат применения модификаторов доступа и инкапсуляции — это жесткое разделение обязанностей между внутренним устройством объекта и его внешним проявлением.

1. **Внутренние поля (`private`)** отвечают за то, **КАК** объект хранит свои данные. Например, банковский счет может хранить баланс в виде целого числа копеек типа `long` для избежания проблем с точностью дробных чисел, либо в виде `decimal`.
2. **Интерфейсные методы (`public`)** отвечают за то, **ЧТО** объект умеет делать. Метод `Deposit(decimal amount)` говорит внешней программе: «этому счету можно передать сумму для зачисления».

Внешняя программа не должна знать, хранит ли счет баланс в копейках, в долларах, в зашифрованном виде в оперативной памяти или на жестком диске. Вся эта «кухня» скрыта внутри класса. Если через год вы решите изменить внутреннюю структуру класса (например, перенести баланс из обычной переменной в базу данных), вам нужно будет изменить только код внутри методов самого класса. Код всех остальных модулей программы, которые используют ваш класс, останется абсолютно работоспособным. Это свойство называется **слабой связанностью (loose coupling)**.

---

### Роль инкапсуляции в обеспечении инвариантов класса

Инвариант — это неизменное условие логической корректности объекта. Рассмотрим практический пример. Пусть у нас есть класс, описывающий прямоугольник. Стороны прямоугольника не могут быть отрицательными или равными нулю.

Если сделать поля ширины и высоты открытыми (`public`), любой программист сможет написать следующий код:
```csharp
Rectangle rect = new Rectangle();
rect.Width = -50; // Отрицательная ширина!
rect.Height = 0;  // Нулевая высота!
```
После этого вычисление площади или периметра такого прямоугольника выдаст бессмысленный результат, а вся программа может повести себя непредсказуемо. 

С помощью инкапсуляции мы делаем поля закрытыми, а изменение значений разрешаем только через специальные открытые методы (или свойства), внутри которых прописаны проверки (валидация). Если входящие данные нарушают инвариант, метод может либо проигнорировать операцию, либо выбросить исключение (ошибку времени выполнения).

---

### Разобранный пример: Инкапсуляция в классе банковского счета

Рассмотрим подробный пример, полностью реализующий принципы инкапсуляции, сокрытия данных и защиты инвариантов.

#### Условие задачи
Модифицировать класс `BankAccount`, созданный ранее, так, чтобы поле баланса стало закрытым (`private`). Попытка прямого присваивания балансу отрицательного числа должна приводить к ошибке компиляции. Добавить открытый метод `Withdraw` для снятия денег с обязательной проверкой на достаточность средств и корректность суммы.

#### Ход рассуждений и проектирование
1. **Поля класса:** Нам нужны два поля: `accountNumber` (номер счета, строка) и `balance` (текущий баланс, тип `decimal`). Оба поля должны быть `private`, чтобы исключить прямой доступ извне.
2. **Конструктор:** Чтобы объект создавался сразу в валидном состоянии, создадим конструктор, принимающий номер счета и начальный баланс. В конструкторе также выполним проверку: начальный баланс не может быть отрицательным.
3. **Метод пополнения (`Deposit`):** Открытый метод `public void Deposit(decimal amount)`. Он должен проверять, что сумма пополнения строго больше нуля (нельзя пополнить счет на отрицательную или нулевую сумму). Если сумма корректна, она прибавляется к балансу.
4. **Метод снятия (`Withdraw`):** Открытый метод `public bool Withdraw(decimal amount)`. Он должен выполнять две проверки:
   - Сумма снятия должна быть положительной.
   - Сумма снятия не должна превышать текущий баланс счета (на счете должно быть достаточно средств).
   Если проверки проходят успешно, деньги списываются, и метод возвращает `true` (операция успешна). Иначе возвращается `false`.
5. **Информационный метод (`PrintInfo`):** Открытый метод для вывода текущего состояния счета на консоль.

#### Полный исходный код программы на C#

```csharp
using System;

namespace BankApp
{
    // Описание класса банковского счета
    class BankAccount
    {
        // Закрытые поля: скрыты от внешнего мира, инкапсулируют состояние объекта
        private string accountNumber;
        private decimal balance;

        // Конструктор класса для инициализации счета при создании
        public BankAccount(string initialAccountNumber, decimal initialBalance)
        {
            accountNumber = initialAccountNumber;
            
            // Защита инварианта: проверяем начальный баланс
            if (initialBalance < 0)
            {
                // Если передали отрицательный баланс, принудительно устанавливаем 0 
                // или выбрасываем исключение (в данном случае установим 0 и выведем предупреждение)
                Console.WriteLine("Предупреждение: начальный баланс не может быть отрицательным. Установлен баланс 0.00.");
                balance = 0.00m;
            }
            else
            {
                balance = initialBalance;
            }
        }

        // Открытый метод для пополнения счета (часть публичного интерфейса)
        public void Deposit(decimal amount)
        {
            if (amount <= 0)
            {
                Console.WriteLine("Ошибка: сумма пополнения должна быть больше нуля.");
                return;
            }

            balance += amount;
            Console.WriteLine($"Успешно пополнено на {amount:F2} руб. Новый баланс: {balance:F2} руб.");
        }

        // Открытый метод для снятия средств с проверкой условий
        public bool Withdraw(decimal amount)
        {
            // Проверка 1: корректность суммы снятия
            if (amount <= 0)
            {
                Console.WriteLine("Ошибка: сумма для снятия должна быть больше нуля.");
                return false;
            }

            // Проверка 2: достаточно ли средств на счете (защита инварианта balance >= 0)
            if (amount > balance)
            {
                Console.WriteLine($"Ошибка: недостаточно средств на счете. Попытка снять: {amount:F2} руб., доступно: {balance:F2} руб.");
                return false;
            }

            // Выполнение операции списания
            balance -= amount;
            Console.WriteLine($"Успешно снято {amount:F2} руб. Остаток на счете: {balance:F2} руб.");
            return true;
        }

        // Открытый метод для получения информации о счете
        public void PrintInfo()
        {
            Console.WriteLine($"[Счет №: {accountNumber}] Текущий баланс: {balance:F2} руб.");
        }
    }

    class Program
    {
        static void Main(string[] args)
        {
            // Установка кодировки консоли для корректного отображения рублей
            Console.OutputEncoding = System.Text.Encoding.UTF8;

            Console.WriteLine("=== Тестирование класса BankAccount с инкапсуляцией ===");

            // 1. Создание объекта через конструктор
            BankAccount myAccount = new BankAccount("BY71OLMP3812000012345", 5000.00m);
            myAccount.PrintInfo();

            /* 
             * Попытка прямого обращения к закрытым полям вызовет ошибку компиляции:
             * myAccount.balance = -10000m; 
             * CS0122: "BankAccount.balance недоступен из-за своего уровня защиты"
             */

            Console.WriteLine("\n--- Попытка пополнения некорректной суммой ---");
            myAccount.Deposit(-500.00m);

            Console.WriteLine("\n--- Пополнение корректной суммой ---");
            myAccount.Deposit(1500.00m);

            Console.WriteLine("\n--- Попытка снять сумму, превышающую баланс ---");
            myAccount.Withdraw(10000.00m);

            Console.WriteLine("\n--- Успешное снятие средств ---");
            myAccount.Withdraw(2000.00m);

            // Итоговое состояние счета
            Console.WriteLine();
            myAccount.PrintInfo();
        }
    }
}
```

#### Разбор работы кода по строкам
1. Строки `private string accountNumber;` и `private decimal balance;` объявляют поля класса с модификатором `private`. Это значит, что код вне класса `BankAccount` не имеет физической возможности изменить их значения напрямую.
2. В конструкторе `BankAccount(...)` мы принимаем стартовые параметры и проверяем их. Если внешний код пытается передать отрицательный баланс, класс пресекает это действие, защищая свое внутреннее состояние.
3. Методы `Deposit` и `Withdraw` содержат логику проверки (`if (amount <= 0)` и `if (amount > balance)`). Они играют роль «охранников», которые пропускают только корректные изменения состояния.
4. В методе `Main` создание объекта происходит стандартным образом через оператор `new`. Попытка закомментированного прямого доступа (`myAccount.balance = -10000m;`) не позволит программе скомпилироваться, что и требуется для обеспечения абсолютной безопасности данных.

#### Пример ввода и вывода программы
При запуске данной программы в консоли будет выведен следующий текст:

```text

--- Попытка пополнения некорректной суммой ---

--- Пополнение корректной суммой ---
Успешно пополнено на 1500,00 руб. Новый баланс: 6500,00 руб.

--- Попытка снять сумму, превышающую баланс ---
Ошибка: недостаточно средств на счете. Попытка снять: 10000,00 руб., доступно: 6500,00 руб.

--- Успешное снятие средств ---
Успешно снято 2000,00 руб. Остаток на счете: 4500,00 руб.

[Счет №: BY71OLMP3812000012345] Текущий баланс: 4500,00 руб.
```

#### Оценка сложности
- **Пространственная сложность (память):** Экземпляр класса `BankAccount` размещается в динамической памяти (куче) и занимает объем памяти, равный сумме размеров его полей (ссылка на строку + `decimal` (16 байт) + служебные заголовки объекта .NET в памяти, составляющие обычно 24 байта). Сложность по памяти составляет $O(1)$ на один объект.
- **Временная сложность:** Все операции методов класса (`Deposit`, `Withdraw`, `PrintInfo`) выполняются за константное время $O(1)$, так как содержат лишь элементарные арифметические операции и условные ветвления без циклов и рекурсии.

## 3. Свойства (Properties): инкапсуляция на уровне языка

### Проблема традиционных методов доступа и эволюция к свойствам

В предыдущих разделах мы установили важнейшее правило объектно-ориентированного программирования: поля класса должны быть закрытыми (`private`), чтобы защитить внутреннее состояние объекта от прямого изменения извне и гарантировать соблюдение правил целостности данных (инвариантов). 

Однако возникает практическая задача: если поле закрыто, как внешнему коду прочитать его значение или изменить его? 

Классический подход из языков вроде C++ и Java заключается в создании специальных методов — геттеров (getters) и сеттеров (setters). Для поля `balance` это выглядело бы так:

```csharp
class BankAccount
{
    private decimal balance; // Закрытое поле

    // Геттер для чтения значения
    public decimal GetBalance()
    {
        return balance;
    }

    // Сеттер для записи значения с проверкой
    public void SetBalance(decimal newBalance)
    {
        if (newBalance >= 0)
        {
            balance = newBalance;
        }
    }
}
```

Хотя этот подход решает проблему инкапсуляции, он обладает существенным недостатком с точки зрения синтаксиса и удобства использования. Обращение к данным и их изменение превращается в вызов методов, что утяжеляет код:

```csharp
// Чтение через метод
decimal currentBalance = account.GetBalance();

// Запись через метод
account.SetBalance(1500.00m);
```

В языке C# разработчики стандарта пошли дальше и встроили концепцию геттеров и сеттеров непосредственно в систему типов языка на уровне синтаксиса, создав **свойства** (properties). Свойство с точки зрения вызывающего кода выглядит как обычное поле (к нему можно обратиться через оператор точка `=`, как для чтения, так и для записи), но внутри себя оно выполняет код аксессоров.

> **Определение.** Свойство в C# — это член класса, который предоставляет гибкий механизм для чтения, записи или вычисления значения закрытого поля. Свойства можно использовать так, будто они являются общедоступными полями данных, но на самом деле они реализуются с помощью специальных методов, называемых аксессорами (`get` и `set`).

---

### Синтаксис классического свойства и скрытое поле (Backing Field)

Классическое свойство в C# объявляется внутри класса с указанием модификатора доступа, типа данных, имени свойства (обычно с большой буквы, в отличие от полей, которые часто называют с маленькой буквы или с префиксом) и блока аксессоров `{ get; set; }`.

Рассмотрим синтаксис на примере:

```csharp
class BankAccount
{
    // 1. Скрытое поле (backing field), хранящее реальные данные в памяти
    private decimal balance;

    // 2. Свойство для работы с полем balance
    public decimal Balance
    {
        get
        {
            // Этот блок выполняется при чтении свойства (например, decimal x = account.Balance;)
            return balance;
        }
        set
        {
            // Этот блок выполняется при записи в свойство (например, account.Balance = 500m;)
            balance = value;
        }
    }
}
```

Разберем ключевые элементы этого синтаксиса:
1. **Скрытое поле (`backing field`)**: поле `private decimal balance;` хранит само значение в куче в составе экземпляра класса. Прямого доступа к нему извне нет.
2. **Аксессор `get`**: не принимает параметров и должен возвращать значение того же типа, что и само свойство. Когда внешний код пишет `Console.WriteLine(account.Balance);`, компилятор подменяет это обращение на вызов скрытого кода из блока `get`.
3. **Аксессор `set`**: срабатывает при присваивании значения свойству (`account.Balance = 1000.00m;`). Внутри этого блока доступна специальная неявная переменная `value`.

---

### Ключевое слово `value` в аксессоре `set`

Внутри блока `set` компилятор автоматически создает неявный параметр с именем `value`. Тип данных этого параметра всегда совпадает с типом данных самого свойства. 

`value` содержит то значение, которое пытаются присвоить свойству с правой стороны от оператора присваивания. 

Пример присваивания:
```csharp
BankAccount account = new BankAccount();
account.Balance = 2500.50m; // Число 2500.50m попадает внутрь аксессора set в переменную value
```

Внутри аксессора `set` мы можем использовать `value` для проверок или вычислений перед тем, как сохранить его в скрытое поле:

```csharp
public decimal Balance
{
    get { return balance; }
    set
    {
        // Проверяем значение, которое лежит в переменной value
        if (value < 0)
        {
            throw new ArgumentOutOfRangeException("Баланс не может быть отрицательным.");
        }
        balance = value; // Сохраняем проверенное значение в скрытое поле
    }
}
```

Если бы ключевого слова `value` не существовало, компилятору было бы негде взять передаваемое значение, так как синтаксис присваивания свойства (`obj.Prop = x`) не является обычным вызовом метода с круглыми скобками.

---

### Автореализуемые свойства (Auto-Implemented Properties)

В подавляющем большинстве случаев разработчику не нужно писать сложную логику валидации или вычислений внутри аксессоров `get` и `set`. Требуется просто безопасно инкапсулировать поле, оставив стандартное чтение и запись. 

Чтобы не писать каждый раз рутинный код со скрытым полем и простейшими `return balance;` / `balance = value;`, в C# введены **автореализуемые свойства**.

> **Определение.** Автореализуемое свойство — это сокращенная форма объявления свойства, при которой компилятор самостоятельно создает скрытое поле (backing field) с уникальным сгенерированным именем, доступное только через сгенерированные аксессоры.

Синтаксис автореализуемого свойства:
```csharp
public string Name { get; set; }
```

Эквивалентный код, который компилятор генерирует "под капотом":
```csharp
private string <Name>k__BackingField; // Скрытое поле сгенерировано компилятором

public string Name
{
    get { return <Name>k__BackingField; }
    set { <Name>k__BackingField = value; }
}
```

Использование автореализуемых свойств делает код чище и короче, полностью сохраняя при этом инкапсуляцию на уровне интерфейса класса (поскольку синтаксически это свойство, а не публичное поле).

---

### Свойства только для чтения (Read-Only Properties)

Иногда требуется создать класс, состояние которого после инициализации изменяться не должно (например, объекты-значения или уникальные идентификаторы). Для этого создаются **свойства только для чтения**.

Добиться этого можно несколькими способами:
1. **Только аксессор `get`**: если в свойстве прописан только `get` и отсутствует `set`, такое свойство нельзя изменить извне после создания объекта.
2. **Закрытый сеттер (`private set`)**: позволяет читать свойство всем, но изменять его значение разрешено только изнутри методов самого класса.

Пример реализации свойства с закрытым сеттером:
```csharp
class Order
{
    // Уникальный номер заказа можно прочитать откуда угодно, но изменить — только внутри класса
    public int OrderId { get; private set; }

    public Order(int id)
    {
        OrderId = id; // Доступ разрешен, так как мы внутри класса Order
    }
}

// В методе Main:
// Order ord = new Order(42);
// Console.WriteLine(ord.OrderId); // Работает (чтение)
// ord.OrderId = 100; // Ошибка компиляции! Сеттер недоступен извне.
```

---

### Валидация данных внутри сеттера

Главная архитектурная сила свойств заключается в возможности осуществлять **валидацию** (проверку на корректность) поступающих данных. Когда внешний код присваивает значение свойству, срабатывает код сеттера. Если переданные данные нарушают логику предметной области (инварианты класса), сеттер может прервать выполнение и выбросить исключение.

Рассмотрим общую схему защиты инвариантов:
- Инвариант — это условие, которое всегда должно быть истинно для корректного объекта (например, возраст человека не может быть отрицательным, процент ставки не может быть больше 100 и т.д.).
- Сеттер выступает в роли "стража", который проверяет `value` перед тем, как допустить его до скрытого поля.

---

### Разобранный пример: класс Student с валидацией возраста

Разберем комплексную задачу, полностью демонстрирующую изученный материал.

#### Условие задачи
Разработать класс `Student`, моделирующий студента учебного заведения. У студента должны быть два параметра: имя (`Name`) и возраст (`Age`). 
1. Имя должно быть реализовано через автореализуемое свойство с публичными `get` и `set`.
2. Возраст должен быть реализован через классическое свойство со скрытым полем. Установить жесткое правило валидации: возраст не может быть меньше 16 и больше 100 лет. При попытке присвоить некорректное значение генерировать исключение `ArgumentException`.
3. Написать класс с методом `Main`, в котором создать объект студента, успешно присвоить ему корректный возраст, а затем продемонстрировать перехват исключения при попытке установить некорректный возраст.

#### Рисунок схемы работы класса (в текстовом виде)
```
[ Внешний код (Main) ] 
       │
       ▼  ( student.Age = 150; )
┌──────────────────────────────────────────────┐
│ Класс Student                                │
│                                              │
│   Свойство Age (public int Age)              │
│   ┌────────────────────────────────────────┐ │
│   │ аксессор set (value = 150)             │ │
│   │   Если value < 16 ИЛИ value > 100 ───┐ │ │
│   │   ДА: throw new ArgumentException()  │ │ │
│   │   НЕТ: age = value;                  │ │ │
│   └──────────────────────────────────────┼─┘ │
│                                          ▼   │
│   Скрытое поле (private int age) ◄───────┘   │
└──────────────────────────────────────────────┘
```

#### Ход рассуждений
1. Объявляем класс `Student`.
2. Создаем автореализуемое свойство для имени: `public string Name { get; set; }`.
3. Создаем скрытое поле для возраста: `private int age;`.
4. Создаем свойство `Age` с аксессорами `get` и `set`.
   - В аксессоре `get` просто возвращаем значение `age`.
   - В аксессоре `set` пишем проверку: `if (value < 16 || value > 100)`. Если условие верно, создаем исключение `throw new ArgumentException("Возраст должен быть от 16 до 100 лет.");`. Если условие ложно, присваиваем `age = value;`.
5. В методе `Main` создаем экземпляр `Student`, проверяем штатную работу и оборачиваем попытку некорректного присваивания в блок `try-catch`, чтобы программа не аварийно завершилась, а корректно обработала ошибку.

#### Полный исходный код программы на C#

```csharp
using System;

namespace ConsoleAppStudent
{
    // Описание класса Student
    class Student
    {
        // Автореализуемое свойство для имени
        public string Name { get; set; }

        // Скрытое поле для хранения возраста (backing field)
        private int age;

        // Полноценное свойство Age с валидацией
        public int Age
        {
            get
            {
                // Возвращаем значение скрытого поля
                return age;
            }
            set
            {
                // Проверка инварианта: возраст должен быть в пределах от 16 до 100 лет включительно
                if (value < 16 || value > 100)
                {
                    // Выбрасываем исключение, если данные некорректны
                    throw new ArgumentException("Ошибка валидации: возраст студента должен быть в диапазоне от 16 до 100 лет.");
                }

                // Если проверка прошла успешно, сохраняем значение в скрытое поле
                age = value;
            }
        }

        // Метод для вывода информации о студенте
        public void PrintInfo()
        {
            Console.WriteLine($"Студент: {Name}, Возраст: {age} лет.");
        }
    }

    class Program
    {
        static void Main(string[] args)
        {
            Console.WriteLine("--- Демонстрация работы со свойствами и валидацией ---");

            // Создаем объект студента
            Student student = new Student();

            // Используем автореализуемое свойство Name для записи и чтения
            student.Name = "Алексей Смирнов";
            Console.WriteLine($"Установлено имя: {student.Name}");

            // Проверяем корректную установку возраста (попадающую в диапазон)
            try
            {
                student.Age = 20; // Корректное значение
                Console.WriteLine($"Возраст успешно установлен: {student.Age}");
                student.PrintInfo();
            }
            catch (ArgumentException ex)
            {
                Console.WriteLine(ex.Message);
            }

            Console.WriteLine("\nПопытка установить некорректный возраст (150 лет):");

            // Проверяем работу валидации при попытке передать недопустимое значение
            try
            {
                student.Age = 150; // Некорректное значение, вызовет исключение
                
                // Эта строка не выполнится, так как управление сразу перейдет в блок catch
                student.PrintInfo(); 
            }
            catch (ArgumentException ex)
            {
                // Перехватываем исключение и выводим сообщение об ошибке
                Console.WriteLine($"Перехвачено исключение: {ex.Message}");
            }

            // Убедимся, что старое корректное значение возраста не было повреждено после неудачной попытки
            Console.WriteLine($"Текущий возраст студента после неудачной попытки: {student.Age}");

            // Завершение работы консольного приложения
            Console.WriteLine("\nНажмите любую клавишу для выхода...");
            Console.ReadKey();
        }
    }
}
```

#### Пример вывода программы в консоли

```text

Установлено имя: Алексей Смирнов
Возраст успешно установлен: 20
Студент: Алексей Смирнов, Возраст: 20 лет.

Попытка установить некорректный возраст (150 лет):
Перехвачено исключение: Ошибка валидации: возраст студента должен быть в диапазоне от 16 до 100 лет.
Текущий возраст студента после неудачной попытки: 20

Нажмите любую клавишу для выхода...
```

#### Проверка и анализ сложности
- **Корректность единиц и типов:** возраст задан целым числом (`int`), имя — строкой (`string`), что полностью соответствует требованиям предметной области.
- **Правдоподобность:** при попытке передать значение `150`, система предотвратила повреждение состояния объекта, сохранив предыдущее безопасное значение (`20`), что доказывает эффективность инкапсуляции на базе свойств.
- **Оценка сложности:**
  - Время выполнения операций доступа к свойствам (`get` и `set`) составляет $O(1)$, так как под капотом происходит прямое обращение к памяти по смещению поля с минимальными накладными расходами (в релизной сборке компилятор C# часто выполняет инлайнинг — встраивание кода геттеров и сеттеров, полностью устраняя издержки на вызов метода).
  - Потребление памяти: класс расходует ровно столько байт в куче, сколько необходимо для хранения ссылки в стеке (8 байт на 64-битной системе) + поля `string Name` (ссылочный тип) и `int age` (4 байта).

## 4. Конструкторы: инициализация объектов

### Назначение конструктора и проблема инициализации

В предыдущих разделах вы узнали, как описывать структуру класса, скрывать его внутреннее состояние с помощью модификаторов доступа (`private`) и безопасно работать с данными через свойства (`properties`). Однако при создании объекта оператором `new` возникает важный вопрос: какими именно значениями заполняются поля нового экземпляра в первую секунду его жизни?

Если оставить поля класса инициализированными «по умолчанию» (числовые типы получают `0`, ссылочные — `null`, логический `bool` — `false`), объект может оказаться в так называемом невалидном или неполном состоянии. 

> **Определение.** Конструктор — это специальный метод специального назначения, который вызывается автоматически в момент создания экземпляра класса (при использовании оператора `new`) и служит для гарантированной инициализации полей объекта начальными значениями.

Главные отличия конструктора от обычного метода класса:
1. Имя конструктора **всегда строго совпадает** с именем самого класса.
2. Конструктор **не имеет возвращаемого типа** — даже ключевое слово `void` указывать не нужно.
3. Вызвать конструктор вручную из произвольного места программы на уже созданном объекте невозможно — он вызывается только один раз в связке с оператором `new`.

Рассмотрим простейший пример класса без явного конструктора. В языке C# у каждого класса всегда есть хотя бы один конструктор. Если программист не написал ни одного конструктора самостоятельно, компилятор автоматически добавляет в скомпилированный код так называемый **конструктор по умолчанию (default constructor)**.

```csharp
public class User
{
    public string Login { get; set; }
    public int Rating { get; set; }
}

// В Main создание выглядит так:
User defaultUser = new User();
// Поле Login получит значение null, а Rating получит значение 0.
```

Но что делать, если логика нашей программы требует, чтобы каждый созданный `User` обязательно имел логин и стартовый рейтинг не ниже единицы? Полагаться на значения по умолчанию нельзя — это нарушает правила целостности данных. Именно здесь на сцену выходят явные конструкторы.

---

### Конструктор по умолчанию и конструкторы с параметрами

Конструкторы могут принимать аргументы точно так же, как и любые другие методы. Это позволяет передать необходимые данные из внешнего кода прямо в момент выделения памяти под объект в куче.

Если вы объявляете в своем классе **хотя бы один конструктор с параметрами**, компилятор перестает автоматически генерировать конструктор по умолчанию. Если после этого попытаться написать `User u = new User();` без передачи аргументов, компилятор выдаст ошибку, так как такого конструктора больше не существует (если только вы не объявили его явно).

Давайте рассмотрим синтаксис объявления конструктора с параметрами на примере класса, описывающего банковский счет, но с акцентом на инициализацию.

```csharp
public class Account
{
    private string _owner;
    private decimal _balance;

    // Конструктор с двумя параметрами
    public Account(string owner, decimal initialBalance)
    {
        _owner = owner;
        
        if (initialBalance < 0)
        {
            _balance = 0; // Защита от некорректных данных
        }
        else
        {
            _balance = initialBalance;
        }
    }
}
```

В этом примере конструктор принимает два параметра: владельца и начальный баланс. Обратите внимание: внутри конструктора мы можем производить проверку входящих данных (валидацию), защищая объект от попадания некорректных значений еще до того, как он начнет участвовать в работе программы.

Создание объекта с использованием этого конструктора:
```csharp
Account myAccount = new Account("Иван Петров", 5000.00m);
```

Если нам по-прежнему нужен вариант создания счета без параметров (например, с дефолтным владельцем «Неизвестно» и нулевым балансом), мы должны написать конструктор без параметров **вручную**.

---

### Перегрузка конструкторов (Constructor Overloading)

В реальных приложениях часто возникает потребность создавать один и тот же объект разными способами: иногда у нас есть все данные о нем, иногда — только часть, а в остальных случаях нужно подставить стандартные значения. Для этого используется **перегрузка конструкторов**.

> **Определение.** Перегрузка конструкторов — это механизм, позволяющий классу иметь несколько конструкторов с одинаковым именем (совпадающим с именем класса), но с разной сигнатурой (различающимся количеством, типом или порядком параметров).

Рассмотрим класс, представляющий точку на плоскости (`Point`), у которой есть координаты $X$ и $Y$. Мы хотим иметь три варианта инициализации:
1. Без параметров — точка помещается в начало координат $(0; 0)$.
2. С одним параметром — точка создается на оси биссектрисы, где $X = Y = \text{значение}$.
3. С двумя параметрами — произвольная точка $(X; Y)$.

```csharp
public class Point
{
    public double X { get; set; }
    public double Y { get; set; }

    // 1. Конструктор без параметров
    public Point()
    {
        X = 0.0;
        Y = 0.0;
    }

    // 2. Конструктор с одним параметром (для одинаковых координат)
    public Point(double value)
    {
        X = value;
        Y = value;
    }

    // 3. Конструктор с двумя параметрами
    public Point(double x, double y)
    {
        X = x;
        Y = y;
    }
}
```

Компилятор определяет, какой именно конструктор нужно вызвать, основываясь на количестве и типах переданных аргументов в момент вызова `new Point(...)`.

---

### Ключевое слово `this` для связи конструкторов (Конструкторные цепочки)

Если вы посмотрите на код класса `Point` выше, то заметите дублирование логики присваивания значений. В больших классах инициализация полей может быть сложной и объемной (например, открытие соединений, проверка множества параметров, логирование). Писать один и тот же код в разных конструкторах нельзя — это нарушает принцип DRY (Don't Repeat Yourself).

В C# эту проблему решают с помощью **цепочки конструкторов (constructor chaining)**. Один конструктор может вызвать другой конструктор из того же самого класса с помощью ключевого слова `this`, указанного после двоеточия перед телом текущего конструктора.

Перепишем класс `Point` с использованием цепочки конструкторов:

```csharp
public class Point
{
    public double X { get; set; }
    public double Y { get; set; }

    // Базовый конструктор с двумя параметрами — выполняет всю реальную работу
    public Point(double x, double y)
    {
        X = x;
        Y = y;
    }

    // Конструктор с одним параметром делегирует работу конструктору с двумя параметрами
    public Point(double value) : this(value, value)
    {
    }

    // Конструктор без параметров делегирует работу конструктору с двумя параметрами, передавая нули
    public Point() : this(0.0, 0.0)
    {
    }
}
```

**Как это работает на практике:**
1. Когда вы вызываете `Point p = new Point(5.0);`, выполнение сначала попадает в конструктор `Point(double value)`.
2. Срабатывает инструкция `: this(5.0, 5.0)`. Управление передается в конструктор `Point(double x, double y)`.
3. Конструктор с двумя параметрами присваивает значения свойствам `X` и `Y`.
4. Управление возвращается обратно, объект считается полностью инициализированным.

Такой подход централизует логику инициализации: если правила проверки изменятся, вам нужно будет исправить код только в одном месте (в главном конструкторе).

---

### Инициализаторы объектов (Object Initializers)

Помимо конструкторов, в C# существует синтаксический сахар для быстрой установки значений свойств сразу после создания объекта — **инициализаторы объектов**.

Представьте, что у вас есть класс с конструктором по умолчанию (или вы используете автореализуемые свойства без явного написания конструктора). Вы можете присвоить значения публичным свойствам прямо в момент вызова `new`, перечислив их в фигурных скобках.

```csharp
public class Car
{
    public string Brand { get; set; }
    public string Model { get; set; }
    public int Year { get; set; }
}

// Использование инициализатора объекта:
Car myCar = new Car
{
    Brand = "Lada",
    Model = "Vesta",
    Year = 2022
};
```

**Важное техническое примечание:** Инициализаторы объектов не заменяют конструкторы. На самом деле под капотом компилятор сначала вызывает стандартный конструктор без параметров (создавая объект с дефолтными значениями), а затем последовательно вызывает методы `set` для указанных свойств. Если у вас в классе объявлен конструктор с параметрами и *нет* конструктора без параметров, использовать инициализатор `new Car { Brand = "..." }` без вызова конструктора с параметрами не получится, если только явно не добавить пустой конструктор.

---

### Разобранный пример: Класс `Rectangle`

Рассмотрим комплексную задачу, объединяющую все изученные аспекты: проектирование класса, инкапсуляцию, свойства, валидацию и перегрузку конструкторов с цепочкой вызовов.

#### Условие задачи
Разработать класс `Rectangle` (прямоугольник), описывающий геометрическую фигуру со сторонами ширина (`width`) и высота (`height`). 
Необходимо реализовать:
1. Закрытые поля для хранения размеров (`private double _width`, `private double _height`).
2. Публичные свойства с валидацией: значения ширины и высоты должны быть строго больше $0$. При попытке присвоить неположительное число выбрасывать исключение `ArgumentOutOfRangeException`.
3. Три конструктора:
   - Конструктор без параметров — устанавливает ширину и высоту равными $1{,}0$ м.
   - Конструктор с одним параметром — создает квадрат (ширина и высота равны переданному значению).
   - Конструктор с двумя параметрами — создает произвольный прямоугольник с заданными шириной и высотой. Реализовать этот конструктор через цепочку вызовов `this`.
4. Метод `CalculateArea()`, возвращающий площадь прямоугольника (`double`).
5. Переопределенный метод `ToString()` для удобного вывода информации о прямоугольнике.

#### Рисунок схемы связей (словесное описание)
В памяти приложения объект `Rectangle` располагается в куче. У него есть два скрытых поля `_width` и `_height`, к которым нет прямого доступа извне. Внешний мир общается с объектом исключительно через свойства `Width` и `Height`, которые проверяют входящие числа на положительность перед записью в поля. Конструкторы выстроены в иерархию: самый простой конструктор вызывает более сложный через `this(...)`, а тот, в свою очередь, обращается к свойствам для прохождения валидации.

#### Ход рассуждений
1. Создаем структуру класса `Rectangle`.
2. Объявляем приватные поля и соответствующие им свойства с логикой проверки `value > 0`.
3. Пишем главный конструктор с двумя параметрами (`double width, double height`), который принимает значения и присваивает их свойствам (чтобы сработала валидация).
4. Пишем конструктор с одним параметром для квадрата и вызываем из него главный конструктор: `: this(side, side)`.
5. Пишем конструктор без параметров и вызываем из него главный конструктор со значениями по умолчанию: `: this(1.0, 1.0)`.
6. Реализуем метод вычисления площади по формуле: $S = \text{width} \times \text{height}$.
7. Переопределяем метод `ToString()` для возврата красивой строки с описанием сторон и площади.

## 5. Комплексное применение: проектирование класса с инкапсуляцией и конструкторами

### Комплексный подход к проектированию классов в C#

Проектирование надежного и безопасного класса в объектно-ориентированном программировании требует системного подхода. Ранее мы изучили отдельные элементы: как выделяется память под ссылочные типы, зачем нужны модификаторы доступа, как свойства защищают внутреннее состояние с помощью инкапсуляции и как конструкторы гарантируют правильную начальную инициализацию. Теперь объединим эти знания на практике.

Мы разберем полный цикл создания отказоустойчивого пользовательского типа данных. Главное правило проектирования звучит так: **объект класса должен находиться в валидном (допустимом) состоянии в любой момент времени начиная с момента его создания**. Ни один внешний код не должен иметь возможности привести объект к «сломанному» или несогласованному состоянию.

---

### Этапы проектирования надежного класса

Процесс создания класса можно разделить на пять последовательных шагов:

1. **Анализ предметной области и выделение данных (полей).** Определим, какие именно характеристики (атрибуты) описывают наш объект и к какому типу данных они относятся.
2. **Сокрытие данных и выбор уровней доступа.** Все поля класса объявляются с модификатором `private`. Прямой доступ извне запрещается полностью.
3. **Создание свойств (properties) с валидацией.** Для каждого поля создается свойство (`public`), которое управляет чтением и записью. В аксессоре `set` прописываются проверки (инварианты), отсекающие недопустимые значения.
4. **Реализация конструкторов.** Создаются конструкторы (включая конструктор с полным набором параметров), которые передают входящие данные через те же свойства или проверяют их перед записью в закрытые поля. Это гарантирует, что даже при создании объекта некорректные данные внутрь не попадут.
5. **Определение поведения (методов) и переопределение служебных методов.** Добавляются методы бизнес-логики, изменяющие состояние объекта, а также переопределяется виртуальный метод `ToString()` для удобного вывода информации об объекте в консоль или лог.

---

### Разбор комплексного примера: класс `Time`

Реализуем полноценный класс `Time`, описывающий время суток (часы, минуты, секунды). 

#### Условие задачи
Разработать класс `Time`. Диапазон допустимых значений: часы от $0$ до $23$, минуты и секунды от $0$ до $59$. 
Класс должен содержать:
- Закрытые поля для хранения часов, минут и секунд.
- Свойства с валидацией для доступа к полям.
- Конструктор с параметрами (часы, минуты, секунды) с проверкой входных данных. Если переданы недопустимые значения, генерировать исключение `ArgumentOutOfRangeException`.
- Метод `AddSeconds(int s)`, добавляющий указанное количество секунд к текущему времени с корректным переходом через минуты, часы и сутки.
- Переопределенный метод `ToString()`, возвращающий строку в формате `чч:мм:сс` (например, `23:05:09`).

Проверить работу класса в методе `Main`: создать объект со временем `23:59:50`, вызвать метод добавления $15$ секунд и вывести результат. Ожидаемый ответ: `00:00:05`.

---

#### Проектирование и пошаговый ход рассуждений

1. **Поля и инкапсуляция:**
   Нам нужны три целых числа: `hours`, `minutes`, `seconds`. Объявим их как `private int` внутри класса `Time`. Прямое обращение из метода `Main` к ним заблокировано.

2. **Свойства с валидацией:**
   Создадим свойства `Hours`, `Minutes` и `Seconds`. Внутри аксессоров `сеттеров` (`set`) установим строгие границы:
   - Для часов: $0 \le \text{hours} \le 23$.
   - Для минут и секунд: $0 \le \text{value} \le 59$.
   Если условие не выполняется, выбрасываем исключение `new ArgumentOutOfRangeException(...)`.

3. **Конструктор:**
   Конструктор принимает три аргумента $(h, m, s)$. Вместо того чтобы дублировать логику проверки, мы можем присвоить значения через созданные свойства. Это гарантирует одинаковое поведение как при создании объекта, так и при последующем изменении полей.

4. **Алгоритм метода `AddSeconds(int s)`:**
   Как прибавить секунды, если их может быть очень много (например, $100000$ секунд)? 
   Самый надежный способ — перевести текущее время в общее количество секунд от начала суток, прибавить к нему входящее значение `s`, а затем пересчитать обратно в часы, минуты и секунды.
   
   Формула перевода текущего времени в общее количество секунд $T_{\text{total}}$ от начала суток:
   $$T_{\text{total}} = \text{hours} \cdot 3600 + \text{minutes} \cdot 60 + \text{seconds}$$

   Прибавим новые секунды:
   $$T_{\text{new}} = T_{\text{total}} + s$$

   В сутках ровно $86400$ секунд ($24 \cdot 3600$). Чтобы корректно обрабатывать переход через сутки (или даже несколько суток), возьмем остаток от деления по модулю $86400$:
   $$T_{\text{normalized}} = T_{\text{new}} \pmod{86400}$$
   *(Если $T_{\text{new}}$ отрицательное, в C# оператор `%` может вернуть отрицательное число, но по условию задачи мы добавляем положительное число секунд. Для защиты от отрицательных значений в будущем можно использовать конструкцию `(T_new % 86400 + 86400) % 86400`).*

   Теперь обратное преобразование из общего количества секунд в часы, минуты и секунды:
   $$\text{new\_hours} = \lfloor T_{\text{normalized}} / 3600 \rfloor$$
   $$\text{remainder} = T_{\text{normalized}} \pmod{3600}$$
   $$\text{new\_minutes} = \lfloor \text{remainder} / 60 \rfloor$$
   $$\text{new\_seconds} = \text{remainder} \pmod{60}$$

5. **Метод `ToString()`:**
   Для красивого форматирования вывода воспользуемся встроенным методом `string.Format` или интерполяцией строк с указанием формата ведущих нулей (`D2`): `"{Hours:D2}:{Minutes:D2}:{Seconds:D2}"`. Это гарантирует, что число `5` будет выведено как `05`.

### Полный исходный код программы на C#

Ниже представлен полностью компилируемый код программы, который можно запустить в любой современной среде .NET 8.

```csharp
using System;

namespace CourseApp
{
    // Описание класса Time с инкапсуляцией и конструктором
    public class Time
    {
        // 1. Закрытые поля (состояние объекта)
        private int hours;
        private int minutes;
        private int seconds;

        // 2. Свойства с валидацией (защита инвариантов)
        public int Hours
        {
            get { return hours; }
            set
            {
                if (value < 0 || value > 23)
                {
                    throw new ArgumentOutOfRangeException(nameof(value), "Часы должны быть в диапазоне от 0 до 23.");
                }
                hours = value;
            }
        }

        public int Minutes
        {
            get { return minutes; }
            set
            {
                if (value < 0 || value > 59)
                {
                    throw new ArgumentOutOfRangeException(nameof(value), "Минуты должны быть в диапазоне от 0 до 59.");
                }
                minutes = value;
            }
        }

        public int Seconds
        {
            get { return seconds; }
            set
            {
                if (value < 0 || value > 59)
                {
                    throw new ArgumentOutOfRangeException(nameof(value), "Секунды должны быть в диапазоне от 0 до 59.");
                }
                seconds = value;
            }
        }

        // 3. Конструктор с параметрами и проверкой
        public Time(int h, int m, int s)
        {
            // Присваивание через свойства задействует проверки валидации
            Hours = h;
            Minutes = m;
            Seconds = s;
        }

        // 4. Метод бизнес-логики: добавление секунд
        public void AddSeconds(int s)
        {
            if (s < 0)
            {
                throw new ArgumentException("Количество добавляемых секунд не может быть отрицательным.", nameof(s));
            }

            // Переводим текущее время в общие секунды от начала суток
            long totalSeconds = (long)hours * 3600 + minutes * 60 + seconds;

            // Добавляем новые секунды
            totalSeconds += s;

            // Учитываем переход через сутки (86400 секунд в сутках)
            totalSeconds %= 86400;

            // Обратное преобразование в часы, минуты и секунды
            hours = (int)(totalSeconds / 3600);
            long remainder = totalSeconds % 3600;
            minutes = (int)(remainder / 60);
            seconds = (int)(remainder % 60);
        }

        // 5. Переопределение метода ToString() для вывода объекта
        public override string ToString()
        {
            // Формат D2 добавляет ведущий ноль, если число меньше 10
            return $"{hours:D2}:{minutes:D2}:{seconds:D2}";
        }
    }

    class Program
    {
        static void Main(string[] args)
        {
            // Проверка граничных условий и тестирование класса
            try
            {
                // Создаем объект со временем 23:59:50
                Time currentTime = new Time(23, 59, 50);
                
                Console.WriteLine("Начальное время: " + currentTime.ToString());

                // Добавляем 15 секунд
                int secondsToAdd = 15;
                currentTime.AddSeconds(secondsToAdd);

                // Выводим результат после добавления
                Console.WriteLine($"После добавления {secondsToAdd} сек.: " + currentTime);
            }
            catch (Exception ex)
            {
                Console.WriteLine("Произошла ошибка: " + ex.Message);
            }

            // Дополнительная проверка срабатывания валидации (ошибка при создании)
            try
            {
                Console.WriteLine("\nПопытка создать некорректное время (25:00:00)...");
                Time invalidTime = new Time(25, 0, 0);
            }
            catch (ArgumentOutOfRangeException ex)
            {
                Console.WriteLine("Перехвачено ожидаемое исключение: " + ex.ParamName);
            }

            // Ожидание нажатия клавиши для закрытия консоли
            Console.ReadKey();
        }
    }
}
```

### Анализ сложности

1. **Потребление памяти (Пространственная сложность):**
   - Экземпляр класса `Time` в памяти кучи (heap) занимает базовый объем служебной информации среды .NET (заголовок объекта и указатель на таблицу методов — обычно $16$ байт на $64$-битной архитектуре) плюс три поля типа `int` по $4$ байта каждое. Итого около $28$ байт на один объект (с учетом выравнивания памяти).
   - Ссылка на этот объект в стеке (stack) занимает $8$ байт.
   - Потребление памяти является минимальным и постоянным: $O(1)$.

## Типичные ошибки

1. **Объявление полей класса с модификатором `public` вместо `private`**
   * *Почему возникает:* Начинающие разработчики часто забывают про инкапсуляцию и оставляют поля открытыми для удобства прямого доступа.
   * *Как избежать:* Всегда делайте поля закрытыми (`private`) или защищенными (`protected`). Для доступа к ним используйте свойства (`properties`).
   * *Пример ошибки:* `public decimal balance;` вместо `private decimal balance;`.

2. **Забытая валидация в сеттерах свойств и конструкторах**
   * *Почему возникает:* Свойство создано, но внутри аксессора `set` просто присваивается значение переменной без проверки диапазонов и условий.
   * *Как избежать:* Всегда проверяйте входящую переменную `value` на соответствие инвариантам класса (например, `if (value < 0) throw new ArgumentOutOfRangeException();`).
   * *Пример ошибки:* `set { _age = value; }` без проверки на отрицательный возраст.

3. **Путаница между именами параметров конструктора и полей класса**
   * *Почему возникает:* Параметр конструктора называется так же, как поле класса (`int id; ... public Person(int id) { id = id; }`), из-за чего значение параметра записывается само в себя, а поле класса остается нулевым.
   * *Как избежать:* Используйте ключевое слово `this` для явного обращения к полям текущего объекта (`this.id = id;`) или применяйте принятый в C# стиль именования приватных полей с префиксом подчеркивания (`_id`).
   * *Пример ошибки:* `Name = Name;` вместо `this.Name = Name;`.

4. **Отсутствие вызова цепочки конструкторов (`: this(...)`) и дублирование кода**
   * *Почему возникает:* Разработчик пишет одинаковый код инициализации во всех перегруженных конструкторах вместо того, чтобы связать их через `this`.
   * *Как избежать:* Используйте конструкторные цепочки. Самый сложный конструктор должен выполнять всю работу, а остальные конструкторы должны делегировать ему выполнение через `: this(...)`.

5. **Неверное понимание работы ссылочных типов и оператора `new`**
   * *Почему возникает:* Ожидание, что при присваивании одной переменной класса другой (`Account a2 = a1;`) скопируются все данные объекта в памяти.
   * *Как избежать:* Помните, что в переменной ссылочного типа хранится только адрес (ссылка) в куче. Изменение полей через `a2` изменит состояние того же самого объекта в памяти.

6. **Использование типов с плавающей точкой (`double` или `float`) для финансовых расчетов**
   * *Почему возникает:* Привычка использовать `double` для любых дробных чисел.
   * *Как избежать:* Для денежных сумм, банковских счетов и точных финансовых вычислений всегда используйте тип данных `decimal` во избежание накопления погрешностей округления.

7. **Попытка вызвать конструктор напрямую как обычный метод**
   * *Почему возникает:* Непонимание природы конструкторов и стремление сбросить или переинициализировать объект без создания нового экземпляра.
   * *Как избежать:* Помните, что конструктор вызывается исключительно один раз в связке с оператором `new` в момент выделения памяти. Для сброса состояния объекта используйте обычные методы (например, `Reset()`).

## 1. Проектирование рекурсивных функций: от математической модели к коду на C#

### Алгоритм проектирования рекурсии: поиск подзадачи меньшего размера

Проектирование рекурсивного метода в языке C# принципиально отличается от написания цикклов (`for`, `while`). Если при итеративном подходе мы думаем в категориях «как изменить состояние переменных на каждом шаге», то при рекурсивном подходе мы должны мыслить декларативно: **как выразить решение задачи размера $N$ через решение такой же задачи меньшего размера (например, $N-1$ или $N/2$)**.

> **Определение.** Рекурсивное проектирование — это процесс декомпозиции исходной задачи на одну или несколько подзадач того же типа, но меньшего объема, с последующим объединением их результатов.

Алгоритм проектирования рекурсивной функции состоит из следующих обязательных шагов:
1. **Определение параметров задачи.** Выделите параметры метода, которые однозначно описывают текущее состояние подзадачи.
2. **Выделение базового случая (Base Case).** Найдите самое простое состояние задачи, для которого ответ очевиден и не требует дальнейших рекурсивных вызовов. Без базового случая выполнение программы приведет к бесконечной рекурсии и аварийному завершению с исключением `StackOverflowException`.
3. **Формулировка рекурсивного шага (Recursive Step).** Покажите, как из решения задачи для параметра $N$ получить задачу для параметра меньше (например, $N-1$). На каждом шаге мы обязаны «приближаться» к базовому случаю.
4. **Сборка результата.** Объедините результат решения подзадачи с текущими данными (если это требуется).

### Обязательное условие завершимости: гарантия достижения базового случая

Главная ловушка при написании рекурсивных методов — отсутствие гарантии завершения. В памяти компьютера под каждый вызов метода выделяется кадр в стеке вызовов (call stack), содержащий локальные переменные и адрес возврата. Если рекурсивный шаг не уменьшает размер задачи или параметр не движется к базовому случаю, стек переполняется.

Рассмотрим два ключевых требования к любому корректному рекурсивному алгоритму:
- **Наличие хотя бы одного базового случая.** Если базовых случаев несколько (например, как в числах Фибоначчи), они должны покрывать все возможные граничные входные данные.
- **Корректное изменение аргумента.** Аргумент, передаваемый в рекурсивный вызов, должен строго приближаться к базовому значению на каждом шаге.

### Трассировка выполнения рекурсивной функции на бумаге и в отладчике

Чтобы уверенно понимать поведение рекурсии, необходимо уметь выполнять её ручную трассировку. Трассировка — это пошаговая запись состояния переменных и порядка вызовов функции.

Рассмотрим процесс трассировки на примере вычисления суммы цифр натурального числа. Пусть дано число $N = 543$.
Математическая модель:
- Последняя цифра числа $N$ получается как остаток от деления на 10: $N \% 10$.
- Оставшаяся часть числа получается целочисленным делением на 10: $N / 10$.
- Сумма цифр числа $N$ равна сумме его последней цифры и суммы цифр оставшейся части.

Базовый случай: если число $N$ стало равным 0, сумма его цифр равна 0.

Напишем код метода на C#:

```csharp
using System;

class Program
{
    static int SumOfDigits(int n)
    {
        // Базовый случай
        if (n == 0)
        {
            return 0;
        }
        
        // Рекурсивный шаг: последняя цифра + сумма цифр оставшейся части
        return (n % 10) + SumOfDigits(n / 10);
    }

    static void Main()
    {
        int number = 543;
        int result = SumOfDigits(number);
        Console.WriteLine($"Сумма цифр числа {number} равна {result}");
    }
}
```

Проведем полную трассировку выполнения метода `SumOfDigits(543)`:

1. Вызов `SumOfDigits(543)`:
   - Проверка: $543 == 0$ — ложь.
   - Вычисление: `543 % 10` равно $3$.
   - Требуется вычислить `SumOfDigits(543 / 10)`, то есть `SumOfDigits(54)`. Метод приостанавливает работу и ждет результата.
2. Вызов `SumOfDigits(54)`:
   - Проверка: $54 == 0$ — ложь.
   - Вычисление: `54 % 10` равно $4$.
   - Требуется вычислить `SumOfDigits(54 / 10)`, то есть `SumOfDigits(5)`. Ожидание ответа.
3. Вызов `SumOfDigits(5)`:
   - Проверка: $5 == 0$ — ложь.
   - Вычисление: `5 % 10` равно $5$.
   - Требуется вычислить `SumOfDigits(5 / 10)`, то есть `SumOfDigits(0)`. Ожидание ответа.
4. Вызов `SumOfDigits(0)`:
   - Проверка: $0 == 0$ — **истина**.
   - Возвращает значение `0` (базовый случай достигнут, раскрутка стека).
5. Возврат в `SumOfDigits(5)`:
   - Метод получает `0` от `SumOfDigits(0)`.
   - Вычисляет: `5 + 0 = 5`.
   - Возвращает `5` на предыдущий уровень.
6. Возврат в `SumOfDigits(54)`:
   - Метод получает `5` от `SumOfDigits(5)`.
   - Вычисляет: `4 + 5 = 9`.
   - Возвращает `9` на предыдущий уровень.
7. Возврат в `SumOfDigits(543)`:
   - Метод получает `9` от `SumOfDigits(54)` -> `SumOfDigits(54)`.
   - Вычисляет: `3 + 9 = 12`.
   - Возвращает финальный результат `12` в метод `Main`.

В отладчике Visual Studio / Rider этот процесс можно наблюдать через окно **Call Stack** (Стек вызовов), где наглядно видно накопление кадров функций при погружении в рекурсию и их исчезновение при возврате значений.

### Преобразование хвостовой рекурсии и оценка глубины рекурсивного дерева

> **Определение.** Рекурсия называется **хвостовой** (tail recursion), если рекурсивный вызов является **последней** операцией, выполняемой методом перед возвратом управления. В хвостовой рекурсии после завершения вложенного вызова метод не выполняет никаких дополнительных математических операций над полученным результатом.

Сравним две реализации вычисления факториала.
Обычная (нехвостовая) рекурсия:
```csharp
static int Factorial(int n)
{
    if (n <= 1) return 1;
    return n * Factorial(n - 1); // Умножение выполняется ПОСЛЕ возврата из рекурсии
}
```
Здесь компилятор или среда выполнения обязаны хранить в стеке значение переменной `n`, чтобы после заверщения `Factorial(n - 1)` умножить его на `n`.

Хвостовая рекурсия (с использованием вспомогательного параметра-аккумулятора):
```csharp
static int FactorialTail(int n, int accumulator = 1)
{
    if (n <= 1) return accumulator;
    return FactorialTail(n - 1, n * accumulator); // Рекурсивный вызов — последнее действие
}
```
В хвостовой рекурсии промежуточный результат передается прямо в аргументах следующего вызова. Современные оптимизаторы компиляторов (включая рантайм .NET) способны выполнять оптимизацию хвостовых вызовов (Tail Call Optimization, TCO), заменяя рекурсивные переходы на обычные прыжки (инструкции `jump`), что сводит потребление памяти в стеке к константному уровню $O(1)$. Однако в управляемой среде C#/.NET оптимизация хвостовой рекурсии для обычных методов используется редко и зависит от настроек компилятора JIT, поэтому на нее нельзя полагаться как на гарантированный инструмент экономии памяти.

#### Оценка глубины рекурсивного дерева и пространственной сложности

Глубина рекурсии (максимальное количество одновременно открытых кадров в стеке) определяет **пространственную сложность** алгоритма ($O(H)$, где $H$ — максимальная глубина).
Для линейной рекурсии (как в поиске суммы цифр или факториале) глубина стека прямо пропорциональна числу шагов: $O(N)$. Если $N = 100\,000$, стандартный стек потока .NET (по умолчанию около 1 МБ) не выдержит и выбросит `StackOverflowException`.

### Типичные архитектурные ошибки при написании рекурсивных методов в C#

1. **Забытый или недостижимый базовый случай.**
   Пример ошибки:
   ```csharp
   static int BadCountdown(int n)
   {
       return BadCountdown(n - 1); // Ошибка: нет условия n == 0, вызов бесконечен
   }
   ```
2. **Отсутствие движения к базовому случаю.**
   Пример ошибки:
   ```csharp
   static int InfiniteStep(int n)
   {
       if (n == 0) return 0;
       return InfiniteStep(n); // Ошибка: аргумент n не меняется, базовый случай никогда не наступит
   }
   ```
3. **Модификация глобального состояния вместо передачи параметров.**
   Использование статических полей класса для накопления промежуточных результатов в рекурсии делает код не потокобезопасным и трудноотлаживаемым. Всегда передавайте состояние через параметры метода.
4. **Избыточные вызовы (дублирование вычислений).**
   Разветвленная рекурсия без кэширования (мемоизации), когда одна и та же подзадача решается многократно (классический пример — наивное вычисление чисел Фибоначчи), приводит к экспоненциальной временной сложности $O(2^N)$.

### Разобранный пример: Сумма цифр натурального числа

#### Условие задачи
Написать статический метод на языке C#, который принимает целое неотрицательное число $N$ и рекурсивно вычисляет сумму его цифр. В методе `Main` продемонстрировать работу программы для числа $N = 543$. Использование циклов (`for`, `while`, `foreach`) строго запрещено.

#### Рисунок схемы работы (текстовая схема)
```text
Вызов: SumOfDigits(543)
 ├── 543 != 0 -> 543 % 10 (3) + SumOfDigits(54)
 │                              │
 │                              ├── 54 != 0 -> 54 % 10 (4) + SumOfDigits(5)
 │                              │                              │
 │                              │                              ├── 5 != 0 -> 5 % 10 (5) + SumOfDigits(0)
 │                              │                              │                              │
 │                              │                              │                              └── 0 == 0 -> возвращает 0
 │                              │                              │
 │                              │                              └── возвращает: 5 + 0 = 5
 │                              │
 │                              └── возвращает: 4 + 5 = 9
 │
 └── возвращает: 3 + 9 = 12 (Итоговый ответ)
```

#### Ход рассуждений (почему делаем именно так)
1. Нам дано целое число. Базовым случаем для работы с числами путем деления на 10 является достижение нуля ($N = 0$). Когда число исчерпано, сумма его цифр равна нулю.
2. На каждом шаге мы отделяем младшую цифру с помощью операции взятия остатка от деления на 10 (`n % 10`).
3. Оставшуюся часть числа передаем в следующий рекурсивный вызов, уменьшив разрядность с помощью целочисленного деления на 10 (`n / 10`).
4. Складываем текущую младшую цифру с результатом, полученным от рекурсивного вызова для остатка числа.

#### Решение на C# (полный компилируемый код)

```csharp
using System;

namespace RecursionDemo
{
    class Program
    {
        /// <summary>
        /// Рекурсивный метод для вычисления суммы цифр числа.
        /// </summary>
        /// <param name="n">Натуральное число или ноль.</param>
        /// <returns>Сумма цифр числа.</returns>
        static int SumOfDigits(int n)
        {
            // Защита от некорректных отрицательных входных данных
            if (n < 0)
            {
                throw new ArgumentException("Число должно быть неотрицательным.", nameof(n));
            }

            // Базовый случай: если число равно 0, сумма его цифр равна 0
            if (n == 0)
            {
                return 0;
            }

            // Рекурсивный шаг: последняя цифра + сумма цифр оставшейся части числа
            int lastDigit = n % 10;
            int remainingNumber = n / 10;

            return lastDigit + SumOfDigits(remainingNumber);
        }

        static void Main(string[] args)
        {
            // Входные данные по условию
            int n = 543;

            // Вызов метода
            int totalSum = SumOfDigits(n);

            // Вывод результата
            Console.WriteLine($"Исходное число: {n}");
            Console.WriteLine($"Сумма цифр: {totalSum}");
        }
    }
}
```

#### Пояснение по строкам кода
- Строка `if (n < 0)` — защитное программирование, обрабатывающее граничный случай с отрицательными числами.
- Строка `if (n == 0) { return 0; }` — базовый случай прекращения рекурсии.
- Строка `int lastDigit = n % 10;` — извлечение правой цифры числа (для 543 это `3`).
- Строка `int remainingNumber = n / 10;` — отбрасывание правой цифры (для 543 это `54`).
- Строка `return lastDigit + SumOfDigits(remainingNumber);` — комбинирование текущего значения с результатом рекурсивного спуска.

#### Пример ввода и вывода
**Входные данные:**
```text
543
```
**Вывод консоли:**
```text
Исходное число: 543
Сумма цифр: 12
```

#### Оценка сложности
- **Временная сложность:** $O(\log_{10} N)$, так как на каждом шаге число делится на 10, а количество шагов равно количеству цифр в числе $N$.
- **Пространственная сложность:** $O(\log_{10} N)$ из-за хранения кадров рекурсивных вызовов в стеке вызовов .NET. Для чисел в пределах стандартного типа `int` глубина стека никогда не превысит 10 кадров, что абсолютно безопасно с точки зрения риска переполнения стека.

Ответ: `12`

## 2. Классические математические задачи и хвостовая оптимизация

### Рекурсивное вычисление факториала и проверка переполнения

Факториал натурального числа $n$ (обозначается как $n!$) определяется для неотрицательных целых чисел как произведение всех натуральных чисел от $1$ до $n$ включительно. Математически рекуррентное определение факториала записывается следующим образом:

$$n! = \begin{cases} 1, & \text{при } n = 0 \text{ или } n = 1 \\ n \cdot (n - 1)!, & \text{при } n > 1 \end{cases}$$

В языке программирования C# для хранения целых чисел со знаком используются различные типы данных, имеющие строго ограниченный диапазон допустимых значений. Например, стандартный 32-битный знаковый тип `int` занимает в памяти $4$ байта ($32$ бита) и хранит значения в диапазоне от $-2\,147\,483\,648$ до $2\,147\,483\,647$. Знаковый 64-битный тип `long` занимает $8$ байт ($64$ бита) и позволяет работать с числами от $-9\,223\,372\,036\,854\,775\,808$ до $9\,223\,372\,036\,854\,775\,807$.

Поскольку факториал растет чрезвычайно быстро (быстрее экспоненты), тип `int` переполняется уже при вычислении $13!$ ($13! = 6\,227\,020\,800$, что больше максимального значения `int`). Тип `long` достигает своего предельного значения при вычислении $21!$ ($20! \approx 2{,}43 \cdot 10^{18}$, а $21!$ не помещается в 64-битный знаковый регистр). При выходе значения за границы диапазона типа в C# по умолчанию не генерируется исключение (если код выполняется в контексте без проверки переполнения), происходит тихий сдвиг бит, что приводит к некорректным отрицательным или случайным положительным результатам. Для предотвращения этого используют явную проверку входных параметров или конструкции `checked`.

Ниже приведена полная программа на C#, реализующая безопасное вычисление факториала с использованием типа `long` и проверкой корректности входных данных.

```csharp
using System;

class Program
{
    static void Main()
    {
        int n = 20;
        try
        {
            long result = Factorial(n);
            Console.WriteLine($"Факториал числа {n} равен {result}");
        }
        catch (ArgumentOutOfRangeException ex)
        {
            Console.WriteLine($"Ошибка аргумента: {ex.Message}");
        }
        catch (OverflowException)
        {
            Console.WriteLine("Произошло переполнение типа данных при вычислении факториала.");
        }
    }

    /// <summary>
    /// Рекурсивный метод вычисления факториала с проверкой переполнения.
    /// </summary>
    /// <param name="n">Исходное число (от 0 до 20 для типа long).</param>
    /// <returns>Значение факториала.</returns>
    static long Factorial(int n)
    {
        if (n < 0)
        {
            throw new ArgumentOutOfRangeException(nameof(n), "Факториал определен только для неотрицательных чисел.");
        }
        
        // Базовый случай
        if (n == 0 || n == 1)
        {
            return 1;
        }

        // Рекурсивный шаг с использованием checked для контроля переполнения long
        return checked(n * Factorial(n - 1));
    }
}
```

*Пояснение к коду:*
1. Метод `Factorial` принимает параметр `int n` и возвращает результат типа `long`.
2. Первая проверка (`n < 0`) отсекает недопустимые отрицательные аргументы, генерируя исключение `ArgumentOutOfRangeException`.
3. Базовый случай `n == 0` или `n == 1` возвращает $1$ и останавливает цепочку рекурсивных вызовов.
4. Выражение `checked(n * Factorial(n - 1))` принудительно вызывает исключение `OverflowException`, если промежуточное или финальное произведение превышает максимально допустимое значение для типа `long`.

Пример ввода: `n = 20`.
Пример вывода: `Факториал числа 20 равен 2432902008176640000`.

### Наибольший общий делитель (НОД) по алгоритму Евклида

Наибольшим общим делителем (НОД) двух целых неотрицательных чисел $a$ и $b$ называется наибольшее целое число, на которое оба эти числа делятся без остатка. Классический алгоритм Евклида основан на математическом свойстве: НОД двух чисел $a$ и $b$ (где $a > b$) равен НОД числа $b$ и остатка от деления $a$ на $b$.

Рекуррентная форма алгоритма Евклида записывается так:

$$\text{NOD}(a, b) = \begin{cases} a, & \text{при } b = 0 \\ \text{NOD}(b, a \pmod b), & \text{при } b \neq 0 \end{cases}$$

Эффективность алгоритма Евклида чрезвычайно высока: его временная сложность составляет $O(\log(\min(a, b)))$, так как на каждом шаге размер чисел уменьшается по меньшей мере вдвое (в худшем случае через числа Фибоначчи).

#### Разобранный пример: НОД для A = 1071 и B = 462

*Условие:* Найти НОД двух целых чисел $A = 1071$ и $B = 462$ с помощью рекурсивного алгоритма Евклида.

*Рисунок словами:*
Представим процесс как последовательное уменьшение пары чисел. На каждом шаге мы заменяем большее число остатком от деления большего на меньшее, пока второе число не станет равным нулю.

*Ход рассуждений:*
1. Проверяем делитель $B$. Поскольку $462 \neq 0$, базовый случай не срабатывает.
2. Вычисляем остаток от деления $1071$ на $462$: $1071 = 462 \cdot 2 + 147$. Остаток равен $147$.
3. Переходим к следующему рекурсивному вызову с параметрами $a = 462$ и $b = 147$.
4. Вычисляем остаток от деления $462$ на $147$: $462 = 147 \cdot 3 + 21$. Остаток равен $21$.
5. Переходим к вызову с параметрами $a = 147$ и $b = 21$.
6. Вычисляем остаток от деления $147$ на $21$: $147 = 21 \cdot 7 + 0$. Остаток равен $0$.
7. Переходим к вызову с параметрами $a = 21$ и $b = 0$.
8. Так как $b = 0$, срабатывает базовый случай, возвращается текущее значение $a$, равное $21$.

*Решение в общем виде и код на C#:*

```csharp
using System;

class Program
{
    static void Main()
    {
        int a = 1071;
        int b = 462;
        int result = Gcd(a, b);
        Console.WriteLine($"НОД чисел {a} и {b} равен {result}");
    }

    /// <summary>
    /// Рекурсивный метод вычисления НОД по алгоритму Евклида.
    /// </summary>
    static int Gcd(int a, int b)
    16
    {
        // Базовый случай: если второе число равно 0, НОД найден
        if (b == 0)
        {
            return Math.Abs(a);
        }

        // Рекурсивный шаг: передаем b и остаток от деления a на b
        return Gcd(b, a % b);
    }
}
```

*Проверка:*
Делим исходные числа на полученный ответ: $1071 / 21 = 51$ (целочисленно), $462 / 21 = 22$ (целочисленно). Общих делителей у чисел $51$ и $22$ больше нет ($51 = 3 \cdot 17$, $22 = 2 \cdot 11$). Результат правдоподобен.

*Ответ:* `21`.

### Быстрое возведение в степень (логарифмическая сложность)

Стандартное возведение числа $x$ в целую неотрицательную степень $n$ ($x^n$) путем последовательного умножения требует $n$ операций, что соответствует линейной сложности $O(n)$. Однако с помощью рекурсивного подхода, известного как алгоритм двоичного возведения в степень (или метод деления степени пополам), можно сократить количество операций до $O(\log n)$.

Математическое обоснование опирается на свойства степеней:

$$x^n = \begin{cases} 1, & \text{при } n = 0 \\ (x^{n/2})^2, & \text{при четном } n \\ x \cdot x^{n-1}, & \text{при нечетном } n \text{ (или } x \cdot (x^{(n-1)/2})^2 \text{)} \end{cases}$$

Для реализации на компьютерах деление целого числа $n$ на $2$ выполняется за один такт процессора, а проверка четности осуществляется через операцию взятия остатка (`n % 2 == 0`) или побитово (`(n & 1) == 0`).

Ниже представлена реализация быстрого возведения в степень для вещественного основания и целого показателя:

```csharp
using System;

class Program
{
    static void Main()
    {
        double x = 2.0;
        int n = 10;
        double result = Power(x, n);
        Console.WriteLine($"{x}^{n} = {result}");
    }

    /// <summary>
    /// Рекурсивное вычисление степени с логарифмической сложностью O(log n).
    /// </summary>
    static double Power(double x, int n)
    {
        // Базовый случай: любое число в степени 0 равно 1
        if (n == 0)
        {
            return 1.0;
        }

        // Обработка отрицательных степеней
        if (n < 0)
        {
            return 1.0 / Power(x, -n);
        }

        // Если степень четная: x^n = (x^(n/2))^2
        if (n % 2 == 0)
        {
            double half = Power(x, n / 2);
            return half * half;
        }
        else // Если степень нечетная: x^n = x * x^(n-1)
        {
            return x * Power(x, n - 1);
        }
    }
}
```

*Оценка сложности:*
Каждый четный шаг уменьшает показатель степени ровно в два раза. Глубина рекурсии и количество умножений равны $\log_2 n$, что для $n = 1024$ составляет всего около $10$ вызовов вместо $1024$ при линейном перемножении.

### Проблема экспоненциального роста на примере чисел Фибоначчи

Числа Фибоначчи образуют последовательность, в которой первые два числа равны $0$ и $1$, а каждое последующее число равно сумме двух предыдущих. Математическая модель имеет вид:

$$F(n) = \begin{cases} 0, & \text{при } n = 0 \\ 1, & \text{при } n = 1 \\ F(n - 1) + F(n - 2), & \text{при } n > 1 \end{cases}$$

Прямая реализация этого определения в виде рекурсивной функции кажется интуитивно понятной, но на практике является классическим примером неэффективного алгоритма с катастрофическим падением производительности.

#### Разобранный пример: Вычисление F(7) с построением дерева вызовов

*Условие:* Вычислить $7$-е число Фибоначчи $F(7)$, используя рекурсивное определение, и проанализировать структуру вызовов.

*Рисунок словами (дерево рекурсивных вызовов):*
Вершина дерева — вызов `F(7)`. Каждая ветвь разветвляется на два поддерева: `F(n-1)` и `F(n-2)`.

```text
                  F(7)
                /      \
            F(6)          F(5)
           /    \        /    \
       F(5)     F(4)  F(4)    F(3)
       /   \    /   \  ...     ...
     F(4) F(3) F(3) F(2)
      ...
```

*Ход рассуждений:*
1. Для вычисления `F(7)` метод запрашивает `F(6)` и `F(5)`.
2. Для вычисления `F(6)` запрашиваются `F(5)` и `F(4)`. Обратите внимание: значение `F(5)` вычисляется заново в левой ветви, хотя оно уже независимо вычисляется как правая ветвь исходного корня `F(7)`.
3. Такой дублирующий пересчет поддеревьев приводит к лавинообразному росту количества операций. Общее число вызовов функции растет пропорционально золотому сечению $\varphi^n$ (где $\varphi \approx 1{,}618$), что дает временную сложность $O(2^n)$.
4. При попытке вычислить, например, $F(50)$ таким методом программа зависнет на неопределенное время, совершив более квадриллиона операций.

*Реализация наивной рекурсии на C#:*

```csharp
using System;

class Program
{
    static void Main()
    {
        int n = 7;
        long result = FibonacciNaive(n);
        Console.WriteLine($"F({n}) = {result}");
    }

    /// <summary>
    /// Наивный рекурсивный расчет чисел Фибоначчи (O(2^n)).
    /// </summary>
    static long FibonacciNaive(int n)
    {
        if (n < 0)
        {
            throw new ArgumentOutOfRangeException(nameof(n));
        }
        if (n == 0) return 0;
        if (n == 1) return 1;

        return FibonacciNaive(n - 1) + FibonacciNaive(n - 2);
    }
}
```

*Ответ:* `F(7) = 13`.

### Мемоизация как способ оптимизации повторяющихся вычислений

Чтобы избавиться от экспоненциального роста в задачах с перекрывающимися подзадачами (как в случае чисел Фибоначчи), применяется техника **мемоизации** (от англ. *memoization*, запоминание). Суть метода заключается в том, что результат выполнения функции для каждого уникального набора аргументов сохраняется в специальном буфере (словаре `Dictionary<int, long>` или массиве). При повторном обращении к функции с тем же аргументом вычисления не выполняются повторно — программа мгновенно возвращает уже готовое значение из памяти.

Благодаря мемоизации временная сложность вычисления чисел Фибоначчи снижается с экспоненциальной $O(2^n)$ до линейной $O(n)$, а пространственная сложность возрастает до $O(n)$ для хранения кэша.

Ниже приведена полная программа на C#, реализующая оптимизированное вычисление чисел Фибоначчи с использованием вспомогательного кэширующего массива:

```csharp
using System;

class Program
{
    static void Main()
    {
        int n = 50;
        // Создаем массив для кэширования результатов (индекс соответствует числу Фибоначчи)
        long[] memo = new long[n + 1];
        
        // Инициализируем массив признаком того, что значения еще не вычислены (-1)
        for (int i = 0; i <= n; i++)
        {
            memo[i] = -1;
        }

        long result = FibonacciMemoized(n, memo);
        Console.WriteLine($"F({n}) = {result}");
    }

    /// <summary>
    /// Рекурсивный метод вычисления чисел Фибоначчи с мемоизацией.
    /// </summary>
    /// <param name="n">Номер числа Фибоначчи.</param>
    /// <param name="memo">Массив для хранения уже вычисленных значений.</param>
    /// <returns>Значение числа Фибоначчи.</returns>
    static long FibonacciMemoized(int n, long[] memo)
    {
        if (n < 0)
        {
            throw new ArgumentOutOfRangeException(nameof(n));
        }

        // Базовый случай
        if (n == 0) return 0;
        if (n == 1) return 1;

        // Если значение уже было вычислено ранее, возвращаем его из кэша
        if (memo[n] != -1)
        {
            return memo[n];
        }

        // Вычисляем рекурсивно, сохраняем в кэш и возвращаем результат
        memo[n] = FibonacciMemoized(n - 1, memo) + FibonacciMemoized(n - 2, memo);
        return memo[n];
    }
}
```

*Пояснение к коду:*
1. Массив `memo` заполняется значением `-1`, что служит индикатором отсутствия данных в кэше.
2. Перед выполнением рекурсивного разветвления проверяется условие `memo[n] != -1`. Если оно истинно, процессор не тратит время на углубление в стек вызовов.
3. Перед возвратом из метода свежевычисленный результат записывается в ячейку `memo[n]`.
4. Это позволяет за доли секунды находить числа Фибоначчи для больших индексов (например, $F(50) = 12\,586\,269\,025$), что принципиально невозможно при использовании наивного рекурсивного подхода.

## 3. Рекурсивные алгоритмы на массивах и строках

### Рекурсивный поиск элемента в отсортированном массиве (бинарный поиск)

Линейный поиск перебирает элементы массива один за другим, затрачивая в худшем случае линейное время $O(N)$. Если исходный массив уже отсортирован по неубыванию, можно применить гораздо более эффективный подход — **бинарный поиск** (деление пополам), который сокращает область поиска вдвое на каждом шаге. Рекурсивная реализация бинарного поиска отлично иллюстрирует парадигму «разделяй и властвуй».

> **Определение.** **Бинарный поиск** — алгоритм поиска элемента в отсортированном массиве, который сравнивает искомое значение с центральным элементом массива и рекурсивно продолжает поиск в левой или правой половине, если значение соответственно меньше или больше центрального.

Пусть у нас есть отсортированный массив целых чисел `arr` и искомое число `target`. Для работы рекурсии нам нужно передавать границы текущего рассматриваемого диапазона: индекс начала `left` и индекс конца `right`. 

Алгоритм рекурсивного бинарного поиска состоит из следующих шагов:
1. **Базовый случай 1 (элемент найден):** Если левая граница стала больше правой (`left > right`), значит, диапазон сузился до пустой области, и искомого элемента в массиве нет. Возвращаем специальное значение (например, `-1`).
2. **Шаг разделения:** Вычисляем индекс среднего элемента диапазона:
   $$mid = \text{left} + \frac{\text{right} - \text{left}}{2}$$
   Использование формулы $\text{left} + (\text{right} - \text{left}) / 2$ вместо $(\text{left} + \text{right}) / 2$ предотвращает потенциальное переполнение памяти (integer overflow) при работе с очень большими индексами.
3. **Базовый случай 2 (совпадение):** Если элемент `arr[mid] == target`, мы нашли искомый индекс `mid` и возвращаем его.
4. **Рекурсивный шаг:** 
   - Если `target < arr[mid]`, искомое значение может находиться только в левой половине. Вызываем метод рекурсивно для диапазона от `left` до `mid - 1`.
   - Если `target > arr[mid]`, искомое значение может находиться только в правой половине. Вызываем метод рекурсивно для диапазона от `mid + 1` до `right`.

Ниже приведена полная и компилируемая реализация бинарного поиска на языке C#:

```csharp
using System;

class BinarySearchDemo
{
    static int BinarySearchRecursive(int[] arr, int target, int left, int right)
    {
        // Базовый случай: границы перекрестились, элемент не найден
        if (left > right)
        {
            return -1;
        }

        // Вычисление середины диапазона без риска переполнения
        int mid = left + (right - left) / 2;

        // Базовый случай: элемент найден в средней позиции
        if (arr[mid] == target)
        {
            return mid;
        }

        // Рекурсивный шаг: если искомое меньше среднего, ищем в левой половине
        if (target < arr[mid])
        {
            return BinarySearchRecursive(arr, target, left, mid - 1);
        }

        // Рекурсивный шаг: если искомое больше среднего, ищем в правой половине
        return BinarySearchRecursive(arr, target, mid + 1, right);
    }

    static void Main()
    {
        int[] sortedArray = { 2, 5, 8, 12, 16, 23, 38, 56, 72, 91 };
        int target = 23;

        int resultIndex = BinarySearchRecursive(sortedArray, target, 0, sortedArray.Length - 1);

        if (resultIndex != -1)
        {
            Console.WriteLine($"Элемент {target} найден по индексу {resultIndex}.");
        }
        else
        {
            Console.WriteLine($"Элемент {target} отсутствует в массиве.");
        }
    }
}
```

**Оценка сложности:**
- **Временная сложность:** $O(\log_2 N)$, так как на каждом шаге размер рабочей области сокращается вдвое.
- **Пространственная сложность:** $O(\log_2 N)$ из-за затрат памяти на стек вызовов рекурсивной функции (глубина рекурсии равна количеству делений массива пополам).

### Проверка строки на палиндром методом сужения границ

Обработка строк с помощью рекурсии часто строится на сравнении символов, расположенных на противоположных концах строки, с последующим переходом к внутренней подстроке. Классическим примером является проверка строки на палиндром.

> **Определение.** **Палиндром** — это строка, которая читается одинаково как слева направо, так и справа налево (игнорируя регистр и пробелы в более сложных случаях, но для базового алгоритма будем рассматривать точное совпадение символов).

Для реализации рекурсивной проверки на палиндром нам понадобятся два индекса: `left` (указывает на первый символ текущего проверяемого диапазона) и `right` (указывает на последний символ).

Ход рассуждений:
1. **Базовый случай 1 (остановка):** Если индекс `left` становится больше или равен индексу `right` (`left >= right`), это означает, что мы успешно сравнили все символы от краев к центру (или остался один центральный символ в строках нечетной длины). Строка является палиндромом, возвращаем `true`.
2. **Сравнение символов:** Сравниваем символы `s[left]` и `s[right]`. Если они не равны (`s[left] != s[right]`), строка гарантированно не является палиндромом, возвращаем `false`.
3. **Рекурсивный шаг:** Если символы совпали, сужаем границы, вызывая метод для внутренней подстроки: проверяем индексы `left + 1` и `right - 1`.

#### Разобранный пример: Проверка строки 'rotor' на палиндром

- **Условие:** Проверить рекурсивно, является ли строка `s = "rotor"` палиндромом.
- **Рисунок (словами):** 
  Индексация строки: `s[0] = 'r'`, `s[1] = 'o'`, `s[2] = 't'`, `s[3] = 'o'`, `s[4] = 'r'`.
  Границы `left = 0`, `right = 4`.
- **Ход рассуждений:**
  - Вызов 1: `IsPalindrome("rotor", 0, 4)`. 
    Сравниваем `s[0] ('r')` и `s[4] ('r')`. Они равны. Делаем рекурсивный шаг с `left = 1`, `right = 3`.
  - Вызов 2: `IsPalindrome("rotor", 1, 3)`. 
    Сравниваем `s[1] ('o')` и `s[3] ('o')`. Они равны. Делаем рекурсивный шаг с `left = 2`, `right = 2`.
  - Вызов 3: `IsPalindrome("rotor", 2, 2)`. 
    Проверяем условие выхода: `left >= right` ($2 \ge 2$). Условие истинно, базовый случай возвращает `true`.
- **Решение в коде на C#:**

```csharp
using System;

class PalindromeDemo
{
    static bool IsPalindrome(string s, int left, int right)
    {
        // Базовый случай: дошли до середины или перешагнули её
        if (left >= right)
        {
            return true;
        }

        // Если символы на текущих границах не равны — это не палиндром
        if (s[left] != s[right])
        {
            return false;
        }

        // Рекурсивный шаг: сужаем границы к центру
        return IsPalindrome(s, left + 1, right - 1);
    }

    static void Main()
    {
        string text = "rotor";
        bool result = IsPalindrome(text, 0, text.Length - 1);

        if (result)
        {
            Console.WriteLine($"Строка \"{text}\" является палиндромом.");
        }
        else
        {
            Console.WriteLine($"Строка \"{text}\" не является палиндромом.");
        }
    }
}
```

- **Проверка:** 
  - Единицы измерения: отсутствуют (логический результат `bool`).
  - Правдоподобность: для строки длины $N$ метод выполнит ровно $\lfloor N / 2 \rfloor$ сравнений, что абсолютно верно.
- **Ответ:** Строка "rotor" является палиндромом.

### Рекурсивный обход и обработка элементов массива без использования циклов

Рекурсия может полностью заменить привычные циклы `for` и `while` при обходе массивов. Идея заключается в том, чтобы обрабатывать текущий элемент массива (например, по индексу `index`), а затем рекурсивно вызывать ту же функцию для обработки оставшейся части массива, увеличивая индекс на единицу.

Рассмотрим задачу вывода всех элементов массива на экран или подсчета их суммы без использования циклов.

```csharp
using System;

class ArrayTraversalDemo
{
    // Рекурсивный метод для вывода элементов массива
    static void PrintArrayRecursive(int[] arr, int index)
    {
        // Базовый случай: если индекс вышел за пределы массива, прекращаем рекурсию
        if (index >= arr.Length)
        {
            return;
        }

        // Обработка текущего элемента
        Console.Write(arr[index] + " ");

        // Рекурсивный шаг: переход к следующему элементу
        PrintArrayRecursive(arr, index + 1);
    }

    static void Main()
    {
        int[] data = { 4, 8, 15, 16, 23, 42 };
        Console.Write("Элементы массива: ");
        PrintArrayRecursive(data, 0);
        Console.WriteLine();
    }
}
```

Каждый вызов метода `PrintArrayRecursive` добавляет новый кадр (stack frame) в стек вызовов. Для массива длиной $N$ глубина рекурсии составит $N$, что безопасно для небольших массивов, но может вызвать исключение `StackOverflowException` при обработке массивов с размером в десятки тысяч элементов.

### Разделяй и властвуй: нахождение максимума в массиве рекурсивным делением пополам

Парадигма «разделяй и властвуй» позволяет эффективно обрабатывать массивы, разбивая задачу на две независимые подзадачи меньшего размера. Классический пример — поиск максимального элемента в массиве путем разделения его пополам.

Ход рассуждений:
1. **Базовый случай 1 (один элемент):** Если диапазон поиска состоит из одного элемента (`left == right`), то этот единственный элемент и является максимальным в данном поддиапазоне, возвращаем `arr[left]`.
2. **Базовый случай 2 (два элемента):** Если в диапазоне два элемента (`left + 1 == right`), возвращаем максимальный из них: `Math.Max(arr[left], arr[right])`.
3. **Рекурсивный шаг:** 
   - Вычисляем индекс середины `mid`.
   - Рекурсивно находим максимум в левой половине: `maxLeft = FindMax(arr, left, mid)`.
   - Рекурсивно находим максимум в правой половине: `maxRight = FindMax(arr, mid + 1, right)`.
   - Возвращаем наибольшее из двух полученных значений: `Math.Max(maxLeft, maxRight)`.

#### Разобранный пример: Нахождение максимума в массиве делением пополам

- **Условие:** Найти максимальный элемент в массиве целых чисел `[3, 8, 2, 15, 6, 9]` с помощью рекурсивной функции деления пополам.
- **Рисунок (словами):**
  Исходный массив индексов от `0` до `5`. 
  Дерево рекурсивных вызовов:
  - Диапазон `[0..5]` делится на `[0..2]` и вирут правый `[3..5]`.
  - Левая ветвь `[0..2]` (`[3, 8, 2]`) делится на `[0..1]` (`[3, 8]`) и `[2..2]` (`[2]`).
    - Подветвь `[0..1]` возвращает `Math.Max(3, 8) = 8`.
    - Сравнение с `[2..2]` дает `Math.Max(8, 2) = 8`.
  - Правая ветвь `[3..5]` (`[15, 6, 9]`) делится на `[3..4]` (`[15, 6]`) и `[5..5]` (`[9]`).
    - Подветвь `[3..4]` возвращает `Math.Max(15, 6) = 15`.
    - Сравнение с `[5..5]` дает `Math.Max(15, 9) = 15`.
  - Итоговое сравнение левой и правой половин: `Math.Max(8, 15) = 15`.
- **Решение в коде на C#:**

```csharp
using System;

class ArrayMaxDivideAndConquer
{
    static int FindMax(int[] arr, int left, int right)
    {
        // Базовый случай 1: в диапазоне один элемент
        if (left == right)
        {
            return arr[left];
        }

        // Базовый случай 2: в диапазоне два элемента
        if (right == left + 1)
        {
            return Math.Max(arr[left], arr[right]);
        }

        // Шаг разделения: находим середину
        int mid = left + (right - left) / 2;

        // Рекурсивный вызов для левой и правой половин
        int maxLeft = FindMax(arr, left, mid);
        int maxRight = FindMax(arr, mid + 1, right);

        // Объединение результатов
        return Math.Max(maxLeft, maxRight);
    }

    static void Main()
    {
        int[] numbers = { 3, 8, 2, 15, 6, 9 };
        int maximum = FindMax(numbers, 0, numbers.Length - 1);

        Console.WriteLine($"Максимальный элемент в массиве: {maximum}");
    }
}
```

- **Проверка:**
  - Единицы измерения: целые числа (значения элементов массива).
  - Правдоподобность: среди чисел 3, 8, 2, 15, 6, 9 наибольшим действительно является 15. Алгоритм корректно обошел все элементы без пропусков.
- **Ответ:** Максимальный элемент в массиве: 15.

### Оценка пространственной сложности рекурсии при работе с большими массивами строк

При написании рекурсивных алгоритмов крайне важно оценивать не только временную сложность (количество операций), но и **пространственную сложность** (количество потребляемой памяти). В языке C# ссылочные типы (к которым относится класс `string` и массивы `string[]`) хранят в куче (heap), однако сами локальные переменные методов, ссылки на массивы и параметры вызовов размещаются в стеке вызовов (call stack) при каждом новом рекурсивном вызове.

> **Важно.** Каждый вызов рекурсивной функции выделяет в стеке памяти кадр вызова (stack frame), содержащий параметры метода, локальные переменные и адрес возврата. Если глубина рекурсии велика, происходит исчерпание выделенной памяти стека, что приводит к неперехватываемому системному исключению `System.StackOverflowException`.

При работе с большими массивами строк (например, обработка текстового файла, содержащего 100 000 строк) рекурсивные подходы, такие как линейный рекурсивный обход с шагом `index + 1`, неприменимы из-за линейной пространственной сложности $O(N)$ по стеку. 

Сравнение потребления памяти для различных подходов приведено в таблице ниже:

| Подход к обработке массива строк | Временная сложность | Пространственная сложность (память в стеке) | Риск переполнения стека (`StackOverflowException`) |
| :--- | :--- | :--- | :--- |
| **Линейный рекурсивный обход** (`index + 1`) | $O(N)$ | $O(N)$ | Высокий (при $N > 10\,000$) |
| **Рекурсия «разделяй и властвуй»** (деление пополам) | $O(N)$ | $O(\log_2 N)$ | Низкий (для $N = 1\,000\,000$ глубина стека $\approx 20$) |
| **Итеративный подход** (цикл `for` / `foreach`) | $O(N)$ | $O(1)$ | Отсутствует |

**Рекомендация для практики:** Если алгоритм можно естественным образом выразить через «разделяй и властвуй» (как бинарный поиск или поиск максимума делением пополам), глубина рекурсии логарифмическая $O(\log_2 N)$, что безопасно. Если же задача требует линейного прохода по элементам огромного массива или длинной строки, в продакшн-коде на C# настоятельно рекомендуется использовать итеративные конструкции с циклами или хвостовую рекурсию (там, где компилятор поддерживает оптимизацию).

## 4. Комбинаторная рекурсия: генерация подмножеств и перестановок

### 4. Комбинаторная рекурсия: генерация подмножеств и перестановок

Многие практические задачи в программировании требуют не просто вычисления одного числа или поиска элемента, а построения полного набора возможных вариантов: составления расписаний, поиска оптимальных маршрутов, генерации паролей или анализа всех возможных состояний игровой системы. Если количество элементов заранее неизвестно или может изменяться, обычные вложенные циклы `for` становятся неприменимыми, так как глубина вложения должна быть динамической. В таких случаях незаменимым инструментом становится комбинаторная рекурсия и метод поиска с возвратом.

> **Определение.** **Поиск с возвратом (backtracking)** — это общий метод систематического перебора всех возможных решений задачи, который строит решение пошагово. Если на очередном шаге обнаруживается, что продолжение текущей ветки не может привести к корректному результату, алгоритм «откатывается» (возвращается) на предыдущий шаг, отменяет последнее действие и пробует другой вариант выбора.

Процесс работы таких алгоритмов удобно представлять в виде **дерева вариантов** (или дерева рекурсивных вызовов). Корень дерева соответствует начальному состоянию (пустое решение), внутренние узлы — промежуточным шагам построения, а листья — полностью сформированным вариантам, которые подлежат выводу или проверке.

Рассмотрим, как этот подход реализуется на практике на языке C# для различных классов комбинаторных задач.

---

### Генерация всех двоичных строк заданной длины N

Первой базовой задачей комбинаторики является построение всех возможных комбинаций из нулей и единиц фиксированной длины $N$. Например, при $N = 2$ таких строк будет $4$: `00`, `01`, `10`, `11`. Общее количество строк всегда равно $2^N$.

Для генерации таких строк рекурсивным методом спроектируем функцию, которая принимает текущую длину строки $N$, текущую глубинную позицию (или уже построенную часть строки) и добавляет поочередно символ `'0'`, а затем символ `'1'`.

В качестве структуры для накопления результата удобно использовать массив символов `char[]` фиксированного размера $N$. По мере погружения в рекурсию мы заполняем ячейку массива на позиции `index`, а достигнув конца ($index == N$), выводим готовую строку в консоль.

Рассмотрим полностью рабочий пример программы на C#, которая генерирует все двоичные строки для $N = 3$.

```csharp
using System;

class BinaryStringGenerator
{
    static void Main()
    {
        int n = 3;
        // Создаем буфер для построения текущей строки длиной N
        char[] buffer = new char[n];
        
        Console.WriteLine($"Генерация всех двоичных строк длины N = {n}:");
        GenerateBinary(n, 0, buffer);
    }

    /// <summary>
    /// Рекурсивный метод генерации двоичных строк.
    /// </summary>
    /// <param name="n">Заданная длина строки</param>
    /// <param name="index">Текущая заполняемая позиция в массиве</param>
    /// <param name="buffer">Массив-буфер для хранения текущей комбинации</param>
    static void GenerateBinary(int n, int index, char[] buffer)
    {
        // Базовый случай: если индекс достиг длины N, строка полностью сформирована
        if (index == n)
        {
            Console.WriteLine(new string(buffer));
            return;
        }

        // Ветвление 1: пробуем поставить '0' на текущую позицию
        buffer[index] = '0';
        GenerateBinary(n, index + 1, buffer);

        // Ветвление 2: пробуем поставить '1' на текущую позицию
        buffer[index] = '1';
        GenerateBinary(n, index + 1, buffer);
    }
}
```

**Разбор кода по шагам:**
1. Метод `Main` инициализирует переменную `n = 3` и выделяет память под буфер `char[] buffer = new char[3]`. Этот буфер используется повторно для всех комбинаций, что экономит память и предотвращает лишние выделения в куче.
2. Метод `GenerateBinary` принимает текущий `index`. Если `index == 3`, условие базового случая срабатывает, и создается объект `string` из текущего содержимого массива `buffer`, после чего строка выводится на экран. Инструкция `return` возвращает управление на предыдущий уровень рекурсии.
3. Если базовый случай не достигнут, выполняются два последовательных рекурсивных вызова. Сначала в ячейку `buffer[index]` записывается символ `'0'`, и запускается вызов для следующей позиции (`index + 1`). Когда этот вызов полностью завершится и вернется назад, значение в ячейке перезаписывается на `'1'`, и запускается второй рекурсивный вызов. Это и есть классический перебор с возвратом на уровне стека вызовов.

**Пример ввода и вывода:**
Входные данные заданы в коде (`n = 3`).
Вывод программы:
```text
Генерация всех двоичных строк длины N = 3:
000
001
010
011
100
101
110
111
```

**Оценка сложности:**
- **Временная сложность:** $O(2^N)$, так как на каждом из $N$ уровней рекурсии происходит разветвление ровно на 2 ветки, что в сумме дает $2^N$ листьев дерева вызовов.
- **Пространственная сложность:** $O(N)$ для хранения стека вызовов максимальной глубины $N$ и буфера размером $N$.

### Рекурсивное построение всех подмножеств заданного множества

Следующая задача — построение всех подмножеств (булеана) заданного множества элементов (например, массива символов или целых чисел). Если исходное множество содержит $N$ элементов, то общее количество подмножеств составляет $2^N$ (включая пустое множество).

Для каждого элемента исходного массива у нас есть ровно два логических варианта: либо мы **включаем** текущий элемент в формируемое подмножество, либо **не включаем** его. Это порождает бинарное дерево решений, аналогичное предыдущей задаче, но с тем отличием, что мы накапливаем элементы в динамическом списке.

Рассмотрим реализацию на C# для массива из трех элементов: `['A', 'B', 'C']`.

```csharp
using System;
using System.Collections.Generic;

class SubsetsGenerator
{
    static void Main()
    {
        char[] elements = { 'A', 'B', 'C' };
        List<char> currentSubset = new List<char>();

        Console.WriteLine("Все возможные подмножества множества {A, B, C}:");
        GenerateSubsets(elements, 0, currentSubset);
    }

    /// <summary>
    /// Рекурсивный метод построения подмножеств методом включения/исключения.
    /// </summary>
    /// <param name="elements">Исходный массив элементов</param>
    /// <param name="index">Индекс текуссматриваемого элемента</param>
    /// <param name="currentSubset">Список, содержащий текущее подмножество</param>
    static void GenerateSubsets(char[] elements, int index, List<char> currentSubset)
    {
        // Базовый случай: рассмотрели все элементы исходного массива
        if (index == elements.Length)
        {
            PrintSubset(currentSubset);
            return;
        }

        // Вариант 1: НЕ включаем текущий элемент elements[index] в подмножество
        GenerateSubsets(elements, index + 1, currentSubset);

        // Вариант 2: Включаем текущий элемент elements[index] в подмножество
        currentSubset.Add(elements[index]);
        GenerateSubsets(elements, index + 1, currentSubset);

        // Шаг возврата (backtracking): удаляем добавленный элемент, 
        // чтобы восстановить состояние списка для предыдущих уровней рекурсии
        currentSubset.RemoveAt(currentSubset.Count - 1);
    }

    static void PrintSubset(List<char> subset)
    {
        Console.Write("{ ");
        Console.Write(string.Join(", ", subset));
        Console.WriteLine(" }");
    }
}
```

**Ход рассуждений и пояснение кода:**
1. Мы рекурсивно идем по индексу исходного массива от `0` до `elements.Length`.
2. На каждом шаге мы сначала вызываем функцию без добавления элемента (`GenerateSubsets(elements, index + 1, currentSubset)`). Это ветка, где элемент пропускается.
3. Затем мы добавляем элемент в список `currentSubset.Add(elements[index])` и вызываем функцию для следующего индекса. Это ветка, где элемент берется в подмножество.
4. **Важнейший момент безопасности работы с общим списком:** после возврата из второго рекурсивного вызова мы обязаны выполнить операцию `currentSubset.RemoveAt(...)`. Поскольку объект `List<T>` передается по ссылке, изменения внутри него видны на всех уровнях. Если не удалить добавленный элемент при возврате наверх, он останется в списке для других ветвлений, что приведет к искажению данных. Это и есть ручная очистка временных буферов при возврате.

**Вывод программы:**
```text
Все возможные подмножества множества {A, B, C}:
{ }
{ C }
{ B }
{ B, C }
{ A }
{ A, C }
{ A, B }
{ A, B, C }
```

### Алгоритм генерации всех перестановок символов строки методом обмена

Перестановка — это упорядоченный набор элементов, в котором важен порядок следования. Для строки из $N$ уникальных символов количество возможных перестановок равно факториалу $N!$ ($N$!). Например, для строки `"ABC"` существует $3! = 6$ перестановок: `ABC`, `ACB`, `BAC`, `BCA`, `CAB`, `CBA`.

Классический рекурсивный подход к генерации перестановок заключается в фиксировании позиции символа и рекурсивном переборе всех возможных замен (обменов мест) для оставшихся позиций.

> **Правило.** Чтобы сгенерировать все перестановки массива символов, начиная с позиции `index`:
> 1. Зафиксируем текущую позицию `index`.
> 2. В цикле переберем все возможные индексы `i` от `index` до конца массива.
> 3. Поменяем местами символ на позиции `index` и символ на позиции `i`.
> 4. Рекурсивно вызовем генерацию для позиции `index + 1`.
> 5. **Обязательно выполним обратный обмен (возврат)**, чтобы восстановить исходный порядок символов перед следующей итерацией цикла.

Реализуем этот алгоритм на C#:

```csharp
using System;

class PermutationsGenerator
{
    static void Main()
    {
        string input = "ABC";
        char[] chars = input.ToCharArray();

        Console.WriteLine($"Все перестановки строки '{input}':");
        GeneratePermutations(chars, 0);
    }

    /// <summary>
    /// Рекурсивный метод генерации перестановок методом обмена (backtracking).
    /// </summary>
    /// <param name="chars">Массив символов, над которым выполняются перестановки</param>
    /// <param name="index">Текущая фиксируемая позиция</param>
    static void GeneratePermutations(char[] chars, int index)
    {
        // Базовый случай: если фиксированная позиция достигла конца массива, 
        // текущая перестановка полностью сформирована
        if (index == chars.Length - 1)
        {
            Console.WriteLine(new string(chars));
            return;
        }

        // Цикл перебора вариантов для текущей позиции
        for (int i = index; i < chars.Length; i++)
        {
            // Шаг 1: делаем выбор (ставим символ i на текущую позицию index)
            Swap(ref chars[index], ref chars[i]);

            // Шаг 2: рекурсивно переходим к генерации оставшейся части строки
            GeneratePermutations(chars, index + 1);

            // Шаг 3: возврат (backtracking) — отменяем обмен, возвращая массив в исходное состояние
            Swap(ref chars[index], ref chars[i]);
        }
    }

    /// <summary>
    /// Вспомогательный метод для обмена двух символов местами по ссылке.
    /// </summary>
    static void Swap(ref char a, ref char b)
    {
        char temp = a;
        a = b;
        b = temp;
    }
}
```

**Трассировка и логика работы:**
Представим вызов для строки `"AB"` (`index = 0`):
1. В цикле `i` начинается с `0`:
   - `i = 0`: обмен `chars[0]` и `chars[0]` (остается `"AB"`), рекурсивный вызов для `index = 1`.
   - Внутри вызова `index = 1` срабатывает базовый случай (`1 == 2 - 1`), выводится строка `"AB"`.
   - Возврат наверх, обратный обмен (ничего не меняется).
2. Цикл продолжает работу, `i = 1`:
   - Обмен `chars[0]` и `chars[1]` (`'A'` и `'B'`), строка становится `"BA"`.
   - Рекурсивный вызов для `index = 1`, срабатывает базовый случай, выводится строка `"BA"`.
   - Возврат наверх, **обязательный обратный обмен** (`Swap`), возвращающий строку в исходное состояние `"AB"`, чтобы не испортить ветвление для других вызовов.

**Пример вывода программы:**
```text
Все перестановки строки 'ABC':
ABC
ACB
BAC
BCA
CBA
CAB
```
*(Примечание: порядок вывода зависит от циклов обмена, но гарантирует генерацию всех уникальных перестановок при условии уникальности исходных символов).*

**Контроль глубины рекурсии и очистка буферов:**
В задачах комбинаторики критически важно следить за тем, чтобы любые мутации общих структур данных (списков, массивов символов, матриц состояний) строго симметрично отменялись после завершения рекурсивного ветвления. Если забыть выполнить обратное действие (`Swap` назад или `RemoveAt`), алгоритм продолжит работу с загрязненным состоянием буфера, что приведет к пропуску корректных вариантов и выводу дубликатов. Глубина рекурсии в комбинаторных задачах всегда строго ограничена размером входных данных ($N$), что полностью исключает риск переполнения стека `StackOverflowException` при разумных значениях $N$ (например, $N \le 12$ для факториала).

## 5. Сложные задачи поиска с возвратом: лабиринты и задачи размещения

### 5.1. Поиск с возвратом (Backtracking): общие принципы и представление двумерных полей

Предыдущие темы показали, как рекурсия применяется для работы с линейными структурами и генерации простых комбинаторных объектов. Однако многие задачи требуют исследования пространств вариантов, где каждый шаг порождает несколько альтернативных ветвей развития событий. Если выбранное направление приводит к тупику, необходимо вернуться на шаг назад, отменить сделанный выбор и попробовать другое направление. Такой подход называется **поиском с возвратом** (backtracking).

> **Определение.** **Поиск с возвратом (backtracking)** — это общий метод построения решений для комбинаторных задач, который заключается в последовательном переборе вариантов. Если текущая ветвь поиска не удовлетворяет условиям задачи или приводит к тупику, алгоритм «откатывается» (возвращается) на предыдущий уровень принятия решений и продолжает обход с другими ветвями.

В программировании поиск с возвратом реализуется с помощью рекурсивных функций. Каждый уровень рекурсии соответствует принятию одного решения (например, сделать шаг в определенном направлении, поставить фигуру на доску). Локальные переменные метода хранят текущее состояние, а стек вызовов автоматически управляет возвратом к предыдущему состоянию при выходе из рекурсивного вызова.

Для моделирования пространственных задач (лабиринты, шахматные доски, карты местности) в языке C# используется двумерный массив (матрица). В зависимости от задачи матрица может содержать символы (`char[,]`), логические значения (`bool[,]`) или целые числа (`int[,]`).

Рассмотрим представление двумерной сетки символов в памяти C#:

```csharp
char[,] grid = {
    { '.', '.', '#', '.' },
    { '#', '.', '.', '.' },
    { '.', '#', '#', '.' },
    { '.', '.', '.', '.' }
};
```

Здесь символы имеют строгую семантику:
- `.` (точка) — свободная для прохода ячейка;
- `#` (решетка) — стена (препятствие), через которую нельзя пройти;
- `V` (или специальная метка в коде) — ячейка, которая уже была посещена в текущем пути.

Доступ к элементам двумерного массива в C# осуществляется по индексам `[row, col]`, где `row` — номер строки (от 0 до `Rows - 1`), а `col` — номер столбца (от 0 до `Cols - 1`). Размеры массива определяются через свойства `grid.GetLength(0)` (количество строк) и `grid.GetLength(1)` (количество столбцов).

### 5.2. Рекурсивный поиск путей в лабиринте: отметка клеток и возврат (backtracking)

Классическая задача поиска пути в лабиринте заключается в том, чтобы найти хотя бы один путь (или подсчитать общее количество путей) из заданной стартовой точки в целевую точку, не пересекая стены.

#### Условия беспрепятственного прохода

Перед тем как сделать шаг из текущей клетки `(row, col)` в соседнюю клетку `(nextRow, nextCol)`, алгоритм обязан проверить четыре фундаментальных условия корректности хода:

1. **Границы поля:** Новые координаты не должны выходить за пределы матрицы:
   $$0 \le \text{nextRow} < \text{Rows} \quad \text{и} \quad 0 \le \text{nextCol} < \text{Cols}$$
2. **Отсутствие стен:** Клетка не должна содержать препятствие: `grid[nextRow, nextCol] != '#'`.
3. **Отсутствие циклов (непосещенность):** Клетка не должна быть уже посещена в текущем пути, чтобы алгоритм не зациклился. Для этого используется временная отметка (например, символ `'v'` или вспомогательный массив посещений `visited[row, col]`).
4. **Базовый случай (достижение цели):** Если `row == targetRow` и `col == targetCol`, цель достигнута, фиксируется успешное завершение ветки.

#### Стратегия сброса отметок (Backtracking step)

Главная особенность поиска *всех* возможных путей (в отличие от поиска *первого* пути) заключается в том, что после проверки всех возможных направлений из текущей клетки необходимо снять временную отметку посещения («сбросить отметку»). Если этого не сделать, ячейка останется заблокированной для других альтернативных путей, которые проходят через ту же точку, но с другого направления.

### 5.3. Разобранный пример: поиск путей в матрице 4x4

#### Условие задачи
Требуется написать программу на C#, которая находит общее количество различных успешных путей из левого верхнего угла `(0, 0)` в правый нижний угол `(3, 3)` в заданной матрице размером $4 \times 4$. Двигаться можно только в четырех направлениях: вправо, вниз, влево, вверх. Диагональные перемещения запрещены. Некоторые ячейки заблокированы стенами.

Исходная матрица лабиринта:
```
S . . #
. # . .
. . # .
# . . E
```
Где:
- `S` (start) — стартовая позиция `(0, 0)`;
- `E` (end) — целевая позиция `(3, 3)`;
- `.` — свободная ячейка;
- `#` — стена.

#### Рисунок схемы перебора направлений
Из каждой текущей клетки `(r, c)` рекурсивная функция пытается сделать шаги в следующем порядке:
1. Вниз: `(r + 1, c)`
2. Вправо: `(r, c + 1)`
3. Вверх: `(r - 1, c)`
4. Влево: `(r - 1, c)`

#### Ход рассуждений (почему делаем именно так)
1. Объявляем метод `CountPaths(int r, int c, int targetR, int targetC, char[,] maze, bool[,] visited)`.
2. Проверяем граничные условия: если текущие координаты выходят за рамки, упираются в стену `#` или уже посещены (`visited[r, c] == true`), возвращаем `0` путей.
3. Проверяем базовый случай: если `r == targetR` и `c == targetC`, мы дошли до финиша. Возвращаем `1` (найден ровно один успешный путь).
4. Делаем шаг: отмечаем текущую клетку как посещенную: `visited[r, c] = true`.
5. Рекурсивно суммируем количество путей, полученных при движении во все 4 стороны.
6. **Шаг возврата (backtracking):** Снимаем отметку посещения: `visited[r, c] = false`. Это критически важно, так как одна и та же ячейка может входить в состав разных независимых маршрутов.
7. Возвращаем накопленную сумму путей.

#### Полный код программы на C#

```csharp
using System;

class MazeSolver
{
    // Метод для рекурсивного подсчета всех путей в лабиринте
    static int CountPaths(int r, int c, int targetR, int targetC, char[,] maze, bool[,] visited)
    {
        int rows = maze.GetLength(0);
        int cols = maze.GetLength(1);

        // 1. Проверка выхода за границы массива
        if (r < 0 || r >= rows || c < 0 || c >= cols)
        {
            return 0;
        }

        // 2. Проверка препятствий (стен) и уже посещенных клеток в текущем пути
        if (maze[r, c] == '#' || visited[r, c])
        {
            return 0;
        }

        // 3. Базовый случай: достигли целевой ячейки
        if (r == targetR && c == targetC)
        {
            return 1;
        }

        // 4. Фиксация посещения текущей клетки
        visited[r, c] = true;

        int totalPaths = 0;

        // 5. Исследование всех 4 возможных направлений (Вниз, Вправо, Вверх, Влево)
        totalPaths += CountPaths(r + 1, c, targetR, targetC, maze, visited); // Вниз
        totalPaths += CountPaths(r, c + 1, targetR, targetC, maze, visited); // Вправо
        totalPaths += CountPaths(r - 1, c, targetR, targetC, maze, visited); // Вверх
        totalPaths += CountPaths(r, c - 1, targetR, targetC, maze, visited); // Влево

        // 6. ВОЗВРАТ (Backtracking): снятие отметки посещения для других ветвей поиска
        visited[r, c] = false;

        return totalPaths;
    }

    static void Main()
    {
        // Инициализация лабиринта 4x4
        char[,] maze = {
            { '.', '.', '.', '#' },
            { '.', '#', '.', '.' },
            { '.', '.', '#', '.' },
            { '#', '.', '.', '.' }
        };

        int startR = 0, startC = 0;
        int targetR = 3, targetC = 3;

        bool[,] visited = new bool[4, 4];

        int result = CountPaths(startR, startC, targetR, targetC, maze, visited);

        Console.WriteLine($"Количество успешных путей: {result}");
    }
}
```

#### Проверка и анализ
- **Единицы измерения:** В данной задаче результатом является безразмерная величина — количество путей (целое число).
- **Правдоподобность:** Для матрицы $4 \times 4$ со средним количеством стен количество путей невелико (обычно от 0 до нескольких десятков). Алгоритм корректно перебирает все возможные не зацикленные траектории.
- **Оценка сложности:** В худшем случае (пустая матрица без стен) количество путей растет экспоненциально в зависимости от площади поля $O(4^{N \times M})$, так как из каждой клетки доступно до 4 направлений. Пространственная сложность по памяти определяется глубиной стека вызовов и матрицей посещений: $O(N \times M)$.

`Ответ: Количество успешных путей: 2`

### 5.4. Классическая задача о расстановке ферзей (N Queens)

Более сложным и глубоким примером поиска с возвратом является классическая **задача о расстановке $N$ ферзей** на шахматной доске размером $N \times N$. Задача требует расставить $N$ ферзей таким образом, чтобы ни один из них не находился под боем другого (то есть ни два ферзя не стояли на одной горизонтали, вертикали или диагонали).

#### Математическая модель и условия безопасности

Поскольку в каждом из $N$ рядов доски должен стоять ровно один ферзь, мы можем проектировать рекурсивный алгоритм построчно. На каждом шаге рекурсии мы пытаемся разместить ферзя в строке `row`, перебирая все возможные столбцы `col` от $0$ до $N-1$.

Для каждой попытки поставить ферзя в позицию `(row, col)` необходимо проверить три условия безопасности по сравнению со всеми ранее расставленными ферзями в предыдущих строках:
1. **Столбец:** В столбце `col` еще нет ферзя.
2. **Главная диагональ:** Разность индексов `row - col` уникальна для каждой диагонали.
3. **Побочная диагональ:** Сумма индексов `row + col` уникальна для каждой диагонали.

#### Реализация проверки и поиска на C#

```csharp
using System;

class NQueens
{
    static int solutionsCount = 0;

    static void Solve(int row, int n, int[] queensColumn)
    {
        // Базовый случай: все ферзи успешно расставлены
        if (row == n)
        {
            solutionsCount++;
            return;
        }

        // Перебираем возможные столбцы для текущей строки
        for (int col = 0; col < n; col++)
        {
            if (IsSafe(row, col, queensColumn))
            {
                queensColumn[row] = col; // Ставим ферзя
                Solve(row + 1, n, queensColumn); // Рекурсивный переход к следующей строке
                // Шаг возврата (backtracking) здесь происходит автоматически, 
                // так как массив queensColumn перезаписывается при следующей итерации цикла for
            }
        }
    }

    static bool IsSafe(int currentRow, int currentCol, int[] queensColumn)
    {
        for (int prevRow = 0; prevRow < currentRow; prevRow++)
        {
            int prevCol = queensColumn[prevRow];

            // Проверка коллизий по вертикали и диагоналям
            if (prevCol == currentCol || 
                Math.Abs(prevRow - currentRow) == Math.Abs(prevCol - currentCol))
            {
                return false;
            }
        }
        return true;
    }

    static void Main()
    {
        int n = 8; // Классическая доска 8x8
        int[] queensColumn = new int[n];

        Solve(0, n, queensColumn);

        Console.WriteLine($"Количество решений для доски {n}x{n}: {solutionsCount}");
    }
}
```

#### Пояснение к коду
- Массив `queensColumn` хранит позицию ферзя для каждой строки (индекс массива — строка, значение элемента — столбец). Это компактное представление позволяет мгновенно проверять вертикали и диагонали без выделения громоздкой двумерной матрицы.
- Функция `IsSafe` проверяет все предыдущие ряды от `0` до `currentRow - 1`. Если разность по вертикали равна разности по горизонтали (`Math.Abs(...) == Math.Abs(...)`), значит, ферзи находятся на одной диагонали.
- `solutionsCount` накапливает общее количество найденных независимых комбинаций расстановки. Для доски $8 \times 8$ число решений равно ровно $92$.

### Контрольные вопросы для самопроверки

1. В чем главное отличие поиска с возвратом (backtracking) от обычного полного перебора без возврата?

3. Каким образом язык C# и рекурсивный вызов методов управляют сохранением состояния при возврате из тупиковых ветвей?
4. Оцените пространственную сложность в стеке вызовов для рекурсивного обхода лабиринта размером $N \times M$.

#### Ход рассуждений (почему делаем именно так)

1. **Моделирование сетки:** Представим лабиринт в виде массива символов `char[,]`. Для отслеживания посещенных клеток в текущей ветке обхода создадим параллельный логический массив `bool[,] visited`, который автоматически инициализируется значениями `false`.
2. **Проектирование рекурсивной функции:** 
   - Функция `CountPaths(int r, int c, int targetR, int targetC, char[,] grid, bool[,] visited)` должна возвращать целое число — количество успешных маршрутов.
   - **Граничные проверки:** Сначала проверяем, не вышли ли мы за границы лабиринта, не уперлись ли в стену (`grid[r, c] == '#'`) и не посещали ли эту клетку ранее (`visited[r, c] == true`). Если хотя бы одно условие нарушено, данный путь недействителен, возвращаем `0`.
   - **Базовый случай (цель достигнута):** Если текущие координаты `r` и `c` совпадают с целевыми координатами `targetR` и `targetC`, мы нашли один полноценный маршрут. Возвращаем `1`.
3. **Рекурсивный шаг (поиск с возвратом):**
   - Помечаем текущую клетку как посещенную: `visited[r, c] = true`.
   - Запускаем рекурсивный поиск во всех 4 возможных направлениях (вниз, вправо, вверх, влево), суммируя возвращенные ими результаты.
   - **Шаг возврата (backtracking):** После того как все четыре направления исследованы, обязательно снимаем отметку посещения: `visited[r, c] = false`. Это позволяет другим веткам алгоритма использовать эту клетку в своих маршрутах.

#### Решение на C# (полный компилируемый код)

```csharp
using System;

class MazeBacktrackingDemo
{
    static void Main()
    {
        // Определение лабиринта 4x4
        // '.' - свободно, '#' - стена
        char[,] maze = {
            { '.', '.', '.', '#' },
            { '.', '#', '.', '.' },
            { '.', '.', '#', '.' },
            { '#', '.', '.', '.' }
        };

        int rows = maze.GetLength(0);
        int cols = maze.GetLength(1);

        // Массив для отслеживания посещенных клеток в текущем пути
        bool[,] visited = new bool[rows, cols];

        // Старт: (0, 0), Конец: (3, 3)
        int startRow = 0, startCol = 0;
        int endRow = rows - 1, endCol = cols - 1;

        int totalPaths = CountPaths(startRow, startCol, endRow, endCol, maze, visited);

        Console.WriteLine($"Общее количество путей из (0,0) в ({endRow},{endCol}): {totalPaths}");
    }

    /// <summary>
    /// Рекурсивный метод подсчета всех путей в лабиринте методом поиска с возвратом.
    /// </summary>
    static int CountPaths(int r, int c, int targetR, int targetC, char[,] grid, bool[,] visited)
    {
        int rows = grid.GetLength(0);
        int cols = grid.GetLength(1);

        // 1. Проверка выхода за границы сетки
        if (r < 0 || r >= rows || c < 0 || c >= cols)
        {
            return 0;
        }

        // 2. Проверка препятствий (стен)
        if (grid[r, c] == '#')
        {
            return 0;
        }

        // 3. Проверка циклов (уже посещенные клетки в текущем пути)
        if (visited[r, c])
        {
            return 0;
        }

        // 4. Базовый случай: достигли целевой клетки
        if (r == targetR && c == targetC)
        {
            return 1;
        }

        // Помечаем текущую клетку как посещенную
        visited[r, c] = true;

        int pathsCount = 0;

        // Исследуем 4 направления: вниз, вправо, вверх, влево
        pathsCount += CountPaths(r + 1, c, targetR, targetC, grid, visited); // Вниз
        pathsCount += CountPaths(r, c + 1, targetR, targetC, grid, visited); // Вправо
        pathsCount += CountPaths(r - 1, c, targetR, targetC, grid, visited); // Вверх
        pathsCount += CountPaths(r, c - 1, targetR, targetC, grid, visited); // Влево

        // Шаг возврата (backtracking): снимаем отметку перед выходом из кадра рекурсии
        visited[r, c] = false;

        return pathsCount;
    }
}
```

---

#### Пояснение по строкам кода
- Строки `if (r < 0 || r >= rows || c < 0 || c >= cols)` реализуют защиту от выхода за пределы матрицы.
- Строка `if (grid[r, c] == '#')` отсекает тупики, упирающиеся в стены.
- Строка `if (visited[r, c])` предотвращает зацикливание алгоритма (чтобы путь не ходил кругами по одним и тем же клеткам).
- Строка `visited[r, c] = true;` фиксирует занятость клетки в текущей ветке.
- Четыре вызова `CountPaths` с изменением координат (`r+1`, `c+1`, `r-1`, `c-1`) порождают ветвление дерева вариантов.
- Строка `visited[r, c] = false;` — критически важный шаг возврата (backtracking), очищающий состояние для альтернативных маршрутов.

#### Оценка сложности
- **Временная сложность:** В худшем случае экспоненциальная $O(4^{N \cdot M})$, где $N$ и $M$ — размеры сетки, так как из каждой клетки теоретически возможны 4 направления перехода. Однако наличие стен и проверки `visited` существенно сокращают реальное дерево поиска.
- **Пространственная сложность:** $O(N \cdot M)$ для хранения матрицы посещений `visited` и стека вызовов, максимальная глубина которого может достигать количества всех клеток поля ($N \cdot M$).

## Типичные ошибки

1. **Забытый базовый случай.**
   * *Почему возникает:* Проектировщик сосредоточился на рекурсивном шаге, но не описал условие остановки.
   * *Как избежать:* Всегда начинайте написание рекурсивного метода с проверки базового случая. 
   * *Пример ошибки:* `static int F(int n) { return F(n - 1); }` (приведет к `StackOverflowException`).

2. **Отсутствие приближения аргумента к базовому случаю.**
   * *Почему возникает:* Аргумент в рекурсивном вызове не изменяется или удаляется от базового значения.
   * *Как избежать:* Убедитесь, что на каждом шаге параметры строго уменьшаются (или приближаются к целевому значению).
   * *Пример ошибки:* `if (n == 0) return 0; return F(n);` (значение `n` не меняется).

3. **Игнорирование возврата состояния (Backtracking Cleanup).**
   * *Почему возникает:* При изменении общих структур данных (списков, массивов посещений, символьных буферов) забывают отменить изменения при возврате из рекурсии.
   * *Как избежать:* Любое действие по модификации общего состояния перед рекурсивным вызовом должно иметь симметричную отмену сразу после него.
   * *Пример ошибки:* Добавление элемента в общий список `list.Add(x)` без последующего `list.RemoveAt(...)`.

4. **Экспоненциальное дублирование вычислений без мемоизации.**
   * *Почему возникает:* Рекурсивная функция решает одни истые подзадачи многократно (как в наивных числах Фибоначчи).
   * *Как избежать:* При наличии перекрывающихся подзадач всегда используйте кэширование результатов (словарь или массив мемоизации).

5. **Превышение глубины стека вызовов (Stack Overflow).**
   * *Почему возникает:* Линейная рекурсия с большой глубиной (например, обход массива из 100 000 элементов).
   * *Как избежать:* Для линейных структур данных большой длины используйте итеративные циклы либо алгоритмы типа «разделяй и властвуй» с логарифмической глубиной.

6. **Использование глобальных не потокобезопасных переменных для накопления результатов.**
   * *Почему возникает:* Желание упростить передачу параметров через статические поля класса.
   * *Как избежать:* Передавайте все промежуточные состояния исключительно через аргументы метода.

7. **Некорректная обработка граничных условий (отрицательные числа, пустые строки).**
   * *Почему возникают:* Отсутствие защитных проверок (`guard clauses`) в самом начале метода.
   * *Как избежать:* Всегда проверяйте входные данные на допустимость (например, `if (n < 0) throw new ArgumentException(...)`).

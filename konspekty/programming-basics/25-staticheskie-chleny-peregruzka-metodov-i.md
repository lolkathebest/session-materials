## 1. Понятие статических членов класса (static)

### Отличие статических членов от членов экземпляра

В объектно-ориентированном программировании на языке C# каждый созданный объект (экземпляр класса) обладает собственным набором данных. Например, если вы проектируете класс `Student`, у каждого конкретного студента будет свое уникальное имя, свой возраст и свой индивидуальный номер зачетной книжки. Переменные, описывающие состояние отдельного объекта, называются **членами экземпляра** (или экземплярными полями и методами). 

Однако на практике часто возникает необходимость хранить данные или выполнять действия, которые относятся ко всему классу в целом, а не к какому-то конкретному объекту. Для этого в C# используется ключевое слово `static`.

> **Определение.** **Статический член класса (static member)** — это поле, метод, свойство или событие, которое принадлежит самому классу, а не какому-либо конкретному экземпляру этого класса. 

Чтобы четко понимать разницу, обратимся к следующей таблице сравнения:

| Характеристика | Члены экземпляра (`instance`) | Статические члены (`static`) |
| :--- | :--- | :--- |
| **Принадлежность** | Конкретному объекту (экземпляру) | Шаблону класса в целом |
| **Создание в памяти** | При каждом вызове оператора `new` | Единственный раз при загрузке класса |
| **Доступ** | Через ссылку на объект (`obj.Member`) | Через имя класса (`ClassName.Member`) |
| **Ключевое слово `this`** | Доступно (ссылается на текущий объект) | **Недоступно** (контекст объекта отсутствует) |

---

### Размещение статических данных в памяти

Чтобы понять, почему статические члены ведут себя именно так, рассмотрим, как .NET распределяет память при выполнении программы. 

Когда программа запускается, среда выполнения .NET (`CLR — Common Language Runtime`) загружает скомпилированный код в память. Для каждого загруженного типа (класса) в специальной области памяти (в современных версиях .NET это часть управляемой кучи, выделенная под метаданные типа и статические поля домена приложения) создается **единственная копия** всех статических полей этого класса.

* **Экземплярные поля** существуют в количестве $N$ штук, если вы создали $N$ объектов через `new`. У каждого объекта своя порция памяти.
* **Статические поля** существуют в единственном экземпляре ($1$ штука) независимо от того, создали вы ноль объектов этого класса, один или миллион.

Если изменить значение статического поля через один объект (или напрямую через имя класса), это изменение мгновенно станет видимым для всей программы при любом последующем обращении к этому полю.

---

### Доступ к статическим членам через имя класса

Поскольку статические члены привязаны к классу, а не к объектам, для доступа к ним **не нужно создавать экземпляр класса** с помощью оператора `new`. 

Синтаксис обращения к статическому члену выглядит следующим образом:

```csharp
ИмяКласса.ИмяСтатическогоЧлена
```

Попытка обратиться к статическому полю через ссылку на созданный объект (например, `obj.StaticField`) в C# является синтаксической ошибкой (или вызывает предупреждение компилятора в зависимости от настроек), так как подчеркивает ошибочное понимание природы статических данных.

---

### Ограничения статических методов

Из-за отсутствия связи с конкретным объектом статические методы накладывают ряд строгих ограничений на то, какой код внутри них может быть написан:

1. **Отсутствие ключевого слова `this`.** Поскольку статический метод не принадлежит какому-то конкретному объекту, у него нет указателя на текущий объект (`this`). Вы не можете узнать, «на каком именно объекте» был вызван этот метод, потому что он вызывается на классе.
2. **Невозможность прямого доступа к нестатическим членам.** Статический метод не может напрямую обратиться к экземплярным полям или методам своего же класса. Чтобы нестатический метод или поле стали доступны внутри статического метода, вам необходимо явно передать ссылку на объект в качестве параметра этого статического метода.

> **Правило компилятора.** Из статического контекста нельзя напрямую ссылаться на нестатические члены (`non-static`). Обратное разрешено: нестатические методы и конструкторы имеют полный доступ к статическим полям и методам своего класса.

---

### Назначение и сценарии использования статических полей

Статические поля незаменимы в следующих сценариях:
* **Глобальные счетчики:** подсчет общего количества созданных объектов определенного класса в системе.
* **Константы и конфигурационные данные:** хранение настроек, путей к файлам, математических или физических констант (например, число Пи, скорость света), общих для всей программы.
* **Разделяемые ресурсы:** кэширование данных, пулы соединений или диспетчеры ресурсов, к которым должен быть обеспечен централизованный доступ из разных частей программы.

---

### Статические свойства: инкапсуляция статических полей

Как и обычные поля классов, статические поля рекомендуется скрывать от прямого изменения извне, применяя принципы инкапсуляции. Для этого используются **статические свойства** (static properties).

Синтаксис статического свойства аналогичен обычному свойству, но с добавлением ключевого слова `static` как в сигнатуре самого свойства, так и перед внутренними переменными (если они используются):

```csharp
class AppConfig
{
    // Закрытое статическое поле
    private static int _maxConnections = 10;

    // Публичное статическое свойство для безопасного доступа
    public static int MaxConnections
    {
        get { return _maxConnections; }
        set 
        { 
            if (value > 0) 
            {
                _maxConnections = value; 
            }
        }
    }
}
```

Обратите внимание: блоки `get` и `set` статического свойства также являются статическими и не имеют доступа к `this`.

### Разобранный пример: Класс `MathHelper`

Рассмотрим комплексный пример, демонстрирующий создание статического поля и статического метода, а также вызов этого метода без создания экземпляра класса.

#### Условие задачи
Требуется разработать вспомогательный класс `MathHelper`, содержащий:
1. Статическое поле `Pi` типа `float`, инициализированное стандартным значением числа $\pi$ ($3{,}14159f$).
2. Статический метод `CalculateCircleArea`, принимающий радиус окружности $r$ (тип `float`) и возвращающий площадь круга по формуле:
   $$S = \pi \cdot r^2$$
3. В методе `Main` продемонстрировать вызов этого статического метода и вывод результата на экран без создания объектов класса `MathHelper`.

#### Ход рассуждений
1. Так как класс `MathHelper` выполняет роль чистого набора утилит (вспомогательных функций) и не хранит состояние конкретного объекта, делать его экземплярным не имеет смысла. Все члены класса будут помечены ключом `static`.
2. Поле `Pi` должно быть доступно для чтения, объявим его как `public static readonly float Pi = 3.14159f;` (или просто `public static float Pi = MathF.PI;`).
3. Метод `CalculateCircleArea` принимает один аргумент `radius`. Площадь рассчитывается умножением статического поля `Pi` на квадрат радиуса (`radius * radius`).
4. В точке входа в программу (`Main`) мы вызываем метод напрямую через имя класса: `MathHelper.CalculateCircleArea(5.0f)`.

#### Полный исходный код программы на C#

```csharp
using System;

namespace StaticMembersDemo
{
    // Вспомогательный класс с математическими утилитами
    public static class MathHelper // Класс целиком помечен как static (статический класс)
    {
        // Статическое поле для хранения значения Пи
        public static float Pi = 3.14159f;

        // Статический метод расчета площади круга
        public static float CalculateCircleArea(float radius)
        {
            // Проверка входных данных на корректность
            if (radius < 0)
            {
                throw new ArgumentException("Радиус не может быть отрицательным.");
            }

            // Вычисление площади: S = Pi * r^2
            // Обратите внимание: метод имеет доступ к статическому полю Pi
            float area = Pi * radius * radius;
            return area;
        }
    }

    class Program
    {
        static void Main(string[] args)
        // Метод Main в C# по стандарту является статическим, 
        // так как с него начинается выполнение программы до создания любых объектов.
        {
            // Зададим радиус окружности для примера
            float radiusValue = 4.5f;

            Console.WriteLine($"Вычисление площади круга для радиуса r = {radiusValue} м:");

            // Вызов статического метода БЕЗ создания объекта (без оператора new)
            // Обращение идет через имя класса MathHelper
            float resultArea = MathHelper.CalculateCircleArea(radiusValue);

            // Вывод результата с округлением до двух знаков после запятой
            Console.WriteLine($"Результат расчета: S = {resultArea:F2} кв. м");

            // Демонстрация прямого доступа к статическому полю класса
            Console.WriteLine($"Использованное значение константы Пи: {MathHelper.Pi}");

            // Попытка изменить значение статического поля глобально
            MathHelper.Pi = 3.14f;
            Console.WriteLine($"Новое значение Пи изменено для всей программы: {MathHelper.Pi}");
        }
    }
}
```

#### Пример ввода и вывода

**Консольный вывод при запуске программы:**
```text
Вычисление площади круга для радиуса r = 4,5 м:
Результат расчета: S = 63,62 кв. м
Использованное значение константы Пи: 3,14159
Новое значение Пи изменено для всей программы: 3,14
```

#### Проверка и анализ
* **Единицы измерения:** Входной параметр `radius` задан в метрах, результат `area` возвращается в квадратных метрах (`кв. м`), что соответствует физическому смыслу площади.
* **Правдоподобность:** При радиусе $r = 4{,}5$ площадь должна составлять примерно $3{,}14159 \cdot 4{,}5^2 = 3{,}14159 \cdot 20{,}25 \approx 63{,}617$, что совпадает с вычисленным программой значением $63{,}62$.
* **Отсутствие ошибок компиляции:** Код полностью компилируется в среде .NET 8, статические поля и методы вызываются строго через имя типа `MathHelper`.

> **Ответ:** Статические члены класса принадлежат типу в целом и выделяются в памяти в единственном экземпляре. Они вызываются через имя класса (`ClassName.Member`), не имеют доступа к ключевому слову `this` и позволяют эффективно реализовывать глобальные счетчики, константы и вспомогательные математические утилиты, такие как метод `CalculateCircleArea`.

## 2. Статические методы и статический конструктор

### Назначение статических методов: утилиты и фабричные методы

В предыдущем разделе мы выяснили, что статические поля принадлежат самому классу, а не какому-то конкретному объекту. Логично, что методы, которые работают с этими статическими данными или выполняют автономные вычисления, не требующие состояния конкретного объекта, тоже объявляются с ключевым словом `static`. Такие методы называются **статическими методами** (static methods).

> **Определение.** Статический метод — это метод класса, который вызывается на уровне всего класса, не имеет доступа к экземпляру класса (`this`) и может оперировать только статическими полями и свойствами этого же класса либо переданными ему через параметры локальными данными.

Для вызова статического метода не нужно создавать экземпляр класса с помощью оператора `new`. Синтаксис вызова выглядит следующим образом:

```csharp
 ИмяКласса.ИмяСтатическогоМетода(аргументы);
```

На практике статические методы чаще всего применяются в двух основных сценариях:

1. **Вспомогательные функции (утилиты, utility methods).** Это методы, которые выполняют логические, математические или преобразовательные операции над входными данными и возвращают результат. Ярким примером из стандартной библиотеки .NET является класс `Math` и его методы `Math.Sqrt(x)`, `Math.Pow(base, exp)`. Им не нужно хранить состояние (поля объекта), они просто берут аргументы, производят расчет и возвращают ответ.
2. **Фабричные методы (factory methods).** Это методы, которые инкапсулируют сложную логику создания объектов. Вместо того чтобы заставлять вызывающий код разбираться в тонких настройках конструктора, фабричный метод создает экземпляр класса, производит предварительную настройку и возвращает готовый объект.

Рассмотрим пример проектирования класса-утилиты, который вычисляет статистические параметры массива чисел без создания объектов этого класса:

```csharp
using System;

namespace CourseApp
{
    public static class StatisticsHelper
    {
        // Статический метод для нахождения среднего арифметического
        public static double CalculateAverage(int[] numbers)
        {
            if (numbers == null || numbers.Length == 0)
            {
                return 0.0;
            }

            long sum = 0;
            foreach (int num in numbers)
            {
                sum += num;
            }

            // Приводим к типу double для получения точного деления
            return (double)sum / numbers.Length;
        }

        // Статический метод для поиска максимального элемента
        public static int FindMax(int[] numbers)
        {
            if (numbers == null || numbers.Length == 0)
            {
                throw new ArgumentException("Массив не может быть пустым или null.");
            }

            int max = numbers[0];
            for (int i = 1; i < numbers.Length; i++)
            {
                if (numbers[i] > max)
                {
                    max = numbers[i];
                }
            }
            return max;
        }
    }

    class Program
    {
        static void Main()
        {
            int[] scores = { 85, 92, 78, 95, 88 };

            // Вызываем статические методы напрямую через имя класса, без new StatisticsHelper()
            double avg = StatisticsHelper.CalculateAverage(scores);
            int maximum = StatisticsHelper.FindMax(scores);

            Console.WriteLine($"Средний балл: {avg}");
            Console.WriteLine($"Максимальный балл: {maximum}");
        }
    }
}
```

Обратите внимание: класс `StatisticsHelper` объявлен как `static class`. Это специальная модификация класса в C#, которая запрещает создание экземпляров этого класса вообще (компилятор выдаст ошибку, если вы напишете `new StatisticsHelper()`). Такие классы могут содержать исключительно статические члены.

### Статический конструктор (статический инициализатор)

Помимо обычных конструкторов, которые выполняют инициализацию конкретного создаваемого объекта (экземпляра), в C# существуют специальные конструкторы для инициализации самого класса. Они называются **статическими конструкторами** или **статическими инициализаторами**.

> **Определение.** Статический конструктор — это специальный член класса, предназначенный для инициализации любых статических данных или выполнения определенного кода, который должен быть выполнен ровно один раз перед тем, как с классом произойдет любое взаимодействие.

Синтаксис объявления статического конструктора строго регламентирован:

```csharp
class ИмяКласса
{
    // Статический конструктор
    static ИмяКласса()
    {
        // Код инициализации статических полей
    }
}
```

#### Ключевые особенности статического конструктора:

1. **Автоматический вызов:** программист не может вызвать статический конструктор вручную из кода. Среда выполнения .NET сама вызывает его в точно определенный момент — перед созданием первого экземпляра этого класса или перед первым обращением к любому статическому члену этого класса (полю, методу или свойству).
2. **Гарантия однократного выполнения:** статический конструктор гарантированно выполняется ровно один раз за все время работы программы, даже если вы создадите миллион объектов этого класса или вызовете статические методы сотни раз.
3. **Отсутствие параметров:** статический конструктор никогда не принимает аргументов. Перегрузить его (создать второй статический конструктор с параметрами) невозможно.
4. **Отсутствие модификаторов доступа:** у статического конструктора нельзя указывать `public`, `private` или `protected`. Он всегда неявно является `private`, так как вызывается исключительно инфраструктурой среды выполнения, а не кодом разработчика.

---

### Инициализация сложных статических данных и конфигураций

Зачем нужен статический конструктор на практике? Обычные статические поля можно инициализировать прямо при их объявлении (например, `public static int MaxConnections = 100;`). Однако если для инициализации статического поля требуется выполнить сложную логику: написать цикл, обработать исключения, прочитать файл конфигурации, подключиться к реестру или внешнему ресурсу — простого присваивания недостаточно. Здесь на помощь приходит статический конструктор.

Рассмотрим классический пример: в программе есть класс для работы с базой данных. Перед тем как этот класс начнет функционировать, необходимо один раз прочитать конфигурационный файл (или смоделировать это чтение), расшифровать строку подключения и настроить глобальные параметры соединения.

```csharp
using System;

namespace CourseApp
{
    public class DatabaseConnection
    {
        // Статические поля для хранения глобальной конфигурации
        private static string _connectionString;
        private static bool _isInitialized;

        // Статический конструктор
        static DatabaseConnection()
        {
            Console.WriteLine("[Система] Вызван статический конструктор DatabaseConnection.");
            
            try
            {
                // Имитируем чтение конфигурации из внешнего источника
                // В реальной программе здесь может быть чтение JSON, XML или реестра
                string serverName = "127.0.0.1";
                string dbName = "EnterpriseDB";
                int timeoutSeconds = 30;

                _connectionString = $"Server={serverName};Database={dbName};Timeout={timeoutSeconds};";
                _isInitialized = true;
                
                Console.WriteLine("[Система] Конфигурация базы данных успешно загружена.");
            }
            catch (Exception ex)
            {
                _isInitialized = false;
                Console.WriteLine($"[Ошибка] Не удалось инициализировать подключение: {ex.Message}");
            }
        }

        // Статический метод для проверки статуса и получения строки подключения
        public static void ExecuteQuery(string query)
        {
            if (!_isInitialized)
            {
                Console.WriteLine("Ошибка: База данных не инициализирована.");
                return;
            }

            Console.WriteLine($"Выполнение запроса: \"{query}\"");
            Console.WriteLine($"Используемая строка подключения: {_connectionString}");
        }
    }

    class Program
    {
        static void Main()
        {
            Console.WriteLine("Главный метод программы запущен.");
            Console.WriteLine("Обращаемся к классу DatabaseConnection впервые...");

            // Первое обращение к статическому члену вызовет статический конструктор
            DatabaseConnection.ExecuteQuery("SELECT * FROM Users");

            Console.WriteLine("----------------------------------------");
            Console.WriteLine("Повторное обращение к классу:");

            // Второе обращение. Статический конструктор НЕ вызывается повторно!
            DatabaseConnection.ExecuteQuery("SELECT * FROM Orders");
        }
    }
}
```

#### Порядок выполнения и вывод программы:

Если скомпилировать и запустить данный код, на экране появится следующий результат:

```text
Главный метод программы запущен.
Обращаемся к классу DatabaseConnection впервые...
[Система] Вызван статический конструктор DatabaseConnection.
[Система] Конфигурация базы данных успешно загружена.
Выполнение запроса: "SELECT * FROM Users"
Используемая строка подключения: Server=127.0.0.1;Database=EnterpriseDB;Timeout=30;
----------------------------------------
Повторное обращение к классу:
Выполнение запроса: "SELECT * FROM Orders"
Используемая строка подключения: Server=127.0.0.1;Database=EnterpriseDB;Timeout=30;
```

**Анализ хода выполнения:**
1. Выполнение программы начинается с метода `Main`. На экран выводится первая строка.
2. В строке `DatabaseConnection.ExecuteQuery(...)` код впервые обращается к статическому методу класса `DatabaseConnection`.
3. Среда выполнения .NET проверяет, был ли уже выполнен статический конструктор этого класса. Поскольку это первое обращение, .NET приостанавливает выполнение метода `Main` и автоматически вызывает статический конструктор `static DatabaseConnection()`.
4. Внутри статического конструктора формируется строка подключения и выводятся системные сообщения.
5. После завершения статического конструктора управление возвращается в метод `Main`, и выполняется сам метод `ExecuteQuery`.
6. При повторном вызове `DatabaseConnection.ExecuteQuery` статический конструктор пропускается, так как инициализация уже была проведена ранее.

---

### Порядок инициализации статических полей и вызова статического конструктора

Чтобы полностью контролировать поведение сложных программ, важно четко понимать последовательность, в которой .NET выделяет память и выполняет код при первом обращении к классу. Правила порядка инициализации следующие:

1. Когда происходит первое обращение к классу (создание экземпляра через `new` или вызов любого статического члена), среда выполнения выделяет память под все статические поля этого класса в специальной области памяти (в куче домена приложений).
2. На этом этапе статические поля получают свои значения по умолчанию (числа — в `0`, ссылки — в `null`, логические переменные — в `false`).
3. Затем выполняются инициализаторы статических полей в том порядке, в котором они написаны в коде класса (например, `private static int Counter = 5;`).
4. После заверщения инициализации полей вызывается статический конструктор класса (если он определен разработчиком).
5. Только после полного завершения работы статического конструктора класс считается готовым к использованию, и выполняется запрошенный пользователем метод или создается экземпляр объекта.

Если в проекте присутствует иерархия классов (наследование), порядок статической инициализации распространяется сверху вниз: сначала выполняются статические поля и статический конструктор базового класса, а затем — производного класса.

## 3. Перегрузка методов (Method Overloading)

### Понятие перегрузки методов

В процессе разработки программ часто возникает ситуация, когда одно и то же логическое действие нужно выполнить над данными разных типов. Например, вывод информации на экран может потребоваться как для целого числа (`int`), так и для строки (`string`) или числа с плавающей точкой (`double`). 

В языках программирования без поддержки перегрузки (например, в чистом Си) разработчику приходилось создавать отдельные имена для каждой функции: `PrintInt`, `PrintString`, `PrintDouble`. Это приводит к загромождению кода и необходимости запоминать множество названий функций, выполняющих по сути одну и ту же задачу.

Язык C# предлагает механизм, который избавляет от этой проблемы.

> **Определение.** Перегрузка методов (Method Overloading) — это механизм полиморфизма во время компиляции, который позволяет создавать в пределах одного класса два или более методов с одинаковым именем, но с разными наборами параметров.

Простыми словами, перегрузка — это способность метода «менять поведение» в зависимости от того, какие аргументы вы ему передаете. Вы вызываете метод с привычным именем (например, `Calculate`), а компилятор сам решает, какой именно кусок кода запустить, основываясь на переданных данных.

Пример из реальной жизни: у вас есть универсальный пульт управления. Кнопка «Ввод» работает по-разному в зависимости от того, находитесь ли вы в меню телевизора, в браузере или в настройках звука. Название команды одно, но контекст различается.


### Сигнатура метода в C#

Чтобы компилятор мог отличить один метод от другого при перегрузке, он использует понятие сигнатуры.

> **Определение.** Сигнатура метода (Method Signature) — это уникальный набор характеристик метода, состоящий из его имени и последовательности типов его параметров (включая их порядок).

Важно четко понимать, что именно входит в сигнатуру, а что — нет. Это один из самых частых вопросов на экзаменах и собеседованиях.

В сигнатуру **входят**:
1. Имя метода.
2. Количество параметров.
3. Типы параметров.
4. Порядок следования типов параметров (если типов несколько).

В сигнатуру **не входят**:
1. Возвращаемый тип метода (`int`, `void`, `string` и т. д.).
2. Имена параметров (компилятору всё равно, назван параметр `a` или `x`).
3. Модификаторы параметров `ref` и `out` (нельзя перегрузить метод только за счет добавления `ref` к существующему параметру по значению, хотя есть нюансы с `out`, но базовая сигнатура от этого не меняется).

Рассмотрим примеры корректных и некорректных сигнатур:

```csharp
class Example
{
    // Базовый метод
    public void Process(int x, double y) { }

    // РАЗРЕШЕНО: изменен тип второго параметра (double заменен на int)
    public void Process(int x, int y) { }

    // РАЗРЕШЕНО: изменен порядок параметров
    public void Process(double y, int x) { }

    // РАЗРЕШЕНО: изменено количество параметров
    public void Process(int x) { }

    // ЗАПРЕЩЕНО! Изменен только возвращаемый тип (с void на int).
    // Компилятор выдаст ошибку "Type 'Example' already defines a member called 'Process' with the same parameter types"
    // public int Process(int x) { return x; }

    // ЗАПРЕЩЕНО! Изменены только имена параметров (с a, b на x, y).
    // public void Process(int a, int b) { }
}
```


### Правила компилятора и разрешающая способность

Когда вы пишете в коде вызов перегруженного метода, например `Print(5)`, компилятор должен выбрать ровно одну конкретную реализацию. Этот процесс называется **разрешением перегрузки (Overload Resolution)**.

Компилятор анализирует все методы с именем `Print` в данном классе и оценивает их по степени соответствия переданным аргументам. Возможны три исхода:
1. **Идеальное совпадение (Exact Match):** найден метод, типы параметров которого точно соответствуют типам переданных аргументов. Он выбирается немедленно.
2. **Неявное приведение типов (Implicit Conversion):** если точного совпадения нет, компилятор ищет метод, для вызова которого требуются безопасные неявные преобразования (например, передача `int` в метод, принимающий `double`).
3. **Ошибка компиляции:** 
   - Если подходящих методов не найдено вообще (нет метода с таким именем или типы аргументов невозможно привести ни к одной сигнатуре).
   - Если найдено *несколько* подходящих методов, но ни один из них не является более специфичным (возникает неоднозначность — амбививалентность).

Пример амбививалентности (ошибка компилятора):
```csharp
class AmbiguityExample
{
    public void Test(int x, double y) { }
    public void Test(double x, int y) { }

    public void Run()
    {
        // Ошибка! Вызов Test(5, 5);
        // Число 5 может быть неявно преобразовано как во второй параметр первого метода (int -> double),
        // так и в первый параметр второго метода (int -> double). 
        // Компилятор не может сделать выбор и останавливает сборку.
    }
}
```


### Преимущества перегрузки

Использование перегрузки дает следующие архитектурные плюсы:
1. **Единообразие интерфейса:** пользователю вашего класса не нужно заучивать десятки разных названий (например, `SaveInt`, `SaveString`, `SaveBool`). Достаточно использовать один интуитивный метод `Save`.
2. **Читаемость кода:** код становится чище, проще для восприятия и поддержики.
3. **Снижение когнитивной нагрузки:** разработчик думает о *сути* действия (что мы делаем?), а не о технической детали (с каким типом данных работаем?).


### Разбор полного примера: класс `PrintService`

Реализуем консольное приложение, содержащее класс `PrintService` с перегруженными статическими методами `ShowData`.

#### Условие задачи
Разработать статический класс `PrintService`, который содержит три перегруженных статических метода с именем `ShowData`:
1. Первый метод принимает целое число (`int`) и выводит его как ID пользователя.
2. Второй метод принимает число с плавающей точкой (`double`) и выводит его как баланс счета с точностью до двух знаков после запятой.
3. Третий метод принимает строку (`string`) и выводит её как имя пользователя, взятое в кавычки.

Также написать метод `Main`, в котором продемонстрировать вызов всех трех перегруженных методов, а также проверить работу компилятора при неявном приведении типов (например, передача `int` в метод для `double`).

#### Рисунок схемы работы (текстовая схема)

```
[ Вызов метода в Main() ]
       │
       ├─► PrintService.ShowData(42)       ──► Совпадение с (int)    ──► Вывод ID
       │
       ├─► PrintService.ShowData(150.75)   ──► Совпадение с (double) ──► Вывод баланса
       │
       ├─► PrintService.ShowData("Анна")   ──► Совпадение с (string) ──► Вывод имени
       │
       └─► PrintService.ShowData(100)      ──► Совпадение с (int), но если оставить 
               (при передаче в double)        только double, сработает неявное приведение int -> double
```

#### Ход рассуждений (почему делаем именно так)
1. Поскольку методы не должны зависеть от конкретного экземпляра класса `PrintService` (внутри нет сохранения полей состояния объекта), объявим класс и все его методы с модификатором `static`, изученным на предыдущих занятиях. Это позволит вызывать их напрямую через имя класса: `PrintService.ShowData(...)`.
2. Имя всех трех методов должно быть абсолютно одинаковым — `ShowData`.
3. Сигнатуры должны различаться типами принимаемых параметров: `int`, `double`, `string`.
4. Возвращаемый тип для всех методов сделаем `void`, так как они выполняют вывод информации в консоль и не возвращают вычислительный результат обратно в вызывающий код.

#### Программный код

```csharp
using System;

namespace OverloadLesson
{
    // Статический класс для предоставления сервиса печати
    public static class PrintService
    {
        // Перегрузка 1: принимает целое число (int)
        public static void ShowData(int userId)
        {
            Console.WriteLine($"[INT OVERLOAD] Идентификатор пользователя (ID): {userId}");
        }

        // Перегрузка 2: принимает число с плавающей точкой (double)
        public static void ShowData(double accountBalance)
        {
            // Используем форматирование F2 для вывода двух знаков после запятой
            Console.WriteLine($"[DOUBLE OVERLOAD] Баланс счета: {accountBalance:F2} руб.");
        }

        // Перегрузка 3: принимает строку (string)
        public static void ShowData(string userName)
        {
            Console.WriteLine($"[STRING OVERLOAD] Имя пользователя: \"{userName}\"");
        }
    }

    class Program
    {
        static void Main(string[] args)
        {
            // Настройка кодировки для корректного отображения кириллицы
            Console.OutputEncoding = System.Text.Encoding.UTF8;

            Console.WriteLine("Запуск демонстрации перегрузки методов:\n");

            // 1. Вызов метода с целым числом. Компилятор ищет ShowData(int).
            int id = 1024;
            PrintService.ShowData(id);

            // 2. Вызов метода с числом двойной точности. Компилятор ищет ShowData(double).
            double balance = 5432.578;
            PrintService.ShowData(balance);

            // 3. Вызов метода со строкой. Компилятор ищет ShowData(string).
            string name = "Александр";
            PrintService.ShowData(name);

            // 4. Демонстрация работы неявного приведения типов (Overload Resolution)
            Console.WriteLine("\n--- Проверка неявного приведения ---");
            
            // Передаем литерал целого типа в метод, который ожидает double.
            // В C# целое число может быть неявно расширено до double.
            // Компилятор автоматически выберет перегрузку для double, если нет точной перегрузки для int 
            // (но в нашем классе есть и int, поэтому вызовется int-версия).
            byte smallNumber = 10;
            PrintService.ShowData(smallNumber); // Вызовет версию для int (через неявное расширение byte -> int)

            Console.WriteLine("\nРабота программы завершена.");
        }
    }
}
```

#### Пояснение по строкам кода
- `public static class PrintService`: объявление статического класса. Экземпляры этого класса создать нельзя (`new PrintService()` вызовет ошибку компиляции), что логично для класса-утилиты.
- `public static void ShowData(int userId)` и др.: три метода с одинаковым именем `ShowData`, но разными типами параметров формируют классическую перегрузку.
- `accountBalance:F2`: форматтер строки, округляющий число типа `double` ровно до двух знаков после запятой.
- `PrintService.ShowData(smallNumber)`: демонстрирует интеллектуальный выбор компилятора. Переменная типа `byte` не имеет точной перегрузки, но компилятор находит безопасный путь расширения типа до `int` и успешно вызывает первый метод.

#### Пример ввода и вывода

**Входные данные (внутри кода):**
- `id = 1024`
- `balance = 5432.578`
- `name = "Александр"`
- `smallNumber = 10` (тип `byte`)

**Вывод в консоли:**
```text
Запуск демонстрации перегрузки методов:

[INT OVERLOAD] Идентификатор пользователя (ID): 1024
[DOUBLE OVERLOAD] Баланс счета: 5432,58 руб.
[STRING OVERLOAD] Имя пользователя: "Александр"

--- Проверка неявного приведения ---
[INT OVERLOAD] Идентификатор пользователя (ID): 10

Работа программы завершена.
```

#### Проверка и оценка сложности
- **Оценка времени выполнения (Time Complexity):** $O(1)$ для вызова каждого метода, так как выбор перегрузки происходит на этапе компиляции (статическое связывание), а сам вызов метода выполняется мгновенно.
- **Оценка затрат памяти (Space Complexity):** $O(1)$, дополнительные структуры данных в куче не создаются, используются локальные стековые кадры метода.
- **Правдоподобность:** значения выводятся корректно, округление для `double` сработало правильно (`5432,578` округлилось до `5432,58`), типы данных соответствуют ожиданиям.

Ответ: механизм перегрузки методов полностью реализован и проверен.

## 4. Перегрузка конструкторов и делегирование конструкторов (this)

### Необходимость перегрузки конструкторов

При проектировании классов часто возникает ситуация, когда объект может быть создан в различных состояниях в зависимости от имеющихся у разработчика исходных данных. Конструктор — это специальный метод класса, который вызывается автоматически в момент создания экземпляра класса (с помощью оператора `new`) и отвечает за инициализацию его полей. 

> **Определение.** Перегрузка конструкторов (Constructor Overloading) — это механизм создания в одном классе нескольких конструкторов, имеющих одинаковое имя (совпадающее с именем класса), но отличающихся сигнатурой, то есть количеством, типами или порядком следования параметров.

Рассмотрим практическую необходимость этого механизма. Допустим, мы разрабатываем программное обеспечение для работы с геометрическими фигурами и проектируем класс `Rectangle` (прямоугольник). Прямоугольник полностью определяется двумя параметрами: шириной (`width`) и высотой (`height`). Однако в клиентском коде (в коде, который использует наш класс) могут возникать разные сценарии:
1. Пользователь создает фигуру по умолчанию, не указывая размеры (например, создается единичный квадрат 1 на 1 метр).
2. Пользователь создает квадрат, задавая только одну сторону.
3. Пользователь задает и ширину, и высоту раздельно, если это произвольный прямоугольник.

Если бы в C# не было перегрузки конструкторов, нам пришлось бы создавать разные классы или писать сложные методы инициализации после создания объекта, что приводит к состоянию объекта, когда он создан, но еще не проинициализирован корректно. Перегрузка конструкторов позволяет жестко гарантировать, что любой объект класса `Rectangle` с момента своего рождения находится в валидном (допустимом) и полностью готовом к работе состоянии.

### Синтаксис делегирования конструкторов и принцип DRY

Когда мы пишем несколько перегруженных конструкторов, возникает соблазн скопировать логику проверки параметров (например, проверку на то, что ширина и высота больше нуля) во все конструкторы. Это противоречит фундаментальному принципу проектирования программного обеспечения **DRY** (Don't Repeat Yourself — «не повторяйся»). Дублирование кода приводит к тому, что при изменении логики валидации или инициализации придется вносить правки во все конструкторы, что неизбежно приведет к ошибкам и багам.

В языке C# эта проблема решается с помощью механизма **делегирования конструкторов** (constructor chaining). Один конструктор может вызвать другой конструктор того же класса до выполнения собственного тела, используя ключевое слово `this` с двоеточием перед телом конструктора.

Рассмотрим синтаксис на общем примере:

```csharp
class Example
{
    private int field1;
    private int field2;

    // Основной (целевой) конструктор с полным набором параметров
    public Example(int f1, int f2)
    {
        field1 = f1;
        field2 = f2;
    }

    // Конструктор с одним параметром делегирует вызов основному конструктору
    public Example(int f1) : this(f1, 0) // передаем f1 и дефолтное значение 0
    {
        // Здесь можно разместить дополнительную логику для этого случая,
        // но чаще тело конструктора остается пустым
    }

    // Конструктор без параметров делегирует вызов конструктору с одним параметром
    public Example() : this(1) // передаем дефолтное значение 1 в конструктор выше
    {
    }
}
```

Порядок выполнения при вызове конструктора по умолчанию `new Example()`:
1. Вызывается конструктор без параметров.
2. Он перенаправляет управление конструктору с одним параметром `this(1)`.
3. Конструктор с одним параметром перенаправляет управление основному конструктору `this(1, 0)`.
4. Основной конструктор выполняет присваивание полей.
5. Управление возвращается обратно по цепочке снизу вверх, и объект считается созданным.

### Совмещение конструкторов: по умолчанию, с частичным и полным набором параметров

При проектировании надежного класса принято выстраивать иерархию конструкторов от частного к общему (или наоборот). «Главным» обычно делают конструктор с наибольшим числом параметров (полный набор), так как именно в нем сосредоточена вся логика проверки входных данных (граничные условия, выброс исключений при некорректных значениях). Конструкторы с частичным набором параметров и конструкторы без параметров выступают в роли удобных «фасадов», подставляющих значения по умолчанию.

Важно помнить правило компилятора C#: если вы не написали в классе ни одного конструктора вообще, компилятор автоматически создает публичный конструктор без параметров (конструктор по умолчанию), который просто устанавливает все поля в их стандартные нулевые значения (`0`, `false`, `null`). Но как только вы явно определяете в классе хотябы один конструктор с параметрами, неявный конструктор по умолчанию **исчезает**. Если вам по-прежнему нужен способ создания объекта без параметров, вы обязаны написать его вручную.

### Взаимодействие статических и экземплярных конструкторов при создании объекта

В предыдущих разделах мы рассматривали статические члены класса и статические конструкторы. Важно четко понимать порядок инициализации данных в памяти при первом создании экземпляра класса, когда в работу включаются и статические, и экземплярные механизмы.

Когда виртуальная машина .NET собирается создать первый объект класса или впервые обратиться к любому статическому члену этого класса, происходит строго детерминированная последовательность шагов:

1. **Инициализация статических полей** на уровне класса в порядке их объявления в коде.
2. **Выполнение статического конструктора** (`static ClassName()`). Он выполняется ровно один раз за все время работы программы.
3. При вызове оператора `new` выделяется память в куче под поля конкретного **экземпляра** класса.
4. Выполняется инициализация экземплярных полей значениями по умолчанию или явными инициализаторами в теле класса.
5. Выполняется цепочка **экземплярных конструкторов** (начиная с перенаправленных через `this(...)` и завершая телом вызываемого конструктора).

### Разобранный пример: класс `Rectangle`

Решим практическую задачу: создадим класс `Rectangle` с полями `width` (ширина) и `height` (высота), реализуем три перегруженных конструктора, используя цепочку `this(...)`, а также добавим метод расчета площади и вывод информации на консоль для проверки.

#### Условие задачи
Разработать класс `Rectangle` на языке C#. Класс должен содержать:
- Два закрытых поля типа `double`: `width` (ширина) и `height` (высота).
- Три перегруженных конструктора:
  1. Конструктор без параметров — создает квадрат размером $1{,}0 \times 1{,}0$ м.
  2. Конструктор с одним параметром (`double side`) — создает квадрат размером $\text{side} \times \text{side}$ м.
  3. Конструктор с двумя параметрами (`double width`, `double height`) — основной конструктор, устанавливающий переданные значения, с проверкой на положительные величины (если передано неположительное число, выбрасывается исключение `ArgumentOutOfRangeException`).
- Метод `GetArea()`, возвращающий площадь прямоугольника в квадратных метрах.
- Метод `PrintInfo()`, выводящий параметры и площадь фигуры в консоль.
Написать полную программу с методом `Main`, демонстрирующую создание объектов с использованием всех трех конструкторов.

#### Рисунок схемы вызовов конструкторов (в виде ASCII-блок-схемы)

```text
[ Вызов new Rectangle() ] 
       │
       ▼
 Rectangle()  ──( делегирует )──►  Rectangle(1.0)
                                        │
                                   ( делегирует )
                                        ▼
                                 Rectangle(width, height) ◄── [ Основной конструктор ]
                                        │
                                    ( Проверка )
                                        │
                         ┌──────────────┴──────────────┐
                         ▼                             ▼
                 [ Значения > 0 ]              [ Значения <= 0 ]
                         │                             │
                 ( Присваивание )              ( Выброс исключения )
```

#### Ход рассуждений
1. Объявляем класс `Rectangle` и приватные поля `private double width;` и `private double height;`.
2. Проектируем основной конструктор `public Rectangle(double width, double height)`. В нем выполняем валидацию: если `width <= 0` или `height <= 0`, генерируем исключение `new ArgumentOutOfRangeException(...)`. Это гарантирует безопасность всего класса.
3. Проектируем конструктор с одним параметром `public Rectangle(double side) : this(side, side)`. Так как квадрат — это частный случай прямоугольника с равными сторонами, мы передаем параметр `side` дважды в основной конструктор.
4. Проектируем конструктор без параметров `public Rectangle() : this(1.0)`. Он передает единицу в конструктор с одним параметром, который, в свою очередь, передает ее в основной конструктор. Получаем единичный квадрат.
5. Пишем метод расчета площади: $S = \text{width} \times \text{height}$. Возвращаемый тип — `double`.

#### Полный компилируемый код программы

```csharp
using System;

namespace RectangleApp
{
    // Описание класса Прямоугольник
    class Rectangle
    {
        private double width;
        private double height;

        // 1. Основной конструктор (с полным набором параметров)
        public Rectangle(double width, double height)
        {
            // Проверка входных данных согласно требованиям надежности
            if (width <= 0)
            {
                throw new ArgumentOutOfRangeException(nameof(width), "Ширина должна быть больше нуля.");
            }
            if (height <= 0)
            {
                throw new ArgumentOutOfRangeException(nameof(height), "Высота должна быть больше нуля.");
            }

            this.width = width;
            this.height = height;
        }

        // 2. Конструктор с одним параметром (для квадрата)
        // Делегирует вызов основному конструктору через this
        public Rectangle(double side) : this(side, side)
        {
            // Тело пустое, вся логика инициализации выполняется в основном конструкторе
        }

        // 3. Конструктор без параметров (по умолчанию — единичный квадрат 1х1)
        // Делегирует вызов конструктору с одним параметром
        public Rectangle() : this(1.0)
        {
            // Тело пустое
        }

        // Метод для расчета площади прямоугольника
        public double GetArea()
        {
            return width * height;
        }

        // Метод для вывода информации об объекте
        public void PrintInfo()
        {
            Console.WriteLine($"Прямоугольник: ширина = {width:F1} м, высота = {height:F1} м, площадь = {GetArea():F2} кв. м");
        }
    }

    class Program
    {
        static void Main(string[] args)
        {
            // Демонстрация работы конструктора без параметров
            Rectangle rect1 = new Rectangle();
            Console.Write("Объект 1: ");
            rect1.PrintInfo();

            // Демонстрация работы конструктора с одним параметром (квадрат)
            Rectangle rect2 = new Rectangle(5.0);
            Console.Write("Объект 2: ");
            rect2.PrintInfo();

            // Демонстрация работы основного конструктора с двумя параметрами
            Rectangle rect3 = new Rectangle(3.0, 7.5);
            Console.Write("Объект 3: ");
            rect3.PrintInfo();

            // Демонстрация работы проверки ошибок (граничный случай)
            try
            {
                Console.WriteLine("Попытка создания некорректного прямоугольника (-2.0, 4.0)...");
                Rectangle rectInvalid = new Rectangle(-2.0, 4.0);
            }
            catch (ArgumentOutOfRangeException ex)
            {
                Console.WriteLine($"Перехвачено ожидаемое исключение: {ex.ParamName} - {ex.Message}");
            }
        }
    }
}
```

#### Пример консольного ввода и вывода

При запуске программы в консоль будет выведено следующее:

```text

Объект 2: Прямоугольник: ширина = 5,0 м, высота = 5,0 м, площадь = 25,00 кв. м
Объект 3: Прямоугольник: ширина = 3,0 м, высота = 7,5 м, площадь = 22,50 кв. м
```

#### Проверка и оценка сложности
- **Проверка единиц измерения:** Входные параметры задаются в метрах (`double`), площадь рассчитывается умножением метров на метры, результат выражается в квадратных метрах (`кв. м`), что физически и математически верно. Формулы перепроверены: $1{,}0 \times 1{,}0 = 1{,}0$; $5{,}0 \times 5{,}0 = 25{,}0$; $3{,}0 \times 7{,}5 = 22{,}5$. Числа подобраны так, чтобы избежать бесконечных десятичных дробей.
- **Оценка сложности:** 
  - Время выполнения (Time Complexity) создания объекта через конструктор: $O(1)$, так как выполняется фиксированное число операций присваивания и проверки условий.
  - Пространственная сложность (Space Complexity): $O(1)$ для каждого созданного экземпляра класса (выделение памяти под два поля типа `double` размером по 8 байт каждое).

## 5. Комплексное применение: класс с статическими членами и перегрузкой

### Проектирование классов, объединяющих статические и экземплярные члены

При разработке реальных программных систем на языке C# крайне редко удается обойтись исключительно статическими классами или только классами, состоящими из одних лишь экземплярных (нестатических) членов. Большинство полезных архитектурных решений основано на синергии обоих подходов. 

Экземплярные члены класса описывают состояние и поведение **отдельного конкретного объекта**. Например, у каждого банковского счета есть свой собственный баланс, свой уникальный номер и свой владелец. Изменение баланса одного счета никак не должно влиять на баланс другого.

Статические члены класса, напротив, описывают **состояние и поведение, общее для всех объектов данного типа**, или предоставляют вспомогательный сервис, не зависящий от конкретного экземпляра. В контексте банковской системы это может быть общая процентная ставка по вкладам для всех счетов определенного типа, счетчик общего количества открытых вкладов в банке или глобальный механизм генерации уникальных идентификаторов.

> **Определение.** Архитектурный гибридный класс — это тип данных, содержащий как экземплярные поля и методы для работы с индивидуальным состоянием объектов, так и статические поля и методы для управления общими ресурсами, конфигурацией или общая статистика класса.

Рассмотрим ключевые правила проектирования такого класса:
1. **Разделение ответственности:** Статические поля не должны хранить индивидуальные данные конкретных объектов (например, имя владельца счета не может быть статическим, иначе оно будет перезаписываться при создании каждого нового счета).
2. **Контекст выполнения:** Экземплярные методы имеют полный доступ как к экземплярным полям (`this`), так и к статическим полям класса. Статические методы имеют доступ **только** к статическим членам и не могут обращаться к нестатическим полям или методам, так как во время выполнения статического метода в памяти может не существовать ни одного экземпляра класса.

---

### Учет объектов и генерация уникальных ID с использованием статических полей

Одной из классических задач при проектировании классов является автоматическое присвоение уникального идентификатора (`ID`) каждому создаваемому экземпляру, а также отслеживание общего количества созданных объектов. 

Для реализации этой задачи применяются **статические поля**. Поскольку такое поле существует в единственном экземпляре на весь класс (в памяти домена приложений), оно идеально подходит для хранения текущего счетчика.

Рассмотрим схему работы статического счетчика:

```
[ Класс BankAccount ]
  ├── Статическое поле: _nextId = 1001  (хранит следующее свободное значение)
  ├── Статическое поле: _totalAccounts = 0 (хранит количество созданных объектов)
  │
  ├── Экземплярное поле: id = 1001      (получает значение из _nextId, затем _nextId увеличивается)
  └── Экземплярное поле: balance = 5000.0 (индивидуальный баланс)
```

Каждый раз, когда вызывается конструктор класса для создания нового объекта, в теле конструктора происходит обращение к статическому полю, присвоение значения экземплярному полю и инкремент (увеличение на единицу) статического счетчика.

---

### Перегрузка статических и экземплярных методов

В рамках одного класса можно одновременно перегружать как экземплярные, так и статические методы. Главное правило компилятора C# остается неизменным: сигнатура метода должна быть уникальной. Сигнатура включает в себя имя метода, а также количество, типы и порядок следования его параметров (но не возвращаемый тип и не модификаторы вроде `ref` или `out`).

* **Перегрузка экземплярных методов** используется тогда, когда операция над объектом может выполняться по-разному в зависимости от переданных аргументов (например, пополнение счета наличными, переводом с карты или в иностранной валюте с автоматической конвертацией).
* **Перегрузка статических методов** применяется для создания универсальных утилит или фабричных методов (например, создание объекта счета из строки текстового файла или из JSON-объекта различными способами).

### Анализ типичных ошибок компиляции и логических сбоев

При совмещении статического и динамического контекста начинающие разработчики часто совершают типичные ошибки:

1. **Попытка обращения к ключевому слову `this` из статического метода.**
   * *Причина ошибки:* Ключевое слово `this` указывает на текущий экземпляр класса. Статический метод вызывается для класса в целом, а не для конкретного объекта, поэтому экземпляра просто не существует. Компилятор выдаст ошибку: `CS0120: An object reference is required for the non-static field, method, or property`.
2. **Обращение к нестатическому полю из статического контекста.**
   * *Причина ошибки:* Аналогична предыдущей. Статический метод не знает, поле какого именно объекта вы хотите прочитать или изменить.
3. **Конфликт сигнатур при перегрузке.**
   * *Причина ошибки:* Попытка создать два метода с одинаковым именем и одинаковыми типами параметров, отличающихся только возвращаемым значением (`int M(double x)` и `double M(double x)`). Компилятор не сможет определить, какой именно метод вызывать, и выдаст ошибку неоднозначности.

### Проблемы многопоточности и гонки данных (Race Conditions)

Если ваше приложение использует многопоточность (что является стандартным для современного .NET), статические поля становятся общей разделяемой памятью (shared mutable state) для всех потоков одновременно.

Представьте ситуацию: два потока одновременно создают два экземпляра класса `BankAccount`. 
1. Поток А читает значение статического счетчика `_nextId` (например, `1005`).
2. Поток Б прерывает поток А и также читает значение `_nextId` (все еще `1005`).
3. Поток А увеличивает счетчик и записывает ID `1005` первому объекту.
4. Поток Б увеличивает счетчик и записывает ID `1005` второму объекту.

В результате мы получаем два объекта с одинаковым идентификатором (`ID`), что нарушает целостность данных. Это явление называется **состоянием гонки (Race Condition)**. 

Для предотвращения подобных ошибок в C# используются механизмы синхронизации потоков, такие как ключевое слово `lock`, класс `Interlocked` или потокобезопасные коллекции. Для нашего простого счетчика идеальным решением является использование атомарных операций:

```csharp
// Безопасное увеличение счетчика в многопоточной среде
int currentId = Interlocked.Increment(ref _nextId);
```

### Разобранный пример: Разработка класса `BankAccount`

Напишем полноценную консольную программу на C#, демонстрирующую совместное использование статических и экземплярных членов, перегрузку конструкторов и методов, а также инкапсуляцию.

#### Постановка задачи
Требуется спроектировать класс `BankAccount`, который содержит:
- Статическое поле для хранения общего количества созданных счетов.
- Статическое поле для хранения базовой процентной ставки по вкладам (с возможностью ее изменения через статический метод).
- Статическое поле для генерации уникальных идентификаторов счета (начиная с `202401`).
- Экземплярные поля для хранения уникального номера счета (`id`), имени владельца (`ownerName`), текущего баланса (`balance`) и валюты счета (`currency`).
- Два перегруженных конструктора: один для открытия счета с нулевым балансом (принимает имя владельца), второй — с указанием начального баланса.
- Цепочку конструкторов через ключевое слово `this(...)` для устранения дублирования кода.
- Перегруженные экземплярные методы `Deposit` для пополнения счета:
  1. Пополнение на указанную сумму в рублях (`decimal amount`).
  2. Пополнение в иностранной валюте с конвертацией (принимает сумму и код валюты `string currencyCode`, а также текущий курс обмена).
- Статический метод `DisplayBankStatistics`, выводящий общую информацию по банку.

#### Полный исходный код программы

```csharp
using System;
using System.Threading;

namespace BankSystemApp
{
    // Главный класс программы для демонстрации работы BankAccount
    class Program
    {
        static void Main(string[] args)
        {
            // Устанавливаем кодировку консоли для корректного отображения символа рубля и кириллицы
            Console.OutputEncoding = System.Text.Encoding.UTF8;

            Console.WriteLine("=== ИНИЦИАЛИЗАЦИЯ БАНКОВСКОЙ СИСТЕМЫ ===");
            
            // Вывод начальной статистики через статический метод
            BankAccount.DisplayBankStatistics();
            
            // Изменение базовой процентной ставки с помощью статического метода
            BankAccount.SetBaseInterestRate(7.5m);
            
            Console.WriteLine();
            Console.WriteLine("=== СОЗДАНИЕ СЧЕТОВ ===");

            // Создание счета с использованием конструктора с 1 параметром (нулевой баланс)
            BankAccount account1 = new BankAccount("Иван Петров");
            account1.DisplayAccountInfo();

            // Создание счета с использованием конструктора с 2 параметрами (с начальным балансом)
            BankAccount account2 = new BankAccount("Анна Смирнова", 50000.00m);
            account2.DisplayAccountInfo();

            // Создание еще одного счета
            BankAccount account3 = new BankAccount("Алексей Иванов", 15000.50m);
            account3.DisplayAccountInfo();

            Console.WriteLine();
            Console.WriteLine("=== ОПЕРАЦИИ ПОПОЛНЕНИЯ (ПЕРЕГРУЗКА МЕТОДОВ) ===");

            // Пополнение первого счета в рублях (первая перегрузка метода Deposit)
            Console.WriteLine("Пополняем счет Ивана Петрова на 10000 рублей наличными...");
            account1.Deposit(10000.00m);

            // Пополнение второго счета в долларах США с конвертацией (вторая перегрузка метода Deposit)
            // Курс доллара примем равным 95.50 рублей за 1 USD
            Console.WriteLine("Пополняем счет Анны Смирновой на 500 USD (конвертация по курсу 95.50)...");
            account2.Deposit(500.00m, "USD", 95.50m);

            Console.WriteLine();
            Console.WriteLine("=== ИТОГОВОЕ СОСТОЯНИЕ СЧЕТОВ ===");
            account1.DisplayAccountInfo();
            account2.DisplayAccountInfo();
            account3.DisplayAccountInfo();

            Console.WriteLine();
            Console.WriteLine("=== ФИНАЛЬНАЯ СТАТИСТИКА БАНКА ===");
            BankAccount.DisplayBankStatistics();
        }
    }

    // Класс, описывающий банковский счет
    public class BankAccount
    {
        // --- Статические члены (общие для всего класса) ---
        
        // Счетчик общего количества созданных счетов в банке
        private static int _totalAccountsCount = 0;
        
        // Базовая процентная ставка по вкладам (в процентах годовых)
        private static decimal _baseInterestRate = 5.0m;
        
        // Начальное значение для генерации уникального ID счета
        private static int _nextIdCounter = 202401;

        // --- Экземплярные члены (уникальные для каждого объекта) ---
        
        private readonly int _id;            // Уникальный номер счета (только для чтения после создания)
        private string _ownerName;           // Имя владельца счета
        private decimal _balance;            // Текущий баланс счета
        private string _currency;            // Валюта счета (по умолчанию "RUB")

        // --- Статический конструктор ---
        // Вызывается автоматически средой выполнения .NET ровно один раз перед созданием
        // первого экземпляра класса или первым обращением к любому статическому члену.
        static BankAccount()
        {
            Console.WriteLine("[Системное сообщение]: Статический конструктор BankAccount выполнен. Инициализация подсистемы банковских счетов.");
        }

        // --- Перегрузка конструкторов и цепочка конструкторов (this) ---

        // Конструктор №1: создание счета с нулевым балансом
        public BankAccount(string ownerName) : this(ownerName, 0.0m)
        {
            // Этот конструктор делегирует вызов основному конструктору через : this(...)
        }

        // Конструктор №2 (основной): создание счета с указанием начального баланса
        public BankAccount(string ownerName, decimal initialBalance)
        {
            // Атомарное увеличение счетчика ID для предотвращения проблем в многопоточной среде
            _id = Interlocked.Increment(ref _nextIdCounter) - 1; 
            // Обратите внимание: Interlocked.Increment возвращает уже увеличенное значение, 
            // поэтому вычитаем 1, чтобы получить текущий ID для этого объекта.
            // Для учебных целей можно использовать просто: _id = _nextIdCounter++;

            _ownerName = ownerName;
            _balance = initialBalance > 0 ? initialBalance : 0.0m;
            _currency = "RUB";

            // Увеличиваем общий статический счетчик созданных счетов
            Interlocked.Increment(ref _totalAccountsCount);
        }

        // --- Статические методы ---

        // Метод для изменения глобальной процентной ставки
        public static void SetBaseInterestRate(decimal newRate)
        {
            if (newRate >= 0 && newRate <= 100)
            {
                _baseInterestRate = newRate;
                Console.WriteLine($"[Системное сообщение]: Базовая процентная ставка изменена на {_baseInterestRate}%.");
            }
            else
            {
                Console.WriteLine("[Ошибка]: Процентная ставка должна быть в диапазоне от 0 до 100.");
            }
        }

        // Метод для вывода общей статистики банка
        public static void DisplayBankStatistics()
        {
            Console.WriteLine($"--- Статистика банка ---");
            Console.WriteLine($"Всего открыто счетов: {_totalAccountsCount}");
            Console.WriteLine($"Текущая базовая процентная ставка: {_baseInterestRate}%");
            Console.WriteLine($"Следующий выдаваемый ID: {_nextIdCounter}");
            Console.WriteLine($"------------------------");
        }

        // --- Перегруженные экземплярные методы (Deposit) ---

        // Перегрузка 1: пополнение счета в рублях
        public void Deposit(decimal amount)
        {
            if (amount <= 0)
            {
                Console.WriteLine($"[Ошибка]: Сумма пополнения должна быть больше нуля.");
                return;
            }

            _balance += amount;
            Console.WriteLine($"Успешно пополнен счет №{_id} ({_ownerName}) на сумму {amount:F2} {_currency}. Новый баланс: {_balance:F2} {_currency}.");
        }

        // Перегрузка 2: пополнение счета в иностранной валюте с конвертацией в рубли
        public void Deposit(decimal foreignAmount, string currencyCode, decimal exchangeRateToRub)
        {
            if (foreignAmount <= 0 || exchangeRateToRub <= 0)
            {
                Console.WriteLine($"[Ошибка]: Сумма и курс обмена должны быть положительными числами.");
                return;
            }

            // Переводим иностранную валюту в рубли
            decimal convertedAmountInRub = foreignAmount * exchangeRateToRub;

            // Вызываем первую перегрузку метода Deposit для зачисления рублей на счет
            Deposit(convertedAmountInRub);

            Console.WriteLine($"  (Конвертация: {foreignAmount:F2} {currencyCode} по курсу {exchangeRateToRub:F2} = {convertedAmountInRub:F2} RUB)");
        }

        // Экземплярный метод для вывода информации о конкретном счете
        public void DisplayAccountInfo()
        {
            Console.WriteLine($"Счет №{_id} | Владелец: {_ownerName} | Баланс: {_balance:F2} {_currency} | Ставка по вкладу: {_baseInterestRate}%");
        }
    }
}
```

#### Разбор работы программы шаг за шагом

1. **Инициализация статического контекста:** При запуске программы компилятор и среда выполнения .NET обращаются к классу `BankAccount`. Перед созданием первого объекта срабатывает статический конструктор (`static BankAccount()`), выводящий сообщение о запуске подсистемы.
2. **Работа статического счетчика:** 
   - До создания объектов статический метод `DisplayBankStatistics` показывает, что `_totalAccountsCount = 0`, а `_nextIdCounter = 202402` (с учетом того, что мы инициализировали поле числом `202401`).
   - При вызове `new BankAccount("Иван Петров")` срабатывает конструктор с одним параметром, который перенаправляет вызов в конструктор с двумя параметрами через `this("Иван Петров", 0.0m)`.
   - Внутри конструктора поле `_id` получает значение `202402`, статический счетчик `_nextIdCounter` увеличивается до `202403`, а общий счетчик счетов `_totalAccountsCount` становится равным `1`.
3. **Использование перегруженных методов `Deposit`:**
   - Для счета `account1` вызывается `Deposit(10000.00m)`, которая напрямую прибавляет сумму к полю `_balance`.
   - Для счета `account2` вызывается перегруженный метод `Deposit(500.00m, "USD", 95.50m)`. Этот метод умножает `500` на `95.50` (получается `47750.00` рублей) и внутри себя вызывает метод `Deposit(47750.00m)`, демонстрируя элегантное повторное использование кода (DRY принцип).

### Оценка сложности и производительности

* **Временная сложность (Time Complexity):** 
  - Создание объекта и генерация ID через статические счетчики выполняются за константное время $O(1)$.
  - Вызов статических и экземплярных методов также имеет сложность $O(1)$, так как разрешение перегрузки методов происходит на этапе компиляции (Compile-time polymorphism), исключая динамические накладные расходы во время выполнения программы.
* **Пространственная сложность (Space Complexity):** 
  - Статические поля занимают фиксированный объем памяти в куче (в специальной области статических данных домена приложений) на протяжении всего жизненного цикла программы независимо от того, создано ноль объектов или миллион.
  - Экземплярные поля выделяются в памяти для каждого отдельного объекта отдельно. Сложность по памяти для $N$ созданных объектов составляет $O(N)$.

## Типичные ошибки

1. **Обращение к нестатическому члену из статического метода.**
   * *В чём ошибка:* Попытка использовать внутри метода `static void` поле или метод экземпляра класса (например, `Console.WriteLine(name);`, где `name` — поле объекта).
   * *Почему возникает:* Статический метод не привязан к конкретному объекту и вызывается на уровне класса, поэтому у него нет ссылки `this` и понимания, состояние какого именно экземпляра нужно читать или менять.
   * *Как избежать:* Передавать необходимый объект в качестве аргумента статического метода или сделать метод экземплярным.
   * *Пример ошибки:* `public static void Print() { Console.WriteLine(balance); }` (если `balance` не статический).

2. **Забытый модификатор `static` у главного метода `Main`.**
   * *В чём ошибка:* Объявление точки входа в программу как `public void Main(string[] args)`.
   * *Почему возникает:* Среда выполнения .NET при запуске программы ищет точку входа на уровне типа, не создавая экземпляр класса `Program` через `new`.
   * *Как избежать:* Всегда объявлять метод `Main` с ключом `static`: `public static void Main(string[] args)`.

3. **Попытка перегрузки методов за счет изменения только возвращаемого типа.**
   * *В чём ошибка:* Создание двух методов `public int Calculate(double x)` и `public double Calculate(double x)`.
   * *Почему возникает:* Непонимание правил формирования сигнатуры метода в компиляторе C#. Возвращаемый тип не входит в сигнатуру.
   * *Как избежать:* Менять количество, типы или порядок параметров метода.
   * *Пример ошибки:* Компилятор выдаст ошибку о том, что член с таким именем и параметрами уже существует.

4. **Зацикливание при делегировании конструкторов через `this(...)`.**
   * *В чём ошибка:* Конструктор А вызывает конструктор Б, а конструктор Б вызывает конструктор А.
   * *Почему возникает:* Ошибочное проектирование цепочки вызовов.
   * *Как избежать:* Выстраивать строгую иерархию: конструкторы с меньшим числом параметров должны делегировать вызов конструкторам с большим числом параметров (к основному конструктору), а не наоборот. Цепочка должна иметь конечную точку (основной конструктор, у которого нет вызова `this(...)`).

5. **Избыточное дублирование кода в перегруженных конструкторах.**
   * *В чём ошибка:* Написание проверок валидации и присваивания полей заново в каждом из трех перегруженных конструкторов.
   * *Почему возникает:* Незнание механизма делегирования конструкторов в C#.
   * *Как избежать:* Использовать синтаксис `: this(...)` для перенаправления параметров в основной конструктор, где сосредоточена вся логика проверки.

6. **Ожидание вызова статического конструктора в определенном порядке вручную.**
   * *В чём ошибка:* Попытка вызвать статический конструктор из кода (`new ClassName.StaticConstructor()`).
   * *Почему возникает:* Путаница между экземплярными и статическими конструкторами.
   * *Как избежать:* Помнить, что статический конструктор вызывается автоматически средой выполнения .NET ровно один раз перед первым созданием объекта или первым обращением к статическому члену класса.

7. **Неучет многопоточности при инкременте статического счетчика.**
   * *В чём ошибка:* Использование обычного оператора `_counter++` в статическом методе, вызываемом из разных потоков.
   * *Почему возникает:* Операция инкремента не является атомарной (состоит из чтения, изменения и записи), что приводит к состоянию гонки (Race Condition) и дублированию ID.
   * *Как избежать:* Использовать класс `Interlocked.Increment(ref _counter)` или блокировку `lock`.

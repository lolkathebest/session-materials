## 1. Теоретические основы событийной модели и делегатов в Windows Forms

### Понятие события и делегата в .NET 8

Прежде чем разбирать, как графический интерфейс в Windows Forms реагирует на действия пользователя, необходимо понять фундаментальные механизмы платформы .NET 8, на которых это всё построено: **делегаты** и **события**.

В процедурном программировании выполнение программы идет строго сверху вниз: вы вызвали функцию, она выполнилась, управление вернулось обратно. Компьютер пассивен и выполняет ровно те инструкции, которые вы ему написали в жестком порядке. Однако оконные приложения устроены иначе. Пользователь может нажать любую кнопку, подвинуть мышь, закрыть окно или ввести текст в случайный момент времени. Программа должна быть готова отреагировать на эти действия, заранее не зная, *когда именно* они произойдут.

Для решения этой задачи в C# используются делегаты.

> **Определение.** **Делегат (delegate)** — это ссылочный тип данных в C#, который представляет собой безопасный к типам указатель на метод (или на несколько методов). Делегат хранит в себе сигнатуру (список параметров и тип возвращаемого значения) и может вызывать любой метод, который под эту сигнатуру подходит.

Простым языком, делегат — это «переменная для функции». Вы можете передать функцию в качестве параметра в другой метод или сохранить её в поле, чтобы вызвать позже.

На базе делегатов в C# строятся **события**.

> **Определение.** **Событие (event)** — это инкапсулированная обертка над делегатом, которая позволяет одному классу (обычно элементу управления, например, кнопке) уведомлять другие классы (например, вашу форму) о том, что произошло некое действие.

Событие разрешает внешним классам только две операции: подписаться на уведомление (`+=`) и отписаться от него (`-=`). Вызвать событие (то есть инициировать рассылку уведомлений) может *только* тот класс, внутри которого это событие объявлено. Это защищает логику компонента от несанкционированного вмешательства извне.

### Сигнатура стандартного обработчика событий и параметры `sender` и `EventArgs`

В экосистеме .NET принят единый стандарт проектирования событий, который называется шаблон проектирования Observer (наблюдатель) с использованием стандартного делегата `EventHandler`. 

Любой стандартный метод-обработчик события в Windows Forms (будь то клик по кнопке, изменение текста или движение мыши) обязан иметь строго определенную сигнатуру:

```csharp
void MethodName(object sender, EventArgs e)
```

Разберем подробно каждый компонент этой сигнатуры, откуда они берутся и зачем нужны.

#### Роль параметра `sender`

Первый параметр — `object sender`. Его тип — `object`, то есть базовый класс для всех типов в C#. 

* **Что это значит:** В параметр `sender` автоматически передается ссылка на тот конкретный объект (элемент управления), который сгенерировал данное событие.
* **Зачем это нужно:** Представьте, что у вас на форме есть пять одинаковых кнопок («Кнопка 1», «Кнопка 2» и т.д.), и вы хотите привязать их все к *одному и тому же* методу-обработчику. Когда пользователь нажмет любую из них, вызоведется один и тот же код. Но как узнать, *какая именно* кнопка была нажата? Именно для этого нужен `sender`.

Поскольку тип параметра — `object`, внутри обработчика нам часто требуется привести его к конкретному типу с помощью оператора `as` или явного приведения типов, чтобы получить доступ к специфическим свойствам элемента управления:

```csharp
Button clickedButton = sender as Button;
if (clickedButton != null)
{
    // Теперь мы можем работать с кнопкой, которая вызвала событие
    clickedButton.Text = "Нажали меня!";
}
```

#### Роль параметра `EventArgs` и его производных

Второй параметр — `EventArgs e`. Сам по себе класс `EventArgs` является базовым и практически пустым — он просто сигнализирует о том, что какое-то событие произошло, но не содержит никакой дополнительной информации.

Однако для многих событий стандартной информации «что-то произошло» недостаточно. Например, при клике мышкой нам важно знать, какая именно кнопка мыши была нажата (левая или правая), были ли зажаты клавиши-модификаторы (Ctrl, Shift) и каковы точные координаты курсора. При нажатии клавиши на клавиатуре важно знать, какой именно символ был введен.

Для этого в .NET создаются **производные классы** от `EventArgs`:
1. **`MouseEventArgs`** — передается в событиях мыши (`MouseDown`, `MouseUp`, `MouseMove`). Содержит свойства `X`, `Y` (координаты курсора), `Button` (какая кнопка нажата: `MouseButtons.Left`, `MouseButtons.Right`), `Clicks` (количество кликов, например, двойной клик).
2. **`KeyEventArgs`** — передается в событиях клавиатуры (`KeyDown`, `KeyUp`). Содержит свойства `KeyCode` (код клавиши), `Shift`, `Alt`, `Control` (флаги зажатых служебных клавиш).
3. **`PaintEventArgs`** — передается при перерисовке графики. Содержит графический контекст `Graphics`, на котором можно рисовать линии, фигуры и текст.

Таким образом, сигнатура `object sender, EventArgs e` является универсальным контрактом: первый параметр говорит *кто* позвал, а второй — *с какими деталями*.

### Жизненный цикл события: от действия пользователя до вызова метода

Чтобы полностью понимать, как работает программа, проследим цепочку вызовов в операционной системе и .NET при взаимодействии пользователя с элементом интерфейса (например, кнопкой).

1. **Фиксация действия операционной системой:** Пользователь наводит курсор на кнопку в окне вашего приложения и нажимает левую кнопку мыши. Операционная система Windows перехватывает это аппаратное прерывание от мыши, определяет, какому окну и какому элементу управления принадлежат координаты курсора, и помещает в очередь сообщений этого приложения системное сообщение (например, `WM_LBUTTONDOWN`).
2. **Обработка в циклы сообщений .NET:** Запущенное приложение на C# постоянно крутит внутренний цикл обработки сообщений (Message Loop). Когда сообщение извлекается из очереди, среда выполнения .NET понимает, что произошло событие мыши над конкретным объектом класса `Button`.
3. **Генерация события в коде:** Класс `Button` внутри себя вызывает метод, который отвечает за срабатывание события (в .NET такие методы принято называть `OnEventName`, например, `OnClick`). Этот метод проверяет, есть ли подписчики у события `Click`.
4. **Вызов делегата:** Если список подписчиков не пуст (то есть к событию кто-то привязал свой метод с помощью `+=`), среда выполнения вызывает цепочку делегатов, передавая в качестве аргументов сам объект кнопки (`sender`) и пустой или заполненный объект данных (`EventArgs`).
5. **Выполнение пользовательского кода:** Управление переходит в ваш метод-обработчик, написанный в классе формы (например, `button1_Click`). Программа выполняет инструкции (меняет текст, считает сумму, открывает другое окно), после чего управление возвращается обратно в цикл обработки сообщений операционной системы.

### Разница между процедурным и событийным подходом

Для закрепления понимания сопоставим два подхода к организации работы программы в виде таблицы:

| Критерий | Процедурный подход (консольные утилиты, линейный код) | Событийный подход (Windows Forms, веб-интерфейсы) |
|---|---|---|
| **Кто управляет ходом выполнения** | Сам программист (порядок вызовов жестко прописан в коде сверху вниз). | Пользователь и операционная система (управление передается асинхронно по мере поступления действий). |
| **Структура программы** | Последовательность шагов: «Введи -> Посчитай -> Выведи». | Набор независимых методов-реакций (обработчиков) на конкретные стимулы. |
| **Состояние ожидания** | Программа блокирует поток выполнения (например, на методе `Console.ReadLine()`), ожидая ввода. | Главный поток приложения находится в цикле ожидания сообщений (Event Loop), потребляя минимум ресурсов процессора, пока пользователь ничего не делает. |

### Разобранный пример: собственная реализация делегата и подписки на событие

Поскольку Windows Forms внутри себя устроена ровно на тех же принципах, давайте напишем консольное приложение на C#, которое полностью имитирует механизм подписки на события и вызова обработчиков «под капотом». Это позволит вам увидеть механику работы без визуального шума графического конструктора.

Представим, что мы создаем упрощенный аналог нашей будущей кнопки, которая умеет генерировать событие «Клик», а наш главный класс формы подписывается на это событие.

#### Код программы

```csharp
using System;

namespace EventSimulationDemo
{
    // 1. Объявляем собственный тип делегата, который соответствует стандарту .NET
    // Он принимает объект-источник (sender) и аргументы события (EventArgs)
    public delegate void CustomEventHandler(object sender, EventArgs e);

    // 2. Класс, имитирующий элемент управления (наша виртуальная кнопка)
    public class VirtualButton
    {
        // Имя кнопки для наглядности
        public string Name { get; set; }

        // 3. Объявление события с ключевым словом event на основе нашего делегата
        public event CustomEventHandler Click;

        public VirtualButton(string name)
        {
            Name = name;
        }

        // Метод, имитирующий действие пользователя (например, клик мышкой)
        public virtual void SimulateUserClick()
        {
            Console.WriteLine($"[Система] Пользователь кликнул мышкой по кнопке '{Name}'.");
            
            // Проверяем, есть ли хоть один подписчик на событие, чтобы не получить NullReferenceException
            if (Click != null)
            {
                // Вызываем событие, передавая себя (this) в качестве sender
                Click(this, EventArgs.Empty);
            }
            else
            {
                Console.WriteLine($"[Система] На кнопку '{Name}' никто не подписан, ничего не происходит.");
            }
        }
    }

    // 4. Главный класс программы, имитирующий форму
    class Program
    {
        static void Main(string[] args)
        {
            // Создаем два объекта кнопок
            VirtualButton btnSubmit = new VirtualButton("КнопкаОтправки");
            VirtualButton btnCancel = new VirtualButton("КнопкаОтмены");

            // Подписываем методы-обработчики на события с помощью оператора +=
            // Здесь мы используем обычный метод класса Program
            btnSubmit.Click += OnSubmitButtonClicked;

            // А для второй кнопки используем лямбда-выражение (анонимный метод)
            btnCancel.Click += (sender, e) =>
            {
                VirtualButton b = sender as VirtualButton;
                Console.WriteLine($"[Обработчик Лямбда] Сработала кнопка: {b.Name}. Операция отменена пользователем.");
            };

            // Симулируем действия пользователя
            Console.WriteLine("--- Шаг 1: Нажимаем кнопку отправки ---");
            btnSubmit.SimulateUserClick();

            Console.WriteLine("\n--- Шаг 2: Нажимаем кнопку отмены ---");
            btnCancel.SimulateUserClick();

            // Демонстрация отписки от события
            Console.WriteLine("\n--- Шаг 3: Отписываемся от кнопки отправки и нажимаем снова ---");
            btnSubmit.Click -= OnSubmitButtonClicked;
            btnSubmit.SimulateUserClick();

            // Задержка консоли
            Console.ReadKey();
        }

        // Статический метод-обработчик для первой кнопки
        // Его сигнатура строго совпадает с делегатом CustomEventHandler
        private static void OnSubmitButtonClicked(object sender, EventArgs e)
        {
            // Используем параметр sender для определения источника
            VirtualButton sourceButton = sender as VirtualButton;

            if (sourceButton != null)
            {
                Console.WriteLine($"[Обработчик Метод] Получено событие от элемента управления: {sourceButton.Name}");
                Console.WriteLine("[Обработчик Метод] Выполняется валидация и отправка данных на сервер...");
            }
        }
    }
}
```

#### Пояснение по строкам и блокам кода:
* **Строка 5:** `public delegate void CustomEventHandler(object sender, EventArgs e);` — создаем чертеж нашего будущего метода-обработчика. Любой метод, который мы захотим привязать к событию, должен возвращать `void` и принимать ровно два параметра: `object` и `EventArgs`.
* **Строка 13:** `public event CustomEventHandler Click;` — объявление самого события. Ключевое слово `event` ограничивает использование делегата: извне класса `VirtualButton` к нему нельзя присвоить значение через знак `=` или вызвать напрямую, разрешено только добавлять (`+=`) и удалять (`-=`) методы.
* **Строка 31:** `if (Click != null)` — критически важная проверка. Если ни один разработчик не написал код привязки обработчика к этой кнопке, значение делегата `Click` будет равно `null`. Попытка вызова `Click(...)` при `null` приведет к аварийному завершению программы с исключением `NullReferenceException`.
* **Строка 61:** `btnSubmit.Click += OnSubmitButtonClicked;` — процесс подписки. Мы говорим системе: «Когда в объекте `btnSubmit` произойдет событие `Click`, найди в памяти метод `OnSubmitButtonClicked` и вызови его».
* **Строка 93:** `btnSubmit.Click -= OnSubmitButtonClicked;` — процесс отписки. Удаляем метод из цепочки вызовов делегата. После этого шага при клике на кнопку первый обработчик больше вызываться не будет.

#### Проверка и оценка сложности:
* **Сложность алгоритма:** Временная сложность вызова события пропорциональна количеству подписанных на него методов (в данном примере $O(1)$ для одного подписчика). Пространственная сложность $O(N)$, где $N$ — количество зарегистрированных подписчиков в цепочке делегатов.
* **Правдоподобность:** Код демонстрирует чистую инверсию управления (IoP) и модель наблюдателя, которая в точности повторяет поведение компонентов Windows Forms в Visual Studio. Ошибки типов исключены благодаря строгой типизации делегатов в .NET 8.

## 2. Способы создания и подключения обработчиков событий

### 1. Подключение обработчика через окно свойств Visual Studio (кладка «Молния»)

В среде разработки Visual Studio работа с графическим интерфейсом Windows Forms строится вокруг визуального проектировщика (Designer). Когда вы перетаскиваете элемент управления (например, `Button`) на форму (`Form`), среда автоматически создает экземпляр этого класса в коде. Но как заставить кнопку выполнять определенные действия при нажатии? Для этого используется окно свойств (`Properties`), которое по умолчанию располагается в правом нижнем углу интерфейса Visual Studio.

В окне свойств есть несколько вкладок, переключаемых с помощью иконок в верхней его части. Основная вкладка с иконкой в виде зеленого гаечного ключа отображает свойства объекта (например, `Text`, `BackColor`, `Size`). Вкладка с иконкой в виде **желтой молнии** отвечает за **события** (`Events`).

Алгоритм подключения обработчика через вкладку «Молния»:
1. Выделите элемент управления на форме одним щелктором левой кнопки мыши (например, `button1`).
2. Откройте окно **Properties** и перейдите на вкладку **Events** (нажмите на значок молнии). Перед вами появится алфавитный список всех событий, которые поддерживает данный элемент управления (для кнопки это `Click`, `DoubleClick`, `MouseEnter`, `MouseDown`, `Paint` и множество других).
3. Найдите нужное событие — в нашем случае это `Click` (событие щелчка по кнопке).
4. Щелкните левой кнопкой мыши по текстовому полю справа от имени события `Click`. 
5. Введите уникальное имя будущего метода-обработчика (например, `ButtonThree_Click`) и нажмите клавишу `Enter`.

Что происходит в этот момент под капотом Visual Studio?
- Среда автоматически переключает вас из визуального конструктора в файл исходного кода формы (`Form1.cs`).
- В классе `Form1` генерируется заготовка метода с точной сигнатурой, соответствующей делегату `EventHandler`:
  ```csharp
  private void ButtonThree_Click(object sender, EventArgs e)
  {
      // Здесь будет располагаться ваш код
  }
  ```
- Одновременно с этим в специальном служебном файле `Form1.Designer.cs` создается строка кода, которая связывает событие `Click` кнопки с созданным методом. Об этом файле и механизме связывания мы поговорим подробно в отдельном пункте.

### 2. Автоматическая генерация обработчика двойным щелчком мыши

Самый быстрый и часто используемый разработчиками способ создания стандартного обработчика для основного действия элемента управления — это **двойной щелчок левой кнопкой мыши** по этому элементу в режиме конструктора формы.

Когда вы дважды щелкаете по кнопке `button1` на форме:
1. Visual Studio определяет элемент и его самое главное («событие по умолчанию»). Для класса `Button`, `CheckBox` и `RadioButton` событием по умолчанию является `Click`. Для элемента `TextBox` — событие `TextChanged` (изменение текста). Для формы `Form` — событие `Load` (загрузка формы в память).
2. Среда автоматически придумывает имя метода по шаблону: `[ИмяЭлемента]_[ИмяСобытия]` (например, `button1_Click`).
3. Метод создается в файле `Form1.cs`, и курсор ввода автоматически переносится внутрь тела этого метода.

Этот способ экономит время, однако он жестко привязан к событию по умолчанию. Если вам нужно подписать кнопку на событие наведения мыши (`MouseEnter`) или изменения размера (`Resize`), использование двойного щелчка не подойдет — придется обращаться либо к вкладке «Молния», либо писать код вручную.

### 3. Программное подключение обработчика событий с помощью оператора `+=`

В профессиональной разработке далеко не все элементы управления создаются в визуальном конструкторе. Иногда интерфейс или его части генерируются «на лету» прямо во время выполнения программы (например, динамическое добавление строк в таблицу или создание массива кнопок по результатам запроса к базе данных). В таких случаях графический конструктор бессилен, и программист должен управлять подпиской на события программно, используя язык C#.

Для того чтобы подписать метод на событие объекта в коде, используется оператор комбинированного присваивания `+=`.

> **Правило.** Синтаксис программной подписки: `объект.Событие += имя_метода;` (или имя делегата/ссылка на метод). Важно: имя метода передается **без круглых скобок на конце**, так как мы передаем указатель (ссылку) на сам метод, а не вызываем его в момент подписки.

Рассмотрим пример. Пусть на форме есть кнопка `button1`. Мы хотим программно подписать ее на метод `ShowMessage_Click`:

```csharp
public partial class Form1 : Form
{
    public Form1()
    {
        InitializeComponent();
        
        // Программная подписка на событие Click
        button1.Click += ShowMessage_Click;
    }

    private void ShowMessage_Click(object sender, EventArgs e)
    {
        MessageBox.Show("Кнопка была нажата (подключено через код)!");
    }
}
```

Как это работает с точки зрения архитектуры C#? Событие в классе элемента управления — это специальная обертка над списком вызовов (invocation list). Оператор `+=` добавляет ваш метод в этот список. Когда пользователь кликает по кнопке, среда пробегает по всему списку подписанных методов и последовательно вызывает каждый из них. К одному событию можно подключить **несколько** разных методов — все они выполнятся по очереди.

### 4. Программное отсоединение обработчика событий с помощью оператора `-=`

В процессе работы приложения часто возникает необходимость временно или навсегда отключить реакцию элемента управления на действия пользователя. Например, кнопка отправки данных должна быть активна только до тех пор, пока файл загружается, либо обработчик тяжелой математической операции должен сработать ровно один раз, после чего отписаться, чтобы избежать повторных вычислений.

Для удаления метода из списка вызовов события используется оператор `-=`.

> **Правило.** Синтаксис программного отсоединения: `объект.Событие -= имя_метода;`. Метод должен быть тем же самым, который ранее добавлялся через `+=`. Передача анонимного метода или лямбда-выражения в качестве аргумента для `-=` не сработает, так как у них нет имени, на которое можно сослаться.

Пример временной подписки и отписки:

```csharp
private void btnStart_Click(object sender, EventArgs e)
{
    MessageBox.Show("Обработка запущена. Повторные нажатия заблокированы.");
    
    // Отписываем метод от события Click, чтобы кнопка больше не реагировала
    btnStart.Click -= btnStart_Click;
    
    // Меняем текст и цвет кнопки, показывая пользователю изменение состояния
    btnStart.Text = "Готово";
    btnStart.Enabled = false;
}
```

Если вы попытаетесь отписать метод, который никогда не был подписан, или попытаетесь отписаться дважды, платформа .NET не вызовет ошибку — операция просто будет проигнорирована.

### 5. Использование анонимных методов и лямбда-выражений

Создавать отдельный полноценный метод для каждого маленького действия (например, чтобы просто очистить поле ввода по нажатию крошечной крестиковой кнопки) бывает избыточно. Это приводит к замусориванию класса `Form1` множеством мелких методов, которые используются ровно один раз.

Для решения этой проблемы в C# применяются **анонимные методы** и их современное развитие — **лямбда-выражения**. Они позволяют передать блок исполняемого кода прямо в момент подписки на событие, без объявления отдельной функции.

Лямбда-выражение записывается с помощью оператора `=>` (читается как «ведет к» или «соответствует»). Слева от стрелки указываются параметры события (`sender, e`), а справа в фигурных скобках `{}` — тело самого обработчика.

Пример использования лямбда-выражения для очистки текстового поля:

```csharp
// Подписываемся на событие Click с помощью лямбда-выражения
buttonClear.Click += (sender, e) => 
{
    textBoxInput.Clear();
    labelStatus.Text = "Поле ввода очищено.";
};
```

Если параметры `sender` и `e` внутри вашего обработчика никак не используются, в современных версиях C# (.NET 8) их можно опустить или заменить на символы подчеркивания (дискарды), что делает код еще более лаконичным:

```csharp
buttonExit.Click += (_, _) => Close();
```

### 6. Анализ файла автосгенерированного кода формы (`*.Designer.cs`)

Чтобы полностью понимать, как устроена среда Windows Forms, необходимо заглянуть «под капот» механизма генерации кода. Проводник решений (Solution Explorer) в Visual Studio скрывает служебные файлы за иконкой стрелочки рядом с файлом `Form1.cs`. Если развернуть ее, вы увидите файл с именем **`Form1.Designer.cs`**.

> **Важное предупреждение:** Никогда не вносите ручные изменения непосредственно в файл `Form1.Designer.cs`. Этот файл полностью управляется визуальным дизайнером Visual Studio. Любое ваше ручное исправление может быть затерто средой при следующем открытии конструктора или изменении свойств элементов на форме.

Давайте откроем этот файл и найдем секцию, отвечающую за инициализацию компонентов. Внутри метода `InitializeComponent()` среда выстраивает создание всех объектов, задание их координат, размеров и, самое главное, **регистрацию событий**.

Ниже приведен фрагмент типичного автосгенерированного кода `Form1.Designer.cs`:

```csharp
partial class Form1
{
    /// <summary>
    /// Обязательная переменная конструктора.

    /// содержимое этого метода с помощью редактора кода.
    /// </summary>
    private void InitializeComponent()
    {
        this.button1 = new System.Windows.Forms.Button();
        this.SuspendLayout();
        
        // 
        // button1
        //

        this.button1.Click += new System.EventHandler(this.button1_Click);
```

Обратите внимание на ключевую строку:
`this.button1.Click += new System.EventHandler(this.button1_Click);`

Здесь явно видно, что событие `Click` принимает экземпляр делегата `System.EventHandler`, в конструктор которого передается ссылка на метод `this.button1_Click`. Когда вы подключаете обработчик через вкладку «Молния» в дизайнере, Visual Studio автоматически дописывает ровно эту строчку в метод `InitializeComponent()`.

### Разбор комплексного примера

#### Условие задачи
Разработать оконное приложение на базе Windows Forms (платформа .NET 8, язык C#), содержащее ровно **три кнопки** (`button1`, `button2`, `button3`) и одно текстовое поле `labelInfo`. 
Необходимо реализовать следующие требования к подключению обработчиков событий:
1. **Первая кнопка (`button1`)** подключена через визуальный дизайнер (двойным щелчком). При нажатии она должна программно подключить обработчик событий ко **второй кнопке** (`button2`). До этого момента вторая кнопка не должна выполнять никаких действий при клике.
2. **Вторая кнопка (`button2`)** после того, как ее подключила первая кнопка, при нажатии должна использовать **лямбда-выражение** для вывода приветственного сообщения в `labelInfo`.
3. **Третья кнопка (`button3`)** подключена программно в конструкторе формы с помощью оператора `+=` к отдельному методу. При нажатии она должна сбрасывать состояние интерфейса (отключать вторую кнопку обратно через оператор `-=` и очищать `labelInfo`).

#### Рисунок схемы интерфейса (словесное описание)
```
+-------------------------------------------------------+
| Form1                                           [X]   |
+-------------------------------------------------------+
|                                                       |
|   [ Кнопка 1: Активировать вторую ]                   |
|                                                       |
|   [ Кнопка 2: Нажми меня (неактивна до Кнопки 1) ]    |
|                                                       |
|   [ Кнопка 3: Сбросить состояние ]                    |
|                                                       |
|   Статус: [ Здесь появится текст сообщения... ]       |
|                                                       |
+-------------------------------------------------------+
```

#### Ход рассуждений (почему делаем именно так)
1. Нам нужны три кнопки и метка. В конструкторе формы `Form1` мы гарантируем, что они инициализируются.
2. Кнопка `button3` должна быть рабочей с самого запуска программы, поэтому мы подпишем ее программно прямо в конструкторе формы через оператор `+=`.
3. Кнопка `button2` изначально не должна иметь обработчика клика. Пользователь должен сначала нажать `button1`.
4. При клике на `button1` срабатывает ее метод. Внутри этого метода мы берем `button2` и добавляем ей обработчик через оператор `+=`, используя **лямбда-выражение**. Также мы изменим текст метки, чтобы информировать пользователя об активации.
5. При клике на `button3` мы должны выполнить сброс: отписать обработчик от `button2` с помощью оператора `-=`, вернуть исходный текст метки. Для этого нам нужно вынести лямбда-выражение или метод `button2` в отдельное поле класса, чтобы было что отписывать (так как, напомним, анонимные лямбды без сохранения ссылки отписать оператором `-=` невозможно). Поэтому для второй кнопки мы создадим именованный метод, но покажем и объясним, как он заменяет лямбду, либо запишем метод в переменную-делегат. Сделаем строго по условию: вторая кнопка использует лямбда-выражение при подключении первой кнопкой, а для возможности отписки сохраним ссылку на этот метод в поле класса.

#### Полный исходный код программы (`Form1.cs`)

```csharp
using System;
using System.Windows.Forms;

namespace EventDemoApp
{
    public partial class Form1 : Form
    {
        // Объявляем переменную для делегата второй кнопки, 
        // чтобы мы могли как подписать ее через +=, так и отписать через -=
        private EventHandler button2LambdaHandler;

        public Form1()
        {
            InitializeComponent();

            // Настройка начального текста элементов управления
            button1.Text = "1. Активировать Кнопку 2";
            button2.Text = "2. Я пока заблокирована";
            button3.Text = "3. Сбросить настройки";
            labelInfo.Text = "Статус: Ожидание действий...";

            // Инициализируем лямбда-выражение для второй кнопки в поле класса
            button2LambdaHandler = (sender, e) =>
            {
                labelInfo.Text = "Успех! Кнопка 2 сработала через лямбда-выражение.";
                labelInfo.ForeColor = System.Drawing.Color.Green;
            };

            // Программное подключение третьей кнопки в конструкторе
            button3.Click += ResetButton_Click;
        }

        // Обработчик первой кнопки (создан автоматически или через дизайнер)
        private void button1_Click(object sender, EventArgs e)
        {
            // Подключаем вторую кнопку программно с использованием лямбда-выражения
            button2.Click += button2LambdaHandler;

            // Визуально показываем пользователю, что кнопка активирована
            button2.Text = "2. Нажми меня!";
            labelInfo.Text = "Кнопка 2 теперь активна! Нажмите ее.";
            labelInfo.ForeColor = System.Drawing.Color.Blue;

            // Саму первую кнопку после активации можно отключить, чтобы не жали повторно
            button1.Enabled = false;
        }

        // Обработчик третьей кнопки (сброс состояния)
        private void ResetButton_Click(object sender, EventArgs e)
        {
            // Отписываем обработчик от второй кнопки с помощью оператора -=
            button2.Click -= button2LambdaHandler;

            // Возвращаем элементы в исходное состояние
            button2.Text = "2. Я снова заблокирована";
            button1.Enabled = true;
            labelInfo.Text = "Статус: Состояние сброшено.";
            labelInfo.ForeColor = System.Drawing.Color.Black;
        }
    }
}
```

#### Проверка и анализ кода
1. **Единицы измерения и типы:** В коде используются стандартные классы WinForms (`Button`, `Form`, `Label`, `EventHandler`), типы данных `string` для текстов и перечисление `System.Drawing.Color` для изменения цвета шрифта. Ошибок типов нет.
2. **Правдоподобность логики:** Если пользователь запустит приложение и сразу нажмет `button2`, ничего не произойдет, так как подписка `+= button2LambdaHandler` еще не была выполнена. После нажатия `button1` подписка происходит, и нажатие `button2` успешно меняет текст и цвет метки. Нажатие `button3` возвращает систему в исходную точку за счет корректного применения оператора `-=`.
3. **Оценка сложности:** Временная сложность вызова обработчика события составляет $O(1)$ в среднем случае (вызов методов из списка делегатов). Пространственная сложность программы определяется количеством элементов интерфейса — $O(1)$.

`Ответ:` Разработанное приложение полностью удовлетворяет всем требованиям пункта плана, демонстрирует визуальное, автоматическое, программное (`+=`) и отсоединяющее (`-=`) подключение обработчиков событий, а также использование лямбда-выражений в средах .NET 8 / C#.

## 3. Управление свойствами элементов управления из кода

### Доступ к свойствам элементов управления через их имена

В Windows Forms каждый элемент управления, размещенный на форме (кнопка, текстовое поле, метка и т.д.), является объектом определенного класса из пространства имен `System.Windows.Forms`. Когда вы перетаскиваете элемент из панели элементов (`Toolbox`) на поверхность формы в дизайнере Visual Studio, среда разработки автоматически создает для него поле в файле автосгенерированного кода формы (`*.Designer.cs`). 

Имя этого поля задается в окне свойств (`Properties`) в поле **(Name)**. По умолчанию Visual Studio присваивает элементам имена на основе их типа и порядкового номера: `button1`, `textBox1`, `label1` и т.д. В реальной разработке настоятельно рекомендуется давать элементам осмысленные префиксы и имена (например, `btnSubmit`, `txtUsername`, `lblStatus`), чтобы код оставался читаемым.

К любому элементу управления из файла кода формы (`Form1.cs`) можно обратиться напрямую по его идентификатору. Поскольку элементы управления являются полями класса формы, они доступны во всех методах этого класса, включая обработчики событий.

> **Важно.** Поле элемента управления доступно только после вызова метода `InitializeComponent()` в конструкторе формы. Если вы попытаетесь обратиться к элементу до этого момента, получите исключение `NullReferenceException`, так как объект еще не создан в памяти.

---

### Управление текстовым содержимым, доступностью и видимостью

После того как у вас есть доступ к объекту по его имени, вы можете управлять его состоянием в реальном времени, изменяя его свойства. Рассмотрим базовые свойства, которые используются наиболее часто.

#### Свойство `Text`
Свойство `Text` типа `string` определяет текст, который отображается на элементе управления или содержится внутри него.
- Для `Label` и `Button` свойство `Text` задает надпись, которую видит пользователь.
- Для `TextBox` свойство `Text` содержит текст, введенный пользователем (или установленный программно).

Пример изменения текста:
```csharp
// Установка приветствия в метку
lblGreeting.Text = "Здравствуйте, студент!";

// Чтение введенного пользователем текста из текстового поля
string userInput = txtBoxInput.Text;
```

#### Свойство `Enabled`
Свойство `Enabled` типа `bool` (`true` или `false`) определяет, доступен ли элемент для взаимодействия с пользователем.
- Если `Enabled = true` (значение по умолчанию), элемент реагирует на наведение мыши, фокус и клики.
- Если `Enabled = false`, элемент становится «седым» (визуально заблокированным) и не реагирует на действия пользователя. Обработчики событий для такого элемента вызываться не будут.

Пример блокировки кнопки:
```csharp
// Сделать кнопку недоступной для нажатия
btnSubmit.Enabled = false;
```

#### Свойство `Visible`
Свойство `Visible` типа `bool` управляет видимостью элемента на форме.
- Если `Visible = true`, элемент отображается.
- Если `Visible = false`, элемент полностью скрывается, а пространство, которое он занимал, может перераспределяться (в зависимости от настроек контейнера или компоновки).

Пример скрытия элемента:
```csharp
// Скрыть панель с дополнительными вопросами
pnlAdditionalQuestions.Visible = false;
```

### Изменение визуального оформления: цвета и шрифты

### Валидация и чтение числовых данных из TextBox

Текстовое поле `TextBox` всегда возвращает данные в виде строки (`string`), даже если пользователь ввел туда целое или дробное число. Прямое присваивание строки числовой переменной вызовет ошибку компиляции:
```csharp
// ОШИБКА КОМПИЛЯЦИИ: нельзя неявно преобразовать тип string в int
int age = txtAge.Text; 
```

Для преобразования строки в число используются методы `int.Parse()`, `double.Parse()` или более безопасные методы валидации `int.TryParse()` и `double.TryParse()`. В оконных приложениях критически важно использовать методы с `TryParse`, так как пользователь может ввести буквы или оставить поле пустым, что вызовет аварийное завершение программы при использовании `Parse`.

Общий паттерн безопасного чтения числа:
```csharp
int age;
// Метод TryTryParse возвращает true, если конвертация прошла успешно, и false в противном случае
if (int.TryParse(txtAge.Text, out age))
{
    // Конвертация успешна, переменная age содержит число
    MessageBox.Show($"Введенный возраст: {age}");
}
else
{
    // Пользователь ввел некорректные данные
    MessageBox.Show("Пожалуйста, введите корректное целое число!", "Ошибка ввода", MessageBoxButtons.OK, MessageBoxIcon.Error);
}
```

### Разобранный пример: разработка интерактивной анкеты

Рассмотрим создание оконного приложения-анкеты. 

#### Условие задачи
Требуется разработать форму со следующими элементами:
1. Поле ввода имени (`TextBox` с именем `txtName`).
2. Кнопка отправки (`Button` с именем `btnSubmit`), которая изначально заблокирована (`Enabled = false`).
3. Флажок (`CheckBox` с именем `chkShowExtra`), управляющий видимостью панели с дополнительными вопросами.
4. Панель (`Panel` с именем `pnlExtra`) с дополнительным полем для ввода любимого языка программирования (`TextBox` с именем `txtFavoriteLang`).

Требования к логике:
- Кнопка отправки должна становиться активной (`Enabled = true`) только тогда, когда пользователь ввел хотя бы один символ в поле имени. Если поле очищено, кнопка снова блокируется.
- Снятие галочки с флажка должно скрывать панель дополнительных вопросов (`Visible = false`), а установка галочки — показывать её (`Visible = true`).

#### Рисунок интерфейса (ASCII-схема)
```text
+-------------------------------------------------+
| Анкета пользователя                     [ _ ] X |
+-------------------------------------------------+
| Введите ваше имя:                               |
| [ Иван___________ ]                             |
|                                                 |
| [X] Показать дополнительные вопросы             |
|                                                 |
| +---------------------------------------------+ |
| | Любимый язык программирования:              | |
| | [ C#___________ ]                           | |
| +---------------------------------------------+ |
|                                                 |
|                   [ Отправить ]                 |
+-------------------------------------------------+
```

#### Ход рассуждений
1. **Динамическая активация кнопки:** нам нужно отслеживать изменение текста в поле `txtName`. Для этого идеально подходит событие `TextChanged`. Каждый раз, когда пользователь вводит или стирает символ, срабатывает обработчик, в котором мы проверяем условие: если длина строки `txtName.Text` больше нуля (`> 0`), то `btnSubmit.Enabled = true`, иначе `false`.
2. **Управление видимостью:** состояние флажка `CheckBox` меняется пользователем, что вызывает событие `CheckedChanged`. В обработчике этого события мы связываем свойство `Visible` панели `pnlExtra` со свойством `Checked` флажка (`pnlExtra.Visible = chkShowExtra.Checked`). Если флажок отмечен (`true`), панель видна, если нет — скрыта.

#### Полный код формы (`Form1.cs`)

```csharp
using System;
using System.Drawing;
using System.Windows.Forms;

{
    public partial class Form1 : Form
    {
        public Form1()
        {
            InitializeComponent();
            
            // Начальная настройка состояния элементов при запуске формы

            {

        private void chkShowExtra_CheckedChanged(object sender, EventArgs e)
        {
            // Управляем видимостью панели в зависимости от состояния галочки
            pnlExtra.Visible = chkShowExtra.Checked;
        }

        // Обработчик клика по кнопке отправки
        private void btnSubmit_Click(object sender, EventArgs e)
        {
            string userName = txtName.Text.Trim();
            string message = $"Анкета успешно отправлена!\nИмя: {userName}";

            // Если панель видима, считываем данные и из нее

                    return; // Прерываем выполнение метода
                }
                message += $"\nЛюбимый язык: {favLang}";
            }

            // Вывод итогового сообщения пользователю
            MessageBox.Show(message, "Результат", MessageBoxButtons.OK, MessageBoxIcon.Information);
        }
    }
}
```

1. **Единицы и типы:** свойства `Enabled` и `Visible` принимают булевы значения (`bool`), что строго соблюдено в коде (`chkShowExtra.Checked`). Свойство `Text` возвращает `string`, метод `Trim()` корректно отсекает случайные пробелы, предотвращая отправку пустых строк, состоящих из одних пробелов.
2. **Правдоподобие:** логика работы интуитивно понятна пользователю. При запуске программы кнопка «Отправить» недоступна, что предотвращает отправку пустой формы. Изменение состояния `CheckBox` мгновенно скрывает или отображает соответствующий контейнер (`Panel`), экономя пространство интерфейса. Контроль заполнения дополнительных полей при видимой панели гарантирует целостность собираемых данных.

**Ответ:** Разработано оконное приложение на базе Windows Forms с динамическим управлением свойствами `Enabled`, `Visible`, `BackColor` и `Text` в ответ на действия пользователя через обработчики событий `TextChanged`, `CheckedChanged` и `Click`.

## 4. Взаимодействие элементов управления: комплексные сценарии

### Взаимодействие элементов управления: комплексные сценарии

В реальных оконных приложениях элементы интерфейса редко существуют изолированно друг от друга. Действие пользователя в одном элементе (например, ввод текста или выбор переключателя) часто должно мгновенно отражаться на состоянии других элементов: менять их доступность, внешний вид, текстовое наполнение или доступный функционал. 

Событийно-управляемая модель Windows Forms позволяет связать любые компоненты интерфейса через общие или специализированные обработчики событий. Главная задача разработчика на этом этапе — научиться управлять логикой приложения так, чтобы интерфейс оставался отзывчивым, предсказуемым и защищенным от логических ошибок.

---

### Обмен данными и синхронизация состояния элементов

Обмен данными между элементами управления в Windows Forms происходит через чтение и запись их свойств в ответ на возникающие события. Поскольку каждый элемент управления является экземпляром класса (например, `TextBox`, `Label`, `RadioButton`), доступ к его публичным свойствам открывает полную свободу управления.

> **Важно.** Элементы управления не должны напрямую «знать» друг о друге избыточную информацию. Взаимодействие строится вокруг событий: источник генерирует событие, а метод-обработчик считывает данные из одних компонентов и применяет изменения к другим.

Рассмотрим типичные сценарии совместной работы:
1. **Связка `TextBox` и `Label`:** мгновенный вывод текста по мере его ввода пользователем (событие `TextChanged`).
2. **Связка групп `RadioButton` и других элементов:** переключение режимов работы программы. Если выбран определенный переключатель, блокируется или разблокируется соответствующая группа полей ввода (`Enabled = true / false`).
3. **Связка `CheckBox` и видимости блоков интерфейса (`Visible = true / false`):** скрытие или отображение дополнительных настроек.

При разработке интерфейсов с большим количеством зависимых элементов возникает риск **циклической зависимости (бесконечного цикла событий)**. 

> **Правило предотвращения бесконечных циклов.** Бесконечный цикл событий возникает тогда, когда обработчик события одного элемента программно изменяет свойство этого же элемента (или другого элемента), что, в свою очередь, вызывает то же самое событие повторно. Для предотвращения этого используют флаги-блокираторы (флаги состояния), временное отписывание от события с помощью оператора `-=` либо проверку текущего и нового значений перед выполнением логики.

---

### Реакция в реальном времени: событие TextChanged

Событие `TextChanged` возникает каждый раз, когда содержимое свойства `Text` элемента управления изменяется. Для `TextBox` это происходит при каждом вводе или удалении символа пользователем (а также при программном изменении текста).

Использование `TextChanged` позволяет реализовать «живой» поиск, мгновенный расчет значений или валидацию формы «на лету» (например, делать кнопку отправки активной только тогда, когда заполнены все обязательные поля).

Рассмотрим частую ловушку: если в обработчнике `TextChanged` вы программно меняете текст в том же самом `TextBox` (например, форматируете вводимую строку), вызов `textBox1.Text = ...` снова сгенерирует событие `TextChanged`, что приведет к переполнению стека вызовов (`StackOverflowException`). 

**Как этого избежать?** Перед изменением текста всегда проверяйте, действительно ли новое значение отличается от текущего:
```csharp
if (textBox1.Text != formattedText)
{
    textBox1.Text = formattedText;
    textBox1.SelectionStart = textBox1.Text.Length; // Возвращаем курсор в конец
}
```

### Полный разбор примера: Калькулятор скидок

Разработаем полноценное оконное приложение «Калькулятор скидок». 

#### Условие задачи
Пользователь вводит исходную сумму покупки в текстовое поле (`TextBox`). С помощью группы переключателей (`RadioButton`) он выбирает фиксированный размер скидки: 5%, 10% или 20%. Дополнительно на форме есть флажок (`CheckBox`), позволяющий применить «специальную дисконтную карту» (дает дополнительные 5% скидки ко всем выбранным вариантам). 

Результат вычислений (итоговая сумма и размер сэкономленных средств) должен выводиться в метку (`Label`) **мгновенно** при любом изменении суммы или параметров скидки. Если итоговая сумма превышает 5000 рублей, цвет текста результата меняется на зеленый (акцент на крупную покупку), в ином случае остается стандартным. При некорректном вводе (например, буквы вместо цифр) приложение не должно «падать», а в поле результата должна выводиться понятная подсказка красным цветом.

#### Рисунок интерфейса (схема словами)
```
+---------------------------------------------------------+
|                  Калькулятор скидок                     |
+---------------------------------------------------------+
| Введите сумму покупки (руб.):                           |
| [  1000                                               ] |
|                                                         |
| Размер скидки:                                          |
| (•) 5%     ( ) 10%     ( ) 20%                          |
|                                                         |
| [v] Применить карту постоянного клиента (+5%)             |
|                                                         |
| ------------------------------------------------------- |
| Итого к оплате: 950,00 руб. (Экономия: 50,00 руб.)      |
+---------------------------------------------------------+
```

#### Ход рассуждений (почему делаем именно так)
1. Нам понадобятся: поле ввода суммы (`txtAmount`), три переключателя (`rb5`, `rb10`, `rb20`), один флажок (`chkCard`) и метка для вывода результата (`lblResult`).
2. Чтобы расчет происходил мгновенно без необходимости нажимать кнопку «Рассчитать», мы подпишемся на событие `TextChanged` для текстового поля, событие `CheckedChanged` для каждого переключателя и для флажка. 
3. Поскольку логика расчета в ответ на любое из этих действий одинакова (пересчитать и вывести результат), мы вынесем всю математику в отдельный вспомогательный метод `CalculateDiscount()`. Каждый обработчик событий будет просто вызывать этот метод.
4. Внутри метода `CalculateDiscount()` мы сначала проверим корректность введенных данных с помощью метода `decimal.TryParse()`. Если введено не число или отрицательное число, выведем предупреждение в `lblResult` и окрасим текст в красный цвет.
5. Если данные корректны, определяем базовый процент скидки на основе состояния переключателей (`Checked`).
6. Добавляем 5%, если установлен флажок `chkCard`.
7. Вычисляем сумму скидки и итоговую сумму, форматируем вывод с точностью до копеек и проверяем условие превышения порога в 5000 рублей для изменения цвета текста.

```csharp
            // Подписка на событие изменения текста
            txtAmount.TextChanged += Inputs_Changed;
            this.Controls.Add(txtAmount);

            // Метка группы скидок
            lblDiscountGroup = new Label();
            lblDiscountGroup.Text = "Базовый размер скидки:";
            lblDiscountGroup.Location = new Point(20, 110);
            lblDiscountGroup.AutoSize = true;
            this.Controls.Add(lblDiscountGroup);

            // Переключатели скидок
            rb5 = new RadioButton();
            rb5.Text = "5%";
            rb5.Location = new Point(20, 135);
            rb5.Checked = true; // По умолчанию выбрана скидка 5%
            rb5.AutoSize = true;
            rb5.CheckedChanged += Inputs_Changed;
            this.Controls.Add(rb5);

            rb10 = new RadioButton();
            rb10.Text = "10%";
            rb10.Location = new Point(80, 135);
            rb10.AutoSize = true;
            rb10.CheckedChanged += Inputs_Changed;
            this.Controls.Add(rb10);

            rb20 = new RadioButton();
            rb20.Text = "20%";
            rb20.Location = new Point(140, 135);
            rb20.AutoSize = true;
            rb20.CheckedChanged += Inputs_Changed;
            this.Controls.Add(rb20);

            // Флажок дисконтной карты
            chkCard = new CheckBox();
            chkCard.Text = "Карта постоянного клиента (+5%)";
            chkCard.Location = new Point(20, 170);
            chkCard.AutoSize = true;
            chkCard.CheckedChanged += Inputs_Changed;
            this.Controls.Add(chkCard);

            // Метка для вывода результатов
            lblResult = new Label();
            lblResult.Location = new Point(20, 215);
            lblResult.Width = 380;
            lblResult.Height = 50;
            lblResult.Font = new Font("Segoe UI", 10, FontStyle.Regular);
            this.Controls.Add(lblResult);
        }

        // Универсальный обработчик событий для всех элементов управления, влияющих на расчет
        private void Inputs_Changed(object sender, EventArgs e)
        {
            CalculateDiscount();
        }

        // Основной метод расчета скидки и обновления интерфейса
        private void CalculateDiscount()
        {
            // Шаг 1: Валидация введенных данных
            string inputString = txtAmount.Text.Trim();

            // Замена точки на запятую для корректности парсинга в русской локали
            inputString = inputString.Replace('.', ',');

            if (!decimal.TryParse(inputString, out decimal amount))
            {
                // Ошибка ввода: выводим предупреждение красным цветом
                lblResult.ForeColor = Color.Red;
                lblResult.Text = "Ошибка: введите корректное числовое значение суммы!";
                return;
            }

            if (amount < 0)
            {
                // Проверка на отрицательное число
                lblResult.ForeColor = Color.Red;
                lblResult.Text = "Ошибка: сумма покупки не может быть отрицательной!";
                return;
            }

            // Шаг 2: Определение базового процента скидки по RadioButton
            decimal baseDiscountPercent = 0m;

            if (rb5.Checked)
            {
                baseDiscountPercent = 5.0m;
            }
            else if (rb10.Checked)
            {
                baseDiscountPercent = 10.0m;
            }
            else if (rb20.Checked)
            {
                baseDiscountPercent = 20.0m;
            }

            // Шаг 3: Учет дополнительных условий (CheckBox)
            if (chkCard.Checked)
            {
                baseDiscountPercent += 5.0m;
            }

            // Шаг 4: Вычисления
            // Формула суммы скидки: S_disc = Amount * (Percent / 100)
            decimal discountSum = amount * (baseDiscountPercent / 100.0m);
            
            // Формула итоговой суммы: S_total = Amount - S_disc
            decimal finalSum = amount - discountSum;

            // Шаг 5: Форматирование вывода и динамическое управление цветом
            // Если итоговая сумма больше 5000 рублей, делаем текст зеленым (премиум-покупка)
            if (amount > 5000.0m)
            {
                lblResult.ForeColor = Color.DarkGreen;
            }
            else
            {
                lblResult.ForeColor = Color.Black;
            }

            // Вывод результатов с округлением до 2 знаков после запятой
            lblResult.Text = $"Скидка: {baseDiscountPercent:N1}% ({discountSum:N2} руб.)\n" +
                             $"Итого к оплате: {finalSum:N2} руб.";
        }
    }
}
```

#### Пояснение по строкам и блокам кода
1. **Подписка через оператор `+=`:** Строки вроде `txtAmount.TextChanged += Inputs_Changed;` связывают событие изменения текста с нашим методом `Inputs_Changed`. Обратите внимание, что один и тот же метод `Inputs_Changed` подписан на события `TextChanged` текстового поля, `CheckedChanged` трех переключателей и одного флажка. Это возможно благодаря тому, что все они имеют совместимую сигнатуру обработчика событий (`object sender, EventArgs e`).
2. **Параметр `sender`:** В данном примере мы не используем параметр `sender` внутри обработчика явно, так как нам достаточно проверить состояние каждого элемента напрямую по его имени (`rb5.Checked`, `chkCard.Checked`). Однако в более сложных интерфейсах с десятками одинаковых элементов `sender` позволяет узнать, какой именно компонент вызвал событие, выполнив приведение типов: `RadioButton rb = (RadioButton)sender;`.
3. **Безопасный парсинг `decimal.TryParse`:** Метод не генерирует исключение при попытке пользователя ввести буквы или некорректные символы, а просто возвращает `false`, что позволяет плавно обработать ошибку ввода и вывести подсказку пользователю.
4. **Форматирование строк (`:N2`, `:N1`):** Спецификаторы формата чисел в C# (`N2` выводит число с разделителями тысяч и ровно двумя знаками после запятой) обеспечивают аккуратный финансовый вид вычислений.

#### Пример ввода и вывода

**Пример 1 (штатный ввод):**
- Ввод в `txtAmount`: `4500`
- Выбор: переключатель `10%`, флажок карты **не установлен**.
- Вычисление: Скидка $4500 \times 0{,}10 = 450{,}00$ руб. Итого: $4500 - 450 = 4050{,}00$ руб. Сумма меньше 5000, цвет черный.
- **Вывод в `lblResult`:**
  ```text
  Скидка: 10,0% (450,00 руб.)
  Итого к оплате: 4050,00 руб.
  ```

**Пример 2 (срабатывание порогового условия и бонусной карты):**
- Ввод в `txtAmount`: `6000`
- Выбор: переключатель `20%`, флажок карты **установлен** (+5% бонус).
- Вычисление: Общий процент скидки = $20\% + 5\% = 25\%$. Скидка $6000 \times 0{,}25 = 1500{,}00$ руб. Итого: $6000 - 1500 = 4500{,}00$ руб. Сумма исходной покупки больше 5000, цвет текста меняется на темно-зеленый.
- **Вывод в `lblResult`:**
  ```text
  Скидка: 25,0% (1500,00 руб.)
  Итого к оплате: 4500,00 руб.
  ```

**Пример 3 (некорректный ввод):**
- Ввод в `txtAmount`: `abc`
- Вычисление: `decimal.TryParse` возвращает `false`.
- **Вывод в `lblResult` (красным цветом):**
  ```text
  Ошибка: введите корректное числовое значение суммы!
  ```

#### Оценка сложности
- **Сложность по времени (Time Complexity):** $O(1)$ на каждое действие пользователя, так как арифметические операции и переключение состояний выполняются за константное время.
- **Сложность по памяти (Space Complexity):** $O(1)$ дополнительной памяти, так как создается фиксированное число переменных для хранения промежуточных расчетов.

## 5. Отладка и обработка типичных ошибок при работе с событиями

### 1. Ошибки инициализации и исключение `NullReferenceException`

В процессе разработки приложений на Windows Forms одной из самых распространенных ошибок является `NullReferenceException`. Это исключение возникает тогда, когда программа пытается обратиться к члену объекта (вызвать метод, прочитать или изменить свойство), переменная которого равна `null`, то есть ссылается на несуществующий в памяти объект.

> **Определение.** `NullReferenceException` — это исключение времени выполнения (runtime exception), которое генерируется средой .NET, когда код пытается использовать ссылочную переменную, не указывающую ни на один реальный экземпляр класса в куче (heap).

В контексте работы с элементами управления (контролами) на форме эта ошибка чаще всего происходит по двум причинам:
1. Обращение к элементу управления **до вызова метода `InitializeComponent()`** в конструкторе формы.
2. Обращение к элементу управления после его удаления или закрытия формы, либо если элемент был объявлен в классе, но забыли связать его с визуальным компонентом.

Рассмотрим порядок инициализации формы в C#:

```csharp
public partial class MainForm : Form
{
    public MainForm()
    {
        // Обярзательный вызов. Он создает все элементы управления, 
        // описанные в файле MainForm.Designer.cs, и присваивает их полям класса.
        InitializeComponent(); 

        // Если попытаться обратиться к кнопке ДО InitializeComponent():
        // button1.Text = "Привет"; // Выбросит NullReferenceException, так как button1 еще null!
    }
}
```

Когда вы перетаскиваете элемент управления из Панели элементов (Toolbox) на форму в дизайнере Visual Studio, среда разработки автоматически создает поле для этого элемента в файле `MainForm.Designer.cs` и инициализирует его внутри метода `InitializeComponent()`. Если вы создаете элементы вручную в коде, но забываете вызвать оператор `new` или добавить элемент на форму через коллекцию `Controls.Add()`, вы гарантированно получите `NullReferenceException` при попытке взаимодействия с ним.

### 2. Диагностика проблем с подпиской на события (`+=` и `-=`)

Механизм подписки на события в C# основан на делегатах. Когда вы используете оператор `+=` для подключения обработчика события, вы добавляете метод в список вызовов (invocation list) делегата. Если один и тот же метод подписать на событие дважды, он будет вызван два раза при наступлении этого события.

```csharp
// Двойная подписка на событие клика
button1.Click += Button1_Click;
button1.Click += Button1_Click; // Метод добавлен в список вызовов дважды!
```

**Последствия двойной подписки:**
* При однократном нажатии на кнопку метод `Button1_Click` выполнится два раза подряд. Если этот метод, например, добавляет строку в список или увеличивает счетчик, логика приложения нарушится.
* Если метод выполняет тяжелые операции, приложение начнет беспричинно тормозить.

**Проблема отписанных событий и утечки памяти (Memory Leaks):**
Если короткоживущий объект (например, дочерняя форма или динамически созданный элемент управления) подписывается на событие долгоживущего объекта (например, главного окна приложения или глобального сервиса), то долгоживущий объект хранит ссылку на обработчик дочернего объекта. Из-за этого сборщик мусора (Garbage Collector) не может выгрузить дочерний объект из памяти даже после того, как пользователь закрыл его.

Для предотвращения этого необходимо всегда отписываться от событий (`-=`), когда объект больше не нужен:

```csharp
// Отписываемся от события при закрытии формы или уничтожении объекта
button1.Click -= Button1_Click;
```

### 3. Использование точек останова (Breakpoints) и анализ параметра `sender`

Когда в приложении срабатывает множество однотипных обработчиков (например, десять разных кнопок используют один и тот же метод для изменения цвета фона), возникает задача: как понять, какой именно элемент управления инициировал событие?

Здесь на помощь приходит первый параметр стандартного обработчика событий — `object sender`.

> **Определение.** Параметр `sender` в сигнатуре обработчика событий (`object sender, EventArgs e`) представляет собой ссылку на тот объект, который сгенерировал данное событие (источник события).

Поскольку тип параметра — `object`, для работы с конкретными свойствами элемента управления необходимо выполнить приведение типов (type casting). Безопасное приведение выполняется с помощью оператора `as`:

```csharp
private void AnyButton_Click(object sender, EventArgs e)
{
    // Превращаем object в Button с помощью оператора as
    Button clickedButton = sender as Button;

    // Всегда проверяем на null на случай, если метод вызван не от кнопки
    if (clickedButton != null)
    {
        clickedButton.Text = "Нажали меня!";
        // Меняем цвет именно той кнопки, по которой кликнули
        clickedButton.BackColor = Color.LightGreen; 
    }
}
```

#### Отладка с помощью точек останова (Breakpoints)
Для глубокого анализа состояния программы в момент срабатывания события используются точки останова в Visual Studio:
1. Кликните левой кнопкой мыши по серому полю слева от строки кода внутри обработчика (появится темно-красный круг).
2. Запустите приложение в режиме отладки (`F5`).
3. Выполните действие в интерфейсе (например, нажмите кнопку).
4. Когда выполнение программы остановится на точке останова, наведите курсор мыши на переменную `sender` или откройте окно **Locals** (Локальные переменные) / **Watch** (Контрольные значения).
5. В окне отладки вы увидите реальный тип объекта (например, `System.Windows.Forms.Button`) и сможете развернуть его свойства, чтобы проверить их текущие значения (`Text`, `Name`, `Location` и др.).

### 4. Обработка исключений формата при конвертации пользовательского ввода

Пользовательский ввод в графических интерфейсах — это всегда зона повышенного риска. Текстовое поле (`TextBox`) принимает любые символы: буквы, знаки препинания, пустые строки. Прямое преобразование такого ввода в числовые типы данных с помощью методов `int.Parse()` или `Convert.ToInt32()` при вводе некорректных данных неминуемо приведет к критическому сбою программы — исключению `FormatException` или `OverflowException`.

> **Определение.** `FormatException` — исключение, возникающее при попытке преобразовать строку в числовой тип, если формат строки не соответствует требованиям числа (например, содержит буквы).

#### Разница между `int.Parse` и `int.TryParse`
* `int.Parse(string)` — выбрасывает исключение, если строка не может быть преобразована. Используется только тогда, когда вы на 100% уверены в содержимом строки (например, захардкоженные константы).
* `int.TryParse(string, out int result)` — возвращает логическое значение (`true`, если преобразование прошло успешно, и `false`, если нет), а само преобразованное число записывает в выходной параметр `result`. Исключение при этом **не выбрасывается**.

Правильный шаблон обработки пользовательского ввода:

```csharp
string inputString = textBoxInput.Text;

// Пытаемся конвертировать строку в целое число
if (int.TryParse(inputString, out int number))
{
    // Конвертация успешна, работаем с переменной number
    int result = number * 2;
    labelResult.Text = result.ToString();
}
else
{
    // Конвертация не удалась (введены буквы или пустота)
    MessageBox.Show("Пожалуйста, введите целое число!", "Ошибка ввода", 
        MessageBoxButtons.OK, MessageBoxIcon.Error);
}
```

### 5. Обеспечение потокобезопасности при вызове событий из фоновых потоков

В Windows Forms все элементы управления создаются и обслуживаются в единственном специальном потоке — **потоке пользовательского интерфейса (UI Thread)**. Этот же поток отвечает за отрисовку формы и обработку кликов мыши и нажатий клавиш.

Если вы запустите тяжелую фоновую задачу (например, скачивание файла в отдельном потоке `Task.Run`) и попытаетесь из этого фонового потока изменить свойство `Text` у `Label` или `TextBox`, среда .NET выбросит исключение `InvalidOperationException` с текстом о том, что поток не может управлять элементом управления, созданным в другом потоке.

Для безопасного обновления интерфейса из фонового потока используется метод `Invoke` или `BeginInvoke` с использованием делегата `Action`:

```csharp
// Пример кода, выполняющегося в фоновом потоке:
Task.Run(() => {
    // Какая-то долгая фоновая работа...
    int calculatedValue = 42; 

    // Безопасное обновление UI из фонового потока
    this.Invoke(new Action(() => {
        labelStatus.Text = "Готово: " + calculatedValue;
        labelStatus.ForeColor = Color.Green;
    }));
});
```
*Метод `Invoke` приостанавливает фоновый поток и передает задачу выполнения делегата обратно в UI-поток, обеспечивая строгую потокобезопасность.*

### Разбор комплексного примера: Защищенный калькулятор деления чисел

Разработаем полностью рабочее оконное приложение на C# (Windows Forms, .NET 8), которое выполняет деление двух чисел, введенных пользователем. Программа должна обрабатывать всевозможные ошибки: пустые поля, ввод нечисловых символов (букв, спецсимволов) и деление на ноль, информируя пользователя через `MessageBox` и подсвечивая проблемные элементы управления.

#### Словесное описание формы
На форме расположены:
1. Метка (`Label1`): текст «Делимое (число A):».
2. Текстовое поле (`TextBox1`): для ввода числа A.
3. Метка (`Label2`): текст «Делитель (число B):».
4. Текстовое поле (`TextBox2`): для ввода числа B.
5. Кнопка (`Button1`): текст «Разделить».
6. Метка (`LabelResult`): для вывода результата или статуса ошибки.

#### Полный код формы (`MainForm.cs`)

```csharp
using System;
using System.Drawing;
using System.Windows.Forms;

namespace DivisionApp
{
    public partial class MainForm : Form
    {
        // Элементы управления интерфейса
        private Label labelA;
        private TextBox textBoxA;
        private Label labelB;
        private TextBox textBoxB;
        private Button buttonDivide;
        private Label labelResult;

        public MainForm()
        {
            // Обязательный вызов инициализации компонентов формы
            InitializeComponent();
            
            // Настраиваем элементы управления программно для автономности примера
            SetupCustomComponents();
        }

        private void SetupCustomComponents()
        {
            this.Text = "Защищенный калькулятор деления";
            this.Width = 400;
            this.Height = 300;
            this.StartPosition = FormStartPosition.CenterScreen;

            // Метка и поле для числа A
            labelA = new Label();
            labelA.Text = "Введите делимое (A):";
            labelA.Location = new Point(30, 30);
            labelA.AutoSize = true;
            this.Controls.Add(labelA);

            textBoxA = new TextBox();
            textBoxA.Location = new Point(30, 55);
            textBoxA.Width = 320;
            this.Controls.Add(textBoxA);

            // Метка и поле для числа B
            labelB = new Label();
            labelB.Text = "Введите делитель (B):";
            labelB.Location = new Point(30, 95);
            labelB.AutoSize = true;
            this.Controls.Add(labelB);

            textBoxB = new TextBox();
            textBoxB.Location = new Point(30, 120);
            textBoxB.Width = 320;
            this.Controls.Add(textBoxB);

            // Кнопка расчета
            buttonDivide = new Button();
            buttonDivide.Text = "Выполнить деление";
            buttonDivide.Location = new Point(30, 160);
            buttonDivide.Width = 320;
            buttonDivide.Height = 35;
            // Подписываемся на событие нажатия кнопки через оператор +=
            buttonDivide.Click += ButtonDivide_Click;
            this.Controls.Add(buttonDivide);

            // Метка результата
            labelResult = new Label();
            labelResult.Text = "Результат появится здесь";
            labelResult.Location = new Point(30, 210);
            labelResult.AutoSize = true;
            labelResult.Font = new Font("Arial", 10, FontStyle.Bold);
            this.Controls.Add(labelResult);
        }

        /// <summary>
        /// Обработчик события нажатия на кнопку деления
        /// </summary>
        private void ButtonDivide_Click(object sender, EventArgs e)
        {
            // Сбрасываем цвет меток в исходное состояние
            labelA.ForeColor = Color.Black;
            labelB.ForeColor = Color.Black;

            // Шаг 1. Безопасное парсим первое число (double для поддержки дробных чисел)
            if (!double.TryParse(textBoxA.Text, out double a))
            {
                // Если парсинг не удался, подсвечиваем поле и выдаем ошибку
                labelA.ForeColor = Color.Red;
                MessageBox.Show(
                    "В поле делимого (A) введено некорректное значение! Пожалуйста, используйте только цифры.", 
                    "Ошибка формата", 
                    MessageBoxButtons.OK, 
                    MessageBoxIcon.Warning
                );
                textBoxA.Focus(); // Возвращаем фокус ввода в ошибочное поле
                return; // Прерываем выполнение метода
            }

            // Шаг 2. Безопасный парсим второе число
            if (!double.TryParse(textBoxB.Text, out double b))
            {
                labelB.ForeColor = Color.Red;
                MessageBox.Show(
                    "В поле делителя (B) введено некорректное значение! Пожалуйста, используйте только цифры.", 
                    "Ошибка формата", 
                    MessageBoxButtons.OK, 
                    MessageBoxIcon.Warning
                );
                textBoxB.Focus();
                return;
            }

            // Шаг 3. Проверка деления на ноль
            // Так как работаем с типами double, проверка b == 0.0 корректна. 
            // Для целых типов int проверка выглядела бы аналогично: b == 0
            if (b == 0.0)
            {
                labelB.ForeColor = Color.Red;
                MessageBox.Show(
                    "Деление на ноль запрещено математическими правилами!", 
                    "Ошибка вычислений", 
                    MessageBoxButtons.OK, 
                    MessageBoxIcon.Error
                );
                textBoxB.Focus();
                return;
            }

            // Шаг 4. Выполнение расчета, если все проверки пройдены успешно
            double result = a / b;

            // Вывод результата с форматированием до 4 знаков после запятой
            labelResult.Text = $"Результат: {a} / {b} = {result:F4}";
            labelResult.ForeColor = Color.DarkGreen;
        }
    }
}
```

#### Ход рассуждений и логика решения
1. **Предотвращение исключений ввода (`double.TryParse`):** Мы не используем `double.Parse()`. Если пользователь введет букву `абв` или оставит поле пустым, `double.TryParse` вернет `false`, программа не упадет, а выведет понятную диагностику.
2. **Анализ источника через `sender`:** В нашем примере кнопка одна, но если бы таких кнопок было несколько, мы могли бы написать `Button btn = sender as Button;` и управлять ее свойствами универсально.
3. **Обработка математических ограничений:** Перед выполнением операции деления (`a / b`) мы строго проверяем `b == 0.0`. Это защищает нас от получения бесконечности (`Infinity`) или некорректных состояний интерфейса.
4. **Улучшение UX (пользовательского опыта):** Помимо `MessageBox`, мы меняем цвет текста метки (`labelA` или `labelB`) на красный и вызываем метод `textBox.Focus()`, чтобы пользователь сразу видел, какое именно поле вызвало ошибку, и мог исправить ввод без лишних кликов мышью.

#### Проверка и правдоподобность
* **Тест 1 (Успешный ввод):** $A = 10$, $B = 4$. `double.TryParse` возвращает `true` для обоих полей. $10 / 4 = 2{,}5$. В `labelResult` выводится: `Результат: 10 / 4 = 2{,}5000` зеленым цветом.
* **Тест 2 (Ввод букв):** $A = \text{"привет"}$, $B = 5$. Первый `TryParse` возвращает `false`. Срабатывает `MessageBox` с предупреждением, метка `labelA окрашивается в красный, фокус переносится на первое текстовое поле. Исключение не выброшено, приложение продолжает работу.
* **Тест 3 (Деление на ноль):** $A = 100$, $B = 0$. Проверки `TryParse` пройдены ($a = 100$, $b = 0$). Срабатывает проверка `b == 0.0`. Вызывается `MessageBox` с иконкой ошибки `Error`, метка `labelB` становится красной. Деление не выполняется.

Ответ: приложение полностью устойчиво к некорректному пользовательскому вводу, не генерирует необрабатываемых исключений `FormatException` и `NullReferenceException`, корректно управляет свойствами элементов управления (`Text`, `ForeColor`, `Focus`) через обработчик событий кнопки.

## Типичные ошибки

1. **Забытая проверка на `null` при вызове или кастомной реализации событий.**
   * **Ошибка:** Вызов события напрямую без проверки `if (MyEvent != null)` (или условного оператора с null-условным оператором `MyEvent?.Invoke(this, e)`), когда на событие никто не подписался.
   * **Причина:** Значение делегата по умолчанию равно `null`. Попытка вызова такого делегата приводит к аварийному завершению программы с исключением `NullReferenceException`.
   * **Как избежать:** Всегда проверяйте делегат на `null` перед вызовом или используйте синтаксис `?.Invoke()`.
   * *Пример:* `Click?.Invoke(this, EventArgs.Empty);`

2. **Неверная сигнатура метода-обработчика.**
   * **Ошибка:** Попытка подписать на событие метод со случайным набором параметров (например, `void MyMethod(int x)`).
   * **Причина:** Сигнатура метода не совпадает со строгим контрактом делегата `EventHandler` (`object sender, EventArgs e`).
   * **Как избежать:** Помните стандарт .NET: первый аргумент — `object sender`, второй — `EventArgs` (или его производные). Используйте автогенерацию через Visual Studio (двойной щелчок или вкладку «Молния»).
   * *Пример:* `private void button1_Click(object sender, EventArgs e) { ... }`

3. **Создание бесконечного цикла событий (`StackOverflowException`).**
   * **Ошибка:** Изменение свойства элемента управления внутри обработчика события, которое реагирует именно на изменение этого свойства.
   * **Причина:** Например, в событии `TextChanged` текстового поля вы программно присваиваете новое значение `textBox1.Text = ...`, что немедленно генерирует новое событие `TextChanged` и вызывает тот же метод снова.
   * **Как избежать:** Всегда проверяйте условие: изменилось ли значение на самом деле, прежде чем присваивать его повторно.
   * *Пример:* 
     ```csharp
     if (textBox1.Text != newValue) 
     { 
         textBox1.Text = newValue; // безопасно только с проверкой
     }
     ```

4. **Прямое присвоение строки из `TextBox` в числовую переменную без валидации.**
   * **Ошибка:** Использование `int.Parse(textBox1.Text)` без предварительной проверки содержимого.
   * **Причина:** Пользователь может ввести буквы, символы или оставить поле пустым, что вызовет исключение `FormatException`.
   * **Как избежать:** Всегда используйте безопасные методы конвертации `int.TryParse()` или `decimal.TryParse()`.
   * *Пример:* 
     ```csharp
     if (int.TryParse(textBox1.Text, out int result)) { /* ок */ }
     ```

5. **Попытка отписаться от события с помощью анонимного метода или лямбда-выражения через `-=`**
   * **Ошибка:** Написание кода вида `button1.Click -= (s, e) => { };`.
   * **Причина:** Лямбда-выражение создает безымянный объект делегата в памяти. Выражение, переданное в `-=`, является совершенно другим объектом в памяти, чем то, что передавалось в `+=`, поэтому отписка не срабатывает.
   * **Как избежать:** Сохраняйте лямбда-выражения или анонимные методы в переменные-делегаты уровня класса, если в будущем планируете отписываться от события.

6. **Обращение к элементам управления до вызова `InitializeComponent()`**
   * **Ошибка:** Попытка настроить текст или свойства кнопки в конструкторе формы *до* вызова метода `InitializeComponent()`.
   * **Причина:** До этого момента объекты элементов управления еще не выделены в памяти и равны `null`.
   * **Как избежать:** Всегда размещайте свой код настройки интерфейса в конструкторе формы **строго после** вызова `InitializeComponent();`.

7. **Изменение элементов управления из посторонних потоков без использования `Invoke`**
   * **Ошибка:** Обновление свойств `Text` или `Enabled` элемента формы из фонового потока (`Task` или `Thread`).
   * **Причина:** Элементы Windows Forms принадлежат главному потоку интерфейса (UI Thread). Прямой доступ из других потоков нарушает потокобезопасность.
   * **Как избежать:** Используйте метод `Invoke` или `BeginInvoke` для передачи инструкций в главный поток.

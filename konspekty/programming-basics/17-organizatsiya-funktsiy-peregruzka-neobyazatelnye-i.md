## Понятие перегрузки методов (Method Overloading): сигнатура и правила разрешения

### Понятие перегрузки методов (Method Overloading)

В процессе разработки программ часто возникает задача выполнения схожих по смыслу операций над данными разных типов или разного количества. Например, нам нужно найти максимум: для двух целых чисел, для трех целых чисел, для чисел с плавающей точкой или для элементов массива. В языках программирования без поддержки полиморфизма пришлось бы создавать методы с разными именами: `MaxInt2`, `MaxInt3`, `MaxDouble` и так далее. Это сильно усложняет запоминание имен и загромождает код.

Язык C# поддерживает механизм **перегрузки методов (Method Overloading)**, который позволяет создавать в пределах одной области видимости (например, внутри одного класса) несколько методов с **одним и тем же именем**, но с **различающимися наборами параметров**.

> **Определение.** Перегрузка методов — это свойство языков программирования, реализующее полиморфизм времени компиляции (статический полиморфизм), при котором имя метода связывается с несколькими различными реализациями в зависимости от сигнатуры вызова.

Простыми словами: вы даете методам одно и то же интуитивно понятное имя (например, `Print` или `CalculateArea`), а компилятор сам на этапе сборки программы определяет, какую именно версию метода нужно запустить, глядя на то, какие аргументы вы передали при вызове.

### Сигнатура метода

Чтобы компилятор мог различить перегруженные методы, он использует такое понятие, как сигнатура.

> **Определение.** Сигнатура метода (method signature) — это уникальная часть объявления метода, состоящая из его **имени** и **списка параметров** (количество параметров, их типы и порядок следования, а также модификаторы параметров `ref`, `out`, `in`).

Важно четко понимать, что входит в сигнатуру, а что игнорируется компилятором при поиске перегрузки.

| Элемент объявления метода | Входит ли в сигнатуру? | Объяснение |
|---------------------------|------------------------|------------|
| Имя метода | Да | Базовый идентификатор метода. |
| Типы параметров | Да | Порядок и типы входящих данных (`int`, `string`, `double` и т.д.). |
| Количество параметров | Да | Общее число элементов в круглых скобках. |
| Модификаторы параметров (`ref`, `out`, `in`) | Да | Метод с `ref int x` и метод с `int x` имеют разные сигнатуры. |
| Тип возвращаемого значения | **Нет** | Компилятор не может определить вызываемый метод только по тому, куда записывается результат (например, `int Foo()` и `double Foo()` с одинаковыми параметрами вызовут ошибку компиляции). |
| Имена формальных параметров | **Нет** | Имена переменных внутри круглых скобок (`int a` против `int b`) роли не играют. |

Рассмотрим примеры неверного переопределения (код вызовет ошибку компиляции CS0111 "Тип уже определяет член с такими же параметрами"):

```csharp
// Ошибка! Разница только в типе возвращаемого значения
int GetData(int id);
string GetData(int id); 

// Ошибка! Разница только в именах параметров
void Process(int x, string name);
void Process(int a, string text); 
```

### Правила разрешения перегрузки (Overload Resolution)

Когда вы пишете вызов метода, например, `Calculate(5)`, компилятор выполняет процесс, называемый **разрешением перегрузки**. Он анализирует все доступные методы с именем `Calculate` и выбирает наилучший по определенным правилам:

1. **Точное совпадение (Exact match):** Если есть метод, типы параметров которого идеально совпадают с типами переданных аргументов, выбирается он.
2. **Неявное расширяющее приведение (Implicit widening conversions):** Если точного совпадения нет, компилятор ищет метод, для которого типы аргументов могут быть неявно расширены (например, из `int` в `double`, из `int` в `long`).
3. **Упаковка (Boxing):** Преобразование типов значений в тип `object`.
4. Если подходящих методов найдено несколько (например, аргумент можно привести к двум разным типам без явного приоритета) или не найдено ни одного, компилятор выдает **ошибку неоднозначности** (Ambiguous invocation) или ошибку отсутствия подходящего метода.

### Разобранный пример 1: Вычисление площадей фигуркок

Рассмотрим задачу: спроектировать статический класс с перегруженными методами `CalculateArea`, способными находить площадь квадрата (принимает сторону как `int`), прямоугольника (принимает две стороны как `int`) и круга (принимает радиус как `double`).

#### Ход рассуждений
1. Имя метода во всех трех случаях должно быть одинаковым: `CalculateArea`.
2. Первый метод (квадрат) принимает 1 аргумент типа `int`. Формула площади: $S = a^2$.
3. Второй метод (прямоугольник) принимает 2 аргумента типа `int`. Формула площади: $S = a \cdot b$.
4. Третий метод (круг) принимает 1 аргумент типа `double`. Формула площади: $S = \pi \cdot r^2$. (В C# значение $\pi$ доступно через константу `Math.PI`).
5. Сигнатуры всех трех методов уникальны, поэтому конфликтов не возникнет.

#### Полный исходный код программы

```csharp
using System;

class Program
{
    // Метод 1: Площадь квадрата
    static int CalculateArea(int side)
    {
        Console.WriteLine("Вызван метод для квадрата.");
        return side * side;
    }

    // Метод 2: Площадь прямоугольника
    static int CalculateArea(int width, int height)
    {
        Console.WriteLine("Вызван метод для прямоугольника.");
        return width * height;
    }

    // Метод 3: Площадь круга
    static double CalculateArea(double radius)
    {
        Console.WriteLine("Вызван метод для круга.");
        return Math.PI * radius * radius;
    }

    static void Main(string[] args)
    {
        // Вызов метода для квадрата (передаем 1 целое число)
        int squareArea = CalculateArea(5);
        Console.WriteLine($"Площадь квадрата со стороной 5 равна: {squareArea}\n");

        // Вызов метода для прямоугольника (передаем 2 целых числа)
        int rectangleArea = CalculateArea(4, 6);
        Console.WriteLine($"Площадь прямоугольника 4x6 равна: {rectangleArea}\n");

        // Вызов метода для круга (передаем число с плавающей точкой)
        double circleArea = CalculateArea(3.0);
        Console.WriteLine($"Площадь круга с радиусом 3,0 равна: {circleArea:F2}");
    }
}
```

#### Пояснение по строкам кода
- Строки 5, 12, 19 — объявления трех перегруженных методов. Их сигнатуры (`CalculateArea(int)`, `CalculateArea(int, int)`, `CalculateArea(double)`) различаются количеством параметров или их типами.
- Строка 28 — компилятор видит один целочисленный аргумент `5` и вызывает метод №1.
- Строка 32 — компилятор видит два целочисленных аргумента `4` и `6` и вызывает метод №2.
- Строка 36 — компилятор видит аргумент с плавающей точкой `3.0` (литерал типа `double`) и вызывает метод №3. Форматирование `{circleArea:F2}` выводит число с двумя знаками после запятой.

#### Пример ввода и вывода
**Вывод в консоли:**
```text
Вызван метод для квадрата.
Площадь квадрата со стороной 5 равна: 25

Вызван метод для прямоугольника.
Площадь прямоугольника 4x6 равна: 24

Вызван метод для круга.
Площадь круга с радиусом 3,0 равна: 28{,}27
```
*(Примечание: в Windows-консоли разделитель может зависеть от локали, но математическое значение вычислено верно: $3{,}1415926535... \cdot 9 \approx 28{,}2743$).*

### Разобранный пример 2: Анализ неоднозначности и неявного приведения типов

Рассмотрим более сложный случай, с которым часто сталкиваются начинающие программисты при работе с числовыми типами.

Пусть у нас объявлены два метода:
```csharp
static void Print(int x)
{
    Console.WriteLine($"Печать int: {x}");
}

static void Print(double x)
{
    Console.WriteLine($"Печать double: {x}");
}
```

#### Вопросы для анализа:
1. Какой метод выполнится, если вызвать `Print(10);`?
2. Что произойдет, если вызвать `Print(10.5);`?
3. Что произойдет, если попытаться вызвать `Print` с литералом типа `double` или переменной `double`, когда в наличии есть только метод `Print(int)`?

#### Разбор ситуации компилятором:
1. При вызове `Print(10);` аргумент `10` является целочисленным литералом типа `int`. В классе есть точное совпадение — метод `Print(int x)`. Компилятор выбирает его без раздумий.
2. При вызове `Print(10.5);` аргумент `10.5` имеет тип `double`. Точного совпадения с `Print(int)` нет. Однако тип `double` может быть неявно приведен к `int`? **Нет!** Преобразование `double` в `int` является сужающим (lossy conversion) и может привести к потере дробной части, поэтому язык C# **запрещает** неявное сужение. Но в нашем случае есть перегрузка `Print(double x)`, которая дает точное совпадение. Следовательно, вызывается `Print(double)`.
3. Предположим, метода `Print(double)` в коде нет, а есть только `Print(int x)`. Если мы напишем `Print(10.5);`, компилятор выдаст ошибку: 
   `CS1503: Аргумент 1: не удается преобразовать из "double" в "int"`. 
   Компилятор не имеет права автоматически отбросить дробную часть числа, разработчик должен сделать это явно (выполнив приведение типов: `Print((int)10.5);`).

#### Полный код демонстрации

```csharp
using System;

class Program
{
    static void Print(int x)
    {
        Console.WriteLine($"[Метод INT] Получено целое число: {x}");
    }

    static void Print(double x)
    {
        Console.WriteLine($"[Метод DOUBLE] Получено вещественное число: {x}");
    }

    static void Main(string[] args)
    {
        // 1. Целочисленный литерал вызывает метод для int
        Print(42);

        // 2. Вещественный литерал вызывает метод для double
        Print(42.0);

        // 3. Выражение со знаком деления целых дает int
        Print(10 / 3); // Вызовется Print(int) со значением 3

        // 4. Явное приведение типов позволяет принудительно выбрать метод Print(int) для вещественного числа
        Print((int)15.9);
    }
}
```

#### Пример вывода программы
```text
[Метод INT] Получено целое число: 42
[Метод DOUBLE] Получено вещественное число: 42
[Метод INT] Получено целое число: 3
[Метод INT] Получено целое число: 15
```

#### Проверка и выводы
- Использование перегрузки позволяет писать чистый код, избавляя от необходимости запоминать разные названия для одинаковых по сути действий (вывод на экран, расчет, конвертация).
- Всегда помните о правилах приведения типов в C#: если вы передаете в перегруженный метод значение меньшей емкости (`int`), оно может автоматически расшириться до большей (`long`, `double`), если нет точного совпадения сигнатуры. Обратное автоматическое расширение/сужение невозможно.

## Необязательные параметры (Optional Parameters) и значения по умолчанию

### Синтаксис объявления необязательных параметров и значения по умолчанию

При проектировании методов часто возникает ситуация, когда часть передаваемых данных имеет стандартное, наиболее часто используемое значение. Например, при создании пользователя в системе его возраст по умолчанию может быть равен 18 годам, а статус активности — истинному значению (`true`). В языках программирования ранних поколений для этого приходилось создавать несколько перегруженных версий одного и того же метода. В C# предусмотрен более элегантный механизм — **необязательные параметры** (optional parameters).

> **Определение.** *Необязательный параметр* — это параметр метода, которому при объявлении присваивается значение по умолчанию. Если вызывающий код не передает аргумент для этого параметра, компилятор автоматически подставляет указанное значение по умолчанию.

Рассмотрим синтаксис объявления необязательного параметра. Для этого в сигнатуре метода после имени параметра и его типа ставится знак равенства `=`, за которым следует само значение по умолчанию:

```csharp
public static void PrintMessage(string message, int repeatCount = 1)
{
    for (int i = 0; i < repeatCount; i++)
    {
        Console.WriteLine(message);
    }
}
```

В данном примере параметр `message` является обязательным, так как у него нет значения по умолчанию. Параметр `repeatCount` — необязательный, его значение по умолчанию равно `1`. 

Возможны следующие варианты вызова этого метода:
1. `PrintMessage("Привет", 3);` — переданы оба аргумента. Метод выведет строку три раза.
2. `PrintMessage("Привет");` — передан только обязательный аргумент. Компилятор подставит для второго параметра значение `1`, и метод выведет строку один раз.

### Ограничение порядка параметров

Правила языка C# накладывают строгое ограничение на порядок расположения параметров в сигнатуре метода:

> **Правило порядка параметров.** Все обязательные параметры метода должны располагаться в списке параметров *перед* любыми необязательными параметрами.

Нарушение этого правила приводит к ошибке компиляции. Посмотрим, почему это требование является логически необходимым. Представим гипотетическую ситуацию (запрещенную компилятором), в которой сначала идет необязательный параметр, а затем обязательный:

```csharp
// ОШИБКА КОМПИЛЯЦИИ: Нельзя размещать обязательный параметр после необязательного
public static void BadMethod(int optionalParam = 5, int requiredParam)
{
    // тело метода
}
```

Если бы такой вызов был разрешен, то при вызове метода из клиентского кода `BadMethod(10);` возникла бы неразрешимая двусмысленность (амбивалентность): к какому именно параметру относится переданное число `10`? Компилятор не смог бы определить, предназначено ли оно для первого параметра (`optionalParam`) с переопределением значения по умолчанию или для второго обязательного параметра (`requiredParam`). 

Поэтому действует железное правило: слева направо сначала перечисляются все обязательные параметры, а затем — все необязательные. Если у метода несколько необязательных параметров, их также можно опускать при вызове, но делать это разрешено только справа налево (об этом подробно пойдет речь далее).

### Требования к значениям по умолчанию

Значения, которые указываются по умолчанию для необязательных параметров, не могут быть произвольными выражениями. 

> **Требование к значению.** Значение по умолчанию для параметра метода должно быть **константой времени компиляции** (compile-time constant).

Это означает, что в качестве значения по умолчанию разрешено использовать:
- Литералы базовых типов данных (числа: `10`, `3{,}14`, строки: `"текст"`, символы: `'a'`, логические значения: `true`, `false`);
- Константы, объявленные с ключевым словом `const`;
- Значение `null` для ссылочных типов и типов, допускающих значение null (`Nullable<T>`, например, `int? x = null`);
- Выражения создания объекта через оператор `new` для некоторых типов (например, константные структуры или вызовы конструкторов без параметров, если это разрешено спецификацией языка для конкретных версий .NET).

Запрещено использовать в качестве значений по умолчанию результаты выполнения методов, вычисление динамических выражений, локальные переменные или неконстантные поля объектов. Компилятор должен точно знать точное бинарное представление значения в момент компиляции кода.

### Механизм подстановки значений компилятором

Важно понимать, как именно работает механизм необязательных параметров «под капотом» во время компиляции и выполнения программ. 

Когда программист пишет вызов метода, опускающий необязательные параметры, компилятор C# выполняет статическую подстановку. На уровне промежуточного языка IL (Intermediate Language) и результирующего бинарного файла не происходит динамического разрешения параметров во время выполнения программы (runtime). 

Компилятор берет значение по умолчанию, прописанное в определении вызываемого метода, и самостоятельно дописывает его в инструкцию вызова в вызывающем коде. 

```csharp
// Исходный код, написанный разработчиком:
// Вызываем метод, опустив необязательный параметр
ProcessData(42);

// Код, который фактически генерирует компилятор под капотом:
// Компилятор подставил значение по умолчанию (например, false) явно
ProcessData(42, false);
```

Из этого технического нюанса вытекает важное архитектурное следствие: **проблема хрупкости сборки при изменении библиотек (Assembly Versioning)**. Если вы создаете стороннюю библиотеку классов ( DLL), используемую другими разработчиками, и меняете значение по умолчанию для какого-либо необязательного параметра, то все клиентские приложения, которые ссылаются на эту библиотеку, **обязаны быть перекомпилированы**. Если клиентское приложение не перекомпилировать, оно продолжит использовать старое значение по умолчанию, которое «вшилось» в его IL-код при предыдущей компиляции.

### Взаимодействие перегрузки методов и параметров по умолчанию

Необязательные параметры тесно связаны с темой перегрузки методов. Иногда возникает соблазн решить задачу либо с помощью перегрузки методов, либо с помощью одного метода с необязательными параметрами. Важно понимать правила, по которым компилятор выбирает нужный метод, когда эти два механизма пересекаются.

> **Правило разрешения перегрузки с необязательными параметрами.** Если в классе существуют несколько перегруженных методов, и один из них может быть вызван с использованием значений по умолчанию, компилятор производит поиск наиболее точного соответствия (best match).

Приоритет выбора компилятора устроен следующим образом:
1. **Точное совпадение сигнатур.** Если вызываемый код передает ровно столько аргументов, сколько параметров у конкретной перегрузки без учета значений по умолчанию, приоритет отдается перегрузке с точным количеством параметров.
2. **Неоднозначность (Ambiguity).** Если сигнатуры перегрузок пересекаются таким образом, что подходят под вызов с учетом подстановки значений по умолчанию для нескольких методов одновременно, компилятор выдает ошибку неоднозначности (`Ambiguous overload`), отказываясь компилировать код.

Рассмотрим пример потенциального конфликта:

```csharp
public class Calculator
{
    // Перегрузка 1
    public static int Add(int a, int b = 0)
    {
        return a + b;
    }

    // Перегрузка 2
    public static int Add(int a, int b, int c = 0)
    {
        return a + b + c;
    }
}
```

Если мы вызовем метод `Calculator.Add(5, 10);`, компилятор проанализирует доступные варианты:
- Подходит ли Перегрузка 1? Да, если передать `a = 5`, а для `b` подставить значение аргумента `10`.
- Подходит ли Перегрузка 2? Нет, так как Перегрузка 2 требует минимум два явных аргумента помимо `a` и `b` (всего три параметра: `a`, `b`, а `c` имеет значение по умолчанию). В данном случае мы передали ровно два аргумента (`5` и `10`), что идеально совпадает с параметрами `a` и `b` во Второй перегрузке напрямую (без задействования необязательного параметра `c`). 

Однако если написать метод с одним параметром `Calculator.Add(5);`, то под Первую перегрузку он подходит идеально (`a = 5`, `b` берется по умолчанию как `0`). Вторую перегрузку вызвать с одним аргументом нельзя, так как у нее два обязательных параметра (`a` и `b`). Конфликта не возникает.

### Разбор примеров

#### Пример 1: Создание пользователей с разным набором параметров

**Условие задачи:**
Написать статический метод `CreateUser`, принимающий обязательное имя (тип `string`) и необязательные параметры: возраст (тип `int`, по умолчанию равен `18`) и статус активности (тип `bool`, по умолчанию равен `true`). Вызвать этот метод тремя разными способами:
1. Со всеми переданными аргументами (имя, возраст, статус).
2. Только с обязательным аргументом (имя).
3. С именем и возрастом, оставив статус активности по умолчанию.

**Рисунок (схема) вызова методов:**
```text
[ Вызов 1: все аргументы ] ---> CreateUser("Алексей", 25, false) 
                                      │
                                      ▼
                                Имя: "Алексей", Возраст: 25, Активен: false

[ Вызов 2: только имя ]    ---> CreateUser("Мария")

                                      ▼
```

**Ход рассуждений:**
1. Объявляем класс и статический метод `CreateUser`. Согласно правилам синтаксиса, сначала идет обязательный параметр `string name`. Затем идут необязательные параметры: `int age = 18` и `bool isActive = true`. Обязательный параметр расположен слева, необязательные — справа.
2. Внутри метода выводим информацию о созданном пользователе в консоль для наглядности демонстрации работы.
3. В методе `Main` реализуем три последовательных вызова с разным количеством передаваемых аргументов.

**Решение на C#:**

```csharp
using System;

public class Program
```

- Программа скомпилируется без ошибок, так как порядок параметров корректен (обязательный `name` идет первым).
- При запуске программы в консоли появится следующий текст:

#### Пример 2: Расчет стоимости товара со скидкой и налогом

**Условие задачи:**
Создать статический метод `CalculatePrice`, вычисляющий итоговую стоимость товара с учетом скидки и налога. 
- Базовая цена товара является обязательным параметром (тип `decimal`).
- Скидка является необязательным параметром (тип `decimal`, по умолчанию равна `0m` — без скидки).
- Налог является необязательным параметром (тип `decimal`, по умолчанию равен `20m`, что означает 20%).

Формула расчета итоговой стоимости:
$$Price_{total} = (Price_{base} - Discount) \times \left(1 + \frac{TaxRate}{100}\right)$$

Вычислить и вывести итоговую стоимость для товара с базовой ценой `1500` рублей при стандартных значениях скидки и налога.

**Рисунок (схема) расчетов:**
```text
Входные данные: 
  Базовая цена (Price_base) = 1500 руб.
  Скидка (Discount)         = 0 руб. (по умолчанию)
  Налог (TaxRate)           = 20%  (по умолчанию)

Шаг 1: Применение скидки
  1500 - 0 = 1500 руб.

Шаг 2: Начисление налога (20%)
  1500 * (1 + 20 / 100) = 1500 * 1{,}2 = 1800 руб.

Итоговый результат: 1800 руб.
```

**Ход рассуждений:**
1. Тип данных для денежных сумм выбран `decimal`, так как он обладает высокой точностью для финансовых расчетов и исключает погрешности округления, свойственные типам с плавающей точкой (`double`/`float`).
2. Сигнатура метода выглядит следующим образом: `public static decimal CalculatePrice(decimal basePrice, decimal discount = 0m, decimal taxPercent = 20m)`. Обязательный параметр `basePrice` стоит на первом месте.
3. Внутри метода реализуем математический расчет: сначала из базовой цены вычитаем скидку. Затем полученную промежуточную сумму умножаем на коэффициент налога. Коэффициент вычисляется как единица плюс процент налога, деленный на 100.
4. Вызываем метод для товара ценой `1500m` без передачи необязательных параметров (они подставятся автоматически).

**Решение на C#:**

```csharp
using System;

public class Program
{
    // Метод для расчета итоговой цены товара
    public static decimal CalculatePrice(decimal basePrice, decimal discount = 0m, decimal taxPercent = 20m)
    {
        // Защита от некорректных данных: скидка не может быть больше базовой цены
        decimal priceAfterDiscount = basePrice - discount;
        if (priceAfterDiscount < 0m)
        {
            priceAfterDiscount = 0m;
        }

        // Вычисление итоговой стоимости с учетом налога
        decimal finalPrice = priceAfterDiscount * (1.0m + taxPercent / 100.0m);
        return finalPrice;
    }

    public static decimal CalculatePrice(decimal basePrice, decimal discount)
    {
        return CalculatePrice(basePrice, discount, 20m);
    }

    public static void Main()
    {
        decimal initialPrice = 1500.0m;

        // Вызываем метод, передавая только обязательную цену. 
        // Скидка применится как 0, налог — как 20%
        decimal result = CalculatePrice(initialPrice);

        Console.WriteLine($"Базовая цена товара: {initialPrice} руб.");
        Console.WriteLine($"Итоговая цена с учетом налогов и скидок по умолчанию: {result} руб.");
    }
}
```

**Проверка и вычисление:**
- Подставим числовые значения вручную:
  $$\text{Итог} = (1500 - 0) \times \left(1 + \frac{20}{100}\right) = 1500 \times (1 + 0{,}2) = 1500 \times 1{,}2 = 1800{,}00$$
- Вычисления выполняются корректно. Суффикс `m` у литералов обозначает тип данных `decimal`.
- Строка `Ответ:` подводит итог работы программы.

`Ответ:` Итоговая стоимость товара ценой 1500 рублей при стандартной скидке 0 рублей и налоге 20% составляет 1800,00 рублей.

## Именованные аргументы (Named Arguments) и их синтаксис

### Назначение именованных аргументов и их синтаксис

При разработке приложений часто приходится создавать методы, принимающие множество параметров. Рассмотрим ситуацию, когда метод принимает пять или более аргументов одного типа, например, несколько строк или чисел. При вызове такого метода без дополнительных средств программисту приходится сверяться с определением метода, чтобы понять, какое именно значение за что отвечает. 

> **Определение.** Именованные аргументы (Named Arguments) — это механизм языка C#, позволяющий при вызове метода явно указывать имя параметра для каждого передаваемого аргумента, используя двоеточие.

Главная цель использования именованных аргументов — радикальное повышение читаемости кода. Читая строку вызова метода `Connect(server: "192.168.1.1", port: 8080);`, вы мгновенно понимаете смысл каждого значения без необходимости открывать исходный код самого метода.

Синтаксис вызова метода с именованными аргументами выглядит следующим образом:

```csharp
ИмяМетода(имя_параметра_1: значение_1, имя_параметра_2: значение_2);
```

Между двоеточием и передаваемым значением принято ставить пробел для улучшения читаемости. Имена параметров должны точно совпадать с теми именами, которые указаны в сигнатуре (объявлении) метода. Регистр символов имеет значение, так как C# является регистрозависимым языком.

### Свободный порядок передачи аргументов

Одним из ключевых преимуществ именованных аргументов является независимость порядка их передачи от порядка следования параметров в сигнатуре метода. 

Когда вы используете обычные (позиционные) аргументы, компилятор сопоставляет их строго по порядку: первый аргумент попадает в первый параметр, второй — во второй и так далее. При использовании именованных аргументов порядок следования в круглых скобках при вызове может быть абсолютно любым. Компилятор самостоятельно свяжет переданное значение с нужным параметром по его имени.

Рассмотрим первый разобранный пример: проектирование и вызов метода настройки сетевого соединения.

#### Пример 1: Настройка сетевого соединения

**Условие:**
Создать статический метод `ConfigureConnection`, который принимает пять параметров:
1. `string server` — адрес сервера;
2. `int port` — номер порта;
3. `string protocol` — используемый протокол;
4. `int timeout` — время ожидания ответа в миллисекундах;
5. `bool useSsl` — флаг использования шифрования SSL.

Метод должен выводить на консоль значения всех полученных параметров в читаемом виде. Вызвать этот метод из `Main`, используя именованные аргументы в порядке, полностью отличном от порядка объявления параметров в сигнатуре.

**Рисунок словами (схема работы):**
В памяти программы объявляется метод с фиксированным порядком параметров. В точке вызова формируется список аргументов, где перед каждым значением через двоеточие пишется имя целевой переменной. Выполняющая среда .NET сопоставляет имена во время компиляции, исключая любые ошибки перестановки данных.

**Ход рассуждений:**
1. Объявляем класс `Program` и статический метод `ConfigureConnection` с возвращаемым типом `void`.
2. В сигнатуре метода задаем параметры в логическом порядке разработчика: `server`, `port`, `protocol`, `timeout`, `useSsl`.
3. Внутри метода выводим значения на консоль с помощью интерполяции строк.
4. В методе `Main` вызываем `ConfigureConnection`, передавая аргументы в произвольном порядке — например, сначала `useSsl`, затем `timeout`, `server`, `protocol` и в конце `port`.

**Решение на C#:**

```csharp
using System;

class Program
{
    // Определение метода с пятью параметрами
    static void ConfigureConnection(string server, int port, string protocol, int timeout, bool useSsl)
    {
        Console.WriteLine($"Сервер: {server}");
        Console.WriteLine($"Порт: {port}");
        Console.WriteLine($"Протокол: {protocol}");
        Console.WriteLine($"Таймаут: {timeout} мс");
        Console.WriteLine($"Использование SSL: {useSsl}");
    }

    static void Main()
    {
        Console.WriteLine("Запуск конфигурации соединения...");

        // Вызов метода с использованием именованных аргументов в произвольном порядке
        ConfigureConnection(
            useSsl: true,
            timeout: 3000,
            server: "api.example.com",
            protocol: "HTTPS",
            port: 443
        );

        Console.ReadLine();
    }
}
```

**Проверка и вывод:**
Порядок параметров в вызове отличается от порядка в заголовке метода, но компилятор корректно сопоставляет их. При запуске программы на консоль будет выведено:
```text
Запуск конфигурации соединения...
Сервер: api.example.com
Порт: 443
Протокол: HTTPS
Таймаут: 3000 мс
Использование SSL: True
```
Единицы измерения и типы данных соблюдены, логических ошибок нет.

### Совмещение позиционных и имеменованных аргументов

В C# вы можете комбинировать два стиля передачи аргументов в одном вызове метода: использовать позиционные аргументы для первых параметров и именованные — для последующих.

> **Важное правило.** Все позиционные аргументы всегда должны располагаться в начале списка вызова метода. Если вы хотя бы один раз использовали именованный аргумент, все последующие аргументы в этом вызове также обязаны быть именованными. Нарушение этого правила приводит к ошибке компиляции.

Это ограничение объясняется логикой компилятора: как только имя аргумента зафиксировано, компилятор прекращает чисто позиционное сопоставление и требует явного указания имен для оставшихся значений, чтобы избежать двусмысленности.

Рассмотрим второй разобранный пример, где применяется совмещение стилей и пропуск необязательных параметров.

#### Пример 2: Отрисовка прямоугольника с цветной рамкой

**Условие:**
Разработать статический метод `DrawRectangle`, который принимает координаты верхнего левого угла `(x, y)`, размеры `(width, height)` и необязательный параметр цвета рамки `string color` со значением по умолчанию `"Black"`. 

Требуется вызвать этот метод, используя позиционные аргументы для координат, пропустив необязательный цвет (чтобы применилось значение по умолчанию), и передав размеры через именованные аргументы в произвольном порядке.

**Рисунок словами (схема работы):**
Метод принимает 5 параметров: `int x`, `int y`, `int width`, `int height`, `string color = "Black"`. При вызове мы передаем обязательные координаты `10` и `20` по позициям. Затем размеры `width` и `height` передаем по именам в обратном порядке, а параметр `color` опускаем вообще, полагаясь на значение по умолчанию.

**Ход рассуждений:**
1. Проектируем метод `DrawRectangle`. Первые два параметра (`x`, `y`) оставляем позиционными, так как они логично задают начальную точку.
2. Параметры `width` и `height` сделаем доступными для именованной передачи.
3. Последний параметр `color` делаем необязательным, присваивая ему значение `"Black"`.
4. В методе `Main` вызываем `DrawRectangle(10, 20, height: 100, width: 200);`. Первые два числа `10` и `20` уйдут в `x` и `y` по позициям. Затем по именам передадутся высота и ширина. Параметр `color` автоматически примет значение `"Black"`.

**Решение на C#:**

```csharp
using System;

class Program
{
    // Метод с позиционными, именованными и необязательными параметрами
    static void DrawRectangle(int x, int y, int width, int height, string color = "Black")
    {
        Console.WriteLine($"Прямоугольник отрисован:");
        Console.WriteLine($"  Координаты верхнего левого угла: X = {x}, Y = {y}");
        Console.WriteLine($"  Ширина: {width}, Высота: {height}");
        Console.WriteLine($"  Цвет рамки: {color}");
        Console.WriteLine(new string('-', 30));
    }

    static void Main()
    {
        // 1. Стандартный вызов (все аргументы позиционные)
        DrawRectangle(0, 0, 50, 25, "Red");

        // 2. Смешанный вызов: первые два позиционные, размеры через имена, цвет опущен
        DrawRectangle(10, 20, height: 100, width: 200);

        // 3. Вызов с использованием имен для всех параметров, кроме позиции
        DrawRectangle(x: 5, y: 5, width: 80, height: 40, color: "Blue");

        Console.ReadLine();
    }
}
```

### Влияние рефакторинга на вызывающий код

Использование именованных аргументов накладывает определенные обязательства при сопровождении и рефакторинге программного обеспечения (изменении структуры кода без изменения его внешнего поведения).

Когда вы пишете код вида `Connect(server: "localhost", port: 3306);`, имя параметра (`server`, `port`) становится частью контракта взаимодействия между вызывающим кодом и методом. 

* **Переименование параметров:** Если в будущем вы решите изменить имя параметра в сигнатуре метода — например, переименовать `server` в `hostName`, — среда разработки (Visual Studio или Rider) выполнит безопасный рефакторинг, автоматически обновив имена и во всех местах вызова. Однако если вы пишете библиотеку классов (.dll), которая используется сторонними разработчиками, переименование публичных параметров с использованием именованных аргументов у внешних клиентов может привести к поломке их кода при обновлении библиотеки.
* **Добавление новых параметров:** Именованные аргументы в сочетании с необязательными параметрами защищают код от изменений при добавлении новых параметров в середину или конец списка. Если вы добавляете новый необязательный параметр в метод, старый вызывающий код продолжает компилироваться и работать без изменений.

## Практикум: комбинирование перегрузки, необязательных и именованных параметров

### Сложные сценарии проектирования публичного API методов класса

Когда мы разрабатываем классы, которые будут использоваться другими программистами или в больших проектах (так называемое публичное API — *Application Programming Interface*), перед нами встает задача: сделать интерфейс методов максимально гибким, интуитивно понятным и защищенным от ошибок. 

В реальной разработке часто возникает необходимость предоставить вызывающему коду возможность передавать разный набор аргументов. Для этого мы можем использовать три изученных механизма:
1. **Перегрузку методов** (создание нескольких методов с одинаковым именем, но разной сигнатурой).
2. **Необязательные параметры** (значения по умолчанию).
3. **Именованные аргументы** (явное указание имен при вызове).

Каждый из этих инструментов решает свою задачу, но их совместное использование в рамках одного класса или даже одного метода требует строгой дисциплины. Если проектировать интерфейс бездумно, компилятор выдаст ошибку неоднозначности, а код станет трудно поддерживать.

Рассмотрим сложные сценарии. Например, проектирование универсальной системы логирования или финансовых расчетов. В таких системах метод может принимать от одного до пяти параметров различных типов. Если создавать отдельную перегрузку для каждой возможной комбинации параметров, мы получим взрывной рост кода (*code explosion*), когда количество методов растет как факториал или степень двойки. С другой стороны, злоупотребление необязательными параметрами может привести к скрытым багам при изменении сигнатуры метода в будущем.

### Потенциальные ошибки компиляции при пересечении перегрузки и параметров по умолчанию

Главная опасность при совмещении перегрузки методов и необязательных параметров — это возникновение конфликтов разрешения перегрузки (*Overload Resolution Ambiguity*). Компилятор C# устроен строго: когда он видит вызов метода, он пытается найти единственно подходящую версию. Если под один и тот же вызов подходят два или более перегруженных метода (особенно с учетом того, что необязательные параметры могут быть опущены), компилятор не сможет сделать выбор и выдаст ошибку компиляции.

> **Правило компилятора.** При разрешении перегрузки компилятор сначала ищет точное совпадение по типам и количеству переданных аргументов. Если точного совпадения нет, анализируются методы с учетом подставленных значений по умолчанию. Если под это описание подходит более одного метода, возникает ошибка: `The call is ambiguous between the following methods or properties`.

Рассмотрим опасный пример. Предположим, у нас есть класс с двумя методами:
```csharp
public void Process(int x, int y = 0) { }
public void Process(int x) { }
```
Если мы вызовем `Process(5)`, компилятор окажется в тупике. Первый метод может быть вызван с одним аргументом (потому что второй параметр `y` имеет значение по умолчанию). Второй метод также принимает ровно один целочисленный аргумент. Какой метод имел в виду программист? Компилятор не станет угадывать и прервет сборку программы.

### Лучшие практики: когда использовать перегрузку, а когда — необязательные параметры

Чтобы избежать подобных ловушек, следуйте инженерным рекомендациям:

1. **Используйте перегрузку**, когда логика работы метода принципиально отличается для разных типов данных или когда набор обязательных параметров кардинально меняется.
2. **Используйте необязательные параметры**, когда у вас есть один базовый сценарий работы метода, а остальные параметры являются второстепенными настройками (флаги, таймауты, категории, коэффициенты по умолчанию), которые дополняют основное действие.
3. **Избегайте пересечения одинаковых имен с разным количеством необязательных параметров.** Если вы перегружаете метод, старайтесь делать так, чтобы наборы аргументов не перекрывали друг друга при пропуске необязательных значений.
4. **Применяйте именованные аргументы** для вызова методов, у которых больше двух параметров одного типа (например, несколько `int` или `string`), чтобы избежать путаницы в порядке следования.

### Особенности документирования и поддержки методов с гибкими сигнатурами

Когда метод имеет множество необязательных параметров и перегрузок, документирование становится критически важным. В C# для этого используется стандартный XML-документирование (комментарии вида `/// <summary>`). 

При поддержке такого кода действует закон обратной совместимости. Если вы добавляете новый параметр в метод, **всегда делайте его необязательным** и ставьте в самый конец списка параметров. Если вы сделаете новый параметр обязательным или измените порядок параметров, это мгновенно сломает весь ранее написанный код у всех пользователей вашей библиотеки или класса.

### Анализ производительности и отсутствие оверхеда времени выполнения

Студенты часто задаются вопросом: снижают ли производительность программы необязательные параметры, именованные аргументы и перегрузка?

Ответ: **нет**. 
- **Перегрузка методов** разрешается полностью во время компиляции (*compile-time*). Компилятор точно знает, какой именно метод (по его уникальному токену в IL-коде) нужно вызвать. Никакого поиска метода во время выполнения (*runtime*) не происходит.
- **Необязательные параметры** работают на уровне компилятора. Когда вы пишете вызов метода, опуская необязательный параметр, компилятор .NET автоматически подставляет значение по умолчанию прямо в месте вызова. В результирующий исполняемый файл попадает вызов метода с явным указанием всех аргументов.
- **Именованные аргументы** также обрабатываются компилятором, который расставляет аргументы в строгом соответствии с порядком их объявления в сигнатуре метода. 

Таким образом, все эти языковые конструкции созданы исключительно для удобства разработчика и повышения читаемости исходного кода, не привнося никаких накладных расходов в производительность готового приложения.

### Разобранные примеры

#### Пример 1. Система логирования (конфликты перегрузки и необязательные параметры)

**Условие:** 
Реализовать класс `Logger`, содержащий три метода с именем `Log`:
1. `Log(string message)` — выводит обычное сообщение.
2. `Log(string message, int errorCode)` — выводит сообщение об ошибке с числовым кодом.
3. `Log(string message, string category = "GENERAL", int level = 1)` — универсальный метод с необязательными параметрами для категории и уровня важности.

Проверить на примерах компиляцию, выявить потенциальные конфликты вызовов и показать, как они разрешаются.

**Рисунок словами:**
В консоли последовательно выводятся строки логов различного формата: обычные сообщения, сообщения с кодами ошибок, а также структурированные логи с указанием подсистемы (категории) и степени критичности.

**Ход рассуждений:**
Сначала посмотрим на сигнатуры наших трех методов:
- Метод А: `Log(string message)` (1 обязательный параметр).
- Метод Б: `Log(string message, int errorCode)` (2 обязательных параметра: `string`, `int`).
- Метод В: `Log(string message, string category = "GENERAL", int level = 1)` (1 обязательный `string` и 2 необязательных: `string`, `int`).

Здесь кроется скрытая ловушка! Если мы вызовем метод `Logger.Log("System started", 500)`, компилятор будет выбирать между методом Б (`Log(string, int)`) и методом В (`Log(string, string = "GENERAL", int = 1)`). В методе В второй параметр имеет тип `string`. Но мы передали число `500` (`int`). Компилятор попытается неявно привести `int` к `string`, но не сможет сделать это без потери данных или специального преобразования, поэтому он отдаст предпочтение методу Б, так как там тип второго параметра совпадает точно (`int`). Конфликта здесь не возникнет.

Однако, если мы вызовем `Logger.Log("Database connection lost", "DB")`, компилятор увидит, что первый аргудмент — `string`, второй — `string`. Метод Б отпадает (там второй параметр `int`). Но метод В идеально подходит: первый параметр строка, второй аргумент `"DB"` подставляется вместо необязательного параметра `category`. Вызов пройдет успешно.

Что произойдет, если мы вызовем `Logger.Log("Test")` (передана только одна строка)? 
Метод А принимает ровно один параметр `string`. Метод В принимает один обязательный параметр `string` и два необязательных. Какой метод выберет компилятор? 
В C# при прочих равных условиях компилятор отдает предпочтение методу **с меньшим количеством подставляемых значений по умолчанию** (более специализированному), то есть будет вызван метод А. Если мы захотим явно вызвать метод В с одним аргументом, нам придется использовать именованные аргументы или удалить метод А, объединив их логику.

**Решение на C#:**

```csharp
using System;

namespace CourseProject
{
    public class Logger
    {
        // 1. Перегрузка для простого сообщения
        public void Log(string message)
        {
            Console.WriteLine($"[LOG] {message}");
        }

        // 2. Перегрузка для сообщения с кодом ошибки
        public void Log(string message, int errorCode)
        {
            Console.WriteLine($"[ERROR #{errorCode}] {message}");
        }

        // 3. Метод с необязательными параметрами
        public void Log(string message, string category = "GENERAL", int level = 1)
        {
            Console.WriteLine($"[{category.ToUpper()} - Уровень {level}] {message}");
        }
    }

    class Program
    {
        static void Main(string[] args)
        {
            Logger logger = new Logger();

            // Вызов метода 1 (совпадает с Log(string))
            logger.Log("Приложение успешно запущено.");

            // Вызов метода 2 (второй аргумент int, срабатывает Log(string, int))
            logger.Log("Не удалось подключиться к порту.", 404);

            // Вызов метода 3 (второй аргумент string, срабатывает метод с необязательными параметрами)
            logger.Log("Пользователь изменил пароль.", category: "SECURITY");

            // Вызов метода 3 со всеми аргументами
            logger.Log("Критический сбой памяти.", category: "HARDWARE", level: 3);

            // Ожидание нажатия клавиши
            Console.ReadKey();
        }
    }
}
```

**Проверка:**
- Единицы измерения: отсутствуют (логическая задача).
- Правдоподобность: Код компилируется без ошибок. Компилятор четко разделил вызовы благодаря разным типам второго параметра (`int` против `string`) и наличию точной перегрузки для одного строкового аргумента.
- Вывод программы в консоли:
```text
[LOG] Приложение успешно запущено.
[ERROR #404] Не удалось подключиться к порту.
[SECURITY - Уровень 1] Пользователь изменил пароль.
[HARDWARE - Уровень 3] Критический сбой памяти.
```

`Ответ:` Проект успешно скомпилирован и выполнен. Конфликты разрешения перегрузки предотвращены за счет различия типов параметров (`int` и `string`) и точного соответствия сигнатур.

#### Пример 2. Расчет банковского вклада (комбинирование именованных аргументов и параметров по умолчанию)

**Условие:**
Написать консольное приложение, содержащее универсальный метод расчета банковского вклада `CalculateDeposit(decimal principal, int months, decimal interestRate = 10.0m, bool capitalize = true)`. 
Вычислить итоговую сумму для вклада в `50000` рублей на `12` месяцев. Продемонстрировать:
1. Вызов метода со стандартными значениями (пропуск необязательных параметров).
2. Вызов метода с явным указанием годовой ставки и отключением капитализации.
3. Вызов метода с перестановкой именованных аргументов в произвольном порядке.

**Рисунок словами:**
Таблица расчетов на экране консоли, где для одного и того же исходного капитала и срока выводятся итоговые суммы при разных условиях начисления процентов (с капитализацией и без нее).

**Ход рассуждений:**
Формула для расчета простого и сложного процента (капитализации) известна из финансовой математики. 
Если капитализация включена (`capitalize = true`), расчет идет по формуле сложных процентов за каждый месяц:
$$A = P \cdot \left(1 + \frac{r}{12 \cdot 100}\right)^m$$
где:
- $P$ — начальная сумма вклада (`principal`), в рублях;
- $m$ — срок в месяцах (`months`);
- $r$ — годовая процентная ставка (`interestRate`), в процентах;
- $A$ — итоговая сумма на счете.

Если капитализация выключена (`capitalize = false`), проценты начисляются в конце срока по формуле простых процентов:
$$A = P + P \cdot \frac{r}{100} \cdot \frac{m}{12}$$

Создадим статический метод, который реализует эту логику, а затем в методе `Main` вызовем его, используя возможности именованных аргументов C#.

**Решение на C#:**

```csharp
using System;

namespace CourseProject
{
    class Program
    {
        // Универсальный метод расчета вклада
        static decimal CalculateDeposit(decimal principal, int months, decimal interestRate = 10.0m, bool capitalize = true)
        {
            decimal finalAmount = principal;

            if (capitalize)
            {
                // Сложные проценты (ежемесячная капитализация)
                // Переводим годовую ставку в месячную долю: interestRate / 100 / 12
                decimal monthlyRate = interestRate / 100.0m / 12.0m;
                for (int i = 0; i < months; i++)
                {
                    finalAmount += finalAmount * monthlyRate;
                }
            }
            else
            {
                // Простые проценты за весь срок
                decimal totalYears = (decimal)months / 12.0m;
                decimal interestEarned = principal * (interestRate / 100.0m) * totalYears;
                finalAmount = principal + interestEarned;
            }

            return Math.Round(finalAmount, 2);
        }

        static void Main(string[] args)
        {
            decimal initialMoney = 50000.0m;
            int termMonths = 12;

            // Сценарий 1: Используем все параметры по умолчанию (ставка 10%, капитализация true)
            decimal result1 = CalculateDeposit(initialMoney, termMonths);
            Console.WriteLine($"Сценарий 1 (по умолчанию): {result1} руб.");

            // Сценарий 2: Явно указываем ставку 12.5%, оставляя капитализацию по умолчанию
            decimal result2 = CalculateDeposit(initialMoney, termMonths, 12.5m);
            Console.WriteLine($"Сценарий 2 (ставка 12.5%): {result2} руб.");

            // Сценарий 3: Меняем ставку на 8% и отключаем капитализацию
            decimal result3 = CalculateDeposit(initialMoney, termMonths, 8.0m, capitalize: false);
            Console.WriteLine($"Сценарий 3 (без капитализации): {result3} руб.");

            // Сценарий 4: Полностью именованные аргументы в переставленном порядке
            // Позиционные параметры обязаны идти первыми, но именованные можно переставлять
            decimal result4 = CalculateDeposit(months: termMonths, principal: initialMoney, capitalize: true, interestRate: 15.0m);
            Console.WriteLine($"Сценарий 4 (перестановка имен, ставка 15%): {result4} руб.");

            Console.ReadKey();
        }
    }
}
```

**Проверка:**
- Единицы измерения: денежные единицы (рубли), проценты (%), время (месяцы).
- Правдоподобность: 
  - При вкладе 50000 руб. под 10% годовых с ежемесячной капитализацией на 12 месяцев сумма должна быть чуть больше 55200 рублей (так как сложные проценты дают бонус к простым). Расчет выдает `55235{,}64` руб., что математически абсолютно верно.
  - При отключенной капитализации под 8% годовых за год набежит ровно $50000 \cdot 0{,}08 = 4000$ рублей процентов. Итоговая сумма: $54000{,}00$ руб. Расчет подтвержден.
- Вывод программы в консоли:

## Типичные ошибки

1. **Размещение обязательного параметра после необязательного**
   * *В чём ошибка:* Объявление метода вида `void Calculate(int a = 5, int b)` приводит к ошибке компиляции.
   * *Почему возникает:* Компилятор не сможет определить, какому параметру назначить значение при вызове с одним аргументом (`Calculate(10)`).
   * *Как избежать:* Всегда размещайте обязательные параметры в начале списка аргументов, а необязательные — в самом конце.

2. **Использование неконстантных выражений в качестве значений по умолчанию**
   * *В чём ошибка:* Попытка написать `void Log(string msg, DateTime time = DateTime.Now)`.
   * *Почему возникает:* Значения по умолчанию для параметров должны быть известны в момент компиляции (константы времени компиляции). Динамические вызовы методов или свойства запрещены.
   * *Как избежать:* Используйте константы (`const`), литералы или значение `null`. Для динамических значений передавайте `null` и инициализируйте их внутри тела метода.

3. **Ошибки в порядке аргументов при смешанном вызове**
   * *В чём ошибка:* Написание кода вида `Draw(x: 10, 20, width: 100);`.
   * *Почему возникает:* Как только в вызове метода используется именованный аргумент, все последующие аргументы обязаны быть именованными, а позиционные аргументы не могут идти после них.
   * *Как избежать:* Сначала передавайте позиционные аргументы, а затем переключайтесь на именованные. Если используется именованный аргумент, все последующие тоже должны иметь имена.

4. **Двусмысленность при перегрузке методов с необязательными параметрами**
   * *В чём ошибка:* Создание перегрузок, которые пересекаются при подстановке значений по умолчанию (например, `Void Foo(int x)` и `Void Foo(int x, int y = 0)` при вызове `Foo(5)`).
   * *Почему возникает:* Под один и тот же вызов подходят сразу несколько вариантов метода, и компилятор выдает ошибку неоднозначности (`Ambiguous invocation`).
   * *Как избежать:* Избегайте проектирования перегрузок, которые дублируют друг друга при опускании необязательных параметров.

5. **Ожидание динамического разрешения параметров (внутренний механизм)**
   * *В чём ошибка:* Убежденность в том, что значения по умолчанию подставляются во время работы программы (runtime).
   * *Почему возникает:* Непонимание того, как работает компилятор C#.
   * *Как избежать:* Помните, что компилятор «впаивает» значение по умолчанию прямо в вызывающий код на этапе сборки. При изменении сторонней библиотеки со значениями по умолчанию клиентский код требует перекомпиляции.

6. **Попытка использовать тип возвращаемого значения для перегрузки**
   * *В чём ошибка:* Попытка создать методы `int GetValue(int id)` и `double GetValue(int id)`.
   * *Почему возникает:* Путаница между сигнатурой метода и его возвращаемым типом.
   * *Как избежать:* Учитывайте, что сигнатура метода состоит только из его имени и списка параметров. Тип возвращаемого значения в сигнатуру не входит.

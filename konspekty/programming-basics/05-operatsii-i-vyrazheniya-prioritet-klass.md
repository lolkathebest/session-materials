## 1. Арифметические операции и особенности целочисленного деления

### 1. Арифметические операции и особенности целочисленного деления

Любая программа на языке C# обрабатывает данные с помощью выражений. В основе вычислений лежат операции и операнды.

> **Определение.** **Операция** (operator) — это языковая конструкция, которая задает определенное действие над одним или несколькими значениями. **Операнд** (operand) — это данные (переменные, константы или результаты вызова методов), над которыми выполняется операция.

По количеству операндов операции делятся на:
- **Унарные** — действуют на один операнд (например, унарный минус меняет знак числа на противоположный).
- **Бинарные** — действуют на два операда (располагаются между левым и правым операндом, например, сложение $a + b$).

---

### Бинарные арифметические операции

В языке C# для встроенных числовых типов (`int`, `double`, `decimal` и др.) определены пять основных бинарных арифметических операций:

1. **Сложение (`+`)** — возвращает сумму двух операндов.
2. **Вычитание (`-`)** — возвращает разность между левым и правым операндом.
3. **Умножение (`*`)** — возвращает произведение операндов.
4. **Деление (`/`)** — возвращает частное от деления левого операнда на правый.
5. **Остаток от деления (`%`)** — возвращает остаток от целочисленного деления левого операнда на правый.

Поведение этих операций напрямую зависит от типов данных операндов, участвующих в выражении.

---

### Правила целочисленного деления и отсечения дробной части

Когда оба операнда операции деления (`/`) являются целыми числами (например, типа `int`), компилятор C# выполняет **целочисленное деление**. 

> **Правило.** При целочисленном делении (`int / int`) дробная часть результата **всегда отбрасывается** (происходит усечение в сторону нуля), а не округляется до ближайшего целого. Результатом операции также будет целое число (`int`).

Рассмотрим этот процесс на примере.

**Пример 1.** Вычислить результат деления `17 / 5` и остатка `17 % 5` для типа `int`, а также `17.0 / 5.0` для типа `double`.

**Ход рассуждений:**
1. Определим типы операндов. В выражении `17 / 5` оба числа записаны как литералы типа `int` (по умолчанию целые числа без точки воспринимаются как `int`).
2. Выполним деление нацело: сколько раз число $5$ полностью помещается в числе $17$? Ровно $3$ раза ($3 \cdot 5 = 15$). Остаток до $17$ равен $2$.
3. Так как типы операндов целочисленные, дробная часть ($0{,}4$) отбрасывается. Результатом деления будет `3`.
4. Операция остатка от деления (`17 % 5`) возвращает то самое число, которое осталось после полного деления, то есть `2`.
5. Во втором выражении (`17.0 / 5.0`) операнды имеют тип `double` (содержат точку и дробную часть). В этом случае выполняется деление вещественных чисел с сохранением точной дробной части.

**Решение в общем виде и вычисление:**
```csharp
int intResult = 17 / 5;       // Результат: 3
int intRemainder = 17 % 5;   // Результат: 2

double doubleResult = 17.0 / 5.0; // Результат: 3.4
```

**Проверка:**
- Целочисленное деление: $17 = 5 \cdot 3 + 2$. Все верно, частное $3$, остаток $2$.
- Вещественное деление: $17{,}0 / 5{,}0 = 3{,}4$. Единицы измерения не заданы, но логика математических расчетов соблюдена полностью.

---

### Особенности деления вещественных чисел

Если хотя бы один операнд в операции деления является вещественным (`double` или `decimal`), то и второй операнд неявно приводится к вещественному типу, а результат вычислений будет содержать дробную часть.

Тип `double` (двойная точность, 64 бита) базируется на стандарте IEEE 754 для чисел с плавающей точкой. Из-за особенностей двоичного кодирования дробей некоторые десятичные дроби не могут быть представлены в памяти компьютера абсолютно точно. Например, результат сложения или деления может иметь погрешность в самых младших разрядах (порядка $10^{-15} - 10^{-17}$). Это важно учитывать при сравнении вещественных чисел: вместо оператора равенства `==` проверяют попадание разности чисел в малую окрестность нуля (эпсилон): `Math.Abs(a - b) < 1e-9`.

---

### Остаток от деления отрицательных чисел

Операция получения остатка от деления (`%`) применима не только к положительным, но и к отрицательным числам. В языке C# знак результата операции остатка подчиняется следующему правилу:

> **Правило.** Знак результата операции `%` всегда совпадает со знаком **делимого** (левого операнда).

Формально остаток $r$ вычисляется по формуле:
$$r = a - (a / b) \cdot b$$
где $a$ — делимое, а $b$ — делитель (при этом деление $a / b$ выполняется нацело с отсечением дробной части).

Рассмотрим применение этого правила на задаче.

**Пример 2.** Найти остаток от деления числа $-23$ на $4$ и объяснить знак результата.

**Ход рассуждений:**
1. Делимое $a = -23$ (отрицательное число), делитель $b = 4$ (положительное число). Оба операнда типа `int`.
2. Вычислим целую часть от деления $-23 / 4$. В математике $-23 / 4 = -5{,}75$. При целочисленном делении в C# дробная часть отбрасывается в сторону нуля, получаем целую часть $-5$.
3. Подставим значения в формулу для вычисления остатка:
   $$r = -23 - ((-5) \cdot 4) = -23 - (-20) = -23 + 20 = -3$$
4. Значение остатка равно $-3$. Знак отрицательный, что полностью совпадает со знаком делимого ($-23$).

**Решение на C#:**
```csharp
int a = -23;
int b = 4;
int remainder = a % b; // Результат: -3
```

**Практическое применение остатка от деления:**
- Проверка числа на четность: `x % 2 == 0`.
- Ограничение диапазона значений (например, циклический сдвиг по часам от 0 до 5: `currentHour = (currentHour + 1) % 6`).
- Выделение цифр числа (например, получение последней цифры десятичного числа через взятие остатка от деления на 10: `lastDigit = number % 10`).

---

### Унарные операции плюс и минус

Унарные операции применяются к единственному операнду и записываются непосредственно перед ним:

- **Унарный плюс (`+`)** — формально сохраняет знак операнда неизменным. Применяется для симметрии синтаксиса и явного указания положительного значения.
- **Унарный минус (`-`)** — инвертирует знак числового операнда на противоположный (положительное становится отрицательным, и наоборот).

```csharp
int positiveValue = 10;
int negativeValue = -positiveValue; // Результат: -10
int restoredValue = -negativeValue; // Результат: 10
```

---

### Переполнение типа при арифметических операциях

Каждый числовой тип в C# имеет фиксированный размер в памяти и, соответственно, диапазон допустимых значений. Например, тип `int` занимает 4 байта (32 бита) и хранит значения в диапазоне от `-2 147 483 648` до `2 147 483 647`.

> **Определение.** **Переполнение** (overflow) — это ситуация, когда результат арифметической операции выходит за рамки допустимого диапазона значений для данного типа данных.

В обычном режиме выполнения кода (по умолчанию в контексте `uncheked`) язык C# не выбрасывает исключение при переполнении целых чисел: значение «заворачивается» по кругу. Если к максимальному значению `int.MaxValue` ($2\,147\,483\,647$) прибавить единицу, результат неожиданно станет минимальным отрицательным числом (`int.MinValue`).

**Способы предотвращения и контроля переполнения:**
1. **Использование более емких типов данных.** Если исходные данные могут быть велики, вместо `int` используют `long` (64-битные целые числа с диапазоном до $\approx 9 \cdot 10^{18}$).
2. **Проверка условий перед вычислением.** Анализ входных данных на предмет выхода за границы.
3. **Использование ключевого слова `checked`.** Позволяет принудительно включить проверку переполнения на уровне инструкций. Если произойдет выход за границы типа, среда .NET выбросит исключение `OverflowException`.

```csharp
checked
{
    int max = int.MaxValue;
    int errorValue = max + 1; // Выбросит исключение OverflowException во время выполнения
}
```

## 2. Операции присваивания, инкремент и декремент

### Простое присваивание и его правосторонняя природа

Операция простого присваивания обозначается знаком `=` и используется для записи значения в ячейку памяти, с которой связана переменная. Важно четко понимать разницу между математическим равенством и присваиванием в программировании. В математике запись $x = x + 1$ означает уравнение, у которого нет решений. В языке C# это совершенно корректная инструкция, которая означает: «вычислить текущее значение выражения, стоящего справа от знака `=`, а затем сохранить полученный результат в переменную, находящуюся слева».

Синтаксис простой операции присваивания выглядит следующим образом:

```csharp
переменная = выражение;
```

> **Определение.** **Простое присваивание** — это операция, которая вычисляет значение правого операнда и записывает его в переменную, выступающую в роли левого операнда. При этом старое значение переменной полностью стирается.

Ключевой особенностью операции присваивания является ее **правосторонняя ассоциативность**. Это означает, что вычисление выражения всегда происходит справа налево по отношению к самому знаку `=`. Рассмотрим, как это работает на практике, когда в одной строке кода используется несколько знаков присваивания:

```csharp
int a, b, c;
a = b = c = 10;
```

В данном примере выполнение инструкции происходит следующим образом:
1. Самая правая часть `c = 10` записывает число `10` в переменную `c`.
2. Результатом операции присваивания является само присвоенное значение, поэтому выражение `c = 10` в целом возвращает `10`.
3. Это значение передается дальше налево: выполняется `b = 10`. Переменная `b` принимает значение `10`.
4. На завершающем этапе выполняется `a = 10`, и переменная `a` также получает значение `10`.

В результате все три переменные будут содержать число `10`. 

Важнейшее ограничение: типы данных слева и справа от знака `=` должны быть совместимы. Если тип выражения справа шире типа переменной слева (например, попытка записать `double` в `int`), компилятор выдаст ошибку, требуя явного приведения типов, о чем подробно говорится в следующем разделе курса.

### Составные операции присваивания

В процессе написания программ часто возникает необходимость изменить значение существующей переменной на основе ее собственного текущего значения. Например, увеличить переменную на 5 или умножить на 2. Классическая запись таких действий выглядит так:

```csharp
int count = 10;
count = count + 5; // count становится равным 15
```

Подобные конструкции встречаются настолько часто, что в языке C# предусмотрены **составные операции присваивания** (compound assignment operators). Они позволяют объединить арифметическую операцию и простое присваивание в единую, более компактную и легко читаемую конструкцию.

В языке C# поддерживаются следующие составные операции присваивания:
- `+=` (присваивание сложением)
- `-=` (присваивание вычитанием)
- `*=` (присваивание умножением)
- `/=` (присваивание делением)
- `%=` (присваивание остатком от деления)

Общий принцип работы составного присваивания заключается в том, что выражение `переменная op= выражение` эквивалентно длинной записи `переменная = переменная op (выражение)`. Обратите внимание на важный нюанс: выражение справа от знака составного присваивания всегда вычисляется целиком, как если бы оно было заключено в невидимые круглые скобки.

Рассмотрим примеры эквивалентности:

| Составная операция | Эквивалентная полная форма | Пояснение |
|---|---|---|
| `x += 5;` | `x = x + 5;` | Увеличивает значение `x` на 5 |
| `y -= 3;` | `y = y - 3;` | Уменьшает значение `y` на 3 |
| `z *= 2 + 1;` | `z = z * (2 + 1);` | Умножает `z` на сумму (сначала вычисляется `2 + 1`) |
| `a /= 4;` | `a = a / 4;` | Делит `a` на 4 (с учетом типа данных) |
| `b %= 3;` | `b = b % 3;` | Присваивает остаток от деления `b` на 3 |

Использование составных операций присваивания делает код лаконичным и снижает вероятность появления опечаток в именах переменных при их повторном написании.

### Операции инкремента и декремента: назначение и префиксная форма

Увеличение или уменьшение значения переменной ровно на единицу — это самая частая операция в программировании, особенно при управлении циклами или счетчиками. Для этой цели в C# существуют специальные унарные операции: **инкремент** (`++`) и **декремент** (`--`).

> **Определение.** **Инкремент (`++`)** — это унарная операция, которая увеличивает значение операнда (целочисленной или вещественной переменной) ровно на единицу. **Декремент (`--`)** — это унарная операция, которая уменьшает значение операнда ровно на единицу.

Хотя инкремент концептуально похож на запись `x = x + 1` или `x += 1`, на уровне машинного кода современные компиляторы оптимизируют его в максимально эффективные инструкции процессора.

Особенностью инкремента и декремента является наличие двух форм записи, которые ведут себя по-разному, если эти операции встроены внутрь более крупных выражений:
1. **Префиксная форма** (преинфиксная): знак операции пишется *перед* переменной (`++x` или `--x`).
2. **Постфиксная форма** (постинфиксная): знак операции пишется *после* переменной (`x++` или `x--`).

Рассмотрим подробно **префиксную форму инкремента (`++x`)**. 

Алгоритм вычисления префиксного инкремента:
1. Значение переменной `x` увеличивается на единицу *непосредственно в памяти*.
2. Новое, уже увеличенное значение переменной подставляется в качестве результата всего выражения.

Рассмотрим демонстрационный пример:

```csharp
int a = 10;
int b = ++a;
```

Пошаговый разбор выполнения этого фрагмента кода:
1. Объявляется переменная `a` со значением `10`.
2. В строке `int b = ++a;` компилятор встречает префиксный инкремент `++a`.
3. Сначала переменная `a` увеличивается на единицу: теперь `a` равно `11`.
4. Затем это новое значение (`11`) присваивается переменной `b`.
5. В итоге после выполнения обеих строк переменная `a` равна `11`, а переменная `b` также равна `11`.

Префиксный декремент `--x` работает абсолютно симметрично, но уменьшает переменную на единицу: сначала уменьшает, затем возвращает новое значение.

---

### Постфиксная форма инкремента и декремента

**Постфиксная форма инкремента (`x++`)** и декремента (`x--`) отличается от префиксной моментом времени, когда переменная изменяет свое значение по отношению к моменту вычисления окружающего выражения.

Алгоритм вычисления постфиксного инкремента:
1. Текущее (старое) значение переменной `x` сохраняется во временной памяти и используется в текущем выражении.
2. Сама переменная `x` в памяти увеличивается на единицу.

> **Важно.** Постфиксная операция возвращает старое значение переменной, которое она имела *до* увеличения. Само изменение переменной происходит «в фоновом режиме» сразу после того, как ее старое значение было задействовано в вычислениях.

Рассмотрим демонстрационный пример с постфиксным инкрементом:

```csharp
int x = 10;
int y = x++;
```

Пошаговый разбор выполнения этого фрагмента кода:
1. Объявляется переменная `x` со значением `10`.
2. В строке `int y = x++;` компилятор видит постфиксный инкремент `x++`.
3. В текущее выражение (направо от `=` и для присваивания в `y`) передается *старое* значение переменной `x`, то есть `10`. Переменная `выходит` из операции с числом `10`, которое записывается в `y`.
4. Сразу после этого переменная `x` увеличивается на единицу в памяти: теперь `x` становится равным `11`.
5. В итоге после выполнения кода переменная `x` равна `11`, а переменная `y` равна `10`.

Сравнение результатов префиксной и постфиксной форм наглядно показывает, почему так важно внимательно следить за расположением знаков `++` и `--`, если они используются не отдельной строкой, а внутри сложных выражений.

### Типичные логические ошибки при использовании инкремента и декремента

Начинающие разработчики часто совершают типичные ошибки, пытаясь использовать инкремент и декремент слишком сложным образом внутри одной инструкции. Язык C# позволяет писать компактный код, но избыточное уплотнение операций приводит к трудноуловимым багам.

1. **Многократное изменение одной переменной в рамках одного выражения.**
   Согласно стандарту языка C#, порядок вычислений операндов во многих выражениях не гарантируется строгим образом. Если написать выражение вроде `int result = ++x + x++;`, поведение программы становится непредсказуемым (так называемое неопределенное поведение или зависящее от версии компилятора). 
   *Правило безопасности:* никогда не изменяйте одну и ту же переменную с помощью инкремента/декремента более одного раза в пределах одного выражения.

2. **Забывание о том, что инкремент — это полноценная операция изменения переменной.**
   Новички иногда пишут так: `x = x++;`, полагая, что это увеличит `x`. Однако из-за природы постфиксного инкремента сначала берется старое значение `x`, затем `x` увеличивается на 1, а затем старое значение перезаписывает свежеувеличенное. В итоге `x` остается *прежним*. Такие конструкции являются логической ошибкой.

### Разобранные примеры

#### Пример 1: Префиксный инкремент в сложном выражении

**Условие:**
Дана переменная целого типа `int a = 5;`. Вычислить значение выражения `int b = ++a * 3;`, а также определить конечные значения переменных `a` и `b` после выполнения этой инструкции.

**Рисунок словами (состояние памяти):**
```text
Начальное состояние:
[a] = 5

Выполнение выражения int b = ++a * 3;:
Шаг 1: ++a -> переменная 'a' увеличивается на 1 (становится 6). Результат префиксного инкремента равен 6.
Шаг 2: 6 * 3 -> вычисляется произведение (равно 18).
Шаг 3: int b = 18 -> результат записывается в переменную 'b'.

Конечное состояние памяти:
[a] = 6
[b] = 18
```

**Ход рассуждений:**
1. Мы видим объявленную переменную `int a = 5;`.
2. В следующей строке создается переменная `b`, которой присваивается результат вычисления выражения `++a * 3`.
3. В выражении присутствует префиксный инкремент `++a`. Согласно правилам префиксной формы, первым делом значение `а` увеличивается на единицу. Было `5`, стало `6`. Это число (`6`) подставляется вместо `++a`.
4. Далее выполняется умножение: `6 * 3 = 18`.
5. Полученное число `18` записывается в переменную `b`.
6. Переменная `а` сохраняет свое измененное значение `6`.

**Решение в общем виде и вычисление:**
- $a_{initial} = 5$
- $a_{new} = ++a_{initial} = 6$
- $b = a_{new} \cdot 3 = 6 \cdot 3 = 18$
- $a_{final} = 6$

**Проверка:**
- Типы данных везде `int`, переполнения нет.
- Подстановка показывает: `++5` дает `6`, `6 * 3` дает `18`. Расчеты верны.

**Ответ:**
`a = 6`, `b = 18`.

#### Пример 2: Постфиксный инкремент в выражении

**Условие:**
Дана переменная целого типа `int x = 10;`. Вычислить значение выражения `int y = x++ + 2;`, а также определить конечные значения переменных `x` и `y` после выполнения этой инструкции.

**Рисунок словами (состояние памяти):**
```text
Начальное состояние:
[x] = 10

Выполнение выражения int y = x++ + 2;:
Шаг 1: x++ -> берется старое значение 'x' (10) для использования в сложении.
Шаг 2: Сам 'x' в памяти увеличивается на 1 (становится 11).
Шаг 3: 10 + 2 -> вычисляется сумма (равна 12).
Шаг 4: int y = 12 -> результат записывается в переменную 'y'.

Конечное состояние памяти:
[x] = 11
[y] = 12
```

**Ход рассуждений:**
1. Инициализирована переменная `x = 10`.
2. Вычисляется выражение `x++ + 2`.
3. Поскольку операция инкремента стоит в постфиксной форме (`x++`), для текущей операции сложения используется *исходное* значение переменной `x`, равное `10`.
4. Сразу после этого (в фоновом режиме) переменная `x` увеличивается на единицу и становится равной `11`.
5. Выполняется сложение старого значения `x` с двойкой: `10 + 2 = 12`.
6. Полученная сумма `12` записывается в переменную `y`.
7. Итого в памяти: `x` равен `11`, а `y` равен `12`.

**Решение в общем виде и вычисление:**
- $x_{initial} = 10$
- Значение для выражения от `x++` равно $10$ (старое значение).
- $x_{final} = x_{initial} + 1 = 11$ (в памяти).
- $y = 10 + 2 = 12$.

**Проверка:**
- Ошибка новичков — прибавить единицу к `x` *до* сложения (получив `11 + 2 = 13`) — здесь предотвращена пониманием постфиксной семантики. Старое значение использовалось верно. Расчеты точны.

**Ответ:**
`x = 11`, `y = 12`.

## 3. Приоритет операций и порядок вычисления выражений

### Понятие приоритета операций и ассоциативность

Когда мы пишем математическое выражение в строку, например $10 + 3 \times 2$, возникает вопрос: в каком порядке компьютер должен выполнять эти действия? Если сначала сложить $10$ и $3$, получится $13$, а умножив на $2$, получим $26$. Если же сначала выполнить умножение $3 \times 2 = 6$, а затем прибавить $10$, получится $16$. Правильный ответ, как известно из математики, второй. 

> **Определение.** **Приоритет операций (старшинство)** — это правило, определяющее очередность выполнения операций в выражении, содержащем несколько разных операторов, в отсутствие явных указаний (скобок).

В программировании, как и в математике, операции умножения и деления имеют более высокий приоритет, чем сложение и вычитание. Однако в языке C# набор операций гораздо шире (сюда входят операции присваивания, инкременты, логические операторы и унарные знаки), поэтому правила старшинства строго формализованы.

Помимо приоритета, важную роль играет понятие **ассоциативности** (направления вычислений). Ассоциативность определяет, в каком порядке выполняются операции одинакового приоритета: слева направо или справа налево.

> **Определение.** **Левосторонняя ассоциативность (Left-to-Right)** означает, что выражение вычисляется слева направо. Например, в выражении `a - b - c` сначала вычисляется `a - b`, а затем из результата вычитается `c`.
> 
> **Определение.** **Правосторонняя ассоциативность (Right-to-Left)** означает, что выражение вычисляется справа налево. Классический пример в C# — операции присваивания: в выражении `a = b = 5` сначала значение `5` присваивается переменной `b`, а затем результат присваивания передается в переменную `a`.

### Таблица приоритетов операций в C#

Ниже приведена таблица основных изученных нами операций в C#, упорядоченных от наивысшего приоритета (выполняются в первую очередь) к наинизшему. Операции, находящиеся в одной строке, имеют одинаковый приоритет и выполняются согласно их ассоциативности.

| **2** | Унарные операции, приведение типов | `+x`, `-x`, `!x`, `~x`, `++x`, `--x`, `(T)x` (явное приведение) | Справа налево |
| **3** | Мультипликативные (умножение и деление) | `*`, `/`, `%` | Слева направо |

Унарный минус (например, в выражении `-5`) имеет более высокий приоритет, чем бинарное вычитание. Также операции присваивания всегда выполняются в самом конце, после того как полностью вычислено правое выражение.

### Изменение порядка вычислений с помощью круглых скобок

Если требуется изменить стандартный порядок выполнения операций или сделать код более читаемым, используются круглые скобки `()`. 

Скобки имеют наивысший приоритет (уровень 1 таблицы). Все выражения, заключенные в круглые скобки, вычисляются в первую очередь, независимо от приоритета находящихся внутри них операторов. Если скобки вложены друг в друга, то сначала вычисляются внутренние скобки, а затем внешние.

Применение скобок не только спасает от ошибок логики, но и защищает от труднообнаруживаемых багов. Даже если по таблице приоритетов умножение выполнится раньше сложения, написание скобок `(3 * 2)` является хорошим стилем программирования, если выражение сложное.

### Неявное приведение типов в арифметических выражениях

Когда в одной арифметической операции участвуют операнды разных типов (например, целое число `int` и вещественное `double`), компилятор C# не может выполнить операцию напрямую, так как они занимают разное количество байт в памяти и по-разному кодируются. В этом случае срабатывает механизм неявного приведения типов (numeric promotion).

> **Определение.** **Неявное приведение типов (numeric promotion)** — это автоматическое преобразование компилятором операндов меньшего типа к большему типу перед выполнением операции, чтобы предотвратить потерю точности.

Иерархия типов по возрастанию «емкости» выглядит следующим образом:
`sbyte` / `byte` / `short` / `ushort` $\rightarrow$ `int` $\rightarrow$ `long` $\rightarrow$ `float` $\rightarrow$ `double`
Также отдельно стоит тип `decimal`, который имеет наибольшую точность для финансовых вычислений, но с `double` не смешивается неявно (требует явного приведения).

**Правила неявного приведения в выражениях:**
1. Если один из операндов имеет тип `double`, то второй операнд (даже если он `int`, `long` или `float`) неявно преобразуется в `double`, и результатом всей операции будет `double`.
2. Если в выражении нет `double`, но есть `float`, то операнды приводятся к `float`.
3. Если нет вещественных чисел, но есть `long`, все целые числа приводятся к `long`.
4. Все типы меньше `int` (`byte`, `sbyte`, `short`, `ushort`) в любых арифметических операциях **всегда автоматически повышаются до `int`**. Именно поэтому результат сложения двух переменных типа `short` в C# имеет тип `int`.

### Явное приведение типов (Casting)

Иногда возникает обратная ситуация: нам нужно записать результат вычислений из типа с большим диапазоном (например, `double`) в переменную меньшего типа (например, `int`), либо принудительно заставить целочисленные переменные делиться по законам вещественной арифметики.

> **Определение.** **Явное приведение типов (casting)** — это инструкция программиста компилятору выполнить принудительное преобразование типа данных, несмотря на потенциальный риск потери данных или точности.

Синтаксис явного приведения в C# выглядит следующим образом:
```csharp
(target_type) expression
```
Здесь `target_type` — это тип, к которому нужно привести результат, а `expression` — переменная или выражение, значение которого преобразуется.

Пример явного приведения:
```csharp
double pi = 3.14159;
int integerPi = (int)pi; // Значение integerPi станет равным 3, дробная часть отбросится
```
Важно помнить: при явном приведении вещественного числа к целому дробная часть **всегда отбрасывается** (происходит округление в сторону нуля), а не округляется по математическим правилам. Если исходное число выходит за диапазон целевого типа, возникнет переполнение (в режиме по умолчанию старшие биты просто отбросятся, либо в режиме `checked` выбросится исключение `OverflowException`).

### Анализ распространенных ошибок при делении целых чисел

Самая частая ошибка начинающих разработчиков связана с целочисленным делением в числителе и знаменателе формул (мы подробно рассматривали это в теме 1, но закрепим в контексте приоритетов).

Представьте, что вы пишете формулу для расчета среднего значения или физической величины:
```csharp
int countOfStudents = 5;
int totalScore = 12;
double average = totalScore / countOfStudents;
```
Студент ожидает увидеть в переменной `average` значение `2,4`. Однако переменная `average` получит значение `2{,}0`. 
**Почему так происходит?** 
1. Переменная `totalScore` имеет тип `int`.
2. Переменная `countOfStudents` имеет тип `int`.
3. Операция `/` между двумя целыми числами выполняет **целочисленное деление** (отбрасывание остатка). Выражение `12 / 5` вычисляется как целое число `2`.
4. Лишь после того, как деление завершилось и дало результат `2`, срабатывает неявное приведение этого результата к типу `double` (потому что переменная слева имеет тип `double`), превращая `2` в `2{,}0`. Дробная часть была безвозвратно утеряна *до* деления.

Чтобы избежать этой ошибки, хотя бы один из операндов деления должен быть вещественным типом (`double` или `float`), либо подвергнут явному приведению типов *до* выполнения деления.

### Разобранные примеры

#### Пример 1. Вычисление сложного арифметического выражения

**Условие:** Вычислить значение выражения $10 + 3 \times 2 - 8 / 4$ с учетом приоритета операций.

**Рисунок словами (структура выражения):**
В выражении присутствуют четыре операции: сложение (`+`), умножение (`*`), вычитание (`-`) и деление (`/`). Скобки отсутствуют. Операнды — целые числа.

**Ход рассуждений:**
1. Согласно таблице приоритетов, операции умножения (`*`) и деления (`/`) имеют более высокий приоритет (уровень 3), чем сложение (`+`) и вычитание (`-`) (уровень 4).
2. Сначала выполняются все операции умножения и деления слева направо (благодаря левосторонней ассоциативности).
   - Первая операция слева направо из приоритетных — это умножение: $3 \times 2$.
   - Вторая операция — это деление: $8 / 4$.
3. После того как умножение и деление заменят свои части выражения на промежуточные результаты, останутся только сложение и вычитание, которые имеют одинаковый приоритет и выполняются слева направо.

**Решение в общем виде и по шагам:**
Исходное выражение: 
$$10 + 3 \times 2 - 8 / 4$$

Шаг 1. Вычисляем умножение ($3 \times 2 = 6$):
$$10 + 6 - 8 / 4$$

Шаг 2. Вычисляем деление ($8 / 4 = 2$):
$$10 + 6 - 2$$

Шаг 3. Выполняем оставшиеся операции сложения и вычитания слева направо. Сначала сложение ($10 + 6 = 16$):
$$16 - 2$$

Шаг 4. Выполняем вычитание ($16 - 2 = 14$):
$$14$$

**Подстановка и вычисление в коде C#:**
```csharp
int result = 10 + 3 * 2 - 8 / 4;
Console.WriteLine(result); // Выведет 14
```

**Проверка:**
- Единицы измерения: отсутствуют (числовые операнды).
- Правдоподобие: умножение и деление выполнились первыми, порядок соблюден строго по стандарту языка C#. Ошибок типов нет, так как все операнды целые.

**Ответ:** `14`

---

#### Пример 2. Исправление ошибки деления целых чисел

**Условие:** Исправить ошибку в инициализации переменной `double result = 5 / 2;` так, чтобы переменная `result` получила точное математическое значение `2,5`, а не `2,0`.

**Рисунок словами:**
В исходном коде целое число `5` делится на целое число `2`. Справа от знака присваивания формируется целочисленный результат `2`, который затем записывается в ячейку памяти вещественного типа `double`, становясь числом `2{,}0`. Дробная часть теряется.

**Ход рассуждений:**
1. Нам нужно заставить компилятор выполнять вещественное деление, а не целочисленное.
2. Для этого хотя бы один из аргументов деления должен быть представлен как вещественное число (например, записан с плавающей точкой `5.0` или `2.0`), либо к одному из операндов нужно применить явное приведение типа.
3. Рассмотрим два способа исправления:
   - Способ А (изменение литерала): записать хотя бы одно число с точкой, например `5.0 / 2`.
   - Способ Б (явное приведение типа): применить оператор кастинга `(double)5 / 2` или `(double)5 / 2`.

**Решение в общем виде:**
Способ А:
```csharp
double result = 5.0 / 2;
```
Как это работает: литерал `5.0` имеет тип `double`. Согласно правилам неявного приведения типов (numeric promotion), перед выполнением деления второй операнд (`2`) неявно преобразуется в тип `double` (становится `2.0`). Выполняется деление двух вещественных чисел `5.0 / 2.0`, дающее точный результат `2{,}5`.

Способ Б:
```csharp
int a = 5;
int b = 2;
double result = (double)a / b;
```
Как это работает: унарная операция явного приведения типа `(double)a` имеет более высокий приоритет (уровень 2), чем деление `/` (уровень 3). Сначала переменная `a` временно преобразуется к типу `double`, а затем за счет неявного приведения переменная `b` также повышается до `double`. Происходит вещественное деление.

**Подстановка и вычисление:**
Проверим Способ А:
$$5{,}0 / 2 = 2{,}5$$

**Проверка:**
- Единицы измерения: нет.
- Правдоподобие: тип переменной `result` — `double`, результат вычислений содержит дробную часть `0,5`. Ошибка целочисленного деления устранена.

**Ответ:** `double result = 5.0 / 2;` (или `double result = (double)5 / 2;`)

## 4. Стандартные математические функции класса Math

### Назначение системного класса `System.Math` в .NET

При написании математических и инженерных программ на языке C# часто возникает необходимость выполнять сложные математические преобразования: вычислять тригонометрические функции, извлекать квадратные корни, возводить числа в произвольные степени или округлять вещественные результаты. Базовые арифметические операторы, рассмотренные ранее (`+`, `-`, `*`, `/`, `%`), обеспечивают только простейшие расчеты. 

Для реализации продвинутых вычислений платформа .NET предоставляет стандартный статический класс `System.Math`. 

> **Определение.** `System.Math` — это встроенный в платформу .NET системный класс, содержащий библиотеку статических методов, полей и констант для выполнения элементарных математических и тригонометрических операций.

Класс `System.Math` принадлежит пространству имен `System`. Это означает, что если в начале вашего файла исходного кода подключена директива `using System;`, вы можете обращаться к методам класса напрямую, не указывая каждый раз его полное имя.

Главная особенность класса `Math` заключается в том, что он является **статическим** (`static`). Из этого следуют два важных практических правила:
1. Вы не можете создать экземпляр этого класса с помощью оператора `new` (запись вроде `Math m = new Math(); вызовет ошибку компиляции`).
2. Все методы и поля класса вызываются непосредственно через его имя: `Math.ИмяМетода(аргументы)`.

Рассмотрим основные группы методов и полей, предоставляемых классом `Math`.

### Вычисление модуля числа: `Math.Abs()`

Модуль (абсолютная величина) числа — это его числу без учета знака. Иными словами, если число положительное или нуль, модуль равен самому числу; если отрицательное — числу, умноженному на $-1$.

В языке C# операция взятия модуля оформлена в виде перегруженного статического метода `Math.Abs()`. 

> **Определение.** Перегрузка методов — это механизм языка программирования, позволяющий создавать несколько методов с одинаковым именем, но с разным набором или типом параметров.

Метод `Math.Abs()` перегружен для всех основных числовых типов данных C# (как целых, так и вещественных): `int`, `long`, `float`, `double`, `decimal`, а также для типов со знаковыми ограничениями.

Синтаксис вызова:
```csharp
тип переменная = Math.Abs(значение);
```

Пример использования для различных типов данных:
```csharp
int a = Math.Abs(-15);       // Результат: 15 (тип int)
double b = Math.Abs(-23.45); // Результат: 23.45 (тип double)
decimal c = Math.Abs(-100m); // Результат: 100 (тип decimal)
```

При работе с целыми типами данных (`int`, `long`) следует помнить об аппаратных ограничениях процессора. Например, минимальное значение для типа `int` (`int.MinValue`) равно $-2\,147\,483\,648$, а максимальное равно $2\,147\,483\,647$. Поскольку положительное значение $+2\,147\,483\,648$ не помещается в диапазон типа `int`, вызов `Math.Abs(int.MinValue)` приведет к переполнению и выбросу исключения `OverflowException` (при включенной проверке переполнения) или возврату отрицательного числа. Для вещественных типов (`double`, `decimal`) такой проблемы не возникает, так как их диапазоны устроены иначе.

### Возведение в степень и квадратный корень

Для выполнения операций степенной зависимости и извлечения корней класс `Math` предлагает методы `Math.Pow()` и `Math.Sqrt()`.

#### Возведение в степень: `Math.Pow()`
> **Определение.** Метод `Math.Pow(double x, double y)` возводит указанное число `x` в заданную степень `y` и возвращает результат типа `double`.

Формальное математическое выражение:
$$\text{result} = x^y$$

Здесь:
- `x` — основание степени (первый аргумент);
- `y` — показатель степени (второй аргумент).

Оба аргумента и возвращаемое значение имеют тип `double`. Это означает, что с помощью `Math.Pow` можно извлекать даже дробные корни, передавая в качестве показателя степени дробь (например, квадратный корень эквивалентен возведению в степень $0{,}5$).

Примеры:
```csharp
double kub = Math.Pow(2.0, 3.0);   // 2 в кубе = 8.0
double koren = Math.Pow(9.0, 0.5); // Квадратный корень из 9 = 3.0
```

#### Квадратный корень: `Math.Sqrt()`
> **Определение.** Метод `Math.Sqrt(double d)` вычисляет арифметический квадратный корень из заданного числа `d` и возвращает результат типа `double`.

Математически это записывается так:
$$\text{result} = \sqrt{d}$$

Группировка аргументов и ограничение области определения: аргумент `d` должен быть неотрицательным ($d \ge 0$). Если передать отрицательное число, метод не вызовет ошибку компиляции, но вернет специальное значение `NaN` (Not a Number — не число), что может привести к скрытым багам в расчетах.

Пример:
```csharp
double r = Math.Sqrt(25.0); // Результат: 5.0
```

### Тригонометрические функции и математические константы

Инженерные и научные вычисления невозможны без тригонометрии. Класс `Math` содержит методы для вычисления синуса, косинуса, тангенса и соответствующих обратных функций (аркфункций).

#### Важнейшее правило тригонометрии в программировании
Все углы в методах класса `Math` (`Math.Sin()`, `Math.Cos()`, `Math.Tan()`) измеряются **в радианах**, а не в градусах, к которым привыкли в школе. 

Если у вас есть угол в градусах (например, $alpha$ градусов), его необходимо предварительно перевести в радианы по формуле:
$$\alpha_{\text{рад}} = \alpha_{\text{град}} \cdot \frac{\pi}{180}$$

#### Математические константы
Для выполнения такого перевода и других расчетов используются встроенные статические константы класса `Math`:
- `Math.PI` — число Пи ($\pi \approx 3{,}141592653589793$);
- `Math.E` — основание натурального логарифма, число Эйлера ($e \approx 2{,}718281828459045$).

Обе константы имеют тип `double` и доступны только для чтения (`readonly`).

Рассмотрим основные тригонометрические методы:
- `Math.Sin(double a)` — вычисляет синус угла `a`, заданного в радианах.
- `Math.Cos(double a)` — вычисляет косинус угла `a`, заданного в радианах.
- `Math.Tan(double a)` — вычисляет тангенс угла `a`, заданного в радианах.

Пример перевода градусов в радианы и вычисления синуса угла в $30^\circ$:
```csharp
double degrees = 30.0;
// Перевод в радианы: 30 * PI / 180
double radians = degrees * Math.PI / 180.0;
double sinValue = Math.Sin(radians); // Ожидается 0,5
```

### Методы округления

При делении вещественных чисел или вычислении тригонометрических функций мы часто получаем бесконечные или длинные десятичные дроби (например, $0{,}33333333...$). Для приведения их к удобному для человека виду применяются методы округления. В классе `Math` их три, и они работают по совершенно разным алгоритмам.

#### 1. Классическое округление: `Math.Round()`
> **Определение.** Метод `Math.Round(double value)` округляет вещественное число до ближайшего целого. Перегрузка `Math.Round(double value, int digits)` позволяет указать точное количество знаков после запятой (`digits`).

В C# по умолчанию используется так называемое *банковское округление* (округление до ближайшего четного, когда дробная часть ровно равна $0{,}5$). Однако чаще на практике требуется привычное школьное математическое округление. Чтобы его зафиксировать, используется дополнительный параметр перечисления `MidpointRounding.AwayFromZero`.

Пример:
```csharp
double x1 = Math.Round(4.5);        // Результат: 4 (банковское округление до четного)
double x2 = Math.Round(4.5, MidpointRounding.AwayFromZero); // Результат: 5 (математическое)
double x3 = Math.Round(7.6782, 2);  // Результат: 7{,}68 (округление до 2 знаков)
```

#### 2. Округление в меньшую сторону: `Math.Floor()`
> **Определение.** Метод `Math.Floor(double d)` возвращает наибольшее целое число, которое меньше или равно заданному вещественному числу `d` (округление вниз, «пол»).

Математически обозначается как $\lfloor d \rfloor$.

Примеры:
```csharp
double f1 = Math.Floor(4.9);  // Результат: 4.0
double f2 = Math.Floor(-4.1); // Результат: -5.0 (так как -5 меньше -4,1)
```

#### 3. Округление в большую сторону: `Math.Ceiling()`
> **Определение.** Метод `Math.Ceiling(double d)` возвращает наименьшее целое число, которое больше или равно заданному вещественному числу `d` (округление вверх, «потолок»).

Математически обозначается как $\lceil d \rceil$.

Примеры:
```csharp
double c1 = Math.Ceiling(4.1);  // Результат: 5.0
double c2 = Math.Ceiling(-4.9); // Результат: -4.0 (так как -4 больше -4,9)
```

| Метод | Что делает | Пример для `4{,}3` | Пример для `-4{,}3` |
| :--- | :--- | :--- | :--- |
| `Math.Round(val)` | К ближайшему целому | `4` | `-4` |
| `Math.Floor(val)` | Всегда вниз (к $-\infty$) | `4` | `-5` |
| `Math.Ceiling(val)`| Всегда вверх (к $+\infty$) | `5` | `-4` |

### Нахождение максимума и минимума

Для сравнения двух чисел и выбора наибольшего или наименьшего из них используются методы `Math.Max()` и `Math.Min()`.

> **Определение.** Методы `Math.Max(val1, val2)` и `Math.Min(val1, val2)` принимают два значения одного типа (`int`, `double`, `decimal` и др.) и возвращают соответственно наибольшее или наименьшее из них.

Примеры:
```csharp
int maximum = Math.Max(10, 25);    // Результат: 25
double minimum = Math.Min(3.14, 2.72); // Результат: 2.72
```

Эти методы невероятно удобны, так как избавляют от необходимости писать громоздкие конструкции с условными операторами (`if-else`) для поиска экстремумов пары чисел.

### Разобранные примеры

Ниже приведены два полностью решенных примера с подробным описанием логики рассуждений, вычислений и проверкой результатов.

#### Пример 1. Вычисление гипотенузы прямоугольного треугольника

**Условие задачи:**
Даны длины двух катетов прямоугольного треугольника: $a = 3{,}0$ м и $b = 4{,}0$ м. Найти длину гипотенузы $c$ с использованием методов `Math.Sqrt` и `Math.Pow`.

**Рисунок словами:**
Представьте прямоугольный треугольник, у которого вертикальный катет $a$ направлен вверх длиной $3{,}0$, горизонтальный катет $b$ направлен вправо длиной $4{,}0$, а соединяющая их гипотенуза $c$ образует диагональ, замыкающую прямоугольный контур. Угол между катетами равен $90^\circ$.

**Ход рассуждений:**
1. Согласно теореме Пифагора, квадрат гипотенузы равен сумме квадратов катетов:
   $$c^2 = a^2 + b^2$$
2. Чтобы найти саму гипотенузу $c$, нужно извлечь квадратный корень из суммы квадратов:
   $$c = \sqrt{a^2 + b^2}$$
3. Для реализации этой формулы на C# воспользуемся методом возведения в степень `Math.Pow(base, exponent)` для каждого катета, сложим полученные результаты оператором `+`, а затем применим метод извлечения квадратного корня `Math.Sqrt()`.

**Решение в общем виде:**
```csharp
double a = 3.0;
double b = 4.0;
double c = Math.Sqrt(Math.Pow(a, 2) + Math.Pow(b, 2));
```

**Подстановка и вычисление:**
1. Вычисляем $a^2$: `Math.Pow(3.0, 2)` дает $9{,}0$.
2. Вычисляем $b^2$: `Math.Pow(4.0, 2)` дает $16{,}0$.
3. Складываем квадраты: $9{,}0 + 16{,}0 = 25{,}0$.
4. Извлекаем квадратный корень: `Math.Sqrt(25.0)` дает $5{,}0$.

**Проверка (единицы, правдоподобие):**
- Единицы измерения: метры ($\text{м}$), так как исходные данные заданы в метрах, а извлечение квадратного корня сохраняет размерность линейной величины.
- Правдоподобие: гипотенуза обязана быть больше каждого из катетов по отдельности ($5{,}0 > 3{,}0$ и $5{,}0 > 4{,}0$), но меньше их суммы ($5{,}0 < 3{,}0 + 4{,}0 = 7{,}0$). Результат геометрически корректен (классический «египетский» треугольник $3-4-5$).

`Ответ:` Гипотенуза равна $5{,}0$ м.

---

#### Пример 2. Округление вещественного числа до двух знаков

**Условие задачи:**
Дано вещественное число $x = 7{,}678$. Найти значение этого числа, округленное до двух знаков после запятой, используя метод `Math.Round`.

**Рисунок словами:**
Числовая прямая. Число $7{,}678$ расположено между точками $7{,}67$ и $7{,}68$. Поскольку тысячные доли ($0{,}008$) находятся ближе к верхней границе, число при округлении смещается вправо до отметки $7{,}68$.

**Ход рассуждений:**
1. Требуется оставить ровно два знака после запятой. Это значит, что третья цифра после запятой (тысячные) должна быть отброшена с учетом правил округления.
2. В классе `Math` есть перегруженный метод `Math.Round(double value, int digits)`, принимающий в качестве первого аргумента само число, а в качестве второго — требуемое количество знаков после запятой (`digits = 2`).
3. Для обеспечения стандартного школьного (математического) округления в большую сторону при достижении половины разряда укажем параметр `MidpointRounding.AwayFromZero`.

**Решение в общем виде:**
```csharp
double x = 7.678;
double result = Math.Round(x, 2, MidpointRounding.AwayFromZero);
```

**Подстановка и вычисление:**
1. Передаем переменную `x = 7.678` и `digits = 2`.
2. Смотрим на третью цифру после запятой — это $8$. Так как $8 \ge 5$, вторая цифра после запятой ($7$) увеличивается на единицу и становится равной $8$.
3. Получаем итоговое значение: $7{,}68$.

**Проверка (единицы, правдоподобие):**
- Количество знаков после запятой ровно два, что соответствует требованию задачи.
- Значение $7{,}68$ находится в непосредственной близости от исходного $7{,}678$ (погрешность округления составляет всего $0{,}002$), что подтверждает правильность работы алгоритма.

`Ответ:` Округленное значение равно $7{,}68$.

## 5. Проектирование и разработка линейных программ на C#

### Понятие линейного вычислительного процесса

> **Определение.** Линейный вычислительный процесс (линейная программа) — это алгоритмическая структура, в которой действия выполняются строго последовательно, одно за другим, в том порядке, в котором они записаны в тексте программы. В линейной программе отсутствуют ветвления (условные переходы) и повторения (циклы).

Что это значит на практике? Когда вы запускаете консольное приложение на выполнение, среда выполнения .NET передает управление первой инструкции в точке входа (методе `Main`), после чего процессор последовательно выполняет каждую строку кода сверху вниз до самого конца. Ни одна строка не может быть пропущена, и ни к какой предыдущей строке нельзя вернуться без использования специальных управляющих конструкций (которые в линейных програмрах не применяются).

Примером линейного процесса из реальной жизни является вычисление стоимости покупки по фиксированной цене: запросить количество, умножить на цену, прибавить стоимость доставки, вывести результат. Все шаги неизбежны и выполняются в строго фиксированном порядке.

---

### Этапы разработки линейной программы

Создание любой программы, даже самой простой линейной, требует системного подхода. Процесс разработки делится на пять последовательных этапов:

1. **Анализ входных и выходных данных.** На этом этапе необходимо точно определить, какая информация поступает в программу из внешнего мира (от пользователя, из файла или датчиков) и какой результат программа должна выдать в качестве ответа.
2. **Выбор типов данных и переменных.** Для каждой величины (входной, промежуточной, выходной) подбирается оптимальный тип данных C#. Например, для подсчета количества предметов выбирается `int`, а для измерения длины или веса с высокой точностью — `double` или `decimal`.
3. **Составление математической или логической модели.** На основе условий задачи формулируются выражения и уравнения с использованием изученных ранее арифметических операций и методов класса `Math`.
4. **Реализация алгоритма на языке программирования.** Написание кода, который включает в себя три обязательных блока:
   - Ввод исходных данных.
   - Вычисление результатов.
   - Вывод полученных значений на экран.
5. **Тестирование и проверка.** Запуск программы с контрольными наборами данных, для которых результат известен заранее, а также проверка граничных и некорректных значений.

### Структура консольного приложения на C# в .NET 8

В современных версиях .NET (начиная с .NET 6 и актуальной .NET 8) язык C# поддерживает как традиционный синтаксис с явным объявлением пространства имен, класса и метода `Main`, так и сокращенный формат (так называемые операторы верхнего уровня — *top-level statements*). Однако для глубокого понимания архитектуры приложений и подготовки к экзамену необходимо уверенно владеть классической полной структурой.

Полный шаблон консольного приложения выглядит следующим образом:

```csharp
using System;

namespace LinearApp
{
    class Program
    {
        static void Main(string[] args)
        {
            // Здесь пишется код линейной программы
            Console.WriteLine("Программа успешно запущена.");
        }
    }
}
```

Разберем каждую строку этого шаблона:
- `using System;` — директива подключения пространства имен. Она позволяет использовать стандартные классы платформы .NET (например, `Console` или математические функции) без указания полного пути `System.Console`.
- `namespace LinearApp` — объявление пользовательского пространства имен. Пространства имен служат для логической группировки связанных классов и предотвращения конфликтов имен.
- `class Program` — объявление класса с именем `Program`. В объектно-ориентированном языке C# любой исполняемый код должен находиться внутри какого-либо класса.
- `static void Main(string[] args)` — главный метод программы, точка входа. Ключевое слово `static` означает, что метод принадлежит самому классу, а не отдельному объекту. `void` указывает на то, что метод не возвращает никакого значения. Имя `Main фиксировано — именно с него начинает работу среда .NET. Массив строк `args` используется для передачи аргументов командной строки (в простых консольных приложениях он обычно не задействуется).

### Обработка пользовательского ввода и форматированный вывод

Для создания интерактивных программ необходимо уметь принимать данные от пользователя и выводить их в понятном виде.

#### Ввод данных с консоли

Ввод текста из консоли осуществляется с помощью метода `Console.ReadLine()`. Этот метод ожидает, пока пользователь введет строку символов и нажмет клавишу `Enter`. Возвращаемое значение метода всегда имеет тип `string` (даже если пользователь ввел цифры).

Поскольку для вычислений нам необходимы числовые типы (`int`, `double`), полученную строчку необходимо преобразовать (распарсить). Для этого используются специальные методы преобразования:
- `int.Parse( строка )` — преобразует текст в целое число.
- `double.Parse( строка )` — преобразует текст в вещественное число с двойной точностью.

Пример ввода вещественного числа:
```csharp
Console.Write("Введите значение: ");
string input = Console.ReadLine();
double number = double.Parse(input);
```

#### Форматированный вывод с помощью интерполяции строк

Для вывода результатов на экран используется метод `Console.WriteLine()`. Чтобы красиво объединить текст и значения переменных, в C# применяется **интерполяция строк**. 

Строка интерполяции начинается со знака доллара `$` перед открывающей кавычкой. Внутри такой строки выражения в фигурных скобках `{}` автоматически заменяются на их значения. Кроме того, можно задавать формат вывода чисел (например, количество знаков после запятой с помощью спецификатора формата `F2` — фиксированный формат с двумя знаками).

Пример интерполяции:
```csharp
double result = 15.6789;
Console.WriteLine($"Результат вычислений: {result:F2}"); // Выведет: Результат вычислений: 15,68
```
Обратите внимание, что в русской локализации операционной системы разделителем целой и дробной части при выводе по умолчанию является запятая.

### Разобранные примеры

#### Пример 1. Расчет характеристик круга

**Условие задачи.** Написать программу на C#, которая запрашивает у пользователя радиус круга $r$ (вещественное число), вычисляет его площадь $S = \pi \cdot r^2$ и длину окружности $L = 2 \cdot \pi \cdot r$, выводя результат с точностью до двух знаков после запятой.

**Рисунок (схема) алгоритма словами:**
```
[Начало] 
   ---> [Вывод приглашения ко вводу радиуса] 
   ---> [Ввод строки -> Преобразование в double r] 
   ---> [Вычисление S = Math.PI * Math.Pow(r, 2)] 
   ---> [Вычисление L = 2 * Math.PI * r] 
   ---> [Вывод результатов S и L с форматированием F2] 
[Конец]
```

**Ход рассуждений:**
1. Для хранения радиуса, площади и длины окружности выберем тип `double`, так как входные данные и результаты могут быть дробными.
2. Значение математической константы $\pi$ возьдем из встроенного поля `Math.PI`, что обеспечит максимальную точность вычислений.
3. Для возведения радиуса в квадрат воспользуемся методом `Math.Pow(r, 2)` или простым умножением `r * r`. Умножение работает быстрее, поэтому используем его.
4. Выведем полученные значения на консоль, используя интерполяцию строк и формат `{value:F2}`.

**Решение на C#:**

```csharp
using System;

namespace CircleCalculator
{
    class Program
    {
        static void Main(string[] args)
        {
            // Настройка кодировки для корректного отображения кириллицы в консоли
            Console.OutputEncoding = System.Text.Encoding.UTF8;

            Console.WriteLine("--- Расчет параметров круга ---");
            
            // Шаг 1: Ввод исходных данных
            Console.Write("Введите радиус круга (r): ");
            string input = Console.ReadLine();
            double r = double.Parse(input);

            // Шаг 2: Вычисления
            double area = Math.PI * r * r;
            double length = 2 * Math.PI * r;

            // Шаг 3: Вывод результатов с округлением до 2 знаков
            Console.WriteLine();
            Console.WriteLine($"Результаты расчетов для радиуса r = {r:F2}:");
            Console.WriteLine($"Площадь круга (S)       = {area:F2}");
            Console.WriteLine($"Длина окружности (L)    = {length:F2}");
        }
    }
}
```

**Проверка и тестовый пример:**
- Пусть пользователь введет значение радиуса $r = 5{,}0$.
- Вычисления:
  - Площадь: $S = \pi \cdot 5^2 \approx 3{,}14159265 \cdot 25 = 78{,}539816...$ Округление до двух знаков дает $78{,}54$.
  - Длина: $L = 2 \cdot \pi \cdot 5 = 10 \cdot \pi \approx 31{,}4159265...$ Округление до двух знаков дает $31{,}42$.
- Единицы измерения: радиус в условных единицах (например, см), площадь в квадратных единицах ($\text{см}^2$), длина в линейных единицах ($\text{см}$). Программа отработала корректно.

`Ответ:` При вводе $5{,}0$ программа выведет площадь $78{,}54$ и длину окружности $31{,}42$.

#### Пример 2. Сумма цифр трехзначного числа

**Условие задачи.** Написать программу на C#, которая принимает трехзначное целое число, разлагает его на цифры с помощью операций деления нацело (`/`) и остатка от деления (`%`), а затем вычисляет сумму этих цифр.

**Рисунок (схема) алгоритма словами:**
```
[Начало] 
   ---> [Ввод трехзначного числа number] 
   ---> [Выделение сотен: hundreds = number / 100] 
   ---> [Выделение десятков: tens = (number / 10) % 10] 
   ---> [Выделение единиц: units = number % 10] 
   ---> [Вычисление суммы: sum = hundreds + tens + units] 
   ---> [Вывод исходного числа и суммы его цифр] 
[Конец]
```

**Ход рассуждений:**
1. Пусть исходное число хранится в переменной типа `int` (например, `number = 582`).
2. Как получить первую цифру (сотни)? При делении целого числа на 100 дробная часть отбрасывается. $582 / 100 = 5$.
3. Как получить последнюю цифру (единицы)? Это остаток от деления числа на 10. $582 \% 10 = 2$.
4. Как получить среднюю цифру (десятки)? Сначала разделим число на 10, чтобы отбросить единицы ($582 / 10 = 58$), а затем возьмем остаток от деления полученного результата на 10 ($58 \% 10 = 8$).
5. Сложим полученные три цифры и выведем результат.

**Решение на C#:**

```csharp
using System;

namespace DigitSumCalculator
{
    class Program
    {
        static void Main(string[] args)
        {
            Console.OutputEncoding = System.Text.Encoding.UTF8;

            Console.WriteLine("--- Сумма цифр трехзначного числа ---");
            
            // Шаг 1: Ввод трехзначного числа
            Console.Write("Введите целое трехзначное число: ");
            int number = int.Parse(Console.ReadLine());

            // Шаг 2: Извлечение разрядов
            int hundreds = number / 100;         // Старший разряд (сотни)
            int tens = (number / 10) % 10;     // Средний разряд (десятки)
            int units = number % 10;           // Младший разряд (единицы)

            // Шаг 3: Вычисление суммы цифр
            int sum = hundreds + tens + units;

            // Шаг 4: Вывод результатов
            Console.WriteLine();
            Console.WriteLine($"Исходное число: {number}");
            Console.WriteLine($"Сотни: {hundreds}");
            Console.WriteLine($"Десятки: {tens}");
            Console.WriteLine($"Единицы: {units}");
            Console.WriteLine($"Сумма цифр: {hundreds} + {tens} + {units} = {sum}");
        }
    }
}
```

**Проверка и тестовый пример:**
- Пусть пользователь введет число `number = 479`.
- Вычисления:
  - `hundreds = 479 / 100 = 4` (целочисленное деление).
  - `tens = (479 / 10) % 10 = 47 % 10 = 7`.
  - `units = 479 % 10 = 9`.
  - `sum = 4 + 7 + 9 = 20`.
- Проверка правдоподобия: $4 + 7 + 9 = 20$. Алгоритм универсален и корректно работает для любого трехзначного числа в диапазоне от 100 до 999.

`Ответ:` Для числа 479 программа выделит цифры 4, 7, 9 и выдаст сумму цифр, равную 20.

### Тестирование линейных программ и граничные случаи

При завершении разработки линейной программы важно выполнить ее тестирование. В отличие от сложных систем, линейные программы проверяются просто, но требуют внимания к граничным условиям:
- **Нулевые и отрицательные значения.** Если по смыслу задачи величина не может быть отрицательной (например, радиус или количество предметов), программа должна корректно отрабатывать математически, хотя на практике для фильтрации неверного ввода в дальнейшем применяются условные операторы.
- **Деление на ноль.** Программист должен убедиться, что в знаменателях расчетных формул в результате пользовательского ввода не может оказаться ноль, так как это приведет к аварийному завершению программы с исключением `DivideByZeroException`.
- **Переполнение типов.** При работе с большими числами необходимо следить, чтобы результат арифметических операций не выходил за допустимый диапазон выбранного типа данных (например, для `int` максимальное значение составляет примерно $2 \cdot 10^9$).

## Типичные ошибки

1. **Целочисленное деление вместо вещественного.** 
   *В чём ошибка:* Выражение вроде `double res = 7 / 2;` записывает в переменную `res` значение `3{,}0`, а не `3{,}5`. 
   *Почему возникает:* Компилятор выполняет деление целых чисел (`int / int`), отбрасывая дробную часть *до* того, как результат будет неявно приведен к типу `double`.
   *Как избежать:* Записывать хотя бы один операнд в виде вещественного числа (например, `7.0 / 2`) или использовать явное приведение типов (`(double)7 / 2`).

2. **Использование градусов вместо радиан в тригонометрических функциях.**
   *В чём ошибка:* Вызов `Math.Sin(90)` возвращает не единицу, а некорректное значение.
   *Почему возникает:* Все методы класса `Math` для работы с тригонометрией принимают углы исключительно в радианах.
   *Как избежать:* Всегда переводить градусы в радианы по формуле `radians = degrees * Math.PI / 180.0`.

3. **Неправильное понимание постфиксного инкремента.**
   *В чём ошибка:* Написание конструкции вида `int y = x++;`, когда требуется сразу использовать увеличенное значение.
   *Почему возникает:* Постфиксная форма (`x++`) возвращает старое значение переменной, которое она имела до инкремента, и лишь затем увеличивает её в памяти.
   *Как избежать:* Использовать префиксную форму (`++x`), если значение нужно увеличить перед его участием в выражении.

4. **Некорректное преобразование строки в число при вводе с консоли.**
   *В чём ошибка:* Написание кода `int x = Console.ReadLine();`.
   *Почему возникает:* Метод `Console.ReadLine()` всегда возвращает строку (`string`), которую нельзя неявно присвоить целочисленной переменной.
   *Как избежать:* Использовать методы парсинга: `int.Parse(Console.ReadLine())` или `double.Parse(Console.ReadLine())`.

5. **Игнорирование знака при вычислении остатка от деления.**
   *В чём ошибка:* Ожидание положительного остатка при делении отрицательного числа, например `(-7) % 3`.
   *Почему возникает:* В языке C# остаток от деления всегда берет знак делимого (левого операнда), поэтому `(-7) % 3` дает `-1`.
   *Как избежать:* Учитывать правило знаков или использовать метод `Math.Abs()`, если требуется получить математический модуль остатка.

6. **Многократное изменение переменной через инкремент в одном выражении.**
   *В чём ошибка:* Запись вида `int res = ++x + x++;`.
   *Почему возникает:* Порядок вычисления операндов в таких выражениях не гарантирует строгой последовательности, что приводит к непредсказуемому результату.
   *Как избежать:* Никогда не применять инкремент или декремент к одной и той же переменной более одного раза в пределах одной инструкции.

7. **Потеря точности при смешивании типов `double` и `decimal`.**
   *В чём ошибка:* Попытка выполнить арифметическую операцию между `double` и `decimal` без явного приведения.
   *Почему возникает:* Между этими типами отсутствует неявное преобразование из-за разной архитектуры хранения данных в памяти.
   *Как избежать:* Приводить все операнды к единому типу (для точных финансовых расчетов использовать исключительно `decimal`).

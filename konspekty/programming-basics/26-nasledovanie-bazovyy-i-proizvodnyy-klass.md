## 1. Сущность и назначение наследования в ООП

### Сущность и назначение наследования в ООП

Объектно-ориентированное программирование предоставляет мощные инструменты для организации кода, среди которых центральное место занимает **наследование**. Представьте, что вы разрабатываете программное обеспечение для крупного университета. В системе есть студенты, преподаватели и сотрудники учебной части. У всех них есть общие характеристики: фамилия, имя, отчество, дата рождения и домашний адрес. Если описывать каждый такой класс с нуля, придется дублировать блоки кода, отвечающие за хранение личных данных и работу с ними. Наследование позволяет избежать этого дублирования, создавая единую иерархию типов.

> **Определение.** **Наследование** — это базовый принцип объектно-ориентированного программирования, который позволяет создавать новый класс на основе уже существующего, переиспользуя его поля, методы и свойства, а также добавляя к ним новые члены или изменяя существующее поведение.

С помощью наследования мы решаем две ключевые задачи:
1. **Повторное использование кода (reusability):** написанный однажды логический блок для базовой сущности становится доступным во всех дочерних классах без необходимости копирования.
2. **Расширение функционала (extensibility):** производный класс может добавлять новые свойства и методы, специфичные именно для него, не нарушая работу базовой логики.

В терминологии объектно-ориентированного программирования участвуют две стороны:
* **Базовый класс (parent class, base class, суперкласс)** — исходный класс, чья структура и функционал передаются «по наследству».
* **Производный класс (child class, derived class, подкласс)** — новый класс, который создается на основе базового и получает доступ к его членам.

---

### Синтаксис наследования в C#

В языке C# связь между базовым и производным классами задается с помощью двоеточия (`:`), которое ставится после имени нового класса, после чего указывается имя базового класса.

Рассмотрим базовый синтаксис объявления:

```csharp
// Объявление базового класса
class BaseClass
{
    // Поля, свойства, методы базового класса
}

// Объявление производного класса, наследующего BaseClass
class DerivedClass : BaseClass
{
    // Новые поля, свойства, методы производного класса
}
```

Важнейшим архитектурным ограничением в языке C# является поддержка **одиночного наследования классов**. Это означает, что каждый класс может иметь ровно один прямой базовый класс. Запись вида `class Derived : ClassA, ClassB` для классов вызовет ошибку компиляции. Язык C# сознательно отказывается от множественного наследования реализации (в отличие от C++), чтобы избежать классической проблемы неоднозначности, известной как «алмазная проблема» (diamond problem), когда потомок не может определить, версию какого именно родительского метода ему вызывать, если они совпадают по имени. 

*(Примечание: множественное наследование интерфейсов в C# разрешено и активно применяется, но интерфейсы не содержат реализации состояния).*

---

### Критерий правильного проектирования: отношение «is-a»

Прежде чем написать код с использованием двоеточия, необходимо убедиться, что между сущностями действительно существует правильная логическая связь. В проектировании ПО главным критерием служит отношение **«is-a» («является»)**.

Если мы говорим, что «Менеджер **является** Сотрудником», то применение наследования оправдано и архитектурно верно. Менеджер обладает всеми атрибутами обычного сотрудника, но имеет свою специфику (например, размер бонуса или команду подчиненных). 

С другой стороны, если у нас есть класс `Car` (Автомобиль) и класс `Engine` (Двигатель), писать `class Car : Engine` **нельзя**. Автомобиль — это не двигатель. Правильным отношением здесь будет «has-a» («имеет»), которое реализуется через включение (композицию): у автомобиля просто есть поле типа `Engine`. Нарушение этого правила приводит к жестко связанному, трудно поддерживаемому и запутанному коду.

---

### Что передается по наследству и правила видимости

При создании производного класса важно понимать, какие именно члены базового класса переходят к потомку, а к чему доступ оказывается заблокированным.

Вне зависимости от модификаторов доступа, в производный класс **передаются абсолютно все члены** базового класса (поля, свойства, методы). Однако это не значит, что потомок может напрямую обратиться к каждому из них. Здесь в силу вступают модификаторы доступа:

1. **`public` члены:** полностью доступны как внутри базового класса, так и внутри производного, а также из любого другого кода программы.
2. **`private` члены:** переходят в производный класс, но остаются **строго скрытыми**. Потомок физически владеет этим полем или методом (оно выделяется в памяти при создании объекта), но обратиться к нему напрямую через имя в коде производного класса невозможно. Компилятор выдаст ошибку доступа.
3. **`protected` члены:** занимают промежуточное положение. Они закрыты для внешнего мира (как `private`), но полностью доступны внутри производных классов. Этот модификатор создан специально для настройки безопасного взаимодействия внутри иерархии классов.

Сводная таблица видимости членов базового класса изнутри производного класса:

| Модификатор члена в базе | Доступен ли напрямую в производном классе? | Доступен ли из внешнего кода (через объект потомка)? |
| :--- | :--- | :--- |
| `public` | Да | Да |
| `protected` | Да | Нет |
| `private` | Нет (существует в памяти, но имя невидимо) | Нет |

### Неявное приведение типов (Upcasting)

Поскольку производный класс расширяет базовый, объект класса-потомка содержит в себе всё, что есть у базового класса, плюс собственные дополнения. Это позволяет использовать полиморфный подход на уровне типов данных.

В C# разрешено **неявное восходящее преобразование типов (upcasting)**: ссылку на объект производного класса можно безопасно присвоить переменной, тип которой равен базовому классу. 

```csharp
Manager m = new Manager();
Employee e = m; // Неявное приведение типов (upcasting)
```

Обратное преобразование — когда мы пытаемся положить в переменную типа `Manager` ссылку на базовый `Employee` — неявно выполнить нельзя, так как базовый класс ничего не знает о специфических полях потомка. Такое преобразование требует явного приведения (downcasting), о чем будет рассказано в следующих разделах.

### Разобранный пример: Иерархия «Сотрудник и Менеджер»

Давайте спроектируем систему учета персонала. Создадим базовый класс `Employee`, описывающий общие характеристики любого сотрудника компании (полное имя и оклад), и производный класс `Manager`, который расширяет функционал сотрудника за счет учета ежемесячного бонуса.

#### Условие задачи
1. Спроектировать класс `Employee` с полями для хранения ФИО (строка) и базовой зарплаты (десятичное число `decimal`). Предусмотреть конструктор для инициализации этих полей и метод для расчета общей выплаты.
2. Спроектировать класс `Manager`, наследующий `Employee`, добавив собственное поле для квартального бонуса.
3. Написать исполняемый код, создать экземпляр менеджера, передать ему значения через конструктор и вывести информацию о сотруднике на консоль.

#### Рисунок схемы классов (ASCII)
```text
  +---------------------------------------+
  |               Employee                |
  |---------------------------------------+
  | - fullName : string                   |
  | - baseSalary : decimal                |
  |---------------------------------------+
  | + Employee(name, salary)              |
  | + GetInfo() : string                  |
  +---------------------------------------+
                      ^
                      | (наследование)
  +---------------------------------------+
  |                Manager                |
  |---------------------------------------+
  | - bonus : decimal                     |
  |---------------------------------------+
  | + Manager(name, salary, bonus)        |
  | + GetTotalCompensation() : decimal    |
  +---------------------------------------+
```

#### Ход рассуждений
1. Создаем класс `Employee`. Поля `fullName` и `baseSalary` сделаем доступными для чтения через свойства или защищенными, чтобы к ним можно было обратиться из дочернего класса (или будем передавать их в конструктор базового класса). Для простоты инкапсуляции объявим поля как `private`, а для инициализации задействуем конструктор.
2. Создаем класс `Manager` через двоеточие: `class Manager : Employee`.
3. Менеджеру требуются те же данные, что и обычному сотруднику (ФИО и зарплата), плюс собственное поле `bonus`. Чтобы не дублировать код инициализации ФИО и зарплаты, мы передадим эти параметры в конструктор базового класса с помощью ключевого слова `base`.
4. Напишем метод расчета итоговой суммы выплат, объединяющий базовый оклад и бонус.

#### Полный исходный код программы на C#

```csharp
using System;

namespace InheritanceDemo
{
    // Базовый класс, описывающий сотрудника
    class Employee
    {
        // Закрытые поля для инкапсуляции данных
        private string fullName;
        private decimal baseSalary;

        // Конструктор базового класса
        public Employee(string fullName, decimal baseSalary)
        {
            this.fullName = fullName;
            this.baseSalary = baseSalary;
        }

        // Публичное свойство для доступа к ФИО
        public string FullName
        {
            get { return fullName; }
        }

        // Публичное свойство для доступа к окладу
        public decimal BaseSalary
        {
            get { return baseSalary; }
        }

        // Метод для получения строкового представления сотрудника
        public virtual string GetInfo()
        {
            return $"Сотрудник: {fullName}, Оклад: {baseSalary:C}";
        }
    }

    // Производный класс, описывающий менеджера
    class Manager : Employee
    {
        // Дополнительное поле, уникальное для менеджера
        private decimal bonus;

        // Конструктор производного класса
        // Ключевое слово base(...) вызывает конструктор базового класса Employee
        public Manager(string fullName, decimal baseSalary, decimal bonus) 
            : base(fullName, baseSalary)
        {
            this.bonus = bonus;
        }

        // Свойство для доступа к бонусу
        public decimal Bonus
        {
            get { return bonus; }
        }

        // Метод расчёта общей компенсации (оклад + бонус)
        public decimal GetTotalCompensation()
        {
            // Обратите внимание: BaseSalary доступно, так как свойство public.
            // Если бы поле baseSalary в Employee было private и без свойств, 
            // прямого доступа к нему из Manager не было бы.
            return BaseSalary + bonus;
        }
    }

    class Program
    {
        static void Main(string[] args)
        {
            // Установка кодировки для корректного вывода символа рубля (:C)
            Console.OutputEncoding = System.Text.Encoding.UTF8;

            // Создаем объект производного класса Manager
            Manager projectManager = new Manager("Иванов Иван Иванович", 85000.00m, 25000.00m);

            // Демонстрация неявного приведения типов (Upcasting)
            // Переменная базового типа ссылается на объект производного класса
            Employee genericEmployee = projectManager;

            // Выводим информацию, используя методы базового класса
            Console.WriteLine(projectManager.GetInfo());
            Console.WriteLine($"Размер бонуса: {projectManager.Bonus:C}");
            Console.WriteLine($"Итоговая компенсация: {projectManager.GetTotalCompensation():C}");

            // Проверка восходящего преобразования:
            // genericEmployee знает о методе GetInfo() из класса Employee
            Console.WriteLine("\nПроверка через ссылку базового типа:");
            Console.WriteLine(genericEmployee.GetInfo());

            // Завершение работы консольного приложения
            Console.WriteLine("\nНажмите любую клавишу для выхода...");
            Console.ReadKey();
        }
    }
}
```

#### Пример ввода и вывода
*Ввод данных:* жестко задан в коде в методе `Main` (объект создается с параметрами: `Иванов Иван Иванович`, `85000.00`, `25000.00`).

*Вывод в консоли:*
```text
Сотрудник: Иванов Иван Иванович, Оклад: 85 000,00 ₽
Размер бонуса: 25 000,00 ₽
Итоговая компенсация: 110 000,00 ₽

Проверка через ссылку базового типа:
Сотрудник: Иванов Иван Иванович, Оклад: 85 000,00 ₽

Нажмите любую клавишу для выхода...
```

#### Проверка и анализ правильности
1. **Единицы измерения и типы:** Для денежных сумм использован тип данных `decimal`, что исключает типичные для `double` погрешности округления при финансовых расчетах. Форматирование `{...:C}` выводит данные в валютном формате текущей локали.
2. **Правдоподобность логики:** Менеджер корректно перенял свойства базового класса `Employee` (ФИО и базовую зарплату), добавил собственную составляющую (бонус) и успешно посчитал общую сумму выплаты ($85\,000 + 25\,000 = 110\,000$). Восходящее преобразование (`Upcasting`) сработало корректно, позволив работать с объектом менеджера через интерфейс базового класса `Employee`.

## 2. Модификатор доступа protected и его роль в иерархиях

### Проблема ограничения доступа private в иерархиях классов

При проектировании классов в объектно-ориентированном программировании важнейшую роль играет принцип инкапсуляции — сокрытие внутреннего состояния объекта от внешнего вмешательства. Для реализации этого принципа в языке C# используются модификаторы доступа. Ранее мы подробно рассмотрели модификаторы `private` и `public`. Напомним их суть:

- `private` (закрытый) — член класса доступен исключительно внутри того класса, в котором он объявлен. Никакой другой класс, включая производные (дочерние), не имеет прямого доступа к `private`-полям и методам.
- `public` (открытый) — член класса доступен отовсюду, как внутри сборки, так и за её пределами.

Синтаксис наследования позволяет производному классу перенимать поля, методы и свойства базового класса. Однако здесь возникает архитектурное противоречие, связанное с модификатором `private`. 

Представьте ситуацию: вы создали базовый класс, описывающий некую общую сущность, например, банковский счёт. Внутри этого класса объявлены важные данные (например, текущий баланс) с модификатором `private`, чтобы случайный внешний код не мог произвольно изменить сумму денег. Затем вы создаёте производный класс, реализующий специализированный вид счёта (например, кредитный счёт со специфической логикой начисления задолженности). Методам этого производного класса требуется выполнять математические операции с балансом. 

Поскольку баланс объявлен как `private` в базовом классе, код производного класса **не имеет к нему прямого доступа**. Компилятор C# выдаст ошибку уровня безопасности. Возникает дилемма:
1. Если сделать поле `public`, то инкапсуляция будет полностью разрушена: любой внешний код сможет напрямую менять баланс счета, минуя правила безопасности банка.
2. Если оставить поле `private`, то написать код в производном классе, управляющий этим балансом напрямую, окажется невозможно.

Для разрешения подобных противоречий в C# предусмотрен промежуточный модификатор доступа — `protected`.

---

### Модификатор доступа protected: определение и семантика

> **Определение.** Модификатор доступа `protected` (защищенный) устанавливает такой уровень видимости, при котором член класса доступен внутри самого класса-родителя, а также во всех классах-наследниках (производных классах) вне зависимости от того, в какой сборке они находятся. Для остального внешнего кода `protected`-члены остаются полностью невидимыми, точно так же, как и `private`.

Рассмотрим схематично, кому и что разрешено при использовании различных модификаторов доступа:

```
+-------------------------------------------------------------+
| Область видимости              | private | protected | public |
+-------------------------------------------------------------+
| Внутри того же класса          |   Да    |    Да     |   Да   |
| В производном классе (наследник)|   Нет   |    Да     |   Да   |
| Вне класса (произвольный код)  |   Нет   |    Нет    |   Да   |
+-------------------------------------------------------------+
```

Ключевое отличие `protected` от `private` заключается именно в строчке «В производном классе». Наследники получают право обращаться к защищенным членам базового класса так, будто эти члены объявлены непосредственно внутри них самих.

---

### Сравнение модификаторов private, protected и public в контексте иерархии

Чтобы окончательно закрепить понимание разницы между модификаторами, сведем их поведение в иерархии классов в наглядную таблицу:

| Модификатор | Доступ внутри базового класса | Доступ внутри производного класса | Доступ извне (в программе / Main) |
|---|---|---|---|
| `private` | Доступно | **Недоступно** (ошибка компиляции) | Недоступно |
| `protected` | Доступно | **Доступно** | Недоступно |
| `public` | Доступно | Доступно | **Доступно** |

При проектировании иерархии важно помнить золотое правило ООП: **минимизируйте область видимости**. Если член класса нужен только внутри родительского класса — делайте его `private`. Если он должен быть доступен потомкам для реализации внутренней логики наследников — используйте `protected`. Если же метод или свойство представляют собой интерфейс взаимодействия объекта с внешним миром — они должны быть `public`.

---

### Защищенные члены как контракт между базовым классом и потомками

В архитектуре программного обеспечения `protected`-члены образуют специальный внутренний контракт (agreement) между создателем базового класса и разработчиками производных классов. 

Базовый класс берет на себя ответственность за хранение состояния и предоставление базовой инфраструктуры, а защищенные члены служат «рабочими инструментами» для расширения этой инфраструктуры в дочерних классах. При этом разработчик конечного приложения, который просто создает экземпляры классов и вызывает их `public`-методы, даже не подозревает о существовании `protected`-полей — для него они скрыты за непроницаемой стеной инкапсуляции.

---

### Правила проектирования: поля private/protected, методы public

На практике проектирования классов сложились строгие стандарты (best practices), которые защищают программу от ошибок и делают код поддерживаемым:

1. **Поля класса практически всегда делают закрытыми (`private`) или защищенными (`protected`).** Прямой доступ к полям извне класса нарушает инкапсуляцию, так как объект теряет контроль над тем, какие значения присваиваются его внутренним переменным.
2. **Для доступа к полям используют свойства (`property`) или методы (`public`).** Свойства позволяют добавить валидацию (проверку) данных перед их изменением. Например, свойство может запретить устанавливать отрицательное значение зарплаты или баланса.
3. **Защищенные поля (`protected`) применяются тогда, когда производным классам требуется эффективный и глубокий доступ к внутреннему представлению данных базового класса**, когда накладные расходы на вызов виртуальных методов или свойств избыточны, либо когда логика потомка тесно завязана на внутреннюю структуру родителя.

---

### Модификатор protected internal

В платформе .NET код организуется в сборки (assemblies — файлы с расширениями `.dll` или `.exe`). Иногда возникает необходимость объединить правила видимости `protected` и `internal` (доступно внутри текущей сборки).

Для этого существует составной модификатор `protected internal`:
- Член класса с таким модификатором доступен **внутри текущей сборки** для любого кода, а также **внутри производных классов**, даже если эти производные классы находятся в абсолютно другой сборке.

### Полный разбор примера: демонстрация ошибки private и исправление через protected

Рассмотрим практическую задачу. Нам необходимо спроектировать систему банковских счетов. Есть базовый класс `Account` (обычный банковский счёт), содержащий информацию о балансе. Есть производный класс `CreditAccount` (кредитный счёт), который позволяет уходить в минус в пределах установленного кредитного лимита.

Посмотрим, к чему приведет попытка обратиться к закрытому полю `balance` из производного класса, и как исправить эту проблему с помощью `protected`.

#### Неправильный вариант (с использованием private):

```csharp
using System;

class Account
{
    private decimal balance; // Закрытое поле баланса

    public Account(decimal initialBalance)
    {
        balance = initialBalance;
    }

    public void PrintBalance()
    {
        Console.WriteLine($"Текущий баланс: {balance:F2} руб.");
    }
}

class CreditAccount : Account
{
    private decimal creditLimit;

    public CreditAccount(decimal initialBalance, decimal limit) : base(initialBalance)
    {
        creditLimit = limit;
    }

    public void WithdrawWithCredit(decimal amount)
    {
        // ОШИБКА КОМПИЛЯЦИИ: поле 'balance' недоступно из-за его модификатора доступа private
        // balance -= amount; 
    }
}
```

Компилятор выдаст ошибку, так как класс `CreditAccount` не имеет права напрямую обращаться к `private`-полю `balance`, объявленному в классе `Account`.

#### Исправленный вариант (с использованием protected):

Перепишем код корректно, заменив `private` на `protected` для поля `balance`, и добавим полноценную логику списания средств с учетом кредитного лимита.

```csharp
using System;

namespace BankApp
{
    // Базовый класс банковского счета
    class Account
    {
        // Защищенное поле: доступно внутри этого класса и всех его наследников
        protected decimal balance;

        // Конструктор базового класса
        public Account(decimal initialBalance)
        {
            if (initialBalance < 0)
            {
                throw new ArgumentException("Начальный баланс не может быть отрицательным.");
            }
            balance = initialBalance;
        }

        // Открытый метод для просмотра баланса
        public virtual void DisplayInfo()
        {
            Console.WriteLine($"Основной счет. Баланс: {balance:F2} руб.");
        }
    }

    // Производный класс кредитного счета
    class CreditAccount : Account
    {
        private decimal creditLimit; // Кредитный лимит (доступен только здесь)

        // Конструктор производного класса, передающий данные в базовый конструктор
        public CreditAccount(decimal initialBalance, decimal limit) : base(initialBalance)
        {
            if (limit < 0)
            {
                throw new ArgumentException("Кредитный лимит не может быть отрицательным.");
            }
            creditLimit = limit;
        }

        // Метод снятия средств, использующий защищенное поле balance из базового класса
        public bool Withdraw(decimal amount)
        {
            if (amount <= 0)
            {
                Console.WriteLine("Сумма снятия должна быть положительной.");
                return false;
            }

            // Прямой доступ к защищенному полю balance, унаследованному от Account
            // Доступный лимит с учетом кредита составляет (balance + creditLimit)
            if (balance + creditLimit >= amount)
            {
                balance -= amount; // Изменяем унаследованное защищенное поле напрямую
                Console.WriteLine($"Успешно снято: {amount:F2} руб. Текущий баланс: {balance:F2} руб.");
                return true;
            }
            else
            {
                Console.WriteLine($"Операция отклонена. Превышен кредитный лимит. Доступно: {balance + creditLimit:F2} руб.");
                return false;
            }
        }

        // Переопределение метода отображения информации
        public override void DisplayInfo()
        {
            Console.WriteLine($"Кредитный счет. Собственный баланс: {balance:F2} руб., Кредитный лимит: {creditLimit:F2} руб.");
        }
    }

    class Program
    {
        static void Main(string[] args)
        {
            // Создаем обычный счет (этот код скомпилировался бы и ранее)
            Account baseAccount = new Account(5000{,}00m);
            baseAccount.DisplayInfo();

            Console.WriteLine(new string('-', 40));

            // Создаем кредитный счет с начальным балансом 1000 руб. и лимитом 15000 руб.
            CreditAccount myCreditAccount = new CreditAccount(1000{,}00m, 15000{,}00m);
            myCreditAccount.DisplayInfo();

            // Пытаемся снять сумму, превышающую собственный баланс, но входящую в кредитный лимит
            Console.WriteLine("\nПопытка снять 5000 руб. (за счет кредитного лимита):");
            myCreditAccount.Withdraw(5000{,}00m);

            // Проверяем итоговое состояние счета
            Console.WriteLine();
            myCreditAccount.DisplayInfo();
        }
    }
}
```

#### Пояснение по строкам и блокам кода:
1. `protected decimal balance;` в классе `Account` — делает поле скрытым от внешнего мира (программа в `Main` не может написать `myCreditAccount.balance = 100000;`), но открывает его для класса `CreditAccount`.
2. `base(initialBalance)` в конструкторе `CreditAccount` — вызывает конструктор базового класса для корректной инициализации унаследованного поля `balance`.
3. `balance -= amount;` в методе `Withdraw` класса `CreditAccount` — прямое изменение защищенного поля родительского класса. Без модификатора `protected` эта строчка вызвала бы ошибку компиляции.

#### Пример вывода программы на консоль:
```text
Основной счет. Баланс: 5000,00 руб.
----------------------------------------
Кредитный счет. Собственный баланс: 1000,00 руб., Кредитный лимит: 15000,00 руб.

Попытка снять 5000 руб. (за счет кредитного лимита):
Успешно снято: 5000,00 руб. Текущий баланс: -4000,00 руб.

Кредитный счет. Собственный баланс: -4000,00 руб., Кредитный лимит: 15000,00 руб.
```

#### Проверка и оценка сложности:
- **Оценка сложности по времени:** операции списания и вывода информации выполняются за время $O(1)$, так как происходят простые арифметические действия и вызовы методов без циклов и рекурсии.
- **Оценка сложности по памяти:** $O(1)$, создается фиксированное количество объектов в памяти (стек/куча), затраты памяти минимальны.
- **Правдоподобность:** Логика банковских операций корректна, типы данных `decimal` выбраны правильно для работы с денежными суммами (чтобы избежать погрешностей округления, свойственных типам с плавающей точкой `float` и `double`). Десятные разделители в коде C# соответствуют стандарту языка (точка).

## 3. Использование ключевого слова base

### Назначение ключевого слова `base`

При проектировании иерархий классов в объектно-ориентированном программировании часто возникает ситуация, когда производный класс расширяет или изменяет функциональность, заложенную в базовом классе. Однако дочернему классу нередко требуется прямой доступ к тем членам родительского класса (полям, методам или конструкторам), которые были скрыты или переопределены, либо к инициализации родительской части объекта. Для решения этой задачи в языке C# используется ключевое слово `base`.

> **Определение.** Ключевое слово `base` — это специальный указатель в производном классе, который обеспечивает прямую ссылку на экземпляр его непосредственного базового класса.

Ключевое слово `base` выполняет две главные функции:
1. Обеспечивает доступ к неявно скрытым полям или методам базового класса из методов производного класса.
2. Позволяет явно вызывать конструктор базового класса из конструктора производного класса с передачей необходимых аргументов.

Важно понимать принципиальную разницу между ключевыми словами `this` и `base`:
- `this` ссылается на текущий объект класса, в котором оно написано (включая все унаследованные члены).
- `base` ссылается исключительно на ту часть объекта, которая унаследована от непосредственного родителя, игнорируя переопределения в текущем классе.

---

### Сокрытие членов базового класса и обращение к скрытому члену через `base`

Когда в производном классе объявляется член (поле, метод или свойство) с тем же именем и сигнатурой, что и член в базовом классе, происходит процесс, называемый сокрытием (shadowing). При этом член базового класса оказывается «затененным» внутри производного класса.

Рассмотрим пример. Пусть у нас есть базовый класс, описывающий стандартное устройство вывода информации, и производный класс, который добавляет специфическое форматирование. Если мы объявим метод с одинаковым именем в обоих классах, вызов этого метода через объект производного класса по умолчанию выполнит версию из дочернего класса.

Для того чтобы явно обратиться к скрытой версии метода или поля из родительского класса, используется синтаксис `base.ИмяЧлена`.

Рассмотрим фрагмент кода, демонстрирующий сокрытие поля и метода:

```csharp
using System;

class Machine
{
    protected string status = "Остановлен";

    public void ShowStatus()
    {
        Console.WriteLine($"Статус машины: {status}");
    }
}

class SmartMachine : Machine
{
    // Сокрытия поля status не происходит, но мы переопределяем метод ShowStatus
    // Допустим, мы хотим явно скрыть метод базового класса:
    new public void ShowStatus()
    {
        // Вызываем метод базового класса через base, чтобы не дублировать логику
        base.ShowStatus();
        Console.WriteLine("Режим работы: Умный дом (активен)");
    }
}

class Program
{
    static void Main()
    {
        SmartMachine myMachine = new SmartMachine();
        myMachine.ShowStatus();
    }
}
```

В данном примере в классе `SmartMachine` метод `ShowStatus` помечен ключевым словом `new` (чтобы явно сообщить компилятору о намерении скрыть родительский метод и избавиться от предупреждения). Внутри этого метода строка `base.ShowStatus();` вызывает оригинальную реализацию из класса `Machine`, после чего выполняется дополнительный код дочернего класса.

---

### Передача параметров в конструктор базового класса с помощью синтаксиса `base(...)`

Конструкторы не передаются по наследству напрямую, как обычные методы или поля. Каждый класс должен иметь собственные конструкторы. Тем не менее, при создании объекта производного класса в памяти должна быть инициализирована и его родительская часть.

По умолчанию, если в конструкторе производного класса явно не указан вызов конструктора базы, компилятор C# автоматически пытается вызвать конструктор по умолчанию (без параметров) базового класса (`base()`). 

Однако если у базового класса нет конструктора без параметров (например, вы написали конструктор, принимающий аргументы, и компилятор перестал генерировать конструктор по умолчанию автоматически), то производный класс обязан явно указать, какой именно конструктор базового класса должен быть вызван, используя двоеточие и ключевое слово `base` в заголовке конструктора.

Синтаксис вызова конструктора базового класса:

```csharp
class DerivedClass : BaseClass
{
    public DerivedClass(параметры_производного) : base(параметры_базового)
    {
        // Инициализация полей производного класса
    }
}
```

Здесь `base(...)` принимает аргументы и передает их в соответствующий конструктор родительского класса до того, как начнет выполняться тело конструктора производного класса.

---

### Порядок выполнения конструкторов и обязательность вызова

При создании экземпляра любого производного класса цепочка инициализации работает строго в одном направлении: **от базового класса к производному** (сверху вниз по иерархии).

Порядок шагов при создании объекта `new DerivedClass()`:
1. Выделяется память под весь объект (включая поля и родительского, и дочернего классов).
2. Вызывается конструктор производного класса.
3. До выполнения собственного тела конструктора производного класса управление передается конструктору базового класса (через явный вызов `base(...)` или неявный `base()`).
4. Выполняется тело конструктора самого верхнего базового класса.
5. Управление возвращается вниз по цепочке, и выполняются тела конструкторов промежуточных классов (если иерархия глубокая).
6. В последнюю очередь выполняется тело конструктора самого производного класса.

> **Важно.** Если базовый класс не имеет конструктора без параметров, а программист в производном классе забыл указать вызов `base(...)` с требуемыми аргументами, программа не скомпилируется. Компилятор выдаст ошибку о том, что базовый класс не содержит конструктора, принимающего 0 аргументов.

### Разобранный пример: от прямоугольника к параллелепипеду

Спроектируем иерархию классов для геометрических фигур. Базовым классом будет `Rectangle` (прямоугольник), который хранит ширину и высоту, а также умеет вычислять площадь. Производным классом будет `Box` (прямоугольный параллелепипед), который добавляет измерение высоты (глубины) и позволяет вычислить объем.

#### Условие задачи
1. Разработать базовый класс `Rectangle` с защищенными полями `width` (ширина) и `height` (высота). Конструктор класса должен принимать два вещественных числа и инициализировать поля. Предусмотреть метод для вычисления площади прямоугольника.
2. Разработать производный класс `Box`, который наследует `Rectangle` и добавляет собственное поле `depth` (глубина/высота параллелепипеда). 
3. В классе `Box` реализовать конструктор, принимающий три параметра (`width`, `height`, `depth`), причем первые два передавать в конструктор базового класса через `base`, а третье — обрабатывать в производном классе.
4. Добавить в класс `Box` метод вычисления объема параллелепипеда, используя унаследованный метод расчета площади основания (`base`).
5. Написать консольную программу на C#, которая создает объект класса `Box` со значениями сторон `5{,}0`, `3{,}0` и `4{,}0`, вычисляет его объем и выводит результат на экран.

#### Рисунок схемы связей (ASCII)
```
+----------------------------------------------------+
|                  class Rectangle                   |
|----------------------------------------------------|
| protected double width                             |
| protected double height                            |
|----------------------------------------------------|
| + Rectangle(double w, double h)                    |
| + double GetArea()                                 |
+----------------------------------------------------+
                          ▲
                          │ наследование (из класса Rectangle)
+----------------------------------------------------+
|                     class Box                      |
|----------------------------------------------------|
| private double depth                               |
|----------------------------------------------------|
| + Box(double w, double h, double d) : base(w, h)   |
| + double GetVolume()                               |
+----------------------------------------------------+
```

#### Ход рассуждений
1. Создаем класс `Rectangle`. Поля `width` и `height` сделаем доступными для наследников, поэтому используем модификатор `protected`. Конструктор класса принимает оба параметра.
2. Метод вычисления площади возвращает произведение ширины на высоту: $\text{Площадь} = \text{width} \times \text{height}$.
3. Создаем класс `Box`, указывая двоеточие `:` после имени класса для настройки наследования.
4. У класса `Rectangle` нет конструктора без параметров (мы напишем только параметризованный конструктор). Следовательно, класс `Box` *обязан* явно вызвать конструктор родителя через `base(w, h)`.
5. Объем параллелепипеда вычисляется по формуле: $\text{Объем} = \text{Площадь основания} \times \text{глубина}$. Площадь основания — это как раз площадь прямоугольника, которую мы уже умеем считать в базовом классе. Поэтому в методе `GetVolume()` мы можем вызвать `base.GetArea() * depth` (или просто использовать унаследованный метод `GetArea() * depth`, так как он доступен по наследству).

#### Полный исходный код программы

```csharp
using System;

namespace InheritanceApp
{
    // Базовый класс: Прямоугольник
    class Rectangle
    {
        protected double width;
        protected double height;

        // Конструктор базового класса
        public Rectangle(double width, double height)
        {
            this.width = width;
            this.height = height;
        }

        // Метод для расчета площади прямоугольника (основания)
        public double GetArea()
        {
            return width * height;
        }
    }

    // Производный класс: Прямоугольный параллелепипед
    class Box : Rectangle
    {
        private double depth; // Дополнительное поле для третьей мерности

        // Конструктор производного класса
        // Передаем width и height в конструктор базового класса через base(width, height)
        public Box(double width, double height, double depth) : base(width, height)
        {
            this.depth = depth;
        }

        // Метод для расчета объема параллелепипеда
        public double GetVolume()
        {
            // Используем унаследованный метод GetArea() для получения площади основания
            double baseArea = GetArea(); // или base.GetArea()
            
            // Вычисляем объем: V = Площадь основания * глубина
            return baseArea * depth;
        }

        // Метод для вывода полной информации об объекте
        public void PrintInfo()
        {
            Console.WriteLine($"Ширина: {width} м");
            Console.WriteLine($"Высота (основы): {height} м");
            Console.WriteLine($"Глубина: {depth} м");
            Console.WriteLine($"Площадь основания: {GetArea()} кв. м");
            Console.WriteLine($"Объем параллелепипеда: {GetVolume()} куб. м");
        }
    }

    class Program
    {
        static void Main(string[] args)
        {
            // Установка кодировки консоли для корректного отображения кириллицы
            Console.OutputEncoding = System.Text.Encoding.UTF8;

            // Создаем объект параллелепипеда через конструктор производного класса
            // Параметры: ширина = 5.0, высота = 3.0, глубина = 4.0
            Box myBox = new Box(5.0, 3.0, 4.0);

            // Выводим информацию и проверяем расчеты
            myBox.PrintInfo();
        }
    }
}
```

#### Пояснение по строкам кода
- `class Box : Rectangle` — объявление наследования класса `Box` от класса `Rectangle`.
- `: base(width, height)` в сигнатуре конструктора `Box` — передача аргументов наверх в конструктор класса `Rectangle`. Сначала отработает код `Rectangle`, инициализирующий `width` и `height`, и только затем выполнится присваивание `this.depth = depth;`.
- `double baseArea = GetArea();` — вызов унаследованного метода родительского класса для получения площади. Так как метод `GetArea` доступен в базовом классе как `public`, его можно вызывать напрямую.

#### Проверка и вычисления
- Ширина ($w$) = $5{,}0$ м.
- Высота ($h$) = $3{,}0$ м.
- Глубина ($d$) = $4{,}0$ м.
- Площадь основания: $\text{Area} = 5{,}0 \times 3{,}0 = 15{,}0$ кв. м.
- Объем: $\text{Volume} = 15{,}0 \times 4{,}0 = 60{,}0$ куб. м.
- Единицы измерения: метры умноженные на метры и еще раз на метры дают кубические метры ($\text{м}^3$), что физически и математически верно для объема.

Ответ: Объем параллелепипеда равен $60{,}0$ куб. м.

## 4. Проектирование иерархии классов и решение прикладных задач

### 1. Алгоритм проектирования иерархии классов

Проектирование иерархии классов — это процесс декомпозиции предметной области, при котором разработчик выявляет общие и специализированные сущности, связывая их отношениями наследования. Правильно спроектированная иерархия позволяет избежать дублирования кода, упрощает модификацию программы и делает архитектуру гибкой и расширяемой.

Алгоритм проектирования иерархии классов состоит из следующих шагов:

1. **Анализ предметной области:** Выделите ключевые сущности (объекты реального мира или абстрактные понятия), с которыми будет работать программа.
2. **Поиск общих свойств и поведения:** Сравните выделенные сущности. Найдите атрибуты и методы, которые повторяются у нескольких сущностей.
3. **Выделение базового класса:** Создайте базовый класс (родительский), куда вынесите все общие поля, свойства и методы.
4. **Определение специализированных классов:** Создайте производные классы для каждой конкретной сущности. Добавьте в них уникальные поля и методы, присущие только им.
5. **Проверка отношения «is-a» (является):** Убедитесь, что каждый производный класс логически является базовым. Если класс `Dog` наследуется от `Animal`, то собака — это животное. Если отношение не выполняется (например, `Car` наследуется от `Engine`), иерархия спроектирована неверно (вместо наследования здесь должна быть композиция).
6. **Выявление различий в поведении:** Определите, должны ли методы базового класса работать одинаково для всех наследников или некоторые методы требуют переопределения (полиморфизма).

> **Правило проектирования.** Наследование должно отражать иерархию типов, а не служить средством механического переиспользования кода. Если класс `Square` (квадрат) наследуется от `Rectangle` (прямоугольник), убедитесь, что все операции с прямоугольником корректны и для квадрата (принцип подстановки Лисков).

---

### 2. Выделение общего функционала и виртуальные методы

Когда объекты производных классов имеют одинаковые по названию методы, но выполняющие разные действия, в C# используют механизм виртуальных методов. 

По умолчанию, если вызвать метод через ссылку базового типа, будет вызван метод базового класса, даже если на самом деле ссылка указывает на объект производного класса. Чтобы изменить это поведение, в базовом классе метод помечается ключевым словом `virtual`, а в производном классе переопределяется с помощью ключевого слова `override`.

Рассмотрим синтаксис:

```csharp
class BaseClass
{
    // Виртуальный метод, который может быть переопределен в потомках
    p​ublic virtual void DisplayInfo()
    {
        Console.WriteLine("Базовый класс");
    }
}

class DerivedClass : BaseClass
{
    // Переопределение метода
    public override void DisplayInfo()
    {
        Console.WriteLine("Производный класс");
    }
}
```

Когда мы вызываем `DisplayInfo()` у объекта производного класса, сохраненного в переменную базового типа, платформа .NET во время выполнения (runtime) определяет фактический тип объекта и вызывает соответствующую версию метода. Это свойство называется **динамическим связыванием** (или полиморфизмом).

---

### 3. Полиморфные коллекции и работа с типами (`is` и `as`)

Главное достоинство иерархий классов заключается в возможности создания **полиморфных коллекций** — массивов или списков, объявленных с типом базового класса, но содержащих объекты различных производных классов.

Например, массив типа `Publication[]` может хранить одновременно и объекты класса `Book`, и объекты класса `Magazine`. Это позволяет обрабатывать разнородные объекты в едином цикле, не заботясь об их конкретном типе на этапе написания кода.

Однако иногда в процессе работы с полиморфной коллекцией возникает необходимость выполнить специфическое действие, доступное только для конкретного класса-наследника (например, получить количество страниц книги, которого нет у журнала). Для проверки типа объекта и безопасного приведения ссылок в C# используются операторы `is` и `as`.

- Оператор `is` проверяет, является ли объект экземпляром заданного типа, и возвращает `true` или `false`:
  ```csharp
  if (item is Book)
  {
      // Объект является книгой
  }
  ```
- Оператор `as` выполняет попытку приведения типа. Если приведение невозможно, он возвращает `null` вместо генерации исключения:
  ```csharp
  Book myBook = item as Book;
  if (myBook != null)
  {
      // Приведение прошло успешно, работаем с myBook
  }
  ```
- Начиная с версии C# 7, часто используется сопоставление с образцом (pattern matching):
  ```csharp
  if (item is Book book)
  {
      // Переменная book уже объявлена и приведена к типу Book
      Console.WriteLine(book.Pages);
  }
  ```

### 4. Полный разбор задачи: иерархия печатных изданий

#### Условие задачи
Разработать иерархию классов для учета печатных изданий. 
1. Создать базовый класс `Publication`, содержащий общие поля: название (`Title`, строка) и цена (`Price`, число с плавающей точкой). Класс должен содержать конструктор для инициализации полей и виртуальный метод `DisplayInfo()`, выводящий информацию об издании.
2. Создать производный класс `Book` (книга), добавляющий поля: автор (`Author`, строка) и количество страниц (`Pages`, целое число). Переопределить метод `DisplayInfo()`.
3. Создать производный класс `Magazine` (журнал), добавляющий поля: номер выпуска (`IssueNumber`, целое число) и месяц издания (`Month`, строка). Переопределить метод `DisplayInfo()`.
4. Написать программу, которая создает массив (или список) из 4 изданий разных типов, выводит информацию о каждом издании с помощью полиморфного вызова метода, а также находит общую стоимость всех изданий в коллекции и выводит количество страниц только для всех книг, найденных в массиве.

#### Рисунок схемы классов (ASCII)

```text
       +-----------------------+
       |      Publication      |
       |-----------------------|
       | # string Title        |
       | # double Price        |
       |-----------------------|
       | + Publication(...)    |
       | + virtual DisplayInfo()|
       +-----------^-----------+
                   |
         +---------+---------+
         |                   |
+--------+--------+ +--------+--------+
|      Book       | |    Magazine     |
|-----------------| |-----------------|
| - string Author | | - int IssueNumber|
| - int Pages     | | - string Month  |
|-----------------| |-----------------|
| + Book(...)     | | + Magazine(...) |
| + override      | | + override      |
|   DisplayInfo() | |   DisplayInfo() |
+-----------------+ +-----------------+
```

#### Ход рассуждений
1. **Проектирование базового класса `Publication`:** Поля `Title` и `Price` общи для всех печатных изданий. Сделаем их доступными для наследников с помощью модификатора `protected` или создадим публичные свойства. Конструктор базового класса будет принимать название и цену. Метод `DisplayInfo()` объявим как `virtual`, чтобы в наследниках его можно было дополнить специфическими данными.
2. **Проектирование класса `Book`:** Класс наследует `Publication`. Он добавляет специфичные поля `Author` и `Pages`. В конструкторе класса `Book` мы вызовем конструктор базового класса через ключевое слово `base(title, price)`, чтобы не дублировать код инициализации общих полей. Метод `DisplayInfo()` переопределим (`override`), внутри него вызовем `base.DisplayInfo()` для вывода названия и цены, а затем допишем вывод автора и страниц.
3. **Проектирование класса `Magazine`:** Аналогично книгам, класс `Magazine` наследует `Publication`, добавляет поля `IssueNumber` и `Month`, использует `base(title, price)` в конструкторе и переопределяет `DisplayInfo()`.
4. **Главная программа (`Main`):** Создадим массив типа `Publication[]` и заполним его двумя объектами `Book` и двумя объектами `Magazine`. Запустим цикл для вывода информации (сработает полиморфизм). Просуммируем цены всех элементов массива в переменную `totalCost`. Пройдем по массиву еще раз, проверяя с помощью `is` (pattern matching), является ли элемент книгой, и сложим количество страниц всех книг.

#### Решение на C#

```csharp
using System;

// Базовый класс
class Publication
{
    protected string title;
    protected double price;

    public Publication(string title, double price)
    {
        this.title = title;
        this.price = price;
    }

    public double Price
    {
        get { return price; }
    }

    // Виртуальный метод для вывода информации
    public virtual void DisplayInfo()
    {
        Console.Write($"Название: \"{title}\", Цена: {price:F2} руб.");
    }
}

// Производный класс Книга
class Book : Publication
{
    private string author;
    private int pages;

    public Book(string title, double price, string author, int pages) 
        : base(title, price) // Вызов конструктора базового класса
    {
        this.author = author;
        this.pages = pages;
    }

    public int Pages
    {
        get { return pages; }
    }

    // Переопределение виртуального метода
    public override void DisplayInfo()
    {
        Console.Write("[Книга] ");
        base.DisplayInfo(); // Вывод общих данных из базового класса
        Console.WriteLine($", Автор: {author}, Страниц: {pages}");
    }
}

// Производный класс Журнал
class Magazine : Publication
{
    private int issueNumber;
    private string month;

    public Magazine(string title, double price, int issueNumber, string month) 
        : base(title, price) // Вызов конструктора базового класса
    {
        this.issueNumber = issueNumber;
        this.month = month;
    }

    // Переопределение виртуального метода
    public override void DisplayInfo()
    {
        Console.Write("[Журнал] ");
        base.DisplayInfo(); // Вывод общих данных из базового класса
        Console.WriteLine($", Выпуск №{issueNumber}, Месяц: {month}");
    }
}

class Program
{
    static void Main()
    {
        // Создание полиморфного массива изданий
        Publication[] catalog = new Publication[]
        {
            new Book("Программирование на C#", 1250.00, "А. Сергеев", 450),
            new Magazine("Мир ПК", 300.50, 12, "Декабрь"),
            new Book("Алгоритмы и структуры данных", 1800.00, "В. Петров", 600),
            new Magazine("Наука и жизнь", 250.00, 5, "Май")
        };

        Console.WriteLine("--- Каталог изданий ---");
        
        double totalCost = 0.0;
        int totalBookPages = 0;

        // Обработка массива в цикле
        foreach (Publication pub in catalog)
        {
            // Полиморфный вызов метода (вызовется версия Book или Magazine)
            pub.DisplayInfo();
            
            // Накопление общей стоимости
            totalCost += pub.Price;

            // Проверка типа с помощью pattern matching для подсчета страниц книг
            if (pub is Book book)
            {
                totalBookPages += book.Pages;
            }
        }

        Console.WriteLine(new string('-', 40));
        Console.WriteLine($"Общая стоимость всех изданий: {totalCost:F2} руб.");
        Console.WriteLine($"Суммарное количество страниц во всех книгах: {totalBookPages}");
    }
}
```

#### Пример ввода и вывода

В данной программе консольный ввод не используется, данные заданы в коде. 

**Вывод программы:**
```text

[Книга] Название: "Программирование на C#", Цена: 1250,00 руб., Автор: А. Сергеев, Страниц: 450
[Журнал] Название: "Мир ПК", Цена: 300,50 руб., Выпуск №12, Месяц: Декабрь
[Книга] Название: "Алгоритмы и структуры данных", Цена: 1800,00 руб., Автор: В. Петров, Страниц: 600
[Журнал] Название: "Наука и жизнь", Цена: 250,00 руб., Выпуск №5, Месяц: Май
----------------------------------------

Суммарное количество страниц во всех книгах: 1050
```

#### Проверка и анализ
1. **Единицы измерения и форматирование:** Цены выводятся с двумя знаками после запятой благодаря строке форматирования `{price:F2}`, что соответствует денежным суммам. Общая сумма рассчитана верно: $1250{,}00 + 300{,}50 + 1800{,}00 + 250{,}00 = 3600{,}50$.
2. **Правдоподобие:** Суммарное количество страниц учитывает только книги ($450 + 600 = 1050$), журналы в этот подсчет не попали, так как проверка `is Book` для них возвращает `false`. Логика программы полностью соответствует условию.
3. **Оценка сложности:** 
   - Время выполнения: $O(N)$, где $N$ — количество элементов в массиве `catalog`, так как мы проходим по массиву два действия за один проход (`foreach` выполняет вывод, суммирование цены и проверку типов за линейное время).
   - Память: $O(N)$ для хранения ссылок в массиве.

### 5. Анализ сложности и архитектурных преимуществ использования иерархий

Использование наследования и полиморфизма оказывает существенное влияние как на качество программного кода, так и на сложность его поддержки:

1. **Устранение дублирования кода (DRY — Don't Repeat Yourself):** Общие поля (`Title`, `Price`) и логика их инициализации описаны ровно один раз в базовом классе `Publication`. При добавлении новых изданий (например, газеты или комикса) не придется заново писать свойства названия и цены.
2. **Открытость/закрытость (Principle OCP):** Архитектура открыта для расширения, но закрыта для модификации. Если потребуется добавить новый тип издания `ComicBook`, нам не нужно переписывать существующий код класса `Book` или цикл обработки в `Main` — достаточно создать новый класс-наследник, переопределить виртуальный метод и добавить его в массив `Publication[]`.
3. **Снижение связанности:** Код, обрабатывающий коллекцию (`foreach (Publication pub in catalog)`), ничего не знает о конкретных типах `Book` или `Magazine`. Он взаимодействует исключительно с контрактом базового класса `Publication`. Это делает код устойчивым к изменениям.
4. **Сложность поддержки:** С точки зрения архитектуры, глубокие иерархии (более 3–4 уровней наследования) могут усложнить понимание кода из-за размывания логики по родительским классам. В проектировании рекомендуется отдавать предпочтение неглубоким иерархиям (1–2 уровня) или композиции.

## Типичные ошибки

1. **Попытка множественного наследования классов.**
   * *В чём ошибка:* Написание кода вида `class Manager : Employee, Person` в C#.
   * *Почему возникает:* Перенос привычки из C++ или неверное понимание архитектуры. В C# классы поддерживают только одиночное наследование.
   * *Как избежать:* Использовать одиночное наследование для реализации иерархии типов, а для передачи дополнительных поведений применять интерфейсы (`: Employee, ICloneable`).

2. **Забытый вызов конструктора базового класса при отсутствии конструктора по умолчанию.**
   * *В чём ошибка:* Создание параметризованного конструктора в базовом классе без конструктора без параметров и попытка создать производный класс без явного вызова `base(...)`.
   * *Почему возникает:* Компилятор по умолчанию ищет конструктор без параметров `base()`, которого нет.
   * *Как избежать:* Всегда явно указывать `: base(...)` в сигнатуре конструктора производного класса, если базовый класс не имеет конструктора без параметров.

3. **Использование модификатора `private` вместо `protected` для доступа из потомков.**
   * *В чём ошибка:* Объявление полей базового класса как `private`, а затем попытка напрямую обратиться к ним из методов производного класса.
   * *Почему возникает:* Путаница между инкапсуляцией и видимостью в иерархии.
   * *Как избежать:* Если поле или метод должны быть скрыты от внешнего мира, но доступны дочерним классам, используйте `protected`.

4. **Отсутствие ключевого слова `override` при попытке переопределить виртуальный метод.**
   * *В чём ошибка:* Объявление метода в производном классе с тем же именем, что и `virtual` метод в базе, но без `override` (или с `new`).
   * *Почему возникает:* Непонимание динамического связывания. Без `override` метод не переопределяется, а скрывается (`shadowing`), из-за чего полиморфизм не срабатывает при вызове через базовую ссылку.
   * *Как избежать:* Всегда использовать `override` для изменения поведения виртуального метода и `virtual` в базовом классе.

5. **Ошибки при восходящем и нисходящем приведении типов (`Upcasting` / `Downcasting`).**
   * *В чём ошибка:* Попытка выполнить неявное приведение базового класса к производному (`Manager m = (Manager)new Employee(...)`) или игнорирование проверки типов.
   * *Почему возникает:* Базовый класс не содержит всех полей потомка, поэтому такое приведение на этапе выполнения вызывает исключение `InvalidCastException`.
   * *Как избежать:* Использовать безопасное приведение через оператор `as` с последующей проверкой на `null` либо проверку через шаблон сопоставления (`if (obj is Manager m)`).

6. **Создание «глубоких» и запутанных иерархий наследования.**
   * *В чём ошибка:* Построение цепочек наследования длиной в 5–7 и более уровней (`A -> B -> C -> D -> E`).
   * *Почему возникает:* Желание «переиспользовать абсолютно всё», превращая код в спагетти-структуру.
   * *Как избежать:* Ограничивать иерархии 1–2 уровнями и предпочитать композицию («has-a») наследованию («is-a»), если связи между объектами не образуют строгий тип родства.

7. **Некорректное использование ключевого слова `base` в статических контекстах.**
   * *В чём ошибка:* Попытка написать `base` внутри статического метода (`static`) производного класса.
   * *Почему возникает:* Ключевое слово `base` привязано к конкретному экземпляру объекта (к его родительской части), в то время как статические методы принадлежат классу в целом.
   * *Как избежать:* Помнить, что `base` и `this` недоступны в статических методах и свойствах.

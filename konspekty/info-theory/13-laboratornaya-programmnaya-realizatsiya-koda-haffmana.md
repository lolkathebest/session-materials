### Архитектура программного комплекса и общая схема работы архиватора

Процесс сжатия и восстановления данных методом Хаффмана состоит из последовательности логических этапов, каждый из которых решает строго определенную задачу. Архитектура разрабатываемого приложения строится по модульному принципу, где функции ввода-вывода, алгоритмическая логика построения дерева и побитовые манипуляции инкапсулированы в виде классов и функций с четко определенными интерфейсами.

Рассмотрим общую схему работы архиватора при сжатии файла:

1. **Анализ файла (Frequency Analysis):** На первом этапе исходный файл открывается в бинарном режиме для чтения. Программа последовательно считывает байт за байтом и строит частотную таблицу, сопоставляющую каждому байту (символу алфавита $c \in [0, 255]$) количество его вхождений в исходный файл ($count$).
2. **Создание дерева Хаффмана (Tree Construction):** На основе построенной частотной таблицы формируется лес корневых узлов, которые затем объединяются с помощью очереди с приоритетом в единое бинарное дерево Хаффмана.
3. **Генерация таблиц кодов (Code Generation):** Полученное бинарное дерево обходится рекурсивно. При переходе к левому потомку к текущей битовой строке добавляется символ `'0'`, а при переходе к правому — `'1'`. В результате для каждого символа формируется уникальный битовый префиксный код переменной длины.
4. **Упаковка в байты (Bitwise Packing):** Поскольку минимальной адресуемой единицей хранения на диске является байт (8 бит), битовые строки кодов невозможно записать напрямую. Специальный модуль буферизации накапливает биты в промежуточном байте-аккумуляторе и записывает его в выходной файл по мере заполнения.
5. **Сохранение служебной информации (Header Serialization):** Чтобы файл можно было успешно распаковать, в начале сжатого файла (или в специальном заголовке) сохраняется информация о структуре дерева Хаффмана или исходных частотах символов, а также служебная информация о количестве значащих бит в последнем байте потока.

Схема процесса распаковки (декомпрессии) является зеркальным отражением описанного алгоритма: программа читает заголовок, восстанавливает дерево Хаффмана, после чего побитово читает сжатый поток из файла, спускаясь по дереву от корня к листьям до тех пор, пока не встретит символ, после чего записывает его в распакованный файл и возвращается в корень дерева.

### Формат хранения служебной информации в сжатом файле

Одной из сложнейших задач при проектировании файловых архиваторов является организация заголовка. Если сохранить только сжатые биты, алгоритм декомпрессии не сможет узнать, какое именно дерево Хаффмана использовалось при сжатии, и восстановление данных станет невозможным. 

В разрабатываемой программе используется подход сохранения **частотной таблицы** в начале выходного файла. Такой метод является простым в реализации и надежным, хотя и добавляет небольшие накладные расходы на размер архива.

Структура результирующего бинарного файла (`.huff`) выглядит следующим образом:

```
+------------------------+------------------------+-----------------------+--------------------+
| Количество уникальных  | Массив пар:            | Общее число байт      | Сжатые данные      |
| символов K (1 байт     | (Символ C, Частота N)  | исходного файла       | (побитовый поток   |
| или 2 байта)           | K раз по (1 + 4 байта) | (8 байт / uint64_t)   | переменной длины)  |
+------------------------+------------------------+-----------------------+--------------------+
```

Подробное описание полей заголовка:
1. **Количество уникальных символов ($K$):** Так как в байте может быть от $1$ до $256$ различных значений, для хранения числа $K$ выделяется $2$ байта (тип `uint16_t`). Значение `0` соответствует пустому файлу, значение `256` означает, что в файле присутствуют все возможные байты от `0x00` до `0xFF`.
2. **Таблица частот:** Для каждого из $K$ уникальных символов записывается сам символ (1 байт, `unsigned char`) и частота его встречаемости в исходном файле (4 байта, `uint32_t`). Суммарный размер этой секции составляет $K \times 5$ байт.
3. **Общий размер исходных данных:** 8 байт (`uint64_t`), содержащие точное количество байт в исходном файле. Это необходимо алгоритму декомпрессии для того, чтобы вовремя остановить чтение и не записать лишние нули дополнения (padding), которые неизменно возникают при выравнивании битового потока по границе байта.
4. **Побитовый поток данных:** Все оставшиеся байты файла представляют собой упакованные битовые последовательности кодов Хаффмана.

### Требования к языку реализации и стандартам кодирования

Лабораторная работа выполняется на языке **C++** с использованием стандарта **C++17**. Выбор этого стандарта обусловлен наличием удобных и эффективных стандартных контейнеров и алгоритмов, входящих в Библиотеку шаблонов (STL).

Для успешной реализации необходимо соблюдать следующие требования:
- **Управление памятью:** Динамические структуры данных (узлы дерева Хаффмана) размещаются в куче с помощью оператора `new` и освобождаются деструктором или с использованием умных указателей (`std::unique_ptr`). Утечки памяти категорически не допускаются.
- **Обработка ошибок:** Все операции ввода-вывода (`std::ifstream`, `std::ofstream`) должны сопровождаться проверкой успешности открытия файлов. При возникновении ошибок программа должна выводить понятное сообщение в поток `std::cerr` и завершаться с ненулевым кодом возврата.
- **Чистота кода:** Именование переменных и функций должно осуществляться в едином стиле (например, `camelCase` для методов и переменных, `PascalCase` для классов и структур). Запрещено использование глобальных переменных для хранения состояния алгоритма сжатия.

Для реализации требуются следующие стандартные библиотеки C++:
- `#include <iostream>` — для организации ввода-вывода в консоль при запуске программы и передачи аргументов командной строки.
- `#include <vector>` — для хранения массивов узлов, байтовых буферов и динамических списков.
- `#include <map>` или `#include <unordered_map>` — для отображения символов в их строковые битовые коды (`std::map<char, std::string>`).
- `#include <queue>` — для реализации очереди с приоритетом (`std::priority_queue`), необходимой для построения дерева Хаффмана.
- `#include <fstream>` — для работы с бинарными файловыми потоками (`std::ifstream`, `std::ofstream`).
- `#include <cstdint>` — для использования фиксированных целочисленных типов (`uint8_t`, `uint32_t`, `uint64_t`), критически важных для кроссплатформенной бинарной сериализации.

### Разобранный пример: Проектирование блок-схемы модулей программы

Рассмотрим проектирование структуры взаимодействия модулей для текстового файла среднего размера (около 1 КБ). Задача заключается в том, чтобы разбить монолитный код на логические компоненты, каждый из которых отвечает за свой этап преобразования.

#### Условие задачи
Требуется спроектировать архитектуру консольного архиватора `huffman_archiver`, принимающего аргументы командной строки вида `./huffman_archiver <-c|-d> <input_file> <output_file>`, где флаг `-c` означает сжатие (compress), а `-d` — декомпрессию (decompress).

#### Схема взаимодействия модулей (в виде блок-схемы словами)

```
[ Main Module (main.cpp) ]
       │
       ├── Анализ аргументов командной строки (argc, argv)
       │
       ├── ЕСЛИ режим == "-c" (Сжатие):
       │     │
       │     ├── 1. [ FrequencyAnalyzer ] 
       │     │     Считывает input_file побайтово, заполняет std::map<char, uint32_t>.
       │     │
       │     ├── 2. [ HuffmanTreeBuilder ] 
       │     │     Строит дерево Хаффмана на основе частот с использованием std::priority_queue.
       │     │     Генерирует кодовую таблицу std::map<char, std::string>.
       │     │
       │     ├── 3. [ ArchiveSerializer ] 
       │     │     Записывает в output_file заголовок (размер K, таблицу частот, размер исходного файла).
       │     │
       │     └── 4. [ BitWriter ] 
       │         Повторно читает input_file, заменяет каждый байт на его битовый код Хаффмана
       │         и упаковывает биты в байтовый поток с записью в output_file.
       │
       └── ЕСЛИ режим == "-d" (Распаковка):
             │
             ├── 1. [ ArchiveDeserializer ] 
             │     Читает из input_file заголовок, восстанавливает частотную таблицу и размер данных.
             │
             ├── 2. [ HuffmanTreeBuilder ] 
             │     Воссоздает то же самое дерево Хаффмана по восстановленной частотной таблице.
             │
             └── 3. [ BitReader & Decoder ] 
                 Побитово читает сжатый поток из input_file, перемещается по дереву Хаффмана
                 до листа и записывает расшифрованные байты в output_file до достижения 
                 исходного размера данных.
```

#### Ход рассуждений при проектировании
1. **Почему разделены чтение файла и подсчет частот?** Чтение файла целиком в оператичную память может привести к проблемам, если размер файла превышает доступный объем RAM. Однако для построения дерева Хаффмана нам обязательно нужна полная частотная таблица. Следовательно, файл на этапе сжатия читается ровно два раза: первый раз — исключительно для подсчета частот (линейный проход $O(M)$, где $M$ — размер файла), второй раз — для кодирования и записи в выходной поток.
2. **Зачем нужен отдельный модуль `BitWriter`?** Стандартные потоки C++ (`std::ofstream`) записывают данные минимальными блоками по 1 байту (8 бит). Коды Хаффмана имеют произвольную длину (например, 3 бита, 5 бит, 12 бит). Прямая запись невозможна без промежуточного буфера-аккумулятора, который накапливает биты слева направо и сбрасывает их в файл, когда накапливается ровно 8 бит. Модуль `BitWriter` инкапсулирует эту сложную логику битовой арифметики, предоставляя остальной программе простой метод `writeBit(bool bit)` или `writeString(const std::string& bits)`.

#### Проверка и правдоподобность
Предложенная архитектура полностью удовлетворяет требованиям модульности и разделения ответственности. Использование независимых классов или структур для узлов дерева, побитового ввода-вывода и сериализации заголовка позволяет легко покрывать каждый модуль автономными юнит-тестами, что существенно снижает количество ошибок при отладке всей программы на последующих этапах лабораторной работы.

## Структуры данных и моделирование узлов дерева

### Структуры данных и моделирование узлов дерева Хаффмана

Для того чтобы программно построить код Хаффмана, требуется представить информацию в виде двоичного дерева, где каждый листовой узел соответствует отдельному символу алфавита, а внутренние узлы служат для объединения поддеревьев. В этом разделе мы спроектируем необходимые структуры данных на языке C++, рассмотрим организацию памяти и разберем алгоритм генерации префиксных кодов.

---

### Архитектура узла дерева (`HuffmanNode`)

Дерево Хаффмана состоит из динамически создаваемых узлов. Каждый узел должен содержать следующие поля:
1. Символ (`char` или `unsigned char`), который он представляет (актуально только для листьев).
2. Частоту встречаемости символа или сумму частот дочерних узлов (`int` или `size_t`).
3. Указатели на левого и правого потомков.

> **Определение.** Узел дерева Хаффмана (`HuffmanNode`) — это структура данных, объединяющая данные о символе, его весе (частоте) и ссылки на дочерние элементы, используемая для построения оптимального префиксного кода снизу вверх.

В процессе построения дерева нам потребуется извлекать два узла с наименьшей частотой. Для автоматизации этого процесса в C++ идеально подходит стандартный контейнер `std::priority_queue` из библиотеки `<queue>`. По умолчанию `std::priority_queue` является *максимальной кучей* (max-heap), то есть на вершине всегда оказывается элемент с наибольшим значением. Нам же требуется *минимальная куча* (min-heap), чтобы извлекать узлы с минимальной частотой.

Для изменения поведения очереди с приоритетом необходимо перегрузить оператор «больше» (`operator>`) так, чтобы узел с *меньшей* частотой имел высший приоритет.

Ниже приведено полное определение структуры `HuffmanNode` на языке C++ с конструкторами и перегруженным оператором сравнения:

```cpp
#include <iostream>
#include <string>
#include <vector>
#include <map>
#include <queue>
#include <memory>

// Структура узла дерева Хаффмана
struct HuffmanNode {
    char character;          // Символ (используется в листовых узлах)
    size_t frequency;        // Частота (вес) узла
    HuffmanNode* left;       // Указатель на левого потомка
    HuffmanNode* right;      // Указатель на правого потомка

    // Конструктор для листовых узлов (содержащих символ и частоту)
    HuffmanNode(char ch, size_t freq) 
        : character(ch), frequency(freq), left(nullptr), right(nullptr) {}

    // Конструктор для внутренних узлов (объединяющих поддеревья)
    HuffmanNode(size_t freq, HuffmanNode* l, HuffmanNode* r) 
        : character('\0'), frequency(freq), left(l), right(r) {}

    // Деструктор для рекурсивного освобождения памяти
    ~HuffmanNode() {
        delete left;
        delete right;
    }

    // Перегрузка оператора сравнения для std::priority_queue.
> **Важно:** std::priority_queue по умолчанию использует std::less (максимальная куча). 
    // Чтобы получить минимальную кучу (min-heap), мы перегружаем operator> так, 
    // чтобы "большим" считался узел с большей частотой. Тогда std::priority_queue 
    // с компаратором по умолчанию (который опирается на operator<, либо мы можем 
    // передать кастомный компаратор) будет корректно выдавать минимум.
    // На практике в C++ для std::priority_queue<T, Container, Compare> 
    // по умолчанию используется std::less<T>, использующий T::operator< 
    // или глобальный operator<. 
    // Перегрузим operator< так, чтобы узел с МЕНЬШЕЙ частотой был "больше" для max-heap, 
    // ЛИБО создадим явную структуру-компаратор. 
    // Самый надежный подход в C++ — использовать отдельный компаратор для очереди.
};

// Компаратор для std::priority_queue, чтобы получить min-heap (на вершине элемент с наименьшей частотой)
struct CompareNodes {
    bool operator()(const HuffmanNode* a, const HuffmanNode* b) const {
        // Если частоты равны, сравниваем по символу для детерминированности
        if (a->frequency == b->frequency) {
            return a->character > b->character;
        }
        return a->frequency > b->frequency; // Инверсия знака для min-heap
    }
};
```

### Управление памятью: сырые указатели против умных

При работе с древовидными структурами в C++ критически важно правильно управлять динамической памятью, чтобы избежать утечек (memory leaks). В нашей программе узлы дерева создаются динамически через оператор `new` в процессе сборки дерева снизу вверх.

У нас есть два основных пути:
1. **Сырые указатели с ручным освобождением:** Мы создаем корневой узел, а в деструкторе структуры `HuffmanNode` рекурсивно удаляем `left` и `right`. После завершения кодирования или декодирования мы вызываем `delete root;`, и вся память под деревом очищается автоматически благодаря деструктору.
2. **Умные указатели (`std::unique_ptr`):** Обеспечивают автоматическое управление памятью по принципу RAII (Resource Acquisition Is Initialization). Однако интеграция `std::unique_ptr` в `std::priority_queue` и операции объединения узлов требуют написания дополнительных перемещающих конструкторов и аккуратного обращения с владением, что усложняет код для учебной лабораторной работы.

Поэтому в данной лабораторной работе мы используем классические сырые указатели с обязательным написанием рекурсивного деструктора, который гарантирует освобождение памяти всех дочерних узлов.

### Рекурсивный обход дерева и генерация кодов

После того как дерево Хаффмана построшено и у нас есть указатель на его корень, необходимо сопоставить каждому исходному символу уникальную двоичную последовательность (префиксный код). Для этого выполняется рекурсивный обход дерева от корня до листьев.

Правило формирования кода при обходе:
- При переходе по левой ветви к битовой строке кода добавляется символ `'0'`.
- При переходе по правой ветви добавляется символ `'1'`.
- Когда мы достигаем листового узла (у которого отсутствуют указатели `left` и `right`), накопленная битовая строка записывается в результирующую таблицу соответствий (`std::map<char, std::string>`).

Рассмотрим реализацию этой функции на C++:

```cpp
#include <map>
#include <string>

/**
 * Рекурсивная функция обхода дерева Хаффмана для генерации таблиц кодов.
 * 
 * @param node Текущий узел дерева.
 * @param current_code Текущая битовая строка, накопленная от корня до данного узла.
 * @param huffman_codes Ссылка на словарь, куда сохраняются пары "символ -> код".
 */
void generateCodes(const HuffmanNode* node, std::string current_code, std::map<char, std::string>& huffman_codes) {
    // Базовый случай: если узел нулевой, прекращаем обход
    if (node == nullptr) {
        return;
    }

    // Проверяем, является ли узел листовым (нет ни левого, ни правого потомка)
    if (node->left == nullptr && node->right == nullptr) {
        // Если файл состоял из одного уникального символа, дерево может иметь высоту 0.
        // По стандарту в таком случае символу присваивается код "0".
        if (current_code.empty()) {
            huffman_codes[node->character] = "0";
        } else {
            huffman_codes[node->character] = current_code;
        }
        return;
    }

    // Рекурсивный спуск в левое поддерие (добавляем '0')
    generateCodes(node->left, current_code + "0", huffman_codes);

    // Рекурсивный спуск в правое поддерие (добавляем '1')
    generateCodes(node->right, current_code + "1", huffman_codes);
}
```

#### Пошаговый разбор работы функции генерации кодов

Предположим, у нас построилось следующее дерево для алфавита из трех символов `{'A', 'B', 'C'}` с корнем `Root`:
- Корень `Root` (частота 10)
  - Левый потомок: Лист `A` (частота 4, код пути от корня: `0`)
  - Правый потомок: Внутренний узел (частота 6)
    - Левый потомок правого узла: Лист `B` (частота 2, путь: от корня вправо `1`, затем влево `0` -> `10`)
    - Правый потомок правого узла: Лист `C` (частота 4, путь: от корня вправо `1`, затем вправо `1` -> `11`)

Ход выполнения функции `generateCodes(Root, "", huffman_codes)`:
1. Вызов для `Root`: `node` не ` nullptr`, не лист. Вызываем левого потомку с кодом `"" + "0" = "0"`.
2. Вызов для листа `A`: `node` — лист (`left == nullptr && right == nullptr`). Записываем в таблицу: `huffman_codes['A'] = "0"`. Возврат.
3. Возврат к `Root`. Вызываем правого потомка с кодом `"" + "1" = "1"`.
4. Вызов для внутреннего узла (частота 6): не лист. Вызываем его левого потомка (`B`) с кодом `"1" + "0" = "10"`.
5. Вызов для листа `B`: `node` — лист. Записываем: `huffman_codes['B'] = "10"`. Возврат.
6. Вызов правого потомка внутреннего узла (`C`) с кодом `"1" + "1" = "11"`.
7. Вызов для листа `C`: `node` — лист. Записываем: `huffman_codes['C'] = "11"`. Возврат.

Итоговый словарь кодов: `{'A': "0", 'B': "10", 'C': "11"}`. Обратите внимание, что ни один код не является префиксом другого (свойство префиксности выполнено строго).

### Обработка граничных случаев

При проектировании структур данных и алгоритмов важно заранее предусмотреть поведение программы в нетипичных или экстремальных ситуациях:

1. **Пустой файл (размер 0 байт):**
   - *Проблема:* Частотная таблица пуста, очередь с приоритетом не содержит элементов, построение дерева невозможно.
   - *Решение:* На этапе анализа файла перед построением дерева необходимо делать проверку: `if (file_size == 0)`. Программа должна корректно завершить работу или записать специальный пустой маркер без попытки построения дерева Хаффмана.

2. **Файл, состоящий из повторяющихся экземпляров ровно одного символа** (например, `1000` символов `'A'`):
   - *Проблема:* В очереди с приоритетом будет всего один уникальный узел. Алгоритм объединения двух наименее вероятных узлов требует как минимум двух элементов в очереди. Если попытаться извлечь два узла из очереди с одним элементом, произойдет аварийное завершение программы (Undefined Behavior / Segmentation Fault).
   - *Решение:* Если количество уникальных символов $K = 1$, алгоритм построения дерева прерывается досрочно. Единственный символ оборачивается в корень, а функция генерации кодов присваивает ему фиксированный однобитовый код `"0"` (или в нашей функции это обрабатывается проверкой `current_code.empty()`, которая присваивает `"0"`). При распаковке декодер также должен учитывать этот случай, чтобы корректно восстановить исходную последовательность.

## Построение дерева Хаффмана и генерация кодов

### Алгоритм подсчета частот символов во входном буфере данных

Прежде чем приступать к построению оптимального префиксного кода Хаффмана, необходимо проанализировать статистические свойства входных данных. В основе метода лежит идея о том, что частовстречающиеся символы должны кодироваться более короткими битовыми последовательностями, а редкие — более длинными. Следовательно, первым этапом работы программы является подсчет абсолютных частот (количества вхождений) каждого уникального символа в обрабатываемом буфере данных.

Для эффективного подсчета частот в языке C++ используется стандартный ассоциативный контейнер `std::map<char, int>` или специализированный массив счетчиков фиксированного размера (например, `int freq[256]` для алфавита ASCII). Использование массива предпочтительнее для обычных текстовых или бинарных файлов, так как диапазон возможных значений байта ограничен 256 значениями, что обеспечивает константное время доступа $O(1)$ при инкременте счетчика. Однако для универсальности и работы с расширенными алфавитами часто применяют `std::map`.

Рассмотрим алгоритм подсчета частот на уровне исходного кода. Предположим, что входные данные передаются в виде строки `std::string text`.

```cpp
#include <iostream>
#include <map>
#include <string>

// Функция для подсчета частот символов в строке
std::map<char, int> calculateFrequencies(const std::string& text) {
    std::map<char, int> frequencies;
    for (char symbol : text) {
        frequencies[symbol]++;
    }
    return frequencies;
}
```

Каждый элемент контейнера `frequencies` после завершения работы цикла содержит пару «символ — количество его повторений во всем тексте». Эти числовые значения в дальнейшем будут выступать в роли весов при построении бинарного дерева.

### Инициализация очереди с приоритетом начальными листовыми узлами

После того как частоты всех символов подсчитаны, необходимо инициализировать структуру данных для построения дерева Хаффмана. Напомним из предыдущего раздела, что узел дерева описывается структурой `HuffmanNode`, которая содержит поле символа `char data`, поле частоты `int freq`, а также указатели на левого и правого потомков (`HuffmanNode* left`, `HuffmanNode* right`).

На первом шаге алгоритма для каждого уникального символа создается отдельный листовой узел (листовой — потому что у него нет потомков, указатели `left` и `right` равны `nullptr`). Все созданные листовые узлы помещаются в очередь с приоритетом (`std::priority_queue`). 

Очередь с приоритетом — это структура данных, которая всегда выдает наружу элемент с наивысшим приоритетом. В стандартной библиотеке C++ `std::priority_queue` по умолчанию является *максимальной кучей* (max-heap, то есть наверху оказывается наибольший элемент). Однако для алгоритма Хаффмана нам требуется извлекать два узла с *минимальными* частотами. Поэтому при объявлении очереди необходимо передать специальный компаратор, который развернет порядок сортировки (min-heap).

Рассмотрим корректное определение очереди с приоритетом для указателей на узлы Хаффмана:

```cpp
#include <queue>
#include <vector>

// Структура для сравнения указателей на узлы (min-heap: меньшая частота имеет высший приоритет)
struct CompareNodes {
    bool operator()(HuffmanNode* const& p1, HuffmanNode* const& p2) {
        return p1->freq > p2->freq;
    }
};

// Определение очереди с приоритетом
using HuffmanQueue = std::priority_queue<HuffmanNode*, std::vector<HuffmanNode*>, CompareNodes>;
```

Инициализация очереди заключается в проходе по карте частот (`std::map<char, int>`) и добавлении каждого созданного узла в `HuffmanQueue`:

```cpp
HuffmanQueue initializeQueue(const std::map<char, int>& frequencies) {
    HuffmanQueue pq;
    for (auto const& [symbol, freq] : frequencies) {
        pq.push(new HuffmanNode(symbol, freq));
    }
    return pq;
}
```

Временная сложность этапа инициализации составляет $O(K \log K)$, где $K$ — количество уникальных символов в алфавите (мощность алфавита), так как каждая вставка в очередь с приоритетом требует логарифмического времени от текущего размера очереди.

### Цикл объединения узлов и построение дерева Хаффмана

Ядром алгоритма построения дерева Хаффмана является жадный процесс последовательного объединения поддеревьев снизу вверх. 

Идея алгоритма по шагам:
1. Пока в очереди с приоритетом находится больше одного узла (`pq.size() > 1`), выполняются следующие действия.
2. Извлекается первый узел с минимальной частотой (назовем его `leftChild`).
3. Извлекается второй узел со следующей по возрастанию минимальной частотой (назовем его `rightChild`).
4. Создается новый внутренний родительский узел `parent`, у которого:
   - поле `data` может принимать специальное служебное значение (например, '\0'), так как внутренние узлы не соответствуют конкретным символам текста;
   - поле `freq` равно сумме частот дочерних узлов: `parent->freq = leftChild->freq + rightChild->freq`;
   - указатель `left` указывает на `leftChild`;
   - указатель `right` указывает на `rightChild`.
5. Новый родительский узел `parent` добавляется обратно в очередь с приоритетом `pq`.
6. Процесс повторяется до тех пор, пока в очереди не останется ровно один узел. Этот оставшийся узел становится корневым узлом (`root`) всего дерева Хаффмана.

Напишем функцию, реализующую этот цикл:

```cpp
HuffmanNode* buildHuffmanTree(HuffmanQueue& pq) {
    // Обработка граничного случая: если в очереди вообще нет элементов
    if (pq.empty()) {
        return nullptr;
    }

    // Пока в очереди больше одного узла, объединяем их
    while (pq.size() > 1) {
        // Извлекаем два узла с наименьшими частотами
        HuffmanNode* leftChild = pq.top();
        pq.pop();

        HuffmanNode* rightChild = pq.top();
        pq.pop();

        // Создаем новый родительский узел с суммарной частотой
        // Внутренние узлы не хранят значимый символ, передаем '\0'
        int combinedFreq = leftChild->freq + rightChild->freq;
        HuffmanNode* parent = new HuffmanNode('\0', combinedFreq, leftChild, rightChild);

        // Возвращаем родительский узел в очередь с приоритетом
        pq.push(parent);
    }

    // Единственный оставшийся узел — это корень дерева Хаффмана
    return pq.top();
}
```

Суммарное время работы алгоритма построения дерева составляет $O(K \log K)$, так как на каждом из $K-1$ шагов выполняются операции извлечения и вставки в очередь с приоритетом, содержащую не более $K$ элементов.

### Генерация префиксных кодов обходом дерева

После того как дерево построено и найден его корень, необходимо присвоить каждому символу уникальную битовую последовательность. Для этого выполняется рекурсивный обход дерева от корня до листовых узлов.

Правила формирования кодов:
- При переходе из родительского узла в левого потомка к текущей битовой строке добавляется символ `'0'`.
- При переходе в правого потомка добавляется символ `'1'`.
- Когда рекурсивная функция достигает листового узла (то есть узла, у которого `left == nullptr` и `right == nullptr`), сформированная к этому моменту строка записывается в таблицу кодов для символа, хранящегося в данном листе (`node->data`).

Реализация функции генерации кодов на C++:

```cpp
#include <map>
#include <string>

void generateCodes(HuffmanNode* root, const std::string& currentCode, std::map<char, std::string>& huffmanCodes) {
    if (root == nullptr) {
        return;
    }

    // Проверяем, является ли узел листовым (содержит исходный символ)
    if (root->left == nullptr && root->right == nullptr) {
        // Если текст состоял всего из одного уникального символа, 
        // обработаем этот случай отдельно, чтобы код не был пустым
        if (currentCode.empty()) {
            huffmanCodes[root->data] = "0";
        } else {
            huffmanCodes[root->data] = currentCode;
        }
        return;
    }

    // Рекурсивный обход левого поддерева (добавляем '0')
    generateCodes(root->left, currentCode + "0", huffmanCodes);

    // Рекурсивный обход правого поддерева (добавляем '1')
    generateCodes(root->right, currentCode + "1", huffmanCodes);
}
```

### Разобранный пример: построение дерева для строки 'ABRACADABRA'

Разберем процесс построения дерева Хаффмана и генерацию кодов на конкретном примере. Пусть входная строка имеет вид: `text = "ABRACADABRA"`.

#### Шаг 1. Подсчет частот символов
Подсчитаем количество вхождений каждого символа в строке длиной 11 символов:
- Символ `'A'`: встречается 5 раз ($5/11$)
- Символ `'B'`: встречается 2 раза ($2/11$)
- Символ `'R'`: встречается 2 раза ($2/11$)
- Символ `'C'`: встречается 1 раз ($1/11$)
- Символ `'D'`: встречается 1 раз ($1/11$)

Проверка суммы частот: $5 + 2 + 2 + 1 + 1 = 11$, что совпадает с длиной исходной строки.

#### Шаг 2. Инициализация очереди с приоритетом
Создаем листовые узлы для каждого символа и помещаем их в очередь с приоритетом (минимальные частоты наверху):
1. Узел `('D', freq = 1)`
2. Узел `('C', freq = 1)`
3. Узел `('B', freq = 2)`
4. Узел `('R', freq = 2)`
5. Узел `('A', freq = 5)`

*(Примечание: в реальной структуре порядок элементов с одинаковой частотой зависит от стабильности очереди, но итоговая длина кодов и корректность сжатия от этого не нарушаются).*

#### Шаг 3. Цикл объединения узлов (пошагово)

- **Итерация 1:**
  - Извлекаем два узла с наименьшими частотами: `('D', 1)` и `('C', 1)`.
  - Создаем родительский узел `P1`: частота $1 + 1 = 2$. Левый потомок — `('D', 1)`, правый — `('C', 1)`.
  - Помещаем `P1 (freq = 2)` в очередь.
  - Содержимое очереди теперь: `('B', 2)`, `('R', 2)`, `P1 (2)`, `('A', 5)`.

- **Итерация 2:**
  - Извлекаем два узла с наименьшими частотами: `('B', 2)` и `('R', 2)`.
  - Создаем родительский узел `P2`: частота $2 + 2 = 4$. Левый потомок — `('B', 2)`, правый — `('R', 2)`.
  - Помещаем `P2 (freq = 4)` в очередь.
  - Содержимое очереди теперь: `P1 (2)`, `P2 (4)`, `('A', 5)`.

- **Итерация 3:**
- Извлекаем два узла с наименьшими частотами: `P1 (freq = 2)` и `('А', freq = 5)`? Стоп! Проверим частоты в очереди: в очереди находятся узлы с частотами 2, 4 и 5. Наименьшие частоты имеют `P1 (freq = 2)` и `P2 (freq = 4)`.
  - Извлекаем `P1 (2)` и `P2 (4)`.
  - Создаем родительский узел `P3`: частота $2 + 4 = 6$. Левый потомок — `P1 (2)`, правый — `P2 (4)`.
  - Помещаем `P3 (freq = 6)` в очередь.
  - Содержимое очереди теперь: `('А', 5)`, `P3 (6)`.

- **Итерация 4:**
  - Извлекаем последние два узла: `('А', 5)` и `P3 (6)`.
  - Создаем корневой узел `Root`: частота $5 + 6 = 11$. Левый потомок — `('А', 5)`, правый — `P3 (6)`.
  - Помещаем `Root (freq = 11)` в очередь.
  - В очереди остался ровно 1 узел. Цикл завершен.

#### Шаг 4. Генерация кодов обходом дерева
Начнем рекурсивный обход от корня (`Root`, частота 11):
- Идем в левого потомка (`'A'`, частота 5) — это лист. Записываем код: `A = "0"`.
- Идем в правого потомка (`P3`, частота 6):
  - Из `P3` идем в левого потомка (`P1`, частота 2) — добавляем `'0'` (теперь строка `"0"`):
    - Из `P1` идем в левого потомка (`'D'`, частота 1) — добавляем `'0'`. Итоговый код: `D = "000"`.
    - Из `P1` идем в правого потомка (`'C'`, частота 1) — добавляем `'1'`. Итоговый код: `C = "001"`.
  - Из `P3` идем в правого потомка (`P2`, частота 4) — добавляем `'1'` (теперь строка `"1"`):
    - Из `P2` идем в левого потомка (`'B'`, частота 2) — добавляем `'0'`. Итоговый код: `B = "10"`.
    - Из `P2` идем в правого потомка (`'R'`, частота 2) — добавляем `'1'`. Итоговый код: `R = "11"`.

#### Итоговая таблица кодов для строки 'ABRACADABRA':
| Символ | Частота | Код Хаффмана | Длина кода |
|:---:|:---:|:---:|:---:|
| **A** | 5 | `0` | 1 бит |
| **B** | 2 | `10` | 2 бита |
| **R** | 2 | `11` | 2 бита |
| **C** | 1 | `001` | 3 бита |
| **D** | 1 | `000` | 3 бита |

Проверим свойство префиксности: ни один код не является префиксом другого (например, код `'A'` — `"0"`, а код `'C'` — `"001"`, код `"0"` не совпадает с началом никакого другого полного кода символов первого уровня, так как для `'D'` и `'C'` префикс начинается с `"00"`).

## Побитовый ввод-вывод и упаковка данных

### Проблема побайтовой записи и концепция буферизации

При реализации алгоритма Хаффмана на языке C++ мы сталкиваемся с фундаментальным противоречием. Префиксные коды, порождаемые деревом Хаффмана, имеют переменную длину — от одного бита до нескольких десятков бит в зависимости от глубины дерева и частоты символа. Стандартные файловые потоки ввода-вывода в C++ (`std::ofstream` и `std::ifstream`), а также типы данных общего назначения (такие как `char` или `unsigned char`) оперируют минимальной неделимой единицей информации — байтом, состоящим из $8$ бит.

> **Определение.** Битовый поток — это упорядоченная последовательность логических нулей и единиц, не выровненная по границам байтов, требующая специальной программной абстракции для побитовой записи и чтения.

Если мы попытаемся записать каждую битовую строку (например, строку `"110"` для символа `'A'`) напрямую в файловый поток как символы ASCII `'1'`, `'1'`, `'0'`, то каждый бит займет целый байт ($8$ бит). В результате вместо сжатия мы получим увеличение объема файла в $8$ раз. Для эффективного сжатия биты необходимо плотно упаковывать в байты: по $8$ штук в один байт. 

Для решения этой задачи создаются вспомогательные классы-обертки над стандартными потоками: `BitWriter` для записи и `BitReader` для чтения. Эти классы накапливают биты во внутреннем промежуточном буфере (аккумуляторе) и выполняют запись в физический файл только тогда, когда накопится ровно один полный байт ($8$ бит).

---

### Архитектура и реализация класса `BitWriter`

Класс `BitWriter` инкапсулирует работу с выходным потоком `std::ofstream`. Внутри него находится буферная переменная (аккумулятор) размером в один байт (`unsigned char`) и счетчик заполненных бит (от $0$ до $7$). 

Рассмотрим процесс накопления битов. Пусть мы хотим записать биты последовательно: $1$, $1$, $0$, $1$, $0$, $1$, $1$, $0$, $1$, $0$. Будем заполнять байт-аккумулятор слева направо (от старшего бита к младшему, то есть от позиции $7$ к позиции $0$). 

Когда поступает очередной бит ($b \in \{0, 1\}$), мы сдвигаем текущее содержимое аккумулятора на один бит влево и записываем новый бит в младший разряд с помощью побитового ИЛИ (`|`). Как только счетчик заполненных бит достигает $8$, содержимое аккумулятора сбрасывается (записывается в файл), а аккумулятор и счетчик обнуляются.

> **Определение.** Выравнивание (padding) — это процесс добавления нулевых бит в конец последнего неполного байта сжатого файла с целью заполнить его до полной длины в $8$ бит, так как физическая файловая система не поддерживает потоки произвольной длины, не кратной байту.

Поскольку общая длина сжатой битовой последовательности редко кратна восьми, в конце потока останется «хвост» из нескольких бит (от $1$ до $7$). Если их не дополнить нулями, файл не запишется полностью. Однако при распаковке нам нужно точно знать, сколько именно бит в последнем байте являются полезными данными, а сколько — служебными нулями дополнения. Эту информацию необходимо сохранять в заголовке файла.

Ниже представлен полный и компилируемый код класса `BitWriter` на языке C++:

```cpp
#include <iostream>
#include <fstream>
#include <vector>
#include <cstdint>

class BitWriter {
private:
    std::ofstream& out_;
    unsigned char buffer_;
    uint8_t bit_count_;
    size_t total_bits_written_;

    // Записать один полный байт в файловый поток
    void flush_byte() {
        if (bit_count_ > 0) {
            // Если в буфере меньше 8 бит, сдвигаем их влево до границы старшего бита (padding нулями)
            buffer_ <<= (8 - bit_count_);
            out_.put(static_cast<char>(buffer_));
            buffer_ = 0;
            bit_count_ = 0;
        }
    }

public:
    explicit BitWriter(std::ofstream& out) 
        : out_(out), buffer_(0), bit_count_(0), total_bits_written_(0) {}

    ~BitWriter() {
        // При уничтожении объекта сбрасываем остатки в файл
        try {
            close();
        } catch (...) {
            // Игнорируем исключения в деструкторе
        }
    }

    // Запись одного бита (принимает '0' или '1' как char, либо целое 0 или 1)
    void write_bit(uint8_t bit) {
        buffer_ = (buffer_ << 1) | (bit & 1);
        bit_count_++;
        total_bits_written_++;

        if (bit_count_ == 8) {
            out_.put(static_cast<char>(buffer_));
            buffer_ = 0;
            bit_count_ = 0;
        }
    }

    // Запись строки битов, например, "1101"
    void write_bits(const std::string& bits) {
        for (char c : bits) {
            write_bit(c == '1' ? 1 : 0);
        }
    }

    // Принудительное завершение записи: выравнивание последнего байта
    void close() {
        if (bit_count_ > 0) {
            flush_byte();
        }
    }

    // Получить общее количество записанных полезных бит (для сохранения в заголовок)
    size_t get_total_bits() const {
        return total_bits_written_;
    }
};
```

### Архитектура и реализация класса `BitReader`

Класс `BitReader` выполняет обратную задачу: он читает байты из входного файлового потока `std::ifstream` и выдает их по одному биту. Для этого также используется внутренний буфер. Когда буфер пуст (все $8$ бит прочитаны), класс считывает следующий байт из файла.

Особое внимание при чтении нужно уделять обработке конца файла и предотвращению чтения мусора вместо реальных данных выравнивания. Для этого конструктор `BitReader` принимает общее количество полезных бит в потоке (`total_bits`), которое было сохранено в заголовке архива.

Ниже представлен полный исходный код класса `BitReader`:

```cpp
class BitReader {
private:
    std::ifstream& in_;
    unsigned char buffer_;
    uint8_t bit_count_;
    size_t total_bits_to_read_;
    size_t bits_read_;

public:
    BitReader(std::ifstream& in, size_t total_bits) 
        : in_(in), buffer_(0), bit_count_(0), total_bits_to_read_(total_bits), bits_read_(0) {}

    // Чтение одного бита. Возвращает 0 или 1, а также сигнализирует, успешен ли чтений.
    bool read_bit(uint8_t& out_bit) {
        if (bits_read_ >= total_bits_to_read_) {
            return false; // Достигнут конец полезных данных
        }

        // Если все биты текущего буфера исчерпаны, читаем следующий байт из файла
        if (bit_count_ == 0) {
            char ch;
            if (!in_.get(ch)) {
                return false; // Неожиданный конец файла
            }
            buffer_ = static_cast<unsigned char>(ch);
            bit_count_ = 8;
        }

        // Извлекаем самый старший бит из буфера
        out_bit = (buffer_ >> 7) & 1;
        buffer_ <<= 1;
        bit_count_--;
        bits_read_++;

        return true;
    }
};
```

### Формирование заголовка сжатого файла

Сжатый файл, созданный методом Хаффмана, не может состоять исключительно из упакованных битов данных. Для того чтобы декодер мог восстановить исходный текст, ему необходима информация о структуре дерева Хаффмана или о частотах символов исходного алфавита. 

> **Определение.** Заголовок сжатого файла — это служебная область данных в начале файла, содержащая метаинформацию, необходимую для декомпрессии (количество уникальных символов, таблицу частот или сериализованное дерево, а также общее количество полезных бит).

Стандартная структура нашего сжатого файла выглядит следующим образом:
1. **Общее количество полезных бит** (тип `size_t`, занимающий $8$ байт в 64-битной системе).
2. **Количество уникальных символов в алфавите** `K` (тип `uint32_t`, занимающий $4$ байта).
3. **Таблица частот** (для каждого из $K$ символов записывается сам символ `char` (1 байт) и его частота `size_t` (8 байт)).
4. **Упакованные данные** (последовательность байтов, сформированная классом `BitWriter`).

При распаковке программа сначала читает заголовок, восстанавливает таблицу частот, заново строит идентичное дерево Хаффмана, а затем запускает `BitReader`, который побитово спускается по дереву от корня к листьям до тех пор, пока не прочитает ровно `total_bits` бит.

### Разобранный пример: упаковка и распаковка битовой последовательности

Рассмотрим детальный пример работы с классами `BitWriter` и `BitReader`. 

#### Условие задачи
Дана битовая строка длиной $10$ символов: `"1101011010"`. Необходимо:
1. Записать ее с помощью `BitWriter` во временный файл.
2. Определить, сколько байт займет запись и каким будет байтовое представление.
3. Прочитать файл с помощью `BitReader` и убедиться, что исходная последовательность восстановилась без потерь.

#### Ход рассуждений и побитовый расчет
Входная строка: `1 1 0 1 0 1 1 0 1 0` (всего $10$ бит).

Поскольку в одном байте $8$ бит, $10$ бит не помещаются в один байт. Нам потребуется:
$$\lceil 10 / 8 \rceil = \lceil 1{,}25 \rceil = 2 \text{ байта}.$$

Заполняем первый байт (первые $8$ бит слева направо):
- Бит 1: `1` $\rightarrow$ буфер `00000001`
- Бит 2: `1` $\rightarrow$ буфер `00000011`
- Бит 3: `0` $\rightarrow$ буфер `00000110`
- Бит 4: `1` $\rightarrow$ буфер `00001101`
- Бит 5: `0` $\rightarrow$ буфер `00011010`
- Бит 6: `1` $\rightarrow$ буфер `00110101`
- Бит 7: `1` $\rightarrow$ буфер `01101011`
- Бит 8: `0` $\rightarrow$ буфер `11010110` (байт заполнен, записывается в файл как `0xD6`).

Остались еще $2$ бита (`1`, `0`). Они попадают во второй байт-аккумулятор:
- Бит 9: `1` $\rightarrow$ буфер `00000001`
- Бит 10: `0` $\rightarrow$ буфер `00000010`

Поток завершается. Срабатывает метод `close()`, который вызывает `flush_byte()`. Оставшиеся в буфере $2$ бита сдвигаются влево на $8 - 2 = 6$ бит (padding нулями):
$$\text{буфер} = \text{`00000010'} \ll 6 = \text{`10000000'}.$$
Второй байт записывается в файл как `0x80` ($128$ в десятичной системе).

Итоговый файл содержит ровно $2$ байта: `0xD6`, `0x80`.

#### Программная реализация примера на C++

Ниже приведена автономная программа, демонстрирующая этот процесс:

```cpp
#include <iostream>
#include <fstream>
#include <string>
#include <vector>
#include <cstdint>
#include <cassert>

// Классы BitWriter и BitReader определены выше

int main() {
    // Установка русской локали для корректного вывода
    std::setlocale(LC_ALL, "Russian");

    std::string original_bits = "1101011010";
    std::string filename = "test_bits.bin";

    // Шаг 1. Запись битов в файл
    {
        std::ofstream outfile(filename, std::ios::binary);
        if (!outfile.is_open()) {
            std::cerr << "Ошибка открытия файла для записи!" << std::endl;
            return 1;
        }

        BitWriter writer(outfile);
        writer.write_bits(original_bits);
        writer.close(); // Завершаем запись, производим padding последнего байта
        
        std::cout << "Записано исходных бит: " << original_bits.length() << std::endl;
        std::cout << "Всего полезных бит в Writer: " << writer.get_total_bits() << std::endl;
    } // outfile закрывается здесь при выходе из области видимости

    // Шаг 2. Чтение битов из файла
    std::string restored_bits = "";
    {
        std::ifstream infile(filename, std::ios::binary);
        if (!infile.is_open()) {
            std::cerr << "Ошибка открытия файла для чтения!" << std::endl;
            return 1;
        }

        // Мы знаем, что записали ровно 10 полезных бит
        BitReader reader(infile, 10);
        uint8_t bit;
        while (reader.read_bit(bit)) {
            restored_bits += (bit == 1 ? '1' : '0');
        }
    }

    // Шаг 3. Проверка корректности
    std::cout << "Восстановленные биты: " << restored_bits << std::endl;

    if (original_bits == restored_bits) {
        std::cout << "Успех: битовая последовательность восстановлена абсолютно точно!" << std::endl;
    } else {
        std::cout << "Ошибка: последовательности не совпадают!" << std::endl;
    }

    return 0;
}
```

#### Проверка и анализ результатов
1. **Единицы измерения:** Размер файла составил $2$ байта ($16$ бит), из которых $10$ бит — полезная информация, а $6$ бит — служебное дополнение (padding).
2. **Правдоподобие:** Алгоритм сдвига влево (`buffer_ <<= (8 - bit_count_)`) гарантирует, что старшие биты неполного байта заполнились нашими данными, а младшие заполнились нулями. `BitReader`, читая ровно $10$ раз, остановился ровно на границе полезных данных и не захватил хвостовые нули второго байта.

### Анализ временной и пространственной сложности

- **Временная сложность побитовой записи и чтения:** Каждая операция с битом в классах `BitWriter` и `BitReader` выполняет простейшие арифметические и побитовые сдвиги (`<<`, `>>`, `|`, `&`), сложность которых составляет $O(1)$ на один бит. Для потока длиной $M$ бит суммарное время работы ввода-вывода составляет $O(M)$.
- **Пространственная сложность:** Классы используют фиксированный объем дополнительной памяти под буфер (один байт `unsigned char` и несколько счетчиков), поэтому пространственная сложность дополнительных структур равна $O(1)$.

## Полная программная реализация и сборка

Для того чтобы студент мог самостоятельно развернуть и запустить проект, мы приведем полностью рабочий исходный код, написанный в строгом соответствии со стандартом C++17. В программе реализована детальная обработка исключительных ситуаций: проверка доступности файлов, корректность аргументов командной строки и проверка целостности заголовка архива.

### Архитектура и интерфейс командной строки

Программа должна работать в двух режимах: режим сжатия (`-c`) и режим распаковки (`-d`). В качестве интерфейса взаимодействия используется стандартный массив аргументов функции `main`: `argc` (количество аргументов) и `argv` (массив строк-аргументов).

Общий формат вызова скомпилированной программы из командной строки выглядит следующим образом:
- Для сжатия: `./huffman -c input.txt compressed.huff`
- Для распаковки: `./huffman -d compressed.huff restored.txt`

Если пользователь передает неверное количество аргументов или ошибочный флаг режима, программа выводит справочное сообщение и завершает работу с кодом возврата, отличным от нуля.

Для обеспечения возможности восстановления дерева Хаффмана при декомпрессии в начале сжатого файла (в заголовке) необходимо сохранить информацию о частотах символов. Мы будем использовать следующий простой и надежный формат заголовка:
1. Количество уникальных символов в алфавите ($K$), записанное как четырехбайтовое целое число (`uint32_t`).
2. Для каждого из $K$ символов: сам символ (1 байт) и его частота в исходном тексте, записанная как четырехбайтовое целое число (`uint32_t`).
3. Общее количество бит в закодированном сообщении (`uint64_t`), необходимое для того, чтобы при декомпрессии отбросить биты дополнения (padding), добавленные в последний байт.
4. Далее следует битовый поток сжатых данных.

### Полный исходный код программы на C++

Ниже представлен монолитный исходный код программы, объединяющий все вспомогательные классы и алгоритмы сжатия и декомпрессии. Вы можете сохранить этот код в файл `huffman.cpp`.

```cpp
#include <iostream>
#include <vector>
#include <string>
#include <map>
#include <queue>
#include <fstream>
#include <memory>
#include <cstdint>
#include <algorithm>

// Структура узла дерева Хаффмана
struct HuffmanNode {
    char character;
    uint32_t frequency;
    std::shared_ptr<HuffmanNode> left;
    std::shared_ptr<HuffmanNode> right;

    HuffmanNode(char ch, uint32_t freq) 
        : character(ch), frequency(freq), left(nullptr), right(nullptr) {}

    HuffmanNode(uint32_t freq, std::shared_ptr<HuffmanNode> l, std::shared_ptr<HuffmanNode> r) 
        : character(0), frequency(freq), left(l), right(r) {}
};

// Компаратор для std::priority_queue (минимальная куча по частоте)
struct CompareNodes {
    bool operator()(const std::shared_ptr<HuffmanNode>& a, const std::shared_ptr<HuffmanNode>& b) {
        return a->frequency > b->frequency;
    }
};

// Вспомогательный класс для побитовой записи в файл
class BitWriter {
private:
    std::ofstream& out_;
    uint8_t current_byte_;
    int bit_count_;

public:
    explicit BitWriter(std::ofstream& out) : out_(out), current_byte_(0), bit_count_(0) {}

    void writeBit(int bit) {
        current_byte_ = (current_byte_ << 1) | (bit & 1);
        bit_count_++;
        if (bit_count_ == 8) {
            out_.put(current_byte_);
            current_byte_ = 0;
            bit_count_ = 0;
        }
    }

    void writeString(const std::string& bits) {
        for (char c : bits) {
            writeBit(c - '0');
        }
    }

    void flush() {
        if (bit_count_ > 0) {
            current_byte_ <<= (8 - bit_count_);
            out_.put(current_byte_);
            current_byte_ = 0;
            bit_count_ = 0;
        }
    }
};

// Вспомогательный класс для побитового чтения из файла
class BitReader {
private:
    std::ifstream& in_;
    uint8_t current_byte_;
    int bit_count_;

public:
    explicit BitReader(std::ifstream& in) : in_(in), current_byte_(0), bit_count_(0) {}

    int readBit() {
        if (bit_count_ == 0) {
            if (!in_.get(reinterpret_cast<char&>(current_byte_))) {
                return -1; // Конец файла
            }
            bit_count_ = 8;
        }
        bit_count_--;
        return (current_byte_ >> bit_count_) & 1;
    }
};

// Рекурсивный обход дерева для генерации таблиц префиксных кодов
void generateCodes(const std::shared_ptr<HuffmanNode>& node, const std::string& code, std::map<char, std::string>& huffmanCodes) {
    if (!node) return;

    // Если узел листовой, сохраняем накопленный код
    if (!node->left && !node->right) {
        huffmanCodes[node->character] = code.empty() ? "0" : code;
        return;
    }

    generateCodes(node->left, code + "0", huffmanCodes);
    generateCodes(node->right, code + "1", huffmanCodes);
}

// Рекурсивное освобождение памяти (хотя smart pointers делают это автоматически, полезно для понимания)
void freeTree(std::shared_ptr<HuffmanNode>& node) {
    node.reset();
}

// Функция сжатия файла
void compressFile(const std::string& inputFilename, const std::string& outputFilename) {
    std::ifstream inFile(inputFilename, std::ios::binary);
    if (!inFile.is_open()) {
        throw std::runtime_error("Ошибка: не удалось открыть входной файл для чтения: " + inputFilename);
    }

    // Шаг 1: Подсчет частот символов
    std::map<char, uint32_t> frequencies;
    char ch;
    uint64_t totalChars = 0;
    while (inFile.get(ch)) {
        frequencies[ch]++;
        totalChars++;
    }

    if (totalChars == 0) {
        std::ofstream outFile(outputFilename, std::ios::binary);
        uint32_t zero = 0;
        outFile.write(reinterpret_cast<const char*>(&zero), sizeof(zero));
        outFile.write(reinterpret_cast<const char*>(&zero), sizeof(uint64_t));
        std::cout << "Предупреждение: входной файл пуст." << std::endl;
        return;
    }

    // Шаг 2: Построение дерева Хаффмана с помощью очереди с приоритетом
    std::priority_queue<std::shared_ptr<HuffmanNode>, std::vector<std::shared_ptr<HuffmanNode>>, CompareNodes> pq;

    for (const auto& pair : frequencies) {
        pq.push(std::make_shared<HuffmanNode>(pair.first, pair.second));
    }

    // Особый случай: если в файле всего один уникальный символ
    if (pq.size() == 1) {
        auto singleNode = pq.top();
        pq.pop();
        auto root = std::make_shared<HuffmanNode>(singleNode->frequency, singleNode, nullptr);
        pq.push(root);
    }

    while (pq.size() > 1) {
        auto left = pq.top(); pq.pop();
        auto right = pq.top(); pq.pop();
        auto parent = std::make_shared<HuffmanNode>(left->frequency + right->frequency, left, right);
        pq.push(parent);
    }

    auto root = pq.top();

    // Шаг 3: Генерация таблиц кодов
    std::map<char, std::string> huffmanCodes;
    generateCodes(root, "", huffmanCodes);

    // Шаг 4: Открытие выходного файла и запись заголовка
    std::ofstream outFile(outputFilename, std::ios::binary);
    if (!outFile.is_open()) {
        throw std::runtime_error("Ошибка: не удалось создать выходной файл: " + outputFilename);
    }

    uint32_t uniqueCount = static_cast<uint32_t>(frequencies.size());
    outFile.write(reinterpret_cast<const char*>(&uniqueCount), sizeof(uniqueCount));

    for (const auto& pair : frequencies) {
        outFile.put(pair.first);
        uint32_t freq = pair.second;
        outFile.write(reinterpret_cast<const char*>(&freq), sizeof(freq));
    }

    // Подсчет общего количества бит для записи в заголовок
    uint64_t totalBits = 0;
    for (const auto& pair : frequencies) {
        totalBits += static_cast<uint64_t>(pair.second) * huffmanCodes[pair.first].length();
    }
    outFile.write(reinterpret_cast<const char*>(&totalBits), sizeof(totalBits));

    // Шаг 5: Повторное чтение файла и побитовая запись закодированного текста
    inFile.clear();
    inFile.seekg(0, std::ios::beg);

    BitWriter bitWriter(outFile);
    while (inFile.get(ch)) {
        bitWriter.writeString(huffmanCodes[ch]);
    }
    bitWriter.flush();

    std::cout << "Файл успешно сжат." << std::endl;
    std::cout << "Исходный размер: " << totalChars << " байт." << std::endl;
}

// Функция декомпрессии файла
void decompressFile(const std::string& inputFilename, const std::string& outputFilename) {
    std::ifstream inFile(inputFilename, std::ios::binary);
    if (!inFile.is_open()) {
        throw std::runtime_error("Ошибка: не удалось открыть файл архива: " + inputFilename);
    }

    // Шаг 1: Чтение заголовка
    uint32_t uniqueCount = 0;
    if (!inFile.read(reinterpret_cast<char*>(&uniqueCount), sizeof(uniqueCount))) {
        throw std::runtime_error("Ошибка: поврежденный заголовок архива (не удалось прочитать количество символов).");
    }

    std::map<char, uint32_t> frequencies;
    for (uint32_t i = 0; i < uniqueCount; ++i) {
        char ch;
        if (!inFile.get(ch)) {
            throw std::runtime_error("Ошибка: неожиданный конец файла при чтении таблицы частот.");
        }
        uint32_t freq = 0;
        if (!inFile.read(reinterpret_cast<char*>(&freq), sizeof(freq))) {
            throw std::runtime_error("Ошибка: поврежденный заголовок архива при чтении частоты символа.");
        }
        frequencies[ch] = freq;
    }

    uint64_t totalBits = 0;
    if (!inFile.read(reinterpret_cast<char*>(&totalBits), sizeof(totalBits))) {
        throw std::runtime_error("Ошибка: поврежденный заголовок архива (не удалось прочитать общее число бит).");
    }

    if (uniqueCount == 0 || totalBits == 0) {
        // Пустой файл
        std::ofstream outFile(outputFilename, std::ios::binary);
        std::cout << "Архив пуст. Восстановлен пустой файл." << std::endl;
        return;
    }

    // Шаг 2: Восстановление дерева Хаффмана
    std::priority_queue<std::shared_ptr<HuffmanNode>, std::vector<std::shared_ptr<HuffmanNode>>, CompareNodes> pq;

    for (const auto& pair : frequencies) {
        pq.push(std::make_shared<HuffmanNode>(pair.first, pair.second));
    }

    if (pq.size() == 1) {
        auto singleNode = pq.top();
        pq.pop();
        auto root = std::make_shared<HuffmanNode>(singleNode->frequency, singleNode, nullptr);
        pq.push(root);
    }

    while (pq.size() > 1) {
        auto left = pq.top(); pq.pop();
        auto right = pq.top(); pq.pop();
        auto parent = std::make_shared<HuffmanNode>(left->frequency + right->frequency, left, right);
        pq.push(parent);
    }

    auto root = pq.top();

    // Шаг 3: Побитовое чтение и проход по дереву для восстановления исходных данных
    std::ofstream outFile(outputFilename, std::ios::binary);
    if (!outFile.is_open()) {
        throw std::runtime_error("Ошибка: не удалось создать восстановленный файл: " + outputFilename);
    }

    BitReader bitReader(inFile);
    uint64_t decodedBits = 0;
    auto currentNode = root;

    while (decodedBits < totalBits) {
        int bit = bitReader.readBit();
        if (bit == -1) {
            throw std::runtime_error("Ошибка: неожиданный конец файла внутри битового потока данных.");
        }
        decodedBits++;

        if (bit == 0) {
            currentNode = currentNode->left;
        } else {
            currentNode = currentNode->right;
        }

        if (!currentNode) {
            throw std::runtime_error("Ошибка: критический сбой декодирования (достигнут нулевой указатель в дереве).");
        }

        // Если достигли листа, записываем символ и возвращаемся в корень
        if (!currentNode->left && !currentNode->right) {
            outFile.put(currentNode->character);
            currentNode = root;
        }
    }

    std::cout << "Файл успешно распакован." << std::endl;
}

// Главная функция с обработкой аргументов командной строки
int main(int argc, char* argv[]) {
    try {
        if (argc != 4) {
            std::cerr << "Использование:" << std::endl;
            std::cerr << "  Сжатие:   " << argv[0] << " -c <входной_файл> <архив.huff>" << std::endl;
            std::cerr << "  Распаковка: " << argv[0] << " -d <архив.huff> <восстановленный_файл>" << std::endl;
            return 1;
        }

        std::string mode = argv[1];
        std::string inputFile = argv[2];
        std::string outputFile = argv[3];

        if (mode == "-c") {
            compressFile(inputFile, outputFile);
        } else if (mode == "-d") {
            decompressFile(inputFile, outputFile);
        } else {
            std::cerr << "Ошибка: неизвестный режим работы '" << mode << "'. Используйте -c или -d." << std::endl;
            return 1;
        }
    } catch (const std::exception& e) {
        std::cerr << e.what() << std::endl;
        return 1;
    }

    return 0;
}
```

### Разбор структуры кода и ключевых функций

1. **Управление памятью через `std::shared_ptr`**:
   Для исключения утечек памяти в динамических структурах данных дерева Хаффмана мы используем умные указатели из стандартной библиотеки C++ (`std::shared_ptr`). Это избавляет нас от необходимости вручную писать сложный деструктор для обхода и удаления дерева при завершении работы функций сжатия и распаковки.

2. **Безопасность потоков ввода-вывода (`std::ios::binary`)**:
   Все операции с файлами (`std::ifstream` и `std::ofstream`) выполняются исключительно в бинарном режиме. Это критически важно, так как в текстовом режиме операционные системы (например, Windows) могут автоматически заменять символы перевода строки (`\n` на пару байт `\r\n`), что привело бы к фатальному искажению битовой последовательности сжатого файла.

3. **Обработка краевых случаев**:
   - **Пустой файл**: проверяется счетчик общего количества байт. Если файл пустой, программа записывает нулевой заголовок и корректно завершает работу без попыток построения дерева.
   - **Один уникальный символ**: если во всем файле повторяется только один символ (например, строка из тысячи букв `'A'`), стандартный алгоритм Хаффмана с двумя дочерними узлами привел бы к неопределенности. В коде предусмотрена специальная проверка (`if (pq.size() == 1)`), которая создает искусственный родительский узел, гарантируя корректное назначение кода `"0"` единственному символу.

## Тестирование, анализ сложности и типичные ошибки

### Методика проверки корректности результатов

После того как программа написана и скомпилирована, критически важно убедиться, что алгоритм сжатия и распаковки работает абсолютно без потерь (lossless compression). Это означает, что для любого входного файла $F$ после последовательного применения операций сжатия (получение файла $F_{\text{comp}}$) и распаковки (получение файла $F_{\text{rest}}$) исходный и восстановленный файлы должны быть **побитово идентичны**.

Для проверки корректности в операционных системах семейства UNIX / Linux используется утилита `diff`, а в Windows — утилита `fc` (File Compare). Однако визуальный или стандартный текстовый `diff` может не подойти, если файлы содержат бинарные данные. Поэтому применяют сравнение контрольных сумм (хеш-сумм) с помощью алгоритмов SHA-256 или MD5.

Пусть исходный файл имеет имя `input.txt`, сжатый — `compressed.huff`, а восстановленный — `restored.txt`. Проверка в командной среде Linux выполняется следующим образом:

```bash
# Вычисление контрольной суммы исходного файла
sha256sum input.txt

# Вычисление контрольной суммы восстановленного файла
sha256sum restored.txt
```

Если шестнадцатеричные строки контрольных сумм для `input.txt` и `restored.txt` полностью совпадают, это является строгим доказательством того, что алгоритм кодирования и декодирования Хаффмана реализован корректно и не вносит искажений в структуру данных.

### Оценка степени сжатия и теоретический предел

Эффективность работы программы оценивается через коэффициент сжатия $K$ и среднюю длину кодового слова. 

Коэффициент сжатия $K$ определяется как отношение размера исходного файла к размеру сжатого файла:

$$K = \frac{L_{\text{исх}}}{L_{\text{сж}}}$$

где:
- $L_{\text{исх}}$ — размер исходного файла в байтах;
- $L_{\text{сж}}$ — размер сжатого файла в байтах, включая служебные данные (заголовок с таблицей частот или сериализованным деревом).

В теории информации предел эффективности префиксного кодирования задается энтропией источника $H(X)$, которая измеряется в битах на символ:

$$H(X) = - \sum_{i=1}^{K} p_i \log_2 p_i$$

где:
- $K$ — мощность алфавита (количество уникальных символов);
- $p_i$ — вероятность появления $i$-го символа в тексте.

Средняя длина кодового слова, полученная с помощью кода Хаффмана, обозначается как $L_{\text{cp}}$ и рассчитывается по формуле:

$$L_{\text{cp}} = \sum_{i=1}^{K} p_i l_i$$

где $l_i$ — длина двоичного кода $i$-го символа в битах.

Согласно первой теореме Шеннона о кодировании источника, средняя длина оптимального префиксного кода удовлетворяет неравенству:

$$H(X) \le L_{\text{cp}} < H(X) + 1$$

### Разобранный пример 1: Расчет коэффициента сжатия и сравнение с энтропией

**Условие:**
Имеется текстовый файл `input.txt` размером $L_{\text{исх}} = 10000$ байт ($80000$ бит), содержащий символы четырех видов: `'A'`, `'B'`, `'C'`, `'D'`. Частоты встречаемости символов в файле распределены неравномерно:
- Символ `'A'`: $5000$ раз ($p_A = 0{,}5$)
- Символ `'B'`: $2500$ раз ($p_B = 0{,}25$)
- Символ `'C'`: $1250$ раз ($p_C = 0{,}125$)
- Символ `'D'`: $1250$ раз ($p_D = 0{,}125$)

Каждый символ в исходном несжатом файле кодируется стандартным образом в кодировке ASCII / UTF-8 одним байтом ($8$ бит). 

Требуется:
1. Рассчитать энтропию источника $H(X)$.
2. Построить дерево Хаффмана и определить длины кодов $l_i$ для каждого символа.
3. Рассчитать среднюю длину кодового слова $L_{\text{cp}}$.
4. Оценить теоретический размер сжатых данных и рассчитать коэффициент сжатия $K$ (без учета заголовка).

**Ход рассуждений:**
1. Вычисляем энтропию дискретного источника по формуле Шеннона, подставляя заданные вероятности.
2. Проводим процедуру построения дерева Хаффмана снизу вверх: объединяем узлы с наименьшими вероятностями ($C$ и $D$), получаем промежуточный узел с вероятностью $0{,}25$, затем объединяем его с символом $B$ (вероятность $0{,}25$) и на финальном шаге — с символом $A$ (вероятность $0{,}5$).
3. По полученному дереву определяем длины двоичных кодов для каждого символа.
4. Находим среднюю длину кодового слова $L_{\text{cp}}$ и умножаем ее на общее число символов ($10000$), чтобы получить размер сжатых данных в битах. Переводим в байты и вычисляем коэффициент $K$.

**Решение в общем виде и вычисления:**

1. Энтропия источника:
$$H(X) = - \left( 0{,}5 \log_2 0{,}5 + 0{,}25 \log_2 0{,}25 + 0{,}125 \log_2 0{,}125 + 0{,}125 \log_2 0{,}125 \right)$$

Учитывая, что $\log_2 0{,}5 = -1$, $\log_2 0{,}25 = -2$, $\log_2 0{,}125 = -3$:
$$H(X) = - \left( 0{,}5 \cdot (-1) + 0{,}25 \cdot (-2) + 0{,}125 \cdot (-3) + 0{,}125 \cdot (-3) \right)$$
$$H(X) = - \left( -0{,}5 - 0{,}5 - 0{,}375 - 0{,}375 \right) = -(-1{,}75) = 1{,}75 \text{ бит/символ}$$

2. Построение кодов Хаффмана:
- Шаг 1: Символы $C$ ($p=0{,}125$) и $D$ ($p=0{,}125$) объединяются в узел $CD$ ($p=0{,}25$). Коды ветвей: пусть $C \to 0$, $D \to 1$.
- Шаг 2: Узел $CD$ ($p=0{,}25$) объединяется с символом $B$ ($p=0{,}25$). Пусть $B \to 0$, узел $CD \to 1$. Тогда полные коды: $B = \text{"0"}$, $C = \text{"10"}$, $D = \text{"11"}$.
- Шаг 3: Полученный узел $BCD$ ($p=0{,}5$) объединяется с символом $A$ ($p=0{,}5$). Пусть $A \to 0$, узел $BCD \to 1$. 

Итоговые кодовые слова и их длины $l_i$:
- Символ `'A'`: код `0`, длина $l_A = 1$ бит
- Символ `'B'`: код `10`, длина $l_B = 2$ бита
- Символ `'C'`: код `110`, длина $l_C = 3 бита$
- Символ `'D'`: код `111`, длина $l_D = 3$ бита

3. Средняя длина кодового слова:
$$L_{\text{cp}} = \sum_{i \in \{A, B, C, D\}} p_i l_i = 0{,}5 \cdot 1 + 0{,}25 \cdot 2 + 0{,}125 \cdot 3 + 0{,}125 \cdot 3$$
$$L_{\text{cp}} = 0{,}5 + 0{,}5 + 0{,}375 + 0{,}375 = 1{,}75 \text{ бит/символ}$$

Полученное значение средней длины точно совпало с энтропией ($L_{\text{cp}} = H(X)$), что свидетельствует об абсолютной оптимальности построенного кода для данного распределения вероятностей.

4. Расчет размера и коэффициента сжатия:
Общий объем сжатых данных в битах:
$$L_{\text{сж\_бит}} = 10000 \text{ симв} \cdot 1{,}75 \text{ бит/симв} = 17500 \text{ бит}$$

Перевод в байты с округлением вверх до целого числа байт:
$$L_{\text{сж}} = \left\lceil \frac{17500}{8} \right\rceil = \left\lceil 2187{,}5 \right\rceil = 2188 \text{ байт}$$

Коэффициент сжатия $K$ (без учета служебного заголовка):
$$K = \frac{10000}{2188} \approx 4{,}57$$

**Проверка:**
Размер исходного файла составлял $10000$ байт, сжатого — $2188$ байт. Файл уменьшился почти в $4,6$ раза. Значение $L_{\text{cp}} = 1{,}75$ находится в допустимом диапазоне $1{,}75 \le 1{,}75 < 2{,}75$. Расчеты верны.

`Ответ:` Энтропия источника $H(X) = 1{,}75$ бит/символ; средняя длина кода $L_{\text{cp}} = 1{,}75$ бит; коэффициент сжатия $K \approx 4{,}57$.

### Анализ временной и пространственной сложности

При разработке программного обеспечения критически важно понимать требования алгоритма к вычислительным ресурсам процессора и оперативной памяти.

#### Временная сложность
1. **Подсчет частот символов:** Осуществляется за один проход по входному файлу размером $M$ байт. Сложность составляет **$O(M)$**.
2. **Построение дерева Хаффмана:** 
   - Инициализация очереди с приоритетом (`std::priority_queue`) для $K$ уникальных символов занимает $O(K)$.
   - На каждом из $K-1$ шагов цикла извлекаются два минимальных элемента (операция `pop` занимает $O(\log K)$) и вставляется новый родительский узел (операция `push` занимает $O(\log K)$).
   - Суммарное время построения дерева: **$O(K \log K)$**, где $K$ — мощность алфавита (для стандартного байтового алфавита $K \le 256$, поэтому $K \log K$ является константой).
3. **Кодирование данных:** Каждый из $M$ байтов исходного файла заменяется на битовую строку средней длиной $L_{\text{cp}}$. Сложность прямого прохода составляет **$O(M)$**.
4. **Декодирование данных:** Процесс побитового обхода дерева Хаффмана от корня к листу для каждого закодированного бита. Сложность пропорциональна количеству бит в сжатом потоке, то есть **$O(M)$**.

#### Пространственная сложность
Основной объем памяти расходуется на хранение структур данных:
1. Таблица частот или отображение кодов (`std::map<char, std::string>`) требует **$O(K)$** памяти.
2. Динамические узлы дерева Хаффмана (`HuffmanNode`) в количестве не более $2K-1$ узлов занимают **$O(K)$** памяти в куче (heap).
3. Буферы чтения и записи файлов фиксированного размера (например, по $4096$ байт) требуют $O(1)$ дополнительной памяти.

Суммарная пространственная сложность алгоритма составляет **$O(K)$**, что делает алгоритм крайне эффективным по памяти, так как размер алфавита $K$ ограничен сверху (например, $256$ для байтов).

### Типичные ошибки студентов и методы их предотвращения

При реализации лабораторной работы студенты часто сталкиваются с характерными программными ошибками. Рассмотрим их подробно.

#### 1. Утечки памяти при уничтожении дерева
* **Суть ошибки:** Узлы дерева Хаффмана создаются в динамической памяти с помощью оператора `new`. После завершения кодирования и записи файла динамические объекты не удаляются, что приводит к утечке памяти (memory leak).
* **Решение:** Необходимо реализовать рекурсивный деструктор или отдельную функцию `freeTree(HuffmanNode* root)`, которая обходит дерево в постфиксном порядке (сначала удаляются левый и правый потомки, затем текущий узел) и освобождает память через `delete`. Пример корректного освобождения:
```cpp
void freeTree(HuffmanNode* node) {
    if (!node) return;
    freeTree(node->left);
    freeTree(node->right);
    delete node;
}
```

#### 2. Неверная обработка отступа (padding) в последнем байте
* **Суть ошибки:** Общая длина всех сжатых бит часто не кратна $8$. При упаковке битов в байтовый массив последние оставшиеся биты дополняются нулями (padding) до полных $8$ бит. При распаковке алгоритм считывает эти лишние нули и воспринимает их как закодированные символы, что приводит к появлению «мусора» в конце восстановленного файла или к аварийному завершению программы.
* **Решение:** В заголовок сжатого файла необходимо записывать служебную информацию — количество валидных бит в последнем байте (число от $0$ до $7$) либо общее количество исходных символов $M$, по которому декодер точно знает, когда следует прекратить чтение.

### Разобранный пример 2: Анализ и исправление ошибки восстановления последнего байта

**Условие:**
В процессе сжатия файла сформировалась битовая последовательность длиной $13$ бит: `1101011010110`. 
Поскольку запись ведется байтами, эта последовательность делится на два байта:
- Первый байт (полные $8$ бит): `11010110`
- Второй байт (остаток из $5$ бит): `10110`

Для заполнения второго байта до $8$ бит программа добавляет справа три нулевых бита (padding): `10110000`.
В результирующий файл записываются два байта: `11010110` (в шестнадцатеричной системе `0xD6`) и `10110000` (`0xB0`).

При распаковке декодер считывает оба байта и начинает побитово обходить дерево Хаффмана. Прочитав первые $8$ бит первого байта, а затем все $8$ бит второго байта (всего $16$ бит вместо исходных $13$), декодер захватывает добавленные нули (`000`), пытаясь интерпретировать их как кодовое слово.

**Ход рассуждений для исправления ошибки:**
1. Необходимо модифицировать заголовок сжатого файла, добавив в него количество бит, записанных в последний байт, либо общее число закодированных символов.
2. В данном примере проще всего сохранить в начале файла 1 байт, хранящий количество значимых бит в последнем байте (в нашем случае это число $5$).
3. При декомпрессии, доходя до чтения последнего байта, декодер должен останавливать чтение и интерпретацию ровно после $5$-го бита, игнорируя оставшиеся $3$ нулевых бита заполнения.

**Решение (фрагмент кода на C++):**

```cpp
#include <iostream>
#include <vector>
#include <fstream>

// Структура для имитации записи битов в байтовый буфер
class BitWriter {
private:
    std::vector<uint8_t> buffer;
    uint8_t current_byte = 0;
    int bit_count = 0;

public:
    void writeBit(int bit) {
        if (bit) {
            current_byte |= (1 << (7 - bit_count));
        }
        bit_count++;
        if (bit_count == 8) {
            buffer.push_back(current_byte);
            current_byte = 0;
            bit_count = 0;
        }
    }

    void flush(std::ofstream& out) {
        uint8_t valid_bits_in_last = bit_count;
        if (bit_count > 0) {
            buffer.push_back(current_byte);
        }
        // Записываем в начало файла (или заголовок) количество валидных бит в последнем байте
        out.put(static_cast<char>(valid_bits_in_last));
        
        // Записываем размер буфера и сам буфер
        size_t size = buffer.size();
        out.write(reinterpret_cast<const char*>(&size), sizeof(size));
        out.write(reinterpret_cast<const char*>(buffer.data()), size);
    }
};
```

При чтении файла класс `BitReader` считывает количество валидных бит в последнем байте и прекращает процесс декодирования сразу после обработки нужного количества бит, полностью исключая влияние padding-нулей.

`Ответ:` Ошибка некорректного восстановления последнего байта устраняется путем сохранения в служебном заголовке файла информации о количестве значимых бит в финальном байте и принудительным прекращением цикла декодирования по достижении этого счетчика.

### Полный исходный код программы на C++ (продолжение)

```cpp
    if (!inFile.read(reinterpret_cast<char*>(&uniqueCount), sizeof(uniqueCount))) {
        throw std::runtime_error("Ошибка чтения заголовка архива: поврежден файл.");
    }

    std::map<char, uint32_t> frequencies;
    for (uint32_t i = 0; i < uniqueCount; ++i) {
        char ch;
        uint32_t freq;
        if (!inFile.get(ch) || !inFile.read(reinterpret_cast<char*>(&freq), sizeof(freq))) {
            throw std::runtime_error("Ошибка чтения частотной таблицы из архива.");
        }
        frequencies[ch] = freq;
    }

    uint64_t totalBits = 0;
    if (!inFile.read(reinterpret_cast<char*>(&totalBits), sizeof(totalBits))) {
        throw std::runtime_error("Ошибка чтения общего числа бит из архива.");
    }

    // Если файл пуст
    if (uniqueCount == 0 && totalBits == 0) {
        std::ofstream outFile(outputFilename, std::ios::binary);
        std::cout << "Файл успешно распакован (пустой файл)." << std::endl;
        return;
    }

    // Шаг 2: Воссоздание дерева Хаффмана по таблице частот
    std::priority_queue<std::shared_ptr<HuffmanNode>, std::vector<std::shared_ptr<HuffmanNode>>, CompareNodes> pq;

    for (const auto& pair : frequencies) {
        pq.push(std::make_shared<HuffmanNode>(pair.first, pair.second));
    }

    if (pq.size() == 1) {
        auto singleNode = pq.top();
        pq.pop();
        auto root = std::make_shared<HuffmanNode>(singleNode->frequency, singleNode, nullptr);
        pq.push(root);
    }

    while (pq.size() > 1) {
        auto left = pq.top(); pq.pop();
        auto right = pq.top(); pq.pop();
        auto parent = std::make_shared<HuffmanNode>(left->frequency + right->frequency, left, right);
        pq.push(parent);
    }

    auto root = pq.empty() ? nullptr : pq.top();

    // Шаг 3: Побитовое чтение и декодирование
    std::ofstream outFile(outputFilename, std::ios::binary);
    if (!outFile.is_open()) {
        throw std::runtime_error("Ошибка создания файла для распаковки: " + outputFilename);
    }

    BitReader bitReader(inFile);
    std::shared_ptr<HuffmanNode> currentNode = root;
    uint64_t bitsRead = 0;

    while (bitsRead < totalBits) {
        int bit = bitReader.readBit();
        if (bit == -1) {
            break; // Неожиданный конец потока
        }
        bitsRead++;

        // Спускаемся по дереву в соответствии с битом (0 — влево, 1 — вправо)
        if (bit == 0) {
            currentNode = currentNode->left;
        } else {
            currentNode = currentNode->right;
        }

        if (!currentNode) {
            throw std::runtime_error("Ошибка декодирования: поврежден битовый поток.");
        }

        // Если достигли листа, записываем символ и возвращаемся в корень
        if (!currentNode->left && !currentNode->right) {
            outFile.put(currentNode->character);
            currentNode = root;
        }
    }

    std::cout << "Файл успешно распакован." << std::endl;
}

            std::cout << "  Сжатие:   " << argv[0] << " -c <input_file> <output_file>" << std::endl;
            std::cout << "  Распаковка: " << argv[0] << " -d <input_file> <output_file>" << std::endl;
            return 1;
        }

        std::string mode = argv[1];
        std::string inputFile = argv[2];
        std::string outputFile = argv[3];

        if (mode == "-c") {
            std::cout << "Запуск сжатия файла \"" << inputFile << "\"..." << std::endl;
            compressFile(inputFile, outputFile);
        } else if (mode == "-d") {
            std::cout << "Запуск распаковки архива \"" << inputFile << "\"..." << std::endl;
            decompressFile(inputFile, outputFile);
        } else {
            std::cerr << "Ошибка: неизвестный режим \"" << mode << "\". Используйте -c или -d." << std::endl;
            return 1;
        }

    } catch (const std::exception& e) {
        std::cerr << "Критическая ошибка: " << e.what() << std::endl;
        return 1;
    }

    return 0;
```

   - Выполним распаковку архива в новый файл:
     ```bash
     ./huffman -d compressed.huff restored.txt
     ```
   - Проверим идентичность исходного и восстановленного файлов (в Linux/macOS):
     ```bash
     diff source.txt restored.txt
     ```
     *(Если утилита `diff` не вывела никакого текста, значит, файлы абсолютно идентичны, сжатие и декомпрессия прошли без единой ошибки).*

### Анализ сложности реализации

- **Временная сложность сжатия:** 
  1. Подсчет частот: $O(M)$, где $M$ — размер файла в байтах.
  2. Построение дерева Хаффмана: $O(K \log K)$, где $K$ — количество уникальных символов ($K \le 256$).
  3. Кодирование и запись: $O(M)$.
  Суммарная временная сложность составляет $O(M + K \log K)$, что на практике работает чрезвычайно быстро (файлы размером в несколько мегабайт сжимаются за доли секунды).
- **Пространственная сложность:** 
  Память расходуется на хранение таблицы частот ($O(K)$), дерева Хаффмана ($O(K)$ узлов в динамической памяти) и буферов ввода-вывода ($O(1)$). Суммарная пространственная сложность равна $O(K)$, что гарантирует минимальное потребление оперативной памяти независимо от размера сжимаемого файла.

## Типичные ошибки

1. **Использование максимальной кучи (`std::priority_queue` по умолчанию) вместо минимальной.**
   - *Почему возникает:* По умолчанию `std::priority_queue` в C++ является max-heap. Если не перегрузить компаратор или не передать `std::greater`, алгоритм начнет объединять самые частые узлы вместо редких.
   - *Как избежать:* Всегда явно указывать компаратор `CompareNodes` с инвертированным знаком `>=` или использовать `std::greater<std::shared_ptr<HuffmanNode>>` с предварительной перегрузкой оператора `<`.

2. **Забытый вызов `flush()` у класса `BitWriter` в конце записи.**
   - *Почему возникает:* Последний неполный байт остается в памяти буфера-аккумулятора и не записывается в файловый поток `std::ofstream`.
   - *Как избежать:* Всегда вызывать метод `flush()` или деструктор, который принудительно сбрасывает остатки байта с добавлением нулей (padding).

3. **Некорректная обработка файла, состоящего из одного уникального символа.**
   - *Почему возникает:* Если в файле повторяется только один символ (например, `AAAAAA`), в очереди с приоритетом находится всего один узел. Попытка извлечь второй элемент приводит к неопределенному поведению (Segmentation Fault).
   - *Как избежать:* Добавить проверку `if (pq.size() == 1)` и искусственно создать фиктивный корневой узел или обрабатывать этот граничный случай отдельно.

4. **Отсутствие сохранения общего количества бит (`totalBits`) в заголовке файла.**
   - *Почему возникает:* Из-за выравнивания последнего байта нулями (padding) при декомпрессии алгоритм считывает из файла лишние биты, что приводит к появлению «мусора» в конце распакованного файла.
   - *Как избежать:* Всегда сохранять точное количество полезных бит `uint64_t` в начале файла и останавливать `BitReader` ровно по достижении этого счетчика.

5. **Утечки динамической памяти при ручном управлении указателями.**
   - *Почему возникает:* Создание узлов через `new` без написания рекурсивного деструктора или использования умных указателей (`std::shared_ptr` / `std::unique_ptr`).
   - *Как избежать:* Использовать современные умные указатели C++ или явно реализовывать рекурсивный обход и удаление узлов в деструкторе структуры `HuffmanNode`.

6. **Ошибки при открытии файлов в текстовом режиме вместо бинарного (`std::ios::binary`).**
   - *Почему возникает:* В операционной системе Windows символы перевода строки (`\n`) автоматически преобразуются в пару символов (`\r\n`), что полностью разрушает статистику частот и побитовую целостность файлов.
   - *Как избежать:* Всегда открывать потоки `std::ifstream` и `std::ofstream` с флагом `std::ios::binary`.

7. **Несоответствие типов данных при сериализации заголовка.**
   - *Почему возникает:* Запись переменных платформо-зависимого размера (например, `int`, который на разных архитектурах может занимать 2 или 4 байта).
   - *Как избежать:* Использовать фиксированные типы из библиотеки `<cstdint>` (`uint32_t`, `uint64_t`).

## Задачи для самостоятельного решения

1. **Задача 1 (Анализ частот):** Дан текст длиной 40 символов, в котором символ `'X'` встречается 12 раз, `'Y'` — 8 раз, `'Z'` — 10 раз, а пробел `' '` — 10 раз. Постройте частотную таблицу и определите начальное состояние очереди с приоритетом (перечислите узлы и их частоты в порядке возрастания).
2. **Задача 2 (Построение дерева):** Используя частотную таблицу из задачи 1 (`X:12`, `Y:8`, `Z:10`, ` ':10`), пошагово выполните алгоритм объединения узлов и нарисуйте схему полученного дерева Хаффмана в виде текстового дерева.
3. **Задача 3 (Генерация кодов):** На основе дерева, построенного в задаче 2, выпишите префиксные коды Хаффмана для каждого из четырех символов (`X`, `Y`, `Z`, `' '`). Вычислите среднюю длину кода $L_{cp}$ для этого алфавита.
4. **Задача 4 (Расчет эффективности):** Исходный текстовый файл имеет размер $1000$ байт. Известно, что энтропия источника составляет $3{,}2$ бита на символ. Рассчитайте теоретический предел минимального размера сжатого файла в байтах и определите коэффициент сжатия, если несжатый файл занимал ровно $8000$ бит.
5. **Задача 5 (Битовый буфер):** Имеется последовательность битов `0110110111001001`. Запишите ее побитово слева направо в байтовый буфер (с размером байта 8 бит). Укажите шестнадцатеричные значения (`0x...`) полученных байтов файла и количество бит заполнения (padding).
6. **Задача 6 (Обратное декодирование):** Задан корень дерева Хаффмана, где левое поддерево по коду `'0'` ведет к листу `'A'`, а правое поддерево по коду `'1'` разветвляется на левое `'0'` (`'B'`) и правое `'1'` (`'C'`). Расшифруйте битовую последовательность `10110010` до исходных символов.
7. **Задача 7 (Граничный случай):** Файл состоит из $500$ одинаковых символов `'K'`. Какой код Хаффмана будет присвоен этому символу в нашей программе и сколько байт займет итоговый сжатый файл с учетом заголовка (при использовании `uint32_t` для счетчика символов и `uint64_t` для общего числа бит)?
8. **Задача 8 (Программирование — модификация):** Модифицируйте функцию `printHuffmanCodes` из конспекта так, чтобы она дополнительно вычисляла и выводила в консоль процентное сокращение длины для каждого символа по сравнению с фиксированным кодом ASCII (8 бит).

## Ответы к задачам

1. **Ответ к задаче 1:** Очередь с приоритетом (min-heap): 1) `( 'Y', freq = 8 )`, 2) `( ' ', freq = 10 )`, 3) `( 'Z', freq = 10 )`, 4) `( 'X', freq = 12 )`.
2. **Ответ к задаче 2:** Корневой узел имеет частоту 40. Левый потомок — узел $N_1(18)$ с дочерними `'Y'` (8) и `' '` (10); правый потомок — узел $N_2(22)$ с дочерними `'Z'` (10) и `'X'` (12).
3. **Ответ к задаче 3:** Коды Хаффмана: `'Y'` = `00` (2 бита), `' '` = `01` (2 бита), `'Z'` = `10` (2 бита), `'X'` = `11` (2 бита). Средняя длина кода $L_{cp} = 2{,}0$ бита на символ.
4. **Ответ к задаче 4:** Теоретический минимум размера сжатого файла составляет $\lceil 3200 / 8 \rceil = 400$ байт. Коэффициент сжатия по сравнению с исходными 1000 байтами равен $2{,}5$ раза (или 40% от исходного объема).
5. **Ответ к задаче 5:** Шестнадцатеричные значения байтов: `0x6D`, `0xC9`. Количество бит заполнения (padding) равно `0` бит.
6. **Ответ к задаче 6:** Расшифрованная битовая последовательность `10110010` соответствует слову `BCAAB`.
7. **Ответ к задаче 7:** Символу `'K'` присваивается код `"0"` длиной 1 бит. Итоговый размер сжатого файла с учетом заголовка составляет $80$ байт.
8. **Ответ к задаче 8:** Процентное сокращение длины вычисляется по формуле $\left(1 - \frac{\text{length(code)}}{8}\right) \cdot 100\%$, которая встраивается в цикл обхода дерева и вывода кодов.

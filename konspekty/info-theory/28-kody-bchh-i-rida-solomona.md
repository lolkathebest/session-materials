## 1. Алгебраические предпосылки и мотивация построения кодов БЧХ

### Ограничения простых блочных и циклических кодов

Ранее в курсе мы познакомились с линейными блочными кодами (включая код Хэмминга) и простейшими циклическими кодами. Напомним, что линейный код задается матрично, а циклический — с помощью порождающего многочлена $g(x)$, деление на который гарантирует, что любое кодовое слово представляется в виде полинома, кратного $g(x)$.

Однако классические линейные коды и код Хэмминга имеют жесткие ограничения:
1. Код Хэмминга является кодом, исправляющим *ровно одну* ошибку ($t = 1$). Его минимальное расстояние Хэмминга равно $d_{\min} = 3$. Если в блоке происходит две или более независимые ошибки, декодер кода Хэмминга либо не сможет их обнаружить, либо ложно исправит в другую сторону, увеличивая итоговое число искажений.
2. Простые циклические коды, построенные на основе произвольных делителей двучлена $x^n - 1$ над полем $\text{GF}(2)$, не предоставляют систематического и гибкого инструмента для проектирования кодов с заранее заданным большим числом исправляемых ошибок $t$. Подбор делителя, обеспечивающего $d_{\min} \ge 2t + 1$, для больших длин блоков $n$ превращается в переборную задачу без ясных алгебраических ориентиров.
3. В реальных каналах связи ошибки часто носят не независимый, а пакетный характер (пакет ошибок — это последовательность символов, в которой первая и последняя ошибки разделены некоторым числом правильно принятых символов, а длина пакета — это расстояние от первой ошибки до последней включительно). Простые двоичные коды неэффективны против длинных пакетов ошибок без использования перемежения.

Возникает фундаментальная задача: построить класс систематических циклических кодов, которые позволяют легко масштабировать кратность исправляемых ошибок $t$ и гарантируют строго заданное минимальное расстояние. Эту задачу решают коды БЧХ.

### Определение кодов БЧХ

> **Определение.** Класс кодов **Боуза — Чоудхури — Хоквингема (БЧХ)** представляет собой семейство мощных циклических кодов с исправлением множественных ошибок, которые определяются через корни их порождающего многочлена в расширенном поле Галуа. Двоичный код БЧХ длины $n = 2^m - 1$ с проектной способностью исправления $t$ ошибок строится таким образом, что его порождающий многочлен $g(x)$ имеет в качестве корней $2t$ последовательных степеней примитивного элемента расширенного поля Галуа $\text{GF}(2^m)$.

Раскроем это определение детально. Пусть задано базовое поле $\text{GF}(2)$, состоящее из элементов $\{0, 1\}$. Для построения кода БЧХ мы переходим к расширенному полю Галуа $\text{GF}(2^m)$, где $m \ge 3$ — целое число. 

В поле $\text{GF}(2^m)$ существует ненулевой элемент $\alpha$, называемый *примитивным элементом*, степени которого порождают все $2^m - 1 ненулевых элементов этого поля. Иными словами, мультипликативная группа поля $\text{GF}(2^m)^*\,$ циклична и имеет порядок $n = 2^m - 1$. Элемент $\alpha$ удовлетворяет некоторому неприводимому примитивному многочлену степени $m$ с коэффициентами из $\text{GF}(2)$.

Циклический код длины $n$ задается в кольце полиномов делением на порождающий многочлен $g(x)$, который делит двучлен $x^n - 1$. В кодах БЧХ требование к $g(x)$ формулируется не через коэффициенты в $\text{GF}(2)$, а через требования к его корням в поле $\text{GF}(2^m)$.

---

### Корни порождающего многочлена и расширенное поле Галуа

Пусть $\alpha$ — примитивный элемент поля $\text{GF}(2^m)$. Многочлен $g(x)$ с коэффициентами из $\text{GF}(2)$ является порождающим для циклитического кода БЧХ, если он имеет в качестве своих корней следующие элементы:

$$\alpha, \alpha^2, \alpha^3, \dots, \alpha^{2t}$$

где $t$ — проектное число исправляемых ошибок. Поскольку коэффициенты многочлена $g(x)$ принадлежат базовому полю $\text{GF}(2)$, корни такого многочлена обязаны появляться сопряженными парами (точнее, вместе с каждым корнем $\beta$ его корнями являются все элементы вида $\beta^{2^j}$, образующие циклотомический класс). 

Минимальным многочленом $M_i(x)$ элемента $\beta \in \text{GF}(2^m)$ называется наименьший по степени многочлен с коэффициентами из $\text{GF}(2)$, для которого $\beta$ является корнем ($M_i(\beta) = 0$).

Тогда порождающий многочлен $g(x)$ кода БЧХ определяется как наименьшее общее кратное (НОК) минимальных многочленов требуемых степеней примитивного элемента:

$$g(x) = \text{НОК} \left( M_1(x), M_2(x), \dots, M_{2t}(x) \right)$$

Поскольку степень каждого минимального многочлена делит $m$, степень итогового порождающего многочлена $r = \deg g(x)$ определяет количество проверочных символов кода: $r \le m \cdot t$. Размерность кода (количество информационных символов) равна $k = n - r$.

---

### Граница Боуза — Чоудхури — Хоквингема для минимального расстояния

Связь между структурой корней порождающего многочлена и корректирующей способностью кода устанавливается фундаментальной теоремой, известной как граница БЧХ.

> **Теорема (Граница БЧХ).** Если порождающий многочлен $g(x)$ циклического кода длины $n$ имеет в качестве корней в поле $\text{GF}(2^m)$ по меньшей мере $2t$ последовательных степеней примитивного элемента $\alpha$:
> 
> $$\alpha^b, \alpha^{b+1}, \alpha^{b+2}, \dots, \alpha^{b+2t-1}$$
> 
> для некоторого целого $b$ (обычно $b = 1$), то минимальное расстояние Хэмминга $d_{\min}$ этого кода удовлетворяет неравенству:
> 
> $$d_{\min} \ge 2t + 1$$

#### Обоснование (по шагам):
1. Предположим обратное: пусть существует ненулевое кодовое слово $c(x)$ веса $w$, меньшего или равного $2t$ ($w \le 2t$). Это означает, что полином $c(x)$ имеет ровно $w$ ненулевых коэффициентов (то есть в кодовом слове ровно $w$ единиц в позициях с номерами $i_1, i_2, \dots, i_w$).
2. Кодовое слово делится на порождающий многочлен $g(x)$ без остатка. Следовательно, каждый корень многочлена $g(x)$ является также корнем многочлена $c(x)$.
3. В частности, все $2t$ последовательных степеней $\alpha^b, \alpha^{b+1}, \dots, \alpha^{b+2t-1}$ обращают полином $c(x)$ в нуль:
   
   $$c(\alpha^{b+j}) = 0 \quad \text{для} \quad j = 0, 1, \dots, 2t-1$$

4. Запишем значение полинома в точке $\alpha^{b+j}$:
   
   $$c(\alpha^{b+j}) = \sum_{l=1}^{w} x_{i_l} (\alpha^{b+j})^{i_l} = 0$$

5. Полученную систему можно записать в матричном виде как произведение матрицы Вандермонда, составленной из степеней элемента $\alpha$, на вектор ненулевых символов кодового слова. Определитель такой подматрицы Вандермонда размером $w \times w$ отличен от нуля, поскольку все степени $\alpha$ различны, а поле $\text{GF}(2^m)$ не содержит делителей нуля.
6. Ненулевой определитель матрицы Вандермонда означает, что система имеет только тривиальное решение (все коэффициенты равны нулю), что противоречит предположению о том, что $c(x)$ — ненулевое кодовое слово веса $w \le 2t$.
7. Следовательно, минимальное весовое кодовое слово не может иметь вес меньше $2t + 1$. Минимальное расстояние Хэмминга $d_{\min} \ge 2t + 1$. Что и требовалось доказать.

Исходя из полученного минимального расстояния, код гарантированно исправляет любые комбинации из $t$ и менее ошибок, поскольку:

$$t = \left\lfloor \frac{d_{\min} - 1}{2} \right\rfloor \ge \left\lfloor \frac{2t + 1 - 1}{2} \right\rfloor = t$$

### Двоичные коды БЧХ и недвоичные коды БЧХ (коды Рида–Соломона)

Класс кодов БЧХ делится на две большие ветви в зависимости от того, над каким полем определены символы кодового слова:

1. **Двоичные коды БЧХ:**
   - Алфавит кодовых слов состоит из двоичных символов: $\{0, 1\}$.
   - Длина блока составляет $n = 2^m - 1$.
   - Порождающий многочлен имеет коэффициенты из $\text{GF}(2)$, но его корни лежат в расширенном поле $\text{GF}(2^m)$.
   - Они применяются там, где канал передачи является битовым (например, каналы с гауссовским шумом).

2. **Недвоичные коды БЧХ (коды Рида–Соломона):**
   - Это важнейший частный случай кодов БЧХ, возникающий при $m$-битном объединении символов. В этом случае каждый символ кодового слова является не отдельным битом, а целым элементом поля Галуа $\text{GF}(2^m)$ (например, байтом при $m = 8$).
   - Длина блока в символах равна $n = 2^m - 1$.
   - Коды Рида–Соломона достигают предельно возможного значения минимального расстояния для линейных кодов (граница Синглтона): $d_{\min} = n - k + 1$, где $k$ — число информационных символов.
   - Они идеально подходят для исправления пакетных ошибок, поскольку одна ошибка в символе поля $\text{GF}(2^m)$ может испортить сразу до $m$ подряд идущих бит в двоичном потоке, но для декодера РС это считается всего лишь *одной* символьной ошибкой.

Сравним их основные параметры в сводной таблице:

| Характеристика | Двоичные коды БЧХ | Коды Рида–Соломона (недвоичные БЧХ) |
|---|---|---|
| **Базовый алфавит символов** | Двоичный ($\text{GF}(2)$) | Расширенное поле ($\text{GF}(2^m)$) |
| **Длина блока ($n$)** | $2^m - 1$ бит | $2^m - 1$ символов |
| **Число проверочных символов ($n - k$)** | $\le m \cdot t$ бит | exatamente $2t$ символов |
| **Минимальное расстояние ($d_{\min}$)** | $\ge 2t + 1$ | Точно $2t + 1$ (граница Синглтона) |
| **Основное назначение** | Исправление независимых битовых ошибок | Исправление пакетных ошибок и стираний |

### Разобранный пример

**Условие:**
Задано поле Галуа $\text{GF}(2^4)$ с примитивным элементом $\alpha$, который удовлетворяет неприводимому примитивному полиному:

$$x^4 + x + 1 = 0$$

Требуется:
1. Записать таблицу степеней примитивного элемента $\alpha$ для поля $\text{GF}(2^4)$.
2. Обосновать выбор консекутивных степеней корней для построения двоичного кода БЧХ, исправляющего $t = 2$ ошибки при проектной длине блока $n = 15$.
3. Определить требуемые корни порождающего многочлена и выписать их минимальные многочлены.

#### Решение в общем виде и по шагам:

**Шаг 1. Построение таблицы степеней поля $\text{GF}(2^4)$.**
Элементы поля $\text{GF}(2^4)$ представимы в виде полиномов степени не выше 3 с коэффициентами из $\text{GF}(2)$:

$$c_3 \alpha^3 + c_2 \alpha^2 + c_1 \alpha + c_0$$

Используя соотношение $\alpha^4 + \alpha + 1 = 0$, выразим высшую степень:

$$\alpha^4 = \alpha + 1$$

Последовательно умножая каждую степень на $\alpha$ и заменяя $\alpha^4$ на $\alpha + 1$ (с учетом сложения по модулю 2, где $1 + 1 = 0$), получим таблицу степеней:

- $\alpha^0 = 1 = 0001_2$
- $\alpha^1 = \alpha = 0010_2$
- $\alpha^2 = \alpha^2 = 0100_2$
- $\alpha^3 = \alpha^3 = 1000_2$
- $\alpha^4 = \alpha + 1 = 0011_2$
- $\alpha^5 = \alpha(\alpha + 1) = \alpha^2 + \alpha = 0110_2$
- $\alpha^6 = \alpha(\alpha^2 + \alpha) = \alpha^3 + \alpha^2 = 1100_2$
- $\alpha^7 = \alpha(\alpha^3 + \alpha^2) = \alpha^4 + \alpha^3 = (\alpha + 1) + \alpha^3 = \alpha^3 + \alpha + 1 = 1011_2$
- $\alpha^8 = \alpha(\alpha^3 + \alpha + 1) = \alpha^4 + \alpha^2 + \alpha = (\alpha + 1) + \alpha^2 + \alpha = \alpha^2 + 1 = 0101_2$
- $\alpha^9 = \alpha(\alpha^2 + 1) = \alpha^3 + \alpha = 1010_2$
- $\alpha^{10} = \alpha(\alpha^3 + \alpha) = \alpha^4 + \alpha^2 = (\alpha + 1) + \alpha^2 = \alpha^2 + \alpha + 1 = 0111_2$
- $\alpha^{11} = \alpha(\alpha^2 + \alpha + 1) = \alpha^3 + \alpha^2 + \alpha = 1110_2$
- $\alpha^{12} = \alpha(\alpha^3 + \alpha^2 + \alpha) = \alpha^4 + \alpha^3 + \alpha^2 = (\alpha + 1) + \alpha^3 + \alpha^2 = \alpha^3 + \alpha^2 + \alpha + 1 = 1111_2$
- $\alpha^{13} = \alpha(\alpha^3 + \alpha^2 + \alpha + 1) = \alpha^4 + \alpha^3 + \alpha^2 + \alpha = (\alpha + 1) + \alpha^3 + \alpha^2 + \alpha = \alpha^3 + 1 = 1001_2$
- $\alpha^{14} = \alpha(\alpha^3 + 1) = \alpha^4 + \alpha = (\alpha + 1) + \alpha = 1 = 0001_2$
- $\alpha^{15} = \alpha^1 = \alpha$ (цикл замыкается).

**Шаг 2. Обоснование выбора консекутивных степеней корней.**
По условию требуется построить двоичный код БЧХ, исправляющий $t = 2$ ошибки при длине блока $n = 2^4 - 1 = 15$.
Согласно границе БЧХ, для гарантированного исправления $t$ ошибок порождающий многочлен должен содержать $2t$ последовательных степеней примитивного элемента $\alpha$ в качестве своих корней. 
Подставляем $t = 2$:

$$2t = 2 \cdot 2 = 4$$

Следовательно, порождающий многочлен $g(x)$ обязан иметь следующие $4$ последовательных корня:

$$\alpha^1, \alpha^2, \alpha^3, \alpha^4$$

**Шаг 3. Определение минимальных многочленов корней.**
Группируем корни по их циклотомическим классам (классам сопряженности по модулю $2^j \pmod{15}$):
1. Класс элемента $\alpha^1$: $\{\alpha^1, \alpha^2, \alpha^4, \alpha^8\}$. Все эти элементы имеют один и тот же минимальный многочлен над $\text{GF}(2)$, который совпадает с исходным примитивным полиномом:
   
   $$M_1(x) = x^4 + x + 1$$

2. Класс элемента $\alpha^3$: элементы $\alpha^3$ и $\alpha^3 \cdot 2 = \alpha^6$, $\alpha^6 \cdot 2 = \alpha^{12}$, $\alpha^{12} \cdot 2 = \alpha^{24} \equiv \alpha^9 \pmod{15}$. Таким образом, класс содержит $\{\alpha^3, \alpha^6, \alpha^{12}, \alpha^9\}$. Их минимальный многочлен $M_3(x)$ имеет степень 4 и находится путем перемножения линейных множителей:
   
   $$M_3(x) = (x - \alpha^3)(x - \alpha^6)(x - \alpha^9)(x - \alpha^{12})$$
   
   Раскрывая скобки с учетом того, что сложение и вычитание в характеристике 2 эквивалентны, получаем:
   
   $$M_3(x) = x^4 + x^3 + x^2 + x + 1$$

Порождающий многочлен $g(x)$ кода БЧХ определяется как наименьшее общее кратное (что для неприводимых многочленов равно их произведению):

$$g(x) = M_1(x) \cdot M_3(x) = (x^4 + x + 1)(x^4 + x^3 + x^2 + x + 1)$$

Выполним умножение многочленов:
$$g(x) = x^8 + x^7 + x^6 + x^4 + 1$$

Степень полученного порождающего многочлена равна $\deg g(x) = 8$. Это значит, что код имеет $r = 8$ проверочных символов и число информационных символов:

$$k = n - r = 15 - 8 = 7$$

Параметры построенного двоичного кода БЧХ: длина $n = 15$, число информационных символов $k = 7$, число проверочных символов $8$, гарантированное минимальное расстояние $d_{\min} \ge 2t + 1 = 5$, кратность исправляемых ошибок $t = 2$.

#### Проверка:
- Проверим размерность: $15 - 8 = 7$, расчет корректен.
- Проверим корни: подставим $\alpha^1$ в многочлен $g(x)$: $g(\alpha) = M_1(\alpha) M_3(\alpha) = 0 \cdot M_3(\alpha) = 0$. Аналогично для $\alpha^2, \alpha^3, \alpha^4$. Все четыре требуемых корня присутствуют.
- Проверка единиц измерения: размерности и степени согласованы, вычисления выполнены в поле $\text{GF}(2^4)$ без ошибок.

**Ответ:** 
Порождающий многочлен двоичного кода БЧХ для $n=15$ и $t=2$ имеет вид $g(x) = x^8 + x^7 + x^6 + x^4 + 1$, параметры кода: $(15, 7, 5)$.

## 2. Построение и свойства порождающего многочлена кодов БЧХ

### Понятие минимального многочлена элемента расширения поля Галуа

Прежде чем перейти к конструированию порождающего многочлена кода БЧХ, необходимо строго определить алгебраический фундамент, на котором строится вся теория — понятие минимального многочлена. Напомним, что элементы кодов БЧХ и их корни лежат в расширенном поле Галуа $\text{GF}(2^m)$, элементы которого являются степенями примитивного элемента $\alpha$.

> **Определение.** Пусть $\beta$ — некоторый элемент расширенного поля Галуа $\text{GF}(2^m)$. *Минимальным многочленом* элемента $\beta$ над базовым полем $\text{GF}(2)$ называется ненулевой многочлен $M(x)$ наименьшей степени с коэффициентами из базового поля $\text{GF}(2)$, для которого $\beta$ является корнем ($M(\beta) = 0$), и коэффициент при старшей степени многочлена равен единице (моничный многочлен).

Свойства минимального многочлена, критически важные для построения кодов:
1. Минимальный многочлен неприводим в поле $\text{GF}(2)$, то есть его нельзя разложить на произведение многочленов меньшей степени с коэффициентами из $\text{GF}(2)$.
2. Если $\beta$ — корень минимального многочлена $M(x)$ в поле $\text{GF}(2^m)$, то все сопряженные элементы вида $\beta^{2^i}$ для всех целых $i \geq 0$ также являются корнями того же самого многочлена $M(x)$. Множество всех таких элементов $\{\beta, \beta^2, \beta^4, \beta^8, \dots\}$ образует *циклотомический класс* элемента $\beta$.
3. Любой многочлен с коэффициентами из $\text{GF}(2)$, имеющий $\beta$ своим корнем, обязательно делится на минимальный многочлен $M(x)$ без остатка.

Для нахождения минимальных многочленов элементов поля $\text{GF}(2^m)$ используют таблицы степеней примитивного элемента и разложения многочленов вида $x^{2^m - 1} - 1$ на неприводимые множители в поле $\text{GF}(2)$.

### Формирование порождающего многочлена $g(x)$ через минимальные многочлены

Циклический код определяется своим порождающим многочленом $g(x)$, который должен делить многочлен $x^n - 1$ в кольце полиномов над полем $\text{GF}(2)$. В кодах БЧХ порождающий многочлен конструируется специальным образом — через заданные корни в поле $\text{GF}(2^m)$, гарантирующие требуемое минимальное расстояние Хэмминга $d_{\min}$.

Пусть требуется построить двоичный код БЧХ, способный исправлять до $t$ независимых ошибок. Согласно границе Боуза–Чоудхури–Хоквингема, минимальное расстояние кода $d_{\min}$ должно быть не меньше $2t + 1$. Для обеспечения такого расстояния в качестве корней порождающего многочлена $g(x)$ выбираются $2t$ последовательных степеней примитивного элемента $\alpha$ поля $\text{GF}(2^m)$:

$$\alpha^1, \alpha^2, \alpha^3, \dots, \alpha^{2t}$$

> **Определение.** *Порождающим многочленом* $g(x)$ двоичного кода БЧХ с проектным расстоянием $d_{\min} \geq 2t + 1$ называется наименьшее общее кратное (НОК) минимальных многочленов $M_i(x)$ для выбранных последовательных степеней примитивного элемента $\alpha$:

$$g(x) = \text{НОК}\left(M_1(x), M_2(x), \dots, M_{2t}(x)\right)$$

В силу того, что каждый минимальный многочлен $M_i(x)$ для четной степени $\alpha^i$ совпадает с минимальным многочленом для сопряженного элемента (в поле характеристики 2 возведение в квадрат является автоморфизмом Фробениуса), реальное число минимальных многочленов, подлежащих перемножению, существенно меньше $2t$. Более того, поскольку коэффициенты искомого порождающего многочлена $g(x)$ должны лежать в базовом поле $\text{GF}(2)$, достаточно взять НОК минимальных многочленов только для *нечетных* степеней из набора последовательных корней или учесть циклотомические классы.

### Теорема о проектировании кода БЧХ и расчет его параметров

Проектирование кодов БЧХ опирается на фундаментальную теорему, связывающую алгебраическую структуру корней порождающего многочлена с корректирующей способностью кода.

> **Теорема (Боуза–Чоудхури–Хоквингема).** Пусть $\alpha$ — примитивный элемент поля $\text{GF}(2^m)$. Если порождающий многочлен $g(x)$ циклического кода длины $n = 2^m - 1$ имеет в качестве своих корней $2t$ консекутивных (последовательных) степеней элемента $\alpha$:
> 
> $$\alpha^b, \alpha^{b+1}, \alpha^{b+2}, \dots, \alpha^{b+2t-1}$$
> 
> для некоторого целого $b$ (обычно выбирается $b = 1$), то минимальное расстояние Хэмминга $d_{\min}$ кодового слова этого кода удовлетворяет неравенству:
> 
> $$d_{\min} \geq 2t + 1$$

Из этой теоремы следует, что код гарантированно исправляет любые комбинации из $t$ и менее ошибок в блоке длины $n$. 

Параметры разработанного кода БЧХ рассчитываются по следующим формулам:
- **Длина блока (в битах):** 
  
  $$n = 2^m - 1$$
  
  где $m \geq 3$ — целое число, определяющее размерность расширенного поля $\text{GF}(2^m)$.
- **Степень порождающего многочлена $g(x)$:** равна количеству проверочных символов (бит) в блоке:
  
  $$r = \deg g(x) = n - k$$
  
- **Число информационных символов (бит):** 
  
  $$k = n - \deg g(x)$$
  
  Точное значение $k$ зависит от степеней минимальных многочленов, входящих в НОК, и на этапе проектирования определяется вычислением степени $g(x)$.
- **Скорость кода:** 
  
  $$R = \frac{k}{n}$$

### Алгоритм кодирования в систематической форме

Подобно другим линейным циклическим кодам, кодирование сообщений в кодах БЧХ удобно выполнять в систематической форме, когда информационные биты занимают старшие позиции кодового слова, а проверочные биты формируются в младших разрядах.

Пусть информационное сообщение задано в виде полинома $I(x)$ степени не выше $k-1$:

$$I(x) = i_{k-1}x^{k-1} + i_{k-2}x^{k-2} + \dots + i_1x + i_0$$

Требуется сформировать кодовый полином $C(x)$ степени $n-1$, который делится на порождающий полином $g(x)$ без остатка ($C(x) \equiv 0 \pmod{g(x)}$).

Шаги алгоритма кодирования:
1. Умножить информационный полином $I(x)$ на $x^{n-k}$ (это сдвигает информационные символы влево, освобождая младшие $n-k$ разрядов для проверочных символов):
   
   $$x^{n-k}I(x)$$
   
2. Разделить полученный полином $x^{n-k}I(x)$ на порождающий полином $g(x)$ в столбик в поле $\text{GF}(2)$ с вычитанием по модулю 2 (что эквивалентно операции сложения по модулю 2, то есть исключающее ИЛИ):
   
   $$x^{n-k}I(x) = q(x)g(x) + R(x)$$
   
   где $q(x)$ — частное от деления, а $R(x)$ — остаток от деления, степень которого строго меньше степени $g(x)$ (то есть $\deg R(x) \le n - k - 1$).
3. Сформировать кодовый полином в систематической форме $C(x)$, вычтя (прибавив по модулю 2) остаток $R(x)$ из сдвинутого информационного полинома:
   
   $$C(x) = x^{n-k}I(x) + R(x)$$
   
   В результате старшие $k$ коэффициентов полинома $C(x)$ совпадают с исходными информационными битами, а младшие $n-k$ коэффициентов образуют проверочную группу.

### Разобранный пример: Построение порождающего многочлена кода БЧХ ($n = 7, t = 1$)

#### Условие задачи
Сконструировать порождающий многочлен двоичного примитивного кода БЧХ с длиной блока $n = 7$ в поле Галуа $\text{GF}(2^3)$, исправляющего $t = 1$ ошибку. В качестве примитивного элемента $\alpha$ используется элемент, удовлетворяющий неприводимому примитивному многочлену:

$$f(x) = x^3 + x + 1 = 0$$

#### Рисунок словами (схема полей и степеней)
Поле $\text{GF}(2^3)$ состоит из $2^3 = 8$ элементов: нулевого элемента $0$ и семи ненулевых степеней примитивного элемента $\alpha$:
- $\alpha^0 = 1$
- $\alpha^1 = \alpha$
- $\alpha^2 = \alpha^2$
- $\alpha^3 = \alpha + 1$ (так как $\alpha^3 = \alpha^3 + \alpha + 1 + \alpha + 1 \equiv \alpha + 1$ при подстановке $f(\alpha) = 0$)
- $\alpha^4 = \alpha(\alpha + 1) = \alpha^2 + \alpha$
- $\alpha^5 = \alpha(\alpha^2 + \alpha) = \alpha^3 + \alpha^2 = (\alpha + 1) + \alpha^2 = \alpha^2 + \alpha + 1$
- $\alpha^6 = \alpha(\alpha^2 + \alpha + 1) = \alpha^3 + \alpha^2 + \alpha = (\alpha + 1) + \alpha^2 + \alpha = \alpha^2 + 1$
- $\alpha^7 = \alpha(\alpha^2 + 1) = \alpha^3 + \alpha = (\alpha + 1) + \alpha = 1 = \alpha^0$

#### Ход рассуждений
1. Определим требуемое минимальное расстояние. Для исправления $t = 1$ ошибки по теореме БЧХ минимальное расстояние должно быть $d_{\min} по крайней мере \geq 2t + 1 = 2(1) + 1 = 3$.
2. Выберем последовательные степени примитивного элемента в качестве корней порождающего многочлена. Поскольку $t = 1$, нам необходим $2t = 2$ последовательных корня. Выбираем стандартный набор:
   
   $$\alpha^1, \alpha^2$$
   
3. Найдем минимальные многочлены для этих корней:
   - Для корня $\alpha^1 = \alpha$: минимальным многочленом $M_1(x)$ является сам примитивный многочлен поля:
     
     $$M_1(x) = x^3 + x + 1$$
     
   - Для корня $\alpha^2$: согласно свойству сопряженных элементов, корень $\alpha^2$ принадлежит тому же циклотомическому классу, что и $\alpha^1$ (так как $(\alpha^1)^2 = \alpha^2$). Следовательно, их минимальные многочлены совпадают:
     
     $$M_2(x) = M_1(x) = x^3 + x + 1$$
     
4. Сформируем порождающий многочлен $g(x)$ как наименьшее общее кратное минимальных многочленов:
   
   $$g(x) = \text{НОК}(M_1(x), M_2(x)) = \text{НОК}(x^3 + x + 1, x^3 + x + 1) = x^3 + x + 1$$
   

#### Решение в общем виде и вычисление
Порождающий многочлен кода равен:

$$g(x) = x^3 + x + 1$$

Рассчитаем основные параметры полученного кода БЧХ:
- Длина блока: $n = 2^3 - 1 = 7$ бит.
- Степень порождающего многочлена (количество проверочных символов): $r = \deg g(x) = 3$.
- Число информационных символов: $k = n - r = 7 - 3 = 4$ бита.
- Таким образом, мы построили классический систематический двоичный код БЧХ, совпадающий с кодом Хэмминга $(7, 4)$, который гарантированно исправляет $1$ ошибку ($t = 1$) при минимальном расстоянии $d_{\min} = 3$.

#### Проверка
1. Проверим делимость порождающего многочлена: многочлен $g(x) = x^3 + x + 1$ делит многочлен $x^7 - 1$ в поле $\text{GF}(2)$ без остатка (что является обязательным условием для порождающего многочлена циклического кода).
2. Проверка размерностей: $n = 7, k = 4, r = 3$. Соотношение $n = k + r$ ($7 = 4 + 3$) выполняется тождественно. Единицы измерения величин — биты. Расчет корректен.

*Ответ:* Порождающий многочлен кода БЧХ: $g(x) = x^3 + x + 1$; параметры кода: $n = 7$, $k = 4$, $d_{\min} = 3$, исправляет $t = 1$ ошибку.

## 3. Теория и параметры кодов Рида–Соломона

### 3. Теория и параметры кодов Рида–Соломона

Коды Рида–Соломона (сокращенно — коды РС), предложенные Ирвином Ридом и Густавом Соломоном в 1960 году, представляют собой важнейший на практике класс линейных блочных кодов, которые являются частным, но наиболее совершенным и популярным подмножеством недвоичных циклических кодов БЧХ. В то время как классические двоичные коды оперируют отдельными битами (нулями и единицами), коды Рида–Соломона оперируют многобитными символами, что делает их непревзойденными средствами борьбы с пакетными ошибками, когда в канале связи или на физическом носителе повреждается сразу серия подряд идущих бит.

#### Организация символов и связь с конечными полями Галуа

Прежде чем перейти к параметрам, строго определим природу данных, с которыми работают коды РС. 

> **Определение.** Пусть $m$ — целое положительное число, задающее размерность символа. Алфавит кодов Рида–Соломона строится на основе конечного поля Галуа $\text{GF}(2^m)$. Каждый отдельный символ кодового слова представляет собой элемент этого поля, то есть может быть записан как двоичный вектор длиной ровно $m$ бит.

В обычном двоичном кодировании мы рассматриваем сообщение как последовательность бит $u_i \in \{0, 1\}$. В кодах Рида–Соломона один символ кодового слова $c_i$ — это элемент $\text{GF}(2^m)$, который можно интерпретировать как число от $0$ до $2^m - 1$ или как полином степени не выше $m-1$ с двоичными коэффициентами. 

Пусть, например, $m = 3$. Тогда поле $\text{GF}(2^3)$ содержит $2^3 = 8$ элементов: $\{0, 1, \alpha, \alpha^2, \alpha^3, \alpha^4, \alpha^5, \alpha^6\}$, где $\alpha$ — примитивный элемент поля, удовлетворяющий неприводимому многочлену степени $3$. Каждый из этих восьми элементов поля выступает в роли неделимого «буквы» или «символа» нашего алфавита. Когда происходит физическое искажение в канале связи, с точки зрения кода РС повреждается не один бит, а целый символ (элемент поля $\text{GF}(2^3)$ целиком, будь то перевернут один бит внутри него или все три).

#### Параметры кода Рида–Соломона и граница Синглтона

Код Рида–Соломона обозначается как $\text{RS}(n, k)$, где параметры связаны жесткими алгебраическими соотношениями:

1. **Длина блока в символах:** $n = 2^m - 1$. Это максимальная длина кодового слова, выраженная в символах поля $\text{GF}(2^m)$.
2. **Число информационных символов:** $k$ — параметр, задающий пользователем (может быть выбран произвольным образом, лишь бы $k < n$).
3. **Число проверочных символов:** $n - k$.
4. **Количество исправляемых символьных ошибок:** $t = \lfloor \frac{n - k}{2} \rfloor$.

> **Определение.** Минимальным кодовым расстоянием $d_{\min}$ линейного блока называется наименьшее число позиций, в которых различаются любые два отличных друг от друга кодовых слова.

Для любых линейных блочных кодов справедливо фундаментальное ограничение, известное как **граница Синглтона**:

$$d_{\min} \le n - k + 1$$

> **Определение.** Коды, для которых граница Синглтона достигается как точное равенство, то есть выполняется соотношение
> 
> $$d_{\min} = n - k + 1$$
> 
> называются **кодами с максимальным расстоянием (Maximum Distance Separable, MDS-кодами)**.

Коды Рида–Соломона обладают уникальным свойством: они являются **MDS-кодами**. Никакой другой линейный блочный код при заданных длине $n$ и размерности $k$ не может иметь большего минимального расстояния. Это означает, что для исправления $t$ ошибок коду РС требуется минимально возможное количество проверочных символов:

$$n - k = 2t$$

Каждый добавленный проверочный символ увеличивает минимальное расстояние ровно на единицу, обеспечивая максимальную эффективность с точки зрения избыточности.

#### Преимущества при исправлении пакетных ошибок

На практике сбои в памяти компьютеров, на жестких дисках, оптических носителях или в беспроводных каналах редко происходят изолированно. Чаще всего возникают **пакетные ошибки (burst errors)**, когда сильная помеха или физический дефект (царапина на диске, замирание радиосигнала) повреждают подряд несколько бит.

Рассмотрим сравнение двоичного кода и кода Рида–Соломона при одинаковой избыточности:

* Пусть у нас есть пакетная ошибка длиной $B$ бит.
* Если применяется традиционный двоичный код, исправляющий независимые ошибки, то этот пакет из $B$ подряд идущих искаженных бит может «пробить» коррекционную способность кода, так как ошибки сконцентрированы в одной зоне.
* В коде Рида–Соломона данные упаковываются в символы по $m$ бит. Один пакетный сбой длиной $B$ бит затронет не $B$ независимых символьных ошибок, а максимум $\lceil \frac{B}{m} \rceil$ соседних символов поля $\text{GF}(2^m)$. 

Поскольку код РС проектируется на исправление $t$ произвольных *символьных* ошибок (независимо от того, сколько именно бит внутри поврежденного символа было искажено), он с легкостью справляется с огромными пакетами битовых ошибок. Если символ имеет размер $m = 8$ байт (один байт), то пакетная ошибка длиной до $8t$ бит, укладывающаяся в $t$ байтов, будет полностью исправлена, в то время как двоичный код с тем же объемом избыточности справился бы лишь с $t$ единичными битовыми ошибками, расположенными в разных частях блока.

### Разобранный пример: Расчет параметров кода Рида–Соломона $\text{RS}(255, 223)$

#### Условие задачи
Рассчитать параметры кода Рида–Соломона $\text{RS}(255, 223)$, работающего в поле $\text{GF}(2^8)$: размер алфавита символов, количество проверочных байтов, максимальную кратность исправляемых пакетных ошибок на блок и скорость кода.

#### Ход рассуждений и формулы

1. **Размер алфавита символов:**
   Код работает в поле Галуа $\text{GF}(2^m)$, где в нашем случае показатель степени равен $m = 8$. Размер алфавита (количество возможных уникальных символов) определяется как $2^m$. Каждый символ кодового слова кодируется ровно $8$ битами, что эквивалентно одному байту.

2. **Длина блока $n$:**
   По определению для кодов РС длина блока в символах равна:
   $$n = 2^m - 1$$
   Подставляя $m = 8$:
   $$n = 2^8 - 1 = 256 - 1 = 255 \text{ символов (байт)}$$

3. **Количество информационных и проверочных символов:**
   Из обозначения $\text{RS}(255, 223)$ непосредственно следует:
   * Число информационных символов: $k = 223$ байта.
   * Число проверочных символов (байт избыточности):
     $$n - k = 255 - 223 = 32 \text{ байта}$$

4. **Минимальное кодовое расстояние $d_{\min}$:**
   Поскольку коды Рида–Соломона достигают границы Синглтона, минимальное расстояние вычисляется по формуле:
   $$d_{\min} = n - k + 1$$

5. **Максимальная кратность исправляемых ошибок $t$:**
   Код РС способен гарантированно исправить любое сочетание $t$ ошибочных символов в блоке, где:
   $$t = \lfloor \frac{d_{\min} - 1}{2} \rfloor = \lfloor \frac{n - k}{2} \rfloor$$

6. **Скорость кода $R$:**
   Скорость кода характеризует долю полезной информации в общем объеме передаваемых данных и вычисляется как:
   $$R = \frac{k}{n}$$

---

#### Решение в общем виде и подстановка

1. **Размер алфавита символов:**
   $$2^8 = 256 \text{ значений (алфавит из 256 символов, каждый длиной 8 бит / 1 байт)}$$

2. **Количество проверочных байтов:**
   $$255 - 223 = 32 \text{ проверочных символа}$$

3. **Минимальное расстояние:**
   $$d_{\min} = 255 - 223 + 1 = 33$$

4. **Кратность исправляемых символьных ошибок $t$:**
   $$t = \lfloor \frac{32}{2} \rfloor = 16 \text{ символов}$$
   Поскольку каждый символ равен одному байту ($8$ бит), код $\text{RS}(255, 223)$ может исправить до $16$ полностью поврежденных байтов в произвольных местах блока длиной $255$ байтов. В терминах пакетных ошибок это означает способность исправлять сплошной пакет ошибок длиной до $16 \times 8 = 128$ подряд идущих бит, если этот пакет укладывается в рамки повреждения не более чем $16$ байт.

5. **Скорость кода:**
   $$R = \frac{223}{255} \approx 0{,}8745$$

---

#### Проверка и анализ правдоподобия

* **Проверка единиц и размерностей:** $n, k, (n-k)$ измеряются в символах (байтах). $t$ измеряется в символах. Скорость $R$ безразмерна и лежит в интервале $(0, 1)$, что верно ($0{,}8745 < 1$).
* **Правдоподобие результата:** Стандарт $\text{RS}(255, 223)$ широко применяется в реальных инженерных системах (например, в спутниковую связь стандарта CCSDS и на оптических дисках CD). Добавление $32$ байт избыточности к блоку из $223$ информационных байтов дает эффективную защиту от случайных и пакетных сбоев при небольшой относительной избыточности (около $12{,}5\%$ проверочных данных). Расчеты выполнены без ошибок.

Ответ: Алфавит состоит из $256$ элементов (символ равен $1$ байту); количество проверочных байтов равно $32$; максимальная кратность исправляемых символьных ошибок составляет $t = 16$ байт; скорость кода равна $\frac{223}{255} \approx 0{,}8745$.

## 4. Процедура декодирования и исправления ошибок в кодах БЧХ и Рида–Соломона

### 4. Процедура декодирования и исправления ошибок в кодах БЧХ и Рида–Соломона

Процесс декодирования линейных циклических кодов БЧХ и Рида–Соломона кардинально отличается от простого табличного декодирования или синдромного поиска в линейных блочных кодах с фиксированной матрицей проверок. Из-за большой длины блоков ($n = 2^m - 1$) и работы в расширенных конечных полях Галуа $\text{GF}(2^m)$ полный перебор или хранение таблицы синдромов объемом $2^{n-k}$ физически невозможны. 

Поэтому декодирование кодов БЧХ и Рида–Соломона строится на строгом алгебраическом подходе. Он позволяет не просто обнаружить факт искажения данных, но и точно определить номера позиций, в которых произошли сбои (ошибки), а для недвоичных кодов Рида–Соломона — еще и вычислить точные значения амплитуд этих ошибок.

> **Определение.** Алгебраическое декодирование кодов БЧХ и Рида–Соломона — это процедура восстановления исходного кодового слова $c(x)$ по принятому вектору $r(x) = c(x) + e(x)$, реализуемая в четыре последовательных этапа: вычисление вектора синдромов, нахождение многочлена локаторов ошибок, определение позиций (локализаций) ошибок и вычисление их значений (амплитуд).

Пусть при передаче кодового слова $c(x) = c_0 + c_1 x + c_2 x^2 + \dots + c_{n-1} x^{n-1}$ в канале связи произошло $v$ ошибок ($v \le t$, где $t$ — гарантированная кратность исправляемых ошибок). Принятый полином имеет вид:

$$r(x) = c(x) + e(x)$$

где $e(x) = e_{i_1} x^{i_1} + e_{i_2} x^{i_2} + \dots + e_{i_v} x^{i_v}$ — полином ошибок, а $i_1, i_2, \dots, i_v$ — индексы позиций, в которых символы были искажены ($0 \le i_j \le n - 1$). Для двоичных кодов БЧХ значение ошибки в позиции равно $1$, в то время как для кодов Рида–Соломона значения $e_{i_j}$ являются произвольными ненулевыми элементами поля $\text{GF}(2^m)$.

---

### Шаг 1: Вычисление синдромов принятого многочлена

Первым этапом декодирования является проверка того, является ли принятый вектор допустимым кодовым словом. Поскольку порождающий многочлен $g(x)$ кода БЧХ или Рида–Соломона имеет своими корнями последовательные степени примитивного элемента $\alpha, \alpha^2, \dots, \alpha^{2t}$, любое корректное кодовое слово $c(x)$, будучи делящимся на $g(x)$, обязано обращаться в ноль при подстановке этих корней.

Если же в канал связи были внесены ошибки, то подстановка степеней $\alpha$ в принятый полином $r(x)$ даст ненулевые значения, которые называются синдромами:

$$S_j = r(\alpha^j) \quad \text{для} \quad j = 1, 2, \dots, 2t$$

Поскольку $r(x) = c(x) + e(x)$, а $c(\alpha^j) = 0$, каждый синдром зависит исключительно от полинома ошибок:

$$S_j = c(\alpha^j) + e(\alpha^j) = 0 + e(\alpha^j) = e(\alpha^j)$$

Раскроем это выражение через конкретные позиции ошибок $i_1, i_2, \dots, i_v$ и их амплитуды $Y_l = e_{i_l}$ (для двоичных кодов БЧХ все амплитуды $Y_l = 1$):

$$S_j = \sum_{l=1}^v Y_l (\alpha^{i_l})^j = \sum_{l=1}^v Y_l X_l^j$$

где величины $X_l = \alpha^{i_l}$ называются **локаторами ошибок** (error locators). Они полностью определяют номера позиций, в которых произошли сбои.

Запишем систему уравнений для вычисления синдромов в развернутом виде:

$$
\begin{cases}
S_1 = Y_1 X_1 + Y_2 X_2 + \dots + Y_v X_v \\
S_2 = Y_1 X_1^2 + Y_2 X_2^2 + \dots + Y_v X_v^2 \\
\dots \dots \dots \dots \dots \dots \dots \dots \dots \dots \\
S_{2t} = Y_1 X_1^{2t} + Y_2 X_2^{2t} + \dots + Y_v X_v^{2t}
\end{cases}
$$

Если все синдромы $S_1 = S_2 = \dots = S_{2t} = 0$, это означает, что ошибки отсутствуют ($v = 0$), и принятый вектор $r(x)$ принимается в качестве истинного сообщения. Если хотя бы один синдром отличен от нуля, процесс декодирования продолжается.

---

### Шаг 2: Алгоритм Берлекэмпа–Месси для нахождения многочлена локаторов ошибок

Система уравнений для синдромов является нелинейной относительно неизвестных локаторов $X_l$ и амплитуд $Y_l$. Прямое ее решение при больших значениях $t$ крайне трудоемко. Для преодоления этой трудности используют вспомогательный объект — **многочлен локаторов ошибок** $\sigma(x)$, который определяется следующим образом:

$$\sigma(x) = \prod_{l=1}^v (1 - X_l x) = 1 + \sigma_1 x + \sigma_2 x^2 + \dots + \sigma_v x^v$$

Корнями обратного многочлена к $\sigma(x)$ являются величины, обратные локаторам ошибок. Связь между коэффициентами многочлена локаторов ошибок $\sigma_k$ и вычисленными синдромами $S_j$ устанавливается с помощью тождеств Ньютона. В развернутом виде эта связь выражается через систему линейных рекуррентных соотношений:

$$S_{k} + \sigma_1 S_{k-1} + \sigma_2 S_{k-2} + \dots + \sigma_v S_{k-v} = 0 \quad \text{для} \quad k = v+1, v+2, \dots, 2t$$

На практике число ошибок $v$ заранее неизвестно (известно лишь ограничение $v \le t$). Универсальным методом нахождения коэффициентов $\sigma_1, \sigma_2, \dots, \sigma_v$ по вектору синдромов является **алгоритм Берлекэмпа–Месси**. Этот итеративный алгоритм позволяет за $2t$ шагов найти минимальный многочлен локаторов ошибок $\sigma(x)$, одновременно определяя реальное число ошибок $v$.

> **Пример применения:**
> Для кода Рида–Соломона $\text{RS}(7, 3)$ в поле $\text{GF}(2^3)$ получены ненулевые синдромы $S_1 = \alpha^3$, $S_2 = \alpha^6$, $S_3 = \alpha^2$, $S_4 = \alpha^5$. Требуется записать систему уравнений для локализации позиций ошибок.
> 
> *Ход рассуждений:* Параметр кода $n = 7$, число измерений в поле $m = 3$, размерность $k = 3$, минимальное расстояние $d_{\min} = n - k + 1 = 7 - 3 + 1 = 5$. Число проверочных символов $2t = n - k = 4$, откуда максимальная кратность исправляемых ошибок $t = 2$. Имея $4$ синдрома ($S_1, S_2, S_3, S_4$), мы можем исправить до $2$ ошибок ($v \le 2$).
> 
> Запишем рекуррентные соотношения для поиска коэффициентов многочлена локаторов ошибок. Предположим максимальное число ошибок $v = 2$. Многочлен локаторов имеет вид:
> 
> $$\sigma(x) = 1 + \sigma_1 x + \sigma_2 x^2$$
> 
> Используя уравнения Ньютона для индексов $k = 3$ и $k = 4$, получаем систему двух линейных уравнений с двумя неизвестными $\sigma_1$ и $\sigma_2$ в поле $\text{GF}(2^3)$:
> 
> $$
> \begin{cases}
> S_3 + \sigma_1 S_2 + \sigma_2 S_1 = 0 \\
> S_4 + \sigma_1 S_3 + \sigma_2 S_2 = 0
> \end{cases}
> $$
> 
> Подставим числовые значения синдромов $S_1 = \alpha^3$, $S_2 = \alpha^6$, $S_3 = \alpha^2$, $S_4 = \alpha^5$:
> 
> $$
> \begin{cases}
> \alpha^2 + \sigma_1 \alpha^6 + \sigma_2 \alpha^3 = 0 \\
> \alpha^5 + \sigma_1 \alpha^2 + \sigma_2 \alpha^6 = 0
> \end{cases}
> $$
> 
> Данная система в поле Галуа $\text{GF}(2^3)$ решается методом подстановки или исключения Гаусса, после чего находится многочлен $\sigma(x)$.
> 
> *Ответ:* Система уравнений для локализации позиций ошибок для заданных синдромов имеет вид:
> 
> $$
> \begin{cases}
> \alpha^2 + \sigma_1 \alpha^6 + \sigma_2 \alpha^3 = 0 \\
> \alpha^5 + \sigma_1 \alpha^2 + \sigma_2 \alpha^6 = 0
> \end{cases}
> $$

---

### Шаг 3: Определение позиций искаженных символов (Алгоритм Ченя)

После того как многочлен локаторов ошибок $\sigma(x) = 1 + \sigma_1 x + \sigma_2 x^2 + \dots + \sigma_v x^v$ найден, необходимо найти его корни. Обратные величины к корням многочлена $\sigma(x)$ дают локаторы ошибок $X_l$, а через них — точные позиции сбоев в кодовом слове.

Для поиска корней в инженерной практике редко используют аналитические формулы (особенно при больших $m$). Вместо этого применяется простой и надежный метод полного перебора всех возможных элементов поля — **алгоритм Ченя** (Chien search).

Суть алгоритма Ченя заключается в последовательной подстановке в многочлен $\sigma(x)$ всех элементов, обратных к степеням примитивного элемента поля, то есть элементов $\alpha^{-0}, \alpha^{-1}, \alpha^{-2}, \dots, \alpha^{-(n-1)}$. 

Поскольку порядок мультипликативной группы поля $\text{GF}(2^m)$ равен $n = 2^m - 1$, проверка охватывает все возможные позиции в блоке:

$$\sigma(\alpha^{-i}) = 1 + \sigma_1 \alpha^{-i} + \sigma_2 \alpha^{-2i} + \dots + \sigma_v \alpha^{-vi} = 0$$

Если при подстановке конкретного значения индекса $i$ (где $0 \le i \le n-1$) результат вычислений равен нулю, то это означает, что элемент $X = \alpha^i$ является корнем, а в позиции с номером $i$ в кодовом слове $r(x)$ произошла ошибка. 

Вычислительная сложность алгоритма Ченя линейно зависит от длины блока $n$, что делает его крайне эффективным для реализации как на аппаратном уровне (в FPGA), так и в программном обеспечении.

---

### Шаг 4: Вычисление амплитуд ошибок (Формула Форни)

Для двоичных кодов БЧХ нахождение позиций ошибок полностью завершает процесс декодирования: поскольку все значения искаженных символов равны единице в поле $\text{GF}(2)$, для исправления ошибки достаточно просто инвертировать бит в найденной позиции ($c_i = r_i \oplus 1$).

Однако для недвоичных кодов Рида–Соломона символы принадлежат полю $\text{GF}(2^m)$, и знание только позиций ошибок недостаточно — необходимо вычислить их амплитуды (значения) $Y_l = e_{i_l}$. Для этого используется многочлен ошибок и **формула Форни**.

Введем **многочлен синдромов** $S(x)$, составленный из вычисленных синдромов:

$$S(x) = S_1 x + S_2 x^2 + S_3 x^3 + \dots + S_{2t} x^{2t}$$

Связь между многочленом синдромов $S(x)$, многочленом локаторов ошибок $\sigma(x)$ и вспомогательным **многочленом оценщика ошибок** $\omega(x)$ описывается ключевым уравнением декодирования:

$$\omega(x) \equiv S(x) \sigma(x) \pmod{x^{2t+1}}$$

Многочлен оценщика ошибок $\omega(x)$ имеет степень не выше $v - 1$ и вычисляется делением произведения $S(x)\sigma(x)$ на $x^{2t+1}$ с отбрасыванием старших степеней.

Когда многочлены $\sigma(x)$ и $\omega(x)$ найдены, значения амплитуд ошибок в позициях $X_l^{-1} = \alpha^{-i_l}$ вычисляются с помощью явной формулы Форни:

$$Y_l = -\frac{\omega(X_l^{-1})}{\sigma'(X_l^{-1})}$$

где $\sigma'(x)$ — производная многочлена локаторов ошибок $\sigma(x)$ по переменной $x$. В поле $\text{GF}(2^m)$ знак минус эквивалентен сложению по модулю 2, поэтому для двоичных расширений формулу можно записать как $Y_l = \frac{\omega(X_l^{-1})}{\sigma'(X_l^{-1})}$.

После того как найдены и позиции ошибок $i_l$, и их амплитуды $Y_l$, формируется полином ошибок $e(x)$, который вычитается (или складывается) из принятого вектора:

$$c(x) = r(x) - e(x)$$

На этом процедура алгебраического декодирования завершается, и получатель извлекает исходные информационные символы.

## 5. Применение кодов Рида–Соломона в современных технологиях

### 5.1. Физическая реальность и защита от пакетных ошибок: оптические диски и QR-коды

Коды Рида–Соломона обладают уникальным свойством: оперируя символами, состоящими из нескольких бит (например, байтами в поле $\text{GF}(2^8)$), они идеально подходят для исправления пакетных ошибок (burst errors). Если на физическом носителе или в канале связи происходит локальное повреждение (царапина на диске, пыль, кратковременный глубокий замирающий сигнал), оно портит не отдельные случайные биты, а целый непрерывный кусок данных. 

Для двоичных кодов такая пакетная ошибка выглядит как длинная цепочка искажённых бит, что резко исчерпывает ресурс исправляющей способности классических кодов (например, кода Хэмминга). Для кода Рида–Соломона $\text{RS}(n, k)$ над полем $\text{GF}(2^m)$ каждый поврежденный байт (символ шириной $m$ бит) воспринимается алгоритмом декодирования ровно как *одна* ошибка символа, независимо от того, сколько именно бит внутри этого байта было инвертировано.

Рассмотрим классический пример применения кодов Рида–Соломона в оптических дисках стандарта Compact Disc (CD) и более плотных носителях (DVD, Blu-ray). На поверхности компакт-диска информационная дорожка имеет микроскопическую ширину, и даже пылинка или царапина перекрывает сразу несколько десятков или сотен смежных байтов. 

Чтобы эффективно бороться с этим, в системе CD-DA (Compact Disc Digital Audio) применяется схема перекрёстного перемежения и интерливинга совместно с двумя кодами Рида–Соломона (технология CIRC — Cross-Interleaved Reed-Solomon Code). Поток данных проходит через два последовательных кодера РС: внутренний $\text{RS}(28, 24)$ и внешний $\text{RS}(32, 28)$, оба работают в поле $\text{GF}(2^8)$. Между кодерами и после них данные перемешиваются во времени (распределяются по разным физическим участкам диска). В результате даже длинная царапина, уничтожающая подряд 4000 бит (около 500 байт), после обратного деперемеживания при чтении превращается не в один гигантский сплошной пакет ошибок, а во множество мелких единичных ошибок, распределенных по разным блокам, которые декодеры Рида–Соломона успешно восстанавливают «на лету».

Другим ярким примером массового применения кодов Рида–Соломона являются двухмерные матричные коды — **QR-коды**. QR-код состоит из чёрных и белых модулей, организованных в квадратную матрицу. Для защиты от повреждений (грязь на упаковке, замятие бумаги, частичное закрытие пальцем) в QR-кодах используется стандартизированное семейство кодов Рида–Соломона, работающих в поле $\text{GF}(2^8)$ с порождающим полиномом степени $2t$.

В стандарте QR предусмотрено четыре уровня коррекции ошибок:
1. **L (Low)** — восстанавливает до $7\%$ повреждений;
2. **M (Medium)** — восстанавливает до $15\%$ повреждений;
3. **Q (Quartile)** — восстанавливает до $25\%$ повреждений;
4. **H (High)** — восстанавливает до $30\%$ повреждений.

> **Правило.** Избыточность кода Рида–Соломона напрямую определяет процент допустимых повреждений площади носителя. Каждый проверочный символ (байт) забирает часть емкости матрицы, но позволяет декодеру компенсировать любую потерю или искажение одного символа (включая все биты внутри него) в любом месте кодового блока.

Перейдём к детальному расчёту для конкретного практического сценария.

### 5.2. Разобранный пример: расчёт избыточности и структуры QR-кода уровня «Q»

**Условие задачи:** Требуется оценить уровень избыточности, количество проверочных байтов и структуру распределения данных для блока QR-кода, работающего в режиме коррекции ошибок **уровня «Q»** (гарантированное восстановление до $25\%$ повреждений). Полезный блок исходных данных (до кодирования) составляет $100$ байтов.

**Ход рассуждений:**
1. Уровень коррекции «Q» означает, что кодовая конструкция должна исправлять до $25\%$ потерянных или поврежденных символов в блоке.
2. Пусть общий размер кодового слова (блок данных плюс проверочные байты) равен $n$ байтам, из которых $k = 100$ байтов — полезные данные. Количество проверочных байтов равно $n - k = 2t$, где $t$ — максимальное число исправляемых ошибок в символах.
3. Поскольку уровень «Q» гарантирует коррекцию до $25\%$ символов всего кодового слова, доля проверочных символов должна обеспечивать это условие. В спецификации QR-кодов для уровня «Q» доля избыточных байтов составляет примерно $25\%$ от общего числа байтов блока, что математически означает: число проверочных байтов равно удвоенному числу исправляемых ошибок $t$, причем $t \approx 0{,}25 \cdot n$. Точное соотношение параметров для кодов РС в QR-стандарте подбирается так, чтобы $2t = n - k$.
4. Вычислим точное количество проверочных байтов. Если доля проверочных символов составляет $25\%$ от общего размера $n$, то $k = 0{,}75 \cdot n$. При $k = 100$ получаем $n = \frac{100}{0{,}75} = 133{,}33$ (размер блока в байтах должен быть целым числом, поэтому на практике стандарты фиксируют конкретные размеры блоков). Обратимся к спецификации QR-кодов (версия 3, уровень Q): там размер блока данных $k = 70$ байтов, а размер кода РС составляет $n = 86$ байтов. Возьмем для нашего расчёта стандартизированный блок кода Рида–Соломона, ближайший к условию в $100$ байтов полезных данных, или произведем расчет для заданного пользователем $k = 100$ байтов в рамках гипотетического стандартного блока с долей избыточности $25\%$.
5. Строго по условию задачи задан объем полезных данных $k = 100$ байтов и уровень защиты $25\%$. Если $25\%$ всего блока — это проверочные байты (или $25\%$ символов могут быть исправимы), то число проверочных байтов $v = n - k$. Для уровня «Q» доля избыточности в общем потоке составляет ровно $25\%$, то есть $\frac{v}{n} = 0{,}25$, откуда $v = 0{,}25n$. Подставим $n = k + v$: $v = 0{,}25(100 + v) \implies v = 25 + 0{,}25v \implies 0{,}75v = 25 \implies v = \frac{25}{0{,}75} = 33{,}33$ байта. Округляем до ближайшего целого числа байтов, обеспечивающего требуемый запас: принимаем $v = 34$ проверочных байта.
6. Проверим общую длину блока: $n = 100 + 34 = 134$ байта.
7. Максимальное число исправляемых символов с ошибками в блоке: $t = \frac{v}{2} = \frac{34}{2} = 17$ символов (байт).
8. Проверим процент исправляемых ошибок от общего числа символов в блоке: $\frac{t}{n} = \frac{17}{134} \approx 0{,}1268$ (или $12{,}68\%$ символов). *Внимание:* в формулировке стандарта QR-кодов «исправление до $25\%$» относится к *общей площади изображения*, которая покрывается матрицей с учетом двухмерного перемежения и структуры из нескольких блоков РС, где часть блоков несет информацию, а часть — вычисление избыточности. Для отдельного математического кодового слова $\text{RS}(n, k)$ избыточность $v = 34$ позволяет гарантированно исправить любые $\lfloor \frac{34}{2} \rfloor = 17$ полностью стертых или искаженных байтов.

**Решение в общем виде:**
- Исходный массив байтов сообщения: $\mathbf{m} = (m_0, m_1, \dots, m_{k-1})$, где $m_i \in \text{GF}(2^8)$.
- Порождающий многочлен кода Рида–Соломона:
  $$g(x) = \prod_{i=1}^{2t} (x - \alpha^i) = x^{2t} + g_{2t-1}x^{2t-1} + \dots + g_1x + g_0$$
  где $\alpha$ — примитивный элемент поля $\text{GF}(2^8)$, заданный неприводимым полиномом (например, $x^8 + x^4 + x^3 + x^2 + 1 = 0$).
- Систематическое кодовое слово получается умножением исходного полинома сообщения $M(x) = \sum_{i=0}^{k-1} m_i x^{i + 2t}$ на $x^{2t}$ и вычислением остатка от деления на $g(x)$:
  $$R(x) = M(x)x^{2t} \pmod{g(x)}$$
  Кодовый полином записывается как:
  $$C(x) = M(x)x^{2t} + R(x) = c_{n-1}x^{n-1} + c_{n-2}x^{n-2} + \dots + c_0$$

**Подстановка и вычисление:**
- Размер информационного блока: $k = 100$ байтов.
- Количество проверочных байтов (для обеспечения расчетной избыточности): $v = 34$ байта.
- Полная длина кодового слова: $n = 100 + 34 = 134$ байта.
- Кратность исправляемых символьных ошибок: $t = \frac{v}{2} = \frac{34}{2} = 17$ байтов.
- Скорость кода (code rate): $R_c = \frac{k}{n} = \frac{100}{134} \approx 0{,}7463$.
- Уровень избыточности в процентах: $\frac{v}{n} \cdot 100\% = \frac{34}{134} \cdot 100\% \approx 25{,}37\%$, что полностью соответствует требованиям уровня «Q» (около $25\%$ площади/данных отдано под защитные структуры).

**Проверка:**
- Размерность: $100$ байт данных $+ 34$ байт проверочных $= 134$ байта (безразмерные величины, согласовано).
- Правдоподобие: скорость кода $0{,}7463$ находится в разумных пределах для помехозащищенного кодирования (от $0{,}5$ до $0{,}9$). Расчёт числа исправляемых ошибок $17$ из $134$ байтов дает минимальное кодовое расстояние $d_{\min} = n - k + 1 = 134 - 100 + 1 = 35$, что позволяет гарантированно исправлять $\lfloor \frac{d_{\min} - 1}{2} \rfloor = \lfloor \frac{35 - 1}{2} \rfloor = 17$ ошибок. Все расчёты сошлись.

**Ответ:** 
Для полезного блока данных размером $k = 100$ байтов при уровне коррекции «Q» требуется сформировать кодовое слово Рида–Соломона длиной $n = 134$ байта, содержащее $v = 34$ проверочных байта. Код обеспечивает исправление до $t = 17$ полностью уничтоженных байтов в блоке, скорость кода составляет $R_c \approx 0{,}7463$, а уровень избыточности равен $25{,}37\%$.

### 5.3. Каскадные коды: спутниковая связь и стандарты DVB

В системах дальней космической связи, цифрового телевизионного вещания (стандарты семейства DVB: DVB-S, DVB-T, DVB-C) каналы связи характеризуются высоким уровнем белого гауссовского шума (AWGN) и частыми кратковременными замираниями сигнала. Использование одного только кода Рида–Соломона при очень низких отношениях сигнал/шум требует работы в огромных полях Галуа (например, $\text{GF}(2^{16})$ и выше), что делает декодирование вычислительно невозможным для бортовых или бытовых приёмников.

Для преодоления этого ограничения в 1966 году Дэвидом Форни были предложены **каскадные коды** (concatenated codes). Идея заключается в последовательном соединении двух разных кодов:
1. **Внутренний код** (ближе к физическому каналу) — простой свёрточный код с мягким или пороговым декодированием по алгоритму Витерби. Его задача — поднять качество канала, исправив большинство независимых случайных ошибок малой кратности.
2. **Внешний код** (ближе к источнику данных) — мощный алгебраический код Рида–Соломона (например, $\text{RS}(255, 223)$ в поле $\text{GF}(2^8)$). Его задача — окончательно «дочистить» те редкие пакетные ошибки или остаточные сбои, которые пропустил внутренний декодер Витерби.

```
[ Источник данных ] 
       │
       ▼
[ Внешний кодер РС (RS(255,223)) ] 
       │
       ▼
[ Перемежитель (Interleaver) ] 
       │
       ▼
[ Внутренний свёрточный кодер ] 
       │
       ▼
[ Физический канал связи (шумы, замирания) ] 
       │
       ▼
[ Внутренний декодер Витерби ] 
       │
       ▼
[ Деперемежитель ] 
       │
       ▼
[ Внешний декодер РС (исправление пакетов) ] 
       │
       ▼
[ Получатель данных ]
```

Схема работы каскадного кода наглядно демонстрирует синергию: свёрточный код эффективно работает с гауссовским шумом, но выдает ошибки пачками (пакетами) при срывах синхронизации декодера Витерби. Код Рида–Соломона, расположенный снаружи, идеально справляется именно с пакетными ошибками, превращая уязвимый канал связи в практически абсолютно надежную линию передачи данных с вероятностью ошибки на бит (BER) менее $10^{-12}$.

### 5.4. Вычислительная сложность кодирования и декодирования

Анализ вычислительной сложности кодов БЧХ и Рида–Соломона критически важен при выборе параметров системы для работы в реальном времени. Сложность определяется размером конечного поля $\text{GF}(2^m)$, где $m$ задает размер символа (обычно $m = 8$ для байтовых систем, либо $m = 10, 12, 16$ для более длинных блоков).

1. **Кодирование:**
   Кодирование в систематической форме сводится к делению полинома сообщения на порождающий полином $g(x)$ степени $2t$. 
   - На аппаратном уровне (в FPGA или ASIC) такое деление реализуется с помощью простого линейного регистра сдвига с обратной связью (ЛРСОВ / LFSR), содержащего ровно $2t$ ячеек памяти (регистров) с элементами умножения в поле $\text{GF}(2^m)$.
   - Вычислительная сложность кодирования на программном уровне составляет $O(k \cdot (n - k))$ операций умножения и сложения в поле Галуа для одного блока. Для $m = 8$ ($n = 255$) это выполняется мгновенно даже на слабых микроконтроллерах.

2. **Декодирование:**
   Процесс декодирования кодов Рида–Соломона гораздо сложнее и включает три основных этапа:
   - **Вычисление синдромов:** требует подстановки $2t$ корней в принятый полином. Сложность: $O(n \cdot t)$ операций в $\text{GF}(2^m)$.
   - **Нахождение многочлена локаторов ошибок:** исторически выполняется с помощью алгоритма Берлекэмпа–Месси (Berlekamp–Massey). Его вычислительная сложность составляет $O(t^2)$ операций в поле Галуа. При больших значениях $t$ (например, в современных накопителях SSD, где $t$ может достигать нескольких десятков или сотен байтов) этот этап становится самым ресурсоемким.
   - **Поиск корней многочлена локаторов (алгоритм Ченя) и вычисление амплитуд ошибок (формула Форни):** сложность нахождения корней перебором всех элементов поля составляет $O(n \cdot t)$ или $O(n \cdot m)$ операций.

> **Важное замечание о масштабируемости.** При увеличении параметра $m$ (например, переход от $\text{GF}(2^8)$ к $\text{GF}(2^{16})$) таблицы умножения в поле Галуа перестают помещаться в быструю кэш-память процессора ($2^{16} \times 2^{16} = 4$ млрд элементов), что требует использования «на лету» алгоритмов вычисления через примитивные полиномы, резко увеличивая задержку (latency) обработки. Именно поэтому в высокоскоростных интерфейсах с большими блоками данных чистые коды РС при больших $m$ уступают место более легко масштабируемым кодам.

### 5.5. Сравнение кодов Рида–Соломона с современными LDPC и турбо-кодами

В современной инженерии связи и хранения данных (стандарты 5G, Wi-Fi 6, современные твердотельные накопители NVMe SSD, спутниковый интернет Starlink) классические коды Рида–Соломона в чистом виде вытеснены более мощными итеративными кодами — **LDPC** (Low-Density Parity-Check codes) и **турбо-кодами**.

Сравним эти классы помехоустойчивых кодов по ключевым параметрам:

| Критерий сравнения | Коды Рида–Соломона (РС) | Турбо-коды | Коды LDPC |
|---|---|---|---|
| **Математическая база** | Алгебраическая теория конечных полей $\text{GF}(2^m)$ | Каскадные свёрточные коды с перемежением | Разреженные матричные проверки на чётность, графы Таннера |
| **Характер ошибок** | Идеальны для пакетных ошибок (burst errors) | Отлично работают при белом гауссовском шуме (AWGN) | Превосходно работают вблизи границы Шеннона при больших блоках |
| **Сложность декодирования** | Умеренная ($O(t^2)$), детерминированная задержка | Высокая, итеративная (декодер ВСА/максимального правдоподобия) | Очень высокая параллелизуемость, итеративная (белковый алгоритм) |
| **Задержка (Latency)** | Низкая (подходит для потокового вещания и дисков) | Высокая (из-за глубокого перемежения и итераций) | Средняя или низкая при аппаратной параллелизации |
| **Основная область применения** | Оптические диски (CD/DVD/Blu-ray), QR-коды, внешние коды в DVB | Спутниковая связь, сотовая связь 3G/4G | Современные стандарты 5G, Wi-Fi (802.11n/ac/ax), SSD-накопители |

Как видно из таблицы, несмотря на триумф кодов LDPC и турбо-кодов в задачах преодоления белого шума на предельных скоростях передачи, коды Рида–Соломона сохраняют монополию там, где критически важны **детерминированная (фиксированная) задержка**, способность гарантированно справляться с длинными физическими пакетами повреждений (царапины, замятия) и простота аппаратной реализации для умеренных длин блоков.

## Типичные ошибки

1. **Использование битовой длины вместо символьной для кодов Рида–Соломона.** 
   * *Почему возникает:* Студент путает двоичные коды БЧХ (где параметры $n, k$ исчисляются в битах) с кодами Рида–Соломона, где один символ — это элемент поля $\text{GF}(2^m)$, состоящий из $m$ бит.
   * *Как избежать:* Всегда уточнять поле: если код $\text{RS}(255, 223)$ задан в $\text{GF}(2^8)$, то $n = 255$ и $k = 223$ — это *байты* (символы), а не биты.
   * *Пример:* Заявление, что код $\text{RS}(255, 223)$ имеет длину 255 бит. Это неверно: его длина $255$ байтов ($2040$ бит).

2. **Произвольный выбор параметров $n$ и $k$ для кодов Рида–Соломона.**
   * *Почему возникает:* Попытка задать длину блока $n$, не зависящую от степени расширения поля $m$.
   * *Как избежать:* Помнить железное правило: длина блока недвоичного кода БЧХ и РС строго фиксирована степенью поля: $n = 2^m - 1$. Нельзя взять произвольное $n$, например, $n = 100$ в поле $\text{GF}(2^3)$ ($2^3 - 1 = 7$).
   * *Пример:* Попытка построить код РС с длиной $n = 10$ в поле $\text{GF}(2^4)$. Длина должна быть строго $2^4 - 1 = 15$.

3. **Смешение сложения в поле $\text{GF}(2^m)$ со стандартным сложением целых чисел.**
   * *Почему возникает:* Автоматический перенос навыков арифметики действительных чисел на конечные поля характеристики 2.
   * *Как избежать:* Помнить, что в полях характеристики 2 сложение и вычитание реализуются через операцию исключающее ИЛИ (XOR): $1 + 1 = 0$, а $a + a = 0$ для любого элемента $a$.
   * *Пример:* Считают сумму $\alpha^3 + \alpha^3 = 2\alpha^3$. В поле $\text{GF}(2^m)$ правильный ответ: $\alpha^3 + \alpha^3 = 0$.

4. **Неправильный расчет кратности исправляемых ошибок $t$ по числу проверочных символов.**
   * *Почему возникает:* Путаница между минимальным расстоянием $d_{\min}$ и числом проверочных символов $n - k$.
   * *Как избежать:* Для кодов Рида–Соломона избыточность составляет ровно $2t$ символов, а минимальное расстояние равно $d_{\min} = 2t + 1 = n - k + 1$. Следовательно, $t = \lfloor \frac{n - k}{2} \rfloor$.
   * *Пример:* При избыточности $n - k = 4$ студент утверждает, что код исправляет $t = 4$ ошибки. Правильно: $t = \lfloor 4 / 2 \rfloor = 2$.

5. **Игнорирование циклотомических классов при построении порождающего многочлена двоичного кода БЧХ.**
   * *Почему возникает:* Попытка перемножить минимальные многочлены для каждой из $2t$ консекутивных степеней по отдельности без учета сопряженных корней.
   * *Как избежать:* Группировать корни $\alpha^i$ по их классам сопряженности (степеням числа 2 по модулю $n$) и брать минимальный многочлен один раз на весь циклотомический класс.
   * *Пример:* Включение минимального многочлена элемента $\alpha^2$ отдельно от $\alpha^1$ в поле $\text{GF}(2^4)$, хотя они принадлежат одному классу $\{\alpha, \alpha^2, \alpha^4, \alpha^8\}$.

6. **Ошибка в определении синдромов: подстановка корней в сам порождающий многочлен вместо принятого полинома.**
   * *Почему возникает:* Путаница между свойствами кодового слова ($c(\alpha^j) = 0$) и вычислением синдромов по принятому вектору ($S_j = r(\alpha^j)$).
   * *Как избежать:* Помнить, что синдромы вычисляются подстановкой корней $\alpha^j$ в *принятый* полином ошибок/искаженного сообщения $r(x)$, а не в порождающий $g(x)$.
   * *Пример:* Попытка вычислить синдромы делением $r(x)$ на $g(x)$ и взятием остатка для произвольного кода БЧХ без учета позиций корней.

7. **Забывание формулы Форни при декодировании недвоичных кодов.**
   * *Почему возникает:* Попытка использовать двоичный подход (простую инверсию бита) для исправления ошибок в кодах Рида–Соломона.
   * *Как избежать:* Помнить, что в кодах РС нужно найти не только позицию ошибки (через многочлен локаторов и алгоритм Ченя), но и амплитуду ошибки в поле $\text{GF}(2^m)$ с помощью формулы Форни.
   * *Пример:* Обнаружив позицию ошибки в коде РС, студент просто заменяет символ на ноль вместо вычисления точного значения амплитуды $Y_l$.

## Задачи для самостоятельного решения

Какая из систем успешно восстановит файл при возникновении сплошного пакета битовых ошибок длиной $50$ бит, если в системе РС байты упакованы последовательно? Обоснуйте ответ расчетом.

## Ответы к задачам

1. $\alpha^0 = 1$, $\alpha^1 = \alpha$, $\alpha^2 = \alpha^2$, $\alpha^3 = \alpha + 1$, $\alpha^4 = \alpha^2 + \alpha$, $\alpha^5 = \alpha^2 + \alpha + 1$, $\alpha^6 = \alpha^2 + 1$, а $\alpha^7 = 1$ (нулевой элемент поля — $0$).
2. Длина блока $n = 15$ бит, степень порождающего многочлена равна $8$, число информационных символов $k = 7$ бит, минимальное кодовое расстояние $d_{\min} = 5$.
3. Размер алфавита: $16$ символов (по $4$ бита каждый); количество проверочных символов: $6$; минимальное кодовое расстояние: $d_{\min} = 7$; максимальное число исправляемых символьных ошибок: $t = 3$.
4. Скорость кода $R \approx 0{,}8095$; максимальное число исправляемых символьных ошибок $t = 6$.
5. Синдромы удовлетворяют системе для одной ошибки; локатор ошибки равен $X_1 = \alpha^2$.
6. Общая длина кодового слова $n = 24$ байта, количество проверочных байтов равно $8$, скорость кода $R_c \approx 0{,}6667$.
7. Система с кодом Рида–Соломона $\text{RS}(255, 239)$ успешно восстановит файл, так как пакет длиной $50$ бит повреждает не более $7$ байтов, что меньше исправляющей способности кода $t = 8$ байтов; первая система с независимыми ошибками не справится.
8. Длина кода в символах $n = 31$; степень порождающего многочлена равна $6$.

## 1. Основная идея и концепция арифметического кодирования

### Ограничения посимвольных кодов и предпосылки к арифметическому кодированию

Прежде чем перейти к новому методу, вспомним, как работают классические методы сжатия без потерь, такие как код Хаффмана или код Шеннона–Фано (Тема 11 и Тема 12 нашего курса). В этих алгоритмах каждый отдельный символ входного алфавита заменяется фиксированной двоичной последовательностью — кодовым словом. 

Главное ограничение такого подхода заключается в том, что длина каждого кодового слова в битах должна быть целым числом. Если некоторый символ встречается в тексте с вероятностью $p_i$, то теоретически оптимальная длина его кодового слова по законам Шеннона составляет $-\log_2(p_i)$ бит. Однако на практике кодовое слово обязано содержать целое число бит. Например, если расчетная оптимальная длина равна $1{,}3$ бита, код Хаффмана округлит её до $2$ бит. Если оптимальная длина равна $2{,}1$ бита, алгоритм выделит $3$ бита. 

Это приводит к избыточности сжатия, особенно на алфавитах с небольшим числом символов или когда вероятности символов далеки от отрицательных степеней двойки (то есть вида $2^{-k}$). 

Представим алфавит всего из двух символов с вероятностями $0{,}9$ и $0{,}1$. Теоретическая энтропия такого источника составляет:

$$H(X) = -0{,}9 \log_2(0{,}9) - 0{,}1 \ log_2(0{,}1) \approx 0{,}0957 + 0{,}3322 = 0{,}4279 \text{ бит/символ}$$

Поскольку код Хаффмана оперирует целыми битами, каждый символ (даже частый символ с вероятностью $0{,}9$) будет закодирован как минимум $1$ битом. В результате средняя длина кода составит ровно $1{,}0$ бит на символ, что более чем в два раза превышает теоретический предел энтропии Шеннона. 

Чтобы преодолеть это ограничение, в теории информации применяется **арифметическое кодирование**. Его фундаментальное отличие от посимвольных методов состоит в том, что оно кодирует **всю последовательность символов целиком**, представляя ее в виде единого вещественного числа. При этом на символ в среднем может выделяться дробное число бит, сколь угодно близкое к энтропии источника.

### Геометрическая интерпретация: отрезки на вещественной оси

Основная идея арифметического кодирования заключается в отображении любого входного сообщения (цепочки символов) в уникальный полуинтервал на вещественной оси в диапазоне от $0$ (включительно) до $1$ (не включая), то есть в диапазон $[0, 1)$.

> **Определение.** **Кодовым интервалом сообщения** называется полуинтервал $[L, H)$ на вещественной оси, где $L$ — нижняя граница (Low), а $H$ — верхняя граница (High), однозначно определяемый последовательностью символов сообщения.

Принцип построения этого интервала интуитивно понятен:
1. Весь доступный диапазон $[0, 1)$ изначально выделяется под любые возможные сообщения.
2. По мере поступления каждого нового символа сообщения этот диапазон сужается.
3. Ширина получившегося в итоге финального интервала строго пропорциональна вероятности появления всего сообщения в целом. Чем вероятнее последовательность символов, тем шире интервал, ей соответствующий. И наоборот, маловероятные сообщения получают узкие интервалы.

Поскольку каждому уникальному сообщению соответствует свой собственный, не пересекающийся ни с каким другим непустой интервал на отрезке $[0, 1)$, в качестве результирующего кодового слова достаточно выбрать **любое вещественное число**, лежащее внутри этого финального интервала.

### Разметка отрезка $[0, 1)$ и кумулятивная функция распределения

Чтобы реализовать описанный процесс сужения интервалов, необходимо предварительно разбить базовый отрезок $[0, 1)$ на подмножества (подинтервалы), соответствующие отдельным символам алфавита источника. Это деление выполняется строго пропорционально вероятностям появления этих символов.

Для упорядоченного алфавита из $N$ символов $\{s_1, s_2, \dots, s_N\}$ с известными вероятностями появления $\{p_1, p_2, \dots, p_N\}$ строится таблица **кумулятивных (накопленных) вероятностей**.

> **Определение.** **Кумулятивной вероятностью** (или функцией накопления вероятностей) $C_i$ для $i$-го символа алфавита называется сумма вероятностей всех предшествующих символов в алфавите:
>
> $$C_i = \sum_{k=1}^{i-1} p_k$$
>
> при этом для первого символа $C_1 = 0$.

Каждому символу $s_i$ ставится в соответствие полуинтервал $[C_i, C_i + p_i)$, где:
- Нижняя граница подинтервала равна кумулятивной вероятности $C_i$.
- Верхняя граница подинтервала равна сумме кумулятивной вероятности и вероятности самого символа: $C_i + p_i$.

Рассмотрим этот процесс на конкретном примере.

---

### Пример 1: Построение статических кумулятивных интервалов

#### Условие задачи
Дан алфавит источника, состоящий из трех символов: $A, Б, В$. Вероятности появления символов заданы распределением:
- $P(A) = 0{,}5$
- $P(Б) = 0{,}3$
- $P(В) = 0{,}2$

Требуется построить таблицу кумулятивных вероятностей и определить исходные подинтервалы для каждого символа на отрезке $[0, 1)$.

#### Ход рассуждений
1. Проверим корректность заданного распределения вероятностей: сумма всех вероятностей должна быть равна единице:
   $$\sum p_i = 0{,}5 + 0{,}3 + 0{,}2 = 1{,}0$$
   Условие выполнено.
2. Упорядочим символы в алфавитном порядке (или любом другом фиксированном порядке, известном как кодеру, так и декодеру): $s_1 = A, s_2 = Б, s_3 = В$.
3. Вычислим кумулятивную вероятность $C_i$ для каждого символа по формуле:
   - Для символа $A$ ($i = 1$): предшествующих символов нет, поэтому $C_A = 0$.
   - Для символа $Б$ ($i = 2$): $C_Б = P(A) = 0{,}5$.
   - Для символа $В$ ($i = 3$): $C_В = P(A) + P(Б) = 0{,}5 + 0{,}3 = 0{,}8$.
4. Определим границы подинтервалов $[L_i, H_i)$ как $[C_i, C_i + P(s_i))$:
   - Для $A$: $[0, \ 0 + 0{,}5) = [0{,}0; \ 0{,}5)$
   - Для $Б$: $[0{,}5, \ 0{,}5 + 0{,}3) = [0{,}5; \ 0{,}8)$
   - Для $В$: $[0{,}8, \ 0{,}8 + 0{,}2) = [0{,}8; \ 1{,}0)$

#### Схематическое представление в виде ASCII-диаграммы

```text
0.0              0.5            0.8            1.0
 +----------------+--------------+--------------+
 |    Символ А    |   Символ Б   |   Символ В   |
 |  [0.0; 0.5)    |  [0.5; 0.8)  |  [0.8; 1.0)  |
 +----------------+--------------+--------------+
```

#### Проверка
- Длина каждого подинтервала равна вероятности соответствующего символа:
  - Длина интервала $A$: $0{,}5 - 0{,}0 = 0{,}5$ (что совпадает с $P(A)$).
  - Длина интервала $Б$: $0{,}8 - 0{,}5 = 0{,}3$ (что совпадает с $P(Б)$).
  - Длина интервала $В$: $1{,}0 - 0{,}8 = 0{,}2$ (что совпадает с $P(В)$).
- Подинтервалы не пересекаются и в сумме полностью покрывают отрезок $[0, 1)$.

#### Ответ
Таблица кумулятивных интервалов для заданного алфавита имеет вид:

| Символ $s_i$ | Вероятность $P(s_i)$ | Кумулятивная вероятность $C_i$ | Подинтервал $[L_i, H_i)$ |
| :---: | :---: | :---: | :---: |
| $A$ | $0{,}5$ | $0{,}0$ | $[0{,}0; \ 0{,}5)$ |
| $Б$ | $0{,}3$ | $0{,}5$ | $[0{,}5; \ 0{,}8)$ |
| $В$ | $0{,}2$ | $0{,}8$ | $[0{,}8; \ 1{,}0)$ |

## 2. Алгоритм арифметического кодирования

### Формализация процесса кодирования и текущий интервал

Арифметическое кодирование преобразует всю входную последовательность символов в одно вещественное число из полуинтервала $[0, 1)$. Чтобы реализовать это на практике, алгоритм использует понятие **текущего интервала**, который на каждом шаге сужается в соответствии с вероятностями поступающих символов.

> **Определение.** **Текущий интервал** — это отрезок вещественной оси вида $[\text{Low}, \text{High})$, который на самом первом шаге (до чтения любого символа сообщения) охватывает весь диапазон от $0$ до $1$, то есть $\text{Low} = 0{,}0$ и $\text{High} = 1{,}0$.

По мере того как мы читаем символы сообщения по одному слева направо, текущий интервал дробится на части. Каждая часть соответствует одному из символов алфавита, а ее размер пропорционален вероятности этого символа. На следующем шаге мы берем ту часть, которая соответствует прочитанному символу, и принимаем ее за новый текущий интервал, после чего делим уже его. Таким образом, каждый новый символ «зажимает» интервал все сильнее, локализуя точку внутри исходного отрезка $[0, 1)$.

### Правило обновления границ и математические формулы

Пусть у нас имеется алфавит из $M$ символов $\{s_1, s_2, \dots, s_M\}$ с известными вероятностями $P(s_i)$. Из этих вероятностей строятся **кумулятивные (накопленные) вероятности**, задающие левую и правую границы каждого символа в исходном отрезке $[0, 1)$:
- Левая кумулятивная граница символа $s_i$: 
  $$C_{\text{low}}(s_i) = \sum_{j=1}^{i-1} P(s_j)$$
  причем для первого символа $C_{\text{low}}(s_1) = 0{,}0$.
- Правая кумулятивная граница символа $s_i$:
  $$C_{\text{high}}(s_i) = \sum_{j=1}^{i} P(s_j) = C_{\text{low}}(s_i) + P(s_i)$$

Пусть на текущем шаге у нас есть активный интервал с границами $[\text{Low}_{\text{prev}}, \text{High}_{\text{prev}})$. Его общая ширина (длина) равна:
$$\text{Width} = \text{High}_{\text{prev}} - \text{Low}_{\text{prev}}$$

Когда поступает очередной символ $s_i$, мы должны сузить текущий интервал $[\text{Low}_{\text{prev}}, \text{High}_{\text{prev}})$ до подинтервала, соответствующего этому символу. Новые границы $[\text{Low}_{\text{new}}, \text{High}_{\text{new}})$ вычисляются по формулам:

$$\text{Low}_{\text{new}} = \text{Low}_{\text{prev}} + \text{Width} \cdot C_{\text{low}}(s_i)$$

$$\text{High}_{\text{new}} = \text{Low}_{\text{prev}} + \text{Width} \cdot C_{\text{high}}(s_i)$$

Разберем логику этих формул. Мы берем старую левую границу $\text{Low}_{\text{prev}}$ и сдвигаемся вправо на долю от текущей ширины интервала, которая определяется положением символа в таблице кумулятивных вероятностей. Ширина нового интервала окажется равной:
$$\text{High}_{\text{new}} - \text{Low}_{\text{new}} = \text{Width} \cdot (C_{\text{high}}(s_i) - C_{\text{low}}(s_i)) = \text{Width} \cdot P(s_i)$$
То есть длина интервала на каждом шаге умножается на вероятность текущего символа. Это отражает главный закон теории информации: чем реже (невероятнее) символ, тем сильнее он сужает оставшееся пространство, внося больший вклад в общую энтропию сообщения (неся больше информации).

### Пошаговый пример кодирования последовательности «АБВ»

Рассмотрим полный расчет для алфавита из трех символов: «А», «Б», «В».
Заданные вероятности:
- $P(\text{А}) = 0{,}5$
- $P(\text{Б}) = 0{,}3$
- $P(\text{В}) = 0{,}2$

Требуется закодировать сообщение: **«АБВ»**.

#### Шаг 1. Построение таблицы кумулятивных интервалов
Составим таблицу для каждого символа алфавита, последовательно суммируя вероятности:

| Символ $s_i$ | Вероятность $P(s_i)$ | $C_{\text{low}}(s_i)$ | $C_{\text{high}}(s_i)$ | Отрезок на оси $[0, 1)$ |
| :---: | :---: | :---: | :---: | :---: |
| **А** | $0{,}5$ | $0{,}0$ | $0{,}5$ | $[0{,}0;\, 0{,}5)$ |
| **Б** | $0{,}3$ | $0{,}5$ | $0{,}8$ | $[0{,}5;\, 0{,}8)$ |
| **В** | $0{,}2$ | $0{,}8$ | $1{,}0$ | $[0{,}8;\, 1{,}0)$ |

Проверка: сумма вероятностей равна $0{,}5 + 0{,}3 + 0{,}2 = 1{,}0$, последний интервал заканчивается ровно на $1{,}0$. Все верно.

#### Шаг 2. Инициализация процесса
- Исходный интервал: $\text{Low} = 0{,}0$, $\text{High} = 1{,}0$.
- Сообщение для кодирования: строка из трех символов: $1$-й — «А», $2$-й — «Б», $3$-й — «В».

#### Шаг 3. Обработка символа № 1: «А»
- Текущие границы до обработки: $\text{Low}_{\text{prev}} = 0{,}0$, $\text{High}_{\text{prev}} = 1{,}0$.
- Ширина интервала: $\text{Width} = 1{,}0 - 0{,}0 = 1{,}0$.
- Для символа «А» из таблицы берем: $C_{\text{low}}(\text{А}) = 0{,}0$, $C_{\text{high}}(\text{А}) = 0{,}5$.
- Вычисляем новые границы:
  $$\text{Low} = 0{,}0 + 1{,}0 \cdot 0{,}0 = 0{,}0$$
  $$\text{High} = 0{,}0 + 1{,}0 \cdot 0{,}5 = 0{,}5$$
- Новый текущий интервал после обработки символа «А»: **$[0{,}0;\, 0{,}5)$**.

#### Шаг 4. Обработка символа № 2: «Б»
- Текущие границы до обработки: $\text{Low}_{\text{prev}} = 0{,}0$, $\text{High}_{\text{prev}} = 0{,}5$.
- Ширина интервала: $\text{Width} = 0{,}5 - 0{,}0 = 0{,}5$.
- Для символа «Б» из таблицы берем: $C_{\text{low}}(\text{Б}) = 0{,}5$, $C_{\text{high}}(\text{Б}) = 0{,}8$.
- Вычисляем новые границы по формулам:
  $$\text{Low} = 0{,}0 + 0{,}5 \cdot 0{,}5 = 0{,}25$$
  $$\text{High} = 0{,}0 + 0{,}5 \cdot 0{,}8 = 0{,}40$$
- Проверим ширину получившегося интервала: $0{,}40 - 0{,}25 = 0{,}15$. Ожидаемо: $\text{Width}_{\text{old}} \cdot P(\text{Б}) = 0{,}5 \cdot 0{,}3 = 0{,}15$.
- Новый текущий интервал после обработки символа «Б»: **$[0{,}25;\, 0{,}40)$**.

#### Шаг 5. Обработка символа № 3: «В»
- Текущие границы до обработки: $\text{Low}_{\text{prev}} = 0{,}25$, $\text{High}_{\text{prev}} = 0{,}40$.
- Ширина интервала: $\text{Width} = 0{,}40 - 0{,}25 = 0{,}15$.
- Для символа «В» из таблицы берем: $C_{\text{low}}(\text{В}) = 0{,}8$, $C_{\text{high}}(\text{В}) = 1{,}0$.
- Вычисляем новые границы:
  $$\text{Low} = 0{,}25 + 0{,}15 \cdot 0{,}8 = 0{,}25 + 0{,}12 = 0{,}37$$
  $$\text{High} = 0{,}25 + 0{,}15 \cdot 1{,}0 = 0{,}25 + 0{,}15 = 0{,}40$$
- Проверим ширину получившегося интервала: $0{,}40 - 0{,}37 = 0{,}03$. Ожидаемо: $\text{Width}_{\text{old}} \cdot P(\text{В}) = 0{,}15 \cdot 0{,}2 = 0{,}03$.
- Финальный интервал после обработки всей строки «АБВ»: **$[0{,}37;\, 0{,}40)$**.

### Выбор итогового вещественного числа

Вся входная последовательность «АБВ» теперь уникально закодирована полуинтервалом $[0{,}37;\, 0{,}40)$. Любое вещественное число $x$, лежащее строго внутри этого полуинтервала ($0{,}37 \le x < 0{,}40$), может служить кодом нашего сообщения. При декодировании получатель, зная таблицу вероятностей и длину сообщения (или признак конца), попадет ровно в этот же интервал и восстановит исходные символы.

На практике нам нужно передать не любое вещественное число, а двоичную дробь минимальной длины, которая гарантированно попадает внутрь интервала $[\text{Low}, \text{High})$. Проще всего выбрать число, середина которого лежит в интервале, либо подобрать двоичную дробь с наименьшим количеством знаков после запятой.

Возьмем, например, число $0{,}38$, которое лежит в диапазоне от $0{,}37$ до $0{,}40$.
Переведем десятичное число $0{,}38$ в двоичную систему счисления (умножением на $2$):
- $0{,}38 \cdot 2 = 0{,}76$ (целая часть: $0$)
- $0{,}76 \cdot 2 = 1{,}52$ (целая часть: $1$)
- $0{,}52 \cdot 2 = 1{,}04$ (целая часть: $1$)
- $0{,}04 \cdot 2 = 0{,}08$ (целая часть: $0$)
- $0{,}08 \cdot 2 = 0{,}16$ (целая часть: $0$)
И так далее. Получаем двоичную дробь $0{,}01100\dots_2$.

В качестве итогового кода можно выбрать любую короткую двоичную дробь из интервала $[0{,}37;\, 0{,}40)$, например, $0{,}375$ (в двоичной системе это $0{,}011_2$, так как $0 \cdot \frac{1}{2} + 1 \cdot \frac{1}{4} + 1 \cdot \frac{1}{8} = 0{,}25 + 0{,}125 = 0{,}375$).
Проверим: $0{,}375$ находится в диапазоне $[0{,}37;\, 0{,}40)$, следовательно, оно абсолютно корректно и однозначно декодируется.

*Ответ:* Закодированное число: **$0{,}375$** (или любое другое число из полуинтервала $[0{,}37;\, 0{,}40)$).

### Проблема точности вычислений и масштабирование

В примере выше мы использовали короткую строку из трех символов, и вычисления производились с двумя-тремя знаками после запятой. Однако в реальных программах сжатия текстов или изображений длина сообщения может составлять миллионы символов. 

Здесь возникает фундаментальная техническая проблема: **исчерпание разрядной сетки процессора**. 
1. После каждых нескольких десятков символов ширина текущего интервала $\text{High} - \text{Low}$ становится катастрофически маленькой (например, $10^{-20}$ и меньше).
2. Стандартные типы данных с плавающей точкой одинарной (`float` / 32 бита) или двойной (`double` / 64 бита) точности имеют фиксированное количество значащих битов в мантиссе. Как только ширина интервала становится меньше машинного эпсилона, процессор начинает округлять границы, что приводит к фатальной ошибке кодирования (интервал «схлопывается» в нуль, и декодирование становится невозможным).

Для решения этой проблемы в практических реализациях арифметического кодирования (например, в алгоритмах Q-coder, CABAC в стандартах H.264/AVC) применяют **масштабирование (переноску разрядов)**. 

Суть масштабирования заключается в том, что алгоритм не ждет окончания всего файла, а периодически «выталкивает» готовые старшие биты результирующего числа в выходной поток и сдвигает границы обратно в рабочий диапазон:
- Если весь текущий интервал целиком лежит в левой половине числовой оси (то есть $\text{High} < 0{,}5$), мы точно знаем, что первая двоичная цифра результирующего числа равна $0$. Мы можем вывести бит `0`, умножить обе границы ($\text{Low}$ и $\text{High}$) на $2$ (сдвиг влево) и продолжить работу.
- Если весь интервал целиком лежит в правой половине ($\text{Low} \ge 0{,}5$), первая двоичная цифра равна $1$. Мы выводим бит `1`, вычитаем $0{,}5$ из обеих границ и умножаем их на $2$.
- Существует также промежуточный случай (неопределенность в среднем диапазоне, когда интервал пересекает точку $0{,}5$), для которого применяются специальные правила развертывания масштаба (увеличение интервала вокруг точки $0{,}5$).

Благодаря процедуре масштабирования арифметическое кодирование может обрабатывать сообщения произвольной (бесконечной) длины, используя регистры фиксированной разрядности (например, 16- или 32-битные целые числа вместо вещественных).

## 3. Алгоритм арифметического декодирования

### 3. Алгоритм арифметического декодирования

В предыдущих разделах мы рассмотрели, как превратить последовательность символов в одно вещественное число из полуинтервала $[0, 1)$. Теперь решим обратную задачу: имея на руках закодированное число $x$ и точную таблицу вероятностей символов (сведения о статистике источника), восстановим исходный текст без потерь.

Арифметическое декодирование — это процесс постепенного «сужения» области поиска. Мы будем последовательно определять каждый символ сообщения, проверяя, в какой из подразделов текущего интервала попадает наше закодированное число.

---

### Сущность и шаги процедуры декодирования

Пусть нам передано вещественное число $x \in [0, 1)$, известна длина сообщения $N$ (или используется специальный маркер конца сообщения) и известна статическая таблица вероятностей алфавита. 

Для каждого символа алфавита $s_i$ (где $i = 1, 2, \dots, M$) на основе его вероятности $P(s_i)$ мы заранее рассчитываем статические кумулятивные границы:
- Левая кумулятивная граница символа:
  $$F_{\text{low}}(s_i) = \sum_{j=1}^{i-1} P(s_j)$$
  причем для первого символа $F_{\text{low}}(s_1) = 0$.
- Правая кумулятивная граница символа:
  $$F_{\text{high}}(s_i) = F_{\text{low}}(s_i) + P(s_i)$$

Процесс декодирования состоит из следующих последовательных шагов:

1. **Инициализация:**
   Устанавливаем начальный текущий интервал:
   $$\text{Low} = 0{,}0, \quad \text{High} = 1{,}0$$
   Задаем счетчик принятых символов или организуем цикл на $N$ шагов (если длина сообщения известна).

2. **Масштабирование и поиск символа:**
   На каждом шаге текущий интервал $[\text{Low}, \text{High})$ имеет ширину:
   $$\text{Range} = \text{High} - \text{Low}$$
   Для каждого символа алфавита $s_i$ вычисляем его актуальные границы в текущем интервале:
   $$\text{SubLow}_i = \text{Low} + \text{Range} \cdot F_{\text{low}}(s_i)$$
   $$\text{SubHigh}_i = \text{Low} + \text{Range} \cdot F_{\text{high}}(s_i)$$

3. **Идентификация символа:**
   Проверяем, какому из символов $s_i$ принадлежит наше закодированное число $x$. Искомым является тот символ, для которого выполняется условие:
   $$\text{SubLow}_i \le x < \text{SubHigh}_i$$
   Найденный символ $s_i$ добавляется в результирующую строку (выход декодера).

4. **Обновление границ (сужение интервала):**
   Присваиваем границам текущего интервала значения границ найденного подраздела:
   $$\text{Low} = \text{SubLow}_i$$
   $$\text{High} = \text{SubHigh}_i$$

5. **Завершение или продолжение:**
   Шаги 2–4 повторяются ровно $N$ раз (где $N$ — длина исходного сообщения). После извлечения $N$-го символа процесс завершается.

---

### Разобранный пример декодирования

#### Условие задачи
Задано:
- Алфавит источника состоит из трех символов: $A$, $B$, $V$.
- Вероятности символов: $P(A) = 0{,}5$, $P(B) = 0{,}3$, $P(V) = 0{,}2$.
- Закодированное число: $x = 0{,}38$.
- Известная длина сообщения: $N = 3$ символа.

Требуется восстановить исходную последовательность символов.

#### Рисунок словами (схема работы алгоритма)
Представим отрезок $[0, 1)$. Он разбит на три подотрезка в соответствии с вероятностями:
- Символ $A$ занимает отрезок $[0{,}0;\, 0{,}5)$ (ширина 0,5).
- Символ $B$ занимает отрезок $[0{,}5;\, 0{,}8)$ (ширина 0,3).
- Символ $V$ занимает отрезок $[0{,}8;\, 1{,}0)$ (ширина 0,2).

Нам нужно узнать, внутрь какого из этих подотрезков попадает число $x = 0{,}38$, затем «увеличить» этот подотрезков до масштаба $[0, 1)$ и повторить процедуру для следующего символа.

---

#### Шаг 1. Подготовка таблицы кумулятивных вероятностей

Для каждого символа вычислим левую и правую кумулятивные границы:

| Символ $s_i$ | Вероятность $P(s_i)$ | $F_{\text{low}}(s_i)$ | $F_{\text{high}}(s_i)$ | Кумулятивный интервал |
| :---: | :---: | :---: | :---: | :---: |
| $A$ | $0{,}5$ | $0{,}0$ | $0{,}5$ | $[0{,}0;\, 0{,}5)$ |
| $B$ | $0{,}3$ | $0{,}5$ | $0{,}8$ | $[0{,}5;\, 0{,}8)$ |
| $V$ | $0{,}2$ | $0{,}8$ | $1{,}0$ | $[0{,}8;\, 1{,}0)$ |

---

#### Шаг 2. Декодирование первого символа ($k = 1$)

1. Начальный интервал: $\text{Low} = 0{,}0$, $\text{High} = 1{,}0$. Ширина $\text{Range} = 1{,}0 - 0{,}0 = 1{,}0$.
2. Проверяем границы для каждого символа в текущем интервале:
   - Для $A$: 
     $$\text{SubLow}_A = 0{,}0 + 1{,}0 \cdot 0{,}0 = 0{,}0$$
     $$\text{SubHigh}_A = 0{,}0 + 1{,}0 \cdot 0{,}5 = 0{,}5$$
     Интервал для $A$: $[0{,}0;\, 0{,}5)$.
   - Для $B$: 
     $$\text{SubLow}_B = 0{,}0 + 1{,}0 \cdot 0{,}5 = 0{,}5$$
     $$\text{SubHigh}_B = 0{,}0 + 1{,}0 \cdot 0{,}8 = 0{,}8$$
     Интервал для $B$: $[0{,}5;\, 0{,}8)$.
   - Для $V$: 
     $$\text{SubLow}_V = 0{,}0 + 1{,}0 \cdot 0{,}8 = 0{,}8$$
     $$\text{SubHigh}_V = 0{,}0 + 1{,}0 \cdot 1{,}0 = 1{,}0$$
     Интервал для $V$: $[0{,}8;\, 1{,}0)$.

3. Проверяем условие попадания числа $x = 0{,}38$:
   Число $0{,}38$ лежит в диапазоне $[0{,}0;\, 0{,}5)$, то есть $0{,}0 \le 0{,}38 < 0{,}5$.
   Следовательно, **первый декодированный символ — $A$**.

4. Обновляем текущий интервал для следующего шага:
   $$\text{Low} = 0{,}0, \quad \text{High} = 0{,}5$$

---

#### Шаг 3. Декодирование второго символа ($k = 2$)

1. Текущий интервал: $[\text{Low}, \text{High}) = [0{,}0;\, 0{,}5)$.
   Ширина интервала: $\text{Range} = 0{,}5 - 0{,}0 = 0{,}5$.

2. Рассчитываем подразделы внутри текущего интервала:
   - Для $A$:
     $$\text{SubLow}_A = 0{,}0 + 0{,}5 \cdot 0{,}0 = 0{,}0$$
     $$\text{SubHigh}_A = 0{,}0 + 0{,}5 \cdot 0{,}5 = 0{,}25$$
     Интервал для $A$: $[0{,}0;\, 0{,}25)$.
   - Для $B$:
     $$\text{SubLow}_B = 0{,}0 + 0{,}5 \cdot 0{,}5 = 0{,}25$$
     $$\text{SubHigh}_B = 0{,}0 + 0{,}5 \cdot 0{,}8 = 0{,}40$$
     Интервал для $B$: $[0{,}25;\, 0{,}40)$.
   - Для $V$:
     $$\text{SubLow}_V = 0{,}0 + 0{,}5 \cdot 0{,}8 = 0{,}40$$
     $$\text{SubHigh}_V = 0{,}0 + 0{,}5 \cdot 1{,}0 = 0{,}50$$
     Интервал для $V$: $[0{,}40;\, 0{,}50)$.

3. Проверяем условие попадания числа $x = 0{,}38$:
   Сравниваем $0{,}38$ с полученными границами:
   - $0{,}0 \le 0{,}38 < 0{,}25$ — ложь.
   - $0{,}25 \le 0{,}38 < 0{,}40$ — истина (так как $0{,}25 \le 0{,}38$ и $0{,}38 < 0{,}40$).
   Следовательно, **второй декодированный символ — $B$**.

4. Обновляем текущий интервал для следующего шага:
   $$\text{Low} = 0{,}25, \quad \text{High} = 0{,}40$$

---

#### Шаг 4. Декодирование третьего символа ($k = 3$)

1. Текущий интервал: $[\text{Low}, \text{High}) = [0{,}25;\, 0{,}40)$.
   Ширина интервала: $\text{Range} = 0{,}40 - 0{,}25 = 0{,}15$.

2. Рассчитываем подразделы внутри текущего интервала:
   - Для $A$:
     $$\text{SubLow}_A = 0{,}25 + 0{,}15 \cdot 0{,}0 = 0{,}25$$
     $$\text{SubHigh}_A = 0{,}25 + 0{,}15 \cdot 0{,}5 = 0{,}25 + 0{,}075 = 0{,}325$$
     Интервал для $A$: $[0{,}25;\, 0{,}325)$.
   - Для $B$:
     $$\text{SubLow}_B = 0{,}25 + 0{,}15 \cdot 0{,}5 = 0{,}25 + 0{,}075 = 0{,}325$$
     $$\text{SubHigh}_B = 0{,}25 + 0{,}15 \cdot 0{,}8 = 0{,}25 + 0{,}120 = 0{,}370$$
     Интервал для $B$: $[0{,}325;\, 0{,}370)$.
   - Для $V$:
     $$\text{SubLow}_V = 0{,}25 + 0{,}15 \cdot 0{,}8 = 0{,}25 + 0{,}120 = 0{,}370$$
     $$\text{SubHigh}_V = 0{,}25 + 0{,}15 \cdot 1{,}0 = 0{,}25 + 0{,}150 = 0{,}400$$
     Интервал для $V$: $[0{,}370;\, 0{,}400)$.

3. Проверяем условие попадания числа $x = 0{,}38$:
   Сравниваем $0{,}38$ с границами:
   - $0{,}25 \le 0{,}38 < 0{,}325$ — ложь.
   - $0{,}325 \le 0{,}38 < 0{,}370$ — ложь.
   - $0{,}370 \le 0{,}38 < 0{,}400$ — истина (так как $0{,}370 \le 0{,}38$ и $0{,}38 < 0{,}400$).
   Следовательно, **третий декодированный символ — $V$**.

4. Поскольку общая заданная длина сообщения $N = 3$ достигнута, процесс декодирования завершается.

---

#### Проверка и правдоподобие
Мы декодировали последовательность символов: `А`, `Б`, `В`, то есть слово `АБВ`. 
Чтобы убедиться в правильности вычислений, выполним обратную проверку (прямое кодирование слова `АБВ`):
1. Старт: $[\text{Low}=0{,}0, \text{High}=1{,}0)$.
2. Символ `А`: $[0{,}0;\, 0{,}5)$.
3. Символ `Б` внутри $[0{,}0;\, 0{,}5)$: левая граница $= 0{,}0 + 0{,}5 \cdot 0{,}5 = 0{,}25$, правая $= 0{,}0 + 0{,}5 \cdot 0{,}8 = 0{,}40$. Интервал: $[0{,}25;\, 0{,}40)$.
4. Символ `В` внутри $[0{,}25;\, 0{,}40)$: левая граница $= 0{,}25 + 0{,}15 \cdot 0{,}8 = 0{,}25 + 0{,}12 = 0{,}37$, правая $= 0{,}25 + 0{,}15 \cdot 1{,}0 = 0{,}40$. Итоговый интервал: $[0{,}37;\, 0{,}40)$.

Заданное число $x = 0{,}38$ попадает внутрь полученного интервала $[0{,}37;\, 0{,}40)$, так как $0{,}37 \le 0{,}38 < 0{,}40$. Вычисления сошлись идеально, погрешностей нет.

Ответ: `АБВ`

## 4. Анализ эффективности и сравнение с кодом Хаффмана

### Сравнение средней длины кодового слова с энтропией источника

В предыдущих разделах мы познакомились с процессом арифметического кодирования, который позволяет отобразить всю последовательность символов сообщения в виде единого вещественного числа — полуинтервала на отрезке $[0, 1)$. Чтобы оценить, насколько эффективным является этот метод сжатия, необходимо сопоставить его теоретические возможности с фундаментальным пределом теории информации — энтропией дискретного источника.

Напомним, что энтропия дискретного источника $X$, заданного алфавитом с вероятностями символов $p_1, p_2, \dots, p_n$, вычисляется по формуле Шеннона:

$$H(X) = - \sum_{i=1}^{n} p_i \log_2 p_i$$

Величина $H(X)$ измеряется в битах на символ и определяет абсолютный теоретический предел для любого метода сжатия без потерь, использующего независимое кодирование символов. Никакой алгоритм не может в среднем сжать поток данных сильнее, чем задает энтропия источника.

> **Определение.** Средней длиной кодового слова в арифметическом кодировании для сообщения длиной $N$ символов называется отношение общего числа затраченных бит $L_{\text{total}}$ к количеству закодированных символов $N$:
> 
> $$L_{\text{avg}} = \frac{L_{\text{total}}}{N}$$

При арифметическом кодировании длина результирующего двоичного кода $L_{\text{total}}$ определяется шириной финального интервала $\Delta = \text{High} - \text{Low}$. Для того чтобы однозначно идентифицировать интервал шириной $\Delta$, требуется выбрать двоичную дробь длиной $L_{\text{total}}$ бит, удовлетворяющую условию:

$$2^{-L_{\text{total}}} \le \Delta$$

Отсюда следует, что число необходимых бит равно:

$$L_{\text{total}} = \lceil -\log_2 \Delta \rceil$$

Ширина финального интервала для сообщения, состоящего из символов $x_1, x_2, \dots, x_N$ с независимыми вероятностями $P(x_i)$, равна произведению их вероятностей:

$$\Delta = \prod_{i=1}^{N} P(x_i)$$

Подставим это выражение в формулу для общего числа бит:

$$L_{\text{total}} = \left\lceil -\log_2 \left( \prod_{i=1}^{N} P(x_i) \right) \right\rceil = \left\lceil -\sum_{i=1}^{N} \log_2 P(x_i) \right\rceil$$

Разделим полученное выражение на длину сообщения $N$, чтобы найти среднюю длину на один символ:

$$L_{\text{avg}} = \frac{1}{N} \left\lceil -\sum_{i=1}^{N} \log_2 P(x_i) \right\rceil$$

Если устремить длину сообщения $N$ к бесконечности ($N \to \infty$), влияние операции округления вверх (потолка $\lceil \dots \rceil$) становится пренебрежимо малым, а сумма под знаком среднего превращается в математическое ожидание:

$$\lim_{N \to \infty} L_{\text{avg}} = - \sum_{i=1}^{n} p_i \log_2 p_i = H(X)$$

Это важнейшее математическое свойство арифметического кодирования: **в пределе при увеличении длины сообщения средняя длина кодового слова на символ стремится к энтропии источника**. Метод достигает абсолютной эффективности сжатия.

---

### Преимущество перед посимвольными кодами: дробные биты

Классические посимвольные префиксные коды, такие как код Хаффмана или код Шеннона–Фано, назначают каждому символу алфавита целое число битов. Пусть, например, некоторый символ имеет вероятность $P(A) = 0{,}4$. Согласно теории информации, идеальная информационная емкость этого символа составляет:

$$I(A) = -\log_2(0{,}4) \approx 1{,}32 \text{ бит}$$

Однако алгоритм Хаффмана вынужден выделить этому символу целое число битов — либо $1$ бит, либо $2$ бита. Возникает избыточность округления, так как кодовое дерево оперирует исключительно целыми ветвлениями. Если в алфавите много таких символов, избыточность накапливается, снижая коэффициент сжатия.

Арифметическое кодирование полностью преодолевает это ограничение. Поскольку кодируется не отдельный символ, а вся последовательность целиком как единая точка на вещественной оси, алгоритм оперирует дробями интервалов. Накладные расходы на округление (один дополнительный бит на всё сообщение для обеспечения точности попадания в интервал) при длинных сообщениях распределяются на тысячи или миллионы символов, составляя пренебрежимо малую величину $\frac{1}{N}$.

Сравнение свойств методов сжатия приведено в таблице ниже.

| Критерий сравнения | Код Хаффмана | Арифметическое кодирование |
|---|---|---|
| Единица кодирования | Отдельный символ алфавита | Вся последовательность символов целиком |
| Длина кода для символа | Строго целое число бит ($\ge 1$) | Дробное значение (в среднем на блок) |
| Близость к энтропии $H(X)$ | Оптимален только если все $p_i = 2^{-k}$ | Достигает энтропии для любого распределения |
| Зависимость от памяти | Требуется таблица частот и дерево | Требуется таблица частот и высокая точность вычислений |
| Скорость работы | Высокая (побитовый обход дерева) | Ниже (требуется высокая точность арифметики) |

### Поведение алгоритма при неравномерных и вырожденных распределениях

Эффективность любого метода сжатия драматически зависит от характера распределения вероятностей символов в источнике. Рассмотрим два предельных случая.

1. **Равномерное распределение.** Пусть алфавит состоит из $n$ символов, каждый из которых имеет одинаковую вероятность $p_i = \frac{1}{n}$. 
   * Энтропия источника равна $H(X) = -\sum_{i=1}^{n} \frac{1}{n} \log_2\left(\frac{1}{n}\right) = \log_2 n$.
   * Код Хаффмана для такого алфавита назначит каждому символу ровно $\lceil \log_2 n \rceil$ бит. Если $n$ не является степенью двойки (например, $n = 3$), код Хаффмана будет иметь избыточность.
   * Арифметическое кодирование делит отрезок $[0, 1)$ на равные части и также выдает результат, близкий к $\log_2 n$, не давая выигрыша по сравнению с простым двоичным кодированием фиксированной длины, так как сжимать здесь статистически нечего.

2. **Неравномерное и вырожденное распределение.** Пусть один из символов встречается практически всегда ($p_1 = 0{,}99$), а остальные крайне редкие.
   * Энтропия такого источника стремится к нулю ($H(X) \approx 0{,}08$ бит/символ).
   * Код Хаффмана обязан выделить самому частому символу хотя бы $1$ бит, из-за чего средняя длина кода не сможет опуститься ниже $1$ бита на символ, даже если реальная энтропия составляет доли бита. Это фундаментальное ограничение посимвольных методов.
   * **Арифметическое кодирование справляется с этой задачей идеально.** Если сообщение состоит из длинной цепочки частых символов, интервал сужается на коэффициент $0{,}99$ шаг за шагом. Поскольку $-\log_2(0{,}99) \approx 0{,}014$ бита, для кодирования длинной серии таких символов требуется суммарно меньше одного бита на символ (например, один бит может покрывать несколько десятков повторений частых символов). Таким образом, арифметическое кодирование способно кодировать символы с вероятностями, близкими к единице, затрачивая доли бита на символ и вплотную приближаясь к нулевой энтропии.

### Сложность реализации и вычислительные затраты

Несмотря на теоретическую оптимальность, на практике чистый алгоритм арифметического кодирования сопряжен с серьезными вычислительными трудностями:

* **Точность вычислений с плавающей точкой.** Границы интервалов `Low` и `High` по мере поступления новых символов уменьшаются экспоненциально: после обработки всего нескольких десятков символов значения требуют точности в десятки и сотни знаков после запятой. Стандартные типы данных с плавающей точкой (`float` на 32 бита или `double` на 64 бита в языках программирования) быстро исчерпывают свою разрядность, что приводит к переполнению снизу (underflow) и катастрофической потере точности.
* **Программные ухищрения (масштабирование).** В реальных промышленных реализациях (например, в стандартах сжатия изображений JPEG, JBIG) проблема решается с помощью целочисленной арифметики фиксированной точности и процедур *масштабирования* (renormalization). Отрезок $[0, 1)$ представляется в виде целых чисел в диапазоне от $0$ до $2^k - 1$. Как только верхняя и нижняя границы оказываются в одной половине или четверти диапазона, происходит сдвиг влево с выводом битов наружу, что позволяет удерживать значения в пределах разрядной сетки процессора.
* **Вычислительная сложность.** На каждом шаге кодирования и декодирования выполняются операции умножения вещественных или больших целых чисел для пересчета границ с учетом кумулятивных вероятностей. Это делает арифметическое кодирование значительно более медленным по сравнению с кодом Хаффмана, где кодирование сводится к простому табличному поиску и побитовой записи.

### Чувствительность к ошибкам передачи

Абсолютная плотность упаковки информации в арифметическом коде оборачивается обратной стороной — **катастрофической чувствительностью к ошибкам в канале связи**.

Поскольку всё сообщение закодировано в виде *единого* вещественного числа (или слитной непрерывной битовой последовательности), искажение хотя бы одного бита при передаче по зашумленному каналу приводит к сдвигу результирующей точки на числовой оси. 

* При декодировании искаженного числа алгоритм на каком-то шаге попадет не в тот кумулятивный интервал.
* Ошибка в определении одного символа сдвигает границы текущего интервала так, что все последующие шаги декодирования интерпретируют поток совершенно иначе.
* Возникает лавинообразное распространение ошибки (error propagation): один поврежденный бит портит не только соответствующий символ, но и все последующие символы до конца сообщения (или до ближайшего маркера синхронизации, если таковой предусмотрен протоколом).

Для борьбы с этим эффектом в практических системах связи длинные потоки данных принудительно разбивают на независимые блоки фиксированного размера, каждый из которых кодируется отдельно, либо применяют совместное помехоустойчивое кодирование (например, коды Рида–Соломона поверх сжатых данных).

### Разобранный пример

#### Условие
Имеется алфавит из трех символов $A, B, C$ со стационарными вероятностями:
- $P(A) = 0{,}5$
- $P(B) = 0{,}3$
- $P(C) = 0{,}2$

Рассмотрим сообщение из трех символов, полученное в Примере 2 предыдущих разделов: **«АБВ»**. В процессе кодирования этого сообщения был сформирован итоговый числовой полуинтервал $[0{,}380000, 0{,}410000)$. В качестве результирующего кодового слова было выбрано число $0{,}385$, двоичное представление которого требует определенного числа бит.

Требуется:
1. Рассчитать энтропию источника $H(X)$.
2. Рассчитать среднюю длину кода на символ $L_{\text{avg}}$ для данного сообщения длиной $N = 3$ с учетом того, что для кодирования итогового интервала шириной $\Delta = 0{,}03$ потребовалось $L_{\text{total}} = 6$ бит (поскольку $2^{-6} = 0{,}015625 \le 0{,}03 < 0{,}03125 = 2^{-5}$).
3. Сравнить полученную среднюю длину с энтропией источника и сделать вывод об эффективности.

---

#### Ход рассуждений

1. **Расчет энтропии источника:**
   Используем формулу Шеннона для заданных вероятностей. Энтропия показывает нижний теоретический предел для любого посимвольного кодирования.
2. **Расчет средней длины кодового слова:**
   По формуле $L_{\text{avg}} = \frac{L_{\text{total}}}{N}$, где $L_{\text{total}} = 6$ бит, а $N = 3$ символа.
3. **Анализ результатов:**
   Сопоставим $L_{\text{avg}}$ с $H(X)$, оценив избыточность кодирования для столь короткой последовательности из-за эффекта округления.

---

#### Решение

**Шаг 1. Вычисление энтропии источника $H(X)$:**

Подставим значения вероятностей в формулу Шеннона:

$$H(X) = - \left( P(A) \log_2 P(A) + P(B) \log_2 P(B) + P(C) \log_2 P(C) \right)$$

Вычислим слагаемые по отдельности (используя формулу $\log_2 x = \frac{\ln x}{\ln 2}$):

- Для символа $A$: 
  $$0{,}5 \cdot \log_2(0{,}5) = 0{,}5 \cdot (-1{,}0000) = -0{,}5000 \text{ бит}$$

- Для символа $B$: 
  $$0{,}3 \cdot \log_2(0{,}3) = 0{,}3 \cdot \left(\frac{-1{,}20397}{0{,}69315}\right) = 0{,}3 \cdot (-1{,}73697) = -0{,}5211 \text{ бит}$$

- Для символа $C$: 
  $$0{,}2 \cdot \log_2(0{,}2) = 0{,}2 \cdot \left(\frac{-1{,}60944}{0{,}69315}\right) = 0{,}2 \cdot (-2{,}32193) = -0{,}4644 \text{ бит}$$

Сложим полученные значения с учетом знака минус:

$$H(X) = -(-0{,}5000 - 0{,}5211 - 0{,}4644) = -(-1{,}4855) = 1{,}4855 \text{ бит/символ}$$

**Шаг 2. Вычисление средней длины кодового слова $L_{\text{avg}}$:**

Для сообщения длиной $N = 3$ («АБВ») ширина финального интервала составила:

$$\Delta = P(A) \cdot P(B) \cdot P(C) = 0{,}5 \cdot 0{,}3 \cdot 0{,}2 = 0{,}0300$$

Определим минимальное число бит $L_{\text{total}}$, необходимое для того, чтобы зафиксировать этот интервал. Проверим степени двойки:
- $2^{-5} = 0{,}03125 > 0{,}0300$ (недостаточно точности, интервал может не поместиться).
- $2^{-6} = 0{,}015625 \le 0{,}0300$ (точности достаточно).

Таким образом, общая длина двоичного кода составляет $L_{\text{total}} = 6$ бит.

Вычислим среднюю длину на один символ:

$$L_{\text{avg}} = \frac{L_{\text{total}}}{N} = \frac{6 \text{ бит}}{3 \text{ символа}} = 2{,}0000 \text{ бит/символ}$$

**Шаг 3. Сравнение с энтропией:**

Сравним полученную среднюю длину с энтропией источника:
- Энтропия источника: $H(X) = 1{,}4855 \text{ бит/символ}$
- Средняя длина арифметического кода для данного короткого сообщения: $L_{\text{avg}} = 2{,}0000 \text{ бит/символ}$

Разница составляет $2{,}0000 - 1{,}4855 = 0{,}5145 \text{ бит/символ}$. Такая заметная избыточность объясняется **крайне малой длиной сообщения ($N = 3$)**: накладные расходы на выборку одной конечной точки интервала (округление до целого числа бит $L_{\text{total}} = 6$) распределяются всего на три символа. 

Если бы мы кодировали длинную последовательность из, например, $1000$ символов с теми же вероятностями, общая ширина интервала была бы $\Delta = (0{,}5)^500 \cdot (0{,}3)^300 \cdot (0{,}2)^200$, а средняя длина $L_{\text{avg}}$ вплотную приблизилась бы к значению $1{,}4855 \text{ бит/символ}$, продемонстрировав высокую эффективность метода.

---

#### Проверка

1. **Единицы измерения:** $H(X)$ и $L_{\text{avg}}$ выражены в битах на символ ($\text{бит/символ}$), общее количество бит $L_{\text{total}}$ — в битах. Размерности согласованы корректно.
2. **Правдоподобность:** Средняя длина кода $2{,}000$ больше энтропии $1{,}4855$, что соответствует фундаментальному закону теории информации (нельзя сжать данные сильнее энтропии). Для короткого сообщения из трех символов избыточность неизбежна из-за дискретности двоичной системы счисления. Вычисления логарифмов и деления проверены дважды.

Ответ: Энтропия источника $H(X) = 1{,}4855 \text{ бит/символ}$; средняя длина кодового слова для сообщения «АБВ» составляет $L_{\text{avg}} = 2{,}0000 \text{ бит/символ}$.

## Типичные ошибки

1. **Неверный порядок символов при построении кумулятивных интервалов.**
   * *Ошибка:* Изменение порядка следования символов в таблице вероятностей между этапами кодирования и декодирования.
   * *Почему возникает:* Забывчивость или отсутствие жесткой фиксации алфавита. Если кодер и декодер используют разный порядок сортировки символов (например, кодер сортирует по алфавиту, а декодер — по частоте), границы интервалов не совпадут, и декодирование выдаст «мусор».
   * *Как избежать:* Всегда фиксировать единый алфавит и строго упорядочивать его символы (например, по алфавиту или по убыванию вероятностей) до начала любых расчетов.

2. **Путаница с включением границ полуинтервала $[0, 1)$.**
   * *Ошибка:* Ошибочное предположение, что отрезок включает правую границу $1{,}0$ в расчетах кумулятивных сумм текущего шага.
   * *Почему возникает:* Непонимание природы полуинтервалов в математическом анализе. Интервал берется полуоткрытым $[L, H)$, чтобы избежать пересечения границ между соседними символами.
   * *Как избежать:* Помнить, что левая граница входит в интервал ($C_{\text{low}}$), а правая граница ($C_{\text{high}}$) является левой границей следующего символа. Проверка условия принадлежности числа $x$ всегда выполняется строгой слева и нестрогой справа: $\text{SubLow} \le x < \text{SubHigh}$.

3. **Нарушение точности вычислений (исчерпание разрядной сетки).**
   * *Ошибка:* Попытка закодировать длинное сообщение в ручном счете или простой программе на `float` без масштабирования.
   * *Почему возникает:* После каждых $10\text{--}20$ символов ширина интервала уменьшается в десятки раз. Тип `float` (32 бита) теряет точность уже после 7–8 знаков после запятой.
   * *Как избежать:* При реализации алгоритма на практике использовать тип `double` (64 бита), библиотеки длинной арифметики (`BigFloat`) либо реализовывать стандартную процедуру *ренормализации* (масштабирования) с выталкиванием старших битов.

4. **Забытая нормализация вероятностей.**
   * *Ошибка:* Использование набора вероятностей, сумма которых не равна ровно $1{,}0$ (например, $0{,}5 + 0{,}3 + 0{,}1 = 0{,}9$).
   * *Почему возникает:* Ошибки ввода исходных данных или округление сырых частот символов из текста.
   * *Как избежать:* Перед построением таблицы кумулятивных вероятностей всегда проверять условие $\sum p_i = 1{,}0$. Если сумма отличается из-за округления, скорректировать вероятность самого частого символа.

5. **Неправильный выбор конечной двоичной дроби из интервала.**
   * *Ошибка:* Выбор числа, лежащего на границе или за пределами финального интервала.
   * *Почему возникает:* Округление вещественного числа при переводе в двоичную систему с запасом в большую сторону.
   * *Как избежать:* Всегда брать середину финального интервала $\frac{\text{Low} + \text{High}}{2}$ или проверять двойное неравенство $\text{Low} \le x < \text{High}$ для выбранной двоичной дроби.

6. **Игнорирование передачи длины сообщения ($N$).**
   * *Ошибка:* Попытка бесконечного декодирования вещественного числа без остановки.
   * *Почему возникает:* Арифметическое кодирование в базовой формулировке выдает бесконечную или длинную точку на оси, и декодер «не знает», когда прекратить извлекать символы.
   * *Как избежать:* Передавать вместе с кодом общую длину сообщения $N$ либо использовать специальный служебный символ конца файла (EOF).

12. Какие обязательные условия должны выполняться для исходного распределения вероятностей символов алфавита перед построением таблицы кумулятивных интервалов?

## Задачи для самостоятельного решения

1. Дан алфавит из двух символов $\{X, Y\}$ с вероятностями $P(X) = 0{,}7$ и $P(Y) = 0{,}3$. Постройте таблицу кумулятивных вероятностей и выполните арифметическое кодирование последовательности **«XYX»**. Определите итоговый числовой интервал $[\text{Low}, \text{High})$.
2. Для алфавита и вероятностей из задачи 1 выполните арифметическое декодирование числа $x = 0{,}42$, если известна длина сообщения $N = 3$. Восстановите исходную последовательность символов.
3. Дан алфавит из трех символов $\{M, N, K\}$ с вероятностями: $P(M) = 0{,}6$, $P(N) = 0{,}3$, $P(K) = 0{,}1$. Постройте таблицу кумулятивных интервалов и закодируйте последовательность **«MNK»**.
4. Используя алфавит и вероятности из задачи 3 ($P(M) = 0{,}6$, $P(N) = 0{,}3$, $P(K) = 0{,}1$), выполните декодирование числа $x = 0{,}58$, если длина сообщения равна $N = 3$. Найдите исходную строку.
5. Рассчитайте теоретическую энтропию $H(X)$ источника сообщений из задачи 3 ($P(M) = 0{,}6$, $P(N) = 0{,}3$, $P(K) = 0{,}1$). Ответ выразите в битах на символ с точностью до четырех знаков после запятой.
6. Дан алфавит из четырех символов $\{1, 2, 3, 4\}$ с равными вероятностями $P(1) = P(2) = P(3) = P(4) = 0{,}25$. Закодируйте последовательность **«132»**. Чему равен итоговый интервал?
7. Вычислите энтропию $H(X)$ источника с равными вероятностями четырех символов из задачи 6 и сравните ее с длиной кода на символ, получаемого при арифметическом кодировании для длинного сообщения.
8. Для последовательности **«MNK»** из задачи 3 ширина финального интервала составила $\Delta = 0{,}0180$. Определите минимальное число бит $L_{\text{total}}$, необходимое для его кодирования, и вычислите среднюю длину кодового слова на символ $L_{\text{avg}}$ для $N = 3$.

## Ответы к задачам

1. Таблица: $X \in [0{,}0;\, 0{,}7)$, $Y \in [0{,}7;\, 1{,}0)$. Итоговый интервал для «XYX»: $[0{,}3430;\, 0{,}4459)$.
2. Декодированное сообщение для фигурирующего в условии числа $x = 0{,}42$ ($N=3$): **«XXY»**.
3. Таблица: $M \in [0{,}0;\, 0{,}6)$, $N \in [0{,}6;\, 0{,}9)$, $K \in [0{,}9;\, 1{,}0)$. Итоговый интервал для «MNK»: $[0{,}5220;\, 0{,}5400)$.
4. Декодированное сообщение для $x = 0{,}58$ ($N=3$): **«MKN»**.
5. Энтропия источника: $H(X) = 1{,}2955 \text{ бит/символ}$.
6. Таблица: $1 \in [0{,}0;\, 0{,}25)$, $2 \in [0{,}25;\, 0{,}5)$, $3 \in [0{,}5;\, 0{,}75)$, $4 \in [0{,}75;\, 1{,}0)$. Итоговый интервал для «132»: $[0{,}140625;\, 0{,}156250)$.
7. Энтропия $H(X) = 2{,}0000 \text{ бит/символ}$. Средняя длина арифметического кода для длинного сообщения в точности равна $\log_2(4) = 2{,}0000 \text{ бит/символ}$.
8. Минимальное число бит $L_{\text{total}} = 6$ бит (так как $2^{-6} = 0{,}015625 \le 0{,}0180 < 0{,}03125 = 2^{-5}$). Средняя длина кодового слова: $L_{\text{avg}} = \frac{6}{3} = 2{,}0000 \text{ бит/символ}$.

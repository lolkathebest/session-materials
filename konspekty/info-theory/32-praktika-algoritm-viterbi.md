## 1. Теоретические основы и алгоритм Витерби для жестких решений

### 1. Теоретические основы и алгоритм Витерби для жестких решений

При передаче информации по реальным каналам связи (например, радиоканалам или линиям беспроводной связи) сигнал подвергается воздействию шумов и помех. В результате на приемной стороне вместо исходной кодовой последовательности принимается искаженный сигнал. Задача помехоустойчивого декодирования заключается в том, чтобы по принятой последовательности символов восстановить переданную информационную последовательность с минимальной вероятностью ошибки.

В данном материале рассматривается алгоритм Витерби для сверточных кодов в Двоичном Симметричном Канале (ДСК, Binary Symmetric Channel, BSC) при принятии **жестких решений** (hard decision decoding). Жесткое решение означает, что демодулятор на приемной стороне принимает однозначное решение о значении каждого принятого бита ($0$ или $1$), преобразуя аналоговый сигнал в дискретный двоичный символ до начала работы декодера.

### Постановка задачи декодирования сверточного кода

Пусть на передающей стороне информационная последовательность длины $L$ бит поступает на вход сверточного кодера с параметрами $(n, k, K)$, где:
- $k$ — число входных информационных бит, подаваемых на кодер за один такт;
- $n$ — число выходных кодовых бит, формируемых кодером за один такт;
- Скорость кода составляет $R = \frac{k}{n}$;
- $K$ — длина памяти кодера (constraint length), определяющая число регистров сдвига. Длина кодового ограничения или глубина памяти по задержке равна $v = K - 1$.

Кодер представляет собой конечный автомат, состояние которого в дискретный момент времени $t$ определяется содержимым его ячеек памяти. Число возможных состояний такого автомата равно $S = 2^{v}$. 

Процесс работы кодера во времени можно представить в виде **решетчатой диаграммы** (trellis diagram). Решетка состоит из узлов, расположенных на вертикальных временных срезах $t = 0, 1, 2, \dots, L + v$, и ребер (ветвей), соединяющих узлы соседних моментов времени. Каждая ветвь соответствует переходу кодера из одного состояния в другое под воздействием входных информационных бит и порождает определенный набор из $n$ выходных бит.

На приемную сторону поступает последовательность из $L + v$ блоков по $n$ бит в каждом. Из-за шумов в канале принятая последовательность $\mathbf{Y}$ может отличаться от переданной кодовой последовательности $\mathbf{X}$. 

> **Определение.** Принцип максимального правдоподобия (Maximum Likelihood Decoding, MLD) в ДСК с жесткими решениями заключается в поиске такого пути в решетчатой диаграмме, которому соответствует кодовое слово, находящееся на минимальном расстоянии Хэмминга от принятой последовательности.

Поскольку полный перебор всех возможных путей в решетке требует экспоненциального роста вычислений $O(2^L)$, алгоритм Витерби решает эту задачу за линейное время $O(L \cdot 2^v)$, используя принцип динамического программирования.

### Метрика ветви и метрика пути

Для оценки степени соответствия принятых данных возможным путям в решетке вводятся две ключевые количественные меры: метрика ветви и метрика пути.

> **Определение.** Метрика ветви (branch metric, BM) — это расстояние Хэмминга между принятой на текущем такте $t$ парой (или блоком) из $n$ бит и ожидаемым выходом кодера (опорной кодовой комбинацией) для конкретного перехода из одного состояния в другое.

Пусть на такте $t$ приемник принял блок из $n$ бит $\mathbf{y}_t = (y_{t,1}, y_{t,2}, \dots, y_{t,n})$, а рассматриваемый переход в решетке порождает ожидаемый выходной блок $\mathbf{x}_t = (x_{t,1}, x_{t,2}, \dots, x_{t,n})$. Тогда метрика ветви для данного перехода вычисляется как:

$$BM(\mathbf{y}_t, \mathbf{x}_t) = \sum_{j=1}^{n} (y_{t,j} \oplus x_{t,j})$$

где $\oplus$ обозначает сложение по модулю 2 (исключающее ИЛИ), а результат равен числу несовпадающих позиций (расстоянию Хэмминга).

> **Определение.** Метрика пути (path metric, PM) для конкретного пути в решетке от начального момента времени $t = 0$ до текущего момента времени $t$ представляет собой сумму метрик ветвей, составляющих этот путь.

Если путь $\mathcal{P}_s$ до состояния в момент времени $t$ состоит из последовательности ветвей с метриками $BM_1, BM_2, \dots, BM_t$, то полная метрика пути выражается формулой:

$$PM_t(s) = \sum_{i=1}^{t} BM_i$$

Единицей измерения метрики пути и метрики ветви является **бит несоответствия** (или просто условные единицы расстояния Хэмминга). Метрика пути является накопительной: чем меньше значение $PM$, тем ближе данный путь к принятой последовательности, то есть тем выше правдоподобие этого пути.

### Операция «Сложение-Сравнение-Выбор» (Add-Compare-Select, ACS)

Алгоритм Витерби на каждом шаге $t$ выполняет в каждом узле решетки фундаментальную процедуру ACS, которая позволяет отсеветь маловероятные пути и сохранять только «выживающие» (survivor paths).

Рассмотрим некоторый узел (состояние) $S_j$ на временном срезе $t$. В этот узел могут входить несколько ветвей из предшествующих состояний момента времени $t-1$ (для сверточных кодов с $k=1$ в каждый узел входят ровно две ветви: одна из состояния, в которое переходят при входном бите $0$, а вторая — при входном бите $1$).

Шаги процедуры ACS для узла $S_j$ на шаге $t$:
1. **Сложение (Add):** К накопленной метрике пути каждого из предшествующих состояний $PM_{t-1}(S_{prev})$ прибавляется метрика ветви $BM$, соответствующая переходу из этого предшествующего состояния в целевое состояние $S_j$. Получаются кандидаты в новые метрики пути:
   
   $$PM_{candidate} = PM_{t-1}(S_{prev}) + BM(S_{prev} \to S_j)$$

2. **Сравнение (Compare):** Полученные значения метрик-кандидатов сравниваются между собой.
3. **Выбор (Select):** Выбирается тот путь, который имеет **минимальную** метрику пути. Этот путь объявляется *выживающим* (survivor path) для данного узла, а его метрика присваивается текущему узлу $S_j$:
   
   $$PM_𝘁(S_j) = \min_{\text{все входящие пути}} \left( PM_{t-1}(S_{prev}) + BM \right)$$

Второй путь (или пути, если их метрики больше минимальной) навсегда удаляется из дальнейшего рассмотрения, что радикально сокращает вычислительную сложность.

#### Правило разрешения коллизий (равенства метрик)
На практике нередко возникают ситуации, когда метрики двух конкурирующих путей, входящих в один узел, оказываются абсолютно равными. 
- *Что делать при равенстве:* В академических задачах и большинстве стандартов выбор делается в пользу пути, пришедшего из состояния с меньшим числовым индексом, либо выбирается ветвь, соответствующая определенному информационному биту (например, биту $0$). Главное требование — следовать выбранному правилу последовательно на протяжении всего расчета.

### Ограничения длины пути и роль хвостовых бит

Сверточный кодер начинает работу из нулевого состояния. Чтобы процесс декодирования завершился корректно и однозначно, необходимо принудительно вернуть кодер в нулевое состояние в конце передачи. 

Для этого после передачи информационной последовательности длины $L$ на вход кодера подают $v$ нулевых бит ($v = K - 1$):
- Эти биты называют **хвостовыми битами** (tail bits).
- На решетчатой диаграмме последние $v$ тактов переходы осуществляются строго в нулевое состояние.
- В результате на конечном временном срезе $t = L + v$ ненулевые метрики остаются только у нулевого состояния, что задает единственную и точную точку старта для обратного хода декодера.

Если хвостовые биты не передаются (потоковая передача без разрыва сеанса), используется метод **усечения решетки** (truncation depth). В этом случае обратный проход начинают из состояния с минимальной метрикой пути на текущем срезе $t$, отступая назад на фиксированную глубину (обычно равную $5 \div 10$ длинам памяти кодера $K$).

### Разобранный пример

**Условие задачи:**
Рассмотрим сверточный кодер с параметрами $(2, 1, 3)$. Это означает:
- Число входов: $k = 1$ (на каждом такте поступает 1 информационный бит).
- Число выходов: $n = 2$ (на каждом такте формируется 2 кодовых бита).
- Длина памяти: $K = 3$, следовательно, число элементов памяти в регистре сдвига равно $v = K - 1 = 2$.
- Число состояний кодера: $S = 2^v = 2^2 = 4$ состояния, обозначаемые как двоичные числа от $00$ до $11$ (или десятичные $0, 1, 2, 3$).

Пусть на приемную сторону на некотором такте $t$ поступила принятая кодовая пара:
$$\mathbf{y}_t = (1, 0)$$

Требуется определить метрики ветвей для всех возможных переходов решетки на данном такте.

#### Решение в общем виде и по шагам

1. **Структура состояний и переходов кодера $(2, 1, 3)$:**
   Состояние кодера в момент времени $t$ определяется содержимым двух ячеек памяти: $S_t = (s_1, s_2)$, где $s_1$ — первый триггер, $s_2$ — второй триггер. Возможные состояния:
   - Состояние $0$: `00`
   - Состояние $1$: `01`
   - Состояние $2$: `10`
   - Состояние $3$: `11`

   При поступлении нового информационного бита $u_t \in \{0, 1\}$ содержимое регистра сдвига обновляется по правилу сдвига вправо, а выходные биты $(x_{t,1}, x_{t,2})$ формируются с помощью генераторных полиномов (например, для стандартного кода этого типа: $g_1 = 111_2$ и $g_2 = 101_2$, что означает сложение по модулю 2 текущего входа и содержимого ячеек памяти).

   Составим полную таблицу переходов кодера (структурную таблицу):

| Текущее состояние $S_{t-1}$ | Входной бит $u_t$ | Новое состояние $S_t$ | Выходные биты $(x_1, x_2)$ |
| :---: | :---: | :---: | :---: |
| `00` ($0$) | $0$ | `00` ($0$) | `00` |
| `00` ($0$) | $1$ | `10` ($2$) | `11` |
| `01` ($1$) | $0$ | `00` ($0$) | `11` |
| `01` ($1$) | $1$ | `10` ($2$) | `00` |
| `10` ($2$) | $0$ | `01` ($1$) | `10` |
| `10` ($2$) | $1$ | `11` ($3$) | `01` |
| `11` ($3$) | $0$ | `01` ($1$) | `01` |
| `11` ($3$) | $1$ | `11` ($3$) | `10` |

2. **Вычисление метрики ветви для каждого перехода:**
   Принятая пара битов на данном такте: $\mathbf{y}_t = (1, 0)$.
   Метрика ветви $BM$ вычисляется как расстояние Хэмминга между принятой парой $(1, 0)$ и ожидаемым выходом $(x_1, x_2)$ для каждого из 8 возможных переходов:
   
   $$BM = (1 \oplus x_1) + (0 \oplus x_2)$$

   Произведем расчет для каждой строки таблицы переходов:
   - Переход из `00` в `00` при входе $0$: выход `00`. $BM = (1 \oplus 0) + (0 \oplus 0) = 1 + 0 = 1$.
   - Переход из `00` в `10` при входе $1$: выход `11`. $BM = (1 \oplus 1) + (0 \oplus 1) = 0 + 1 = 1$.
   - Переход из `01` в `00` при входе $0$: выход `11`. $BM = (1 \oplus 1) + (0 \oplus 1) = 0 + 1 = 1$.
   - Переход из `01` в `10` при входе $1$: выход `00`. $BM = (1 \oplus 0) + (0 \oplus 0) = 1 + 0 = 1$.
   - Переход из `10` в `01` при входе $0$: выход `10`. $BM = (1 \oplus 1) + (0 \oplus 0) = 0 + 0 = 0$.
   - Переход из `10` в `11` при входе $1$: выход `01`. $BM = (1 \oplus 0) + (0 \oplus 1) = 1 + 1 = 2$.
   - Переход из `11` в `01` при входе $0$: выход `01`. $BM = (1 \oplus 0) + (0 \oplus 1) = 1 + 1 = 2$.
   - Переход из `11` в `11` при входе $1$: выход `10`. $BM = (1 \oplus 1) + (0 \oplus 0) = 0 + 0 = 0$.

#### Сводная таблица результатов расчета метрик ветвей

| Исходное состояние | Новое состояние | Входной бит | Ожидаемый выход | Принятый сигнал | Метрика ветви ($BM$) |
| :---: | :---: | :---: | :---: | :---: | :---: |
| `00` | `00` | $0$ | `00` | `10` | $1$ |
| `00` | `10` | $1$ | `11` | `10` | $1$ |
| `01` | `00` | $0$ | `11` | `10` | $1$ |
| `01` | `10` | $1$ | `00` | `10` | $1$ |
| `10` | `01` | $0$ | `10` | `10` | **$0$** |
| `10` | `11` | $1$ | `01` | `10` | $2$ |
| `11` | `01` | $0$ | `01` | `10` | $2$ |
| `11` | `11` | $1$ | `10` | `10` | **$0$** |

#### Проверка и анализ
- Полученные значения метрик ветвей представляют собой целые неотрицательные числа в диапазоне от $0$ до $2$ (так как длина блока $n = 2$, максимальное расстояние Хэмминга равно $2$).
- Значение $BM = 0$ получено для переходов, где ожидаемый выход совпал с принятым сигналом `10` абсолютно точно (это переходы из состояния `10` при входе $0$ и из состояния `11` при входе $1$). Это логично, поскольку выход `10` совпадает с принятым вектором.
- Вычисления выполнены корректно, единицы измерения метрик — биты ошибок (несоответствий).

Ответ: Метрики ветвей для переходов из состояний (`00`, `01`, `10`, `11`) равны соответственно $\{1, 1\}$, $\{1, 1\}$, $\{0, 2\}$ и $\{2, 0\}$.

## 2. Декодирование коротких последовательностей: пошаговый расчет решетки

### Инициализация метрик путей и подготовка к прямому ходу алгоритма Витерби

Прежде чем приступить к построению решетки и вычислению метрик, необходимо строго зафиксировать начальные условия процесса декодирования. В теории сверточных кодов принято считать, что передача информационной последовательности начинается из нулевого состояния кодера. Это достигается либо принудительной установкой регистров сдвига кодера в нулевое состояние перед началом работы, либо добавлением специальных хвостовых (нулевых) битов в конце сообщения.

Пусть кодер имеет длину памяти $K$, тогда число ячеек памяти равно $\nu = K - 1$. Количество состояний решетки определяется как $S = 2^\nu$. Каждое состояние кодера в момент времени $t$ кодируется двоичным вектором содержимого регистров сдвига.

В начальный момент времени $t = 0$ кодер гарантированно находится в нулевом состоянии. Это означает, что степень уверенности в нахождении системы в нулевом состоянии абсолютна, а в любых других состояниях — нулевая. В терминологии алгоритма Витерби это выражается через инициализацию метрик путей (Path Metric, PM):

$$PM_0(s) = \begin{cases} 0, & \text{если } s = 00\dots0 \\ \infty, & \text{для всех остальных состояний } s \end{cases}$$

На практике вместо бесконечности в программной реализации или ручном счете используют достаточно большое число, заведомо превышающее максимально возможную суммарную метрику (например, $999$ или специальный флаг недоступности узла).

### Построение графа переходов и шаги решетки

Решетчатая диаграмма ( trellis diagram ) представляет собой развертку конечного автомата во времени. По горизонтальной оси откладывается дискретное время $t$ от $t = 0$ до $t = L + \nu$, где $L$ — длина информационной последовательности (в битах), а $\nu$ — степень памяти кодера (число добавочных хвостовых нулей). По вертикальной оси располагаются все возможные состояния кодера $s \in \{0, 1, \dots, 2^\nu - 1\}$.

Для каждого такта времени $t$ от $t = 1$ до $t = L + \nu$ выполняются следующие операции для каждого узла (состояния) решетки:
1. **Определение входящих ветвей:** выясняется, из каких состояний предыдущего момента времени $t-1$ можно перейти в текущее состояние $s$ при подаче информационного бита $u_t \in \{0, 1\}$. Для каждого такого перехода из состояния $s_{prev}$ в состояние $s_{next}$ кодер вырабатывает ожидаемый кодовый вектор (символы ветви).
2. **Вычисление метрик ветвей (Branch Metric, BM):** для каждой входящей ветви вычисляется расстояние Хэмминга между принятой в текущем такте кодовой парой (или блоком) и ожидаемым кодовым вектором, сформированным кодером.
3. **Операция Сложение-Сравнение-Выбор (Add-Compare-Select, ACS):**
   - **Сложение:** к метрике пути предыдущего состояния $PM_{t-1}(s_{prev})$ прибавляется метрика соответствующей ветви $BM$:
     $$\text{Candidate\_PM} = PM_{t-1}(s_{prev}) + BM$$
   - **Сравнение:** если в текущее состояние $s_{next}$ ведут две ветви (что характерно для сверточных кодов с кодовой скоростью $R = 1/n$, где из каждого состояния исходят две ветви и в каждое состояние входят две ветви), сравниваются значения $\text{Candidate\_PM}$ для обоих путей.
   - **Выбор:** выбирается путь с минимальной суммарной метрикой (минимальным расстоянием Хэмминга). Полученное значение становится новой метрикой пути для текущего состояния:
     $$PM_t(s_{next}) = \min \big( PM_{t-1}(s_{prev}^{(1)}) + BM^{(1)}, \, PM_{t-1}(s_{prev}^{(2)}) + BM^{(2)} \big)$$
4. **Фиксация указателя (предшественника):** в узле решетки сохраняется информация о том, из какого состояния $s_{prev}$ пришел выживающий путь. Эта информация необходима для последующего обратного трассирования (backtracking). Если метрики путей-кандидатов равны, фиксируется правило разрешения конфликтов (например, выбирается путь, соответствующий информационному биту $0$, или путь с меньшим номером предыдущего состояния).

### Полный разбор примера: декодирование для кода (2, 1, 2)

#### 1. Условие задачи и параметры кодера
Рассмотрим сверточный код со следующими параметрами:
- Кодовая скорость: $R = \frac{k}{n} = \frac{1}{2}$ (на 1 информационный бит на выходе формируется $2$ кодовых бита).
- Длина памяти: $K = 3$.
- Число ячеек памяти (степень памяти): $\nu = K - 1 = 3 - 1 = 2$.
- Число состояний кодера: $S = 2^\nu = 2^2 = 4$. Состояния обозначим двоичными кодами содержимого регистров сдвига: $00$, $01$, $10$, $11$.
- Порождающие многочлены (в восьмеричной или двоичной записи):
  - $g_1 = 111_2$ (что соответствует соединениям с входа и ячеек памяти: $1 \cdot x^2 + 1 \cdot x^1 + 1 \cdot x^0$)
  - $g_2 = 101_2$ ($1 \cdot x^2 + 0 \cdot x^1 + 1 \cdot x^0$)
- Принятая зашумленная последовательность из $L + \nu = 4$ шагов (предполагаем $L = 2$ информационных бита и $\nu = 2$ хвостовых бита):
  $$\text{Принято} = \big( (1, 1), \, (1, 0), \, (0, 0), \, (1, 1) \big)$$

#### 2. Структура переходов кодера
Для построения решетки вспомним правила переходов кодера с $\nu = 2$. Состояние кодера задается двухбитным регистром $(s_1, s_2)$, где $s_1$ — самый старый бит в регистре, $s_2$ — самый молодой. При поступлении информационного бита $u$ новое состояние определяется как $(u, s_1)$, а выходные биты $(c_1, c_2)$ вычисляются по формулам свертки:
- $c_1 = u \oplus s_1 \oplus s_2$ (по модулю 2 для многочлена $111$)
- $c_2 = u \oplus s_2$ (по модулю 2 для многочлена $101$)

Составим таблицу всех возможных переходов в кодере:

| Текущее состояние $(s_1 s_2)$ | Информационный бит $u$ | Следующее состояние $(u \, s_1)$ | Выходные биты $(c_1 c_2)$ |
| :---: | :---: | :---: | :---: |
| $00$ | $0$ | $00$ | $00$ |
| $00$ | $1$ | $10$ | $11$ |
| $01$ | $0$ | $00$ | $11$ |
| $01$ | $1$ | $10$ | $00$ |
| $10$ | $0$ | $01$ | $10$ |
| $10$ | $1$ | $11$ | $01$ |
| $11$ | $0$ | $01$ | $01$ |
| $11$ | $1$ | $11$ | $10$ |

Из таблицы видно, что в каждое состояние ведут ровно две ветви от двух разных предыдущих состояний.

## 3. Обратный проход и восстановление информационной последовательности

### 1. Завершение прямого хода решетки и хвостовые биты

Прямой ход алгоритма Витерби, рассмотренный на предыдущих этапах, завершается в момент времени $t = L + v$, где $L$ — длина информационной последовательности (в битах), а $v = K - 1$ — степень кодового многочлена (или длина памяти кодера, определяемая как число ячеек сдвигового регистра за исключением текущей). 

Чтобы декодер мог однозначно завершить процесс поиска и зафиксировать правильное конечное состояние, на передающей стороне в конец информационной последовательности всегда добавляется $v$ нулевых бит. Эти биты называют *хвостовыми* (tail bits). Их назначение — принудительно перевести кодер из любого текущего состояния обратно в фиксированное начальное (нулевое) состояние $S_0 = 00\dots0$. 

> **Определение.** Хвостовые биты (tail bits) — это добавочная последовательность из $v$ нулевых символов, которая дописывается в конец информационного блока перед кодированием с целью гарантированного возврата кодера в нулевое состояние.

Пусть, например, используется сверточный кодер с параметрами $(n, k, K) = (2, 1, 3)$. Здесь кодовая скорость равна $R = \frac{1}{2}$, длина памяти $K = 3$, а степень кодового многочлена (число ячеек памяти) составляет $v = K - 1 = 2$. Если информационная последовательность имеет длину $L = 3$ бита, то для ее передачи потребуется передать $L$ информационных бит и $v = 2$ хвостовых бита. Общая длина закодированной последовательности составит:

$$N_{\text{тактов}} = L + v = 3 + 2 = 5 \text{ шагов (тактов)}$$

На последнем такте $t = 5$ после приема и обработки хвостовых нулей все выживающие пути в решетчатой диаграмме должны сойтись в единственном конечном состоянии — нулевом состоянии $S_0 = 00$. Если в канале связи действовали сильные помехи, допускается ситуация, когда метрики в нулевом и некоторых других состояниях на финальном шаге могут различаться, однако теоретически правильный путь обязан завершиться в состоянии $S_0$.

### 2. Правило старта обратного трассирования

После завершения прямого хода для всех тактов от $t = 1$ до $t = L + v$ в каждом узле решетки хранятся два параметра:
1. Метрика пути $PM(S, t)$ — суммарное расстояние Хэмминга от начала до данного узла.
2. Указатель предшественника (backpointer) — информация о том, из какого состояния предыдущего такта $t-1$ пришел выживающий путь в текущее состояние $S$ на такте $t$.

Процедура обратного трассирования (backtracking) начинает свою работу с конечного момента времени $t = L + v$. 

> **Определение.** Обратное трассирование (backtracking) — это процедура восстановления исходной информационной последовательности путем последовательного движения по решетчатой диаграмме в обратном направлении: от момента окончания приема блока $t = L + v$ к моменту старта $t = 0$ с использованием сохраненных указателей предшественников.

Правило выбора стартовой точки для обратного прохода формулируется следующим образом:
- Если передача велась с использованием хвостовых бит, то стартовым состоянием для обратного прохода на шаге $t = L + v$ выбирается **нулевое состояние** $S_0 = 00\dots0$, так как кодер гарантированно закончил работу в нем.
- Если хвостовые биты не использовались (непрерывный поток или усеченная решетка), то в качестве стартового выбирается состояние $S_{\text{opt}}$ на шаге $t = L + v$, которое обладает **минимальной метрикой пути**:

$$S_{\text{opt}} = \arg\min_{S} PM(S, L + v)$$

В случае возникновения ситуации, когда несколько различных состояний на финальном шаге имеют одинаковые минимальные метрики путей, выбирается состояние с наименьшим двоично-десятичным номером (или то состояние, чей путь на предшествующем шаге обладал лучшей метрикой). Это соглашение исключает неопределенность.

---

### 3. Пошаговый процесс восстановления информационной последовательности

Имея стартовую точку в момент времени $t = L + v$, мы выполняем следующие шаги для восстановления информационной последовательности:

1. Фиксируем текущее состояние $S^{(t)}$ на шаге $t$.
2. Обращаемся к таблице указателей (предшественников) для данного состояния и момента времени $t$. Указатель сообщает, из какого состояния $S^{(t-1)}$ был совершен переход.
3. Переходим в состояние $S^{(t-1)}$ на шаг назад ($t \leftarrow t - 1$).
4. Определяем информационный бит $u_t$, который спровоцировал данный переход. Структура сверточного кодера устроена так, что переход из состояния $S^{(t-1)}$ в состояние $S^{(t)}$ всегда однозначно определяется входным битом $u_t$ (обычно переход сверху соответствует входному нулю $u_t = 0$, а снизу — единице $u_t = 1$, либо наоборот, согласно принятой схеме нумерации состояний).
5. Повторяем шаги 2–4 до тех пор, пока не достигнем начального момента времени $t = 0$.
6. Полученная последовательность информационных бит записывается в прямом порядке от $t = 1$ до $t = L + v$ (поскольку трассирование идет назад, биты фиксируются в обратном порядке: от последнего к первому, а затем инвертируются).

### 4. Полный разобранный пример: декодирование методом обратного прохода

#### Условие задачи
Пусть задан сверточный кодер с параметрами $(2, 1, 2)$, где длина памяти $K = 2$, степень $v = K - 1 = 1$. Информационная последовательность имеет длину $L = 3$ бита, плюс $v = 1$ хвостовой бит. Общая длина передаваемой последовательности составляет $L + v = 3 + 1 = 4$ такта.

Порождающие многочлены кодера:
- $g_1 = 11_8$ (в двоичном виде: $111_2$, то есть связи с нулевой, первой и второй ячейками регистра, но для $K=2$ регистр имеет 1 ячейку памяти и вход, итого 2 бита памяти: $g_1 = 11_2$, выходы формируются как суммы). 
Для однозначности примем стандартный кодер с полиномами:
  - Первый выход: $g_1 = 1 + D^2$ (или в двоичной записи матрица соединений `101`, что соответствует $1 \cdot d_0 + 0 \cdot d_1 + 1 \cdot d_2$, или проще для $K=2$: $g_1 = 11_2$, $g_2 = 01_2$ — используем заданные в плане курса полиномы: пусть кодер имеет выходы, определяемые структурой, где переходы из состояния в состояние генерируют конкретные пары символов).

Предположим, что в результате работы прямого хода алгоритма Витерби для принятой последовательности **$(01, 11, 10, 00)$** была заполнена таблица выживающих путей и указателей предшественников. 

Ниже приведена таблица состояний решетки для каждого такта $t$ от $0$ до $4$, где для каждого состояния указана пара значений: `(МетрикаПути / СостояниеПрешественник / ВходнойБит)`:

| Такт $t$ | Состояние $S = 0$ | Состояние $S = 1$ |
| :---: | :---: | :---: |
| **$t = 0$** | `(0 / — / —)` | `(inf / — / —)` |
| **$t = 1$** | `(1 / S0 / 0)` | `(1 / S0 / 1)` |
| **$t = 2$** | `(1 / S0 / 0)` | `(2 / S1 / 1)` |
| **$t = 3$** | `(2 / S0 / 0)` | `(1 / S1 / 1)` |
| **$t = 4$** | `(2 / S0 / 0)` | `(3 / S1 / 1)` |

*(Примечание: в данном примере состояния обозначаются одним битом состояния $S \in \{0, 1\}$, так как $v = 1$. Состояние кодера на шаге $t$ совпадает со значением бита в ячейке памяти).*

#### Ход рассуждений и обратный проход

1. **Определение стартовой точки ($t = 4$):**
   Поскольку использовался один хвостовой бит, на финальном такте $t = 4$ кодер обязан находиться в нулевом состоянии. Проверяем метрики в строке $t = 4$:
   - Состояние $S = 0$: метрика равна $2$.
   - Состояние $S = 1$: метрика равна $3$.
   
   Минимальная метрика достигается в состоянии $S = 0$. Это подтверждает корректность приема и возврата в нулевое состояние. Стартуем обратное трассирование из узла **$S^{(4)} = 0$**.

2. **Шаг назад от $t = 4$ к $t = 3$:**
   - Находимся в состоянии $S^{(4)} = 0$.
   - Смотрим указатель предшественника для состояния $0$ на такте $4$: путь пришел из состояния $S^{(3)} = 0$, а породивший этот переход информационный бит равен $u_4 = 0$.
   - Запоминаем бит: $u_4 = 0$ (это хвостовой бит).
   - Текущее состояние становится равным $S^{(3)} = 0$.

3. **Шаг назад от $t = 3$ к $t = 2$:**
   - Находимся в состоянии $S^{(3)} = 0$.
   - Смотрим указатель предшественника для состояния $0$ на такте $3$: путь пришел из состояния $S^{(2)} = 0$, информационный бит равен $u_3 = 0$.
   - Запоминаем бит: $u_3 = 0$.
   - Текущее состояние становится равным $S^{(2)} = 0$.

4. **Шаг назад от $t = 2$ к $t = 1$:**
   - Находимся в состоянии $S^{(2)} = 0$.
   - Смотрим указатель предшественника для состояния $0$ на такте $2$: путь пришел из состояния $S^{(1)} = 0$, информационный бит равен $u_2 = 0$.
   - Запоминаем бит: $u_2 = 0$.
   - Текущее состояние становится равным $S^{(1)} = 0$.

5. **Шаг назад от $t = 1$ к находке старта ($t = 0$):**
   - Находимся в состоянии $S^{(1)} = 0$.
   - Указатель говорит, что путь пришел из начального состояния $S^{(0)} = 0$, информационный бит равен $u_1 = 0$.
   - Запоминаем бит: $u_1 = 0$.

Собранная в ходе обратного трассирования последовательность бит (в обратном порядке от $t=4$ к $t=1$): $(u_4, u_3, u_2, u_1) = (0, 0, 0, 0)$. Разворачиваем ее в правильном временном порядке:
- Информационные биты: $u_1 = 0$, $u_2 = 0$, $u_3 = 0$.
- Хвостовой бит: $u_4 = 0$.

#### Проверка правильности и оценка исправляющей способности

Чтобы убедиться в правильности декодирования, подставим полученную информационную последовательность $(0, 0, 0)$ вместе с хвостовым битом $(0)$ обратно в модель сверточного кодера:
1. Прогоняем биты $(0, 0, 0, 0)$ через кодер.
2. Получаем ожидаемую кодовую последовательность.
3. Сравниваем ее с исходно принятой зашумленной последовательностью `(01, 11, 10, 00)` путем подсчета суммарного расстояния Хэмминга.

Декодер Витерби является алгоритмом максимального правдоподобия (Maximum Likelihood Decoding, MLD). В двоичном симметричном канале с вероятностью ошибки на бит $p < 0{,}5$ декодер Витерби минимизирует вероятность ошибки на блок, выбирая тот путь в решетке, который имеет минимальное суммарное расстояние Хэмминга до принятой последовательности. 

Оценка общего числа ошибок, исправленных декодером, определяется через *мощность свободного расстояния кода* $d_{\text{free}}$. Декодер Витерби способен исправить любые пакеты ошибок, суммарное число искажений в которых на длине пути меньше или равно:

$$t_{\text{corr}} = \left\lfloor \frac{d_{\text{free}} - 1}{2} \right\rfloor$$

Для нашего кода с параметрами $(2, 1, 2)$ свободное расстояние составляет $d_{\text{free}} = 5$, следовательно, декодер гарантированно исправляет до $\lfloor (5-1)/2 \rfloor = 2$ ошибок на кодовое ограничение.

```
Ответ: Информационная последовательность: 000, хвостовой бит: 0.
```

## 4. Экзаменационные задачи повышенной сложности

### Особенности декодирования потоковых данных и неопределенное конечное состояние

При классическом блочном подходе к сверточному кодированию в конец информационной последовательности длины $L$ добавляют $v$ нулевых бит (где $v = K - 1$ — длина памяти кодера, а $K$ — кодовое ограничение). Эти хвостовые биты принудительно переводят конечный автомат кодера в фиксированное нулевое состояние $S_0 = 00\dots0$. Это гарантирует, что на последнем шаге решетчатой диаграммы все выживающие пути сойдутся в одном известном узле, откуда и начинается однозначный обратный проход.

Однако в реальных телекоммуникационных системах (например, в стандартах связи реального времени) передача ведется непрерывными потоками (streaming data). Информационная последовательность может быть бесконечной или разбитой на очень длинные кадры, причем принудительный сброс кодера нулями в конце каждого кадра снижает эффективную скорость передачи и разрывает поток. В таких сценариях конечное состояние кодера после передачи информационной последовательности неизвестно.

> **Определение.** Глубина усечения (truncation depth, $D$) — это фиксированное число шагов решетки назад от текущего момента времени, используемое для принятия решения о декодировании самого раннего из рассматриваемых информационных символов в условиях неизвестного конечного состояния.

При потоковом декодировании алгоритм Витерби работает следующим образом:
1. Прямой ход решетки продолжается неограниченно (или до конца текущего блока).
2. На каждом шаге $t$ для каждого состояния вычисляются метрики путей и выбираются выжившие пути с помощью операции ACS (Add-Compare-Select).
3. Из-за свойства сходимости путей (path convergence) в сверточных решетках, все выжившие пути на достаточно большой глубине назад $D$ почти всегда сходятся к единому предку. 
4. Оптимальная эмпирическая глубина усечения для большинства стандартных кодов составляет $D \approx (4 \div 5) \cdot K$, где $K$ — кодовое ограничение. При такой глубине вероятность того, что расхождение путей начнется раньше, пренебрежимо мала.
5. На каждом шаге $t$ декодер фиксирует решение для информационного бита, соответствующего самому первому узлу в окне глубины усечения $t - D$, и выдает его в выходной поток, сдвигая окно вперед.

### Разрешение ситуаций с равенством метрик путей

В процессе выполнения операции сравнения в узлах решетки (ACS) может возникнуть ситуация, когда две разные ветви, входящие в один и тот же узел состояния на шаге $t$, имеют абсолютно одинаковые метрики путей. 

> **Определение.** Коллизия метрик (tie) — это ситуация равенства метрик путей, сходящихся в одном узле решетки:
> $$PM^{(t)}(S_j) = PM^{(t)}(S_m)$$
> при поступлении из разных предшествующих состояний.

Поскольку метрика пути представляет собой суммарное расстояние Хэмминга, равенство метрик означает, что оба кандидата в равной степени удалены от принятой последовательности. В программной и аппаратной реализации алгоритма Витерби необходимо строгое правило разрешения коллизий, чтобы декодер был детерминированным (выдавал одинаковый результат при повторной обработке).

Основные правила разрешения равенства метрик:
1. **Правило меньшего индекса (статическое):** выбирается путь, пришедший из состояния с меньшим числовым индексом (или соответствующий информационному биту $0$, если ветви соответствуют разным битам).
2. **Случайный выбор (рандомизация):** выбор фиксируется псевдослучайным образом (применяется редко, так как нарушает воспроизводимость отладки).
3. **Ветвление по дополнительному метрическому критерию:** анализ надежности на предыдущих шагах (например, сравнение запаса по метрикам для альтернативных путей).

В ручных расчетах экзаменационного уровня при возникновении равенства метрик студент обязан явно зафиксировать факт коллизии в решении, указать выбранный путь (например, «в силу равенства метрик выбираем путь из состояния с меньшим номером») и продолжать расчет строго по выбранному варианту.

### Расчет энергетического выигрыша от кодирования

Главная цель применения сверточных кодов и алгоритма Витерби — повышение надежности передачи данных в зашумленном канале при сохранении или уменьшении требуемой мощности передатчика.

> **Определение.** Выигрыш от кодирования (coding gain, $G_c$) — это разница (в децибелах) между отношениями сигнал/шум на бит ($E_b/N_0$), необходимыми для достижения заданной вероятности ошибки на бит ($P_b$) для несокодированной системы и системы со сверточным кодированием.

Пусть задана требуемая вероятность ошибки на бит, например $P_b = 10^{-5}$.
1. Для несокодированной передачи в двоичном симметричном канале (ДСК) с гауссовским шумом (BPSK/AWGN) зависимость вероятности ошибки имеет вид:
   $$P_{b,\text{uncod}} = Q\left(\sqrt{\frac{2 E_b}{N_0}}\right)$$
   где $Q(x)$ — функция Q-статистики (интеграл вероятности). Находим требуемое значение $(E_b/N_0)_{\text{uncod}}$.
2. Для сверточного кода с кодовой скоростью $R = k/n$ и кодовым расстоянием свободного члена $d_{\text{free}}$ вероятность ошибки при максимальном правдоподобном декодировании (граница Юнга) оценивается как:
   $$P_{b,\text{cod}} \approx \sum_{d=d_{\text{free}}}^{\infty} c_d Q\left(\sqrt{2 R d \frac{E_b}{N_0}}\right)$$
   где $c_d$ — весовые коэффициенты ошибок (число путей веса $d$).
3. Выигрыш от кодирования вычисляется как:
   $$G_c = \left(\frac{E_b}{N_0}\right)_{\text{uncod}} - \left(\frac{E_b}{N_0}\right)_{\text{cod}} \quad [\text{дБ}]$$

Физический смысл выигрыша от кодирования заключается в том, что сверточный код позволяет снизить требования к мощности передатчика в несколько раз (или увеличить дальность связи) при той же верности приема. При этом эффективная скорость передачи падает в $R$ раз, что требует расширения полосы пропускания канала.

### Полный разбор комплексной задачи экзаменационного уровня

- Такт $t = 3$: принятая пара $\mathbf{r}_3 = (11)$
- Такт $t = 4$: принятая пара $\mathbf{r}_4 = (00)$

Метрика ветви (branch metric, BM) вычисляется как расстояние Хэмминга между принятой парой бит $\mathbf{r}_t$ и ожидаемой выходной парой на переходе.

##### Шаг 1 ($t = 1$, принята пара $10$):
Вычисляем метрики ветвей из возможных состояний:
- Из $S_0 (00)$ в $S_0 (00)$ (вход $0$), выход $00$: $\text{BM} = d_H((10), (00)) = 1 + 0 = 1$.
- Из $S_0 (00)$ в $S_2 (10)$ (вход $1$), выход $11$: $\text{BM} = d_H((10), (11)) = 0 + 1 = 1$.
- Из остальных состояний ($S_1, S_2, S_3$) переходов в $t = 1$ нет (их метрики пути равны $\infty$).

Вычисляем новые метрики путей ($PM^{(1)}$):
- Для $S_0$: приходит только из $S_0$ (вход $0$). $PM^{(1)}(00) = PM^{(0)}(00) + 1 = 0 + 1 = 1$. Предшественник: $S_0$.
- Для $S_1$: никто не приходит. $PM^{(1)}(01) = \infty$.
- Для $S_2$: приходит только из $S_0$ (вход $1$). $PM^{(1)}(10) = PM^{(0)}(00) + 1 = 0 + 1 = 1$. Предшественник: $S_0$.
- Для $S_3$: никто не приходит. $PM^{(1)}(11) = \infty$.

Состояние путей на шаге $t = 1$:
- $PM^{(1)}(00) = 1$ (предш. $S_0$)
- $PM^{(1)}(01) = \infty$
- $PM^{(1)}(10) = 1$ (предш. $S_0$)
- $PM^{(1)}(11) = \infty$

Вычисляем метрики путей для переходов из состояний с конечными метриками ($S_0$ и $S_2$):

1. Узел $S_0 (00)$ на шаге 2:
   - Приходит из $S_0$ (вход $0$, выход $00$): $\text{BM} = d_H((01), (00)) = 1$. Путь: $1 + 1 = 2$.
   - Приходит из দী $S_1$ (нет пути, метрика $\infty$).
   - Выбор: единственный путь из $S_0 \to S_0$ с метрикой $2$.

2. Узел $S_1 (01)$ на шаге 2:
   - Приходит из $S_2$ (вход $0$, выход $10$): $\text{BM} = d_H((01), (10)) = 1 + 1 = 2$. Путь: $PM^{(1)}(10) + 2 = 1 + 2 = 3$.
   - Выбор: $PM^{(2)}(01) = 3$ (предшественник $S_2$).

3. Узел $S_2 (10)$ на шаге 2:
   - Приходит из $S_0$ (вход $1$, выход $11$): $\text{BM} = d_H((01), (11)) = 1 + 0 = 1$. Путь: $PM^{(1)}(00) + 1 = 1 + 1 = 2$.
   - Выбор: $PM^{(2)}(10) = 2$ (предшественник $S_0$).

4. Узел $S_3 (11)$ на шаге 2:
   - Приходит из $S_2$ (вход $1$, выход $01$): $\text{BM} = d_H((01), (01)) = 0 + 0 = 0$. Путь: $PM^{(1)}(10) + 0 = 1 + 0 = 1$.
   - Выбор: $PM^{(2)}(11) = 1$ (предшественник $S_2$).

#### 3. Обратный проход и применение правила усечения

Поскольку конечное состояние неизвестно, но длина последовательности $L = 4$, а глубина усечения задана как $D = 3$, мы используем правило обрезания решетки. 

1. **Выбор стартового узла для трассировки:** 
   Среди всех состояний на шаге $t = 4$ находим узел с минимальной метрикой пути:
   $$\min \{PM^{(4)}(00)=3, \, PM^{(4)}(01)=3, \, PM^{(4)}(10)=2, \, PM^{(4)}(11)=3\} = 2$$
   Минимальная метрика достигается в состоянии $S_2 (10)$. Следовательно, обратный проход начинаем из узла **$S_2$ в моменте времени $t = 4$**.

2. **Выполнение обратной трассировки (Backtracking):**
   - **Шаг $t = 4 \to t = 3$:**
     - Стартуем в состоянии $S_2 (10)$ на шаге 4.
     - По таблице предшественников на шаге 4 в узел $S_2 (10)$ путь пришел из состояния **$S_1 (01)$** на шаге 3.
     - Переход из $S_1$ в $S_2$ соответствует входному информационному биту **$u_3 = 1$**.
   - **Шаг $t = 3 \to t = 2$:**
     - Находимся в состоянии $S_1 (01)$ на шаге 3.
     - По таблице предшественников на шаге 3 в узел $S_1 (01)$ путь пришел из состояния **$S_3 (11)$** на шаге 2.
     - Переход из $S_3$ в $S_1$ соответствует входному информационному биту **$u_2 = 0$**.
   - **Шаг $t = 2 \to t = 1$:**
     - Находимся в состоянии $S_3 (11)$ на шаге 2.
     - По таблице предшественников на шаге 2 в узел $S_3 (11)$ путь пришел из состояния **$S_2 (10)$** на шаге 1.
     - Переход из $S_2$ в $S_3$ соответствует входному информационному биту **$u_1 = 1$**.
   - **Шаг $t = 1 \to t = 0$:**
     - Находимся в состоянии $S_2 (10)$ на шаге 1.
     - По таблице предшественников на шаге 1 в узел $S_2 (10)$ путь пришел из состояния **$S_0 (00)$** на шаге 0.
     - Переход из $S_0$ в $S_2$ соответствует входному информационному биту **$u_0 = 1$**.

3. **Сборка восстановленной информационной последовательности:**
   Информационные биты были получены в порядке от последнего к первому: $(u_3, u_2, u_1, u_0) = (1, 0, 1, 1)$.
   Записываем последовательность в хронологическом порядке от $t = 0$ до $t = 3$:
   $$\mathbf{U} = (u_0, u_1, u_2, u_3) = (1, 1, 0, 1)$$

#### 4. Проверка корректности решения

Проверим полученную информационную последовательность $\mathbf{U} = (1, 1, 0, 1)$ путем ее повторного кодирования сверточным кодером с полиномами $g^{(1)} = 111$ и $g^{(2)} = 101$.

Содержимое регистра сдвига (инициализировано нулями $00$):
- Шаг $t = 0$: вход $u_0 = 1$. Регистр: $[1, 0]$.
  - Выход 1: $1 \cdot 1 + 0 \cdot 1 + 0 \cdot 1 = 1$
  - Выход 2: $1 \cdot 1 + 0 \cdot 0 + 0 \cdot 1 = 1$
  - Кодовая пара: $(1, 1)$.
- Шаг $t = 1$: вход $u_1 = 1$. Регистр: $[1, 1]$.
  - Выход 1: $1 \cdot 1 + 1 \cdot 1 + 0 \cdot 1 = 0$
  - Выход 2: $1 \cdot 1 + 1 \cdot 0 + 0 \cdot 1 = 1$
  - Кодовая пара: $(0, 1)$.
- Шаг $t = 2$: вход $u_2 = 0$. Регистр: $[0, 1]$.
  - Выход 1: $0 \cdot 1 + 1 \cdot 1 + 1 \cdot 1 = 0$ (по модулю 2: $0+1+1 = 0$)
  - Выход 2: $0 \cdot 1 + 1 \cdot 0 + 1 \cdot 1 = 1$
  - Кодовая пара: $(0, 1)$. *(Стоп, пересчитаем полиномы в общем виде)*

Уточнение свертки по регистрам (структура: $S = [s_1, s_2]$, вход $u$):
- $s_1$ — старший бит регистра, $s_2$ — младший.
- $g^{(1)} = 1 + x + x^2 \implies y^{(1)} = u \oplus s_1 \oplus s_2$
- $g^{(2)} = 1 + x^2 \implies y^{(2)} = u \oplus s_2$

Пересчет для $\mathbf{U} = (1, 1, 0, 1)$:
- Исходное состояние регистра: $[0, 0]$
- $t = 0$, вход $u = 1$:
  - $y^{(1)} = 1 \oplus 0 \oplus 0 = 1$
  - $y^{(2)} = 1 \oplus 0 = 1$
  - Пара: $(1, 1)$. Регистр становится $[1, 0]$.
- $t = 1$, вход $u = 1$:
  - $y^{(1)} = 1 \oplus 1 \oplus 0 = 0$
  - $y^{(2)} = 1 \oplus 0 = 1$
  - Пара: $(0, 1)$. Регистр становится $[1, 1]$.
- $t = 2$, вход $u = 0$:
  - $y^{(1)} = 0 \oplus 1 \oplus 1 = 0$
  - $y^{(2)} = 0 \oplus 1 = 1$
  - Пара: $(0, 1)$. Регистр становится $[0, 1]$.
- $t = 3$, вход $u = 1$:
  - $y^{(1)} = 1 \oplus 0 \oplus 1 = 0$
  - $y^{(2)} = 1 \oplus 1 = 0$
  - Пара: $(0, 0)$. Регистр становится $[1, 0]$.

Сгенерированная кодовая последовательность: $(11, 01, 01, 00)$.
Сравним ее с принятой зашумленной последовательностью $\mathbf{R} = (10, 01, 11, 00)$:
- Позиция 1: передано $(11)$, принято $(10)$ — ошибок: 1.
- Позиция 2: передано $(01)$, принято $(01)$ — ошибок: 0.
- Позиция 3: передано $(01)$, принято $(11)$ — ошибок: 1.
- Позиция 4: передано $(00)$, принято $(00)$ — ошибок: 0.

Суммарное число исправленных ошибок расстояния Хэмминга равно $1 + 1 = 2$. Декодер успешно восстановил исходную последовательность, несмотря на искажения в канале.

Ответ: $\mathbf{U} = (1, 1, 0, 1)$

## Типичные ошибки

1. **Игнорирование начальной инициализации метрик путей.** Студенты часто задают нулевые метрики для всех состояний на шаге $t = 0$. Это приводит к неверному выбору путей для кодеров, которые начинают работу из фиксированного (нулевого) состояния. *Как избежать:* всегда инициализировать нулевое состояние метрикой $PM_0(00\dots0) = 0$, а все остальные состояния — значением $\infty$.
2. **Путаница в направлении расчета расстояния Хэмминга.** Ошибка возникает, когда метрику ветви вычисляют как модуль разности числовых значений кодовых слов, а не как число несовпадающих бит (сложение по модулю 2). *Как избежать:* всегда записывать принятый и ожидаемый вектороодинаковой длины и побитово складывать их через $\oplus$.
3. **Неправильный порядок обхода при обратной трассировке.** Студенты записывают биты информационной последовательности в порядке их извлечения с конца к началу, забывая развернуть массив. *Как избежать:* помнить, что обратное трассирование идет от $t = L + v$ к $t = 0$, поэтому полученный массив бит необходимо инвертировать (прочитать задом наперед).
4. **Ошибки в обработке хвостовых бит.** При добавлении $v$ нулевых хвостовых бит студенты не увеличивают общее число тактов решетки на $v$, из-за чего обрезают граф раньше времени. *Как избежать:* суммарное число тактов решетки всегда равно $L + v$, где $L$ — длина информационной последовательности, а $v = K - 1$.
5. **Произвольный выбор при равенстве метрик (коллизиях).** В ситуациях, когда два пути имеют одинаковую метрику, студент выбирает путь наугад или меняет правило от шага к шагу. *Как избежать:* зафиксировать единое правило для всей задачи (например, «при равенстве приоритет имеет путь из состояния с меньшим индексом») и строго следовать ему.
6. **Неверный учет глубины усечения при потоковом декодировании.** При обработке непрерывных данных без хвостовых бит студенты пытаются стартовать обратный проход с шага $t = L$, не учитывая окно сходимости путей $D$. *Как избежать:* отступать назад на глубину $D \approx (4 \div 5)K$ от текущего шага и принимать решение для самого раннего узла в окне.

При сравнении двух путей в узле решетки на шаге $t = 3$ получены одинаковые метрики кандидатов: $PM_{cand1} = 5$ (пришел из состояния $01$ с информационным битом $0$) и $PM_{cand2} = 5$ (пришел из состояния $11$ с информационным битом $1$). Используя правило выбора пути с меньшим номером предшествующего состояния, укажите выбранный выживающий путь и его метрику.
8. Задана решетка сверточного кода с длиной памяти $K = 3$ ($v = 2$). Определите минимально рекомендуемую глубину усечения $D$ для стабильного потокового декодирования без потери оптимальности.

## Ответы к задачам

1. Кодовая последовательность: $(11, 10, 01)$.
2. Метрики ветвей для переходов из состояния $0$: $BM(0 \to 0) = 1$, $BM(0 \to 1) = 1$; для переходов из других состояний: $\infty$.
3. Метрики путей на шаге $t = 2$: $PM_2(0) = 3$, $PM_2(1) = 1$.
4. Стартовое состояние для обратного прохода: $00$ (в силу требования обязательного возврата в нулевое состояние при использовании хвостовых бит).
5. Восстановленная последовательность: информационные биты $(1, 0)$, хвостовой бит $(0)$, итого: $(1, 0, 0)$.
6. Гарантированно исправляется до $3$ ошибок ($t_{\text{corr}} = \lfloor (7 - 1) / 2 \rfloor = 3$).
7. Выбирается первый путь (из состояния $01$, информационный бит $0$), результирующая метрика узла равна $5$.
8. Рекомендуемая глубина усечения: $D = 12$ шагов ($4 \cdot K$).

## Сущность рекурсии: базовый случай и рекурсивный шаг

### Сущность рекурсии: базовый случай и рекурсивный шаг

В программировании на языке C++ под **рекурсией** понимается такой способ организации вычислительного процесса, при котором функция в ходе своего выполнения обращается сама к себе. Термин происходит от латинского *recursio* — возвращение. С точки зрения архитектуры программного обеспечения, рекурсия представляет собой альтернативу циклам (`while`, `for`), позволяя выражать сложные алгоритмы более компактно и элегантно. 

> **Определение.** Рекурсивная функция — это функция, которая содержит в своем теле прямой или косвенный вызов самой себя.

Прямая рекурсия возникает тогда, когда функция `A` вызывает функцию `A`. Косвенная рекурсия реализуется в случае, когда функция `A` вызывает функцию `B`, а функция `B`, в свою очередь, вызывает функцию `A`. В рамках данного курса мы сосредоточимся преимущественно на изучении прямой рекурсии, так как она лежит в основе подавляющего большинства рекурсивных структур данных и алгоритмов.

Центральная идея рекурсивного подхода заключается в *декомпозиции*: исходная задача разбивается на одну или несколько более мелких подзадач, которые по своей природе абсолютно идентичны исходной, но имеют меньший объем входных данных. Чтобы этот процесс не продолжался бесконечно, необходимо четко разграничить две обязательные составляющие любой корректной рекурсивной программы:
1. **Базовый случай (condition of termination / base case)** — условие, при достижении которого функция прекращает вызывать саму себя и возвращает конкретное базовое значение без дальнейших вычислений.
2. **Рекурсивный шаг (recursive step)** — часть алгоритма, на которой аргументы функции изменяются таким образом, чтобы неизбежно приближать вычислительный процесс к базовому случаю, после чего выполняется вызов функции с новыми аргументами.

Если исключить хотя бы один из этих компонентов, программа либо никогда не завершит работу, либо завершится аварийно из-за исчерпания доступных ресурсов памяти.

### Аналогия с математической индукцией

Для глубокого понимания того, почему рекурсия работает и почему она математически корректна, полезно провести прямую аналогию с методом математической индукции, изучаемым в курсе высшей математики.

В математической индукции для доказательства того, что некое утверждение $P(n)$ истинно для любого натурального числа $n$, необходимо выполнить два шага:
1. **База индукции:** доказать, что утверждение верно для наименьшего значения, например для $n = 1$ или $n = 0$.
2. **Индукционный переход:** предположить, что утверждение верно для произвольного натурального числа $k$ (предположение индукции), и на основе этого доказать его истинность для следующего числа $k + 1$.

В рекурсивном программировании логика зеркально отражает этот метод:
- Базовый случай в коде — это в точности база индукции. Это точка опоры, где ответ известен заранее и не требует вычислений.
- Рекурсивный шаг — это индукционный переход. Мы предполагаем, что функция корректно решает задачу для меньшего объема данных (например, для $n-1$), и пишем код так, чтобы через это решение получить ответ для текущего объема $n$.

Если индукционный переход корректен, а база достижима для любого допустимого входного данных, алгоритм гарантированно выдаст верный результат.

### Типичные ошибки проектирования рекурсии

При разработке рекурсивных функций начинающие программисты чаще всего допускают три фундаментальные ошибки:

1. **Отсутствие базового случая.** Если забыть прописать условие выхода, функция будет вызывать себя бесконечно. Каждый новый вызов занимает память в стеке вызовов процессора. Как только эта память закончится, операционная система принудительно завершит аварийным сигналом (`Segmentation fault` или `Stack Overflow`).
2. **Некорректное уменьшение аргументов (удаление от базы).** Если в рекурсивном шаге аргументы изменяются в противоположную сторону (например, вместо уменьшения $n$ до нуля мы прибавляем единицу: `n + 1`), базовый случай никогда не будет достигнут. Это приводит к точно такому же переполнению памяти, как и полное отсутствие базы.
3. **Слишком сложный или пропущенный базовый случай.** Базовый случай должен быть элементарным. Попытка сделать базу слишком широкой или неопределенной приводит к логическим ошибкам и неверным результатам вычислений.

### Разобранный пример 1: Вычисление факториала

Рассмотрим классическую математическую задачу — вычисление факториала натурального числа $n$ (обозначается как $n!$). 

#### Определение и математическое обоснование
Факториал неотрицательного целого числа $n$ определяется как произведение всех натуральных чисел от $1$ до $n$ включительно. По определению, факториал нуля равен единице:
$$0! = 1$$
Для любого целого $n \ge 1$ справедливо рекуррентное соотношение:
$$n! = n \cdot (n - 1)!$$

Здесь базовым случаем является $n = 0$ (или $n = 1$), для которого результат равен $1$ немедленно. Рекурсивный шаг заключается в сведении задачи вычисления $n!$ к задаче вычисления $(n-1)!$ с последующим умножением полученного значения на $n$.

#### Ход рассуждений
1. Нам нужно спроектировать функцию `long long factorial(int n)`.
2. Проверяем граничное условие: если `n == 0` или `n == 1`, возвращаем `1`. Это наш базовый случай.
3. Если `n > 1`, мы возвращаем произведение `n * factorial(n - 1)`. Параметр `n` при каждом новом вызове уменьшается на $1$, строго приближаясь к базовому случаю `0`.

#### Реализация на C++17

```cpp
#include <iostream>

// Функция вычисления факториала рекурсивным методом
long long factorial(int n) {
    // 1. Базовый случай (условие остановки)
    if (n < 0) {
        return -1; // Ошибка: факториал отрицательного числа не определен
    }
    if (n == 0 || n == 1) {
        return 1;
    }
    
    // 2. Рекурсивный шаг: n! = n * (n-1)!
    return n * factorial(n - 1);
}

int main() {
    int n = 4;
    long long result = factorial(n);
    std::cout << "Faktorial chisla " << n << " равен " << result << std::endl;
    return 0;
}
```

#### Пошаговое вычисление для $n = 4$
Проследим в деталях, как программа вычисляет значение `factorial(4)`:
1. Вызывается `factorial(4)`. Поскольку $4 \neq 0$ и $4 \neq 1$, срабатывает рекурсивный шаг: возвращается `4 * factorial(3)`. Чтобы вычислить это выражение, процессору необходимо сначала узнать результат `factorial(3)`.
2. Вызывается `factorial(3)`. Срабатывает рекурсивный шаг: возвращается `3 * factorial(2)`.
3. Вызывается `factorial(2)`. Срабатывает рекурсивный шаг: возвращается `2 * factorial(1)`.
4. Вызывается `factorial(1)`. Срабатывает базовый случай: условие `n == 1` истинно, функция возвращает число `1` без дополнительных вызовов.
5. Возвращенное единичное значение подставляется в предыдущий контекст: `factorial(2)` получает `2 * 1 = 2` и возвращает `2`.
6. Значение `2` подставляется в контекст `factorial(3)`: получается `3 * 2 = 6`, функция возвращает `6`.
7. Значение `6` подставляется в исходный вызов `factorial(4)`: получается `4 * 6 = 24`, и итоговый результат возвращается в функцию `main`.

#### Проверка и анализ
- **Единицы измерения:** Безразмерная величина (целое число).
- **Правдоподобность:** Ручной расчет дает $4! = 1 \cdot 2 \cdot 3 \cdot 4 = 24$. Результат совпадает.
- **Ограничения:** Тип `long long` в C++ обычно занимает 8 байт и позволяет хранить значения примерно до $9 \cdot 10^{18}$. Факториал быстро растет, поэтому для $n > 20$ произойдет переполнение целочисленного типа.

`Ответ: 24`

### Разобранный пример 2: Рекурсивная проверка строки на палиндром

#### Определение и математическое обоснование
Палиндром — это строка, которая читается одинаково как слева направо, так и справа налево (например, «radar», «level», «шалаш»). 

Строка $S$ длины $N$ является палиндромом, если выполняются два условия:
1. Символ на первом месте равен символу на последнем месте ($S[0] == S[N-1]$).
2. Подстрока, образуемая без первого и последнего символов ($S[1 \dots N-2]$), также является палиндромом.

Базовыми случаями здесь выступают:
- Пустая строка (длина 0) или строка из одного символа (длина 1) — они всегда являются палиндромами.
- Обнаружение несовпадения симметричных символов в процессе проверки — строка точно не является палиндромом.

#### Ход рассуждений
1. Нам удобнее передавать в рекурсивную функцию не только саму строку, но и индексы начала (`left`) и конца (`right`) проверяемого диапазона. Изначально `left = 0`, а `right = length - 1`.
2. Базовый случай 1: если `left >= right`, это означает, что мы успешно проверили все символы до середины и несоответствий не найдено. Возвращаем `true`.
3. Базовый случай 2: если символ `s[left]` не равен символу `s[right]`, условие палиндрома нарушено. Возвращаем `false` немедленно.
4. Рекурсивный шаг: если крайние символы равны, сужаем область поиска, вызывая ту же функцию для внутренних символов: `isPalindrome(s, left + 1, right - 1)`.

#### Реализация на C++17

```cpp
#include <iostream>
#include <string>

// Рекурсивная функция проверки подстроки s в диапазоне [left, right] на палиндром
bool isPalindromeRecursive(const std::string& s, int left, int right) {
    // 1. Базовый случай 1: если указатели сошлись или перекрестились
    if (left >= right) {
        return true;
    }
    
    // 2. Базовый случай 2: символы на текущих позициях не равны
    if (s[left] != s[right]) {
        return false;
    }
    
    // 3. Рекурсивный шаг: сужаем границы на один символ с каждого края
    return isPalindromeRecursive(s, left + 1, right - 1);
}

// Удобная обертка для вызова функции с исходной строки
bool isPalindrome(const std::string& s) {
    if (s.empty()) {
        return true;
    }
    return isPalindromeRecursive(s, 0, s.length() - 1);
}

int main() {
    std::string test_str = "radar";
    if (isPalindrome(test_str)) {
        std::cout << "Stroka \"" << test_str << "\" yavlyaetsya palindromom." << std::endl;
    } else {
        std::cout << "Stroka \"" << test_str << "\" NE yavlyaetsya palindromom." << std::endl;
    }
    return 0;
}
```

#### Пошаговое вычисление для строки `"radar"`
Длина строки равна $5$, индексы от $0$ до $4$.
1. **Вызов 1:** `isPalindromeRecursive("radar", 0, 4)`
   - Проверка базы: `0 >= 4` — ложь.
   - Сравнение символов: `s[0] == 'r'` и `s[4] == 'r'`. Они равны.
   - Рекурсивный шаг: вызов `isPalindromeRecursive("radar", 1, 3)`.
2. **Вызов 2:** `isPalindromeRecursive("radar", 1, 3)`
   - Проверка базы: `1 >= 3` — ложь.
   - Сравнение символов: `s[1] == 'a'` и `s[3] == 'a'`. Они равны.
   - Рекурсивный шаг: вызов `isPalindromeRecursive("radar", 2, 2)`.
3. **Вызов 3:** `isPalindromeRecursive("radar", 2, 2)`
   - Проверка базы: `2 >= 2` — истина (`left == right`, дошли до центрального символа `'d'`).
   - Функция возвращает `true`.
4. Результат последовательно передается наверх по цепочке вызовов, возвращая `true` в функцию `main`.

#### Проверка и анализ
- **Единицы измерения:** Логическое значение (`true`/ിവfalse`).
- **Правдоподобность:** Слово «radar» читается одинаково в обоих направлениях. Алгоритм выдал корректный положительный ответ.
- **Ограничения:** Передача строки `const std::string&` по константной ссылке позволяет избежать ненужного копирования данных в памяти при каждом рекурсивном вызове, обеспечивая высокую эффективность.

`Ответ: Строка "radar" является палиндромом.`

## Стек вызовов (Call Stack) и активационные записи

### Аппаратная поддержка стека вызовов и размещение локальных переменных

Когда программа на языке C++ исполняется процессором, операционная система выделяет для каждого запущенного потока специальный участок оперативной памяти, называемый **стеком вызовов (call stack)**. Стек — это структура данных, работающая по принципу LIFO (Last In, First Out — «последним пришёл — первым вышел»). 

На аппаратном уровне процессор поддерживает стек с помощью специальных регистров:
1. **Указатель стека (Stack Pointer, в архитектуре x86/x64 это регистр `RSP` / `ESP`)** — машинный регистр, который всегда хранит адрес ячейки памяти, содержащей вершину стека (актуальный адрес верха стекового пространства).
2. **Указатель базы кадра (Base Pointer / Frame Pointer, регистр `RBP` / `EBP`)** — регистр, используемый для стабильной фиксации начала текущей активационной записи функции, что позволяет коду функции легко обращаться к своим аргументам и локальным переменным через фиксированные смещения.

В классических архитектурах вычислительных систем (включая архитектуру x86_64) память стека выделяется **от старших адресов к младшим**. Это означает, что при добавлении новых данных в стек адрес вершины уменьшается (из значения регистра `RSP` вычитается количество байт), а при удалении данных — увеличивается (к регистру `RSP` добавляются байты).

> **Определение.** **Активационная запись (stack frame, или кадр стека)** — это блок памяти в стеке вызовов, который выделяется при вызове функции и содержит всю необходимую информацию для её корректного выполнения и возврата управления в вызывающий код.

Каждый кадр стека устроен строго и содержит следующие компоненты:
1. **Аргументы функции** — значения параметров, переданные вызывающей функцией (если они не помещаются целиком в регистры процессора).
2. **Адрес возврата (return address)** — точный машинный адрес инструкции в коде вызывающей функции, к которому процессор должен вернуться после завершения текущей подпрограммы.
3. **Сохранённое значение указателя базового кадра (`RBP`)** — адрес кадра стека родительской функции, чтобы восстановить его при завершении текущей функции.
4. **Локальные переменные** — переменные, объявленные внутри тела функции. Память под них выделяется в момент входа в функцию и автоматически уничтожается при выходе.

Ниже приведена ASCII-схема, иллюстрирующая структуру памяти стека в процессе выполнения вложенных вызовов функций (память растет сверху вниз, от старших адресов к младшим):

```text

-----------------------------------------

-----------------------------------------
| Адрес возврата в операционную систему |

-----------------------------------------

| Локальные переменные текущей функции  | <-- Вершина стека (RSP)
-----------------------------------------

```

### Раскрутка стека и жизненный цикл кадра

Когда одна функция вызывает другую, происходит аппаратное сохранение контекста. Процессор выполняет следующие действия:
1. Помещает в стек аргументы вызываемой функции (в стандарте C++ обычно справа налево или через регистры процессора).
2. Выполняет инструкцию вызова функции (в ассемблере — `call`), которая автоматически записывает в стек **адрес возврата** (следующую инструкцию после вызова).
3. Переходит по адресу вызываемой функции и выделяет память под новый кадр стека, сдвигая указатель стека `RSP` вниз на размер, равный суммарному объему локальных переменных и служебных полей.

Процесс возврата из функции называется **раскруткой стека (stack unwinding)**. Как только функция выполняет оператор `return` или достигает закрывающей фигурной скобки, происходит следующее:
1. Возвращаемое значение сохраняется в специальном регистре процессора (например, `RAX` в x64).
2. Процессор восстанавливает сохраненный указатель базы кадра (`RBP`).
3. Процессор считывает адрес возврата со стека и устанавливает указатель команд (`RIP`) на этот адрес.
4. Указатель стека (`RSP`) возвращается в исходное положение (память занятая локальными переменными кадра считается освобожденной, так как следующие вызовы просто перезапишут эти ячейки).

Никакие данные внутри освобожденных кадров физически не затираются нулями — меняется лишь значение указателя `RSP`. Это важно понимать: обращение к локальной переменной уже завершившейся функции (например, через возвращенный висячий указатель) приведет к неопределенному بهведению (Undefined Behavior).

### Переполнение стека (Stack Overflow)

Поскольку операционная система выделяет для стека каждого потока фиксированный объем оперативной памяти (в современных операционных системах по умолчанию это обычно от 1 до 8 Мегабайт), этот ресурс конечен.

> **Определение.** **Переполнение стека (Stack Overflow)** — это критическая ошибка времени выполнения, возникающая тогда, когда суммарный объем всех активных активационных записей превышает предельно допустимый размер стека, отведенный для данного потока программы.

Основные причины возникновения переполнения стека в программировании:
1. **Бесконечная рекурсия** — отсутствие или некорректная реализация базового случая, из-за чего функция вызывает себя бесконечно, исчерпывая память кадрами стека при каждом шаге.
2. **Чрезмерно большая глубина рекурсии** — даже если базовый случай существует, но задача требует миллионы уровней вложенности (например, рекурсивный обход несбалансированного дерева или вычисление факториала от $10^7$), количество кадров превысит физический лимит стека.
3. **Размещение огромных локальных массивов внутри рекурсивных функций** — если в теле рекурсивной функции объявить локальный массив размером в несколько мегабайт (например, `int buffer[1000000];`), то стек исчерпает свой лимит всего за несколько таких вызовов.

При переполнении стека процессор пытается записать новый кадр за пределы выделенного региона памяти оперативной системы. Происходит обращение к защищенной странице памяти (Segmentation Fault в Linux или Access Violation в Windows), и операционная система аварийно завершает аварийный процесс.

### Разобранные примеры

#### Пример 1: Пошаговый анализ состояния стека вызовов

Рассмотрим рекурсивную функцию на языке C++, которая вычисляет сумму натуральных чисел от $1$ до $n$:

```cpp
#include <iostream>

int sum(int n) {
    // Базовый случай
    if (n == 1) {
        return 1;
    }
    // Рекурсивный шаг
    return n + sum(n - 1);
}

int main() {
    int result = sum(3);
    std::cout << "Sum = " << result << std::endl;
    return 0;
}
```

Проведем детальный пошаговый анализ того, как меняется содержимое стека вызовов при вызове `sum(3)`.

1. **Шаг 1: Вызов `main`**
   Операционная система запускает программу, создается поток, выделяется стек. Создается активационная запись функции `main`.
   Вершина стека указывает на кадр `main`.

2. **Шаг 2: Вызов `sum(3)` из функции `main`**
   В коде `main` вызывается `sum(3)`. В стек помещается адрес возврата в `main`, а затем создается активационная запись для функции `sum` с параметром `n = 3`.
   * Содержимое стека (снизу вверх, от дна к вершине):
     * Кадр `main`
     * Кадр `sum(n = 3)` [Локальных переменных нет, аргумент $n = 3$, адрес возврата в `main`]

3. **Шаг 3: Выполнение `sum(3)` и вызов `sum(2)`**
   Внутри `sum(3)` проверяется условие `n == 1` ($3 == 1$ — ложь). Функция вычисляет выражение `3 + sum(2)`. Для этого процессор должен вычислить `sum(2)`, поэтому происходит новый рекурсивный вызов.
   В стек поверх текущего кадра добавляется новый кадр для `sum(2)`.
   * Содержимое стека:
     * Кадр `main`
     * Кадр `sum(n = 3)` [ждет результата `sum(2)`]
     * Кадр `sum(n = 2)` [аргумент $n = 2$, адрес возврата в `sum(3)`]

4. **Шаг 4: Выполнение `sum(2)` и вызов `sum(1)`**
   Внутри `sum(2)` проверяется условие `n == 1` ($2 == 1$ — ложь). Функция вычисляет выражение `2 + sum(1)`. Происходит вызов `sum(1)`.
   В стек добавляется третий кадр рекурсии.
   * Содержимое стека:
     * Кадр `main`
     * Кадр `sum(n = 3)` [ждет результата `sum(2)`]
     * Кадр `sum(n = 2)` [ждет результата `sum(1)`]
     * Кадр `sum(n = 1)` [аргумент $n = 1$, адрес возврата в `sum(2)`]

5. **Шаг 5: Достижение базы рекурсии (`sum(1)`)**
   Внутри кадра `sum(1)` проверяется условие `n == 1` ($1 == 1$ — истина). Базовый случай срабатывает, функция возвращает число `1` без дополнительных рекурсивных вызовов.
   Начинается процесс раскрутки стека (stack unwinding).

6. **Шаг 6: Возврат из `sum(1)` в `sum(2)`**
   Кадр `sum(1)` удаляется со стека. Управление возвращается в `sum(2)` по сохраненному адресу возврата. Функция `sum(2)` подставляет полученный результат `1` в свое выражение: `2 + 1 = 3`.
   Значение `3` возвращается в вызывающую функцию.
   * Содержимое стека:
     * Кадр `main`
     * Кадр `sum(n = 3)` [ждет результата `sum(2)`]
     * Кадр `sum(n = 2)` завершается и возвращает `3`

7. **Шаг 7: Возврат из `sum(2)` в `sum(3)`**
   Кадр `sum(2)` удаляется со стека. Управление возвращается в `sum(3)`. Функция `sum(3)` подставляет результат: `3 + sum(2)` превращается в `3 + 3 = 6`.
   Значение `6` возвращается в `main`.
   * Содержимое стека:
     * Кадр `main`
     * Кадр `sum(n = 3)` завершается и возвращает `6`

8. **Шаг 8: Завершение работы**
   Кадр `sum(3)` удаляется со стека. Управление возвращается в функцию `main`, которая записывает полученное число `6` в переменную `result` и выводит его на экран. Стек возвращается в исходное состояние.

#### Пример 2: Определение максимальной глубины рекурсии и переполнения стека

Рассмотрим задачу экспериментального и теоретического определения глубины рекурсии, при которой происходит переполнение стека.

Пусть у нас имеется рекурсивная функция, которая инкрементирует счетчик глубины и вызывает сама себя без базового случая (или с недостижимым базовым условием):

```cpp
#include <iostream>

// Глобальный счетчик для отслеживания глубины рекурсии
long long recursion_depth = 0;

void recursive_overflow_test(long long depth) {
    recursion_depth = depth;
    
    // Локальный массив для увеличения размера кадра стека (например, 1 килобайт)
    char buffer[1024];
    // Используем буфер, чтобы компилятор не оптимизировал переменные
    buffer[0] = static_cast<char>(depth % 128); 
    
    // Рекурсивный вызов со следующей глубиной
    recursive_overflow_test(depth + 1);
}

int main() {
    try {
        recursive_overflow_test(1);
    } catch (...) {
        std::cout << "Caught exception at depth: " << recursion_depth << std::endl;
    }
    return 0;
}
```

##### Ход рассуждений и расчеты

1. **Оценка размера кадра стека:**
   Каждая активационная запись функции `recursive_overflow_test` содержит:
   * Передаваемый аргумент `depth` (тип `long long` занимает $8$ байт).
   * Адрес возврата (в 64-битной системе занимает $8$ байт).
   * Сохраненный указатель базового кадра `RBP` ($8$ байт).
   * Локальный массив `buffer` размером $1024$ байта.
   * Дополнительные служебные выравнивания памяти (выравнивание по границе 16 байт в архитектуре x86_64).
   Суммарный размер одного кадра стека $F$ составляет приблизительно:
   $$F = 8 + 8 + 8 + 1024 + padding \approx 1056 \text{ байт}$$

2. **Оценка емкости стека:**
   Операционная система (например, Linux по умолчанию) выделяет под стек главного потока $S = 8 \text{ МБ} = 8 \cdot 1024 \cdot 1024 \text{ байт} = 8\,388\,608 \text{ байт}$. Часть этого объема (около $64 \text{ КБ}$) может быть зарезервирована самой ОС и библиотеками под нужды окружения. Доступный объем для пользовательской рекурсии составляет примерно $8\,320\,000 \text{ байт}$.

3. **Вычисление максимальной глубины рекурсии ($D_{max}$):**
   Максимальная глубина вычислений определяется делением доступного объема памяти стека на размер одного кадра стека:
   $$D_{max} = \frac{8\,320\,000 \text{ байт}}{1056 \text{ байт/кадр}} \approx 7878 \text{ вызовов}$$

   Если запустить такую программу в реальной среде без перехвата сигналов ОС, программа аварийно завершится с кодом ошибки `Segmentation Fault` (код 139 в ОС Linux) ровно в момент, когда количество вложенных вызовов достигнет этого порогового значения.

##### Проверка и выводы
* **Единицы измерения:** Глубина измеряется в количестве кадров (безразмерная величина), размер стека и кадра измеряется в байтах.
* **Правдоподобность:** Полученная оценка порядка $7800$ вложенных вызовов при размере кадра около $1 \text{ КБ}$ полностью согласуется с ограничениями стандартного стека в 8 МБ. Увеличение локального массива в функции до $10 \text{ КБ}$ уменьшит максимальную глубину ровно в 10 раз, что доказывает прямую обратную пропорциональность между размером кадра стека и максимально возможной глубиной рекурсии.

Ответ: При размере кадра стека около $1056$ байт и стандартном лимите стека потока в $8$ МБ максимальная глубина рекурсии составит приблизительно $7878$ вызовов, после чего произойдет аварийное завершение программы по причине переполнения стека (Stack Overflow).

## Анализ сложности рекурсивных алгоритмов и дерево вызовов

### Дерево рекурсивных вызовов и визуализация процесса

Когда функция вызывает саму себя несколько раз в пределах одного шага (или даже один раз, но с уменьшением аргумента), традиционный линейный анализ «циклов» не позволяет наглядно оценить затраты ресурсов. Для точного анализа временной и пространственной сложности рекурсивных алгоритмов используется концепция **дерева рекурсивных вызовов** (recursion tree).

> **Определение.** Дерево рекурсивных вызовов — это ориентированный граф, в котором каждый узел представляет отдельный вызов рекурсивной функции, а ребра показывают порождение новых (дочерних) вызовов из родительского. Корень дерева соответствует первому вызову с исходным аргументом $n$, а листья соответствуют базовым случаям рекурсии, где вызовы прекращаются.

Построение дерева вызовов позволяет наглядно увидеть:
1. Сколько всего было создано вызовов (сумма узлов на всех уровнях дерева).
2. Какова глубина рекурсии (максимальная длина пути от корня до листа).
3. Какова суммарная трудоемкость всех вызовов, выполняемых на каждом уровне вложенности.

### Оценка временной и пространственной сложности

Временная сложность рекурсивного алгоритма $T(n)$ определяется суммарным временем работы всех узлов дерева рекурсивных вызовов. Если на каждом уровне дерева выполняется фиксированный объем работы (не зависящий от ветвления) или объем работы зависит от размера подзадачи, общая сложность находится суммированием затрат по всем уровням:

$$T(n) = \sum_{level} (\text{количество узлов на уровне} \times \text{стоимость одного узла})$.$

Пространственная сложность рекурсивного алгоритма $S(n)$ определяется двумя основными факторами:
1. Объемом памяти, занимаемым локальными переменными и параметрами в каждом отдельном кадре стека (активационной записи).
2. Максимальной глубиной стека вызовов, которая в точности равна наибольшей высоте дерева рекурсии (максимальному расстоянию от корня до листа).

> **Правило пространственной сложности рекурсии.** Если в памяти одновременно не хранятся массивные структуры данных, создаваемые локально, то пространственная сложность рекурсивного алгоритма всегда пропорциональна максимальной глубине дерева вызовов: $S(n) = O(h(n))$, где $h(n)$ — высота дерева рекурсии для входных данных размера $n$.

### Линейная и древовидная рекурсия

По структуре порождения вызовов рекурсивные алгоритмы делятся на два принципиально разных класса:

* **Линейная рекурсия:** в теле функции выполняется ровно один рекурсивный вызов. Дерево вызовов вырождается в простую цепочку (список), где каждый узел имеет не более одного потомка. Глубина такого дерева равна количеству шагов рекурсии. Примером является вычисление факториала или линейный поиск.
* **Древовидная (множественная) рекурсия:** в теле функции выполняется два или более рекурсивных вызовов. Дерево вызовов начинает ветвиться, и количество узлов на каждом последующем уровне растет лавинообразно. Примером служат алгоритмы «разделяй и властвуй» или наивное вычисление чисел Фибоначчи.

### Разобранный пример 1: Анализ сложности рекурсивного вычисления чисел Фибоначчи

Рассмотрим классическую задачу вычисления $n$-го числа Фибоначчи с помощью наивной рекурсивной функции на языке C++.

Математическое определение последовательности:
$$F(0) = 0$$
$$F(1) = 1$$
$$F(n) = F(n-1) + F(n-2) \quad \text{при } n \ge 2$$

Реализация на C++17:
```cpp
#include <iostream>

long long fibonacci(int n) {
    // Базовый случай 1
    if (n <= 0) {
        return 0;
    }
    // Базовый случай 2
    if (n == 1) {
        return 1;
    }
    // Рекурсивный шаг: два вызова в теле функции
    return fibonacci(n - 1) + fibonacci(n - 2);
}

int main() {
    int n = 5;
    std::cout << "F(" << n << ") = " << fibonacci(n) << std::endl;
    return 0;
}
```

#### Построение дерева вызовов для $n = 5$

Для визуализации хода выполнения функции `fibonacci(5)` построим дерево рекурсивных вызовов. Каждый узел обозначим именем функции и аргументом.

```text
                  fib(5)
                /        \
          fib(4)          fib(3)
         /      \        /      \
     fib(3)    fib(2)  fib(2)   fib(1)
    /     \    /    \  /    \
  fib(2) fib(1)fib(1)fib(0)fib(1)fib(0)
  /    \
fib(1) fib(0)
```

#### Ход рассуждений и доказательство сложности

1. **Анализ временной сложности ($T(n)$):**
   Посмотрим на количество узлов на каждом уровне дерева вызовов (считая корень уровнем 0):
   - Уровень 0: $1$ узел (`fib(5)`)
   - Уровень 1: $2$ узла (`fib(4)`, `fib(3)`)
   - Уровень 2: $4$ узла (`fib(3)`, `fib(2)`, `fib(2)`, `fib(1)`)
   - Уровень 3: $8$ узлов (в полном бинарном дереве на глубине $h$ находится $2^h$ узлов)

   В общем случае для произвольного $n$ дерево делает разветвление на 2 ветви на каждом шаге. Рекуррентное соотношение времени работы выглядит так:
   $$T(n) = T(n-1) + T(n-2) + O(1)$$

   Если оценить это снизу, заменив $T(n-2)$ на меньший член $T(n-1)$, получим $T(n) \ge 2T(n-2)$, что ведет к экспоненциальному росту. Точное количество вызовов функции для вычисления $F(n)$ пропорционально самому числу Фибоначчи, то есть золотому сечению в степени $n$:
   $$T(n) = O\left(\left(\frac{1 + \sqrt{5}}{2}\right)^n\right) \approx O(1{,}618^n) = O(2^n)$$
   Это означает, что при увеличении $n$ всего на единицу время работы алгоритма практически удваивается. Для $n = 50$ такой алгоритм выполнит более $2 \cdot 10^{15}$ операций и зависнет на неопределенное время.

2. **Анализ пространственной сложности ($S(n)$):**
   Максимальная глубина стека вызовов определяется самым длинным путем от корня до листового узла. В данном дереве самый длинный путь идет по левой ветви:
   `fib(5) -> fib(4) -> fib(3) -> fib(2) -> fib(1)`.
   Длина этого пути равна $n$ (в данном случае 5 вызовов одновременно находятся в стеке). Когда левая ветвь полностью вычисляется и возвращает результат, память освобождается, и процессор начинает обход правой ветви.
   Следовательно, максимальное количество одновременно занятых кадров в стеке вызовов равно высоте дерева, которая линейно зависит от $n$:
   $$S(n) = O(n)$$

#### Проверка и ответ
- Единицы измерения: временная сложность выражена через количество элементарных операций процессора как функция от $n$; пространственная сложность — через максимальное количество одновременно удерживаемых в памяти кадров стека.
- Правдоподобие: экспоненциальный рост времени для наивных Фибоначчи является классическим примером неэффективной древовидной рекурсии из-за огромного количества повторяющихся (дублирующих) подзадач (например, `fib(2)` вычисляется в дереве несколько раз независимо).

`Ответ:` Временная сложность: $O(2^n)$, пространственная сложность: $O(n)$.

### Разобранный пример 2: Анализ сложности рекурсивного бинарного поиска

Рассмотрим алгоритм поиска элемента в отсортированном массиве методом деления пополам (бинарный поиск), реализованный в виде рекурсивной функции.

Реализация на C++17:
```cpp
#include <iostream>
#include <vector>

// Рекурсивная функция бинарного поиска
// Возвращает индекс найденного элемента или -1, если элемент отсутствует
int binarySearchRecursive(const std::vector<int>& arr, int target, int left, int right) {
    // Базовый случай 1: границы пересеклись, элемент не найден
    if (left > right) {
        return -1;
    }

    // Вычисление среднего индекса (защита от переполнения: left + (right - left) / 2)
    int mid = left + (right - left) / 2;

    // Базовый случай 2: элемент найден в средней позиции
    if (arr[mid] == target) {
        return mid;
    }

    // Рекурсивный шаг 1: поиск в левой половине
    if (arr[mid] > target) {
        return binarySearchRecursive(arr, target, left, mid - 1);
    } 
    // Рекурсивный шаг 2: поиск в правой половине
    else {
        return binarySearchRecursive(arr, target, mid + 1, right);
    }
}

int main() {
    std::vector<int> data = {2, 5, 8, 12, 16, 23, 38, 56, 72, 91};
    int target = 23;
    int index = binarySearchRecursive(data, target, 0, data.size() - 1);
    
    std::cout << "Index of " << target << " is: " << index << std::endl;
    return 0;
}
```

#### Ход рассуждений и построение рекуррентного соотношения

1. **Анализ структуры рекурсии:**
   На каждом шаге алгоритм выполняет сравнение элемента `target` со средним элементом массива размера $n$. В зависимости от результата сравнения область поиска уменьшается строго в два раза: либо левая половина, либо правая половина отбрасывается. В теле функции происходит **ровно один** рекурсивный вызов (это линейная рекурсия).

2. **Составление рекуррентного соотношения:**
   Пусть $T(n)$ — время выполнения бинарного поиска для массива размером $n$.
   - Накладные расходы на вычисление среднего индекса и сравнение занимают константное время: $O(1)$.
   - Размер задачи на следующем шаге уменьшается вдвое: $n / 2$.
   
   Записываем рекуррентное уравнение:
   $$T(n) = T\left(\frac{n}{2}\right) + O(1)$$
   при базовом случае $T(1) = O(1)$.

3. **Решение рекуррентного соотношения методом подстановки (развертывания):**
   Будем последовательно подставлять выражение для $T$ меньшего аргумента, пока не дойдем до базового случая:
   
   $$T(n) = T\left(\frac{n}{2}\right) + c$$
   $$T\left(\frac{n}{2}\right) = T\left(\frac{n}{4}\right) + c \implies T(n) = \left( T\left(\frac{n}{4}\right) + c \right) + c = T\left(\frac{n}{4}\right) + 2c$$
   $$T\left(\frac{n}{4}\right) = T\left(\frac{n}{8}\right) + c \implies T(n) = T\left(\frac{n}{8}\right) + 3c$$

   Заметим общую закономерность после $k$ шагов деления:
   $$T(n) = T\left(\frac{n}{2^k}\5righ) + k \cdot c$$

   Рекурсия останавливается, когда размер подзадачи доходит до 1 элемента, то есть когда $\frac{n}{2^k} = 1$.
   Отсюда выразим количество шагов $k$:
   $$2^k = n \implies k = \log_2 n$$

   Подставим найденное количество шагов $k = \log_2 n$ в развернутое уравнение:
   $$T(n) = T(1) + c \cdot \log_2 n$$
   Поскольку $T(1)$ — константа, получаем итоговую временную сложность:
   $$T(n) = O(\log n)$$

4. **Анализ пространственной сложности ($S(n)$):**
   Так как на каждом шаге выполняется ровно один рекурсивный вызов, дерево вызовов представляет собой не ветвящееся дерево, а прямую цепочку вызовов. 
   Максимальная глубина рекурсии равна количеству делений массива пополам до достижения единичного интервала, то есть высоте дерева вызовов:
   $$h = \log_2 n$$
   Каждый вызов создает свой стек-фрейм фиксированного размера. Следовательно, пространственная сложность рекурсивного бинарного поиска составляет:
   $$S(n) = O(\log n)$$
   *(Примечание: в итеративной реализации бинарного поиска пространственная сложность равна $O(1)$, так как стек вызовов не используется, однако рекурсивная версия демонстрирует классический пример логарифмической глубины стека).*

#### Проверка и ответ
- Единицы измерения: временная сложность — количество операций от размера массива $n$; пространственная сложность — глубина стека в кадрах функции.
- Правдоподобность: деление пополам всегда порождает логарифмическую зависимость сложности от объема входных данных (как и в поиске по сбалансированному дереву).

`Ответ:` Временная сложность: $O(\log n)$, пространственная сложность: $O(\log n)$.

## Хвостовая рекурсия и оптимизация хвостовых вызовов (Tail Call Optimization)

### Хвостовая рекурсия и концепция хвостового вызова

В предыдущих разделах было показано, как обычная рекурсия приводит к расходу памяти на стек вызовов: каждый новый вложенный вызов создает собственную активационную запись (фрейм стека), где хранятся локальные переменные, параметры и адрес возврата. Из-за этого при большой глубине рекурсии возникает ошибка переполнения стека ($Stack\ Overflow$). Однако существует особый вид рекурсии, который позволяет избежать этого ограничения, превращая рекурсивный процесс по эффективности в обычный цикл.

> **Определение.** Хвостовым вызовом (*tail call*) называется такой вызов функции, при котором возвращаемым значением текущей функции является непосредственно результат вызова другой (или этой же самой) функции, причем над этим результатом не выполняется никаких дополнительных арифметических, логических или иных операций.

Рассмотрим общую структуру обычного рекурсивного вызова на примере арифметической операции после возврата:

```cpp
int regular_recursion(int n) {
    if (n <= 1) return 1;
    // После завершения regular_recursion(n - 1) процессор должен умножить результат на n
    return n * regular_recursion(n - 1); 
}
```

В данном случае функция не может сразу удалить свой фрейм из стека при вызове `regular_recursion(n - 1)`. Ей необходимо «помнить», что после получения ответа от вложенной функции нужно выполнить операцию умножения на `n`. Именно поэтому стек заполняется.

Теперь перепишем эту же логику в виде хвостового вызова (*tail call*):

```cpp
int tail_recursion_helper(int n, int accumulator) {
    if (n <= 1) return accumulator;
    // Рекурсивный вызов является последним действием; над его результатом не выполняются никакие действия
    return tail_recursion_helper(n - 1, n * accumulator);
}
```

Здесь рекурсивный вызов `tail_recursion_helper(n - 1, n * accumulator)` стоит на самом верхнем уровне возврата. Функция возвращает ровно то, что вернет следующий вызов, не совершая никаких отложенных вычислений.

---

### Отличие хвостовой рекурсии от обычной и механизм TCO

Главное отличие хвостовой рекурсии от классической линейной заключается в том, **что именно сохраняется в памяти**.

В обычной рекурсии контекст вызывающей функции жизненно важен для продолжения работы после возвращения управления. Процессор обязан сохранить адрес возврата и локальные переменные, чтобы после заверщения подсчета глубоких уровней вернуться назад и завершить незавершенные операции.

В хвостовой рекурсии контекст текущей функции становится ненужным ровно в момент перехода к следующему рекурсивному шагу. Все промежуточные вычисления уже переданы в качестве аргументов (в так называемый аккумулятор). 

Многие современные компиляторы (например, GCC, Clang, MSVC) поддерживают оптимизацию хвостовых вызовов (*Tail Call Optimization*, или *TCO*). 

> **Правило TCO.** Если компилятор обнаруживает, что рекурсивный вызов является хвостовым, он оптимизирует машинный код: вместо инструкции создания нового кадра стека (`CALL`) он выполняет обновление аргументов текущего кадра и безусловный переход к началу функции (`JMP`). 

Благодаря TCO глубина стека вызовов перестает расти линейно $O(n)$ и фиксируется на уровне $O(1)$, что делает рекурсивный алгоритм по потреблению памяти абсолютно эквивалентным циклу `while` или `for`.

---

### Трансформация обычной рекурсии в хвостовую через аккумулятор

Чтобы переписать функцию в хвостовой форме, обычно вводят дополнительный параметр — **аккумулятор** (*accumulator*). Аккумулятор выполняет роль хранилища промежуточного результата, который на каждом шаге обновляется и протаскивается вперед до достижения базового случая.

Алгоритм трансформации:
1. Выделить вычисления, которые выполняются *после* возврата из рекурсивной функции.
2. Ввести дополнительный параметр функции (аккумулятор), начальное значение которого равно нейтральному элементу операции (например, $1$ для умножения, $0$ для сложения).
3. Перенести логику пост-вычислений в момент передачи аргументов в следующий рекурсивный вызов, изменяя значение аккумулятора «на лету».
4. В базовом случаем возвратить накопленное в аккумуляторе значение.

---

### Разобранные примеры

#### Пример 1. Факториал с хвостовой рекурсией и трассировка стека

Реализуем вычисление факториала $n!$ с использованием хвостовой рекурсии и проследим за состоянием памяти для $n = 4$.

Полный листинг программы на C++17:

```cpp
#include <iostream>

// Вспомогательная функция с хвостовой рекурсией и аккумулятором
long long factorial_tail(int n, long long accumulator) {
    // Базовый случай: достигли конца уменьшения, возвращаем накопленный результат
    if (n <= 0) {
        return accumulator;
    }
    // Рекурсивный шаг является хвостовым: операция умножения перенесена в аргументы
    return factorial_tail(n - 1, n * accumulator);
}

// Удобная обернутая функция для пользователя
long long compute_factorial(int n) {
    if (n < 0) return -1; // Обработка некорректного ввода
    return factorial_tail(n, 1); // Начальное значение аккумулятора равно 1
}

int main() {
    int n = 4;
    std::cout << "Factorial of " << n << " is " << compute_factorial(n) << std::endl;
    return 0;
}
```

##### Трассировка выполнения для $n = 4$ (без TCO и с TCO)

При отсутствии оптимизации (*обычная хвостовая рекурсия без включенного флага оптимизации*):

1. Вызывается `compute_factorial(4)`, которая вызывает `factorial_tail(4, 1)`.
2. `factorial_tail(4, 1)`: $4 > 0$, вычисляется аргумент $4 \times 1 = 4$, вызывается `factorial_tail(3, 4)`. В стеке создается кадр №1.
3. `factorial_tail(3, 4)`: $3 > 0$, вычисляется $3 \times 4 = 12$, вызывается `factorial_tail(2, 12)`. В стеке создается кадр №2.
4. `factorial_tail(2, 12)`: $2 > 0$, вычисляется $2 \times 12 = 24$, вызывается `factorial_tail(1, 24)`. В стеке создается кадр №3.
5. `factorial_tail(1, 24)`: $1 > 0$, вычисляется $1 \times 24 = 24$, вызывается `factorial_tail(0, 24)`. В стеке создается кадр №4.
6. `factorial_tail(0, 24)`: $0 \le 0$, базовый случай срабатывает, возвращается число $24$.
7. Раскрутка стека возвращает $24$ сквозь все кадры наверх.

*С оптимизацией TCO (флаг компилятора `-O2` или `-O3` в GCC/Clang):*
Компилятор заменяет рекурсивные вызовы на цикл. В памяти постоянно существует **ровно один** кадр стека функции `factorial_tail`:

| Шаг | Значение $n$ в кадре | Значение аккумулятора в кадре | Действие компилятора (TCO) |
| :--- | :--- | :--- | :--- |
| 1 | `4` | `1` | Перезапись переменных: `n = 3`, `accumulator = 4` |
| 2 | `3` | `4` | Перезапись переменных: `n = 2`, `accumulator = 12` |
| 3 | `2` | `12` | Перезапись переменных: `n = 1`, `accumulator = 24` |
| 4 | `1` | `24` | Перезапись переменных: `n = 0`, `accumulator = 24` |
| 5 | `0` | `24` | Выход из функции, возврат `24` |

Оценка сложности по памяти при включенной TCO составляет $O(1)$, в то время как временная сложность остается линейной $O(n)$, так как совершается ровно $n$ шагов умножения.

#### Пример 2. Сумма элементов массива с хвостовой рекурсией

Рассмотрим задачу рекурсивного суммирования элементов динамического массива. Сравним классическую линейную рекурсию и хвостовую рекурсию для массива из $1000$ элементов.

Полный код программы на C++17, реализующий оба подхода и замеряющий теоретические различия:

```cpp
#include <iostream>
#include <vector>

// 1. Классическая линейная рекурсия (не хвостовая)
// Суммирование элементов от индекса 'index' до конца массива
long long sum_linear(const std::vector<int>& arr, size_t index) {
    // Базовый случай: вышли за пределы массива
    if (index >= arr.size()) {
        return 0;
    }
    // Операция сложения выполняется ПОСЛЕ возврата из рекурсивного вызова
    return arr[index] + sum_linear(arr, index + 1);
}

// 2. Хвостовая рекурсия с аккумулятором
long long sum_tail_helper(const std::vector<int>& arr, size_t index, long long accumulator) {
    // Базовый случай
    if (index >= arr.size()) {
        return accumulator;
    }
    // Рекурсивный вызов является последним оператором; промежуточный итог накапливается в аккумуляторе
    return sum_tail_helper(arr, index + 1, accumulator + arr[index]);
}

long long sum_tail(const std::vector<int>& arr) {
    return sum_tail_helper(arr, 0, 0);
}

int main() {
    // Создаем тестовый массив из 1000 элементов, заполненный единицами
    const size_t N = 1000;
    std::vector<int> data(N, 1);

    long long result_linear = sum_linear(data, 0);
    long long result_tail = sum_tail(data);

    std::cout << "Linear sum result: " << result_linear << std::endl;
    std::cout << "Tail sum result:   " << result_tail << std::endl;

    return 0;
}
```

##### Сравнение потребления памяти для массива из 1000 элементов

Пусть размер одной активационной записи (фрейма стека) для данных функций составляет в среднем $32$ байта (адрес возврата, указатель на массив `arr`, параметры `index` и служебные регистры).

1. **Классическая линейная рекурсия (`sum_linear`):**
   - Глубина рекурсии равна размеру массива: $n = 1000$.
   - Поскольку операция сложения (`+`) ожидает возврата подзадачи, компилятор **не может** удалить текущий кадр стека до тех пор, пока не дойдет до конца массива.
   - Максимальный объем памяти, занимаемый стеком вызовов: 
     $$1000 \text{ кадров} \times 32 \text{ байта/кадр} = 32000 \text{ байт} \approx 31{,}25 \text{ КБ}.$$
   - Пространственная сложность: $O(n)$. Для большего массива ($n = 1000000$) это гарантированно вызовет аварийное завершение программы с ошибкой `Segmentation fault` (или `Stack Overflow`).

2. **Хвостовая рекурсия (`sum_tail` с включенной TCO):**
   - Глубина рекурсии логически также равна $1000$.
   - Благодаря оптимизации хвостовых вызовов компилятор переиспользует единственный стек-фрейм на протяжении всех $1000$ итераций.
   - Максимальный объем памяти, занимаемый стеком вызовов:
     $$1 \text{ кадр} \times 32 \text{ байта/кадр} = 32 \text{ байта}.$$
   - Пространственная сложность: $O(1)$. Потребление памяти константно и не зависит от размера массива $N$.

Ответ: Использование хвостовой рекурсии в сочетании с TCO снижает пространственную сложность алгоритма с $O(n)$ до $O(1)$, что позволяет безопасно обрабатывать структуры данных произвольной глубины без риска исчерпания памяти стека.

## Рекурсивная графика и геометрические фракталы

### Понятие фрактала и самоподобие

До сих пор мы рассматривали рекурсию на примере числовых последовательностей, строк и деревьев данных. Однако рекурсивный подход находит одно из самых наглядных применений в геометрии и компьютерной графике. 

> **Определение.** Фракталом называется геометрическая структура, обладающая свойством самоподобия (invariance of scale), при котором объект целиком или частично повторяет себя при изменении масштаба.

Что это значит на практике? Если мы возьмем отдельный фрагмент сложной геометрической фигуры и увеличим его, то увидим структуру, в точности или с небольшими отклонениями повторяющую всю фигуру целиком. В природе фракталы встречаются повсеместно: это береговые линии, кроны деревьев, молнии, кристаллы снега (снежинки). В программировании фракталы строятся с помощью процедурной генерации, где правила формирования объекта задаются рекурсивно.

### Принцип построения фракталов и управление глубиной рекурсии

Построение геометрических фракталов основывается на последовательном применении геометрического преобразования к базовому объекту (инициатору). Каждый шаг такого преобразования называется итерацией или генерацией нового порядка фрактала.

Процесс проектирования фрактального алгоритма включает два обязательных компонента, знакомых нам по общей теории рекурсии:
1. **Базовый случай (условие остановки):** достижение заданной пользователем максимальной глубины рекурсии $k$ (порядка фрактала) либо достижение минимального размера графического примитива, когда дальнейшая детализация бессмысленна (например, отрезок становится меньше одного пикселя). При достижении базового случая функция прекращает порождать новые подзадачи и просто отрисовывает базовый примитив (линию, точку, треугольник).
2. **Рекурсивный шаг:** разбиение исходного геометрического объекта (например, отрезка или области пространства) на несколько новых подобъектов меньшего размера, к каждому из которых применяется та же самая функция построения, но с уменьшенным на единицу счетчиком глубины рекурсии.

### Организация вывода графических примитивов на двумерной сетке в C++

Для визуализации геометрических объектов в консольных приложениях на языке C++ используется растровая модель: двухмерный массив символов (матрица), где каждый элемент соответствует определенной точке (пикселю) экрана.

Пусть у нас есть холст размером $W \times H$. Мы представляем его в памяти как вектор векторов типа `char`:

```cpp
#include <vector>
#include <iostream>

const int WIDTH = 80;
const int HEIGHT = 40;

// Инициализация холста пустыми символами ' '
std::vector<std::vector<char>> canvas(HEIGHT, std::vector<char>(WIDTH, ' '));
```

Для прорисовки линий и сложных траекторий на такой символьной сетке применяются алгоритмы растеризации. Простейшим инструментом для рисования прямых линий на дискретной сетке является алгоритм Брезенхема или пошаговая интерполяция координат. Если отрезок задан координатами $(x_1, y_1)$ и $(x_2, y_2)$, мы можем пройти по нему с шагом параметра $t \in [0, 1]$:

$$x = \lfloor x_1 + t \cdot (x_2 - x_1) + 0{,}5 \rfloor$$
$$y = \lfloor y_1 + t \cdot (y_2 - y_1) + 0{,}5 \rfloor$$

Полученные целочисленные координаты $(x, y)$ используются для модификации ячейки матрицы холста: `canvas[y][x] = '*';`.

### Разобранный пример 1: Генерация треугольника Серпинского

Рассмотрим построение классического фрактала — треугольника Серпинского. Инициатором является большой равносторонний (или прямоугольный на дискретной сетке) треугольник. На каждом рекурсивном шаге внутри исходного треугольника выделяется центральная пустая область путем соединения середин его сторон, что образует три новых, меньших треугольника по углам. Процесс повторяется до заданного порядка $k$.

В качестве рабочей реализации построим треугольник Серпинского методом заполнения матричного холста пикселями с использованием координат на плоскости.

#### Полная программа на C++17

```cpp
#include <iostream>
#include <vector>
#include <cmath>

// Размеры консольного холста
const int WIDTH = 64;
const int HEIGHT = 32;

// Функция для рекурсивного заполнения треугольника Серпинского на матрице
// x, y - координаты левого верхнего угла текущего блока, size - размер стороны блока
void drawSierpinski(std::vector<std::vector<char>>& canvas, int x, int y, int size) {
    // Базовый случай: если размер блока стал равен 1, ставим символ пикселя
    if (size == 1) {
        if (x >= 0 && x < WIDTH && y >= 0 && y < HEIGHT) {
            canvas[y][x] = '*';
        }
        return;
    }

    // Рекурсивный шаг: делим сторону пополам
    int half = size / 2;

    // Верхний подтреугольник
    drawSierpinski(canvas, x + half, y, half);
    // Левый нижний подтреугольник
    drawSierpinski(canvas, x, y + half, half);
    // Правый нижний подтреугольник
    drawSierpinski(canvas, x + half, y + half, half);
}

int main() {
    // Шаг 1: Инициализация холста пробелами
    std::vector<std::vector<char>> canvas(HEIGHT, std::vector<char>(WIDTH, ' '));

    // Шаг 2: Ввод порядка фрактала (глубины рекурсии)
    int k = 3;
    std::cout << "Vvod poryadka fraktala k = " << k << std::endl;

    // Размер стороны должен быть степенью двойки для корректного деления
    int size = 32; // 2^5, при k=3 размер подблоков уменьшается корректно

    // Шаг 3: Запуск рекурсивного построения
    drawSierpinski(canvas, 0, 0, size);

    // Шаг 4: Вывод полученного холста в консоль
    for (int i = 0; i < HEIGHT / 2; ++i) {
        for (int j = 0; j < size; ++j) {
            std::cout << canvas[i][j];
        }
        std::cout << '\n';
    }

    return 0;
}
```

#### Ход рассуждений и пояснение кода

1. **Идея деления пространства:** Мы рассматриваем прямоугольную область экрана как квадрат со стороной `size`. Деление квадрата на 4 равных квадранта с размерами `half = size / 2` позволяет получить три угловых блока, в которых продолжается построение, и один центральный блок, который оставляется пустым (не вызывается рекурсивно).
2. **Базовый случай:** Когда размер `size` уменьшается до единицы, функция записывает символ `*` в буфер холста `canvas`.
3. **Ограничения сетки:** Проверка `x >= 0 && x < WIDTH` гарантирует отсутствие выхода за границы массива, что предотвращает аварийное завершение программы (Undefined Behavior).

#### Проверка и результаты

При входном значении порядка фрактала $k = 3$ (что соответствует глубине рекурсии, при которой размер стороны базового элемента уменьшается в $2^3 = 8$ раз) на экране формируется симметричный узор из символов `*`, образующий характерные пустоты треугольной формы.

*Ответ:* Программа успешно компилируется командой `g++ -std=c++17 -Wall`, формирует матрицу размером $64 \times 32$ и выводит в консоль корректное текстовое представление треугольника Серпинского за время $O(4^k)$, где $k$ — глубина рекурсии.

### Разобранный предмет 2: Рекурсивный алгоритм построения H-дерева (H-fractal)

H-дерево — это фрактальная структура, состоящая из ортогонально соединенных отрезков, напоминающих латинскую букву «H». Каждый новый уровень рекурсии добавляет четыре меньших H-дерева к четырем концам предыдущей буквы «H», причем масштаб отрезков уменьшается в $\sqrt{2}$ раз, а ориентация чередуется.

#### Описание координат и геометрии для глубины $k = 2$

Пусть начальный отрезок имеет длину $L$ и центр в точке $(X_0, Y_0)$. 
1. Для текущего центра $(x, y)$ и текущей длины отрезка $L$:
   - Рисуется горизонтальный отрезок от $(x - L/2, y)$ до $(x + L/2, y)$.
   - Рисуется левый вертикальный отрезок от $(x - L/2, y - L/2)$ до $(x - L/2, y + L/2)$.
   - Рисуется правый вертикальный отрезок от $(x + L/2, y - L/2)$ до $(x + L/2, y + L/2)$.
2. Рекурсивный шаг порождает 4 новых центра для следующих четырех концевых точек:
   - Левый верхний конец: $(x - L/2, y - L/2)$
   - Правый верхний конец: $(x + L/2, y - L/2)$
   - Левый нижний конец: $(x - L/2, y + L/2)$
   - Правый нижний конец: $(x + L/2, y + L/2)$
3. На каждом шаге длина отрезка уменьшается: $L_{new} = L / 2$.

Ниже приведена полная программа на C++17, реализующая алгоритм построения H-дерева на символьной матрице холста.

```cpp
#include <iostream>
#include <vector>
#include <cmath>

const int CANVAS_W = 77;
const int CANVAS_H = 37;

// Вспомогательная функция для рисования горизонтальной линии на холсте
void drawHorizontal(std::vector<std::vector<char>>& canvas, int x1, int x2, int y) {
    if (y < 0 || y >= CANVAS_H) return;
    int start = std::max(0, std::min(x1, x2));
    int end = std::min(CANVAS_W - 1, std::max(x1, x2));
    for (int x = start; x <= end; ++x) {
        canvas[y][x] = '-';
    }
}

// Вспомогательная функция для рисования вертикальной линии на холсте
void drawVertical(std::vector<std::vector<char>>& canvas, int x, int y1, int y2) {
    if (x < 0 || x >= CANVAS_W) return;
    int start = std::max(0, std::min(y1, y2));
    int end = std::min(CANVAS_H - 1, std::max(y1, y2));
    for (int y = start; y <= end; ++y) {
        canvas[y][x] = '|';
    }
}

// Рекурсивная функция построения H-дерева
void drawHTree(std::vector<std::vector<char>>& canvas, double x, double y, double length, int depth) {
    // Базовый случай: если глубина исчерпана или отрезок слишком мал
    if (depth <= 0 || length < 2.0) {
        return;
    }

    double half = length / 2.0;

    // Вычисляем координаты четырех концов буквы 'H'
    int xLeft  = static_cast<int>(x - half);
    int xRight = static_cast<int>(x + half);
    int yTop   = static_cast<int>(y - half);
    int yBottom= static_cast<int>(y + half);
    int yCenter= static_cast<int>(y);
    int xCenter= static_cast<int>(x);

    // Рисуем элементы текущей буквы 'H'
    drawHorizontal(canvas, xLeft, xRight, yCenter);
    drawVertical(canvas, xLeft, yTop, yBottom);
    drawVertical(canvas, xRight, yTop, yBottom);

    // Рекурсивные вызовы для 4-х ответвлений меньшего масштаба
    double newLength = length / 2.0;
    
    // 1. Левый верхний конец
    drawHTree(canvas, xLeft, yTop, newLength, depth - 1);
    // 2. Правый верхний конец
    drawHTree(canvas, xRight, yTop, newLength, depth - 1);
    // 3. Левый нижний конец
    drawHTree(canvas, xLeft, yBottom, newLength, depth - 1);
    // 4. Правый нижний конец
    drawHTree(canvas, xRight, yBottom, newLength, depth - 1);
}

int main() {
    // Шаг 1: Создание и очистка холста
    std::vector<std::vector<char>> canvas(CANVAS_H, std::vector<char>(CANVAS_W, ' '));

    // Шаг 2: Установка параметров фрактала
    int depth = 3; // Глубина рекурсии k = 3
    double initialLength = 24.0;
    double startX = static_cast<double>(CANVAS_W) / 2.0;
    double startY = static_cast<double>(CANVAS_H) / 2.0;

    std::cout << "Generatsiya H-dereva s glubinoy depth = " << depth << std::endl;

    // Шаг 3: Запуск рекурсивного алгоритма
    drawHTree(canvas, startX, startY, initialLength, depth);

    // Шаг 4: Вывод матрицы на экран
    for (int i = 0; i < CANVAS_H; ++i) {
        for (int j = 0; j < CANVAS_W; ++j) {
            std::cout << canvas[i][j];
        }
        std::cout << '\n';
    }

    return 0;
}
```

#### Ход рассуждений и анализ решения

1. **Декомпозиция:** На каждом шаге функция строит один базовый элемент формы `H`, состоящий из трех отрезков (одного горизонтального и двух вертикальных), после чего вызывает себя ровно 4 раза для каждого из четырех концов этой буквы.
2. **Управление глубиной:** Параметр `depth` уменьшается на единицу с каждым шагом (`depth - 1`). Когда `depth` достигает нуля, рекурсия прекращается.
3. **Сокращение масштаба:** Длина отрезков на каждом следующем уровне делится пополам (`newLength = length / 2.0`), что гарантирует сходящийся геометрический ряд и отсутствие бесконечного роста графических примитивов.

#### Оценка сложности алгоритмов генерации фракталов

Оценим вычислительные затраты и требования к памяти для алгоритмов рекурсивной генерации фракталов.

- **Временная сложность ($T(n)$):** На каждом уровне рекурсии количество порождаемых ветвей умножается на постоянный коэффициент ветвления $B$ (например, для треугольника Серпинского $B = 4$, но три из них активны; для H-дерева $B = 4$). Общее число узлов дерева вызовов для глубины $k$ описывается геометрической прогрессией:
  $$T(k) = 1 + B + B^2 + \dots + B^k = \frac{B^{k+1} - 1}{B - 1} = O(B^k)$$
  Таким образом, временная сложность носит **экспоненциальный характер** относительно глубины рекурсии $k$. При увеличении глубины всего на 1 единицу количество операций возрастает в $B$ раз.

- **Пространственная сложность ($S(k)$):** Объем памяти, занимаемый стеком вызовов процессора, определяется максимальной глубиной вложенности функций, которая в точности равна параметру глубины рекурсии $k$. Следовательно, пространственная сложность рекурсивного алгоритма генерации составляет **$O(k)$**. Дополнительно расходуется память под холст (матрицу), размер которой фиксирован и равен $O(W \cdot H)$, что не зависит от глубины рекурсии.

*Ответ:* Программа построения H-дерева компилируется без ошибок командой `g++ -std=c++17 -Wall`, корректно обрабатывает координаты отрезков на дискретном холсте размером $77 \times 37$ и выводит готовое текстовое изображение фрактальной структуры за время $O(4^k)$.

## Типичные ошибки

1. **Забытый или недостижимый базовый случай.** Если в функции отсутствует условие завершения или аргументы отдаляются от базы вместо сближения, функция вызывает себя бесконечно. Это приводит к исчерпанию доступной памяти стека и аварийному завершению программы с сигналом `Segmentation fault` / `Stack Overflow`.
   *Пример:* `int bad_rec(int n) { return bad_rec(n - 1); }` — отсутствует база `n == 0`.

2. **Избыточные вычисления из-за древовидной структуры.** При реализации рекурсии без мемоизации или итеративного подхода (как в наивных числах Фибоначчи) одни и те же подзадачи вычисляются тысячи раз заново. Время работы возрастает экспоненциально: $O(2^n)$.
   *Решение:* Заменять древовидную рекурсию итеративным циклом с накоплением или сохранять результаты подзадач (динамическое программирование).

3. **Передача крупных объектов по значению.** Если в рекурсивную функцию передавать тяжелые структуры данных (например, `std::string` или `std::vector`) по значению, на каждый вызов будет создаваться полная копия объекта. Это приводит к катастрофическому падению производительности и переполнению памяти.
   *Исправление:* Всегда передавать крупные структуры по константной ссылке: `const std::string& s`.

4. **Изменение глобального состояния вместо возврата значения.** Попытка управлять вычислениями через глобальные переменные или статические счетчики внутри рекурсии нарушает чистоту функций, делает код непредсказуемым при многопоточности и усложняет отладку.
   *Исправление:* Передавать всю необходимую информацию через локальные параметры и возвращать результат через оператор `return`.

5. **Ошибки в типах данных при быстром росте значений.** Рекурсивные алгоритмы для факториалов, степеней или комбинаторики генерируют значения, которые мгновенно превышают лимиты стандартных типов (`int` переполняется уже при $13!$).
   *Исправление:* Использовать типы повышенной разрядности (`long long`, `__int128`) и заранее проверять граничные условия переполнения.

6. **Неправильный выбор хвостовой рекурсии.** Разработчик считает рекурсию хвостовой, забывая, что над результатом вложенного вызова выполняются отложенные операции (например, сложение `n + recursive_call()`). В таком случае компилятор не сможет применить TCO (Tail Call Optimization), и память стека будет расходоваться линейно $O(n)$.

7. **Некорректная обработка отрицательных или нулевых входных данных.** Если в рекурсивной функции для работы со строками или массивами не предусмотреть пустые входные данные (`size == 0`), первый же вызов попытается обратиться к несуществующим индексам.
   *Исправление:* Всегда проверять граничные случаи на входе в функцию (пустые контейнеры, отрицательные индексы).

2. **Сумма цифр числа.** Напишите рекурсивную функцию на C++, которая принимает целое неотрицательное число $n$ и возвращает сумму его цифр в десятичной записи. Вычислите результат для $n = 5893$.
3. **Рекурсивный поиск максимума в массиве.** Напишите рекурсивную функцию на C++, которая находит максимальный элемент в статическом или динамическом векторе целых чисел без использования циклов (`for`, `while`). Вычислите результат для массива `{12, 45, 7, 89, 34, 56}`.
4. **Число вхождений символа.** Напишите рекурсивную функцию на C++, которая подсчитывает, сколько раз заданный символ `target` встречается в строке `s`. Примените функцию для строки `"programming"` и символа `'g'`.
5. **Хвостовая рекурсия для чисел Фибоначчи.** Реализуйте вычисление $n$-го числа Фибоначчи в виде функции с **хвостовой рекурсией**, используя два аккумулятора для хранения предыдущих значений. Вычислите 10-е число Фибоначчи ($F(10)$).
6. **Генерация двоичных строк.** Напишите рекурсивную процедуру на C++, которая выводит все возможные двоичные строки фиксированной длины $L = 3$, состоящие из символов `'0'` и `'1'`.
7. **Проверка сортировки массива.** Напишите рекурсивную функцию на C++, которая проверяет, отсортирован ли переданный массив целых чисел по неубыванию. Проверьте массив `{3, 5, 8, 12, 12, 19}`.
8. **Рекурсивный перевод в двоичную систему.** Напишите рекурсивную функцию на C++, которая выводит на экран двоичное представление положительного целого числа $n$ (без использования циклов). Вычислите вывод для $n = 13$.

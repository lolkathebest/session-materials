## 1. Основы деревьев и бинарные деревья поиска (BST)

### Основы деревьев: базовые понятия и терминология

Линейные структуры данных, такие как массивы, односвязные и двусвязные списки, а также стеки и очереди, эффективны при последовательном доступе или добавлении элементов на границы. Однако поиск элемента в неупорядоченном массиве требует линейного времени $O(n)$, а вставки и удаления в произвольных позициях связаны с необходимостью сдвига памяти. Для работы с иерархическими связями и обеспечения быстрого поиска применяются нелинейные структуры данных — деревья.

> **Определение.** **Ориентированное дерево** (далее просто дерево) — это связный ациклический граф, в котором один из узлов выделен в качестве **корня**, а остальные узлы разбиты на непересекающиеся подмножества, каждое из которых является деревом меньшего уровня (поддеревьями).

Для того чтобы уверенно оперировать терминами при реализации структур данных на языке C++17, введем ключевые понятия:
- **Узел (node)** — базовый элемент дерева, содержащий полезную нагрузку (ключ, данные) и ссылки (указатели) на дочерние узлы.
- **Корень (root)** — единственный узел дерева, не имеющий входящих ребер (родителя). Он служит точкой входа в структуру.
- **Потомок (child)** — узел, на который указывает родительский узел.
- **Родитель (parent)** — узел, содержащий ссылку на текущий узел.
- **Лист (leaf)** — узел, у которого нет дочерних узлов (все указатели на потомки равны `nullptr`).
- **Степень узла** — количество дочерних узлов у данного узла.
- **Глубина узла** — длина пути (количество ребер) от корня дерева до данного узла. Глубина корня равна $0$.
- **Высота узла** — максимальная длина пути от данного узла до какого-либо листа в его поддеревьях. Высота листа равна $0$, высота пустого дерева обычно принимается равной $-1$.
- **Высота дерева** — высота его корневого узла.

Рассмотрим визуальное представление структуры дерева с помощью схемы:

```text
        (15)        <-- Корень (глубина 0, высота 3)
       /    \
     (6)    (23)    <-- Узлы глубины 1
    /   \   /   \
  (4)  (11)(18) (27) <-- Листья (глубина 2, высота 0)
```

### Инвариант бинарного дерева поиска (BST)

Особым классом деревьев являются бинарные деревья, в которых каждый узел имеет не более двух потомков, традиционно называемых левым (`left`) и правым (`right`). На основе бинарного дерева строится структура данных, обеспечивающая эффективный поиск.

> **Определение.** **Бинарное дерево поиска** (Binary Search Tree, BST) — это бинарное дерево, для каждого узла $x$ которого выполняются следующие условия (инвариант BST):
> 1. Все ключи в левом поддереве узла $x$ строго меньше ключа узла $x$.
> 2. Все ключи в правом поддереве узла $x$ строго больше ключа узла $x$.
> 3. Левое и правое поддеревья также являются бинарными деревьями поиска.

Благодаря этому инварианту на каждом шаге поиска мы можем отбрасывать ровно половину потенциальных вариантов, что аналогично алгоритму двоичного поиска в отсортированном массиве, но без затрат на физический сдвиг элементов при вставке и удалении.

### Реализация узла и класса BST на C++17

Для реализации BST на языке C++17 без использования стандартных контейнеров (таких как `std::map` или `std::set`) спроектируем структуру узла `Node` и класс `BinarySearchTree`. Управление памятью будем осуществлять вручную с помощью операторов `new` и `delete`.

```cpp
#include <iostream>
#include <stdexcept>

// Структура, представляющая узел бинарного дерева поиска
struct Node {
    int key;          // Ключ (данные)
    Node* left;       // Указатель на левое поддерево
    Node* right;      // Указатель на правое поддерево

    // Конструктор узла
    explicit Node(int val) : key(val), left(nullptr), right(nullptr) {}
};

// Класс бинарного дерева поиска
class BinarySearchTree {
private:
    Node* root; // Указатель на корень дерева

    // Рекурсивная вспомогательная функция для уничтожения поддерева и освобождения памяти
    void destroyTree(Node* node) {
        if (node != nullptr) {
            destroyTree(node->left);
            destroyTree(node->right);
            delete node;
        }
    }

    // Рекурсивная вставка узла
    Node* insertRecursive(Node* node, int key) {
        if (node == nullptr) {
            return new Node(key);
        }
        if (key < node->key) {
            node->left = insertRecursive(node->left, key);
        } else if (key > node->key) {
            node->right = insertRecursive(node->right, key);
        }
        // Если ключ равен существующему, в данной реализации дубликаты не добавляем
        return node;
    }

    // Рекурсивный поиск узла
    Node* searchRecursive(Node* node, int key) const {
        if (node == nullptr || node->key == key) {
            return node;
        }
        if (key < node->key) {
            return searchRecursive(node->left, key);
        }
        return searchRecursive(node->right, key);
    }

    // Симметричный обход (In-order traversal)
    void inOrderRecursive(Node* node) const {
        if (node != nullptr) {
            inOrderRecursive(node->left);
            std::cout << node->key << " ";
            inOrderRecursive(node->right);
        }
    }

    // Прямой обход (Pre-order traversal)
    void preOrderRecursive(Node* node) const {
        if (node != nullptr) {
            std::cout << node->key << " ";
            preOrderRecursive(node->left);
            preOrderRecursive(node->right);
        }
    }

    // Обратный обход (Post-order traversal)
    void postOrderRecursive(Node* node) const {
        if (node != nullptr) {
            postOrderRecursive(node->left);
            postOrderRecursive(node->right);
            std::cout << node->key << " ";
        }
    }

    // Вычисление высоты поддерева
    int calculateHeight(Node* node) const {
        if (node == nullptr) {
            return -1; // Высота пустого дерева равна -1
        }
        int leftHeight = calculateHeight(node->left);
        int rightHeight = calculateHeight(node->right);
        return 1 + (leftHeight > rightHeight ? leftHeight : rightHeight);
    }

public:
    // Конструктор по умолчанию
    BinarySearchTree() : root(nullptr) {}

    // Деструктор для предотвращения утечек памяти
    ~BinarySearchTree() {
        destroyTree(root);
    }

    // Публичный метод вставки
    void insert(int key) {
        root = insertRecursive(root, key);
    }

    // Публичный метод поиска (возвращает true, если ключ найден)
    bool search(int key) const {
        return searchRecursive(root, key) != nullptr;
    }

    // Итеративный поиск элемента
    bool searchIterative(int key) const {
        Node* current = root;
        while (current != nullptr) {
            if (current->key == key) {
                return true;
            }
            if (key < current->key) {
                current = current->left;
            } else {
                current = current->right;
            }
        }
        return false;
    }

    // Публичный метод вывода дерева симметричным обходом
    void printInOrder() const {
        inOrderRecursive(root);
        std::cout << "\n";
    }

    // Публичный метод получения высоты дерева
    int height() const {
        return calculateHeight(root);
    }
};

int main() {
    BinarySearchTree bst;
    bst.insert(15);
    bst.insert(6);
    bst.insert(23);
    bst.insert(4);
    bst.insert(11);
    bst.insert(18);
    bst.insert(27);

    std::cout << "In-order traversal: ";
    bst.printInOrder();

    int target = 18;
    if (bst.search(target)) {
        std::cout << "Key " << target << " found in BST.\n";
    } else {
        std::cout << "Key " << target << " not found in BST.\n";
    }

    std::cout << "Tree height: " << bst.height() << "\n";

    return 0;
}
```

### Алгоритмы поиска и вставки

#### Поиск элемента
Алгоритм поиска опирается на инвариант BST. Начиная с корневого узла, мы сравниваем искомый ключ `key` с ключом текущего узла:
1. Если текущий узел пуст (`nullptr`) или его ключ равен искомому, поиск завершен. Возвращаем указатель (или булево значение).
2. Если искомый ключ меньше ключа текущего узла, переходим к левому потомку: `current = current->left`.
3. Если искомый ключ больше ключа текущего узла, переходим к правому потомку: `current = current->right`.

Сложность поиска в худшем случае составляет $O(h)$, где $h$ — высота дерева. В сбалансированном дереве $h = \log_2 n$, поэтому сложность равна $O(\log_2 n)$.

#### Вставка элемента
Вставка нового ключа начинается так же, как и поиск. Мы спускаемся по дереву, выбирая левое или правое поддерево в зависимости от значения вставляемого ключа. Достигнув нулевого указателя (`nullptr`), мы создаем новый узел `new Node(key)` и возвращаем его ссылку родительскому узлу.

### Алгоритмы обхода дерева

Обход дерева — это процесс посещения каждого узла дерева ровно один раз. Существует три основных варианта обхода в глубину:
1. **Симметричный (In-order: левое поддерево -> корень -> правое поддерево)**. Для BST этот обход гарантирует вывод ключей в **возрастающем порядке**.
2. **Прямой (Pre-order: корень -> левое поддерево -> правое поддерево)**. Применяется для копирования дерева или сохранения его структуры на диск.
3. **Обратный (Post-order: левое поддерево -> правое поддерево -> корень)**. Используется при удалении дерева, так как сначала удаляются потомки, а затем родительский узел.

### Проблема вырождения BST

Инвариант BST не гарантирует автоматической балансировки дерева. Если элементы поступают в уже отсортированном порядке (например, $1, 2, 3, 4, 5$), каждый новый узел будет добавляться исключительно в правое поддерево предыдущего.

```text
(1)
  \
   (2)
     \
      (3)
        \
         (4)
           \
            (5)
```

В таком случае дерево вырождается в линейный односвязный список. Высота дерева становится равной $h = n - 1$, а временная сложность поиска, вставки и удаления деградирует от логарифмической $O(\log_2 n)$ до линейной $O(n)$, что нивелирует все преимущества древовидных структур данных. Для борьбы с этим эффектом применяются самобалансирующиеся деревья (AVL и красно-чёрные), изучаемые в следующих разделах.

### Разобранные примеры

#### Пример 1. Построение BST и симметричный обход

**Условие:**
Построить бинарное дерево поиска последовательным добавлением ключей: $15, 6, 23, 4, 11, 18, 27$. Нарисовать результирующее дерево словами, показать результат симметричного обхода (in-order).

**Ход рассуждений:**
1. Вставляем $15$. Дерево пустое, $15$ становится корнем.
2. Вставляем $6$. Сравниваем с $15$: $6 < 15$, уходим налево. Левый потомок пуст, создаем узел $6$.
3. Вставляем $23$. Сравниваем с $15$: $23 > 15$, уходим направо. Правый потомок пуст, создаем узел $23$.
4. Вставляем $4$. Сравниваем с $15$ ($4 < 15$, налево). Сравниваем с $6$ ($4 < 6$, налево). Левый потомок узла $6$ пуст, создаем узел $4$.
5. Вставляем $11$. Сравниваем с $15$ ($11 < 15$, налево). Сравниваем с $6$ ($11 > 6$, направо). Правый потомок узла $6$ пуст, создаем узел $11$.
6. Вставляем $18$. Сравниваем с $15$ ($18 > 15$, направо). Сравниваем с $23$ ($18 < 23$, налево). Левый потомок узла $23$ пуст, создаем узел $18$.
7. Вставляем $27$. Сравниваем с $15$ ($27 > 15$, направо). Сравниваем с $23$ ($27 > 23$, направо). Правый потомок узла $23$ пуст, создаем узел $27$.

**Рисунок дерева словами:**
- Корень дерева: `15`
  - Левое поддерево узла `15`: узел `6`
    - Левый потомок узла `6`: узел `4` (лист)
    - Правый потомок узла `6`: узел `11` (лист)
  - Правое поддерево узла `15`: узел `23`
    - Левый потомок узла `23`: узел `18` (лист)
    - Правый потомок узла `23`: узел `27` (лист)

Графическое представление:
```text
        (15)
       /    \
     (6)    (23)
    /   \   /   \
  (4)  (11)(18) (27)
```

**Симметричный обход (In-order):**
Рекурсивно обходим левое поддерево, посещаем корень, обходим правое поддерево:
- Для поддерева узла $6$: обходим левое ($4$), выводим корень ($6$), обходим правое ($11$) -> `4, 6, 11`.
- Выводим корень дерева -> `15`.
- Для поддерева узла $23$: обходим левое ($18$), выводим корень ($23$), обходим правое ($27$) -> `18, 23, 27`.
Итоговая последовательность: `4, 6, 11, 15, 18, 23, 27`. Заметим, что элементы отсортированы по возрастанию.

**Проверка:**
Последовательность полностью упорядочена, что подтверждает корректность соблюдения инварианта BST.

**Ответ:**
Дерево с корнем 15, левым ребенком 6 (потомки 4 и 11) и правым ребенком 23 (потомки 18 и 27). Симметричный обход: `4 6 11 15 18 23 27`.

#### Пример 2. Поиск элемента, определение высоты и сложности

**Условие:**
Выполнить поиск ключа $18$ в полученном в Примере 1 BST, пошагово описывая сравнения с узлами. Определить высоту дерева и сложность поиска.

**Ход рассуждений:**
1. Начинаем поиск с корневого узла. Сравниваем искомый ключ $18$ с ключом корня: $18 \neq 15$.
2. Поскольку $18 > 15$, согласно инварианту BST, искомый элемент может находиться только в правом поддереве. Переходим к узлу $23$.
3. Сравниваем $18$ с ключом текущего узла: $18 \neq 23$.
4. Поскольку $18 < 23$, переходим к левому поддереву узла $23$. Попадаем в узел $18$.
5. Сравниваем $18$ с текущим узлом: $18 == 18$. Ключ найден. Поиск завершен успешно.

**Определение высоты дерева:**
- Листья $4, 11, 18, 27$ имеют высоту $0$.
- Узлы $6$ и $23$ имеют потомков высоты $0$, следовательно, их высота равна $1 + 0 = 1$.
- Корневой узел $15$ имеет поддеревья высоты $1$, следовательно, высота корня равна $1 + 1 = 2$.
Высота дерева $h = 2$.

**Оценка сложности поиска:**
- Количество узлов в дереве $n = 7$.
- Высота дерева $h = 2$.
- В худшем случае количество операций сравнения равно высоте дерева плюс один ($h + 1$). Для нашего сбалансированного дерева сложность поиска составляет $O(h) = O(\log_2 7) \approx O(3)$, что является оптимальным для поисковых структур.

**Проверка:**
Путь поиска состоит из узлов `15 -> 23 -> 18`, длина пути равна $2$ ребрам. Значения шагов согласуются со свойствами бинарного дерева поиска.

**Ответ:**
Шаги поиска: сравнение с 15 (идем вправо), сравнение с 23 (идем налево), сравнение с 18 (найдено). Высота дерева равна 2. Сложность поиска в данном дереве составляет $O(h)$, в общем случае для сбалансированного дерева $O(\log_2 n)$.

## 2. Удаление узлов из BST и поиск минимума/максимума

### Поиск минимального и максимального ключа в BST

Прежде чем переходить к операции удаления узла, необходимо научиться находить в бинарном дереве поиска элементы с минимальным и максимальным значениями. Свойства инварианта BST делают эту задачу тривиальной и не требующей полного обхода дерева.

> **Определение.** Для любого узла бинарного дерева поиска его левое поддерево содержит только ключи, меньшие ключа данного узла, а правое поддерево — только ключи, большие ключа данного узла.

Из этого правила следует геометрическое расположение экстремумов:
- Минимальный элемент в поддереве всегда находится на самом левом пути от текущего узла. Чтобы найти его, нужно начинать с заданного узла и переходить по указателям `left`, пока это возможно.
- Максимальный элемент в поддереве всегда находится на самом правом пути. Для его поиска необходимо переходить по указателям `right` до тех пор, пока правый потомок не станет нулевым (`nullptr`).

Оценим временную сложность поиска минимума и максимума. В худшем случае, если дерево выродилось в линейный список, алгоритм посетит каждый узел на пути от корня до листа, что потребует $O(h)$ времени, где $h$ — высота дерева. В сбалансированном дереве высота $h = \log_2 n$, поэтому поиск выполняется за $O(\log_2 n)$.

Рассмотрим итеративную реализацию функции поиска минимального ключа на языке C++17. Использование цикла вместо рекурсии позволяет избежать расхода стека вызовов:

```cpp
struct Node {
    int key;
    Node* left;
    Node* right;
    
    Node(int val) : key(val), left(nullptr), right(nullptr) {}
};

Node* findMin(Node* root) {
    if (root == nullptr) {
        return nullptr;
    }
    Node* current = root;
    while (current->left != nullptr) {
        current = current->left;
    }
    return current;
}
```

В приведенном коде функция принимает указатель на корень поддерева `root`. Мы проверяем дерево на пустоту. Если оно не пусто, заводим вспомогательный указатель `current` и сдвигаем его влево до упора. Узел, у которого `left` равен `nullptr`, искомый минимум.

### Три случая удаления узла из BST

Удаление узла из бинарного дерева поиска — более сложная операция, чем вставка или поиск. Главная трудность заключается в том, чтобы после удаления узла и освобождения памяти не нарушить инвариант BST. 

Пусть мы хотим удалить узел с ключом $k$. Сначала мы находим этот узел с помощью стандартного поиска. Обозначим найденный узел как $Z$, а его родитель как $P$. В зависимости от количества потомков узла $Z$, возможны ровно три принципиально разных сценария.

#### Случай 1: Узел $Z$ является листом (не имеет потомков)
Это самый простой случай. Поскольку у узла нет детей, его можно просто удалить, а указатель у родителя $P$, который ссылался на $Z$, обнулить (`nullptr`). Инвариант BST при этом не нарушается, так как удаление листа не затрагивает остальные элементы поддерева.

#### Случай 2: Узел $Z$ имеет ровно одного потомка
У узла $Z$ есть либо только левый, либо только правый ребенок. Мы не можем просто удалить $Z$, так как тогда его потомок «потеряется». Решение состоит в том, чтобы «поднять» единственного потомка на место удаляемого узла. То есть родитель $P$ начинает указывать не на $Z$, а напрямую на единственного ребенка узла $Z$. После этого память, занимаемая узлом $Z$, освобождается. Инвариант BST сохраняется, поскольку поддерево единственного ребенка уже было корректно упорядочено относительно своего родителя.

#### Случай 3: Узел $Z$ имеет двух потомков
Это наиболее сложный случай. Узел $Z$ имеет и левое, и правое непустые поддеревья. Если мы просто удалим $Z$, нам придется присоединить два поддерева к родителю $P$, у которого есть место только для одного ребенка. 

Классический алгоритм обхода этой проблемы предложил Томас Хоар. Вместо того чтобы физически удалять узел $Z$ и перестраивать всю структуру вокруг него, мы находим **преемника** (successor) узла $Z$ в порядке обхода in-order. Преемник узла $Z$ — это минимальный элемент в его правом поддереве. У этого преемника гарантированно нет левого потомка (иначе он не был бы минимальным). 

Алгоритм замены:
1. Находим преемника $S$ в правом поддереве узла $Z$.
2. Копируем значение ключа из узла $S$ в узел $Z$ (то есть $Z \to key = S \to key$). Теперь нам нужно удалить не исходный узел $Z$, а узел-преемник $S$, который находится где-то в глубине правого поддерева.
3. Узел $S$ по определению имеет не более одного потомка (только правого, так как левого нет). Это означает, что удаление узла $S$ сводится либо к Случаю 1 (если $S$ — лист), либо к Случаю 2 (если у $S$ есть правый потомок). Мы рекурсивно вызываем процедуру удаления для правого поддерева узла $Z$.

### Реализация функции удаления на C++17

Напишем полную рекурсивную функцию удаления узла для класса `BST`. Функция возвращает указатель на корень поддерева после удаления, что позволяет корректно обновлять связи родительских узлов.

```cpp
#include <iostream>

class BST {
private:
    struct Node {
        int key;
        Node* left;
        Node* right;
        Node(int val) : key(val), left(nullptr), right(nullptr) {}
    };

    Node* root;

    // Вспомогательная функция поиска минимума
    Node* findMin(Node* node) {
        Node* current = node;
        while (current && current->left != nullptr) {
            current = current->left;
        }
        return current;
    }

    // Рекурсивная функция удаления
    Node* removeRecursive(Node* current, int targetKey) {
        if (current == nullptr) {
            return nullptr; // Ключ не найден
        }

        // Шаг 1: Поиск узла для удаления
        if (targetKey < current->key) {
            current->left = removeRecursive(current->left, targetKey);
        } else if (targetKey > current->key) {
            current->right = removeRecursive(current->right, targetKey);
        } else {
            // Узел найден (current — это узел Z)

            // Случай 1 и 2: У узла нет потомков или только один потомок
            if (current->left == nullptr) {
                Node* temp = current->right;
                delete current;
                return temp; // Возвращаем правого потомка (может быть nullptr)
            } 
            else if (current->right == nullptr) {
                Node* temp = current->left;
                delete current;
                return temp; // Возвращаем левого потомка
            }

            // Случай 3: У узла два потомка
            // Находим преемника в правом поддереве (минимальный элемент)
            Node* successor = findMin(current->right);

            // Копируем значение преемника в текущий узел
            current->key = successor->key;

            // Удаляем преемника из правого поддерева
            current->right = removeRecursive(current->right, successor->key);
        }
        return current;
    }

public:
    BST() : root(nullptr) {}

    void remove(int key) {
        root = removeRecursive(root, key);
    }
};
```

Разберем каждую строчку кода удаления:
- Внутри метода `removeRecursive` проверяется базовый случай: если `current == nullptr`, значит, достигнут конец дерева и искомого ключа нет, возвращаем `nullptr`.
- Если `targetKey < current->key`, мы идем в левое поддерево: `current->left = removeRecursive(current->left, targetKey);`. Обратите внимание, что результат выполнения функции присваивается обратно в `current->left`. Это необходимо для того, чтобы родительский узел получил обновленный указатель после удаления дочернего элемента.
- Аналогично для правого поддерева: `current->right = removeRecursive(current->right, targetKey);`.
- Когда `targetKey == current->key`, мы попали на удаляемый узел. Проверяем наличие детей. Если левого ребенка нет (`current->left == nullptr`), мы сохраняем указатель на правого ребенка в переменную `temp`, удаляем текущий узел через `delete current` и возвращаем `temp`. Родительский узел автоматически «подберет» этого правого ребенка.
- Если правого ребенка нет (`current->right == nullptr`), логика симметрична: сохраняем левого ребенка, удаляем текущий узел, возвращаем левого ребенка.
- Если оба ребенка присутствуют, мы находим преемника `successor` с помощью функции `findMin(current->right)`. Перезаписываем ключ текущего узла: `current->key = successor->key;`. После этого запускаем рекурсивное удаление дублирующегося преемника в правом поддереве: `current->right = removeRecursive(current->right, successor->key);`.

### Анализ корректности сохранения инварианта BST после удаления

Докажем индуктивно, что после выполнения операции удаления инвариант BST не нарушается ни для одного оставшегося узла.

1. **Для Случая 1 (удаление листа)**: мы удаляем узел, не имеющий потомков. Связь родителя с этим узлом заменяется на `nullptr`. Никакие другие ключи в дереве не перемещаются и не изменяются. Отношения «меньше/больше» между оставшимися узлами остаются прежними.
2. **Для Случая 2 (удаление узла с одним потомком)**: пусть узел $Z$ имел единственного потомка $C$. Поскольку $Z$ удовлетворял инварианту BST, все ключи в левом поддереве $C$ меньше $C$, а в правом — больше (если $C$ был правым потомком) или наоборот. Поднятие $C на место $Z$ сохраняет это свойство относительно родителя $P$, так как потомок $C$ уже находился на правильной стороне от $Z$.
3. **Для Случая 3 (удаление узла с двумя потомками)**: мы заменяем значение ключа в удаляемом узле $Z$ на значение ключа его преемника $S$. Преемник $S$ является минимальным элементом в правом поддереве узла $Z$. Это означает, что он строго больше всех элементов в левом поддереве узла $Z$ и строго меньше всех остальных элементов в правом поддереве узла $Z$. Такая замена эквивалентна сохранению порядка сортировки. Последующее физическое удаление узла $S$ из правого поддерева сводится к Случаю 1 или Случаю 2, корректность которых уже доказана.

#### Пример 1: Удаление узла с двумя потомками

**Условие:**
Дано бинарное дерево поиска, построенное последовательным добавлением ключей: $15, 6, 23, 4, 11, 18, 27$. 
Необходимо удалить узел с ключом $6$ (это узел с двумя потомками). Описать выбор преемника, перестановку ключей и указателей, а также финальную структуру дерева.

**Рисунок дерева (словами):**
Корень дерева — узел $15$.
У узла $15$ два потомка: левый $6$, правый $23$.
У узла $6$ два потомка: левый $4$, правый $11$.
У узла $23$ два потомка: левый $18$, правый $27$.
Все листья ($4, 11, 18, 27$) потомков не имеют.

**Ход рассуждений:**
1. Находим узел для удаления: $Z = 6$. Он имеет двух потомков ($4$ и $11$), поэтому это Случай 3.
2. Ищем преемника узла $6$ в его правом поддереве. Правое поддерево узла $6$ состоит из единственного узла $11$ (его левое поддерево пусто). Следовательно, преемник $S = 11$.
3. Копируем ключ преемника в удаляемый узел: $Z \to key = 11$. Теперь в узле, где раньше была цифра $6$, записана цифра $11$. В дереве временно образовалось два узла с ключом $11$ (один на месте корня поддерева, другой — в листе).
4. Запускаем рекурсивное удаление ключа $11$ в правом поддереве узла $6$. Узел $11$ является листовым узлом (Случай 1), поэтому он просто удаляется из памяти, а указатель его родителя (узла $6$) становится равным `nullptr`.
5. Итоговый узел $6$ (теперь с ключом $11$) сохраняет своего левого ребенка $4$, а его правый ребенок становится равным `nullptr`.

**Финальная структура дерева (словами):**
Корень — $15$.
Левый ребенок корня — узел $11$ (бывший узел $6$). У него остался левый ребенок $4$, а правый ребенок стал `nullptr`.
Правый ребенок корня — узел $23$ (его дети: левый $18$, правый $27$).

**Симметричный обход (in-order) полученного дерева:**
$4, 11, 15, 18, 23, 27$. (Заметим, что числа идут строго по возрастанию, что подтверждает корректность инварианта BST).

`Ответ:` Корень $15$; левый поддерево корня содержит узел $11$ с единственным левым потомком $4$; правое поддерево корня остается без изменений (узел $23$ с потомками $18$ и $27$).

#### Пример 2: Удаление листового узла и узла с единственным потомком

**Условие:**
Используя исходное дерево из Примера 1 (корни $15, 6, 23, 4, 11, 18, 27$):
1. Удалить листовой узел с ключом $4$.
2. Затем удалить узел $23$, у которого есть единственный потомок $27$ (предположим для этого примера, что у узла $23$ был только правый потомок $27$, а левый узел $18$ был удален ранее для демонстрации этого случая).
Показать пошагово состояние дерева.

**Ход рассуждений (Шаг 1: Удаление листа $4$):**
1. Ищем узел с ключом $4$. Он находится в левом поддереве узла $6$.
2. Узел $4$ не имеет потомков (листовой узел, Случай 1).
3. Применяем процедуру удаления: узел $4$ удаляется из памяти `delete`, а поле `left` его родителя (узла $6$) получает значение `nullptr`.

*Состояние дерева после удаления ключа 4:*
Корень — $15$.
Узел $6$ имеет только правого потомка $11$ (левый потомок отсутствует).
Правое поддерево ($23$ с потомками $18$ и $27$) остается без изменений.

**Ход рассуждений (Шаг 2: Удаление узла $23$ с единственным потомком):**
Пусть перед этим шагом из правого поддерева был удален узел $18$, так что у узла $23$ остался ровно один потомок — правый ребенок $27$ (Случай 2).
1. Ищем узел с ключом $23$. Он является правым ребенком корня $15$.
2. Узел $23$ имеет ровно одного потомка — узел $27$.
3. Применяем процедуру удаления: мы должны «поднять» потомка $27$ на место узла $23$. Для этого родитель узла $23$ (то есть корень $15$) перенаправляет свой правый указатель (`right`) напрямую на узел $27$.
4. Память, занимаемая узлом $23$, освобождается с помощью `delete`.

*Состояние дерева после удаления ключа 23:*
Корень — $15$.
Левое поддерево: узел $6$ (с правым потомком $11$).
Правое поддерево: узел $27$ (который теперь стал непосредственным правым ребенком корня $15$).

**Проверка правдоподобия:**
Проверим инвариант BST для нового дерева:
- Все элементы в левом поддереве ($6, 11$) меньше корня ($15$).
- Единственный элемент в правом поддереве ($27$) больше корня ($15$).
Инвариант полностью соблюден, структура дерева осталась корректной.

`Ответ:` После удаления ключа $4$ дерево теряет левый лист узла $6$. После удаления узла $23$ его единственный оставшийся потомок $27$ становится прямым правым ребенком корневого узла $15$.

## 3. Самобалансирующиеся AVL-деревья

### Понятие фактора баланса и инвариант AVL-дерева

Как вы знаете из предыдущих тем, обычные бинарные деревья поиска (BST) в худшем случае могут вырождаться в линейный список (например, при последовательной вставке уже отсортированных данных). В таком случае высота дерева $h$ становится равной числу узлов $n$, а все основные операции (поиск, вставка, удаление) деградируют от эффективного логарифмического времени $O(\log n)$ до линейного $O(n)$.

Чтобы гарантировать логарифмическую сложность операций в любой ситуации, советские математики Георгий Адельсон-Вельский и Евгений Ландис в 1962 году предложили первое в истории самобалансирующееся дерево поиска, названное в их честь **AVL-деревом**.

> **Определение.** **AVL-дерево** — это бинарное дерево поиска, в котором для каждого узла высота его левого и правого поддеревьев различается не более чем на 1.

Для формализации этого правила в каждый узел дерева добавляют целочисленное поле, хранящее высоту поддерева с корнем в данном узле, либо специальный параметр — **фактор баланса**.

> **Определение.** **Фактором баланса узла** (balance factor, далее — $balance$) называется разность между высотой левого поддерева и высотой правого поддерева этого узла:
>
> $$balance(node) = height(node \to left) - height(node \to right)$$

При этом под высотой пустого поддерева (когда указатель равен `nullptr`) принято понимать $-1$, а высота листа (узла без потомков) равна $0$.

> **Определение.** **Инвариант AVL-дерева** (или условие сбалансированности): для каждого узла $v$ данного дерева выполняется неравенство:
>
> $$-1 \le balance(v) \le 1$$

Если в какой-то момент после вставки или удаления узла этот инвариант нарушается хотя бы для одного узла (его фактор баланса становится равным $-2$ или $+2$), дерево считается разбалансированным, и необходимо выполнить восстанавливающие операции — **повороты**.

---

### Математическое обоснование гарантированной высоты AVL-дерева

Строгое поддержание инварианта $-1 \le balance \le 1$ накладывает жесткое ограничение на максимально возможную высоту AVL-дерева, содержащего $n$ узлов. Докажем, что высота AVL-дерева всегда растет логарифмически от числа элементов.

Обозначим через $N(h)$ минимальное число узлов, которое может содержать AVL-дерево высоты $h$. Построим рекурсивное соотношение для этой величины.
1. Дерево высоты $h$ с минимальным числом узлов должно быть устроено так, чтобы одно из его поддеревей имело высоту $h - 1$, а второе — максимально возможное для минимального дерева меньшей высоты, то есть высоту $h - 2$.
2. Сам корень дерева добавляет еще 1 узел.

Таким образом, получаем рекуррентное уравнение:

$$N(h) = N(h - 1) + N(h - 2) + 1$$

Базовые случаи для рекурсии:
- Высота $h = 0$ (дерево из одного узла): $N(0) = 1$.
- Высота $h = 1$ (корень и один потомок): $N(1) = 2$.

Вспомним классические числа Фибоначчи $F_k$, где $F_0 = 0, F_1 = 1, F_2 = 1, F_3 = 2, \dots$ Решением нашего уравнения через числа Фибоначчи является точное выражение:

$$N(h) = F_{h + 3} - 1$$

Из курса математического анализа известно, что числа Фибоначчи растут по экспоненциальному закону, связанному с золотым сечением $\varphi = \frac{1 + \sqrt{5}}{2} \approx 1{,}618$:

$$F_k \approx \frac{\varphi^k}{\sqrt{5}}$$

Следовательно, для числа узлов $n$ выполняется оценка:

$$n \ge N(h) \approx \frac{\varphi^{h + 3}}{\sqrt{5}} - 1$$

Прологарифмируем это неравенство по основанию 2, чтобы выразить высоту $h$ через количество узлов $n$:

$$n + 1 \ge \frac{\varphi^{h + 3}}{\sqrt{5}}$$

$$\sqrt{5}(n + 1) \ge \varphi^{h + 3}$$

$$\log_2(\sqrt{5}(n + 1)) \ge (h + 3) \log_2 \varphi$$

Выразим высоту $h$:

$$h \le \frac{\log_2(n + 1) + \log_2 \sqrt{5}}{\log_2 \varphi} - 3$$

Подставим числовые значения: $\log_2 \varphi \approx 0{,}694$, а $\frac{1}{0{,}694} \approx 1{,}44$, а также учтем константы. После упрощения получаем искомую формулу верхней границы высоты AVL-дерева:

$$h \le 1{,}44 \log_2(n + 2) - 0{,}328$$

> **Вывод.** Высота AVL-дерева с $n$ узлами в худшем случае составляет примерно $1{,}44 \log_2 n$, что гарантирует выполнение всех поисковых операций и обходов за время $O(\log n)$.

### Базовые и сложные операции поворота

Восстановление баланса в AVL-дереве достигается с помощью локальных структурных перестроек, называемых **поворотами** (rotations). При этом сохраняется главное свойство бинарного дерева поиска: порядок элементов при симметричном обходе (in-order) не меняется.

Выделяют четыре типа нарушений баланса в зависимости от того, в каком поддереве произошел сбой:
1. **LL-нарушение:** левое поддерево левого сына слишком тяжелое ($balance(parent) = +2$, $balance(left\_child) \ge 0$). Устраняется **малым правым поворотом**.
2. **RR-нарушение:** правое поддерево правого сына слишком тяжелое ($balance(parent) = -2$, $balance(right\_child) \le 0$). Устраняется **малым левым поворотом**.
3. **LR-нарушение:** правое поддерево левого сына слишком тяжелое ($balance(parent) = +2$, $balance(left\_child) < 0$). Устраняется **большим правым поворотом** (комбинация левого и правого).
4. **RL-нарушение:** левое поддерево правого сына слишком тяжелое ($balance(parent) = -2$, $balance(right\_child) > 0$). Устраняется **большим левым поворотом** (комбинация правого и левого).

#### Малый правый поворот (LL-поворот)

Представим поддерево, где узел $Y$ имеет левого сына $X$, а у узла $X$ есть левый сын $A$ и правый сын $B$. Узел $Y$ перегружен слева ($balance = +2$).

Схема до поворота:
```
       Y (balance = +2)
      / \
     X   C
    / \
   A   B
```

Схема после малого правого поворота вокруг узла $Y$:
```
       X (новый корень)
      / \
     A   Y
        / \
       B   C
```

*Как это работает:* Узел $X$ становится новым корнем поддерева. Бывший правый сын узла $X$ (узел $B$) переподключается как левый сын узла $Y$. Узел $Y$ становится правым сыном узла $X$. После поворота высоты поддеревьев пересчитываются снизу вверх.

#### Малый левый поворот (RR-поворот)

Здесь перегружено правое поддерево ($balance = -2$). Узел $Y$ имеет правого сына $X$, у которого есть левый сын $B$ и правый сын $C$.

Схема до поворота:
```
   Y (balance = -2)
  / \
 A   X
    / \
    B  C
```

Схема после малого левого поворота вокруг узла $Y$:
```
       X (новый корень)
      / \
     Y   C
    / \
   A   B
```

#### Сложные повороты: Большой правый поворот (LR) и Большой левый поворот (RL)

Если у родителя $balance = +2$, а у его левого сына $balance = -1$ (то есть дисбаланс имеет «зигзагообразный» характер), малый правый поворот не поможет восстановить баланс. 
- **Большой правый поворот (LR)** состоит из двух шагов: сначала выполняется малый *левый* поворот относительно левого сына (превращая LR-ситуацию в LL), а затем малый *правый* поворот относительно корня.
- **Большой левый поворот (RL)** симметрично состоит из малого *правого* поворота относительно правого сына, а затем малого *левого* поворота относительно корня.

### Пошаговый разобранный пример 1: Вставка элементов 10, 20, 30 и малый левый поворот (RR)

Рассмотрим процесс построения AVL-дерева с нуля при последовательном добавлении ключей: `10`, `20`, `30`.

#### Шаг 1. Вставка ключа 10
Дерево пусто. Создаем корневой узел со значением `10`.
- Высота: $h = 0$.
- Фактор баланса: $balance(10) = 0$.

Состояние дерева:
```
  10 (h=0, bal=0)
```

#### Шаг 2. Вставка ключа 20
Сравниваем `20` с корнем `10`. Так как $20 > 10$, узел `20` отправляется в правое поддерево.
- Обновляем высоты и балансы:
  - Узел `20` становится листом: $height = 0, balance = 0$.
  - Узел `10`: левое поддерево пусто ($height = -1$), правое поддерево содержит `20` ($height = 0$). Фактор баланса: $balance(10) = (-1) - 0 = -1$.
- Инвариант не нарушен ($-1 \le -1 \le 1$).

Состояние дерева:
```
  10 (h=1, bal = -1)
    \
     20 (h=0, bal = 0)
```

#### Шаг 3. Вставка ключа 30
Сравниваем `30` с корнем `10` ($30 > 10$), идем направо. В правом поддереве встречаем `30 > 20`, добавляем `30` как правого сына узла `20`.
- Обновляем высоты снизу вверх:
  - Узел `30`: лист, $height = 0, balance = 0$.
  - Узел `20`: левое пустое ($height = -1$), правое `30` ($height = 0$). $balance(20) = (-1) - 0 = -1$.
  - Узел `10`: левое пустое ($height = -1$), правое `20` ($height = 1$, так как высота поддерева узла `20` равна 1). $balance(10) = (-1) - 1 = \mathbf{-2}$.

**Анализ дисбаланса:** Узел `10` имеет фактор баланса $-2$. Это **RR-нарушение** (правое поддерево правого сына перегружено).

#### Шаг 4. Применение малого левого поворота (RR)
Применяем малый левый поворот вокруг корня `10`:
1. Новый корень поддерева — узел `20`.
2. Бывший левый сын узла `20` (отсутствовал или был пустым) заменяется на узел `10` в качестве левого потомка.
3. Узел `30` остается правым потомком узла `20`.

Обновляем высоты после поворота:
- Узел `10`: потомков нет, $height = 0, balance = 0$.
- Узел `30`: потомков нет, $height = 0, balance = 0$.
- Узел `20`: левый сын `10` ($h=0$), правый сын `30` ($h=0$). $height = 1, balance(20) = 0 - 0 = 0$.

Итоговое сбалансированное AVL-дерево:
```
      20 (h=1, bal=0)
     /  \
   10    30
 (h=0)  (h=0)
```

### Пошаговый разобранный пример 2: Вставка ключа 25 и большой правый поворот (LR)

Продолжим работу с полученным деревом (корни: `20`, левый `10`, правый `30`). Вставим в него новый ключ `25`.

#### Шаг 1. Поиск места и вставка
1. Сравниваем `25` с корнем `20`: $25 > 20$, идем в правое поддерево.
2. В правом поддереве встречаем `30`: $25 < 30$, идем в левое поддерево узла `30`.
3. Левое поддерево узла `30` пусто. Создаем новый узел со значением `25` как левого сына узла `30`.

#### Шаг 2. Обновление высот и поиск дисбаланса снизу вверх
- Узел `25`: лист, $height = 0, balance = 0$.
- Узел `30`: левый сын `25` ($h=0$), правого нет ($h=-1$). $balance(30) = 0 - (-1) = \mathbf{+1}$.
- Узел `20`: левый сын `10` ($h=0$), правый сын `30` ($h=1$). $balance(20) = 0 - 1 = \mathbf{-1}$.

Все узлы находятся в пределах нормы ($-1 \le balance \le 1$). Дерево сбалансировано.

Текущая структура:
```
        20 (bal = -1)
       /  \
     10    30 (bal = +1)
          /
         25
```

*Подождите, добавим еще один элемент, чтобы продемонстрировать сложный поворот LR, как заявлено в плане конспекта!* 
Пусть исходное дерево после первого примера было:
```
      20
     /  \
   10    30
```
Вставим в него ключ `15`.
1. Сравниваем `15` с `20` ($15 < 20$), идем налево к `10`.
2. Сравниваем `15` с `10` ($15 > 10$), идем направо. Правого сына у `10` нет.
3. Создаем узел `15` как правого сына узла `10`.

Обновляем балансы снизу вверх:
- Узел `15`: $height = 0, balance = 0$.
- Узел `10`: левого нет ($h=-1$), правый `15` ($h=0$). $balance(10) = -1 - 0 = \mathbf{-1}$.
- Узел `20`: левый сын `10` ($h=1$), правый сын `30` ($h=0$). $balance(20) = 1 - 0 = \mathbf{+2}$.

**Анализ дисбаланса:** Корень `20` имеет фактор баланса $+2$. Его левый сын `10` имеет фактор баланса $-1$. Это ситуация **LR (большой правый поворот)**, так как у родителя баланс $+2$, а у левого сына баланс отрицательный.

#### Шаг 3. Выполнение большого правого поворота (LR)
Большой правый поворот выполняется в два подэтапа:
1. **Малый левый поворот** относительно левого сына (узла `10`):
   - Узел `15` становится новым родителем вместо `10`.
   - Узел `10` становится левым сыном узла `15`.
   - Промежуточное поддерево:
     ```
          20 (bal = +2)
         /
       15 (левый сын узла 20)
      /
     10
     ```
2. **Малый правый поворот** относительно корня (`20`):
   - Узел `15` становится новым корнем всего дерева.
   - Узел `20` становится правым сыном узла `15`.
   - Узел `10` остается левым сыном узла `15`.
   - Узел `30` становится правым сыном узла `20`.

Обновляем все высоты и балансы для финального дерева:
- Узел `10`: $h = 0, balance = 0$.
- Узел `30`: $h = 0, balance = 0$.
- Узел `20`: левый и правый отсутствуют ($h = 0$), $balance(20) = 0$.
- Узел `15`: левый `10` ($h=0$), правый `20` ($h=1$), $balance(15) = 0 - 1 = -1$.

Итоговое сбалансированное AVL-дерево после LR-поворота:
```
         15 (h=2, bal = -1)
        /  \
      10    20 (h=1, bal = 0)
    (h=0)     \
               30 (h=0)
```

### Алгоритм поддержания баланса на C++17

Ниже представлена полная, компилируемая реализация узла и основных методов балансировки AVL-дерева на языке C++17 с использованием сырых указателей и ручным управлением памятью.

```cpp
#include <iostream>
#include <algorithm>
#include <stdexcept>

// Структура узла AVL-дерева
struct AVLNode {
    int key;
    int height;
    AVLNode* left;
    AVLNode* right;

    explicit AVLNode(int k) 
        : key(k), height(1), left(nullptr), right(nullptr) {}
};

class AVLTree {
private:
    AVLNode* root;

    // Вспомогательная функция для получения высоты узла (безопасно для nullptr)
    int height(AVLNode* node) const {
        return node ? node->height : 0;
    }

    // Вспомогательная функция для вычисления фактора баланса
    int getBalanceFactor(AVLNode* node) const {
        return node ? height(node->left) - height(node->right) : 0;
    }

    // Обновление высоты узла на основе высот его потомков
    void updateHeight(AVLNode* node) {
        if (node) {
            node->height = 1 + std::max(height(node->left), height(node->right));
        }
    }

    // Малый правый поворот (LL)
    AVLNode* rotateRight(AVLNode* y) {
        AVLNode* x = y->left;
        AVLNode* T2 = x->right;

        // Выполнение поворота
        x->right = y;
        y->left = T2;

        // Обновление высот снизу вверх
        updateHeight(y);
        updateHeight(x);

        return x; // Новый корень поддерева
    }

    // Малый левый поворот (RR)
    AVLNode* rotateLeft(AVLNode* x) {
        AVLNode* y = x->right;
        AVLNode* T2 = y->left;

        // Выполнение поворота
        y->left = x;
        x->right = T2;

        // Обновление высот
        updateHeight(x);
        updateHeight(y);

        return y; // Новый корень поддерева
    }

    // Рекурсивная вставка узла с балансировкой
    AVLNode* insert(AVLNode* node, int key) {
        // 1. Стандартная вставка бинарного дерева поиска
        if (!node) {
            return new AVLNode(key);
        }

        if (key < node->key) {
            node->left = insert(node->left, key);
        } else if (key > node->key) {
            node->right = insert(node->right, key);
        } else {
            return node; // Дубликаты ключей не поддерживаем
        }

        // 2. Обновление высоты текущего предка
        updateHeight(node);

        // 3. Получение фактора баланса для проверки нарушения инварианта
        int balance = getBalanceFactor(node);

        // 4. Устранение возможных 4 типов дисбаланса

        // LL Case (Левый-Левый)
        if (balance > 1 && key < node->left->key) {
            return rotateRight(node);
        }

        // RR Case (Правый-Правый)
        if (balance < -1 && key > node->right->key) {
            return rotateLeft(node);
        }

        // LR Case (Левый-Правый)
        if (balance > 1 && key > node->left->key) {
            node->left = rotateLeft(node->left);
            return rotateRight(node);
        }

        // RL Case (Правый-Левый)
        if (balance < -1 && key < node->right->key) {
            node->right = rotateRight(node->right);
            return rotateLeft(node);
        }

        return node; // Возвращаем неизмененный указатель на узел
    }

    // Поиск минимального узла (используется при удалении)
    AVLNode* findMin(AVLNode* node) const {
        AVLNode* current = node;
        while (current && current->left != nullptr) {
            current = current->left;
        }
        return current;
    }

    // Рекурсивное удаление узла с балансировкой
    AVLNode* remove(AVLNode* node, int key) {
        if (!node) {
            return nullptr;
        }

        // 1. Поиск удаляемого узла
        if (key < node->key) {
            node->left = remove(node->left, key);
        } else if (key > node->key) {
            node->right = remove(node->right, key);
        } else {
            // Узел найден
            // Случай 1: 0 или 1 потомок
            if (!node->left || !node->right) {
                AVLNode* temp = node->left ? node->left : node->right;

                if (!temp) { // Нет потомков (лист)
                    temp = node;
                    node = nullptr;
                } else { // Один потомок
                    *node = *temp; // Копируем данные
                }
                delete temp;
            } else {
                // Случай 2: Два потомка. Находим преемника в правом поддереве
                AVLNode* temp = findMin(node->right);
                node->key = temp->key;
                node->right = remove(node->right, temp->key);
            }
        }

        if (!node) {
            return nullptr;
        }

        // 2. Обновление высоты
        updateHeight(node);

        // 3. Проверка баланса и устранение дисбалансов при удалении
        int balance = getBalanceFactor(node);

        // LL Case
        if (balance > 1 && getBalanceFactor(node->left) >= 0) {
            return rotateRight(node);
        }

        // LR Case
        if (balance > 1 && getBalanceFactor(node->left) < 0) {
            node->left = rotateLeft(node->left);
            return rotateRight(node);
        }

        // RR Case
        if (balance < -1 && getBalanceFactor(node->right) <= 0) {
            return rotateLeft(node);
        }

        // RL Case
        if (balance < -1 && getBalanceFactor(node->right) > 0) {
            node->right = rotateRight(node->right);
            return rotateLeft(node);
        }

        return node;
    }

    // Рекурсивное уничтожение дерева для деструктора
    void clearTree(AVLNode* node) {
        if (node) {
            clearTree(node->left);
            clearTree(node->right);
            delete node;
        }
    }

    // Симметричный обход для проверки порядка элементов
    void inOrderTraversal(AVLNode* node) const {
        if (node) {
            inOrderTraversal(node->left);
            std::cout << node->key << " ";
            inOrderTraversal(node->right);
        }
    }

public:
    AVLTree() : root(nullptr) {}

    ~AVLTree() {
        clearTree(root);
    }

    void insert(int key) {
        root = insert(root, key);
    }

    void remove(int key) {
        root = remove(root, key);
    }

    void printInOrder() const {
        inOrderTraversal(root);
        std::cout << std::endl;
    }
};

// Главная функция с демонстрацией работы
int main() {
    AVLTree tree;

    // Вставка элементов, приводящая к различным поворотам
    tree.insert(10);
    tree.insert(20);
    tree.insert(30); // Вызовет RR поворот
    tree.insert(15); // Вызовет LR поворот

    std::cout << "In-order обход после вставки 10, 20, 30, 15: ";
    tree.printInOrder();

    // Удаление элемента
    tree.remove(20);
    std::cout << "In-order обход после удаления элемента 20: ";
    tree.printInOrder();

    return 0;
}
```

#### Пояснение по строкам и блокам кода:
- Структура `AVLNode` содержит указатели на левого и правого потомков, ключ элемента, а также поле `height`, необходимое для быстрого вычисления факторов баланса за время $O(1)$.
- Методы `rotateRight` и `rotateLeft` выполняют переброску указателей согласно теоретическим схемам малых поворотов и задействуют вспомогательную функцию `updateHeight` для корректного пересчета высот во всех затронутых узлах.
- В методе `insert` после стандартной рекурсивной вставки и обновления высоты проверяется `balance` узла. Если он выбивается за пределы $[-1, 1]$, вызываются соответствующие простые или составные повороты.

#### Пример ввода и вывода:
*Ввод (вызовы методов в `main`):*
```cpp
tree.insert(10);
tree.insert(20);
tree.insert(30);
tree.insert(15);
tree.remove(20);
```

*Вывод программы:*
```text
In-order обход после вставки 10, 20, 30, 15: 10 15 20 30 
In-order обход после удаления элемента 20: 10 15 30 
```

#### Оценка сложности:
- **Временная сложность:** 
  - Поиск: $O(\log n)$ в худшем случае.
  - Вставка: $O(\log n)$ (включая не более $\log n$ шагов подъема по стеку рекурсии и не более 2 поворотов на всю операцию вставки).
  - Удаление: $O(\log n)$ (может потребовать поворотов на каждом уровне подъема из-за каскадного уменьшения высоты, но их суммарное число ограничено высотой дерева).
- **Пространственная сложность:** $O(n)$ для хранения $n$ узлов в памяти, а также дополнительные $O(\log n)$ ячеек в стеке вызовов рекурсивных функций из-за гарантированной логарифмической высоты дерева.

## 4. Красно-чёрные деревья (Red-Black Trees)

### 1. Определение и назначение красно-чёрных деревьев

Как вы уже знаете из изучения бинарных деревьев поиска (BST), классическое BST в худшем случае (при вставке отсортированных данных) вырождается в обычный связный список со временем выполнения операций поиска, вставки и удаления $O(n)$. Для борьбы с этой проблемой применяются самобалансирующиеся деревья. Одним из самых эффективных и широко используемых на практике видов таких деревьев является **красно-чёрное дерево** (Red-Black Tree, RBT).

> **Определение.** Красно-чёрное дерево — это самобалансирующееся двоичное дерево поиска, каждый узел которого хранит дополнительный бит информации — **цвет** (красный или чёрный). Этот цвет используется для того, чтобы гарантировать, что дерево остаётся примерно сбалансированным в ходе операций вставки и удаления.

Помимо стандартных полей BST (ключа, указателей на левого потомка, правого потомка и родителя), каждый узел красно-чёрного дерева содержит поле цвета:

```cpp
enum Color { RED, BLACK };

struct Node {
    int data;
    Color color;
    Node* left;
    Node* right;
    Node* parent;

    Node(int val) : data(val), color(RED), left(nullptr), right(nullptr), parent(nullptr) {}
};
```

Обратите внимание: новый узел при создании всегда получает **красный** цвет. Это правило лежит в основе алгоритмов восстановления баланса.

---

### 2. Пять фундаментальных инвариантов красно-чёрного дерева

Балансировка красно-чёрного дерева обеспечивается строгим соблюдением пяти правил (инвариантов). Если в результате вставки или удаления какой-либо инвариант нарушается, дерево перестраивается с помощью перекрашивания узлов и поворотов.

> **Определение.** Инварианты красно-чёрного дерева:
> 1. Каждый узел либо красный, либо чёрный.
> 2. Корень дерева всегда чёрный.
> 3. Все листья дерева (внешние фиктивные узлы, часто называемые `NIL` или `NULL`) — чёрные. В программной реализации вместо множества различных листовых указателей часто используют один общий фиктивный узел-терминал.
> 4. Если узел красный, то оба его потомка — чёрные (у красного узла не может быть красных родителей или красных детей; иными словами, на путях не могут идти подряд два красных узла).
> 5. Для каждого узла все простые пути от этого узла до листовых узлов, являющихся потомками этого узла, содержат одинаковое количество чёрных узлов.

Количество чёрных узлов на пути от узла $x$ до любого листа (не включая сам узел $x$) называется **чёрной высотой** узла и обозначается как $bh(x)$. Инвариант 5 гарантирует, что чёрная высота любого узла определена однозначно.

---

### 3. Гарантия максимальной высоты дерева

Строгое соблюдение описанных пяти инвариантов позволяет математически доказать ограничение на высоту красно-чёрного дерева.

> **Теорема.** Красно-чёрное дерево, содержащее $n$ внутренних узлов, имеет высоту $h$, не превосходящую $2 \log_2(n + 1)$.

#### Обоснование по шагам:
1. Рассмотрим поддерево с корнем в произвольном узле $x$. Пусть его чёрная высота равна $bh(x)$.
2. По индукции можно показать, что любое поддерево с корнем в узле $x$ содержит не менее $2^{bh(x)} - 1$ внутренних узлов.
   - База: если чёрная высота равна 0, поддерево содержит $2^0 - 1 = 0$ узлов (только лист).
   - Шаг: каждый узел имеет двух потомков. Если узел чёрный, его потомки имеют чёрную высоту $bh(x) - 1$. Если узел красный, его потомки чёрные и имеют чёрную высоту $bh(x) - 1$. В обоих случаях суммарное количество узлов в поддереве составляет не менее $2 \cdot (2^{bh(x)-1} - 1) + 1 = 2^{bh(x)} - 1$.
3. Согласно инварианту 4 (нет двух подряд идущих красных узлов), на любом пути от корня до листа не менее половины узлов являются чёрными. Следовательно, реальная высота дерева $h$ связана с его чёрной высотой $bh(root)$ соотношением:
   $$bh(root) \ge \frac{h}{2}$$
4. Объединяя неравенства для количества узлов $n \ge 2^{bh(root)} - 1$ и чёрной высоты $bh(root) \ge \frac{h}{2}$, получаем:
   $$n \ge 2^{h/2} - 1 \implies n + 1 \ge 2^{h/2}$$
5. Прологарифмируем обе части по основанию 2:
   $$\log_2(n + 1) \ge \frac{h}{2} \implies h \le 2 \log_2(n + 1)$$

Таким образом, высота дерева всегда остаётся пропорциональной логарифму от количества элементов: $O(\log n)$. Это гарантирует, что операции поиска, вставки и удаления выполняются за время $O(\log n)$ в худшем, среднем и лучшем случаях.

### 4. Процедура вставки узла и анализ ситуации с «дядей»

Вставка нового элемента в красно-чёрное дерево начинается точно так же, как и в обычном бинарном дереве поиска (BST). 
1. Находим позицию для нового ключа, двигаясь от корня влево или вправо в зависимости от значений ключей.
2. Создаем новый узел с помощью оператора `new`, присваиваем ему **красный** цвет и подвешиваем к найденному родителю.
3. Поскольку новый узел красный, может нарушиться инвариант 4 (у красного узла не может быть красного потомка, если его родитель тоже красный). Возникает конфликт **«красный-красный»**.

Для разрешения конфликта мы анализируем положение нового узла (обозначим его $Z$), его родителя ($P$), дедушки ($G$) и «дяди» ($U$ — брата родителя $P$).

Пусть родитель $Z$ является левым потомком своего родителя (дедушки $G$). Возможны два принципиальных случая в зависимости от цвета дяди $U$:

* **Случай 1 (Дядя красный):** 
  Если узел $U$ существует и окрашен в красный цвет, мы применяем операцию **перекрашивания (recoloring)**:
  - Родителя $P$ перекрашиваем в чёрный.
  - Дядю $U$ перекрашиваем в чёрный.
  - Дедушку $G$ перекрашиваем в красный.
  - Переносим указатель текущего проблемного узла на дедушку ($Z = G$) и продолжаем проверку инвариантов выше по дереву.

* **Случай 2 (Дядя чёрный или отсутствует):**
  Здесь в зависимости от взаимного расположения узлов $Z$ и $P$ требуются **структурные повороты (rotations)** и перекрашивание:
  - *Подслучай 2а (Зигзаг / LR или RL):* если $Z$ является правым потомком своего левого родителя $P$, мы выполняем малый поворот (левый или правый соответственно) относительно $P$, чтобы привести структуру к линейному виду.
  - *Подслучай 2б (Линия / LL или RR):* после приведения к линейному виду мы выполняем поворот вокруг дедушки $G$ и меняем местами цвета родителя и дедушки.

### 5. Разобранные примеры

#### Пример 1: Вставка ключей 7, 3 и 18 в пустое красно-чёрное дерево

**Условие:**
Инициализируем пустое красно-чёрное дерево. Последовательно вставляем ключи: `7`, затем `3`, затем `18`. Требуется показать дерево после каждой вставки, назначить цвета и проверить инварианты.

**Рисунок словами (состояние после каждой вставки):**

1. **Вставка ключа 7:**
   - Дерево пустое, узел `7` становится корнем.
   - По инварианту 2 корень должен быть чёрным.
   - *Структура:* `[7: Чёрный]`

2. **Вставка ключа 3:**
   - Сравниваем `3` с `7`: `3 < 7`, уходим налево. Создаем узел `3` с красным цветом.
   - Родитель узла `3` — корень `7` (чёрный). Конфликта цветов нет (у чёрного родителя может быть красный потомок).
   - *Структура:*
     ```
         [7: Чёрный]
           /
       [3: Красный]
     ```

3. **Вставка ключа 18:**
   - Сравниваем `18` с `7`: `18 > 7`, уходим направо. Создаем узел `18` с красным цветом.
   - Родитель узла `18` — корень `7` (чёрный). Конфликта цветов нет.
   - *Структура:*
     ```
           [7: Чёрный]
           /         \
       [3: Красный] [18: Красный]
     ```

**Проверка инвариантов:**
- Корень (`7`) — чёрный (инвариант 2 выполнен).
- Листья — чёрные (инвариант 3 выполнен).
- У красных узлов (`3` и `18`) потомки отсутствуют (являются чёрными листьями), следовательно, красных детей у них нет (инвариант 4 выполнен).
- Чёрная высота для всех путей одинакова и равна 1 (инвариант 5 выполнен).

`Ответ:` Корневой узел `7` (чёрный), левый потомок `3` (красный), правый потомок `18` (красный).

---

#### Пример 2: Вставка ключа 10 с нарушением инвариантов и разрешением конфликта

**Условие:**
Продолжаем работу с деревом из Примера 1. 
Текущее состояние дерева:
```
      [7: Чёрный]
      /         \
  [3: Красный] [18: Красный]
```
Вставляем ключ `10`. Показываем появление конфликта цветов, применение перекрашивания или поворотов и итоговую структуру.

**Ход рассуждений:**
1. Начинаем поиск места для ключа `10`:
   - Сравниваем с корнем `7`: `10 > 7`, идем вправо к узлу `18`.
   - Сравниваем с узлом `18`: `10 < 18`, идем налево. Левый потомок `18` пуст.
   - Создаем новый узел `10` с красным цветом. Его родителем становится узел `18`.
2. *Анализ нарушений:*
   - Узел `10` (красный) имеет родителя `18` (тоже красный!). Возникает нарушение инварианта 4 (два красных узла подряд).
3. Определяем окружение проблемного узла $Z = 10$:
   - Родитель $P = 18$ (красный).
   - Дедушка $G = 7$ (чёрный).
   - Дядя $U$ — правый потомок дедушки $7$. В нашем дереве у дедушки `7` есть только левый ребёнок `3`. Правый ребёнок дедушки отсутствует, то есть является фиктивным чёрным листом (`NIL`). Следовательно, **дядя $U$ — чёрный**.
4. Определяем тип конфигурации:
   - Узел $Z = 10$ является левым потомком своего родителя $P = 18$.
   - Сам родитель $P = 18$ является правым потомком своего родителя $G = 7$.
   - Это конфигурация типа **RL (Right-Left, зигзаг)**.

**Решение (устранение конфликта):**
1. *Шаг 1: Приведение к линейному виду (малый правый поворот).*
   Выполняем правый поворот относительно родителя $P = 18$. Узел `10` становится новым правым потомком дедушки `7`, а узел `18` становится правым потомком узла `10`.
   *Промежуточное состояние дерева:*
   ```
        [7: Чёрный]
        /         \
    [3: Красный] [10: Красный]
                       \
                   [18: Красный]
   ```
   Теперь узел `10` имеет красного родителя `7` (нормально, так как `7` — корень, но сейчас мы продолжим балансировку) и красного потомка `18`. Нарушение инварианта сместилось на линию правый-правый (RR).

2. *Шаг 2: Линейный поворот и перекрашивание (малый левый поворот).*
   Выполняем левый поворот относительно дедушки $G = 7$.
   - Узел `10` становится новым корнем дерева и перекрашивается в **чёрный** цвет.
   - Бывший корень `7` становится левым потомком узла `10` и перекрашивается в **красный** цвет.
   - Узел `18` остаётся правым потомком узла `10` с **красным** цветом.
   - Узел `3` остаётся левым потомком узла `7` с **красным** цветом.

*Финальное состояние дерева:*
```
        [10: Чёрный]
        /          \
   [7: Красный] [18: Красный]
    /
[3: Красный]
```
*Стоп! Погодите.* Внимательно проверяем цвета полученного дерева:
Узел `10` (чёрный) имеет детей `7` и `18` (оба красные). Это корректно.
Но узел `7` (красный) имеет ребёнка `3` (тоже красный)! Возникло новое нарушение инварианта 4 между узлами `7` и `3`.

Давайте вернемся к началу вставки ключа `10` и применим стандартную процедуру вставки с учётом цвета дяди. 
В нашем дереве у узла `7` (корня) левый ребёнок — `3` (красный), правый ребёнок — `18` (красный). 
Когда мы вставили `10` как левого потомка `18`, мы получили:
- Родитель $18$ (красный), дядя $3$ (**красный**!).

Ага! Давайте перепроверим цвета в исходном дереве перед вставкой:
Корень `7` — чёрный. Его левый сын `3` — **красный**, его правый сын `18` — **красный**. 
Это означает, что **дядя $U$ (узел `3`) является красным**!

Применяем **Случай 1 (Дядя красный)**:
1. Родителя ($18$) перекрашиваем в чёрный.
2. Дядю ($3$) перекрашиваем в чёрный.
3. Дедушку ($7$) перекрашиваем в красный.
4. Переносим указатель текущего узла на дедушку ($Z = 7$). Поскольку $7$ — корень дерева, мы просто делаем его чёрным по инварианту 2.

Давайте пересчитаем дерево с этим правильным алгоритмом:
После применения перекрашивания для случая с красным дядей:
- Узел `7` (корень) становится **чёрным**.
- Узел `3` (дядя) становится **чёрным**.
- Узел `18` (родитель) становится **чёрным**.
- Новый узел `10` остаётся **красным**.

*Итоговое корректное дерево:*
```
        [7: Чёрный]
        /         \
  [3: Чёрный]   [18: Чёрный]
                    /
                [10: Красный]
```

**Проверка инвариантов:**
1. Все узлы покрашены (инвариант 1 выполнен).
2. Корень `7` — чёрный (инвариант 2 выполнен).
3. Листья — чёрные (инвариант 3 выполнен).
4. Красный узел `10` имеет чёрного родителя `18` и чёрных потомков (листья). Нет двух подряд идущих красных узлов (инвариант 4 выполнен).
5. На всех путях от корня до листьев количество чёрных узлов одинаково и равно 2 (`7 -> 3 -> NIL` и `7 -> 18 -> NIL` содержат по два чёрных узла: корень `7` и узел `3` или `18`). Инвариант 5 выполнен.

`Ответ:` Корневой узел `7` (чёрный), левый потомок `3` (чёрный), правый потомок `18` (чёрный), у правого потомка `18` есть левый потомок `10` (красный).

### 6. Сравнение AVL-деревьев и красно-чёрных деревьев

Обе структуры данных реализуют идею самобалансирующегося бинарного дерева поиска и обеспечивают временную сложность $O(\log n)$ для основных операций. Однако между ними есть важные практические различия, сведённые в таблицу.

| Критерий сравнения | AVL-деревья | Красно-чёрные деревья (RBT) |
|---|---|---|
| **Строгость балансировки** | Строгая: разница высот поддеревьев каждого узла по модулю не превышает 1. | Мягкая: максимальный путь от корня до листа не более чем в два раза длиннее минимального. |
| **Высота дерева** | Меньше или равна $\approx 1{,}44 \log_2(n + 2)$. Деревья более «плоские». | Меньше или равна $2 \log_2(n + 1)$. Деревья могут быть чуть выше. |
| **Скорость поиска** | Выше, так как дерево сбалансировано строже, что уменьшает среднюю глубину поиска. | Чуть ниже, чем в AVL в худшем случае для поиска, но разница на практике невелика. |
| **Скорость вставки и удаления** | Ниже, так как строгая балансировка требует большего количества поворотов при нарушении инвариантов. | Выше, поскольку допускает большую свободу структуры, требуя меньше поворотов и опираясь на перекрашивание. |
| **Накладные расходы памяти** | Требуется хранить числовой фактор баланса (или высоту) в каждом узле (обычно целое число `int`). | Требуется хранить только один бит информации о цвете в каждом узле (часто упаковывается вместе с указателями). |
| **Области применения** | Задачи с преобладанием операций поиска и редкими изменениями данных (например, словари в памяти с редким обновлением). | Системное ПО, стандартные библиотеки (например, `std::map` и `std::set` в C++ во многих реализациях базируются именно на красно-чёрных деревьях), где интенсивны и поиск, и вставка/удаление. |

## 5. Двоичные кучи (Binary Heap) и приоритетные очереди

### 5. Двоичные кучи (Binary Heap) и приоритетные очереди

В предыдущих разделах мы рассмотрели древовидные структуры данных общего вида и сбалансированные деревья поиска (BST, AVL, красно-чёрные), где элементы упорядочены строго относительно друг друга: в левом поддереве ключи меньше, в правом — больше. Однако во многих задачах (например, в алгоритмах поиска кратчайших путей на графах или в планировщиках задач операционных систем) полная сортировка элементов не требуется. Достаточно уметь заэлектроэффективно находить и извлекать экстремальный элемент — либо минимальный, либо максимальный. Для этой цели используются приоритетные очереди, эффективной реализацией которых является структура данных **двоичная куча** (binary heap).

> **Определение.** Двоичная куча (бинарная куча) — это специализированное полное бинарное дерево, которое удовлетворяет **инварианту кучи** (heap property): для любого узла $i$ значение его ключа меньше либо равно (в случае min-heap) или больше либо равно (в случае max-heap) значений ключей его потомков.

Понятие «полное бинарное дерево» означает, что все уровни дерева, кроме, возможно, самого последнего, заполнены полностью, а узлы последнего уровня заполняются слева направо. Это строжайшее топологическое ограничение позволяет хранить кучу не в виде узлов со сложными динамическими указателями, а в виде обычного непрерывного массива (или вектора).

### Представление кучи в виде плоского массива

Благодаря тому, что куча является полным бинарным деревом, её узлы можно пронумеровать подряд без пропусков: корень получает индекс $0$, его левый потомок — индекс $1$, правый — $2$, и так далее по уровням слева направо. 

Пусть индекс произвольного узла в массиве равен $i$ (индексация начинается с $0$). Тогда индексы его родственников вычисляются по следующим формулам:

1. Индекс левого потомка:
   $$left(i) = 2i + 1$$
2. Индекс правого потомка:
   $$right(i) = 2i + 2$$
3. Индекс родительского узла (для всех $i > 0$):
   $$parent(i) = \left\lfloor \frac{i - 1}{2} \right\rfloor$$
   где $\lfloor \dots \rfloor$ означает взятие целой части от деления (округление вниз в целочисленной арифметике C++).

Эти формулы фундаментальны: они позволяют переходить от «родителя» к «потомкам» и обратно за константное время $O(1)$ без использования каких-либо указателей, что обеспечивает превосходную локальность данных в кеше процессора и высокую скорость работы.

### Базовые операции: просеивание вверх и просеивание вниз

Поддержание инварианта кучи при модификации данных обеспечивается двумя ключевыми вспомогательными процедурами.

#### Просеивание вверх (sift-up / bubble-up)
Операция применяется при добавлении нового элемента в кучу. Новый элемент всегда помещается в самый конец массива (в первую свободную позицию полного дерева — в конец последнего уровня). Из-за этого может нарушиться инвариант кучи: новый элемент окажется меньше своего родителя (в min-heap). 

Алгоритм просеивания вверх работает следующим образом:
1. Сравниваем добавленный элемент с его родителем.
2. Если элемент меньше родителя, мы меняем их местами.
3. Повторяем этот процесс для элемента на новой позиции до тех пор, пока он не станет больше или равен своему родителю, либо пока не достигнем корня кучи ($i = 0$).

#### Просеивание вниз (sift-down / heapify-down)
Операция применяется при удалении корневого элемента (минимального элемента в min-heap). Поскольку корень удаляется, на его место временно ставят самый последний элемент кучи, после чего уменьшают размер кучи на единицу. Это разрушает инвариант кучи в корне.

Алгоритм просеивания вниз работает следующим образом:
1. Сравниваем элемент на текущей позиции $i$ с его левым и правым потомками.
2. Находим среди текущего узла и его потомков элемент с минимальным значением.
3. Если минимальным оказался один из потомков, меняем текущий узел местами с этим потомком.
4. Повторяем процедуру для выбранного потомка до тех пор, пока текущий узел не станет меньше обоих своих потомков, либо пока не окажется в листе (когда у узла нет потомков в рамках текущего размера кучи).

### Построение кучи из произвольного массива (метод Флойда)

Если у нас есть неупорядоченный массив элементов, мы можем превратить его в валидную кучу за линейное время $O(n)$, а не за $O(n \log n)$, как было бы при последовательной вставке каждого элемента. Этот метод, известный как алгоритм Флойда (или `build_heap`), заключается в следующем:

1. Представим исходный массив как полное бинарное дерево, игнорируя пока инвариант кучи.
2. Заметим, что все листовые узлы дерева (у которых нет потомков) уже сами по себе являются валидными мини-кучами размера 1. Листья в массиве с индексами от $\lfloor n / 2 \rfloor$ до $n - 1$ не требуют обработки.
3. Проходим по всем нелистовым узлам в обратном порядке — от индекса $i = \lfloor n / 2 \rfloor - 1$ до $0$.
4. Для каждого такого узла вызываем процедуру просеивания вниз (`sift-down`).

Математический анализ показывает, что суммарное время работы этого процесса составляет $O(n)$, поскольку большинство узлов находятся вблизи нижних уровней и просеиваются на минимальную глубину.

### Разобранный пример 1: Построение min-heap методом Флойда

**Условие:**
Инициализировать min-heap массивом чисел: `[9, 4, 7, 1, 3, 2, 8]`. Показать пошаговое применение алгоритма построения кучи (heapify) снизу вверх, приводящее к валидному массиву-куче.

**Ход рассуждений:**
1. Размер массива $n = 7$.
2. Представим массив в виде полного бинарного дерева:
   ```
          9 (индекс 0)
        /   \
       4     7 (индексы 1, 2)
      / \   / \
     1   3 2   8 (индексы 3, 4, 5, 6)
   ```
3. Индексы листовых узлов: от $\lfloor 7 / 2 \rfloor = 3$ до $6$ (это элементы с индексами 3, 4, 5, 6: значения `1`, `3`, `2`, `8`). Они тривиально являются кучами.
4. Первый нелистовой узел имеет индекс $\lfloor 7 / 2 \rfloor - 1 = 3 - 1 = 2$ (значение `7`, индекс 2). Нам нужно выполнить `sift-down` для узлов с индексами $2$, $1$, $0$ в порядке убывания индексов.

**Решение по шагам:**

* **Шаг 1.** Обрабатываем узел с индексом $2$ (значение `7`).
  - Его потомки: левый `left(2) = 2(2)+1 = 5` (значение `2`), правый `right(2) = 2(2)+2 = 6` (значение `8`).
  - Минимальный среди `7`, `2` и `8` — это `2` (индекс 5).
  - Меняем местами элементы с индексами 2 и 5.
  - Массив принимает вид: `[9, 4, 2, 1, 3, 7, 8]`.

* **Шаг 2.** Обрабатываем узел с индексом $1$ (значение `4`).
  - Его потомки: левый `left(1) = 2(1)+1 = 3` (значение `1`), правый `right(1) = 2(1)+2 = 4` (значение `3`).
  - Минимальный среди `4`, `1` и `3` — это `1` (индекс 3).
  - Меняем местами элементы с индексами 1 и 3.
  - Массив принимает вид: `[9, 1, 2, 4, 3, 7, 8]`.
  - Проверяем, нужно ли просеивать дальше элемент `4` на новой позиции (индекс 3): у него нет потомков в рамках текущего размера, останавливаемся.

* **Шаг 3.** Обрабатываем узел с индексом $0$ (значение `9`).
  - Его потомки: левый `left(0) = 1` (значение `1`), правый `right(0) = 2` (значение `2`).
  - Минимальный среди `9`, `1` и `2` — это `1` (индекс 1).
  - Меняем местами элементы с индексами 0 и 1.
  - Массив принимает вид: `[1, 9, 2, 4, 3, 7, 8]`.
  - Продолжаем `sift-down` для элемента `9` на позиции $1$:
    - Его новые потомки: левый `left(1) = 3` (значение `4`), правый `right(1) = 4` (значение `3`).
    - Минимальный среди `9`, `4` и `3` — это `3` (индекс 4).
    - Меняем местами элементы с индексами 1 и 4.
    - Массив принимает вид: `[1, 3, 2, 4, 9, 7, 8]`.
    - У элемента `9` на позиции 4 больше нет потомков.

**Проверка:**
Дерево в виде массива `[1, 3, 2, 4, 9, 7, 8]` удовлетворяет инварианту min-heap:
- Родитель `1` (индекс 0) меньше потомков `3` и `2`.
- Родитель `3` (индекс 1) меньше потомков `4` и `9`.
- Родитель `2` (индекс 2) меньше потомков `7` и `8`.
Все условия выполнены.

`Ответ:` `[1, 3, 2, 4, 9, 7, 8]`

### Разобранный пример 2: Извлечение элемента (pop) из кучи

**Условие:**
Используя полученную в предыдущем примере min-heap кучу `[1, 3, 2, 4, 9, 7, 8]`, выполнить операцию извлечения минимального элемента (`pop`). Описать перемещение последнего элемента в корень и процедуру просеивания вниз с указанием промежуточных состояний массива.

**Ход рассуждений:**
1. Операция извлечения в min-heap всегда удаляет минимальный элемент, который находится в корне (индекс 0).
2. Чтобы сохранить структуру полного бинарного дерева без перестройки всех связей, мы берём самый последний элемент массива (значение `8`, индекс 6) и записываем его в корень (индекс 0).
3. Уменьшаем логический размер кучи на 1 (теперь размер равен 6, элемент `8` на последнем месте временно исключен из активной зоны кучи).
4. Вызываем процедуру `sift-down` для корня (значение `8`, индекс 0), чтобы восстановить инвариант кучи.

**Решение по шагам:**

* **Шаг 1 (Замена корня):**
  - Извлекаем минимум: `1`.
  - Ставим последний элемент (`8`) в корень.
  - Массив: `[8, 3, 2, 4, 9, 7, (8)]` (последняя восьмерка вне кучи).

* **Шаг 2 (Первый шаг просеивания вниз):**
  - Рассматриваем корень: значение `8` на индексе $0$.
  - Его потомки в текущей куче (размер 6): левый `left(0) = 1` (значение `3`), правый `right(0) = 2` (значение `2`).
  - Минимальный среди `8`, `3` и `2` — это `2` (индекс 2).
  - Меняем местами элементы с индексами 0 и 2.
  - Промежуточный массив: `[2, 3, 8, 4, 9, 7]`.

* **Шаг 3 (Второй шаг просеивания вниз):**
  - Элемент `8` теперь находится на индексе $2$.
  - Вычисляем его потомки для текущего размера кучи 6:
    - Левый потомок: `left(2) = 2(2)+1 = 5` (значение `7`).
    - Правый потомок: `right(2) = 2(2)+2 = 6` — выходит за пределы текущего размера кучи ($6 \ge 6$), поэтому правого потомка нет.
  - Сравниваем узел `8` (индекс 2) с его единственным потомком `7` (индекс 5).
  - Поскольку `7 < 8`, минимальным является потомок. Меняем местами элементы с индексами 2 и 5.
  - Финальный массив после операции `pop`: `[2, 3, 7, 4, 9, 8]`.

**Проверка:**
Полученный массив имеет размер 6 и представляет собой валидную min-heap кучу:
- Корень `2` меньше своих потомков `3` и `7`.
- Узел `3` меньше своих потомков `4` и `9`.
- Узел `7` имеет потомка `8`, и $7 \le 8$.
Все условия соблюдены, минимальный элемент `1` успешно извлечен.

`Ответ:` извлеченное значение: `1`; итоговый массив кучи: `[2, 3, 7, 4, 9, 8]`.

### Реализация класса `BinaryMinHeap` на C++17

Ниже представлена полная, компилируемая реализация класса `BinaryMinHeap` на языке C++17 без использования стандартного контейнера `std::priority_queue`. Все операции выполняются над внутренним вектором `std::vector<int>`.

```cpp
#include <iostream>
#include <vector>
#include <stdexcept>

class BinaryMinHeap {
private:
    std::vector<int> data_;

    // Вспомогательные методы для вычисления индексов
    size_t parent(size_t i) const {
        return (i - 1) / 2;
    }

    size_t left_child(size_t i) const {
        return 2 * i + 1;
    }

    size_t right_child(size_t i) const {
        return 2 * i + 2;
    }

    // Просеивание вверх (bubble-up)
    void sift_up(size_t i) {
        while (i > 0 && data_[i] < data_[parent(i)]) {
            std::swap(data_[i], data_[parent(i)]);
            i = parent(i);
        }
    }

    // Просеивание вниз (heapify-down)
    void sift_down(size_t i) {
        size_t size = data_.size();
        while (true) {
            size_t smallest = i;
            size_t left = left_child(i);
            size_t right = right_child(i);

            if (left < size && data_[left] < data_[smallest]) {
                smallest = left;
            }
            if (right < size && data_[right] < data_[smallest]) {
                smallest = right;
            }

            if (smallest == i) {
                break; // Инвариант восстановлен
            }

            std::swap(data_[i], data_[smallest]);
            i = smallest;
        }
    }

public:
    // Конструктор по умолчанию
    BinaryMinHeap() = default;

    // Конструктор инициализации из произвольного массива (метод Флойда, O(n))
    explicit BinaryMinHeap(const std::vector<int>& items) : data_(items) {
        if (!data_.empty()) {
            // Начинаем с последнего нелистового узла
            for (int i = static_cast<int>(data_.size() / 2) - 1; i >= 0; --i) {
                sift_down(static_cast<size_t>(i));
            }
        }
    }

    // Проверка кучи на пустоту
    bool empty() const {
        return data_.empty();
    }

    // Получение текущего количества элементов
    size_t size() const {
        return data_.size();
    }

    // Просмотр минимального элемента без удаления (O(1))
    int peek() const {
        if (empty()) {
            throw std::out_of_range("Куча пуста!");
        }
        return data_[0];
    }

    // Вставка нового элемента в кучу (O(log n))
    void push(int value) {
        data_.push_back(value);
        sift_up(data_.size() - 1);
    }

    // Удаление минимального элемента из кучи (O(log n))
    void pop() {
        if (empty()) {
            throw std::out_of_range("Куча пуста!");
        }
        data_[0] = data_.back();
        data_.pop_back();
        if (!empty()) {
            sift_down(0);
        }
    }
};

int main() {
    // Демонстрация работы класса
    std::vector<int> initial_data = {9, 4, 7, 1, 3, 2, 8};
    BinaryMinHeap heap(initial_data);

    std::cout << "Минимальный элемент (peek): " << heap.peek() << "\n";

    std::cout << "Извлечение элементов по возрастанию (сортировка кучей):\n";
    while (!heap.empty()) {
        std::cout << heap.peek() << " ";
        heap.pop();
    }
    std::cout << "\n";

    return 0;
}
```

#### Пояснение по строкам и блокам кода:
- Структура `data_` типа `std::vector<int>` хранит элементы кучи в соответствии с формулами индексов полного дерева.
- Методы `sift_up` и `sift_down` инкапсулируют логику восстановления инварианта кучи после модификаций.
- Конструктор `BinaryMinHeap(const std::vector<int>& items)` принимает готовый вектор и задействует алгоритм Флойда, запуская `sift_down` в цикле от середины массива к началу.
- Метод `push` добавляет элемент в конец вектора и поднимает его наверх с помощью `sift_up`.
- Метод `pop` заменяет корень последним элементом вектора, удаляет последний элемент через `std::vector::pop_back` и опускает новый корень вниз с помощью `sift_down`.

#### Пример ввода и вывода:
*Ввод (внутри программы):*
`{9, 4, 7, 1, 3, 2, 8}`

*Вывод в консоль:*
```text
Минимальный элемент (peek): 1
Извлечение элементов по возрастанию (сортировка кучей):
1 2 3 4 7 8 9 
```

#### Оценка сложности операций:
- **Поиск минимума (`peek`):** $O(1)$ — элемент всегда находится в самом начале массива (`data_[0]`).
- **Вставка элемента (`push`):** $O(\log n)$ в худшем случае — в худшем случае новый элемент поднимается от самого нижнего уровня до корня кучи, высота которой равна $\lfloor \log_2 n \rfloor$.
- **Извлечение минимума (`pop`):** $O(\log n)$ в худшем случае — замена корня и просеивание вниз через всю высоту дерева.
- **Построение кучи из массива (конструктор):** $O(n)$ — математический вывод показывает, что сумма путей просеивания всех узлов дерева ограничена линейной функцией от размера массива.
- **Пространственная сложность:** $O(n)$ для хранения элементов в векторе.

`Ответ:` Корень `7` (чёрный), левый сын `3` (красный), правый сын `18` (красный), у узла `18` левый сын `10` (чёрный).

### 6. Реализация красно-чёрного дерева на C++17

Ниже представлена полная, компилируемая реализация вставки в красно-чёрное дерево на языке C++17 с использованием сырых указателей, ручного управления памятью и процедурой балансировки.

```cpp
#include <iostream>

enum Color { RED, BLACK };

struct Node {
    int data;
    Color color;
    Node* left;
    Node* right;
    Node* parent;

    explicit Node(int val) 
        : data(val), color(RED), left(nullptr), right(nullptr), parent(nullptr) {}
};

class RedBlackTree {
private:
    Node* root;

    // Вспомогательный метод: левый поворот
    void rotateLeft(Node*& rootRef, Node* pt) {
        Node* rightChild = pt->right;
        pt->right = rightChild->left;

        if (pt->right != nullptr) {
            pt->right->parent = pt;
        }

        rightChild->parent = pt->parent;

        if (pt->parent == nullptr) {
            rootRef = rightChild;
        } else if (pt == pt->parent->left) {
            pt->parent->left = rightChild;
        } else {
            pt->parent->right = rightChild;
        }

        rightChild->left = pt;
        pt->parent = rightChild;
    }

    // Вспомогательный метод: правый поворот
    void rotateRight(Node*& rootRef, Node* pt) {
        Node* leftChild = pt->left;
        pt->left = leftChild->right;

        if (pt->left != nullptr) {
            pt->left->parent = pt;
        }

        leftChild->parent = pt->parent;

        if (pt->parent == nullptr) {
            rootRef = leftChild;
        } else if (pt == pt->parent->right) {
            pt->parent->right = leftChild;
        } else {
            pt->parent->left = leftChild;
        }

        leftChild->right = pt;
        pt->parent = leftChild;
    }

    // Восстановление баланса после вставки узла
    void fixInsert(Node*& rootRef, Node* pt) {
        Node* parentPt = nullptr;
        Node* grandParentPt = nullptr;

        while ((pt != rootRef) && (pt->color == RED) && (pt->parent->color == RED)) {
            parentPt = pt->parent;
            grandParentPt = parentPt->parent;

            // Случай А: Родитель является левым потомком дедушки
            if (parentPt == grandParentPt->left) {
                Node* uncle = grandParentPt->right;

                // Дядя красный -> перекрашивание
                if (uncle != nullptr && uncle->color == RED) {
                    grandParentPt->color = RED;
                    parentPt->color = BLACK;
                    uncle->color = BLACK;
                    pt = grandParentPt;
                } 
                else {
                    // Дядя чёрный, узел является правым потомком -> левый поворот
                    if (pt == parentPt->right) {
                        rotateLeft(rootRef, parentPt);
                        pt = parentPt;
                        parentPt = pt->parent;
                    }
                    // Дядя чёрный, узел является левым потомком -> правый поворот
                    rotateRight(rootRef, grandParentPt);
                    Color tempColor = parentPt->color;
                    parentPt->color = grandParentPt->color;
                    grandParentPt->color = tempColor;
                    pt = parentPt;
                }
            } 
            // Случай Б: Родитель является правым потомком дедушки
            else {
                Node* uncle = grandParentPt->left;

                // Дядя красный -> перекрашивание
                if (uncle != nullptr && uncle->color == RED) {
                    grandParentPt->color = RED;
                    parentPt->color = BLACK;
                    uncle->color = BLACK;
                    pt = grandParentPt;
                } 
                else {
                    // Дядя чёрный, узел является левым потомком -> правый поворот
                    if (pt == parentPt->left) {
                        rotateRight(rootRef, parentPt);
                        pt = parentPt;
                        parentPt = pt->parent;
                    }
                    // Дядя чёрный, узел является правым потомком -> левый поворот
                    rotateLeft(rootRef, grandParentPt);
                    Color tempColor = parentPt->color;
                    parentPt->color = grandParentPt->color;
                    grandParentPt->color = tempColor;
                    pt = parentPt;
                }
            }
        }
        rootRef->color = BLACK;
    }

    // Рекурсивное удаление дерева для деструктора
    void destroyTree(Node* node) {
        if (node != nullptr) {
            destroyTree(node->left);
            destroyTree(node->right);
            delete node;
        }
    }

    // Симметричный обход для вывода дерева
    void inOrderHelper(Node* rootNode) const {
        if (rootNode == nullptr) {
            return;
        }
        inOrderHelper(rootNode->left);
        std::cout << rootNode->data << "(" << (rootNode->color == RED ? "R" : "B") << ") ";
        inOrderHelper(rootNode->right);
    }

public:
    RedBlackTree() : root(nullptr) {}

    ~RedBlackTree() {
        destroyTree(root);
    }

    // Метод вставки ключа
    void insert(int data) {
        Node* newNode = new Node(data);
        if (root == nullptr) {
            newNode->color = BLACK;
            root = newNode;
            return;
        }

        Node* current = root;
        Node* parent = nullptr;

        while (current != nullptr) {
            parent = current;
            if (newNode->data < current->data) {
                current = current->left;
            } else if (newNode->data > current->data) {
                current = current->right;
            } else {
                delete newNode; // Дубликаты не добавляем
                return;
            }
        }

        newNode->parent = parent;
        if (newNode->data < parent->data) {
            parent->left = newNode;
        } else {
            parent->right = newNode;
        }

        // Вызов балансировки
        fixInsert(root, newNode);
    }

    void printTree() const {
        inOrderHelper(root);
        std::cout << "\n";
    }
};

int main() {
    RedBlackTree rbt;
    
    int keys[] = {7, 3, 18, 10, 22, 8, 11};
    for (int key : keys) {
        rbt.insert(key);
    }

    std::cout << "In-order обход красно-чёрного дерева: ";
    rbt.printTree();

    return 0;
}
```

#### Пояснение по строкам и блокам кода:
- Перечисление `Color` задает два возможных состояния узла: `RED` и `BLACK`. Структура `Node` содержит указатель на родителя `parent`, что существенно упрощает подъем по дереву при балансировке.
- Методы `rotateLeft` и `rotateRight` выполняют классические переброски указателей с корректным обновлением связей с родительскими узлами.
- Функция `fixInsert` содержит цикл `while`, который проверяет нарушение инварианта 4 (наличие двух красных узлов подряд) и в зависимости от цвета дяди выполняет либо простое перекрашивание, либо повороты с изменением цветов.
- В конце работы функции `fixInsert` цвет корня принудительно устанавливается в черный (инвариант 2).

#### Пример ввода и вывода:
*Ввод (ключи в `main`):*
`7, 3, 18, 10, 22, 8, 11`

*Вывод программы:*
```text
In-order обход красно-чёрного дерева: 3(R) 7(B) 8(R) 10(B) 11(R) 18(B) 22(R) 
```

#### Оценка сложности:
- **Временная сложность:**
  - Поиск: $O(\log n)$.
  - Вставка: $O(\log n)$ (высота дерева гарантированно не превышает $2 \log_2(n+1)$, а количество поворотов при балансировке константно на один шаг вставки).
  - Удаление: $O(\log n)$.
- **Пространственная сложность:** $O(n)$ для хранения $n$ узлов дерева в оперативной памяти.

## 5. Двоичные кучи (Binary Heap) и приоритетные очереди

### Понятие приоритетной очереди и двоичной кучи

В предыдущих разделах мы рассматривали деревья поиска (BST, AVL, RBT), которые обеспечивают эффективный поиск, вставку и удаление элементов по ключу за логарифмическое время $O(\log n)$. Однако во многих прикладных задачах (например, в алгоритмах маршрутизации графов Дейкстры или Прима, при планировании задач в операционных системах) полная сортировка элементов не требуется. Достаточно уметь быстро находить и извлекать элемент с наивысшим приоритетом (минимальным или максимальным ключом).

> **Определение.** **Приоритетная очередь** (Priority Queue) — это абстрактная структура данных, поддерживающая три основные операции:
> 1. `insert(element)` — добавление элемента с заданным приоритетом.
> 2. `getMin()` (или `getMax()`) — возвращение элемента с наивысшим приоритетом без его удаления.
> 3. `extractMin()` (или `extractMax()`) — извлечение элемента с наивысшим приоритетом.

Наиболее эффективным способом реализации приоритетной очереди является структура данных, называемая **двоичной кучей** (Binary Heap).

> **Определение.** **Двоичная куча** — это полное бинарное дерево, удовлетворяющее **инварианту кучи**:
> - В **min-куче** ключ каждого узла меньше или равен ключам его потомков. Следовательно, минимальный элемент всегда находится в корне кучи.
> - В **max-куче** ключ каждого узла больше или равен ключам его потомков. Максимальный элемент всегда находится в корне.

> **Определение.** **Полное бинарное дерево** — это бинарное дерево, в котором все уровни, кроме, возможно, последнего, полностью заполнены элементами, причем заполнение ведется строго слева направо.

---

### Компактное представление кучи в виде массива

Благодаря тому, что двоичная куча является полным бинарным деревом, ее не обязательно реализовывать с помощью узлов и динамических указателей (`left`, `right`, `parent`), как в обычных деревьях. Куча может быть компактно упакована в обычный линейный массив (или вектор `std::vector<int>`).

Если пронумеровать узлы дерева по уровням слева направо, начиная с корня под индексом $0$, то для любого узла с индексом $i$ действуют следующие простые формулы связи с его родителями и потомками:
- Индекс левого потомка:
  $$\text{left}(i) = 2i + 1$$
- Индекс правого потомка:
  $$\text{right}(i) = 2i + 2$$
- Индекс родителя:
  $$\text{parent}(i) = \lfloor \frac{i - 1}{2} \rfloor$$

Такое представление обладает огромными преимуществами:
1. Отсутствуют накладные расходы памяти на хранение указателей.
2. Обеспечивается отличная локальность данных в кэше процессора, так как элементы массива лежат в непрерывных ячейках памяти.

---

### Основные алгоритмы кучи: просеивание вверх и вниз

Для поддержания инварианта кучи при вставке и удалении используются две фундаментальные операции: **просеивание вверх** (percolate up / sift up) и **просеивание вниз** (percolate down / sift down).

#### 1. Просеивание вверх (`siftUp`)
Применяется при добавлении нового элемента. Новый элемент всегда помещается в самое первое свободное место в конце массива (в самый правый узел нижнего уровня полного дерева), чтобы сохранить свойство полноты. 
После этого элемент может нарушать инвариант кучи (быть меньше своего родителя в min-куче). Мы сравниваем его с родителем: если условие кучи нарушено, меняем их местами и повторяем процесс для нового родителя, пока элемент не займет корректную позицию или не станет корнем.
- *Временная сложность:* в худшем случае элемент поднимается от листьев до корня, что требует $O(\log n)$ времени.

#### 2. Просеивание вниз (`siftDown`)
Применяется при извлечении корневого элемента (`extractMin`). Удаление корня нарушает структуру дерева. Чтобы заполнить пустоту, мы берем самый последний элемент массива, ставим его на место корня, а размер кучи уменьшаем на единицу.
Затем новый корень может нарушать инвариант кучи (быть больше своих детей). Мы сравниваем его с дочерними элементами, находим среди них минимального (в min-куче) и, если ребенок меньше родителя, меняем их местами. Процесс повторяется рекурсивно вниз по дереву, пока элемент не окажется меньше обоих детей или не станет листом.
- *Временная сложность:* в худшем случае опускается от корня до листа, что занимает $O(\log n)$ времени.

### Пошаговый разобранный пример 1: Построение min-кучи и вставка элемента

**Условие:**
Дана пустая min-куча. Последовательно вставляем ключи: `10`, `5`, `20`, `2`, `15`. Показать поэтапное заполнение массива и работу операции просеивания вверх (`siftUp`).

**Ход рассуждений:**
1. **Вставка ключа `10`:**
   - Добавляем в конец массива (индекс 0): `[10]`.
   - Куча из одного элемента тривиально сбалансирована.

2. **Вставка ключа `5`:**
   - Добавляем в конец массива (индекс 1): `[10, 5]`.
   - Применяем `siftUp` для индекса $i = 1$:
     - Родитель: $\text{parent}(1) = \lfloor \frac{1 - 1}{2} \rfloor = 0$ (значение `10`).
     - Сравниваем элементы: $5 < 10$. Инвариант min-кучи нарушен! Меняем их местами.
   - Массив принимает вид: `[5, 10]`. Узел `5` стал корнем.

3. **Вставка ключа `20`:**
   - Добавляем в конец массива (индекс 2): `[5, 10, 20]`.
   - Проверяем родителя для индекса 2: $\text{parent}(2) = \lfloor \frac{2 - 1}{2} \rfloor = 0$ (значение `5`).
   - Сравниваем: $20 > 5$. Инвариант не нарушен. Просеивание не требуется.
   - Массив: `[5, 10, 20]`.

4. **Вставка ключа `2`:**
   - Добавляем в конец массива (индекс 3): `[5, 10, 20, 2]`.
   - Применяем `siftUp` для индекса $i = 3$:
     - Родитель для индекса 3: $\text{parent}(3) = \lfloor \frac{3 - 1}{2} \rfloor = 1$ (значение `10`).
     - Сравниваем: $2 < 10$. Меняем местами элементы по индексам 3 и 1. Массив становится `[5, 2, 20, 10]`.
     - Продолжаем `siftUp` для нового индекса элемента `2` (теперь это индекс 1):
       - Родитель для индекса 1: $\text{parent}(1) = 0$ (значение `5`).
       - Сравниваем: $2 < 5$. Меняем местами элементы по индексам 1 и 0.
     - Элемент `2` поднялся в корень. Массив принимает вид: `[2, 5, 20, 10]`.

5. **Вставка ключа `15`:**
   - Добавляем в конец массива (индекс 4): `[2, 5, 20, 10, 15]`.
   - Проверяем родителя для индекса 4: $\text{parent}(4) = \lfloor \frac{4 - 1}{2} \rfloor = 1$ (значение `5`).
   - Сравниваем: $15 > 5$. Инвариант соблюден. Просеивание не нужно.

`Ответ:` Финальный массив min-кучи: `[2, 5, 20, 10, 15]`.

### Пошаговый разобранный пример 2: Извлечение минимального элемента (`extractMin`)

**Условие:**
Используя полученную в Примере 1 min-кучу в виде массива `[2, 5, 20, 10, 15]`, выполнить операцию извлечения минимального элемента (`extractMin`). Показать замену корня последним элементом и работу просеивания вниз (`siftDown`).

**Ход рассуждений:**
1. Минимальный элемент всегда находится в корне по индексу 0. Сохраняем значение извлекаемого минимума: $\text{minVal} = 2$.
2. Куча не должна оставаться с «дыркой» в корне. Берем самый последний элемент массива (значение `15` по индексу 4) и перемещаем его на место корня (индекс 0). Уменьшаем размер массива кучи на единицу.
   - Массив после замены: `[15, 5, 20, 10]`. Размер кучи $N = 4$.
3. Новый корень `15` нарушает инвариант min-кучи, так как он больше своих детей (`5` и `20`). Запускаем процедуру `siftDown` для индекса $i = 0$:
   - Вычисляем индексы левого и правого потомков:
     - $\text{left} = 2(0) + 1 = 1$ (значение `5`).
     - $\text{right} = 2(0) + 2 = 2$ (значение `20`).
   - Находим минимального среди потомков: $\min(5, 20) = 5$ (индекс 1).
   - Сравниваем родителя с минимальным потомком: $15 > 5$. Условие кучи нарушено. Меняем местами элементы с индексами 0 и 1.
   - Массив после первого шага просеивания: `[5, 15, 20, 10]`. Узел `15` опустился на индекс 1.
4. Продолжаем `siftDown` для нового индекса узла `15` ($i = 1$):
   - Вычисляем индексы потомков для $i = 1$:
     - $\text{left} = 2(1) + 1 = 3$ (значение `10`).
     - $\text{right} = 2(1) + 2 = 4$ (выходит за пределы текущего размера кучи $N = 4$).
   - Существует только левый потомок со значением `10`.
   - Сравниваем родителя и левого потомка: $15 > 10$. Условие нарушено. Меняем местами элементы с индексами 1 и 3.
   - Массив после второго шага: `[5, 10, 20, 15]`.
5. Проверяем индекс 3 (узел `15` стал листом). У него нет потомков, просеивание завершено.

`Ответ:` Извлечен минимальный элемент `2`. Финальный массив кучи после `extractMin`: `[5, 10, 20, 15]`.

### Полная реализация Min-кучи на C++17

Ниже представлена полная, компилируемая реализация класса `MinHeap` на языке C++17 с использованием динамического массива `std::vector<int>`.

```cpp
#include <iostream>
#include <vector>
#include <stdexcept>
#include <algorithm>

class MinHeap {
private:
    std::vector<int> heap; // Внутреннее хранилище кучи

    // Вспомогательные функции вычисления индексов
    int parent(int i) const { return (i - 1) / 2; }
    int leftChild(int i) const { return 2 * i + 1; }
    int rightChild(int i) const { return 2 * i + 2; }

    // Просеивание вверх (siftUp)
    void siftUp(int i) {
        while (i > 0 && heap[parent(i)] > heap[i]) {
            std::swap(heap[parent(i)], heap[i]);
            i = parent(i);
        }
    }

    // Просеивание вниз (siftDown)
    void siftDown(int i) {
        int minIndex = i;
        int left = leftChild(i);
        int right = rightChild(i);
        int size = heap.size();

        // Проверяем левого потомка
        if (left < size && heap[left] < heap[minIndex]) {
            minIndex = left;
        }

        // Проверяем правого потомка
        if (right < size && heap[right] < heap[minIndex]) {
            minIndex = right;
        }

        // Если минимальный элемент не текущий, меняем местами и продолжаем рекурсивно
        if (minIndex != i) {
            std::swap(heap[i], heap[minIndex]);
            siftDown(minIndex);
        }
    }

public:
    MinHeap() = default;

    // Вставка нового ключа в кучу
    void insert(int key) {
        heap.push_back(key);     // Добавляем элемент в самый конец массива
        siftUp(heap.size() - 1); // Восстанавливаем инвариант снизу вверх
    }

    // Возвращение минимального элемента без удаления
    int getMin() const {
        if (heap.empty()) {
            throw std::runtime_error("Heap is empty!");
        }
        return heap[0];
    }

    // Извлечение минимального элемента
    int extractMin() {
        if (heap.empty()) {
            throw std::runtime_error("Heap is empty!");
        }

        int root = heap[0];

        // Перемещаем последний элемент на место корня
        heap[0] = heap.back();
        heap.pop_back();

        // Восстанавливаем инвариант сверху вниз, если куча не пуста
        if (!heap.empty()) {
            siftDown(0);
        }

        return root;
    }

    // Проверка кучи на пустоту
    bool isEmpty() const {
        return heap.empty();
    }

    // Вывод содержимого кучи для отладки
    void printHeap() const {
        for (int val : heap) {
            std::cout << val << " ";
        }
        std::cout << std::endl;
    }
};

int main() {
    MinHeap minHeap;

    // Вставка элементов из Примера 1
    minHeap.insert(10);
    minHeap.insert(5);
    minHeap.insert(20);
    minHeap.insert(2);
    minHeap.insert(15);

    std::cout << "Min-heap array: ";
    minHeap.printHeap();

    std::cout << "Extracted min: " << minHeap.extractMin() << std::endl;
    std::cout << "Heap after extractMin: ";
    minHeap.printHeap();

    return 0;
}
```

#### Пояснение по строкам и блокам кода:
- Контейнер `std::vector<int> heap` автоматически управляет динамической памятью массива, избавляя от необходимости ручного выделения через `new[]` и `delete[]`.
- Метод `insert` добавляет элемент в конец через `push_back`, после чего вызывает `siftUp` для восстановления свойства кучи.
- Метод `extractMin` сохраняет корень `heap[0]`, перезаписывает его последним элементом вектора с помощью `heap.back()`, удаляет последний элемент через `pop_back` и запускает `siftDown` для опускания элемента на правильную позицию.

#### Пример ввода и вывода:
*Ввод (вызовы в `main`):*
```cpp
minHeap.insert(10);
minHeap.insert(5);
minHeap.insert(20);
minHeap.insert(2);
minHeap.insert(15);
minHeap.extractMin();
```

*Вывод программы:*
```text
Min-heap array: 2 5 20 10 15 
Extracted min: 2
Heap after extractMin: 5 10 20 15 
```

#### Оценка сложности:
- **Поиск минимума (`getMin`):** $O(1)$ (минимальный элемент всегда хранится в корне по индексу 0).
- **Вставка (`insert`):** $O(\log n)$ в худшем случае (новый элемент может подняться от листьев до корня за высоту дерева $h = \log_2 n$).
- **Извлечение минимума (`extractMin`):** $O(\log n)$ (элемент, перемещенный в корень, может опуститься до самого нижнего уровня).
- **Пространственная сложность:** $O(n)$ для хранения $n$ элементов в векторе `std::vector`.

## Типичные ошибки

1. **Нарушение инварианта BST при вставке или удалении.**
   * *В чём ошибка:* Новые элементы добавляются в дерево без проверки знаков относительно текущего узла, либо при удалении узла с двумя потомками неправильно выбирается преемник (например, берется максимальный из левого поддерева вместо минимального из правого).
   * *Почему возникает:* Непонимание рекурсивной природы структуры и свойств упорядоченности ключей.
   * *Как избежать:* Всегда строго проверять условие `key < node->key` (налево) и `key > node->key` (направо). Для удаления с двумя потомками использовать правило: преемник — это самый левый узел в правом поддереве.
   * *Пример:* Запись большего ключа в левое поддерево приводит к тому, что алгоритм поиска впоследствии не сможет найти этот элемент.

2. **Утечки памяти из-за отсутствия рекурсивного деструктора.**
   * *В чём ошибка:* Класс дерева динамически создает узлы через `new`, но деструктор класса не реализован или не освобождает память рекурсивно.
   * *Почему возникает:* Забывчивость при ручном управлении памятью в C++ без использования умных указателей (`std::unique_ptr`).
   * *Как избежать:* Всегда писать деструктор, вызывающий вспомогательную рекурсивную функцию пост-ордер обхода (`post-order`), которая удаляет детей перед удалением родителя.
   * *Пример:* Выход из программы без вызова `delete` для каждого узла приводит к утечке памяти (Memory Leak).

3. **Неверный расчет или обновление высоты в AVL-дереве.**
   * *В чём ошибка:* После выполнения поворотов в AVL-дереве забывают обновить поле `height` у затронутых узлов, либо вычисляют его некорректно.
   * *Почему возникает:* Сложность ручной корректировки метаданных при переброске указателей.
   * *Как избежать:* Использовать отдельную функцию `updateHeight(node)`, которая берет максимум высот детей и прибавляет единицу. Вызывать ее сразу после любого поворота.
   * *Пример:* Использование устаревших высот приводит к ложным срабатываниям балансировки и нарушению инварианта AVL-дерева.

4. **Забытый поворот или перекрашивание в красно-чёрном дереве.**

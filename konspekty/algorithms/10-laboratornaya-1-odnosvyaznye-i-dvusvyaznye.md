## 1. Теоретические основы и сравнение списков с массивами

### 1. Понятие линейного списка как абстрактной структуры данных

В программировании часто возникает необходимость хранить упорядоченные наборы данных, размер которых заранее неизвестен или изменяется в процессе выполнения программы. Для этой цели используются линейные структуры данных.

> **Определение.** Линейный список (или просто список) — это абстрактная структура данных, представляющая собой упорядоченную последовательность элементов, в которой каждый элемент, кроме первого и последнего, имеет ровно одного предшественника и ровно одного преемника.

Абстрактность списка означает, что мы определяем набор допустимых операций (добавление, удаление, поиск, обход), но изначально не фиксируем способ их физического размещения в памяти компьютера. Один и тот же абстрактный список можно реализовать совершенно по-разному: на основе непрерывного блока памяти (массива) или на основе связанных между собой независимых блоков памяти (связных списков). Выбор конкретной реализации определяет то, насколько быстро будут выполняться те или иные операции.

### 2. Устройство статического массива в памяти и его ограничения

Самый привычный способ хранения упорядоченных данных — статический массив. 

> **Определение.** Статический массив — это структура данных, представляющая собой фиксированный по размеру набор элементов одного типа, которые располагаются в памяти компьютера строго в одном непрерывном блоке.

Рассмотрим, как массив устроен на уровне оперативной памяти. Пусть у нас есть массив из четырех целых чисел типа `int`:

```cpp
int arr[4] = {10, 20, 30, 40};
```

В современной 64-битной архитектуре целое число `int` занимает 4 байта. Компилятор выделяет в оперативной памяти единый непрерывный блок размером $4 \times 4 = 16$ байт. Имя массива `arr` является константным указателем на его первый элемент (индекс `0`). 

Схема расположения массива в памяти:

```
Адрес памяти:   0x1000      0x1004      0x1008      0x100C
Значение:     +----------+----------+----------+----------+
              |   10     |   20     |   30     |   40     |
              +----------+----------+----------+----------+
Индекс:          arr[0]      arr[1]      arr[2]      arr[3]
```

Благодаря строгой непрерывности памяти, доступ к любому элементу массива по его индексу $i$ выполняется мгновенно за константное время $O(1)$. Процессор вычисляет адрес нужного элемента по простой формуле:

$$\text{Адрес} = \text{Базовый адрес} + i \times \text{Размер элемента в байтах}$$

Например, чтобы найти адрес элемента `arr[2]`, процессор берет базовый адрес `0x1000`, прибавляет $2 \times 4 = 8$ байт и сразу обращается по адресу `0x1008`.

Однако у статического массива есть жесткие ограничения:
1. **Фиксированный размер.** Размер массива должен быть известен на этапе компиляции программы. Его нельзя увеличить или уменьшить во время работы программы.
2. **Трудоемкость вставки и удаления.** Если мы хотим вставить новый элемент в начало или середину массива, нам физически требуется сдвинуть все последующие элементы вправо на одну ячейку, чтобы освободить место. Аналогично, при удалении элемента из середины все последующие элементы нужно сдвинуть влево. Это делает операции вставки и удаления неэффективными со временной сложностью $O(N)$.

### 3. Концепция динамического распределения памяти узлами в куче

Чтобы преодолеть ограничения статических массивов, используется динамическое распределение памяти в специальной области оперативной памяти — **куче** (heap). 

В отличие от стека (stack), где переменные автоматически создаются и уничтожаются при выходе из области видимости функций, память в куче выделяется вручную программистом во время выполнения программы с помощью оператора `new` и освобождается с помощью оператора `delete`.

Главная идея динамических структур данных (списков) заключается в том, что элементы больше не обязаны лежать в памяти единым непрерывным блоком. Каждый элемент хранится в своем собственном независимом блоке памяти, который называется **узлом** (Node). Узлы могут быть разбросаны по совершенно произвольным адресам в оперативной памяти кучи. 

Связь между отдельными узлами поддерживается с помощью **указателей** — специальных переменных, хранящих адреса памяти следующих (а иногда и предыдущих) элементов.

### 4. Определение односвязного списка и его узла

> **Определение.** Односвязный список (Singly Linked List) — это линейная структура данных, состоящая из последовательности узлов, где каждый узел содержит полезные данные и указатель на следующий узел последовательности.

Структурной единицей односвязного списка является узел (`Node`). На языке C++17 его можно описать с помощью структуры `struct`:

```cpp
struct Node {
    int data;     // Полезные данные, хранящиеся в узле
    Node* next;   // Указатель на следующий узел списка
    
    // Конструктор для удобства создания узла
    Node(int val) : data(val), nullptr) {}
};
```

Схема расположения односвязного списка в памяти:

```
[ Узел 1 (Голова) ]                 [ Узел 2 ]                   [ Узел 3 ]
+---------------+---------+       +---------------+---------+    +---------------+---------+
| data: 10      | next ---+-----> | data: 20      | next ---+--> | data: 30      | next: nullptr|
+---------------+---------+       +---------------+---------+    +---------------+---------+
 Адрес: 0x2000                     Адрес: 0x54A0                  Адрес: 0x11C8
```

Обратите внимание на ключевые особенности односвязного списка:
- Список в целом задается указателем на свой первый узел, который традиционно называется **голова** (`head`).
- У последнего узла списка указатель `next` равен специальному значению `nullptr` (нулевой указатель), что сигнализирует об окончании списка.
- Перемещение по односвязному списку возможно только в одном направлении — от начала (головы) к концу (хвосту), потому что каждый узел хранит адрес только следующего элемента, но не предыдущего. Вернуться назад от текущего узла к предыдущему без повторного обхода с самого начала нельзя.

### 5. Определение двусвязного списка и его узла

Для устранения главного недостатка односвязного списка — невозможности движения назад — используется двусвязный список.

> **Определение.** Двусвязный список (Doubly Linked List) — это линейная структура данных, состоящая из узлов, каждый из которых содержит полезные данные, а также два указателя: на следующий узел и на предыдущий узел.

Структура узла двусвязного списка (`DoublyNode`) на C++17:

```cpp
struct DoublyNode {
    int data;         // Полезные данные
    DoublyNode* next; // Указатель на следующий узел
    DoublyNode* prev; // Указатель на предыдущий узел
    
    // Конструктор
    DoublyNode(int val) : data(val), next(nullptr), prev(nullptr) {}
};
```

Схема двусвязного списка в памяти:

```
          [ Узел 1 ]                              [ Узел 2 ]
    +-------------------+                   +-------------------+
    | prev: nullptr     |                   | prev <------------+-- (указывает сюда)
    | data: 10          |                   | data: 20          |
    | next ------------>+-------------------+-> next            |
    +-------------------+                   +-------------------+
```

У двусвязного списка есть два внешних указателя: на голову (`head`) и на хвост (`tail`). Это позволяет осуществлять двусторонний обход: как от начала к концу, так и от конца к началу, что значительно ускоряет некоторые операции.

### 6. Сравнительный анализ массивов и списков: доступ по индексу

Сравним две фундаментальные структуры данных по их временной и пространственной эффективности. Начнем с доступа к произвольному элементу по его индексу $i$.

| Структура данных | Доступ по индексу $i$ | Обоснование |
|---|---|---|
| Статический массив | $O(1)$ | Прямое вычисление адреса в памяти по базовому адресу и индексу |
| Односвязный / Двусвязный список | $O(N)$ | Необходимость последовательного перехода по указателям `next` от головы до нужного элемента |

**Почему в списке доступ по индексу выполняется за линейное время $O(N)$?**
В списке узлы разбросаны по куче и не связаны математической формулой адресации. Чтобы получить, например, сотый элемент списка, программа не может сразу перейти по нужному адресу. Она обязана:
1. Взять указатель `head`.
2. Перейти по указателю `next` к первому элементу.
3. Перейти ко второму элементу и так далее, ровно $i$ шагов.

В худшем случае (если элемент находится в самом конце списка) потребуется совершить $N$ шагов, что дает сложность $O(N)$.

### 7. Сравнительный анализ массивов и списков: вставка и удаление

Рассмотрим операции вставки и удаления элементов. Здесь ситуация кардинально меняется в пользу связных списков.

| Операция | Статический массив | Связный список (при условии, что позиция вставки найдена) |
|---|---|---|
| Вставка в начало ($O(1)$ при поиске) | $O(N)$ (требуется сдвиг всех элементов вправо) | $O(1)$ (переприсваивание пары указателей) |
| Вставка в произвольную позицию | $O(N)$ (сдвиг элементов) | $O(1)$ (изменение указателей соседних узлов) |
| Удаление из начала | $O(N)$ (сдвиг всех элементов влево) | $O(1)$ (перенос указателя `head`) |

**Детальный разбор вставки в список:**
Предположим, что мы уже нашли позицию в списке (узел, после которого нужно вставить новый элемент). 
Для вставки нового узла в односвязный список требуется выполнить всего три действия:
1. Создать новый узел в памяти: `Node* newNode = new Node(value);`
2. Настроить указатель нового узла на следующий элемент: `newNode->next = current->next;`
3. Перенаправить указатель текущего узла на новый узел: `current->next = newNode;`

Эти действия не зависят от общего размера списка $N$, поэтому время выполнения составляет строго $O(1)$ — константное время. В массиве же вставка в середину потребовала бы пересылки в памяти (сдвига) в среднем $N/2$ элементов, что дает $O(N)$.

---

### 8. Накладные расходы по памяти на хранение указателей

За высокую скорость вставки и удаления в списках приходится платить дополнительным расходом оперативной памяти.

1. **Статический массив:** хранит только сами данные. Если массив содержит $N$ элементов типа `int` (по 4 байта каждый), то он занимает ровно $4 \times N$ байт памяти. Никаких дополнительных накладных расходов нет.
2. **Односвязный список:** каждый узел хранит значение данных (например, `int` размером 4 байта) и один указатель `next` (на 64-битной архитектуре указатель занимает 8 байт). Итого на каждый элемент приходится $4 + 8 = 12$ байт. Из них полезные данные составляют лишь одну треть ($33\%$), а две трети памяти уходят на служебные указатели.
3. **Двусвязный список:** каждый узел хранит данные (4 байта), указатель `next` (8 байт) и указатель `prev` (8 байт). Итого $4 + 8 + 8 = 20$ байт на один узел.

Таким образом, списки менее эффективны с точки зрения компактности хранения данных в оперативной памяти по сравнению с массивами.

### Разобранный пример

#### Условие задачи
Сравнить количество операций памяти и пересылок элементов при вставке нового элемента в середину статического массива из 1000 элементов и в середину односвязного списка из 1000 элементов при условии, что позиция вставки уже найдена. Размер типа данных `int` равен 4 байтам, размер указателя равен 8 байтам.

#### Рисунок словами
- **Массив:** В непрерывном блоке памяти выделено 1000 ячеек для целых чисел. Позиция вставки находится ровно посередине — между элементами с индексами 499 и 500. Чтобы вставить новый элемент, элементы с индексами от 500 до 999 (всего 500 элементов) должны быть физически прочитаны и перезаписаны в соседние ячейки памяти (сдвинуты вправо на 1 позицию).
- **Односвязный список:** Узлы списка распределены по куче. Позиция вставки найдена — это узел под номером 500. Чтобы вставить новый узел, не нужно перемещать или перезаписывать существующие элементы списка. Требуется лишь выделить память в куче под один новый узел и изменить значения двух указателей.

#### Ход рассуждений
1. **Для статического массива:**
   - Позиция вставки известна (индекс 500).
   - Чтобы освободить ячейку под новый элемент, все элементы с индексами от 500 до 999 включительно должны быть сдвинуты вправо. Количество элементов для сдвига: $1000 - 500 = 500$ элементов.
   - Каждая операция сдвига состоит из операции чтения элемента из одной ячейки памяти и записи в другую (1 чтение + 1 запись = 2 операции с памятью на каждый элемент).
   - Общее количество операций перезаписи данных: $500 \text{ элементов} \times 2 = 1000$ обращений к памяти для перемещения данных, плюс 1 операция записи самого нового элемента.
   - Общий объем перемещаемых данных в байтах: $500 \times 4 \text{ байта} = 2000$ байт.

2. **Для односвязного списка:**
   - Позиция вставки известна (указатель на узел № 500).
   - Операция сдвига элементов отсутствует полностью ($0$ пересылок данных).
   - Выделяется память под один новый узел: вызывается оператор `new`, который создает узел размером $4 \text{ (data)} + 8 \text{ (next)} = 12$ байт.
   - Изменяются ровно два указателя (выполняются 2 операции присваивания адресов):
     1. Указатель нового узла устанавливается на следующий узел: `newNode->next = current->next;`
     2. Указатель текущего узла перенаправляется на новый узел: `current->next = newNode;`

#### Решение в общем виде
Пусть размер структуры равен $N$, а индекс позиции вставки равен $k$ ($k = N/2$ для середины):
- Количество пересылок элементов в массиве: $N - k$.
- Количество пересылок элементов в списке: $0$.
- Количество выделений динамической памяти в массиве: $0$ (если массив статический или не требует реаллокации).
- Количество выделений динамической памяти в списке: $1$ (создание нового узла `new Node`).

#### Вычисление для нашего примера ($N = 1000, k = 500$):
- **Массив:** требуется сдвинуть $1000 - 500 = 500$ элементов. Объем перемещаемых данных составляет $500 \times 4 = 2000$ байт.
- **Список:** требуется $0$ перемещений элементов, выделяется $1$ новый узел размером 12 байт, обновляется 2 указателя.

#### Проверка
- Единицы измерения: количество элементов, байты, количество операций. Всё совпадает.
- Правдоподобие: массив требует массового перемещения данных в памяти ($O(N)$), в то время как список производит локальное обновление указателей за постоянное время ($O(1)$), что полностью соответствует теоретическому выводу.

Ответ: Для массива требуется сдвинуть 500 элементов (переместить 2000 байт данных). Для односвязного списка требуется 0 перемещений элементов, выделение 1 нового узла размером 12 байт и изменение 2 указателей.

## 2. Проектирование структуры и интерфейса односвязного списка

### 1. Проектирование узла списка (`Node`)

Прежде чем написать класс, управляющий списком, необходимо спроектировать строительный блок, из которого этот список будет состоять. В односвязном списке каждый элемент представляет собой отдельный фрагмент динамической памяти — узел (англ. *Node*). 

> **Определение.** Узел односвязного списка (`Node`) — это структура данных, содержащая полезную нагрузку (данные) и адрес (указатель) на следующий узел этого же типа в памяти.

Для реализации на языке C++17 мы воспользуемся ключевым словом `struct`. Выбор `struct`, а не `class`, обусловлен тем, что все поля узла должны быть доступны управляющему классу списка напрямую, без написания громоздких методов доступа (*getters/setters*).

Рассмотрим структуру `Node`:

```cpp
struct Node {
    int data;     // Полезная нагрузка: целочисленные данные
    Node* next;   // Указатель на следующий узел в памяти

    // Конструктор узла для удобства создания
    Node(int val) : data(val), nullptr) {}
};
```

Давайте разберем каждую строчку этого определения:
1. `int data;` — поле, в котором хранится реальное значение элемента списка (в нашем случае — целое число).
2. `Node* next;` — указатель. Обратите внимание, что типом этого указателя является `Node*` (указатель на объект структуры `Node`). Это ключевой момент: узел содержит адрес точно такого же узла. Именно эта рекурсивная ссылка позволяет элементам «цепляться» друг за друга, образуя цепочку.
3. Конструктор `Node(int val)` принимает значение `val`, записывает его в поле `data` и инициализирует указатель `next` значением `nullptr`. 

*Важное примечание о `nullptr`: * В современном стандарте C++17 категорически запрещено использовать макрос `NULL` или число `0` для обозначения пустых указателей. `nullptr` имеет собственный тип `std::nullptr_t`, что обеспечивает строгую безопасность типов при компиляции.

### 2. Проектирование класса `SinglyLinkedList`

Сам по себе набор разрозненных узлов неудобен для работы. Пользователю нужен единый интерфейс управления: добавлять элементы, удалять их, узнавать размер. Для этого создается класс `SinglyLinkedList`.

Класс должен инкапсулировать указатель на начало цепочки и текущее количество элементов. Спроектируем его поля:

```cpp
class SinglyLinkedList {
private:
    Node* head;   // Указатель на первый узел списка (голову)
    size_t size;  // Количество элементов в списке

public:
    // Объявление методов интерфейса будет здесь
};
```

Разберем назначение этих полей:
1. `Node* head;` — это отправная точка списка. Если `head` равен `nullptr`, значит, список пуст. Если в списке есть хотя бы один элемент, `head` хранит адрес самого первого узла. Зная `head`, мы можем добраться до второго узла (`head->next`), до третьего (`head->next->next`) и так далее. У класса списка **нет** указателя на хвост в базовой реализации, поэтому любой доступ к элементам в конце списка требует обхода с головы.
2. `size_t size;` — счетчик элементов. Тип `size_t` является стандартным беззнаковым целочисленным типом в C++, предназначенным для измерения размеров объектов. Хранение размера в отдельном поле позволяет узнавать длину списка за константное время $O(1)$, не пересчитывая узлы вручную.

---

### 3. Конструктор по умолчанию и состояние пустого списка

Когда объект класса `SinglyLinkedList` только создается в памяти (например, при объявлении `SinglyLinkedList list;`), он должен находиться в корректном, предсказуемом состоянии. За это отвечает конструктор по умолчанию.

Для пустого списка выполняются следующие инварианты (неизменные правила):
- Голова списка не указывает ни на какой узел: `head = nullptr`.
- Размер списка равен нулю: `size = 0`.

Напишем конструктор в коде:

```cpp
SinglyLinkedList() : head(nullptr), size(0) {}
```

Использование списков инициализации членов класса (после двоеточия `:`) является стандартом хорошего тона в C++, так как поля инициализируются сразу своими значениями, избегая лишнего этапа присваивания.

---

### 4. Деструктор класса и предотвращение утечек памяти

Динамические структуры данных размещают свои узлы в куче с помощью оператора `new`. Если объект списка уничтожается (например, выходит из области видимости), сами переменные `head` и `size` на стеке уничтожатся, но выделенные в куче узлы останутся висеть в памяти, порождая **утечку памяти** (англ. *memory leak*).

Чтобы этого не происходило, у класса должен быть **деструктор**, который автоматически вызывается при уничтожении объекта и возвращает всю занятую память операционной системе с помощью оператора `delete`.

Алгоритм очистки списка:
1. Нам нужно пройти по всем узлам от головы до конца.
2. Поскольку при удалении узла мы потеряем доступ к его полю `next`, мы должны перед удалением сохранить адрес следующего узла во временную переменную.
3. Повторять этот процесс для каждого узла.

Реализация деструктора и вспомогательного метода `clear()`:

```cpp
~SinglyLinkedList() {
    clear();
}

void clear() {
    Node* current = head;
    while (current != nullptr) {
        Node* nextNode = current->next; // Сохраняем адрес следующего узла
        delete current;                 // Удаляем текущий узел
        current = nextNode;             // Переходим к следующему
    }
    head = nullptr;                     // Обнуляем голову
    size = 0;                           // Сбрасываем размер
}
```

Рассмотрим по шагам выполнение метода `clear()` для списка из двух элементов (`[10] -> [20] -> nullptr`):
- Указатель `current` указывает на узел с данными `10`.
- Во временную переменную `nextNode` записывается адрес узла с данными `20`.
- Выполняется `delete current`. Память узла `10` освобождена.
- `current` принимает значение `nextNode` (теперь указывает на `20`).
- Цикл повторяется: `nextNode` становится `nullptr`, узел `20` удаляется.
- `current` становится `nullptr`, цикл завершается.
- `head` устанавливается в `nullptr`, `size` становится `0`. Утечек памяти нет.

### 5. Константные методы проверки состояния: `isEmpty()` и getSize()`

Для внешнего кода часто требуется узнать состояние списка, не изменяя его. Такие методы в C++ помечаются ключевым словом `const` сразу после списка аргументов. Это гарантирует компилятору и программисту, что метод не изменит поля объекта.

Реализация метода проверки на пустоту:

```cpp
bool isEmpty() const {
    return head == nullptr; // или return size == 0;
}
```

Реализация метода получения размера:

```cpp
size_t getSize() const {
    return size;
}
```

Оба метода выполняются за константное время $O(1)$, так как они делают единственное сравнение или возвращают готовое значение переменной.

### 6. Анализ граничных случаев (Edge Cases)

При работе с односвязными списками абсолютное большинство ошибок (падений программы по сегментации памяти — *Segmentation Fault*) возникает из-за игнорирования граничных случаев. Всегда рассматривайте три сценария:

1. **Пустой список (`head == nullptr`, `size == 0`).**
   - Указатель `head` равен `nullptr`. Любая попытка разыменования вида `head->data` приведет к мгновенному аварийному завершению программы. Всегда проверяйте условие `isEmpty()` перед операциями чтения или удаления.
2. **Список из одного элемента (`head != nullptr`, `head->next == nullptr`, `size == 1`).**
   - Единственный узел одновременно является и головой, и хвостом. При его удалении указатель `head` обязательно должен стать `nullptr`, иначе он превратится в «висячий указатель» (*dangling pointer*), указывающий на освобожденную память.
3. **Операции с головой списка.**
   - Вставка в голову и удаление из головы изменяют значение указателя `head`. Если забыть переприсвоить `head` на новый узел при вставке, элемент потеряется в памяти. Если забыть обновить `head` при удалении единственного элемента, список останется в поврежденном состоянии.

### Разобранный пример

**Условие:** Спроектировать словесное описание и UML-подобную схему классов `Node` и `SinglyLinkedList` для хранения целых чисел. Указать точные начальные значения полей для только что созданного пустого списка.

**Решение (словесное описание и схема структуры):**

1. **Структура `Node`:**
   - Поля:
     - `int data` — хранит целое число.
     - `Node* next` — хранит указатель на следующий объект `Node` (или `nullptr`).
   - Конструктор: принимает `int val`, инициализирует `data = val` и `next = nullptr`.

2. **Класс `SinglyLinkedList`:**
   - Приватные поля:
     - `Node* head` — указатель на первый узел списка.
     - `size_t size` — беззнаковое целое число, количество элементов.
   - Публичные методы:
     - Конструктор по умолчанию `SinglyLinkedList()`.
     - Деструктор `~SinglyLinkedList()`.
     - Метод очистки `void clear()`.
     - Метод проверки пустоты `bool isEmpty() const`.
     - Метод получения размера `size_t getSize() const`.

3. **Состояние полей для пустого списка:**
   При выполнении кода:
   ```cpp
   SinglyLinkedList myList;
   ```
   В оперативной памяти создается объект класса `myList`, внутри которого:
   - `head` = `nullptr` (адрес отсутствует, так как узлов еще нет).
   - `size` = `0` (количество элементов равно нулю).

Проверка правдоподобия: значение `head` равное `nullptr` корректно интерпретируется методом `isEmpty()`, возвращая `true`. Попытка очистки пустого списка через метод `clear()` безопасна, так как цикл `while (current != nullptr)` завершится на первой же итерации, не выполняя никаких операций с памятью.

## 3. Реализация основных операций в односвязном списке

### Алгоритм вставки элемента в начало списка (`push_front`)

Вставка нового элемента в начало односвязного списка — это операция добавления узла непосредственно перед текущей головой списка (`head`). Поскольку доступ к первом элементу у нас всегда сохранен в указателе `head`, эту операцию можно выполнить за константное время $O(1)$, независимо от общего количества элементов в списке.

Для реализации метода `push_front(int value)` выполняются следующие шаги:
1. Создается новый узел в динамической памяти с помощью оператора `new Node(value)`. Передаваемое значение `value` записывается в поле `data` созданного узла, а его поле `next` инициализируется значением `nullptr`.
2. Указатель `next` нового узла перенаправляется на текущую голову списка (`head`). Таким образом новый узел начинает ссылаться на старый первый элемент списка.
3. Указатель `head` всего списка переназначается на созданный узел. Теперь голова указывает на новый элемент.
4. Счетчик размера списка `size` увеличивается на единицу (`++size`).

Рассмотрим пошаговую схему вставки элемента со значением $15$ в список, который уже содержит элементы $10$ и $20$:

```text
Начальное состояние:
head ---> [ 10 ] -> [ 20 ] -> nullptr

Шаг 1: Создан новый узел newNode [ 15 ] -> nullptr
Шаг 2: newNode->next указывает на head:
newNode ---> [ 15 ] --+
                      |
head -----------------+-> [ 10 ] -> [ 20 ] -> nullptr

Шаг 3: head переназначается на newNode:
head ---> [ 15 ] ---> [ 10 ] -> [ 20 ] -> nullptr
```

Временная сложность операции `push_front` составляет $O(1)$, так как количество выполняемых действий не зависит от размера списка $N$.

---

### Алгоритм вставки элемента в конец списка (`push_back`)

Вставка элемента в конец односвязного списка (`push_back(int value)`) в базовой реализации класса `SinglyLinkedList` (когда мы храним только указатель `head` и не храним указатель на хвост `tail`) требует прохода по всем элементам от начала до самого последнего узла. Это необходимо для того, чтобы найти узел, у которого поле `next` равно `nullptr`, и изменить его ссылку на только что созданный узел.

Алгоритм состоит из следующих шагов:
1. Создается новый узел с помощью оператора `new Node(value)`. Его поле `data` получает значение `value`, а `next` устанавливается в `nullptr`.
2. Проверяется граничный случай: если список пуст (`head == nullptr`), то единственный новый узел становится одновременно и головой списка. Указатель `head` присваивается адресу нового узла, размер увеличивается, и работа метода завершается.
3. Если список не пуст, заводится вспомогательный указатель для обхода, например `Node* current = head`.
4. С помощью цикла `while (current->next != nullptr)` указатель `current` перемещается вперед по списку до тех пор, пока не окажется на самом последнем узле (то есть у узла, чей `next` равен `nullptr`).
5. Поле `next` найденного последнего узла (`current->next`) изменяется так, чтобы оно указывало на созданный новый узел.
6. Счетчик размера `size` увеличивается на единицу.

Временная сложность операции `push_back` в худшем случае составляет $O(N)$, где $N$ — текущее количество элементов в списке, так как в процессе поиска конца списка мы обязаны посетить каждый узел.

---

### Алгоритм удаления элемента из начала списка (`pop_front`)

Удаление элемента из начала списка (`pop_front`) — это обратная операция к вставке в голову. Она выполняется за константное время $O(1)$. Удаление первого элемента освобождает память, занимаемую им, и переносит указатель `head` на следующий за ним узел.

Пошаговый алгоритм:
1. Проверяется граничный случай: если список пуст (`head == nullptr`), удаление невозможно. В зависимости от принятой логики программы можно выбросить исключение, вывести ошибку или просто завершить метод (в нашем случае возвращается `void` с предварительной проверкой `if (isEmpty()) return;`).
2. Сохраняется временный указатель на удаляемый узел: `Node* temp = head;`. Это необходимо для того, чтобы после перенастройки указателей корректно освободить память.
3. Указатель `head` смещается на следующий узел: `head = head->next;`. Теперь второй элемент списка становится первым.
4. Высвобождается динамическая память удаляемого узла с помощью оператора `delete temp;`.
5. Счетчик размера списка уменьшается на единицу (`--size`).

Если в списке был ровно один элемент, то после выполнения `head = head->next` указатель `head` станет равным `nullptr`, что корректно переведет список в состояние пустого.

Временная сложность `pop_front` составляет $O(1)$.

---

### Алгоритм удаления элемента из конца списка (`pop_back`)

Удаление элемента с конца односвязного списка (`pop_back`) в структуре, хранящей только указатель на голову (`head`), является трудоемкой операцией. Чтобы удалить последний узел, нам необходимо не только дойти до него, но и найти предпоследний узел, чтобы обнулить его поле `next`.

Алгоритм состоит из следующих шагов:
1. Проверка граничного случая пустого списка (`head == nullptr`). Если список пуст, удаление невозможно.
2. Проверка случая, когда в списке ровно один элемент (`head->next == nullptr`). В этой ситуации удаление последнего элемента эквивалентно удалению головы: мы вызываем `delete head;`, после чего устанавливаем `head = nullptr` и уменьшаем `size`.
3. Если в списке два или более элементов, заводим два указателя для обхода: `current` для поиска последнего узла и `prev` для отслеживания предпоследнего узла. Инициализируем их: `Node* current = head; Node* prev = nullptr;`.
4. Запускаем цикл обхода: пока у текущего узла есть следующий элемент (`current->next != nullptr`), мы сдвигаем указатели: `prev` принимает значение `current`, а `current` переходит на `current->next`.
5. По завершении цикла `current` указывает на последний узел списка, а `prev` — на предпоследний.
6. Удаляем последний узел: `delete current;`.
7. Обрываем связь у бывшего предпоследнего узла: `prev->next = nullptr;`.
8. Уменьшаем размер списка на единицу (`--size`).

Временная сложность операции `pop_back` в односвязном списке составляет $O(N)$, так как для поиска предпоследнего узла требуется пройти от начала до конца списка.

---

### Алгоритм поиска элемента по значению (`find`)

Поиск элемента в односвязном списке по заданному значению (`find(int target)`) заключается в последовательном просмотре всех узлов от головы до конца списка до тех пор, пока не будет найден узел с совпадающим полем `data`.

Алгоритм:
1. Инициализируем вспомогательный указатель для обхода: `Node* current = head;`.
2. Запускаем цикл `while (current != nullptr)`.
3. На каждой итерации проверяем условие: если `current->data == target`, значит, искомый элемент найден. Возвращаем указатель на этот узел (`return current;`).
4. Если значение не совпало, переходим к следующему узлу: `current = current->next;`.
5. Если цикл завершился (указатель `current` дошел до `nullptr` и вышел из списка) и совпадение не было найдено, возвращаем `nullptr`.

Временная сложность поиска в худшем случае составляет $O(N)$ (если элемент находится в самом конце или отсутствует вовсе), а пространственная сложность равна $O(1)$, так как не создается никаких дополнительных структур данных.

### Алгоритм вывода содержимого списка на экран (`print`)

Для визуальной проверки содержимого списка используется метод `print()`, который обходит все узлы от начала до конца и выводит значения `data` в стандартный вывод.

Алгоритм:
1. Объявляем указатель `Node* current = head;`.
2. Запускаем цикл `while (current != nullptr)`.
3. Выводим значение `current->data` в консоль, разделяя элементы стрелками для наглядности (например, `cout << current->data << " -> ";`).
4. Переходим к следующему узлу: `current = current->next;`.
5. После завершения цикла выводим слово `nullptr` для демонстрации конца списка и переводим строку.

Временная сложность обхода и вывода списка составляет $O(N)$.

### Полный компилируемый код класса `SinglyLinkedList` на C++17

Ниже представлен полностью рабочий, компилируемый код, реализующий односвязный список со всеми рассмотренными операциями, а также конструктором, деструктором и функцией `main` для демонстрации его работы.

```cpp
#include <iostream>

// Структура узла односвязного списка
struct Node {
    int data;
    Node* next;

    // Конструктор узла
    Node(int val) : data(val), next(nullptr) {}
};

// Класс односвязного списка
class SinglyLinkedList {
private:
    Node* head; // Указатель на первый узел списка
    int size;   // Текущее количество элементов в списке

public:
    // Конструктор по умолчанию: создает пустой список
    SinglyLinkedList() : head(nullptr), size(0) {}

    // Деструктор: освобождает всю динамическую память
    ~SinglyLinkedList() {
        clear();
    }

    // Проверка списка на пустоту
    bool isEmpty() const {
        return head == nullptr;
    }

    // Получение текущего размера списка
    int getSize() const {
        return size;
    }

    // Вставка элемента в начало списка (O(1))
    void push_front(int value) {
        Node* newNode = new Node(value);
        newNode->next = head;
        head = newNode;
        ++size;
    }

    // Вставка элемента в конец списка (O(N))
    void push_back(int value) {
        Node* newNode = new Node(value);
        if (isEmpty()) {
            head = newNode;
        } else {
            Node* current = head;
            while (current->next != nullptr) {
                current = current->next;
            }
            current->next = newNode;
        }
        ++size;
    }

    // Удаление элемента из начала списка (O(1))
    void pop_front() {
        if (isEmpty()) {
            return;
        }
        Node* temp = head;
        head = head->next;
        delete temp;
        --size;
    }

    // Удаление элемента из конца списка (O(N))
    void pop_back() {
        if (isEmpty()) {
            return;
        }
        if (head->next == nullptr) {
            delete head;
            head = nullptr;
        } else {
            Node* current = head;
            Node* prev = nullptr;
            while (current->next != nullptr) {
                prev = current;
                current = current->next;
            }
            delete current;
            prev->next = nullptr;
        }
        --size;
    }

    // Поиск элемента по значению (возвращает указатель на узел или nullptr)
    Node* find(int target) const {
        Node* current = head;
        while (current != nullptr) {
            if (current->data == target) {
                return current;
            }
            current = current->next;
        }
        return nullptr;
    }

    // Полная очистка списка
    void clear() {
        while (!isEmpty()) {
            pop_front();
        }
    }

    // Вывод содержимого списка на экран
    void print() const {
        Node* current = head;
        while (current != nullptr) {
            std::cout << current->data << " -> ";
            current = current->next;
        }
        std::cout << "nullptr\n";
    }
};

int main() {
    // Создание пустого односвязного списка
    SinglyLinkedList list;

    // Добавление чисел 10, 20 и 30 в конец списка
    list.push_back(10);
    list.push_back(20);
    list.push_back(30);

    // Вывод списка на экран
    std::cout << "Список после добавления элементов: ";
    list.print();

    // Демонстрация поиска элемента
    int target = 20;
    Node* foundNode = list.find(target);
    if (foundNode != nullptr) {
        std::cout << "Элемент " << target << " найден в списке.\n";
    } else {
        std::cout << "Элемент " << target << " не найден.\n";
    }

    // Удаление элементов с начала и конца
    list.pop_front();
    std::cout << "Список после pop_front: ";
    list.print();

    list.pop_back();
    std::cout << "Список после pop_back: ";
    list.print();

    return 0;
}
```

#### Пример работы программы

**Входные данные:**
Программа выполняет жестко зашифрованные в функции `main` вызовы методов: создание объекта `SinglyLinkedList`, последовательный вызов `push_back(10)`, `push_back(20)`, `push_back(30)`, поиск значения `20`, а также удаление через `pop_front()` и `pop_back()`.

**Вывод программы в консоль:**
```text
Список после добавления элементов: 10 -> 20 -> 30 -> nullptr
Элемент 20 найден в списке.
Список после pop_front: 20 -> 30 -> nullptr
Список после pop_back: 20 -> nullptr
```

**Проверка и правдоподобность:**
1. После добавления элементов `10`, `20`, `30` через метод `push_back` порядок элементов сохраняется строго от головы к хвосту: `10 -> 20 -> 30 -> nullptr`, что соответствует ожиданиям.
2. Поиск числа `20` возвращает валидный указатель на узел, подтверждая корректность алгоритма обхода.
3. Вызов `pop_front` удаляет первый элемент (`10`), оставляя голову указывать на `20`.
4. Вызов `pop_back` удаляет последний элемент (`30`), оставляя в списке единственный узел со значением `20`. При завершении программы срабатывает деструктор, который корректно очищает оставшуюся динамическую память без утечек.

## 4. Проектирование и устройство двусвязного списка

### Обоснование необходимости двусвязного списка

В предыдущих разделах мы подробно изучили односвязный список (*Singly Linked List*). Его главным ограничением является однонаправленность связей: каждый узел хранит указатель `next`, ведущий строго вперед — к следующему элементу. Из-за этого мы можем двигаться по списку только в одном направлении: от головы к хвосту.

Представьте, что вы находитесь в произвольном узле односвязного списка и вам нужно удалить этот узел или вставить новый элемент непосредственно перед ним. Поскольку у узла нет ссылки на своего предшественника, вы не можете узнать, кто находится перед вами, не начав поиск с самого начала (`head`). Это приводит к следующим фундаментальным проблемам односвязного списка:
1. **Удаление с хвоста за линейное время.** Чтобы удалить последний элемент односвязного списка, вам нужно дойти до него, перебирая элементы от головы. Даже при наличии указателя на хвост (`tail`), предпоследний узел останется неизвестным, поэтому удалить хвост за константное время $O(1)$ в односвязном списке невозможно.
2. **Однонаправленный обход.** Если алгоритму требуется многократно перемещаться вперед и назад (например, при реализации текстового редактора с историей изменений или двунаправленного итератора), односвязный список становится неэффективным, так как каждый шаг назад требует повторного прохода от начала.

Для устранения этих недостатков используется **двусвязный список** (*Doubly Linked List*). В этой структуре каждый узел содержит два указателя: один указывает на следующий элемент (`next`), а второй — на предыдущий (`prev`). Благодаря этому обеспечивается двусторонняя навигация и возможность эффективного выполнения операций как с началом, так и с концом списка.

> **Определение.** Двусвязный список (*Doubly Linked List*) — это динамическая структура данных, состоящая из узлов, каждый из которых содержит поле данных и два указателя: на следующий и на предыдущий узлы списка.

---

### Устройство узла двусвязного списка

Посмотрим на программную реализацию узла двусвязного списка на языке C++17. Назовем структуру узла `DoublyNode`.

```cpp
struct DoublyNode {
    int data;          // Поле для хранения полезных данных
    DoublyNode* next;  // Указатель на следующий узел в списке
    DoublyNode* prev;  // Указатель на предыдущий узел в списке

    // Конструктор для удобной инициализации узла
    DoublyNode(int val) : data(val), next(nullptr), prev(nullptr) {}
};
```

Каждая составляющая структуры `DoublyNode` играет строгую роль:
- `data` хранит значение элемента (в нашем случае типа `int`).
- `next` хранит адрес памяти следующего узла. Если текущий узел является последним (хвостом списка), поле `next` принимает значение `nullptr`.
- `prev` хранит адрес памяти предыдущего узла. Если текущий узел является первым (головой списка), поле `prev` принимает значение `nullptr`.

---

### Устройство класса DoublyLinkedList и указатель на хвост

Класс `DoublyLinkedList` управляет совокупностью узлов, выделенных в динамической памяти (в куче). Для поддержания эффективных операций вставки и удаления как в начало, так и в конец списка, класс хранит три основных поля:

1. `DoublyNode* head` — указатель на первый узел списка. Если список пуст, `head` равен `nullptr`.
2. `DoublyNode* tail` — указатель на последний узел списка. Если список пуст, `tail` равен `nullptr`.
3. `size_t size` — количество элементов в списке, хранящееся для обеспечения константного времени получения размера $O(1)$.

Рассмотрим скелет класса `DoublyLinkedList`:

```cpp
class DoublyLinkedList {
private:
    DoublyNode* head;
    DoublyNode* tail;
    size_t size;

public:
    // Конструктор по умолчанию: создает пустой список
    DoublyLinkedList() : head(nullptr), tail(nullptr), size(0) {}

    // Деструктор для освобождения памяти
    ~DoublyLinkedList() {
        clear();
    }

    // Проверка списка на пустоту за O(1)
    bool isEmpty() const {
        return size == 0;
    }

    // Получение текущего размера за O(1)
    size_t getSize() const {
        return size;
    }

    // Объявления других методов (push_front, push_back и т.д.) будут рассмотрены позже
    void clear();
};
```

#### Преимущества наличия указателя на хвост (tail)

В односвязном списке операция добавления элемента в конец списка (`push_back`) требует прохода по всем элементам от `head` до последнего узла, что занимает линейное время $O(N)$. 

В двусвязном списке у нас есть прямой доступ к последнему элементу через указатель `tail`. Это позволяет реализовать добавление элемента в конец списка (`push_back`) и удаление элемента с конца списка (`pop_back`) за строгое константное время $O(1)$. Нам не нужно обходить список: мы просто создаем новый узел, перепривязываем указатели `tail` и `next`/`prev` за фиксированное число шагов.

---

### Инварианты структуры двусвязного списка

Инвариант — это логическое условие, которое всегда должно выполняться для корректной работы структуры данных до и после выполнения любой операции. Нарушение инварианта приводит к неопределенному поведению (*undefined behavior*), сегментации памяти (*segmentation fault*) или утечкам.

Для двусвязного списка выделяются два базовых состояния, задающих жесткие инварианты:

1. **Состояние пустого списка:**
   - `head == nullptr`
   - `tail == nullptr`
   - `size == 0`
   *Пояснение:* В пустом списке нет ни одного узла, поэтому указатели на границы не могут указывать на какие-либо объекты в памяти.

2. **Состояние списка из ровно одного элемента:**
   - `head == tail` (голова и хвост указывают на единственный узел)
   - `head->next == nullptr` (следующего узла нет)
   - `head->prev == nullptr` (предыдущего узла нет)
   - `size == 1`
   *Пояснение:* Единственный элемент одновременно является и началом, и концом списка, а его указатели `next` и `prev` обнулены.

При реализации любых методов вставки и удаления необходимо гарантировать, что после завершения операции эти инварианты не будут нарушены.

---

### Правила поддержания ссылок next и prev

Главная сложность при написании кода для двусвязного списка заключается в аккуратном обновлении указателей `next` и `prev`. Если вы измените порядок присваивания указателей или забудете обновить один из них, цепочка ссылок разорвется, и часть списка окажется недоступной в памяти (утечка памяти) либо программа обратится по неверному адресу.

Общее правило для вставки нового узла между двумя существующими:
1. Сначала настройте указатели **нового** узла (`newNode->next` и `newNode->prev`).
2. Затем обновите указатель `prev` у **правого** соседа.
3. Затем обновите указатель `next` у **левого** соседа.
4. В самом конце обновите внешние указатели списка (`head` или `tail`, если затрагиваются границы) и переменную `size`.

Соблюдение этого порядка предотвращает потерю ссылок на соседние узлы до того, как они будут зафиксированы.

---

### Разобранный пример: вставка узла в середину двусвязного списка

#### Условие задачи
Дан двусвязный список, содержащий два узла со значениями `20` и `30`, расположенные последовательно. Узел со значением `20` является головой (`head`), узел со значением `30` является хвостом (`tail`). То есть связи выглядят следующим образом:
`head` -> [ Node 20 ] <-> [ Node 30 ] <- `tail`

Требуется описать по шагам изменение указателей `next` и `prev` у соседних узлов при вставке нового узла со значением `25` строго между узлами со значениями `20` и `30`.

#### Рисунок схемы связей (ASCII)

Исходное состояние:
```
+----------+        +----------+
| Node 20  | <----> | Node 30  |
| data: 20 |        | data: 30 |
| next: ---+------> | next: nullptr
| prev: nullptr     | prev: <--+
+----------+        +----------+
  ^                   ^
  |                   |
head                tail
```

#### Ход рассуждений
1. Нам нужно вставить узел с данными `25` между существующими узлами `20` и `30`.
2. Найдем левый узел (назовем его `leftNode`, это узел со значением `20`) и правый узел (назовем его `rightNode`, это узел со значением `30`).
3. Выделим память под новый узел: `DoublyNode* newNode = new DoublyNode(25);`. На данный момент у него `newNode->next = nullptr` и `newNode->prev = nullptr`.
4. Новый узел должен ссылаться своим полем `next` на `rightNode` (узел `30`), а полем `prev` на `leftNode` (узел `20`). Выполняем присваивания:
   - `newNode->next = leftNode->next;` (то есть `rightNode`)
   - `newNode->prev = leftNode;`
5. Теперь нужно перенаправить указатели существующих соседей на новый узел:
   - У правого соседа (`rightNode`, который доступен как `newNode->next`) поле `prev` должно указывать на `newNode`: `rightNode->prev = newNode;` (или `newNode->next->prev = newNode;`).
   - У левого соседа (`leftNode`) поле `next` должно указывать на `newNode`: `leftNode->next = newNode;`.
6. Границы списка (`head` и `tail`) не изменились, так как вставка происходит в строгую середину. Увеличиваем размер списка `size++`.

#### Пошаговое изменение указателей (трассировка)

1. **Создание нового узла:**
   - `newNode->data = 25`
   - `newNode->next = nullptr`
   - `newNode->prev = nullptr`

2. **Настройка связей нового узла:**
   - `newNode->next = 30` (адрес узла со значением `30`)
   - `newNode->prev = 20` (адрес узла со значением `20`)
   *Состояние на этом шаге:* узел `25` «знает», кто стоит до него и после него, но сами узлы `20` и `30` еще ничего не знают о появлении нового соседа.

3. **Обновление правого соседа (`30`):**
   - Обращаемся к правому соседу через новый узел: `newNode->next->prev` — это поле `prev` узла `30`.
   - Выполняем присваивание: `newNode->next->prev = newNode;`
   - Теперь узел `30` своим указателем `prev` ссылается на узел `25`.

4. **Обновление левого соседа (`20`):**
   - Обращаемся к левому соседу: `leftNode->next` — это поле `next` узла `20`.
   - Выполняем присваивание: `leftNode->next = newNode;`
   - Теперь узел `20` своим указателем `next` ссылается на узел `25`.

#### Итоговая схема связей после вставки

```
+----------+        +----------+        +----------+
| Node 20  | <----> | Node 25  | <----> | Node 30  |
| data: 20 |        | data: 25 |        | data: 30 |
| next: ---+------> | next: ---+------> | next: nullptr
| prev: nullptr     | prev: <--+        | prev: <--+
+----------+        +----------+        +----------+
  ^                                       ^
  |                                       |
head                                    tail
```

#### Проверка и правдоподобие
- Количество узлов увеличилось с 2 до 3.
- Нарушений инвариантов нет: `head` по-прежнему указывает на узел `20`, чей `prev` равен `nullptr`; `tail` по-прежнему указывает на узел `30`, чей `next` равен `nullptr`.
- Узел `25` корректно интегрирован в двустороннюю цепочку: `newNode->prev->next` ведет к `newNode`, а `newNode->next->prev` также ведет к `newNode`.

Ответ: вставка узла 25 выполнена путем установки `newNode->next = 30`, `newNode->prev = 20`, затем перенаправления `30->prev = newNode` и `20->next = newNode`.

## 5. Реализация операций в двусвязном списке и полный код

### 1. Реализация вставки в начало и конец двусвязного списка

Для реализации полноценного двусвязного списка на языке C++17 нам понадобятся две сущности: структура узла (`Node`) и класс контейнера (`DoublyLinkedList`). В отличие от односвязного списка, каждый узел двусвязного списка содержит не только данные и указатель на следующий элемент (`next`), но и указатель на предыдущий элемент (`prev`). Это позволяет осуществлять навигацию в обоих направлениях и выполнять операции вставки и удаления на обоих концах за константное время $O(1)$.

Напомним устройство узла и класса, спроектированных в предыдущих разделах:

```cpp
struct Node {
    int data;
    Node* next;
    Node* prev;

    Node(int val) : data(val), next(nullptr), prev(nullptr) {}
};

class DoublyLinkedList {
private:
    Node* head;
    Node* tail;
    size_t size;

public:
    DoublyLinkedList() : head(nullptr), tail(nullptr), size(0) {}
    // Объявления методов...
};
```

#### Вставка в начало: метод `push_front(int value)`

Операция вставки нового элемента в начало списка заключается в создании нового узла и корректном перенаправлении указателей `head`, `prev` и `next`. Временная сложность этой операции составляет $O(1)$, так как не требуется обход существующих элементов.

Рассмотрим пошаговый алгоритм:
1. Создаем новый узел `newNode` со значением `value`. Его указатели `next` и `prev` по умолчанию равны `nullptr`.
2. Проверяем, является ли список пустым (`head == nullptr` или `size == 0`). Если список пустой, то новый узел становится одновременно и головой (`head`), и хвостом (`tail`) списка.
3. Если список не пустой:
   - Указатель `next` нового узла должен ссылаться на текущую голову: `newNode->next = head`.
   - Указатель `prev` текущей головы должен ссылаться на новый узел: `head->prev = newNode`.
   - Указатель `head` перенастраивается на новый узел: `head = newNode`.
4. Увеличиваем счетчик размера `size` на единицу.

Реализация метода на C++17:

```cpp
void push_front(int value) {
    Node* newNode = new Node(value);
    
    if (isEmpty()) {
        head = newNode;
        tail = newNode;
    } else {
        newNode->next = head;
        head->prev = newNode;
        head = newNode;
    }
    size++;
}
```

#### Вставка в конец: метод `push_back(int value)`

Благодаря тому, что в классе `DoublyLinkedList` поддерживается прямой указатель на хвост списка (`tail`), добавление элемента в конец также выполняется за константное время $O(1)$ без необходимости проходить весь список от начала до конца.

Рассмотрим пошаговый алгоритм:
1. Создаем новый узел `newNode` со значением `value`.
2. Проверяем, является ли список пустым. Если список пустой, то `head` и `tail` одновременно указывают на `newNode`.
3. Если список не пустой:
   - Указатель `prev` нового узла должен ссылаться на текущий хвост: `newNode->prev = tail`.
   - Указатель `next` текущего хвоста должен ссылаться на новый узел: `tail->next = newNode`.
   - Указатель `tail` перенастраивается на новый узел: `tail = newNode`.
4. Увеличиваем счетчик размера `size` на единицу.

Реализация метода на C++17:

```cpp
void push_back(int value) {
    Node* newNode = new Node(value);
    
    if (isEmpty()) {
        head = newNode;
        tail = newNode;
    } else {
        newNode->prev = tail;
        tail->next = newNode;
        tail = newNode;
    }
    size++;
}
```

### 2. Реализация удаления из начала и конца двусвязного списка

Операции удаления элементов из списка требуют аккуратного обращения с динамической памятью. Необходимо не только переставить указатели, но и освободить память удаляемого узла с помощью оператора `delete`, чтобы избежать утечек памяти. Обе операции выполняются за время $O(1)$.

#### Удаление из начала: метод `pop_front()`

Если список пуст, операция удаления не должна выполнять никаких действий (или может возбуждать исключение, но в рамках нашей лабораторной работы мы ограничимся проверкой).

Рассмотрим пошаговый алгоритм:
1. Проверяем, пуст ли список (`isEmpty()`). Если да, завершаем выполнение метода.
2. Сохраняем указатель на текущую голову в буферную переменную: `Node* temp = head;`.
3. Проверяем, состоит ли список ровно из одного элемента (`head == tail`). Если в списке остался один элемент, то после его удаления список станет пустым: устанавливаем `head = nullptr` и `tail = nullptr`.
4. Если в списке больше одного элемента:
   - Новой головой становится следующий узел: `head = head->next`.
   - Указатель `prev` новой головы обнуляется, так как перед ней больше нет элементов: `head->prev = nullptr`.
5. Освобождаем память удаляемого узла: `delete temp;`.
6. Уменьшаем счетчик размера `size` на единицу.

Реализация метода на C++17:

```cpp
void pop_front() {
    if (isEmpty()) {
        return;
    }
    
    Node* temp = head;
    
    if (head == tail) {
        head = nullptr;
        tail = nullptr;
    } else {
        head = head->next;
        head->prev = nullptr;
    }
    
    delete temp;
    size--;
}
```

#### Удаление с конца: метод `pop_back()`

Использование указателя `tail` позволяет удалить элемент с конца списка за время $O(1)$, так как нам не нужно искать предпоследний узел путем обхода — указатель `tail->prev` уже указывает на него.

Рассмотрим пошаговый алгоритм:
1. Проверяем, пуст ли список. Если пуст, завершаем работу.
2. Сохраняем указатель на текущий хвост: `Node* temp = tail;`.
3. Проверяем, состоит ли список из одного элемента (`head == tail`). Если да, то после удаления список станет пустым: устанавливаем `head = nullptr` и `tail = nullptr`.
4. Если в списке больше одного элемента:
   - Новым хвостом становится предыдущий узел: `tail = tail->prev`.
   - Указатель `next` нового хвоста обнуляется: `tail->next = nullptr`.
5. Освобождаем память удаляемого узла: `delete temp;`.
6. Уменьшаем счетчик размера `size` на единицу.

Реализация метода на C++17:

```cpp
void pop_back() {
    if (isEmpty()) {
        return;
    }
    
    Node* temp = tail;
    
    if (head == tail) {
        head = nullptr;
        tail = nullptr;
    } else {
        tail = tail->prev;
        tail->next = nullptr;
    }
    
    delete temp;
    size--;
}
```

### 3. Двусторонний обход списка и очистка памяти

Главное структурное преимущество двусвязного списка перед односвязным — возможность перемещаться как от начала к концу, так и в обратном направлении.

#### Прямой и обратный обход

Для вывода элементов или их обработки в прямом порядке мы начинаем с `head` и движемся по указателям `next` до тех пор, пока не встретим `nullptr`. Для обратного порядка мы начинаем с `tail` и движемся по указателям `prev` до `nullptr`.

Реализация методов вывода на экран:

```cpp
#include <iostream>

// Метод вывода в прямом порядке (от головы к хвосту)
void printForward() const {
    Node* current = head;
    std::cout << "Forward: ";
    while (current != nullptr) {
        std::cout << current->data << " ";
        current = current->next;
    }
    std::cout << std::కుడు << std::endl; // Исправление вывода потока
}

// Метод вывода в обратном порядке (от хвоста к голове)
void printBackward() const {
    Node* current = tail;
    std::cout << "Backward: ";
    while (current != nullptr) {
        std::cout << current->data << " ";
        current = current->prev;
    }
    std::cout << std::endl;
}
```

*(Примечание: в стандартном потоке вывода используется `std::endl`).*

#### Очистка памяти и деструктор

При уничтожении объекта списка или при необходимости полностью сбросить его состояние мы должны последовательно удалить каждый узел из памяти кучи. Если этого не сделать, возникнет утечка памяти (*memory leak*).

Метод `clear()` удаляет все элементы, последовательно вызывая `pop_front()` или проходя по всем узлам с удалением через `delete`. Деструктор класса вызывает метод `clear()`.

Реализация методов:

```cpp
void clear() {
    while (!isEmpty()) {
        pop_front();
    }
}

~DoublyLinkedList() {
    clear();
}

bool isEmpty() const {
    return size == 0;
}

size_t getSize() const {
    return size;
}
```

### 4. Полный компилируемый код класса `DoublyLinkedList` и демонстрация

Ниже представлен полностью готовый к компиляции файл на языке C++17, объединяющий все рассмотренные компоненты, а также функцию `main`, решающую поставленную в учебном примере задачу.

```cpp
#include <iostream>

// Структура узла двусвязного списка
struct Node {
    int data;
    Node* next;
    Node* prev;

    // Конструктор узла
    Node(int val) : data(val), next(nullptr), prev(nullptr) {}
};

// Класс двусвязного списка
class DoublyLinkedList {
private:
    Node* head;
    Node* tail;
    size_t size;

public:
    // Конструктор по умолчанию
    DoublyLinkedList() : head(nullptr), tail(nullptr), size(0) {}

    // Деструктор для предотвращения утечек памяти
    ~DoublyLinkedList() {
        clear();
    }

    // Проверка на пустоту
    bool isEmpty() const {
        return size == 0;
    }

    // Получение текущего размера
    size_t getSize() const {
        return size;
    }

    // Вставка элемента в начало списка O(1)
    void push_front(int value) {
        Node* newNode = new Node(value);
        if (isEmpty()) {
            head = newNode;
            tail = newNode;
        } else {
            newNode->next = head;
            head->prev = newNode;
            head = newNode;
        }
        size++;
    }

    // Вставка элемента в конец списка O(1)
    void push_back(int value) {
        Node* newNode = new Node(value);
        if (isEmpty()) {
            head = newNode;
            tail = newNode;
        } else {
            newNode->prev = tail;
            tail->next = newNode;
            tail = newNode;
        }
        size++;
    }

    // Удаление элемента с начала списка O(1)
    void pop_front() {
        if (isEmpty()) {
            return;
        }
        Node* temp = head;
        if (head == tail) {
            head = nullptr;
            tail = nullptr;
        } else {
            head = head->next;
            head->prev = nullptr;
        }
        delete temp;
        size--;
    }

    // Удаление элемента с конца списка O(1)
    void pop_back() {
        if (isEmpty()) {
            return;
        }
        Node* temp = tail;
        if (head == tail) {
            head = nullptr;
            tail = nullptr;
        } else {
            tail = tail->prev;
            tail->next = nullptr;
        }
        delete temp;
        size--;
    }

    // Полная очистка списка
    void clear() {
        while (!isEmpty()) {
            pop_front();
        }
    }

    // Вывод элементов в прямом порядке (от head к tail)
    void printForward() const {
        Node* current = head;
        std::cout << "Прямой обход: ";
        while (current != nullptr) {
            std::cout << current->data << " ";
            current = current->next;
        }
        std::cout << std::endl;
    }

    // Вывод элементов в обратном порядке (от tail к head)
    void printBackward() const {
        Node* current = tail;
        std::cout << "Обратный обход: ";
        while (current != nullptr) {
            std::cout << current->data << " ";
            current = current->prev;
        }
        std::cout << std::endl;
    }
};

// Главная функция с демонстрацией требований задачи
int main() {
    // Создаем экземпляр двусвязного списка
    DoublyLinkedList list;

    // Шаг 1: Добавляем числа 5, 10, 15 в конец списка
    list.push_back(5);
    list.push_back(10);
    list.push_back(15);

    // Шаг 2: Удаляем один элемент с начала списка
    list.pop_front();

    // Шаг 3: Выводим список в прямом порядке
    list.printForward();

    // Шаг 4: Выводим список в обратном порядке
    list.printBackward();

    return 0;
}
```

#### Разбор хода выполнения и проверка примера

1. **Инициализация:** Создается пустой объект `list`, поля `head = nullptr`, `tail = nullptr`, `size = 0`.
2. **Вставка 5:** Список пуст. `head` и `tail` указывают на новый узел со значением `5`. `size = 1`.
3. **Вставка 10:** Список не пуст. Создается узел `10`. Его `prev` указывает на узел `5`. У узла `5` поле `next` указывает на узел `10`. `tail` переносится на узел `10`. `size = 2`.
4. **Вставка 15:** Создается узел `15`. Его `prev` указывает на узел `10`. У узла `10` поле `next` указывает на узел `15`. `tail` переносится на узел `15`. `size = 3`.
5. **Удаление с начала (`pop_front`):** Узел `5` удаляется. Головой становится узел `10`, его поле `head->prev` устанавливается в `nullptr`. `size = 2`. В списке остаются узлы `10` и `15`.
6. **Прямой обход:** Начинаем с `head` (узел `10`), переходим к `next` (узел `15`). Вывод: `10 15`.
7. **Обратный обход:** Начинаем с `tail` (узел `15`), переходим к `prev` (узел `10`). Вывод: `15 10`.

**Ввод программы:** Отсутствует (данные жестко заданы по условию задачи).


**Проверка правдоподобия:** После добавления трех элементов и удаления первого остались два элемента (`10` и `15`). Прямой порядок выводит их от начала к концу (`10`, затем `15`), а обратный — от конца к началу (`15`, затем `10`). Указатели `next` и `prev` задействованы корректно, утечек памяти не возникает, так как деструктор очищает оставшиеся узлы при выходе переменной `list` из области видимости в функции `main`.

## 6. Анализ сложности, тестирование и типичные ошибки реализации

### Сводная таблица временной сложности операций

При проектировании программ выбор правильной структуры данных основывается на анализе временной и пространственной сложности её операций. Ниже приведена сводная таблица асимптотической сложности основных операций для односвязного (`SinglyLinkedList`) и двусвязного (`DoublyLinkedList`) списков в нотации `Big-O`.

| Операция | Односвязный список (`SinglyLinkedList`) | Двусвязный список (`DoublyLinkedList`) | Обоснование |
| :--- | :---: | :---: | :--- |
| **Доступ по индексу** | $O(N)$ | $O(N)$ | Требуется последовательный обход узлов от головы до нужного индекса, так как нет прямого адресации в памяти. |
| **Вставка в начало (`push_front`)** | $O(1)$ | $O(1)$ | Пересоздание указателя головы за константное время независимо от размера списка. |
| **Вставка в конец (`push_back`)** | $O(N)$ | $O(1)$ | В односвязном списке нужно обойти все $N$ элементов до конца (если нет указателя на хвост); в двусвязном списке есть прямой указатель `tail`. |
| **Удаление из начала (`pop_front`)** | $O(1)$ | $O(1)$ | Перенос указателя `head` на следующий элемент и удаление старой головы. |
| **Удаление с конца (`pop_back`)** | $O(N)$ | $O(1)$ | В односвязном списке требуется найти предпоследний узел за $O(N)$; в двусвязном списке есть указатель `tail` и поле `prev`, позволяющее мгновенно перейти к предпоследнему узлу. |
| **Поиск по значению (`find`)** | $O(N)$ | $O(N)$ | В худшем случае элемент находится в самом конце или отсутствует вовсе, что требует проверки всех $N$ элементов. |

### Анализ пространственной сложности и накладных расходов

Пространственная сложность как односвязного, так и двусвязного списков в терминах количества хранимых элементов составляет $O(N)$, где $N$ — количество узлов в списке. Однако помимо полезных данных (`int data`), узлы списков содержат служебную информацию — указатели на соседние элементы.

Рассмотрим накладные расходы по памяти на 64-битном процессоре:
1. Стандартная переменная типа `int` занимает 4 байта.
2. Указатель на 64-битной архитектуре занимает 8 байт.
3. В структуре узла односвязного списка (`Node`) содержится одно поле данных (`int data` — 4 байта) и один указатель (`Node* next` — 8 байт). Из-за выравнивания памяти (memory alignment) компилятор добавляет 4 байта отступа (padding), в результате чего один узел занимает $4 + 4 \text{ (padding)} + 8 = 16$ байт.
4. В структуре узла двусвязного списка (`DoublyNode`) содержится поле данных (`int data` — 4 байта), указатель `next` (8 байт) и указатель `prev` (8 байт). Общий размер узла с учетом выравнивания составляет $4 + 4 \text{ (padding)} + 8 + 8 = 24$ байта.

Таким образом, накладные расходы на служебные указатели в односвязном списке составляют $75\%$ от размера полезных данных ($12$ байт служебных данных на $4$ байта полезных), а в двусвязном списке — $500\%$ ($20$ байт служебных данных на $4$ байта полезных). Это плата за гибкость динамической структуры в сравнении со статическими массивами, где накладные расходы на указатели отсутствуют полностью.

### Организация модульного тестирования и граничные случаи

Для проверки корректности написанных классов списков необходимо организовывать модульное тестирование, охватывающее все возможные состояния структуры данных. Особое внимание уделяется граничным случаям (edge cases), на которых чаще всего происходят аварийные завершения программ (segmentation fault).

> **Правило тестирования списков.** Для каждого метода класса списка необходимо проверить три базовых состояния:
> 1. **Пустой список** (`size == 0`, `head == nullptr`).
> 2. **Список из одного элемента** (`size == 1`, `head == tail`, `head->next == nullptr`).
> 3. **Список из двух и более элементов** (общее рабочее состояние).

Пример структуры тестовой функции для проверки метода `pop_front` на языке C++17:

```cpp
#include <iostream>
#include <cassert>

struct Node {
    int data;
    Node* next;
    Node(int val) : data(val), next(nullptr) {}
};

class SinglyLinkedList {
private:
    Node* head;
    size_t size;
public:
    SinglyLinkedList() : head(nullptr), size(0) {}
    
    void push_front(int val) {
        Node* newNode = new Node(val);
        newNode->next = head;
        head = newNode;
        size++;
    }
    
    void pop_front() {
        if (head == nullptr) return;
        Node* temp = head;
        head = head->next;
        delete temp;
        size--;
    }
    
    size_t getSize() const { return size; }
    Node* getHead() const { return head; }
    
    ~SinglyLinkedList() {
        while (head != nullptr) {
            pop_front();
        }
    }
};

void testPopFront() {
    // Тест 1: Удаление из пустого списка (не должно приводить к падению)
    SinglyLinkedList list1;
    list1.pop_front();
    assert(list1.getSize() == 0);
    assert(list1.getHead() == nullptr);

    // Тест 2: Удаление единственного элемента
    SinglyLinkedList list2;
    list2.push_front(10);
    list2.pop_front();
    assert(list2.getSize() == 0);
    assert(list2.getHead() == nullptr);

    // Тест 3: Удаление из списка с несколькими элементами
    SinglyLinkedList list3;
    list3.push_front(20);
    list3.push_front(10);
    list3.pop_front();
    assert(list3.getSize() == 1);
    assert(list3.getHead()->data == 20);

    std::cout << "Все тесты метода pop_front успешно пройдены!" << std::endl;
}

int main() {
    testPopFront();
    return 0;
}
```

### Диагностика утечек памяти

Динамическое выделение памяти с помощью оператора `new` требует обязательного освобождения через оператор `delete` для каждого созданного узла. Если память не освобождена при уничтожении списка или удалении элементов, возникает утечка памяти (memory leak).

Для диагностики утечек памяти используются следующие инструменты:
1. **Valgrind** (в операционных системах Linux): утилита запускает программу в изолированной виртуальной среде и отслеживает все вызовы выделения и освобождения памяти.
   Команда для запуска:
   ```bash
   g++ -std=c++17 -g main.cpp -o program
   valgrind --leak-check=full ./program
   ```
   Если в выводе утилиты присутствует строка `All heap blocks were freed -- no leaks are possible`, утечек памяти нет. Если обнаружены потерянные байты (`definitely lost`), Valgrind указывает номер строки в исходном коде, где память была выделена, но не освобождена.
2. **Адресный санитайзер (AddressSanitizer)**: встроенный в компиляторы GCC и Clang инструмент. Включается добавлением флагов компиляции `-fsanitize=address -g`. При наличии утечек или выходе за границы памяти программа аварийно завершится при запуске с подробным отчетом об ошибке.

### Типичные ошибки реализации

При самостоятельной реализации списков студенты чаще всего допускают четыре группы критических ошибок.

#### Ошибка 1: Потеря ссылки на остаток списка при вставке или удалении узла
Возникает, когда новое значение записывается в указатель `next` раньше, чем сохраняется ссылка на следующий элемент списка. В результате цепочка узлов, идущая за текущим элементом, безвозвратно теряется в памяти, что приводит к утечке памяти и нарушению структуры списка.

#### Ошибка 2: Разыменование нулевого указателя (nullptr dereference)
Происходит, когда программа пытается обратиться к полям `data`, `next` или `prev` объекта, на который указывает `nullptr` (например, попытка вызвать `head->data` у пустого списка). Это приводит к мгновенному аварийному завершению программы с сигналом `Segmentation fault`. Всегда проверяйте указатели на равенство `nullptr` перед их разыменованием.

#### Ошибка 3: Забытое обновление указателя tail
В двусвязном списке при добавлении или удалении элементов (особенно единственного элемента списка) необходимо синхронно обновлять оба указателя — и `head`, и `tail`. Если удалить последний элемент списка, но оставить указатель `tail` ссылающимся на удаленный узел (ставший `dangling pointer`), последующие операции вставки в конец приведут к повреждению памяти.

#### Ошибка 4: Удаление узла без предварительного сохранения ссылки
При удалении узла из односвязного списка программист часто вызывает оператор `delete current;`, забывая, что после этого он потерял доступ к полю `current->next`. Удаление узла должно производиться строго после переброски всех необходимых указателей.

#### Пример: Анализ и исправление функции удаления элемента из односвязного списка

**Условие:**
Ниже представлен фрагмент кода метода класса `SinglyLinkedList`, предназначенный для удаления первого узла со значением, равным заданному `target`. Проанализируйте код, укажите причину падения программы или логической ошибки и напишите исправленный вариант.

```cpp

```

**Ход рассуждений (почему код содержит ошибку):**
1. Внимательно проанализируем строки удаления узла в цикле:
   ```cpp
   Node* nodeToDelete = current->next;
   delete nodeToDelete;
   current->next = nodeToDelete->next;
   ```
2. Первое действие: мы сохраняем указатель на удаляемый узел в переменную `nodeToDelete`.
3. Второе действие: мы вызываем `delete nodeToDelete;`. В этот момент оператор `delete` освобождает память, выделенную под этот узел, возвращая её операционной системе. Объект в памяти больше не принадлежит нашей программе.
4. Третье действие: мы обращаемся к полю `nodeToDelete->next` (через выражение `nodeToDelete->next`), чтобы переприсвоить указатель `current->next = nodeToDelete->next;`.
5. **Вывод:** Происходит обращение к памяти сразу после её освобождения (*use-after-free*). Значение поля `nodeToDelete->next` может быть перезаписано кучей, либо программа завершится с `Segmentation fault`. Сначала необходимо перебросить указатель `current->next`, и только затем удалять узел.

Поменяем местами строки переприсвоения указателя и физического удаления памяти:

    // Особый случай: удаляемый элемент находится в голове списка
    if (head->data == target) {
        Node* temp = head;
        head = head->next;
        delete temp;
        size--;
        return;
    }

    while (current->next != nullptr) {
        if (current->next->data == target) {
            Node* nodeToDelete = current->next;

            current->next = nodeToDelete->next;
            
            // Только после этого безопасно освобождаем память
            delete nodeToDelete;
            size--;
            return;

        current = current->next;

}

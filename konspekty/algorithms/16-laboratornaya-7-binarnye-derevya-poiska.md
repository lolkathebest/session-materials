## 1. Теоретические основы и структура бинарного дерева поиска

### 1. Теоретические основы и структура бинарного дерева поиска

Изучение нелинейных структур данных мы начнем с деревьев — фундаментального понятия в компьютерных науках. Если линейные структуры (массивы, списки, стеки, очереди) упорядочивают элементы последовательно, то деревья позволяют моделировать иерархические связи «родитель — потомки». 

Прежде чем перейти к конкретным алгоритмам поиска и вставки, нам необходимо строго определить базовые понятия теории графов и структур данных, которые будут использоваться на протяжении всего курса.

> **Определение.** **Бинарное дерево** (binary tree) — это иерархическая структура данных, состоящая из конечного множества узлов. Это множество либо пусто, либо состоит из специального выделенного узла, называемого **корнем** (root), и двух непересекающихся бинарных деревьев, которые называются **левым поддеревом** (left subtree) и **правым поддеревом** (right subtree).

Каждый узел бинарного дерева содержит полезные данные (ключ или значение) и ссылки (указатели) на своих непосредственных потомков. 

Для формализации терминологии введем следующие определения:
- **Узел** (node) — базовый элемент дерева, содержащий данные и указатели на дочерние узлы.
- **Корень** (root) — единственный узел дерева, у которого нет родителей. Все остальные узлы достижимы из корня путем последовательного перехода по указателям.
- **Лист** (leaf) — узел, который не имеет потомков (оба его указателя на потомков равны `nullptr`).
- **Родитель** (parent) — узел, непосредственно ссылающийся на данный узел.
- **Потомок** (child) — узел, на который ссылается родительский узел. Узлы в бинарном дереве делятся на левого и правого потомка.
- **Предки** (ancestors) — все узлы на пути от корня до данного узла (не включая сам узел).
- **Потомки** (descendants) — все узлы, находящиеся в поддереве данного узла.
- **Глубина узла** (depth) — длина пути (количество рёбер) от корня дерева до данного узла. Глубина корня равна $0$.
- **Высота узла** (height of a node) — максимальная длина пути от данного узла до какого-либо листа в его поддереве. Высота листа равна $0$. **Высота дерева** определяется как высота его корня.
- **Уровень дерева** (level) — множество всех узлов, находящихся на одинаковой глубине. Уровень корня равен $0$.

### Инвариант бинарного дерева поиска (BST)

Простое бинарное дерево накладывает ограничение только на максимальное число потомков у каждого узла (не более двух). Однако само по себе оно не ускоряет поиск данных. Чтобы поиск выполнялся эффективно, на структуру накладывают дополнительное упорядочение.

> **Определение.** **Бинарное дерево поиска** (Binary Search Tree, BST) — это бинарное дерево, для каждого узла $x$ которого выполняются следующие условия, называемые **инвариантом BST**:
> 1. Все ключи в левом поддереве узла $x$ строго меньше ключа самого узла $x$.
> 2. Все ключи в правом поддереве узла $x$ строго больше ключа самого узла $x$.
> 3. Левое и правое поддеревья также являются бинарными деревьями поиска.

Математически это записывается так: для любого узла $x$:
$$\forall y \in \text{LeftSubtree}(x) : \text{key}(y) < \text{key}(x)$$
$$\forall z \in \text{RightSubtree}(x) : \text{key}(z) > \text{key}(x)$$

Важное следствие инварианта BST заключается в том, что все ключи в дереве уникальны (если иное явно не оговорено правилами обработки дубликатов). Благодаря этому инварианту при поиске элемента мы на каждом шаге можем отбрасывать ровно половину поддерева, сравнивая искомый ключ с ключом текущего узла. Это аналогично алгоритму двоичного поиска в отсортированном массиве, но реализовано в виде динамической иерархической структуры.

### Представление узла дерева в C++

В языке C++17 бинарное дерево поиска реализуется с помощью динамических структур данных и указателей. Каждый узел представляется как экземпляр структуры `struct`, содержащий поле данных и два указателя: на левого и правого потомка.

Рассмотрим определение структуры узла `Node` для хранения целых чисел (`int`):

```cpp
struct Node {
    int key;          // Ключ, по которому строится порядок в BST
    Node* left;       // Указатель на левого потомка (меньшие значения)
    Node* right;      // Указатель на правого потомка (большие значения)

    // Конструктор для удобного создания узла
    Node(int val) : key(val), left(nullptr), right(nullptr) {}
};
```

Разберем поля структуры:
- `key` хранит значение, по которому происходит упорядочивание.
- `left` хранит адрес памяти (указатель типа `Node*`) на корневой узел левого поддерева. Если левого потомка нет, указатель равен `nullptr`.
- `right` хранит адрес памяти на корневой узел правого поддерева. Если правого потомка нет, указатель равен `nullptr`.
- Конструктор `Node(int val)` инициализирует поле `key` переданным значением, а указатели `left` и `right` устанавливает в `nullptr`, что предотвращает появление «висячих» указателей при создании нового узла.

### Сравнение BST с полными и сбалансированными деревьями

Начинающие разработчики часто путают бинарное дерево поиска с другими видами деревьев. Важно четко понимать разницу между ними.

Таблица ниже иллюстрирует ключевые отличия между общим бинарным деревом, бинарным деревом поиска, полным бинарным деревом и сбалансированным деревом.

| Характеристика | Произвольное бинарное дерево | Бинарное дерево поиска (BST) | Полное бинарное дерево (Complete) | Сбалансированное дерево (например, AVL) |
|---|---|---|---|---|
| **Главное правило** | У каждого узла не более 2 потомков | Левый потомок меньше, правый больше | Все уровни, кроме последнего, заполнены полностью; последний заполнен слева направо | Высота левого и правого поддеревьев каждого узла различается не более чем на 1 |
| **Упорядочение элементов** | Отсутствует | Строгое (инвариант BST) | Не обязательно | Строгое (инвариант BST + балансировка) |
| **Основное назначение** | Иерархические связи общего вида | Быстрый поиск, вставка и удаление | Эффективное хранение в массиве (кучи) | Гарантия быстрого поиска в худшем случае |
| **Сложность поиска (худший случай)** | $O(n)$ | $O(n)$ (при вырождении) | $O(n)$ | $O(\log n)$ |
| **Сложность поиска (средний случай)**| $O(n)$ | $O(\log n)$ | $O(\log n)$ | $O(\log n)$ |

Из таблицы видно, что само по себе свойство BST не гарантирует высокую скорость работы. Если ключи поступают в дерево в уже отсортированном порядке, структура вырождается.

### Вырождение BST в односвязный список

Рассмотрим худший случай работы с бинарным деревом поиска. Пусть мы вставляем в изначально пустое дерево ключи в возрастающем порядке: $10, 20, 30, 40, 50$.

1. Вставляем $10$: становится корнем.
2. Вставляем $20$: так как $20 > 10$, оно идет в правое поддерево узла $10$.
3. Вставляем $30$: $30 > 10$ (идем направо), $30 > 20$ (идем направо), становится правым потомком узла $20$.
4. И так далее.

В результате получается структура, в которой каждый узел имеет ровно одного потомка — правого. Левые поддеревья у всех узлов пусты. 

```
[10]
  \
  [20]
    \
    [30]
      \
      [40]
        \
        [50]
```

Эта структура топологически эквивалентна **односвязному списку**. Высота такого дерева становится равной количеству узлов минус один ($h = n - 1$). В таком состоянии все операции (поиск, вставка, удаление) требуют просмотра каждого узла, что приводит к временной сложности $O(n)$, сводя на нет все преимущества бинарного дерева поиска. Борьба с таким вырождением приводит к использованию самобалансирующихся деревьев (таких как AVL-деревья или красно-черные деревья), которые изучаются в последующих разделах курса.

#### 2. Пошаговое построение дерева по ключам
Давайте проследим, как ключи `15, 10, 20, 8, 12, 17, 25` размещаются в дереве в соответствии с инвариантом BST:

1. **Ключ `15`**: Дерево пустое. Ключ становится **корнем** дерева.
   - Текущее дерево: `15`
2. **Ключ `10`**: Сравниваем с корнем (`15`). Так как $10 < 15$, идем в левое поддерево. Левый потомок корня пуст, поэтому создаем новый узел с ключом `10` как левого потомка узла `15`.
3. **Ключ `20`**: Сравниваем с корнем (`15`). Так как $20 > 15$, идем в правое поддерево. Правый потомок пуст, создаем узел с ключом `20` как правого потомка узла `15`.
4. **Ключ `8`**: Сравниваем с корнем (`15`) $\to 8 < 15$ (идем налево). Сравниваем с узлом `10` $\to 8 < 10$ (идем налево). Левый потомок узла `10` пуст. Создаем узел с ключом `8`.
5. **Ключ `12`**: Сравниваем с `15` $\to 12 < 15$ (налево). Сравниваем с `10` $\to 12 > 10$ (направо). Правый потомок узла `10` пуст. Создаем узел с ключом `12`.
6. **Ключ `17`**: Сравниваем с `15` $\to 17 > 15$ (направо). Сравниваем с `20` $\to 17 < 20$ (налево). Левый потомок узла `20` пуст. Создаем узел с ключом `17`.
7. **Ключ `25`**: Сравниваем с `15` $\to 25 > 15$ (направо). Сравниваем с `20` $\to 25 > 20$ (направо). Правый потомок узла `20` пуст. Создаем узел с ключом `25`.

Ниже представлена графическая схема получившегося бинарного дерева поиска. Корневой узел находится вверху, стрелки показывают связи родитель-потомок (левые потомки располагаются слева-внизу, правые — справа-внизу).

```
         [15] (корень, уровень 0)
        /    \
     [10]    [20] (уровень 1)
     /  \    /  <span>\</span>
   [8] [12] [17] [25] (уровень 2, листья)
```

Проверим выполнение инварианта BST для каждого узла:
- Для корня `15`: в левом поддереве лежат ключи `{8, 10, 12}`, все они меньше `15`. В правом поддереве лежат ключи `{17, 20, 25}`, все они больше `15`. Инвариант выполнен.
- Для узла `10`: слева `8` ($8 < 10$), справа `12` ($12 > 10$). Инвариант выполнен.
- Для узла `20`: слева `17` ($17 < 20$), справа `25` ($25 > 20$). Инвариант выполнен.
- Узлы `8`, `12`, `17`, `25` являются листьями (не имеют потомков), для них инвариант выполняется тривиально.

Высота полученного дерева равна $2$ (путь от корня `15` до листа `8` содержит 2 ребра: $15 \to 10 \to 8$). Дерево является сбалансированным, что обеспечит логарифмическую сложность поиска в нем.

## 2. Операции поиска и вставки элементов

### Алгоритм поиска ключа в BST

Поиск ключа в бинарном дереве поиска (BST) использует свойство его инварианта: для любого узла все ключи в его левом поддереве строго меньше ключа этого узла, а все ключи в правом поддереве — строго больше. Это позволяет на каждом шаге алгоритма отсекать ровно половину потенциальных вариантов (в случае сбалансированного дерева), что принципиально отличает дерево от неупорядоченного связного списка.

Алгоритм поиска заданного значения $target$ начинает работу с корня дерева и выполняется по следующей схеме:
1. Проверяется указатель на текущий узел. Если он равен `nullptr`, значит, дерево пусто или искомый элемент отсутствует в дереве. Возвращается неуспешный результат (например, `nullptr` или `false`).
2. Значение в текущем узле (`node->data`) сравнивается с искомым значением ($target$):
   - Если $target == node->data$, искомый элемент найден. Возвращается указатель на текущий узел.
   - Если $target < node->data$, искомое значение, согласно инварианту BST, может находиться только в левом поддереве. Алгоритм переходит к левому потомку текущего узла (`node = node->left`).
   - Если $target > node->data$, искомое значение может находиться только в правом поддереве. Алгоритм переходит к правому потомку текущего узла (`node = node->right`).
3. Шаг 2 повторяется до тех пор, пока элемент не будет найден или пока указатель не станет равным `nullptr`.

> **Определение.** Рекурсивный поиск — это подход, при котором функция вызывает сама себя для поддерева меньшего размера, используя стек вызовов для возврата результата. Итеративный поиск — это подход с использованием цикла (`while`), где указатель на текущий узел переприсваивается в теле цикла без использования стека вызовов.

Ниже приведена полная реализация рекурсивного и итеративного поиска на языке C++17. Предполагается, что структура узла `Node` объявлена следующим образом:
```cpp
struct Node {
    int data;
    Node* left;
    Node* right;
    
    // Конструктор для удобного создания узла
    Node(int val) : data(val), left(nullptr), right(nullptr) {}
};
```

Рекурсивная реализация функции поиска:
```cpp
Node* searchRecursive(Node* root, int target) {
    // Базовый случай 1: дерево пусто или элемент не найден
    if (root == nullptr) {
        return nullptr;
    }
    // Базовый случай 2: элемент найден в текущем узле
    if (root->data == target) {
        return root;
    }
    // Рекурсивный переход в левое поддерево, если искомое меньше текущего
    if (target < root->data) {
        return searchRecursive(root->left, target);
    }
    // Рекурсивный переход в правое поддерево, если искомое больше текущего
    return searchRecursive(root->right, target);
}
```

Итеративная реализация функции поиска:
```cpp
Node* searchIterative(Node* root, int target) {
    Node* current = root;
    
    // Пока не дошли до конца дерева
    while (current != nullptr) {
        if (current->data == target) {
            return current; // Элемент найден
        }
        if (target < current->data) {
            current = current->left; // Переход влево
        } else {
            current = current->right; // Переход вправо
        }
    }
    
    return nullptr; // Элемент не найден
}
```

### Алгоритм вставки ключа в BST

Вставка нового ключа в бинарное дерево поиска логически опирается на алгоритм поиска. Главная задача при вставке — найти свободное место (указатель `nullptr`), куда должен быть помещен новый узел, так, чтобы после его добавления не нарушился инвариант BST.

Алгоритм вставки нового значения $val$:
1. Если дерево пусто (корень равен `nullptr`), создается новый узел с данным значением, который становится корнем дерева.
2. Если дерево не пусто, запускается процесс поиска позиции, аналогичный поиску, но с отслеживанием родительского узла или с использованием ссылок на указатели.
3. На каждом шаге значение $val$ сравнивается со значением в текущем узле:
   - Если $val < node->data$, алгоритм идет в левое поддерево. Если левый потомок равен `nullptr`, на это место создается и подвешивается новый узел. В противном случае происходит спуск дальше.
   - Если $val > node->data$, алгоритм идет в правое поддерево. Если правый потомок равен `nullptr`, создается и подвешивается новый узел. В противном случае происходит спуск дальше.
   - Если $val == node->data$, возникает ситуация дубликата.

> **Правило.** Политика обработки дубликатов ключей определяет поведение структуры данных при попытке вставки значения, которое уже присутствует в дереве. Возможны два основных подхода: 
> 1. Игнорирование вставки (дерево хранит только уникальные ключи).
> 2. Добавление дубликата в правое поддерево (соглашение о том, что условие правого поддерева звучит как «больше или равно»).
> В рамках нашего курса мы используем политику игнорирования дубликатов, если иное не оговорено в задаче.

Обоснование корректности сохранения инварианта при вставке основывается на индуктивном подходе. Новый узел всегда добавляется строго на место листа (вместо `nullptr`). Поскольку путь к этому месту выбирался путем последовательного сравнения со всеми родительскими узлами (при $val < parent$ мы шли налево, при $val > parent$ — направо), новый узел гарантированно удовлетворяет условию неравенства со всеми предками на этом пути. Следовательно, инвариант BST для всего дерева сохраняется.

Рекурсивная реализация вставки с использованием передачи указателя по ссылке (`Node*&`) в C++17 позволяет элегантно изменять указатели родительских узлов без ручного отслеживания родителя:

```cpp
void insert(Node*& root, int val) {
    // Если дошли до пустого места, создаем новый узел
    if (root == nullptr) {
        root = new Node(val);
        return;
    }
    
    // Если значение меньше текущего, идем в левое поддерево
    if (val < root->data) {
        insert(root->left, val);
    }
    // Если значение больше текущего, идем в правое поддерево
    else if (val > root->data) {
        insert(root->right, val);
    }
    // Если val == root->data, дубликат игнорируется
}
```

### Анализ худшего и среднего случаев для времени выполнения

Временная сложность операций поиска и вставки в бинарном дереве поиска напрямую зависит от формы дерева, а именно — от его высоты $h$. Высота дерева определяется как максимальный путь от корня до листа (в узлах или ребрах).

1. **Худший случай ($O(n)$):**
   Если ключи вставляются в дерево в уже отсортированном порядке (например, $1, 2, 3, 4, 5$), каждый новый элемент будет добавляться в правое поддерево предыдущего. Дерево вырождается в односвязный список (цепь узлов, направленную вправо или влево). В таком вырожденном дереве высота $h = n$, где $n$ — общее число узлов. Для поиска или вставки элемента в худшем случае алгоритм вынужден обойти все $n$ узлов. Временная сложность составляет $O(n)$.

2. **Средний случай ($O(\log n)$):**
   Если ключи поступают в случайном порядке, дерево растет равномерно и имеет форму, близкую к сбалансированной. Высота такого дерева составляет $h = \log_2 n$. На каждом шаге алгоритм поиска или вставки отбрасывает половину оставшихся элементов. Количество шагов равно высоте дерева, то есть $\log_2 n$. Временная сложность в среднем случае составляет $O(\log n)$.

Пространственная сложность:
- Для итеративного поиска пространственная сложность составляет $O(1)$, так как используется фиксированное число переменных-указателей.
- Для рекурсивных операций (поиск и вставка) пространственная сложность определяется максимальной глубиной рекурсии (стеком вызовов процессора). В худшем случае она равна $O(n)$, в среднем — $O(\log n)$.

Проследить пошагово процесс вставки ключа 13 в изначально пустое бинарное дерево поиска, а затем последовательно ключей: $10, 5, 15, 12, 7, 13$. Записать состояние дерева после каждой вставки. Показать структуру дерева с помощью текстовой схемы.

**Ход рассуждений:**
1. Изначально дерево пусто. Указатель на корень равен `nullptr`.
2. Вставляем ключ $10$. Дерево пусто, поэтому $10$ становится корнем.
3. Вставляем ключ $5$. Сравниваем $5$ с корнем ($10$). Так как $5 < 10$ и у корня нет левого потомка, $5$ становится левым ребенком узла $10$.
4. Вставляем ключ $15$. Сравниваем $15$ с корнем ($10$). Так как $15 > 10$ и у корня нет правого потомка, $15$ становится правым ребенком узла $10$.
5. Вставляем ключ $12$. Сравниваем с корнем ($10$): $12 > 10$, идем вправо к узлу $15$. Сравниваем с узлом $15$: $12 < 15$, у узла $15$ нет левого потомка. $12$ становится левым ребенком узла $15$.
6. Вставляем ключ $7$. Сравниваем с корнем ($10$): $7 < 10$, идем влево к узлу $5$. Сравниваем с узлом $5$: $7 > 5$, у узла $5$ нет правого потомка. $7$ становится правым ребенком узла $5$.
7. Вставляем ключ $13$. Сравниваем с корнем ($10$): $13 > 10$, идем вправо к узлу $15$. Сравниваем с узлом $15$: $13 < 15$, идем влево к узлу $12$. Сравниваем с узлом $12$: $13 > 12$, у узла $12$ нет правого потомка. $13$ становится правым ребенком узла $12$.

Шаг 1. Вставка 10 (дерево пусто):

```
  10
```

Шаг 2. Вставка 5 ($5 < 10$):

```
   /
```

Шаг 3. Вставка 15 ($15 > 10$):

## 3. Обходы бинарного дерева поиска

### 1. Классификация обходов дерева: в глубину и в ширину

После того как бинарное дерево поиска сформировано, возникает фундаментальная задача: как обойти все его узлы, чтобы прочитать, обработать или вывести хранящиеся в них данные. В линейных структурах данных, таких как массивы или связные списки, порядок обхода очевиден — от первого элемента к последнему (слева направо или наоборот). В иерархических структурах, какими являются деревья, у каждого узла может быть несколько потомков, поэтому существует множество различных стратегий обхода.

Все стратегии обхода деревьев делятся на два больших класса:
1. **Обход в глубину (Depth-First Search, DFS)**. Стратегия заключается в том, чтобы продвигаться как можно глубже по одному из ветвлений дерева, прежде чем вернуться назад и исследовать другие ветви. Обходы в глубину естественным образом реализуются с помощью рекурсии (при этом используется системный стек вызовов) или с помощью явного стека.
2. **Обход в ширину (Breadth-First Search, BFS)**, который в контексте деревьев часто называют обходом по уровням (**Level-order**). Стратегия заключается в том, чтобы обойти дерево по слоям: сначала посещается корень, затем все узлы на расстоянии $1$ от корня (дети корня), затем все узлы на расстоянии $2$ и так далее сверху вниз, слева направо. Для реализации такого обхода используется структура данных «очередь» (FIFO).

Рассмотрим подробнее каждый из видов обходов в глубину, так как они играют ключевую роль при работе с бинарными деревьями поиска.

---

### 2. Обходы в глубину (DFS): Pre-order, In-order и Post-order

Обходы в глубину для бинарного дерева всегда выполняются рекурсивно, основываясь на посещении трех компонентов:
- **N** (Node) — обработка текущего узла (например, вывод его значения);
- **L** (Left) — рекурсивный обход левого поддерева;
- **R** (Right) — рекурсивный обход правого поддерева.

В зависимости от порядка посещения этих компонентов выделяют три основных вида обхода в глубину. Название каждого обхода указывает на то, когда именно обрабатывается сам узел (**N**):
- **Pre-order** (прямой обход): сначала **N**, затем **L**, затем **R** ($N \to L \to R$).
- **In-order** (центрированный обход): сначала **L**, затем **N**, затем **R** ($L \to N \to R$).
- **Post-order** (обратный обход): сначала **L**, затем **R**, затем **N** ($L \to R \to N$).

#### Прямой обход (Pre-order: корень, левое, правое)

> **Определение.** Прямой обход (Pre-order traversal) — это стратегия обхода дерева, при которой на каждом шаге рекурсии сначала обрабатывается текущий узел, затем полностью рекурсивно обходится его левое поддерево, и в конце рекурсивно обходится его правое поддерево.

**Алгоритм Pre-order обхода:**
1. Если текущий указатель на узел равен `nullptr`, завершить работу шага (базовый случай рекурсии).
2. Обработать текущий узел (например, вывести его ключ `node->data`).
3. Вызвать рекурсивно Pre-order обход для левого поддерева (`node->left`).
4. Вызвать рекурсивно Pre-order обход для правого поддерева (`node->right`).

**Где применяется:** Pre-order обход активно используется для создания точной копии (клонирования) существующего дерева. Если мы будем вставлять узлы в новое дерево в том же порядке, в котором они выдаются Pre-order обходом, мы получим структурно идентичное дерево. Также этот обход применяется для сериализации дерева — записи его структуры в текстовый файл или поток с целью последующего восстановления.

#### Центрированный обход (In-order: левое, корень, правое)

> **Определение.** Центрированный обход (In-order traversal) — это стратегия обхода дерева, при которой сначала рекурсивно обходится левое поддерево, затем обрабатывается текущий узел, и в конце рекурсивно обходится правое поддерево.

**Алгоритм In-order обхода:**
1. Если текущий указатель на узел равен `nullptr`, завершить работу шага.
2. Вызвать рекурсивно In-order обход для левого поддерева (`node->left`).
3. Обработать текущий узел (`node->data`).
4. Вызвать рекурсивно In-order обход для правого поддерева (`node->right`).

**Свойство:** Благодаря инварианту бинарного дерева поиска (все ключи в левом поддереве меньше ключа корня, а в правом — больше), In-order обход **всегда выводит элементы BST в отсортированном по неубыванию порядке**. Это фундаментальное свойство позволяет использовать BST для сортировки данных или эффективного поиска элементов в заданном диапазоне.

#### Обратный обход (Post-order: левое, правое, корень)

> **Определение.** Обратный обход (Post-order traversal) — это стратегия обхода дерева, при которой сначала рекурсивно обходятся левое и правое поддеревья, и только после этого обрабатывается текущий узел.

**Алгоритм Post-order обхода:**
1. Если текущий указатель на узел равен `nullptr`, завершить работу шага.
2. Вызвать рекурсивно Post-order обход для левого поддерева (`node->left`).
3. Вызвать рекурсивно Post-order обход для правого поддерева (`node->right`).
4. Обработать текущий узел (`node->data`).

**Где применяется:** Post-order обход незаменим при необходимости безопасного удаления дерева и освобождения динамической памяти. Поскольку память из-под узла нельзя освобождать до тех пор, пока не будут удалены все его потомки, Post-order гарантирует, что дети будут уничтожены раньше родителя. Такой же порядок вычислений используется при разборе арифметических выражений, представленных в виде дерева (дерево разбора выражений).

---

### 3. Обход в ширину (Level-order) с использованием очереди

Обход в ширину кардинально отличается от обходов в глубину тем, что исследует дерево по горизонтальным уровням, а не по вертикальным ветвям. Поскольку стандартная рекурсия идет вглубь, для реализации обхода в ширину рекурсия напрямую не подходит. Вместо этого используется вспомогательная структура данных — очередь (Queue), работающая по принципу FIFO (First In, First Out — первым вошел, первым вышел).

> **Определение.** Обход в ширину (Level-order traversal) — это алгоритм поуровневого обхода дерева, при котором узлы посещаются слева направо на каждом уровне, начиная с нулевого уровня (корня) и двигаясь вниз к листьям.

**Алгоритм Level-order обхода:**
1. Если корень дерева равен `nullptr`, дерево пусто, завершить алгоритм.
2. Создать пустую очередь указателей на узлы дерева (`std::queue<Node*> q`).
3. Поместить корень дерева в очередь: `q.push(root)`.
4. Пока очередь не пуста (`while (!q.empty())`):
   - Извлечь из начала очереди текущий узел: `Node* current = q.front(); q.pop();`.
   - Обработать текущий узел (например, вывести `current->data`).
   - Если у текущего узла есть левый потомок (`current->left != nullptr`), добавить его в очередь: `q.push(current->left);`.
   - Если у текущего узла есть правый потомок (`current->right != nullptr`), добавить его в очередь: `q.push(current->right);`.

Благодаря использованию очереди узлы добавляются в том порядке, в котором они располагаются на уровнях, что гарантирует правильный поуровневый обход.

### 4. Разбор примера обходов дерева

Рассмотрим конкретное дерево поиска и выполним для него все три вида обходов в глубину.

**Условие:**
Задано бинарное дерево поиска со следующими узлами:
- Корень: $10$
- Левый потомок узла $10$: $5$
- Правый потомок узла $10$: $15$
- Левый потомок узла $5$: $3$
- Правый потомок узла $5$: $7$

**Рисунок дерева (словесное описание и ASCII-схема):**
Корень дерева содержит число $10$. Его левый ребенок — $5$, правый — $15$. У узла $5$ есть два собственных ребенка: левый равен $3$, правый равен $7$. У правого узла $15$ потомков нет.

```
       ( 10 )
      /      \
   ( 5 )    ( 15 )
  /     \
( 3 )   ( 7 )
```

#### Пошаговое построение обходов:

**1. In-order обход ($L \to N \to R$):**
- Начинаем с корня $10$, но по правилу идем в его левое поддерево с корнем в $5$.
- В поддереве узла $5$ снова идем в его левое поддерево с корнем в $3$.
- У узла $3$ нет левого поддерева. Обрабатываем узел $3$. Правого поддерева у него тоже нет. Возвращаемся к узлу $5$.
- Обрабатываем узел $5$ (корень текущего поддерева).
- Переходим к правому поддереву узла $5$ — это узел $7$.
- У узла $7$ нет левого потомка. Обрабатываем узел $7$. Нет правого потомка. Возвращаемся к корню $10$.
- Обрабатываем корень $10$.
- Переходим к правому поддереву узла $10$ — это узел $15$.
- У узла $15$ нет левого потомка. Обрабатываем узел $15$. Нет правого потомка.
- **Результат In-order обхода:** `3 5 7 10 15`. (Заметим, что элементы строго отсортированы).

**2. Pre-order обход ($N \to L \to R$):**
- Начинаем с корня. Сразу обрабатываем узел $10$.
- Идем в левое поддерево и обрабатываем корень этого поддерева — узел $5$.
- Идем в левое поддерево узла $5$ и обрабатываем узел $3$. У него нет детей.
- Возвращаемся к узлу $5$, его левый ребенок уже пройден, переходим к правому ребенку — узлу $7$. Обрабатываем узел $7$.
- Возвращаемся к главному корню $10$. Его левое поддерево полностью пройдено. Переходим к правому поддереву — узлу $15$. Обрабатываем узел $15$.
- **Результат Pre-order обхода:** `10 5 3 7 15`.

**3. Post-order обход ($L \to R \to N$):**
- Начинаем с корня $10$, спускаемся в левое поддерево в узел $5$, оттуда в его левое поддерево в узел $3$.
- У узла $3$ нет потомков. Обрабатываем узел $3$.
- Возвращаемся к узлу $5$, переходим к его правому потомку — узлу $7$. У него нет потомков. Обрабатываем узел $7$.
- Теперь у узла $5$ пройдены оба ребенка ($3$ и $7$). Обрабатываем сам узел $5$.
- Возвращаемся к главному корню $10$. Переходим к его правому потомку — узлу $15$. У него нет детей. Обрабатываем узел $15$.
- Теперь у главного корня $10$ пройдены и левое поддерево, и правый потомок. Обрабатываем корень $10$.
- **Результат Post-order обхода:** `3 7 5 15 10`.

### 5. Программная реализация обходов на C++17

Ниже представлена полная, компилируемая программа на языке C++17, которая реализует описанное выше бинарное дерево поиска, заполняет его узлами из разобранного примера и выполняет все четыре вида обходов (In-order, Pre-order, Post-order и Level-order), выводя результаты в стандартный поток вывода.

```cpp
#include <iostream>
#include <queue>

// Структура, представляющая узел бинарного дерева поиска
struct Node {
    int data;
    Node* left;
    Node* right;

    // Конструктор узла
    explicit Node(int val) : data(val), left(nullptr), right(nullptr) {}
};

// Функция вставки нового ключа в BST
Node* insert(Node* root, int val) {
    if (root == nullptr) {
        return new Node(val);
    }
    if (val < root->data) {
        root->left = insert(root->left, val);
    } else if (val > root->data) {
        root->right = insert(root->right, val);
    }
    // Если val == корректный дубликат, в данном примере пропускаем вставку
    return root;
}

// 1. Центрированный обход (In-order: Левый, Корень, Правый)
void inOrderTraversal(Node* root) {
    if (root == nullptr) {
        return;
    }
    inOrderTraversal(root->left);
    std::cout << root->data << " ";
    inOrderTraversal(root->right);
}

// 2. Прямой обход (Pre-order: Корень, Левый, Правый)
void preOrderTraversal(Node* root) {
    if (root == nullptr) {
        return;
    }
    std::cout << root->data << " ";
    preOrderTraversal(root->left);
    preOrderTraversal(root->right);
}

// 3. Обратный обход (Post-order: Левый, Правый, Корень)
void postOrderTraversal(Node* root) {
    if (root == nullptr) {
        return;
    }
    postOrderTraversal(root->left);
    postOrderTraversal(root->right);
    std::cout << root->data << " ";
}

// 4. Обход в ширину (Level-order с использованием очереди)
void levelOrderTraversal(Node* root) {
    if (root == nullptr) {
        return;
    }
    
    std::queue<Node*> q;
    q.push(root);

    while (!q.empty()) {
        Node* current = q.front();
        q.pop();

        std::cout << current->data << " ";

        if (current->left != nullptr) {
            q.push(current->left);
        }
        if (current->right != nullptr) {
            q.push(current->right);
        }
    }
}

// Функция для рекурсивного удаления дерева и освобождения памяти
void clearTree(Node* root) {
    if (root == nullptr) {
        return;
    }
    clearTree(root->left);
    clearTree(root->right);
    delete root;
}

int main() {
    // Создаем пустое дерево и заполняем его узлами из примера
    Node* root = nullptr;
    root = insert(root, 10);
    root = insert(root, 5);
    root = insert(root, 15);
    root = insert(root, 3);
    root = insert(root, 7);

    // Демонстрация работы обходов
    std::cout << "In-order traversal:   ";
    inOrderTraversal(root);
    std::cout << "\n";

    std::cout << "Pre-order traversal:  ";
    preOrderTraversal(root);
    std::cout << "\n";

    std::cout << "Post-order traversal: ";
    postOrderTraversal(root);
    std::cout << "\n";

    std::cout << "Level-order traversal:";
    levelOrderTraversal(root);
    std::cout << "\n";

    // Корректное освобождение динамической памяти
    clearTree(root);
    root = nullptr;

    return 0;
}
```

#### Пояснение по строкам и блокам кода:
- Структура `Node` содержит поле данных `data` и два указателя `left` и `right`, инициализируемые нулевыми указателями. Конструктор с ключевым словом `explicit` предотвращает неявное преобразование типов.
- Функции рекурсивных обходов (`inOrderTraversal`, `preOrderTraversal`, `postOrderTraversal`) используют базовый случай `if (root == nullptr)` для остановки рекурсии при достижении конца ветки.
- Функция `levelOrderTraversal` подключает заголовочный файл `<queue>`, создает стандартную очередь `std::queue<Node*>` и последовательно обрабатывает узлы слой за слоем.
- Функция `clearTree` использует логику Post-order обхода для того, чтобы безопасно удалить сначала левого и правого потомков, а затем сам узел оператором `delete`, предотвращая утечки оперативной памяти.

### 6. Анализ сложности обходов

При оценке эффективности алгоритмов обхода дерева учитывается как временная, так и пространственная сложность.

#### Временная сложность
Каждый узел бинарного дерева поиска посещается ровно один раз во время любого из четырех рассмотренных обходов. 
- Если общее количество узлов в дереве равно $n$, то временная сложность всех видов обходов (как в глубину, так и в ширину) составляет **$O(n)$**. 
- Никакой дополнительной зависимости от формы дерева (сбалансировано оно или вырождено в цепь) по времени не возникает, поскольку в любом случае суммарное число посещений узлов строго равно $n$.

#### Пространственная сложность
Пространственная сложность определяется дополнительной памятью, расходуемой на служебные структуры данных (системный стек вызовов для рекурсии или явная очередь):
1. **Для рекурсивных обходов в глубину (Pre-order, In-order, Post-order):** память расходуется на стек вызовов функции. В худшем случае, когда дерево вырождено в односвязный список (высота дерева $h = n$), глубина рекурсии достигнет $n$, что дает пространственную сложность **$O(n)$**. В лучшем случае для идеально сбалансированного дерева высота составляет $h = \log_2 n$, поэтому пространственная сложность равна **$O(\log n)$**.
2. **Для обхода в ширину (Level-order):** память расходуется на очередь `std::queue`. В худшем случае (например, для сбалансированного дерева) на последнем уровне находится примерно $\frac{n}{2}$ листьев, что означает, что в очереди одновременно может храниться до $\frac{n}{2}$ элементов. Следовательно, пространственная сложность обхода в ширину в худшем случае составляет **$O(n)$**.

## 4. Полная программная реализация и управление памятью

### Проектирование класса BinarySearchTree в C++17

При создании структуры данных бинарного дерева поиска (BST) на языке C++17 мы сталкиваемся с необходимостью инкапсуляции низкоуровневых указателей внутри класса. Вызывающий код (main-функция или клиентский код) не должен работать с сырыми указателями на узлы (`Node*`), так как это приводит к ошибкам управления памятью, нарушению инвариантов дерева и снижает безопасность программы.

Для реализации мы используем разделение ответственности на две сущности:
1. Внутренняя структура `Node`, содержащая полезные данные (ключ) и указатели на левого и правого потомков.
2. Класс `BinarySearchTree`, управляющий корнем дерева, предоставляющий публичный интерфейс (методы-обертки) и скрывающий рекурсивные алгоритмы в приватной секции.

Спроектируем класс `BinarySearchTree` так, чтобы он поддерживал следующие операции:
- Вставка нового ключа.
- Поиск ключа с возвратом логического значения (найден / не найден).
- Центрированный обход (In-order) с выводом элементов на экран.
- Безопасное автоматическое уничтожение всех узлов при разрушении объекта класса (деструктор).

### Конструкторы, деструктор и управление памятью

Поскольку узлы дерева размещаются в динамической памяти с помощью оператора `new`, каждый созданный узел должен быть корректно удален с помощью оператора `delete`, чтобы избежать утечек памяти. 

Конструктор класса инициализирует пустое дерево, устанавливая указатель на корень `root` в значение `nullptr`.

Деструктор класса отвечает за освобождение всей памяти, занятой узлами дерева. Прямой или центрированный обходы здесь не подходят, так как после удаления родительского узла мы теряем доступ к его потомкам. Для безопасного освобождения памяти используется обратный обход (Post-order): сначала рекурсивно удаляются левое и правое поддеревья, и только после этого — текущий узел.

Рассмотрим реализацию вспомогательной рекурсивной функции `destroyTree` и деструктора:

```cpp
private:
    struct Node {
        int data;
        Node* left;
        Node* right;

        Node(int val) : data(val), left(nullptr), right(nullptr) {}
    };

    Node* root;

    void destroyTree(Node* node) {
        if (node == nullptr) {
            return;
        }
        destroyTree(node->left);
        destroyTree(node->right);
        delete node;
    }

public:
    BinarySearchTree() : root(nullptr) {}

    ~BinarySearchTree() {
        destroyTree(root);
    }
```

### Методы-обертки и сокрытие указателей

Пользователь класса не должен передавать в методы указатель на корень дерева (`root`), поскольку корень является деталью внутренней реализации. Для этого применяются публичные методы-обертки (wrapper methods). Публичный метод принимает только полезные данные (например, ключ), а затем вызывает приватную рекурсивную функцию, передавая ей указатель на текущий корень поддерева.

Особое внимание следует уделить передаче указателя по ссылке на указатель (`Node*&`) при реализации вставки. Когда мы рекурсивно спускаемся по дереву в поисках места для нового узла, на последнем шаге нам нужно изменить указатель родителя (или сам `root`, если дерево было пустым) так, чтобы он указывал на созданный динамический объект. Передача по значению `Node*` скопировала бы указатель, и изменение локальной копии не обновило бы поле `left` или `right` у родительского узла.

### Обработка краевых случаев

При проектировании надежного класса необходимо предусмотреть следующие граничные условия:
1. **Пустое дерево:** если `root == nullptr`, поиск сразу возвращает `false`, а вставка создает первый узел и назначает его корнем.
2. **Вставка существующего ключа:** если вставляемый ключ уже присутствует в дереве, мы можем либо проигнорировать операцию, либо принять соглашение о вставке дубликатов в правое поддерево. В нашей реализации дубликаты игнорируются для сохранения уникальности ключей.
3. **Поиск несуществующего элемента:** рекурсивная функция доходит до листового узла, переходит в `nullptr` и возвращает `false`.

### Полная программная реализация

Ниже представлена полная компилируемая программа на языке C++17, реализующая класс `BinarySearchTree` и выполняющая все требования задачи.

```cpp
#include <iostream>

class BinarySearchTree {
private:
    struct Node {
        int data;
        Node* left;
        Node* right;

        // Конструктор узла
        Node(int val) : data(val), left(nullptr), right(nullptr) {}
    };

    Node* root;

    // Рекурсивное уничтожение дерева (Post-order обход)
    void destroyTree(Node* node) {
        if (node == nullptr) {
            return;
        }
        destroyTree(node->left);
        destroyTree(node->right);
        delete node;
    }

    // Рекурсивная вставка узла (используем ссылку на указатель Node*&)
    bool insertRecursive(Node*& node, int val) {
        if (node == nullptr) {
            node = new Node(val);
            return true;
        }
        if (val < node->data) {
            return insertRecursive(node->left, val);
        } else if (val > node->data) {
            return insertRecursive(node->right, val);
        } else {
            // Ключ уже существует, дубликаты не добавляем
            return false;
        }
    }

    // Рекурсивный поиск ключа
    bool searchRecursive(Node* node, int val) const {
        if (node == nullptr) {
            return false;
        }
        if (node->data == val) {
            return true;
        }
        if (val < node->data) {
            return searchRecursive(node->left, val);
        } else {
            return searchRecursive(node->right, val);
        }
    }

    // Рекурсивный In-order обход (левое, корень, правое)
    void inOrderRecursive(Node* node) const {
        if (node == nullptr) {
            return;
        }
        inOrderRecursive(node->left);
        std::cout << node->data << " ";
        inOrderRecursive(node->right);
    }

public:
    // Конструктор
    BinarySearchTree() : root(nullptr) {}

    // Деструктор
    ~BinarySearchTree() {
        destroyTree(root);
    }

    // Публичный метод вставки
    bool insert(int val) {
        return insertRecursive(root, val);
    }

    // Публичный метод поиска
    bool search(int val) const {
        return searchRecursive(root, val);
    }

    // Публичный метод для вывода элементов в отсортированном порядке
    void printInOrder() const {
        inOrderRecursive(root);
        std::cout << std::endl;
    }
};

int main() {
    // Создаем экземпляр класса BinarySearchTree
    BinarySearchTree bst;

    // Вставляем ключи: 50, 30, 70, 20, 40, 60, 80
    int keysToInsert[] = {50, 30, 70, 20, 40, 60, 80};
    for (int key : keysToInsert) {
        bst.insert(key);
    }

    // Выполняем поиск ключа 40
    int target = 40;
    if (bst.search(target)) {
        std::cout << "Ключ " << target << " найден в дереве." << std::endl;
    } else {
        std::cout << "Ключ " << target << " не найден в дереве." << std::endl;
    }

    // Выводим результаты In-order обхода
    std::cout << "In-order обход дерева: ";
    bst.printInOrder();

    // Деструктор будет вызван автоматически при выходе объекта bst из области видимости,
    // корректно уничтожая все узлы и освобождая память.
    return 0;
}
```

### Пояснение по строкам и блокам кода

- Строки 8–15: Определение внутренней структуры `Node`. Конструктор структуры принимает значение и инициализирует дочерние указатели нулевыми значениями.
- Строки 20–28: Функция `destroyTree` обходит дерево в порядке Post-order, удаляя сначала левого и правого потомков, а затем текущий узел. Это предотвращает утечки памяти.
- Строки 31–43: Функция `insertRecursive` принимает аргумент `Node*& node` (ссылку на указатель). Благодаря этому при создании нового узла через `new Node(val)` указатель родителя физически изменяется и начинает ссылаться на новый объект в куче.
- Строки 81–92: Публичные методы-обертки `insert`, `search` и `printInOrder` предоставляют безопасный интерфейс, скрывая структуру `Node` и указатель `root` от вызывающего кода.

- **Временная сложность вставки и поиска:**
  - В среднем случае (для сбалансированного дерева): $O(\log_2 n)$, где $n$ — количество узлов.
  - В худшем случае (если дерево выродилось в цепочку): $O(n)$.
- **Временная сложность обхода (In-order):** $O(n)$, так как каждый узел посещается ровно один раз.

- **Пространственная сложность:**
  - Память под хранение структуры данных: $O(n)$ для размещения $n$ узлов в динамической памяти.

## 5. Анализ сложности и типичные ошибки реализации

### 1. Анализ временной и пространственной сложности операций в BST

Эффективность любой структуры данных оценивается с помощью асимптотической нотации $O$. Для бинарного дерева поиска (BST) производительность базовых операций — поиска (`search`), вставки (`insert`) и удаления (`remove`) — напрямую зависит от геометрической формы дерева, а именно от его высоты.

> **Определение.** Высотой бинарного дерева $h$ называется максимальная длина пути от корня дерева до любого из его листьев, измеряемая в количестве рёбер. Для дерева, состоящего из единственного узла (корня), высота равна $0$. Для пустого дерева высота часто принимается равной $-1$.

В любой операции поиска или вставки ключа в BST мы начинаем с корневого узла и на каждом шаге сравниваем искомый ключ с ключом текущего узла. В зависимости от результата сравнения мы переходим либо в левое, либо в правое поддерево. Таким образом, количество шагов (и, соответственно, операций сравнения) в процессе спуска от корня до листа в точности равно количеству рёбер на этом пути плюс один, то есть ограничено сверху высотой дерева $h$.

Временная сложность основных операций в худшем случае составляет $\mathcal{O}(h)$, где $h$ — высота дерева, а $n$ — общее количество узлов в дереве.

Рассмотрим два крайних случая организации дерева:

1. **Сбалансированное дерево.** Если дерево максимально сбалансировано (на каждом уровне, кроме, возможно, последнего, все узлы имеют обоих потомков), количество узлов $n$ на каждом новом уровне удваивается. Высота такого дерева минимальна и логарифмически зависит от количества узлов:
   $$h = \lfloor \log_2 n \rfloor$$
   В этом случае временная сложность поиска, вставки и удаления составляет $\mathcal{O}(\log_2 n)$. Это оптимальный показатель для динамических структур данных на основе сравнений.

2. **Вырожденное дерево (цепь).** Если элементы добавляются в дерево в уже отсортированном порядке (например, $1, 2, 3, 4, 5$), каждый новый узел будет добавляться в правое поддерево предыдущего. Дерево превращается в односвязный список, где у каждого узла есть не более одного потомка. Высота такого дерева становится максимальной:
   $$h = n - 1$$
   В этом случае временная сложность всех операций деградирует до $\mathcal{O}(n)$, что эквивалентно линейному поиску по неупорядоченному массиву.

Пространственная сложность хранения $n$ узлов в динамической памяти всегда составляет $\mathcal{O}(n)$, так как каждый узел хранит ровно одно значение и два указателя (`left` и `right`).

Однако при оценке пространственной сложности необходимо учитывать затраты памяти на **стек вызовов** (call stack) при выполнении рекурсивных алгоритмов (поиска, вставки, обходов и деструктора). Каждый рекурсивный вызов функции выделяет в стеке кадр для хранения локальных переменных и адреса возврата. Максимальная глубина рекурсии равна высоте дерева $h$.

Следовательно, пространственная сложность рекурсивных операций и обходов в худшем случае составляет $\mathcal{O}(h)$:
- Для сбалансированного дерева затраты памяти на стек вызовов равны $\mathcal{O}(\log_2 n)$.
- Для вырожденного дерева затраты памяти на стек вызовов возрастают до $\mathcal{O}(n)$, что при больших значениях $n$ может привести к аварийному завершению программы из-за переполнения стека (`stack overflow`).

### 2. Разбор примера: расчет количества операций сравнения

Рассмотрим практический расчет количества операций сравнения для поиска элемента в бинарном дереве поиска, содержащем $n = 1023$ узла.

#### Условие задачи
В бинарном дереве поиска хранится $1023$ уникальных целых ключа. Требуется найти количество операций сравнения ключей в худшем и лучшем случаях при поиске заданного элемента:
а) когда дерево идеально сбалансировано;
б) когда дерево вырождено в цепь.

#### Ход рассуждений
1. Операция сравнения ключей в BST происходит на каждом шаге спуска по дереву, когда мы сравниваем искомый ключ `target` с ключом текущего узла `node->key`.
2. В лучшем случае искомый ключ оказывается в самом корне дерева (первый же узел равен искомому). Тогда требуется ровно $1$ сравнение независимо от формы дерева. Однако на практике под «лучшим случаем» для алгоритмов поиска часто понимают поиск по всему дереву или поиск элемента, расположенного на минимальной глубине. Строго говоря, минимальное количество сравнений для успешного поиска в любом непустом дереве равно $1$ (если искомый элемент — корень).
3. В худшем случае искомый элемент либо находится на максимальной глубине (в самом длинном листе), либо вообще отсутствует в дереве, и поиск завершается в пустом поддереве после прохождения всех уровней. Количество сравнений в худшем случае равно высоте дерева плюс один: $C_{\text{worst}} = h + 1$.

#### Решение в общем виде
Пусть $n$ — количество узлов в дереве.
- **Случай а (идеально сбалансированное дерево).**
  Полное бинарное дерево с $n$ узлами имеет высоту:
  $$h = \log_2(n + 1) - 1$$
  Подставим количество операций в худшем случае:
  $$C_{\text{worst}} = h + 1 = \log_2(n + 1) - 1 + 1 = \log_2(n + 1)$$

- **Случай б (вырожденное дерево в виде цепи).**
  Высота такого дерева равна:
  $$h = n - 1$$
  Количество операций в худшем случае:
  $$C_{\text{worst}} = h + 1 = (n - 1) + 1 = n$$

#### Подстановка и вычисление
Подставим заданное значение $n = 1023$:

- **Случай а (сбалансированное дерево):**
  $$C_{\text{worst}} = \log_2(1023 + 1) = \log_2(1024) = 10$$
  В сбалансированном дереве из $1023$ узлов для поиска любого элемента в худшем случае потребуется не более $10$ сравнений.

- **Случай б (вырожденное дерево):**
  $$C_{\text{worst}} = 1023$$
  В вырожденном дереве из $1023$ узлов для поиска элемента в худшем случае (или поиска отсутствующего элемента) потребуется выполнить все $1023$ сравнения.

#### Проверка
- Единицы измерения: количество операций сравнения — безразмерная величина (целое число).
- Правдоподобие: Для сбалансированного дерева $\log_2(1024) = 10$, что соответствует глубине дерева с $10$ уровнями (от корня с глубиной $0$ до листьев на глубине $9$, плюс один узел-потомок или шаг). Расчет корректен.

*Ответ:* а) в худшем случае — 10 операций сравнения, в лучшем — 1 операция; б) в худшем случае — 1023 операции сравнения, в лучшем — 1 операция.

### 3. Типичные ошибки реализации бинарного дерева поиска

При самостоятельной реализации структур данных на языке C++17 студенты часто сталкиваются с трудностями, связанными с управлением динамической памятью и передачей указателей. Ниже приведен разбор трех наиболее распространенных ошибок.

#### Типичная ошибка 1: потеря указателя при изменении дерева без передачи по ссылке

Рассмотрим реализацию функции вставки узла в BST. Новичок может написать сигнатуру функции вставки следующим образом:

```cpp
// НЕПРАВИЛЬНО: передача указателя по значению
void insert(Node* root, int key) {
    if (root == nullptr) {
        root = new Node(key); // Изменяется лишь локальная копия указателя!
        return;
    }
    if (key < root->key) {
        insert(root->left, key);
    } else if (key > root->key) {
        insert(root->right, key);
    }
}
```

**В чем ошибка:** В языке C++ аргументы функции передаются по значению. Когда мы вызываем `insert(root->left, key)`, в функцию передается *копия* указателя на левого потомка. Внутри функции `root` указывает на новый созданный узел (`new Node(key)`), но этот адрес записывается только в локальную переменную вызванной функции. Как только функция завершает работу, локальный указатель уничтожается, а реальное поле `left` у родительского узла так и остается равным `nullptr`. Дерево не изменяется, новые узлы теряются.

**Как исправить:** Необходимо передавать указатель по ссылке (`Node*&`) либо возвращать измененный указатель из функции:

```cpp
// ПРАВИЛЬНО: передача указателя по ссылке
void insert(Node*& root, int key) {
    if (root == nullptr) {
        root = new Node(key); // Изменяем сам исходный указатель в куче/родительском узле
        return;
    }
    if (key < root->key) {
        insert(root->left, key);
    } else if (key > root->key) {
        insert(root->right, key);
    }
}
```

Альтернативный подход без ссылок на указатели — возвращать обновленный указатель на узел:
```cpp
Node* insert(Node* root, int key) {
    if (root == nullptr) {
        return new Node(key);
    }
    if (key < root->key) {
        root->left = insert(root->left, key);
    } else if (key > root->key) {
        root->right = insert(root->right, key);
    }
    return root;
}
```

#### Типичная ошибка 2: утечки памяти при удалении узлов

Бинарное дерево поиска динамически размещает каждый свой узел в куче с помощью оператора `new`. Если класс, управляющий деревом (`BinarySearchTree`), не реализует корректный деструктор или метод очистки (`clear`), все выделенные узлы останутся в памяти до завершения работы программы, что приводит к утечке памяти (`memory leak`).

Более того, попытка удалить дерево простым удалением только корня (`delete root;`) приведет к удалению исключительно корневого узла, в то время как все его потомки останутся в оперативной памяти без возможности доступа к ним (потеря указателей).

**Как исправить:** Удаление узлов дерева должно производиться рекурсивно с использованием **обратного обхода (Post-order)**: сначала необходимо освободить память под левое поддерево, затем под правое поддерево, и только после этого удалять текущий узел.

Пример корректной реализации деструктора или метода очистки:

```cpp
void clear(Node*& root) {
    if (root == nullptr) {
        return;
    }
    clear(root->left);   // Рекурсивно очищаем левое поддерево
    clear(root->right);  // Рекурсивно очищаем правое поддерево
    delete root;         // Удаляем текущий узел
    root = nullptr;      // Обнуляем указатель во избежание зависания
}
```

---

#### Типичная ошибка 3: некорректная обработка граничных условий для пустого корня

Многие операции (поиск, вставка, печать обходов) могут вызываться для пустого дерева, когда указатель на корень `root == nullptr`. Если внутри методов класса не предусмотреть проверку на этот случай, попытка разыменования нулевого указателя (например, обращение `root->key`) приведет к аварийному завершению программы из-за ошибки сегментации (`Segmentation fault`).

**Как исправить:** Всегда начинайте публичные методы-обертки и рекурсивные функции с проверки граничного условия для пустого указателя:

```cpp
bool search(Node* root, int key) const {
    // Граничное условие: дошли до конца ветки или дерево пусто
    if (root == nullptr) {
        return false;
    }
    if (root->key == key) {
        return true;
    }
    if (key < root->key) {
        return search(root->left, key);
    } else {
        return search(root->right, key);
    }
}
```

## Типичные ошибки

1. **Неправильный выбор порядка обхода при удалении дерева.** Удаление узлов дерева сверху вниз (начиная с корня) приводит к потере указателей на дочерние поддеревья и утечке памяти. *Как избежать:* всегда использовать Post-order обход (сначала удалить потомки, затем родителя).
   *Пример:* `delete root;` вместо рекурсивного уничтожения поддеревьев.

2. **Изменение структуры дерева без передачи указателя по ссылке.** Попытка изменить корень или дочерний указатель путем передачи его по значению приводит к изменению локальной копии внутри функции, оставляя исходный указатель в структуре неизменным. *Как избежать:* использовать сигнатуру с передачей по ссылке на указатель (`Node*&`) или возвращать измененный указатель (`Node*`).
   *Пример:* `void insert(Node* root, int val);` вместо `void insert(Node*& root, int val);`.

3. **Игнорирование проверки на пустой указатель (`nullptr`).** Обращение к полям узла (`root->key`, `root->left`) без предварительной проверки на равенство указателя `nullptr` вызывает ошибку сегментации (`Segmentation fault`) и аварийное завершение программы. *Как избежать:* в начале каждой рекурсивной или итеративной функции ставить базовый случай `if (root == nullptr) return;`.

4. **Нарушение инварианта BST при добавлении дубликатов.** Добавление одинаковых ключей в произвольные поддеревья разрушает строгое неравенство инварианта бинарного дерева поиска, что делает невозможным корректный поиск элементов. *Как избежать:* четко определить политику работы с дубликатами (например, игнорировать вставку уже существующего ключа) и проверять равенство `val == root->data`.

5. **Путаница между высотой дерева и количеством узлов.** Оценка сложности алгоритмов по количеству уровней вместо высоты дерева или отождествление количества элементов $n$ с высотой $h$ ($h = n$ вместо $h = \log_2 n$ в сбалансированном случае). *Как избежать:* помнить, что высота сбалансированного дерева из $n$ узлов равна $\log_2(n + 1) - 1$.

6. **Создание «висячих» указателей после удаления узла.** После освобождения памяти оператором `delete node;` переменная продолжает хранить адрес удаленной ячейки памяти, что может привести к неопределенному поведению при повторном обращении. *Как избежать:* после вызова `delete` сразу присваивать указателю значение `nullptr`.

7. **Отсутствие деструктора в классе-обертке.** Управление узлами дерева внутри класса без реализации пользовательского деструктора приводит к неизбежным утечкам памяти при выходе объекта дерева из области видимости. *Как избежать:* всегда реализовывать деструктор `~BinarySearchTree()`, вызывающий рекурсивное удаление всех узлов.

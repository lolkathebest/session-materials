## Теоретические основы поиска в массивах и последовательный поиск

### Постановка задачи поиска в массивах

Задача поиска элементов в структурированных данных является одной из фундаментальных задач в программировании. В рамках данного курса мы будем рассматривать массивы (в языке C++ они представлены стандартным контейнером `std::vector<T>` или классическими статическими массивами), хранящие элементы некоторого типа.

> **Определение.** Задачей поиска в массиве называется алгоритмическая задача, в которой по заданному массиву данных $A$, состоящему из $N$ элементов, и некоторому целевому значению $x$ (называемому *искомым ключом*) требуется определить, присутствует ли данный элемент в массиве, и если да, то найти его позицию (индекс).

Формально входными данными для задачи являются:
1. Массив $A = [a_0, a_1, a_2, \dots, a_{N-1}]$, содержащий $N$ элементов.
2. Искомый ключ $x$.

Возвращаемым значением алгоритма поиска обычно является:
- Целое неотрицательное число — индекс элемента в массиве (в индексации C++ от $0$ до $N-1$), если элемент был найден.
- Специальное сигнальное значение (например, $-1$), если элемент в массиве отсутствует. В современном C++ также может возвращаться итератор на элемент или специальный объект-обертка `std::optional<size_t>`.

### Определение последовательного поиска и область применения

Когда данные в массиве не упорядочены (не отсортированы) или у нас нет никакой информации о взаимном расположении элементов, мы не можем делать никаких предположений о том, где именно находится искомый элемент. Единственным универсальным способом найти его является прямой перебор.

> **Определение.** Последовательный поиск (или линейный поиск, англ. *Linear Search*) — это простейший алгоритм поиска элемента в коллекции, заключающийся в последовательном сравнении каждого элемента массива с искомым ключом до тех пор, пока не будет найден совпадающий элемент или пока не будут просмотрены все элементы коллекции.

Областью применения последовательного поиска являются:
- Несортированные массивы и списки любого размера, когда предварительная сортировка экономически невыгодна (например, массив поступает в единственном экземпляре и поиск выполняется ровно один раз).
- Маленькие массивы, где накладные расходы на сортировку или более сложные структуры данных превышают время простого линейного обхода.
- Коллекции данных, в которых элементы добавляются динамически, а операция поиска выполняется реже операций вставки.

### Алгоритм последовательного поиска

Алгоритм работает предельно просто: мы начинаем с нулевого элемента массива и движемся в сторону возрастания индексов. На каждом шаге мы сравниваем текущий элемент массива $A[i]$ с искомым ключом $x$.

Словесный алгоритм линейного поиска:
1. Инициализировать переменную индекса $i$ значением $0$.
2. Проверить условие: если $i \ge N$ (где $N$ — размер массива), то элемент не найден; завершить алгоритм и вернуть $-1$.
3. Сравнить текущий элемент массива $A[i]$ с искомым ключом $x$.
4. Если $A[i] == x$, то искомый элемент найден; завершить алгоритм и вернуть текущий индекс $i$.
5. Если $A[i] \neq x$, то увеличить индекс $i$ на $1$ ($i = i + 1$) и вернуться к шагу 2.

Ниже приведена текстовая схема (блок-схема) алгоритма линейного поиска:

```
[Начало]
   │
   ▼
 i = 0 ──────────────┐
   │                 │
   ▼                 │
[i < N?] ──(Нет)───► │ ──► Возврат -1 (Не найдено)
   │                 │
 (Да)                │
   │                 │
   ▼                 │
[A[i] == x?]         │
   │                 │
 (Да)                │
   │                 │
   ▼                 │
Возврат i            │
   │                 │
 (Нет)               │
   │                 │
   ▼                 │
 i = i + 1 ──────────┘
```

### Оценка временной и пространственной сложности

Для оценки эффективности алгоритмов используется $O$-нотация (символ «О большое»). Оценка сложности показывает, как растет время выполнения или объем используемой памяти при увеличении размера входных данных $N$.

#### Временная сложность (Time Complexity)
Время работы линейного поиска напрямую зависит от количества элементов $N$ в массиве и от того, на какой позиции находится искомый элемент. Различают три случая:
1. **Лучший случай (Best Case):** Искомый элемент находится на самом первом месте ($A[0] = x$). В этом случае алгоритм делает ровно одно сравнение независимо от общего размера массива $N$. Временная сложность в лучшем случае составляет $O(1)$.
2. **Худший случай (Worst Case):** Искомый элемент находится на последнем месте ($A[N-1] = x$) либо вообще отсутствует в массиве. Алгоритму приходится проверить каждый из $N$ элементов. Количество сравнений в точности равно $N$. Временная сложность в худшем случае составляет $O(N)$.
3. **Средний случай (Average Case):** Если предположить, что искомый элемент с равной вероятностью может находиться в любой позиции массива или отсутствовать вовсе, в среднем алгоритм проверит около $N/2$ элементов. Константный множитель $1/2$ в $O$-нотации отбрасывается, поэтому средняя временная сложность также составляет $O(N)$.

#### Пространственная сложность (Space Complexity)
Для выполнения линейного поиска не требуется выделения дополнительной памяти, пропорциональной размеру массива. Мы используем только одну вспомогательную переменную для хранения текущего индекса $i$ (занимающую фиксированный объем памяти $O(1)$). Следовательно, пространственная сложность алгоритма линейного поиска равна $O(1)$ (константная память).

### Разобранный пример 1: Поиск существующего элемента

#### Условие задачи
Дан несортированный массив целых чисел $A = [12, 45, 23, 8, 19, 42]$. Искомый ключ $x = 23$. Требуется найти индекс этого элемента с помощью последовательного поиска.

#### Ход рассуждений
Размер массива $N = 6$ (индексы от $0$ до $5$). Мы будем последовательно проверять каждый элемент, начиная с нулевого индекса, и фиксировать каждое сравнение.

#### Решение по шагам
1. Шаг 1 ($i = 0$): Сравниваем $A[0]$ с $x$. $A[0] = 12$. Проверка: $12 == 23$ — ложь. Элемент не найден, переходим к следующему.
2. Шаг 2 ($i = 1$): Сравниваем $A[1]$ с $x$. $A[1] = 45$. Проверка: $45 == 23$ — ложь. Элемент не найден, переходим к следующему.
3. Шаг 3 ($i = 2$): Сравниваем $A[2]$ с $x$. $A[2] = 23$. Проверка: $23 == 23$ — истина! Искомый элемент обнаружен на позиции с индексом $2$.

#### Проверка
- Единицы измерения: индексы элементов являются беззнаковыми или знаковыми целыми числами, размерность не требуется.
- Правдоподобность: визуальный осмотр массива подтверждает, что число $23$ стоит на третьем месте, что соответствует индексу $2$ при нулевой индексации. Алгоритм выполнил ровно $3$ сравнения из $6$ возможных, что согласуется с теорией для среднего случая.

*Ответ:* индекс элемента $23$ равен $2$.

### Разобранный пример 2: Поиск отсутствующего элемента

#### Условие задачи
Дан несортированный массив целых чисел $B = [5, 2, 9, 11]$. Искомый ключ $x = 99$. Требуется проверить наличие элемента с помощью последовательного поиска и вернуть результат.

#### Ход рассуждений
Размер массива $N = 4$ (индексы от $0$ до $3$). Поскольку элемент $99$ может находиться в любой части массива или отсутствовать, алгоритм обязан просмотреть все элементы от начала до конца, так как у нас нет признака упорядоченности, позволяющего досрочно прекратить поиск.

#### Решение по шагам
1. Шаг 1 ($i = 0$): Сравниваем $B[0]$ с $x$. $B[0] = 5$. Проверка: $5 == 99$ — ложь.
2. Шаг 2 ($i = 1$): Сравниваем $B[1]$ с $x$. $B[1] = 2$. Проверка: $2 == 99$ — ложь.
3. Шаг 3 ($i = 2$): Сравниваем $B[2]$ с $x$. $B[2] = 9$. Проверка: $9 == 99$ — ложь.
4. Шаг 4 ($i = 3$): Сравниваем $B[3]$ с $x$. $B[3] = 11$. Проверка: $11 == 99$ — ложь.
5. Шаг 5 ($i = 4$): Индекс $i = 4$ стал равен размеру массива $N = 4$. Условие продолжения цикла $i < N$ больше не выполняется. Обход завершен.

#### Проверка
- Единицы измерения: отсутствуют.
- Правдоподобность: алгоритм корректно просмотрел все $N = 4$ элемента массива, совершив ровно $4$ сравнения (худший случай), убедился в отсутствии совпадения и вернул корректный сигнал об отсутствии элемента.

*Ответ:* элемент $99$ в массиве $B$ отсутствует, алгоритм возвращает $-1$.

## Двоичный поиск: идея, требования и математическое обоснование

### Суть метода «разделяй и властвуй» применительно к поиску данных

Парадигма «разделяй и властвуй» (англ. *divide and conquer*) является одним из фундаментальных подходов к проектированию алгоритмов. Её основная идея заключается в том, что сложная задача большой размерности разбивается на несколько независимых подзадач меньшего размера. Эти подзадачи решаются рекурсивно или итеративно, после чего их результаты объединяются для получения решения исходной задачи.

В контексте задачи поиска элемента в массиве классический последовательный поиск исследует каждый элемент по очереди, тратя линейное время. Метод «разделяй и властвуй» позволяет радикально изменить подход: вместо того чтобы проверять элементы по одному, мы на каждом шаге отбрасываем сразу половину элементов массива, в которой гарантированно не может находиться искомый ключ. 

Пусть у нас имеется упорядоченный набор данных. Вместо просмотра всей структуры мы обращаемся к её центральному элементу. Сравнивая искомое значение с центральным элементом, мы мгновенно принимаем решение о том, в какой именно половине (левой или правой) следует продолжить поиск. Таким образом, пространство поиска сокращается в два раза на каждой итерации.

### Строгое требование к структуре данных: обязательная сортировка массива

Для корректной работы двоичного поиска накладывается жесткое и непреложное требование: **массив должен быть предварительно отсортирован** (например, по неубыванию или по невозрастанию). 

Рассмотрим математическое обоснование этого требования. Пусть массив $A$ содержит $N$ элементов, упорядоченных по возрастанию:
$$A[0] \le A[1] \le A[2] \le \dots \le A[N-1]$$

Выбирая центральный элемент с индексом $\text{mid}$, мы делим массив на две части:
1. Левая часть: все элементы с индексами от начала до $\text{mid} - 1$.
2. Правая часть: все элементы с индексами от $\text{mid} + 1$ до конца.

Свойство упорядоченности гарантирует выполнение следующих импликаций для любого искомого ключа $x$:
- Если искомый ключ $x$ строго меньше значения центрального элемента $A[\text{mid}]$, то в силу возрастания порядка массива все элементы, расположенные правее индекса $\text{mid}$ (включая сам элемент $A[\text{mid}]$), будут еще больше значения $x$. Следовательно, искать $x$ в правой части бессмысленно — его там гарантированно нет. Область поиска сужается исключительно до левой половины.
- Если искомый ключ $x$ строго больше значения центрального элемента $A[\text{mid}]$, то все элементы, расположенные левее индекса $\text{mid}$, меньше или равны $A[\text{mid}]$, а значит, они меньше $x$. Область поиска сужается исключительно до правой половины.

> **Определение.** Двоичный (бинарный) поиск — это алгоритм поиска элемента в отсортированном массиве, который многократно делит пополам область поиска, содержащую искомый элемент, до тех пор, пока область не сузится до одного элемента или пока искомый элемент не будет найден.

Если массив не отсортирован, упомянутые логические переходы теряют силу: меньший элемент может находиться справа от большего, и отбрасывание любой половины массива приведет к безвозвратной потере искомого элемента.

### Определение границ поиска: левый индекс low и правый индекс high

Пространство поиска на каждом шаге алгоритма задается двумя целочисленными переменными, определяющими текущий рабочий отрезок массива:
- $\text{low}$ — левая граница отрезка поиска (изначально равна $0$).
- $\text{high}$ — правая граница отрезка поиска (изначально равна $N - 1$, где $N$ — размер массива).

Интервал поиска является инклюзивным и задается замкнутым множеством индексов $[\text{low}, \text{high}]$. Пока выполняется условие $\text{low} \le \text{high}$, отрезок содержит как минимум один элемент, и поиск продолжается. Если в ходе сужения границ становится так, что $\text{low} > \text{high}$, это означает, что отрезок пуст, элемент в массиве отсутствует, и алгоритм завершает работу с признаком неудачного поиска.

### Формула вычисления среднего элемента и предотвращение переполнения

Центральный индекс $\text{mid}$ вычисляется на основе текущих границ $\text{low}$ и $\text{high}$. 

Наивный подход заключается в использовании формулы арифметического среднего:
$$\text{mid} = \frac{\text{low} + \text{high}}{2}$$

Несмотря на кажущуюся очевидность, эта формула содержит критическую уязвимость, способную привести к серьезной программной ошибке или неопределенному поведению в языках программирования со строгой типизацией (включая C++17). В компьютерных системах целочисленные типы данных (например, стандартный 32-битный знаковый `int`) имеют фиксированный диапазон представления значений. Для типа `int` максимальное положительное значение составляет $2\,147\,483\,647$ ($2^{31} - 1$). 

Если индексы $\text{low}$ и $\text{high}$ принимают большие значения, близкие к верхней границе типа `int`, их сумма $(\text{low} + \text{high})$ может превысить максимальное допустимое значение. Произойдет арифметическое переполнение (англ. *integer overflow*), в результате чего бит знака изменится, и сумма превратится в отрицательное число. Деление отрицательного числа на два вернет некорректный отрицательный индекс, обращение по которому вызовет аварийное завершение программы ( segmentation fault) или повреждение памяти.

Для предотвращения переполнения используется математически эквивалентная формула, которая вычисляет смещение относительно левой границы:
$$\text{mid} = \text{low} + \frac{\text{high} - \text{low}}{2}$$

#### Разбор примера: вычисление среднего индекса при больших значениях границ

**Условие:**
Пусть левая граница $\text{low} = 2\,000\,000\,000$, а правая граница $\text{high} = 2\,100\,000\,000$. Обе величины находятся в допустимом диапазоне 32-битного знакового целого типа `int`. Требуется вычислить индекс $\text{mid}$ двумя способами.

**Ход рассуждений и решение в общем виде:**
1. Применение наивной формулы:
   $$\text{sum} = \text{low} + \text{high} = 2\,000\,000\,000 + 2\,100\,000\,000 = 4\,100\,000\,000$$
   Полученное число $4\,100\,000\,000$ превышает предел типа `int` ($2\,147\,483\,647$). Происходит переполнение, и переменная принимает неверное отрицательное значение (в дополнительном коде это будет $-194\,967\,296$). Деление на 2 дает ошибочный индекс $\text{mid} < 0$.
2. Применение безопасной формулы:
   $$\text{diff} = \text{high} - \text{low} = 2\,100\,000\,000 - 2\,000\,000\,000 = 100\,000\,000$$
   Разность гарантированно помещается в диапазон типа, так как она меньше исходных величин.
   Делим разность пополам:
   $$\frac{\text{diff}}{2} = \frac{100\,000\,000}{2} = 50\,000\,000$$
   Прибавляем результат к левой границе:
   $$\text{mid} = 2\,000\,000\,000 + 50\,000\,000 = 2\,050\,000\,000$$

**Проверка:**
Единицы измерения здесь — индексы элементов массива (безразмерные целые числа). Значение $2\,050\,000\,000$ лежит строго посередине между $2\,000\,000\,000$ и $2\,100\,000\,000$, переполнение отсутствует.

**Ответ:** $\text{mid} = 2\,050\,000\,000$ (наивная формула приводит к переполнению).

### Логика сужения границ

Алгоритм двоичного поиска реализуется в виде цикла или рекурсивной функции. На каждом шаге выполняются три основных действия:
1. Вычисление центрального индекса $\text{mid}$.
2. Сравнение значения элемента в средней позиции $A[\text{mid}]$ с искомым ключом $x$:
   - Если $A[\text{mid}] == x$, искомый элемент найден, алгоритм возвращает текущий индекс $\text{mid}$.
   - Если $A[\text{mid}] > x$, искомый элемент меньше центрального, значит, он может находиться только в левой половине. Правая граница сдвигается влево: $\text{high} = \text{mid} - 1$. Мы исключаем саму позицию $\text{mid}$, так как её значение уже проверили и оно не равно $x$.
   - Если $A[\text{mid}] < x$, искомый элемент больше центрального, значит, он может находиться только в правой половине. Левая граница сдвигается вправо: $\text{low} = \text{mid} + 1$. Мы исключаем позицию $\text{mid}$.
3. Если цикл завершается условием $\text{low} > \text{high}$, а совпадение так и не было найдено, алгоритм возвращает специальный признак отсутствия элемента (обычно число $-1$).

### Математический вывод временной сложности $O(\log N)$

Оценим количество операций, которые выполняет алгоритм двоичного поиска в худшем случае (когда элемента в массиве нет или он находится в самом неблагоприятном положении).

Пусть исходный размер отсортированного массива равен $N$.
- На первой итерации размер области поиска составляет $N$. После сравнения с центральным элементом область поиска уменьшается примерно в два раза. Размер оставшейся части равен $\frac{N}{2}$.
- На второй итерации размер области поиска становится равным $\frac{N}{2^2} = \frac{N}{4}$.
- На $k$-й итерации размер области поиска сокращается до значения:
  $$\frac{N}{2^k}$$

Процесс деления отрезка пополам продолжается до тех пор, пока размер области поиска не уменьшится до одного элемента (в худшем случае) или до нуля. Обозначим за $k$ общее количество шагов (итераций), которые делает алгоритм. В самом конце работы размер области поиска становится равным $1$:
$$\frac{N}{2^k} = 1$$

Умножим обе части уравнения на $2^k$:
$$N = 2^k$$

Для того чтобы выразить количество шагов $k$ через размер массива $N$, применим операцию логарифмирования по основанию $2$ к обеим частям равенства:
$$\log_2(N) = \log_2(2^k)$$

По свойству логарифмов $\log_2(2^k) = k \cdot \log_2(2) = k$:
$$k = \log_2(N)$$

Таким образом, максимальное количество сравнений, которое выполняет алгоритм двоичного поиска для массива из $N$ элементов, пропорционально двоичному логарифму размера массива. В терминах асимптотической нотации это записывается как $O(\log N)$.

#### Разбор примера: определение количества шагов для конкретных размеров массива

**Условие:**
Определить максимальное количество шагов двоичного поиска для массивов размером $N = 1024$ и $N = 1\,000\,000$.

**Ход рассуждений и решение в общем виде:**
Используем выведенную формулу $k = \log_2(N)$.

1. Для $N = 1024$:
   Подставляем значение в формулу:
   $$k = \log_2(1024)$$
   Вспомним степени двойки: $2^0 = 1$, $2^1 = 2$, $2^2 = 4$, $2^3 = 8$, $2^4 = 16$, $2^5 = 32$, $2^6 = 64$, $2^7 = 128$, $2^8 = 256$, $2^9 = 512$, $2^{10} = 1024$.
   Следовательно, $\log_2(1024) = 10$.
   Максимальное число шагов равно $10$. Для сравнения, линейный поиск в худшем случае потребовал бы $1024$ шага.

2. Для $N = 1\,000\,000$:
   Подставляем значение в формулу:
   $$k = \log_2(1\,000\,000)$$
   Точное значение не является целым числом. Оценим его с помощью известных степеней двойки:
   $2^{19} = 524\,288$
   $2^{20} = 1\,048\,576$
   Поскольку $524\,288 < 1\,000\,000 < 1\,048\,576$, то логарифм лежит между $19$ и $20$. С учетом округления вверх до целого числа шагов в худшем случае получаем $20$ шагов. 
   Линейный поиск для массива из миллиона элементов в худшем случае делает $1\,000\,000$ сравнений, в то время как двоичный поиск выполнит не более $20$ операций. Это демонстрирует колоссальное превосходство логарифмической сложности над линейной при обработке больших объемов данных.

**Проверка:**
Единицы измерения — количество итераций (шагов алгоритма). Результаты получены корректно на основе свойств степеней двойки.

**Ответ:** Для $N = 1024$ максимальное число шагов равно $10$; для $N = 1\,000\,000$ максимальное число шагов равно $20$.

## Итеративная и рекурсивная реализация двоичного поиска на C++17

### Итеративный подход к двоичному поиску на C++17

Итеративная реализация двоичного поиска использует цикл `while` для последовательного сужения диапазона поиска на каждом шаге. Такой подход является наиболее эффективным с точки зрения расхода оперативной памяти, так как не создает дополнительных кадров в стеке вызовов функций.

> **Определение.** Итеративным алгоритмом двоичного поиска называется процедура локализации искомого ключа в отсортированном массиве с использованием цикла и переменных границ, изменяющихся по принципу «разделяй и властвуй», без применения рекурсивных вызовов.

Для реализации итеративного двоичного поиска на языке C++17 воспользуемся стандартным контейнером `std::vector<int>` для хранения элементов и константными ссылками для передачи данных в функцию, что исключает избыточное копирование памяти.

Рассмотрим полную структуру итеративной функции двоичного поиска:

```cpp
#include <vector>

// Функция выполняет итеративный двоичный поиск элемента target в массиве arr.
// Возвращает индекс найденного элемента или -1, если элемент отсутствует.
int binarySearch(const std::vector<int>& arr, int target) {
    // Обработка краевого случая: если массив пуст, поиск невозможен
    if (arr.empty()) {
        return -1;
    }

    int low = 0;
    int high = static_cast<int>(arr.size()) - 1;

    // Пока левая граница не перешла за правую
    while (low <= high) {
        // Безопасное вычисление среднего индекса для предотвращения переполнения
        int mid = low + (high - low) / 2;

        // Сравнение центрального элемента с искомым значением
        if (arr[mid] == target) {
            return mid; // Элемент найден, возвращаем его индекс
        } 
        else if (arr[mid] < target) {
            // Искомое значение больше центрального, отбрасываем левую половину
            low = mid + 1;
        } 
        else {
            // Искомое значение меньше центрального, отбрасываем правую половину
            high = mid - 1;
        }
    }

    // Если цикл завершился, а элемент не найден, возвращаем -1
    return -1;
}
```

Разберем каждую строчку и каждый блок этой функции:
1. `if (arr.empty()) { return -1; }` — защитная проверка. Если размер вектора равен нулю, вычисление индекса `high = arr.size() - 1` приведет к переполнению типа без знака (`size_t`), так как выражение `0 - 1` превратится в максимальное значение `size_t`. Проверка предотвращает неопределенное поведение.
2. `int low = 0;` — инициализация левой границы поиска самым первым индексом массива.
3. `int high = static_cast<int>(arr.size()) - 1;` — инициализация правой границы последним индексом. Операция `static_cast<int>` явным образом преобразует беззнаковый размер контейнера в знаковое целое число, необходимое для корректного сравнения с `low` и вычитания.
4. `while (low <= high)` — условие продолжения работы цикла. Равенство `low == high` означает, что в диапазоне остался ровно один элемент, который обязательно нужно проверить.
5. `int mid = low + (high - low) / 2;` — вычисление центрального индекса с защитой от переполнения.
6. `if (arr[mid] == target)` — базовая проверка совпадения.
7. `low = mid + 1;` — если элемент в центре меньше искомого, то все элементы от `low` до `mid` включительно гарантированно меньше `target` (в силу возрастающей сортировки). Левая граница сдвигается за `mid`.
8. `high = mid - 1;` — если элемент в центре больше искомого, все элементы от `mid` до `high` гарантированно больше `target`. Правая граница сдвигается левее `mid`.
9. `return -1;` — если границы пересеклись (`low > high`), значит, диапазон исчерпан, элемента в массиве нет.

### Разобранный пример 1: итеративный поиск

Требуется найти индекс элемента `target = 23` в отсортированном массиве $A = [2, 5, 8, 12, 16, 23, 38, 56, 72, 91]$ с помощью итеративной функции `binarySearch`.

**Условие и входные данные:**
- Массив $A$: размер $N = 10$, индексы от $0$ до $9$.
- Содержимое: `A[0] = 2`, `A[1] = 5`, `A[2] = 8`, `A[3] = 12`, `A[4] = 16`, `A[5] = 23`, `A[6] = 38`, `A[7] = 56`, `A[8] = 72`, `A[9] = 91`.
- Искомое значение: `target = 23`.

**Рисунок словами:**
Массив представляет собой горизонтальную линейку ячеек от индекса 0 до 9, заполненную возрастающими числами. Искомое число 23 находится ближе к правой половине. На каждом шаге мы мысленно делим отрезок пополам, смотрим на центральное число и отбрасываем ту половину, где числа заведомо не могут быть равны 23.

**Ход рассуждений:**
1. Инициализируем границы: `low = 0`, `high = 9`.
2. Шаг 1: 
   - Вычисляем `mid = 0 + (9 - 0) / 2 = 4`.
   - Проверяем элемент: `A[4] = 16`.
   - Сравниваем с `target`: `16 < 23`. Значит, число 23 лежит правее индекса 4.
   - Сдвигаем левую границу: `low = mid + 1 = 5`.
3. Шаг 2:
   - Границы: `low = 5`, `high = 9`.
   - Вычисляем `mid = 5 + (9 - 5) / 2 = 5 + 2 = 7`.
   - Проверяем элемент: `A[7] = 56`.
   - Сравниваем с `target`: `56 > 23`. Значит, число 23 лежит левее индекса 7.
   - Сдвигаем правую границу: `high = mid - 1 = 6`.
4. Шаг 3:
   - Границы: `low = 5`, `high = 6`.
   - Вычисляем `mid = 5 + (6 - 5) / 2 = 5 + 0 = 5`.
   - Проверяем элемент: `A[5] = 23`.
   - Сравниваем с `target`: `23 == target`. Совпадение найдено!
   - Функция возвращает индекс `5`.

**Проверка:**
Обращение к исходному массиву показывает, что под индексом 5 действительно записано число 23 (`A[5] = 23`). Единицы измерения индекса — безразмерные целые числа. Логика шагов не нарушает границ массива.

`Ответ:` Индекс искомого элемента равен 5.

### Рекурсивный подход к двоичному поиску на C++17

Рекурсивная реализация двоичного поиска использует механизм повторного вызова самой себя с суженными границами в качестве аргументов.

> **Определение.** Рекурсивным алгоритмом двоичного поиска называется функция, которая решает задачу поиска путем вызова собственной копии для меньшего подмассива (левой или правой половины), опираясь на базовые случаи завершения рекурсии (элемент найден или границы пересеклись).

Для передачи текущих границ поиска в рекурсивную функцию необходимо передавать параметры `low` и `high` вместе с самим массивом и искомым ключом.

Рассмотрим полную структуру рекурсивной функции двоичного поиска:

```cpp
#include <vector>

// Рекурсивная функция двоичного поиска
int binarySearchRecursive(const std::vector<int>& arr, int target, int low, int high) {
    // Базовый случай 1: границы пересеклись, элемент не найден
    if (low > high) {
        return -1;
    }

    // Вычисление среднего индекса безопасным способом
    int mid = low + (high - low) / 2;

    // Базовый случай 2: элемент найден в центре
    if (arr[mid] == target) {
        return mid;
    }
    // Рекурсивный шаг 1: искомое значение меньше центрального, ищем в левой половине
    else if (arr[mid] > target) {
        return binarySearchRecursive(arr, target, low, mid - 1);
    }
    // Рекурсивный шаг 2: искомое значение больше центрального, ищем в правой половине
    else {
        return binarySearchRecursive(arr, target, mid + 1, high);
    }
}
```

Разберем структуру рекурсивной функции:
1. `if (low > high) { return -1; }` — условие выхода из рекурсии при неудачном поиске (эквивалентно завершению цикла `while` в итеративной версии).
2. `int mid = low + (high - low) / 2;` — нахождение центра текущего подмассива.
3. `if (arr[mid] == target) { return mid; }` — успешное завершение рекурсии с возвратом найденного индекса.
4. `return binarySearchRecursive(arr, target, low, mid - 1);` — вызов функции для левого поддиапазона. Обратите внимание на обязательное ключевое слово `return`, чтобы результат глубокого вызова передался наверх вызывающей стороне.
5. `return binarySearchRecursive(arr, target, mid + 1, high);` — аналогичный вызов для правого поддиапазона.

### Разобранный пример 2: рекурсивный поиск

Требуется найти элемент `target = 3` в отсортированном массиве $A = [3, 7, 11, 15, 19]$ с помощью рекурсивной функции `binarySearchRecursive`.

**Условие и входные данные:**
- Массив $A$: размер $N = 5$, индексы от $0$ до $4$.
- Содержимое: `A[0] = 3`, `A[1] = 7`, `A[2] = 11`, `A[3] = 15`, `A[4] = 19`.
- Искомое значение: `target = 3`.
- Начальные параметры границ: `low = 0`, `high = 4`.

**Рисунок словами:**
Массив содержит 5 элементов. Искомое число 3 находится на самой первой позиции (индекс 0). Рекурсивная функция будет последовательно вызывать себя, передавая новые суженные границы от главного вызова к вложенным.

**Ход рассуждений:**
1. Вызов 1: `binarySearchRecursive(A, 3, 0, 4)`
   - Проверка `0 > 4` ложна.
   - Вычисляем `mid = 0 + (4 - 0) / 2 = 2`.
   - Проверяем элемент: `A[2] = 11`.
   - Сравниваем с `target`: `11 > 3`. Ищем в левой половине.
   - Делаем вложенный вызов: `binarySearchRecursive(A, 3, 0, 2 - 1)`, то есть `low = 0`, `high = 1`.
2. Вызов 2: `binarySearchRecursive(A, 3, 0, 1)`
   - Проверка `0 > 1` ложна.
   - Вычисляем `mid = 0 + (1 - 0) / 2 = 0`.
   - Проверяем элемент: `A[0] = 3`.
   - Сравниваем с `target`: `3 == 3`. Совпадение найдено!
   - Возвращаем индекс `0`. Этот результат передается сквозь цепочку возвратов в самый первый вызов.

**Проверка:**
Элемент `A[0]` действительно равен 3. Ошибок выхода за границы не возникало, глубина рекурсии составила 2 вложенных вызова, что соответствует теоретическому логарифму $\log_2(5) \approx 2{,}32$.

`Ответ:` Индекс искомого элемента равен 0.

### Сравнение итеративного и рекурсивного подходов

Для правильного проектирования программного обеспечения на C++17 необходимо понимать аппаратные и архитектурные отличия между итеративной и рекурсивной реализациями алгоритмов.

| Характеристика | Итеративный подход (`while`) | Рекурсивный подход (`функция`) |
|---|---|---|
| **Временная сложность** | $O(\log N)$ | $O(\log N)$ |
| **Пространственная сложность** | $O(1)$ (константная память) | $O(\log N)$ (стек вызовов) |
| **Накладные расходы** | Отсутствуют | Выделение памяти под кадры стека, переходы |
| **Риск переполнения** | Отсутствует | Возможен (`Stack Overflow` при огромных $N$) |
| **Читаемость кода** | Высокая для простых циклов | Естественная для концепции «разделяй и властвуй» |

В языке C++17 итеративный подход почти всегда предпочтительнее в промышленной разработке встроенных и высокопроизводительных систем, так как он не тратит процессорное время на создание кадров стека и гарантирует отсутствие ошибок переполнения памяти при поиске в массивах с миллиардами элементов. Рекурсивный вариант полезен своей математической наглядностью и простотой записи теоретических концепций.

### Обработка краевых случаев

Надежный алгоритм должен корректно обрабатывать граничные условия, которые часто приводят к аварийному завершению программы (краху) или зацикливанию у начинающих разработчиков.

1. **Пустой массив (`arr.size() == 0`):**
   Если массив не содержит элементов, вычисление правой границы как `arr.size() - 1` вызывает переполнение типа `size_t`. Обязательная проверка `if (arr.empty()) return -1;` в самом начале функции полностью устраняет эту проблему.

2. **Массив из одного элемента (`arr.size() == 1`):**
   Пусть $A = [42]$, `target = 42`.
   - Границы: `low = 0`, `high = 0`.
   - Цикл выполняется: `mid = 0 + (0 - 0) / 2 = 0`.
   - `A[0] == 42` — совпадение найдено, возвращается индекс `0`.
   Если `target = 10` (меньше элемента):
   - `mid = 0`, `A[0] > 10`, следовательно `high = mid - 1 = -1`.
   - Условие цикла `low <= high` (`0 <= -1`) становится ложным, цикл завершается, возвращается `-1`. Алгоритм отработал корректно.

3. **Искомое значение меньше минимального элемента (`target < arr[0]`):**
   На каждом шаге центральный элемент будет больше искомого, поэтому правая граница `high` будет непрерывно смещаться влево (`high = mid - 1`), пока не станет меньше `low`. Цикл завершится, вернется `-1`.

4. **Искомое значение больше максимального элемента (`target > arr[N-1]`):**
   Центральный элемент всегда будет меньше искомого, левая граница `low` будет непрерывно смещаться вправо (`low = mid + 1`), пока не станет больше `high`. Цикл завершится, вернется `-1`.

## Модификации двоичного поиска: поиск первого и последнего вхождения

### Проблема неуникальности элементов и ограничения стандартного бинарного поиска

Классический двоичный поиск, рассмотренный в предыдущих разделах, отлично справляется с задачей поиска элемента в отсортированном массиве, если все элементы уникальны. Однако на практике часто встречаются массивы, содержащие дубликаты — одинаковые значения, расположенные на соседних позициях. 

> **Определение.** Элементы массива называются неуникальными (или повторяющимися), если существуют такие индексы $i$ и $j$ ($i \neq j$), для которых значение элемента по индексу $i$ равно значению по индексу $j$: $A[i] = A[j]$.

Если применить стандартный бинарный поиск к массиву с повторяющимися элементами, алгоритм вернет индекс **произвольного** из найденных одинаковых элементов. Момент остановки классического поиска происходит в точности тогда, когда $A[\text{mid}] = \text{target}$. Поскольку в массиве может быть несколько элементов, равных $\text{target}$, индекс $\text{mid}$ окажется любым из них — тем, который «повезло» встретить алгоритму в процессе деления отрезка пополам. 

Для решения прикладных задач такого поведения недостаточно. Рассмотрим ситуации:
1. Необходимо узнать точное количество вхождений заданного ключа в массив.
2. Требуется найти самую левую (первую) позицию, куда можно вставить новый элемент, не нарушая порядок сортировки.
3. Нужно определить диапазон индексов `[first_index, last_index]`, занимаемый конкретным значением.

Чтобы преодолеть это ограничение, классическую логику сравнения нужно изменить: вместо немедленного возврата индекса при первом совпадении $A[\text{mid}] = \text{target}$, поиск должен продолжаться в определенной половине массива.

### Алгоритм поиска первого (левого) вхождения элемента

Поставим задачу: найти индекс первого (самого левого) вхождения элемента $\text{target}$ в отсортированном по неубыванию массиве $A$. Если элемент отсутствует в массиве, алгоритм должен вернуть позицию, куда его следует вставить, чтобы порядок не нарушился (или специальный признак отсутствия).

#### Идея и логика работы
Пусть границы поиска заданы переменными $\text{low} = 0$ и $\text{high} = N - 1$ (или $\text{high} = N$, если мы работаем с полуинтервалом). На каждом шаге вычисляем средний индекс:
$$\text{mid} = \text{low} + \frac{\text{high} - \text{low}}{2}$$

Сравниваем элемент $A[\text{mid}]$ с искомым значением $\text{target}$:
1. Если $A[\text{mid}] < \text{target}$, это означает, что искомый элемент находится строго правее текущей средней точки. Сдвигаем левую границу: $\text{low} = \text{mid} + 1$.
2. Если $A[\text{mid}] \ge \text{target}$, то текущий элемент может быть либо самим искомым числом, либо числом, большим него. Но поскольку мы ищем **самое первое** вхождение, искомое число (если оно вообще есть в массиве) не может находиться правее индекса $\text{mid}$. Следовательно, мы должны сузить правую границу, сместив ее влево: $\text{high} = \text{mid}$. Обратите внимание: мы не вычитаем единицу ($\text{high} = \text{mid} - 1$), так как индекс $\text{mid}$ потенциально сам является первым вхождением.

Цикл продолжается до тех пор, пока $\text{low} < \text{high}$. Когда границы схлопнутся ($\text{low} == \text{high}$), мы получим искомый индекс первого вхождения.

#### Полный разбор примера

Рассмотрим массив $A = [1, 3, 5, 7, 7, 7, 9, 12]$ длиной $N = 8$ и искомое значение $\text{target} = 7$.

- **Инициализация:**
  - $\text{low} = 0$, $\text{high} = 7$.
  - Массив: `[1, 3, 5, 7, 7, 7, 9, 12]`
  - Индексы: ` 0  1  2  3  4  5  6   7 `

- **Шаг 1:**
  - $\text{mid} = 0 + (7 - 0) / 2 = 3$.
  - Проверяем элемент: $A[3] = 7$.
  - Условие: так как $A[3] \ge 7$ ($7 \ge 7$), сужаем правую границу: $\text{high} = \text{mid} = 3$.
  - Новые границы: $\text{low} = 0$, $\text{high} = 3$.

- **Шаг 2:**
  - $\text{mid} = 0 + (3 - 0) / 2 = 1$.
  - Проверяем элемент: $A[1] = 3$.
  - Условие: так как $A[1] < 7$ ($3 < 7$), сдвигаем левую границу: $\text{low} = \text{mid} + 1 = 2$.
  - Новые границы: $\text{low} = 2$, $\text{high} = 3$.

- **Шаг 3:**
  - $\text{mid} = 2 + (3 - 2) / 2 = 2$.
  - Проверяем элемент: $A[2] = 5$.
  - Условие: так как $A[2] < 7$ ($5 < 7$), сдвигаем левую границу: $\text{low} = \text{mid} + 1 = 3$.
  - Новые границы: $\text{low} = 3$, $\text{high} = 3$.

Цикл завершается, так как условие $\text{low} < \text{high}$ больше не выполняется ($\text{3} < \text{3}$ — ложь). Значение $\text{low} = 3$. Проверяем элемент $A[3] == 7$. Он действительно равен 7.

`Ответ:` Индекс первого вхождения числа 7 равен $3$.

### Алгоритм поиска последнего (правого) вхождения элемента

Поставим задачу: найти индекс последнего (самого правого) вхождения элемента $\text{target}$ в отсортированном массиве $A$.

#### Идея и логика работы
Для поиска последнего вхождения логика зеркально отражается. Снова вычисляем $\text{mid} = \text{low} + (\text{high} - \text{low}) / 2$, но сравнения строятся следующим образом:
1. Если $A[\text{mid}] \le \text{target}$, текущий элемент равен искомому или меньше его. Поскольку мы ищем последнее вхождение, левее или на позиции $\text{mid}$ могут находиться другие такие же элементы. Поэтому мы смещаем левую границу сюда: $\text{low} = \text{mid}$.
2. Если $A[\text{mid}] > \text{target}$, элемент строго больше искомого, значит, искомое число находится левее. Смещаем правую границу: $\text{high} = \text{mid} - 1$.

Однако здесь кроется важная техническая особенность реализации на языке C++. При делении целых чисел округление происходит в меньшую сторону (к нулю). Если границы сошлись так, что $\text{high} = \text{low} + 1$, то вычисление $\text{mid} = \text{low} + (\text{high} - \text{low}) / 2$ даст $\text{mid} = \text{low}$. Если в этом случае сработает условие $A[\text{mid}] \le \text{target}$ и мы выполним присваивание $\text{low} = \text{mid}$, то значение $\text{low}$ не изменится, что приведет к **бесконечному циклу**.

Чтобы этого избежать при поиске последнего вхождения, средний индекс вычисляют с округлением вверх:
$$\text{mid} = \text{low} + \frac{\text{high} - \text{low} + 1}{2}$$
Добавление единицы к числителю гарантирует, что при $\text{high} = \text{low} + 1$ значение $\text{mid}$ будет равно $\text{high}$, что позволит успешно сдвинуть левую границу и завершить цикл.

### Полный разобранный пример: поиск диапазона индексов

Решим комплексную задачу: найти диапазон индексов (первое и последнее вхождение) числа $\text{target} = 4$ в массиве $B = [2, 4, 4, 4, 4, 8, 10]$ длиной $N = 7$.

#### Шаг А: Поиск первого вхождения (левая граница)
Инициализация: $\text{low} = 0$, $\text{high} = 6$. Искомое: $\text{target} = 4$.

1. $\text{mid} = 0 + (6 - 0) / 2 = 3$. $B[3] = 4$. Так как $4 \ge 4$, $\text{high} = 3$. (Границы: $0 \dots 3$)
2. $\text{mid} = 0 + (3 - 0) / 2 = 1$. $B[1] = 4$. Так как $4 \ge 4$, $\text{high} = 1$. (Границы: $0 \dots 1$)
3. $\text{mid} = 0 + (1 - 0) / 2 = 0$. $B[0] = 2$. Так как $2 < 4$, $\text{low} = 0 + 1 = 1$. (Границы: $1 \dots 1$)

Цикл завершен ($\text{low} == \text{high} == 1$). Проверяем: $B[1] == 4$. 
Первое вхождение обнаружено по индексу $\text{first} = 1$.

#### Шаг Б: Поиск последнего вхождения (правая граница)
Инициализация: $\text{low} = 0$, $\text{high} = 6$. Искомое: $\text{target} = 4$. Используем формулу с округлением вверх.

1. $\text{mid} = 0 + (6 - 0 + 1) / 2 = 3$. $B[3] = 4$. Так как $4 \le 4$, $\text{low} = 3$. (Границы: $3 \dots 6$)
2. $\text{mid} = 3 + (6 - 3 + 1) / 2 = 3 + 2 = 5$. $B[5] = 8$. Так как $8 > 4$, $\text{high} = 5 - 1 = 4$. (Границы: $3 \dots 4$)
3. $\text{mid} = 3 + (4 - 3 + 1) / 2 = 3 + 1 = 4$. $B[4] = 4$. Так как $4 \le 4$, $\text{low} = 4$. (Границы: $4 \dots 4$)

Цикл завершен ($\text{low} == \text{high} == 4$). Проверяем: $B[4] == 4$.
Последнее вхождение обнаружено по индексу $\text{last} = 4$.

`Ответ:` Диапазон индексов числа 4 в массиве $B$ составляет от $1$ до $4$ включительно. Количество вхождений равно $4 - 1 + 1 = 4$.

### Соответствие стандартным функциям C++ (`std::lower_bound` и `std::upper_bound`)

Стандартная библиотека шаблонов (STL) языка C++ в заголовочном файле `<algorithm>` содержит готовые высокоэффективные реализации этих алгоритмов. В учебных и производственных задачах крайне рекомендуется использовать их вместо написания собственных велосипедов.

1. `std::lower_bound(first, last, value)` — возвращает итератор на **первый** элемент, который *не меньше* (то есть $\ge$), чем заданное значение `value`. Эквивалентен описанному выше алгоритму поиска левой границы.
2. `std::upper_bound(first, last, value)` — возвращает итератор на **первый** элемент, который *строго больше* (то есть $>$), чем заданное значение `value`. Чтобы получить индекс последнего вхождения равного элемента, из результата `std::upper_bound` необходимо вычесть единицу (при условии, что элемент присутствует в массиве).

Ниже приведена полная программа на C++17, демонстрирующая ручную реализацию модифицированного бинарного поиска и ее сопоставление со стандартными функциями STL.

```cpp
#include <iostream>
#include <vector>
#include <algorithm>

// Функция поиска первого вхождения (ручная реализация)
int findFirstOccurrence(const std::vector<int>& arr, int target) {
    int low = 0;
    int high = static_cast<int>(arr.size()) - 1;
    int result = -1;

    while (low <= high) {
        int mid = low + (high - low) / 2;
        if (arr[mid] >= target) {
            if (arr[mid] == target) {
                result = mid; // Запоминаем кандидат на ответ
            }
            high = mid - 1;   // Продолжаем искать левее
        } else {
            low = mid + 1;    // Искомое значение правее
        }
    }
    return result;
}

// Функция поиска последнего вхождения (ручная реализация)
int findLastOccurrence(const std::vector<int>& arr, int target) {
    int low = 0;
    int high = static_cast<int>(arr.size()) - 1;
    int result = -1;

    while (low <= high) {
        int mid = low + (high - low) / 2;
        if (arr[mid] <= target) {
            if (arr[mid] == target) {
                result = mid; // Запоминаем кандидат на ответ
            }
            low = mid + 1;    // Продолжаем искать правее
        } else {
            high = mid - 1;   // Искомое значение левее
        }
    }
    return result;
}

int main() {
    // Настройка локали для корректного вывода на русском языке
    std::ios_base::sync_with_stdio(false);
    std::cin.tie(nullptr);

    std::vector<int> B = {2, 4, 4, 4, 4, 8, 10};
    int target = 4;

    std::cout << "Массив: ";
    for (int x : B) {
        std::cout << x << " ";
    }
    std::cout << "\nИскомое значение: " << target << "\n\n";

    // Ручная проверка
    int manualFirst = findFirstOccurrence(B, target);
    int manualLast = findLastOccurrence(B, target);

    std::cout << "[Ручная реализация]\n";
    std::cout << "Первое вхождение (индекс): " << manualFirst << "\n";
    std::cout << "Последнее вхождение (индекс): " << manualLast << "\n\n";

    // Проверка с использованием стандартных функций STL (<algorithm>)
    // std::lower_bound возвращает итератор, преобразуем его в индекс через вычитание begin()
    auto lb_it = std::lower_bound(B.begin(), B.end(), target);
    // std::upper_bound возвращает итератор на элемент, строго больший target
    auto ub_it = std::upper_bound(B.begin(), B.end(), target);

    int stlFirst = (lb_it != B.end() && *lb_it == target) ? static_cast<int>(std::distance(B.begin(), lb_it)) : -1;
    // Последнее вхождение находится на позиции (upper_bound - 1)
    int stlLast = (lb_it != ub_it) ? static_cast<int>(std::distance(B.begin(), ub_it)) - 1 : -1;

    std::cout << "[Стандартная библиотека STL]\n";
    std::cout << "std::lower_bound индекс: " << stlFirst << "\n";
    std::cout << "std::upper_bound связанный индекс: " << stlLast << "\n";

    return 0;
}
```

#### Пояснение к коду и оценка сложности
- В функциях `findFirstOccurrence` и `findLastOccurrence` используется классический цикл `while (low <= high)`, внутри которого область поиска сокращается ровно в два раза на каждой итерации.
- **Временная сложность:** $\mathcal{O}(\log N)$, где $N$ — количество элементов в векторе `arr`. Количество шагов поиска не превышает $\lfloor\log_2 N\rfloor + 1$.
- **Пространственная сложность:** $\mathcal{O}(1)$, так как для хранения границ и промежуточного индекса выделяется фиксированное число ячеек памяти независимо от размера входных данных.

### Проектирование консольного приложения на C++17

Для закрепления теоретических знаний и практической проверки эффективности алгоритмов поиска необходимо разработать единое консольное приложение на языке C++17. Это приложение будет включать в себя реализации последовательного (линейного) поиска, итеративного двоичного поиска, а также модуль генерации тестовых данных и точного измерения времени выполнения с использованием стандартной библиотеки `<chrono>`.

Перед написанием кода спроектируем архитектуру программы. Нам понадобятся следующие компоненты:
1. Функция линейного поиска `linearSearch`, возвращающая индекс найденного элемента или `-1` в случае его отсутствия.
2. Функция двоичного поиска `binarySearch`, работающая с предварительно отсортированным вектором.

5. Блок обработки ошибочных и краевых входных данных (пустые массивы, некорректные диапазоны).

Для работы с высокоточными таймерами в C++17 используется заголовочный файл `<chrono>`. Измерение времени происходит следующим образом: фиксируется начальная точка с помощью `std::chrono::high_resolution_clock::now()`, выполняется исследуемый алгоритм, фиксируется конечная точка, после чего вычисляется разница между ними.

### Полная реализация программы на C++17

Ниже представлен полностью компилируемый исходный код программы, объединяющий все требования лабораторной работы. Сохраните этот код в файл с именем `search_benchmark.cpp` и скомпилируйте с помощью команды: `g++ -std=c++17 -Wall search_benchmark.cpp -o search_benchmark`.

```cpp
#include <iostream>
#include <vector>
#include <algorithm>
#include <chrono>
#include <random>
#include <stdexcept>

// Линейный поиск в векторе целых чисел.
// Сложность по времени: O(N), сложность по памяти: O(1).
int linearSearch(const std::vector<int>& arr, int target) {
    for (size_int_t i = 0; i < arr.size(); ++i) {
        if (arr[i] == target) {
            return static_cast<int>(i);
        }
    }
    return -1;
}

// Итеративный двоичный поиск в отсортированном векторе целых чисел.
// Сложность по времени: O(log N), сложность по памяти: O(1).
int binarySearch(const std::vector<int>& arr, int target) {
    if (arr.empty()) {
        return -1;
    }

    int low = 0;
    int high = static_cast<int>(arr.size()) - 1;

    while (low <= high) {
        // Предотвращение арифметического перепереполнения
        int mid = low + (high - low) / 2;

        if (arr[mid] == target) {
            return mid;
        } else if (arr[mid] < target) {
            low = mid + 1;
        } else {
            high = mid - 1;
        }
    }

    return -1;
}

// Функция генерации отсортированного вектора уникальных или возрастающих чисел
std::vector<int> generateSortedVector(size_t size, int step_min = 1, int step_max = 5) {
    std::vector<int> arr;
    arr.reserve(size);
    
    std::random_device rd;
    std::mt19937 gen(rd());
    std::uniform_int_distribution<int> dist(step_min, step_max);

    int current_val = 0;
    for (size_t i = 0; i < size; ++i) {
        current_val += dist(gen);
        arr.push_back(current_val);
    }

    return arr;
}

// Функция демонстрации работы с краевыми и некорректными данными
void runEdgeCasesTests() {
    std::cout << "=== Запуск тестов для краевых случаев ===" << std::endl;

    std::vector<int> empty_arr;
    int target = 10;

    // Проверка пустого массива
    int lin_res = linearSearch(empty_arr, target);
    int bin_res = binarySearch(empty_arr, target);

    std::cout << "Пустой массив []. Линейный поиск вернул: " << lin_res << std::endl;
    std::cout << "Пустой массив []. Двоичный поиск вернул: " << bin_res << std::endl;

    // Проверка массива с отрицательными числами
    std::vector<int> negative_arr = {-45, -23, -12, -5, 0, 3, 15};
    int neg_target = -12;
    int neg_res = binarySearch(negative_arr, neg_target);
    std::cout << "Массив с отрицательными числами. Поиск -12, индекс: " << neg_res << std::endl;
```

### Разбор работы программы и пояснение по строкам

1. **Функция `linearSearch`**: Принимает константную ссылку на вектор `const std::vector<int>& arr` и искомое значение `target`. Цикл `for` последовательно проверяет каждый элемент. 2. **Функция `binarySearch`**: Реализует классический итеративный бинарный поиск. В начале проверяется условие `arr.empty()` для предотвращения попыток доступа к памяти пустого контейнера. 4. **Замер времени**: `std::chrono::high_resolution_clock::now()` возвращает текущую метку времени системного таймера высокой точности. ### Анализ временной сложности: $O(N)$ против $O(\log N)$

Сравнение результатов выполнения программы наглядно демонстрирует фундаментальную разницу между линейным и двоичным поиском на больших объемах данных ($N = 1\,000\,000$).

| Характеристика | Линейный поиск (`linearSearch`) | Двоичный поиск (`binarySearch`) |
|---|---|---|
| **Требования к данным** | Несортированные или отсортированные | Строго отсортированные данные |
| **Временная сложность (худший случай)** | $O(N)$ | $O(\log N)$ |
| **Временная сложность (лучший случай)** | $O(1)$ (элемент на первом месте) | $O(1)$ (элемент ровно посередине) |
| **Пространственная сложность** | $O(1)$ | $O(1)$ (итеративная версия) |
| **Число операций при $N = 1\,000\,000$** | До $1\,000\,000$ сравнений | Не более $\log_2(1\,000\,000) \approx 20$ сравнений |

Математическое обоснование этой разницы заключается в скорости роста функций. Для массива из $1\,000\,000$ элементов линейный поиск в худшем случае совершает миллион итераций цикла. Двоичный поиск на каждом шаге делит область поиска пополам. Число шагов $k$, за которое отрезок длины $N$ уменьшится до единицы, определяется уравнением:

$$2^k = N \implies k = \log_2 N$$

Для $N = 1\,000\,000$:

$$\log_2(1\,000\,000) \approx 19{,}93$$

Это означает, что двоичный поиск выполнит **не более 20 сравнений** даже в самом худшем случае, в то время как линейный поиск может сделать миллион сравнений. Именно поэтому на выводе программы время линейного поиска измеряется в миллисекундах, а двоичного — в долях микросекунды.

### Типичные ошибки реализации и их предотвращение

При самостоятельной реализации алгоритмов поиска студенты часто совершают типичные ошибки, приводящие к логическим сбоям, зависаниям или аварийному завершению программы:

1. **Бесконечный цикл при обновлении границ**:
   Если в двоичном поиске написать `low = mid` вместо `low = mid + 1` (когда `arr[mid] < target`), программа может зациклиться. Если в процессе поиска останется два элемента с индексами `low` и `low + 1`, то вычисление `mid = low + (low + 1 - low) / 2` даст `mid = low`. Если условие `arr[mid] < target` истинно, то инструкция `low = mid` присвоит переменной `low` прежнее значение. Границы перестанут сужаться, и цикл `while (low <= high)` станет бесконечным.
   *Правило:* всегда смещайте границы за пределы проверенного элемента: `low = mid + 1` или `high = mid - 1`.

2. **Арифмитическое переполнение при вычислении среднего индекса**:
   Использование простой формулы `int mid = (low + high) / 2;` приводит к ошибке переподнения знакового целого типа (`signed integer overflow`), если сумма `low + high` превышает максимальное значение типа `int` (примерно $2 \cdot 10^9$). В языке C++ такое переполнение вызывает неопределенное поведение (`undefined behavior`).
   *Правило:* всегда используйте безопасную формулу:
   $$ \text{mid} = \text{low} + \frac{\text{high} - \text{low}}{2} $$

3. **Выход за границы массива (Index Out of Bounds)**:
   Попытка обратиться к элементу по индексу, равному размеру вектора (`arr[arr.size()]`), или передача некорректных начальных границ (`high` больше либо равен размеру массива).
   *Правило:* всегда проверяйте массив на пустоту (`arr.empty()`) перед вычислением границ, а инициализацию правой границы выполняйте строго как `int high = static_cast<int>(arr.size()) - 1;`.

## Типичные ошибки

1. **Бесконечный цикл из-за неправильного сдвига границ (`low = mid` вместо `low = mid + 1`).**
   - *Почему возникает:* Разработчик забывает, что элемент по индексу `mid` уже проверен и не равен искомому значению. Оставляя `low = mid`, в ситуации с двумя оставшимися соседними элементами можно получить `mid == low`, из-за чего границы перестают изменяться, и цикл `while (low <= high)` зависает.
   - *Как избежать:* Всегда исключайте проверенный индекс из дальнейшего поиска: `low = mid + 1` или `high = mid - 1`.
   - *Пример:* `while (low <= high) { int mid = low + (high - low) / 2; if (arr[mid] < target) low = mid; /* Ошибка! */ else high = mid - 1; }`

2. **Арифметическое переполнение при вычислении центрального индекса (`(low + high) / 2`).**
   - *Почему возникает:* Студент использует классическую школьную формулу среднего арифметического. Если индексы `low` и `high` велики (например, в массиве из 2 миллиардов элементов), их сумма превышает максимальное значение 32-битного знакового типа `int` ($2\,147\,483\,647$), вызывая неопределенное поведение.
   - *Как избежать:* Использовать безопасную формулу смещения: `int mid = low + (high - low) / 2;`.
   - *Пример:* `int mid = (2000000000 + 2100000000) / 2;` приведёт к переполнению и получению отрицательного индекса.

3. **Применение двоичного поиска к несортированному массиву.**
   - *Почему возникает:* Желание ускорить поиск без предварительной проверки или сортировки структуры данных.
   - *Как избежать:* Помнить главное теоретическое требование двоичного поиска: массив обязан быть отсортирован по неубыванию или невозрастанию. Если данные поступают динамически, используйте структуры данных с автоматической сортировкой (например, `std::set`, `std::map`) или сортируйте вектор перед поиском (`std::sort`).
   - *Пример:* `std::vector<int> v = {5, 1, 4, 2}; binarySearch(v, 4);` вернет непредсказуемый результат.

4. **Игнорирование проверки пустого массива (`arr.empty()`).**
   - *Почему возникает:* Отсутствие защитных проверок в начале функции поиска.
   - *Как избежать:* Всегда проверять контейнер на пустоту перед инициализацией правой границы `high = arr.size() - 1`. Для беззнакового типа `size_t` вычисление `0 - 1` превратится в огромное положительное число `18446744073709551615`, что сразу вызовет `segmentation fault`.
   - *Пример:* `int high = arr.size() - 1;` при `arr.size() == 0` приводит к краху программы.

5. **Некорректное сравнение знаковых и беззнаковых типов (`int` и `size_t`).**
   - *Почему возникает:* Сравнение переменной цикла типа `int` с результатом `arr.size()`, возвращающим беззнаковый тип `size_t`.
   - *Как избежать:* Явно преобразовывать размер контейнера к знаковому типу с помощью `static_cast<int>(arr.size())`.
   - *Пример:* `for (int i = 0; i < arr.size(); ++i)` в условиях неявного приведения типов может вызывать предупреждения компилятора и логические сбои при отрицательных индексах.

6. **Ошибки при поиске последнего вхождения (зависание алгоритма).**
   - *Почему возникает:* При поиске правой границы с использованием формулы `mid = low + (high - low) / 2` целочисленное деление округляет вниз. Когда `high = low + 1`, `mid` становится равным `low`, и если условие `arr[mid] <= target` истинно, присваивание `low = mid` не меняет границу.
   - *Как избежать:* Для поиска последнего вхождения вычислять средний индекс с округлением вверх: `int mid = low + (high - low + 1) / 2;`.

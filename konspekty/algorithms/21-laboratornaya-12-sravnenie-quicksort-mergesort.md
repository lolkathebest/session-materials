## 1. Теоретические основы и сравнительный анализ алгоритмов сортировки

### 1. Теоретические основы и сравнительный анализ алгоритмов сортировки

Сортировка данных — одна из фундаментальных задач в информатике. Эффективность работы многих сложных систем (баз данных, поисковых индексов, систем геопозиционирования) напрямую зависит от того, насколько быстро и рационально упорядочены хранящиеся в них элементы.

> **Определение.** Задача сортировки заключается в переупорядочении заданного набора элементов (массива, списка) в соответствии с определенным линейным порядком (обычно по неубыванию или невозрастанию ключей).

Формально пусть на входе имеется массив элементов $A = [a_1, a_2, \dots, a_n]$. Требуется получить переставленный массив $A' = [a'_1, a'_2, \dots, a'_n]$ такой, что $a'_1 \le a'_2 \le \dots \le a'_n$, причем $A'$ состоит из тех же элементов, что и $A$.

При выборе алгоритма сортировки для конкретной практической задачи инженеры руководствуются следующими ключевыми критериями:
1. **Временная сложность** — оценка того, как быстро растет время работы алгоритма при увеличении количества элементов $n$. Различают оценки для худшего ($O$), среднего ($\Theta$) и лучшего ($\Omega$) случаев.
2. **Пространственная сложность** — объем дополнительной оперативной памяти, требуемой алгоритму помимо той, которую занимает исходный массив. Если алгоритм сортирует данные «на месте» (in-place), его пространственная сложность составляет $O(1)$.
3. **Устойчивость (stability)** — сохранение относительного порядка элементов с одинаковыми ключами.

---

### Свойство устойчивости (stability) сортировки

> **Определение.** Алгоритм сортировки называется **устойчивым** (stable), если он гарантирует сохранение исходного относительного порядка элементов, обладающих равными ключами.

Пусть в исходном массиве есть элементы с одинаковыми значениями, причем элемент $x_i$ стоял левее элемента $x_j$, и их ключи равны ($key(x_i) = key(x_j)$). Если после завершения сортировки элемент $x_i$ гарантированно останется левее $x_j$, то алгоритм устойчив.

#### Практическое значение
Устойчивость критически важна при многокритериальной сортировке. Например, у вас есть список студентов, уже отсортированный по фамилиям. Вы хотите отсортировать его по баллам за экзамен. Если алгоритм сортировки по баллам устойчив, то студенты с одинаковыми баллами останутся отсортированными по фамилиям. Если алгоритм неустойчив, этот алфавитный порядок нарушится.

#### Проверка рассматриваемых алгоритмов:
* **Insertion Sort (Сортировка вставками):** Устойчива. Когда элемент сравнивается с элементами слева, сдвиг вправо происходит только для элементов, строго больших вставляемого. Равные элементы не переставляются местами, их относительный порядок сохраняется.
* **Merge Sort (Сортировка слиянием):** Устойчива. В процедуре слияния двух подмассивов, при обнаружении равных элементов из левого и правого подмассивов, предпочтение отдается элементу из левого подмассива, что сохраняет исходный порядок.
* **Quick Sort (Быстрая сортировка):** Неустойчива. В процессе разбиения массива (partition) элементы переставляются на большие расстояния друг от друга без учета их исходного относительного положения.

---

### Сортировка вставками (Insertion Sort)

Идея алгоритма интуитивно понятна каждому, кто когда-либо раскладывал карты в руке: мы поддерживаем правую границу для еще не отсортированной части и левую — для уже отсортированной. На каждом шаге мы берем первый элемент из несортированной части («текущий элемент») и находим ему правильное место в отсортированной части, сдвигая элементы вправо.

#### Алгоритм по шагам:
1. Считаем первый элемент массива (индекс $0$) уже отсортированной последовательностью длины 1.
2. Цикл по индексу $i$ от $1$ до $n-1$:
   * Сохраняем значение текущего элемента в переменной `key = A[i]`.
   * Заводим вспомогательный индекс `j = i - 1`.
   * Пока `j >= 0` и элемент `A[j] > key`, сдвигаем его вправо: `A[j + 1] = A[j]`, и уменьшаем `j` на 1.
   * Как только условие нарушилось, вставляем сохраненный `key` на освободившуюся позицию `A[j + 1]`.

#### Анализ сложности:
* **Лучший случай ($\Omega(n)$):** Массив уже отсортирован. Внутренний цикл ` mientras` (while) не выполняет ни одного сдвига, так как `A[j] <= key` выполняется сразу. Время линейно.
* **Худший случай ($O(n^2)$):** Массив отсортирован в обратном порядке. На каждом шаге $i$ текущий элемент приходится сравнивать и сдвигать через все $i$ предшествующих элементов.
* **Средний случай ($O(n^2)$):** В среднем элементы смещаются на половину длины отсортированной части.
* **Пространственная сложность:** $O(1)$, так как сортировка происходит на месте.

### Разобранный пример 1: Сортировка вставками

**Условие:** Требуется проследить работу алгоритма Insertion Sort для массива $A = [5, 2, 4, 1, 3]$. Рассчитать количество сравнений и пересылок (сдвигов) элементов на каждом шаге внешнего цикла.

#### Ход рассуждений:
Внешний цикл идет от $i = 1$ до $n-1$ (где $n = 5$). 
* Сравнение — это проверка условия в цикле (`A[j] > key`).
* Пересылка — это операция присваивания (`A[j + 1] = A[j]` или `A[j + 1] = key`).

#### Решение в общем виде и по шагам:

**Начальное состояние:** `[5, 2, 4, 1, 3]`. Отсортированная часть: `[5]`.

* **Шаг 1 ($i = 1$):** `key = A[1] = 2`, `j = 0`.
  * Сравнение 1: `A[0] (5) > 2` (истинно). Сдвиг 1: `A[1] = 5`. Получаем `[5, 5, 4, 1, 3]`, `j = -1`.
  * Цикл завершен. Вставка: `A[0] = 2`. Пересылка 2: запись `key`.
  * Итог шага: `[2, 5, 4, 1, 3]`.
  * *Статистика шага:* 1 сравнение, 2 пересылки.

* **Шаг 2 ($i = 2$):** `key = A[2] = 4`, `j = 1`.
  * Сравнение 1: `A[1] (5) > 4` (истинно). Сдвиг 1: `A[2] = 5`. Получаем `[2, 5, 5, 1, 3]`, `j = 0`.
  * Сравнение 2: `A[0] (2) > 4` (ложно). Цикл завершен.
  * Вставка: `A[1] = 4`. Пересылка 2: запись `key`.
  * Итог шага: `[2, 4, 5, 1, 3]`.
  * *Статистика шага:* 2 сравнения, 2 пересылки.

* **Шаг 3 ($i = 3$):** `key = A[3] = 1`, `j = 2`.
  * Сравнение 1: `A[2] (5) > 1` (истинно). Сдвиг 1: `A[3] = 5`. `[2, 4, 5, 5, 3]`, `j = 1`.
  * Сравнение 2: `A[1] (4) > 1` (истинно). Сдвиг 2: `A[4] = 4` (в контексте индексации массива). `[2, 4, 4, 5, 3]`, `j = 0`.
  * Сравнение 3: `A[0] (2) > 1` (истинно). Сдвиг 3: `A[1] = 2`. `[2, 2, 4, 5, 3]`, `j = -1`.
  * Цикл завершен. Вставка: `A[0] = 1`. Пересылка 4: запись `key`.
  * Итог шага: `[1, 2, 4, 5, 3]`.
  * *Статистика шага:* 3 сравнения, 4 пересылки.

* **Шаг 4 ($i = 4$):** `key = A[4] = 3`, `j = 3`.
  * Сравнение 1: `A[3] (5) > 3` (истинно). Сдвиг 1: `A[4] = 5`. `[1, 2, 4, 5, 5]`, `j = 2`.
  * Сравнение 2: `A[2] (4) > 3` (истинно). Сдвиг 2: `A[3] = 4`. `[1, 2, 4, 4, 5]`, `j = 1`.
  * Сравнение 3: `A[1] (2) > 3` (ложно). Цикл завершен.
  * Вставка: `A[2] = 3`. Пересылка 3: запись `key`.
  * Итог шага: `[1, 2, 3, 4, 5]`.
  * *Статистика шага:* 2 сравнения, 3 пересылки.

#### Проверка и суммарные итоги:
Общее количество сравнений: $1 + 2 + 3 + 2 = 8$.
Общее количество пересылок: $2 + 2 + 4 + 3 = 11$.
Массив полностью отсортирован корректно. Ответ правдоподобен.

> **Ответ:** Общее число сравнений: 8, общее число пересылок: 11; отсортированный массив: `[1, 2, 3, 4, 5]`.

### Сортировка слиянием (Merge Sort)

Алгоритм основан на парадигме **«разделяй и властвуй»** (divide and conquer). 

#### Идея алгоритма:
1. Если длина массива равна 0 или 1, он считается отсортированным. Возвращаем его.
2. Исходный массив делим пополам на две примерно равные части.
3. Рекурсивно применяем сортировку слиянием к каждой из двух частей.
4. Объединяем (сливаем) два полученных отсортированных подмассива в один большой отсортированный массив с помощью вспомогательной процедуры.

#### Анализ сложности:
* **Временная сложность во всех случаях (лучший, средний, худший):** $\Theta(n \log n)$. Это объясняется тем, что дерево рекурсии имеет глубину $\log_2 n$, а на каждом уровне дерева выполняется линейная работа по слиянию элементов общей длиной $n$.
* **Пространственная сложность:** $O(n)$. Алгоритму требуется дополнительная память под временные буферы для слияния подмассивов (если не используются сложные оптимизации со слиянием на месте).

### Быстрая сортировка (Quick Sort)

Также использует парадигму «разделяй и властвуй», но упор делается на этап разделения.

#### Идея алгоритма:
1. Выбирается опорный элемент (pivot) $x$ из массива.
2. Процедура **partition** (разделение) переупорядочивает массив так, что все элементы, меньшие либо равные опорному, оказываются слева от него, а все элементы, большие — справа. Сам опорный элемент встает на свое окончательное место.
3. Рекурсивно вызывается быстрая сортировка для левой и правой частей относительно опорного элемента.

#### Схемы разделения (Partition):
* **Схема Ломуто:** Использует один индекс для сканирования и один для отслеживания границы элементов, меньших опорного. Опорным обычно выбирают последний элемент.
* **Схема Хоара:** Использует два указателя, движущихся навстречу друг другу от границ массива до тех пор, пока они не найдут элементы, нарушающие порядок относительно опорного (выбираемого обычно посередине), после чего эти элементы меняются местами. Схема Хоара эффективнее схемы Ломуто, так как совершает в среднем в 3 раза меньше пересылок.

#### Анализ сложности:
* **Лучший и средний случаи:** $\Theta(n \log n)$. Достигается, когда опорный элемент делит массив примерно пополам.
* **Худший случай:** $O(n^2)$. Происходит, когда опорный элемент оказывается минимальным или максимальным (например, массив уже отсортирован, а опорным берут первый или последний элемент).
* **Пространственная сложность:** $O(\log n)$ в среднем на хранение стека рекурсивных вызовов.

### Разобранный пример 2: Разделение по схеме Ломуто

**Условие:** Показать по шагам разделение массива $A = [7, 2, 1, 6, 8, 5, 3, 4]$ с опорным элементом (pivot), равным последнему элементу $4$, по схеме Ломуто.

#### Ход рассуждений по схеме Ломуто:
* Опорный элемент: `pivot = A[high] = 4` (где `high = 7`, значение 4).
* Заведем индекс границы `i = low - 1` (начинаем с `-1`). Индекс `i` указывает на границу элементов, меньших или равных `pivot`.
* Запустим цикл по индексу `j` от `low` до `high - 1` (от 0 до 6).
* Если `A[j] <= pivot`, то инкрементируем `i` (`i++`) и меняем местами `A[i]` и `A[j]`.
* В конце цикла ставим опорный элемент на его законное место: меняем местами `A[i + 1]` и `A[high]`. Возвращаем индекс `i + 1`.

#### Решение по шагам:
Исходный массив: `[7, 2, 1, 6, 8, 5, 3, 4]`, `pivot = 4`, `i = -1`.

* **Шаг $j = 0$:** `A[0] = 7`. Сравниваем: `7 <= 4` (ложно). Ничего не делаем.
  * Массив: `[7, 2, 1, 6, 8, 5, 3, 4]`, `i = -1`.
* **Шаг $j = 1$:** `A[1] = 2`. Сравниваем: `2 <= 4` (истинно). 
  * Увеличиваем `i` до `0`. Меняем `A[0]` и `A[1]`.
  * Массив: `[2, 7, 1, 6, 8, 5, 3, 4]`, `i = 0`.
* **Шаг $j = 2$:** `A[2] = 1`. Сравниваем: `1 <= 4` (истинно).
  * Увеличиваем `i` до `1`. Меняем `A[1]` и `A[2]`.
  * Массив: `[2, 1, 7, 6, 8, 5, 3, 4]`, `i = 1`.
* **Шаг $j = 3$:** `A[3] = 6`. Сравниваем: `6 <= 4` (ложно). Ничего не делаем.
  * Массив: `[2, 1, 7, 6, 8, 5, 3, 4]`, `i = 1`.
* **Шаг $j = 4$:** `A[4] = 8`. Сравниваем: `8 <= 4` (ложно). Ничего не делаем.
  * Массив: `[2, 1, 7, 6, 8, 5, 3, 4]`, `i = 1`.
* **Шаг $j = 5$:** `A[5] = 5`. Сравниваем: `5 <= 4` (ложно). Ничего не делаем.
  * Массив: `[2, 1, 7, 6, 8, 5, 3, 4]`, `i = 1`.
* **Шаг $j = 6$:** `A[6] = 3`. Сравниваем: `3 <= 4` (истинно).
  * Увеличиваем `i` до `2`. Меняем `A[2]` и `A[6]`.
  * Массив: `[2, 1, 3, 6, 8, 5, 7, 4]`, `i = 2`.

Завершение цикла. Ставим опорный элемент (`A[high] = 4`, находящийся на позиции 7) на правильную позицию `i + 1 = 3`. Меняем `A[3]` и `A[7]`.
* Массив после финального обмена: `[2, 1, 3, 4, 8, 5, 7, 6]`.
* Опорный элемент 4 занял индекс 3. Слева от него находятся элементы `[2, 1, 3]` (все $\le 4$), справа — `[8, 5, 7, 6]` (все $> 4$).

> **Ответ:** Результирующий массив после раздела: `[2, 1, 3, 4, 8, 5, 7, 6]`, индекс опорного элемента: 3.

### Теоретические ограничения на алгоритмы сортировки на основе сравнений

Важнейший теоретический результат в теории алгоритмов доказывает, что ни один алгоритм сортировки, основанный на парных сравнениях элементов, не может работать быстрее, чем за $O(n \log n)$ операций в худшем случае.

#### Доказательство через дерево решений:
Любой алгоритм сортировки на основе сравнений можно представить в виде бинарного дерева решений.
1. Каждый узел дерева соответствует одному сравнению двух элементов: $a_i \le a_j$.
2. У каждого узла есть два дочерних ответа: «да» (истинно) и «нет» (ложно).
3. Листья дерева соответствуют всем возможным результатам работы алгоритма — а именно, всем возможным перестановкам (пермутациям) исходного массива.

Для массива из $n$ элементов существует ровно $n!$ ($n$ факториал) различных возможных исходных перестановок. Следовательно, дерево решений обязано содержать не менее $n!$ листьев.

Пусть глубина дерева (высота) равна $h$. Бинарное дерево высоты $h$ может содержать не более $2^h$ листьев. Отсюда получаем неравенство:
$$2^h \ge n!$$

Прологарифмируем обе части по основанию 2:
$$h \ge \log_2(n!)$$

Воспользуемся формулой Стирлинга для приближения факториала при больших $n$: $\ln(n!) \approx n \ln n - n$, следовательно, $\log_2(n!) \approx n \log_2 n$.
Таким образом, высота дерева решений (минимально возможное число сравнений в худшем случае) оценивается как:
$$h = \Omega(n \log_2 n)$$

Это означает, что построить универсальный алгоритм сортировки на основе сравнений с асимптотикой лучше, чем $O(n \log n)$, в общем случае математически невозможно.

## 2. Генерация тестовых данных и методика бенчмаркинга

### Необходимость эмпирического тестирования и ограничения O-нотации

Асимптотический анализ в рамках $O$-нотации (например, $\mathcal{O}(n \log n)$ для быстрой сортировки или $\mathcal{O}(n^2)$ для сортировки вставками) описывает то, как ведет себя время выполнения алгоритма при стремлении размера входных данных $n$ к бесконечности. Теория отбрасывает константы и младшие члены, что позволяет абстрагироваться от характеристик конкретного процессора. Однако при написании реального программного обеспечения чистая теория часто расходится с практикой. 

Рассмотрим ключевые причины, по которым эмпирическое тестирование (бенчмаркинг) является обязательным этапом проектирования алгоритмов:

1. **Влияние иерархии памяти (кэш процессора):** Современные процессоры работают с оперативной памятью через многоуровневый кэш (L1, L2, L3). Доступ к оперативной памяти (RAM) занимает сотни тактов процессора, в то время как чтение из кэша L1 — всего несколько тактов. Алгоритмы с последовательным доступом к памяти (например, сортировка вставками или линейный проход в быстрой сортировке) эффективно используют механизмы аппаратного предсказания переходов и пространственной локальности данных, попадая в кэш процессора. Напротив, алгоритмы с хаотичным доступом или большим количеством аллокаций памяти (например, классическая сортировка слиянием с созданием промежуточных буферов в динамической памяти) вызывают частые промахи кэша (cache misses), что существенно увеличивает реальное время работы.
2. **Константы скрытые за $O$-нотацией:** Пусть алгоритм $A$ имеет сложность $1000 \cdot n \log n$, а алгоритм $B$ — сложность $2 \cdot n^2$. При малых значениях $n$ (например, $n = 10$) алгоритм $B$ отработает быстрее, несмотря на худшую асимптотику. На практике размер входных данных часто лежит в фиксированном диапазоне, где константа имеет решающее значение.
3. **Оптимизации компилятора:** Современные компиляторы C++ выполняют агрессивные оптимизации (векторизацию циклов, инлайнинг функций, развертывание циклов), которые могут радикально изменить производительность кода. Эмпирический замер позволяет оценить реальный эффект этих оптимизаций.

### Модели тестовых распределений данных

Чтобы объективно оценить поведение алгоритмов сортировки, недостаточно проверять их только на случайных массивах. Различные структуры входных данных способны активировать худшие или лучшие сценарии работы алгоритмов. Выделяют следующие базовые модели распределений:

- **Случайный массив (Random):** Элементы заполняются псевдослучайными числами в заданном диапазоне. Это стандартный тест для оценки среднего времени работы.
- **Строго возрастающий массив (Sorted):** Данные уже отсортированы по возрастанию. Для алгоритмов вроде наивной быстрой сортировки (с выбором первого или последнего элемента в качестве опорного) это приводит к деградации производительности до $\mathcal{O}(n^2)$ из-за несбалансированного разделения. Для сортировки вставками это лучший случай со сложностью $\mathcal{O}(n)$.
- **Строго убывающий массив (Reversed):** Данные отсортированы в обратном порядке. Это худший случай для сортировки вставками, требующий максимального количества сдвигов элементов, и еще один стресс-тест для алгоритмов разделения в быстрой сортировке.
- **Массив с дубликатами (Duplicates):** Массив, содержащий всего несколько уникальных значений (например, оценки студентов от 2 до 5). Проверяет устойчивость алгоритмов к избыточным сравнениям одинаковых элементов. Особое значение имеет схема разделения в быстрой сортировке (например, трехпутевое разбиение Дейкстры), которая эффективно обрабатывает массивы с большим количеством равных ключей.

### Современный генератор случайных чисел в C++17

В устадавших стандартах C и ранних версиях C++ для генерации случайных чисел использовалась функция `rand()` из заголовочного файла `<cstdlib>`. Она обладает серьезными недостатками: малой длиной периода повторения последовательности, предсказуемостью и плохими статистическими свойствами (например, проявлением паттернов в младших битах).

В стандарте C++17 для генерации псевдослучайных чисел используется заголовочный файл `<random>`, который разделяет генератор и распределение.

> **Определение.** Вихрь Мерсенна (`std::mt19937`) — это генератор псевдослучайных чисел, основанный на линейном рекурсивном соотношении над двоичной матрицей. Он имеет огромный период повторения $2^{19937}-1$ и проходит строгие статистические тесты на случайность.

Для настройки диапазона значений используется класс `std::uniform_int_distribution`. Рассмотрим практическую реализацию генерации массива.

#### Пример 1. Генерация вектора случайных чисел в C++17

Напишем фрагмент кода на C++17 для генерации вектора из $10000$ целых чисел, распределенных равномерно в диапазоне от $-500$ до $500$, с использованием `std::mt19937`.

```cpp
#include <iostream>
#include <vector>
#include <random>

// Функция генерации случайного вектора
std::vector<int> generateRandomVector(size_t size, int min_val, int max_val) {
    // Создаем и инициализируем аппаратный или псевдослучайный сид
    std::random_device rd;
    
    // Инициализируем генератор Вихря Мерсенна полученным сидом
    std::mt19937 gen(rd());
    
    // Настраиваем равномерное целочисленное распределение в закрытом интервале [min_val, max_val]
    std::uniform_int_distribution<int> distrib(min_val, max_val);
    
    std::vector<int> vec(size);
    for (size_t i = 0; i < size; ++i) {
        vec[i] = distrib(gen);
    }
    
    return vec;
}

int main() {
    // Установка локали для корректного вывода в консоль
    std::setlocale(LC_ALL, "Russian");
    
    size_t n = 10000;
    std::vector<int> test_data = generateRandomVector(n, -500, 500);
    
    std::cout << "Успешно сгенерирован вектор размером: " << test_data.size() << std::endl;
    std::cout << "Первые 5 элементов: ";
    for (size_t i = 0; i < 5; ++i) {
        std::cout << test_data[i] << " ";
    }
    std::cout << std::endl;
    
    return 0;
}
```

**Пояснение по строкам кода:**
1. `std::random_device rd;` — объект, обращающийся к системному источнику энтропии (если доступен), чтобы получить начальное зерно (seed).
2. `std::mt19937 gen(rd());` — инициализация генератора вихря Мерсенна. Использование одного экземпляра генератора на всю функцию критически важно для производительности и качества последовательности.
3. `std::uniform_int_distribution<int> distrib(min_val, max_val);` — объект распределения, гарантирующий равную вероятность выпадения любого целого числа из диапазона $[-500; 500]$.
4. `vec[i] = distrib(gen);` — генерация очередного числа путем вызова распределения от генератора.

### Организация точного замера времени выполнения

Для измерения времени работы алгоритмов в C++17 применяется библиотека `<chrono>`. Стандартный класс `std::chrono::high_resolution_clock` предоставляет часы с наивысшим доступным в системе разрешением.

Измерение времени строится по следующей схеме:
1. Создается копия исходного массива (чтобы все алгоритмы сортировали идентичные наборы данных).
2. Фиксируется момент времени до начала сортировки: `auto start = std::chrono::high_resolution_clock::now();`.
3. Выполняется тестируемый алгоритм.
4. Фиксируется момент времени после завершения: `auto end = std::chrono::high_resolution_clock::now();`.
5. Вычисляется разность и преобразуется в миллиметры или микросекунды.

#### Нивелирование погрешности измерений

Эмпирические замеры подвержены системным погрешностям: фоновые процессы операционной системы, динамическое изменение частоты процессора (Thermal Throttling) и состояние кэша. Для получения достоверных результатов применяются следующие методы:
- **Прогрев кэша (Warm-up):** Перед основными заделами алгоритм запускается один раз на черновом массиве, чтобы загрузить инструкции в кэш процессора.
- **Многократный запуск:** Измерение повторяется несколько раз (например, $5$ или $10$ раз), после чего берется минимальное или среднее значение времени. Использование минимального времени эффективно отсекает погрешности, вызванные прерываниями операционной системы.
- **Управление оптимизациями компилятора:** При отладке код компилируется без оптимизаций (`-O0`), что искажает реальную производительность. Для бенчмаркинга обязательно включается максимальный уровень оптимизации (флаг `-O3` в GCC/Clang). Компилятор должен видеть, что результат сортировки используется, иначе он может полностью вырезать неиспользуемый код (Dead Code Elimination).

#### Пример 2. Структура эксперимента по измерению времени сортировки

Опишем и реализуем структуру эксперимента по измерению времени сортировки массивов размером $n = 1000$, $n = 10000$ и $n = 100000$ для отсортированных входных данных. Для демонстрации используем заготовку функции сортировки вставками.

```cpp
#include <iostream>
#include <vector>
#include <chrono>
#-include <algorithm>

// Заглушка для сортировки вставками (Insertion Sort)
void insertionSort(std::vector<int>& arr) {
    size_t n = arr.size();
    for (size_t i = 1; i < n; ++i) {
        int key = arr[i];
        int j = static_cast<int>(i) - 1;
        while (j >= 0 && arr[j] > key) {
            arr[j + 1] = arr[j];
            j--;
        }
        arr[j + 1] = key;
    }
}

// Функция генерации отсортированного массива
std::vector<int> generateSortedVector(size_t size) {
    std::vector<int> vec(size);
    for (size_t i = 0; i < size; ++i) {
        vec[i] = static_cast<int>(i);
    }
    return vec;
}

int main() {
    std::setlocale(LC_ALL, "Russian");
    
    // Размеры входных данных для эксперимента
    std::vector<size_t> sizes = {1000, 10000, 100000};
    
    std::cout << "Эксперимент: замер времени Insertion Sort на отсортированных данных\n";
    std::cout << "--------------------------------------------------------\n";
    std::cout << "Размер (n)\tВремя (мс)\n";
    std::cout << "--------------------------------------------------------\n";
    
    for (size_t n : sizes) {
        // Подготовка отсортированных данных
        std::vector<int> original_data = generateSortedVector(n);
        
        // Создаем копию для эксперимента
        std::vector<int> work_data = original_data;
        
        // Замер времени с использованием high_resolution_clock
        auto start = std::chrono::high_resolution_clock::now();
        
        insertionSort(work_data);
        
        auto end = std::chrono::high_resolution_clock::now();
        
        // Вычисление длительности в миллисекундах с плавающей точкой
        std::chrono::duration<double, std::milli> elapsed = end - start;
        
        std::cout << n << "\t\t" << elapsed.count() << " мс" << std::endl;
    }
    std::cout << "--------------------------------------------------------\n";
    
    return 0;
}
```

## 3. Реализация алгоритмов на C++17

### 3.1. Требования к архитектуре кода и модульной структуре

Для того чтобы написанный код соответствовал стандартам академического проектирования и промышленной разработки на языке C++17, необходимо разделить всю логику программы на изолированные логические модули. Смешение генерации данных, алгоритмов сортировки и кода бенчмаркинга в одной функции `main` делает программу нечитаемой, затрудняет модульное тестирование и нарушает принцип единственной ответственности.

Проектируемая система должна состоять из следующих компонентов:
1. **Модуль генерации данных (`DataGenerator`)**: отвечает за создание векторов с заданными распределениями (случайные, отсортированные, обратно отсортированные, с дубликатами).
2. **Модуль сортирующих алгоритмов (`SortingAlgorithms`)**: содержит чистые реализации алгоритмов (`Insertion Sort`, `Merge Sort`, `Quick Sort`) без примеси кода ввода-вывода или замера времени.
3. **Модуль верификации (`Verifier`)**: реализует функцию проверки корректности сортировки (`is_sorted`).
4. **Модуль бенчмаркинга и оркестрации (`BenchmarkRunner`)**: организует замеры времени выполнения с использованием библиотеки `std::chrono` и вывод результатов.

Ниже приведены требования к типам данных: в качестве базового контейнера используется `std::vector<int>`, а для передачи коллекций в алгоритмы применяется передача по ссылке (`std::vector<int>&`), чтобы избежать избыточного копирования элементов на каждом рекурсивном шаге.

### 3.2. Пошаговая реализация сортировки вставками (Insertion Sort)

Сортировка вставками работает по принципу постепенного построения отсортированной части массива. Мысленно разделим массив на две части: левая часть (изначально состоящая только из первого элемента под индексом $0$) считается отсортированной, а правая часть — несортированной.

На каждом шаге внешнего цикла, начиная с индекса $i = 1$ до $n - 1$, мы берем первый элемент из несортированной части (назовем его ключевым элементом — `key = arr[i]`) и пытаемся вставить его на правильное место в уже отсортированную левую часть. Для этого мы сдвигаем элементы левой части вправо до тех пор, пока не найдем элемент, меньший или равный `key`, либо пока не упремся в начало массива.

#### Код реализации на C++17

```cpp
#include <vector>

void insertionSort(std::vector<int>& arr) {
    int n = static_cast<int>(arr.size());
    for (int i = 1; i < n; ++i) {
        int key = arr[i];
        int j = i - 1;
        
        // Сдвигаем элементы отсортированной части вправо, если они больше key
        while (j >= 0 && arr[j] > key) {
            arr[j + 1] = arr[j];
            j = --j; // уменьшаем индекс для проверки следующего элемента слева
        }
        
        // Вставляем key на освободившееся место
        arr[j + 1] = key;
    }
}
```

#### Пояснение по строкам:
- `int key = arr[i];` — сохраняем значение текущего элемента, так как при сдвиге элементов вправо значение `arr[i]` может быть затерто.
- `while (j >= 0 && arr[j] > key)` — цикл продолжается, пока мы не вышли за границу массива слева (`j >= 0`) и пока элемент слева строго больше нашего `key`.
- `arr[j + 1] = arr[j];` — сдвигаем элемент на одну позицию вправо освобождая ячейку.
- `arr[j + 1] = key;` — когда цикл `while` завершился (нашли элемент $\le key$ или дошли до начала), вставляем `key` в позицию `j + 1`.

### 3.3. Реализация сортировки слиянием (Merge Sort) и разбор функции слияния

Сортировка слиянием основана на парадигме «разделяй и властвуй». Массив рекурсивно деление пополам до тех пор, пока размер подмассива не станет равен $1$ (любой массив из одного элемента считается отсортированным). После этого запускается процедура `merge`, которая объединяет два отсортированных подмассива в один общий отсортированный массив.

#### Разбранный пример: функция слияния двух частей

Рассмотрим задачу: реализовать функцию слияния двух отсортированных частей вектора `arr[left...mid]` и `arr[mid + 1...right]`. 

> **Определение.** Процедура слияния (merge) — это алгоритм линейного времени $O(n)$, принимающий два отсортированных массива (или подмассива) и объединяющий их в один результирующий отсортированный массив путем последовательного сравнения элементов с указателями на начала обоих подмассивов.

Ниже приведена полная реализация функции слияния с временным буфером:

```cpp
#include <vector>

void merge(std::vector<int>& arr, int left, int mid, int right) {
    // Вычисляем размеры левой и правой частей
    int n1 = mid - left + 1;
    int n2 = right - mid;

    // Создаем временные буферы для левой и правой частей
    std::vector<int> leftArr(n1);
    std::vector<int> rightArr(n2);

    // Копируем данные во временные буферы
    for (int i = 0; i < n1; ++i) {
        leftArr[i] = arr[left + i];
    }
    for (int j = 0; j < n2; ++j) {
        rightArr[j] = arr[mid + 1 + j];
    }

    int i = 0; // Индекс для левого буфера leftArr
    int j = 0; // Индекс для правого буфера rightArr
    int k = left; // Индекс для записи объединенного массива в arr

    // Сливаем временные буферы обратно в arr[left...right]
    while (i < n1 && j < n2) {
        if (leftArr[i] <= rightArr[j]) {
            arr[k] = leftArr[i];
            ++i;
        } else {
            arr[k] = rightArr[j];
            ++j;
        }
        ++k;
    }

    // Копируем оставшиеся элементы leftArr, если они остались
    while (i < n1) {
        arr[k] = leftArr[i];
        ++i;
        ++k;
    }

    // Копируем оставшиеся элементы rightArr, если они остались
    while (j < n2) {
        arr[k] = rightArr[j];
        ++j;
        ++k;
    }
}

// Рекурсивная функция Merge Sort
void mergeSortRecursive(std::vector<int>& arr, int left, int right) {
    if (left >= right) {
        return; // Базовый случай: 0 или 1 элемент
    }
    
    int mid = left + (right - left) / 2; // Предотвращение переполнения целых чисел
    
    mergeSortRecursive(arr, left, mid);      // Сортировка левой половины
    mergeSortRecursive(arr, mid + 1, right); // Сортировка правой половины
    
    merge(arr, left, mid, right);            // Слияние отсортированных половин
}

void mergeSort(std::vector<int>& arr) {
    if (arr.empty()) {
        return;
    }
    mergeSortRecursive(arr, 0, static_cast<int>(arr.size()) - 1);
}
```

#### Пояснение индексов и логики слияния:
1. `int n1 = mid - left + 1;` и `int n2 = right - mid;` определяют точное количество элементов в левом и правом подмассивах. Например, если `left = 0`, `mid = 2`, то `n1 = 2 - 0 + 1 = 3` элемента (индексы $0, 1, 2$).
2. `mid = left + (right - left) / 2;` используется вместо стандартного `(left + right) / 2`, чтобы исключить потенциальное переполнение памяти (integer overflow), если `left` и `right` принимают очень большие значения.
3. Условие `leftArr[i] <= rightArr[j]` обеспечивает **устойчивость (stability)** сортировки слиянием: при равенстве элементов первым в исходный массив записывается элемент из левого подмассива, сохраняя их исходный относительный порядок.

### 3.4. Быстрая сортировка (Quick Sort) и схема разделения Хоара

Быстрая сортировка также использует подход «разделяй и властвуй», но разделение массива происходит не пополам, а вокруг опорного элемента (`pivot`). Элементы переставляются так, чтобы все элементы, меньшие либо равные опорному, оказались слева от него, а большие — справа.

#### Разбранный пример: функция разбиения по схеме Хоара

> **Определение.** Схема разделения Хоара (Hoare partition scheme) использует два указателя, которые начинают движение с противоположных концов массива (слева и справа) и движутся навстречу друг другу, меняя местами элементы, нарушающие порядок относительно опорного элемента.

Ниже приведена полная реализация Quick Sort с использованием схемы Хоара:

```cpp
#include <vector>
#include <algorithm>

// Функция разбиения по схеме Хоара
int partitionHoare(std::vector<int>& arr, int low, int high) {
    // Выбираем опорный элемент как средний элемент подмассива
    int pivot = arr[low + (high - low) / 2];
    
    int i = low - 1;
    int j = high + 1;
    
    while (true) {
        // Двигаем указатель i вправо, пока элемент меньше pivot
        do {
            ++i;
        } while (arr[i] < pivot);
        
        // Двигаем указатель j влево, пока элемент больше pivot
        do {
            --j;
        } while (arr[j] > pivot);
        
        // Если указатели встретились или пересеклись, возвращаем границу j
        if (i >= j) {
            return j;
        }
        
        // Меняем местами элементы, стоящие не на своих местах
        std::swap(arr[i], arr[j]);
    }
}

// Рекурсивная функция Quick Sort
void quickSortRecursive(std::vector<int>& arr, int low, int high) {
    if (low < high) {
        int pi = partitionHoare(arr, low, high);
        
        // Рекурсивная сортировка левой и правой частей
        quickSortRecursive(arr, low, pi);
        quickSortRecursive(arr, pi + 1, high);
    }
}

void quickSort(std::vector<int>& arr) {
    if (arr.empty()) {
        return;
    }
    quickSortRecursive(arr, 0, static_cast<int>(arr.size()) - 1);
}
```

#### Пояснение по шагам схемы Хоара:
1. `int pivot = arr[low + (high - low) / 2];` — выбор опорного элемента в середине подмассива защищает от худшего случая $O(n^2)$ при передаче уже отсортированного массива (в отличие от выбора первого или последнего элемента).
2. Цикл `do { ++i; } while (arr[i] < pivot);` гарантирует, что мы пропустим все элементы, которые уже находятся на корректной стороне от опорного (меньше `pivot`).
3. Аналогично, `do { --j; } while (arr[j] > pivot);` находит элемент справа, который меньше либо равен `pivot` и должен находиться слева.
4. `if (i >= j) return j;` — остановка работы алгоритма разделения, когда указатели пересеклись. Возвращаемый индекс `j` служит границей раздела для последующих рекурсивных вызовов.

### 3.5. Оптимизация Quick Sort: медиана трех и гибридизация с Insertion Sort

Классическая реализация Quick Sort может деградировать до квадратичной сложности $O(n^2)$ на определенных типах данных (например, на уже отсортированных массивах, если опорный элемент выбран неудачно) или исчерпать стек вызовов из-за большой глубины рекурсии для мелких подмассивов. 

Для устранения этих недостатков применяются две стандартные промышленные оптимизации:
1. **Правило «медианы трех» (Median-of-Three)** для выбора опорного элемента: берется первый, средний и последний элементы подмассива, находится их медиана, которая и назначается в качестве `pivot`.
2. **Гибридный алгоритм (IntroSort / Insertion Sort threshold)**: при уменьшении размера подмассива ниже порогового значения (обычно $n \le 16$) рекурсия Quick Sort прекращается, и оставшийся кусок сортируется с помощью высокоэффективной на малых объемах сортировки вставками (`Insertion Sort`).

Ниже представлена оптимизированная версия Quick Sort:

```cpp
#include <vector>
#include <algorithm>

// Функция сортировки вставками для небольших подмассивов
void insertionSortRange(std::vector<int>& arr, int low, int high) {
    for (int i = low + 1; i <= high; ++i) {
        int key = arr[i];
        int j = i - 1;
        while (j >= low && arr[j] > key) {
            arr[j + 1] = arr[j];
            --j;
        }
        arr[j + 1] = key;
    }
}

// Функция выбора медианы трех для опорного элемента
int medianOfThree(std::vector<int>& arr, int low, int high) {
    int mid = low + (high - low) / 2;
    
    // Сортируем элементы low, mid, high для нахождения медианы
    if (arr[low] > arr[mid]) {
        std::swap(arr[low], arr[mid]);
    }
    if (arr[low] > arr[high]) {
        std::swap(arr[low], arr[high]);
    }
    if (arr[mid] > arr[high]) {
        std::swap(arr[mid], arr[high]);
    }
    
    // Медиана теперь находится в позиции mid. Меняем ее с high - 1 для удобства partitioning
    std::swap(arr[mid], arr[high - 1]);
    return arr[high - 1];
}

int partitionOptimized(std::vector<int>& arr, int low, int high) {
    int pivot = medianOfThree(arr, low, high);
    int i = low;
    int j = high - 1;
    
    while (true) {
        while (arr[++i] < pivot) {}
        while (arr[--j] > pivot) {}
        
        if (i >= j) {
            break;
        }
        std::swap(arr[i], arr[j]);
    }
    
    // Возвращаем опорный элемент на его законное место
    std::swap(arr[i], arr[high - 1]);
    return i;
}

void quickSortOptimizedRecursive(std::vector<int>& arr, int low, int high) {
    // Порог переключения на Insertion Sort равен 16 элементам
    const int INSERTION_THRESHOLD = 16;
    
    while (high - low > INSERTION_THRESHOLD) {
        int pi = partitionOptimized(arr, low, high);
        
        // Хвостовая рекурсия: рекурсивно вызываем для меньшей части, а большую итерируем
        if (pi - low < high - pi) {
            quickSortOptimizedRecursive(arr, low, pi - 1);
            low = pi + 1;
        } else {
            quickSortOptimizedRecursive(arr, pi + 1, high);
            high = pi - 1;
        }
    }
    
    // Финальная досортировка малых массивов вставками
    if (low < high) {
        insertionSortRange(arr, low, high);
    }
}

void quickSortOptimized(std::vector<int>& arr) {
    if (arr.size() <= 1) {
        return;
    }
    quickSortOptimizedRecursive(arr, 0, static_cast<int>(arr.size()) - 1);
}
```

### 3.6. Верификация корректности и обработка граничных условий

Перед тем как передавать реализованные алгоритмы в модуль бенчмаркинга для замеров времени, необходимо строго убедиться в том, что они корректно сортируют массивы данных и не падают на граничных случаях.

#### Функция проверки отсортированности (`is_sorted`)

Написанная функция должна проходить по всему вектору и проверять, что каждый текущий элемент меньше либо равен следующему за ним элементу.

```cpp
#include <vector>

bool verifyIsSorted(const std::vector<int>& arr) {
    size_t n = arr.size();
    if (n <= 1) {
        return true;
    }
    for (size_t i = 0; i < n - 1; ++i) {
        if (arr[i] > arr[i + 1]) {
            return false; // Найдено нарушение порядка
        }
    }
    return true;
}
```

#### Обработка граничных условий
Каждая реализованная сортировка должна корректно отрабатывать в следующих ситуациях без возникновения исключений или бесконечных циклов:
1. **Пустой массив (`arr.size() == 0`)**: проверка на `arr.empty()` на входе в функцию предотвращает любые попытки доступа по индексам.
2. **Массив из одного элемента (`arr.size() == 1`)**: условие `left >= right` в рекурсивных сортировках и циклы для `Insertion Sort` корректно завершаются мгновенно, не изменяя структуру.
3. **Массивы с отрицательными числами**: алгоритмы используют оператор сравнения `>`, который корректно работает со знаковыми целыми числами (например, $-5 < -2$).
4. **Массивы с дубликатами**: алгоритмы не должны приводить к зависанию или бесконечной рекурсии при наличии большого количества абсолютно одинаковых элементов (благодаря строгим неравенствам `<` и `>`).

Ниже приведен полный компилируемый файл на C++17, объединяющий все рассмотренные модули, генерирующий тестовые данные, выполняющий сортировку и проверяющий ее корректность.

```cpp
#include <iostream>
#include <vector>
#include <random>
#include <algorithm>
#include <chrono>

// --- Модуль 1: Генератор данных ---
class DataGenerator {
public:
    static std::vector<int> generateRandom(size_t size, int minVal = -10000, int maxVal = 10000) {
        std::vector<int> arr(size);
        std::random_device rd;
        std::mt19937 gen(rd());
        std::uniform_int_distribution<int> dist(minVal, maxVal);
        for (size_t i = 0; i < size; ++i) {
            arr[i] = dist(gen);
        }
        return arr;
    }

    static std::vector<int> generateSorted(size_t size) {
        std::vector<int> arr(size);
        for (size_t i = 0; i < size; ++i) {
            arr[i] = static_cast<int>(i);
        }
        return arr;
    }

    static std::vector<int> generateReverseSorted(size_t size) {
        std::vector<int> arr(size);
        for (size_t i = 0; i < size; ++i) {
            arr[i] = static_cast<int>(size - i);
        }
        return arr;
    }
};

// --- Модуль 2: Верификатор ---
bool isSorted(const std::vector<int>& arr) {
    for (size_t i = 0; i + 1 < arr.size(); ++i) {
        if (arr[i] > arr[i + 1]) {
            return false;
        }
    }
    return true;
}

// --- Модуль 3: Алгоритмы сортировки ---

// 1. Insertion Sort
void insertionSort(std::vector<int>& arr) {
    int n = static_cast<int>(arr.size());
    for (int i = 1; i < n; ++i) {
        int key = arr[i];
        int j = i - 1;
        while (j >= 0 && arr[j] > key) {
            arr[j + 1] = arr[j];
            --j;
        }
        arr[j + 1] = key;
    }
}

// 2. Merge Sort
void merge(std::vector<int>& arr, int left, int mid, int right) {
    int n1 = mid - left + 1;
    int n2 = right - mid;
    std::vector<int> leftArr(n1);
    std::vector<int> rightArr(n2);

    for (int i = 0; i < n1; ++i) leftArr[i] = arr[left + i];
    for (int j = 0; j < n2; ++j) rightArr[j] = arr[mid + 1 + j];

    int i = 0, j = 0, k = left;
    while (i < n1 && j < n2) {
        if (leftArr[i] <= rightArr[j]) {
            arr[k++] = leftArr[i++];
        } else {
            arr[k++] = rightArr[j++];
        }
    }
    while (i < n1) arr[k++] = leftArr[i++];
    while (j < n2) arr[k++] = rightArr[j++];
}

void mergeSortRecursive(std::vector<int>& arr, int left, int right) {
    if (left >= right) return;
    int mid = left + (right - left) / 2;
    mergeSortRecursive(arr, left, mid);
    mergeSortRecursive(arr, mid + 1, right);
    merge(arr, left, mid, right);
}

void mergeSort(std::vector<int>& arr) {
    if (arr.empty()) return;
    mergeSortRecursive(arr, 0, static_cast<int>(arr.size()) - 1);
}

// 3. Quick Sort (Оптимизированный)
int medianOfThree(std::vector<int>& arr, int low, int high) {
    int mid = low + (high - low) / 2;
    if (arr[low] > arr[mid]) std::swap(arr[low], arr[mid]);
    if (arr[low] > arr[high]) std::swap(arr[low], arr[high]);
    if (arr[mid] > arr[high]) std::swap(arr[mid], arr[high]);
    std::swap(arr[mid], arr[high - 1]);
    return arr[high - 1];
}

int partitionOptimized(std::vector<int>& arr, int low, int high) {
    int pivot = medianOfThree(arr, low, high);
    int i = low;
    int j = high - 1;
    while (true) {
        while (arr[++i] < pivot) {}
        while (arr[--j] > pivot) {}
        if (i >= j) break;
        std::swap(arr[i], arr[j]);
    }
    std::swap(arr[i], arr[high - 1]);
    return i;
}

void insertionSortRange(std::vector<int>& arr, int low, int high) {
    for (int i = low + 1; i <= high; ++i) {
        int key = arr[i];
        int j = i - 1;
        while (j >= low && arr[j] > key) {
            arr[j + 1] = arr[j];
            --j;
        }
        arr[j + 1] = key;
    }
}

void quickSortRecursive(std::vector<int>& arr, int low, int high) {
    const int THRESHOLD = 16;
    while (high - low > THRESHOLD) {
        int pi = partitionOptimized(arr, low, high);
        if (pi - low < high - pi) {
            quickSortRecursive(arr, low, pi - 1);
            low = pi + 1;
        } else {
            quickSortRecursive(arr, pi + 1, high);
            high = pi - 1;
        }
    }
    if (low < high) {
        insertionSortRange(arr, low, high);
    }
}

void quickSort(std::vector<int>& arr) {
    if (arr.size() <= 1) return;
    quickSortRecursive(arr, 0, static_cast<int>(arr.size()) - 1);
}

// --- Главная программа с демонстрацией ---
int main() {
    size_t testSize = 10000;
    std::cout << "Generating test data of size " << testSize << "...\n";
    
    std::vector<int> originalData = DataGenerator::generateRandom(testSize);

    // Тест Insertion Sort
    {
        std::vector<int> dataset = originalData;
        auto start = std::chrono::high_resolution_clock::now();
        insertionSort(dataset);
        auto end = std::chrono::high_resolution_clock::now();
        std::chrono::duration<double, std::milli> elapsed = end - start;
        
        std::cout << "Insertion Sort: " << elapsed.count() << " ms | Sorted: " 
                  << (isSorted(dataset) ? "YES" : "NO") << "\n";
    }

    // Тест Merge Sort
    {
        std::vector<int> dataset = originalData;
        auto start = std::chrono::high_resolution_clock::now();
        mergeSort(dataset);
        auto end = std::chrono::high_resolution_clock::now();
        std::chrono::duration<double, std::milli> elapsed = end - start;
        
        std::cout << "Merge Sort:     " << elapsed.count() << " ms | Sorted: " 
                  << (isSorted(dataset) ? "YES" : "NO") << "\n";
    }

    // Тест Quick Sort
    {
        std::vector<int> dataset = originalData;
        auto start = std::chrono::high_resolution_clock::now();
        quickSort(dataset);
        auto end = std::chrono::high_resolution_clock::now();
        std::chrono::duration<double, std::milli> elapsed = end - start;
```

- **Временная сложность Insertion Sort**: в худшем случае $O(n^2)$, в лучшем (на отсортированных данных) $O(n)$.
- **Временная сложность Merge Sort и Quick Sort**: в среднем и худшем случаях $O(n \log n)$.
- **Пространственная сложность**: для Insertion Sort — $O(1)$, для Quick Sort — $O(\log n)$ (стек рекурсии), для Merge Sort — $O(n)$ (выделение буферов во время слияния).

## 4. Эмпирический анализ, тестирование и типичные ошибки

### Анализ экспериментальных данных и построение таблиц производительности

Теоретический анализ с использованием $O$-нотации описывает асимптотическое поведение алгоритмов при стремлении размера входных данных $n$ к бесконечности. Однако на практике на время выполнения программы влияют аппаратные факторы: архитектура процессора, иерархия кэш-памяти ($L1$, $L2$, $L3$), предсказатели переходов и накладные расходы на выделение памяти. Для оценки реальной эффективности проводят эмпирическое тестирование (бенчмаркинг) на массивах разного размера и структуры.

Рассмотрим типичные результаты замеров времени выполнения трех алгоритмов (сортировка вставками — *Insertion Sort*, сортировка слиянием — *Merge Sort*, быстрая сортировка — *Quick Sort*) на массивах со случайно распределенными целочисленными данными. Время измеряется в миллисекундах ($\text{мс}$).

| Размер массива ($n$) | Insertion Sort ($O(n^2)$), $\text{мс}$ | Merge Sort ($O(n \log n)$), $\text{мс}$ | Quick Sort ($O(n \log n)$), $\text{мс}$ |
|---|---|---|---|
| $10^3$ | $0{,}12$ | $0{,}18$ | $0{,}09$ |
| $10^4$ | $12{,}40$ | $2{,}15$ | $1{,}10$ |
| $10^5$ | $1250{,}00$ | $24{,}80$ | $12{,}50$ |
| $10^6$ | $128000{,}00$ ($128$ с) | $295{,}00$ | $142{,}00$ |

Анализ таблицы подтверждает теоретические выводы. Для малых объемов данных ($n = 1000$) разница во времени минимальна, а сортировка вставками даже опережает алгоритм слияния за счет отсутствия рекурсивных вызовов и накладных расходов на управление памятью. Однако с ростом $n$ квадратичная зависимость *Insertion Sort* приводит к катастрофическому падению производительности: при увеличении $n$ в $10$ раз (от $10^4$ до $10^5$) время работы возрастает примерно в $100$ раз ($12{,}40 \to 1250{,}00$). В то же время алгоритмы с логарифмическим множителем (*Merge Sort* и *Quick Sort*) масштабируются линейно-логарифмически: рост $n$ в $10$ раз увеличивает время примерно в $10\text{--}12$ раз.

### Деградация Quick Sort и способы её предотвращения

Классическая реализация быстрой сортировки выбирает опорным элементом (*pivot*) фиксированный элемент, например, последний или первый элемент подмассива. Если входной массив уже отсортирован или обратно отсортирован, а в качестве опорного всегда выбирается крайний элемент, процедура разбиения (*partition*) делит массив на две части неравномерно: одна часть содержит $0$ элементов, а вторая — $n-1$ элементов.

В этом случае глубина рекурсии достигает $n$, а общее количество операций становится равным сумме арифметической прогрессии:

$$T(n) = T(n-1) + O(n) = \sum_{i=1}^{n} i = \frac{n(n+1)}{2} = O(n^2)$$

Алгоритм деградирует до квадратичной сложности и может вызвать переполнение стека вызовов (*Stack Overflow*) при больших $n$.

Для устранения этого недостатка применяют следующие подходы:
1. **Медиана трех (*Median of Three*):** В качестве опорного элемента выбирается медиана между первым, средним и последним элементами подмассива. Это гарантирует, что в худшем случае на отсортированных данных разбиение будет близко к половинному.
2. **Рандомизированный выбор (*Randomized Quick Sort*):** Опорный элемент выбирается случайно в диапазоне текущих индексов. Вероятность построения худшего дерева рекурсии на любых входных данных становится пренебрежимо малой.
3. **Гибридная сортировка (*Introsort*):** Алгоритм начинает работу как *Quick Sort*, но если глубина рекурсии превышает допустимый порог $2 \cdot \lfloor\log_2 n\rfloor$, управление переключается на сортировку кучей (*Heapsort*), гарантирующую $O(n \log n)$ в худшем случае.

### Преимущества Insertion Sort на малых массивах и почти отсортированных данных

Несмотря на теоретическую сложность $O(n^2)$ в худшем и среднем случаях, *Insertion Sort* обладает выдающимися практическими характеристиками на двух типах входных данных:

1. **Почти отсортированные массивы:** Если элементы смещены относительно своих правильных позиций на небольшое расстояние $k$, внутренний цикл сдвига в *Insertion Sort* выполняется не на каждый элемент, а ровно столько раз, сколько требуется для перестановки. Временная сложность в таком случае составляет $O(kn)$, что при малом $𝑘$ стремится к $O(n)$ (линейное время). Ни *Merge Sort*, ни *Quick Sort* не способны адаптироваться к степени упорядоченности исходного массива и выполняют одинаковое количество операций независимо от него.
2. **Очень маленькие массивы:** Накладные расходы на вызов функций, создание стековых кадров рекурсии и ветвления в *Merge Sort* и *Quick Sort* делают их применение неэффективным при $n \le 16$. *Insertion Sort* написан компактно, использует локальность кэш-памяти и не создает рекурсивных вызовов, поэтому на коротких массивах работает быстрее сложных алгоритмов. На этом свойстве основана оптимизация профессиональных библиотечных сортировок: когда размер подмассива в рекурсивном алгоритме становится меньше порогового значения (обычно от $10$ до $32$), рекурсия останавливается и вызывается *Insertion Sort*.

---

### Накладные расходы памяти в Merge Sort

Алгоритм *Merge Sort* требует выделения дополнительной памяти для промежуточного буфера при слиянии двух отсортированных частей. Пространственная сложность алгоритма составляет $O(n)$.

В языке C++ выделение памяти под вспомогательный массив может осуществляться двумя способами:
- **Динамическое выделение в куче (*Heap Allocation*):** Создание вектора `std::vector<int> temp(right - left + 1)` или использование оператора `new` внутри функции слияния. Выделение памяти в куче через системные вызовы операционной системы является дорогостоящей операцией. Накладные расходы на запросы к памяти могут превысить выигрыш от эффективного алгоритма сортировки, резко увеличив время работы.
- **Статическое выделение буфера заранее:** Создание единого буфера вспомогательной памяти размера $n$ до начала сортировки и передача его по ссылке во все рекурсивные вызовы. Это полностью устраняет накладные расходы на динамическое выделение памяти во время работы рекурсии.

### Разобранные примеры

#### Пример 1. Анализ результатов эмпирического тестирования
**Условие:** Алгоритм *Insertion Sort* для $n = 100\,000$ на случайных данных выполнился за $4500\text{ мс}$, а *Quick Sort* — за $15\text{ мс}$. Требуется объяснить причину столь резкой разницы на основе теоретических оценок и аппаратных особенностей.

**Ход рассуждений:**
1. Запишем теоретические оценки сложности для обоих алгоритмов на случайных входных данных:
   - *Insertion Sort*: средняя сложность $T_{ins}(n) = \Theta(n^2)$.
   - *Quick Sort*: средняя сложность $T_{quick}(n) = \Theta(n \log_2 n)$.
2. Подставим значение $n = 100\,000$:
   - Для *Insertion Sort* количество операций пропорциональна $(10^5)^2 = 10^{10}$ операций.
   - Для *Quick Sort* количество операций пропорциональна $10^5 \cdot \log_2(10^5) \approx 10^5 \cdot 16{,}61 \approx 1{,}66 \cdot 10^6$ операций.
3. Вычислим теоретическое соотношение количества операций:
   
   $$\frac{10^{10}}{1{,}66 \cdot 10^6} \approx 6024$$
   
4. Фактическое отношение времени работы составляет:
   
   $$\frac{4500\text{ мс}}{15\text{ мс}} = 300\text{ раз}$$
   
5. Объясним расхождение между теоретическим отношением операций ($6000$) и практическим отношением времени ($300$): *Insertion Sort* обладает исключительно высокой эффективностью использования кэша процессора (элементы считываются подряд линейно, процессорный предсказатель переходов работает идеально). Тем не менее, квадратичный рост числа операций делает разрыв непреодолимым при больших $n$.

**Ответ:** Резкая разница в пользу *Quick Sort* объясняется разницей асимптотических классов сложности: $O(n^2)$ против $O(n \log n)$. Для $n = 100\,000$ *Insertion Sort* выполняет на несколько порядков больше операций сравнения и сдвига, чем *Quick Sort*.

---

#### Пример 2. Поиск ошибки в реализации рекурсивного шага Merge Sort
**Условие:** Студент написал реализацию *Merge Sort*, где условие выхода из рекурсии задано как `left >= right`, однако при вызове рекурсии передаются неверные индексы `mid`, что приводит к аварийному завершению программы из-за переполнения стека вызовов (*Stack Overflow*). Ниже приведена ошибочная функция:

```cpp
void mergeSort(std::vector<int>& arr, int left, int right) {
    if (left >= right) {
        return;
    }
    int mid = left + (right - left) / 2;
    mergeSort(arr, left, mid);
    mergeSort(arr, mid, right); // Ошибка здесь
    merge(arr, left, mid, right);
}
```

**Ход рассуждений:**
1. Проанализируем границы подмассивов, передаваемых в рекурсивные вызовы.
2. Пусть исходный массив состоит из двух элементов: `left = 0`, `right = 1`.
3. Вычисляем середину: `mid = 0 + (1 - 0) / 2 = 0`.
4. Первый рекурсивный вызов: `mergeSort(arr, 0, 0)`. Так как `left == right` ($0 \ge 0$), срабатывает условие выхода, вызов завершается корректно.
5. Второй рекурсивный вызов: `mergeSort(arr, 0, 1)`. Обратите внимание: передаются границы от $0$ до $1$.
6. Внутри этого второго вызова снова вычисляется `mid = 0`, и снова вызываются `mergeSort(arr, 0, 0)` и `mergeSort(arr, 0, 1)`. Возникает бесконечная рекурсия для подмассива с границами `0` и `1`, так как правая граница не уменьшается. Стек вызовов заполняется до исчерпания выделенной памяти.
7. Для корректного разделения второй вызов должен охватывать правую половину: от `mid + 1` до `right`.

**Ответ:** Ошибка заключается в передаче неверной правой границы во второй рекурсивный вызов. Строку `mergeSort( необходимо исправить на `mergeSort(arr, mid + 1, right)`.

### Типичные ошибки реализации

1. **Выход за границы массива в функции слияния (*Merge*):** При слиянии двух отсортированных частей забывают проверить условие исчерпания элементов одного из временных буферов, что приводит к обращению по неверному индексу вектора.
2. **Бесконечная рекурсия в Quick Sort:** Возникает, если функция разбиения (*partition*) возвращает индекс опорного элемента, равный левой или правой границе во всех вызовах (например, при некорректном выборе опорного элемента на массиве с равными элементами).
3. **Утечки памяти или падение производительности при динамическом выделении буферов:** Создание нового объекта `std::vector` на каждой итерации слияния в *Merge Sort* приводит к непрерывным обращениям к куче. Необходимо либо использовать единый предварительно выделенный буфер, либо отказаться от ручного управления памятью в пользу стандартных контейнеров с правильным проектированием индексов.

### Контрольные вопросы к защите лабораторной работы

1. **Вопрос:** Почему сортировка вставками на массиве размером $n = 10$ работает быстрее, чем быстрая сортировка, а на массиве $n = 1\,000\,000$ проигрывает в сотни раз?
   **Ответ:** На малых массивах накладные расходы на рекурсию и создание стековых кадров в *Quick Sort* превышают время работы простого линейного алгоритма. На больших массивах доминирует асимптотическая сложность: квадратичная $O(n^2)$ у *Insertion Sort* приводит к лавинообразному росту числа операций по сравнению с $O(n \log n)$ у *Quick Sort*.

2. **Вопрос:** В чем заключается худший случай для классического алгоритма *Quick Sort* и как его избежать?
   **Ответ:** Худший случай — это уже отсортированный или обратно отсортированный массив при выборе фиксированного опорного элемента (первого или последнего). Сложность деградирует до $O(n^2)$, возникает переполнение стека. Способы предотвращения: выбор медианы трех элементов в качестве опорного, использование рандомизации или переход на гибридную сортировку (*Introsort*).

3. **Вопрос:** Какова пространственная сложность алгоритма *Merge Sort* и почему она выше, чем у *Insertion Sort*?
   **Ответ:** Пространственная сложность *Merge Sort* составляет $O(n)$, так как для процедуры слияния требуется дополнительный буфер памяти аналогичного размера. *Insertion Sort* сортирует данные «на месте» (*in-place*) и требует $O(1)$ дополнительной памяти.

4. **Вопрос:** Почему для генерации тестовых данных в современном C++ запрещено использовать функцию `rand()` из библиотеки `<cstdlib>`?
   **Ответ:** Функция `rand()` использует устаревшие линейные конгруэнтные генераторы с малым периодом повторения, низкой статистической надежностью и предсказуемой структурой последовательности. В C++17 стандартная библиотека `<random>` предоставляет криптостойкие и статистически корректные генераторы (например, `std::mt19937`) с настраиваемыми распределениями.

## Типичные ошибки

1. **Неправильный выбор опорного элемента (*pivot*) в Quick Sort на отсортированных данных.** 
   * *Почему возникает:* Выбор первого или последнего элемента массива в качестве опорного при сортировке уже отсортированных или обратно отсортированных данных приводит к деградации алгоритма до квадратичной сложности $O(n^2)$ и переполнению стека.
   * *Как избежать:* Всегда использовать стратегию «медианы трех» или случайный выбор опорного элемента.
   * *Пример:* `int pivot = arr[high];` на отсортированном массиве приведет к худшему случаю разделения.

2. **Забытая проверка выхода из рекурсии (базовый случай).**
   * *Почему возникает:* Отсутствие условия `if (left >= right)` или `if (n <= 1)` в рекурсивных алгоритмах (*Merge Sort*, *Quick Sort*).
   * *Как избежать:* Начинать любую рекурсивную функцию с проверки условий завершения.
   * *Пример:* Написание `mergeSort(arr, left, mid)` без проверки приведет к бесконечной рекурсии и падению по `Stack Overflow`.

3. **Ошибки в индексации при разделении подмассивов.**
   * *Почему возникает:* Путаница между включительными и исключительными границами диапазонов (например, использование `high` как индекса последнего элемента против `high` как длины).
   * *Как избежать:* Четко документировать границы: пусть `low` и `high` всегда задают включительный диапазон `[low, high]`.
   * *Пример:* Передача `mid` вместо `mid + 1` во второй рекурсивный вызов *Merge Sort*.

4. **Выделение памяти под временные буферы внутри глубокой рекурсии.**
   * *Почему возникает:* Создание `std::vector` внутри функции слияния `merge` без переиспользования памяти.
   * *Как избежать:* Выделять вспомогательный буфер один раз до начала сортировки и передавать его по ссылке.
   * *Пример:* `std::vector<int> temp(n1 + n2);` внутри рекурсивного слияния замедляет работу в десятки раз из-за постоянных обращений к куче.

5. **Нарушение условия устойчивости в кастомных сравнениях.**
   * *Почему возникает:* Использование строгого знака `<` вместо нестрогого `<=` при слиянии равных элементов.
   * *Как избежать:* Для сохранения устойчивости (*stability*) при равенстве элементов предподчтение всегда должно отдаваться элементам из левого подмассива: `leftArr[i] <= rightArr[j]`.
   * *Пример:* Написание `leftArr[i] < rightArr[j]` делает сортировку слиянием неустойчивой на равных ключах.

6. **Использование устаревшей функции `rand()` вместо `<random>`.**
   * *Почему возникает:* Привычка из языка C использовать `rand() % N`.
   * *Как избежать:* Применять современные инструменты C++17: `std::mt19937` и `std::uniform_int_distribution`.
   * *Пример:* `int val = rand() % 100;` обладает плохими статистическими свойствами и ограничен диапазоном `RAND_MAX`.

7. **Некорректная обработка массивов нулевой длины.**
   * *Почему возникает:* Отсутствие проверки `arr.empty()` на входе в алгоритм.
   * *Как избежать:* Всегда проверять размер контейнера перед вычислением индексов `high = size - 1`, так как `size_t` является беззнаковым типом, и вычитание единицы из нуля приведет к переполнению (`SIZE_MAX`).
   * *Пример:* `int high = arr.size() - 1;` для пустого вектора вызовет неопределенное поведение.

1. **Задача 1.** Проследите по шагам выполнение алгоритма *Insertion Sort* для массива $A = [8, 3, 5, 1, 9, 2]$. Укажите общее количество выполненных сравнений и пересылок элементов.
2. **Задача 2.** Выполните один шаг разбиения массива $A = [9, 1, 5, 8, 3, 7, 4, 6]$ по схеме Ломуто, приняв в качестве опорного элемента последний элемент (`pivot = 6`). Запишите результирующий массив и возвращаемый индекс.
3. **Задача 3.** Имеется два отсортированных подмассива: левый `[2, 5, 8]` и правый `[1, 4, 9]`. Покажите по шагам работу процедуры слияния (*merge*) из алгоритма *Merge Sort* и запишите итоговый объединенный массив.
4. **Задача 4.** Напишите программу на C++17, которая генерирует массив из $50\,000$ случайных целых чисел в диапазоне от $-1000$ до $1000$, сортирует его с помощью реализованной вами функции *Merge Sort* и проверяет корректность с помощью функции `isSorted`. Выведите затраченное время в миллисекундах.
5. **Задача 5.** Модифицируйте функцию разбиения *Quick Sort* так, чтобы в качестве опорного элемента выбирался элемент, вычисленный по правилу «медианы трех» для первого, среднего и последнего элементов. Проверьте работу на обратно отсортированном массиве из $10\,000$ элементов.
6. **Задача 6.** Напишите гибридную функцию сортировки на C++17, которая использует *Quick Sort* для крупных подмассивов, а при уменьшении размера подмассива до $16$ элементов и меньше переключается на *Insertion Sort*. Протестируйте её на массиве из $100\,000$ элементов с большим количеством дубликатов (значения от $1$ до $5$).
7. **Задача 7.** Студент запустил бенчмарк для *Insertion Sort* и *Quick Sort* на массиве размером $n = 1000$ из уже отсортированных данных. Время работы *Insertion Sort* составило $0{,}002\text{ мс}$, а *Quick Sort* — $0{,}015\text{ мс}$. Объясните, почему *Insertion Sort* оказался быстрее в данном конкретном эксперименте.
8. **Задача 8.** Реализуйте функцию проверки корректности сортировки `bool isNearlySorted(const std::vector<int>& arr, int k)`, которая возвращает `true`, если каждый элемент массива смещен относительно своего отсортированного положения не более чем на $k$ позиций, и `false` в противном случае.

## Ответы к задачам

1. Общее число сравнений: $12$, общее число пересылок (сдвигов): $9$. Отсортированный массив: `[1, 2, 3, 5, 8, 9]`.
2. Результирующий массив после раздела: `[1, 5, 3, 4, 6, 7, 8, 9]`, индекс опорного элемента: $4$.
3. Итоговый объединенный массив: `[1, 2, 4, 5, 8, 9]`.
4. Программа выводит время выполнения сортировки $50\,000$ элементов (в диапазоне $0{,}5\text{ мс}$ — $3{,}0\text{ мс}$) и статус `Sorted: YES`.
5. Использование медианы трех устраняет худший случай на отсортированных данных; время сортировки $10\,000$ элементов составляет менее $2\text{ мс}$, `isSorted` возвращает `YES`.
6. Гибридный алгоритм (Quick Sort + Insertion Sort при размере $\le 16$) сортирует $100\,000$ элементов с дубликатами за $2\text{--}5\text{ мс}$, проверка `isSorted` возвращает `YES`.
7. На уже отсортированных данных *Insertion Sort* работает за линейное время $O(n)$ ($n-1$ сравнение и $0$ сдвигов), в то время как *Quick Sort* тратит дополнительные ресурсы на рекурсивные вызовы и разбиение, выполняя работу за $O(n \log n)$.
8. Функция корректно проверяет условие сдвига элементов не более чем на $k$ позиций за время $O(n \log n)$ (путем сопоставления с эталонным отсортированным массивом) или $O(n)$, возвращая `true` для почти отсортированных массивов.
